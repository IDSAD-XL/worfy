# Аудит кодовой базы: от чтения до тикетов

Результат — эпик `<корень тикетов>/audit-<дата>/` (корень — `F tickets.root`): находки с адресом `file:line` и доказательством,
тикеты размером в один PR, разбивка на волны. Правило скилла — **находка остаётся заявлением, пока её
не воспроизвёл второй агент**: тикет, написанный по одной прочитанной строке, врёт примерно в трети
утверждений (так показала ревизия 67 тикетов Auction, разбор `.scratch/ui-triage/triage-27-41.md`
в его репозитории).

Аргументы: `--lenses a,c,i` сужает набор линз (по умолчанию все линзы профиля), `--live` включает
проход по стенду. Запуск по расписанию идёт без вопросов: спорное уходит в `map.md`.

## Профиль проекта

Всё проектное — линзы, база ветвления, корень тикетов, коллекции `qmd`, стенд, каталог ADR — берётся
из профиля (`~/.claude/bin/profile`, контракт — `~/.claude/profiles/README.md`). Ниже `F <поле>` —
сокращение для `~/.claude/bin/profile --field <поле>`, запущенного в корне проекта или в worktree
аудита (профиль находится по репозиторию, worktree опознаётся так же). В блоках bash ниже оно
объявлено функцией первой строкой: состояние shell между вызовами не сохраняется.

```bash
~/.claude/bin/profile --name; echo "КОД=$?"
```

- `0` — работать по профилю.
- `3` — проект не зарегистрирован или у него нет профиля. **Стоп**: сказать «проект `<путь>` не
  зарегистрирован — профиля нет, аудиту не по чему» и предложить завести профиль
  (`~/.claude/profiles/README.md`, раздел «Новый проект»). Линзы и пути не угадывать. По
  расписанию — та же строка в ответ, без эпика.
- `1`, `2` — сломан реестр или профиль: стоп, сообщение из stderr — в ответ.

Поле, которого нет (`F` вернул код 4 или напечатал `null`), выключает шаг, который на нём держится, и
это говорится словами («проход по стенду пропущен: в профиле нет `dev_stack`»). Без `audit_lenses`
аудит не идёт вовсе — стоп с той же формулировкой. Проектные факты, которые не уместились в поля, —
`~/.claude/bin/profile --rules`; прочитать один раз до брифов. Тексты `spec.md`, `map.md` и тикетов —
на языке, которым написаны уже существующие тикеты проекта (нет ни одного — `F language.reports`);
отчёт пользователю — `F language.reports`; заголовки шаблона тикета — как в шаблоне ниже.

## 0. Ориентировка

```bash
F() { ~/.claude/bin/profile --field "$1"; }
BASE=$(F worktree.base) && [ "$BASE" != null ] || BASE=$(git symbolic-ref -q --short refs/remotes/origin/HEAD)
T=$(F tickets.root)                      # корень эпиков, например .scratch/
A=audit-$(date +%F); { git show-ref -q "refs/heads/$A" || [ -d "$T$A" ]; } && A=$A-2   # эпик = ветка = worktree; повтор в тот же день — суффикс -2, -3, …
git fetch origin --prune && git log --oneline -1 "$BASE"   # коммит аудита — в шапку spec.md
git worktree add "../$A" -b "$A" "$BASE" && cd "../$A"
~/.claude/bin/epic-status; find "${T%/}" -maxdepth 1 -type d -name 'audit-*' | sort | tail -1   # все эпики; прошлый аудит (не `ls audit-*/`: в zsh пустая маска — ошибка)
```

Путь `../$A` — это worktree аудита; он идёт в каждый бриф ниже как «Дерево». Имя `$A` — это и
эпик, и ветка worktree: в следующих блоках оно выводится заново, `git branch --show-current` в
worktree аудита (состояние shell между вызовами не сохраняется). Ниже `$T$A` — `<tickets.root><эпик
аудита>`, например `.scratch/audit-2026-10-05/`.

Один вызов `qmd` (скилл `qmd`), `intent` «уроки прошлых аудитов»: `vec` «прошлые аудиты кода и ложные
находки», `lex` `аудит находк ложн`. Ищется весь индекс: `F qmd.collections` (что в них — `F qmd.covers`)
— подсказка, где ждать ответа, а не фильтр для параметра `collections`. Оплаченный урок меняет брифы
до отправки.

Из `spec.md` прошлого аудита выписать находки по линзам с путём тикета и его `state` из
`epic-status --json`; список уходит в бриф линзы, агент по каждой отвечает `fixed | still | regressed`.
Каждый `regressed` любой severity идёт в фазу 2 вместе с HIGH; подтверждённый — новый тикет с
`Source:` на старый. `still` при открытом тикете — напоминание в `spec.md`. У первого аудита список пуст.

## 1. Линзы — параллельные агенты, только чтение

Линза — одна тема проверки со своим агентом `scout` (только чтение, ответ до 30 строк с
`путь:строка`); все линзы уходят одним сообщением. Таблица линз — из профиля, по строке на линзу:

```bash
F() { ~/.claude/bin/profile --field "$1"; }
F audit_lenses | jq -r '.[] | "| \(.id) — \(.title) | \(.where | map("`\(.)`") | join(", ")) | \(.finding) |"'
```

Столбцы: `| Линза | Где смотреть | Что считается находкой |`. `--lenses` отбирает строки по `id`.

Бриф каждой линзы — дословно:

> Дерево: `<путь worktree аудита>` — профиль запускай с `-C` на нём.
> Линза `<id>`: `<строка таблицы>`. Коммит `<hash>`.
> Старые находки линзы: `<список>` — по каждой ответить `fixed | still | regressed` с `file:line`.
> По одной находке на строку, JSON без переносов:
> `{"lens","severity":"HIGH|MED|LOW","file","line","evidence_command","claim","suggested_fix","acceptance"}`.
> `evidence_command` — команда, показывающая дефект (`sed -n`, `grep -n`, команда проекта из
> `commands` профиля); `acceptance` — проверяемое условие «готово, когда». Утверждение без
> `file:line` или вывода команды в отчёт не попадает. Пусто — так и написать: «ничего не нашёл».
> Больше 30 находок — оставить старшие по severity и добавить строку `dropped: N`.

**Проход по стенду** (`--live`) ведёт главная сессия, не линза. Стек поднят — каждая команда из
`F dev_stack.check` отвечает как положено (база в списке контейнеров, слушатель на порту
`F dev_stack.web_port`); сервер запускает только `preview_start`, страницы читаются `read_page` и
снимками экрана. Снимок — не замер: производительность на dev-сервере в отчёт не идёт; непроверенное
перечислить поимённо. `dev_stack` нет — проход пропускается, и это пишется в `spec.md`.

## 2. Перекрёстная проверка

Каждая HIGH-находка и каждый `regressed` получают агента `reviewer` с брифом опровергнуть: дерево —
`<путь worktree аудита>`; выполнить `evidence_command`, перечитать `file:line` ±20 строк, найти
проверку выше по вызову. Группировка по линзе, до 8 находок на агента; автор линзы своё не
проверяет. Ответ — строка на находку `confirmed | not-reproduced | moved <file:line>` с причиной и
строка «что запускал, код выхода». `not-reproduced` выбывает; `moved` — подтверждена по новому адресу.

Итог фазы — таблица в `spec.md`, она же сводка качества линз:
`| Линза | проверено | подтверждено | снято | доля ложных |`. Линза с долей ложных выше трети
получает пометку в брифе следующего аудита. Остальные MED и LOW попадают в тикеты только после
перечитывания `file:line` в фазе 4.

## 3. Дедупликация

Источники — тикеты проекта там, куда указывает `tickets.path` (других трекеров скилл не опрашивает),
и решения: MCP-сервер `qmd`, где ждать ответа подсказывают `F qmd.collections` и `F qmd.covers`
(тикеты на основной ветке, ADR, файл состояния, словарь). Часть тикетов живёт только на ветках, ещё
не влитых в основную: открытые тикеты веток с коммитами за 14 дней собирает обход ниже (как
`epic-board`, но без HTML):

```bash
git for-each-ref refs/remotes/origin --format='%(refname:short) %(committerdate:unix)' \
  | awk -v t="$(date -v-14d +%s)" '$2>t{print $1}' \
  | while read -r b; do ~/.claude/bin/epic-status --json --ref "$b"; done \
  | jq -c '.tickets[]|select(.state!="done")|[.ref,.epic,.num,.slug,.title]' > "$TMPDIR/live-tickets.jsonl"
```

Агент на линзу — `scout`: у него есть инструменты `qmd` (`query`, `get`), а правила `qmd` написаны под
MCP-форму (`searches`, `intent`, `minScore`). В брифе — дерево аудита и путь к `live-tickets.jsonl`.
Находки HIGH и MED; на каждую один вызов `query` по всему индексу (коллекции профиля — подсказка, не
фильтр), `intent` — тема линзы, два подзапроса: `lex` из 2–4 основ плюс идентификатор из кода (имя
функции, флага или файла без пути), `vec` — `claim` своими словами.
Попадание с баллом ≥ 0.6 читается через `get` до вердикта. По `live-tickets.jsonl` — `grep` по файлу
и словам дефекта, тело тикета — `git show <ref>:<путь тикета по tickets.path>`. Вердикты:

- **дубль** — тикет в `state` `open | work | blocked`, чьё тело называет тот же файл и тот же
  дефект. В `spec.md` строкой «уже в работе: `<эпик>/<NN>`», тикета нет.
- **регрессия** — тикет `done`, дефект подтверждён в фазе 2. Новый тикет, `Source:` на старый.
- **решено** — ADR принял решение против `suggested_fix`, и его посылка жива. В `map.md` под
  «решение принято», без тикета. Посылка ушла — тикет `Type: grilling` на новый ADR: старый
  неизменен, пересмотр пишется новым номером.
- **новое** — попаданий ≥ 0.6 нет либо все прочитанные о другом.

Ответ агента — таблица `находка | вердикт | путь или ADR`, без пересказа документов.

## 4. Тикеты

Эпик `$T$A/` — три вещи:

- `spec.md`: `Status: ready-for-agent`, коммит аудита, линзы; по темам — находки с `file:line`,
  `evidence_command` и вердиктом фазы 2; таблица ложных; таблица дедупликации; список
  непроверенного из прохода по стенду.
- `map.md`: у каждой находки адрес — **очередь исправлений** (тикет здесь), **решение** (моё —
  тикет `Type: grilling`; заказчика — вопрос в пакет), **правка доков** (тикет `Type: task`),
  **будущая фаза** (указатель в `<tickets.root>roadmap`). Карта закрыта, когда без адреса не осталось
  ни одной находки.
- `issues/NN-<slug>.md`, нумерация с `01` в порядке волн, шаблон дословно (`<adr_dir>` — `F docs.adr_dir`;
  нет каталога ADR — ссылка на ADR из `Source:` убирается):

```markdown
# NN — <Заголовок: что меняется, не что сломано>

Type: task
Status: open
Blocked by: —
Source: [spec.md](../spec.md), раздел «<тема>», находка <линза>-<N>; [ADR-NNNN](../../../<adr_dir>/NNNN-….md)

## Что делаем
<дефект с file:line на коммите аудита; что станет вместо него; границы правки>

## Готово, когда
- [ ] <проверяемое условие из acceptance>

## Тесты
- `<путь к файлу тестов>` — критерии 1, 2 (новый | дополнить)

## Где в коде
- `<путь>` — <что там>
```

`Type` — из словаря репозитория: `task | research | grilling`; тикет-решение — `Type: grilling` с
`## Question` и `## Решение владельца` вместо «Что делаем» (образец — любой такой тикет проекта:
`grep -l '^Type: grilling' "$(~/.claude/bin/profile --field tickets.root)"*/issues/*.md | head -1`). `Blocked by` — `—` либо номера этого эпика
через запятую (`01, 03`); иное `epic-status` считает неразобранным.

Размер — один PR: один модуль, один тест-файл, до пяти путей в «Где в коде». Находка на два модуля
режется на два тикета с `Blocked by`. Миграция — не больше одной на тикет (если у проекта есть
миграции: `F numbering.migrations` не `null`).

Перед коммитом один агент перечитывает каждый `file:line` из `issues/` (в брифе — дерево аудита) и
возвращает расхождения; расхождения правятся. Затем:

```bash
cd <путь worktree аудита>
F() { ~/.claude/bin/profile --field "$1"; }
T=$(F tickets.root); A=$(git branch --show-current)          # ветка worktree = имя эпика аудита
~/.claude/bin/epic-status --json | jq --arg a "$A" '.tickets[]|select(.epic==$a and .blockedParsed==false)'  # пусто
~/.claude/bin/epic-status "$A"                    # «/to-tickets · audit-… 0/N · тикет 01 — …»
git add "$T$A" && git commit -m "docs: аудит $A — N тикетов" && gh pr create --fill   # мерж — руками
```

Как CI обходится с PR, где только файлы тикетов, — в `rules.md` профиля, если там это сказано.

## 5. Волны, отчёт, статус

Волна — тикеты, которые можно вести параллельно: без `Blocked by` на ещё не выкаченные и без общих
путей в «Где в коде». Два тикета с общим файлом — либо в разные волны, либо в один тикет. Тикет с
миграцией — один на волну: номер миграции делят все сессии. Таблица — в `spec.md`, раздел «Волны»,
строка на тикет; столбцы `| Тикет | Файлы из «Где в коде» | Миграция (да/нет) | Волна |` — контракт
для скилла `epic-wave`; тикет по одному ведёт скилл из `F workflow.ticket_skill`. У проекта без
миграций столбец «Миграция» везде «нет».

HTML-отчёт на одну страницу — через Artifact, последним и только когда его прочтёт человек (по
расписанию пропускается): темы, под каждой находки со ссылкой на тикет, вердиктом и severity;
таблица ложных; список непроверенного.

Ответ заканчивается блоком из четырёх строк:

    — Этап: <строка epic-status $A>
    — Сейчас: <N находок, M снято проверкой, K дублей, T тикетов, PR #…>
    — Дальше: мерж PR и первая волна
    — Жду: <решения из map.md, или «ничего»>

Границы: PR мержит человек; статусы чужих тикетов через `ticket`, старые тикеты, `spec.md` и `map.md`
других эпиков остаются нетронутыми.
