# Аудит кодовой базы: от чтения до тикетов

Результат — эпик `.scratch/audit-<дата>/`: находки с адресом `file:line` и доказательством, тикеты
размером в один PR, разбивка на волны. Правило скилла — **находка остаётся заявлением, пока её не
воспроизвёл второй агент**: тикет, написанный по одной прочитанной строке, врёт примерно в трети
утверждений (разбор `.scratch/ui-triage/triage-27-41.md`, ревизия на 67 тикетов).

Аргументы: `--lenses a,c,i` сужает набор линз (по умолчанию все девять), `--live` включает проход
по стенду. Запуск по расписанию идёт без вопросов: спорное уходит в `map.md`.

## 0. Ориентировка

```bash
A=audit-$(date +%F); { git show-ref -q "refs/heads/$A" || [ -d ".scratch/$A" ]; } && A=$A-2   # эпик = ветка = worktree; повтор в тот же день — суффикс -2, -3, …
git fetch origin --prune && git log --oneline -1 origin/main   # коммит аудита — в шапку spec.md
git worktree add "../$A" -b "$A" origin/main && cd "../$A"
~/.claude/bin/epic-status; ls -d .scratch/audit-*/ | sort | tail -1   # все эпики; прошлый аудит
```

Один вызов `qmd` (скилл `qmd`), `collections: ["tickets", "memory"]`, `intent` «уроки прошлых
аудитов»: `vec` «прошлые аудиты кода и ложные находки», `lex` `аудит находк ложн`. Оплаченный урок
меняет брифы до отправки.

Из `spec.md` прошлого аудита выписать находки по линзам с путём тикета и его `state` из
`epic-status --json`; список уходит в бриф линзы, агент по каждой отвечает `fixed | still | regressed`.
Каждый `regressed` любой severity идёт в фазу 2 вместе с HIGH; подтверждённый — новый тикет с
`Source:` на старый. `still` при открытом тикете — напоминание в `spec.md`. У первого аудита список пуст.

## 1. Линзы — параллельные агенты, только чтение

Линза — одна тема проверки со своим агентом `auction-scout` (только чтение, ответ до 30 строк
с `путь:строка`); все линзы уходят одним сообщением.

| Линза | Где смотреть | Что считается находкой |
| --- | --- | --- |
| a — архитектура, границы модулей | `apps/api/src`, `apps/web/src`, `packages/shared` | импорт внутренностей чужого модуля мимо его входа; доменное правило в контроллере или компоненте; одно правило в двух местах |
| b — данные и миграции | `apps/api/drizzle`, `drizzle/meta/_journal.json`, `apps/api/src/database`, `apps/web/e2e/dev-doors.ts`, `apps/web/e2e/actors.ts` | `when` в журнале не возрастает; колонка в `schema.ts` без миграции или наоборот; e2e читает таблицу или колонку, которой в схеме нет; `$onUpdate` с SQL-выражением |
| c — авторизация и модерация | `*.controller.ts`, guards, `apps/api/src/moderation` | ручка без проверки роли или владельца; действие модератора без записи в журнал; смена статуса в обход правил перехода |
| d — i18n и тексты | `apps/web/src/i18n`, словари, `apps/web/src/app` | ключ есть в `uk` и нет в `ru` или наоборот; русская форма в украинском блоке; код протокола в тексте для человека; отказ без названного предела |
| e — доступность | `apps/web/src/components`, `apps/web/src/app` | интерактив без имени для экранного диктора; фокус не виден; зона нажатия меньше 44 px; пустой `alt` у содержательной картинки |
| f — производительность и стабильность раскладки | `apps/web/src/app`, `apps/web/src/lib` | картинка без размеров; запрос в цикле или водопад запросов; клиентский компонент там, где хватает серверного; список без устойчивых ключей |
| g — ошибки, outbox, наблюдаемость | `apps/api/src/outbox/events`, `apps/api/src/http`, `instrument.ts` | обработчик глотает ошибку; повтор без идемпотентности; `catch` без записи; лог без идентификатора сущности |
| h — тесты против спецификаций | `.scratch/*/spec.md`, `.scratch/*/issues`, `apps/api/test`, `apps/web/src/**/*.test.ts(x)`, `apps/web/e2e` | критерий «Готово, когда» закрытого тикета без теста; spec-файл, названный в тикете, отсутствует |
| i — деньги | `apps/api/src/wallet`, `apps/api/src/deals`, ADR-0022, ADR-0023 | сумма не в UAH; проводка мимо `WalletService`; обход комиссии или блица; расхождение с ADR-0022/0023 |

Бриф каждой линзы — дословно:

> Линза `<буква>`: `<строка таблицы>`. Коммит `<hash>`.
> Старые находки линзы: `<список>` — по каждой ответить `fixed | still | regressed` с `file:line`.
> По одной находке на строку, JSON без переносов:
> `{"lens","severity":"HIGH|MED|LOW","file","line","evidence_command","claim","suggested_fix","acceptance"}`.
> `evidence_command` — команда, показывающая дефект (`sed -n`, `grep -n`, `pnpm …`); `acceptance` —
> проверяемое условие «готово, когда». Утверждение без `file:line` или вывода команды в отчёт не
> попадает. Пусто — так и написать: «ничего не нашёл». Больше 30 находок — оставить старшие по
> severity и добавить строку `dropped: N`.

**Проход по стенду** (`--live`) ведёт главная сессия, не линза: стек поднят (`docker compose ps`
показывает базу, `lsof -iTCP:3000 -sTCP:LISTEN` — слушателя), сервер запускает только `preview_start`,
страницы читаются `read_page` и снимками экрана. Снимок — не замер: производительность на
dev-сервере в отчёт не идёт; непроверенное перечислить поимённо.

## 2. Перекрёстная проверка

Каждая HIGH-находка и каждый `regressed` получают агента `auction-reviewer` с брифом опровергнуть:
выполнить `evidence_command`, перечитать `file:line` ±20 строк, найти проверку выше по вызову.
Группировка по линзе, до 8 находок на агента; автор линзы своё не проверяет. Ответ — строка на
находку `confirmed | not-reproduced | moved <file:line>` с причиной и строка «что запускал, код
выхода». `not-reproduced` выбывает; `moved` — подтверждена по новому адресу.

Итог фазы — таблица в `spec.md`, она же сводка качества линз:
`| Линза | проверено | подтверждено | снято | доля ложных |`. Линза с долей ложных выше трети
получает пометку в брифе следующего аудита. Остальные MED и LOW попадают в тикеты только после
перечитывания `file:line` в фазе 4.

## 3. Дедупликация

Источники (GitHub Issues в проекте не используются): MCP-сервер `qmd` — коллекции `tickets`
(`.scratch/**` на `origin/main`) и `auction` (ADR, HANDOFF, CONTEXT); живые ветки — на `main` меньше
половины тикетов, открытые тикеты веток с коммитами за 14 дней собирает обход ниже (как `epic-board`, но без HTML):

```bash
git for-each-ref refs/remotes/origin --format='%(refname:short) %(committerdate:unix)' \
  | awk -v t="$(date -v-14d +%s)" '$2>t{print $1}' \
  | while read -r b; do ~/.claude/bin/epic-status --json --ref "$b"; done \
  | jq -c '.tickets[]|select(.state!="done")|[.ref,.epic,.num,.slug,.title]' > "$TMPDIR/live-tickets.jsonl"
```

Агент на линзу — `general-purpose`: у `auction-scout` нет MCP-инструментов, а правила qmd написаны
под MCP-форму (`searches`, `collections`, `intent`, `minScore`). Находки HIGH и MED; на каждую один
вызов `query`, `collections: ["tickets", "auction"]`, `intent` — тема линзы, два подзапроса: `lex` из
2–4 основ плюс идентификатор (`legal_lock`, имя файла без пути), `vec` — `claim` своими словами.
Попадание с баллом ≥ 0.6 читается через `get` до вердикта. По `live-tickets.jsonl` — `grep` по файлу
и словам дефекта, тело тикета — `git show <ref>:.scratch/<эпик>/issues/NN-<slug>.md`. Вердикты:

- **дубль** — тикет в `state` `open | work | blocked`, чьё тело называет тот же файл и тот же
  дефект. В `spec.md` строкой «уже в работе: `<эпик>/<NN>`», тикета нет.
- **регрессия** — тикет `done`, дефект подтверждён в фазе 2. Новый тикет, `Source:` на старый.
- **решено** — ADR принял решение против `suggested_fix`, и его посылка жива. В `map.md` под
  «решение принято», без тикета. Посылка ушла — тикет `Type: grilling` на новый ADR: старый
  неизменен, пересмотр пишется новым номером.
- **новое** — попаданий ≥ 0.6 нет либо все прочитанные о другом.

Ответ агента — таблица `находка | вердикт | путь или ADR`, без пересказа документов.

## 4. Тикеты

Эпик `.scratch/$A/` — три вещи:

- `spec.md`: `Status: ready-for-agent`, коммит аудита, линзы; по темам — находки с `file:line`,
  `evidence_command` и вердиктом фазы 2; таблица ложных; таблица дедупликации; список
  непроверенного из прохода по стенду.
- `map.md`: у каждой находки адрес — **очередь исправлений** (тикет здесь), **решение** (моё —
  тикет `Type: grilling`; заказчика — вопрос в пакет), **правка доков** (тикет `Type: task`),
  **будущая фаза** (указатель в `.scratch/roadmap`). Карта закрыта, когда без адреса не осталось
  ни одной находки.
- `issues/NN-<slug>.md`, нумерация с `01` в порядке волн, шаблон дословно:

```markdown
# NN — <Заголовок: что меняется, не что сломано>

Type: task
Status: open
Blocked by: —
Source: [spec.md](../spec.md), раздел «<тема>», находка <линза>-<N>; [ADR-NNNN](../../../docs/adr/NNNN-….md)

## Что делаем
<дефект с file:line на коммите аудита; что станет вместо него; границы правки>

## Готово, когда
- [ ] <проверяемое условие из acceptance>

## Тесты
- `apps/api/test/<имя>.spec.ts` — критерии 1, 2 (новый | дополнить)

## Где в коде
- `<путь>` — <что там>
```

`Type` — из словаря репозитория: `task | research | grilling`; тикет-решение — `Type: grilling` с `## Question`
и `## Решение владельца` вместо «Что делаем» (образец — `.scratch/catalog-violity/issues/04-…`). `Blocked by` —
`—` либо номера этого эпика через запятую (`01, 03`); иное `epic-status` считает неразобранным.

Размер — один PR: один модуль, один тест-файл, до пяти путей в «Где в коде». Находка на два модуля
режется на два тикета с `Blocked by`. Миграция — не больше одной на тикет.

Перед коммитом один агент перечитывает каждый `file:line` из `issues/` и возвращает расхождения;
расхождения правятся. Затем:

```bash
~/.claude/bin/epic-status --json | jq --arg a "$A" '.tickets[]|select(.epic==$a and .blockedParsed==false)'  # пусто
~/.claude/bin/epic-status "$A"                    # «/to-tickets · audit-… 0/N · тикет 01 — …»
git add ".scratch/$A" && git commit -m "docs: аудит $A — N тикетов" && gh pr create --fill   # только .scratch/: джоба changes тяжёлых проверок не запустит; мерж — руками
```

## 5. Волны, отчёт, статус

Волна — тикеты, которые можно вести параллельно: без `Blocked by` на ещё не выкаченные и без общих
путей в «Где в коде». Два тикета с общим файлом — либо в разные волны, либо в один тикет. Тикет с
миграцией — один на волну: номер миграции делят все сессии. Таблица — в `spec.md`, раздел «Волны»,
строка на тикет; столбцы `| Тикет | Файлы из «Где в коде» | Миграция (да/нет) | Волна |` — контракт
для будущего скилла `epic-wave` (пока волну ведёт `ship-ticket` по одному тикету).

HTML-отчёт на одну страницу — через Artifact, последним и только когда его прочтёт человек (по
расписанию пропускается): темы, под каждой находки со ссылкой на тикет, вердиктом и severity;
таблица ложных; список непроверенного.

Ответ заканчивается блоком из четырёх строк:

    — Этап: <строка epic-status $A>
    — Сейчас: <N находок, M снято проверкой, K дублей, T тикетов, PR #…>
    — Дальше: мерж PR и первая волна
    — Жду: <решения из map.md, или «ничего»>

Границы: PR мержит человек; статусы чужих тикетов через `ticket`, старые тикеты, `spec.md` и `map.md`
других эпиков остаются нетронутыми.
