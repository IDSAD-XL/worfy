# Провести тикет от взятия до зелёного прода

Цикл ниже — один тикет. Волна — это тот же цикл на каждый тикет, но номера ADR и
миграций занимаются заранее и по одному, иначе вторая вливающаяся ветка встанет.

## 1. Взять

```bash
~/.claude/bin/epic-status <эпик>          # что уже сделано, что свободно
~/.claude/bin/ticket claim <эпик> <NN>    # пишет Status в том написании, что уже в файле
```

Прочитать сам тикет и `spec.md` рядом. Если решение в нём не заперто — сначала ADR,
код после; иначе переделка гарантирована.

Один вызов `qmd` по теме тикета (MCP-сервер `qmd`, скилл `qmd`: ADR, уроки в HANDOFF,
закрытые тикеты, память) — до плана, не после. Принятое решение или уже оплаченный
урок меняют план, пока он ещё не написан.

## 2. Свежий `origin/main`, своё дерево и свободные номера

```bash
~/.claude/bin/preflight --epic <эпик>; echo "КОД=$?"
```

Одна команда вместо шагов в тексте: `git fetch`, отставание локального `main`,
`worktree-lock status`, дубли и старший номер ADR на `origin/main`, во всех ветках
`origin/*` и в локальных, последняя миграция там же, открытые PR, активный аккаунт gh
против владельца remote, строка `epic-status`. Последняя строка вывода — `GO` или
`BLOCKED: <причины>`, код 1 при BLOCKED. Причина «чужая живая сессия в дереве» значит,
что команда запущена из общего checkout: уйти в свой worktree (следующий абзац) и
повторить. Остальные причины — стоп, не обходить. Строку `origin/main: <sha> …`
вставлять в бриф каждому агенту как базу — субагент, читавший локальный `main`, однажды
рассуждал по устаревшему дереву.

`main` двигается каждые 15–30 минут. Работать из собственного worktree с первой
минуты: дерево общее с другими сессиями, побеждает последняя запись.

## 3. Занять номера до содержания

Следующий свободный номер ADR печатает `preflight` (строка `ADR:`), а строка
`migrations:` показывает последнюю миграцию на `origin/main`, в ветках и локально и
предупреждает, когда локальный `pnpm db:generate` выдаст уже занятый номер. Считает он по
всем веткам `origin/*` и локальным, а не по одному каталогу.
Номер занимается заглушкой сразу, содержание пишется потом: так 0039 разъехался в
0059, когда две сессии взяли один номер. Миграции — только `pnpm db:generate`;
порядок держит `when` в `apps/api/drizzle/meta/_journal.json`, не имя файла, и при
слиянии двух зелёных веток младшая по `when` молча не применится — лечение одно,
перегенерировать поверх свежего `main`.

## 4. Падающий тест первым

```bash
pnpm --filter @auction/api exec vitest run test/<файл>.spec.ts
```

`pnpm test -- <файл>` не фильтрует: аргумент до vitest не доходит, гонится весь
набор. Формулировка с `--` встречается в самих тикетах — это ошибка, не образец.
Тестам нужен поднятый Docker: Postgres поднимается через Testcontainers.

## 5. Реализация

По «Следу по файлам» из тикета. Выход за след — повод сказать об этом, а не молча
расширить правку.

## 6. Проверки — голыми, с кодом возврата

```bash
pnpm typecheck && pnpm lint && pnpm test; echo "КОД=$?"
```

Фильтровать длинный вывод нужно, терять код возврата нельзя:
`set -o pipefail; pnpm test | tail -n 30`. Хук `guard.mjs` откажет в трубе без
`pipefail` — это не придирка, так падающий линтер однажды был объявлен чистым.
Контракт в `pnpm test` не входит: `pnpm --filter @auction/api test:contract`.
Итог подводит гейт: `bash ~/.claude/hooks/gate.sh fast </dev/null` — обязательно с закрытым
stdin: скрипт написан под хук и первым делом вычерпывает stdin через `cat`, а без stdin
висит вечно (так тикет 63 простоял десять часов).

## 7. Ревью-агенты на диффе

Сначала WIP-коммит: detached-дерево ревьюера берёт только закоммиченное, незакоммиченную
правку он не увидит и отревьюит старый код.
Затем каждому ревьюеру — своё дерево; создаёт его оркестратор до запуска, путь идёт в бриф:

```bash
W=/Users/alexey/Work/Auction/.claude/worktrees/review-<линза>-<NN>
git worktree add "$W" --detach <ветка> && (cd "$W" && pnpm install --frozen-lockfile --prefer-offline && pnpm --filter @auction/shared build)
git worktree remove "$W"     # после вердикта; отказ «dirty» значит, что ревьюер оставил правки — смотреть, не --force
```

Два-три параллельно, по одной линзе каждому (корректность, границы модулей,
покрытие тестами). Параллельные ревьюеры не делят одно дерево: 16 сентября два ревьюера
шли в одном, один гонял мутантов, второй принял мутанта за нестабильный тест. Мутации —
только в своём дереве или на копиях в scratchpad, восстанавливать из копии, не через
`git checkout`. Контракт: только находки, `file:line`, явное «ничего не нашёл».
Каждую ссылку `file:line` перечитать самому — субагенты цитировали строки, которых
на месте не было.

## 8. PR и зелёный CI

```bash
gh pr create --fill
gh pr checks <N>                    # отдельной командой, без пайпа
gh pr view <N> --json mergeStateStatus
```

При конфликте с `main` чеки не краснеют, а **исчезают** («no checks reported») —
поэтому смотреть `mergeStateStatus`, а не только список чеков. Тикет, добавивший
или снявший обработчик outbox, обязан поправить их число в `verify-deploy`, иначе
CI покраснеет уже на `main`, после выката.

## 9. Мерж — отдельным шагом, по зелёному

```bash
gh pr merge <N> --squash
```

Статус и мерж никогда не сливаются в одну команду: пайп съедает код возврата.

## 10. Проверить прод

Дождаться, пока `/version` отдаст свежий commit, и повторить дымовые проверки из
джобы `verify-deploy` (`.github/workflows/ci.yml`) — адреса и ожидаемые ответы там.
Стенд закрыт basic-auth целиком. Без ответа живого адреса выкат не считается
проверенным.

## 11. Закрыть

```bash
~/.claude/bin/ticket done <эпик> <NN> --pr <N>
```

`HANDOFF.md` — единственный файл состояния, снимок, а не журнал (ADR-0085): на границе
фазы он **переписывается**, а не дописывается. Каждый пункт либо ещё верен (обновить),
либо переезжает на своё место — урок в `docs/lessons/<тема>.md`, рассказ о сделанном в
описание PR и тикет, ответ владельца в ADR или тикет, — либо удаляется. Раздела про тикет
в HANDOFF не заводить: форму проверяет `node scripts/check-handoff.mjs` (200 строк,
фиксированные разделы, без `###`), он же стоит в CI. ADR не трогать: они неизменны.

## Когда останавливаться

Спорное решение в спецификации, конфликт, который не разводится механически, и
красный CI, не починившийся с двух попыток, — это остановка с вопросом, а не
догадка. Непроверенное называть непроверенным.
