## Риски и долги

- CI не запускается на PR, который конфликтует с main: GitHub не создаёт прогон `pull_request` при `mergeStateStatus: DIRTY`. Коммит статусов волны в main меняет файлы тикетов, и все открытые PR волны становятся DIRTY; в волне 2 так остались без CI коммиты круга исправления 32, 02 и 03. Перед ожиданием CI нужен rebase на main.
- Agent SDK из packaged `.app` — решено: окружение Claude Code берётся из `$SHELL -ilc`, запущенного из минимального окружения (ADR-0007); бинарник — нативный, из пакета SDK, по явному пути в `app.asar.unpacked` (ADR-0008); вход проверяется через `accountInfo()` (ADR-0009). Реализует тикет 07, он же добавляет `asarUnpack` для SDK в `electron-builder.yml`.
- Размер контекста от MCP-серверов пользователя (тикет 06). С `settingSources` пользователя приходят 634 tools. На haiku второй ход падает с «Prompt is too long» (~236 657 токенов при лимите 200 000). Первый ход на sonnet — ~507 тыс. токенов, $2.03. `ENABLE_TOOL_SEARCH=true` на haiku не помогает. Решать тикету 07 по замеру на модели по умолчанию (`opus[1m]`); этот замер не сделан.
- Stop hook пользователя при красном gate продолжает ход сессии — тикет 06 подтвердил: три продолжения подряд. Учесть в тикете 07.
- Effort не проверен (тикет 06): применился ли `applyFlagSettings({effortLevel:'low'})`, и несут ли уровень поле `effort.level` во входе hooks и переменная `CLAUDE_EFFORT`. Известно только из `sdk.d.ts`. Касается тикета 07.
- Источник лимитов: `rate_limit_event` приходит один раз за Сессию, перед первым запросом, и `utilization` в нём есть не всегда; поле `rate_limits` статус-строки не проверено (тикет 22).
- Долг тикета 03 (граница модулей): удаление временного каталога с повторами (`maxRetries`) заведено только в `test/e2e/window.spec.ts:9`. Общая очистка `cleanDirs` в `test/e2e/helpers.ts:45-47` (на main после мержа 32), через которую идут остальные e2e test-ы, осталась без повторов.
- Возможный flaky test: в круге исправления 03 первый полный `pnpm test:e2e` после сборки упал на `test/e2e/launch.spec.ts:5` — первый запуск приложения не уложился в 60 с, затем «Worker teardown timeout». Два следующих полных прогона — 12 из 12 зелёные. Причину не искали.
- Тикет 03: `test/unit/shell-discovery.test.tsx` пишет временные файлы в `src/renderer/shell/{sidebar,toolbar}`. При параллельном запуске с lint, typecheck или сборкой они могут попасть в их вход. Если vitest убит посреди test-а, файл `ZzVitestProbe*` остаётся до следующего прогона.
- `postinstall` (тикет 32) компилирует `node-pty` из C++ через `@electron/rebuild`: на новой машине нужны Xcode Command Line Tools и Python, иначе `pnpm install` упадёт.
- Gate по умолчанию (`fast` с сужением по диффу) не видит `scripts/` и `test/fixtures/`: на тикете 09 он ответил «ничего не прогналось», зелёный вердикт дал только `GATE_SCOPE=all`. Правка — в `~/.claude/gate/config.json` или в самом gate.
- Запись gate в `~/.claude/gate/config.json` живёт вне репозитория. Скрипт `test:package` (тикет 32) в gate не попал, его проверяет только CI; новые скрипты проверки нужно вписывать туда вручную.
- Путь сбоя запуска в `src/main/index.ts` (`.catch` → `showErrorBox` → `app.exit(1)`, PR #3) без автоматического test-а: файл импортирует electron и в vitest не грузится, а e2e test встанет на модальном окне.
- React Flow (тикет 05) и xterm.js (тикет 27) внутри вида, скрытого через `display:none` (тикет 03), не проверены: при показе может понадобиться пересчёт размеров.
- Транскрипты (тикет 09): кириллица в cwd и пути длиннее 200 символов в данных не встречались, правило имени папки взято из кода Agent SDK.
- Fixtures `test/fixtures/sdk-messages/`: в пяти перечищенных файлах номер сервера в именах MCP tools (`server-4`) не связан с номерами в `mcp_servers`, исходные имена потеряны раньше. Сказано в README этой папки.
- pnpm 11 не читает поле `pnpm` в `package.json`. Список пакетов, которым разрешены install-скрипты, — настройка `allowBuilds` в `pnpm-workspace.yaml`. Новая зависимость со скриптом, которой нет в списке, роняет `pnpm install` (`ERR_PNPM_IGNORED_BUILDS`) — её нужно явно добавить туда. `node-pty` в списке уже есть.
- Electron 44 скачивает свой бинарник при первом запуске, а не в `pnpm install`: в CI загрузка идёт в шаге `pnpm test`, без сети unit test-ы под Electron не стартуют.
- Hook инструмента Edit не даёт писать в worktree другого тикета из исходного worktree сессии. Агент тикета 02 переключил сессию в `.claude/worktrees/02` через EnterWorktree; hook не отключали.
- Версии ниже последних из-за совместимости: `vite` 7 (electron-vite 5 не поддерживает vite 8), `typescript` 6.0 (typescript-eslint 8.71 требует `<6.1`). Обновлять вместе.
