## Что происходит

Владелец: нужна возможность вставлять картинки на Canvas. Карточку с картинкой можно растягивать как
угодно — и по ширине, и по высоте, независимо, — но сама картинка внутри не растягивается: пропорции
сохраняются, картинка вписывается в карточку, как `object-fit: contain`.

Сейчас картинку на Canvas положить нельзя. Типа Node-а для картинки нет. Canvas не обрабатывает ни
⌘V / Ctrl+V, ни перетаскивание файлов: вставка из буфера есть только у Terminal-а
(`src/renderer/canvas/nodes/TerminalNode.tsx`, `terminal-user-input.ts`) и у поля сообщения Session
(`src/renderer/session/MessageInput.tsx:262-286`, `onPaste` и `onDrop`).

## Что сделать

Решения с причинами. Где написано «решение» — это выбор по умолчанию; владелец может выбрать иначе.

1. **Как картинка попадает на Canvas.**
   - ⌘V / Ctrl+V на Canvas: картинка из буфера встаёт под курсором, а если курсор вне Canvas — в
     центре видимой области (viewport). Вставка срабатывает, только когда фокус на самом Canvas: в
     поле ввода, в Terminal-е, в поле сообщения Session и в Browser-е ⌘V работает как сейчас.
   - Перетаскивание файлов картинок на Canvas: Node встаёт там, где отпустили. Несколько файлов —
     несколько Node-ов, каждый следующий сдвинут вправо-вниз, чтобы они не легли друг на друга.
   - Форматы: png, jpeg, gif, webp. Формат проверяется по первым байтам файла, не по расширению
     (как `imageTypeOf` в `src/main/agent/attachments.ts:46`).
   - **Решение: svg отклоняется.** svg — это XML, и в нём может быть script; показывать его безопасно
     можно только как `<img>` без scripts, и это отдельная проверка. Отклонить проще и безопасно.
     Пользователь видит понятное сообщение (toast), что svg не поддерживается.
   - Пункта «New image» в меню нет (у Node-а нет `createLabel`): картинка приходит только вставкой
     или перетаскиванием.

2. **Тип Node-а `image`.** Новый файл `src/renderer/canvas/nodes/ImageNode.tsx`. Реестр типов
   находит его сам: `import.meta.glob('./*Node.tsx')` в `src/renderer/canvas/nodes/index.ts:109`.
   Файл экспортирует `kind`, `defaultWidth`, `defaultHeight`, `minimapColor`, как
   `NoteNode.tsx:10-13`.
   - Начальный размер — по естественному размеру картинки, уменьшенный так, чтобы длинная сторона
     была не больше 480 px; пропорции сохраняются. Маленькая картинка не увеличивается.
   - Размер меняется рамкой `NodeResizeClamp` и операцией `resize`, как в `NoteNode.tsx:69-73`.
     Ширина и высота меняются независимо: рамка не держит пропорции.
   - Внутри карточки — `<img>` с `object-fit: contain`, по центру. При любом размере карточки
     картинка не искажается; свободное место — фон карточки.
   - Минимальный размер карточки (например, 48 × 48 px), чтобы её можно было найти и схватить.

3. **Где хранятся байты. Решение: вариант B — один файл на картинку в папке данных Project-а.**
   **Подтверждено владельцем 2026-10-25:** картинки хранятся только на этой машине, в данных
   приложения (`<Project data folder>/images/<id>.<ext>`), и никогда — в репозитории Project-а
   (ADR-0005).
   Путь: `<Project data folder>/images/<id>.<ext>` (Project data folder — папка Project-а внутри
   данных приложения, не в репозитории). В Layout (файл раскладки Canvas) у Node-а только
   `data: { file, width, height, mime }`: имя файла, естественный размер и тип.
   Почему так:
   - не в папке Project-а: ADR-0005 (`docs/adr/0005-worfy-own-state-inventory.md`, worfy не оставляет
     следов в репозиториях пользователя);
   - не data URL внутри Layout: main переписывает весь Layout после каждого изменения, не реже чем
     через секунду (`LAYOUT_SAVE_MAX_DELAY_MS` в `src/main/layout/store.ts:72`), и каждый ответ IPC с
     Layout-ом нёс бы мегабайты.
   - Предел — 20 MB на картинку, как у вложений сообщения (`FILE_COPY_LIMIT_BYTES`,
     `src/shared/agent/attachments.ts:30`). Больше — toast с понятной причиной, Node не создаётся.
   - Байты идут renderer → main через новый канал IPC. Preload остаётся без знания каналов
     (ADR-0006, контракт IPC через declaration merging). Образец — вложения сообщения:
     `MessageInput.tsx:262-286` (`onPaste`, `onDrop`) и `attachBytes` в
     `src/main/agent/attachments.ts:114`. Main сам проверяет размер, формат и строит путь; имя
     файла — новый id, а не имя от пользователя.

4. **Как картинка показывается.** Свой protocol, например `worfy-image://<project>/<id>`, по образцу
   `worfy-card` (`registerCardScheme` и `installCardRuntime` в
   `src/main/cards/protocol.ts:383-391`, регистрация в `src/main/index.ts:113`). Handler проверяет,
   что путь остаётся внутри `<Project data folder>/images/`, и отдаёт только файлы с id из шаблона.
   CSP renderer-а (`src/renderer/index.html:5`) не задаёт `img-src`, поэтому для картинок действует
   `default-src 'self'` и `data:`, `blob:` и свои схемы закрыты. В `img-src` добавляется `'self'` и
   только новая схема. Та же схема нужна ticket-у worfy-ui 28 (превью картинок в отправленном
   сообщении чата): одна схема с двумя корнями — картинки Canvas и `<data>/attachments/images/`.
   Кто из двух ticket-ов вливается первым, тот вводит схему и `img-src`; второй добавляет свой корень.

5. **Удаление и undo.** `image` добавляется в `TRASHABLE_KINDS` (`src/shared/ipc/trash.ts:22`). При
   удалении Node-а файл картинки уезжает в корзину (trash) вместе с ним, как папка Card
   (`src/main/layout/trash.ts:1-12`); undo возвращает и Node, и файл; через `TRASH_KEEP_MS` (3 дня)
   `purge()` удаляет запись. Файл уезжает, только если его не показывает другой Node: копирования
   Node-ов на Canvas сегодня нет, но правило то же, что у Card. Файлов без Node-а не остаётся.

6. **Другие списки kind-ов.** Решение по каждому:
   - `KIND_LABELS` в `src/renderer/find/search-index.ts:94` (имя типа для людей в поиске) —
     добавить `image: 'Image'`: у Node-а картинки нет своего заголовка.
   - `SOURCE_NODE_KINDS` в `src/shared/layout/derived.ts:57` (типы, которые рисует только источник
     Node-ов) — не добавлять: картинка — обычный Node Layout-а.
   - `src/main/link/notes.ts:38` — это тип сообщения link-а (уведомление Session на другую машину),
     а не kind Node-а; не трогать.

## Вне скоупа

- Tool MCP `create_image` для агентов — не сейчас.
- Картинка на Linked machine (другой машине, к которой подключён Canvas) — ticket 24.
- Обрезка, поворот и замена картинки в уже созданном Node-е.

## Тесты

- unit по образцу `test/unit/note-node.test.tsx`: `object-fit: contain` и центр при крайних
  пропорциях (карточка 1000 × 50 и 50 × 1000); начальный размер — большая картинка уменьшена до 480 px
  по длинной стороне с теми же пропорциями, маленькая не увеличена; минимальный размер.

  первым байтам, проверка пути в protocol handler-е (`..`, чужой Project, чужой id — отказ), корзина:
  удаление переносит файл, undo возвращает, purge удаляет, файл другого Node-а остаётся.
- e2e по образцу `test/e2e/canvas-layout.spec.ts:103-125`: вставить картинку, растянуть карточку в
  очень широкую и в очень высокую, по пикселям проверить, что картинка не искажена (пропорции видимой
  области картинки равны естественным); перезапуск приложения — картинка на месте; удаление и undo.

## Платформа

Вставка из буфера, перетаскивание файлов и пути к файлам ведут себя по-разному на macOS и Windows,
поэтому PR платформенный: вердикт Windows выбирает `scripts/windows-verdict-scope.mjs` (скрипт
решает по списку изменённых файлов, какой прогон на Windows нужен PR-у).

## Итог

**Как картинка попадает на Canvas.** Overlay `src/renderer/canvas/overlays/ImageDrop.tsx`: вставка
(⌘V / Ctrl+V), когда Canvas на экране и фокус на нём или ни на чём, но не в поле ввода
(`isTextTarget`: поле, textarea Terminal-а, поле сообщения), — картинка встаёт под курсором, если он
над Canvas, иначе в центре Canvas. Drop файлов — только на пустое место Canvas: drop на Node остаётся
Node-у (Session Node берёт файл вложением). Несколько файлов — каскад со сдвигом 32 px, один шаг ⌘Z
(`addImages`, `src/renderer/canvas/image-drop.ts`). На экране только для чтения — toast с причиной.

**Запись.** Канал `canvasImage.add` (`src/shared/ipc/canvas-images.ts`, `project`/`write`). Main
(`storeImage`, `src/main/layout/images.ts`): предел 20 MB, тип по первым байтам (png, jpeg, gif,
webp), svg — отдельное сообщение, натуральный размер — из заголовка картинки (PNG IHDR, GIF, JPEG SOF,
WebP VP8/VP8L/VP8X), имя файла — 32 hex от main, запись с флагом `wx`. Файл —
`<Project data folder>/images/<id>.<ext>`; в Layout — только `{ file, width, height, mime }`.
Renderer до чтения отклоняет файл больше 20 MB. Отказы — toast `image-refused`.

**Node `image`.** `src/renderer/canvas/nodes/ImageNode.tsx`: `<img>` 100 % × 100 %, `object-fit:
contain`, по центру; рамка `NodeResizeClamp` без сохранения пропорций, минимум 48 × 48. Начальный
размер — естественный, длинная сторона не больше 480 px, без увеличения (`initialImageSize`).
Заголовка у Node-а нет (исключение в `test/unit/canvas-zoom.test.tsx`). Картинка, которая не
загрузилась, — плашка «Image not available».

**Показ.** Схема `worfy-image://` из worfy-ui 28 (#835): хранилище `canvas.<project label>` →
`<Project data folder>/images/`, имена `IMAGE_FILE_PATTERN`, лимит 20 MB (`canvasImageStore`, одна
ветка locator-а в `src/main/index.ts`). Адрес строит `canvasImageUrl` (`src/shared/images.ts`);
project label считается в renderer-е так же, как `projectIdHash` в main (сверяет contract test). Окно
на Linked machine строит адрес с её machine label, main отвечает 404, Node показывает плашку; чтение
через link — ticket 24.

**Корзина.** `image` — в `TRASHABLE_KINDS`. Удаление переносит файл в запись корзины, restore
возвращает Node и файл, purge удаляет; файл, который показывает другой Node, остаётся. ⌘Z вставки
убирает Node, а файл оставляет для ⇧⌘Z; такие файлы удаляет проверка при старте (`sweepImages`):
только файлы старше 10 минут без Node-а и только если `layout.json` есть, разбирается и ни разу не
откладывался как unreadable — пустой Layout из битого файла не стоит пользователю всех картинок.

**Известное ограничение.** Размер JPEG не учитывает EXIF orientation (`shortcut:` в
`src/main/layout/images.ts`): снятое боком фото начнёт с переставленными сторонами, но картинка не
искажается.

**Тесты.** unit `test/unit/image-node.test.tsx`, `test/unit/image-src.test.ts`; contract
`test/contract/canvas-images.test.ts` (запись, предел, svg и не-картинки, корзина, проверка при
старте), `test/contract/canvas-image-protocol.test.ts` (`..`, чужой Project, чужой id, имя вне
шаблона, svg, больше лимита, Linked machine → 404); e2e `test/e2e/canvas-image.spec.ts` (вставка,
очень широкая и очень высокая карточка — пропорции видимой картинки по пикселям, перезапуск, Delete и
⌘Z с файлом, вставка в поле заметки остаётся полю, drop двух файлов, отказ svg и 20 MB). Mutation
testing: 33 + 12 мутантов новых строк убиты; e2e-мутант `object-fit: fill` падает на проверке
пикселей.
