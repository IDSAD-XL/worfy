## Что происходит

- **Уроки** лежат в `docs/lessons/` по темам (`README.md`: `process.md`, `agents.md`,
  `ci-merge.md`, `testing.md`). README говорит, когда писать урок, но не связывает урок с test-ом:
  урок может описать сбой, который потом ничем не проверяется.
- **Skill `retro`** Harness (`harness/skills/retro/SKILL.md`) записывает урок туда, куда указывает
  поле Profile `lessons` (у worfy — `repo:docs/lessons`). Он не классифицирует причину сбоя.
- **Eval-кейсы Harness** — Ticket-ы 27–29 Epic-а worfy-harness открыты: 27 (платная часть eval) ждёт
  28, 29 — после 27 и 28. Проверить правило prompt-а прогоном eval сейчас нельзя.
- **Причины сбоев бывают разные**, а путь у всех один — урок или правило. Примеры из Project-а:
  - временный сбой машины — `fseventsd` краснил gate full 2026-10-12 (`HANDOFF.md`, «Риски и долги»);
  - регрессия SDK поставщика — повтор вызова tool в Claude Code 2.1.296 (Ticket 01);
  - слабая fixture, нарушение ADR, дефект кода, ошибка правила Harness или prompt-а.

## Что делаем

Документ-предложение и решение владельца. Код, Harness и Profile не меняются.

1. **Классы инцидента**, у каждого — признак и куда идёт вывод:
   - временный сбой (`fseventsd`, сеть, заблокированный экран) — запись в «Риски и долги» или урок
     «как распознать», без нового правила;
   - регрессия SDK поставщика — правило версий (как в Ticket-е 01) и fixture новой версии;
   - слабая fixture — test с fixture, которая воспроизводит сбой;
   - нарушение ADR — test или проверка Gate на это ADR;
   - дефект кода — регрессионный test: красный до правки, зелёный после;
   - правило Harness или prompt-а — eval-кейс (когда 27–29 закрыты) или правка `harness/` через PR.
2. **Шаги процесса:** сбой → запись инцидента со ссылками (PR, «Итог», строка журнала, коммит) →
   дедупликация по корневой причине → класс → детерминированный test (красный до, зелёный после)
   или явное «урока нет» с причиной.
3. **Что процесс не поощряет никогда:** выключить или пометить skip flaky test вместо разбора;
   перевести Ticket из `blocked` в `done` без доказательства; обойти Gate; добавить правило prompt-а
   без проверки, что оно что-то меняет.
4. **Проверка на прошлом.** Прогнать процесс вручную по 3–5 прошлым сбоям из «Итог» и
   `docs/lessons/` и показать, какой класс и какой test вышел бы у каждого.
5. **Куда встроить**, если владелец согласится: `docs/lessons/README.md`, skill `retro`, правило
   Orchestrator-а — варианты с ценой каждого. Сами правки — отдельными Ticket-ами после решения:
   Harness и Profile меняются только через PR в `harness/`.
