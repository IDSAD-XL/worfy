## Что происходит

- **Сейчас доработка ограничена** (ADR-0046, skill `epic-wave`, раздел 3): после первого `REJECTED`
  ревью — ровно один круг доработки; второй `REJECTED` выводит Ticket из Wave (`ticket block`, Status
  `blocked`). Исключение — один узкий круг по устоявшим находкам для Ticket-а на критическом пути,
  если находки не уровня high. Круг ведёт тот же агент-исполнитель с тем же контекстом.
- **Идея «Memento».** В исследовании Anthropic экземпляр агента, у которого кончилось время,
  оставляет короткую запись: что пробовал, что не вышло, какие гипотезы опровергнуты. Свежий
  экземпляр получает рабочую папку и эту запись. Выигрыш там показан в части постановок и на задаче
  развёртывания на незнакомом железе, не на написании кода. Для worfy это непроверенная гипотеза.
- **Данные уже есть, на машине владельца:**
  - журналы прогонов Autopilot — `~/Library/Application Support/worfy/autopilot/*.jsonl` (19 файлов
    на 2026-10-15; формат — шапка `src/shared/autopilot/journal.ts`, виды событий — `:146-163`, в том
    числе `narrow-round`);
  - разделы «Итог» Ticket-ов в `.scratch/*/issues/` — круги ревью, находки, причины `blocked`;
  - комментарии Gate в PR (`gh pr view <N> --comments`);
  - транскрипты Session-ов в `~/.claude/projects/` — только для уточнения, не для цитат.
- Классификации застреваний нет: неизвестно, как часто Ticket застревает и почему.

## Что делаем

Только разбор того, что уже записано. Без кода, без запусков агентов, без платных вызовов.

1. **Найти застрявшие Ticket-ы:** Status `blocked`, второй `REJECTED`, `narrow-round` с итогом
   `rejected`, ручная доработка после Autopilot. Список — номер Ticket-а, Epic, PR, ссылка на «Итог».
2. **Классифицировать каждый случай** (один или несколько классов, с доказательством-ссылкой):
   - одна и та же падающая команда повторяется;
   - колебание между двумя подходами;
   - доказательства test-ов не меняются от круга к кругу;
   - повторно отклонённая правка (та же находка ревью снова);
   - другое — назвать.
3. **Сравнить с текущим ограничением** (ADR-0046): для каждого случая — что сделал круг доработки и
   узкий круг, и помогла бы свежему агенту короткая запись попыток: SHA git, лог падения, что
   пробовали, какие гипотезы опровергнуты.
4. **Ответ «да/нет»** на вопрос: стоит ли follow-up Ticket с экспериментом «свежий агент с записью
   попыток» сверх ADR-0046. Если «да» — набросок Ticket-а: условие запуска по наблюдаемому отсутствию
   прогресса (не по таймеру), отдельный worktree, ограничение числа попыток, что сравнивать. Если
   данных мало — так и написать.

## Итог

Отчёт — [docs/research/2026-10-15-застрявшие-ticket-ы.md](../../../docs/research/2026-10-15-застрявшие-ticket-ы.md).

- **Что прочитано.** Все 22 журнала Autopilot (2026-10-06 … 2026-10-15). Разделы «Итог» всех
  `.scratch/*/issues/*.md`. Первые строки комментариев-вердиктов всех 337 PR репозитория. Транскрипты
  не открывались. Агентов и платных вызовов не было, `src/` и `harness/` не менялись.
- **Сколько застреваний.** Вердикт ревью есть у 160 PR. Первый `REJECTED` получили 56, из них 47
  закрыл один круг доработки. Второй `REJECTED` — у 9 Ticket-ов: worfy-daily 03 и 15,
  worfy-harness 14, 22, 24 и 26, worfy-link 02, worfy-terminal-ai 02, worfy-ui 06. Шесть из них шли в
  Wave Autopilot, три — в Wave Orchestrator-а. Узкий круг был в 6 PR: 4 `NARROW: VERIFIED`, 2
  `NARROW: REJECTED`. Ещё восемь Ticket-ов в `blocked` — не из-за ревью: отложены владельцем, ждут его
  решения, приёмки, ждут Windows-ПК.
- **По классам** (случай может быть в нескольких):
  - одна и та же падающая команда — 0;
  - колебание между двумя подходами — 0;
  - доказательства test-ов не меняются — 0;
  - та же находка снова — 3;
  - другое: доработка внесла новый дефект — 7;
  - другое: нужен ввод извне агента (номер ADR, решение по замыслу, разрешение на пробы) — 3.
- **Ответ: нет.** Случаев без прогресса, на которые нацелен «Memento», нет. Главный класс — новый
  дефект в самой правке, и свежий агент его не устраняет. Остальные тупики снимало решение
  владельца. Запись попыток (Act on, SHA до доработки, «Итог») уже есть. Свежий исполнитель с ней
  уже доводил застрявший Ticket до конца: worfy-ui 06, worfy-harness 22.
- **Предложение (черновик для владельца).** Follow-up Ticket по «Memento» не заводить. Вернуться к
  вопросу, если появятся три и больше случаев без прогресса: та же падающая команда или те же
  доказательства test-ов два круга подряд. Или если отчёт о критическом пути (worfy-reliability 04)
  покажет, что больше всего времени уходит между вторым `REJECTED` и решением владельца. Класс
  «доработка вносит новый дефект» — 7 случаев после урока 2026-10-06 в `docs/lessons/testing.md` —
  передать как входные данные в worfy-reliability 03 (сбой → инцидент → регрессионный test).
- **Решение владельца 2026-10-16:** ответ «нет» принят, follow-up Ticket по «Memento» не заводится.
  7 случаев «доработка вносит новый дефект» переходят в Ticket 03 как входные данные (сбой →
  инцидент → регрессионный test); там они — примеры классов для README уроков (Ticket 06).
