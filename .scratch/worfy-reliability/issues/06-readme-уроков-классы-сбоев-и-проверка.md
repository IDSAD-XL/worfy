## Что происходит

- `docs/lessons/README.md` говорит, когда писать урок, и задаёт формат: заголовок-утверждение, суть,
  путь к коду, `Источник:` (`docs/lessons/README.md:15-21`). Поля «чем это проверяется» нет; классов
  сбоя нет; где записывать инцидент — не сказано.
- Процесс принят владельцем 2026-10-16: шесть классов без изменений, инцидент — подраздел «Инцидент» в
  «Итог» Ticket-а, где случился сбой (сбой без Ticket-а — в «Итог» Ticket-а, который чинит его
  последствия), строка `Проверка:` у каждого урока.
- Входные данные из Ticket-а 02: 7 случаев «доработка вносит новый дефект» после урока 2026-10-06 в
  `docs/lessons/testing.md` («Итог» Ticket-а 02) — примеры класса «дефект кода» для README.

## Что делаем

1. **Раздел «Классы сбоев»** в `docs/lessons/README.md`: шесть классов из таблицы документа (признак,
   как подтвердить, вывод) — коротко, со ссылкой на документ за подробностями.
2. **Раздел «Инцидент»**: где записывать (правило владельца выше), поля — симптом, ссылки,
   воспроизведение, корневая причина, дубликат; «причина не найдена» — не «урока нет».
3. **Формат урока** получает строку `Проверка:` перед `Источник:` — `file:line` test-а, hook, eval-кейс
   или явное «проверки нет: <почему>».
4. **Пороги владельца**: flaky test вылечен после 10 повторов без единого красного под параллельной
   нагрузкой полного `pnpm test` (как в gate full), прогоны на тихой машине не считаются; класс
   «временный сбой машины» ставится только после зелёного повтора того же commit-а, когда машину
   вылечили.
5. **Запреты** из документа («Что процесс не поощряет никогда») — списком из 4–5 строк.
