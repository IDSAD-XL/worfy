## Что происходит

- Machine — компьютер с worfy. При связывании каждая Machine проверяет id другой: если этот id уже
  связан с другим сертификатом, связь не записывается. Это `checkPeerId`
  (`src/main/link/service.ts:487-496`). Pairing вызывает его через `accept` (`src/main/link/pairing.ts:338-346`).
- Запись связи — `commitLink` (`service.ts:501-519`). Она эту проверку не повторяет и заменяет
  запись с тем же id (`this.store.put(record)`, `:516`).
- На стороне A между `accept` и `commit` есть ожидание сети: `accept` — после `pake2`
  (`pairing.ts:373`), `commit` — после `pake4` (`:378-380`). Два связывания, которые идут одновременно,
  с одним id и разными сертификатами проходят проверку оба. Второе перезапишет первое. Так бывает при
  двух вызовах `pair()` подряд или при `pair()` одновременно с ответом этой Machine как B
  (`service.ts:645-660`).
- Для атаки нужны два верных кода. Поэтому уровень low.

## Что делаем

- `commitLink` вызывает `checkPeerId` для `result.peer.id` и сертификата этой попытки до первой записи
  (`this.secrets.set`, `:504`). Отказ — та же `PairingError`, что и сейчас; ничего не записано.
