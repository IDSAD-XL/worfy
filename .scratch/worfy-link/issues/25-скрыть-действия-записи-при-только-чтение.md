## Что происходит

- Machine — компьютер с worfy, на котором лежит Project. Linked machine — другой компьютер с worfy,
  связанный с этим по коду.
- После Ticket-а 18 Machine Project-а даёт каждой Linked machine свой уровень доступа: Off, Read only
  или Full access (ADR-0066). При Read only каналы IPC с пометкой `write` отвечают отказом «Linked
  machines can only view the Projects of <Machine>: access is read-only»
  (`src/main/link/ipc-adapter.ts`, `readOnlyRefusal`).
- Экран Linked machine-а знает свой уровень: `readOnly` в состоянии Linked machine-ов
  (`src/shared/ipc/linked.ts`, `linkedMachineSchema`; приходит из сообщения `projects-access`,
  `src/main/link/remote-calls.ts`).
- Экран это поле пока не читает. Действия записи на Project-е такой Machine видны и активны: «New
  session», ввод в Terminal, перемещение Node-ов на Canvas, Autopilot, Ship ticket и другие. Нажатие
  отвечает отказом с текстом выше — так решил владелец для Ticket-а 18 (ответ 4).

## Что делаем

- Экран Linked machine-а с `readOnly` скрывает или выключает действия, которые вызывают каналы
  `write` на этой Machine (список — `test/unit/link-access.test.ts`, `WRITE_CALLS`).
- Вид — скрыть или показать неактивными с подсказкой «<Machine> gives this Machine read-only access» —
  решает владелец при claim; тексты и вид — в `docs/design/F-SPEC.md`.
- Canvas Project-а такой Machine — только для просмотра: Node-ы не двигаются и не меняют размер,
  Trash и создание Node-ов недоступны.

## Вопросы владельцу до начала

1. Действия записи скрыть или показать неактивными с подсказкой? Предложение: неактивными с
   подсказкой — так видно, что действие есть и почему оно недоступно.
2. Нужна ли пометка «Read only» у Machine и её Project-ов в боковой панели? Предложение: да, рядом с
   состоянием «Online».

## Итог

**Ответы владельца (решено без владельца, подтвердить).** Вопрос 1 — действия записи показаны
неактивными с подсказкой «<Machine> gives this Machine read-only access» (`aria-disabled` и
подсказка-tooltip, как у кнопок действий Ticket-а 23), не скрыты. Вопрос 2 — метка «Read only» в
боковой панели рядом с «Online» у Machine; у строк её Project-ов метки нет, она одна на группу.
Владелец принял эти решения 2026-10-18.

**Что сделано.** Хук `useReadOnly` (и `readOnlyNow` вне React) знает уровень окна из `linked.state`
и имя Machine из `link.state`; смена уровня действует без перезагрузки окна. Отправка остановлена в
общих местах: `sendLayoutOp` ничего не шлёт (`layout.apply`), `deleteToTrash` / `trashRecorded` не
зовут trash, undo/redo не исполняют шаг (шаг остаётся), Binding-и, «Go to Orchestrator» и запись
данных Card-а не шлют ничего. Canvas: overlay `ReadOnlyCanvas.tsx` ставит в store React Flow
`nodesDraggable: false` — Node не берётся мышью, поэтому ничего не «прыгает» назад, панорама и
масштаб работают; без правки `Canvas.tsx` (он не задаёт свой `nodesDraggable`, React Flow его не
возвращает). Ручек размера нет (`NodeResizeClamp.tsx`), Terminal заменён заглушкой в
`NodeChrome.tsx` — `TerminalNode` не монтируется и `terminal.open` не вызывается. Session view на
read-only не зовёт `orchestrator.open`, а берёт Node Orchestrator-а из Layout.
