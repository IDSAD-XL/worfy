## Что происходит

- Кнопка «+» в поле ввода Session зовёт `agent.attachPick` (`src/renderer/session/MessageInput.tsx:206-212`).
  Main открывает `dialog.showOpenDialog` на окне своей машины (`src/main/ipc/agent.ts:100-107`,
  `:159-169`). Файлы идут источником `path` — абсолютный путь от `/`
  (`src/shared/agent/attachments.ts:42`, `:66-67`). Файл внутри Project-а идёт по пути любого
  размера, файл вне его — копией до 20 МБ (`attachments.ts:28-29`).
- Вставка и drag-drop читают байты в renderer (`FileReader`, `MessageInput.tsx:98-108`) и шлют
  `agent.attach` источниками `pasted` и `dropped` — base64 до 20 МБ (`attachments.ts:68-75`;
  `MessageInput.tsx:184-204`, `:259-283`). Файл больше предела отклоняется до чтения (`:193`). Main
  кладёт копию в папку данных Project-а (`agent.ts:95-99`). Не больше 20 вложений на сообщение
  (`attachments.ts:31`).
- Ссылки https открывает `shell.openExternal` (`src/main/ipc/shell.ts:65-69`, `src/shared/ipc/shell.ts:20`).
  Его зовут Markdown (`src/renderer/markdown/Markdown.tsx:30-34`) и кнопка «Open PR»
  (`src/renderer/canvas/actions/OpenPr.tsx:34`).
- «Открыть в редакторе» — `shell.openInEditor`: `shell.openPath` файла внутри Project-а или его
  worktree (`shell.ts:57-64`). Его зовут Markdown для ссылки на файл (`Markdown.tsx:35-38`), строка ADR
  в боковой панели (`src/renderer/shell/sidebar/AdrSection.tsx:110`) и Ticket Node
  (`src/renderer/canvas/nodes/TicketNode.tsx:90`).
- View ▸ Show Minimap: пункт меню своей машины (`src/main/menu.ts:29`, `:38`), состояние — в памяти
  main этой машины (`src/main/ipc/view.ts:8-20`), рассылка всем её окнам (`view.ts:17-19`).
- После Ticket-ов 08 и 09 окно на Linked machine-е M шлёт на M каналы с пометкой `project` и
  `desktop` (нужен рабочий стол машины Project-а), а каналы `local` (состояние машины экрана) — в
  свой main:
  - `agent.attachPick` (`desktop`) ушёл бы на M и открыл диалог на экране M. M его отклоняет — кнопка
    «+» отвечает отказом;
  - `shell.openExternal` и `shell.openInEditor` (`desktop`) — так же: отказ;
  - `view.get` и `view.changed` (`local`): меню своей машины переключает Minimap и в окне на M.

## Что делаем

1. **До начала — два вопроса владельцу.** Ticket делает по ответам.
   - **«Открыть в редакторе» для Project-а Linked machine-а** (Ticket Node, строка ADR, ссылка на файл
     в Markdown). Файл лежит на машине Project-а; Q14 этот случай не покрывает. Варианты:
     (а) открыть на машине Project-а, как сейчас, — на экране, которого пользователь не видит;
     (б) показать текст файла в worfy на машине экрана, только чтение — нужен новый канал чтения файла
     Project-а: `docs.read` читает только HANDOFF и ADR (`src/shared/ipc/docs.ts:55-64`);
     (в) не открывать, показать подсказку «File is on <Machine>». Рекомендация: (в) в этом Ticket-е,
     (б) — отдельным Ticket-ом, если нужен.
   - **View ▸ Show Minimap** — своё у каждого экрана или общее для всех экранов Project-а.
     Рекомендация: своё, как камера Canvas (Q15) и выделение (Q2). Так уже работает после Ticket-а 09
     (меню машины экрана), правка — только test.
2. **«+» на Session Project-а Linked machine-а** (Q14). Кнопка открывает диалог своей машины и шлёт
   байты тем же путём, что drag-drop. В окне на M (Machine окна — из Ticket-а 09) `pick` не зовёт
   `agent.attachPick`, а открывает скрытый `<input type="file" multiple>`: Electron показывает диалог
   ОС машины экрана. Выбранные файлы идут в `attachFiles(files, 'dropped')` (`MessageInput.tsx:184`):
   тот же предел 20 МБ, то же число вложений, отказ до чтения. M кладёт копии в папку данных
   Project-а, как при drag-drop. Файл со своей машины никогда не лежит внутри Project-а M, поэтому
   вложение по пути ему не нужно. На своей машине «+» не меняется: `agent.attachPick`, файл внутри
   Project-а — по пути.
3. **Ссылка открывается на машине, где кликнули.** Это вывод из Q14, владелец отдельно не решал.
   Пометка `shell.openExternal` меняется с `desktop` на `local` (объявление канала —
   `src/shared/ipc/shell.ts:20`): в окне на M вызов идёт в свой main (Ticket 09), а Linked machine
   этот канал на машине Project-а по-прежнему не зовёт. Markdown и «Open PR» не меняются.
4. **«Открыть в редакторе»** — по ответу на первый вопрос. Для (в): в окне на M ссылка на файл в
   Markdown, Ticket Node и строка ADR вместо вызова показывают подсказку «File is on <Machine>»;
   `shell.openInEditor` остаётся `desktop`. Для (а) — пометка `project`: файл открывается на машине
   Project-а. Для (б) — этот Ticket делает (в), а чтение файла уходит в новый Ticket.
5. **Show Minimap** — по ответу на второй вопрос. Для «своё» — только test. Для «общее» — состояние
   Minimap Project-а живёт на машине Project-а и рассылается всем его экранам; тогда правятся
   `src/main/ipc/view.ts` и `src/main/menu.ts` (список ниже дополняется).

**Не входит:** подтверждение Card (Ticket 10), выбор папки Project-а (Ticket 11), уведомления
(Ticket 13).
