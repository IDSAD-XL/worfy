## Что происходит

- Получатель события из main — `webContents` окна Electron. Общего реестра получателей нет.
- Рассылку «всем окнам» делает `BrowserWindow.getAllWindows()` в восьми местах.
  - `toEveryWindow` (`src/main/broadcast.ts:6-15`): события Orchestrator-а
    (`src/main/agent/app-orchestrators.ts:41-42`), Session-ов Session Node-ов
    (`src/main/agent/app-node-sessions.ts:32-33`) и Autopilot (`src/main/ipc/autopilot.ts:75`).
    Отказ одного окна не останавливает остальные (`broadcast.ts:9-13`).
  - Напрямую: `layout.changed` (`src/main/ipc/layout.ts:10-14`), `view.changed`
    (`src/main/ipc/view.ts:15-20`), `cards.changed` (`src/main/ipc/cards.ts:9-13`),
    `projects.changed` и `projects.settings.changed` (`src/main/ipc/projects.ts:24-33`, `:74-80`),
    `trash.changed` (`src/main/ipc/trash.ts:34-38`), `actions.launches.changed`
    (`src/main/ipc/actions.ts:29-33`). Последние два в брифе фактов разведки не названы.
- Подписки hub-ов (общих наблюдателей, которые шлют изменения подписавшимся окнам) берут окно из
  `event.sender` и отписывают его только по событию `destroyed` окна.
  - workflow: `WeakSet<WebContents>` и `once('destroyed')` → `workflowHub.drop(id)`
    (`src/main/ipc/workflow.ts:10-28`).
  - docs: так же (`src/main/ipc/docs.ts:57-67`, `:105-106`). У main свой подписчик с id `'main'`
    (`:75-76`).
  - claude-home: тип `Subscriber` — `id`, `send`, `isDestroyed`, `once('destroyed')`
    (`src/main/ipc/claude-home.ts:27-33`); подписка — `:70-77`; вызовы — `:146`, `:152`.
  - bindings: `BindingsWindow` (`src/main/ipc/bindings.ts:17`, `:24-38`).
  - limits: `LimitsWindow` (`src/main/ipc/limits.ts:9`, `:13-26`).
  Каждый файл приводит `event.sender` к своему типу сам (`as BindingsWindow`, `as Subscriber`).
- id подписчиков — числа `webContents.id`. В `workflowHub` есть и отрицательные id: Autopilot
  подписывается сам (`src/main/ipc/autopilot.ts:43-44`, `watchIds -= 1`). У `DocsSubscriber` id —
  `number | string` (`src/main/docs/watch.ts:222-225`), у `WorkflowSubscriber` — `number`
  (`src/main/workflow/watch.ts:236-239`).
- Клик по уведомлению: `holdFor` кладёт заметку по `window.webContents.id`
  (`src/main/notify.ts:160-170`), `PendingOpens` держит заметки в `Map` по этому id
  (`src/main/notify-pending.ts:11-31`), `notify.pending` отдаёт заметку по `event.sender.id`
  (`src/main/ipc/notify.ts:8`).
- Второе окно при открытом первом сейчас не открыть ни человеку, ни e2e. `createMainWindow`
  (`src/main/window.ts:61`) вызывают `second-instance` и `activate`, и только когда окон нет
  (`src/main/index.ts:53-62`, `:93-94`). Renderer новых окон не открывает: `setWindowOpenHandler`
  (`src/main/window.ts:210`). В `app.evaluate` Playwright даёт только модуль `electron`. Два окна
  запуском не проверялись.
- Contract test-ы подменяют `BrowserWindow.getAllWindows`, чтобы поймать рассылку:
  `test/contract/layout-store.test.ts:31`, `trash.test.ts:28`, `projects.test.ts:25` (и пустым
  списком — `node-sessions`, `docs`, `autopilot*`). `test/contract/orchestrator.test.ts:685` и
  `:690` считают подписки на события `app`: после импорта ни одной, после `startOrchestrators` —
  ровно одна на `browser-window-created`.
- Активный Project — один на приложение (`activeId` в `projects.json`,
  `src/main/projects/store.ts:24`, `:152`). Оба окна показывают один Project. Этот Ticket это не
  меняет.
- Привязки к окну, которые остаются другим Ticket-ам: Session из `agent.start`
  (`src/main/ipc/agent.ts:41`, `:138-139` — Ticket 04), Terminal (`src/main/ipc/terminal.ts:21`,
  `:54`, `:69` — Ticket 05), окно-родитель нативных диалогов `BrowserWindow.fromWebContents`
  (`projects.ts:44` — Ticket 11, `agent.ts:104` — Ticket 12, `card-api.ts:96` — Ticket 10).

## Что делаем

1. **Клиент** (Q2; ADR-0053) — общий тип получателя в новом модуле (предлагается
   `src/main/clients.ts`): `id`, `send(channel, ...args)`, `isDestroyed()`,
   `once('destroyed', listener)`. `webContents` окна подходит как есть. Соединение Linked
   machine-а (адаптер Ticket-а 01) станет клиентом в Ticket-е 08.
2. **Реестр.** Клиенты — это окна из `BrowserWindow.getAllWindows()`, как сейчас, плюс клиенты без
   окна, добавленные явно; `destroyed` убирает такого клиента. Своей подписки на
   `browser-window-created` реестр не заводит. Так окно, открытое test-ом, попадает в реестр само;
   подмены `getAllWindows` в contract test-ах и счёт подписок в `orchestrator.test.ts:685`, `:690`
   остаются верными; `src/main/index.ts` и `src/main/window.ts` не меняются.
3. **id клиентов.** Нужно правило, при котором id окна, клиента без окна и внутреннего подписчика
   Autopilot (`autopilot.ts:43-44`) не совпадают ни в одном hub-е. Окна сохраняют
   `webContents.id`: на нём держатся `PendingOpens` и test-ы. Для остальных — выбор Ticket-а
   (например, строковые id и типы hub-ов `number | string`, как уже у docs). Правило — в «Итог»:
   по нему Ticket 08 даёт id соединениям.
4. **Рассылка.** `toEveryWindow` перебирает реестр: окна и клиенты без окна. Имя можно оставить —
   тогда вызовы в `app-orchestrators.ts`, `app-node-sessions.ts` и `autopilot.ts` не меняются.
   Шесть файлов с прямым `getAllWindows()` переходят на неё. Отказ одного клиента по-прежнему не
   останавливает остальных.
5. **Подписки hub-ов по клиенту.** workflow, docs, claude-home, bindings, limits берут клиента из
   `event.sender` одной функцией модуля клиентов вместо своих приведений типа. Отписка — по
   `destroyed` клиента, у окна и у клиента без окна одинаково. То, что импортируют hub-ы, не тянет
   `electron` во время выполнения (только `import type`): их test-ы — `test/contract/limits.test.ts`,
   `bindings.test.ts`, `claude-home-registry.test.ts`, `workflow-reader.test.ts` — идут без mock
   `electron`. Перебор окон (`getAllWindows`) живёт там, где рассылка.
6. **`notify.pending` по клиенту.** `PendingOpens` хранит заметку по id клиента, `notify.pending`
   отдаёт её вызвавшему клиенту, `destroyed` клиента её сбрасывает. Для окна поведение прежнее:
   `holdFor` кладёт по id его `webContents`.
7. **Helper второго окна** в `test/e2e/helpers.ts`: `app.evaluate` создаёт `BrowserWindow` с
   preload сборки (`out/preload/index.cjs`, как `src/main/window.ts:83`) и `contextIsolation`,
   `sandbox`, загружает адрес первого окна и ждёт `app.waitForEvent('window')`. Способ не
   проверен: проверить, что вызовы второго окна проходят проверку `isAppUrl`. Не выйдет — другой
   способ, в «Итог». Пункт меню «New Window» владелец не решал — без его ответа не добавлять.
   Этим helper-ом пользуются Ticket-ы 04–07.

Не входит: Session из `agent.start` (Ticket 04), Terminal (Ticket 05), нативные диалоги (Ticket-ы
10–12), сеть (Ticket-ы 01 и 08), свой активный Project у каждого окна. Меню View ▸ Show Minimap
по-прежнему меняет `view` у всех окон: общее оно или своё у экрана, решает Ticket 12.

## Итог

- **Клиент и реестр** — `src/main/clients.ts`: тип `Client` (`id`, `send`, `isDestroyed`,
  `once('destroyed')`), `ClientId = number | string`, `isWindowlessId`, `clientOf(event)` и класс
  `ClientRegistry` (`add`, `list`, `broadcast`, `held` — счётчик для test-ов). Модуль не тянет
  `electron` во время выполнения. Реестр приложения — `clients` в `src/main/broadcast.ts`: окна
  берутся из `BrowserWindow.getAllWindows()` при каждом вызове (своей подписки на
  `browser-window-created` нет), клиенты без окна — через `addClient(client)`; `destroyed` убирает
  такого клиента, поздний `destroyed` старого клиента не убирает нового с тем же id.
- **Правило id (для Ticket-а 08).** Окно — `webContents.id`, положительное число. Подписчик
  Autopilot в `workflowHub` — отрицательные числа (`src/main/ipc/autopilot.ts`, без изменений).
  Подписчик main в docs — `'main'`. Клиент без окна — строка `<kind>:<name>`
  (`^[a-z][a-z0-9-]*:\S+$`), например `link:<id соединения>`. `addClient` отказывает в id вне
  правила и в id живого клиента; уже уничтоженного клиента молча не добавляет. Тип
  `WorkflowSubscriber.id` стал `number | string` (`src/main/workflow/watch.ts`), как у docs.
  *Решено без владельца, подтвердить.*
- **Рассылка.** `toEveryWindow` — имя оставлено (*решено без владельца, подтвердить*), вызовы в
  `app-orchestrators.ts`, `app-node-sessions.ts`, `autopilot.ts` не менялись; теперь она идёт по
  реестру: сначала окна, потом клиенты без окна. Шесть файлов (`layout`, `view`, `cards`,
  `projects` — оба события, `trash`, `actions`) перешли на неё. Отказ одного клиента пишется в
  `console.warn` с его id и не останавливает остальных — теперь и в этих шести.
- **Hub-ы.** workflow, docs, claude-home, bindings, limits берут клиента через `clientOf(event)`;
  `BindingsWindow`, `LimitsWindow` и своё описание `Subscriber` в claude-home убраны
  (`Subscriber` = `Client`). Отписка — по `destroyed` клиента. Без `event.sender`:
  `workflow.open`/`docs.open` отвечают ошибкой, `*.close` — `closed: false`, claude-home и bindings
  не подписывают (как раньше); limits больше не подписывает уже уничтоженного клиента.
- **`notify.pending`.** `PendingOpens` хранит заметку по `ClientId`; новый `holdFor(client, note)`
  кладёт заметку и сбрасывает её по `destroyed` клиента (один слушатель на клиента).
  `notify.pending` отдаёт заметку клиенту из `clientOf(event)`. Окна — как раньше:
  `src/main/notify.ts` не менялся и кладёт по `webContents.id`.
- **Helper второго окна** — `openSecondWindow(launched)` в `test/e2e/helpers.ts`: `app.evaluate`
  создаёт `BrowserWindow` с `out/preload/index.cjs`, `contextIsolation`, `sandbox`,
  `nodeIntegration: false`, загружает адрес первого окна, test ждёт `app.waitForEvent('window')`.
  Вызовы второго окна проходят проверку `isAppUrl` (в e2e `layout.get` и `workflow.open` из окна 2
  отвечают `ok: true`). Только для сборки `out/`, не для собранного `.app`.
- **Как падал первый test** (`test/contract/clients.test.ts` на коде main): 6 из 7 красные —
  `TypeError: addClient is not a function` и `Cannot find module '/src/main/clients'`. Test «id окна,
  клиента без окна и Autopilot в одном watcher-е» зелёный и на main: эти id и раньше не совпадали.
- **e2e** `test/e2e/two-windows.spec.ts` не красный на main: окна и раньше получали рассылку
  через `getAllWindows()`. Он проверяет helper и поведение двух окон, а не реестр.
- Mutation testing (мутанты в своём worktree): убрать клиентов без окна из `list`, `try/catch`
  рассылки, забывание по `destroyed`, проверку «тот же клиент» при забывании, проверку
  уничтоженного при `add`, проверку дубля, правило id, отписку по `destroyed` в каждом из пяти
  hub-ов, сброс и «один слушатель» в `PendingOpens` — каждый мутант краснит
  `test/contract/clients.test.ts` или `test/unit/notify.test.ts`.
- `grep -rn "getAllWindows" src/main/ipc src/main/broadcast.ts`:
  `src/main/broadcast.ts:11:  for (const window of BrowserWindow.getAllWindows()) {` — и только.
  Вне следа остались `src/main/notify.ts:177` (окно для клика по уведомлению) и
  `src/main/index.ts:54`, `:94` (создание окна).
