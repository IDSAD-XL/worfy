## Что происходит

Строки — на origin/main `2414734ed`.

- **CI run-ы и смены статуса Ticket-ов main читает, экран их не рисует.** Модель собирает их вне дорожек:
  `OFF_LANE_KINDS` (`src/shared/work-track/lanes.ts:27`) и `offLaneSpans` (`lanes.ts:140-143`) отдают PR, CI и
  `ticket-status`. Вид берёт из них только ромбы merged PR: `src/renderer/work-track/Lanes.tsx:274` фильтрует
  `span.kind === 'pr'`. Spec обещал их на экране: отметки на оси и запись в боковой панели (п. 4 и 7 «Что видит
  владелец»). Подписи для панели уже есть (`src/renderer/work-track/SpanPanel.tsx:40-42`: «CI run», «Ticket status
  change»), но щёлкнуть не по чему.
- **Пробелы GitHub и git считаются в сводке, но не заштрихованы ни на одной дорожке.** Сводка сливает пробелы всех
  источников (`src/shared/work-track/summary.ts:61-83`, `mergeGaps` по `WORK_SOURCES`) — KPI «no-data gaps» их
  включает. Штриховку дорожки даёт `laneGaps` (`lanes.ts:145`), а его вызывают только дорожки Session (`lanes.ts:235`),
  «Autopilot Runs» (`lanes.ts:241`) и «Gate runs» (`lanes.ts:254`). Источники `github` и `git` не попадают никуда:
  «нет сети» или «нет git» на ленте не видны, хотя п. 6 «Что видит владелец» требует штриховку там, где источник
  ничего не хранит.
- **Команда Command palette «Open Run history» открывает Work track.** `src/renderer/palette/commands.ts:409-419`
  зовёт `openRunHistory(projectId)` без Run-а и Epic-а. `RunsView.tsx:44-45` переключает вкладку на «Run history»
  только когда назван Run или Epic, поэтому если Project последним выбрал Work track, команда открывает Work track.
  Это расходится с названием команды и с `docs/features/flight-recorder.md:33` («the screen at the newest run of the
  active Project»).

## Что делаем

1. **Отметки CI run-ов и смен статуса.** На оси времени (рядом с ромбами PR) или в отдельной узкой строке под осью —
   выбор implementer-а, записать в «Итог»: отметка CI run-а (цвет по исходу) и отметка смены статуса Ticket-а. Щелчок
   — боковая панель `SpanPanel.tsx` с этой записью (When, Epic, Ticket, PR, Outcome, «Source: …»). В Month — счёт в
   клетке дня не меняется; отметки — только в Day и Week.
2. **Штриховка пробелов GitHub и git.** Пробел `github` штрихует строку, где видны PR и CI (ось или новая строка из
   п. 1); пробел `git` — строку смен статуса. Подсказка — источник и причина, как у остальных пробелов. Сводка не
   меняется.
3. **«Open Run history» всегда открывает Run history** (рекомендация). Команда ставит вкладку «Run history» перед
   `openRunHistory` (или `openRunHistory` получает явный признак вкладки) — implementer выбирает способ. Отдельная
   команда «Open Work track» (вкладка Work track, неделя по умолчанию) — по желанию implementer-а; если добавлена, она
   в группе View рядом с «Open Run history».
4. Обновить `docs/features/work-track.md` и `docs/features/ru/work-track.md` (страницу создаёт Ticket 11): отметки,
   штриховка GitHub/git, команды Command palette.

## Итог

- Сначала падающий: до реализации красные 6 новых unit test-ов — `markRows` нет, строк отметок нет, панели CI и смены
  статуса нет, команда Command palette оставляла вкладку Work track. Test «пробелы GitHub и git не попадают на дорожки» был
  зелёным и на старом коде: он сторожит, что штриховка не переехала на дорожки.
- Выбор п. 1: **отдельные узкие строки под осью**, не ось. Две строки — «CI runs · GitHub» и «Ticket status · git log»
  (`MarkRows` в `Lanes.tsx`, модель — `markRows` в `src/shared/work-track/lanes.ts`). Причина: у пробелов `github` и
  `git` должна быть своя строка, а штриховка поверх оси закрыла бы подписи часов и дней. Ромбы PR остались на оси,
  как были. Строки — вне прокрутки дорожек, одинаковые в `by Session` и `by Epic`.
- Отметка CI run-а — длиной с run (не меньше 4 px), цвет по исходу: `ok` — `--ready-dot`, `failed`/`rejected` —
  `--span-problem`, `stopped`/`cut-off`/`blocked` — `--text-muted`, идёт — `--working-dot`. Отметка смены статуса —
  точка 8 px цветом `--span-ticket`, смена на `blocked` — `--blocked-ring`. Tooltip — тот же, что у полос; у момента
  (start = end) — одно время без длительности.
- Панель: для момента When — одно время, Duration — `—`; Outcome смены статуса — сама смена (`claimed → done`), взятая
  из title после номера Ticket-а (`ticketStatusFact` в `src/main/work-track/ticket-status.ts` пишет title как
  `<ticket> <from> → <to>`); если title другой формы — прежний outcome.
- Month: строк отметок нет, счёт merge в клетке дня не менялся. Поэтому пробел GitHub или git в Month виден только в
  KPI «no-data gaps» — так и записано на странице.
- П. 3: команда «Open Run history» зовёт `setRunsTab(projectId, 'history')` перед `openRunHistory(projectId)`
  (`src/renderer/palette/commands.ts`). `open.ts` и `RunsView.tsx` не тронуты: кнопка Runs панели инструментов тоже
  зовёт `openRunHistory` без Run-а и должна сохранять выбор Work track. Команду «Open Work track» не добавлял.
