## Что происходит

- `scripts/agent-cost.mjs` делит token-ы по ролям (`roleOf`, `:297-308`) и по Ticket-ам (`--by-ticket`, `:54-59`), но
  считает verifier reviewer-ом, любую Session — Orchestrator-ом и делит Orchestrator-а поровну между Ticket-ами Wave.
- Факты, к которым можно привязать ответ, уже есть: Ticket факта Flight Recorder (`WorkFact.ticket`,
  `src/shared/flight-recorder/facts.ts:174-186`), попытки Span-а (`attempt`, `retryOf`,
  `src/shared/flight-recorder/spans.ts:96-98`, `:413`), причины повторов из журнала (`facts.ts:67`), `ticket` и `epic`
  фактов Work track (`src/shared/work-track/facts.ts:73-75`), вердикт в фактах Work track (`verdictOf`,
  `src/main/work-track/transcripts.ts:127`), Binding на Canvas (`resolveBinding`, `src/shared/binding/resolve.ts:242`).

## Что строить

- `src/shared/usage/ledger.ts` — чистый модуль: записи `UsageRecord` и факты Work track или Flight Recorder → срезы по
  Epic-у, Ticket-у, Session, роли, раунду, модели, Vendor-у; итог периода. Каждый срез — token-ы, вес, доля чтения из
  cache.
- Ответ относится к факту, внутри которого он по Session и времени.
- Роли: Orchestrator, другая Session, implementer, verifier (`worfy:reviewer` с линзой «implementer's report», имя
  `verify-<NN>`, `harness/skills/epic-wave/SKILL.md:421`, `:559`), reviewer (остальные reviewer-ы и sceptic-и), scout,
  Assistant (вызовы из `usage.json`), другой Subagent.
- Orchestrator — своя строка уровня Epic-а, не делится между Ticket-ами и по раундам.
- Раунды: внутри Run-а — попытка 1 первый проход, 2 и больше — доработка с причиной (Span rejected или stopped,
  `narrow-round`); вне Run-а — implementer того же Ticket-а после вердикта REJECTED.
- Ticket ответа: Run → Flight Recorder; вне Run-а → Work track, только когда reader уверен; Canvas → Binding. Иначе —
  «No Ticket».
- Ответы других папок — одна строка «Other Projects on this Machine», без имён (решение владельца 2026-11-28, Q7 (а)).
