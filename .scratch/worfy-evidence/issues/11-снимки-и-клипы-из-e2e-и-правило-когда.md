## Что происходит

- Снимки-доказательства есть (вид `screenshot`; в папках `evidence/` 857 png), но helper-а для них нет: каждый spec снимает сам и
  кладёт в свой output, например `bothThemes` в `test/e2e/ticket-evidence.spec.ts:83-89`. Куда класть снимок, который останется
  доказательством, говорит только rules.md Profile-а worfy (`.scratch/<эпик>/evidence/NN-что.png`, решение владельца Р4 2026-10-06).
- Клипов нет совсем. Приложение в e2e запускает `launchApp` через `_electron.launch` (`test/e2e/helpers.ts:290-293`); у `LaunchOptions`
  (`helpers.ts:145-153`) только `env` и `executablePath`. Playwright (`package.json:56`, 1.63) умеет `recordVideo: { dir, size }` у
  `_electron.launch`: webm (VP8) на каждое окно, файл готов после закрытия приложения (`page.video().saveAs()`).
- Для клипа Playwright нужен свой ffmpeg (`playwright install ffmpeg`); CI его не ставит — в `.github/workflows/ci.yml` нет
  `playwright install` (Ответ Qv4).
- Правило агентов (`step-6-manual-gui-checks.md:11-13`, `:23-25`): экран через ОС не снимать, снимки — только Playwright
  `page.screenshot` своей сборки. Когда пункту нужна картинка, а когда нет, не сказано нигде: агент снимает или по привычке, или никогда.

## Что делаем

1. **`test/e2e/evidence-capture.ts`** (новый) — два helper-а:
   - `captureScreenshot(target, what, options?)`: `target` — `Page` или `Locator` окна приложения; снимок в светлой и тёмной теме
     (`emulateMedia`, как `bothThemes`), `options.themes` — сузить. Файлы — `<NN>-<what>-light.png`, `<NN>-<what>-dark.png`.
   - `recordClip(what, scenario, options?)`: запускает приложение через `launchApp({ recordVideo })`, выполняет `scenario(launched)`,
     закрывает приложение и сохраняет клип главного окна `<NN>-<what>.webm` (Ответ Qv3); размер — по умолчанию 1280 × 800, жёсткий
     предел записи — 60 с (сценарий дольше — ошибка helper-а, клип не сохраняется). Пока сценарий идёт, раз в секунду
     `page.screenshot` главного окна; из этих кадров — `<NN>-<what>.sheet.png`: сетка, кадр в своём размере (1:1, CSS px окна; было «шириной 320 px», изменено в ревью — см. «Итог»), под кадром номер секунды.
     Сборка sheet — без новых зависимостей: в скрытом окне того же приложения (`BrowserWindow` с `show: false`, страница с кадрами,
     `webContents.capturePage()`) до его закрытия, или иначе на усмотрение implementer-а. Клип больше 8 MB — ошибка helper-а с
     советом уменьшить `size` или сценарий.
   - **Куда пишут.** Переменная `WORFY_EVIDENCE=<epic>/<NN>` — в `.scratch/<epic>/evidence/` worktree-а, с префиксом `<NN>-`; без неё
     — в `test.info().outputPath()` (CI её не ставит, в репозиторий ничего не попадает). После записи helper печатает команду
     `ticket evidence <epic> <NN> <item> screenshot|video pass --ref "…" --copy dev --scrub <дата>` с путём относительно файла
     Ticket-а — дату и номер пункта человек или агент вписывает после проверки пикселей.
   - Записывают только fixture-сборку: helper отказывается, если `launchApp` получил `executablePath` (установленная или Stable
     copy с данными машины), — Ответ Qv1.
2. **`test/e2e/helpers.ts`** — `LaunchOptions.recordVideo?: { dir: string; size?: { width: number; height: number } }`, передаётся в
   `_electron.launch`; без поля всё как сейчас.
3. **`test/e2e/evidence-capture.spec.ts`** (новый) — проверяет сами helper-ы на fixture-проекте: снимок в двух темах, клип короткого
   сценария (открыть Ticket в focus mode, перетащить карточку), sheet рядом; затем `node harness/bin/evidence-check <клип> <sheet>`
   с отметкой во временном Ticket-е — exit 0. Строка spec-а — в `scripts/e2e-specs.table.json`.
   **ffmpeg (Ответ Qv4):** при варианте (а) — шаг `pnpm exec playwright install ffmpeg` в e2e job-ах `.github/workflows/ci.yml`
   (macOS и Windows); при варианте (б) случай клипа пропускается без ffmpeg с причиной «Playwright ffmpeg is not installed».
4. **Правило «когда картинка»** — `harness/skills/ship-ticket/step-6-manual-gui-checks.md` (текст Harness — английский, ADR-0074,
   без имён helper-ов worfy):
   - пункт «Готово, когда» о том, **как что-то выглядит** (вёрстка, цвет, подпись, состояние control-а, тема) — снимок окна
     приложения в обеих темах, строка `screenshot`;
   - пункт о **движении** — анимация, drag, последовательность через несколько экранов, timing (что-то появляется через N секунд,
     держится, исчезает) — клип с contact sheet, строка `video`;
   - **всё остальное** — без картинки: доказывает test с exit code. Картинка «на всякий случай» не нужна: каждая — ещё один файл на
     ручную проверку пикселей;
   - картинка — только из своей сборки с fixture-данными, через e2e runner проекта; `scrub:` — после проверки каждого кадра sheet (для
     снимка — самого снимка).
   Та же короткая строка — в `harness/agents/implementer.md` (раздел о доказательствах пунктов, который пишет 07), и случай в
   `harness/bin/tests/agents-text.test.sh`. Имена helper-ов worfy — строкой в rules.md Profile-а worfy (вне репозитория; правит
   Orchestrator при закрытии).

Не входит: перенос `bothThemes` из `ticket-evidence.spec.ts` (его правит 12), клипы второго окна, запись не из e2e runner-а.

## Итог

Сделано в PR #1385: `test/e2e/evidence-capture.ts` (`captureScreenshot`, `recordClip`), `recordVideo` у `launchApp`, spec
`test/e2e/evidence-capture.spec.ts`, правило «когда картинка» в `harness/skills/ship-ticket/step-6-manual-gui-checks.md`, клип
`../evidence/11-card-drag.webm` с sheet.

Решено без владельца:

- Короткая строка правила стоит в `harness/skills/ship-ticket/implementer-finish.md` (там раздел о строках Evidence, который
  написал 07), а не в `harness/agents/implementer.md`: стартовый контекст implementer-а на main — 14 998 из 15 000 токенов, одна
  строка дала 15 202, и `start-context.test.sh` стал красным.
- `test/contract/ci-workflow.test.ts` правился вне следа в первом раунде (шаг ffmpeg в e2e job-ах). Во втором раунде ffmpeg
  ставит сам `pnpm test:e2e` (`playwright install ffmpeg` первым шагом скрипта): так он есть и на CI, и на новой машине, и в
  gate full на ПК; шаги в `ci.yml` и правка contract test-а убраны.
- Строку `video` со `scrub:` под ручным пунктом 6 записал агент сам (Qv1 (а)): клип fixture-сборки, каждый кадр sheet проверен.
  Исключение для такого клипа теперь записано и в step 6, и в `implementer-finish.md`.
- Sheet — кадры в своём размере (1:1, CSS px окна), решение Orchestrator-а в ревью: при 320 px подписи шириной 13 px не читались.
  Сетка — близкая к квадрату, сторона не больше 16 384 px (предел поверхности Chromium); не помещается — ошибка helper-а
  «shorten the scenario».
- Для e2e — `WORFY_TAILSCALE` (новая переменная `findTailscale`, `src/main/link/tailscale.ts`) на файл, которого нет: приложение
  под test-ом не видит Tailscale CLI, и в снимок или клип не попадают имена tailnet машины разработчика.
- Повторный запуск с тем же `WORFY_EVIDENCE` не перезаписывает файл, который git уже отслеживает: helper отказывает.

Известные пределы:

- Клип включает запуск и выход приложения, на несколько секунд дольше сценария; sheet покрывает только сценарий.
- `emulateMedia({ colorScheme: null })` в Electron даёт системную тему, а не светлую по умолчанию Playwright, поэтому
  `captureScreenshot` возвращает ту схему, что была до него. `bothThemes` в `ticket-evidence.spec.ts` (Ticket 12) так не делает.
- Без ffmpeg Playwright 1.63 не падает при запуске, а виснет на первом `page.screenshot`; поэтому `recordClip` проверяет
  `ffmpeg-<revision>/INSTALLATION_COMPLETE` до запуска и называет команду установки.
