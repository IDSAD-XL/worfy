## Question

Run идёт по списку Epic-ов по порядку. Как устроена очередь?

- Как задаётся: список при запуске (кнопка Canvas, команда чата, MCP tool `autopilot_start` — сейчас `{epic, tickets?}`, `src/shared/canvas/tools.ts:87-88`), «все принятые Epic-и с готовыми Ticket-ами» — какой порядок (план, приоритет в HANDOFF, дата принятия) и что значит «принятый» (строка `Status:` spec-а?).
- Можно ли менять очередь во время Run-а (добавить, убрать, переставить)?
- Когда Run переходит к следующему Epic-у: все Ticket-ы `done`; а если остались только `blocked`, ждущие владельца (приёмка, `Waits: owner`) или Ticket-ы «не в Autopilot» — пропустить с записью в журнал, или остановиться?
- Названные Ticket-ы (`tickets`) — только для одного Epic-а или по Ticket-ам в каждом Epic-е очереди.
- Остановки Run-а (красный CI на main, `tickets-done`, Limits-timeout): одна на весь Run или Run идёт к следующему Epic-у.
- Журнал (`epic` в каждой строке, `journal.ts:415`), Run history (заголовок с одним Epic-ом, фильтр Epic-а, `RunHistoryView.tsx:24,96,111`), `RunningElsewhere` по Epic-у (`run.ts:982`), строка Autopilot на Canvas — что показывают при очереди.
- Слово «Run» в глоссарии («Один запуск Autopilot над одним Epic», `CONTEXT.md:104`) — новое определение.
- Codex Orchestrator и бюджет Wave — меняется ли что-то при очереди.

## Решения владельца 2026-11-05

Grilling 2026-11-05, раунд 1 (владелец: «по остальному все да» — все рекомендации) и раунд 2 («1-10 согласен»); прототип
окна запуска с очередью принят. Q — вопросы этого Ticket-а по порядку.

1. **Q1. Как задаётся очередь.** → Списком Epic-ов в команде чата и в MCP tool `autopilot_start`, и действием «Run all
   accepted». Принятый Epic — тот, чей spec принят владельцем, и у которого есть готовые Ticket-ы. Порядок — тот, что
   задал владелец, иначе по дате принятия spec-а. В окне запуска очередь до старта можно править: снять галочку и
   перетащить (прототип `card-918c77d9`, вид «Queue»).
2. **Q2. Правка очереди во время Run-а.** → Между Wave-ами можно добавить Epic в конец и убрать ещё не начатый;
   переставлять нельзя.
3. **Q3. Когда Run переходит к следующему Epic-у.** → Когда все Ticket-ы Epic-а `done`. Если остались только Ticket-ы,
   ждущие владельца (приёмка, `Waits: owner`, «не в Autopilot»), Run пропускает Epic с записью в журнал, а строка
   Epic-а показывает «Ждёт владельца».
4. **Q4. Названные Ticket-ы.** → Только у Run-а из одного Epic-а; у очереди Ticket-ы не называются.
5. **Q5. Остановки.** → Красный CI на main и `limits-timeout` останавливают весь Run; конец Epic-а (`tickets-done`) ведёт
   к следующему Epic-у очереди.
6. **Q6. Журнал и виды.** → Одна строка Run-а в Run history со списком Epic-ов; новые события журнала `epic-started` и
   `epic-finished`; строка Autopilot — «Epic 2/3: <имя>».
7. **Q7. Слово «Run».** → «Один запуск Autopilot: от старта до остановки ведёт Wave-ы одного Epic-а или очереди Epic-ов
   по порядку»; _Avoid_: сессия Autopilot, прогон.
8. **Q8. Codex и budget Wave.** → Без изменений: Orchestrator на Codex ведёт очередь так же, budget считается по Wave-ам,
   как сейчас.

Итог — spec [`../spec.md`](../spec.md), «Решения владельца» и Ticket-ы 12–16.
