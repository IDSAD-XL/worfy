# 02 — Старт Autopilot-а, пока идёт работа: как ждёт Run

Type: grilling
Status: done 2026-11-05T19:15Z
Blocked by: 01
Source: [map.md](../map.md); Ticket 01, Q2

## Question

Run принят и ждёт, пока Orchestrator освободится. Что именно он ждёт и как это выглядит?

- Что считается «работой»: фоновые задачи Orchestrator-а (`orchestrator.ts:324`), его ход (`:313`), очередь сообщений (`:325`); а другие Session на Canvas, Terminal, gate в фоне — ждать их или нет?
- Сообщения в очереди: они предназначались человеку (`orchestrator.ts:216`). Отправить их до старта Run-а, оставить человеку, или старт ждёт, пока очередь опустеет?
- Человек пишет Orchestrator-у, пока Run ждёт: ожидание продолжается (новый ход — снова работа), или сообщение отменяет запланированный старт?
- «Start now»: подтверждение, что именно останавливается (задачи, ход), что пишется в журнал; есть ли «Cancel» у ожидания; предел ожидания (часы) или бессрочно.
- Причина ожидания: новая (`orchestrator-busy`) или существующая `background-tasks` (`src/shared/flight-recorder/facts.ts:29`) — что она значит сейчас и где её пишет Run.
- Окно запуска (`start-window`), бюджет и Limits: считаются ли с момента нажатия или с настоящего старта.
- Run, остановленный ошибкой при живых задачах (`orchestrator.ts:303-304`): сразу вернуть Session человеку и что делать с задачами.
- Отказ кнопки Canvas как toast (`action-button.ts:41,44`): какие отказы остаются отказами (dev-сборка worfy, пустой шаблон, Codex без hook-ов, Run на Linked machine — `run.ts:935-982`).
- Autopilot из Session без человека (`chat-confirm.ts:240`) — остаётся отказом?

## Решения владельца 2026-11-05

Grilling 2026-11-05, раунд 1 (владелец: «по остальному все да» — все рекомендации) и раунд 2 («1-10 согласен»); прототип
окна запуска принят («посмотрел прототип, все устраивает»). Q — вопросы этого Ticket-а по порядку.

1. **Q1. Что считается работой.** → Только работа самого Orchestrator-а: его ход, очередь сообщений и его фоновые задачи.
   Другие Session на Canvas, Terminal, gate в фоне Run не ждёт.
2. **Q2. Сообщения в очереди.** → Run ждёт, пока очередь опустеет; сообщения человека не отправляются Run-ом и не
   удаляются.
3. **Q3. Человек пишет Orchestrator-у, пока Run ждёт.** → Ожидание продолжается: новый ход — снова работа. Отменяет
   запланированный старт только Cancel.
4. **Q4. «Start now», Cancel, предел.** → «Start now» после подтверждения прерывает ход и останавливает фоновые задачи
   так же, как Stop (ADR-0050), и Run стартует сразу; маленькое окно подтверждения перечисляет, что остановится. Cancel
   у ожидания есть. Предела ожидания нет.
5. **Q5. Причина ожидания.** → Новая причина Wait — `orchestrator-busy`; `background-tasks` (`src/shared/flight-recorder/facts.ts:29`)
   остаётся за ожиданием задач внутри Run-а.
6. **Q6. Окно запуска, budget, Limits.** → Считаются от настоящего старта Run-а, не от нажатия.
7. **Q7. Run, остановленный ошибкой при живых задачах.** → Сразу возвращает Session человеку; задачи не убиваются,
   журнал и строка Autopilot их называют.
8. **Q8. Отказ кнопки Canvas.** → Четыре отказа остаются отказами и видны toast-ом: dev-сборка worfy на своём
   репозитории, пустой шаблон «Run wave», Vendor без гарантий Harness-а (Codex без hook-ов), Run того же Epic-а на
   Linked machine. Занятый Orchestrator — не отказ, а ожидание.
9. **Q9. Autopilot из Session без человека.** → Остаётся отказом (`chat-confirm.ts:240`).

Новое требование владельца (раунд 1): системное окно подтверждения старта (`dialog.showMessageBox`,
`src/main/autopilot/chat-confirm.ts:127-145`) заменяется окном внутри worfy. Раунд 2:

10. **Одно окно на две точки входа.** → Просьба агента (`autopilot_start`) и кнопка Autopilot на Canvas открывают одно
    окно запуска в приложении; команда в чате (`/worfy:epic-wave …`) стартует без окна, как сейчас.
11. **Содержимое окна.** → Как в прототипе (Card `card-918c77d9`, `~/Library/Application Support/worfy/CanvasForAI-a2cd477b/cards/card-918c77d9/index.html`):
    кто просит и обратный отсчёт 10 мин (для просьбы агента), Project, Epic или очередь, Ticket-ы и сколько Wave
    осталось, Vendor Orchestrator-а, прогноз против budget, Limits, Modes (только чтение), выбор Run mode, уведомление
    «Orchestrator занят».
12. **Ожидание после окна.** → Видно в строке Autopilot на Canvas с кнопками «Start now» (маленькое окно подтверждения со
    списком того, что остановится) и «Cancel».
13. **Клавиатура.** → Фокус на Cancel, Esc закрывает, ⌘↩ запускает.
14. **Защита от клика агента по окну.** → Не нужна (99,9 % не случится, и если случится — не катастрофа): никаких мер
    против клика или CDP, вопрос больше не поднимать.
15. **Выбор прототипа, принятый как есть.** → Основная кнопка при занятом Orchestrator-е — «Start when free»; «Interrupt
    and start» — красная (новый цвет, в F-SPEC его ещё нет); Run mode по умолчанию — из Settings.
