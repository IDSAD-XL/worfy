## Question

Чем заканчивается карта, и что значат три пожелания владельца: старт Autopilot-а при идущей работе, Autopilot не по одному Epic-у, Work track по датам?

## Answer

Ответы владельца 2026-11-05 («со всем согласен» — все рекомендации):

1. **Q1. Финиш.** Одна карта, два spec-а: `worfy-autopilot-queue` (старт при идущей работе + очередь Epic-ов: оба меняют Run и его цикл) и `worfy-work-track` (область Flight Recorder, свой код и риски, раздаётся параллельно).
2. **Q2. Старт при идущей работе.** Старт принят, Run ждёт, пока у Orchestrator-а кончатся фоновые задачи, ход и очередь; ожидание видно в строке Autopilot и в Run history; затем Run перезапускает Session и идёт. Кнопка «Start now» останавливает задачи после подтверждения. В тот же Epic: отказ кнопки Canvas — toast, а Run, остановленный ошибкой, не оставляет Session unattended (случай 2026-11-03). Отвергнуты: старт без перезапуска (Session под человеком — стоп на первом запросе разрешения), всегда останавливать задачи, отдельная Session (Out of scope).
3. **Q3. Несколько Epic-ов.** Очередь: Run идёт по списку Epic-ов по порядку, закончил один — берёт следующий; при запуске можно выбрать «все принятые Epic-и с готовыми Ticket-ами». Смешанные Wave-ы — Out of scope.
4. **Q4. Данные Work track.** Сначала считается из источников Run history без нового хранилища (ADR-0092 в силе); то, что источник потерял, показано пометкой «данных нет». Журнал работы — только если не хватит (research 04).
5. **Q5. Что входит.** Вся работа Project-а на этой Machine: Run-ы, ручные ходы Orchestrator-а, другие Session на Canvas и их Subagent-ы, PR / merge / CI из GitHub, run-ы gate, смены статуса Ticket-ов. Работа Linked machine — в «Not yet specified»; её PR и merge видны через GitHub.
6. **Q6. Имя.** «Work track» — пункт в Runs рядом со списком Run-ов; глоссарий получает Work track, Run history, Flight Recorder.
