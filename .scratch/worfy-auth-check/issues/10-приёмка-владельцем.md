Type: task
Status: open

«Решения владельца», Q1–Q11

Кто: владелец, с Orchestrator-ом. Autopilot этот Ticket не берёт.

Платформенный Ticket: приёмка идёт в Mac Stable и в Stable на ПК владельца (Windows). Кода не вливает.

## Что происходит

- К claim Ticket-ы 01, 03–05, 07–09 влиты: модель Health check, иконка на rail, строка GitHub access Project-а,
  сообщения PR inbox, PR badges и прочих фич, строки Codex, Browser и Link, документы.
- Ticket 06 (SSO) может быть ещё не готов: он ждёт ответа тестера через Ticket 02. Готов — SSO входит в эту приёмку;
  нет — SSO принимается отдельно после него.
- Аналитики нет. Мерило — живые Machine владельца и слова владельца.

## Что делаем

1. Orchestrator проходит пункты «Готово, когда» spec-а без (вручную) с доказательствами: CI каждого PR, имена test-ов
   из файлов на `main` (test утечки токена — по имени).
2. Orchestrator обновляет Stable до `main` с этими Ticket-ами на Mac и на ПК (с согласия владельца).
3. Владелец на Mac Stable и на ПК, на Project-е с origin на GitHub:
   - токен окружения: `GH_TOKEN` задан (`launchctl setenv` / `setx`), `github.account` пуст — строка GitHub access
     называет переменную, а не значение; при рабочем токене — жёлтая точка и «Use <login>»; щелчок пишет
     `github.account`, строка становится `ok`;
   - нет `github.account` и токен окружения не работает — красная точка; в PR inbox — строка причины и «Open Health
     check»; щелчок открывает Settings → Health со строкой Project-а;
   - нет моделей qmd — жёлтая точка, не красная;
   - Codex без входа — жёлтая точка, строка с «Sign in to Codex…»; в Session Codex — `notice` с «Open Health check»;
   - иконка: серое кольцо до первого отчёта, без точки при всех `ok`; Command palette «Health check» открывает
     Settings → Health; First run не открывается сам на строках Project-а;
   - после опыта переменная снята, тестовый токен отозван.
4. SSO — если Ticket 06 влит: на выводе тестера или его повторе — строка со ссылкой авторизации; иначе запись в «Итог»,
   что SSO принимается отдельно.
