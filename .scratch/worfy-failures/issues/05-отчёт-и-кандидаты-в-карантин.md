## Что делаем

1. `harness/lib/gate-failures/report.mjs` — `gate-failures report [--days 14] [--computer <name>] [--json]`:
   - читает файлы run-ов и повторов через `listRuns` Ticket-а 01 — свои и из `imported/` (их кладёт Ticket 06), за
     `--days`; run с `dirty: true` (шёл не по `head`) в классы и кандидаты не входит, отчёт называет их число
     отдельной строкой;

   - по test-у: число каждого класса, компьютеры и платформы, последний SHA, последняя ошибка; порядок —
     стабильно красные, затем flaky по числу, затем без повтора; записи шагов без test-а — отдельным списком;
   - run-ы «под нагрузкой» — отдельной строкой с числами («19 failed, 17 green alone»);
   - кандидаты: карантин — flaky в ≥ 2 разных run-ах за 14 дней (Q4); Windows exception — стабильно красный только
     на `win32` (Q5); `--json` — тот же отчёт одним объектом с полем `candidates`.
2. `scripts/quarantine-suggest.mjs` (worfy) — `node scripts/quarantine-suggest.mjs [<report.json>]` (без файла — сам
   зовёт `gate-failures report --json` через `profile` Harness): для каждого кандидата печатает готовый JSON записи
   и имя файла `test/quarantine/<id>.json`: `runner`, `file`, `test`, `platforms`, `reason` (класс, run-ы, SHA,
   первая строка ошибки), `owner: "<ticket>"`, `since` — сегодня UTC, `until` — +14 (Windows exception — +45,
   `owner` — `worfy-windows 117`, `kind`). Пропускает test-ы, у которых запись уже есть; печатает предупреждение,
   если предел 15 или 30 был бы превышен. Ничего не пишет.

## Итог

Сделано в ветке `worfy-failures/05`.

- `harness/lib/gate-failures/report.mjs` — подкоманда `gate-failures report [--days N] [--computer <имя>] [--json]`
  (`--days` по умолчанию 14). Класс ставится каждому падению test-а в run-е по повторам этого run-а на том же SHA и
  том же компьютере: хоть один зелёный поодиночке — flaky; иначе хоть один красный — стабильно красный; иначе (повтора
  не было, `rerun` = `null`, повтор на другом SHA, `exit` = `null`) — без повтора. Run с `dirty: true` и его повторы
  не входят ни в классы, ни в кандидатов, строка `N dirty run(s) skipped`. Строка «под нагрузкой» — у run-а, где
  больше половины упавших test-ов зелёные поодиночке. Записи шагов без test-а — свой список по `step`.
- Кандидаты — из падений последних 14 дней, какое бы ни было `--days`: карантин — flaky в ≥ 2 run-ах с разной парой
  (SHA, компьютер); Windows exception — стабильно красный на `win32`, и на тех же SHA на другой платформе test не падал
  (или падал, но был зелёным поодиночке). Test, подходящий под оба, — только Windows exception.
- `--json` — один объект `{ version: 1, kind: "report", at, days, computer, runs, tests, steps, underLoad, candidates,
  skipped }`; его схема (zod) — в `test/contract/gate-failures-report.test.ts`.
- `scripts/quarantine-suggest.mjs [<report.json>]` — без файла зовёт `harness/bin/gate-failures report --json` этого же
  репозитория (той же версии, что скрипт); печатает имя `test/quarantine/<id>.json` и JSON записи. Ничего не пишет.
  Пределы и сроки `test/quarantine.ts` повторены в скрипте (он на Node без TypeScript); unit test сверяет их с
  `test/quarantine.ts`.
- Test-ы: contract `test/contract/gate-failures-report.test.ts` (6), unit `test/unit/quarantine-suggest.test.ts` (6);
  fixture — `test/fixtures/gate-failures/report/` (`base/`, `dirty/` — папка состояния gate; `report.json` — отчёт
  `--json` над `base/`). Contract test копирует fixture во временный `CLAUDE_GATE_STATE` и сдвигает все `at` так, что
  новейший run — двухчасовой давности.
- Первый падающий test был красным, потому что подкоманды `report` не было (exit 2, usage).
- Страницы `docs/features` не правились: раздел «Failure records» — Ticket 08.
- Gate fast на Mac 2026-11-05: первый run — exit 2 при load average 52: упали `test/contract/codex-parity.test.ts` (row 2,
  Stop и красный gate) и `test/contract/login-shell-capture.test.ts:138`; оба файла этот Ticket не трогает, `codex-parity`
  поодиночке зелёный, а голый `pnpm test` перед этим прошёл целиком. Второй run остановлен по пределу времени фоновой
  команды (30 мин), третий — `[gate] green (fast)`, exit 0, на `15d7cfcb1`.

Решено без владельца, подтвердить:

1. Класс считается на каждое падение в run-е (run × test), а не один на пару (test, SHA): так «flaky 2 раза, `darwin` и
   `win32`» — два падения на разных SHA. Повтор всегда на SHA своего run-а, так что пара (test, SHA) соблюдена.
2. `--computer` сравнивает и имя, и id компьютера.
3. id записи — слова имени файла test-а и последней части имени test-а через `-`, до 60 знаков; у Windows exception —
   суффикс `-win32`; занятый id получает `-2`, `-3`. Уже есть запись на тот же test (runner, file, test) — кандидат
   пропущен со строкой на stderr, под любым id.
4. `owner` записи карантина — заглушка `<ticket>`, её заполняет тот, кто кладёт запись. Поле `kind` пишется только у
   Windows exception: записи карантина в `test/quarantine/` его не несут.
5. Кандидат не из раннеров worfy (не vitest-файл `test/unit|contract`, не spec `test/e2e`) — пропущен со строкой на stderr.
