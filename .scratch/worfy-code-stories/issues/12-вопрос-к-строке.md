  Ticket 04. Хранилище — Ticket 08.

## Что делаем

1. Выделение строк в блоке кода story → поле вопроса рядом с выделением.
2. Невидимый агент (`oneShot` Vendor-а Project-а) получает:
   - story, diff PR (в тексте запроса), файл Ticket-а, текст PR и вердикты;
   - выделенные строки и вопрос.
3. Ответ по JSON Schema: текст, цитата строк и источник — код, story, текст PR или вердикт. Если опоры нет, ответ
   так и говорит: «опоры нет».
4. Ответ появляется рядом со строкой. Progress bar — на месте поля, пока агент работает; остановка — как в Ticket-е 04.
5. Ответы хранятся вместе со story (хранилище Ticket-а 08) и видны при следующем открытии. Для PR коллег — без их слов,
   как story по кнопке (ADR-0105).
6. На Project-е с Codex без `oneShot` поле показывает причину из Ticket-а 04.
