Kind: pr · Epic: worfy-code-stories · Ticket: 13 · PR: - · Language: ru

## 1. Что было не так

Вид Story (Ticket 09) отмечал прочитанные сегменты полоски только пока вид открыт: после перезапуска все шаги снова
непрочитанные. Последний экран «Проверить себя» показывал одни вопросы — ответить на них и увидеть правильный ответ со
ссылками на строки было нельзя.

## 3. Ссылка строки открывает шаг, который показывает эти строки

Code: `src/renderer/stories/StoryView.tsx:139-147` · key lines: 145

```tsx
function stepWithLines(screens: readonly Screen[], lines: string, labels: StoryLabels): LinesStep | null {
  const match = /^(.+):(\d+)(?:-(\d+))?$/u.exec(lines)
  if (match === null) return null
  const [, path, first, last] = match
  const from = Number(first)
  const to = last === undefined ? from : Number(last)
  const index = screens.findIndex((screen) => fragmentsOf(screen).some((fragment) => fragment.path === path && fragment.startLine <= to && fragment.endLine >= from))
  return index < 0 ? null : { index, name: screenName(screens[index]!, labels) }
}
```

- Что делает: разбирает строку ответа `path:line` или `path:from-to` и ищет первый экран-шаг, фрагмент которого из того
  же файла пересекается с этими строками; его номер становится ссылкой. Строку, которую не показывает ни один шаг,
  экран пишет текстом, с подсказкой.
- Почему здесь: экраны story знает только `StoryView.tsx`; почему строка без шага — текст, а не ссылка в никуда, не
  записано.
- Без него: ссылка вела бы на первый шаг того же файла, даже с другими строками (мутант «только путь» убит test-ом).
- Требование: [Что делаем, пункт 1](../issues/13-проверить-себя-и-отметки-прочитано.md#что-делаем)
- Риски и пробелы test-ов: номера строк ответа сравниваются с номерами фрагмента story, то есть head PR; если код с тех
  пор сдвинулся, ссылка всё равно открывает шаг story.

## 4. Отметка шага — Ticket и номер шага внутри него, как у ответов Ticket-а 12

Code: `src/renderer/stories/StoryView.tsx:120-129` · key lines: 123

```tsx
function markOf(screen: Screen): StoryReadMark | null {
  switch (screen.kind) {
    case 'step':
      return { ticket: screen.place.ticket, step: screen.place.step }
    case 'not-ready':
      return null
    default:
      return { screen: screen.kind }
  }
}
```

- Что делает: даёт экрану имя для хранения: шагу — `{ ticket, step }` его главы (в story PR — Ticket заголовка),
  остальным экранам story Epic-а и «Проверить себя» — их вид; глава без готового PR отметки не получает.
- Почему здесь: бриф требует ключевать отметки как ответы Ticket-а 12 (`about.ticket`/`about.step`): тогда глава Epic-а,
  ставшая готовой раньше, не сдвигает отметки следующих шагов.
- Без него: отметка по номеру экрана поехала бы, как только перед шагом появится новый (мутант `screen.number` убит
  test-ом story Epic-а).
- Требование: [Что делаем, пункт 3](../issues/13-проверить-себя-и-отметки-прочитано.md#что-делаем)
- Риски и пробелы test-ов: при правке story шаг с тем же номером, но другим текстом, останется отмеченным — отметки
  хеша текста не несут, в отличие от ответов.

## 5. Ключ называет main один раз, отметки до него ждут

Code: `src/renderer/stories/story-marks.ts:61-68` · key lines: 65, 66

```ts
  void invoke('stories.marks', { projectId, story }).then((result) => {
    // A reply of another shape (a stand-in of main) keeps nothing.
    if (!result.ok || !Array.isArray(result.value.read) || !Array.isArray(result.value.checks)) return
    const { key, read, checks } = result.value
    entry.key = key
    for (const mark of entry.pending) if (!read.some((one) => sameMark(one, mark))) send(projectId, key, mark)
    for (const answer of entry.pendingChecks) sendCheck(projectId, key, answer)
    entry.pending = []
```

- Что делает: при первом показе story спрашивает у main `stories.marks` — ключ (тот же `answersKey`, что у ответов на
  строки), прочитанные экраны и ответы; экраны, прочитанные до ответа main, и ответы, данные до него, уходят после.
- Почему здесь: `answersKey` читает модель workflow; читать её на каждый поворот экрана дорого, поэтому окно получает
  ключ один раз и пишет по нему (`stories.markRead`, `stories.selfCheck`).
- Без него: первая отметка (экран открытия) терялась бы, ведь она ставится раньше, чем main ответит (мутант убит
  test-ом).
- Требование: [Что делаем, пункт 3](../issues/13-проверить-себя-и-отметки-прочитано.md#что-делаем)
- Риски и пробелы test-ов: ключ пишет окно; запись под чужим ключом возможна, но это данные worfy на этой машине,
  а не репозиторий.

## 7. Что сознательно не меняли

Вид открывается, как раньше, с первого экрана, а не с первого непрочитанного: Ticket просит только отметки. Отметки
ничего не требуют при приёмке — это вне скоупа. Строку о качестве вопросов Ticket называет в `SKILL.md`, но правила
story PR теперь живут в `harness/skills/ship-ticket/story-pr.md`: строка добавлена туда.

- Требование: [Вне скоупа](../issues/13-проверить-себя-и-отметки-прочитано.md#вне-скоупа)

## Проверить себя

1. Почему отметка шага хранит Ticket и номер шага внутри главы, а не номер экрана?
   - Ответ: глава Epic-а, ставшая готовой, добавляет экраны перед следующими шагами; номер экрана сдвинулся бы, а пара
     Ticket и шаг внутри него — нет.
   - Строки: `src/renderer/stories/StoryView.tsx:120-129`
2. Что происходит с экраном, прочитанным до того, как main назвал ключ?
   - Ответ: он ждёт в `pending` и уходит в `stories.markRead` сразу после ответа `stories.marks`, если main его ещё не
     хранит.
   - Строки: `src/renderer/stories/story-marks.ts:61-68`
