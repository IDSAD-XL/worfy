## 4. Ответ без опоры не цитирует строк, путь только внутри checkout-а

Code: `src/main/stories/ask.ts:79-91` · key lines: 86, 88

```ts
export function readAskAnswer(value: unknown): { ok: true; answer: AskAnswer } | { ok: false; reason: string } {
  const parsed = askAnswerSchema.safeParse(value)
  if (!parsed.success) {
    const shown = parsed.error.issues.slice(0, 5).map((issue) => `${issue.path.length > 0 ? issue.path.map(String).join('.') : 'the answer'}: ${issue.message}`)
    return { ok: false, reason: shown.join('; ') }
  }
  const answer = parsed.data
  if (answer.source === 'none' && answer.lines.length > 0) return { ok: false, reason: 'lines: an answer with no support quotes no lines' }
  for (const [index, line] of answer.lines.entries()) {
    if (!insideCheckout(line.path)) return { ok: false, reason: `lines.${String(index)}.path: a file inside the checkout, relative to it` }
    if (line.to < line.from) return { ok: false, reason: `lines.${String(index)}.to: the last line comes after the first` }
  }
  return { ok: true, answer }
```

- Что делает: сверяет ответ агента со схемой (текст, источник `code`/`story`/`pr`/`verdict`/`none`, строки) и с
  правилами: у `none` строк нет, путь — относительный, без `..`. Иначе — ошибка с причиной, ничего не сохраняется.
- Почему здесь: ответ модели — непроверенный ввод; строки потом хранятся ссылками `path:line@commit`, и путь из ответа
  не должен указывать за пределы checkout-а.
- Без него: «опоры нет» могло бы прийти с цитатой, а ссылка — на файл вне Project-а.
- Требование: [Что делаем, пункт 3](../issues/12-вопрос-к-строке.md#что-делаем)
- Риски и пробелы test-ов: соответствует ли текст ответа строкам, которые он цитирует, не проверяется — только форма.

## 5. Ответы хранятся по тому, что story называет, с хешем текста

Code: `src/main/stories/store.ts:112-125` · key lines: 119, 120, 124

```ts
/**
 * The key the answers of `story` are kept under — what the story names, so an edit keeps them. A committed story
 * (no commit in its header): its file. A story made by the button: `owner/name#N` for a PR, as saveStory keeps it. An
 * Epic story: its file, else `epic:<name>`. Nothing named: `story:` and its digest, so a question is still kept.
 */
export function storyAnswersKey(story: StoryFile, names: StoryNames): string {
  if (story.kind === 'pr') {
    if (story.header.commit === null && names.file !== null) return names.file
    if (story.header.pr !== null && names.repo !== null) return `${names.repo}#${String(story.header.pr)}`
    if (names.file !== null) return names.file
    return `story:${storyDigest(story)}`
  }
  return names.file ?? `epic:${story.header.epic}`
}
```

- Что делает: даёт ключ, под которым `stories.json` данных worfy хранит ответы: файл story (путь под корнем Tickets) для
  story из файла, `owner/name#N` для story по кнопке, `<epic>/story.md` или `epic:<name>` для story Epic-а. Ключ считает
  main по модели workflow и remote-у Project-а; каждый ответ несёт SHA-256 текста story, о котором спросили.
- Почему здесь: правка story (шаг «Что нашёл review» после merge) не должна терять ответы; вид сравнивает хеш ответа с
  хешем показанной story и помечает ответ к прежнему тексту. Хранилище одно: `addStoryAnswer` Ticket-а 08 теперь пишет
  по этому ключу, поле `answers` у story по кнопке убрано. `open.ts` (его правит Ticket 10) не тронут.
- Без него: любая правка story отрывала бы ответы; было бы два места для ответов.
- Требование: [Что делаем, пункт 5](../issues/12-вопрос-к-строке.md#что-делаем)
- Риски и пробелы test-ов: story из файла без записи в модели (Epic не найден) хранится по хешу, и правка её
  отрывает ответы; e2e проверяет ответ после перезапуска, но не после правки story.

- Что делает: для каждой строки кода шага отдаёт блоку Markdown то, что стоит после неё: сохранённые ответы о строках,

  вопрос в работе (`onBusy`), новое выделение и «Задать вопрос» поле не заменяют; Esc и «Отмена» возвращают фокус на
  кнопку. Слова поля и ответа — на языке story (`labels.json`).
- Почему здесь: только блок кода знает, где кончается строка; номера и шаг ответа (`about`) сохраняются, поэтому ответ
  встаёт на то же место после перезапуска.
- Без него: ответ оказался бы под всем фрагментом, а не рядом со строкой.
- Требование: [Что делаем, пункты 1 и 4](../issues/12-вопрос-к-строке.md#что-делаем)
- Риски и пробелы test-ов: выделение мышью проверено в jsdom и e2e на одной и двух строках; выделение, которое
  начинается вне блока кода, поле не открывает.
