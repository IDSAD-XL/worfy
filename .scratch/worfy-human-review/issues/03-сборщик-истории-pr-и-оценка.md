# 03 — Сборщик истории PR и оценка: `bin/review-history`

Type: task
Status: open
Blocked by: —
Source: [spec.md](../spec.md), «Решения владельца 2026-11-07», п. 3, 4, 8; «Как работает» → «Частная папка», «Сбор истории»; «Сгенерированное и решения без владельца», п. 1, 2; «Вопросы владельцу», Q2, Q9; [исследование](../../../docs/research/2026-11-07-human-review-из-истории-pr.md), разделы 1–6, 8

Платформенный Ticket: новый скрипт Harness, пути ОС, `gh` на Mac и Windows — Windows verdict до merge (ADR-0056).
Глубина ревью — `high`: скрипт держит в руках слова коллег; ошибка фильтра (бот или автор в голосе команды) или
забытый `raw/` держит merge.

## Что происходит

- Скрипта, который читает историю ревью проекта, нет. В приложении PR читает `src/main/github/prs.ts` (`gh pr list`,
  без ревью и комментариев к строкам), с токеном аккаунта Profile-а (`:12-16`, `accountAuth` `:146`).
- Session получает `GH_TOKEN` аккаунта `github.account` от hook-а `gh-token-env.mjs`
  (`harness/profiles/README.md:192`).
- В папке Profile-а нет места для частных данных генератора; `state/` уже вне истории git Harness home
  (`harness/bin/project-connect:108-118`), контракт — `harness/profiles/README.md:24-38`.
- Замеры исследования: 100 merged PR одним GraphQL-запросом — 32 очка; боты — 68% знаков; текст людей — около
  1 250 знаков на PR (раздел 3).

## Что делаем

1. `harness/bin/review-history` (Node, ADR-0055), подкоманды из spec, «Сбор истории»: `fetch [--since <дата>]`,
   `estimate`, `probe`, `stats`, `clean`. Общие флаги: `-C <папка проекта>`, `--json`.
2. Папка — `<_resolved.dir>/state/human-review/` (Q2 (а), подтверждено владельцем 2026-11-07; путь задан в одном месте скрипта).
   `raw/` — JSONL по PR; `meta.json` — окно, счётчики, дата и курсор последнего PR.
3. GraphQL через `gh api graphql` с `$endCursor`, запросы по одному; ошибка лимита — ждать `retry-after` /
   `x-ratelimit-reset`, не больше 3 повторов, потом exit 1 с причиной. PR с более чем 30 ревью или 50 комментариями
   дочитываются отдельным запросом.
4. Окно: PR, обновлённые за 12 месяцев, у которых есть ревью, не больше 500. Фильтр: `__typename = Bot`, `[bot]`,
   `ignore.json` (логины и префиксы тела — создаётся с пустыми списками, если его нет), автор PR, внешние
   (`CONTRIBUTOR`, `NONE`) — как контекст нити. Определение «содержательного» — spec, «Сбор истории».
5. `estimate`: счётчики, знаки, оценка токенов по формуле spec с пометкой «estimate», `voice: yes` или
   `voice: no (N of 30)`. Exit 0 в обоих случаях.
6. `probe`: тот же фильтр, без записи текстов на диск; останавливается на 30-м содержательном комментарии.
   Exit 0 — ответ; exit 3 — нет `origin` на GitHub, нет `gh` или нет доступа (одна строка причины).
7. `stats`: механические числа для `research.md` (spec, «Сбор истории»), JSON.
8. `clean` удаляет `raw/` — литеральный путь, без glob.
9. Контракт Profile-а: строка `state/human-review/` в дереве «Where it lives» `harness/profiles/README.md`.

## Готово, когда

- [ ] `fetch` на fixture-истории (боты `Bot` и служебный `User` из `ignore.json`, автор PR, внешний, agent-отчёт
      с префиксом) пишет в `raw/` только тексты команды и контекст; test называет каждый отброшенный вид.
- [ ] `estimate` печатает число PR, комментариев по видам, содержательных, ревьюеров, знаки, оценку токенов и
      `voice`; на fixture-е с 29 содержательными — `voice: no (29 of 30)`, с 30 — `voice: yes`.
- [ ] Окно: PR старше 12 месяцев и 501-й PR не читаются; PR, одобренный без комментариев, считается.
- [ ] `probe` не пишет ни одного файла (test сравнивает дерево Harness home до и после) и останавливается на 30-м
      комментарии (stand-in `gh` считает запросы).
- [ ] `fetch --since` читает только новое; `clean` удаляет `raw/` и ничего больше.
- [ ] Ошибка лимита — повтор после `retry-after`; после трёх — exit 1 с причиной, `raw/` не остаётся наполовину.
- [ ] Global `gh` не переключается: в test-е stand-in видит `GH_TOKEN` и ни одного `gh auth switch`.
- [ ] Test проходит на Windows (shell test в своём job-е, `test/harness-shell-tests.ts`); `ci-ok` на PR зелёный;
      Windows verdict есть.
