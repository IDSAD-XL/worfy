## Что происходит

- В plugin-е `worfy` нет skill-а, который читает историю ревью. `bin/review-history` (Ticket 03) собирает данные,
  считает оценку и механические числа, но не раскладывает комментарии по уровням и темам.
- `harness/evals/lib/coverage.json` требует случай eval или запись в `uncovered` для каждого нового файла правил;
  `node scripts/eval-harness.mjs --dry-run --changed origin/main` выходит с exit 1, если карта не совпадает.
- Тексты plugin-а — английские (ADR-0074), `node scripts/check-cyrillic.mjs` это проверяет.

   — `review-history clean`.

   `/worfy:code-review`. Если 80% и больше содержательных комментариев — от одного человека, сказать это прямо.
4. Отложить 5 PR для проверки (Q5 (а)) до анализа: номера — в `meta.json`, анализ их пропускает.
5. `harness/skills/human-review-setup/analyse.md` — шаг 4: Subagent-ы по пачкам из `raw/` по областям кода (верхние
   папки или репозитории), каждый комментарий — уровень (let go, nit, question, heads-up, followup, argued, blocker)
   и тема; признаки «настоял» — `CHANGES_REQUESTED`, `isResolved`, правка кода после комментария, повтор в разных PR.
   Итог — `research.md`: разделы `## R<n> — <заголовок>` с числами из `review-history stats`, долями и ссылками на
   комментарии; ревьюеры — метками «ревьюер A», без логинов. Обязательные разделы: triage (молчаливый approve и
   исключения «маленький — не значит безопасный», просьбы разделить PR), темы по областям, «не трогать», голос по
   уровням (длины, обороты, регистр, наклоны), состояния ревью.
6. `coverage.json` — оба файла в `uncovered` с причиной «No case yet: worfy-human-review 12 adds cases».
