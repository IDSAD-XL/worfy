# worfy-guide — короткая живая справка внутри приложения

Status: готов к работе после `worfy-onboarding` 13 и 14
Source: слово владельца 2026-10-31, grill в два раунда, вопросы Q1–Q23
Ticket-ы: Epic `worfy-guide`, 21 Ticket, нумерация с 01. Шапка — как у worfy-onboarding (Type:/Status:/Blocked by:/Source:)

## Цель

Owner: «Теперь нужна документация прямо в приложении, но в сильно сжатом и упрощенном виде, с графикой, диаграммами, визуализацией». Одновременно нужны простое объяснение и технические детали реализации. Главное: читается быстро и понятно.

Guide дополняет `docs/features/`, а не заменяет их. Страницы остаются полной версией и источником. Guide открывают, чтобы за минуту понять функцию, и там же можно увидеть, как она устроена в коде.

Читатель (Q2): разработчик, новый в worfy, который знает Claude Code, Git и PR. Термины worfy Guide объясняет, общие инженерные — нет.

## Как устроено

**Окно (Q3, Q4).** Окно поверх интерфейса, как Keyboard Shortcuts: список Topic-ов слева, Topic справа. Работает без Project и без сети. Открывается из Help ▸ worfy Guide, из Command palette (каждый Topic — отдельная строка поиска), по ссылке из Getting started и First run. Само не открывается никогда. Контекстного «?» в первой версии нет, решение после пилота.

**Topic (Q5).** Один экран:

```
┌ схема (живая) ──────────────────┐
│ короткий текст                  │
├ ▸ Under the hood (свёрнут) ─────┤
│ схема потока данных             │
│ текст, таблица главных файлов   │
│ важные лимиты                   │
└ Full page ↗ ────────────────────┘
```

Числа слов — ориентир, не лимит: примерно 60 EN / 80 RU на простом уровне и 150 EN / 200 RU в Under the hood. Test-а на число слов нет. Объём автор решает по каждому Feature: цель — быстрое чтение, а не короткий счётчик.

**Содержание (Q7, Q18).** Map of worfy (из `docs/features/concepts.md`) и 12 Topic-ов:

| Topic | Страницы-источники |
|---|---|
| Canvas | canvas, epic-frames, focus-mode |
| Sessions | sessions, transcripts-and-usage |
| Workflow | workflow |
| Autopilot | autopilot |
| Gate and GitHub | gate-and-github |
| Terminal | terminal |
| Browser | browser |
| Cards | cards |
| Projects | projects |
| Link | link |
| Harness | harness, skills-agents-and-hooks |
| The window and your data | app-shell, notifications, storage-and-diagnostics |

Страница `onboarding` своего Topic-а не получает: новому пользователю этот путь показывает Getting started.

**Графика (Q6, Q13, Q14).** Собственный SVG, CSS и Web Animations: потоки движутся по стрелкам, наведение подсвечивает связи, проигрыватель шагов показывает процессы, блоки Map of worfy ведут в Topic-и. Библиотека `motion` — только если без неё сцены заметно хуже. Схемы похожи на настоящий интерфейс. Стиль выбрал owner в Ticket-е 02 из трёх работающих направлений: Living Canvas, правила — в разделе «Стиль: Living Canvas» ниже.

**Языки (Q8, Q16, Q17).** Английский основной, русский полный. Переключатель EN / RU только в шапке Guide, остальной интерфейс остаётся английским. По умолчанию русский, если система на русском, иначе английский; выбор запоминается. Подписи на схемах переводятся, технические термины и названия UI остаются английскими. Новый Topic пишется сразу на двух языках, test требует обе версии каждой строки. Позже английский может уйти вперёд перевода: отчёт об отставании это показывает, перевод догоняют пачками.

**Где живёт содержание (Q9).** В коде, `src/renderer/guide/`, попадает в сборку. Каждый Topic называет свои страницы `docs/features/*.md` и commit, с которым сверен. PR, меняющий страницу, не обязан менять Topic. Отчёт об отставании работает как у перевода страниц и входит в ежемесячный аудит.

**Ссылки (Q9, Q20).** Full page и файлы Under the hood ведут на GitHub, на commit этой сборки; если он неизвестен, на `main`.

**Производительность и доступность (Q21).** Guide — отдельный чанк, загружается при открытии. Закрытый Guide ничего не анимирует, открытый анимирует только видимую схему. `prefers-reduced-motion` даёт статичную схему. У каждой схемы есть текстовое описание для screen reader.

### Стиль: Living Canvas (решение владельца 2026-10-31)

Образец — направление 1 на Card «Guide — three directions: Map of worfy» (Ticket 01). Ниже только то, что в нём
видно; в скобках — строки `index.html` этой Card на 2026-10-31. Чего в прототипе нет, сказано прямо.

**Из чего строится схема.**

- Схема — один SVG с `viewBox` 1200×720, масштабируется целиком (`preserveAspectRatio="xMidYMid meet"`) [458, 73].
- Canvas — рамка с точечным полем: узор 16×16, точка r 1,1 цвета `--canvas-dot` на `--canvas`; рамка rx 14,
  обводка `--border-strong` 1,5 px [672–674, 683, 135].
- Epic — рамка внутри Canvas: rx 10, заливка 8 % цвета группы Workflow, обводка 70 % того же цвета, 1,5 px [697, 136].
- У рамки нет отдельного блока: её блок — плашка-вкладка на верхней кромке. Плашка высотой 32, rx 8, фон `--surface`,
  обводка цвета группы 1,5 px, точка r 4,5, название 14 px / 700; справа от неё — подпись 11 px цвета
  `--text-muted` [684–691, 139–141].
- Node — прямоугольник 160×58, rx 8, фон `--surface`, обводка `--border-strong` 1 px [662, 703, 124]. Шапка
  высотой 26 залита 13 % цвета группы поверх `--surface`, под ней линия `--border`, слева точка r 4 цвета группы,
  название 13 px / 650 [704–707, 125–127]. Под шапкой — подпись 11 px `--text-secondary`; длинная переносится на две
  строки по 10,5 px [708–716, 128].
- Вычисляемая вещь, которая не хранится (Wave), рисуется пунктиром `4 3` цвета группы [129]. Wave — не Node, а плашка
  «Ready wave · N» на рамке Epic: высота 26, rx 13, заливка 16 % цвета группы, пунктир `4 3`, 12 px / 650 [720–726, 148–150].
- Вложенность рисуется положением, а не линией: Node-ы внутри рамки Canvas, Ticket внутри рамки Epic; связи
  «Canvas → Node» и «Epic → Ticket» линий не имеют [268, 760–762].
- То, что не Node (Linked machine, Machine, Project, Harness, Profile, Gate, Autopilot, Limits, Terminal AI), стоит
  вне рамки Canvas тем же прямоугольником Node, под подписями областей «OTHER MACHINE», «THIS MACHINE», «NOT NODES»:
  11 px / 600, разрядка 0,06 em, `--text-muted` [664–669, 675–679, 719, 153, 388].
- Связь — кубическая кривая Безье от середины стороны блока к середине стороны другого, плечо `max(26, 0,42 × длина)`;
  линия `--edge` 1,5 px, на конце наконечник-стрелка [734–738, 763–764, 142, 144, 527–531].
- Все связи одного вида: разных стилей линий под разные виды Edge в прототипе нет.

**Цвета и токены.**

- Прототип не подключает `src/renderer/theme/tokens.css`: он повторяет его значения литералами, светлая тема —
  палитра E, тёмная — Graphite [8–33]. Взятые переменные: `--bg`, `--canvas`, `--canvas-dot`, `--toolbar`,
  `--toolbar-border`, `--surface`, `--surface-raised`, `--selected`, `--border`, `--border-strong`, `--text`,
  `--text-secondary`, `--text-muted`, `--primary`, `--primary-text`, `--accent`, `--segment-track`,
  `--segment-thumb`, `--shadow-node`, `--shadow-control`, `--hover-veil`, шрифты `--font-ui`, `--font-mono` [10–18, 25–29].
- Свои переменные прототипа, которых нет в `tokens.css`: шесть цветов групп `--g-machine`, `--g-project`,
  `--g-workflow`, `--g-agents`, `--g-tools`, `--g-harness` и цвет линий `--edge` [19–21, 30–31]. Три цвета групп
  совпадают с `kind-*`: Workflow = `kind-epic`, Agents = `kind-session`, Harness = `kind-orchestrator`. Три своих:
  Machine, Project, Tools. Блок получает цвет группы через `--c` [34–35].
- Две темы — два набора тех же переменных: `:root` и `[data-theme="dark"]` [9–33]. По умолчанию тема берётся из
  `prefers-color-scheme` и следует за ним, пока пользователь не выбрал тему руками [413–415, 1051].
- В тёмной теме теней нет: `--shadow-node` пустая, у Node снят `drop-shadow` [29, 132–133].
- Оттенки строятся `color-mix(in srgb, …)` от цвета группы и `--surface` или `transparent`, а не отдельными
  токенами [125, 136, 148].

**Анимация.**

- Движутся только точки по связям: по две точки r 3 цвета группы на каждой нарисованной связи, 55 единиц `viewBox`
  в секунду, равномерно, по кругу [660, 764, 146, 560–572]. Двигает их `requestAnimationFrame` и
  `getPointAtLength`, не Web Animations [574–581].
- Остальное — CSS-переходы при подсветке: прозрачность блоков, линий и точек 0,22 s `ease`; подписи связей 0,18 s
  `ease`; обводка Node 0,2 s [112, 116, 124]. Других длительностей и easing в Living Canvas нет.
- Скрытая страница не анимирует: `visibilitychange` останавливает кадр и запускает снова [1053].
- Reduce motion: класс `.rm` на корне снимает все `transition` и `animation`; кадр не идёт, точки стоят неподвижно
  на равных долях связи (`(i + 0,5) / n`); подсветка переключается сразу [207–208, 566, 582–591]. По умолчанию
  берётся из `prefers-reduced-motion` и следует за ним, пока пользователь не нажал переключатель «Reduce motion» [414–415, 1050, 1052].

**Подсветка связей.**

- Наведение, фокус с клавиатуры и выбранный блок подсвечивают одинаково [476–479, 594].
- Подсвечены: сам блок (обводка цвета группы 2 px), его соседи по связям и его связи (линия цвета группы 2,2 px,
  стрелка и точки того же цвета, точка r 4) [130, 143, 145, 147, 596–609].
- Остальное гаснет: блоки до 0,2, линии и стрелки до 0,1, точки до 0 [113–115].
- Подписи связей видны только у подсвеченных: «пилюля» высотой 19, rx 9,5, фон `--surface`, обводка
  `--border-strong`, текст 11 px / 500 `--text-secondary` [116–119, 505–510]. Подпись сдвигается вдоль линии, пока не
  перестанет перекрывать блоки и другие подписи [534–558].
- Фокус и выбор — обводка `--accent` 2,5 px [131, 152]. Клик, Enter или пробел открывают панель справа (ширина 316):
  описание, список связей, Topic, источник; Esc закрывает и возвращает фокус на блок [80, 481–483, 618–655].

**Проигрыватель шагов.** В прототипе его нет. Spec его требует («проигрыватель шагов показывает процессы»), значит, его
вид определяет Ticket 04 по этим правилам, без образца.

**Шрифты, плотность, размеры.**

- Только системные шрифты: `--font-ui` (-apple-system, SF Pro Text, Helvetica Neue), `--font-mono` (ui-monospace,
  SF Mono, Menlo); внешних шрифтов нет [10–11].
- Текст страницы 13/17 px [39]. На схеме: название Node 13 px / 650, вкладки рамки 14 px / 700, плашки 12 px / 650,
  подписи 11 px, перенос 10,5 px, подписи областей 11 px [127–128, 140, 150, 153, 714].
- Плотность Map of worfy: 18 блоков и 25 связей в 1200×720 [284–367]. Место каждого блока задано координатами
  руками, автоматической раскладки нет [663–669].

**Доступность.**

- Блок — `role="button"`, `tabindex="0"`, `aria-label` «название: подпись» [472–474]; SVG — `role="group"` с
  `aria-label` [458].
- Для screen reader рядом лежит скрытый список всех связей «A → B: подпись», SVG ссылается на него через
  `aria-describedby` [1034–1041].

**Чего стиль не делает.**

- Нет проигрывателя шагов, зума и прокрутки схемы, библиотеки анимации, Web Animations API.
- Подписи связей постоянно не показываются, только у подсвеченных.
- Цветом не кодирует вид связи: все линии одного цвета `--edge`, пока не подсвечены.
- Теней в тёмной теме нет.
- Не проверено прототипом, потому что схема на странице одна: «открытый Guide анимирует только видимую схему».

**Расходится с F-SPEC — решить в Ticket-е 03 или 04.** F-SPEC (раздел «Kind colours», ADR-0077) не даёт цвет `kind-*`
линиям, а Card и Terminal оставляет нейтральными. В прототипе подсвеченная линия берёт цвет группы [143], а Card, Terminal
и Browser окрашены цветом группы Tools [125–126]. В тёмной теме цвет Project совпадает с `--accent`, а цвет Tools — с
`--blocked-text` из `tokens.css` [27, 30]. Это схема справки, а не Canvas, но правило F-SPEC о цвете, который не путают
со статусом, касается и её.

## Риски

- **Красивая схема с неверным утверждением.** На страницах `docs/features/` чтение кода оставляло около 1.8 % неверных утверждений, пока отдельный агент не сверял каждое. Поэтому один агент на Topic проверяет каждое утверждение и каждую подпись на схеме по коду.
- **Стоимость.** Оценка 400–500 тысяч токенов на Topic, всего около 6 миллионов без прототипов. Ticket 10 пересчитывает её по факту пилота, до слова владельца об остальных.
- **Topic отстаёт от кода.** Содержание в коде не ломает сборку при изменении функции. Защита: отчёт об отставании в ежемесячном аудите.
- **Анимации нагружают приложение.** Защита: отдельный чанк, анимирует только видимая схема, e2e проверяет закрытый Guide.
- **Зависимость от onboarding.** Панель Getting started меняется в `worfy-onboarding` 13, подсветка в 14. До их merge Epic не раздаётся.

## Соглашения для Ticket-ов этого Epic-а

- Ветка `worfy-guide/<NN>`.
- Глубина ревью `medium`; PR каркаса (03) начинает с `high`.
- Каждый Topic в своём файле; реестр Topic-ов — одна строка на Topic, чтобы параллельные PR почти не конфликтовали.
- Снимки в `.scratch/worfy-guide/evidence/<NN>/`: обе темы, оба языка, reduced motion. Как проверка глазами, без сравнения по пикселям.
- `## Итог` Topic-а называет токены автора и проверки, чтобы пересчитать оценку.
- Topic ссылается только на файлы, которые есть в репозитории: test это проверяет.
