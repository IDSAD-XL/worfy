# 08 — ⌘Z после перетаскивания рамки Epic-а возвращает рамку; сворачивание рамки тоже отменяется

Type: task
Status: claimed — 2026-10-07
Blocked by: —
Source: ручные проверки 2026-10-07, второй круг, проверка M21 ([PR #93](https://github.com/IDSAD-XL/worfy/pull/93), a3a2c50) — Ticket [03](03-elk-раскладка-рамок-epic-ов.md), подраздел [«Ручная проверка 2026-10-07»](03-elk-раскладка-рамок-epic-ов.md#ручная-проверка-2026-10-07); HANDOFF, «Риски и долги»; [spec.md](../spec.md), этап 3

## Что происходит

- Рамку Epic-а тянут за заголовок. Когда её бросают, Canvas (`onNodeDragStop`,
  `src/renderer/canvas/Canvas.tsx:346`) отдаёт её source-у рамок. `moved()`
  (`src/renderer/canvas/sources/epics.ts:459-465`) считает смещение рамки от её автоматического
  места и сохраняет его через `saveEpicChange` (`:152-166`).
- `saveEpicChange` пишет Layout через `applyLayoutOp()` (`:162`, `:164`, `:165`), то есть мимо
  истории ⌘Z. По [ADR-0016](../../../docs/adr/0016-trash-folder-per-entry-undo-in-renderer.md) так
  пишут только автоматические источники. Комментарии `src/renderer/canvas/history.ts:8-12` и
  `src/renderer/canvas/useLayout.ts:84-88` относят к ним и source рамок. Но перетаскивание рамки —
  жест пользователя.
- Поэтому ⌘Z после перетаскивания рамки не возвращает рамку, а отменяет прошлый шаг пользователя.
  В проверке M21 (Stable copy из 6df9791, Canvas Auction) ⌘Z вернул Session Node, удалённый раньше,
  и колонка рамок уехала на x=1620.
- Сворачивание и раскрытие рамки — кнопка в заголовке, `toggleCollapsed`
  (`src/renderer/canvas/nodes/EpicFrameNode.tsx:41`) — идёт тем же путём: `saveEpicChange` с
  `collapsed`, операция `patchData`. Её ⌘Z тоже не отменит. На Stable copy это не проверялось, вывод
  сделан по коду. Есть и вторая причина: `inverseOf` (`history.ts:142`) для `patchData` обратной
  операции не даёт — данные Node-а в историю не пишутся.
- Стопка done внутри рамки открывается и сворачивается в памяти renderer-а (`toggleDoneStack`,
  `epics.ts:90-93`, store `useEpicsUi`). В Layout она не попадает. После перезапуска стопка снова
  свёрнута.

## Что делаем

- Перетаскивание рамки Epic-а — шаг истории ⌘Z, как перетаскивание любого Node-а пользователя.
  ⌘Z возвращает рамку туда, где она стояла до жеста. ⇧⌘Z ставит её туда, куда её бросили. Шаги
  других жестов ⌘Z не трогает.
- Первое изменение рамки создаёт её Node `epic-frame` в Layout (`saveEpicChange`,
  `epics.ts:157-163`). ⌘Z такого шага удаляет этот Node или ставит смещение (0, 0) — решает
  исполнитель. Требование одно: после ⌘Z рамка на прежнем месте, и свёрнута она или раскрыта — как
  до жеста.
- Перетаскивание выделения, в котором есть рамка и Node-ы пользователя, — один шаг (группа
  `grouped()`, `history.ts:237`). Один ⌘Z возвращает всё выделение.
- Сворачивание и раскрытие рамки — тоже шаг ⌘Z. Обратная операция возвращает то состояние, которое
  рамка показывала до нажатия. Ключа `collapsed` в Layout может не быть: тогда рамка свёрнута по
  умолчанию, только когда все её Ticket-ы done (`epics.ts:8-10`). Обратная операция ставит это
  значение явно или убирает ключ — решает исполнитель.
- Стопка done — не шаг истории. Она не часть Layout: живёт в памяти renderer-а и не переживает
  перезапуск, как viewport, который в историю тоже не пишется (`inverseOf`, `history.ts:142`).
  После открытия стопки ⌘Z по-прежнему отменяет прошлый шаг пользователя. Это решение автора
  Ticket-а, без владельца. Если исполнитель видит причину решить иначе, он записывает решение и
  причину в «Итог» и пункт в HANDOFF, раздел «Ждёт владельца».
- Комментарии `history.ts:8-12` и `useLayout.ts:84-88` говорят правду: жесты над рамкой Epic-а идут
  через `LayoutOps`. Автоматическими писателями остаются синхронизация Session Node-ов и source
  Subagent-ов.

ADR не нужен: правило ADR-0016 «в историю пишутся только жесты пользователя» не меняется.
Исправляется путь, которым жест над рамкой пишет Layout.

## Итог

Сделано в ветке `worfy-week/08`, база `origin/main` c539cfd. ADR не заводился: правило ADR-0016
«в историю пишутся только жесты пользователя» не меняется, меняется путь, которым жест над рамкой
пишет Layout.

**Как падал первый test.** `test/unit/epic-canvas.test.tsx`, «⌘Z after a drag of a frame puts the
frame back…»: на `origin/main` первый ⌘Z после перетаскивания рамки вернул удалённый в корзину Note
(единственный шаг в истории), а смещение рамки осталось там, куда её бросили:
`expected { dx: 40, dy: 25 } to deeply equal { dx: 10, dy: 0 }`.

**Что сделано.**

- `saveEpicChange` (`sources/epics.ts`) пишет изменение рамки через `LayoutOps` Canvas-а, то есть
  через `applyRecorded()`: перетаскивание — `move` Node-а `epic-frame`, кнопка сворачивания —
  `patchData` с `collapsed`. Оба — шаг ⌘Z.
- Первое изменение рамки без Node-а `epic-frame`: Node создаётся без записи в историю в точке (0, 0)
  и без данных — рамка выглядит так же, как без Node-а. Шаг — следующий за ним `move` или
  `patchData`. ⌘Z такого шага ставит смещение (0, 0), Node остаётся: удалить его нельзя, он
  `locked`, и main отказывает в `remove`. Решено исполнителем, как разрешал Ticket.
- `collapsed`: обратная операция возвращает прежнее значение ключа; если ключа не было — `null`.
  main сливает данные и не умеет убрать ключ, а `readSaved` читает не-boolean как «по умолчанию».
  Значит, после ⌘Z первого сворачивания рамка снова сама свернётся, когда все Ticket-ы станут done.
  Решено исполнителем, как разрешал Ticket.
- `history.ts`: `inverseOf` и `applyRecorded` принимают `RecordOptions { data }`. `patchData` пишется
  в историю только с `data: true`; текст note по-прежнему не шаг.
- Перетаскивание: `extensions.ts` — `dropNodes()`: весь бросок в одной группе `grouped()`. Node-ы
  Layout-а — один `move`/`moveMany`, Node-ы source-ов — через `moved(context, node, drop)`, где
  `drop = { ops, group }`. Source рамок возвращает promise сохранения, и группа закрывается, когда
  оно закончено. Выделение из рамки и Node-а — один шаг. `Canvas.tsx` зовёт `dropNodes()`.
- Смещение по-прежнему считается от места приземления (snapping Ticket-а 06): `moved()` получает
  уже поправленную позицию, как раньше.
- Стопка done — не шаг, как и было: она не в Layout-е.
- Комментарии `history.ts` и `useLayout.ts` теперь относят жесты над рамкой к `LayoutOps`;
  автоматическими писателями остались синхронизация Session Node-ов и source Subagent-ов.
