# 14 — Бюджет времени: от зелёных проверок до merge по каждому Ticket-у, отчёт о превышении (15 min без UI, 30 min с UI)

Type: task
Status: open
Blocked by: 10
Source: [spec.md](../spec.md), раздел «Решения владельца 2026-10-20: скорость test-ов», решения Q1 и Q2;
скрипт `scripts/critical-path.mjs` (`worfy-reliability` 04, PR #341).

## Что происходит

- `scripts/critical-path.mjs` считает шаги claim → PR → CI → Gate → merge по Ticket-у из журналов
  Autopilot, заголовков Ticket-ов и данных PR (`gh`). Gate — последний комментарий `VERIFIED`; CI —
  последний зелёный workflow run ветки до Gate. Шаг Gate → merge близок к метрике Q1.
- С batch CI (ADR-0068) у PR нет CI run-ов, и шаг CI пуст. После Ticket-а 12 CI на PR вернётся.
- Бюджета и отчёта о его превышении нет.

## Что делаем

1. Метрика Q1 в `scripts/critical-path.mjs`: время на часах от «проверки зелёные» до merge, по Ticket-у.
   «Проверки зелёные» — позднее из двух моментов: последний `VERIFIED` и зелёный CI на head PR (когда
   он есть). Если скрипт не подходит — новый скрипт, и причина в «Итог».
2. Бюджет Q2: без UI — 15 min, с UI — 30 min. Отчёт называет Ticket-ы сверх бюджета: номер, PR, время,
   на каком шаге ушло время (CI, gate, очередь merge).
3. База — замер по последним закрытым Wave-ам до Ticket-ов 11–13; повтор — после каждого из них.

- [ ] «Итог»: база по последним двум Wave-ам — медиана метрики, число Ticket-ов сверх бюджета, команда и
      код выхода; без личных путей.
- [ ] `pnpm lint`, `pnpm typecheck`, `pnpm test` — exit 0; gate full — шаг Orchestrator-а перед merge.
