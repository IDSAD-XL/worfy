# 14 — Бюджет времени: от зелёных проверок до merge по каждому Ticket-у, отчёт о превышении (15 min без UI, 30 min с UI)

Type: task
Status: open
Blocked by: 10
Source: [spec.md](../spec.md), раздел «Решения владельца 2026-10-20: скорость test-ов», решения Q1 и Q2;
скрипт `scripts/critical-path.mjs` (`worfy-reliability` 04, PR #341); ответы владельца 2026-10-29, раунд 3, Q8
(что такое Ticket с UI и куда идёт отчёт).

## Что происходит

- `scripts/critical-path.mjs` считает шаги claim → PR → CI → Gate → merge по Ticket-у из журналов
  Autopilot, заголовков Ticket-ов и данных PR (`gh`). Gate — последний комментарий `VERIFIED`; CI —
  последний зелёный workflow run ветки до Gate. Шаг Gate → merge близок к метрике Q1.
- С batch CI (ADR-0068) у PR нет CI run-ов, и шаг CI пуст. После Ticket-а 12 CI на PR вернётся.
- Бюджета и отчёта о его превышении нет.

## Что делаем

1. Метрика Q1 в `scripts/critical-path.mjs`: время на часах от «проверки зелёные» до merge, по Ticket-у.
   «Проверки зелёные» — позднее из двух моментов: последний `VERIFIED` и зелёный CI на head PR (когда
   он есть). Если скрипт не подходит — новый скрипт, и причина в «Итог».
2. Бюджет Q2: без UI — 15 min, с UI — 30 min; «с UI» — по diff PR (раздел «Ответы владельца» ниже).
   Отчёт называет Ticket-ы сверх бюджета: номер, PR, время, на каком шаге ушло время (CI, gate, очередь
   merge). Этот текст идёт строкой в «Итог» Ticket-а и в отчёт Wave.
3. База — замер по последним закрытым Wave-ам до Ticket-ов 11–13; повтор — после каждого из них.

- [ ] «Итог»: база по последним двум Wave-ам — медиана метрики, число Ticket-ов сверх бюджета, команда и
      код выхода; без личных путей.
- [ ] `pnpm lint`, `pnpm typecheck`, `pnpm test` — exit 0; gate full — шаг Orchestrator-а перед merge.

## Ответы владельца (2026-10-29, раунд 3, Q8)

- **Что такое Ticket «с UI».** Ticket с UI — тот, чей diff трогает `src/renderer/**` (файлы `.tsx` и `.css`)
  или тексты UI. Остальные — без UI. Метки в заголовке Ticket-а нет; e2e в «Готово, когда» не в счёт.
- **Куда идёт отчёт.** Превышение бюджета — строка в «Итог» Ticket-а и в отчёте Wave Orchestrator-а.
  Отдельного файла отчёта нет.

## Итог

- Метрика Q1 — столбец `Green → merge` в отчёте `scripts/critical-path.mjs` (CSV: `green_to_merge_s`,
  `green_to_merge_why`, `green_by`). «Проверки зелёные» — позднее из последнего `VERIFIED` (и
  `NARROW: VERIFIED`) и зелёного `ci-ok` на head PR; без `ci-ok` — все check run-ы head; без CI на head —
  только `VERIFIED`. Push после `VERIFIED` (фикс CI) переносит момент на `ci-ok` нового head. Статусы
  `review` и `check/windows` — отметки merge Orchestrator-а, не CI.
- Бюджет Q2 — столбец `Budget` (CSV: `ui`, `budget_s`, `over_budget`, `budget_why`): 15 min без UI, 30 min с UI,
  ровно 15 min — ещё в бюджете. «С UI» — diff PR (поле `files` у `gh`) трогает `src/renderer/**` `.tsx`/`.css`,
  `src/renderer/index.html` или модули текстов UI renderer-а по имени (`hints`, `notice`, `*-text`, `labels`,
  `strings`, `copy`, `messages`). Тексты UI внутри другого `.ts` renderer-а не видны — это `shortcut:` в коде.
- Сводка Epic-а: строка «Over budget: N of M Tickets with data» и по строке на Ticket сверх бюджета — номер,
  PR, время, бюджет, чем стали зелёными проверки (CI или Gate) и куда ушло время после зелёного: gate (до
  последней отметки `review`/`check/windows`) или очередь merge.
- Нет данных — пустая ячейка с причиной: нет `VERIFIED`, `ci-ok` красный или не закончен, PR не влит, merge
  раньше зелёного, нет списка файлов PR (бюджет неизвестен, время есть).
- Тесты: `test/unit/critical-path.test.ts`, describe «green checks → merge and its budget»: 14 и 15 min без UI —
  в бюджете, 16 — сверх, 29 min с UI — в бюджете, 31 — сверх; 15 мутантов кода — все убиты.
