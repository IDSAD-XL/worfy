## Что происходит

- Карту файлов Ticket-а строит agent `worfy:scout`, только когда список «Где в коде» неполный
  (`harness/skills/epic-wave/SKILL.md:240-243`). Карта живёт в контексте одной Wave и не сохраняется: следующий
  Ticket той же папки разведывает заново.
- Сколько Limits уходит на разведку (scout плюс чтение файлов implementer-ом до первой правки) — базы нет. Для
  сравнения, на другом репозитории (Auction, 2026-09-23): карта scout-а — медиана 46k token-ов, а главная проблема
  карты — полнота, не цена (память `scout-audit-2026-09-23`).
- graphify (граф кода на tree-sitter) оценён 2026-09-23 и отвергнут — причины в spec-е, раздел «Что не входит».

## Что делаем

1. **Замер.** `scripts/agent-cost.mjs` (Ticket 19) считает по ролям за период, не по Ticket-у и не долю scout-а.
   Поэтому сначала — `--by-ticket`: номер Ticket-а и Epic берутся из брифа subagent-а (первая строка или строка
   `Ticket:`), Session Orchestrator-а делится по `wave-started`; Subagent без номера — строка «без Ticket-а». Потом
   замер по транскриптам 2026-10-20…27:
   - token-ы scout-ов на Ticket и их доля от всех token-ов Ticket-а;
   - token-ы implementer-а от старта до первой правки (`Edit`/`Write`), сколько файлов он прочитал и сколько из
     них читали агенты прошлых Ticket-ов того же Epic-а.
   Итог — таблица в «Итог».
2. **Доля маленькая** (разведка — меньше 10 % token-ов Ticket-а; порог предлагает этот Ticket, решает
   владелец) — Ticket закрывается этим ответом. Если в замере видна неполнота карт, как на Auction, —
   предложение правки брифа scout-а в «Итог», не код.
3. **Доля большая** — своя карта scout-а:
   - Markdown на репозиторий, рядом с Profile на Machine, вне репозитория Project (Q-L6);
   - у каждой папки — строка коммита, на котором её описали; `harness/bin/code-map stale` печатает папки, где
     `git diff --name-only <коммит>..HEAD` задел файлы;
   - scout читает карту первым и переписывает только устаревшие папки; модель для этого не нужна, кроме самого
     scout-а.

Нужен ПК: нет. **Трогает Harness:** нет на шагах 1–2 (`scripts/` — не Harness); да на шаге 3 (`harness/bin/code-map`,
`harness/agents/scout.md`) — тогда слово владельца дано (Q-L0 spec-а: «да» 2026-10-28) и это платформенный PR (ADR-0056, пункт 2).
