## Цель

Разработчик или агент открывает одну страницу и узнаёт о Feature worfy три вещи: как он себя ведёт, по
каким принципам работает и как реализован. Сегодня такого места нет. [README.md](../../README.md) — это
установка и настройка, [CONTEXT.md](../../CONTEXT.md) — определения терминов,
[docs/roadmap.md](../../docs/roadmap.md) разбит по Epic-ам и описывает планы. 560 Ticket-ов и 83 ADR
организованы по изменениям, а не по Feature-ам.

Проверок актуальности описаний сейчас нет. `pnpm lint` запускает `eslint`, `check-cyrillic`,
`check-handoff` и `check-lessons`. Из документов он проверяет форму `HANDOFF.md` и уроки: `check-lessons`
ещё сверяет, что файл и строка из ссылки урока на test существуют. Утверждения документов с кодом не
сверяет никто. Поэтому Epic создаёт не только страницы, но и механизм, который держит их актуальными.

### Шаблон раздела

Порядок идёт от пользователя к коду, один раздел отвечает обоим читателям:

- **Behaviour** — что видит и делает разработчик, состояния, ограничения. Без путей к файлам.
- **How it works** — принципы и модель. «Почему так» — одна-две фразы и ссылка на ADR.
- **Implementation** — модули и точки входа с путями, поток данных, главные test-ы. Без номеров строк и
  без копий сигнатур: они устаревают первыми.

Отличия платформ и работа на Linked machine — подзаголовком внутри нужного блока (`On a Linked machine`). Для
Feature с многими состояниями внутри Behaviour разрешены подзаголовки и таблицы. Конкретные числа на странице
остаются: устаревшее число ловит линза `documentation`. Linux не описывается: пакета для него нет. Скриншотов
нет: они устаревают и не проверяются.
Страница описывает только настоящее: без changelog и без пересказа ADR. Страница больше примерно 400 строк
делится на две.

### Перевод

Английская версия — единственный источник. PR, который меняет поведение Feature, правит только её.
Русская версия может отставать, и её шапка это показывает. Первая строка русского файла под заголовком
видна при чтении на GitHub:

```markdown
> Перевод [английской версии](../autopilot.md), commit `1a2b3c4d`.
```

Commit — это последний commit, менявший английский файл, с которого сделан перевод. В первой версии
страницы английский и русский файлы вливаются одним PR. Merge в этом репозитории идёт через squash,
поэтому SHA commit-а заранее неизвестен, и шапка несёт слово `same-pr`:

```markdown
> Перевод [английской версии](../autopilot.md), commit `same-pr`.
```

`same-pr` значит: перевод соответствует английской версии на том commit-е, который последним менял
русский файл. Отставание по такой шапке считается от этого commit-а. Любая отдельная правка перевода,
включая пакетное обновление, заменяет `same-pr` настоящим SHA: английский файл к этому моменту уже в
`main`, его commit известен. Иначе новая правка сдвинула бы точку отсчёта и скрыла бы отставание.

### Проверки

- **Проверка путей в `pnpm lint`.** Падает, только если английская страница ссылается на файл или папку,
  которых нет. Русские файлы она не читает: иначе перевод, которому разрешено отставать, ломал бы lint
  после rename. Форму ссылок задаёт индекс (Ticket 01), скрипт её читает (Ticket 02). Номера строк
  запрещает шаблон, их ловит review, а не скрипт.
- **Отчёт об отставании перевода.** Скрипт вне lint: печатает страницы, у которых английская версия ушла
  вперёд. Поломанная или отсутствующая шапка — ошибка скрипта.
- **Обновление в том же PR.** Необязательное поле Profile включает шаг в `worfy:ship-ticket`: если PR
  меняет поведение, описанное страницей, страница меняется в этом же PR. Для проверки есть новая линза
  review `documentation`, описанная в `harness/agents/reviewer.md`. Она входит только в `review.lenses`, а
  не в `review.ticket_lenses`, где по контракту две-три линзы. Проект без этого поля шаг пропускает,
  поэтому Harness остаётся нейтральным (ADR-0074).
- **Аудит раз в месяц.** Локальная запланированная задача приложения Claude на Mac: ей нужен локальный
  checkout. Текст задачи — в Ticket-е 19.

## Решения владельца

Все — 2026-10-30.

1. **Q1. Читатели — разработчик-пользователь и разработчик продукта, на равных.** Владелец: «на равных,
   но читать его будут заведомо разработчики, поэтому уровень юзеров не нулевой». Отдельного текста для
   неразработчиков нет.
2. **Q2. Единица — Feature, а не Epic.** Epic закрывается, Feature живёт дальше, и его меняют несколько
   Epic-ов. Страница — это не обязательно один Feature: близкие Feature идут разделами одной страницы,
   потому что одна страница на каждый Feature — перебор (слово владельца).
3. **Q3. Страница описывает только настоящее.** Расхождение страницы и кода — баг, который чинят. История и
   причины остаются в ADR и Ticket-ах.
4. **Q4. Актуальность:** обновление в том же PR, линза review, периодический аудит. Жёсткой блокировки в
   CI «код изменён без правки страницы» нет: она срабатывала бы на рефакторингах и вызывала бы правки
   ради зелёного CI.
5. **Q5. Сначала пилот,** затем Wave-ы по утверждённому шаблону.
6. **Q6. Английский — основная версия, русский — дополнительный перевод,** термины на английском в обоих.
7. **Q7. Источник — код и test-ы.** Ticket-ы описывают изменение на момент merge, и более поздние могли его
   отменить. Ticket-ы и ADR нужны только для «почему так» и как подсказка, где искать.
8. **Q8. Harness входит,** отдельной страницей в том же месте и на тех же языках, внутрь plugin-а страницы
   не попадают. Пишется после страниц приложения.
9. **Q9. 14 страниц** из таблицы выше; при написании деление и отдельная страница Focus mode дали 19; страница больше примерно 400 строк делится на две.
10. **Q10. Шаблон** Behaviour / How it works / Implementation, без скриншотов.
11. **Q11. Место:** `docs/features/`, перевод в `docs/features/ru/`, индекс, ссылка из README, без сайта.
12. **Q12. В PR только английский;** шапка русского файла называет commit английской версии, скрипт
    показывает отставшие переводы, агент обновляет их пачкой.
13. **Q13. Исключение из языкового правила** — только `docs/features/`, запись в ADR-0088.
14. **Q14. `docs/features/concepts.md`** — основные понятия на английском. `CONTEXT.md` остаётся источником
    терминов и не переводится целиком.
15. **Q15. Проверка путей в lint** — да: ложных срабатываний почти нет, а rename без правки ссылки она
    поймает.
16. **Q16. Исключение из запрета на новые Epic-и** — см. раздел «Исключения».
17. **Q17. `docs/roadmap.md`** не переносится и не правится: это планы, а Feature page — настоящее. Индекс
    на него только ссылается.
18. **Q18. Пилот:** Autopilot (фоновая логика и много состояний), Terminal (несколько Feature на странице,
    отличия Windows), Cards (файлы на диске и интерфейс для агентов), плюс `concepts.md`, индекс и перевод
    всех трёх. После пилота — остановка.
19. **Q19. Правило — необязательное поле Profile и шаг в `worfy:ship-ticket`,** плюс линза
    `documentation`. Включается после утверждения пилота.
20. **Q20. Behaviour проверяется по коду и test-ам,** без ручных запусков, для Windows-частей тоже.
    Утверждение, которое не подтверждается кодом или test-ом, на страницу не попадает и уходит в раздел
    `## Итог` Ticket-а.
21. **Q21. Review страницы:** один агент уровня `low` сверяет утверждения с кодом, merge блокирует только
    неверное утверждение. Gate full не нужен, код не меняется; lint и CI остаются. PR со скриптами и правкой
    plugin-а идут как обычный код. Это исключение из общего правила о PR только с документами, см. раздел
    «Исключения».
22. **Q22. Один Ticket — одна страница и один PR, сразу на двух языках.** Индекс создаётся один раз и в
    PR страниц не правится.
23. **Q23. Условие готовности** — раздел «Готово, когда». Дальше аудит раз в месяц: правило в PR ловит
    основное, а частый аудит расходовал бы лимиты.
24. **Q24. Epic, spec, Ticket-ы и ADR** выпускаются docs-PR вместе с правкой `CONTEXT.md`.

## Исключения

- **Из `language.docs: ru`.** Profile и `rules.md` Profile-а (раздел «Язык») задают русский для документов
  репозитория. Исключение действует только для `docs/features/`, английская версия там основная.
  `language.docs` не меняется: Ticket-ы, spec-и, ADR, `HANDOFF.md`, `CONTEXT.md` остаются на русском. Этот
  spec и Ticket-ы Epic-а тоже на русском. Запись — [ADR-0088](../../docs/adr/0088-feature-pages-in-english.md).
- **Из запрета на новые Epic-и.** Правило владельца от 2026-10-22: новых Epic-ов нет, пока не закрыты
  `worfy-windows` и `worfy-browser` (на 2026-10-30 — 110 из 114 и 18 из 19). Этот Epic — исключение: он не
  трогает код продукта и не конфликтует с ними по файлам. Epic `audit-<date>`, который создаёт
  `worfy:continuous-audit`, — тоже исключение: это принятый владельцем аудит (Q23). Правило для остальных
  Epic-ов действует.
- **Из правила «PR только с документами ревью агентами не проходит».** Правило записано в `rules-merge.md`
  Profile-а worfy и в `harness/skills/ship-ticket/review-of-another-pr.md`. Q21 — принятое владельцем
  исключение для страниц `docs/features/`: один агент уровня `low`. Исключение действует на уровне
  проекта, поэтому `review-of-another-pr.md` в plugin-е не меняется. В `rules-merge.md` на Mac строку внёс
  Orchestrator, на ПК её добавляет Ticket 07.

## Решено без владельца

- **Р1. Шапка `same-pr`.** Владелец принял «шапка называет commit английской версии». Первая версия
  страницы вливается одним PR с переводом, а squash меняет SHA, поэтому точный commit тут неизвестен.
  Слово `same-pr` решает только этот случай.
- **Р2. Заготовки всех страниц в Ticket-е 01.** Индекс создаётся один раз и ссылается на 14 страниц, а
  проверка путей падает на ссылке в никуда. Ticket 01 кладёт заготовку каждой страницы в одну строку:
  «This page is not written yet.» Ссылки индекса работают сразу, а PR страницы заменяет заготовку и индекс
  не правит, так что параллельные PR не конфликтуют.
- **Р3. Проверка путей читает только английские файлы.** Причина — в разделе «Проверки».
- **Р4. Линза аудита — отдельное поле.** `worfy:continuous-audit` берёт линзы из `audit_lenses`, а не из
  `review.lenses`, и без этого поля не запускается. У worfy оно сейчас `null`. Ticket 07 заполняет его
  записью с `id` `documentation`. В рекомендации к Q19 было сказано, что отдельной настройки аудита не
  нужно: это неверно.

## Не в этом Epic-е

- Сайт документации и показ страниц внутри приложения.
- Текст для неразработчиков, скриншоты, видео.
- Перевод `CONTEXT.md` целиком, правка `docs/roadmap.md`, индекс ADR, правка языка корневого README.
- SSH session и другие Feature, которых нет в `main`.
- Блокировка CI «код изменён без правки страницы».
- Исправление багов продукта, найденных при написании страниц: такая находка уходит в `## Итог` Ticket-а.
  Новые Ticket-ы — по обычному правилу владельца от 2026-10-22: находки уровня low Ticket-ами не становятся.

## Риски

1. **Ошибки поведения, видимые только при запуске.** Behaviour сверяется с кодом и test-ами, без запуска
   приложения (Q20). Часть ошибок останется на страницах, особенно в Windows-частях. Их поймает чтение
   владельцем пилота и дальнейшее использование. Запуск на каждую страницу дорог, а настоящий Autopilot ещё
   и тратит платные запросы к Claude.
2. **Группировка без чтения кода.** Список страниц выведен из имён папок. Пилот проверяет его на трёх
   страницах; остальные могут поменять состав разделов. Такое изменение правит таблицу этого spec-а и индекс
   отдельным PR.
3. **Расход токенов неизвестен.** Оценки нет. Orchestrator записывает токены на страницу при закрытии
   Ticket-а, а Ticket 06 показывает их владельцу до запуска остальных страниц.
4. **Агент «исправит» английский на русский** по правилу из Profile: `ship-ticket` велит писать документы
   на `language.docs`. Каждый Ticket страницы говорит о языке прямо, ADR-0088 это фиксирует, Ticket 07
   добавляет строку в `rules.md` Profile-а на обеих машинах.

## Соглашения для Ticket-ов этого Epic-а

- **Ветки** — `worfy-feature-docs/<NN>`; worktree — `.claude/worktrees/<NN>`.
- **Источник страницы** — код и test-ы из свежего `origin/main` (Q7). Список папок в Ticket-е выведен из их
  имён: автор сам проверяет его при claim и дополняет.
- **Что не подтвердилось** — в `## Итог`, а не на страницу (Q20).
- **Review страницы** — один агент уровня `low`, блокирует только неверное утверждение, gate full не нужен
  (Q21). Условие merge — как у любого PR, `ci-ok` и отметка `review` (ADR-0083).
- **Токены на страницу** записывает Orchestrator при закрытии Ticket-а, не implementer.
- **PR страницы** содержит английский и русский файлы и не правит индекс (Q22).
- **Язык** — английская страница основная, русская — перевод с шапкой `same-pr`, термины на английском в
  обеих. Раздел `## Итог` Ticket-а — по-русски.
