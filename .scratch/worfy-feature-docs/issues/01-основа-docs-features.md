## Что делаем

1. `docs/features/README.md` на английском: что это за документация и для кого, шаблон раздела (Behaviour /
   How it works / Implementation), как устроен перевод (раздел «Перевод» spec-а, вместе с правилом «отдельная
   правка заменяет `same-pr` настоящим SHA»), список всех 14 страниц со ссылками, ссылка на
   [docs/roadmap.md](../../../docs/roadmap.md) как на планы. `docs/roadmap.md` не правится.
2. В индексе — абзац о форме ссылок. Эту форму читает проверка путей Ticket-а 02. На английской странице
   `docs/features/*.md` путём считается:
   - inline code без пробелов, который начинается с `src/`, `test/`, `scripts/`, `harness/`, `docs/`,
     `build/` или `.github/`;
   - относительная ссылка Markdown на файл репозитория, без внешних адресов и без части после `#`.

   Код внутри fenced-блоков не читается. Токен с `<`, `>`, `*` или `{` считается шаблоном и пропускается.
3. `docs/features/ru/README.md` — перевод индекса с шапкой `same-pr`.
4. `docs/features/concepts.md` на английском: основные понятия в нескольких абзацах (Project, Canvas, Node,
   Card, Session, Epic, Ticket, Wave, Binding, Harness и другие, какие потребуются страницам). Источник
   терминов — `CONTEXT.md`, он не переводится целиком. `docs/features/ru/concepts.md` — перевод с шапкой.
5. Заготовки 14 страниц из таблицы spec-а в `docs/features/` и `docs/features/ru/`: заголовок и одна строка
   «This page is not written yet.» (в русском файле — «Страница ещё не написана.»). Ссылки индекса работают
   сразу, а PR страницы индекс не правит (Р2 spec-а).
6. Ссылка на индекс в корневом [README.md](../../../README.md).
