## Что происходит

- `pnpm lint` запускает `eslint`, `check-cyrillic`, `check-handoff`, `check-lessons` (`package.json`). Из
  документов он проверяет форму `HANDOFF.md` и уроки; `check-lessons` ещё сверяет, что файл и строка из ссылки
  урока на test существуют. Feature page не читает никто.
- Merge идёт через squash, поэтому шапка первой версии перевода не может назвать настоящий SHA: она несёт
  слово `same-pr` (раздел «Перевод» spec-а).
- Форму ссылок на пути задаёт абзац индекса `docs/features/README.md` из Ticket-а 01. Этот Ticket её читает и
  индекс не правит.
- `check-cyrillic` запрещает кириллицу в `scripts/` не только в комментариях, но и в строковых литералах. Поэтому
  разбор шапки не может содержать слово «Перевод» литералом.

## Что делаем

Сначала падающий test.

1. **`scripts/check-feature-docs.mjs`,** по образцу `check-handoff` и `check-lessons`: читает английские страницы
   `docs/features/*.md` и пути в форме из индекса. Падает только на несуществующем пути: строка
   `<file>:<line>: <path> does not exist`, exit code 1. Суффикс `:<число>` перед проверкой отбрасывается: номера
   строк запрещает шаблон, их ловит review, а не скрипт. Чистый run — одна строка и exit code 0. Русские файлы
   `docs/features/ru/` не читаются: перевод вправе отставать, и он не должен ломать lint после rename.
2. Подключить в `lint` в `package.json` рядом с `check-lessons`.
3. **`scripts/feature-docs-lag.mjs`,** в lint не входит: для каждого файла `docs/features/ru/*.md` читает шапку и
   печатает страницы, у которых английский файл менялся после commit-а шапки. Для `same-pr` точка отсчёта —
   последний commit, менявший русский файл. Exit code 0 — отчёт напечатан (в том числе пустой). Exit code 1 — шапки
   нет, шапка не разбирается, или commit не найден. Заготовка без шапки — не ошибка, если английский файл тоже
   заготовка.
4. Разбор шапки использует только латиницу: строка цитаты с маркером commit-а, например
   `/^> .*, commit `(same-pr|[0-9a-f]{7,40})`\.$/`. Другой вариант — слово в JSON, как `scripts/doc-headings.json`.
   Русские шапки в test-ах допустимы: `check-cyrillic` разрешает их в test-файлах вне комментариев.
5. Комментарии и сообщения — только по-английски. Пути нормализуются к `/`: в CI `pnpm lint` идёт на Linux
   (job `lint-typecheck`), но unit test-ы скриптов идут и на Windows-runner-е (`windows-tests.yml`, полный
   `pnpm test`), а на Windows-ПК lint запускают локально.

## Готово, когда

- [ ] Несуществующий путь даёт exit code 1 с адресом `<file>:<line>`; существующий — 0, в том числе с суффиксом
      `:<число>`.
- [ ] Отставший перевод показан в отчёте; перевод с настоящим SHA и с `same-pr` без изменений английского — нет.
- [ ] Поломанная шапка даёт exit code 1.
- [ ] `pnpm lint` включает проверку путей и зелёный; `ci-ok` зелёный.
- [ ] Review как у PR с кодом, gate по обычному правилу.

## Тесты

Unit test-ы на временных папках и временном git-репозитории, по образцу `test/unit/check-lessons.test.ts`:
пути, суффикс строки, шаблоны, fenced-блоки, ссылки Markdown, шапка с SHA, `same-pr`, поломанная шапка.

## Где в коде

- `scripts/check-handoff.mjs`, `scripts/check-lessons.mjs`, `scripts/doc-headings.mjs`, `scripts/doc-headings.json` — образец.
- `scripts/check-cyrillic.mjs` (только чтение), `package.json` (`lint`), `test/unit/check-lessons.test.ts`.
- Автор проверяет `test/unit/affected-tests.test.ts`: выбор затронутых test-ов может требовать записи о новых скриптах.

## Вне скоупа

- Блокировка CI «код изменён без правки страницы» (Q4 отклонил её).
- Проверка смысла страницы и номера строк — это review и аудит.
- Правка индекса `docs/features/README.md`.

## Итог

- `scripts/check-feature-docs.mjs` стоит в `pnpm lint` после `check-lessons`. На 2026-10-30 он читает 16 страниц и 30 путей,
  все существуют. Сверх формы индекса он читает ссылки-определения `[id]: path` и картинки и отбрасывает `?query` в
  ссылке: это те же ссылки Markdown. Путь, выходящий за корень репозитория, считается несуществующим.
- `scripts/feature-docs-lag.mjs` в lint не входит. Сверх списка Ticket-а exit code 1 даёт и SHA вне истории HEAD (SHA
  ветки до squash, а его commit локально есть), и русский файл без английского: иначе такая страница молча выпала бы
  из отчёта.
- Заготовка распознаётся так: английский файл — ровно строка «This page is not written yet.» под заголовком; русский без
  шапки — одна строка под заголовком. Русского слова в скрипте нет.
