## Что делаем

1. `PrInboxNotices` в `src/main/notify.ts`: по снимку читателя (Ticket 02) — уведомление ОС на новый запрос ревью у
   меня и на новый ответ в нити моего PR; одно на PR и событие; только без фокуса окна; заголовок — имя Project-а.
   Щелчок поднимает окно и открывает вид Pull requests на этом PR (`openPrInboxOf` из Ticket-а 03). Ни слова коллеги в тексте уведомления: только
   `repo#N`, заголовок PR и вид события.
2. Утренняя сводка: первый фокус окна за календарный день — одно action toast, например «3 reviews wait for you
   (oldest 2 days) · 2 PRs have new comments · 1 ready to merge», кнопка Open. Пустой inbox — сводки нет. Модель не
   нужна.
3. Настройки Machine в `app-settings.json` (`src/shared/settings/app-settings.ts`): `prInboxNotify` и
   `prInboxDigest`, оба включены по умолчанию; раздел Settings `src/renderer/settings/PullRequestsSection.tsx`.
4. `docs/features/notifications.md` — новые уведомления и сводка.

## Решено без владельца

- Первое чтение Project-а — точка отсчёта: что в нём уже было, уведомления не даёт (как ожидание Ticket-а в
  `docs/features/notifications.md`). О том, что пришло, пока worfy был закрыт, говорит утренняя сводка.
- Событие при фокусе окна или при выключенном `prInboxNotify` считается увиденным и позже не приходит (у gate queue
  оно ждёт следующего чтения; здесь пользователь в окне, и раздел sidebar уже показывает его).
- «Новый ответ» — последний комментарий нерешённой нити моего PR, если он не мой; несколько нитей одного PR за одно
  чтение — одно уведомление. Комментарии вкладки Conversation уведомления не дают.
- Сводка — одна на Machine, по всем её Project-ам; Open открывает вид активного Project-а, если сводка его считает,
  иначе первого посчитанного. «PRs have new comments» — PR с «N new since you looked» больше нуля; Needs a fix в
  сводку не входит (как в примере тикета).
- День сводки держится в памяти main: перезапуск worfy в тот же день покажет её снова. Файл в `WORFY_DATA_DIR` —
  новая запись в перечне ADR-0005, это не тикет-уровень (`shortcut:` в `src/main/github/inbox-digest.ts`).
- Пока хоть один включённый Project ни разу не прочитан, сводка ждёт и приходит с первым чтением; сбой чтения её не
  держит. Пустой inbox тоже занимает день.
- Вне списка «Где в коде», без этого пункты не сделать: `src/shared/ipc/notify.ts`, `src/main/notify-pending.ts`,
  `src/renderer/canvas/overlays/NotificationTarget.tsx` (щелчок открывает вид на PR); `src/main/settings/store.ts`
  (хранение переключателей); `src/main/ipc/pr-inbox.ts`, `src/shared/ipc/pr-inbox.ts`,
  `src/main/github/inbox-digest.ts`, `src/renderer/pr-inbox/digest.ts`, `src/renderer/main.tsx` (сводка);
  `docs/features/app-shell.md`, `docs/features/pr-inbox.md`; `src/main/github/inbox.ts` (ревью, раунд 1: читатель
  сообщает `onChange` один раз, когда Project выключен, и уведомления забывают его) с test-ом
  `test/contract/pr-inbox.test.ts`; test-ы `test/unit/pr-inbox-digest-toast.test.tsx`,
  `test/contract/app-settings.test.ts`, `test/contract/app-user-model-id.test.ts`. `ToastRegion.tsx` не менялся:
  action toast уже умеет всё, что нужно.
