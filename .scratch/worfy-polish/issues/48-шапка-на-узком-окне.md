## Что происходит

- На минимальном окне 800×520 с открытой боковой панелью шапка шире окна: 71 px до вкладки `Runs`, 106 px после
  (снимки `.scratch/worfy-flight-recorder/evidence/28-header-800x520-*.png`). В `src/renderer/shell/shell.css:63`
  правило `max-width: 1400px` прячет только подписи вкладок; у Limits, Harness и Search правил на узкое окно нет;
  колонка Harness не сжимается (`src/renderer/shell/toolbar/HarnessStatus.tsx:117` `flex: none`, `shell.css:139` `nowrap`).
- Во время сборки Update chip пишет «Updating · 2/3 Installing dependencies» — около 262 px вместо около 127
  (`src/renderer/update/UpdateChip.tsx:254`): шапка растёт ещё примерно на 135 px.
- Двойной toast «Update failed» на одну упавшую сборку после перезапуска (state `build.phase: failed`), `src/renderer/update/toasts.ts`.
- `UpdateChip.tsx:272`: флаг `pointed` остаётся `true`, когда кнопку chip-а заменяет `<small>`; tooltip потом тикает без наведения.

## Что делаем

1. Шапка не шире окна на 800×520 с открытой боковой панелью: на узком окне Limits показывает только проценты
   (подписи `5-hour`/`7-day` и строки сброса — в tooltip), Search — только иконку с `⌘K`, Harness сжимается с
   многоточием; порядок и состав элементов не меняются.
2. Текст шага Update на chip-е — `max-width` с многоточием; полный текст — в tooltip.
3. Один toast «Update failed» на одну упавшую сборку (ключ toast-а — версия сборки).
4. `pointed` сбрасывается, когда кнопка chip-а исчезает.
