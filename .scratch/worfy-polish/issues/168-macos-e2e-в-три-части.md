# 168 — macOS e2e в три части: часть идёт 35–37 минут при общем лимите 40

Type: task
Status: open
Blocked by: —
Source: решение владельца 2026-11-27 («на все вопросы - да»). Ночью 2026-11-27 часть `macos-e2e (1/2)` PR #2306
(worfy-layout 02) упёрлась в общий лимит `globalTimeout` 40 минут: 216 test-ов прошли, 56 не запустились, ни один не
упал (run 45928325369). Та же часть на PR #2304, #2305, #2295 и #2293 шла 35–37 минут. Один `gh run rerun --failed`
дал зелёный.

## Что происходит

`ci.yml` гонит `pnpm test:e2e` на macOS в двух частях; `scripts/e2e-shard.mjs` делит spec-файлы по измеренному времени
из `test/e2e/timings.json`. Каждая часть идёт почти до лимита `globalTimeout` (`playwright.config.ts:83`, 40 минут
в CI): медленный runner GitHub, и часть не успевает. Лимит не поднимается (правило владельца: test timeout не
поднимать).

## Что строить

- macOS e2e — в три части вместо двух, если PR их просит целиком; меньшее число частей, когда spec-файлов меньше, — как
  сейчас решает `e2e-shard.mjs`.
- `ci-ok` и всё, что читает имена job-ов `macos-e2e (1/2)`, `(2/2)` (land, `ci-scope`, правила, документы CI), знает
  о третьей части.
- `test/e2e/timings.json` при необходимости обновлён по последним зелёным run-ам.

## Где в коде

- `.github/workflows/ci.yml` — job `macos-e2e`, его matrix и комментарий в шапке (строки 37–40, 86).
- `scripts/e2e-shard.mjs` — деление по времени, число частей.
- `playwright.config.ts:83` — `globalTimeout` (не меняется).
- Скрипты orchestrator-а и `rules.md`, если называют `macos-e2e (1/2)` по имени.

## Решения (владелец, 2026-11-27)

- Лимит `globalTimeout` не поднимается; ускорение — делением на части.
- Пока ticket не сделан: часть macOS e2e, упёршаяся в лимит без упавшего test-а, перезапускается один раз
  (`gh run rerun --failed`, один раз на head), с записью в verdict PR.
