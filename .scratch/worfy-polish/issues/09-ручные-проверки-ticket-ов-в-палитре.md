## Что происходит

- В разделе «Готово, когда» Ticket-ов пункты, которые проверяет человек, помечены `(вручную)`. На main
  `fff11ba` в `.scratch/*/issues/` 70 неотмеченных `- [ ] (вручную)` и 22 отмеченных; неотмеченные есть в
  34 файлах со `Status: done` — Ticket влит, а ручная проверка ещё впереди.
- Найти их можно только `grep`-ом или по HANDOFF, который ведётся руками и отстаёт.
- worfy уже читает markdown каждого Ticket-а: `reader.ts:270-275` берёт из него раздел «Где в коде»
  (`codeSection`, `:156`). Модель Ticket-а (`ticketSchema`, `src/shared/workflow/types.ts:53-63`) ручных
  проверок не несёт.

## Что делаем

1. **Разбор** — `src/shared/workflow/manual-checks.ts`: из markdown Ticket-а — пункты списка раздела
   `## Готово, когда`, текст которых после `[ ]` или `[x]` начинается с `(вручную)`. Результат:
   `{ text, checked }[]` в порядке файла; текст — первая строка пункта без `(вручную)`, продолжения
   строк склеены через пробел. Другие разделы не читаются.
2. **Модель.** `ticketSchema` получает `manualChecks` — необязательное поле с default `[]`: старые
   fixture-ы и Linked machine со старой версией worfy читаются как раньше. `reader.ts` заполняет его там
   же, где `codeSection`.
3. **Палитра.** Новая группа `Manual check` в `src/renderer/palette/commands.ts`: по строке на каждую
   **неотмеченную** проверку всех Epic-ов Project-а — «`<epic>` NN · <текст>». Выбор строки — как «Go to»
   Ticket-а: Canvas едет к Node-у Ticket-а (тот же `focusCanvasNode`). Строки ищутся по тексту палитрой,
   как прочие команды; пустая палитра (без запроса) группу не показывает — чтобы не забивать список.
4. **Только чтение** (ADR-0002): отметить проверку из worfy нельзя; отметка — правкой Ticket-а, как сейчас.

## Риски

- Пункты, где `(вручную)` стоит не первым словом, не попадут. Это правило формата Ticket-ов; если
  исполнитель найдёт такие в `.scratch/`, он перечисляет их в «Итог», файлы не правит.

## Итог

Ветка `worfy-polish/09`. Разбор — `src/shared/workflow/manual-checks.ts` (`manualChecks`), поле
`manualChecks` в `ticketSchema`, заполняет `enrichSnapshot` в `reader.ts`, группа `Manual check` — в
`src/renderer/palette/commands.ts`.

- **Пустая палитра без группы.** Палитра ранжирует команды в `CommandPalette.tsx`, `commands.ts` запроса
  не видит, а при пустом запросе каждая команда получает одинаковый вес. Поэтому строки проверок несут
  флаг `queryOnly`, а `forQuery` в `commands.ts` убирает их при пустом поле; вызов `forQuery` — одна
  строка в `CommandPalette.tsx`. Файл стоял в «Только читать»; след расширил оркестратор 2026-10-15
  (Ticket 10 стартует с main после влития этого PR).
- **`(вручную, <пометка>)` тоже проверка** — решено без владельца, подтвердить. В `.scratch/` 14
  неотмеченных пунктов вида `(вручную, владелец)`, `(вручную, после влития)`; без них палитра теряла
  ручные шаги владельца. Пометка остаётся в начале текста: «(владелец) Stable copy: …».
- **Поле необязательное, без default** — решено без владельца, подтвердить. С `.default([])` тип `Ticket`
  требует поле, и каждый Ticket, собранный в test-ах (больше 20 файлов, среди них файлы соседей по Wave),
  перестаёт проходить typecheck. Отсутствие поля читается как `[]` — так же, как задумано для Linked
  machine со старой версией worfy.
- **Числа на копии `.scratch/` с main `12b46d8`** (247 Ticket-ов, только чтение): в модели 86
  неотмеченных проверок в 56 Ticket-ах (37 из них — `Status: done`) и 23 отмеченных.
  `grep -h -- "- \[ \] (вручную)" .scratch/*/issues/*.md | wc -l` — 74; с формой `(вручную, …)`
  (`grep -hE -- "- \[ \] \(вручную[,)]"`) — 88. Разница 88 − 86 = 2 — строки вне раздела «Готово,
  когда»: абзац «Что происходит» этого Ticket-а (строка 13) и «Итог» `worfy-harness` 21 (строка 147).
  Без формы с пометкой модель дала бы 72 = 74 − 2.
- **Пункты, где `(вручную)` не первое слово** (не берутся, файлы не правил): `worfy-daily` 32:129 (`[x]`),
  `worfy-harness` 26:150 (`[x]`, «Пункт 4 (вручную)»), `worfy-windows` 07:224 и 22:66 (`[ ]`, «вручную»
  в середине текста).
- Снимки ревью (собранное приложение, временный HOME, обе темы) — в scratchpad, не в репозитории:
  пустая палитра без группы `Manual check`, запрос «stable» — две строки группы, отмеченной нет; выбор
  строки done-Ticket-а центрирует рамку Epic-а. Длинный текст проверки обрезается многоточием по ширине
  палитры — полный текст виден только в Ticket-е.
- Mutation testing: «брать `(вручную)` из любого раздела», «терять продолжение строки», «показывать
  отмеченные», «не убирать строки при пустом поле», «reader не заполняет поле», «терять пометку» —
  каждый мутант краснит свой test.
