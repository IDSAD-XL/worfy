# Code story — worfy-polish 166: Настройки по группам и с иконками

Kind: pr · Epic: worfy-polish · Ticket: 166 · PR: - · Language: ru

## 1. Что было не так

Окно Settings показывало 15 разделов одним столбцом по `order`, без групп и без иконок, и список уже не помещался в
высоту окна. Каждый раздел — свой файл `*Section.tsx`, его находит `import.meta.glob` в `sections.ts`.

- Требование: [Что происходит](../issues/166-настройки-по-группам-и-с-иконками.md#что-происходит)

## 2. Файл раздела сам называет группу и иконку

Code: `src/renderer/settings/GeneralSection.tsx:18-21` · key lines: 20, 21

```tsx
export const order = 10
export const title = 'General'
export const group: SettingsGroup = 'App'
export const icon: SettingsIconName = 'sliders'
```

- Что делает: рядом с `order` и `title` каждый из 15 файлов объявляет `group` и `icon`; тип ловит опечатку ещё на
  typecheck.
- Почему здесь: Ticket, «Что строить», п. 3: объявление в файле раздела, добавить файл — всё, что нужно.
- Без него: группы и иконки жили бы в отдельной таблице, и новый файл без строки в ней выпал бы из списка молча.
- Требование: [Что строить, п. 3](../issues/166-настройки-по-группам-и-с-иконками.md#что-строить)
- Риски и пробелы test-ов: состав групп реальных файлов проверяет test `the section files of the window fall into App,
  Agents, Workflow and Workspace`; он же закрепляет порядок внутри групп.

## 3. Пропуск или незнакомое значение — исключение с путём файла

Code: `src/renderer/settings/sections.ts:47-55` · key lines: 47, 50, 55

```ts
      if (!isOneOf(SETTINGS_GROUPS, group)) {
        throw new Error(`${path} must export a \`group\`, one of ${SETTINGS_GROUPS.join(', ')}`)
      }
      if (!isOneOf(SETTINGS_ICONS, icon)) {
        throw new Error(`${path} must export an \`icon\`, one of ${SETTINGS_ICONS.join(', ')}`)
      }
      return { ...extension, title, group, icon }
    })
    .sort((a, b) => SETTINGS_GROUPS.indexOf(a.group) - SETTINGS_GROUPS.indexOf(b.group) || a.order - b.order || a.id.localeCompare(b.id))
```

- Что делает: проверяет `group` и `icon` так же, как `title`, и сортирует сначала по группе, потом по `order`, потом
  по имени файла.
- Почему здесь: `collectSections` уже бросал исключение с путём файла при пропущенном `title`; Ticket просит то же для
  группы и иконки.
- Без него: раздел без группы не попал бы ни под один заголовок, и его не было бы в окне.
- Требование: [Что строить, п. 3](../issues/166-настройки-по-группам-и-с-иконками.md#что-строить)
- Риски и пробелы test-ов: номера `order` не меняли (решение Orchestrator-а), поэтому внутри групп порядок не тот, что
  в перечне просьбы: Terminal AI (50) перед Assistant (55), Pull requests (66) перед Autopilot, Integrations (64)
  перед Canvas.

## 4. Окно идёт по строкам в порядке групп

Code: `src/renderer/settings/SettingsDialog.tsx:32-34` · key lines: 33, 34

```tsx
  // The rows in the order the list shows them, group after group: ↑ and ↓ and the row index follow it.
  const groups = groupSections(given)
  const sections = groups.flatMap((each) => each.sections)
```

- Что делает: строит группы из переданных разделов, а плоский список для ↑/↓ и индекса выбранной строки берёт из тех
  же групп.
- Почему здесь: Ticket, «Что строить», п. 4: ↑ и ↓ ходят по строкам через границы групп. `SettingsDialogView` берёт
  разделы и из test-ов, не только из `collectSections`, поэтому порядок строк выводится здесь же.
- Без него: при списке, который пришёл не по группам, ↓ прыгал бы на строку, которая на экране стоит в другом месте.
- Требование: [Что строить, п. 4](../issues/166-настройки-по-группам-и-с-иконками.md#что-строить)
- Риски и пробелы test-ов: нет.

## 5. Заголовок группы — подпись, не кнопка

Code: `src/renderer/settings/SettingsDialog.tsx:74-86` · key lines: 77, 78, 82

```tsx
          <div className="w-settings__nav-list">
            {groups.map(({ group, sections: inGroup }) => (
              // A group of rows named by its heading; the heading is a label, never a control or a Tab stop.
              <div key={group} className="w-settings__nav-group" role="group" aria-labelledby={`${groupId}-${group}`}>
                <p id={`${groupId}-${group}`} className="w-settings__nav-group-title">
                  {group}
                </p>
                {inGroup.map((each) => (
                  <ListRow key={each.id} icon={<SettingsIcon name={each.icon} />} label={each.title} selected={each === shown} onSelect={() => selectSection(each.id)} />
                ))}
              </div>
            ))}
          </div>
```

- Что делает: каждая группа — `role="group"`, названная своим заголовком; заголовок — `<p>` без `tabindex`, строки —
  прежние `ListRow` с иконкой.
- Почему здесь: Ticket, «Что строить», п. 4: заголовки не выбираются и не получают фокус. Почему `<p>`, а не `<h3>` —
  not recorded.
- Без него: заголовок-кнопка встал бы в обход Tab, и e2e, которые проходят Tab-ом строки списка
  (`test/e2e/settings.spec.ts`), споткнулись бы о лишнюю остановку.
- Требование: [Что строить, п. 4](../issues/166-настройки-по-группам-и-с-иконками.md#что-строить)
- Риски и пробелы test-ов: прокрутка столбца — CSS (`overflow-y: auto` на `.w-settings__nav`), jsdom её не видит;
  проверяет её ручной пункт.

## Проверить себя

1. Почему порядок строк для ↑/↓ берётся из `groupSections`, хотя `collectSections` уже сортирует по группе?
   - Ответ: окно принимает разделы и не из `collectSections` (test-ы, Health с заглушкой); порядок на экране задают
     группы, и навигация должна идти по нему же.
   - Строки: `src/renderer/settings/SettingsDialog.tsx:32-34`
2. Что случится с файлом раздела, который забыл `icon`?
   - Ответ: `collectSections` бросит исключение с путём файла при первом импорте `sections.ts`, и renderer не
     смонтируется, вместо того чтобы молча потерять строку.
   - Строки: `src/renderer/settings/sections.ts:47-55`
3. Почему Tab не останавливается на заголовке группы?
   - Ответ: заголовок — `<p>` без `tabindex`, подпись `role="group"` через `aria-labelledby`; фокус получают только
     кнопки строк.
   - Строки: `src/renderer/settings/SettingsDialog.tsx:74-86`
