# Code story — worfy-polish 175: Подъём Agent SDK до 0.3.332 (Claude Code 2.1.332)

Kind: pr · Epic: worfy-polish · Ticket: 175 · PR: - · Language: ru

## 1. Что было не так

`package.json` держал `@anthropic-ai/claude-agent-sdk` на 0.3.322 (Claude Code 2.1.322), на npm уже 0.3.332. Dependabot
PR #1854 поднимал только пакет и был красным в двух местах: `pnpm typecheck` (методы `Query` нового SDK не совпали с
`QueryHandle` worfy) и `test/contract/sdk-compat.test.ts` (manifest и `claude_code_version` снятых сообщений — от
2.1.322).

- Требование: [Что происходит](../issues/175-agent-sdk-0-3-332.md#что-происходит)

## 2. `setPermissionMode` нового SDK отвечает режимом

Code: `src/main/agent/session/types.ts:75-79` · key lines: 79

```ts
  /**
   * Since SDK 0.3.332 it answers with the mode now in effect (or nothing, depending on the host);
   * worfy does not read the answer.
   */
  setPermissionMode(mode: PermissionModeChoice): Promise<unknown>
```

- Что делает: `QueryHandle` принимает новый ответ `Promise<SDKControlSetPermissionModeResponse | undefined>` SDK
  0.3.332; `Promise<void>` у fake-query по-прежнему подходит.
- Почему здесь: `test/contract/sdk-compat.test.ts` сверяет результат каждого метода `Query` с `QueryHandle` (tsc); на
  `Promise<void>` проверка `ResultMismatch<Query>` давала `setPermissionMode`, отсюда красный `lint-typecheck` у #1854.
- Без него: `pnpm typecheck` exit 2.
- Требование: [Что делаем, п. 2](../issues/175-agent-sdk-0-3-332.md#что-делаем)
- Риски и пробелы test-ов: worfy не узнаёт, если Claude Code поставил другой режим, чем просили; это возможность на
  будущее, не дефект этого PR.

## 3. Подпись `reloadPlugins` в manifest

Code: `test/contract/sdk-compat.test.ts:377-380` · key lines: 379

```ts
    // SDK 0.3.332 added refuseIfBusy (reject instead of reloading while a turn runs); worfy does not pass it.
    expect(manifest.queryMethods['reloadPlugins'], RECAPTURE).toBe(
      'reloadPlugins(options?: {holdOnCacheImpact?: boolean; addPlugins?: SdkPluginConfig[]; refuseIfBusy?: boolean;}): Promise<SDKControlReloadPluginsResponse>;',
    )
```

- Что делает: test держит точную подпись метода, которым worfy подхватывает MCP-сервер на ходу (worfy-mcp-live 03);
  новая необязательная опция `refuseIfBusy` записана, вызов worfy без аргументов прежний.
- Почему здесь: Ticket называет `test/contract/sdk-compat.test.ts`; почему подпись держится строкой целиком — not recorded.
- Без него: test красный при любом новом SDK, даже если вызов worfy не изменился — так и задумано.
- Требование: [Что делаем, п. 2](../issues/175-agent-sdk-0-3-332.md#что-делаем)
- Риски и пробелы test-ов: поведение `reloadPlugins` без `refuseIfBusy` на 2.1.332 проверено только снятием
  `mcp-live` (сервер подхвачен, `scope` теперь `project`/`local`, а не `dynamic`).

## 4. Probe-ы без Electron для снятий без модели

Code: `scripts/spikes/sdk-probe.ts:39-43` · key lines: 42, 43

```ts
// Electron when the probe runs inside it (`pnpm exec electron …`, the Node of worfy's main process);
// plain Node 24 runs it too (`node scripts/spikes/sdk-probe.ts no-login`, `--rescrub`): the SDK starts
// its own Claude Code binary either way, and no scenario opens a window.
const electronApp = process.versions.electron ? (await import('electron')).app : undefined
const exit = (code: number): void => (electronApp ? electronApp.exit(code) : process.exit(code))
```

- Что делает: probe грузит Electron, только когда запущен в нём. Так же сделано в `scripts/spikes/harness-plugin/probe.ts`:
  там сценарии `integrations*` без Electron отказываются с ошибкой, остальные идут под Node 24.
- Почему здесь: бриф запрещает Electron и вызовы модели; Ticket велит снять заново всё, что снимается без модели
  и без входа. Так сняты `no-login`, `plugin-mcp-name-*`, `plugin-mcp-live-*` и `test/fixtures/mcp-live/*.json`
  (`init-plugin-errors` снимал probe `harness-hooks`, он уже был на Node).
- Без него: эти снятия потребовали бы `pnpm exec electron`.
- Требование: [Что делаем, п. 3](../issues/175-agent-sdk-0-3-332.md#что-делаем)
- Риски и пробелы test-ов: снятия под Node, а не под Node Electron-а; поток сообщений даёт бинарник Claude Code, но
  это не проверено сравнением на одном и том же SDK. Остальные 12 файлов сняты позже, под Electron, по разрешению
  владельца (шаг 6).

## 5. Code Mode worfy не включает

Code: `test/unit/claude-code-mode-off.test.ts:16-23` · key lines: 20, 21

```ts
function codeModeIn(options: { settings?: unknown; env?: Record<string, string | undefined> }): string[] {
  const found: string[] = []
  const settings = typeof options.settings === 'string' ? (JSON.parse(options.settings) as unknown) : options.settings
  const settingsEnv = (settings as { env?: Record<string, unknown> } | undefined)?.env
  if (settingsEnv !== undefined && Object.keys(settingsEnv).some((key) => key.startsWith(CODE_MODE))) found.push('settings.env')
  if (options.env !== undefined && Object.keys(options.env).some((key) => key.startsWith(CODE_MODE))) found.push('env')
  return found
}
```

- Что делает: ищет `CLAUDE_CODE_EXPERIMENTAL_CODE_MODE*` в `settings.env` (объект или JSON-строка) и в `env` опций;
  test-ы файла гоняют через неё `sessionOptions` пяти видов Session, `draftSessionOptions`, `inventoryOptions` и
  `harnessCheckOptions`.
- Почему здесь: Ticket: Agent SDK-приложение включает Code Mode 2.1.332 только через `env` опции `settings`; worfy
  не должен.
- Без него: переменная, добавленная в `sessionEnv` или во flag settings, прошла бы незаметно.
- Требование: [Что делаем, п. 6](../issues/175-agent-sdk-0-3-332.md#что-делаем)
- Риски и пробелы test-ов: красный до проверки — с переменной, подставленной в `sessionEnv`, 6 из 7 test-ов красные.
  Переменная, которую пользователь сам поставил в окружение worfy, пройдёт в `env` — test подаёт окружение без неё;
  другие места, где worfy строит query (Terminal AI, разовые вызовы), не покрыты.

## 6. Снятия с моделью: account для `env-file`

Code: `scripts/spikes/harness-plugin/probe.ts:617-623` · key lines: 622

```ts
function profileAccount(): string {
  const fromFlag = flag('--account')
  if (fromFlag) return fromFlag
  // The repository's own copy of the Harness: ~/.claude/bin/profile is gone since the Harness became
  // the worfy plugin.
  return execFileSync(join(repo, 'harness', 'bin', 'profile'), ['-C', repo, '--field', 'github.account'], { encoding: 'utf8' }).trim()
```

- Что делает: сценарий `env-file` берёт `github.account` Profile-а через `harness/bin/profile` самого репозитория.

  ENOENT` — с тех пор как Harness стал plugin-ом worfy, этой копии нет. Бриф разрешил чинить причину в probe и одну
  повторную попытку.
- Без него: `plugin-env-file-sdk.jsonl` не снимается.
- Требование: [Готово, когда, п. 4](../issues/175-agent-sdk-0-3-332.md#готово-когда)
- Риски и пробелы test-ов: probe не покрыт test-ами; `--account` по-прежнему главнее Profile-а.

## 7. Как проверено

Снятия по подписке владельца 2026-11-28 (разрешение на один прогон): `sdk-probe.ts` шести сценариев, `harness-plugin/probe.ts`
`known`, `workflow-hooks`, `env-file`, `integrations` — exit 0; около 2,70 USD по `total_cost_usd`. Первое снятие
`sdk-probe.ts` выброшено: Stop hook пользователя читал красный gate этого worktree и держал ходы; второе — с
`--env CLAUDE_GATE_STATE=<пустая папка>`. Значения нового снятия — в `test/contract/agent-events.test.ts`,
`test/contract/limits.test.ts` и `test/fixtures/sdk-events/claude.json`. `node scripts/check-personal.mjs` — exit 0;
`pnpm lint`, `pnpm typecheck` — exit 0; 13 файлов test-ов, которые читают снятия, — exit 0. Весь `pnpm test` на Mac —
exit 1 только на 28 test-ах, которые ждут уведомлений о файлах (`fseventsd` перегружен); вердикт — `ci-ok`. e2e
локально не запускали.

## Проверить себя

1. Почему `setPermissionMode` в `QueryHandle` стал `Promise<unknown>`, а не ответом SDK?
   - Ответ: worfy ответ не читает, а `unknown` принимает и ответ SDK 0.3.332, и `Promise<void>` fake-query.
   - Строки: `src/main/agent/session/types.ts:79`
2. Почему probe-ы под Node 24 не сняли `init.jsonl`, и его пришлось снимать отдельно?
   - Ответ: Node снимает запрет на Electron, а не на модель: `init` — настоящие ходы модели по подписке и с настройками пользователя.
   - Строки: `scripts/spikes/sdk-probe.ts:42`
3. Откуда сценарий `env-file` берёт GitHub account, если `--account` не задан?
   - Ответ: из `github.account` Profile-а, через `harness/bin/profile` репозитория, а не через исчезнувший `~/.claude/bin/profile`.
   - Строки: `scripts/spikes/harness-plugin/probe.ts:622`
