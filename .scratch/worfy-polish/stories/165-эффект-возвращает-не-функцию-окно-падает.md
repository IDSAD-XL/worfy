# Code story — worfy-polish 165: эффект возвращает не функцию: Chat падает с «destroy_ is not a function»

Kind: pr · Epic: worfy-polish · Ticket: 165 · PR: - · Language: ru

## 1. Что было не так

React 19 хранит то, что вернула функция эффекта, и, если это не `undefined`, вызывает его перед следующим запуском
эффекта и при снятии компонента. Вкладка Chat раздела Assistant прокручивала к последнему сообщению эффектом-стрелкой
без фигурных скобок, и эффект возвращал то, что вернул `scrollIntoView`. Если это Promise, React бросает
«destroy_ is not a function» — ровно этот текст владелец увидел в запасной карточке «in Chat» после polish 163.
TypeScript этого не видит: в типах DOM `scrollIntoView` возвращает `void`.

- Требование: [Что происходит](../issues/165-эффект-возвращает-не-функцию-окно-падает.md#что-происходит)

## 4. Правило ESLint: тело эффекта без скобок — только очистка

Code: `scripts/eslint-effect-cleanup.mjs:68-84` · key lines: 71, 73, 77, 78, 81, 82

```js
      CallExpression(node) {
        const hook = hookName(node.callee)
        const callback = node.arguments[0]
        if (!HOOKS.has(hook) || !callback || !isFunction(callback)) return
        const data = { hook }
        if (callback.async) {
          context.report({ node: callback, messageId: 'async', data })
          return
        }
        if (callback.body.type !== 'BlockStatement') {
          if (!isCleanup(callback.body)) context.report({ node: callback.body, messageId: 'concise', data })
          return
        }
        for (const statement of returnsOf(callback.body)) {
          if (statement.argument && VALUES.has(statement.argument.type)) context.report({ node: statement.argument, messageId: 'value', data })
        }
      },
```

- Что делает: для `useEffect`, `useLayoutEffect` и `useInsertionEffect` тело стрелки без скобок должно быть функцией,
  именем, `undefined`, `void`-выражением или условием из них; вызов там — ошибка. `async`-эффект — ошибка. В скобках —
  ошибка `return` литерала, шаблона, объекта, массива, арифметики или сравнения и `await`.
- Почему здесь: Ticket требует защиту в `pnpm lint` без новой зависимости; правило живёт рядом с `check-cyrillic.mjs`
  и подключено к тому же локальному plugin-у `worfy`.
- Без него: следующий эффект-стрелка с вызовом снова вернёт то, что вернёт вызов, и ни TypeScript, ни test в jsdom
  этого не заметят.
- Требование: [Что строить, п. 3](../issues/165-эффект-возвращает-не-функцию-окно-падает.md#что-строить)
- Риски и пробелы test-ов: правило судит по форме кода, без типов. `return` вызова в скобках оно пропускает: автор
  пишет `return` сам и отвечает за то, что вызов возвращает отписку. Эффект, переданный не стрелкой, а именем функции
  (`useEffect(run, [])`), не проверяется.

## Проверить себя

1. Почему TypeScript пропустил эффект Chat?
   - Ответ: в типах DOM `scrollIntoView` возвращает `void`, а тип результата эффекта допускает `void`; что метод
     на деле возвращает Promise, типы не знают.
   - Строки: `src/renderer/assistant/AssistantPanel.tsx:349`
2. Почему правило пропускает `useEffect(() => { return followAssistant() }, [])`, но не `useEffect(() => followAssistant(), [])`?
   - Ответ: правило не знает типов; вызов без скобок может вернуть что угодно, а `return` в скобках — явный выбор
     автора, что вызов возвращает отписку.
   - Строки: `scripts/eslint-effect-cleanup.mjs:77-83`
3. Почему test ждёт ошибку уже при втором сообщении, а не только при смене вкладки?
   - Ответ: перед повторным запуском эффекта React вызывает то, что вернул прошлый запуск, так что бросок случается
     и без снятия Chat.
   - Строки: `test/unit/assistant-panel.test.tsx:484-486`
