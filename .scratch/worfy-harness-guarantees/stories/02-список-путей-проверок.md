Списка файлов, которые судят работу (workflow CI, scope-скрипты, Quarantine, настройки test-ов и lint, агенты

## 2. Итоговый список: defaults, затем поле Profile-а

Code: `harness/lib/verification-paths.cjs:92-97` · key lines: 95, 96

```js
/** The defaults, then the usable globs of the profile's verification.paths as normalizeGlob writes them, each once. */
function verificationPaths(profile) {
    const v = isObject(profile) ? profile.verification : undefined
    const added = isObject(v) && Array.isArray(v.paths) ? v.paths.map(normalizeGlob).filter((g) => g !== null) : []
    return [...new Set([...DEFAULT_VERIFICATION_PATHS, ...added])]
}
```

- Что делает: берёт defaults и дописывает к ним glob-ы Profile-а в той форме, в какой они сравниваются (`\` как
  `/`, без `./` и ведущего `/`, `tools/` как `tools/**`), каждый один раз; пустой список, `null`, значение не того
  вида, glob с `!` или с `..` default не убирают и ничего не добавляют.
- Почему здесь: Ticket называет новый модуль `harness/lib/verification-paths.cjs` одним местом списка для guard и
  `land`.
- Без него: Profile с пустым списком или с `!CLAUDE.md` снял бы защиту с файла из defaults.
- Требование: [Готово, когда, п. 1](../issues/02-список-путей-проверок.md#готово-когда)
- Риски и пробелы test-ов: `bin/profile` отказывает Profile-у с `!` раньше (exit 1), так что фильтр — вторая
  линия для вызова мимо `bin/profile`.

## 3. Путь проверки или нет

Code: `harness/lib/verification-paths.cjs:188-197` · key lines: 190, 194, 195

```js
/** Whether `file` matches one of the globs `paths`. */
function isVerificationPath(file, paths, options = {}) {
    const p = normalizePath(file, options)
    if (p === null || !Array.isArray(paths)) return false
    const flags = ignoresCase(options.platform || process.platform) ? "i" : ""
    return paths.some((glob) => {
        const g = normalizeGlob(glob)
        return g !== null && new RegExp(`^${source(g)}$`, flags).test(p)
    })
}
```

- Что делает: приводит путь к форме от корня репозитория с `/` (`\` тоже разделитель; с `root` относительный путь
  сначала берётся от `root`, абсолютный засчитывается только внутри него; на Windows `/c/x` — это `c:/x`), glob — к
  той же форме, и сравнивает целиком; на Windows и macOS без регистра.
- Почему здесь: Ticket требует сравнение `/` и `\` и регистра на Windows; macOS добавлен, потому что его файловая
  система по умолчанию тоже не различает регистр.
- Без него: `.GitHub\Workflows\ci.yml` с Windows прошёл бы мимо списка, хотя это тот же файл.
- Требование: [Что строить](../issues/02-список-путей-проверок.md#что-строить)
- Риски и пробелы test-ов: glob-синтаксис свой (`*`, `?`, `**`, `{a,b}`), классов `[...]` нет — такой символ
  читается как сам себя.

## 4. `bin/profile` печатает список целиком

Code: `harness/bin/profile:444-448` · key lines: 448

```js
// The verification paths, the files that judge work: the defaults of every project, then the globs of
// verification.paths (lib/verification-paths.cjs, the one copy of the list). The field is
// printed resolved, as workflow.ci is: `--field verification.paths` is the whole list, never only the
// project's additions, and a profile without the field still has the defaults.
profile.verification = { ...(profile.verification || {}), paths: verificationPaths(profile) }
```

- Что делает: заменяет поле итоговым списком, как `workflow.ci` получает свой default, — его видят `--field`,
  `--json` и сводка.
- Почему здесь: Ticket называет `bin/profile --field verification.paths`; проверка поля стоит выше, в
  `profileProblems`.
- Без него: читатель получил бы только добавки Project-а и должен был бы сам помнить defaults.
- Требование: [Готово, когда, п. 2](../issues/02-список-путей-проверок.md#готово-когда)
- Риски и пробелы test-ов: не записано

      const [edit, fixed, paths] = await Promise.all([

- Что делает: рядом с чтением полей формы читает итоговый список через `bin/profile --field verification.paths`;

- Требование: [Готово, когда, п. 3](../issues/02-список-путей-проверок.md#готово-когда)
- Риски и пробелы test-ов: e2e test-а формы с этим разделом нет; проверено unit test-ом и contract test-ом.

## Проверить себя

1. Почему Profile с `"verification": {"paths": ["!CLAUDE.md"]}` не снимает защиту с `CLAUDE.md` даже при вызове
   модуля мимо `bin/profile`?
   - Ответ: `verificationPaths` пропускает glob-ы через `normalizeGlob`, который для glob-а с `!` даёт `null`, и
     defaults всегда стоят первыми.
   - Строки: `harness/lib/verification-paths.cjs:95-96`
2. Откуда Edit profile берёт список, и почему не из `profile-set --read`?
   - Ответ: из `bin/profile --field verification.paths`, который печатает defaults вместе с полем; `--read` отдаёт
     только записанное в файле.
   - Строки: `src/main/ipc/profile-edit.ts:299`
