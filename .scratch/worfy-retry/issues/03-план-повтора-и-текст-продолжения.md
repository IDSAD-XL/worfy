**Решено без владельца** (всё — в сторону «безопасно по умолчанию»; п. 1, 2, 9–12 — после ревью high, раунд 2; п. 13–16 — раунд 3; п. 17–20 — узкая правка после раунда 3):

1. **Локальное — только то, что модуль знает.** Tool не из списка `LOCAL_TOOLS` (Read, Write, Edit, Glob, Grep,
   TodoWrite, WebFetch, WebSearch, Skill, `fileChange` Codex и т. п.) — внешний: RemoteTrigger, PushNotification,
   Artifact, Monitor, CronCreate. Tool MCP чужого сервера (`mcp__github__…`, `mcp__slack__…`, qmd Harness-а) — внешний.
   Цена — лишние строки в тексте для tool-ов, которые только читают.
2. **Команда shell — внешняя, локальная или неизвестная.** Внешняя — запись через git, gh, HTTP-клиент (`curl`/`wget`
   с методом не GET или с телом, `Invoke-WebRequest`/`Invoke-RestMethod` с `-Method`/`-Body`), `ssh`/`scp`/`sftp`,
   `rsync` на другую машину, `npm|pnpm|yarn|bun publish` (и `unpublish`, `deprecate`, `dist-tag`, `owner`),
   `docker|podman push`. Локальная — каждая простая команда из списка `LOCAL_PROGRAMS` (ls, cat, grep, rg, чтение gh,
   `pnpm test|lint|typecheck|build`, `node <файл>`, …; git, curl и PowerShell — по п. 13–15), с учётом `env`, `timeout`, `bash -c '…'`, `for`/`if`.
   Остальное (`make deploy`, `./deploy.sh`, `docker build`, alias вроде `g pr create`) — неизвестная: без результата
   останавливает повтор (`in-flight`), как внешняя; с результатом названа отдельной строкой «worfy could not tell
   whether these commands … changed something outside this Session», и фразы «worfy saw no action…» тогда нет.
3. **gh — список того, что только читает, а не того, что пишет.** Внешний — любой `gh <группа> <глагол>`, кроме
   глаголов `view`, `list`, `status`, `checks`, `diff`, `checkout`, `watch`, `download` и групп `search`, `status`,
   `browse`, `help`, `version`, `completion`. Так `gh pr comment`, `gh issue create`, `gh run rerun`, `gh workflow run`
   тоже внешние, хотя Ticket их не называл; `gh release view` и `gh release list` — нет.
4. **`gh api` без `-X`, но с `-f`/`-F`/`--field`/`--raw-field`/`--input` — внешний:** gh тогда шлёт POST. Ticket называл
   только `-X`/`--method`. `GET` и `HEAD` — только чтение.
5. **git:** к списку Ticket-а (`commit`, `push`, `merge`, `rebase`, `reset`, `tag`) добавлены `pull`, `cherry-pick`,
   `revert`, `am` — они делают commit или merge так же. Опции до подкоманды (`-C <path>`, `-c k=v`, `--git-dir`, …)
   пропускаются; команды после `&&`, `;`, `|`, внутри `$(…)`, обратных кавычек и строк в кавычках (`bash -c '…'`,
   `ssh host "…"`) читаются отдельно; перенаправление (`>file`, `2>&1`) кончает слово. Слово `git` в любом месте
   простой команды (`xargs git push`, `echo git push`) — тоже считается: ложное «внешнее» безопаснее пропуска.
6. **Фоновая задача** — Bash (и PowerShell, `commandExecution` Codex) с `run_in_background`, `Agent`/`Task`,
   `Workflow`; **`SendMessage`** (сообщение другому агенту) — тоже внешнее.
7. **Считаются только вызовы самого хода** (`parentToolUseId` null). Вызов внутри Subagent-а — его собственный: у
   вызова `Agent` есть результат — Subagent идёт (или кончился) сам, продолжение хода его не повторит; результата нет —
   в полёте сам вызов `Agent`. Иначе любой фоновый Agent, занятый `git push` в момент ошибки, запрещал бы повтор.
8. **Порядок отказов:** `not-transient`, потом `in-flight`, потом `cap`. При шестой попытке с действием в полёте
   причина — `in-flight`: человеку важнее узнать, что push мог пройти.
9. **Действие в тексте — сводка worfy, а не слова модели:** программа, подкоманда и короткая цель (ветка, номер PR,
   endpoint, URL) — `git commit`, `git push origin main`, `gh pr merge 12`, `Agent (worfy:implementer)`. Сообщение
   commit-а, описание Agent-а, текст here-document с кавычками (`<<'EOF'`) в текст не попадают: продолжение уходит от
   имени человека, и слова модели не должны вернуться к ней как указание.
10. **Первая фраза называет вид ошибки** в скобках — «…with a temporary API error (the API was overloaded) before it
    finished (retry 2 of 5)…»; в образце spec-а («Повтор после ошибки API (A)», п. 3) скобок нет. Остальной текст — по
    образцу; в тексте названы только действия с результатом; просьба проверить git log / gh pr view / список задач —
    всегда.
11. **Codex 429 — не в этом PR.** Решение Orchestrator-а: `responseTooManyFailedAttempts` с `httpStatusCode` 429 —
    `other`, как Claude `API Error: 429`; Q4 не задумывал повтор rate limit-а, на котором Codex сам сдался. Сделать здесь
    нельзя: `httpStatusCode` до `turnFailureKind` не доходит (`errorKind`, `src/main/vendors/codex/items.ts:74-78`, берёт
    только ключ `codexErrorInfo`; в `TurnEndInput` кода нет). Работа и test-ы — в Ticket 08 (п. 4 «Что делаем», «Где в
    коде», «Готово, когда»); решение записано в spec рядом с Q4.
12. **Subagent-ы Codex** (`collabAgentToolCall`) не становятся `tool_use` и `externalActions` их не видит — записано в
    Ticket 08, п. 5.
13. **git — список подкоманд, которые только читают.** Локальные — `status`, `diff`, `log`, `show`, `fetch`, `ls-files`,
    `rev-parse`, `blame`, `grep` и т. п. (список `GIT_READ`), плюс `add`: он меняет только index этой Session. Формы
    чтения `branch`, `tag`, `config`, `remote`, `worktree`, `stash`, `reflog` — без позиционных аргументов или со списком
    (`-l`, `--list`, `--contains`, `-n5`), и без опции записи (`branch -f`, `tag -d`). Всё прочее — неизвестное: alias
    (`git p`), `send-email`, `svn dcommit`, `p4 submit`, `branch -f`, `update-ref`, `switch -C`, `stash`, `clean`.
14. **curl читается по опциям.** Короткие опции склеиваются (`-sX POST`, `-sd x`, `-fsSd`, `-sT f`); значение — остаток
    слова или следующее слово. Опция, которой нет в списках, `-K`/`--config` (команды из файла) и опция без значения —
    неизвестное. Метод — `-X`, иначе PUT при `-T`, POST при теле без `-G`/`--get`, иначе GET.
15. **PowerShell `Invoke-WebRequest`/`Invoke-RestMethod`** — параметр по префиксу, как его читает PowerShell (`-Meth`,
    `-me`, `-b`, `-inf`), и в форме с двоеточием (`-Method:Post`, `-Body:x`). Splatting `@params`, метод в переменной и
    `-Method` без значения — неизвестное.
16. **Чужая программа внутри команды:** `find -exec`/`-execdir`/`-ok`/`-okdir` (каждая команда до `;` или `+`),
    `node -e`/`-p`/`--eval`, `python -c`, `awk` с `system(` или `|` — неизвестные, если вложенная команда не локальна.
    Подстановка процесса `<(…)`/`>(…)` читается как вложенная команда. Цель-URL обрезается до `?`: строка запроса —
    текст модели. Каждое действие в тексте продолжения — в обратных кавычках.
17. **PowerShell: неизвестный параметр — неизвестное.** Параметры `Invoke-WebRequest`/`Invoke-RestMethod` — список
    PowerShell 5.1 и 7 с общими (`-ErrorAction`, …), с указанием, берёт ли параметр значение. Префикс читается, только
    если он однозначен (`-Meth`, `-cu`); `-Fo` (Form или FollowRelLink), `-inf` (InFile или InformationAction) —
    неизвестное. `-CustomMethod`, его alias `-CM` и префиксы — метод. Второе позиционное слово — неизвестное. В
    PowerShell `curl` и `wget` — ещё и alias `Invoke-WebRequest` (Windows PowerShell 5.1): читаются обоими способами,
    побеждает менее безопасное чтение; скрипт `pwsh -Command` читается как PowerShell, `bash -c` — как POSIX shell.
18. **wget и `gh api` читаются по опциям**, как curl: wget — длинная опция по однозначному префиксу (`--post-d=`,
    `--meth=`), `-e`/`--execute`, `--config`, `--use-askpass` и незнакомая опция — неизвестное; `gh api` — склеенные
    короткие опции pflag (`-iX POST`, `-iXPUT`, `-X=PATCH`, `-if a=b`), незнакомая опция или опция без значения —
    неизвестное.
19. **git, который запускает программу, — неизвестное:** `-c` или `--config-env` с ключом, значение которого —
    программа или файл настроек (`core.sshCommand`, `core.pager`, `core.fsmonitor`, `alias.x=!…`, `include.path`,
    `*.textconv`, `credential.helper`, …), `--exec-path=`, у команд чтения — `--upload-pack`, `--receive-pack`,
    `--exec`, `--open-files-in-pager` (по префиксу), `grep -O`, `ls-remote -u`. Команда записи остаётся внешней. В
    сводке git пропускаются глобальные опции и их значения: `git -c alias.st=push st` → `git st`.
20. **Код со stdin и подстановка в двойных кавычках.** node и python без файла (или с `-`), `python -m`,
    `node --run`, `bun -e` — неизвестные. Внутри двойных кавычек `$(…)` и обратные кавычки читаются как команды (как в
    shell); одинарные кавычки и `\$(` — текст. Цель обрезается и до `#`.
