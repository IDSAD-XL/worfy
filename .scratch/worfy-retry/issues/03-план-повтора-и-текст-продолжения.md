**Решено без владельца** (всё — в сторону «безопасно по умолчанию»):

1. **Неизвестный tool MCP — внешний.** Tool другого сервера (`mcp__github__…`, `mcp__slack__…`, qmd Harness-а) может
   менять что угодно: без `tool_result` он останавливает повтор, с результатом — назван в тексте. Цена — лишние строки
   в тексте продолжения для tool-ов, которые только читают.
2. **gh — список того, что только читает, а не того, что пишет.** Внешний — любой `gh <группа> <глагол>`, кроме
   глаголов `view`, `list`, `status`, `checks`, `diff`, `checkout`, `watch`, `download` и групп `search`, `status`,
   `browse`, `help`, `version`, `completion`. Так `gh pr comment`, `gh issue create`, `gh run rerun`, `gh workflow run`
   тоже внешние, хотя Ticket их не называл; `gh release view` и `gh release list` — нет.
3. **`gh api` без `-X`, но с `-f`/`-F`/`--field`/`--raw-field`/`--input` — внешний:** gh тогда шлёт POST. Ticket называл
   только `-X`/`--method`. `GET` и `HEAD` — только чтение.
4. **git:** к списку Ticket-а (`commit`, `push`, `merge`, `rebase`, `reset`, `tag`) добавлены `pull`, `cherry-pick`,
   `revert`, `am` — они делают commit или merge так же. Опции до подкоманды (`-C <path>`, `-c k=v`, `--git-dir`, …)
   пропускаются; команды после `&&`, `;`, `|`, внутри `$(…)`, обратных кавычек и строк в кавычках
   (`bash -c '…'`, `ssh host "…"`) читаются отдельно. Слово `git` в любом месте простой команды (`xargs git push`,
   `echo git push`) — тоже считается: ложное «внешнее» безопаснее пропуска.
5. **Фоновая задача** — Bash (и PowerShell, `commandExecution` Codex) с `run_in_background`, `Agent`/`Task`,
   `Workflow`; **`SendMessage`** (сообщение другому агенту) — тоже внешнее.
6. **Считаются только вызовы самого хода** (`parentToolUseId` null). Вызов внутри Subagent-а — его собственный: у
   вызова `Agent` есть результат — Subagent идёт (или кончился) сам, продолжение хода его не повторит; результата нет —
   в полёте сам вызов `Agent`. Иначе любой фоновый Agent, занятый `git push` в момент ошибки, запрещал бы повтор.
7. **Порядок отказов:** `not-transient`, потом `in-flight`, потом `cap`. При шестой попытке с действием в полёте
   причина — `in-flight`: человеку важнее узнать, что push мог пройти.
8. **В тексте названы только сделанные действия** (`done`); без них — строка «worfy saw no action of that turn that
   changes something outside this Session.» Просьба проверить git log / gh pr view / список задач — всегда.

**Не сделано:** `curl`/`wget` с не-GET методом (сообщение в webhook) не распознаются как внешние — Ticket их не
называл. Если нужно — отдельный Ticket: разбор метода у HTTP-клиентов, как у `gh api`.
