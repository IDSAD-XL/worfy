# 02 — Codex: как worfy ведёт Session

Type: research
Status: done 2026-11-02
Blocked by:
Source: [map.md](../map.md), Ticket 01

## Question

Через что worfy может вести Session Codex так, как сейчас ведёт Claude Code через Agent SDK (`QueryHandle`, `src/main/agent/session/types.ts:39`): TypeScript SDK Codex, `codex app-server` (JSON-RPC IDE-расширения), `codex exec --json` или что-то ещё? Для выбранного пути: поток событий (сообщения, tool calls, вывод команд, ошибки, конец хода) и его стабильность между версиями; отправка сообщения во время хода и очередь; interrupt; продолжение прежней Session (resume); смена Model и effort на ходу; режимы разрешений и запрос подтверждения у пользователя (аналог `canUseTool`); slash-команды и их список; проверка входа и данные аккаунта (аналог `accountInfo`, ADR-0009); вход по подписке ChatGPT без API-ключа; macOS и Windows; лицензия и как поставляется бинарник (аналог ADR-0008).

## Answer

Проверено 2026-11-02. Версии: последний stable Codex CLI — `rust-v0.166.0` (2026-10-29), alpha — `0.167.0-alpha.3` (2026-11-01); исходники протокола читались с `main` (последний push 2026-11-01), поэтому отдельные поля могут быть новее 0.166.0. Документация OpenAI (страницы на `learn.chatgpt.com`, куда с 308 redirect ведёт `developers.openai.com/codex/...`) даты не указывает — дата чтения 2026-11-02. Локально `codex` не установлен, ничего не запускалось.

### Рекомендуемый путь: `codex app-server` (JSON-RPC по stdio)

- **app-server.** OpenAI сама направляет туда продукты, которым нужны «authentication, conversation history, approvals, and streamed agent events»; на нём работают VS Code extension и Python SDK ([app-server](https://learn.chatgpt.com/docs/app-server), [codex-sdk](https://learn.chatgpt.com/docs/codex-sdk)). Это единственный путь, где есть всё, что нужно `QueryHandle`: один долгоживущий процесс, поток notification-ов, server→client request на подтверждение, `turn/steer`, `turn/interrupt`, `account/*`, `model/list`.
- **TypeScript SDK `@openai/codex-sdk` 0.166.0 не подходит.** Это обёртка над `codex exec --experimental-json`: один процесс на каждый ход ([exec.ts](https://github.com/openai/codex/blob/main/sdk/typescript/src/exec.ts)). Нет callback-а подтверждения, нет steer, interrupt — только `AbortSignal`, который убивает процесс. Нет account, login и списка Model. Сама OpenAI рекомендует его «for CI/job automation».
- **`codex exec --json` не подходит по тем же причинам.** Это неинтерактивный режим, approval-ы задаются заранее флагами ([non-interactive-mode](https://learn.chatgpt.com/docs/non-interactive-mode)).
- **`codex mcp-server` удалён** ([mcp-server](https://learn.chatgpt.com/docs/mcp-server)).
- **Как встраивать.** worfy запускает `codex app-server`, проходит `initialize` → `initialized`. На каждую Session — `thread/start` или `thread/resume`, затем `turn/start` на каждое сообщение. TypeScript-типы генерируются командой `codex app-server generate-ts` для закреплённой версии Codex: «each output is specific to the Codex version you ran». Первый выпуск держится стабильной поверхности (`experimentalApi` выключен): тогда сервер отвергает experimental-методы, и worfy незаметно на них не опирается.
- **Главный риск.** Та же документация пишет: «The app-server command is experimental and isn't supported for production workloads» ([mcp-server](https://learn.chatgpt.com/docs/mcp-server); то же в разделе Code Mode страницы [app-server](https://learn.chatgpt.com/docs/app-server)). Обещания совместимости между версиями нет. Отсюда: версия Codex закрепляется, нужен compatibility suite по версиям и contract test-ы адаптера.

### Чего не знаем

- Разрешает ли OpenAI стороннему desktop-приложению вести Codex по подписке ChatGPT. Документация говорит только, что «usage follows your ChatGPT workspace permissions»; прямого разрешения или запрета для сторонних клиентов не нашли. Плюс app-server помечен «experimental, not supported for production».
- Политики совместимости протокола между версиями нет. Релизы выходят часто: stable 0.165.0 — 2026-10-27, 0.166.0 — 2026-10-29. Насколько ломается стабильная (не experimental) поверхность — проверит только compatibility suite.
- Совпадает ли `main`, по которому читался протокол, с 0.166.0 в деталях полей. Проверить командой `codex app-server generate-ts` на закреплённой версии.
- Один процесс app-server на все Session-ы или процесс на каждую. Протокол допускает много Thread-ов в одном процессе; изоляцию падений и расход памяти не проверяли.
- Как показывать `acceptEdits` и `plan` пользователю. Будет ли `plan` через `collaborationMode` стабильным. Спрашивает ли Codex когда-нибудь о чтении файлов.
- Названия и длительности окон Limits у разных планов (есть ли 5-часовое окно у Plus и Pro) — видно только на живом аккаунте.
- Windows на ПК владельца: доступен ли `mxc`, или понадобится настройка `elevated` с подтверждением UAC.
