# 09 — Limits, Autopilot и Resource Planner при двух Vendor-ах

Type: grilling
Status: done 2026-11-02
Blocked by: 03
Source: [map.md](../map.md), Ticket 01

## Question

Limits — отдельно по каждому Vendor-у или общий вид? Бюджет Autopilot и прогноз Resource Planner — по Vendor-у Session, которая ведёт Run? Что Autopilot делает, когда окно одного Vendor-а кончилось, а у другого есть запас: ждёт сброса, как сейчас, или предлагает продолжить на другом Vendor-е (и если да — в этой карте или после)? Как меняется термин Limits в `CONTEXT.md` («окна подписки Claude»)?

## Answer

Решено Orchestrator-ом 2026-11-02 по поручению владельца («да, можешь работать над этим эпиком полностью на автопилоте»), подтвердить при приёмке. Ticket-ы — в [spec.md](../spec.md).

- **Limits — список окон по Vendor-у.** Панель показывает раздел на каждого Vendor-а, в которого выполнен вход.
- **Термин Limits в `CONTEXT.md` меняется:** «Доля использованных окон подписки Vendor-а и время их сброса; набор окон у каждого Vendor-а свой (у Claude — 5 часов и 7 дней, у Codex — primary и secondary по плану)».
- **Budget Autopilot и прогноз Resource Planner** берут Vendor той Session, которая ведёт Run (его Orchestrator-а).
  - Прогноз для Codex — по самому длинному из пришедших окон, калибровка по проценту, который наблюдается за Wave. Метод тот же, что доля у Claude; до накопления данных он помечен как более широкая неопределённость.
- **Codex `usageLimitExceeded`:**
  - окно на 100 % и у него есть `resetsAt` — Run ждёт сброса, как сейчас;
  - иначе (план не включает Codex, или квота превышена без исчерпанного окна) — Run останавливается с этой причиной и не ждёт.
- **Продолжить Run на другом Vendor-е, когда окно одного кончилось** — вне этой карты. Это отдельная идея на потом, и ей сначала нужны смешанные Vendor-ы по ролям.

Почему так: у Codex набор окон зависит от плана и не имеет имён `five_hour` / `seven_day` (Ticket 03), поэтому модель — список окон с длительностью, а не два поля. Ждать сброса можно только при исчерпанном окне: тем же кодом `usageLimitExceeded` приходят `QuotaExceeded` и `UsageNotIncluded`, у которых сброса нет, и Run ждал бы бесконечно.
