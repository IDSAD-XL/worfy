# 08 — Приёмка Epic-а worfy-faults с владельцем: CI на Mac и Windows и одна ручная проверка на Mac Stable

Type: task
Status: open
Blocked by: 01, 02, 03, 04, 05, 06, 07
Source: [spec.md](../spec.md), «Готово, когда» (все пункты), «Вопросы владельцу», Q7; [ADR-0071](../../../docs/adr/0071-windows-runner-counts-as-the-windows-verdict.md) (job Windows runner-а — вердикт Windows)

## Что происходит

- К claim Ticket-ы 01–07 влиты; сценарии зелёные в CI своих PR.
- Набор — только test-ы; живой Run со сбоем на машине владельца никто не смотрел.
- Приёмку ведёт владелец с Orchestrator-ом, не Autopilot.

## Что делаем

1. Orchestrator собирает «Итог»: SHA последнего merge Epic-а; ссылки на job-ы `linux-tests`, `windows`, `macos-e2e`,
   `windows-e2e` push-а в `main` на этом SHA; таблица «сценарий → файл test-а → время»; таблица «правило → испорченный
   fixture → красный» из Ticket-а 01.
2. **Mac Stable, ручная проверка** (владелец выбрал её в Q7, 2026-11-04): Run на демо-проекте вне репозитория; владелец
   закрывает worfy через Activity Monitor («Force Quit») посреди Wave и запускает снова. Ожидание: Run сам не
   продолжается, Run history показывает прошлый Run оборванным, кнопка Autopilot стартует новый Run.
3. Найденный дефект — новый Ticket Epic-а, его номер дописывается в `Blocked by` этого.
4. Отметки «Готово, когда» в `spec.md` со ссылкой на «Итог».

Не входит: новые сценарии.

## Чек-лист приёмки

Для владельца, на Mac, без ПК, 20–30 мин; время выбирает владелец. Правила И1–И8 — раздел «Правила восстановления»
[spec.md](../spec.md). Команды — из своего worktree: в главном checkout `pnpm` не запускать (он пересобирает
`node_modules` и `node-pty` в дереве Orchestrator-а). Подтверждено владельцем 2026-11-06: состав и порядок шагов.

1. **Worktree, 3–5 мин.** В Terminal:
   ```sh
   R=~/Stuff/CanvasForAI; W=$R/.claude/worktrees/faults-08
   git -C $R fetch origin && git -C $R worktree add --detach $W origin/main
   cd $W && pnpm install --frozen-lockfile
   ```
   Ждём: `install` кончается без ошибки.
2. **Правила на испорченных Journal, 1 мин** (И1–И8, Ticket 01): `pnpm test test/unit/autopilot-invariants.test.ts`.
   Ждём: все test-ы зелёные, exit 0. Хороший Run не нарушает ни одного правила, а каждое правило ловит свою испорченную
   копию из `test/fixtures/autopilot-faults/`.
3. **Contract-сценарии, 1–2 мин** (Ticket-ы 02, 03, 04, 06):
   ```sh
   pnpm test test/contract/autopilot-faults-api.test.ts test/contract/autopilot-faults-process.test.ts test/contract/autopilot-faults-github.test.ts test/contract/autopilot-faults-codex.test.ts
   ```
   Ждём: четыре файла зелёные. Время файлов в выводе vitest — только ориентир: предел 20 s пункта «Время» ниже
   меряется по логу job-а `linux-tests` в CI, его приносит Orchestrator в «Итог».
4. **e2e в собранном приложении, 3–5 мин** (Ticket 05: убитое приложение и GitHub без сети). Экран не блокировать до
   конца. Замок `/tmp/worfy-e2e.lock` — общий с агентами: если `mkdir` отказал, сейчас идёт чужой e2e, повторить позже.
   ```sh
   mkdir /tmp/worfy-e2e.lock && { pnpm test:e2e test/e2e/autopilot-faults.spec.ts; rmdir /tmp/worfy-e2e.lock; }
   ```
   Ждём: `2 passed`. После Ctrl+C замок остаётся — снять его: `rmdir /tmp/worfy-e2e.lock`. Время spec-а здесь —
   ориентир; предел 30 s меряется по логу `macos-e2e` в CI.
5. **Таблицы, 5 мин** (пункт «Владелец прочёл таблицу…» ниже): разделы «Правила восстановления» и «Сценарии»
   [spec.md](../spec.md) и строки `autopilot-faults` таблицы «Tests» в `docs/features/autopilot.md`. Вопрос владельцу:
   какого сбоя не хватает. Ответ «хватает» — набор принят; новый сбой — новый Ticket (Q4).
6. **Mac Stable: Force Quit посреди Wave, 10 мин** (Q7; И1, И4, И6 на живом Run). Тратит немного usage Claude Code.
   1. Stable worfy → Command palette → «Getting started» → шаг 2 «Create demo project» (папка `~/worfy-demo`; если
      Demo project уже есть — он).
   2. На рамке Epic-а `todo` — **Autopilot**. Ждём строку статуса `Wave 1 · running` и команду `/epic-wave` в чате
      Orchestrator-а; ещё 20–30 s, пока implementer работает.
   3. Activity Monitor → worfy → «Force Quit». Запустить Stable worfy снова.
   4. Ждём: в чат Orchestrator-а при старте не ушло ни одного нового сообщения (И1); строки `Wave 1 · running` нет,
      кнопка **Autopilot** активна.
   5. Command palette → «Open Run history». Ждём: выбран прошлый Run, причина — `no stop in the Journal` (И4).
   6. Esc, снова **Autopilot**. Ждём: новый Run, `Wave 1 · running`, без отказа старта (И6). Его можно остановить
      (Stop): дальше usage не нужен.
7. **Уборка, 1 мин:** `cd ~ && git -C ~/Stuff/CanvasForAI worktree remove --force ~/Stuff/CanvasForAI/.claude/worktrees/faults-08`.

Результат — Orchestrator-у: номера шагов, которые не сошлись, и что было на экране. Все сошлись — Orchestrator отмечает
оба пункта «(вручную)» ниже и пишет «Итог». И2, И3, И5, И7, И8 руками не проверяются: их держат шаги 2–4.
