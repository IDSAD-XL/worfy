## Что происходит

- Каждый test Autopilot сверяет свой кусок Journal и сообщений по-своему: `prepare` (`test/e2e/autopilot.spec.ts:161`),
  `journalKinds` и `messages` внутри этого spec-а, свои проверки в `test/contract/autopilot-limits.test.ts`.
- Общей проверки «после сбоя Run ведёт себя правильно» нет. Сценарии Ticket-ов 02–06 должны звать одну и ту же.
- Journal читается `parseJournal` (`src/shared/autopilot/journal.ts`): нечитаемые строки считаются в `skipped`, не
  бросают. `ticket-status` — одна строка на изменение `Status:` (`statusChanges` в `src/main/autopilot/run.ts`).
- Сообщения fake agent — строки `WORFY_AGENT_LOG` в e2e или `FakeCall` в contract (`src/main/agent/fake-query.ts`).
- gh stub пишет в `GH_STUB_LOG` только аргументы каждого вызова, без exit code (`test/fixtures/gh/gh-stub.mjs:37`);
  любая команда кроме чтения — exit 2 (`gh-stub.mjs:100`).

## Что делаем

1. **`test/autopilot-invariants.ts`** — чистые функции без Electron и без файловой системы:
   `checkRecovery(input): string[]` — список нарушений, пустой — всё в порядке. Вход:
   - `events` — события Journal одного или нескольких Run-ов по порядку (файлы читает вызывающий);
   - `messages` — тексты, которые получил Orchestrator, по порядку;
   - `gh` — массивы аргументов вызовов gh stub (необязательно);
   - `statusWrites` — изменения `Status:` Ticket-ов, которые test сделал за Orchestrator-а, со временем;
   - `projectBefore` / `projectAfter` — снимки файлов Project-а (путь → base64), как `files()` в e2e;
   - `expect` — сценарий: ожидаемая причина `run-stopped` (или `resumed`, или «нет `run-stopped`» для убитого
     приложения), регулярное выражение текста причины, число Wave, разрешена ли одна нечитаемая последняя строка.
2. Правила И1–И8 spec-а — по функции на правило, `checkRecovery` зовёт все. И2 сверяет каждую строку лога gh с
   белым списком аргументов чтения (spec, таблица правил). И4 берёт требуемое событие из таблицы причин spec-а
   (`wave-unfinished` и `blocked-tickets` — без события). Текст нарушения — английский, называет
   правило и строку: «I1: /epic-wave for wave 1 sent 2 times».
3. **Fixture-ы** `test/fixtures/autopilot-faults/`: хороший Run после API 500 (Journal, сообщения, лог gh) и по
   одному испорченному варианту на правило — вторая команда Wave, `gh pr merge` в логе gh, лишний и пропущенный
   `ticket-status`, `turn-error` без `session-error` (и `wave-unfinished` без события — не нарушение), `human-input`, отказ нового старта, лишний файл в Project-е,
   нечитаемая строка в середине. Пути и id в fixture-ах — выдуманные (`/tmp/demo`, `demo-000000a4`).
