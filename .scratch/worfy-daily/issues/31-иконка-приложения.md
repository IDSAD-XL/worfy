## Что сейчас

- `pnpm package` собирает `.app` с иконкой Electron. electron-builder пишет в лог «default Electron
  icon is used» с причиной «application icon is not set». В `electron-builder.yml` нет `mac.icon`.
- `pnpm dev` запускает Electron.app из `node_modules`: в Dock — иконка Electron.
- Владелец выбрал знак 2026-10-06, вариант «ABC3». Буква W нарисована волной через узлы. В среднем
  узле — лаймовое ядро (Orchestrator). Вокруг — большая тонкая орбита с одним лаймовым спутником.
  Подложка — графитовый squircle дизайна F. Цвета — токены темы dark из F-SPEC: поверхность
  `#1B1A18`, рамка strong `#3B3834`, текст `#ECE8E1`, лайм `#C8F25A`.
- Исходники финальные, Ticket их не перерисовывает:
  - `build/brand/icon.svg` — холст 1024, тело 824 по сетке иконок macOS (поле 100 с каждой стороны);
  - `build/brand/mark.svg` — упрощённый знак без орбиты для 16–32 px, viewBox 120, без поля сетки.
- Почему `build/brand/`, а не `build/`. `build/` — папка ресурсов electron-builder
  (`directories.buildResources`, значение по умолчанию). Без `mac.icon` electron-builder 26.15.3
  ищет в ней и в корне репозитория `icon.icns`, `icons`, `icon`, `icon.png` и `icon.svg`
  (`app-builder-lib/out/util/iconConverter.js`, функция `buildSourceCandidates`). Файл
  `build/icon.svg` он взял бы сам: при каждом `pnpm package` скачивал бы свой набор инструментов
  для иконок и растеризовал SVG целиком, без упрощённого знака для 16–32 px. Подпапки он не смотрит.

## Что делаем

**1. Иконка пакета.**

- Скрипт `scripts/make-icons.mjs`, команда `pnpm icons`. Он рисует 10 прозрачных PNG iconset-а из
  `build/brand/*.svg` и собирает из них `build/icon.icns` командой `iconutil -c icns`:

  | Файл iconset | px | Источник |
  | --- | --- | --- |
  | `icon_16x16.png` | 16 | `mark.svg` |
  | `icon_16x16@2x.png` | 32 | `mark.svg` |
  | `icon_32x32.png` | 32 | `mark.svg` |
  | `icon_32x32@2x.png` | 64 | `icon.svg` |
  | `icon_128x128.png` | 128 | `icon.svg` |
  | `icon_128x128@2x.png` | 256 | `icon.svg` |
  | `icon_256x256.png` | 256 | `icon.svg` |
  | `icon_256x256@2x.png` | 512 | `icon.svg` |
  | `icon_512x512.png` | 512 | `icon.svg` |
  | `icon_512x512@2x.png` | 1024 | `icon.svg` |

- `mark.svg` встаёт в ту же сетку, что `icon.svg`: тело — 824/1024 стороны, по центру, поле
  прозрачное. Без поля маленькая иконка worfy в Finder крупнее соседних. Скрипт оборачивает
  `mark.svg` во временный SVG с холстом 1024 и тем же `translate(100,100) scale(6.866667)`, что у
  `icon.svg`.
- Рендер — `sips -s format png -z <px> <px> <svg> --out <png>`, новой зависимости нет. На macOS
  26.6.1 `sips` растеризует SVG с прозрачным фоном: проверено 2026-10-06 на обоих SVG — угол
  alpha 0, центр непрозрачный, iconset из 10 PNG проходит `iconutil -c icns` и обратно. Не годится
  `qlmanage -t`: его миниатюры заливают прозрачный фон. Если `sips` на машине не растеризует SVG
  (старая macOS), скрипт падает с понятной ошибкой. Запасной путь — скрытое окно Electron рисует SVG
  на `<canvas>` и отдаёт PNG через `canvas.toDataURL('image/png')`. Выбор — в «Итог».
- Скрипт пишет ещё два файла:
  - `build/icon.png` — 1024 px из `icon.svg`, для Dock в dev (пункт 2);
  - `build/icons.json` — sha256 обоих SVG и список размеров. По нему test ловит SVG, изменённый без
    `pnpm icons`.
- `electron-builder.yml`: `mac.icon: build/icon.icns`.
- В репозиторий идут `build/icon.icns`, `build/icon.png` и `build/icons.json`. Iconset — временная
  папка вне репозитория. Почему не собирать при каждом `pnpm package`:
  - сборка пакета не зависит от `sips`, `iconutil` и того, как установленная macOS рисует SVG;
    результат одинаков на любой машине;
  - картинка меняется редко, файлы небольшие — сотни КБ;
  - устаревший icns ловит test по `build/icons.json`, а не память человека.

## Итог

**Рендер — `sips`, запасной путь через окно Electron не понадобился.** На macOS 26.6.1 `sips`
растеризует оба SVG с прозрачным фоном. Если `sips` не отдал PNG нужного размера, скрипт падает с
понятной ошибкой и кодом 1. Скрипт детерминирован: два запуска подряд дают побайтно одинаковые
`icon.icns`, `icon.png` и `icons.json`.

**Неочевидные решения.**

- `build/icons.json` хранит не только sha256 обоих SVG, но и sha256 `build/icon.icns` и
  `build/icon.png`. Так test ловит и icns, подменённый руками в обход `pnpm icons`.
- `mark.svg` встаёт в сетку только при `viewBox="0 0 120 120"`: другой viewBox скрипт отвергает с
  ошибкой, а не рисует знак мимо сетки.
- Источник размера test определяет по пикселю лаймового спутника на орбите: он есть только в
  `icon.svg`. Сетку — по прозрачному углу и прозрачному полю у левого края.
- `mac.icon` в `electron-builder.yml` формально избыточен: без него electron-builder сам находит
  `build/icon.icns` в папке ресурсов. Строка оставлена явной, чтобы сборка не зависела от порядка
  поиска кандидатов. Поэтому мутант «убрать `mac.icon`» test не ловит. Мутант «как на main» (нет
  `mac.icon`, `build/icon.icns`, `build/icon.png`) test ловит: `CFBundleIconFile` = `electron.icns`.
- `installDevDockIcon` не роняет запуск и при исключении из `setIcon`: оно уходит в лог
  предупреждением.

**Проверено руками.** Иконка, которую macOS отдаёт для собранного `dist/mac-arm64/worfy.app`
(`NSWorkspace.iconForFile`, то же, что рисует Finder): 512 px — полный знак с орбитой
([../evidence/31-app-icon-512.png](../evidence/31-app-icon-512.png)), 32 и 16 px — упрощённый
знак без орбиты ([../evidence/31-app-icon-32.png](../evidence/31-app-icon-32.png),
[../evidence/31-app-icon-16.png](../evidence/31-app-icon-16.png)). `pnpm dev` с этой веткой
запускается, предупреждения «no Dock icon» в логе нет.

**Не проверено: Dock, Cmd-Tab, уведомление и «About worfy» — у стабильной копии и в `pnpm dev`.**
2026-10-07 у Stable copy проверены «About worfy» и Cmd-Tab — подраздел [«Ручная проверка 2026-10-07»](#ручная-проверка-2026-10-07).
У процесса агента нет права Screen Recording (`screencapture` отвечает «could not create image
