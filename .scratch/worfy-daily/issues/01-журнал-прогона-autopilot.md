## Что делаем

Журнал прогона — файл, куда Autopilot пишет каждое своё событие. По нему утром видно, что
происходило ночью и где понадобился бы человек. Сейчас журнала нет. Единственная дозапись в файл —
`WORFY_AGENT_LOG` fake-агента (`src/main/agent/app-registry.ts:47-51`), и она только для test-ов.

**Формат.** JSONL, одна строка на событие:
`{ "at": <ISO-время>, "run": <id прогона>, "project": <ключ Project>, "epic": <имя>, "kind": <вид>, ...поля вида }`.

- Файл: `<dataRoot>/autopilot/<run>.jsonl`. `run` — время старта плюс короткий суффикс. Один файл на
  прогон, отдельной ротации нет.
- worfy пишет только в dataRoot (`src/main/storage/paths.ts:10-13`, ADR-0005). В репозиторий
  Project и в `~/.claude` журнал не пишется.
- Путь к папке собирается в самом `journal.ts` как `join(dataRoot(), 'autopilot')`. `paths.ts` не
  меняется.

**`src/shared/autopilot/journal.ts`** — чистый код: типы событий и разбор файла.

- Виды событий: `run-started`, `wave-started`, `wave-finished`, `limits-hit`, `waiting-until`,
  `resumed`, `session-error`, `refused-dialog`, `human-input`, `run-stopped` (с причиной).
- `human-input` — любое вмешательство человека в прогон. Поля: `source` и `what`.
  - `source: "worfy"` пишет сам worfy (Ticket 04) на действие пользователя в Session прогона:
    сообщение Orchestrator-у или его Subagent-у, «Send queued», смена режима или модели, ручной
    перезапуск Session.
  - `source: "observer"` пишет агент-наблюдатель: касание вне worfy, которое видно только на экране
    (системный диалог macOS, Keychain, ручной перезапуск приложения). Он дописывает строку в тот же
    файл по формату из комментария, без кода worfy.
  - На такую запись ссылается `Source` Ticket-а, заведённого по вмешательству (условие готовности 2
    в [spec.md](../spec.md)).
- Комментарий в начале файла описывает формат. По нему агент-наблюдатель читает журнал без кода
  worfy.
- Строка неизвестного вида и оборванная последняя строка (после аварийного завершения) разбор не
  роняют. Такие строки пропускаются, и разбор возвращает их число.

**`src/main/autopilot/journal.ts`** — работа с файлами:

- открыть новый прогон;
- дописать событие — одна строка за вызов, через `appendFile`;
- список прогонов Project, последний первым;
- чтение одного прогона через разбор из shared.

Образец записи файлов — `src/main/storage/json-file.ts`.

Показа журнала в UI в этом Ticket-е нет. Ticket 04 показывает только строку состояния прогона.

## Итог

- **Падающий test первым.** `test/unit/autopilot-journal.test.ts`, случай «оборванная последняя
  строка», до кода падал на импорте: `Failed to resolve import "../../src/shared/autopilot/journal"`
  (`pnpm test test/unit/autopilot-journal.test.ts`, код 1). После `src/shared/autopilot/journal.ts`
  — 12 из 12 зелёные.
- **Поля видов.** Ticket задал только виды; поля выбраны так: `wave-started` и `wave-finished` —
  `wave` (номер от 1) и `tickets` (номера Ticket-ов строками); `limits-hit` — `window` и `resetsAt`
  (ISO или `null`); `waiting-until` — `until`; `session-error` — `session` (id или `null`) и
  `message`; `refused-dialog` — `session` и `what`; `human-input` — `source` и `what`;
  `run-stopped` — `reason` свободным текстом. Ticket 04 и 05 могут добавить поле: строки старого
  формата при этом остаются читаемыми, если новое поле необязательное.
- **`at`** — ISO 8601 с `Z` или со смещением: наблюдатель пишет время из shell, где удобнее
  `date -Iseconds` с местным смещением.
- **id прогона** — `2026-10-06T01-02-03-004Z-a1b2c3`: время старта в UTC без `:` и `.` плюс шесть
  hex-цифр. Имя файла проверяется по этому шаблону и при чтении, поэтому `readRun('../x')`
  отказывает, а не читает файл вне папки журнала.
- **Одна папка на все Project-ы**, как сказано в Ticket-е: `<dataRoot>/autopilot/`. Принадлежность
  прогона Project-у берётся из поля `project` строки `run-started` (если её нет — из первой
  читаемой строки). Файл без единой читаемой строки в список не попадает.
- **Порядок дозаписи.** `append` пишет одной `appendFile` на строку; вызовы одного прогона идут
  цепочкой, поэтому строки лежат в порядке вызовов, даже если их не ждали по одному. Неудачная
  запись отклоняет только свой вызов. Новый прогон создаёт файл с флагом `wx`: чужой файл с тем же
  id не дописывается, берётся новый суффикс.
- **Строка вне формата** не пишется: `formatJournalLine` разбирает событие схемой, лишние ключи
  отбрасывает, общие поля (`at`, `run`, `project`, `epic`) ставит сам журнал.
- **Mutation testing** (копии в scratchpad, восстановление из копии): 15 мутантов — без очереди
  дозаписи, очередь без `catch`, без сортировки, без фильтра по Project, `ENOENT` при чтении
  бросает, без `wx`, `listRuns` создаёт папку, поля события перекрывают общие, `readRun` без
  проверки id, запись и разбор сырого значения вместо разобранного, пустая строка считается
  пропущенной, `at` без смещения, шаблон id без `^` и без `$`. Все красные.
- Ручных пунктов в Ticket-е нет; UI не меняется.
