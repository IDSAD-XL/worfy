## Что делаем

- Каждая живая Сессия Проекта из реестра (тикет 13) получает Узел Сессии с пометкой «read-only»,
  источником («terminal · <cwd>» или «Claude desktop»), статусом `idle | busy` и заголовком.
  Узел появляется, когда Сессия стартует, и остаётся со статусом «finished», когда процесс
  кончился; скрыть его можно, удалить — тоже, Сессия от этого не меняется.
- Сессия, запущенная самим worfy, тоже пишет транскрипт. Узел всё равно один: совпадение по
  `sessionId`, Сессия worfy главнее (опирается на ответ 06, вопрос 7).
- Двойной щелчок — Session view: тот же `Transcript.tsx`, события из файла, поле ввода скрыто,
  вместо него строка «Read-only: started in terminal».
- **Одна схема событий для обоих источников.** Тикет 13 разбирает транскрипт в свою схему
  `transcriptEventSchema` (`src/shared/transcript/parse.ts`), потому что `src/shared/agent/events.ts`
  тикета 07 к тому времени ещё не было. Здесь их сводят: `parse.ts` выдаёт события из
  `events.ts` (общие виды `text`, `thinking`, `tool_use`, `tool_result`, `hook`, `subagent`,
  `unknown` — одной схемой; виды только из файла, `command` и `title`, добавляются в
  `events.ts`), канал `claudeHome.transcript` отдаёт их же, и `Transcript.tsx` принимает
  события любого источника без перевода. Contract test-ы 13 на fixtures 09 остаются зелёными.
- `SessionNode.tsx` — общий Узел Сессии для внешних и (в тикете 18) запущенных в worfy. Слот
  бейджей — тот же, что у Тикета.
- Sidebar, раздел «Sessions»: «N live» и список живых Сессий Проекта; щелчок — к Узлу.

**Неочевидные решения.**

- Дедупликация: Сессия worfy главнее. Её id — `data.sessionId` любого Узла не вида `session`
  (Оркестратор) или id из `agent.list`; такой Сессии внешний Узел не создаётся, а созданный раньше,
  чем worfy назвал id, удаляется. `agent.list` спрашивается только когда план что-то создаёт.
- Удалённый пользователем Узел не возвращается, пока приложение запущено (память «уже был Узел» в
  renderer). После перезапуска живая Сессия снова получит Узел: помнить удаление в Раскладке — лишнее
  состояние, которое никто не просил.
- Конец процесса без удаления файла реестра не даёт события файловой системы. Поэтому renderer
  спрашивает только живые Сессии новым каналом `claudeHome.live` (без чтения истории) при изменении
  реестра и раз в 2 с, пока есть живые Сессии. Отсюда правка вне следа: `src/main/ipc/claude-home.ts`
  и метод `ClaudeHomeRegistry.live` в `src/main/claude-home/registry.ts`.
- История (заголовки) читается заново один раз для Сессии, новой для renderer, и ещё раз — на
  ближайшем опросе после изменения её транскрипта, пока у живой Сессии нет ни `name` в реестре, ни
  заголовка в истории: файл реестра может появиться раньше, чем первый промпт создаст транскрипт.
  Не больше одного чтения истории за опрос (2 с), и ни одного, когда заголовок уже есть.
- Hook из файла показывается по тому же правилу, что у живой Сессии (`hookSaidSomething`): ненулевой
  код, исход не success или вывод. Молчаливые Stop hook-и из файла больше не выходят из разбора.
- Синхронный вызов Agent в файле даёт `subagent started` и сразу `subagent finished` со статусом из
  `toolUseResult` — иначе Transcript показывал бы его «running» навсегда.
- `unknown` из файла: в `sdkType` — тип записи (`attachment/invoked_skills`), `<тип>:invalid` для
  записи неожиданной формы, `line:unparsable` для строки не JSON.
- Slash-команда из файла рисуется строкой `rows/CommandRow.tsx` (точка расширения), `fold.ts` и
  `Transcript.tsx` не правились: режим только для чтения живёт в `ExternalSessionPanel.tsx`.
- Правки центральных файлов, без которых не обойтись: `SessionView.tsx` (ветка на внешнюю Сессию),
  `navigation.ts` (поле `external`), `canvas/badges/index.ts` (вид `session` в `SlotSubject`).
