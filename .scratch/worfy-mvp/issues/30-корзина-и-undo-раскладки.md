## Что делаем

- **Undo / redo** (`history.ts`): ⌘Z и ⇧⌘Z отменяют и повторяют операции Раскладки — создание,
  сдвиг, размер, скрытие, удаление, теги, закрепление. Глубина 40 шагов. Отмена — обратная
  операция, отправленная в main тем же каналом, что и любая другая: Раскладку по-прежнему пишет
  только main. Операции, пришедшие от агентов через MCP-tools, в историю пользователя не
  попадают.
- **Удаление**: Delete или кнопка в панели выделения (`SelectionToolbar.tsx`). Удалять можно
  Карточки, заметки, Терминалы, Узлы внешних Сессий (сама Сессия не трогается). Узлы с `locked`
  (Оркестратор, HANDOFF, Тикеты, рамки Эпиков) не удаляются. Занятую Сессию нельзя.
- **Корзина** (`src/main/layout/trash.ts`): удалённая Карточка переезжает с файлами и данными в
  `<папка Проекта>/trash/<метка>/` вместе с записью Раскладки. Popover «Trash» показывает
  содержимое и «Restore». Записи старше 3 дней удаляются при запуске.
- Удаление и корзина работают только внутри папки данных worfy: файлы репозитория и транскрипты
  Claude Code не удаляются никогда.

Решения, которые не очевидны из кода:

- **Историю держит renderer, Раскладку по-прежнему пишет только main.** Шаг истории — пара функций
  «отменить / повторить»; для операции Раскладки это обратная операция и сама операция, посланные
  тем же `layout.apply`; для удаления — `trash.restore` и повторный `trash.put` (новая метка).
  Обратная операция считается по копии Раскладки в renderer (последний ответ main) прямо перед
  отправкой.
- **В историю пишут только жесты пользователя**, и граница проходит по каналу, а не по фильтру:
  `LayoutOps` из `LayoutOpsContext` (его даёт `Canvas.tsx`) записывает каждую операцию, поэтому
  через него идут только жесты пользователя. Всё автоматическое шлёт `applyLayoutOp` напрямую, мимо
  истории: синхронизация Узлов внешних Сессий (`overlays/SessionNodes.tsx`, исправлено после
  ревью — до этого её создания и удаления попадали в историю, и ⌘Z удалял новый Узел Сессии
  вместо шага пользователя), источники Эпиков и Субагентов. MCP-tools и сам main вызывают
  `LayoutStore.apply` напрямую. Отмена после таких правок откатывает только шаг пользователя;
  если агент удалил Узел, обратная операция отклоняется main, шаг выбрасывается, следующий ⌘Z
  идёт к шагу перед ним.
- **Что записывается:** `create`, `move`, `resize`, `hide`, `remove`, `tag`, `pin` и удаление в
  корзину. Не записываются `setViewport` и `patchData` (текст заметки — у поля ввода своя отмена);
  сдвиги рамок Эпиков и Тикетов идут через источник Узлов (`source.moved`) и тоже не записываются.
  Создание без id получает id в renderer (`crypto.randomUUID()`), чтобы отмена могла его назвать.
- **Создание и удаление Узла возвращают Узел таким, каким он был, когда уходил.** Отмена `create`
  (и повтор `remove`) перед `remove` читает Узел из текущей Раскладки и запоминает его; повтор
  `create` (и отмена `remove`) создаёт этот запомненный Узел. Так текст, набранный в новой заметке
  (`patchData`, сам не шаг), переживает ⌘Z и ⇧⌘Z. Отмена создания убирает Узел обычным `remove`, не
  в корзину: корзина — для удалений пользователя. Цена: если после такой отмены сделать новый
  шаг, повторить создание уже нельзя, и набранный текст пропадает, как в любом редакторе.
- **Один жест — один шаг** (`grouped`): перетаскивание нескольких Узлов, тег или Pin на всё
  выделение, удаление выделения. Отмена группы выполняет все части, даже если одна отклонена.
  Группа (`Group`) передаётся операциям жеста явно (`ops.apply(op, group)`), а не лежит в
  глобальной переменной модуля: операция другого жеста, завершившаяся, пока группа ждёт ответа
  main, остаётся отдельным шагом. Шаг, пришедший в уже закрытую группу, записывается отдельно.
- **Что удаляется в корзину:** виды `card`, `note`, `terminal`, `session`, без `locked`
  (`trashRefusal` в `src/shared/ipc/trash.ts`, общая для кнопки и main). Оркестратор и HANDOFF
  (`locked`), рамки Эпиков и Тикеты (производные Узлы, ADR-0011; их id в Раскладке нет либо вид
  `epic-frame` / `ticket`) — отказ. Узел Сессии, на котором worfy сейчас ведёт Сессию (вид её не
  `closed`), main отклоняет с текстом «close the Session before deleting its Node» — то же правило,
  что у кнопки Remove на самом Узле. «Занятая» Сессия понята как «запущенная», а не только «идёт
  ход»: удалить Узел с живой Сессией значило бы оставить её без Узла. Кнопка «Delete» для такой
  Сессии активна, отказ main показывается в панели выделения текстом (renderer не знает
  состояния всех Сессий выделения без новой подписки).
- **Карточка уезжает в корзину с файлами, только если её не показывает другой Узел** (`data.cardId`
  другого Узла указывает на неё); иначе в корзину идёт только запись Узла.
- **Restore отклоняется**, если id Узла снова занят или Карточка с тем же id уже записана заново:
  чужие файлы не перезаписываются, запись остаётся в корзине.
- **Существующие кнопки Узлов** (закрыть Терминал, Remove у Сессии) по-прежнему шлют `remove`, а не
  кладут в корзину; теперь это шаг истории — ⌘Z возвращает Узел (у Терминала — с новым shell).
- **Клавиши** работают, когда Холст на экране и фокус на нём или нигде (не в поле ввода, не в
  слое focus mode, не в sidebar). Пункт меню Edit ▸ Undo — роль Electron, отменяет ввод текста, а
  не Раскладку; ⌘Z с клавиатуры перехватывается страницей раньше.
- **Очистка при запуске** — в `src/main/ipc/trash.ts` через `setTimeout(…, 0)` по всем Проектам
  списка; возраст записи берётся из её метки. Посторонние файлы и папки в `trash/` не трогаются.
