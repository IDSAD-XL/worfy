## Что делаем

worfy должен видеть Сессии Проекта, где бы они ни были запущены. Источник — только файлы Claude
Code под `WORFY_CLAUDE_HOME`.

- `src/main/claude-home/registry.ts`:
  - живые Сессии — `sessions/*.json`, чей `cwd` равен корню Проекта или лежит внутри одного из его
    worktree (`git worktree list --porcelain`). Жива, если процесс `pid` существует. Статус
    `idle | busy`, `entrypoint`, имя;
  - история — все `projects/<папка cwd>/*.jsonl` для корня и worktree Проекта: `sessionId`,
    заголовок, время первой и последней записи, `cwd`, `gitBranch`. Для списка читаются только
    начало и хвост файла, не весь файл;
  - слежение за `sessions/` и папками транскриптов, debounce, канал `claudeHome.changed`.
- `src/main/claude-home/tail.ts`: чтение транскрипта по смещению в байтах; неполная последняя
  строка ждёт следующего чтения; усечённый или пересозданный файл читается заново.
- `src/shared/transcript/parse.ts` — чистая функция «строка JSONL → события»: те же события, что
  у живой Сессии (`src/shared/agent/events.ts` из тикета 07), чтобы один `Transcript.tsx`
  показывал оба источника. Неизвестный тип записи или поле — событие `unknown`, без исключения.
  Записи Subagent-ов (`isSidechain`, `agentId`) помечаются, но дерево строит тикет 15.
- Каналы: `claudeHome.sessions` (живые и история Проекта), `claudeHome.transcript` (события с
  позиции), `claudeHome.changed`.
- Ничего не пишется в `WORFY_CLAUDE_HOME`: ни кэша, ни меток. Кэш индекса, если нужен, — в папке
  данных Проекта.

Решения, которых нет в тикете:

- **События транскрипта — своя схема в `parse.ts`, а не `src/shared/agent/events.ts`.** Тикет
  велит отдавать «те же события, что у живой Сессии» из тикета 07, но 07 идёт в той же волне 3
  параллельно, и на базе `7fd8b74` файла `events.ts` нет. Схема `transcriptEventSchema` (zod)
  названа так же, как события из текста тикета 07: `text`, `thinking`, `tool_use`,
  `tool_result`, `hook`, `subagent`, `unknown`; плюс два вида, которых у SDK-потока нет: `command`
  (slash-команда пользователя) и `title` (`custom-title`, `ai-title`, `agent-name`). Свести две
  схемы в одну — работа того тикета, который первым показывает оба источника одним
  `Transcript.tsx` (тикет 14), или 07, если он вольётся позже и захочет взять эту схему.
- **Что считается `unknown`.** Событие определяют `type` записи и `message.content[].type`
  (вывод 09). Всё остальное — служебные записи (`queue-operation`, `last-prompt`, `pr-link`,
  `mode`, `file-history-snapshot`, `bridge-session`), attachment-ы кроме `hook_*`, system кроме
  `stop_hook_summary`, неизвестные блоки — событие `unknown` с `recordType`, `subtype` и
  причиной (`unknown-type`, `unparsable`, `invalid-shape`). Лишние поля записи в событие не
  попадают.
- **Subagent-ы.** Каждое событие несёт `sidechain` и `agentId` записи. Запуск Subagent-а —
  событие `subagent` с `phase: started` рядом с `tool_result`, если у записи есть
  `toolUseResult.agentId`; task-notification — `subagent` с `phase: notification` (`task-id`,
  `tool-use-id`, `status`, `summary`, `result`). Дерево и файлы `subagents/` — тикет 15, в
  историю они не входят.
- **Подписка на `claudeHome.changed`.** Отдельного канала подписки нет: вызов
  `claudeHome.sessions` подписывает окно-отправителя на изменения этого Проекта (один watcher на
  пару окно + Проект), подписка снимается, когда окно уничтожено. Событие называет, что
  изменилось: `sessions` (реестр) и `transcripts` (id Сессий); renderer дочитывает транскрипт
  через `claudeHome.transcript` со своего курсора.
- **Курсор транскрипта** — `{offset, fileId}`, где `fileId` = `dev:ino`. Файл читается заново с
  начала (`reset: true`), если он короче смещения, если это другой файл (новый inode) или если
  байт перед смещением уже не перевод строки (файл переписан на месте). Чтение ограничено
  `maxBytes` (по умолчанию 1 MB, `more: true` — читать дальше); строка длиннее окна
  возвращается целиком.
- **Жива ли Сессия** — как решил 09: `process.kill(pid, 0)` (EPERM тоже «жив») и совпадение
  `procStart` с `ps -p <pid> -o lstart=` при `TZ=UTC LC_ALL=C`. Файлы `<pid>.<sha256>.key`
  не открываются. Статус вне `idle | busy` отдаётся как `unknown`.
- **Папки истории.** Корень Проекта и worktree-ы из `git worktree list --porcelain` (только
  чтение репозитория; ошибка git — пустой список), плюс все папки с префиксом
  `<папка корня>--claude-worktrees-`: так в историю попадают удалённые worktree (вывод 09 про
  51 недостающую Сессию Auction). Новые такие папки подхватывает и watcher.
- **Заголовок в истории** — последняя `custom-title`, иначе последняя `ai-title`, иначе первый
  user-текст без `isMeta` (slash-команда даёт `/имя`, текст, начинающийся с `<`, пропускается).
  Ищется в голове и хвосте файла (по 64 KB, голова растёт до 1 MB, если в ней нет целой строки),
  середина не читается; `custom-title` только из середины файла не будет найден (test это
  фиксирует). `<sessionId>/custom-title.json` не читается.
- **Слежение** — chokidar 5 на корне Claude home, глубина 2, с фильтром по пути: смотрятся только
  `sessions/<pid>.json` и `projects/<папка Проекта>/<id>.jsonl`; остальные каталоги не
  обходятся. Debounce 150 мс.
- **ADR не нужен**: всё решение — пять файлов одного модуля, заменяется без миграции данных
  (worfy ничего не хранит).
