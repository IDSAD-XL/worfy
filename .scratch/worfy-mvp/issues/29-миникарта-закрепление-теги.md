# 29 — Миникарта, закрепление Узла на экране и теги Узлов

Type: task
Status: done — 2026-10-05, [PR #14](https://github.com/IDSAD-XL/worfy/pull/14)
Blocked by: 05
Source: [spec.md](../spec.md), этап 5; [BRIEF.md](../../../docs/design/BRIEF.md), Screen 1 «minimap bottom-right»

## Что делаем

- **Миникарта** (`MiniMapOverlay.tsx`): внизу справа, Узлы окрашены по типу токенами темы,
  щелчок и перетаскивание двигают viewport. Скрывается из меню View.
- **Панель выделения** (`SelectionToolbar.tsx`): появляется над выделенными Узлами; здесь кнопки
  этого тикета, дальше её дополняет 30.
- **Закрепление на экране** (`pinning.ts`): «Pin» оставляет Узел на месте экрана при pan и zoom
  (рисуется в слое поверх Холста), «Unpin» возвращает его на Холст в текущую точку под ним.
  Хранится в поле `pinned` Раскладки (заведено в 05). Защита от удаления — отдельное поле `locked`
  (Оркестратор, HANDOFF, Тикеты, рамки Эпиков); этот тикет его не трогает, и «Pin» не делает Узел
  неудаляемым.
- **Теги** (`tags.ts`): свободные строки на Узле, видны в его заголовке; добавить и убрать из
  панели выделения, для нескольких Узлов сразу. Хранятся в поле `tags` Раскладки. Фильтр по тегу
  — в палитре (31).

- [x] Тег, добавленный трём Узлам сразу, виден на каждом и переживает перезапуск.

## Итог

Сделано:

- **Миникарта** — `src/renderer/canvas/overlays/MiniMapOverlay.tsx` (+ `minimap.css`): React Flow
  `<MiniMap>` внизу справа, цвет Узла — токен темы, который объявляет файл его типа
  (`export const minimapColor` рядом с `kind`; реестр `nodes/index.ts` его собирает и проверяет).
  `note` — `--border-strong`; тип без цвета и неизвестный `kind` — `--text-muted`. Новый тип Узла
  заводит свой цвет в своём файле, общих файлов не правит. Щелчок центрирует viewport на точке
  щелчка с тем же zoom (`setCenter`), перетаскивание по миникарте панорамирует (`pannable`).
  Закреплённые Узлы на миникарте не рисуются: их нет на плоскости.
- **Меню View ▸ Show Minimap** — меню приложения собирает `src/main/menu.ts` (стандартное меню
  Electron по ролям: App, File, Edit, View, Window, плюс checkbox в конце View), ставит его
  `src/main/index.ts` после `whenReady`. Что переключают пункты View — новый IPC-домен `view` по
  ADR-0006: `src/shared/ipc/view.ts` (`view.get`, событие `view.changed`) и `src/main/ipc/view.ts`
  (состояние, рассылка окнам, обработчик). Состояние живёт в памяти main до выхода; после
  перезапуска миникарта снова показана.
- **Панель выделения** — `overlays/SelectionToolbar.tsx`: `NodeToolbar` над выделенными Узлами;
  панель — ряд секций (`SELECTION_SECTIONS`), каждая получает Layout-записи выделенных Узлов и
  сама шлёт операции. Тикет 30 добавляет свою секцию одной строкой в этот список.
- **Закрепление** — `src/renderer/canvas/pinning.ts`: пересчёт экран ↔ Холст через viewport,
  операции Pin / Unpin, размещение закреплённых Узлов на плоскости под текущий viewport и размер
  Холста (`usePinnedPlacement`, подписка только пока есть закреплённый Узел). Кнопка «Pin»
  закрепляет незакреплённые Узлы выделения, «Unpin» (когда закреплены все) возвращает на Холст.
  Ни Pin, ни Unpin не двигают Узел на экране и не меняют его размер на экране при любом zoom:
  операция `pin` несёт и положение, и размер (`w`, `h`), пересчитанные через viewport.
  Закреплённый Узел, чьё сохранённое место не помещается в Холст (окно меньше, чем в момент
  закрепления), показывается сдвинутым внутрь Холста, и «Unpin» кладёт его туда, где он показан.
  Main отказывает в `move` и `resize` закреплённому Узлу, кто бы их ни прислал (renderer, MCP-tools
  тикета 24): его x, y, w, h — экранные пиксели. `locked` не трогается: закреплённый Узел
  удаляется как обычный (contract-test).
- **Теги** — `src/renderer/canvas/tags.ts` (нормализация: trim, схлопывание пробелов, до 40
  символов; объединение тегов выделения со счётчиком; операции на добавление и удаление).
  В панели выделения: «Add tag» → поле, Enter добавляет тег всем выделенным; у каждого тега
  выделения «×» снимает его со всех выделенных, которые его несут.
- **Обёртка Узла** — `src/renderer/canvas/NodeChrome.tsx` (+ `node-chrome.css`): теги в правой
  части заголовка любого Узла и рамка закреплённого Узла, без правки файлов типов Узлов;
  `src/renderer/canvas/withNodeChrome.ts` оборачивает в неё компонент типа.
- **Раскладка** — две новые операции в `src/shared/layout/types.ts`, применяются в
  `src/main/layout/store.ts`: `pin {id, pinned, x, y, w, h}` и `tag {id, add[], remove[]}` (тег
  проверяется схемой: строка, trim, 1–40 символов; не больше 50 тегов в операции); `move` и
  `resize` закреплённого Узла main отклоняет.
- **`Canvas.tsx`** — каждый тип Узла регистрируется через `withNodeChrome`, React Flow получает
  Узлы после `usePinnedPlacement`; два импорта отдельными строками после импорта `useLayout`.

Неочевидные решения:

- Test-ы названы `pinning.test.tsx` и `tags.test.tsx`, а не `.ts`, как в разделе «Тесты»:
  проект typecheck-а `tsconfig.test.node.json` не включает `src/renderer/`, а `.tsx`-test-ы
  идут в проекте jsdom, где renderer виден.
- Закреплённый Узел нельзя тащить мышью и менять ему размер ручками: чтобы сдвинуть, его
  открепляют, двигают и закрепляют снова. Перетаскивание в экранных координатах потребовало бы
  своей обработки drag поверх React Flow — не в объёме тикета.
- Закреплённый Узел остаётся Узлом React Flow (а не отдельным слоем вне его): так работают
  выделение, `NodeToolbar` и hooks типов Узлов (`NodeResizer`). Рамка `NodeChrome` сама
  ставит Узел по viewport текущего рендера, поэтому при pan он не отстаёт на кадр.
- Меню собирается целиком из ролей (Electron не даёт дописать пункт в стандартное меню без его
  замены). Пункты стандартного меню сохранены, кроме Help (у Electron там ссылки на сайт Electron).
- След тикета перечислял только renderer-файлы, но операций для `pinned` и `tags` в Раскладке не
  было (тикет 05 завёл только поля), а пункта меню View нет без кода main. Поэтому правка вышла за
  след: `src/shared/layout/types.ts`, `src/main/layout/store.ts`, `src/main/index.ts` (одна
  строка: меню), `src/renderer/canvas/Canvas.tsx`, `src/renderer/canvas/nodes/index.ts` и
  `NoteNode.tsx` (цвет на миникарте), новые `src/main/menu.ts`, `src/shared/ipc/view.ts`,
  `src/main/ipc/view.ts`, `src/renderer/canvas/NodeChrome.tsx`, `withNodeChrome.ts`, CSS
  оверлеев; test-ы `test/unit/canvas.test.tsx`, мок `Menu` в
  `test/contract/main-ipc-wiring.test.ts`, точка щелчка в `test/e2e/canvas-layout.spec.ts`.

- Первый CI run PR упал на двух test-ах `test/e2e/canvas-layout.spec.ts` (тикет 05): щелчок по
  пустому Холсту в точке (700, 500), чтобы снять фокус с `note`, в окне CI меньшего размера
  попадал на миникарту, и она перехватывала щелчок. Точка перенесена в левый верхний угол
  Холста (40, 40); смысл test-ов не менялся.

- Закреплённый Узел, который не помещается в Холст, сдвигается внутрь целиком (а не «хотя бы
  краешком»): так он всегда достижим, а Pin Узла, торчащего за край, ставит его внутрь. У нижнего
  правого угла он может оказаться под миникартой — она рисуется поверх Узлов.
