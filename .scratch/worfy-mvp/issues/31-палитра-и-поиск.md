## Что делаем

- **Палитра** (⌘K, `CommandPalette.tsx`): одно поле, нечёткий поиск, ↑/↓ и Enter. Команды
  (`commands.ts`) собираются из того, что уже есть:
  - перейти к Эпику, Тикету (`worfy-mvp/07`), Сессии, Карточке, ADR;
  - «New session», «New terminal»;
  - «Ship ticket <эпик>/<NN>», «Run wave <эпик>» — те же действия и те же условия активности, что
    кнопки из 23;
  - переключить Canvas / Session; показать только Узлы с тегом; переключить Проект.
- **Поиск** (⌘F, `CanvasFind.tsx`): строка поиска поверх Холста; ищет в заголовках Узлов,
  заголовках Тикетов, тексте открытых транскриптов, HANDOFF и видимом тексте Карточек (`card.text`
  из 26). Число совпадений, Enter / ⇧Enter — следующее / предыдущее, Холст подъезжает к нему и
  подсвечивает Узел. Есть выделение — поиск только в нём. Esc закрывает.
- `search-index.ts` — чистые функции индекса и ранжирования; индекс обновляется по событиям, а не
  пересобирается на каждый символ.

## Итог

Сделано: командная палитра ⌘K и поиск по Холсту ⌘F.

- **Палитра** — `src/renderer/palette/CommandPalette.tsx`. Поле «Search or run… ⌘K» в toolbar
  (тикет 03) стало кнопкой: щелчок или ⌘K открывает одно поле над окном, ↑/↓ выбирают, Enter
  запускает, Esc закрывает. Команды — `src/renderer/palette/commands.ts` (`buildCommands`): «New
  session» (тот же `sessions.new`, что в sidebar), «New …» из `createLabel` файлов типов Узлов
  (тот же реестр, что меню Холста, ADR-0014), «Run wave <эпик>» и «Ship ticket <эпик>/<NN>» (те же
  `actions.runWave` / `actions.shipTicket`, что кнопки тикета 23; активность считают те же
  `runWaveState` / `shipTicketState` и `useLaunched`, неактивная строка показывает ту же причину в
  `title`, Enter по ней ничего не делает), «Switch to Canvas / Session», «Show only tag <тег>» и
  «Show all Nodes», «Switch to project <имя>» (`projects.select`), переход к Эпику, Тикету, Сессии,
  Карточке, любому Узлу Раскладки и ADR. Команды для Тикетов в работе и готовых не заводятся — у
  них нет кнопки.
- **Ранжирование** — `src/renderer/find/search-index.ts` (`rankItems`): точный ключ (номер Тикета
  «07», «7», «worfy-mvp/07»; номер ADR; id Карточки) выше любого совпадения в заголовке, дальше
  начало заголовка, начало слова, подстрока в заголовке, подстрока в detail, все слова запроса,
  буквы по порядку.
- **Поиск** — `src/renderer/find/CanvasFind.tsx`, overlay Холста (подключён файлом
  `src/renderer/canvas/overlays/CanvasFind.tsx`, одна строка re-export). Ищет в заголовках Узлов
  (`data.title`, иначе первая строка `data.text`), заголовках Эпиков и Тикетов, транскриптах
  Сессий, открытых в этом окне (события `useSessionLogs`), HANDOFF.md и видимом тексте Карточек
  (`card.text`). Число совпадений, Enter / ⇧Enter — следующее / предыдущее, Холст подъезжает к
  Узлу, текущий Узел обведён сплошной линией, остальные с совпадениями — пунктиром, под строкой —
  поле и кусок текста вокруг совпадения. Выделение в момент открытия ⌘F — область поиска (метка
  «in selection»), вместе с тем, что внутри выделенных Узлов; повторный ⌘F при открытой строке
  берёт выделение заново (если область изменилась, переход по совпадениям начинается сначала).
  Esc закрывает. Запрос короче 2
  символов ничего не ищет; счёт останавливается на 1000 («1000+»).
- **Индекс** (`FindIndex`): документы хранятся в нижнем регистре, `sync()` пересчитывает только
  изменившиеся документы и вызывается, когда меняется источник (Раскладка, модель workflow, события
  Сессии, HANDOFF, ответ Карточки), а не на символ. Запрос, который только дописали, ищет по
  документам, совпавшим с прошлым.
- Запросы палитры к Холсту (центрировать, создать Узел, фильтр тега, открыть ADR) —
  `src/renderer/find/canvas-requests.ts`: палитра живёт в toolbar вне React Flow, поэтому
  оставляет запрос, а overlay внутри React Flow его выполняет. Новый Узел идёт через `LayoutOps`
  Холста и попадает в историю ⌘Z, как пункт меню Холста.

Проекте отдельно не мерилась.

Неочевидные решения:

- Переход из палитры не меняет выделение (в отличие от sidebar, который выделяет Сессию):
  выделение — область ⌘F, и переход к Узлу не должен сужать следующий поиск.
- Тикет, которого нет на Холсте (свёрнутая рамка, сложенная стопка готовых), — палитра и поиск
  центрируют его рамку Эпика.
- «Show only tag» — вид этого окна, не сохраняется: Узлы без тега и рёбра к ним скрываются
  правилом CSS (`visibility: hidden`), под Холстом — плашка «Only tag … · Show all». Рамки Эпиков и
  Тикеты тегов не имеют и при фильтре скрыты.
- Открыть ADR из палитры — запрос в `canvas-requests.ts`, его выполняет `AdrSection.tsx`: панель
  ADR живёт там. `seq` запроса только растёт, а номер последнего выполненного запроса
  (`adrHandled`) хранится в том же store, а не в sidebar: так каждый следующий «Go to ADR»
  открывается, а sidebar, показанный заново, не открывает тот же ADR второй раз. При скрытом
  sidebar запрос ждёт, пока sidebar покажут; запрос для другого Проекта отбрасывается.
- Когда кнопки «Run wave» и «Ship ticket» есть и активны ли они — общий код
  `src/renderer/canvas/actions/gates.ts` (`hasRunWave`, `hasShipTicket`, `useRunWaveState`,
  `useShipTicketState`); его вызывают и кнопки тикета 23 (`EpicActions.tsx`, `TicketActions.tsx`),
  и строки палитры, так что правило не расходится.
- Пункты «New …» палитра берёт не из реестра типов Узлов напрямую: их публикует Холст
  (`CanvasFind.tsx` кладёт тот же список, что у `CanvasMenu.tsx`, в `canvas-requests.ts`). Иначе
  toolbar тянул бы `canvas/nodes/index.ts` с его `import.meta.glob`, и в CI тест
  `test/unit/canvas.test.tsx` («draws a Node type added as one file») падал: shell-тесты, идущие
  параллельно, разворачивали glob раньше, чем тест кладёт свой файл типа Узла (run 37362886833).
  Новый Узел из палитры встаёт в центр видимой части Холста в момент команды.
- Текст Карточки спрашивается при открытии ⌘F, после остановки Холста (250 мс), при смене набора
  Карточек и раз в 1.5 с, пока какая-то Карточка не ответила. Карточка отвечает, только пока её
  страница запущена (на экране и при масштабе ≥ 0.4, `CardNode.tsx`); последний ответ хранится,
  пока строка поиска открыта.
