## Что делаем

Сессии, запущенные в терминале или Claude desktop, worfy видит только через файлы Claude Code. Это
внутренний формат без обещаний совместимости. Прежде чем писать разбор (тикет 13), нужно знать,
что в файлах есть на самом деле, как формат менялся между версиями и сколько там данных.

Обойти скриптом (только чтение) `~/.claude` и ответить:

1. `~/.claude/sessions/<pid>.json`: поля (`sessionId`, `cwd`, `status`, `entrypoint`, `name`,
   `updatedAt` …), как понять, что процесс жив (pid существует), что остаётся после выхода.
2. `~/.claude/projects/<cwd>/<sessionId>.jsonl`: правило превращения cwd в имя папки (сверить на
   путях с точками, пробелами и кириллицей), типы записей и их доли по версиям Claude Code (поле
   `version`), откуда брать заголовок Сессии (`custom-title`, summary, первое сообщение
   пользователя).
3. Subagent-ы: `<sessionId>/subagents/agent-<id>.jsonl` и `agent-<id>.meta.json`; как связать
   запуск Agent tool (`tool_use` → `toolUseResult.agentId`) с файлом; вложенность
   (`spawnDepth`); где итог; как выглядит task-notification о завершении фонового агента.
4. Где в транскрипте видны: Bash-команда `ticket claim <эпик> <NN>`, вызов skills
   `/ship-ticket` и `/epic-wave` (`invoked_skills`, текст команды), вывод `gate.sh`
   (`hook_success.stdout`, `tool_result`), `gitBranch`, `cwd`.
5. Объёмы на Auction: число файлов, самый большой транскрипт, время полного чтения против
   чтения хвоста.

Итог — заметки в «Итог» и обезличенные fixtures: короткие транскрипты из 3–4 версий Claude Code,
с подменой текста сообщений и путей, но с сохранённой структурой записей. Тикет 13 пишет на них
contract test-ы.

### 1. Реестр `sessions/<pid>.json`

- 6 файлов, все 6 процессов живы. Поля во всех файлах: `pid`, `sessionId`, `cwd`, `startedAt`
  (мс), `procStart`, `version`, `peerProtocol`, `peerFeatures`, `kind` (везде `interactive`),
  `entrypoint` (`claude-desktop` 5, `cli` 1), `pidDomain`, `messagingSocketPath`, `name`,
  `nameSince`, `status` (`idle` 5, `busy` 1), `updatedAt`, `statusUpdatedAt`. Не во всех:
  `hostSessionId` (5, только desktop), `bridgeSessionId` (4), `nameSource` (3: `user`, `derived`).
- Рядом с каждым лежит `<pid>.<sha256>.key`. Скрипт его не открывает, worfy тоже не должен.
- Жива ли Сессия: `process.kill(pid, 0)` без ошибки (EPERM тоже значит «процесс есть»). От
  переиспользования pid защищает `procStart`: это `ps -p <pid> -o lstart=` в **UTC**
  (`TZ=UTC LC_ALL=C`), совпало 6 из 6. В местном времени строка на 3 часа другая.
- Что остаётся после выхода: при 178 транскриптах в реестре 6 записей, и все шесть живы — запись
  удаляется при выходе. После `kill -9` файл остаётся со `status: "idle"` (проверено 2026-10-06
  ночью, подраздел [«Ручная проверка 2026-10-06, ночь»](#ручная-проверка-2026-10-06-ночь)). Поэтому «жива» — это
  pid + `procStart`, а не наличие файла.
- Записей с `kind` не `interactive` (SDK-сессии) в реестре не встретилось — это тикет 06.
- Образцы: `sessions/41004.json` (cli, busy, cwd — worktree), `sessions/41005.json` (desktop,
  idle, `hostSessionId`, `bridgeSessionId`).

### 2. Транскрипты `projects/<папка>/<sessionId>.jsonl`

**Имя папки.** На macOS cwd приводится к NFC, затем каждый символ вне `[A-Za-z0-9]` заменяется на
`-`. Если имя длиннее 200 символов — первые 200 + `-` + base36 от |hash|, где hash — 32-битный
`h = h*31 + charCode`. Источник — код Agent SDK
(`node_modules/@anthropic-ai/claude-agent-sdk/sdk.mjs`, функции с `replace(/[^a-zA-Z0-9]/g,"-")`).
На реальных данных cwd первой записи совпадает с папкой в 170 из 178 файлов, хотя бы одной записи —
в 177 из 178. Расхождения — Сессии, продолженные из другого каталога, и `cd` посреди Сессии
(есть запись `relocated` с `relocatedCwd`). Значит, папка — это cwd запуска, а поле `cwd` в
записях может меняться. Точки (76 файлов) и пробелы (2) проверены на данных. Кириллицы и путей
длиннее 200 символов в данных нет: правило взято из кода SDK, и SDK `listSessions` находит
fixture с кириллицей. Образцы: `projects/-Users-test-My-Projects-demo-app/` (пробел, точка, `cd`
в подпапку), `projects/-Users-test-------/` (`/Users/test/проект`).

Внутри `<sessionId>/` бывают `subagents/` (131 Сессия), `tool-results/` (47),
`custom-title.json` (33, `{customTitle}`), `workflows/` (10).

**Типы записей.** 224 066 записей в 178 главных транскриптах, нечитаемых строк 0. Поле `version`
есть только у `user`, `assistant`, `attachment`, `system`. Служебные записи без `version` — 30 %

### Решение для тикета 13 (не ADR)

В Agent SDK 0.3.289 (уже зависимость, ADR 0004) есть свой разбор этих же файлов: `listSessions`,
`getSessionInfo`, `getSessionMessages`, `listSubagents`, `getSubagentMessages`. Записи он не
пишет (проверено на копии fixtures: mtime и sha1 всех файлов не изменились). Но
`getSessionMessages` отдаёт только `user`/`assistant`/`system` с `message: unknown`, без
attachment и `toolUseResult`, а worfy нужны именно они (agentId, вывод gate, task-notification).
Рекомендация: свой разбор событий в `src/shared/transcript/parse.ts`, правила (имя папки, порядок
заголовка, голова+хвост) — как в SDK; `listSessions` годится как образец или для индекса истории.
Решение обратимо (один модуль), поэтому ADR не нужен.
