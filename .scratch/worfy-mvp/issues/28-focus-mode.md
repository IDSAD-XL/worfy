# 28 — Focus mode: выбранные Узлы на весь экран плиткой, остальной Холст скрыт

Type: task
Status: claimed — 2026-10-05
Blocked by: 05
Source: [spec.md](../spec.md), этап 5; поведение Morphy описано в `INVENTORY-ui-domain.md`, раздел 3.2 (описание поведения, код не переносится — [ADR-0001](../../../docs/adr/0001-clean-room-reimplementation.md))

## Что делаем

- Выделить Узлы → кнопка «Focus» (оверлей у выделения, `FocusEntry.tsx`) или ⌘↩: выделенные
  Узлы занимают всё окно плиткой, остальные скрыты, pan и zoom выключены. Esc — выход, Холст
  возвращается в прежний вид.
- Плитка — дерево разбиений (`split-tree.ts`, чистые функции): перетаскивание границы меняет
  доли; двойной щелчок по границе выравнивает; перетаскивание заголовка Узла на другую плитку
  меняет их местами, на край плитки — делит её.
- Пресеты: Even, Main + side, Columns, Rows.
- Внутри плитки Узел живёт как обычно: транскрипт обновляется, поле ввода работает, Карточка
  исполняется.
- Раскладка Холста в focus mode не меняется: плитка — отдельное состояние, не сохраняется между
  запусками.

## Готово, когда

- [x] Перетаскивание границы и пресеты меняют доли; двойной щелчок выравнивает.

## Итог

Сделано: focus mode — слой поверх всего окна (`createPortal` в `document.body`, `position: fixed`),
в нём выделенные Узлы плиткой. Вход — кнопка «Focus ⌘↩» над выделением (`NodeToolbar` React Flow)
или ⌘↩; выход — Esc или «Exit focus». Пресеты Even, Main + side, Columns, Rows.

Как падал первый test: `test/unit/split-tree.test.ts`, «divides the target tile at the edge the
moved tile was dropped on» — при заготовке `splitTile`, возвращавшей дерево без изменений, ожидание
`row[a, column[b, c]]` с долями `[1/3, 2/3]` не совпало с исходным `row[a, b, c]` (`pnpm test
test/unit/split-tree.test.ts`, код 1). После реализации — зелёный.

Решения, которые не очевидны из кода:

- **Canvas.tsx не тронут.** Оверлеи Холста находятся сами (`canvas/extensions.ts`,
  `import.meta.glob('./overlays/*.tsx')`), поэтому `FocusEntry.tsx` подключается одним файлом, без
  строки в Canvas.tsx (бриф допускал одну строку).
- **Focus mode не трогает Холст и Раскладку.** Слой непрозрачный и закрывает Холст целиком;
  viewport React Flow не меняется, ни одной операции Раскладки focus mode сам не шлёт, поэтому
  «Esc возвращает тот же viewport» выполняется без сохранения и восстановления. Pan и zoom выключены
  тем, что колесо и мышь до Холста не доходят, а ⌘= / ⌘− / ⌘0 перехватываются на window в фазе
  capture (иначе обработчик зума в Canvas.tsx приблизил бы невидимый Холст, и `setViewport`
  записал бы `layout.json`).
- **Узел в плитке — второй экземпляр его компонента.** Плитка рисует компонент типа Узла
  (`nodes/index.ts`) с теми же `data` из store React Flow; экземпляр на Холсте под слоем остаётся
  смонтированным. Для `note` это проверено e2e (ввод в плитке доходит до main, копия на Холсте
  показывает текст). Тип Узла, который не терпит двух экземпляров одновременно (например, держит
  единственное подключение к pty), должен это учесть — касается тикета 27 (Узел Терминал).
  Внутри плитки компонент получает `selected: false`, поэтому `NodeResizer` в плитке не рисуется;
  `NodeIdContext` React Flow не экспортирует, `useNodeId()` в плитке вернёт `null`.
- **Перетаскивается заголовок плитки**, а не заголовок самого Узла: у каждого типа Узла свой
  заголовок, focus mode добавляет над ним общую тонкую полосу «⠿ <title>» (`data.title` или kind).
  Бросок в пределах 25 % от края целевой плитки делит её у этого края, в середине — меняет местами.
- **⌘↩ ловится в фазе capture** и не доходит до Узла: React Flow по Enter на Узле в фокусе
  переключает его выделение (с ⌘ — снимает), и focus mode открывался бы на пустом выделении. В
  полях ввода ⌘↩ не перехватывается (оставлен полю ввода сессии).
- **Esc** выходит, если его не обработал (`preventDefault`) сам Узел — так попап внутри Узла может
  закрываться по Esc, не закрывая focus mode.
- Узел, который удалили или скрыли во время focus mode, уходит из плитки; когда не осталось
  ни одного, focus mode закрывается (`test/unit/focus-mode.test.tsx`).
- **Клавиатурный фокус — в слое.** При входе фокус переходит на корень слоя (`tabIndex=-1`), а
  остальные дочерние элементы `body` получают `inert` (снимается при выходе только с тех, кому его
  поставил focus mode). Иначе клавиши доходили до Узла Холста под слоем: React Flow двигал выделенные
  Узлы стрелками и снимал выделение по Esc, и Холст расходился с Раскладкой в main (находка ревью).
  `inert` заодно не пускает Tab на Холст под слоем. При выходе фокус возвращается туда, где был, —
  кроме Узла Холста вне видимой области: React Flow при фокусе с клавиатуры центрирует такой Узел, и
  viewport изменился бы. Вход кнопкой «Focus» фокус не возвращает: кнопка при входе размонтируется.
- **Перетаскивание заголовка плитки хранится в ref**, как перетаскивание границы; state только
  рисует его: pointerup может прийти раньше, чем React отрисовал предыдущий pointermove
  (jsdom test: pointermove и pointerup в одном `act`). Причиной потерь в e2e это не было — см. ниже.
- **Жесты заголовка и границы идут по window, а не по pointer capture** (круг исправления после
  второго ревью). Прежняя запись здесь называла причиной потерь обмена и деления плиток в e2e
  чтение state вместо ref; это было неверно. Настоящая причина найдена журналом pointer-событий в
  e2e под нагрузкой: посреди перетаскивания приходит pointermove без нажатой кнопки в точке вне
  пути жеста (во всех случаях одна и та же точка окна, 975×784; вероятно, это настоящий курсор,
  под которым появилось окно соседнего worker-а), Chromium из-за него снимает pointer capture
  (`lostpointercapture`, pointercancel не приходит), и остаток жеста — pointermove и pointerup —
  уходит в элементы под курсором, а не в заголовок или границу. Граница при этом останавливалась
  на 20 px из 120, обмен и деление терялись. Теперь pointerdown подписывает на window (фаза
  capture) pointermove, pointerup, pointercancel и pointerdown этого указателя
  (`followPointer` в `FocusMode.tsx`), pointer capture только убирает hover с остального слоя.
- **Решения внутри этой правки.** Потеря capture жест не завершает: это ровно тот случай, на
  котором терялись жесты (ревью предлагало завершать жест по `lostpointercapture` — тогда потери
  остались бы). pointermove без нажатой кнопки пропускается, а не считается отпусканием — по той же
  причине. Отпускание, которого focus mode не увидел (кнопку отпустили над другим приложением),
  проявляется следующим нажатием: оно отменяет жест без броска. pointercancel отменяет жест; выход
  из focus mode посреди жеста снимает подписки. Каждое из этих правил покрыто jsdom test в
  `test/unit/focus-mode.test.tsx`, который краснеет на мутанте этого правила (проверено).
- **Замеры e2e** (`playwright test test/e2e/focus.spec.ts`, три test-а файла; падения — из
  первого test-а, строки обмена, деления и границы). До правки: `--repeat-each=40 --workers=6` —
  3 падения из 120 (граница 1, деление 2), `--repeat-each=60 --workers=8` — 0 из 180; с журналом
  событий 40×6 — 4 из 120. Промежуточная версия, которая отменяла жест по pointermove без кнопки, —
  1 падение из 600 (40×6 и 60×8 по два раза): журнал и показал, что такой pointermove — не
  отпускание. После правки: 40×6 четыре раза и 60×8 четыре раза — 0 из 1200; с журналом
  событий 3×40 прогонов первого test-а — 3 потери capture посреди жеста, все 120 прошли. Сам e2e
  test не менялся: гонки в нём не нашлось, ожидание индикатора броска перед `mouse.up` не
  понадобилось.
- **Кнопка «Focus» — под выделением, а не над ним** (тот же круг). После rebase на main, где
  появилась панель выделения тикета 29 (`SelectionToolbar.tsx`, Pin и Tags, `NodeToolbar` сверху),
  кнопка «Focus» легла поверх неё, и три e2e test-а `test/e2e/pin-tags.spec.ts` падали: клик по Pin
  перехватывала кнопка. `FocusEntry.tsx` ставит её снизу (`Position.Bottom`, отступ 12 px), а
  первый test `test/e2e/focus.spec.ts` проверяет, что кнопка не пересекает панель выделения
  (краснеет, если вернуть кнопку наверх).
- Вне следа: `src/renderer/focus/focus.css` (стили слоя, новый файл в каталоге тикета) и одна
  строка в `tsconfig.test.node.json` — `src/renderer/focus/split-tree.ts` в `include`, иначе
  node-test `test/unit/split-tree.test.ts` (имя из раздела «Тесты») не проходит typecheck: проект
  test.node видит только `src/main`, `src/preload`, `src/shared`. Новый jsdom test
  `test/unit/focus-mode.test.tsx` (фокус, ушедший Узел, жест заголовка) — по требованию ревью.
