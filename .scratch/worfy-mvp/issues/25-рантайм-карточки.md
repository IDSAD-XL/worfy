## Что делаем

Карточка — папка `<папка Проекта>/cards/<id>/` с `index.html` (и, если нужно, своими css/js/картинками).

- Протокол `worfy-card://` (`src/main/cards/protocol.ts`) регистрируется как привилегированный до
  `app.ready`. Адрес `worfy-card://<id>.<ключ проекта>/<путь>`: у каждой Карточки свой origin,
  одна Карточка не видит другую и не видит окно worfy.
- Отдаются только файлы из папки этой Карточки (`realpath` внутри папки, белый список
  расширений), с заголовками: CSP `default-src 'self'; script-src 'self' 'unsafe-inline';
  style-src 'self' 'unsafe-inline'; img-src 'self' data: https:; font-src 'self' data: https:;
  connect-src https:; frame-src 'none'; form-action 'none'; object-src 'none'; base-uri 'none'`,
  `X-Content-Type-Options: nosniff`, `Cache-Control: no-store`.
- `CardNode.tsx`: заголовок из `<title>`, iframe `sandbox="allow-scripts allow-same-origin"`
  (origin свой, поэтому `allow-same-origin` не даёт доступа к окну). Навигация iframe наружу и
  `window.open` запрещены в main. При zoom < 0.4 вместо живого iframe — заголовок и рамка (для
  скорости).
- `src/main/cards/store.ts`: список Карточек Проекта, слежение за папками; правка файла
  перезагружает iframe ≤ 1 с; Карточка, чьей папки больше нет, показывает «Card files missing».
- Карточка живёт только в папке данных worfy (`~/Library/Application Support/worfy/<ключ
  проекта>/cards/`). Переноса Карточки в репозиторий Проекта нет: worfy ничего не пишет в
  репозитории ([ADR-0005](../../../docs/adr/0005-worfy-own-state-inventory.md)).

## Итог

Сделано: протокол `worfy-card://` (`src/main/cards/protocol.ts`) — привилегированная схема
(`standard`, `secure`), регистрация до `app.ready`, отдача только обычных файлов из папки
Карточки (`realpath` внутри `<папка данных Проекта>/cards/<id>/`, сама папка Карточки — не
симлинк наружу, белый список расширений), на каждом ответе (и на 404) CSP из тикета,
`X-Content-Type-Options: nosniff`, `Cache-Control: no-store`. Main не пускает фрейм Карточки
никуда, кроме её же origin (`will-frame-navigate`), запрещает `window.open` из Карточки и
отказывает Карточке в web-разрешениях (камера, уведомления и т. п.). `src/main/cards/store.ts` —
список Карточек Проекта, `<title>` из `index.html`, слежение за папкой `cards/` (chokidar, тишина
100 мс) и номер ревизии Карточки. `CardNode.tsx` — Узел `kind = 'card'`: заголовок из `<title>`,
iframe `sandbox="allow-scripts allow-same-origin"`, новый iframe на каждую ревизию, «Card files
missing» без папки, при zoom < 0.4 — заголовок в рамке без iframe.

Первый test падал так: `test/contract/card-protocol.test.ts` → «answers 404 to a path that climbs
out of the Card folder with ..». Сначала — нет модуля `src/main/cards/protocol.ts`; затем, с
обработчиком без проверки «путь внутри папки Карточки», — `expected 200 to be 404`: запрос
`worfy-card://c1.0a1b2c3d/..%2F..%2Flayout.json` отдавал `layout.json` Проекта.

Проверки: `pnpm lint && pnpm typecheck && pnpm test` — код 0 (464 test-а);
`gate.sh fast` — код 0, `[gate] зелено (fast)`; `pnpm test:e2e` — код 0 (26 test-ов, из них 4 новых
в `test/e2e/card-runtime.spec.ts`). Два мутанта в `protocol.ts` (убрать `preventDefault` навигации,
разрешать web-разрешения Карточке) краснят e2e на нужных строках.

Решения и отступления от текста тикета:

- **Адрес Карточки — `worfy-card://<id Карточки>.<метка Проекта>/`, где метка — 8 hex-символов в
  конце id Проекта, а не весь «ключ проекта».** Ключ проекта — имя папки плюс хеш; имя папки может
  содержать заглавные буквы, пробелы, кириллицу, а хост URL стандартной схемы их не несёт без
  изменений (пробел — невалидный URL, заглавные приводятся к строчным). Метка находит Проект по
  списку; если меток две одинаковых — 404. Черновик ADR ниже.
- **id Карточки — одна DNS-метка**: `[a-z0-9]`, дефисы внутри, до 63 символов
  (`CARD_ID_PATTERN`, `src/shared/ipc/cards.ts`); UUID подходит. Тикету 24 (`create_card`) —
  заводить id по этому шаблону.
- **Узел Карточки**: `kind: 'card'`, Карточка — `data.cardId`, а если его нет — id Узла. Проект
  Узла — активный Проект (тот же, что показывает Холст). Тикету 24 — ставить Узел с этим `kind`.
- **Вне следа тикета пришлось тронуть** (без этого рантайм не работает):
  `src/main/index.ts` — регистрация схемы до `ready` и `installCardRuntime` до первого окна
  (привилегии схемы задаются только до `ready`, а модули IPC грузятся после);
  `src/renderer/index.html` — CSP окна получила `frame-src worfy-card:` (иначе `default-src 'self'`
  запрещает iframe Карточки); `test/contract/main-ipc-wiring.test.ts` — мок `electron` дополнен
  `protocol`/`session` и test-ом порядка «схема → обработчик → окно»; новый IPC-домен по точке
  расширения — `src/shared/ipc/cards.ts` (`cards.get`, событие `cards.changed`) и
  `src/main/ipc/cards.ts`.
- **`connect-src https:` (как в тикете) не включает `'self'`**: Карточка не может `fetch`-ом
  прочитать свои же файлы (JSON рядом с `index.html`); `<script src>`, `<link>`, `<img>` свои файлы
  грузят. e2e это фиксирует. Если понадобится — добавить `'self'` в `connect-src` осознанно.
- **Навигацию фрейма Карточки на https/file:// первой останавливает CSP окна** (`frame-src
  worfy-card:`), фрейм показывает страницу ошибки; на другой `worfy-card://` origin — main
  (`will-frame-navigate`), Карточка продолжает работать. Обе стены проверены e2e.
- `fetch('https://…')` проверен без https-stub: запрос к `https://127.0.0.1:9/` не даёт нарушения
  CSP (падает только сетью), а `worfy-card://` и `file://` дают нарушения.
- Папка `cards/` Проекта создаётся в папке данных worfy при первом запросе Карточки, чтобы за ней
  можно было следить до появления первой Карточки (ADR-0005: это собственное состояние worfy).
- Ручная проверка в собранном `.app` из Finder не делалась: всё, что требует «Готово, когда»,
  проверено e2e против собранного `out/`.

### Черновик ADR: Адрес и изоляция Карточки — свой origin `worfy-card://<id>.<метка проекта>`

Дата: 2026-10-05. Статус: черновик (номер выдаст оркестратор).

Карточка — исполняемый HTML/JS, написанный агентом. worfy показывает её в iframe на своей
привилегированной схеме `worfy-card://` (`standard`, `secure`), у каждой Карточки свой origin
`worfy-card://<id Карточки>.<метка Проекта>`, где метка — 8 hex-символов хеша пути Проекта из его
id. iframe — `sandbox="allow-scripts allow-same-origin"`: origin свой, поэтому доступа к окну
worfy (file:// или dev-сервер) и к другим Карточкам нет. Протокол отдаёт только файлы из папки
Карточки с CSP (`connect-src https:`, `frame-src 'none'`, без форм и плагинов), main не пускает
фрейм на чужой origin, не открывает окна и не даёт web-разрешений.

Решение трудно обратимо: origin — ключ хранилищ браузера Карточки (localStorage, IndexedDB в
userData worfy) и ожидаемый origin в мосте `postMessage` (тикет 26). Смена схемы адреса теряет
данные Карточек в этих хранилищах и меняет проверку отправителя.

#### Considered Options

- Весь ключ Проекта в хосте (`<id>.<ключ>`, как в тикете 25) — отвергнуто: имя папки Проекта с
  пробелами, заглавными или не-ASCII буквами не проходит в хост без искажения.
- Ключ Проекта в hex/base32 в хосте — отвергнуто: длинные имена папок не помещаются в метку DNS
  (63 символа), а адрес становится нечитаемым.
- Один origin на все Карточки с путём `/<проект>/<id>/` — отвергнуто: Карточки видели бы
  хранилища и DOM друг друга.
- `srcdoc`/`data:` без своего протокола — отвергнуто: opaque origin без своих файлов и без
  контроля заголовков.
