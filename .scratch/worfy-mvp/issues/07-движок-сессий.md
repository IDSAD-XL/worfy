## Что делаем

Main умеет держать несколько живых Сессий одновременно. Каждая — один долгий вызов SDK `query()`
с асинхронным входом: сообщения пользователя кладутся в него по одному, Сессия не пересоздаётся
между ходами.

- Опции (`src/main/agent/options.ts`): `cwd` — корень Проекта; `settingSources: ['user',
  'project', 'local']`; системный промпт — preset `claude_code` без своих добавок (добавки придут
  в 24); `permissionMode` по умолчанию `bypassPermissions` вместе с
  `allowDangerouslySkipPermissions: true` (ответ 06, вопрос 9); `includePartialMessages` и
  `includeHookEvents`; `resume`, если Сессия продолжается.
- Окружение (`src/main/agent/env.ts`, ADR-0007): переменные интерактивного login shell
  пользователя — `$SHELL -ilc`, запущенный из минимального окружения (`HOME`, `USER`, `LOGNAME`,
  `SHELL`, `TMPDIR`, `LANG`, `SSH_AUTH_SOCK`, `__CF_USER_TEXT_ENCODING`,
  `PATH=/usr/bin:/bin:/usr/sbin:/sbin`), печатает `env -0` между маркерами; снимается один раз,
  с таймаутом. Из результата убраны только `ANTHROPIC_API_KEY` и `ANTHROPIC_AUTH_TOKEN`. Ключей
  API worfy не хранит и не принимает.
  Приложение, запущенное из Finder, получает от launchd голый `PATH`: без login shell ни Claude
  Code, ни hooks пользователя не найдут `node`, `pnpm`, `gh`.
- **Собранное приложение** (ADR-0008). SDK запускает нативный бинарник Claude Code из
  платформенного пакета `@anthropic-ai/claude-agent-sdk-<platform>-<arch>/claude`, а файл внутри
  `app.asar` запустить нельзя. `electron-builder.yml` (тикет 32) получает `asarUnpack` для
  `node_modules/@anthropic-ai/claude-agent-sdk-*/**`. `options.ts` задаёт
  `pathToClaudeCodeExecutable` только в сборке — путь в `app.asar.unpacked`; в `pnpm dev` SDK
  находит бинарник сам. `executable` не задаётся: `node` для запуска не нужен.
- **Stop hook пользователя.** `~/.claude/hooks/stop.sh` блокирует конец хода (exit 2), пока Gate
  worktree красный, до двух раз за Сессию: ход продолжается сам, без сообщения пользователя.
  Движок считает такие продолжения частью того же хода: состояние `busy` держится до
  окончательного `result` и после него никогда не остаётся `busy`; каждое срабатывание hook-а —
  событие `hook`, видимое в транскрипте. Форма сообщений — из ответа 06, вопрос 2: событие
  строится из `hook_response` (`stop_hook_summary` в поток SDK не приходит).
- Сообщения SDK превращаются в свои события (`src/shared/agent/events.ts`, zod-схемы):
  `init` (модель, режим, `apiKeySource` — только для показа, slash-команды), `account` (вход по
  `accountInfo()`, ADR-0009), `text`, `thinking`, `tool_use`, `tool_result`, `hook`, `subagent` (запуск Agent tool и
  task-notification), `rate_limit`, `result` (стоимость, токены, длительность, ошибка), `state`
  (`starting | busy | idle | needs_permission | error | closed`). Неизвестное сообщение SDK не
  роняет Сессию, а превращается в событие `unknown` с типом — его видно в отладке.
- Каналы: `agent.start`, `agent.send`, `agent.interrupt`, `agent.close`, `agent.list` и поток
  `agent.event` с `sessionId`. Сессия получает свой `sessionId` из `system/init`; до этого
  renderer видит временный id, который потом заменяется.
- `WORFY_AGENT=fake`: вместо `query()` — `fake-query.ts`, который проигрывает сценарий из
  `test/fixtures/agent-scripts/<имя>.jsonl` (имя передаётся в test-е). Сценарии на этот тикет:
  обычный ход, ход с ошибкой, ход, прерванный `interrupt`, ход, который Stop hook продлевает
  дважды.
- Падение процесса Claude Code переводит Сессию в `error` с текстом; повторная отправка
  поднимает её через `resume`.

### Решения, которых нет в тексте тикета

- **`init` приходит только с первым сообщением.** Настоящий SDK не шлёт `system/init`, пока в
  Сессию не положено сообщение (проверено: 8 с ожидания без сообщения — ни одного `init`).
  Поэтому `starting` → `idle` переключает ответ `accountInfo()`: процесс поднялся и вход известен
  (событие `account`). Slash-команды до первого хода приходят событием `commands`
  (`system/commands_changed`, 4 раза за старт).
- **Временный id и событие `renamed`.** `agent.start` отвечает `pending-<uuid>`. Когда `init`
  приносит id Claude Code, Сессия переходит на него и шлёт `renamed` с прежним id; события до
  него идут под временным id, с него — под настоящим. Каналы принимают оба id.
- **Какой `hook_response` становится событием `hook`.** Только hook, который что-то сказал:
  код выхода не 0, `outcome` не `success`, непустой `stdout` или `stderr`. Молчаливые
  SessionStart и Stop hooks (их по три на ход) в поток не идут. На настоящем `stop.sh` это три
  события на ход: две блокировки (exit 2) и `additionalContext` (exit 0 с выводом). Синтетическое
  сообщение «Stop hook feedback» — событие `notice` с `kind: synthetic`, чтобы оно не выглядело
  как текст пользователя.
- **`busy` держится до `result`.** `idle` ставит только `result`; `init` при `idle` — начало хода,
  отправленного во время предыдущего, и снова `busy` (test «a message sent during a turn runs as
  the next turn»).
- **Пометка прерывания.** `interrupted: true`, если `terminal_reason` — `aborted_streaming` или
  `aborted_tools`, либо ход кончился ошибкой после `agent.interrupt`. Ход, завершившийся
  нормально несмотря на запрос, прерванным не считается.
- **Падение Claude Code.** Исключение итератора или конец потока без `agent.close` — состояние
  `error` с текстом ошибки и последними строками stderr. Следующий `agent.send` запускает новый
  `query()` с `resume` = id Claude Code; без `init` до падения — новую Сессию.
- **Окружение.** Снимается при первом `agent.start` и запоминается до конца работы приложения.
  Если shell не ответил за 10 с, упал или не напечатал маркеры, Claude Code получает минимальное
  окружение (тоже без ключей API), в лог — предупреждение. Маркеры окружены NUL с обеих сторон,
  а не только завершены им, как в ADR-0007: rc-файл, который печатает текст без перевода строки и
  NUL, склеивал его с первым маркером, и окружение терялось (поймано test-ом
  «keeps a value with a newline whole and ignores what the rc file prints»).
- **Сессии закрываются при выходе из приложения** (`will-quit` → `closeAll()`).
- **Сессия закрывается вместе с окном, которое её запустило** (доработка по ревью). На macOS
  приложение переживает своё окно, а `activate` открывает новое; события Сессии привязаны к
  `webContents` окна, так что после Cmd+W Сессия держала бы процесс Claude Code с
  `bypassPermissions`, а её события никто бы не видел. `agent.start` вешает на `webContents` один
  обработчик `destroyed` на окно, и он закрывает все Сессии этого окна (`src/main/ipc/agent.ts`,
  `ownership()`). Другой путь — слать события окну, которое на них подписано, — отложен: подписки
  на Сессию в renderer пока нет (её заводит тикет 33), и решать за него, кто подписчик, рано.
  Если `send` бросает внутри `destroyed`, остальные Сессии окна всё равно закрываются, а реестр
  забывает закрытую Сессию в `finally`.
- **`agent.start` с `resume` живой Сессии отказывает** («Session <id> is already live»).
  Сравнивается и id Сессии, и SDK id, известный из `resume` до первого `init`: иначе два процесса
  Claude Code писали бы один транскрипт, события обеих Сессий шли бы под одним id, а после
  закрытия одной другая пропадала бы из реестра, оставаясь живой. Отказ выбран вместо «вернуть
  живую Сессию»: окно, которое просит `resume`, может не быть владельцем той Сессии и не получит
  её событий.
- **Директивы fake-агента для путей ошибок** (доработка по ревью): `{"fake":"exit"}` — поток
  кончается без исключения, `{"fake":"stderr","text":…}` — строка в stderr Claude Code,
  `{"fake":"account","error":…}` — `accountInfo()` отклоняет запрос. Сценарии `exit.jsonl` и
  `account-error.jsonl`; в `crash.jsonl` перед падением строка stderr.
- **MCP-серверы пользователя не трогаются.** Риск размера контекста из 06 (634 tools, «Prompt is
  too long» на haiku) остаётся за моделью пользователя: Сессия идёт на модели из его настроек, у
  владельца это `claude-opus-5-5[1m]` (окно 1M токенов, `init` ручного прогона). worfy не
  отключает connectors и не включает tool search: так Сессия совпадает с `claude` в терминале
  (ADR-0002). Не проверено: сколько стоит ход на этой модели с 634 tools — ход на opus с таким
  контекстом стоит долларов, на замер их не тратил.
