## Что делаем

Main умеет держать несколько живых Сессий одновременно. Каждая — один долгий вызов SDK `query()`
с асинхронным входом: сообщения пользователя кладутся в него по одному, Сессия не пересоздаётся
между ходами.

- Опции (`src/main/agent/options.ts`): `cwd` — корень Проекта; `settingSources: ['user',
  'project', 'local']`; системный промпт — preset `claude_code` без своих добавок (добавки придут
  в 24); `permissionMode` по умолчанию `bypassPermissions` (нужен ли вдобавок
  `allowDangerouslySkipPermissions: true` — по ответу 06, вопрос 9); `resume`, если Сессия
  продолжается.
- Окружение (`src/main/agent/env.ts`): `PATH` и прочие переменные из login shell пользователя
  (`$SHELL -lc env`, снимаются один раз при старте, с таймаутом), из окружения убраны
  `ANTHROPIC_API_KEY` и `ANTHROPIC_AUTH_TOKEN`. Ключей API worfy не хранит и не принимает.
  Приложение, запущенное из Finder, получает от launchd голый `PATH`: без login shell ни Claude
  Code, ни hooks пользователя не найдут `node`, `pnpm`, `gh`.
- **Собранное приложение.** SDK запускает Claude Code дочерним процессом, а файл внутри
  `app.asar` запустить нельзя. `electron-builder.yml` (тикет 32) получает `asarUnpack` для
  `node_modules/@anthropic-ai/claude-agent-sdk/**`. `options.ts` задаёт явно
  `pathToClaudeCodeExecutable` — `cli.js` SDK из `app.asar.unpacked` в сборке и из `node_modules`
  в `pnpm dev` — и `executable`: `node` из `PATH` login shell; если его нет — вариант из ответа 06,
  вопрос 4.
- **Stop hook пользователя.** `~/.claude/hooks/stop.sh` блокирует конец хода (exit 2), пока Gate
  worktree красный, до двух раз за Сессию: ход продолжается сам, без сообщения пользователя.
  Движок считает такие продолжения частью того же хода: состояние `busy` держится до
  окончательного `result` и после него никогда не остаётся `busy`; каждое срабатывание hook-а —
  событие `hook`, видимое в транскрипте. Форма сообщений — из ответа 06, вопрос 2.
- Сообщения SDK превращаются в свои события (`src/shared/agent/events.ts`, zod-схемы):
  `init` (модель, режим, `apiKeySource`, slash-команды), `text`, `thinking`, `tool_use`,
  `tool_result`, `hook` (в том числе `stop_hook_summary`), `subagent` (запуск Agent tool и
  task-notification), `rate_limit`, `result` (стоимость, токены, длительность, ошибка), `state`
  (`starting | busy | idle | needs_permission | error | closed`). Неизвестное сообщение SDK не
  роняет Сессию, а превращается в событие `unknown` с типом — его видно в отладке.
- Каналы: `agent.start`, `agent.send`, `agent.interrupt`, `agent.close`, `agent.list` и поток
  `agent.event` с `sessionId`. Сессия получает свой `sessionId` из `system/init`; до этого
  renderer видит временный id, который потом заменяется.
- `WORFY_AGENT=fake`: вместо `query()` — `fake-query.ts`, который проигрывает сценарий из
  `test/fixtures/agent-scripts/<имя>.jsonl` (имя передаётся в test-е). Сценарии на этот тикет:
  обычный ход, ход с ошибкой, ход, прерванный `interrupt`, ход, который Stop hook продлевает
  дважды.
- Падение процесса Claude Code переводит Сессию в `error` с текстом; повторная отправка
  поднимает её через `resume`.
