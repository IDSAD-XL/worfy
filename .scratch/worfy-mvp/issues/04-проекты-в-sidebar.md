## Что делаем

Проект — один git-репозиторий; у каждого Проекта ровно один Холст. В sidebar раздел «Projects»:
список Проектов, активный подсвечен, кнопка «Add project».

- «Add project» открывает системный выбор папки. Папка принимается, только если это корень
  git-репозитория (`git rev-parse --show-toplevel` совпадает с папкой). Выбор worktree или
  подпапки приводит к корню репозитория, с сообщением, что выбран корень.
- Список Проектов и активный Проект хранятся в `<WORFY_DATA_DIR>/projects.json`. Папка данных
  Проекта — `<WORFY_DATA_DIR>/<имя папки>-<sha256(путь)[0:8]>/`, создаётся при добавлении.
- `src/main/storage/json-file.ts` — общий помощник: чтение с zod-схемой, атомарная запись
  (временный файл + rename), испорченный файл не затирается, а откладывается как
  `<имя>.unreadable-<время>`, и приложение стартует с пустым состоянием. Его используют все
  следующие хранилища.
- Переключение Проекта — событие из main, на которое подписываются остальные части. Ветка
  активного Проекта (`git rev-parse --abbrev-ref HEAD`) показывается в toolbar.
- Проект удаляется из списка через контекстное меню; его папка данных остаётся (удаление данных
  — не этот тикет).
- **Шаблоны действий.** У каждого Проекта свой процесс, поэтому текст сообщения, которое шлют
  действия «Ship ticket» и «Run wave» (тикет 23), — настройка Проекта. Хранится в
  `<папка Проекта>/settings.json` (`src/main/projects/settings.ts`, через `json-file.ts`), схема и
  значения по умолчанию — в `src/shared/projects/action-templates.ts`:
  - подстановки — `{epic}`, `{NN}`, `{wave}`, `{slug}`, `{branch}`; любая другая в `{…}` — ошибка
    схемы;
  - по умолчанию для нового Проекта: Ship ticket → `/ship-ticket {epic} {NN}`, Run wave →
    `/epic-wave волна {wave} эпика {epic}`;
  - пустой шаблон значит «действие не настроено».
  worfy не знает, что делает skill: он хранит строку и отдаёт её тикету 23 на подстановку.
- «Project settings…» в контекстном меню Проекта открывает окно
  (`src/renderer/shell/ProjectSettings.tsx`): по полю на шаблон, список подстановок, «Reset to
  default». Сохранение — канал `projects.settings.get/set`; шаблон с неизвестной подстановкой не
  сохраняется, ошибка видна под полем.
- worfy ничего не пишет в репозиторий Проекта: ни список Проектов, ни настройки, ни шаблоны.

## Итог

Сделано: раздел «Projects» в sidebar (список, активный подсвечен, ветка справа, «Add project»,
контекстное меню «Project settings…» / «Remove from list»), ветка активного Проекта в toolbar,
окно «Project settings» с шаблонами «Ship ticket» и «Run wave». Main: `projects.json`, папка
данных Проекта `<WORFY_DATA_DIR>/<имя папки>-<sha256(путь)[0:8]>/` с `settings.json`, общий
помощник `json-file.ts`. Каналы `projects.pickFolder`, `projects.add/list/select/remove`,
`projects.settings.get/set` и событие `projects.changed` — по ADR-0006 (свой файл в
`src/shared/ipc/` и `src/main/ipc/`, центральные файлы не менялись).

Пункты «Готово, когда» проверены e2e-test `test/e2e/projects.spec.ts` (Playwright против
собранного приложения, диалог выбора папки подменяется в main через `app.evaluate`); вид
sidebar и окна настроек — по снимкам `page.screenshot()` этого test-а.

Решения, которых нет в тикете:

- **`json-file.ts` синхронный.** Файлы маленькие; синхронная запись нужна сохранению положения
  окна в обработчике `close`; синхронный read-modify-write в одном процессе не перемежается с
  другим, поэтому хранилищам не нужна своя очередь. Временный файл —
  `.<имя>.<pid>.<n>.tmp` в том же каталоге (rename не пересекает файловые системы), при ошибке
  удаляется. Испорченный файл — и неразбираемый JSON, и несовпадение со схемой — переименовывается
  в `<имя>.unreadable-<ISO-время без двоеточий>`, при совпадении имени добавляется `-1`, `-2`…
  Ошибки ввода-вывода, кроме «файла нет» (например, нет прав), бросаются, а не прячутся.
- **Выбор папки и добавление — два канала** (`projects.pickFolder` и `projects.add({path})`):
  так contract-test и e2e-test добавляют Проект без системного диалога, а renderer всё равно не
  получает доступ к файлам — main только запускает `git rev-parse` по присланному пути.
- **Корень репозитория.** `git rev-parse --show-toplevel` для подпапки и
  `--path-format=absolute --git-common-dir` для связанного worktree: если общий каталог git
  называется `.git`, корень — его родитель (основной репозиторий), иначе (submodule) — toplevel.
  Папка вне git отклоняется ответом `status: 'rejected'` с текстом для пользователя, а не ошибкой
  канала. Повторное добавление того же репозитория делает его активным и говорит «already in the
  list». Добавленный Проект сразу становится активным.
- **git запускается без переменных `GIT_*` и с `GIT_OPTIONAL_LOCKS=0`**: `GIT_DIR` из hook-а
  указал бы на чужой репозиторий, а без optional locks git не пишет даже обновление индекса
  (ADR-0005). Ветка — `git symbolic-ref --short -q HEAD` (работает и в репозитории без коммитов),
  при detached HEAD — `git rev-parse --abbrev-ref HEAD` (`HEAD`); не читается — `null`, в UI «—».
- **Id Проекта = имя его папки данных** (`<имя>-<hash8>`). Каналы принимают id, а main ищет его в
  списке, поэтому из renderer нельзя получить путь вне `WORFY_DATA_DIR`.
- **Шаблоны по умолчанию записываются в `settings.json` при добавлении**, а не подставляются при
  каждом чтении: смена значений по умолчанию в будущей версии не переписывает молча шаблоны уже
  добавленных Проектов. Нет файла или он испорчен — отдаются значения по умолчанию. «Reset to
  default» меняет поля в окне; сохраняется только по «Save». Пустой или пробельный шаблон —
  «не настроено» (`isActionConfigured`). Подстановкой считается любая группа `{…}` без вложенных
  скобок, имена чувствительны к регистру (`{nn}` — ошибка); одиночная `{` без пары — обычный текст.
- **Событие переключения.** Для других частей main — `ProjectStore.onChange` (`activeId`,
  `previousActiveId`, `revision`; переключение — когда они различаются). Для renderer —
  `projects.changed` во все окна. Состояние несёт `revision`; renderer берёт состояние с
  наибольшей ревизией, потому что рассылка асинхронна (спрашивает git про ветки) и ответы могут
  прийти не по порядку. Удаление активного Проекта делает активным первый оставшийся.
- **Ветка обновляется при возврате фокуса в окно** (повторный `projects.list`): её меняют вне
  worfy, например checkout в терминале. Отдельного наблюдения за `.git/HEAD` нет.
- **Контекстное меню — HTML, а не нативное `Menu.popup`**: нативное меню Playwright не нажимает,
  и пункт «Готово, когда» про удаление не проверялся бы автоматически.
- **Файл вне следа: `src/renderer/projects/useProjects.ts`** — общее состояние списка для sidebar
  и toolbar (`main.tsx`): одна подписка и один запрос на всех. Хук нельзя экспортировать из
  `ProjectsSection.tsx`: правило ESLint `react-refresh/only-export-components` разрешает в файле
  компонента только компоненты и простые константы. Подписка, упавшая без preload, пишет ошибку
  в консоль и не роняет окно (как `AppVersion`).
- **`window-state.json` на `json-file.ts` не переведён.** Бриф разрешал это, «если дёшево»; это
  три файла тикета 03 (`window.ts`, `shared/window/bounds.ts`, `test/unit/window-bounds.test.ts`),
  `parseWindowState`/`serializeWindowState` стали бы мёртвым кодом, а испорченное положение окна
  стало бы откладываться в `.unreadable-*`, хотя потерять его не жалко. Перевод — отдельной правкой,
  когда кто-то будет трогать `window.ts`.
- **Цвет ошибки** — токен `--blocked-text`: отдельного токена ошибки в F-SPEC нет.
