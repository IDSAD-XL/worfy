## Что делаем

У активного Проекта появляется Холст: бесконечная плоскость с точечным фоном, pan (колесо, Space +
перетаскивание, средняя кнопка), zoom (⌘ + колесо вокруг курсора, ⌘= / ⌘−, диапазон 0.2–2.5).

- Раскладка — список Узлов `{id, kind, x, y, w, h, hidden, locked, pinned, tags, data}` плюс
  viewport. Два разных флага: `locked` — Узел нельзя удалить (Оркестратор из 08, HANDOFF из 12,
  Тикеты и рамки Эпиков из 11), двигать и менять размер можно; `pinned` — Узел закреплён на месте
  экрана при pan и zoom (UI — тикет 29). Операция `remove` для Узла с `locked` отклоняется в main.
  Поля `locked`, `pinned` и `tags` заводятся сразу: так следующим тикетам не нужно менять схему.
- Хранится в `<папка Проекта>/layout.json` через `json-file.ts`. Пишет её только main
  (`src/main/layout/store.ts`): renderer шлёт операции `create`, `move`, `resize`, `hide`,
  `remove`, `patchData`; main проверяет их схемой, применяет, сохраняет с debounce и рассылает
  новую Раскладку всем подписчикам. Та же операция потом приходит от MCP-tools (тикет 24).
- Перетаскивание и изменение размера в renderer — оптимистичные, итог отправляется по отпусканию
  мыши.
- Точки расширения Холста: типы Узлов из `src/renderer/canvas/nodes/*Node.tsx` (модуль
  экспортирует `kind` и компонент), источники рёбер из `src/renderer/canvas/edges/*.ts`, оверлеи
  из `src/renderer/canvas/overlays/*.tsx`. `nodes/index.ts` собирает реестр через
  `import.meta.glob`. Узел неизвестного типа показывается заглушкой «Unknown node: <kind>», а не
  ломает Холст.
- Для проверки — тип Узла `note` (простой текст), который можно создать двойным щелчком по
  пустому месту. Он остаётся как отладочный и пригодится тестам.
- `onlyRenderVisibleElements` включён с самого начала (риск 8 в spec).

Доработка по ревью (круг 2, узкий): поздний ответ main на прежнюю отправку текста `note` затирал
более новый набор — защита была только для неотправленного набора. Теперь `LayoutOps.apply`
возвращает Promise, который разрешается, когда main ответил (применил или отклонил), а
`NoteNode.tsx` считает отправки в полёте: текст из main не заменяет textarea, пока есть
неотправленный набор или хоть одна отправка без ответа; когда ответ на последнюю отправку пришёл,
textarea берёт текст, который main прислал за это время. Новый unit-test
`test/unit/note-node.test.tsx` (5 test-ов) сначала падал на поздний ответ (`expected 'abc' to be
'abcd'`); мутанты, которые он убивает: снята проверка отправок в полёте; снята проверка
неотправленного набора; убран `send()` при размонтировании; не перечитывать текст main после
ответа на последнюю отправку. Следствие, которое раньше было иначе: если main отклонил
`patchData`, textarea после ответа показывает текст, который есть у main, — как Узлы, которые
Холст при отказе ставит туда, где их держит main.

Решения, которых нет в тикете:

- **Седьмая операция `setViewport`.** Раскладка хранит viewport, а в списке операций тикета его
  менять нечем. Renderer шлёт её по концу pan / zoom (`onMoveEnd`), только если viewport
  изменился.
- **`create` без `id`** получает UUID от main; занятый `id` отклоняется. Renderer при двойном
  щелчке `id` не шлёт: Узел появляется по ответу main, оптимистичны только перетаскивание и
  изменение размера.
- **`resize` несёт необязательные `x`, `y`:** изменение размера за левый или верхний край сдвигает
  Узел, иначе Узел прыгал бы после ответа main.
- **`patchData` сливает ключи на один уровень**; удалить ключ из `data` этой операцией нельзя.
- **Debounce записи — 250 мс после последней операции, без верхнего предела ожидания.** Операции
  приходят по отпусканию мыши, а не на каждый кадр. Несохранённое пишется сразу при `will-quit`
  (`src/main/ipc/layout.ts`). Ошибка записи логируется, изменения остаются помеченными и
  пишутся при следующей операции или выходе.
- **Текст `note` уходит в main по паузе в наборе (200 мс), по blur и по `beforeunload` /
  `pagehide`**, а не только по blur: выход из приложения с фокусом в `note` blur не даёт, а main
  сохраняет только полученное. textarea больше не пересоздаётся по ключу из сохранённого текста
  (так ответ main на собственный набор сбрасывал бы фокус и каретку): правка из main меняет
  значение textarea на месте, если у пользователя нет неотправленного набора, иначе ждёт.
- **`revision` — счётчик изменений Раскладки Проекта в памяти main**, с нуля при каждом запуске;
  renderer держит самую новую на каждый Проект, как со списком Проектов.
- **Один битый Узел портит весь файл:** `layout.json`, который не проходит схему (в том числе
  повтор `id`), откладывается в `layout.json.unreadable-<время>` по правилу `json-file.ts`, Холст
  начинается пустым. Узел неизвестного `kind` схеме не противоречит и сохраняется как есть, с
  `data`.
- **Удаление с клавиатуры выключено** (`deleteKeyCode={null}`): без корзины и undo (тикет 30)
  Backspace стирал бы Узел без возврата. `remove` есть в IPC и store.
- **Левая кнопка по пустому месту выделяет рамкой**, pan — колесо, Space + перетаскивание,
  средняя кнопка; zoom — ⌘ + колесо (и pinch на trackpad) вокруг курсора, ⌘= / ⌘−, диапазон
  0.2–2.5. Двойной щелчок не масштабирует: он создаёт `note`.
- **Версия приложения переехала в toolbar**: `src/renderer/AppVersion.tsx` стал элементом
  `src/renderer/shell/toolbar/AppVersion.tsx` (`order = 1000`, перед подсказкой палитры) — слот
  Canvas занял Холст (договорённость из «Итог» тикета 02). Toolbar виден всегда, в отличие от
  sidebar, поэтому e2e-test версии не зависит от того, скрыт ли sidebar.
- **Контракты точек расширения.** Тип Узла: `export const kind` (строчные слова через дефис),
  компонент по умолчанию, необязательные `defaultWidth` / `defaultHeight`; два файла с одним
  `kind` или файл без компонента роняют renderer при загрузке. Источник рёбер: функция по
  умолчанию `(nodes) => Edge[]`; источник, который бросил исключение, пропускается. Оверлей —
  как элемент shell: компонент по умолчанию и `order`; рисуется внутри React Flow, чтобы
  пользоваться его hooks и `<Panel>`.
- **Риск из тикета 03 (React Flow в скрытом виде)** проверен e2e: после Session → Canvas
  `note` на том же месте и того же размера.

Не проверено:

- не проверено: ⌘= / ⌘− против стандартного меню Electron (View → Zoom In / Zoom Out
  масштабирует всю страницу). Своего меню у приложения нет; e2e шлёт клавиши через CDP прямо в
  страницу, мимо нативного меню, а `osascript` без Accessibility нажать их в окне не может. Если
  меню перехватывает сочетание раньше страницы, ⌘= увеличит весь интерфейс, а не Холст; лечится
  своим меню без ролей zoom (`src/main/window.ts` или `src/main/index.ts`, вне следа).
- не проверено: pan через Space + перетаскивание и средней кнопкой — заданы настройками React
  Flow (`panActivationKeyCode`, `panOnDrag={[1]}`), e2e их не гоняет.
- не проверено: сходство с макетом `F-canvas-*.dc.html` сверх точечного фона и поверхности Узла;
  снимки сделаны, сравнения пиксель в пиксель нет.
