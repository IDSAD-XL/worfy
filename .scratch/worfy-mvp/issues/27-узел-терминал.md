## Что делаем

Терминал — Узел с интерактивной shell-сессией пользователя. Агент им не пользуется.

- `src/main/terminal/pty.ts`: `node-pty` (собран под ABI Electron в тикете 32) запускает `$SHELL -l`
  в корне Проекта, `TERM=xterm-256color`, `TERM_PROGRAM=worfy`, окружение — из login shell
  (как у Сессий, `src/main/agent/env.ts`). Размер ограничен 20–500 × 5–300. Последние 256 КБ
  вывода хранятся для повторного подключения (переключение Canvas / Session, перезагрузка
  renderer-а).
- Каналы: `terminal.open`, `terminal.input`, `terminal.resize`, `terminal.close` и поток
  `terminal.output`.
- `TerminalNode.tsx`: xterm.js + fit addon, цвета — токены «terminal node» в обеих темах,
  моноширинный шрифт темы. Создаётся из контекстного меню Холста «New terminal».
- Узел Терминала хранится в Раскладке. После перезапуска worfy в нём запускается новый shell в
  той же папке; старый вывод не восстанавливается.
- Закрытие Узла убивает процесс; выход из worfy убивает все процессы Терминалов.

## Итог

Сделано: shell пользователя в Узле `terminal`. main запускает `$SHELL -l` в корне Проекта через
`node-pty` (`src/main/terminal/pty.ts`, класс `TerminalRegistry`), окружение — окружение
интерактивного login shell по ADR-0007 (`agentEnv()`, то же, что у Сессий, без
`ANTHROPIC_API_KEY` / `ANTHROPIC_AUTH_TOKEN`), без `PWD`, `OLDPWD`, `SHLVL`, `_` захватившего
shell, плюс `PWD=<корень>`, `TERM=xterm-256color`, `COLORTERM=truecolor`, `TERM_PROGRAM=worfy` и
`LANG=en_US.UTF-8`, если `LANG` не задан (у приложения из Finder его нет). Размер ограничивается в
main: 20–500 колонок × 5–300 строк. Хранятся последние 256 К символов (UTF-16) вывода.

Каналы по ADR-0006 (`src/shared/ipc/terminal.ts`, `src/main/ipc/terminal.ts`): `terminal.open`,
`terminal.input`, `terminal.resize`, `terminal.close`, события `terminal.output` и
`terminal.exit`. Терминал назван парой «Проект + Узел». Renderer не передаёт ни папку, ни
программу: main берёт корень Проекта из списка Проектов и запускает shell только для Узла вида
`terminal`, который есть в Раскладке. Каждый кусок вывода несёт `end` — длину всего вывода до
его конца; ответ на `open` несёт `end` своего replay. Так renderer не пишет дважды то, что уже
пришло в replay.

Узел (`src/renderer/canvas/nodes/TerminalNode.tsx`, стили `TerminalNode.css`): xterm.js + fit
addon, цвета из токенов `--terminal-bg` / `--terminal-text` обеих тем (тема xterm.js
пересчитывается при смене системной темы), шрифт — `--font-mono`. Заголовок как в макете F:
иконка, «Terminal», имя shell, бейдж `exit N` и кнопка «Restart», когда shell завершился, кнопка
«Close terminal» (её нет у `locked` Узла). Размер xterm.js подгоняется `ResizeObserver`-ом по
размеру Узла. Пока Холст скрыт `display:none` (Session view), подгонка пропускается: у Узла нет
размера. Когда Холст снова виден, `ResizeObserver` срабатывает, и терминал подгоняется. Это риск
из тикета 03; e2e меняет размер Узла, пока Холст скрыт, и проверяет `tput cols` после возврата.

Жизнь процесса: размонтирование Узла (Session view, Узел ушёл за край экрана при
`onlyRenderVisibleElements`, перезагрузка окна, переключение Проекта) shell не трогает — следующий
монтаж подключается заново и рисует сохранённый вывод. shell завершается: (1) `terminal.close`
по кнопке Узла; (2) удаление Узла из Раскладки любым путём (`layoutStore().onChange`, операция
`remove`); (3) удаление Проекта из списка; (4) уничтожение окна, которое открыло терминал последним; (5) выход из worfy — на
`will-quit` выход откладывается (`preventDefault`), пока все shell не завершатся (не дольше 3 с),
затем `app.quit()` повторяется. Завершение: SIGHUP группе процессов shell и самому shell, через
1 с — SIGKILL, если shell игнорирует SIGHUP. После перезапуска worfy Узел из Раскладки запускает
новый shell в той же папке; старый вывод не восстанавливается.

shell, завершившийся сам (`exit`), остаётся завершённым: main хранит его код выхода и последний
вывод, пока Узел не закрыт или не нажат «Restart». Следующий монтаж Узла (перезагрузка окна, Узел
вернулся из-за края экрана) получает от `terminal.open` поле `exited` и показывает бейдж `exit N`
с выводом, а не запускает новый shell молча. Новый shell запускает только `terminal.open` с
`restart: true` — его шлёт Узел после нажатия «Restart». Закрытие Узла, удаление Узла из
Раскладки и удаление Проекта забывают сохранённый выход.

Подписки на Раскладку, список Проектов и `will-quit` вынесены в `wireRegistry()`
(`src/main/ipc/terminal.ts`): приложение передаёт ей `layoutStore()`, `projectStore()` и `app`,
contract-test — свои объекты, которые сам и дёргает.

**Терминал в focus mode (тикет 28) — не прошло.**

- Терминал и заметка на Холсте; ширина shell на Холсте `tput cols` = N1 = 74.
- Терминал + ⌘-щелчок по заметке → «Focus ⌘↩» → «Focus · 2 nodes», две плитки. В плитке N2 = 84.
  `top` перерисовывается чисто при сдвиге границы плиток влево (≈53 колонки) и вправо (≈123). После
  `q` — N3 = 123.
- «Exit focus» → на Холсте N4 = 123, а ожидалось N4 = N1 = 74. После небольшого resize угла Узла
  (560×340 → 540×330) `tput cols` = 71: число исправилось, значит shell остался с шириной плитки.
- Команды из плитки видны на Холсте и не задвоены. Но после каждой команды, выполненной при ширине
  pty не 74, в копии на Холсте остаётся строка с инверсным «%»: zsh (`PROMPT_SP`) добивает строку
  пробелами до `$COLUMNS` 84 или 123, и в виде шириной 74 колонки она переносится. Пункт гайда «вывод
  нигде не ломается» на копии Холста не выполнен. После resize Узла новые строки «%» не появляются.
- Причина: копия Терминала на Холсте шлёт `terminal.resize`, только когда меняется размер её
  собственного xterm (`onResize` — `TerminalNode.tsx:106`, `ResizeObserver` — `:112-114`). Вид в
  плитке при монтировании вызывает `terminal.open` (`:128`), и main меняет размер pty под плитку
  (`src/main/terminal/pty.ts:193-198`). Cleanup плитки (`TerminalNode.tsx:148-158`) размер не
  возвращает, а копия на Холсте всё это время смонтирована под слоем
  (`src/renderer/focus/FocusMode.tsx:10`) и свой размер не меняла, так что 74 колонки никто заново не
  шлёт.
- Косметика, низкий приоритет: в focus mode заголовок «Focus · 2 nodes» вплотную прилегает к зелёной
  кнопке окна macOS, без отступа (`9-10-focus-opened.png`).
