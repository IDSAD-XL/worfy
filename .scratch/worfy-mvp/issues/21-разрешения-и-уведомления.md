## Что делаем

**Разрешения.** Каждая новая Сессия стартует в `bypassPermissions`, и запросов нет. Если
пользователь сменил режим (тикет 19), SDK зовёт `canUseTool`.

- `src/main/agent/permissions.ts` — обработчик `canUseTool`: событие `needs_permission` с
  инструментом, входом и `suggestions`; ждёт ответа UI. Ответы:
  - «Allow» — разрешить этот вызов;
  - «Always allow» — разрешить этот инструмент до конца этой Сессии. Список разрешённых
    инструментов живёт в памяти main у объекта Сессии: на диск не пишется, другим Сессиям не
    передаётся, после перезапуска worfy или Resume он пуст. `suggestions` с `destination`, которые
    пишут в файлы настроек (`localSettings`, `projectSettings`, `userSettings`), worfy не
    применяет;
  - «Deny» — отказ с сообщением модели, что пользователь отказал.
  Неотвеченный запрос отклоняется при «Interrupt» и закрытии Сессии.
- `PermissionCard.tsx` — карточка в транскрипте: инструмент, вход (команда Bash — моноширинно,
  целиком), три кнопки. Узел Сессии на Холсте показывает chip «Needs permission» — это бейдж
  `src/renderer/canvas/badges/NeedsPermission.tsx` в слоте бейджей (11), `SessionNode.tsx` не
  меняется; Session открывается щелчком по нему.
- Подключение обработчика — в `src/main/agent/options.ts`.
- Fake-агент (`fake-query.ts` из 07) учится сценариям с `canUseTool`: запрос, ответ, отмена.

**Уведомления** (`src/main/notify.ts`): системное уведомление macOS, когда Сессия закончила ход
или ждёт разрешения, и окно worfy не в фокусе. Для внешних Сессий — переход `busy → idle` в
реестре. Щелчок по уведомлению поднимает окно и открывает эту Сессию. Одна Сессия не шлёт больше
одного уведомления в 10 с.

Решения, которые не очевидны из кода:

- **«Always allow» — свой список в памяти, без `updatedPermissions`.** Итог тикета 06 (вопрос 8)
  предлагал отвечать `updatedPermissions` со слоем `session`. Этот тикет требует пустой список
  после Resume, а переживает ли слой `session` `resume`, в 06 не проверено. Поэтому worfy не
  передаёт SDK ни одного правила и ни одной `suggestion`: `canUseTool` по-прежнему зовётся на
  каждый вызов, и gate Сессии отвечает `allow` сам, без карточки. Цена: для команды с путём вне
  `cwd` SDK будет спрашивать каждый раз, но ответ мгновенный и без карточки.
- **`suppressAlwaysAllowRule`.** Если Claude Code так помечает запрос, кнопки «Always allow» нет,
  а ответ `always_allow` main отклоняет ошибкой.
- **Закрытие при `needs_permission` не запрещено.** `closeRefusal` (тикет 18) запрещает закрыть
  только `busy`; тикет требует, чтобы закрытие отклоняло открытый запрос, так что закрыть Сессию,
  ждущую ответа, можно.
- **Interrupt в шапке Session view активен и в `needs_permission`** (`SessionView.tsx`): иначе
  отменить запрос из UI было бы нечем.
- **Двойное уведомление о Сессии worfy.** Сессии worfy есть и в реестре `~/.claude`; их `result`
  и переход `busy → idle` в реестре идут под одним SDK id, второе в пределах 10 с отбрасывается.

- **Щелчок по уведомлению без окна.** На macOS worfy живёт и без окон, Сессии и Оркестратор тоже,

  раскладки (`ProjectCanvas`), то есть заметно позже `did-finish-load`, и событие, посланное

- **Заметка ждёт, пока Сессия станет известна.** Только что открытое окно ещё не знает видов

  Проекта и сам запрашивает виды Узлов Сессий активного Проекта (`ensureProject`). Не нашлась за
  10 с — заметка отбрасывается. Раньше заметка, для которой Узла нет, отбрасывалась сразу.
- **«Always allow» и уже открытые запросы того же инструмента.** `PermissionGate.answer` после

### Ручная проверка уведомлений: как пройти

Агенту недоступно: щёлкнуть настоящее уведомление, разрешить уведомления в системном запросе,
снять экран (`screencapture` без Screen Recording, `osascript` без Accessibility). Поэтому пункт
«Готово, когда» про `.app` проверяет владелец. Порядок:

1. **Собрать `.app`.** В worktree тикета (или на `main` после мержа): `pnpm install --frozen-lockfile`,
   затем `pnpm package`. Приложение — `dist/mac-arm64/worfy.app` (на Intel — `dist/mac/worfy.app`).
   Сборка с ad-hoc подписью, bundle id `dev.worfy.app`.
2. **Запустить из Finder.** Открыть `dist/mac-arm64` в Finder, двойной щелчок по `worfy.app`. Если
   macOS говорит «не удаётся проверить разработчика» — правый щелчок → Open → Open. Ожидается окно
   worfy с Холстом активного Проекта.
3. **Разрешить уведомления.** Первое уведомление нового bundle id macOS показывает только после
   согласия: системный запрос «worfy would like to send notifications» → Allow. Если запроса не
   было — System Settings → Notifications → worfy → Allow notifications, стиль Banners или Alerts
   (Alerts удобнее: баннер не исчезает сам). Если worfy в списке нет — уведомление ещё ни разу не
   отправлялось; пройти шаг 4 и вернуться.
4. **Уведомление о запросе разрешения.** Двойной щелчок по заголовку Узла Оркестратора — откроется
   его Session view. В выпадающем списке режима разрешений выбрать «Ask before tools». Написать в
   поле «Message Orchestrator»: `Run the Bash command: ls -la` и нажать Enter. Сразу переключиться
   в другое приложение (⌘Tab), чтобы ни одно окно worfy не было в фокусе. Ожидается: баннер с
   заголовком — имя папки Проекта, текст «Needs permission: Bash ls -la», имя приложения в баннере
   — **worfy** (не «Electron»).
5. **Снимок для «Итог».** Открыть Центр уведомлений (щелчок по часам в строке меню) и снять его:
   ⌘⇧4, пробел, щелчок по окну Центра уведомлений; или ⌘⇧5. Снимок приложить к PR или положить
   рядом с тикетом и сослаться из «Итог»; отметить последний пункт «Готово, когда».
6. **Щелчок при открытом окне.** Щёлкнуть баннер. Ожидается: окно worfy поднимается (из свёрнутого
   — разворачивается), открыт Session view Оркестратора с карточкой запроса (Allow / Always allow
   / Deny). Ответить Allow — ход продолжается.
7. **Щелчок, пока грузится Карточка (случай этого круга).** Если на Холсте есть Карточка, повторить
   шаг 4 и в момент щелчка по баннеру перезагружать Карточку (её собственное обновление, если оно
   есть). Ожидается то же, что в шаге 6: Сессия открывается. Раньше в этом случае ничего не
   открывалось. Точно попасть в момент загрузки руками трудно — путь покрыт unit-test-ами.
8. **Щелчок при закрытом окне.** Повторить шаг 4, затем закрыть окно worfy (⌘W; приложение остаётся
