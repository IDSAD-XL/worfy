## Решения

spec.md, раздел «Решения по реализации», «Бейджи», «Отрисовка: одна кнопка, три вида», «Ширина окна», «Sidebar
спрятан», «Footer»; «Решения владельца 2026-11-25»:

- По умолчанию (Q1, Q12): Header — Canvas, Session; Sidebar — Pull requests, Acceptance; Footer — Pipeline, Runs.
- Бейджи — решено без владельца: бейдж считает то, что показывает сам вид.
  - Acceptance — счёт Ready to check по всем Project-ам (`useReadyCount`).
  - Pull requests — счёт pull request-ов открытого Project-а, которым нужен ты (группы `PR_NEED_YOU`, как у секции).
  - Pipeline — точка, пока Ticket открытого Project-а `blocked` или ждёт кого-то (правило секции).
  - Canvas, Session, Runs — без бейджа.
  - Счёт берётся из того же источника, что читает сам вид: виды смонтированы всегда. Новых вызовов gh и git нет.
    `useRailBadge` секций для этого не годится: секции размонтированы, пока sidebar спрятан.
- Активное состояние — у кнопки открытого вида в любой зоне. У `story` и `changes` кнопки нет, и ни одна кнопка не
  активна.
- Header — та же группа, что сейчас: kit ToggleGroup с видом `SegmentedControl`, `aria-label="View"`, иконка, подпись и
  бейдж. Порядок — из `viewButtons.header`. Бейдж Acceptance переезжает из `w-acc-tab__count` в общий вид бейджа. Нет
  кнопок — нет группы, заголовок Project-а остаётся.
- Sidebar (rail) — блок `role="group" aria-label="Views"` под секциями верхней группы. Тонкая черта сверху (Q9), кнопка
  34 × 34 px, как `w-sidebar__rail-button`, иконка 18 px, бейдж — `RailBadgeMark`, tooltip справа. Блок — не часть
  tablist секций: нажатие переключает main area, а не панель секции. По порядку CSS блок стоит после верхних секций и
  до Health check. Отдельный Tab stop, ↑ и ↓ ходят внутри блока. Пустая зона — без черты и без блока. Rail уже
  прокручивается: при шести кнопках на rail в окне 800×520 нижняя группа доступна прокруткой. Нижняя группа rail
  (Machines, Health check, Settings) не меняется (Q11).
- Решение владельца B (2026-11-25): у View button-а на rail в углу иконки — метка «окно» (вид открывается в main area,
  а не панелью); бейджа у него нет, пока на rail стоит одноимённая секция со своим бейджем (Pull requests,
  Acceptance). В header и footer метки нет, бейдж есть всегда.
- Footer — кнопки 22 px высотой: иконка 13 px, подпись, бейдж; `aria-label` — подпись, tooltip — `title`.
- Неактивная кнопка (нужен Project) — тусклая, причина в tooltip-е, во всех трёх зонах.
- Ширина окна — решено без владельца:
  - Header: при 1–3 кнопках подписи видны до 1100 px. При 4–6 кнопках правило 1400 px остаётся: только иконки
    (условие по `data-count` группы). При 1100 px и уже — только иконки при любом числе кнопок.
  - Footer: подписи видны шире 1100 px; при 1100 px и уже — иконка и бейдж, подпись в tooltip-е.
  - Rail: всегда только иконки.
- Sidebar спрятан (Cmd/Ctrl+B) — решение владельца A (2026-11-25): rail тогда не нарисован, и его View button-ы
  рисуются в конце группы header после тонкой черты. Расстановка не меняется. Эти кнопки — не зона для drop. Меню и
  клавиши у них работают так же.
- Focus mode: View button-ы footer и блока rail получают `inert`, как header под слоем. Chip версии остаётся рабочим.
  Решено без владельца; `inert` ставит этот Ticket.
- Окно Linked machine (Q13) уже читает app settings этого компьютера через каналы `local`; отдельный канал не
  вводится.
- Риски (раздел «Риски»): две одинаковые иконки на rail различают черта блока, tooltip-ы, действие и метка «окно»;
  footer забирает 28 px, окно 800×520 — самое тесное, проверяется снимком; Ticket, где правка test-ов больше правки
  кода, — сигнал делить 04.
