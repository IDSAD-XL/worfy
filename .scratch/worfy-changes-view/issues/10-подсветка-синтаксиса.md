## Что делаем

1. Зависимость: `pnpm add --save-exact` пакетов Shiki (`shiki` или `@shikijs/core` с `@shikijs/engine-javascript`,
   `@shikijs/langs`, `@shikijs/themes` — что даёт меньший JS renderer-а). Проверка, как в ADR-0106: лицензия каждого
   нового пакета lockfile-а, нет install scripts, `allowBuilds` в `pnpm-workspace.yaml` не меняется.
2. ADR-0113 «Подсветка синтаксиса в diff-е — Shiki»: контекст (D4), решение, сравнение из таблицы выше с проверенными
   цифрами, движок без WebAssembly, темы, пределы (пункт 5), размер JS renderer-а до и после в gzip; раздел
   «Considered Options».
3. `src/renderer/changes/highlight.ts` (новый): один highlighter на окно; язык — по расширению и имени файла
   (`Dockerfile`, `Makefile`); грамматика подгружается динамическим `import` при первом файле этого языка; незнакомый
   язык — простой текст, как сейчас. Разбор — по стороне hunk-а целиком (строки старой стороны отдельно, новой —
   отдельно), чтобы многострочные комментарии и строки внутри hunk-а красились верно. Кэш — по пути, стороне и тексту
   hunk-а.
4. `Code` (`DiffPane.tsx:244-256`) рисует tokens как `span` с цветами из CSS variables темы; пока tokens не готовы —
   тот же текст без цвета (ширина строки не меняется). Фон добавленных и удалённых строк остаётся; `textContent` строки
   равен `line.text`, так что выделение, Copy line, `anchorLines` и подсказка Ticket-а 09 работают как раньше.
5. Пределы: свёрнутые файлы не красятся до Show; строка длиннее 1 000 символов и hunk длиннее 2 000 строк — простой
   текст; разбор идёт только для hunk-ов в окне DOM (`diff-window.ts`).
6. Стили — в новом `src/renderer/changes/highlight.css`: светлая тема по умолчанию, тёмная — под
   `@media (prefers-color-scheme: dark)`.
7. CSP (`src/renderer/index.html:5`) не меняется.
8. Документы: раздел про подсветку в `docs/features/changes.md` и строка в `docs/features/human-review.md` (diff PR),
   переводы в `docs/features/ru/`; в spec.md, «Решения по реализации — часть 1», пункт «Цвета без подсветки синтаксиса»
   получает пометку «отменено D4 2026-11-21, см. Ticket 10».

## Решено без владельца

1. **Shiki с движком на JavaScript**, а не starry-night: CSP renderer-а не ослабляется ради WebAssembly, а цвета тем
   `github-light` и `github-dark` — те же, что на GitHub.
2. **Разбор по стороне hunk-а, а не по файлу целиком.** Файл целиком пришлось бы читать ради каждого hunk-а; hunk,
   который начинается внутри многострочного комментария, может окраситься неверно до Show whole file — это цена.
3. **Без переключателя «выключить подсветку»**: у GitHub его нет, а простой текст остаётся у незнакомых языков и длинных
   строк.
4. **Темы `github-light-default` и `github-dark-default`**, а не `github-light` и `github-dark` (implementer,
   2026-11-21): это нынешние цвета github.com (ключевое слово `#CF222E` / `#FF7B72`), старые темы — цвета GitHub до 2021
   года. ADR-0113, пункт 3.
5. **Четыре пакета `@shikijs/*`, а не `shiki`** (implementer): `shiki` тянет `@shikijs/engine-oniguruma` на WebAssembly,
   которым worfy не пользуется.
6. **Подсветка PR описана в `docs/features/pr-inbox.md`, а не в `human-review.md`** (implementer): Review mode описан
   на странице Pull requests; `human-review.md` — Team reviewer. В `docs/features/ru/pr-inbox.md` раздела Review mode
   нет (перевод отстаёт), поэтому строку туда не добавить.
7. **Предел строки — 400 символов, а не 1 000, и чтение стороны шагами** (implementer, раунд 2 ревью): строковый
   литерал в 1 000 символов разбирается 66 ms, в 400 — 10 ms; сторона hunk-а читается шагами по 2 000 символов, по
   задаче event loop-а на шаг, сторона длиннее 100 000 символов — простой текст. Замеры — ADR-0113, «Цена разбора».
