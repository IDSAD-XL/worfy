# Code story — worfy-changes-view 10: Подсветка синтаксиса в diff-е Changes и PR, как на GitHub

Kind: pr · Epic: worfy-changes-view · Ticket: 10 · PR: - · Language: ru

## 1. Что было не так

Код в diff-е Changes и Review mode PR рисовался одним цветом: `Code` в `DiffPane.tsx` ставил `{line.text}` в один
`span`, цвета были только у фона добавленных и удалённых строк. Владелец 2026-11-21 (D4): «нужен хайлайтинг синтаксиса
кода, как в гитхабе» — в обоих местах, это один экран.

- Требование: [Что происходит](../issues/10-подсветка-синтаксиса.md#что-происходит)

## 2. Каждая сторона hunk-а — один текст для Shiki, прочитанный шагами

Code: `src/renderer/changes/highlight.ts:254-277` · key lines: 255, 261, 263, 264, 266, 268

```ts
async function sideTokens(core: HighlighterCore, language: Language, texts: readonly string[], alive: Alive): Promise<(LineTokens | null)[] | null> {
  const parsed = texts.map((text) => (text.length > MAX_LINE_LENGTH ? '' : text))
  const shiki: ShikiToken[][] = []
  let state: GrammarState | undefined
  for (let start = 0; start < parsed.length; ) {
    let end = start + 1
    let size = parsed[start]!.length
    while (end < parsed.length && size + parsed[end]!.length + 1 <= CHUNK_CHARS) size += parsed[end++]!.length + 1
    if (start > 0) {
      await nextTask()
      if (!alive()) return null
    }
    const step = core.codeToTokens(parsed.slice(start, end).join('\n'), { lang: language, themes: THEMES, defaultColor: false, grammarState: state })
    for (let index = 0; index < end - start; index += 1) shiki.push(step.tokens[index] ?? [])
    state = step.grammarState
    start = end
  }
  return texts.map((text, index) => {
    if (text.length > MAX_LINE_LENGTH) return null
    const line = shiki[index]!.map(tokenOf)
    // Tokens that would not spell the line's text are not drawn: the text is what the user copies and quotes.
    return line.map((token) => token.text).join('') === text ? line : null
  })
}
```

- Что делает: строки одной стороны hunk-а (старой — контекст и удалённые, новой — контекст и добавленные) читаются
  как один текст, но шагами из целых строк по `CHUNK_CHARS` (2 000) символов: между шагами — своя задача event loop-а
  и проверка отмены, `grammarState` Shiki несёт состояние грамматики через границу шага. Строка длиннее предела (400)
  уходит в разбор пустой и остаётся простым текстом; tokens, чей текст не равен строке, не рисуются.
- Почему здесь: Ticket называет `src/renderer/changes/highlight.ts` и требует разбор «по стороне hunk-а целиком»,
  чтобы многострочные комментарии красились верно ([Что делаем, пункт 3](../issues/10-подсветка-синтаксиса.md#что-делаем)).
- Без него: комментарий, открытый на удалённой строке, красил бы добавленные строки как комментарий; hunk в 1 800
  строк держал бы окно около 650 ms одним куском (раунд 2 ревью), а строковый литерал в 1 000 символов — 66 ms.
- Требование: [Что делаем, пункты 3 и 5](../issues/10-подсветка-синтаксиса.md#что-делаем)
- Риски и пробелы test-ов: проверка «текст tokens равен строке» — защитная: ни одного входа, на котором Shiki меняет
  текст, не найдено (мутант без неё выжил). Hunk, начатый внутри комментария, красится неверно — цена, записанная в
  Ticket-е.

## 3. Shiki приходит только по требованию

Code: `src/renderer/changes/highlight.ts:199-211` · key lines: 202, 204, 207

```ts
/** The one highlighter of the window, made on the first hunk that needs it; Shiki and both themes come with it. */
function theHighlighter(): Promise<HighlighterCore> {
  highlighter ??= (async () => {
    const [{ createHighlighterCore }, { createJavaScriptRegexEngine }] = await Promise.all([import('@shikijs/core'), import('@shikijs/engine-javascript')])
    return createHighlighterCore({
      themes: [import('@shikijs/themes/github-light-default'), import('@shikijs/themes/github-dark-default')],
      langs: [],
      // Forgiving: a pattern of a grammar the engine cannot translate matches nothing instead of failing the grammar.
      engine: createJavaScriptRegexEngine({ forgiving: true }),
    })
  })()
  return highlighter
}
```

- Что делает: один highlighter на окно; ядро, движок и обе темы GitHub грузятся через `import()` на первом hunk-е,
  которому они нужны; движок — регулярные выражения JavaScript, без WebAssembly.
- Почему здесь: CSP renderer-а без `'wasm-unsafe-eval'` и должен таким остаться; e2e test бюджета старта не должен
  платить за грамматики (ADR-0113, пункты 2 и 4).
- Без него: Shiki попал бы во входной chunk renderer-а (+95 KB gzip на старте), а движок Oniguruma упёрся бы в CSP.
- Требование: [Что делаем, пункты 3 и 7](../issues/10-подсветка-синтаксиса.md#что-делаем)
- Риски и пробелы test-ов: темы — `github-*-default`, а не `github-light` и `github-dark` из рекомендации Ticket-а;
  выбор записан в ADR-0113, пункт 3.

## 4. Очередь: по одному hunk-у за задачу, ушедший из окна не читается

Code: `src/renderer/changes/highlight.ts:385-415` · key lines: 390, 395, 396, 409

```ts
function next(): void {
  const job = queue.shift()
  if (job === undefined) {
    running = false
    return
  }
  if (job.cancelled) {
    next()
    return
  }
  void readHunk(job.path, job.hunk, () => !job.cancelled).then((read) => {
    if (read !== 'cancelled' && !job.cancelled) job.done(read)
    setTimeout(next, 0)
  })
}

/**
 * Asks for the tokens of a hunk; `done` gets them in a task of its own, after the hunks asked for before it. The
 * function returned cancels the request: a hunk the window no longer draws is not read.
 */
export function requestHunkTokens(path: string, hunk: DiffHunk, done: (tokens: HunkTokens | null) => void): () => void {
  const job: Job = { path, hunk, done, cancelled: false }
  queue.push(job)
  if (!running) {
    running = true
    setTimeout(next, 0)
  }
  return () => {
    job.cancelled = true
  }
}
```

- Что делает: запросы hunk-ов окна разбираются по одному, между ними — задача event loop-а; отменённый запрос
  пропускается и не разбирается.
- Почему здесь: «long diffs stay responsive» брифа и пункт 5 Ticket-а: разбор только для hunk-ов в окне DOM.
- Без него: экран новых hunk-ов разбирался бы одним куском, а быстрая прокрутка 300 файлов разбирала бы всё, мимо чего
  прошла.
- Требование: [Что делаем, пункт 5](../issues/10-подсветка-синтаксиса.md#что-делаем)
- Риски и пробелы test-ов: отзывчивость проверена замером в e2e (самый долгий экран 18 ms), а не порогом.

## 6. Кэш — не больше 1 000 000 символов

Code: `src/renderer/changes/highlight.ts:316-329` · key lines: 317, 324, 325

```ts
function remember(key: string, hunk: DiffHunk, tokens: HunkTokens | null): void {
  const chars = hunk.lines.reduce((sum, line) => sum + line.text.length, 0)
  const before = cache.get(key)
  if (before !== undefined) held -= before.chars
  cache.delete(key)
  cache.set(key, { tokens, chars })
  held += chars
  while (held > CACHE_CHARS && cache.size > 0) {
    const [oldest, entry] = cache.entries().next().value!
    cache.delete(oldest)
    held -= entry.chars
  }
}

```

- Что делает: считает символы каждого hunk-а в кэше и выбрасывает самые старые, пока всего больше `CACHE_CHARS`.
- Почему здесь: раунд 2 ревью — прежний предел в 600 записей не ограничивал размер записи (до 2 000 строк tokens).
- Без него: 600 больших hunk-ов держали бы в памяти окна сотни мегабайт tokens.
- Требование: [Что делаем, пункт 3](../issues/10-подсветка-синтаксиса.md#что-делаем)
- Риски и пробелы test-ов: память считается по символам текста, не по байтам tokens.

## 7. `Code` рисует tokens, а до них — тот же текст

Code: `src/renderer/changes/DiffPane.tsx:247-262` · key lines: 253, 255, 258, 262

```tsx
/** A token's colours in both themes, as CSS variables: highlight.css picks the one of the window's theme. */
const tokenStyle = (light: string | null, dark: string | null): CSSProperties => ({ '--hl-light': light ?? undefined, '--hl-dark': dark ?? undefined }) as CSSProperties

/** The code of a line: its tokens in their colours once they are read, its plain text until then. Either way its text is the line's. */
function Code({ line, at, tokens }: { line: DiffLine; at?: CellAt; tokens?: LineTokens | null }) {
  const { mark = '', ...data } = at ?? {}
  const lit = tokens != null
  return (
    <span className={`w-changes__code${lineClass(line.kind)}${mark}`} data-highlighted={lit ? 'true' : undefined} {...data}>
      {lit
        ? tokens.map((token, index) => (
            <span key={index} className={`w-hl${token.bold ? ' w-hl--bold' : ''}${token.italic ? ' w-hl--italic' : ''}`} style={tokenStyle(token.light, token.dark)}>
              {token.text}
            </span>
          ))
        : line.text}
```

- Что делает: пока tokens нет, строка — её простой текст; когда есть — `span` на token с цветами обеих тем как CSS
  variables. Класс строки (`--add`, `--del`) и её атрибуты `data-side`, `data-line` остаются на том же `span`.
- Почему здесь: Ticket называет `Code` в `DiffPane.tsx`; diff PR рисует тот же `DiffPane` (Review mode).
- Без него: ни Changes, ни Review mode не окрашены.
- Требование: [Что делаем, пункт 4](../issues/10-подсветка-синтаксиса.md#что-делаем)
- Риски и пробелы test-ов: выделение мышью через границы token-ов проверено только щелчком по token-у, не протяжкой.

/* The syntax colours of the diff (worfy-changes-view ticket 10, ADR-0113): each token carries its colour of the light

>
> - What the user sees: code in a diff is coloured by language with the current github.com colours (github-light-default / github-dark-default), following the system's light or dark theme; added and deleted lines keep their background; an unknown language, a line over 400 characters or a hunk side over 100 000 characters stays plain text; a line's text, copying, search, quoting and line picking are unchanged.
