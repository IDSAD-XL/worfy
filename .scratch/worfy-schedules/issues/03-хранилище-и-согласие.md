## Что происходит

- Сущности Schedule нет. Настройки и данные Machine лежат в папке данных через `src/main/storage/json-file.ts` (zod,
  временный файл и rename, нечитаемый файл переименовывается).
- Q3: Accept — согласие, пока текст, Project, Vendor и модель те же; Q4 spec-а: в согласии точный id модели.

## Что строить

- `src/shared/schedules/schedule.ts` — схема Schedule и строки истории (поля — spec, «Модель данных»), правило из
  Ticket-а 02.
- `src/main/schedules/store.ts`:
  - `<WORFY_DATA_DIR>/schedules/schedules.json` и `<WORFY_DATA_DIR>/schedules/runs/<id>.json`;
  - отпечаток — SHA-256 текста, id Project-а, Vendor-а и точного id модели; `accept()` пишет его и время;
    `consentHolds()` считает заново из файла; файл без отпечатка или поправленный руками — Needs Accept;
  - Accept и Resume 21-го Active — отказ «20 active schedules is the limit on this machine. Pause one first.»;
  - история — не больше 50 строк на Schedule, старые уходят;
  - имя уникально в Project-е, slug ветки из имени.
- Каналы IPC (`src/shared/ipc/schedules.ts`): `schedules.list`, `schedules.history` — `project`, `read`;
  `schedules.pause` — `project`, `write`; create, update, accept, resume, delete, run-now — `local`.
