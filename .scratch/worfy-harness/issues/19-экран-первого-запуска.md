# 19 — Экран первого запуска: проверки машины и действия с подтверждением

Type: task
Status: claimed — 2026-10-08
Blocked by: 16, 17
Source: решения владельца 2026-10-07, вопросы Q22 и Q20 ([spec.md](../spec.md)); [ADR-0040](../../../docs/adr/0040-harness-delivery-local-marketplace.md) — установка plugin и минимальная версия Claude Code; [ADR-0043](../../../docs/adr/0043-qmd-is-part-of-harness.md) — qmd с согласия; [ADR-0009](../../../docs/adr/0009-claude-code-login-check-account-info.md) — проверка входа через `accountInfo()`; [ADR-0005](../../../docs/adr/0005-worfy-own-state-inventory.md) — собственное состояние worfy

## Что происходит

- **Машину worfy не проверяет.** На старте он проверяет только свои шаги: папку данных, меню, IPC,
  окно (`src/main/startup-failure.ts:11-21`). Нет `node`, `gh`, `jq` или Harness — это всплывает
  потом, когда падает скрипт Harness или Session.
- **Вход в Claude** проверяется только на старте Session: `accountInfo()`
  (`src/main/agent/session.ts:623-635`, ADR-0009).
- **Версия Claude Code.** Встроенная версия — `claudeCodeVersion` в `package.json` пакета
  `@anthropic-ai/claude-agent-sdk` (сейчас 2.1.289; SDK 0.3.289 закреплён в `package.json:23`).
  С `claude --version` из терминала её никто не сравнивает (Q20).
- **Окружение.** Инструменты worfy зовёт в окружении login shell (`src/main/agent/env.ts`, ADR-0007).
  e2e подменяет его через `SHELL` и `HOME` (`test/e2e/terminal.spec.ts:40`).
- **Terminal Node** умеет только запустить shell (`-l`, `src/main/terminal/pty.ts:229`). Команды у
  `terminal.open` нет (`src/shared/ipc/terminal.ts:25-33`). Terminal Node лежит на Canvas
  Project-а. Без Project-ов боковая панель пишет «No projects yet»
  (`src/renderer/shell/sidebar/ProjectsSection.tsx:162`).
- **Что уже сделано к этому Ticket-у.** Установщик plugin (Ticket 13), форма переноса (Ticket 14) и
  установка qmd, моделей и коллекций (Ticket 17) — функции main. Экрана, который их вызывает, нет.
  Их точные имена — в «Итог» этих Ticket-ов.
- **Дизайна экрана нет.** В `docs/design/F-SPEC.md` (43 строки) — только типографика, форма, токены
  и правило пар тем.

## Что делаем

1. **Проверки** (Q22). Только чтение, в окружении login shell. Каждая отдаёт `ok`, `warn` или
   `fail` и одну строку «что сделать».
   - **Вход в Claude** — `accountInfo()` (ADR-0009). Нет входа — `fail` с подсказкой: `claude` в
     Terminal Node, затем `/login`. Вход делает пользователь.
   - **`claude --version` из терминала** против встроенной `claudeCodeVersion` (Q20). Старше или
     `claude` нет — `warn` с командой `claude update`. worfy не блокируется.
   - **`git`, `gh`, `node` ≥ 22, `jq`.** Чего нет — `fail` с `brew install <что нет>`. worfy их не
     ставит (Q22).
   - **Аккаунты `gh`** — `gh auth status`. Нет ни одного входа — действие «`gh auth login`»
     (пункт 3). Аккаунт отдельного Project-а — Ticket 25.
   - **Harness** установлен, и его версия равна `<semver>+<SHA>` этой сборки (состояние установщика,
     Ticket 13). Нет или старше — действие «установить / обновить».
   - **Старый Harness в `~/.claude`** — файлы из списка Q19 на месте. Действие — открыть форму
     переноса Ticket-а 14.
   - **qmd**: установлен ли и какой версии, есть ли модели, что пользователь про них ответил
     (Ticket 17). Действия:
     - поставить qmd;
     - скачать модели — с размером;
     - пропустить модели;
     - завести коллекции уже подключённых Project-ов (`qmd-collections` Ticket-а 17).
2. **Действия — только с подтверждения** (Q22).
   - **Окно подтверждения** до запуска называет, что будет сделано: команда, папка, объём
     скачивания.
   - **Запуск** — только по «Confirm». Само при старте не запускается ничего.
   - **После действия** проверки идут заново.
   - **Сбой действия** — `fail` с текстом ошибки действия.
3. **`gh auth login` в Terminal Node** (Q22).
   - `terminal.open` получает необязательную команду. main вводит её в shell после старта.
   - Вход в `gh` делает пользователь.
   - Если Project-а нет, класть Terminal Node некуда. Тогда экран показывает команду для копирования,
     как `brew install …`. Владелец этого не решал; решение — в F-SPEC и «Итог».
   - Ticket 25 пользуется тем же механизмом.
4. **Когда экран показывается.**
   - На старте — если в папке данных worfy (`WORFY_DATA_DIR`, ADR-0005) нет отметки, что экран
     пройден.
   - На старте — если какая-то проверка `fail`. На `warn` экран сам не открывается.
   - Всегда — из command palette.

   Повторный показ владелец не решал. Выбор — в F-SPEC и «Итог».
5. **Дизайн.** В `docs/design/F-SPEC.md` — раздел `## First run` по-английски, как весь файл:
   - расположение блоков экрана;
   - цвета статусов — существующими токенами обеих тем (`src/renderer/theme/tokens.css`);
   - названия кнопок по-английски (`docs/design/BRIEF.md`).
6. **Не делаем:**
   - не ставим `node`, `git`, `gh`, `jq`;
   - не входим в Claude и `gh` за пользователя;
   - аккаунт Project-а — Ticket 25;
   - подключение Project — Ticket 24.

Это часть пункта 1 «Готово, когда» Epic-а (Q35): «первый запуск показывает проверки; qmd ставится с
согласия». Весь пункт проверяет приёмка — Ticket 26.

## Итог

Сделано в ветке `worfy-harness/19`.

- **Модули.** `src/main/first-run/checks.ts` — 12 проверок Q22 в пяти группах (Claude Code, Command-line tools, GitHub,
  Harness, qmd); `src/main/first-run/actions.ts` — действия с подтверждением; `src/main/ipc/first-run.ts` — IPC
  `firstRun.startup`, `firstRun.checks`, `firstRun.run`, `firstRun.close` (контракт — `src/shared/ipc/first-run.ts`);
  экран — `src/renderer/shell/FirstRun.tsx`, его состояние — `src/renderer/shell/first-run-store.ts`; команда палитры
  «First-run checks» (группа View, есть и без Project-а). Раздел `## First run` в `docs/design/F-SPEC.md`.
- **Проверки только читают**, в окружении login shell (ADR-0007). Вход — `accountInfo()` процесса Claude Code, запущенного
  тем же `queryFactoryFromEnv()`, что и Session (с `WORFY_AGENT=fake` — фейковый агент), в домашней папке, без prompt; после
  ответа процесс закрывается. Версия встроенного Claude Code — `claudeCodeVersion` из `package.json` пакета SDK.
  Состояние Harness — `appInstaller().status()` Ticket-а 13; старый Harness — `bin/epic-status` в Claude home или то, что
  взяла бы форма Ticket-а 14 (`hasLegacyHarness` один не видит старых файлов, пока plugin не установлен — у них нет пары);
  qmd — `qmdState` Ticket-а 17; коллекции — `bin/profile --name` и `--field qmd.collections` по каждому подключённому Project-у.
- **Статусы.** Нет git, gh, node, jq — `fail` с `brew install <что>`; node < 22 — `fail` с `brew install node`; `claude
  --version` старше встроенной — `warn` с `claude update`; та же или новее — `ok`; нет `claude` — `warn` без команды (`claude
  update` без `claude` не запустить; подсказка — поставить Claude Code); нет входа в Claude — `fail`, «claude в Terminal Node,
  затем /login»; `gh` без входа — `fail` с действием «Sign in…» и `gh auth login` для копирования; Harness не установлен или
  ошибка — `fail`, другая версия — `warn` (оба с Install / Update / Retry; dev-сборка без песочницы кнопки не даёт); старый
  Harness — `warn` с «Move…» (форма Ticket-а 14); qmd, модели, коллекции — только `warn`: без них Harness ищет grep-ом.
  **Решено без владельца, подтвердить:** другая версия Harness — `warn`, а не `fail` (после каждой пересборки Stable copy
  версия меняется, а `fail` открывал бы экран на каждом старте; toolbar и так показывает «Update Harness»); старый Harness —
  `warn`; «пропущено» у моделей — `ok`.
- **Действия.** Каждое — только после нативного диалога main с кнопками «Confirm» / «Cancel»; диалог называет команду, папку
  и объём скачивания (у моделей — каждая модель с размером, папка кэша, `qmd pull` с переменными, файл ответа; у qmd — `npm
  install -g @tobilu/qmd@2.8.3` и `npm prefix -g`; у Harness — текст установщика Ticket-а 13 и «Nothing is downloaded»).
  «Skip» моделей тоже идёт через Confirm (он пишет файл ответа). После действия проверки идут заново. Сбой — строка его
  проверки `fail` с «The last attempt failed: <ошибка>» до следующей попытки этого действия. Одно действие за раз.
  Функции Ticket-ов 13, 14, 17 не менялись — только два `export`.
- **`gh auth login` в Terminal Node.** `terminal.open` получил необязательный `command` — только из списка
  `TERMINAL_COMMANDS` (`gh auth login`), чтобы renderer по-прежнему не называл свою программу. main вводит команду с `\n` в
  shell, который запустил этот вызов: после первого вывода shell-а или через 1 с тишины; к уже идущему shell-у ничего не
  вводится. Экран после «Confirm» кладёт на Canvas активного Project-а скрытый Terminal Node, открывает его shell с командой,
  потом показывает Node и центрирует Canvas на нём. Скрытым — потому что Canvas не рисует скрытый Node, и его собственный
  `terminal.open` без команды не успеет запустить shell первым.
  **Решено без владельца, подтвердить:** без Project-а кнопки «Sign in…» нет, строка показывает `gh auth login` для копирования
  с «No Project is connected yet, so run it in a terminal».
- **Когда экран открывается.** На старте — если в папке данных нет `first-run.json`; на старте — если сейчас `fail` у проверки,
  которая не падала, когда экран закрыли в прошлый раз; всегда — из палитры. Закрытие (Close, Esc, вход в gh) пишет
  `first-run.json` со списком проверок, которые падали в этот момент. **Решено без владельца, подтвердить** (повторный показ):
  уже виденный и закрытый `fail` не открывает экран на каждом старте; `warn` не открывает никогда.
  `WORFY_FIRST_RUN_AUTO=0` выключает показ на старте (его ставит `launchApp` для всех e2e, кроме `first-run.spec.ts`).
- **Красный test первым.** `test/contract/first-run-checks.test.ts` на main падал на импорте: модуля
  `src/main/first-run/actions` нет — «Test Files 1 failed (1), Tests no tests».
- **Test-ы.** `test/contract/first-run-checks.test.ts` (25): список проверок; нет jq, node 20, `claude` старше, та же/новее,
  нет `claude`, gh без входа — каждый даёт ровно свой статус против базового прогона; нет git/gh, нет входа в Claude, Claude
  Code не ответил, Harness (нет / старше / этой сборки), старый Harness, qmd и модели, коллекции; «ничего не пишут» — mtime
  каждого файла и папки во временных HOME (с `.claude` и `worfy-harness`) и папке Project-а до и после одинаковы, и `claude
  plugin list` при этом вызывался; действия: отказ не зовёт npm, Confirm зовёт и проверки идут заново, сбой npm — `fail` с
  текстом до следующей попытки, модели (размер, папка, `qmd pull`, Skip только после Confirm), сбой `qmd pull`, установка
  Harness через Confirm, отказ ничего не пишет, gh-login только подтверждается, второе действие во время первого — отказ.
  `test/contract/terminal.test.ts` (+7): настоящий pty — `gh auth login` введён и выполнен (подменённый `gh` печатает строку),
  без команды — ничего; команда вне списка — отказ IPC; подменённый pty — ввод после первого вывода и один раз, через задержку
  при тишине, без команды — ничего, к идущему shell-у — ничего, shell вышел до вывода — ничего.
