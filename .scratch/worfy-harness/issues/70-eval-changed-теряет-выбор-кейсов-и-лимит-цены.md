Blocked by: —
Source: платный run на PR #738 (2026-10-22): `pnpm eval:harness --changed origin/main -- --max-cost-usd 3`
стоил 30.29 USD вместо ожидаемых ~1 USD; log run-а — в scratchpad сессии Orchestrator-а (`eval-738.log`), выдержки ниже.
Код — `scripts/eval-harness.mjs` на `7fcb5f74`. `--changed` ввёл [Ticket 29](29-кейсы-eval-по-изменённым-файлам-правил.md)

Приоритет — high: каждый следующий `--changed` перед мержем PR с правками правил Harness платит за все кейсы тега
`main`, а лимит цены пользователя не действует. До исправления платный `--changed` не запускать.

## Что происходит

- Скрипт выбрал правильно: в log-е `harness/skills/epic-wave/SKILL.md -> epic-wave-old-form, epic-wave-tickets,
  reviewer-verdict`. Выбрана часть кейсов тега `main`, поэтому по одному вызову на кейс
  (`scripts/eval-harness.mjs:235`, `args: ['--case', name]`).
- Но вызов `main-epic-wave-old-form` прогнал 9 кейсов, `main-epic-wave-tickets` — 6 (на нём кончились деньги).
  Командная строка первого вызова в log-е кончается так:
  `--tag main --allow-tools Bash Write Edit -- --max-cost-usd 3 --case epic-wave-old-form`.
- **Причина обеих ошибок — один `--`, который остался в аргументах для `claude`.**
  - pnpm 11 передаёт `--` скрипту как есть: в log-е `$ node scripts/eval-harness.mjs --changed origin/main --
    --max-cost-usd 3`.
  - `scripts/eval-harness.mjs:204` убирает `--`, только если он первый аргумент (`passThrough[0] === '--'`). Здесь первым
    идёт `--changed`, и `--` остаётся. `:212` вырезает `--changed origin/main` уже после этой проверки, и `--` становится
    первым — но проверка уже прошла.
  - `scripts/eval-harness.mjs:282` собирает вызов в порядке `--allow-tools …grants, ...passThrough, ...call.args`: `--`
    пользователя встаёт перед `--max-cost-usd 3` пользователя и перед `--case <кейс>` самого скрипта.
  - Для `claude plugin eval` всё после `--` — позиционные аргументы, не опции. Поэтому:
    1. **`--case` до `claude` не доходит** (`:235` + `:282`): каждый вызов гонит все кейсы своего `--tag main`
       (9 кейсов в первом вызове);
    2. **`--max-cost-usd 3` пользователя не действует**: лимит вызова — только `--max-cost-usd <остаток>` скрипта
       (`:281`), то есть `BUDGET_USD = 30` (`:66`) на весь run. Вызовы получили 30 и 13.8 USD, run остановился
       на 30.29 USD (`:270-276`).
- Без `--changed` ошибка та же для любой опции скрипта перед `--`, а `--max-cost-usd` пользователя без `--`
  (`pnpm eval:harness -- --max-cost-usd 3`) дошёл бы до `claude` второй копией опции после опции скрипта. Какую из двух
  берёт `claude`, не проверено; бюджет скрипта (`:268-269`, `spentIn` `:176-184`) про лимит пользователя не знает
  в обоих случаях.
- Строки для описания PR врут, но молча: `eval:harness main: casesPassed 5 of 1, … cases epic-wave-old-form` и
  `casesPassed 3 of 1, … partial`. `summary` (`:187-201`) берёт знаменатель из выбора скрипта и не сверяет его с числом
  кейсов в `aggregate-result.json`.
- Почему test-ы Ticket-а 29 этого не поймали: stub вместо `claude` записывает аргументы, а test ищет `--case` где угодно
  (`listAfter`, `test/contract/harness-evals.test.ts:786-790`), не так, как парсер `claude`, для которого после `--`
  опций нет. И ни один test не передаёт `--` не первым аргументом: есть `['--', '--changed', 'HEAD']` (`:1373`) и
  `['--changed', 'main']` (`:1394`), нет `['--changed', 'main', '--', …]`.
- Посмотреть командные строки вызовов, не заплатив, нельзя: скрипт печатает их только перед настоящим вызовом
  (`:284-285`).

## Что делаем

1. **`--changed` передаёт каждому вызову только выбранные кейсы.**
   - В командной строке `claude` нет `--` ни в каком месте. `--` от pnpm или пользователя убирается, где бы он ни стоял
     (не только первым аргументом, `:204`); опции до и после него разбираются одинаково.
   - Опции самого вызова (`--case <кейс>`, `--tag`, `--max-cost-usd`, `--output-dir`) стоят до аргументов
     пользователя или проверяются так, чтобы их не мог перекрыть аргумент пользователя.
   - Сверка после вызова: если в `aggregate-result.json` кейсов больше, чем выбрал скрипт для этого вызова, строка
     для PR кончается на `, cases mismatch: report <n>, chosen <m>`, и код выхода скрипта — не 0. Сейчас такая строка
     выглядит как `casesPassed 5 of 1` и проходит незамеченной.
2. **`--max-cost-usd` пользователя снижает бюджет run-а и никогда не теряется.**
   - Скрипт сам забирает `--max-cost-usd <x>` и `--max-cost-usd=<x>` из своих аргументов, до `--` и после него; в
     `claude` эта опция пользователя не уходит.
   - Бюджет run-а = `min(BUDGET_USD, x)`. Дальше всё как сейчас: каждый вызов получает остаток этого бюджета, остаток 0
     — оставшиеся вызовы не стартуют, exit 2.
   - `x` больше `BUDGET_USD` — бюджет остаётся 30 USD, скрипт пишет об этом строкой; поднять потолок этой опцией
     нельзя.
   - `x` не число, не больше 0 или опция без значения — exit 1 без вызова `claude`.
   - Перед первым вызовом скрипт печатает бюджет run-а и откуда он: `eval:harness: budget 3 USD (--max-cost-usd 3)` или
     `eval:harness: budget 30 USD (BUDGET_USD)`.
3. **`--dry-run`** — опция самого скрипта, в `claude` не уходит.
   - Делает всё, что не стоит денег: разбор аргументов, `--changed` (git, карта `coverage.json`, строки «файл -> кейсы»),
     план вызовов, бюджет.
   - Печатает бюджет run-а и для каждого вызова его полную командную строку `claude …` в том виде, в каком она ушла бы
     в первый вызов (`--max-cost-usd` — полный бюджет; у следующих вызовов он станет остатком, об этом одна строка).
   - Не делает: не запускает `claude` (и `claude --version` тоже), не копирует плагин и git (`pluginCopy`,
     `gitForRuns`), не создаёт папок в `harness/evals/results/`. Exit 0; ошибки разбора и `--changed` — exit 1, как без
     `--dry-run`.
   - Место в `harness/README.md`, раздел «Evals»: перед платным `--changed` — `--dry-run` с теми же аргументами, и в
     его выводе у каждого вызова есть `--case` и нет `--`.
4. **Test-ы для всех трёх, без платных вызовов** (раздел «Тесты»).

**Не входит:** переделка выбора кейсов `casesFor` (он выбрал верно); новый способ передать `claude` список кейсов
(`--case` берёт один glob, по вызову на кейс — как сейчас); поднятие `BUDGET_USD`; платный run для проверки исправления
— это решение владельца на конкретный PR (Q-H29, решение 2026-10-22).
