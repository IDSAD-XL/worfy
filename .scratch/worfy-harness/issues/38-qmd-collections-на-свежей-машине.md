## Что происходит

qmd — локальный поиск по markdown-документам, который Harness ставит и настраивает. Коллекция qmd —
именованная папка с документами. Список коллекций qmd держит в файле `~/.config/qmd/index.yml` под
ключом `collections`. Скрипт `harness/bin/qmd-collections <project>` дописывает в этот файл три
коллекции Project-а (`<project>-docs`, `<project>-tickets`, `<project>-memory`) и записывает их
имена в Profile Project-а (`profile.json` в папке Harness на машине).

На машине, где qmd ещё ни разу не настраивали, скрипт отказывается работать, если до него
отработала команда `qmd pull`. Эту команду worfy запускает сам — кнопкой «Download…» в строке
«qmd models» окна First run. First run — окно первого запуска: строки проверок машины и кнопки
установки.

## Что делаем

Скрипт принимает пустой словарь в строке ключа и переписывает его в блочную запись. Словарь с
содержимым в строке ключа по-прежнему даёт отказ, но текст отказа говорит, что делать.

1. **Пустой словарь.** Строка `collections:`, после которой стоит только `{}`, читается как «ключ
   есть, коллекций нет». Пробелы между скобками и после них допустимы. Примерное выражение:
   `/^collections:\s*\{\s*\}\s*$/`.
2. **Запись.** Эта строка заменяется на `collections:`, блоки новых коллекций встают сразу под ней.
   Остальные строки файла не меняются ни на байт. Копия `index.yml.<дата>` делается как при любой
   записи (`writeIndex`, `:170-183`). Строка `collections: {}` с блоками под ней остаться не
   должна: это неверный YAML.
3. **Любое другое значение в строке ключа** — отказ, как сейчас: exit code 1, `index.yml` и Profile
   не тронуты, копии нет. Текст отказа обязан:
   - назвать файл;
   - сказать, что ничего не изменено;
   - сказать, что скрипт правит только блочную запись, и как к ней привести: `collections:` один в
     строке, каждая коллекция под ним с отступом в два пробела, её `path:` и `pattern:` — с
     отступом в четыре;
   - сказать, что после правки скрипт запускают снова.
   Весь текст отказа — одна строка в stderr, без переводов строки внутри. `project-connect` берёт
   из stderr только последнюю строку (`harness/bin/project-connect:499`), а First run — три
   последние непустые строки вывода (`src/main/first-run/actions.ts:87-93`, `:257`). От текста в
   несколько строк в сайдбар попадёт один хвост. Главное — в начале этой строки: блок сайдбара
   показывает три ряда текста, остальное прокручивается.
4. **Остальное поведение не меняется:** файла нет, ключа нет, блок под ключом, ключ без блока,
   ключ в последней строке без перевода строки (строки 1–4 и 8 таблицы), чужая коллекция с тем же
   именем, Profile с уже названными коллекциями.
5. **Комментарий в шапке скрипта** (`:29-31`) — одна фраза о пустом словаре.

Почему правка в скрипте, а не в порядке шагов First run. Порядок шагов не закрывает команду qmd,
набранную руками, и случай, когда пользователь удалил последнюю коллекцию: qmd снова запишет
`collections: {}`. YAML-парсер в скрипт не добавляем: plugin Harness идёт без зависимостей, а
находке хватает одной строки.

## Риски

- Выражение для пустого словаря не должно совпасть со словарём, в котором что-то есть: иначе скрипт
  заменит чужие коллекции строкой `collections:`. Мутант на это — в «Готово, когда».
- qmd переписывает `index.yml` целиком при любой своей записи (`saveConfig`). После этого кавычки
  у значений могут стать другими. Отступы остаются 2 и 4 пробела (`indent: 2`), а чтение скрипта
  опирается именно на них. Это не новое.
- Скрипт и qmd могут писать файл одновременно. В прогоне фоновое обновление `qmd-mcp` началось в
  01:57:09, через секунду после записи `qmd-models`. Скрипт берёт общий замок `refresh.lock` только
  на свой `qmd update` (`:353-377`), а не на запись `index.yml` (`:308`). Это не новое; здесь не
  расширяем. Если одновременная запись проявится в test-ах — записать в «Итог».
- Тот же файл правит открытый Ticket `worfy-windows/15` (qmd на Windows). Перед claim сверить
  открытые PR.
- Правка `harness/` действует в установленной копии приложения после `pnpm install:stable` — шаг
  владельца.
