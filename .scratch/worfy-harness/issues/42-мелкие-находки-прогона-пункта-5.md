- Autopilot — режим, в котором worfy запускает Wave за Wave без человека.

### (a) Строка `gate: VERIFIED — <дата>` не последняя в файле Ticket-а

- **Наблюдение прогона.** Критерий 18 инструкции: «Файл Ticket-а в Workflow folder заканчивается
  строкой `gate: VERIFIED — <дата>`». В Project-е `silent-app` (Wave 02:08–02:12) строка
  `gate: VERIFIED — 2026-10-14` есть, но за ней идёт строка `Noted: [low] the acceptance item stays
  unchecked — CI did not run, the repository has no remote`. В Project-е `silent-app-2` (Wave с
  02:31) — то же: после строки `gate:` стоит строка `Noted: [low] …`. Так в двух Wave из трёх. Про
  третью Wave (Ticket 02, 02:44) отчёт говорит только, что строка `gate: VERIFIED — 2026-10-14`
  есть; что стоит после неё, не записано.
- **Подтверждено в исходниках.**
  - Строку вердикта пишет Orchestrator по skill-у `epic-wave` (skill, который ведёт Wave):
    `harness/skills/epic-wave/SKILL.md:312-320`. Текст skill-а: вердикт — «a line at the end of the
    ticket file in the Workflow folder, under its result section». Команда дописывает строку в
    конец файла: `printf '\n%s\n' "gate: VERIFIED — $(date +%F)" >>"$f"` (`:318`).
  - Строку `Noted:` пишет тот же Orchestrator по тому же skill-у. Находки ревью он делит на четыре
    группы: Act on (в доработку), Consider (долги), Noted (мелкие, правка не нужна), Dismissed
    (опровергнутые). Группа Noted идёт «one line each in the ticket's result section» (`:340-341`).
    Для вердикта `REJECTED` skill говорит прямо: в Silent mode строки групп стоят после строки
    `gate: REJECTED: …` (`:378-381`). Для `VERIFIED` место строк групп не названо.
  - Другие тексты строку `gate:` в файл Ticket-а не пишут. В `harness/agents/` слова `gate:` и
    `Noted` не встречаются. В skill-е `ship-ticket` группа Noted идёт в result section
    (`harness/skills/ship-ticket/SKILL.md:285-286`, `:302`), строки вердикта там нет.
  - Читатели строки. Test `harness/bin/tests/skill-blocks.test.sh:158` ищет её командой
    `grep -q "^gate: VERIFIED — "` — в любом месте файла. Счётчик кругов доработки —
    `grep -c '^gate: REJECTED' "$f"` (`harness/skills/epic-wave/SKILL.md:319`). Возобновление Wave:
    «with `local-green` its verdicts are the `gate:` lines of its file» (`:665-666`). Ни один
    читатель не ждёт, что строка последняя в файле.
  - В `src/` файл Ticket-а на строку `gate:` не читает никто. `grep -rn VERIFIED src` находит
    только вердикт в комментариях PR (`src/main/github/prs.ts:164`) и вердикт subagent-а

    `gate:` не проверяет.
  - Строка группы не начинается с `gate:` (`harness/skills/epic-wave/SKILL.md:380-381`). Поэтому
    счётчики верны и тогда, когда `Noted:` стоит после вердикта.
- **Не найдено.** Откуда инструкция взяла слова «заканчивается строкой». В файле
  `/Users/Shared/worfy-item5/README-item5.md` шаг 18 ни на какой файл не ссылается.
- **Вывод.** Слишком строго сформулирован критерий инструкции. Skill обещает «строку в конце
  файла» только на момент записи вердикта. Поведение агента skill-у не противоречит. В тексте

### (b) В одном файле `Status: done — 2026-10-13` и `gate: VERIFIED — 2026-10-14`

- **Наблюдение прогона.** Wave закончилась в 23:12 UTC 13 октября. По местному времени (EEST,
  UTC+3) это 02:12 14 октября. `epic-status --json` показал `"statusRaw":"done — 2026-10-13"`, а в
  том же файле стоит `gate: VERIFIED — 2026-10-14`.
- **Подтверждено в исходниках.**
  - Дату строки `Status:` ставит скрипт `ticket`: `harness/bin/ticket:220`,
    `new Date().toISOString().slice(0, 10)`. Это дата по UTC. Её получают команды `done` и `claim`
    (`:249-250`).
  - Дату строки `gate:` ставит shell: `$(date +%F)` (`harness/skills/epic-wave/SKILL.md:318`). Это
    дата по местному времени.
  - Правила «какая дата нужна» в проекте нет. Слово UTC о дате Ticket-а не встречается ни в
    `docs/`, ни в `harness/profiles/README.md`, ни в `harness/bin/TICKETS.md`, ни в
    `harness/hooks/rules/`, ни в skills.
  - Остальные даты Harness-а делятся на два вида. Отметки времени для программ — UTC с буквой `Z`:
    `harness/hooks/gate.sh:166`, `:494`; `harness/hooks/session-end.sh:36`;
    `harness/bin/decision-log:128`; имя папки прогона в `harness/skills/epic-wave/SKILL.md:166`.
    Даты без времени, которые читает человек, — местные: `harness/skills/epic-wave/SKILL.md:318`,
    `harness/skills/overnight-fix-loop/SKILL.md:74`, `harness/skills/continuous-audit/SKILL.md:59`.
    Скрипт `ticket` — единственное место, где дата без времени взята по UTC.
  - Нынешнее поведение закреплено test-ами: `harness/bin/tests/silent-mode.test.sh:80` и `:313`
    ждут `$(date -u +%F)`.
  - Дату из строки `Status:` программы не разбирают. worfy показывает строку целиком в подсказке
    Ticket-а (`src/renderer/canvas/nodes/TicketNode.tsx:137`).
  - То же видно в истории самого worfy. Commit `ff61b06f` от 2026-10-14 02:28:13 +03:00 ставит
    Ticket-у 05 Epic-а `worfy-ui` строку
    `Status: done — 2026-10-13, [PR #296](https://github.com/IDSAD-XL/worfy/pull/296)`. Сам PR #296
    влит 14 октября в 01:04:34 +03:00 (commit `ba8a58cb`).
- **Воспроизведено в песочнице** (2026-10-14, 00:04 UTC). Команда:
  `env -i PATH=<node>:/usr/bin:/bin HOME=<песочница>/home HARNESS_HOME=<песочница>/harness-home
  TZ=Etc/GMT+12 node harness/bin/ticket done demo 01 -n --root <песочница>/repo/.scratch`. Зона
  `Etc/GMT+12` — это UTC−12. Вывод: `now: Status: done — 2026-10-14`, код 0. В том же окружении
  `date +%F` печатает `2026-10-13`. С `TZ=Pacific/Kiritimati` (UTC+14) `ticket` печатает ту же
  дату `2026-10-14`. Значит, `ticket` на часовой пояс не смотрит.
- **Догадка.** Точное время вызова `ticket done` для Ticket-а 05 из истории worfy в git не
  записано: commit — squash. По порядку skill-а статус ставится после merge PR. Второй пример из
  истории ничего не доказывает. Commit `4658e395` (2026-10-14 00:18:58 +03:00) ставит
  `done — 2026-10-13` Ticket-у 44 Epic-а `worfy-windows`. Но PR #293 этого Ticket-а влит
  2026-10-13 в 23:44:35 +03:00 (commit `6033e145`), до местной полуночи. `ticket done` мог быть
  вызван до полуночи, и тогда дата верна и по местному времени.
- **Вывод.** Малый дефект. Две соседние строки одного файла считают день по-разному. В часы, когда
  местная дата и дата UTC различаются, дата `Status:` отстаёт на день от даты `gate:`.

### (f) «Run wave» не задал ни одного вопроса о разрешениях

- **Наблюдение прогона.** Шаг 16 инструкции: «Кнопка „Run wave“ отдаёт Wave Orchestrator-у с
  вопросами о разрешениях: на них придётся отвечать». В Project-е `silent-app-2` Wave запущена
  кнопкой «Run wave» (02:31). Вопросов не было. В файле `session-settings.json` Project-а у Session
  Orchestrator-а стоит `permissionMode: bypassPermissions`, в окне — «Permissions: Bypass
  permissions».
- **Подтверждено в исходниках.**
  - `bypassPermissions` — режим Claude Code, в котором инструменты запускаются без вопросов. Это
    умолчание любой новой Session worfy: `src/shared/agent/settings.ts:7-8` и `:33`
    (`DEFAULT_SETTINGS`).
