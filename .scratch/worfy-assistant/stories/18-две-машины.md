# Code story — worfy-assistant 18: Две машины: Assistant каждой машины, Project-ы второй машины только для чтения

Kind: pr · Epic: worfy-assistant · Ticket: 18 · PR: - · Language: ru

## 1. Что было не так

Assistant видел только Project-ы своей Machine: `worfy-app` отвечал на `projects_list` одной этой Machine (в коде стояла
пометка «shortcut … are worfy-assistant ticket 18»), а раздел Assistant-а не знал о Linked machine вовсе. Все каналы
`assistant.*` были `local`, так что прочитать, что ждёт на другой Machine, было нечем. Ticket просит: Assistant каждой
Machine ведёт только свои Project-ы, а список «что ждёт» показывает и Project-ы второй Machine — только для чтения.

- Требование: [Что строить](../issues/18-две-машины.md#что-строить)

## 2. Один канал чтения, открытый Linked machine

  `project` помечается `read` или `write`, и test `link-access.test.ts` называет его по имени.
- Без него: Machine не могла бы узнать, что ждёт на другой, не открыв ей каналы, которые меняют пункты.
- Требование: [Решения](../issues/18-две-машины.md#решения)
- Риски и пробелы test-ов: сборка Linked machine старее этого PR канала не знает; её ответ — отказ, и раздел показывает
  его текст как `problem`.

## 3. Что отдаёт Machine: только своё, без средств действия

Code: `src/main/assistant/window/view.ts:412-422` · key lines: 417, 420

```ts
   * What a Linked machine reads of this one (`assistant.waiting`): the Projects of this Machine and the items the section
   * shows now, urgent first, as words and times — no prepared text, proposal, target or rating. An item's id is a digest
   * of the core's, which may hold a source's text. Reading counts nothing as shown, and nothing of a third Machine goes.
   */
  waiting(): LinkedWaits {
    const view = this.view()
    return {
      projects: this.deps.projects().map((project) => ({ id: project.id, name: project.name })),
      items: view.items.slice(0, LINKED_ITEMS_MAX).map((item) => ({ ...linkedItemOf(item), id: createHash('sha256').update(item.id).digest('hex').slice(0, 24) })),
    }
  }
```

- Что делает: берёт `view.items` — только пункты своих Project-ов, уже отобранные обязанностями, правилами и Snooze, — и
  отдаёт их словами и временем (`linkedItemOf`): без Prepare, предложения, цели Open и оценки. Id ядра заменён digest-ом.
- Почему здесь: `view()` уже собирает список «что ждёт»; повторять обязанности другой Machine на этой не нужно (раздел
  «Решено без владельца» тикета, пункт 1). Id ядра может содержать текст источника — пункт 5 того же раздела.
- Без него: Linked machine получила бы либо ничего, либо сырые пункты ядра с текстом Slack в id.
- Требование: [Готово, когда](../issues/18-две-машины.md#готово-когда)
- Риски и пробелы test-ов: `view.linked` в ответ не входит — test «never hands the Linked machine what it read from
  another one» это проверяет.

## 4. Как Machine читает другую

Code: `src/main/assistant/window/linked.ts:55-67` · key lines: 56, 63, 65

```ts
  private async readOne(machine: { id: string; name: string; online: boolean }): Promise<LinkedMachineWaits> {
    if (!machine.online) return empty(machine, `${machine.name} is offline`)
    let result: IpcResult<unknown>
    try {
      result = await this.deps.call(machine.id)
    } catch (error) {
      return empty(machine, error instanceof Error ? error.message : String(error))
    }
    if (!result.ok) return empty(machine, result.error)
    const parsed = linkedWaitsSchema.safeParse(result.value)
    if (!parsed.success) return empty(machine, `${machine.name} answered outside the contract`)
    return { id: machine.id, name: machine.name, online: true, projects: parsed.data.projects, items: parsed.data.items, problem: null }
  }
```

- Что делает: Machine offline не вызывается; отказ, исключение и ответ вне схемы становятся `problem` словами и пустым
  списком. Раздел показывает последний ответ (`snapshot`), `worfy-app` читает заново (`refresh`).
- Почему здесь: Ticket называет `src/main/link/` (`remote-calls.ts`); вызов идёт через `callOn` в
  `src/main/assistant/window/app.ts`, а сам класс не знает о связи — test подставляет stub вместо неё.
- Без него: один недоступный или старый Linked machine ломал бы раздел или ответ Assistant-у.
- Требование: [Что строить](../issues/18-две-машины.md#что-строить)
- Риски и пробелы test-ов: подписка на `connected`/`disconnected`/`unlinked` службы связи в `app.ts` test-ом не
  покрыта — настоящая связь в test-ах не поднимается.

## 5. `worfy-app`: читать можно, действовать нельзя

Code: `src/main/mcp/app-server.ts:313-329` · key lines: 319, 326

```ts
  const linkedMachines = async (): Promise<AppMachine[]> => (await deps.machines()).filter((machine) => !machine.thisMachine)
  /** A read of a Project this Machine does not have: refused, with the Linked machine it is of when it is one's. */
  const readableProject = async (projectId: string): Promise<void> => {
    if (deps.projects().some((project) => project.id === projectId)) return
    const machine = (await linkedMachines()).find((each) => each.projects.some((project) => project.id === projectId))
    if (machine === undefined) throw new ToolError(`${projectId} is not a Project of this Machine: projects_list lists them`)
    throw new ToolError(`${projectId} is a Project of the Linked machine ${machine.name}: read what waits there with items_list; its workflow, PRs and runs are read on that machine.`)
  }
  /** An id of an item of a Linked machine (linkedItemId): refused, with the Machine; anything else goes on. */
  const refuseLinkedItem = async (id: string, what: string): Promise<void> => {
    if (!id.startsWith('linked-')) return
    for (const machine of await linkedMachines()) {
      if (machine.items.some((item) => linkedItemId(machine.id, item.id) === id)) {
        throw new ToolError(`Item ${id} waits on the Linked machine ${machine.name}: its Projects are read-only, and its own Assistant keeps them. ${what}`)
      }
    }
  }
```

- Что делает: `action_run` и `proposal_create` с пунктом Linked machine отказывают с её именем, до любого вызова main;
  `workflow_read`, `pr_threads_read` и `autopilot_runs_read` по её Project-у тоже. `items_list` отдаёт её пункты под
  `linked` с `readOnly: true` и текстом как outside text.
- Почему здесь: граница 5 spec-а («Project-ы второй машины Assistant только читает») и стык Б Ticket-а; Prepare в чужом
  Project-е уже отказывал (`ownProject`), его не трогали.
- Без него: агент получил бы невнятное «No item … is shown now» и мог бы пытаться снова.
- Требование: [Test-ы](../issues/18-две-машины.md#test-ы)
- Риски и пробелы test-ов: отказ чтения workflow, PR и Run-ов — решение без владельца (пункт 3): такие чтения через
  связь не сделаны.


- Что делает: после своих групп вкладки Waits — группа «On <Machine> · read-only» на каждую Linked machine; карточки

- Почему здесь: пункт 2 «Что строить» — список «что ждёт» показывает Project-ы обеих машин; место в конце вкладки —
  решение без владельца, пункт 2.
- Без него: пункты второй Machine были бы видны только Assistant-у, но не пользователю.
- Требование: [Готово, когда](../issues/18-две-машины.md#готово-когда)
- Риски и пробелы test-ов: вид проверен test-ом jsdom, не в собранном приложении (e2e не запускались по правилу
  владельца); снимков нет.

## 7. Что сознательно не меняли

Свой список, сводка, счётчик вкладки, карточка-реплика и системные уведомления считают только пункты этой Machine. Каналы
`assistant.*`, кроме нового, остались `local`. ADR не менялись.

## Проверить себя

1. Почему Linked machine получает digest вместо id пункта ядра?
   - Ответ: id ядра может содержать текст источника (сообщения Slack или Jira); digest различает пункты и не уносит этот
     текст.
   - Lines: `src/main/assistant/window/view.ts:412-422`
2. Machine A показывает пункты Machine B. Почему B, спросив A, не получит обратно свои же пункты?
   - Ответ: `waiting()` берёт только `view.items` — пункты своих Project-ов; прочитанное у B лежит в `view.linked` и в
     ответ не входит.
   - Lines: `src/main/assistant/window/view.ts:412-422`
3. Linked machine выключила доступ. Что увидит Assistant этой Machine в `items_list`?
   - Ответ: часть `linked` этой Machine с пустым списком и `problem` с текстом отказа «access is off»; ни одного её
     пункта.
   - Lines: `src/main/assistant/window/linked.ts:55-67`
