# Code story — worfy-assistant 16: Знакомство: шаг приветствия, одно предложение после обновления, первое включение; настройка источников в разговоре

Kind: pr · Epic: worfy-assistant · Ticket: 16 · PR: - · Language: ru

## 1. Что было не так

После Ticket-а 15 Assistant выключен у всех, и включить его можно только в Settings → Assistant. worfy ни разу не
предлагал его включить: ни новому пользователю на шаге приветствия, ни тому, кто обновил worfy. Включённый Assistant
молчал: не говорил, кто он и что умеет, не спрашивал work hours и источники и не показывал, какие connectors claude.ai
он видит.

- Требование: [Что строить](../issues/16-знакомство.md#что-строить)

## 2. Одно предложение: когда оно стоит и как на него отвечают

Code: `src/main/assistant/intro/intro.ts:115-128` · key lines: 118, 119, 125

```ts
  /** The offer as the window reads it. */
  offer(): OfferView {
    const state = this.deps.store.read()
    if (this.deps.on() || state.offer !== null || state.introduction !== null) return { ...NO_OFFER }
    return { owed: true, notice: !state.noticeShown && this.deps.noticeAllowed() }
  }

  /** The person's answer to the offer. `accepted` turns the Assistant on; its start brings the introduction. */
  answer(answer: OfferAnswer): void {
    if (answer === 'seen') this.edit((state) => void (state.noticeShown = true))
    else this.edit((state) => void (state.offer = answer))
    if (answer === 'accepted') this.deps.turnOn()
    this.deps.changed()
  }
```

- Что делает: предложение стоит, пока Assistant выключен, ни разу не знакомился и пользователь его не принял и не
  отказался. Сообщение для обновившегося (`notice`) — только пока оно не показано. «Not now» записывает отказ навсегда,
  «Turn on and meet» включает Assistant тем же полем настроек, что переключатель Settings.
- Почему здесь: состояние живёт в main, в `<WORFY_DATA_DIR>/assistant/intro.json`, чтобы все окна и перезапуски видели
  один ответ; worfy пишет только в свою папку данных (ADR-0005).
- Без него: отказ не запоминался бы, и предложение приходило бы снова; после выключения знакомого Assistant-а worfy
  предлагал бы его ещё раз.
- Требование: [Что строить, п. 2](../issues/16-знакомство.md#что-строить)
- Риски и пробелы test-ов: `notice` под `WORFY_GETTING_STARTED_AUTO=0` всегда false — e2e не видит toast
  обновившегося, его проверяет только unit test `assistant-offer.test.tsx`.

## 3. Знакомство один раз, при первом включении

Code: `src/main/assistant/intro/intro.ts:150-185` · key lines: 153, 157, 161, 165, 184

```ts
  private async introduce(atStartup: boolean): Promise<void> {
    const state = this.deps.store.read()
    if (state.introduction === 'done') return
    if (state.introduction === null && atStartup && state.offer !== 'accepted') {
      this.edit((next) => void (next.introduction = 'done'))
      return
    }
    this.edit((next) => void (next.introduction = 'owed'))
    let connected: SourceCheckKind[] | null = null
    try {
      const connectors = await this.deps.connectors()
      connected = SOURCE_CHECK_KINDS.filter((kind) => connectors.some((each) => SOURCE_CONNECTOR[kind](each.name) && each.status === 'connected'))
    } catch (error) {
      this.deps.log?.('[assistant] the introduction could not read the claude.ai connectors', error)
    }
    const change = this.firstSetup(connected ?? [])
    const words = introWords(this.deps.language(), {
      machine: this.deps.machine(),
      connected,
      notConnected: connected === null ? [] : SOURCE_CHECK_KINDS.filter((kind) => !connected.includes(kind)),
      setup: change !== null,
    })
    let proposalId: string | null = null
    if (change !== null) {
      try {
        proposalId = this.deps.propose({ title: words.setupTitle, why: words.setupWhy, change }).id
      } catch (error) {
        this.deps.log?.('[assistant] the first setup of the introduction was not proposed', error)
      }
    }
    const [who, what, setup] = words.messages
    this.deps.say(who, null)
    this.deps.say(what, null)
    this.deps.say(setup, proposalId)
    this.edit((next) => void (next.introduction = 'done'))
  }
```

- Что делает: при первом включении пишет `owed`, читает connectors claude.ai без модели, собирает первую настройку
  (work hours, если не выбраны, и проверки подключённых источников) и говорит три сообщения на языке Guide; последнее
  передаёт карточку «было → станет». Затем пишет `done`. Assistant, уже включённый при старте worfy без записи, считается
  знакомым без сообщений. Connectors не прочитались — Assistant честно говорит об этом и куда их подключить.
- Почему здесь: решение 12 spec — знакомство при одноразовом предложении или при первом самостоятельном включении; слова
  — worfy, без модели (раздел «Решено без владельца», п. 1 тикета).
- Без него: второй старт повторял бы знакомство, а закрытие worfy между включением и записью теряло бы его; владелец,
  у которого Assistant уже включён, получил бы знакомство после обновления.
- Требование: [Что строить, п. 3 и 4](../issues/16-знакомство.md#что-строить)
- Риски и пробелы test-ов: ответ модели на вопрос про work hours не проверяется — после знакомства разговор идёт через
  Session Assistant-а Ticket-а 10, которую test-ы не запускают.

## 4. Переключатель различает старт с worfy и включение человеком

Code: `src/main/assistant/session/switch.ts:39-49` · key lines: 40, 43, 45, 49

```ts
  // Off once since worfy started: a start after it is the person's turn of the switch, not one that came with worfy's.
  let seenOff = false
  const follow = (): void => {
    const on = deps.on()
    if (!on) seenOff = true
    if (on && stop === null) {
      if (seenOff) deps.turnedOn?.()
      stop = deps.start()
      if (stop === null) return log('the Assistant did not start: the attention core is not running')
      deps.changed()
      deps.started?.(!seenOff)
```

- Что делает: включение человеком (переключатель был выключен с запуска worfy) сначала отмечает знакомство как
  должное (`turnedOn` → `owe()`), ещё до старта, который может не взяться. После каждого старта, который взялся,
  говорит знакомству, был ли Assistant включён с самого старта worfy (`!seenOff`) или его включили позже.
- Почему здесь: переключатель Ticket-а 15 — единственное место, где Assistant стартует, и через него проходят оба пути
  включения: предложение и Settings.
- Без него: знакомство не отличило бы включение человеком от Assistant-а, включённого до этого изменения.
- Требование: [Что строить, п. 1](../issues/16-знакомство.md#что-строить)
- Риски и пробелы test-ов: ошибка записи `intro.json` в приложении ловится и пишется одной строкой `[assistant]`
  (`startAssistantSwitch`); эта обвязка над настройками приложения unit test-ом не покрыта.

## 6. Одно сообщение обновившемуся

Code: `src/renderer/assistant/offer-notice.ts:59-69` · key lines: 63, 64, 66

```ts
export function installAssistantOffer(): void {
  if (installed || windowMachine() !== null) return
  installed = true
  void invoke('gettingStarted.state').then((result) => {
    if (!result.ok) return console.error('gettingStarted.state failed:', result.error)
    if (result.value.user !== 'existing') return
    whenView((view) => {
      if (view.offer.notice) showNotice()
    })
  })
}
```

- Что делает: обновившемуся (`user: existing` Getting started) — один action toast с «Meet Assistant» и «Not now», как
  notice Getting started; новому — ничего, ему предлагает шаг приветствия. В окне связанной машины не показывается.
- Почему здесь: владелец просил переиспользовать механизм onboarding; notice Getting started — его образец.
- Без него: обновивший worfy не узнал бы об Assistant-е.
- Требование: [Готово, когда, п. 2](../issues/16-знакомство.md#готово-когда)
- Риски и пробелы test-ов: два окна, открытые вместе, оба покажут toast, пока одно его не закроет — как у notice
  Getting started.
