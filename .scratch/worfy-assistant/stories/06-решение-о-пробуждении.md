# Code story — worfy-assistant 06: Решение о пробуждении: срочное сразу, несрочное пачкой в work hours, утренняя сводка

Kind: pr · Epic: worfy-assistant · Ticket: 06 · PR: - · Language: ru

## 1. Что было не так

Ядро внимания (Ticket 03) собирает пункты, планировщик (Ticket 04) знает work hours, проверка Ticket-а 05 говорит,
можно ли будить модель. Но никто не решал, когда будить: срочное сразу, несрочное пачкой, утром сводка, на сообщение
пользователя. Этот PR даёт это решение без модели и цикл, который его применяет; Session, которую будить, — Ticket 10.

- Требование: [Что строить](../issues/06-решение-о-пробуждении.md#что-строить)

## 2. Одно решение на взгляд: срочное, утро, пачка, потом проверка

Code: `src/main/assistant/wake/planner.ts:105-131` · key lines: 111, 115, 116, 122, 129

```ts
  evaluate(): WakeDecision | null {
    const now = this.options.now()
    const hours = this.options.workHours()
    const items = this.options.items()
    const pending = this.pending(items)
    const escalated = items.filter((item) => isOpen(item) && this.state.escalated.includes(item.id))
    const urgent = escalated.length > 0 || pending.some((item) => URGENT_ITEM_KINDS.has(item.kind) && item.updatedAt >= this.state.since)
    let reason: Exclude<WakeReason, 'user'> | null = null
    if (urgent) reason = 'urgent'
    else if (inWorkHours(now, hours)) {
      if (this.morningDayOf(now, hours) !== this.state.morningDay) reason = 'morning'
      else if (pending.length > 0 && now >= this.batchDueAt(pending, now)) reason = 'batch'
    }
    if (reason === null) {
      this.held = null
      return null
    }
    const verdict = assistantWakeGate({ limits: this.options.limits(), urgent, wakesToday: this.options.ledger.automaticWakesToday(), now })
    if (!verdict.ok) {
      this.held = { type: 'held', reason, verdict }
      return this.held
    }
    this.held = null
    const wake = this.handOver(reason, now, items, [...escalated, ...pending.filter((item) => !escalated.includes(item))])
    this.options.ledger.noteWake(wake.id, urgent)
    return wake
  }
```

- Что делает: из пунктов ядра выбирает ждущие (непереданные события). Срочно, если есть пункт `run-stopped` новее
  первого запуска или пункт, по которому закрытый список не помог (`escalate`). Иначе, только в work hours, — утренняя
  сводка, если её ещё не было в этот день work hours, или пачка, если пришёл её срок. Перед пробуждением —
  `assistantWakeGate` Ticket-а 05; пробуждение, которое пошло, записывается в журнал расхода (`noteWake`).
- Почему здесь: spec, «Решение о пробуждении» — срочное сразу, несрочное пачкой в work hours, утром сводка, перед каждым
  автоматическим — проверка Limits и дневной предел. Папка `src/main/assistant/wake/` — новая: «Где в коде» тикета
  называет только модули Ticket-ов 03–05, на которые решение опирается.
- Без него: Session Assistant-а (Ticket 10) не знала бы, когда стартовать, и каждый пункт будил бы модель.
- Требование: [Готово, когда, пункты 1–4 и 6](../issues/06-решение-о-пробуждении.md#готово-когда)
- Риски и пробелы test-ов: `run-stopped` будит и при остановке самим пользователем — вид пункта не несёт причину
  (решено без владельца, «Итог», пункт 3).

## 3. Пачка: собрать и не будить чаще раза в час

Code: `src/main/assistant/wake/planner.ts:160-174` · key lines: 161, 168, 173

```ts
  private pending(items: readonly AttentionItem[]): AttentionItem[] {
    return items.filter((item) => item.state === 'new' && (this.state.delivered[item.id] ?? 0) < item.events).sort((a, b) => a.updatedAt - b.updatedAt)
  }

  private batchDueAt(pending: readonly AttentionItem[], now: number): number {
    // A time past `now` (the clock went back) counts as `now`.
    const oldest = Math.min(now, ...pending.map((item) => item.updatedAt))
    const last = this.state.lastWakeAt === null ? Number.NEGATIVE_INFINITY : Math.min(now, this.state.lastWakeAt)
    return Math.max(oldest + BATCH_GATHER_MS, last + BATCH_SPACING_MS)
  }

  /** The day of the work hours `now` is in: a window across midnight belongs to the day it starts on. */
  private morningDayOf(now: number, hours: WorkHours): string {
    return dayOf(workWindowStartOf(now, hours) ?? now, hours.timeZone ?? machineTimeZone())
  }
```

- Что делает: ждущий пункт — в состоянии `new` и с событиями, которых модель ещё не видела. Срок пачки — 15 минут после
  самого старого из них и не раньше часа после прошлого пробуждения. День утренней сводки — день начала окна work hours
  в его часовом поясе, поэтому окно через полночь даёт одну сводку.
- Почему здесь: значения 15 и 60 минут spec не задаёт; они решены без владельца («Итог», пункт 5).
- Без него: каждый новый PR в inbox будил бы модель отдельно, и дневной предел 20 кончался бы к обеду.
- Требование: [Готово, когда, пункт 3](../issues/06-решение-о-пробуждении.md#готово-когда)
- Риски и пробелы test-ов: время пункта — `updatedAt` по часам ядра; часы, отведённые назад, считаются как «сейчас».

## 4. Сначала файл, потом память

Code: `src/main/assistant/wake/planner.ts:176-196` · key lines: 178, 186, 193

```ts
  /** The file first, then memory: a write that throws leaves the wake due, so it is tried again. */
  private save(next: WakeState): void {
    this.options.store.write(next)
    this.state = next
  }

  private handOver(reason: WakeReason, now: number, items: readonly AttentionItem[], carried: AttentionItem[]): AssistantWake {
    const present = new Set(items.map((item) => item.id))
    // Items the core dropped (ATTENTION_KEEP_DAYS) leave the file too.
    const delivered = Object.fromEntries(Object.entries(this.state.delivered).filter(([id]) => present.has(id)))
    for (const item of carried) delivered[item.id] = item.events
    const hours = this.options.workHours()
    this.save({
      ...this.state,
      delivered,
      escalated: reason === 'urgent' ? [] : this.state.escalated.filter((id) => present.has(id)),
      lastWakeAt: now,
      morningDay: reason === 'morning' ? this.morningDayOf(now, hours) : this.state.morningDay,
    })
    return { type: 'wake', id: `${reason}-${now}`, reason, at: now, items: carried.map((item) => structuredClone(item)) }
  }
```

- Что делает: передача пункта модели — запись в `<WORFY_DATA_DIR>/assistant/wake.json`: сколько событий каждого пункта
  передано, день сводки, время пробуждения. Память меняется только после удачной записи.
- Почему здесь: Test-ы тикета требуют перезапуск: он не должен повторять сводку и пункты. Запись, которая бросает,
  проверяет test «a look that fails» в `test/unit/assistant-wake-loop.test.ts`: сводка остаётся должной.
- Без него: после перезапуска worfy модель получала бы те же пункты заново, а сводка шла бы второй раз за день.
- Требование: [Test-ы](../issues/06-решение-о-пробуждении.md#test-ы)
- Риски и пробелы test-ов: файл — пятое место состояния Assistant-а; поправка ADR-0005 перечисляет четыре, строку
  добавляет Orchestrator.

## 5. Цикл: взгляд на изменение и по таймеру, пауза после ошибки

Code: `src/main/assistant/wake/loop.ts:63-82` · key lines: 68, 70, 81

```ts
  const plan = (failed = false): void => {
    if (timer !== undefined) clearTimer(timer)
    timer = undefined
    if (stopped) return
    const next = options.planner.nextCheckAt()
    const wait = next === null ? MAX_TIMER_MS : Math.min(Math.max(next - options.now(), 0), MAX_TIMER_MS)
    // A wake that is due stays due when its look fails: without the pause the timer would spin at 0 ms.
    timer = setTimer(look, failed ? Math.max(wait, LOOK_AFTER_ERROR_MS) : wait)
  }
  function look(): void {
    if (stopped) return
    let failed = false
    try {
      hand(options.planner.evaluate())
    } catch (error) {
      failed = true
      log('[assistant] the decision to wake failed', error)
    }
    plan(failed)
  }
```

- Что делает: после каждого взгляда ставит таймер к сроку, который называет планировщик (начало work hours, срок пачки,
  `until` проверки), но не дальше часа (`MAX_TIMER_MS` Ticket-а 04): так сон Mac и перевод часов подхватываются. Взгляд,
  который упал, повторяется через минуту, а не сразу.
- Почему здесь: spec, «Расписание проверок» — вместо новых `setInterval` один таймер к сроку; почему пауза — минута, не
  записано.
- Без него: должная сводка при сломанной записи файла крутила бы таймер с задержкой 0.
- Требование: [Что строить](../issues/06-решение-о-пробуждении.md#что-строить)
- Риски и пробелы test-ов: `startAssistantWake` в `app.ts` (источники приложения) test-ом не покрыт: его ещё никто не
  вызывает.

## Проверить себя

1. Почему Run, который остановился до первого запуска решения о пробуждении, не будит модель сразу?
   - Ответ: срочным считается только пункт `run-stopped`, обновлённый не раньше `since` файла; старая остановка идёт с
     утренней сводкой или пачкой.
   - Строки: `src/main/assistant/wake/planner.ts:111-111`
2. Почему перезапуск worfy в 10:00 не даёт второй утренней сводки, а сломанная запись файла не теряет её?
   - Ответ: день сводки сравнивается с днём, записанным в файл, а память принимает его только после удачной записи.
   - Строки: `src/main/assistant/wake/planner.ts:115-115`, `src/main/assistant/wake/planner.ts:176-180`
3. Что происходит, когда пробуждение держит дневной предел?
   - Ответ: решение `held` с `until` — местной полуночью; пункты остаются ждущими, в журнал расхода ничего не пишется,
     и цикл смотрит снова в `until`.
   - Строки: `src/main/assistant/wake/planner.ts:122-126`
