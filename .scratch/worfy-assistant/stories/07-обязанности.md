## 3. Что обязанность показывает, счётчики и пауза

Code: `src/main/assistant/duties/duties.ts:274-311` · key lines: 285, 292, 295, 296, 298, 310

```ts
  look(items: readonly AttentionItem[]): DutyLook {
    const now = this.options.now()
    const known = this.known()
    const memory = this.load()
    let changed = false
    const shown: ShownItem[] = []
    for (const item of items) {
      const duty = item.duty === null ? undefined : known.get(item.duty)
      if (duty === undefined) continue
      const id = duty.definition.id
      const state = memory.duties[id]
      if (item.state === 'dismissed') {
        // Dismiss is a reaction: it turns down the proposal of the duty that showed it.
        const shownBy = memory.items[item.id]?.duty
        if (shownBy !== undefined) changed = this.settle(shownBy, item.id, 'declined') || changed
        continue
      }
      if (item.state !== 'new' && item.state !== 'seen') continue
      if (state?.enabled === false || state?.paused !== undefined) continue
      if (state?.projects !== undefined && (item.projectId === null || !state.projects.includes(item.projectId))) continue
      // From the latest event glued into the item: a question at noon after a turn-end at ten waits from noon.
      if (item.source === 'session' && WAITED_KINDS.has(item.kind) && now - (item.lastAt ?? item.startedAt) < this.thresholdMs(id)) continue
      if (memory.rules.some((rule) => rule.duty === id && rule.projectId === item.projectId && rule.source === item.source && rule.kind === item.kind)) continue
      const counted = memory.items[item.id]
      if (counted === undefined || counted.duty !== id) {
        memory.items[item.id] = { duty: id, shownAt: now }
        this.state(id).counters.shown += 1
        changed = true
      } else if (counted.outcome === undefined && now - counted.shownAt >= IGNORED_AFTER_MS) {
        changed = this.settle(id, item.id, 'ignored') || changed
      }
      shown.push({ item, duty: id, proposals: this.proposals(duty.definition, item) })
    }
    if (changed) this.save()
    const duties = [...known.values()].map((each) => this.status(each))
    const paused = new Set(duties.filter((duty) => duty.paused !== null).map((duty) => duty.id))
    return { duties, shown: shown.filter((each) => !paused.has(each.duty)) }
  }
```

- Что делает: показывает открытый пункт, если обязанность включена, не на паузе, Project в её области, вопрос или
  молчание Session-а ждали порог из настроек от последнего склеенного события (`lastAt`) и ни одно правило из dislike его не прячет. Каждый пункт считается
  показанным один раз (пункт, склеенный в другую обязанность, — новый пункт для неё); Dismiss считается отказом; пункт без реакции через сутки — проигнорированным. Серия
  проигнорированных и dislike ставит обязанность на паузу, и `paused` виден в её состоянии.
- Почему здесь: не записано.
- Без него: Assistant показывал бы все пункты ядра, и like, dislike и пауза ничего бы не меняли.
- Требование: [Что строить, пункты 1 и 4](../issues/07-обязанности.md#что-строить)
- Риски и пробелы test-ов: «проигнорировано» считается только когда кто-то вызывает `look` (экран — Ticket 14);
  пока экрана нет, счётчики в приложении не растут.

## 5. CI основной ветки красный — пункт только через N минут

Code: `src/main/assistant/duties/main-ci.ts:28-49` · key lines: 34, 36, 44, 46, 47

```ts
export function mainCiAttention(core: Pick<AttentionCore, 'expect' | 'resolve'>, read: MainCiObservation, thresholdMs: number): void {
  const id = `ci:${read.repo}@${read.branch}`
  const subject = { kind: 'check' as const, id, label: `CI of ${read.branch} · ${read.repo}` }
  if (read.state === 'green') {
    core.resolve(read.projectId, subject)
    return
  }
  const cause = read.pr === null ? read.commit.slice(0, 9) : `${read.repo}#${read.pr.number} ${read.pr.title}`
  core.expect({
    source: 'ci',
    id,
    revision: read.commit,
    projectId: read.projectId,
    subject,
    kind: 'main-red',
    text: `The CI of ${read.branch} is red since ${cause}`,
    duty: 'main-ci-red',
    ...(read.pr === null ? {} : { pr: { repo: read.repo, number: read.pr.number, title: read.pr.title } }),
    quietMs: thresholdMs,
    from: read.redSince,
  })
}
```

- Что делает: красное чтение ветки взводит условие ядра «ничего не произошло» на порог обязанности от первого
  красного run-а; пункт несёт PR, после которого покраснело, и обязанность `main-ci-red`, а её предложение
  `fix-session` — текст Session починки. Зелёное чтение закрывает пункт и снимает условие.
- Почему здесь: не записано.
- Без него: красный main давал бы пункт сразу или не давал бы вовсе, и порог N из настроек ничего бы не значил.
- Требование: [Готово, когда](../issues/07-обязанности.md#готово-когда)
- Риски и пробелы test-ов: чтения CI основной ветки с GitHub в main нет, и ядро такого источника не знает; функция
  принимает прочитанное, а в приложении её пока никто не вызывает.
