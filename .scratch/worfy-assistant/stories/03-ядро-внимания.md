# Code story — worfy-assistant 03: Ядро внимания в main: пункты, дедупликация и склейка, «ничего не произошло», хранение, waits всех Project-ов

Kind: pr · Epic: worfy-assistant · Ticket: 03 · PR: - · Language: ru

## 1. Что было не так

По всем Project-ам worfy видел только счётчики. Что уже уведомлено, main помнил только в памяти, поэтому событие,
которое пришло, пока worfy был закрыт, терялось. Счётчик waits Project-а был, только пока окно показывало его Pipeline.
Общей шины событий в main не было, а Assistant-у нужен список пунктов.

- Требование: [Что строить](../issues/03-ядро-внимания.md#что-строить)

## 2. Событие становится пунктом: повтор отбрасывается, события предмета за день склеиваются

Code: `src/main/assistant/core/attention-core.ts:119-147` · key lines: 122, 125, 127, 134

```ts
  ingest(event: AttentionEvent): AttentionItem | null {
    const file = this.load(event.projectId)
    const key = keyOf(event.source, event.id, event.revision)
    if (file.seen[key] !== undefined) return null
    const now = this.options.now()
    const at = event.at ?? now
    file.seen[key] = now
    // An item already holds this revision (its key is gone, a source read its state again): it stays as it is.
    if (file.items.some((item) => item.condition === undefined && item.source === event.source && sameSubject(item.subject, event.subject) && item.revision === event.revision)) {
      this.save(event.projectId, file)
      return null
    }
    // Something happened on the subject: its pending condition ends, and an open «nothing happened» item is stale.
    this.settle(file, event.subject, 'stale')
    const day = dayOf(at, this.timeZone())
    const glued = file.items.find((item) => item.condition === undefined && sameSubject(item.subject, event.subject) && dayOf(item.startedAt, this.timeZone()) === day)
    let item: AttentionItem
    if (glued !== undefined) {
      Object.assign(glued, { source: event.source, kind: event.kind, text: event.text, revision: event.revision, updatedAt: now, events: glued.events + 1 })
      // A dismissed or snoozed item stays so; a seen, closed or stale one asks again.
      if (glued.state === 'seen' || glued.state === 'closed' || glued.state === 'stale') glued.state = 'new'
      item = glued
    } else {
      item = { ...this.fresh(event, at, now), events: 1 }
      file.items.push(item)
    }
    this.save(event.projectId, file)
    return item
  }
```

- Что делает: ключ «источник, id, ревизия» записывается в файл Project-а, и повтор с тем же ключом не даёт ничего, в
  том числе после перезапуска. Событие с ревизией, которая уже есть у пункта предмета, пункт не трогает, даже когда
  ключ уже удалён по сроку хранения: снятый пункт остаётся снятым. Событие предмета (PR, Ticket, Session, Run) того же местного дня склеивается в его
  пункт; день считается по времени самого события в часовом поясе настроек, так что сутки 25 часов при смене летнего
  времени — один день.
- Почему здесь: ключи дедупликации и склейки заданы в Ticket-е («Что строить», 3) и в spec-е («Ядро внимания (main)»);
  место кода — папка `src/main/assistant/core/` из брифа, чтобы PR-ы Ticket-ов 04 и 05 не пересекались с этим.
- Без него: 1 188 отказов `rate_limit` одной Session 2026-11-13 дали бы 1 188 пунктов вместо одного, а повтор того же
  ожидания Ticket-а после перезапуска — второй пункт.
- Требование: [Что строить, 3](../issues/03-ядро-внимания.md#что-строить)
- Риски и пробелы test-ов: часовой пояс по умолчанию — машины; work hours и их часовой пояс приносит Ticket 04, и
  тогда настройку дня надо будет брать оттуда. Test-ы проверяют Europe/Berlin, другие пояса не проверены.

## 3. «Ничего не произошло» — одно условие, один пункт

Code: `src/main/assistant/core/attention-core.ts:178-189` · key lines: 182, 184, 185

```ts
  private raise(scope: string | null, now: number): void {
    const file = this.load(scope)
    const due = file.conditions.filter((condition) => condition.dueAt <= now)
    if (due.length === 0) return
    file.conditions = file.conditions.filter((condition) => condition.dueAt > now)
    for (const condition of due) {
      file.seen[keyOf('condition', condition.id, condition.revision)] = now
      for (const item of file.items) if (item.condition === condition.id && isOpen(item)) item.state = 'stale'
      file.items.push({ ...this.fresh(condition, condition.dueAt, now), events: 1, condition: condition.id })
    }
    this.save(scope, file)
  }
```

- Что делает: условие со сроком лежит в файле Project-а. tick() обходит Machine и каждый Project, и ошибка файла
  одного Project-а пишется в лог, не останавливая остальные. Первый tick после срока поднимает один пункт с временем начала,
  равным сроку, и запоминает ключ условия: тот же tick ещё раз, `expect` той же ревизии и перезапуск второго пункта не
  дают. Новая ревизия того же условия даёт новый пункт, а открытый пункт старой ревизии становится `stale`.
- Почему здесь: «ничего не произошло» считает ядро, без модели (Ticket, «Что строить», 4); что такие пункты не
  склеиваются с пунктами событий — решено без владельца, пункт 4 «Решено без владельца» в «Итог».
- Без него: Session, которая закончила ход и молчит, не давала бы пункта вовсе; после сна Mac каждый tick давал бы ещё
  один пункт.
- Требование: [Что строить, 4](../issues/03-ядро-внимания.md#что-строить)
- Риски и пробелы test-ов: свой таймер раз в минуту (`ATTENTION_TICK_MS`, `shortcut:`) до планировщика Ticket-а 04.

## Проверить себя

1. Почему пункт «Session ждёт» после смены ревизии условия не склеивается с прежним, а прежний становится `stale`?
   - Ответ: условие изменилось — это новое ожидание, а старое уже неправда; пункты условий отмечены `condition` и
     исключены из склейки, а tick переводит открытый пункт того же условия в `stale`.
   - Строки: `src/main/assistant/core/attention-core.ts:134`, `src/main/assistant/core/attention-core.ts:185`
2. Почему Mac, проспавший 8 часов, даёт ровно один пункт «ничего не произошло», а не по одному на каждую пропущенную
   минуту?
   - Ответ: пропущенные tick-и не идут вовсе; первый tick после пробуждения снимает условие из файла и записывает его
     ключ, так что ни следующий tick, ни повторный `expect` той же ревизии пункта не дают.
   - Строки: `src/main/assistant/core/attention-core.ts:182`, `src/main/assistant/core/attention-core.ts:184`
