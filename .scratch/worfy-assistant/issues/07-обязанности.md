## Что строить

1. **Обязанность:** trigger, область (Project-ы, источники), режим каждого действия, счётчики и пауза.
   - Режимы действия: сам, по заранее данному «да», спросить, отдать пользователю.
   - Счётчики: показано, принято, отклонено, проигнорировано, like, dislike.
   - Пауза: после N проигнорированных предложений или dislike подряд обязанность встаёт на паузу, и это видно.
2. **Встроенные обязанности — только общие:** «работа стоит»; «CI основной ветки красный»; «ждёт пользователя»;
   утренняя сводка; по одной на каждый внешний источник. Их встроенные правила опираются только на то, что есть у любого
   Project-а:
   - Session молчит или ждёт ответа — дольше порога, который задал пользователь;
   - Run остановился;
   - CI основной ветки красный дольше N минут; N и само правило задаёт пользователь; у пункта — PR, после которого
     покраснело, и предложение Session починки;
   - PR ждёт пользователя.
3. **Правила конкретного Project-а** — процесс Project-а (land, `pc-main-red`, gate) — лежат в настройках этого
   Project-а; например «land закончился, а Orchestrator спит».
4. **Оценки:** dislike сразу снимает такие пункты этой обязанности и пишет правило в файл памяти Assistant-а. Правила
   видны и удаляются (экран — Ticket-ы 14 и 15).

### Решено без владельца (подтвердить)

1. **Пауза** — после 5 проигнорированных предложений или dislike подряд (`DEFAULT_PAUSE_AFTER`); like, принятие или
   отказ обрывают серию. Пауза снимается только пользователем (`resume`).
2. **Проигнорировано** — пункт всё ещё открыт через сутки после первого показа, а реакции не было
   (`IGNORED_AFTER_MS`). Пункт, который закрылся сам (пользователь ответил в Session), не считается проигнорированным.
   Dismiss считается отказом.
3. **Пороги по умолчанию** — Session молчит или ждёт ответа 15 минут (как `SESSION_WAIT_MS` Ticket-а 03), CI
   основной ветки красный 30 минут. Пользователь меняет их (`configure`, экран — Ticket 15).
4. **Какие пункты чьи.** «Работа стоит»: Session молчит (`quiet`, `waiting`) или упала (`error`), любая строка Autopilot-а,
   заблокированный Ticket, Limits. «Ждёт пользователя»: вопрос и разрешение Session-а, Ticket ждёт человека, PR ждёт
   пользователя, строка Health check. «CI основной ветки красный» — источник `ci`. Конец хода Session-а ни одна
   обязанность не показывает.
5. **«Такие пункты» после dislike** — пункты той же обязанности того же источника и вида в том же Project-е.
6. **Правило Project-а** — `when` (закончилась background task Session-а Project-а, в описании которой есть текст,
   или пришёл пункт Project-а по источнику, виду и тексту), затем `quietMinutes` тишины на том же предмете. «land
   закончился, а Orchestrator спит» — `{ when: { task: 'land' }, quietMinutes: 10 }`.
7. **Файл памяти** — `<WORFY_DATA_DIR>/assistant/memory.json`: обязанности с выбором пользователя, счётчики, пауза,
   правила из dislike. Ticket 10 может перенести его, когда назовёт файл памяти Session-а Assistant-а.
8. **Режимы по умолчанию**: разбудить Orchestrator, продолжить Session и Session починки CI — `ask`; открыть
   предмет — `hand-over`; утренняя сводка — `self`.
