## Что строить

1. **Assistant на каждой машине** отвечает за её Project-ы.
2. **Project-ы второй машины** он видит через Link только для чтения (ADR-0066): список «что ждёт» показывает пункты
   Project-ов обеих машин, а Project-ы второй машины — только для чтения.

- `worfy-app` — Ticket 09; раздел Assistant-а — Ticket 14.

## Решения

- По Assistant-у на каждую машину; Project-ы второй машины он только читает (решение 6).
- Project-ы второй машины Assistant только читает (spec, «Границы», 5).

## Итог

Assistant каждой Machine по-прежнему ведёт только свои Project-ы; то, что ждёт на Linked machine, приходит по одному
новому каналу чтения и показывается рядом, только для чтения.

- **Канал** `assistant.waiting` (`src/shared/ipc/assistant.ts`) — `project`, `read` (ADR-0066): Linked machine с
  уровнем Read only тоже его читает, при выключенном доступе — отказ «access is off». Ответ — Project-ы Machine и пункты,
  которые её раздел показывает сейчас, только слова и время (`src/shared/assistant/linked.ts`, `linkedItemOf`): без
  Prepare, предложения, цели Open и оценки; id пункта — digest id ядра. Остальные каналы `assistant.*` остались `local`
  (test `link-access.test.ts` называет это по имени).
- **Отдача** — `AssistantWindow.waiting()` (`src/main/assistant/window/view.ts`): только свои пункты, никогда не то, что
  Machine прочитала у другой. Project с `localOnly` (Demo project, worfy-onboarding 11) и его пункты, и пункты без
  Project-а (Limits) не уходят — как `ProjectStore.states()` не отдаёт их Linked machine (ревью, раунд 1). `AssistantWindow.start` теперь отказывает, если Project не этой Machine.
- **Чтение** — `LinkedWaits` (`src/main/assistant/window/linked.ts`): по вызову на каждую Linked machine, которая online;
  ответ ещё раз проверяется схемой; offline, отказ, ответ вне контракта — `problem` словами. Раздел читает последний
  ответ; в приложении (`src/main/assistant/window/app.ts`) чтение идёт при старте, раз в `WINDOW_LOOK_MS` и на каждый
  `changed` RemoteCalls (соединение, отвязка, сообщение `projects-access`), по одному чтению за раз (ревью, раунд 1).
- **Раздел** — `view.linked` (`src/shared/assistant/window.ts`) и группа «On <Machine> · read-only» во вкладке Waits
  (`src/renderer/assistant/parts.tsx`, `LinkedMachine`): карточки без кнопок, с пометкой Read-only; причина, если Machine
  ничего не отдала. Свой список, сводка, счётчик вкладки и уведомления считают только свои пункты.
- **`worfy-app`** (`src/main/mcp/app-server.ts`): `projects_list` называет Linked machine, её Project-ы и `problem`;
  `items_list` отдаёт под `linked` её пункты (`readOnly: true`, id `linked-…`); текст пункта, имена Project-ов, название
  обязанности и текст отказа Linked machine — outside text (ревью, раунд 1). `action_run` и
  `proposal_create` с пунктом Linked machine отказывают с её именем; Prepare в её Project-е отказывает, как раньше;
  `workflow_read`, `pr_threads_read` и `autopilot_runs_read` по её Project-у отказывают с её именем.
- Test-ы: `test/contract/assistant-two-machines.test.ts` (настоящий link adapter: Read only читает, Off отказ, остальные
  каналы `assistant.*` закрыты и при Full access; `worfy-app` над ответом Linked machine — стык Б),
  `test/unit/assistant-linked-waits.test.ts`, `test/unit/assistant-window.test.ts`, `test/unit/assistant-panel.test.tsx`,
  `test/contract/worfy-app-tools.test.ts`, `test/unit/link-access.test.ts`.

### Решено без владельца

1. **Новый канал чтения, а не `projects.list` и файлы ядра Linked machine.** Один вызов отдаёт Project-ы и пункты такими,
   какими их уже отобрали обязанности, правила и Snooze той Machine; так на этой Machine не нужно повторять её
   обязанности. Цена — сборка Linked machine старее этого Ticket-а канала не знает: её `problem` — текст отказа «not open
   to Linked machines», пунктов нет.
2. **Пункты Linked machine — отдельной группой в конце вкладки Waits, без кнопок.** Не входят в «Needs you now», сводку,
   счётчик вкладки, карточку-реплику и системные уведомления: их ведёт и о них сообщает Assistant своей Machine. Open с
   такого пункта не сделан: Project Linked machine пользователь открывает в sidebar, как раньше.
3. **Чтение workflow, нитей PR и Run-ов Project-а Linked machine через `worfy-app` отказывает с понятной причиной,** а не
   идёт через связь: Ticket просит Project-ы и пункты на чтение; прочее потребовало бы новых каналов. В ответе сказано,
   что это читается на той машине.
4. **Частота чтения** — при старте, раз в минуту (`WINDOW_LOOK_MS`, как остальной взгляд раздела) и на каждое изменение,
   о котором говорит RemoteCalls (соединение, отвязка, уровень доступа); `worfy-app` читает заново на каждом `projects_list`, `items_list` и проверке отказа.
5. **В ответе Linked machine нет id ядра:** id пункта ядра может содержать текст источника (Slack, Jira), поэтому уходит
   digest.
