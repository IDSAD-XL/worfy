# 21 — Читатель CI основной ветки: источник `ci` ядра внимания для обязанности «CI основной ветки красный»

Type: task
Status: open
Blocked by: 04, 07
Source: [spec.md](../spec.md), «Ticket-ы», строка 21; «Обязанности» («CI основной ветки красный дольше N минут»);
история 8; «Волны», Wave 3. Пробел нашёл implementer Ticket-а 07 (PR #2217): обязанность и функция
`mainCiAttention(core, прочитанное, порог)` есть, но в main нет кода, который читает CI основной ветки с GitHub,
поэтому в живом worfy пункт не появляется.

Кто: агент.

## Что строить

1. **Читатель.** Для каждого Project-а с GitHub-репозиторием main раз в N минут читает CI последнего commit-а основной
   ветки: сводный статус check-ов и PR, после которого ветка стала красной (gh GraphQL
   `defaultBranchRef.target.history` со `statusCheckRollup` и `associatedPullRequests`).
2. **Расписание** — через планировщик проверок Ticket-а 04, а не свой таймер: интервал, сон вне work hours и
   догон после сна Mac берутся оттуда. Проверка включена, только когда включена обязанность «CI основной ветки красный».
3. **Прочитанное** передаётся в `mainCiAttention` Ticket-а 07: красная ветка дольше порога даёт пункт с PR, зелёная
   закрывает его.
4. **Без лишних вызовов.** Project без GitHub-репозитория или без входа в gh не читается и пункта не даёт; ошибка
   чтения пишется в log и пунктом не становится. Аккаунт gh — тот же, которым worfy уже читает PR этого Project-а.

## Где в коде

- Образец чтения с GitHub — `src/main/github/deployments.ts`, `src/main/github/prs.ts` (`statusCheckRollup`).
- Планировщик — `src/main/assistant/schedule/`.
- Обязанность и `mainCiAttention` — `src/main/assistant/duties/main-ci.ts`.

## Решения

- Не использовать marker `main-red` у land: это процесс worfy, обязанности его не называют (Ticket 07).
- Интервал по умолчанию выбирает агент и пишет в «Решено без владельца».

## Test-ы

- Unit test на записанных ответах gh (fixture): красная ветка → прочитанное с PR; зелёная; Project без репозитория;
  ошибка gh.
- Unit test расписания: проверка регистрируется в планировщике, только пока обязанность включена.
- Test-ы не ходят в сеть и не вызывают настоящий gh.

## Готово, когда

- [ ] Unit test: записанный ответ gh с красной основной веткой даёт прочитанное с PR; зелёная — без PR.
- [ ] Unit test: Project без GitHub-репозитория и ошибка gh пункта не дают; ошибка пишется в log.
- [ ] Unit test: проверка CI основной ветки зарегистрирована в планировщике Ticket-а 04, только пока обязанность
      «CI основной ветки красный» включена.
- [ ] Unit test: прочитанное доходит до `mainCiAttention`, и пункт появляется после порога обязанности.
- [ ] `pnpm lint`, `pnpm typecheck`, `pnpm test` — exit 0; `ci-ok` зелёный на head PR.
