## Что строить

1. **Читатель.** Для каждого Project-а с GitHub-репозиторием main раз в N минут читает CI последнего commit-а основной
   ветки: сводный статус check-ов и PR, после которого ветка стала красной (gh GraphQL
   `defaultBranchRef.target.history` со `statusCheckRollup` и `associatedPullRequests`).
2. **Расписание** — через планировщик проверок Ticket-а 04, а не свой таймер: интервал, сон вне work hours и
   догон после сна Mac берутся оттуда. Проверка включена, только когда включена обязанность «CI основной ветки красный».
3. **Прочитанное** передаётся в `mainCiAttention` Ticket-а 07: красная ветка дольше порога даёт пункт с PR, зелёная
   закрывает его.
4. **Без лишних вызовов.** Project без GitHub-репозитория или без входа в gh не читается и пункта не даёт; ошибка
   чтения пишется в log и пунктом не становится. Аккаунт gh — тот же, которым worfy уже читает PR этого Project-а.

## Итог

- Чтение с GitHub — `src/main/github/main-ci.ts` (`readMainBranchCi`): один read-only `gh api graphql`
  (`defaultBranchRef.target.history` со `statusCheckRollup.contexts` и `associatedPullRequests`). Состояние ветки —
  состояние её последнего commit-а с итогом: commit, у которого check-и ещё идут или которого CI пропустил, ничего не
  говорит, как и commit, у которого упали только отменённые run-ы. Отметки агентов (`review`, `check/*`, `deploy`) не
  считаются, как в `ciOf` для PR. Красная серия начинается
  с самого старого красного commit-а после последнего зелёного; «покраснела» — когда упал первый check этого commit-а;
  PR — тот, что влит этим commit-ом.
- Проверка — `src/main/assistant/duties/main-ci-check.ts`: `mainCiCheck` читает каждый Project этой машины и каждый его
  репозиторий на github.com и отдаёт прочитанное в `mainCiAttention` с порогом обязанности; `followMainCiDuty` держит
  проверку в планировщике Ticket-а 04 (вид `main-ci`), только пока обязанность «CI основной ветки красный» включена.
  `Duties` получил `enabled(id)` и `onChange(listener)`. Красное условие живёт, пока его подтверждает чтение (решение 8).
- В приложении — `startDuties` (`src/main/assistant/duties/app.ts`): репозитории Project-а — `remoteRepos` папок его
  layout-а, gh — `sharedPrTracker().gh`, то есть аккаунт из Profile-а Project-а, которым worfy читает его PR.
- Вид проверки `main-ci` добавлен в `CHECK_KINDS`; обязанности и источника ядра у него нет: встроенные обязанности источников,
  `ATTENTION_SOURCES` и `ConnectorRecipe.kind` берут `SOURCE_CHECK_KINDS` (Slack, Jira).
- Стык: `test/unit/assistant-main-ci-check.test.ts` на записанных ответах gh (`test/fixtures/assistant-main-ci/`), с
  ненастоящими часами; настоящий gh и сеть не вызываются.

### Решено без владельца (подтвердить)

1. **Интервал** — 10 минут: с порогом обязанности 30 минут пункт приходит через 30–40 минут после того, как ветка
   покраснела.
2. **По умолчанию выключена** (`enabled: false`), как Slack и Jira: GitHub — внешний источник (решение 10 spec-а), и
   без включения worfy не вызывает gh ради этой проверки. Включается в настройках проверок (`assistantSchedule.checks`,
   поле `main-ci`); экрана для этого пока нет (Ticket 15).
3. **Ночью не спит** (`sleepOutsideWorkHours: false`): красная ветка ночью останавливает агентов, которые работают ночью;
   вызов — один GraphQL-запрос на репозиторий раз в 10 минут.
4. **Окно** — 20 последних commit-ов основной ветки и до 100 check-ов на commit. Серия длиннее 20 commit-ов начинается с
   самого старого красного из увиденных.
5. **Ошибка чтения** (gh упал, нет входа в gh для аккаунта Project-а, ответ не читается, layout не читается) пишется в
   log один раз на Project и репозиторий, пока причина не изменится.
6. **Пауза обязанности** проверку не снимает: снимает только выключение обязанности. Область обязанности (выбранные
   Project-ы) чтение не сужает: пункты вне области не показывает сама обязанность.
7. **Отменённый run** (review round 1): commit, у которого все упавшие check-и — отменённые run-ы, ничего не говорит, и
   состояние ветки решает commit до него (ADR-0068: run, который вытеснил более новый, — не красный). Commit с одним
   отменённым необязательным job-ом и остальными зелёными тоже ничего не говорит. Отменённый run не считается временем
   «покраснела»; отметки агентов тоже.
8. **Красное условие без чтения** (review round 1): условие, которое следующий run не подтвердил (чтение упало,
   репозиторий или Project ушёл), снимается; выключение обязанности, выключение проверки в настройках и выход из worfy
   снимают всё, что проверка взвела. Уже поднятый пункт остаётся открытым до зелёного чтения. Новый метод ядра —
   `AttentionCore.disarm(scope, id)`.
9. **Старая сборка worfy и файл меток проверок**: сборка до этого Ticket-а не знает вида `main-ci`. Встретив его в
   `assistant-check-marks.json`, она откладывает файл в сторону, и все проверки один раз идут как ни разу не шедшие.
   Это бывает только при откате на старую сборку; не исправляется.
