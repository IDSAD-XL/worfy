## Что строить

Ядро внимания в main, без модели. Собирает события всех Project-ов машины как пункты, а не счётчики; хранит их между
перезапусками; само замечает, что «ничего не произошло». Общей шины событий в main нет — ядро становится такой шиной
для Assistant-а. Решение о пробуждении — Ticket 06, не этот.

1. **Источники** — то, что в main уже есть:
   - события Session-ов: вопрос, разрешение, ошибка, конец хода, пометка `quiet` молчащего хода;
   - уведомления о Ticket-ах, которые ждут пользователя;
   - изменения PR inbox;
   - workflow: Ticket заблокирован, Ticket ждёт человека;
   - состояние и журнал Autopilot-а;
   - Health check;
   - Limits.
2. **Пункт журнала:** источник, Project, предмет (PR, Ticket, Session, Run, сообщение источника), вид, время начала,
   ревизия, состояние (новый, просмотрен, отложен, снят, закрыт, устарел), обязанность.
3. **Дедупликация** — по источнику, id и ревизии. **Склейка** — по предмету за день.
4. **«Ничего не произошло»** считает ядро: одно условие даёт один пункт, пока условие не изменится.
5. **Хранение** — в папке данных Project-а на его машине. После запуска worfy ядро догоняет то, что пропустило.
6. **Waits для всех Project-ов машины**, а не только пока окно показывает Pipeline.

## Решения

- Без модели; пункты, а не счётчики; хранение между перезапусками (spec, «Решение», слой 1).
- Поля и состояния пункта, ключи дедупликации и склейки, «ничего не произошло», хранение в папке данных Project-а,
  waits для всех Project-ов (spec, «Ядро внимания (main)»).
- Встроенные правила опираются только на то, что есть у любого Project-а (spec, «Решено советником», «Общие встроенные
  правила»).
