## Что строить

Ядро внимания в main, без модели. Собирает события всех Project-ов машины как пункты, а не счётчики; хранит их между
перезапусками; само замечает, что «ничего не произошло». Общей шины событий в main нет — ядро становится такой шиной
для Assistant-а. Решение о пробуждении — Ticket 06, не этот.

1. **Источники** — то, что в main уже есть:
   - события Session-ов: вопрос, разрешение, ошибка, конец хода, пометка `quiet` молчащего хода;
   - уведомления о Ticket-ах, которые ждут пользователя;
   - изменения PR inbox;
   - workflow: Ticket заблокирован, Ticket ждёт человека;
   - состояние и журнал Autopilot-а;
   - Health check;
   - Limits.
2. **Пункт журнала:** источник, Project, предмет (PR, Ticket, Session, Run, сообщение источника), вид, время начала,
   ревизия, состояние (новый, просмотрен, отложен, снят, закрыт, устарел), обязанность.
3. **Дедупликация** — по источнику, id и ревизии. **Склейка** — по предмету за день.
4. **«Ничего не произошло»** считает ядро: одно условие даёт один пункт, пока условие не изменится.
5. **Хранение** — в папке данных Project-а на его машине. После запуска worfy ядро догоняет то, что пропустило.
6. **Waits для всех Project-ов машины**, а не только пока окно показывает Pipeline.

### Решено без владельца (подтвердить)

1. **Где лежат пункты Machine.** Пункты без Project-а (Limits, строка Health check без Project-а) лежат в
   `<WORFY_DATA_DIR>/assistant/items.json`; пункты Project-а — в `<папка данных Project-а>/assistant-items.json`.
2. **Предметы сверх spec-а.** Кроме PR, Ticket, Session, Run и сообщения источника у пункта есть предметы `check`
   (строка Health check) и `limit` (окно Limits).
3. **Склейка и состояния.** Событие предмета в тот же день, что и его пункт, склеивается в этот пункт: `seen`, `closed`
   и `stale` снова становятся `new`, `dismissed` и `snoozed` остаются. День — местный, по часовому поясу настроек
   (по умолчанию — часовой пояс машины), поэтому сутки 23 и 25 часов — один день. День берётся по времени самого
   события (время `Status:` Ticket-а, `at` строки журнала), а не по времени, когда ядро его увидело.
4. **«Ничего не произошло».** Источник называет условие и срок; если до срока на предмете ничего не случилось, условие
   даёт один пункт. Такие пункты не склеиваются с пунктами событий: изменившееся условие даёт новый пункт, а открытый
   пункт старой ревизии становится `stale`. Событие на предмете до срока снимает условие. Встроенное условие одно:
   Session закончила ход и молчит `SESSION_WAIT_MS` = 15 минут (правило (e) замера событий). Остальные правила —
   обязанности Ticket-а 07.
5. **Закрытие пунктов.** Пункты предмета закрываются (`closed`), когда причина ушла: prompt человека или ответ на
   запрос в Session; Ticket больше не ждёт и не заблокирован или исчез; PR перешёл в группу, которая не ждёт
   пользователя; строка Health check снова `ok`; окно Limits снова `allowed`.
6. **Срок хранения.** `ATTENTION_KEEP_DAYS` = 14 дней (период замера): пункты не в открытом состоянии и ключи
   принятых событий старше 14 дней удаляются. Открытые пункты хранятся, пока открыты.
7. **История до ядра — не пункты.** Строки журнала Autopilot-а старше первого запуска ядра для Project-а (`since` в
   файле) пунктами не становятся: первый запуск не заваливает список старыми остановками. Состояния (Ticket ждёт,
   PR ждёт, строка Health check, окно Limits) становятся пунктами и при первом запуске.
8. **Какие строки журнала Autopilot-а — пункты.** `run-stopped`, `ticket-set-aside`, `session-error`, `limits-hit`,
   `retry-refused` (`AUTOPILOT_ITEM_KINDS`); `run-stopped` с причиной `tickets-done` — пункт вида `run-finished`.
9. **PR inbox.** Пункт — PR в группе, которая ждёт пользователя (`needs-review`, `needs-answer`, `needs-fix`, как
   счётчик «PR need you»); ревизия — `updatedAt` PR-а.
10. **Таймер.** Условия проверяются раз в минуту (`ATTENTION_TICK_MS`) своим таймером и сразу на старте; помечено
    `shortcut:` — заменить планировщиком Ticket-а 04.
11. **Ядро работает всегда.** Выключателя Assistant-а ещё нет (Ticket 15), поэтому ядро собирает пункты у всех: когда
    Assistant включат, список уже готов. Пишет только в папку данных worfy (ADR-0005).
