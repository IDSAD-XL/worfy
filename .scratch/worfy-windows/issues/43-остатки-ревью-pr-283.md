### 1. Повтор удаления в `install-stable`: test только на Windows, между запусками нет паузы

- **Что сейчас.** На Windows каждое удаление скрипта (остатки прерванного запуска `:522`, недописанная копия
  `:550`, прежняя копия `:561`) запускается до пяти раз. Цикл стоит в `installStable` за проверкой системы
  (`scripts/install-stable.mjs:432-441`). Его test (`test/unit/install-stable.test.ts:408`)
  вне Windows выходит на `:424-428`, не дойдя до цикла; Linux CI блок с ним пропускает (`:48`).
- **Запущено на Mac:** четыре мутанта цикла проходят этот test-файл, exit code 0: `REMOVE_ROUNDS` 1 и 0 вместо
  5, список кодов без `EPERM`, повтор после любой ошибки. На ПК мутанты числа запусков красные (текст PR).
- **Прочитано: и на Windows закреплены два кода из четырёх.** Подменное удаление test-а бросает `EBUSY`,
  `EPERM` и `EIO` (`:414-423`; коды — `:430`, `:435`, `:442`); список без `ENOTEMPTY` или `EACCES` не меняет ни одной проверки. Обход по
  умолчанию (`removeFolder = removeTree`) с занятой записью не идёт ни в одном test-е.
- **Сделать.** Вынести цикл в экспортируемую функцию, которая принимает удаление параметром, как `swapIn` —
  файловую систему. Test в `install-stable-functions.test.ts` идёт на любой системе: пять запусков, каждый из
  четырёх кодов, другой код заканчивает сразу. Удаление в нём подменное: функция бросает код и диск не
  трогает. Ещё один test — в `test/unit/remove-tree.test.ts`, где лежат модель (`model`, `:286`) и копия обхода
  из текста скрипта (`builtCopy`, `:626`): вынесенная функция получает копию обхода `scripts/install-stable.mjs`;
  запись занята дольше одного запуска и уходит на следующем.
- **Между запусками нет паузы** (`:434-440` скрипта): обход (`:365-377`) ждёт на `unlink` и `rmdir`, не на
  `lstat` и `readdir`. На модели: `lstat` всегда с `EPERM` — 5 запусков, 0 ожиданий. Даёт ли Windows такой
  код, не проверялось. Сделать: пауза `RETRY_MS` перед каждым повторным запуском — цикл не знает, тратил ли
  обход ожидания: их запас создаётся в `removeTree` (`:327`), а текст между метками менять нельзя — или
  строка в комментарии `:45`.

### 2. Запрет `rmSync` (`test/unit/no-rmsync.test.ts`): что он пропускает и что говорит шапка

- **В `test/` поиск видит только `rmSync(`** (`recursiveUses`, `:136-142`); alias импорта и `rmdirSync`
  проверяет `uses` (`:119-121`) в `src/` и `scripts/`. Запущено на Mac временным файлом в `test/unit/`:
  `import { rmSync as wipe }`, `rmdirSync` с `recursive`, `const wipe = fs.rmSync` — запрет зелёный.
- **Шапка (`:14-22`) не называет** ни этого, ни форм, которые поиск не находит в `src/` и `scripts/` (запущено
  на Mac над строками-образцами): `rm` из `node:fs` с callback-ом; `rmdir` из `node:fs/promises`;
  `fs.rmdirSync?.(…)`; `fs.rmdirSync.call(…)`; `fs['rmdirSync'](…)`; `rmdirSync(...args)`; `)` в комментарии
  внутри вызова; строка кода, начатая с `*`. В коде их сегодня нет (grep ревью). Ещё две формы для `test/`,
  над строками-образцами: `rmSync(...args)` и `fs.rmSync?.(…)` (`:140`, `:101-102`).
- **Новое ложное срабатывание** (`:50-61`): кавычка в regex-литерале открывает строку. Запущено на Mac:
  `rmSync(name.replace(/'/g, ''))` перед строкой с `recursive` срабатывает. Настоящий вызов не теряется.
- **Сделать.** Применять в `recursiveUses` проверки alias-а и `rmdirSync` — либо сказать в шапке, что в
  `test/` ищется только `rmSync(`. Шапку дополнить формами или назвать её список примерами; назвать там ложное
  срабатывание. Описание `uses` (`:41-48`) перенести к самой функции (`:105`). Alias и `rmdirSync` в `test/`
  названы и в пункте 3 Ticket-а 32 (строка 33): правка делается здесь, в «Итог» Ticket-а 32 идёт ссылка на неё.
