# 70 — Одна папка в двух написаниях (8.3, `subst`, регистр) вне среза 3 Ticket-а 14

Type: bug
Status: open
Blocked by: —
Source: ревью PR #521, #523 и #525 (срезы 3g, 3j, 3h Ticket-а 14), 2026-10-19. Чистый runner GitHub для Windows
держит TEMP под коротким 8.3-именем (`C:\Users\RUNNER~1\…`); так же выглядит TEMP пользователя с длинным именем
учётной записи. Срезы 3 исправили свои места (`apply.ts` `isRepoRoot`, `gate-resolve.mjs` `onDisk`,
`projects/store.ts` и `projects/connect.ts` `realpathOrSelf`); ревьюеры нашли ещё места того же рода вне их diff-ов.
Строки — на main `a905e124`.

Приоритет — med для `checkHome` (отказ ради безопасности обходится коротким написанием домашней папки; решение
Session на Mac, 2026-10-19), low для остальных двух пунктов: в обычной работе оба написания приходят из git или из
длинного `USERPROFILE`, и разница возникает, только когда путь набран или сохранён коротким, через `subst`-диск
или в другом регистре.

## Что происходит

На Windows у одной папки есть написания, которые не являются ссылками: короткое 8.3-имя, буква `subst`-диска,
другой регистр. git, `fs.realpathSync.native` и `realpath` из `node:fs/promises` дают длинное написание с диска;
`fs.realpathSync` и `fs.realpath` с callback-ом оставляют набранное (проверено на ПК через `subst W:`: sync и
callback — `W:\…`, native и promises — `C:\…`). Сравнение двух путей, полученных разными способами, говорит
«разные папки» про одну папку.

- `src/main/harness/migrate/apply.ts:112-117`, `checkHome`: отказ «not a folder the move may write in» сравнивает
  `realpathSync(path)` с `realpathSync(homedir())`. Домашняя папка, переданная коротким написанием, отказа не
  получает: guard против записи в саму домашнюю папку обходится.
- `src/main/mcp/canvas-server.ts:363-382`, `projectForCwd`: `cwd` и `project.path` идут через `realpathSync`. `cwd`
  в коротком написании (или через `subst`) не находит свой Project, если тот сохранён длинным (а #525 сохраняет
  корень так, как его печатает git, — длинным).
- `harness/hooks/gate-paths.mjs:89-94`, `isSameOrInside`: запись реестра на корень диска (`C:\`) не покрывает
  вложенных папок — после свёртки база `c:/`, и префикс становится `c://`. К написанию не относится, найдено тем же
  ревью.

Проверено и не затронуто: `src/main/autopilot/run.ts:300` `canonical()` — `realpath` из `node:fs/promises`, то
есть native; `src/main/harness/migrate/restore.ts:442-446` — `process.argv[1]` и `import.meta.url` Node строит
одним и тем же обычным realpath (test restore.mjs в #521 зелёный с `TEMP=W:\`).

## Что делаем

1. Test на каждое место, красный до правки:
   - `checkHome`: домашняя папка в другом написании (на Windows — другой регистр и `/`; на macOS — другой регистр;
     на диске с учётом регистра — пропуск с причиной) отказывается так же, как в обычном.
   - `projectForCwd`: `cwd` в другом написании корня находит тот же Project.
   - `isSameOrInside("C:\\a\\b", "C:\\", "win32")` — true; `isSameOrInside("/a", "/", "darwin")` — тоже проверить.
2. Правка: сравнение через `realpathSync.native` с запасным `realpathSync` (как `realpathOrSelf` в
   `projects/store.ts` после #525); в `gate-paths.mjs` — база, уже оканчивающаяся на `/`, не получает второй.
3. Поиск по `src/` и `harness/`: нет ли ещё сравнения путей, где одна сторона пришла от git или native, а другая
   — от `fs.realpathSync` / `fs.realpath`. Найденное — в «Итог» и в правку.

Правки:

  `checkHome` (`:130`) сравнивает с домашней папкой через `onDisk` с обеих сторон; `isRepoRoot` (`:175`) берёт тот же
  `onDisk` вместо своей копии. `checkHome` по-прежнему возвращает обычный `realpathSync`: дальше по коду написание
  не меняется.
- `src/main/mcp/canvas-server.ts` — свой `realpathOrSelf` с обычным `realpathSync` заменён на `onDisk` (`:372`) поверх

- `harness/hooks/gate-paths.mjs:94` — база, уже оканчивающаяся на `/` (корень диска `C:\`, `/`, `match` со `/` на

  программу запустили (проверено: программа, запущенная как `W:\…\x.exe`, видна как `W:\…`), а цель через junction

- Круг ревью 2: `isSameOrInside` принимает и саму папку базы со `/` на конце (`C:\a\repo` под `C:/a/repo/`),

- После ревью PR #562 (ветка `worfy-windows/70-lows`, follow-up): `apply.ts` берёт `realpathOnDisk` из
