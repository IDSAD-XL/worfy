## Что происходит

- **Не про Windows.** Дефект есть на main и был до PR #281; виден он на macOS. Ticket лежит в этом
  Epic-е, потому что найден ревью его Ticket-а 27 и Epic сейчас в работе. Всё ниже, кроме заметки о
  Linux, запущено на Mac: Darwin 25.6.0, Node 24.21.0 из Electron 44.5.1.
- **`DocsWatcher`** — наблюдатель worfy за `HANDOFF.md` и ADR Project-а: один рекурсивный
  `fs.watch` на корне (`src/main/docs/watch.ts:182`). Когда `HANDOFF.md` читается как отсутствующий,
  main скрывает HANDOFF Node и ставит ему пометку `missing` (`src/main/ipc/docs.ts:50-54`); список
  ADR пуст. Node не удаляется. Когда файл вернулся, Node показывается снова (`:43-49`).
- **Что шлёт macOS, когда корень удалён или переименован.** Одно событие за 3 s. Имя в нём —
  последнее имя корня (в замере `project`): не полный путь и не `null`. `error` и `close` нет;
  1–2 ms процессорного времени. Рекурсивный и не рекурсивный watch ведут себя одинаково.
- **Что делает код.** Такое имя не проходит `isWatchedPath` (`watch.ts:165-170`), и строка `:276`
  чтения не назначает. Ветка PR #281 — имя — полный путь (`:275`) — на macOS не выполняется; исключение — корень `/`
  ([Ticket 36](36-остатки-ревью-pr-281.md), пункт 3).
- **Что видно.** За 3 s подписчик не получает ничего; `watcher.current` держит прежние `HANDOFF.md`
  и список ADR; в логе пусто. У другого reviewer-а документы не прочитались как отсутствующие и за
  9 s — в четырёх прогонах из четырёх. HANDOFF Node не скрыт, список ADR не пуст.
- **Устаревшее состояние — в 8 из 10 измеренных способов убрать корень:** `unlink` + `rmdir`;
  `rename`; `rmSync` с `recursive`; `rmSync` корня с 4000 лишних файлов (4040–4062 события, ни
  одного про `HANDOFF.md` или `docs`). Каждый способ — с ADR и без.
- **Верно только в двух:** `HANDOFF.md` удалён за 300 ms до папки, с ADR и без. Подписчик получает
  `handoff: null` через 63–65 ms — от события самого файла.
- **Состояние лечится, когда корень создан снова по тому же пути.** Тот же watch сообщает о папке:
  сам `fs.watch` — через 11–13 ms; `DocsWatcher` видит новый `HANDOFF.md` через 64–74 ms у одного
  reviewer-а, 78–106 ms у второго, 103 ms у третьего. Переименованную папку watch под новым именем
  не видит: 0 событий за 1,5 s.
- **Код PR #281 и main дают одни и те же числа** (кроме корня `/`)**.** После PR Windows читает удалённый корень как
  пропавший — Node скрыт, список ADR пуст, — а macOS нет.
- **Заметка о Linux — прочитано, не запускалось** (Node 24.21.0 из Electron 44.5.1,
  `internal/fs/recursive_watch`). Удаление корня приходит событием с пустым именем `''`. Рекурсивный
  watch Node при этом сам закрывает все свои внутренние watch-и, без `close` и без `error`. Имя `''` —
  не полный путь и не путь документов: `DocsWatcher` его отбрасывает и держит мёртвый watch. Так и
  на main.

## Что делаем

1. **Сначала падающий test на настоящих папках, только macOS:** корень удалён — состояние
   становится `{ handoff: null, adrs: [] }`. Способы из замера: `unlink` + `rmdir`, `rename`,
   `rmSync` с `recursive`.
2. **Правка.** Событие, имя которого — последнее имя корня, значит «изменился сам корень»:
   назначить чтение. Чтение корня, которого нет, даёт `handoff: null` и пустой список ADR.
3. **Решить, нужно ли на macOS ждать корень.** По замеру watch того же пути сам сообщает о папке,
   созданной снова; переименованную он не видит. Решение — в «Итог».
4. **Linux.** Если worfy выпускается под Linux — считать имя `''` потерей корня (`lost()`): тогда
   ожидание через `stat` работает как на Windows. Сначала замер на Linux: сейчас это только чтение.
   Иначе — записать ограничение в шапку `DocsWatcher` (`watch.ts:212-220`).
