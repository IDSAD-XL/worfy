- **`DocsWatcher`** — наблюдатель worfy за `HANDOFF.md` и ADR Project-а: один рекурсивный
  `fs.watch` на корне (`src/main/docs/watch.ts:182`). Когда `HANDOFF.md` читается как отсутствующий,
  main скрывает HANDOFF Node и ставит ему пометку `missing` (`src/main/ipc/docs.ts:50-54`); список
  ADR пуст. Node не удаляется. Когда файл вернулся, Node показывается снова (`:43-49`).
- **Что шлёт macOS, когда корень удалён или переименован.** Одно событие за 3 s. Имя в нём —
  последнее имя корня (в замере `project`): не полный путь и не `null`. `error` и `close` нет;
  1–2 ms процессорного времени. Рекурсивный и не рекурсивный watch ведут себя одинаково.
- **Что делает код.** Такое имя не проходит `isWatchedPath` (`watch.ts:165-170`), и строка `:276`
  чтения не назначает. Ветка PR #281 — имя — полный путь (`:275`) — на macOS не выполняется; исключение — корень `/`
  ([Ticket 36](36-остатки-ревью-pr-281.md), пункт 3).
- **Что видно.** За 3 s подписчик не получает ничего; `watcher.current` держит прежние `HANDOFF.md`
  и список ADR; в логе пусто. У другого reviewer-а документы не прочитались как отсутствующие и за
  9 s — в четырёх прогонах из четырёх. HANDOFF Node не скрыт, список ADR не пуст.
- **Устаревшее состояние — в 8 из 10 измеренных способов убрать корень:** `unlink` + `rmdir`;
  `rename`; `rmSync` с `recursive`; `rmSync` корня с 4000 лишних файлов (4040–4062 события, ни
  одного про `HANDOFF.md` или `docs`). Каждый способ — с ADR и без.
- **Верно только в двух:** `HANDOFF.md` удалён за 300 ms до папки, с ADR и без. Подписчик получает
  `handoff: null` через 63–65 ms — от события самого файла.
- **Состояние лечится, когда корень создан снова по тому же пути.** Тот же watch сообщает о папке:
  сам `fs.watch` — через 11–13 ms; `DocsWatcher` видит новый `HANDOFF.md` через 64–74 ms у одного
  reviewer-а, 78–106 ms у второго, 103 ms у третьего. Переименованную папку watch под новым именем
  не видит: 0 событий за 1,5 s.
- **Код PR #281 и main дают одни и те же числа** (кроме корня `/`)**.** После PR Windows читает удалённый корень как
  пропавший — Node скрыт, список ADR пуст, — а macOS нет.
- **Заметка о Linux — прочитано, не запускалось** (Node 24.21.0 из Electron 44.5.1,
  `internal/fs/recursive_watch`). Удаление корня приходит событием с пустым именем `''`. Рекурсивный
  watch Node при этом сам закрывает все свои внутренние watch-и, без `close` и без `error`. Имя `''` —
  не полный путь и не путь документов: `DocsWatcher` его отбрасывает и держит мёртвый watch. Так и
  на main.

   ожидание через `stat` работает как на Windows. Сначала замер на Linux: сейчас это только чтение.

### Что сделано

- **Правка** (`src/main/docs/watch.ts`, обработчик события в `DocsWatcher.watch`): событие, имя которого — последнее имя корня (`basename` корня), назначает чтение, как событие `HANDOFF.md`. Чтение корня, которого нет, даёт `{ handoff: null, adrs: [] }`; watch не закрывается, в лог ничего не идёт. Правило одно на всех системах: на Windows такое имя бывает только у файла прямо под корнем с тем же именем — лишнее чтение, подписчику не уходит, если ничего не изменилось.
- **Шапка `DocsWatcher`** — поведение macOS и ограничение Linux (пункты 3 и 4).

### Замер на Mac (пункт 3)

Проба — рекурсивный `fs.watch` папки `project` под Node из Electron, 1,5 s до действия и после, два прогона с одинаковым результатом: `../evidence/38-probe.mjs`, `../evidence/38-probe-parent.mjs`.

| Что сделано с корнем | События после действия |
|---|---|
| `rename` прочь | одно: `change "project"` через 12 ms |
| затем `mkdir` по старому пути и запись `HANDOFF.md` | `change "project"`, `rename "HANDOFF.md"` через 12 ms |
| затем запись в переименованную папку | ни одного |
| `rename` прочь, затем `rename` обратно | `change "project"` через 13 ms; позже запись `HANDOFF.md` — `rename "HANDOFF.md"` |
| `rm` из `node:fs/promises` с `recursive`, затем `mkdir` снова | `change "project"`; после `mkdir` — `change "project"`, `rename "HANDOFF.md"` |
| `unlink` + `rmdir` без ADR | одно: `change "project"` |
| файл `project` прямо под корнем | `rename "project"` — то же имя, что у самого корня |
| папка выше корня переименована и возвращена; удалена с `recursive` | ни одного события |

- **Решение по пункту 3: на macOS корень не ждём.** FSEvents следит за путём, а не за папкой: тот же watch сообщает о корне, созданном снова или переименованном обратно, — тем же событием с последним именем корня. Это событие и назначает чтение, документы возвращаются. Ожидание через `stat` раз в 2 s, как на Windows, дало бы возврат через 2 s вместо десятков ms и закрывало бы watch, который продолжает работать. Мутант «имя корня — потеря корня, `lost()`» красный в шести test-ах (ниже).
- **Возврат переименованием обратно правка чинит отдельно:** до неё такое возвращение давало только событие `project`, и документы оставались «пропавшими» до следующей правки файла.
- **Чего правка не покрывает:** папка выше корня удалена или переименована — FSEvents не шлёт ни одного события, документы остаются как были прочитаны. Записано в шапке `DocsWatcher`; это не входит в Ticket.

### Решение по пункту 4 (Linux)

worfy под Linux не выпускается: `electron-builder.yml` — только `mac` и `win`; ADR-0054 — «Linux-сборка, которой нет». Поэтому `''` не считается потерей корня, ограничение записано в шапку `DocsWatcher`: удалённый корень приходит событием с именем `''`, рекурсивный watch Node сам закрывает свои внутренние watch-и, документы остаются как были прочитаны, корень никто не ждёт. По чтению исходников Node 24, на Linux не запускалось.
