## Что происходит

Три e2e падают на ПК в каждом прогоне (пересчёт, два gate full и сравнения с main). Все три — сравнение
размера с целым числом CSS px, а на ПК `devicePixelRatio` = 1.5.

1. `test/e2e/done-stack.spec.ts:139` («the open done stack folds by Collapse in the place of Expand, and by
   Esc once nothing else takes the press»), `:169`:
   ```
   expect(locator).toHaveCSS(expected) failed — getByTestId('done-stack-toggle')
   Expected: "1px"   Received: "0.666667px"
   ```
   0.666667 = 1 / 1.5: рамка в 1 CSS px нарисована одним device px. Вероятно, Chromium округляет ширину
   рамки вниз до целых device px и `getComputedStyle` отдаёт уже округлённое значение. Тогда неверна
   проверка, а не кнопка. Похожий случай — чип Open в [Ticket-е 94](94-чип-open-на-windows-выше-своей-рамки.md).
2. `test/e2e/palette-find.spec.ts:101` («⌘K goes to a Ticket and runs commands as the buttons do; ⌘F finds
   words in a transcript and a Card»), `:193`:
   ```
   Expected { field: 28, input: 28, row: 28 }
   Received { field: 28, input: 28.000003814697266, row: 28.00000762939453 }
   ```
   `field` — `clientHeight` (целое), `input` и `row` — `boundingBox()` (дробное). Разница 2⁻¹⁸ и 2⁻¹⁷ px —
   шум перевода координат при дробном масштабе, меньше одной единицы раскладки Chromium (1/64 px).
   Вероятно, неверна проверка: она сравнивает дробное число точным `toMatchObject`.
3. `test/e2e/window.spec.ts:179` («the window position and size survive a restart»), `:201`:
   ```
   Expected { x: 60, y: 100, width: 900, height: 560 }
   Received { x: 60, y: 100, width: 900, height: 562 }
   ```
   Первый запуск записал верные границы (`window-state.json` равен `wanted`, проверка `:197` прошла). Второй
   запуск открыл окно на 2 px выше. Это похоже на продукт или Electron: в
   [Ticket-е 97](97-browser-layer-правый-край-страницы-не-найден-на-windows.md) окно без рамки 638×410 при
   150 % тоже вышло 638×412, там помог `setContentSize`. 2026-10-21 `window.spec.ts` на ПК был зелёным после
   [Ticket-а 79](79-e2e-window-и-settings-health-на-windows.md), то есть это регрессия.

## Что делаем

Для каждой проверки сначала причина, потом правка. Допуск в test-е — только если неверна сама проверка при
дробном масштабе; в «Итог» для каждой из трёх сказать, что неверно: продукт или проверка.

1. Рамка: замерить на ПК `getComputedStyle(toggle).borderTopWidth` и ширину рамки на снимке в device px.
   Если рамка — ровно 1 device px, а Chromium так округляет любую рамку в 1 CSS px, ожидание — то, что
   Chromium отдаёт при этом масштабе (например, `floor(1 × dpr) / dpr`), а не строка `1px`.
2. Высоты: если разница — шум перевода координат, сравнивать с точностью до единицы раскладки
   (`toBeCloseTo(28, 1)` или округление до 1/64). Если высота поля на самом деле дробная — править CSS.
3. Окно: найти, где второй запуск получает 562: границы из `window-state.json` при создании окна, рамка
   Windows, `setBounds` против `setContentBounds`, минимальный размер. Правка — в продукте, чтобы
   восстановленное окно было ровно сохранённого размера при любом масштабе; test остаётся точным.
