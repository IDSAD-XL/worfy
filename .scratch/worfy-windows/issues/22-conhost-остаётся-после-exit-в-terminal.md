PR #239 правит тот же файл и вливается раньше. Делается после Ticket-а [20](20-chokidar-не-идёт-по-ссылке-на-unc.md) (watcher-ы chokidar и ссылка на share). Делает Session на Windows-ПК; проверяет и вливает Session на Mac, как у Ticket-а 20.

## Что происходит

Замер на ПК владельца, 2026-10-12. В Terminal Node оболочка завершается сама: пользователь набрал
`exit`. Её дочерний `conhost.exe` остаётся, пока worfy не выйдет. 20 таких выходов оставляют 20
`conhost.exe` — и до правок PR #239, и после них. Каждый — процесс и сколько-то памяти; сколько,
не мерили.

Причина — по исходникам node-pty 1.1.0, файл `node_modules/node-pty/src/win/conpty.cc`:

- pseudo-console закрывает только `PtyKill` (`:534`): `ClosePseudoConsole(handle->hpc)`
  (`:554-559`) — и только если запись о ней найдена (`:547`, `:549`).
- Когда оболочка вышла, поток ожидания убирает запись: `assert(remove_pty_baton(baton->id))`
  (`:105-106`). После этого `kill()` закрывать нечего. Вызов стоит внутри `assert`. В
  prebuild `win32-x64` текст этого assert есть (в UTF-16), значит вызов собран.
- Ссылку, которая держит conhost, отпускает `ConptyReleasePseudoConsole`. Он зовётся только при
  `useConptyDll` (`:431-437`); по умолчанию опция выключена (`lib/windowsPtyAgent.js:31`). worfy её
  не передаёт (`src/main/terminal/pty.ts:415`, main `f9c005b`; сверить после PR #239).

PR #239 чинит закрытие самим worfy (закрыт Terminal Node): `pty.kill()` идёт при живой оболочке,
рабочий поток node-pty и conhost освобождаются. Для оболочки, которая вышла сама, PR #239
освобождает поток, но не conhost. Этот Ticket — только про второй случай.

## Что делаем

- (а) **Новая версия node-pty**, которая закрывает pseudo-console при выходе оболочки. Есть ли
  такая, по `node_modules` не определить: там только 1.1.0 (`package.json:33`), changelog в пакете
  нет — проверить в upstream (microsoft/node-pty). Цена: на macOS и Linux `scripts/postinstall.mjs`
  пересобирает node-pty под Electron (`:25`); на Windows он ничего не делает (`:22`) — берётся
  готовый `prebuilds/win32-x64` (`:7`), сборка из исходников там падает (`:8-9`). Новый prebuild
  должен грузиться в Electron 44.5.1: проверить на ПК. В packaged-сборке node-pty лежит вне
  app.asar (`electron-builder.yml:42-43`).
- (б) **`useConptyDll: true`** при `win32`. node-pty грузит `conpty\conpty.dll` рядом с
  `conpty.node` (`conpty.cc:181`) вместо системной. Оба файла в пакете есть:
  `prebuilds/win32-x64/conpty/conpty.dll` и `OpenConsole.exe`. В typings опция помечена
  `(EXPERIMENTAL)` (`typings/node-pty.d.ts:99-104`); с ней `kill()` идёт другой веткой
  (`lib/windowsPtyAgent.js:153-159`) и зовёт `TerminateProcess` оболочки (`conpty.cc:562-563`).
- (в) Свой native-вызов — только если (а) и (б) не подошли. Способ выбирает исполнитель; выбор и
  причина — в «Итог».

- **Остатки ревью PR #239** (Ticket 10, все low; тот же файл и те же test-ы):
  - `src/main/terminal/pty.ts:710`: половина `ended &&` в условии `if (ended && terminal.closing)`
    не закреплена. Ни один test не печатает ничего между `close()` и выходом оболочки.
  - `src/main/projects/settings.ts:35`: запись настроек через мягкую схему проходит все test-ы.
  - gate предупреждает: `test/contract/terminal.test.ts` вырос до 1418 строк при пороге 1000.
    Вынести случаи Windows на настоящем pty в отдельный файл.

### Выбранный способ

**Вариант (б): на Windows оболочка стартует с консолью из пакета node-pty** (`useConptyDll: true`) — `conpty.dll` и `OpenConsole.exe` рядом с `conpty.node`. Такую консоль node-pty отпускает сразу после старта оболочки (`ConptyReleasePseudoConsole`), поэтому её хост уходит вместе с оболочкой.

- **Почему не (а).** Стабильной версии node-pty новее 1.1.0 нет: в npm только `1.2.0-beta.15`. В исходниках upstream (ветка `main`, `src/win/conpty.cc` и `src/windowsPtyAgent.ts`) логика та же: поток ожидания по-прежнему убирает запись о pseudo-console при выходе оболочки и не закрывает её. Это прочитано через пересказ страницы, сам код upstream не запускался.
- **Почему не (в).** (б) подошёл.
- **Вызов `spawn` на macOS и Linux не меняется:** опция добавляется только при `process.platform === 'win32'`.

### Что сделано

1. **`src/main/terminal/pty.ts`, `spawnShellPty`** — так реестр запускает оболочку: на Windows с `useConptyDll: true`.
2. **Там же, `stopOutputWorker`.** С консолью из пакета `kill()` в node-pty останавливает поток, читающий вывод консоли, только когда после него приходит вывод. Когда оболочки уже нет, вывода не будет, и поток остаётся до выхода из worfy — по одному на каждый Terminal (третья и четвёртая строки таблицы). Реестр останавливает этот поток сам, сразу после `kill()`: и при закрытии Terminal Node, и после выхода оболочки. Это второе место, где worfy трогает внутренности node-pty (первое — `withoutConsoleHelper` из Ticket-а 10). Если у pty такого потока нет, в лог идёт одна строка, закрытие идёт дальше.
3. **Test-ы на настоящем pty** запускают оболочку так же, как приложение (`spawnShellPty`), а не голым node-pty.

### Побочный эффект: консоль из пакета задаёт терминалу вопрос

- **Что видно.** При старте оболочки `OpenConsole.exe` шлёт терминалу `ESC[1t ESC[c ESC[?1004h ESC[?9001h`. `ESC[c` — запрос «что ты за терминал» (DA1). Пока ответа нет, вывод оболочки не идёт около трёх секунд. Системная консоль такого запроса не шлёт.
- **Замер** (`probe-t22-da1.out`, Windows PowerShell, по два запуска):

| Консоль | Ответ на `ESC[c` | Приглашение через |
|---|---|---|
| системная | не нужен | 297–318 ms |
| из пакета | нет | 3275–3283 ms |
| из пакета | сразу (`ESC[?1;2c`, как отвечает xterm.js) | 274–276 ms |

- **В приложении отвечает xterm.js** Terminal Node: его ответ уходит в оболочку как ввод. Проверено на packaged-сборке (ниже): приглашение через 374–397 ms.
- **Ответ, пришедший поздно** (через 4 s после приглашения — так будет, когда новый экран получает сохранённый вывод с этим запросом внутри): в строке приглашения лишних символов нет, следующая команда выполняется как обычно.
- **Test-ы.** У harness-а test-ов терминала нет: каждая оболочка стартовала на три секунды позже, и в полном прогоне случай с Git Bash вышел за свои 5 s. Harness теперь отвечает на запрос сам, один раз на оболочку, как xterm.js. Два файла test-ов Terminal вместе идут 39 s.
- **Чего worfy не делает:** main сам на запрос не отвечает. Если оболочка стартует, а экрана с xterm.js нет, приглашение придёт на три секунды позже. Сейчас такого пути в приложении нет: оболочку открывает только экран.
