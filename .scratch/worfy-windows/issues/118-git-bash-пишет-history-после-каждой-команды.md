Source: решение владельца Q10, 2026-10-31 («со всем согласен»); остаток тикета 116 (#1148): под нагрузкой 2 из 120
закрытий Git Bash без `.bash_history`, потому что `kill.exe` не всегда успевает доставить SIGHUP. Платформенный: делает
Session на ПК, проверяет и вливает Mac (ADR-0056).

## Что происходит

Bash дописывает `.bash_history` только при выходе: по `exit` или по SIGHUP. worfy закрывает Terminal Git Bash на Windows через
`kill.exe` (src/main/terminal/windows-pty.ts). На занятой машине сигнал иногда не доходит до bash в отведённые 1500 ms, и
команды этой Session теряются.

## Что делаем

В окружении Terminal-а Git Bash, который запускает worfy, задаём `PROMPT_COMMAND`, который выполняет `history -a`. Тогда bash
дописывает каждую команду в файл сразу после неё, и закрытию сигнал для history больше не нужен.

- Только Git Bash на Windows. macOS, Linux, WSL, PowerShell и cmd не трогаем.
- Если в окружении уже есть `PROMPT_COMMAND`, `history -a` дописывается к нему, а не заменяет его.
- Если `.bashrc` пользователя сам переопределяет `PROMPT_COMMAND`, наш не действует. Это ожидаемо, и worfy с этим не борется.
- Закрытие через `kill.exe` остаётся как есть. `exit` и SIGHUP по-прежнему пишут history.

Цена, известная владельцу: при двух открытых Terminal-ах строки в `.bash_history` перемежаются. History внутри каждой
Session от этого не меняется.

## Итог

Git Bash, запущенный worfy на Windows, получает `PROMPT_COMMAND` с `history -a` (`gitBashEnv`, `src/main/terminal/pty.ts`).
Заданный в окружении `PROMPT_COMMAND` сохраняется: `history -a` идёт после него с новой строки, потому что `;` сломал бы
значение, которое кончается на `;` или на комментарий.

Точная строка: `[ -z "${HISTFILE-}" ] || history -a 2>/dev/null`. Голый `history -a` нашло ревью: с пустым `HISTFILE` или с
папкой, которой нет, он печатал ошибку после каждой команды, а после `unset HISTFILE` писал в существующий `~/.history`. Замер ниже
сделан с голым `history -a`; условие не меняет случай, который мерили (`HISTFILE` задан), повторный замер не делался.

**Замер ПК, 2026-10-31, локальный коммит `be634b08` (до rebase, тот же код):** 120 закрытий Git Bash и 120 PowerShell подряд,
под полным vitest на 8 workers. CPU здесь считан только по строкам Git Bash, поэтому в левой колонке не 71 / 99 % из тикета 116:
там считаны все 240 строк.

| | до тикета, с #1148 | с `history -a` |
| --- | --- | --- |
| нет `.bash_history` | 2 из 120 | **0 из 120** (обе команды в файле в 120 из 120) |
| CPU, медиана / максимум | 69 / 95 % | 96 / 100 % |
| `terminal.close`, медиана / p95 / максимум | 2457 / 3721 / 4933 ms | 1359 / 1623 / 2051 ms |
| helper, медиана / p95 / максимум | 2378 / 3650 / 4855 ms | 1294 / 1547 / 1975 ms |
| `kill.exe` ещё работал в конце ожидания | 2 | 0 |

**Как это читать.** В этом замере сигнал дошёл до bash во всех 120 закрытиях, поэтому сам замер не показывает случай, когда
сигнал опоздал: 0 из 120 здесь не доказывает, что `history -a` спас хотя бы одно закрытие. Это показывает contract test
`a command is in .bash_history before the close`: команда в файле, пока bash работает, до любого сигнала; без вызова
`gitBashEnv` в `pty.ts` он красный. Сам сигнал проверяет соседний test: он снимает `PROMPT_COMMAND`, убеждается, что файла с
командами до закрытия нет, и ждёт их после закрытия. Почему закрытия стали быстрее при большей загрузке CPU, не установлено: 2 из 120 и 0 из 120 — не сравнение
при равных условиях. В это же время на ПК шли и небольшие test-ы другой работы.

**Проверено на настоящем Git Bash 5.2.26:** `$?` команды доходит до следующей (`(exit 7)`, затем `status-7`), при `exit` строки не
задваиваются. После `unset HISTFILE` команда не попадает в файл, даже в существующий `~/.history`.

**Остаётся.**
- Команда, после которой bash не успел показать приглашение, пишется только по сигналу: `history -a` идёт перед приглашением.
- Команда, которую `.bashrc` дописывает к `PROMPT_COMMAND` после нашей, читает `$?` нашей, а не последней команды пользователя.
  Сохранить его можно только `(exit $s)`, это лишний процесс на каждое приглашение; описано в `docs/features/terminal.md`.
- Значение из окружения с `\` в конце склеивается с нашей строкой, и `history -a` не выполняется.
- Цена, известная владельцу: при двух открытых Terminal-ах строки в `.bash_history` перемежаются.
