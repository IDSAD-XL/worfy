# 26 — Test-ы на Windows оставляют папки в `%TEMP%` и падают: `afterEach` удаляет через `rmSync`

Type: task
Status: open
Blocked by: 23
Source: замеры Session на Windows-ПК 2026-10-12, переданы Session на Mac сообщениями; все числа ниже — её

## Что происходит

- **`afterEach` чистит временную папку через `fs.rmSync` с `recursive`.** Под Node 24.21.0 из
  Electron 44.5.1 на Windows этот вызов бросает EPERM на файле «только для чтения». Такие файлы —
  объекты git: test создаёт во временной папке репозиторий. Причина та же, что в Ticket-е 23
  (общая функция удаления для `src/main` и `scripts/`). Test-ы вынесены из Ticket-а 23 сюда: его PR
  уже большой, а правка `afterEach` — механическая и проверяется отдельно.
- **Следствие первое: test падает.** Из 681 падения `pnpm test` на Windows у 153 в причинах есть
  этот EPERM, у 68 — только он. По файлам: `harness-migrate` 54, `projects` 24, `docs` 22,
  `projects-connect` 21, `clients` 10, `shell` 10, `harness-drift` 9, `build-version` 2,
  `canvas-tools` 1.
- **Следствие второе: папка остаётся.** Один полный `pnpm test` оставляет около 250 папок `worfy-*`
  в `%TEMP%`. За 2026-10-09 — 2026-10-12 на ПК владельца их набралось 9510 (`worfy-migrate` 2268,
  `worfy-canvas` 1134, `worfy-docs` 959, `worfy-projects` 946 и мельче); объём не замерен.
- **Что уже сделано в PR Ticket-а 23:** в двух файлах `afterEach` зовёт новую функцию удаления.
  `harness-migrate`: 54 падения → 25; `build-version`: 2 → 0. Папок после прогона: 253 → 248.
- **Сколько всего мест.** На main `81930f0` в `test/` — 158 вызовов `rmSync` в 57 файлах (grep).
  Какие из них удаляют папку с репозиторием git, не разбиралось.

- **macOS тоже оставляет папки, по другой причине** (ревью PR #257 на Mac, 2026-10-13).
  `test/contract/canvas-tools.test.ts` после каждого зелёного прогона оставляет 11 папок
  `worfy-canvas-*`: `afterEach` папку удаляет, а более поздняя запись Layout создаёт её снова. Так же
  на main (`canvas-tools.test.ts:97-100`). Во временной папке Mac владельца — 57 487 записей
  `worfy-*`, из них 30 743 `worfy-canvas-*` (счёт агента ревью через `readdir`; `ls` с шаблоном там
  уже не работает: «argument list too long»).
- **`ShellIntegration.prepare()` на Windows при каждом вызове создаёт новую папку,** а `disposeSync`
  убирает только последнюю (проба Session на Windows-ПК под Node 24.21.0: 2 папки, затем 3, после
  `disposeSync` осталось 2). zsh на Windows не запускается, так что эти папки там не нужны вовсе.
- **Связанное наблюдение, причина не доказана** (Mac владельца, 2026-10-13). После дня прогонов
  служба macOS `fseventsd`, которая рассылает уведомления об изменении файлов, перестала успевать за
  набором test-ов: во время `pnpm test` она держит 102–116 % CPU, уведомление приходит с задержкой
  до 2,5 s, и test-ы наблюдателей (`docs.test.ts`, `claude-home-registry.test.ts`) падают — `gate
  full` красный и на main. Память службы — 4,2 ГБ, растёт на каждом прогоне. Влияют ли на это
  оставленные папки, не замерено. Запись — в `HANDOFF.md`, «Риски и долги».

## Что делаем

1. **Один helper удаления для test-ов** — обёртка над общей функцией Ticket-а 23 — в папке, которую
   видят и `test/unit`, и `test/contract`. Имя и место выбирает исполнитель; в «Итог» — почему.
2. **Семь файлов из списка падений** переходят на helper: `test/contract/projects.test.ts`,
   `docs.test.ts`, `projects-connect.test.ts`, `clients.test.ts`, `shell.test.ts`,
   `harness-drift.test.ts`, `canvas-tools.test.ts`.
3. **Остальные файлы с рекурсивным `rmSync` в `test/` — тоже все.** Под Node 24 из Electron на Windows (системный Node 24.21.0 так себя не ведёт — замер в «Итог» Ticket-а 23) тот же
   вызов ещё и проходит через junction, и test-ы с junction сейчас обходят это руками (мнение
   Session на Windows-ПК, принято). Замер: число папок `worfy-*` в `%TEMP%` до и после одного
   полного `pnpm test`. Цель — 0 новых папок. Числа — в «Итог».
4. **`canvas-tools.test.ts` на любой системе:** после `afterEach` папка не появляется снова — дождаться
   отложенной записи Layout или остановить её до удаления.
5. **`ShellIntegration.prepare()` на Windows** не создаёт папку, которая там не нужна, либо
   `disposeSync` убирает все созданные. Выбор — в «Итог».
6. **Test против возврата** — по образцу запрета `rmSync` в `src/main` из Ticket-а 23: красный, если
   рекурсивный `rmSync` снова появился в `test/`.

## Риски

- **Helper зависит от кода приложения.** Ошибка в общей функции удаления станет ошибкой чистки во
  всех test-ах сразу. Её собственные test-ы — в Ticket-е 23.
- **Часть папок может оставаться по другой причине** (процесс ещё держит файл). Тогда цель «0 новых
  папок» не достигается одной заменой; остаток — списком в «Итог».
