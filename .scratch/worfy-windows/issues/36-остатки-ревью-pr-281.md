  - Причина: правку `HANDOFF.md` (`:128-131`) доставляют чтения после старта watch — через 100, 400 и
    1000 ms (`SETTLE_READS_MS`, `watch.ts:173`). Без единого события она дошла через 417 ms.
  - Вторая потеря корня не проверена ни на одной системе: мутант «`lost()` зовёт только первая
    потеря» проходит так же. Полный путь после возврата test шлёт только в закрытый watch (`:134`).
  - Сделать: послать полный путь через `model.made[1]`; ждать закрытый watch, вторую строку в логе и
    третий watch после возврата. На ПК: второе удаление корня в test-е Windows — тот ждёт 1200 ms
    до последней правки (`test/contract/docs-watch-root.test.ts:57`), но удаление в нём одно.
- **«Медленный опрос остаётся» — без test-а** (`test/unit/limits-watch-gone.test.ts:58`).
  - Запущено на Mac. Мутант «потеря папки останавливает и опрос» (`src/main/agent/limits.ts:176-177`:
    вместо двух строк — `this.stop()`) проходит все test-ы Limits: 39 прошло, 1 пропущен, exit code 0.
  - Test двигает часы на 200 ms (`:68`) и после потери ничего не читает; test Windows — тоже, по
    чтению. Код верен: в пробном test-е ревью опрос читает файл, записанный после потери.
  - Сделать: после потери записать файл status line, сдвинуть часы на 1100 ms, ждать ещё одно
    чтение. Второй случай: папку данных удалили и создали заново.

### 2. После `error` watch документов только пишет в лог (старше PR)

- **Что сейчас.** Обработчик ошибки — один `console.error` (`src/main/docs/watch.ts:278`); так было и
  до PR. Прочитано в исходниках Node 24.21.0 из Electron 44.5.1: при ошибке `FSWatcher` сначала
  закрывает свой handle, потом шлёт `error`. Watch после этого мёртв на любой системе.
- **Запущено на Mac:** настоящий `DocsWatcher`, настоящая папка, ошибка подана через callback самого
  handle. Код PR и main дают одно и то же: одна строка в логе; за 3,5 s после следующей записи
  подписчик не получил ничего. Документы не читаются, пока Project не откроют заново.
- **Сделать.** Если handle ещё текущий: строка в лог с самой ошибкой, дальше как в `lost()` — закрыть,
  перечитать, ждать корень. Так делает `src/main/link-safe-watch.ts:301-305`. Мутант ревью с такой
  правкой возвращает наблюдение на настоящей папке macOS. Test на подменном watch: `fail()` → новый watch.
- **Замер на ПК.** Когда Windows даёт `error` вместо событий с полным путём, не запускалось. Нужен
  рекурсивный `fs.watch` папки на томе, который можно отнять (USB-накопитель или share самого ПК):
  отнять том, 3 s считать события и ждать `error`, вернуть том, записать `HANDOFF.md`. Share
  создаётся только с разрешения владельца в чате Session на ПК.

### 3. Замечания low: код и test-ы

- **`catch` вокруг нового watch считает любую ошибку «корень снова пропал»** (`watch.ts:311-314`).
  Запущено на подменном watch с отказом `EMFILE`: 13 отказов за 300 ms при retry 20 ms, в логе пусто,
  документы «пропавшие», хотя `HANDOFF.md` на диске. Сделать: писать ошибку один раз, если её код не
  `ENOENT` и не `ENOTDIR`; просить чтение, когда корень — папка.
- **Корень `/` на macOS** получает имена событий полным путём (`watch.ts:274-275`). Запущено: за 7 s
  код PR сделал 3 вызова `fs.watch` и 3 строки в логе; main — 1 вызов, 0 строк. Настоящий Project
  таким корнем не бывает. Сделать: один `stat` перед `lost()` — либо поправить комментарий на `:274`.
- **Правило «имя — полный путь» и seam для watch записаны в трёх файлах** без общего helper-а:
  `link-safe-watch.ts:298`, `:465`; `docs/watch.ts:265`, `:275`; `agent/limits.ts:164`, `:175`.
- **Проверка зависит от времени** (`docs-watch-root-gone.test.ts:106-108`): пауза 50 ms, затем
  «взглядов больше одного». С подставленной задержкой worker-а в 45 ms падает 10 раз из 10; в 45
  настоящих прогонах не падала. Сделать: `await until(…)` на второй взгляд, потом — что watch один.
- **Значения по умолчанию идут только в test-ах Windows.** На Mac проходят четыре мутанта: правило
  полного пути — `() => false` (`watch.ts:265`, `limits.ts:164`); проверка корня «всегда да»
  (`watch.ts:302`); пауза в 100 раз длиннее (`watch.ts:316`). Сделать: unit-test без подменённого правила, имя события — корень.
- **Названия говорят больше, чем проверяют.** `limits-watch-gone.test.ts:58` — «на первом событии», а
  `closed` проверен после 50 событий (`:62-63`): мутант «закрыть на 50-м» проходит.
  `docs-watch-root-gone.test.ts:210` — «каждые две секунды», тело сверяет константу (`:211`).
