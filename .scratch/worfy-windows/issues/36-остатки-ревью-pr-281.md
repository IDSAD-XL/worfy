### 2. После `error` watch документов только пишет в лог (старше PR)

- **Что сейчас.** Обработчик ошибки — один `console.error` (`src/main/docs/watch.ts:278`); так было и
  до PR. Прочитано в исходниках Node 24.21.0 из Electron 44.5.1: при ошибке `FSWatcher` сначала
  закрывает свой handle, потом шлёт `error`. Watch после этого мёртв на любой системе.
- **Запущено на Mac:** настоящий `DocsWatcher`, настоящая папка, ошибка подана через callback самого
  handle. Код PR и main дают одно и то же: одна строка в логе; за 3,5 s после следующей записи
  подписчик не получил ничего. Документы не читаются, пока Project не откроют заново.
- **Сделать.** Если handle ещё текущий: строка в лог с самой ошибкой, дальше как в `lost()` — закрыть,
  перечитать, ждать корень. Так делает `src/main/link-safe-watch.ts:301-305`. Мутант ревью с такой
  правкой возвращает наблюдение на настоящей папке macOS. Test на подменном watch: `fail()` → новый watch.
- **Замер на ПК.** Когда Windows даёт `error` вместо событий с полным путём, не запускалось. Нужен
  рекурсивный `fs.watch` папки на томе, который можно отнять (USB-накопитель или share самого ПК):
  отнять том, 3 s считать события и ждать `error`, вернуть том, записать `HANDOFF.md`. Share
  создаётся только с разрешения владельца в чате Session на ПК.
