## Что делаем

### 1. Разбор запроса консоли: два края и формы запроса

- **Запрос разрезан на два куска, между ними больше 50 ms** (`pty.ts:844`, `HELD_OUTPUT_MS`). Через 50 ms придержанное начало уходит на экраны как текст (`sendHeld`, `:824-829`). Остаток реестр запросом уже не считает. Модель на Mac: подменный pty печатает `one ESC[`, через 80 ms — `ctwo`. main не ответил, ответил xterm.js экрана. В сохранённом выводе остался целый запрос, и второй экран ответил ещё раз. Это дефект первого круга, только по времени.
- **Запрос стоит внутри начала другого** (`src/main/terminal/console-request.ts:48`). Замена идёт одним проходом. Запущено на Mac: кусок `ESC[ESC[cc` даёт текст `ESC[c` — запрос остаётся в выводе. Куски `ESC[ESC[c` и `c` дают два ответа и теряют букву `c`.
- **Формы запроса, на которые xterm.js отвечает, а реестр их не узнаёт** (`console-request.ts:31`): `ESC[00c`, `ESC[;c`, `ESC[0;0c` и запрос с CSI одним символом U+009B. Модель на Mac: на такой запрос отвечает каждый экран, и ещё раз — при показе сохранённого вывода. Так было и до правки второго круга.
- **Насколько узко.** Сама консоль так не пишет: её стартовый запрос — одна строка (прочитано в `OpenConsole.exe` 1.23). Запрос программы может разрезаться только на границе чтения внутри большого вывода.
- **Сделать.** Разбор по символам с состоянием вместо «замена, потом проверка конца куска»; помнить, что отданный по timer-у конец был началом запроса. Либо запись «не делаем, причина» в «Итоге». В обоих случаях поправить комментарий «no xterm.js ever sees it» (`console-request.ts:14-15`).

В лог ничего не идёт; timer (`:853-864`) срабатывает каждые 500 ms, пока жив Terminal. Модель на Mac: pty без `_agent` и pty, у которого `exitCode` — строка: выход не сообщён, предупреждений 0. Слушатель ошибки входного сокета тоже пропускается молча (`:391-392`). Два других обращения пишут в лог.
- **Вне Windows закреплено одно поле из четырёх.** Test `test/contract/terminal.test.ts:939-947` грузит `node-pty/lib/windowsPtyAgent.js` на любой системе и проверяет `_getConsoleProcessList`. Не закреплены: `_conoutSocketWorker` и `ConoutConnection.prototype.dispose`; getter-ы `exitCode` (`lib/windowsPtyAgent.js:196-206`) и `inSocket` (`:93-97`). Переименование `_conoutSocketWorker` или `exitCode` в новой версии node-pty увидит только test на настоящей оболочке (`test/contract/terminal-windows.test.ts:206` и `:190`), а он идёт только на ПК. Переименование `inSocket` не увидит ни один test: подменный pty в `test/unit/terminal-console.test.ts:23-32` сам даёт `_agent.inSocket`.
- **Два файла пакета не проверены.** Без `prebuilds/win32-x64/conpty/conpty.dll` старт pty на Windows бросает «Cannot find conpty.dll» (прочитано, `src/win/conpty.cc:182-186`); рядом лежит `OpenConsole.exe`. На Mac оба файла в пакете есть. Test-а на это нет.
- **`release()` выходит до `kill()` и до остановки потока, когда нет `_getConsoleProcessList`** (`pty.ts:1036`) — для оболочки, которая вышла сама. На консоли из пакета `kill()` этот метод не зовёт (прочитано, `lib/windowsPtyAgent.js:137-160`), и остановка потока от него не зависит. На 1.1.0 безвредно.
- **Мелкие пробелы unit-test-ов** — мутанты второго круга, которые прошли все test-ы на Mac:
  - опции `exitPollMs` и `exitGraceMs` (`pty.ts:544-547`, `:594-595`) не читает ни test, ни код приложения;
  - условия `spawnShellPty` для pty без `_agent` и без `on` (`:391-392`): у подменного pty есть оба (`test/unit/terminal-console.test.ts:32`);

- **Сделать.** Расширить test `terminal.test.ts:939` тремя полями и двумя файлами. Строка в лог при старте на `win32`, когда у `_agent` нет `exitCode`. Звать `stopOutputWorker` до раннего выхода из `release()`. Две опции убрать или прочитать в test-е. По остальным мутантам — test или «не делаем, причина».

### 3. `applySize` ловит любую ошибку `resize`

- **Что сейчас** (`pty.ts:709-716`). `try/catch` стоит на всех системах и не смотрит ни на текст ошибки, ни на систему. Строка в лог идёт при каждой попытке. Задуман был один случай: на Windows node-pty отказывает в `resize` для pty, чья оболочка вышла (`lib/windowsPtyAgent.js:120-122`).
- **Модель на Mac.** На `win32` и на `darwin` ошибка «Cannot resize a pty that has already exited» и придуманная «ioctl(2) failed, EBADF» дают одно и то же: исключения нет, одно предупреждение. На JavaScript node-pty для Windows один `resize` и одна клавиша между «код известен» и «выход сообщён» дают два предупреждения: `write` зовёт `touch()`, а тот пробует тот же размер ещё раз.
- **Сделать одно из двух.** Ловить только на `win32` или только этот текст. Либо оставить и дописать комментарий: любая ошибка `resize` пишется в лог и не бросается, на всех системах. В обоих случаях писать в лог один раз на Terminal.

### 7. Тексты

- **Комментарии `pty.ts`, которые расходятся с кодом или с node-pty:**
  - `:821-822`, «output never waits for more than HELD_OUTPUT_MS». Запущено на Mac: `x ESC`, через 49 ms `[`, ещё через 49 ms `0` — придержанный ESC дошёл до экрана через 148 ms;
  - `:411-412`, «knows the exit code half a second after the shell is gone». node-pty знает код сразу (прочитано, `src/win/conpty.cc:101-108`); полсекунды — шаг чтения;
  - `:413` и `:63`, «as node-pty does on the console of the system» и «after node-pty knew the exit code». node-pty отсчитывает секунду от последнего вывода (`lib/windowsPtyAgent.js:224-238`). Реестр отсчитывает её от чтения, которое нашло код: это 1,0–1,5 s после выхода;
  - `:522`, «node-pty's exit event calls it, once». `finish` зовут ещё чтение кода (`:862`) и граница закрытия (`:972`);

  - `:967-968`, «reports the exit a second after the last output of the console». Так на консоли системы, не на консоли из пакета;
  - `:370`, «next to conpty.node». Оба файла лежат в папке `conpty` рядом с ним (`conpty.cc:181`).
