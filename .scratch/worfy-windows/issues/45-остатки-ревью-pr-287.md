### 1. Test первого `rmdir` на настоящих папках — после слова владельца

- **Пункт начинается со слова владельца в чате Session на Windows-ПК.** Правило безопасности Ticket-а 35 (его

  Поэтому замер 2 первого круга ревью не сделан; вопрос владельцу задан.
- **Что сейчас.** На настоящей файловой системе первый `rmdir` проверен только вручную, на ПК, внутри тома
  для замера: шаг 4в замера Ticket-а 35 (под обоими Node, до и после правки первого круга) и замер 5
  (junction по GUID на папку того же тома в трёх состояниях). Все test-ы правила идут на модели
  (`test/unit/remove-tree.test.ts:328-468`; с PR #293 ещё один test обхода Windows на модели —
  `test/unit/remove-tree-mounted.test.ts:259-274`, на записи модели для точки монтирования macOS). На чистом
  runner-е Windows (ручной job «Windows tests» в GitHub Actions) test-а с настоящим junction по GUID нет.
- **Что предлагает ревью:** junction по GUID на папку **того же** тома. `dev` у него тот же, что у соседних
  папок. Проверка тома поэтому ничего не даёт, и от перечисления защищает только первый `rmdir`. Повышение
  прав, вероятно, не нужно; это не измерено.
  1. Через `mkdtemp` под `%TEMP%` создать папку `D`, в ней `D\outside\notes.txt` и `D\tree\sub\own.txt`.
  2. Узнать GUID-путь тома, на котором лежит `%TEMP%`: `mountvol C:\ /L` (если `%TEMP%` на другом диске —
     корень того диска).
  3. Создать junction командой cmd:
     `mklink /J "D\tree\sub\linked" "\\?\Volume{GUID}\<путь D без буквы диска>\outside"`. Цель — папка,
     которую test только что создал. Корень тома целью не бывает никогда.
  4. `removeTree(D\tree)`. Ожидание: папки `D\tree` нет, `D\outside\notes.txt` на месте.
- **Если владелец разрешил — сначала замер, потом test.** Замер на ПК под системным Node и под Node из
  Electron: exit code `mklink` и нужно ли повышение прав; что отвечают `lstat` (папка или ссылка; `dev` против
  `dev` папки `D\tree\sub`), `readlink`, `readdir`; итог `removeTree` с head. Потом — test только для `win32`
  в блоке test-ов на настоящих папках (`:42-312`), рядом с test-ом обычного junction (`:110-118`): то же
  дерево, та же проверка `outsideIsWhole` (`:87-91`). Так чистый runner Windows проверяет первый `rmdir` на
  настоящей файловой системе, а не только на модели.
- **Если владелец не разрешил или `mklink` требует повышения прав** — записать это в «Итог»; test не пишется.

  `lstat` точки монтирования (папка ли; `dev` против `dev` папки-родителя), `readlink`, один `rmdirSync`,
  `removeTree` папки, в которой она лежит; на месте ли файлы-метки. Что решает: если `rmdirSync` проходит,
  первый `rmdir` защищает и такой том. Если он отвечает `ENOTEMPTY`, путь, данный `removeTree`, защищает
  только проверка тома. Размонтирует владелец: `mountvol <папка> /D`.

## Риски

- **Пункт 1 создаёт junction по GUID на диске с данными владельца** (поэтому нужно его слово — пункт 1).
  Цель junction — папка, которую test создал сам. При ошибке в пути цели junction поведёт в другую папку или в корень тома, и код без первого `rmdir`
  удалит файлы там. Поэтому: путь цели строится от `realpathSync.native` папки `D`; до `removeTree` test
  кладёт в `D\outside` файл-метку со случайным содержимым, читает её через junction и при несовпадении
  останавливается; junction записывается в список `links` (`test/unit/remove-tree.test.ts:50-53`), чтобы
  `afterEach` (`:72-86`) снял его как ссылку до удаления папки test-а; копия обхода с main и мутант «первого
  `rmdir` нет» на настоящих папках не запускаются без отдельного слова владельца.
- **Пункт 1 на чистом runner-е не измерен.** Неизвестно, даёт ли runner `mklink /J` и `mountvol … /L` без
  повышения прав. `%TEMP%` там — путь с коротким именем 8.3 (`C:\Users\RUNNER~1\…`, Ticket 14); цель junction
  с таким именем не проверялась.
- **Замеры 6 и 7 пункта 2 требуют тома для замера и повышения прав владельца.** Правило безопасности Ticket-а
  35 (его раздел о замере) действует целиком: том создаёт и подключает владелец, GUID тома называет он;
  Session сверяет GUID с томом VHD перед `mklink` и перед каждым шагом, который удаляет. В замере Ticket-а
  35 она сверяла метку тома, его размер и файл диска.
- **Пункт 3 меняет код удаления в четырёх местах.** Три копии — один текст между метками; test
  `test/unit/remove-tree.test.ts:827-831` сверяет их и запрещает в тексте backquote: копия `restore.ts` лежит
  в template-строке. `statSync` через
  `RemoveFs` меняет интерфейс и модель. Модель PR #293 (Ticket 44, его пункт 2) уже изменил и вынес в
