# 84 — Test-ы с настоящим Terminal на Windows пишут в профиль владельца

Type: task
Status: open
Blocked by: —
Source: ревью PR #710 (Terminal e2e на Windows), Session на Mac, 2026-10-21. Правило владельца: test-ы
никогда не трогают настоящие файлы владельца.

Приоритет — выше оставшихся косметических групп e2e тикета 14: каждый прогон test-ов на ПК дописывает
строки в настоящую историю владельца.

## Что происходит

На Windows shell Terminal-а получает от worfy переменные сеанса из его процесса — `USERPROFILE`,
`APPDATA`, `LOCALAPPDATA` (`WINDOWS_SESSION_VARS`, `src/main/agent/env.ts`); `SHELL` и `HOME` там
ничего не решают. Test запускает worfy с окружением владельца, поэтому shell Terminal-а в test-е —
shell в профиле владельца:

- PowerShell читает `$PROFILE` владельца: `pwsh` — по `USERPROFILE`/`Documents`, Windows PowerShell 5.1 —
  по известным папкам (known folders) профиля;
- PSReadLine дописывает каждую набранную test-ом команду в настоящую историю владельца
  (`ConsoleHost_history.txt` под `%APPDATA%\Microsoft\Windows\PowerShell\PSReadLine`);
- Git Bash берёт `HOME` из `USERPROFILE` и читает rc-файлы владельца (`.bashrc`, `.bash_profile`).

Это не только e2e. Contract test-ы, которые запускают настоящий shell Terminal-а через
`test/contract/terminal-harness.ts` (`terminal.test.ts`, `terminal-screen.test.ts`,
`terminal-windows.test.ts`), набирают команды в тот же PowerShell с тем же профилем. На 2026-10-21 в
истории владельца — около 30 строк из прогонов e2e и около 30 строк из прогонов contract test-ов
Terminal-а.

Terminal-ы запускают 12 файлов e2e:

- `test/e2e/first-run.spec.ts`
- `test/e2e/focus-sidebar.spec.ts`
- `test/e2e/focus.spec.ts`
- `test/e2e/linked-machines.spec.ts`
- `test/e2e/linked-read-only.spec.ts`
- `test/e2e/palette-find.spec.ts`
- `test/e2e/terminal-ai-helpers.ts` (общий код spec-ов `terminal-ai-*`)
- `test/e2e/terminal-ai-history.spec.ts`
- `test/e2e/terminal-ai-settings.spec.ts`
- `test/e2e/terminal.spec.ts`
- `test/e2e/wheel-over-nodes.spec.ts`
- `test/e2e/zoom-whole-nodes.spec.ts`

Что уже сделал PR #710 (только test-ы, три spec-а): `windowsProfileEnv(dir)` в
`test/e2e/terminal-shell.ts` даёт приложению `USERPROFILE`, `APPDATA`, `LOCALAPPDATA` во временной
папке test-а (на других системах — пустой объект). Ими запускаются `terminal.spec.ts`, `focus.spec.ts`
(test Terminal-а в focus mode) и `wheel-over-nodes.spec.ts`. Проба на ПК: Windows PowerShell 5.1 с
таким окружением видит `$PROFILE` пустым, а `(Get-PSReadLineOption).HistorySavePath` — под временной
`APPDATA`; `pwsh` берёт оба из временной папки; `HOME` Git Bash — временная папка. Свои папки worfy
не двигаются: их задают `WORFY_DATA_DIR` и `WORFY_CLAUDE_HOME`. Остальные 9 файлов из списка и
contract test-ы этим PR не тронуты.

## Что делаем

Один из двух путей (выбор — за тем, кто возьмёт тикет; оба закрывают и e2e, и contract test-ы):

1. **worfy под переменной окружения только для test-ов** (например, `WORFY_TERMINAL_NO_PROFILE=1`)
   запускает PowerShell с `-NoProfile` и без истории PSReadLine (`-HistorySaveStyle SaveNothing` при
   старте), а Git Bash — без rc-файлов и без `HISTFILE`. Переменную ставят `launchEnv`/`directStartEnv`
   (`test/e2e/launch-env.ts`) и `terminal-harness.ts`; в продукте она не стоит никогда.
2. **Перенаправление профиля для всех**: `windowsProfileEnv` (или его аналог) ставится в общем окружении
   запуска — `isolation` в `test/e2e/launch-env.ts` — для всех 12 файлов e2e, и тем же способом в
   `terminal-harness.ts` для contract test-ов.

В обоих случаях — contract или unit test, который закрепляет правило: shell Terminal-а в test-е не
получает `USERPROFILE`/`APPDATA`/`LOCALAPPDATA` владельца (или стартует с `-NoProfile` и без истории).
