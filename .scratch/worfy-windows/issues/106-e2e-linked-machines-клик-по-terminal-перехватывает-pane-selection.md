## Что происходит

`test/e2e/linked-machines.spec.ts:757` («A opens a Project of B: its Canvas, Node moves, Session, Terminal and
Autopilot go to B; B gone — "unreachable", B back — the Canvas again») на Windows-ПК красный:

```
TimeoutError: locator.click: Timeout 30000ms exceeded.
  - <div class="react-flow__pane selection">…</div> intercepts pointer events
```

Падает клик по экрану Terminal в окне A (`termA.getByTestId('terminal-screen').click()`, `:818`): pane React Flow
стоит в режиме выделения (класс `selection`) и перехватывает каждый повтор клика. На снимке после падения узел
Terminal почти целиком за правым краем окна — Canvas сдвинулся уже во время попыток.

Замеры на ПК:
- до 14:00 test зелёный 4 раза подряд (ветка `worfy-windows/99`, прогоны после правки);
- с 14:07 красный: на ветке `worfy-windows/99` 2 из 2, на main `14f008a4` 2 из 2, на ветке
  `worfy-windows/105-helpers` (поверх main `1e1027f2`) 2 из 2;
- окно не урезано: содержимое 1400×900 (`SIZE`, `:581`) на основном дисплее, `scaleFactor` 1.5;
- настоящий курсор во время прогона стоял внутри окон теста: `screen.getCursorScreenPoint()` = (1798, 424),
  то есть (1151, 77) в окне — полоса инструментов над Canvas.

Вероятная причина, не подтверждена: перед кликом test перетаскивает Node синтетической мышью Playwright
(`drag`, `:674`; вызов на `:801`). Windows отдаёт окну под курсором и события физической мыши; вместе они
оставляют pane в режиме выделения. Это объясняет, почему test стал красным после 14:00, когда владелец вернулся
к ПК. На Mac test зелёный.

## Что делаем

1. Проверить гипотезу: прогнать test, когда физический курсор вне окон теста. Курсор двигает владелец или
   test, но не агент руками. Если красный и так — искать причину в самом test-е.
2. Если причина в курсоре — сделать test независимым от него: например, перед прогоном уводить курсор
   из окна средствами test-а (на Windows) или открывать окна теста там, где курсора нет. Решение — в «Итог».

## Итог

**Курсор в окне для падения не нужен.** Прогон `:756` с `--repeat-each 3`, пока физический курсор все три
повтора стоял на другом мониторе (DISPLAY3, точка 4363,1346 до и после; окна теста — на основном): 1 passed,
2 failed с тем же текстом (`element is not stable`, затем `react-flow__pane selection intercepts pointer events`).
Что курсор совсем не влияет, этот замер не доказывает.

**Причина — камера после новой Session.** Перед кликом по Terminal test создаёт Session (`sidebar-new-session`).
`SessionNodes.tsx:68` плавно (250 мс) ставит камеру по центру новой Session. Замер (временный код в spec, в коммит
не вошёл), три повтора, окно 1400×900:

- сразу перед кликом камера ещё едет: `scale` 0.462 / 0.477 / 0.478, сдвиг меняется;
- через 1 с камера стоит: `translate(475px, 69px) scale(0.5)` во всех трёх; экран Terminal начинается с x = 1365
  при ширине окна 1400, его центр (куда кликает Playwright) — за правым краем.

Дальше — вывод, не замер. Playwright, вероятно, прокручивает к Terminal контейнер Canvas (`overflow: hidden`),
Canvas сдвигается, и клик ловит pane. Чем это кончается, по замеру не предсказать: в одном из трёх повторов клик
прошёл, хотя камера к тому моменту уже стояла так же.

Не объяснено: почему до 14:00 test был зелёным 4 раза из 4, а с 14:07 — красным 6 раз из 6, и почему на Mac он
зелёный при тех же `SIZE` и `setCenter`.

**Правка (только test).** Шаг с Terminal перенесён до шага с Session: пока камера стоит там, где её открывает
Layout. Перед кликом — `toBeInViewport({ ratio: 1 })` на экране Terminal, чтобы при новом сдвиге камеры test падал
с понятной причиной, а не на клике. Код продукта не меняли: камера к новой Session — задуманное поведение.

**Проверки на ПК**, ветка `worfy-windows/106` поверх main `a371f5fe`, Windows 11, масштаб 150 %:

  время — не проверено.
