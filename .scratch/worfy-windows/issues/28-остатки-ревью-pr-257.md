## Что делаем

### 1. `install-stable` на Windows: пять ожиданий на всю копию

- **Что сейчас.** Скрипт `pnpm install:stable` удаляет старую копию своей копией функции
  `removeTree`. У неё один запас в пять ожиданий на весь вызов (`scripts/install-stable.mjs:321`,
  `:365-366`, `:418`). На main было пять попыток на каждую запись.
- **Пример.** Шесть файлов заняты на одну попытку каждый. Сейчас скрипт уберёт пять и оставит
  шестой. Main убирал все шесть.
- **Последствие.** Установка всё равно проходит. Остаток убирает следующий запуск.
- **Почему запас общий.** Он нужен приложению: там ожидание блокирует main process. Скрипт — команда
  в терминале, ему это ограничение не нужно.
- **Что сделать — одно из двух:**
  - скрипт повторяет весь вызов удаления ещё раз, если первый оставил записи;
  - или этот случай записан рядом с ценой запаса в шапке копии, и больше ничего не меняется.

### 2. Запас ожиданий — второй параметр функции

- **Что сейчас.** Три копии (`scripts/remove-tree.mjs:22`, тот же текст в `restore.ts` и
  `install-stable.mjs`) принимают запас ожиданий вторым параметром той же функции, которую зовут
  снаружи.
- **Чем плохо.** `paths.forEach(removeTree)` передаст вторым параметром номер записи. Первый же
  ответ «занято» бросит `TypeError` вместо настоящей ошибки.
- **Сегодня ошибки нет:** все пять мест вызова передают один аргумент.
- **Что сделать.** Внешняя функция принимает только путь; запас живёт во внутренней.

### 3. Test, который запрещает `rmSync` (`test/unit/no-rmsync.test.ts`)

Test ищет в коде рекурсивное удаление в обход `removeTree`. Он пропускает:

- `rmSync as <имя>` в импорте файла, у которого есть копия (`:40-66`);
- `rmdirSync(dir, options)`, когда параметры лежат в переменной;
- два вызова `rmdirSync` на одной строке и закрывающую скобку внутри строкового аргумента — прежний
  поиск их находил; окно поиска — 8 строк (`:114-120`);
- вторую пару меток копии `// <remove-tree>` в одном из трёх файлов: текст между ними не ищется и не
  сверяется с модулем;
- `rm` из `node:fs/promises` — test не покрывает его по своей же шапке. Так удаляет
  `harness/install.ts`.

**Что из этого пункта уже закрыто в PR Ticket-а 26:** ни одна из форм выше. Там исправлена другая ошибка того же поиска, которой в этом списке не было: вызов `rmdirSync` с `recursive`, начавшийся на следующей строке, засчитывался и строкам перед ним (до семи). Теперь вызов ищется только от строки, где он начался; test на это есть. Тот же поиск в PR Ticket-а 26 читает и `test/` — для `rmSync` с `recursive`.
