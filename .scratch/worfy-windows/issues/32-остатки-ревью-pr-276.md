## Что делаем

### 1. Проверка «папка наша» без test-а (medium, старше PR)

- **Что сейчас.** `ownFolder` (`src/main/terminal/shell-integration.ts:104-114`) вне Windows сверяет владельца и биты доступа папки (`:109-110`). Ответ `prepare()` идёт прямо в `ZDOTDIR` zsh (`src/main/terminal/pty.ts:664-668`), а `.zshrc` исполняет каждый `rc.d/*.zsh` этой папки.
- **Пробел.** Два мутанта проходят все три test-файла модуля на Mac: проверка системы на `:108` перевёрнута (тогда macOS берёт любую папку, которая не ссылка) и строка `:110` заменена на `true`.
- **Что сделать.** Test вне Windows: после первого `prepare()` сделать папке `chmod 0o755`; следующий `prepare()` отвечает другой папкой и ничего не пишет в первую.

### 2. `saveLayoutNow()` дописывает только последний store

- **Что сейчас.** Helper берёт store из модулей в момент вызова (`test/remove.ts:27-30`). Три test-а `test/contract/trash.test.ts` меняют Layout и зовут `start()` ещё раз (`:310`, `:327`, `:346`); `start()` сбрасывает модули (`:50`). У первого store остаётся timer, и его запись создаёт папку заново.
- **Почему не видно.** Процесс test-файла завершается раньше, чем сработает timer. Если держать процесс живым ещё 700 ms, ветка оставляет 4 папки: 3 от `trash.test.ts` и 1 от `test/contract/projects-hold.test.ts`, где изменение Layout приходит уже после `saveLayoutNow()`. Main в тех же условиях оставляет 101.
- **Что сделать:**
  - в `start()` у `trash.test.ts` и `layout-store.test.ts` дописывать store, который test держит, до `vi.resetModules()`;
  - в `projects-hold.test.ts` дождаться, пока обработчики ответят, до `saveLayoutNow()`;
  - в комментарии `test/remove.ts:24-25` сказать «store последнего старта».

### 3. Запрет `rmSync` с `recursive` обходится по привычке

- **Не ловит** (`test/unit/no-rmsync.test.ts:87`): опции в константе; `import { rmSync as rm }`; `rmdirSync` с `recursive`; `rm` из `node:fs/promises`; второй вызов в одной строке; опции на восьмой строке после вызова.
- **Ложно срабатывает** на вызове внутри строки и в комментарии в конце строки.
- **Что сделать.** Ловить `rmdirSync` и async `rm` с `recursive`; читать каждый `rmSync(` строки; считать нарушением вызов, у которого второй аргумент — не литерал объекта.

### 4. Новые test-ы `ShellIntegration` работают в `/tmp`

- **`test/unit/shell-integration-rename.test.ts:37`.** Префикс `worfy-si-rename-` даёт путь в 79 байт — на один больше, чем допускает `tempBase`. Папка `ShellIntegration` поэтому создаётся в `/tmp`, вне папки, которую удаляет `afterEach` (`:42-44`). Упавшая проверка оставляет её там: под двумя мутантами остались `/tmp/worfy-XXXXXX`.
- **`test/unit/shell-integration-dispose.test.ts:52-89`.** Два новых test-а зависят от длины временной папки: за 62 байтами оба создают папку в общей `/tmp`, а первый ещё и сверяет её список (`:55`, `:57`).
- **Что сделать.** Короткий префикс; `disposeSync` в `afterEach`; в обоих файлах проверять `tempBase(scratch) === scratch`.

### 5. Сторона Windows у новых test-ов идёт только на Windows

- **Что сейчас.** Система берётся как есть (`const WINDOWS`, `shell-integration-rename.test.ts:13`); test «десять попыток» идёт под `it.runIf(WINDOWS)` (`:64`), первый test ветвится через `if (WINDOWS)` (`:50`). На Mac и в Linux CI выживают 16 мутантов строк, которые работают только на win32.
- **Что сделать.** Подменять `process.platform` на время `prepare()` и возвращать до удаления; добавить в test «не повторяется» второй код, например ENOENT. Пробный test с подменой убивает все 16 на Mac.

### 6. Комментарии и тексты

- **На Windows приложение не доходит до изменённых веток.** `terminalShell()` отвечает там только Git Bash или PowerShell (`src/main/terminal/pty.ts:182-196`), `prepare()` не вызывается. Сказать это в комментарии `ownFolder`. В Ticket-е 26 к строке «если пользователь Windows запускает zsh, папка ему нужна» дописать, что worfy на Windows сейчас zsh не запускает; текст PR #276 называл это «редко».
- `shell-integration.ts:183-184`: комментарий устарел для win32 — папку под этим именем там берут, кто бы её ни создал; не берут только ссылку.
- `shell-integration-dispose.test.ts:61`: «вызовы делят одну запись» — код повторяет `rename`, ничего не делит.
- `test/remove.ts:5-6`: «ни один test не зовёт `rmSync` с `recursive`» — `test/unit/glob-probe.tsx` зовёт, он в исключениях.
- **«Итог» Ticket-а 26:**
  - `saveLayoutNow` вызывается в шести файлах, а не в пяти (`projects-hold.test.ts:115`);
  - у test-а helper-а нет контрольного случая «без записи папка возвращается», хотя текст PR говорит, что он это закрепляет (само утверждение верно — проба на Mac);
  - папку `worfy-e3-sandbox-test` из 62 папок первого шага не объясняет ни один следующий шаг.
