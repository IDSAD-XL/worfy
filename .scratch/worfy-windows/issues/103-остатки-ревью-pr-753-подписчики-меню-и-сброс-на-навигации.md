## Что происходит

1. **Вызов `menu.ready` у трёх подписчиков ничем, кроме e2e, не закреплён.** Подписчики команд меню:
   - `src/renderer/settings/settings-window.ts:51` (`settings`);
   - `src/renderer/shell/sidebar-visibility.ts:77` (`toggleSidebar`);
   - `src/renderer/shortcuts/shortcuts-window.ts:50` (`shortcuts`).

   Каждый зовёт `followMenuCommand` (`src/renderer/menu-command.ts:13`), который подписывается на
   `menu.command` и потом вызывает `menu.ready`. Мутант, который возвращает один из них к простой подписке без
   `menu.ready`, проходит все unit- и contract-test-ы. Краснеет только e2e, и только когда клик успевает раньше
   монтирования.

2. **Проверка preload bridge есть только у Sidebar.** `followSidebarCommand` (`sidebar-visibility.ts:76`)
   возвращает пустую отписку, когда `globalThis.worfy` нет. `followMenuCommands` окна Settings и подписчик
   Shortcuts такой проверки не делают. Без bridge `followMenuCommand` показывает toast ошибки подписки
   (`showSubscribeError`). Их комментарии («without the preload bridge … it subscribes to nothing»,
   `settings-window.ts:48`, `shortcuts-window.ts:46-47`) неверны. Комментарий самого `followMenuCommand`
   (`menu-command.ts:11`) говорит то же, а проверки в нём нет.

## Что делаем

1. Unit-test оболочки: для каждой из трёх команд bridge получает `invoke('menu.ready', <command>)` после
   подписки. Мутант «простая подписка» у любого из трёх — красный.
2. Проверку bridge переносим в `followMenuCommand`: без `globalThis.worfy` — пустая отписка, без toast.
   Проверку в `followSidebarCommand` убираем, комментарии трёх подписчиков приводим к коду.
