## Что происходит

- К claim Ticket-ы 01–07, 09 и 10 влиты: лестница Run-а и `main-red`, `turn-hung`, пометка тишины Session и Subagent-а с
  Interrupt и Restart, call log Harness в форме записи, документы.
- Это первый Epic, который целиком прошёл с Code stories: после merge последнего PR с кодом `land` собирает story
  Epic-а, и toast её предлагает. Приёмка Ticket-а worfy-code-stories 17 идёт на этой story.
- Аналитики нет. Мерило — Run history и слова владельца. Замер `loop-log` — отдельный Ticket 12: этот Ticket его не
  ждёт.

## Что делаем

1. Orchestrator проходит пункты «Готово, когда» spec-а с доказательствами: CI каждого PR, имена test-ов из файлов на
   main, Fault scenarios, e2e.
2. Orchestrator обновляет Stable до main с Ticket-ами 01–07, 09, 10 (с согласия владельца) и проверяет, что hook-и Harness
   одобрены в Codex `/hooks` на каждой Machine.
3. Владелец:
   - запускает Run на ночь над очередью из двух и больше Epic-ов; утром смотрит Run history: был ли застрявший Ticket,
     дошёл ли Run до следующего Epic-а, понятна ли причина в тосте;
   - днём один раз видит `busy · quiet N min` (живой случай или ход fake agent-а по сценарию Orchestrator-а), жмёт
     Interrupt или Restart;
   - открывает story Epic-а из toast-а (приёмка worfy-code-stories 17).
4. В «Итог» — цена implementer-а и доля шага story по Wave-ам этого Epic-а (решение 2026-11-17, Q5).
