# Code story — worfy-stuck-agents 06: UI тишины хода: chip `busy · quiet N min`, Interrupt и Restart на hint line

Kind: pr · Epic: worfy-stuck-agents · Ticket: 06 · PR: - · Language: ru

## 1. Что было не так

После Ticket-а 03 main уже шлёт событие `quiet` с `quietSince`, когда ход Session 10 минут идёт без признаков жизни, но
renderer его никак не показывал: chip Session говорил просто `busy`, а событие ложилось в лог Session как строка
транскрипта, которую никто не рисовал. Restart с тем же разговором (`restartProcess`) был, но его звали только
MCP-действия; у человека не было кнопки, чтобы перезапустить замолчавший ход.

- Требование: [Что происходит](../issues/06-ui-тишины-хода.md#что-происходит)

## 2. Restart как публичный метод Session

Code: `src/main/agent/session.ts:868-876` · key lines: 870, 871, 872, 873

```ts
  async restart(): Promise<RestartAnswer> {
    this.assertOpen()
    if (this.launch.unattended) throw new Error('An unattended Session is not restarted by hand: its run decides')
    if (this.halted) throw new Error('This Session was stopped: a Restart would start a second process on its conversation')
    if (this.liveTaskList.length > 0) return { restarted: false, reason: restartWouldEndTasks(this.liveTaskList.length) }
    if (await this.restartProcess()) return { restarted: true, reason: null }
    // A task started while the turn was ending kept the process: the turn stays interrupted, as after an Interrupt.
    return { restarted: false, reason: restartWouldEndTasks(this.liveTaskList.length) }
  }
```

- Что делает: закрытая, unattended и остановленная (`halted`) Session — ошибка, ничего не меняется. Живые background
  tasks — ответ `restarted: false` с тем же текстом, что у MCP Restart (`restartWouldEndTasks`), ход не прерывается.
  Иначе — `restartProcess`: ход прерван, старый процесс закрыт, новый ждёт его выхода (ADR-0064) и продолжает тот же
  разговор. Если task началась, пока ход кончался, `restartProcess` вернёт `false` — ответ тот же, с причиной.
- Почему здесь: Ticket просит публичный метод Session, который зовёт `restartProcess`, с отказами как у `restartFor`
  ([Что делаем, п. 4](../issues/06-ui-тишины-хода.md#что-делаем)); `restartProcess` приватный и живёт в этом классе.
- Без него: Restart с hint line пришлось бы делать через `mcpAction('restart')`, который требует MCP-сервер и флаг
  `restarts` драйвера.
- Требование: [Что делаем, п. 4](../issues/06-ui-тишины-хода.md#что-делаем), [Решено без владельца, 8](../spec.md#решено-без-владельца)
- Риски и пробелы test-ов: флаг драйвера `parts.mcp.restarts` здесь не проверяется — Restart идёт для любого Vendor-а,
  и Codex через этот путь в test-ах не проверен (contract test-ы — только Claude Code на fake agent). Отказ `halted`
  отдельным test-ом не покрыт.

## 3. Хранилище renderer-а держит `quietSince`, а не строку транскрипта

Code: `src/renderer/session/store.ts:167-168` · key lines: 168

```ts
      case 'quiet':
        return { ...log, quietSince: event.quietSince }
```

- Что делает: событие `quiet` больше не добавляется в события транскрипта; лог Session держит последнее `quietSince`.
  Событие `state` с состоянием не `busy` сбрасывает его в `null` (строка 188), как main сбрасывает тишину в
  `turnWatch`; `loadControls` берёт `quietSince` из `agent.controls`, если событие не приходило (окно открылось позже).
- Почему здесь: в этом файле так же хранятся `queue`, `settings`, `context` и `mcp` — события, которые не часть
  транскрипта; файла нет в списке Ticket-а, почему хранилище, а не отдельный модуль, не записано.
- Без него: chip и пункт hint line не знали бы, что ход тих; окно, открытое после события, не узнало бы о тишине.
- Требование: [Что делаем, п. 1–2](../issues/06-ui-тишины-хода.md#что-делаем)
- Риски и пробелы test-ов: сброс по `state` повторяет правило main, а не читает его; разойдутся — пункт может
  остаться или исчезнуть раньше main. Тишина Session на Linked machine считается по `quietSince` её main, а минуты —
  по часам окна; расхождение часов сдвигает N, test-а нет.

## 4. Chip: `busy · quiet N min`

Code: `src/renderer/session/format.ts:21-24` · key lines: 23

```ts
export function stateChip(state: SessionState, quietMinutes: number | null): { status: Status; label: string } {
  const chip = STATE_CHIPS[state]
  return state === 'busy' && quietMinutes !== null ? { ...chip, label: `${chip.label} · quiet ${quietMinutes} min` } : chip
}
```

- Что делает: к `busy` дописывает `· quiet N min`, любое другое состояние оставляет как есть; цвет chip-а тот же
  (`working`). Минуты считает `useQuietMinutes` в `store.ts`: целые минуты от `quietSince`, с часами, которые идут раз
  в секунду, пока ход тих. Chip рисует новый `SessionStateChip.tsx` в шапке Session view.
- Почему здесь: Ticket называет `src/renderer/session/format.ts`, где лежит `STATE_CHIPS`
  ([Что делаем, п. 1](../issues/06-ui-тишины-хода.md#что-делаем)). Порог здесь не проверяется: main шлёт `quietSince`
  только после своей пометки, так что e2e с порогом в 2 с видит пометку так же, как приложение с 10 минутами.
- Без него: человек видит `busy` и не отличает работающий ход от замолчавшего.
- Требование: [Что делаем, п. 1](../issues/06-ui-тишины-хода.md#что-делаем)
- Риски и пробелы test-ов: chip показан только в шапке Session view; Orchestrator Node и Session Node на Canvas
  по-прежнему пишут `busy`.

## 5. Пункт hint line и его кнопки

Code: `src/renderer/session/composer/QuietTurn.tsx:36-43` · key lines: 39, 41, 42

```tsx
    if (acting || readOnlyNow() !== null) return
    setActing(true)
    setReason(null)
    void invoke(channel, { sessionId }).then((result) => {
      setActing(false)
      if (!result.ok) setReason(`${channel === 'agent.restart' ? 'Restart' : 'Interrupt'} did not go through: ${readableReason(failureReason(channel, result.error))}`)
      else if ('reason' in result.value) setReason(result.value.reason)
    })
```

- Что делает: Interrupt зовёт `agent.interrupt`, Restart — новый канал `agent.restart` (`src/shared/ipc/agent.ts`,
  обработчик в `src/main/ipc/agent.ts`). Отказ main или причина «живые background tasks» встаёт в строку вместо текста
  `No sign of life for N min: …`. Пункт виден, только пока хранилище держит `quietSince`; ключ `since` сбрасывает
  причину на новой тишине. На read-only экране кнопки ничего не шлют.
- Почему здесь: Ticket называет новый файл `composer/QuietTurn.tsx` по образцу `ContinueCountdown.tsx`
  ([Что делаем, п. 2–4](../issues/06-ui-тишины-хода.md#что-делаем)). Пункт берёт классы `.w-continue` того образца:
  обратный отсчёт Auto-continue виден между ходами, этот пункт — только в ходе, и вместе они не встают.
- Без него: Restart с тем же разговором был бы доступен только из popover-а MCP-серверов.
- Требование: [Что делаем, п. 2–4](../issues/06-ui-тишины-хода.md#что-делаем)
- Риски и пробелы test-ов: канал `agent.restart` — write-канал (`test/unit/link-access.test.ts`): Linked machine с
  доступом только на чтение его не зовёт. Что пункт и обратный отсчёт не встают вместе, test-ом не проверено.

## 6. Порог для e2e

Code: `src/main/agent/app-registry.ts:42-47` · key lines: 44, 46

```ts
export function quietMarkSeam(env: NodeJS.ProcessEnv, packaged: boolean): Partial<QuietWatch> {
  const given = env.WORFY_QUIET_MARK_MS
  if (packaged || given === undefined || !/^[1-9]\d*$/u.test(given)) return {}
  const markMs = Number(given)
  return { markMs, lookMs: Math.min(markMs, QUIET_LOOK_MS) }
}
```

- Что делает: в непакованной сборке `WORFY_QUIET_MARK_MS` ставит порог пометки и частоту взгляда main; без переменной
  и в собранном `.app` — порог приложения (10 минут, раз в минуту).
- Почему здесь: Ticket разрешает задать порог переменной окружения, как делают другие e2e
  ([Что делаем, п. 6](../issues/06-ui-тишины-хода.md#что-делаем)); так устроен `WORFY_CONTINUE_PAUSE_MS` в
  `app-orchestrators.ts`. Файла нет в списке Ticket-а: реестр Session-ов приложения создаётся только здесь.
- Без него: e2e ждал бы 10 минут тишины.
- Требование: [Что делаем, п. 6](../issues/06-ui-тишины-хода.md#что-делаем)
- Риски и пробелы test-ов: unit test-а у `quietMarkSeam` нет; его проверяет только e2e `test/e2e/quiet-turn.spec.ts`,
  который локально не запускался — его гоняет CI.

## 7. Что сознательно не меняли

Строку в `scripts/e2e-specs.table.json` не добавили: `QuietTurn.tsx` и хранилище рисуются в каждом Session view, их
видят и другие e2e, а правило таблицы — добавлять путь, только если его видят одни свои spec-файлы. Автоматического
Interrupt или Restart нет (ADR-0050). Orchestrator Node и Session Node на Canvas пометку не показывают.

## 8. Как проверено

`pnpm lint`, `pnpm typecheck`, `pnpm test` и gate fast — коды выхода в отчёте implementer-а и в Evidence-строках
Ticket-а. Новые test-ы: `test/unit/quiet-turn.test.tsx`, `test/unit/session-state-chip.test.tsx`, раздел
`agent.restart` в `test/contract/agent-session.test.ts`; e2e `test/e2e/quiet-turn.spec.ts` — только typecheck, его
гоняет CI. Снимок chip-а `busy · quiet 1 min` и hint line в «Итог» Ticket-а снят отдельным скриптом на собранном
приложении с fake agent-ом, не этим e2e.

## Проверить себя

1. Почему пункт hint line пропадает, когда ход ждёт ответа на запрос разрешения, хотя main в этот момент ещё не прислал
   `quiet` null?
   - Ответ: хранилище само сбрасывает `quietSince` на любом событии `state`, кроме `busy`, — так же, как main в
     `turnWatch`.
   - Строки: `src/renderer/session/store.ts:188-188`
2. Что ответит Restart, если background task стартовала, пока прерывался ход?
   - Ответ: `restartProcess` вернёт `false`, процесс останется, и Restart ответит причиной `restartWouldEndTasks`; ход
     при этом уже прерван.
   - Строки: `src/main/agent/session.ts:873-875`
3. Почему chip не сравнивает `quietSince` с `QUIET_MARK_MS`?
   - Ответ: main присылает `quietSince` только после своей пометки; порог живёт в main, и e2e может его сдвинуть.
   - Строки: `src/renderer/session/format.ts:21-24`, `src/main/agent/app-registry.ts:42-47`
