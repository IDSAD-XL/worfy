## Что происходит

- Живая шкала (Ticket 17, `src/main/flight-recorder/service.ts`) пересчитывает открытый live Run каждые 5 с, если
  Journal или прочитанный транскрипт выросли. Строки транскриптов дочитываются с места остановки (`TailLines`,
  `readNewLines` из `src/main/claude-home/tail.ts`) и хранятся сжатыми (`TranscriptCompactor`,
  `src/main/flight-recorder/transcripts.ts`).
- Но факты транскрипта (`transcriptFacts` в `src/shared/flight-recorder/from-transcript.ts`) строятся из всех строк
  файла: каждый шаг заново разбирает все сжатые строки Orchestrator-а и всех Subagent-ов Run, а `agentIdsIn` ещё раз
  проходит весь транскрипт.
- Замер ревьюера round 2 #1198 на реальной Session (транскрипт 164 MB, 111 Subagent-ов, окно Run 12 ч, main process,
  Mac): шаг пересчёта — 200–370 ms, медиана 319 ms, раз в 5 с, пока открыт live Run; только транскрипт
  Orchestrator-а — 197–261 ms. Сжатие при первом открытии — 0,5–1,6 с. Синтетические числа «Итог» Ticket-а 17 (шаг
  115 ms, открытие 280 ms) ниже реальных: синтетический файл сжимается лучше. Цель — реальные.
- Пока идёт шаг, main process занят: окна приложения не отвечают.

## Что делаем

1. В `from-transcript.ts` — разбор, который держит состояние: состояние и новые строки на входе → новые факты и
   состояние на выходе. Факты те же, что у разбора всех строк сразу, при любом разбиении строк на порции, в том числе
   когда между порциями появились Ticket-ы новой Wave или meta Subagent-а.
2. Сервис (`service.ts`) берёт этот разбор для пересчётов live Run: каждая строка транскрипта Orchestrator-а и
   Subagent-а разбирается один раз. Полный разбор остаётся для первого открытия, для законченного Run и после
   truncate или замены файла (`reset` из `tail.ts`).
3. Контракт фактов (`facts.ts`), модель (`spans.ts`, `summary.ts`) и другие readers (`from-*.ts`) не меняются.

Не входит: сжатие при первом открытии (0,5–1,6 с), стоимость модели (`buildTimeline`, `summarize`) на шаге.

- **Что зависит от Run, читается при запросе фактов.** Ticket-ы Run (новая Wave добавляет их), meta Subagent-а (файл

- **Reader.** `TranscriptParses` (src/main/flight-recorder/transcripts.ts:193) держит разбор каждого файла между

  раньше. Разбор файла, который чтение больше не смотрит, отпускается в конце чтения; `TailLines.clear` отпускает и
  разборы (service.ts:204).
- **Сервис.** `TailLines.parses` (service.ts:136) передаётся в `readRunTranscripts` для live Run (service.ts:475).
