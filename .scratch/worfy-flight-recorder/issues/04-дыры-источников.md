## Question

Каких событий модели spans нет ни в одном источнике, и кто их начнёт писать? Известные дыры: Journal не знает, какой Session или Subagent взял Ticket, когда открыт PR, какой был CI, verdict ревью и gate, когда merge; gate хранит только последний verdict на worktree; заголовок Ticket-а хранит только текущий статус. Для каждой дыры: пишет worfy (main видит транскрипты и GitHub) или Harness (агент знает момент сам), в какой источник, и не становится ли это новым хранилищем событий вопреки ADR-0002?

## Answer

Владелец 2026-11-01: «да, все верно» на Q1–Q8. Факты — разведка 2026-11-01 по коду на `a52c7d13`.

- Q1: сначала читаем после факта из источника, который уже хранит событие; в Journal пишем только то, чего не хранит никто (ADR-0002, ADR-0005). Поправка к карте: в ADR-0002 нет слов «нового хранилища событий» — там «worfy читает факт, а не копирует»; собственный файл Journal в data folder правилу не противоречит.
- Q2: какой агент взял Ticket, его начало и отчёт — из транскрипта Orchestrator-а (вызов `Agent` с именем `impl-NN` и описанием, `task-notification`) плюс правила Binding (`src/shared/binding/resolve.ts`); в Journal не пишем.
- Q3: PR, CI, verdict ревью, merge — из GitHub при открытии шкалы, как `scripts/critical-path.mjs`; ответ держится в памяти.
- Q4: единственная настоящая дыра — история статусов Ticket-а (файл хранит только текущий). Новое событие Journal `ticket-status` пишет worfy main, когда его наблюдатель за файлами Ticket-ов (`src/main/workflow/watch.ts`) видит смену статуса во время Run: claim, block с причиной и `Waits:`, done. Закрывает и Silent mode, и Ticket-ы без PR.
- Q5: gate не меняется; запуски берутся из его логов (`timings.json` на запуск, последние 10 на worktree, до 8 дней). Потери старых запусков — Ticket 08.
- Q6: ходы Orchestrator-а — из транскрипта.
- Q7: Limits, background tasks, waiting-until — из уже существующих событий Journal; `gate-queue` получает событие конца; ожидание другой Machine выводится из GitHub (метка PR и время отчёта); ожидание e2e lock в v1 остаётся частью span агента; ожидания человека внутри Run нет — Autopilot отклоняет диалоги, а нужда в человеке останавливает Run.
- Q8: Journal пишет только worfy main; Harness в Journal не пишет. Исключение observer-а (`human-input`) остаётся.
