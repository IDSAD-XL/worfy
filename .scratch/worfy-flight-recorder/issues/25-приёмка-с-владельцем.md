## Что происходит

- К claim Ticket-ы 10–24, 26 влиты, у каждого свои test-ы. В test-ах агенты — fake, Journal и транскрипты — fixture,
  `gh` — stand-in (соглашения spec-а); на живом ночном Run и на Windows-ПК шкалу никто не смотрел.
- На Windows пути другие: Journal — `%APPDATA%\worfy\autopilot\<run>.jsonl` (dev-сборка — `worfy-dev`), транскрипты —
  `%USERPROFILE%\.claude\projects\<projectDirName(root)>\`, логи gate —
  `%USERPROFILE%\.claude\worfy-harness\gate\state\logs\<tag>\<run>\timings.json`.
- На ПК Bash Session приложения Claude пишет `%APPDATA%` в приватную папку пакета: строка `human-input` observer-а из
  Git Bash не попадает в настоящий Journal. Это не меняется; приёмка это записывает.
- Приёмка — не в Autopilot: её ведёт владелец вместе с Orchestrator-ом.

## Что делаем

1. Mac Stable из `origin/main` с влитыми 10–24, 26, Harness обновлён из неё.
2. **Mac, ночной Run** — владелец проходит пункты «Готово, когда» Epic-а; Orchestrator ведёт записи и снимки в
   `.scratch/worfy-flight-recorder/evidence/25/`.
3. **Windows-ПК** — Run на ПК: Journal, транскрипты и логи gate находятся по путям Windows, шкала строится.
4. Найденный дефект — новый Ticket Epic-а, номер дописывается в `Blocked by` этого.
5. Отмечает пункты «Готово, когда» в `spec.md` со ссылкой на «Итог».

Не входит: новые функции.
