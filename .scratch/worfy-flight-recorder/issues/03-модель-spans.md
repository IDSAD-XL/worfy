## Question

Из каких видов span состоит шкала Run и как они вкладываются друг в друга? Кандидаты: Run, Wave, Ticket, Stage Ticket-а, Session и Subagent агента, CI run, запуск gate, ожидание (Limits, сон Machine, другая Machine, человек), круг доработки после REJECTED, повторный запуск implementer-а. Что отличает ожидание от блокировки и от повтора? Какие поля обязательны у каждого вида (начало, конец, исход, причина, ссылки на commit, PR, verdict)? Что делать со span без конца — Run оборвался, агент не отчитался?

## Answer

Владелец 2026-11-01: «со всем согласен» на Q1–Q10.

- Q1: шкала — дерево: Run → Wave (`wave-started`…`wave-finished`) → Ticket → Stage Ticket-а по Pipeline Project-а → работа внутри Stage (агент — Session или Subagent, CI run, запуск gate). Отдельная дорожка Run — Wait-ы уровня Run: Limits, сон Machine, другая Machine, человек, background tasks.
- Q2: Ticket, который шёл в нескольких Wave, — одна дорожка на весь Run: отрезки по Wave и видимый пробел между ними.
- Q3: Stage не хранится (ADR-0067); каждая граница Stage-span — событие источника (claim, PR открыт, CI начат и кончен, verdict-комментарий, merge). Нет события — нет границы (Ticket 08).
- Q4: span агента — один отрезок активной работы, от раздачи или SendMessage на доработку до отчёта, а не вся жизнь Session. Доработка — второй span того же агента под вторым Implementing.
- Q5: **Wait** — span, работа стоит по внешней причине с ожидаемым концом (Limits, сон Machine, другая Machine, человек, очередь — e2e lock или gate queue, background tasks), всегда с причиной. **Блокировка** — не span, а отметка на дорожке Ticket-а (`ticket block`, причина, `Waits:`); дальше дорожка серая до снятия или конца Run. **Повтор** — новый span того же вида с номером попытки и ссылкой на причину: круг доработки после REJECTED, узкий круг, перезапуск implementer-а после ошибки Session, повторный CI run.
- Q6: обязательные поля span: вид, начало, конец или «не закончен», исход (`ok`, `failed`, `rejected`, `blocked`, `stopped`, `cut-off`), причина (для Wait, повтора и неуспеха), ссылки (run, номер Wave, Ticket, session/agent id, PR, sha, verdict — какие есть у вида), источник начала и конца.
- Q7: span без конца (Run оборвался, агент не отчитался) кончается последним событием о нём в любом источнике, исход `cut-off`, на шкале рисуется с обрывом.
- Q8: у каждого span — собственное время (длительность минус вложенные spans), Wait-ы суммируются по причинам. Сверху шкалы итог: три самых долгих Stage по собственному времени и время Wait-ов по причинам.
- Q9: ходы Orchestrator-а — отдельная дорожка Run, связанная с Ticket-ами ссылками, а не вложенная в них.
- Q10: в `CONTEXT.md` заведены **Span** и **Wait**; блокировка остаётся пометкой; повтор — Span с номером попытки, отдельного термина нет.
