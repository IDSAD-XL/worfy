- Причина во всех записях — timeout под нагрузкой или зависание окна на runner-е, то есть flaky, а не стабильно сломанные
  test-ы. `worfy-polish/47` (flaky test-ы Windows в gate full) открыт, но ни одну из этих записей не называет.

Путь по умолчанию — без продления. Для каждой из 11 записей:

1. Починить или сделать устойчивым test (причина timeout-а, общий `beforeAll`, ожидание окна) и удалить запись.
2. Удалить test можно только по правилу владельца: test сопротивлялся починке (не меньше двух попыток или не меньше дня),
   то же поведение покрыто другим test-ом (назвать его в PR), и test не охраняет разрушительное действие (удаление файлов,
   kill процесса, замену копии). `harness-migrate-toolbar-offer` стоит рядом с переносом файлов Harness: перед удалением
   проверить, что перенос покрыт другим test-ом.
3. Запись, которая остаётся, переводится на новый открытый owner Ticket с новой `since` только с явного согласия
   владельца — «подтвердить». Без его слова этот путь не применяется.

Записи `worfy-windows 117` (Windows exception, до 2026-12-15) не трогаем. Лимит карантина — 15 записей, новых не добавляем.
По желанию, отдельным commit-ом: `test/unit/quarantine.test.ts` краснеет, если owner Ticket записи закрыт.
