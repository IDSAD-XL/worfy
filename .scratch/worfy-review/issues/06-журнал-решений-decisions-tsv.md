## Что происходит

- **После прогона без человека непонятно, почему решено так.** Autopilot (worfy сам запускает Wave и
  ведёт её без владельца) пишет журнал событий `<WORFY_DATA_DIR>/autopilot/<run>.jsonl`: Wave началась,
  кончилась, прогон остановлен. Почему Orchestrator вывел Ticket из Wave, дал узкий круг доработки
  или выбрал порядок merge, там нет. Это есть только в транскрипте Session — длинном и неудобном.
- **HANDOFF.md отвечает на другой вопрос.** Это файл состояния Project-а: что в работе, что ждёт
  владельца, следующий шаг. Он переписывается на границах фаз, а не на каждом решении
  (`harness/hooks/rules/orchestrator.md:140-147`).
- **Правило «не заводить второй файл состояния»** (`orchestrator.md:149-150`): два файла о том, где мы,
  — значит, один врёт. Журнал решений не говорит, где мы. Он говорит, почему и на каком
  доказательстве. Но без явной оговорки агент прочтёт правило как запрет.
- **В pstack** журнал — TSV с колонками время, фаза, решение, почему, ссылка на доказательство,
  результат. Строки только дописываются. В конце журнал сверяется с транскриптом: пропущенное
  решение — новая строка, старые строки не правятся.

## Что делаем

1. **Helper `harness/bin/decision-log`** на Node (ADR-0055: новые скрипты Harness — на Node):
   `decision-log <файл> <решение> <почему> [<доказательство>]`. Дописывает строку
   `время UTC ⇥ решение ⇥ почему ⇥ доказательство`. Табуляции и переводы строк в значениях заменяет
   пробелами. Создаёт файл с заголовком, если его нет. Только дописывает.
2. **Где лежит файл** — предложено: `~/.claude/worfy-harness/runs/<project>/<epic>-wave-<N>-<время
   старта>/decisions.tsv`. Это папка состояния машины, вне репозитория Project-а. Она переживает
   конец Session и работает в Silent mode. Сама папка — локальный git-репозиторий, но её `.gitignore`
   уже исключает всё в корне, кроме `projects/` и `gate/` (правило `/*`). Значит, `runs/` в историю не
   попадёт без правок.
3. **В epic-wave** (только для Session без человека — Autopilot):
   - в начале Wave — путь к файлу;
   - строка на каждое решение: Ticket выведен из Wave, узкий круг, порядок merge, Ticket пропущен,
     находка отклонена;
   - в разделе 5 (отчёт) — сверка: каждое решение из отчёта имеет строку; нет — дописать с пометкой
     `added at reconciliation`;
   - путь к журналу — строкой в отчёте Wave.

   Все новые строки epic-wave, и пометка тоже, — по-английски, как весь текст Harness (ADR-0044).
   `epic-wave-ship-ticket.test.sh` пропускает кириллицу в epic-wave только из списка `ALLOWED`
   (`:221-238`), а этот test Ticket не правит.
4. **Оговорка в `orchestrator.md`** рядом с правилом о втором файле состояния: журнал прогона — не
   файл состояния. HANDOFF говорит, где мы; журнал говорит, почему так решили в одном прогоне. Журнал
   не коммитится и не читается при возобновлении работы.

## Риски

- **Orchestrator забудет писать.** Сверка в конце ловит пропуски, но только те, что попали в отчёт.
- **Чувствительные данные в «почему».** Журнал вне репозитория, но в нём может оказаться текст
  находки с путями. Секреты в журнал не пишутся — то же правило, что для Profile.
- **Запрос разрешения в Session без человека.** Запись `decisions.tsv` в
  `~/.claude/worfy-harness/runs/` — запись внутрь `~/.claude`. Claude Code может спросить на неё
  разрешение, и Session без человека остановится. До выбора места проверить запись в Silent mode и в
  Autopilot; итог — в «Итог».
- **Открытый вопрос: где файл.** Папка состояния машины (предложено), scratchpad Session (пропадает с
  Session) или Workflow folder (в Full mode — это репозиторий, и журнал станет коммитом). Решает
  исполнитель, итог — в «Итог».
