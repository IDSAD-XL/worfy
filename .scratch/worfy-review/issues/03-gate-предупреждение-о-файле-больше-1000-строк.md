## Что происходит

- **В Thermos это правило живёт в prompt-е.** Если оно останется в prompt-е, модель тратит токены на
  подсчёт строк и может ошибиться. Подсчёт строк — детерминированная проверка, ей место в Gate.
- **Gate (`harness/hooks/gate.sh`) уже знает diff.** Он находит merge-base с базовой веткой
  (`:260-261`). Список изменённых файлов собирает функция `changed_paths` (`:283-290`): изменения
  worktree, индекса и всей ветки. Перед вердиктом Gate печатает служебную строку
  `[gate] scope (…)` (`:372-374`).
- **Gate не печатает предупреждений.** Выход — одна из строк вердикта (`зелено`, `красно`,
  `ничего не прогналось`, `ПРОВЕРИТЬ НЕ УДАЛОСЬ`) и код 0, 2 или 3. Файл вердикта `verdict-<tag>.json`
  читает worfy (Ticket 09 Epic-а worfy-harness, комментарий в начале `gate.sh`).
- **В репозитории уже есть длинные файлы.** Например, `test/unit/autopilot-run.test.ts` — 1645 строк,
  `pnpm-lock.yaml` — 7053. Правило касается только перехода через порог, а не уже длинных файлов.

## Что делаем

1. **Проверка в `gate.sh`** для `fast` и `full`. Для каждого файла из `changed_paths`:
   - строк на merge-base (`git show <mb>:<path>`; нового файла там нет — 0);
   - строк сейчас в worktree;
   - было ≤ 1000, стало > 1000 — строка
     `[gate] warning: file over 1000 lines: <path> (<было> → <стало>)`.
   Язык строки — английский, как у `[gate] scope`. Строка идёт до строки вердикта.
2. **Не блокирует.** Код выхода, строка вердикта и `verdict-<tag>.json` не меняются. Кэш зелёного
   результата не прячет предупреждение: проверка идёт до проверки кэша.
3. **Список исключений** в `gate.sh`:
   - lock-файлы (`pnpm-lock.yaml`, `package-lock.json`, `yarn.lock` и подобные);
   - сгенерированное: `*.min.js`, `*.map`, `*.snap`, папки `dist/`, `out/`, `build/`;
   - двоичные файлы (у `git diff --numstat` вместо чисел `-`);
   - удалённые файлы.
4. Без merge-base (Gate сам пишет, что база сомнительна) проверка пропускается молча.

## Риски

- **Порог 1000 произвольный** и одинаков для всех языков. Это предупреждение, а не запрет, — цена
  ошибки низкая.
- **Скорость.** `git show` на каждый изменённый файл. На diff-е из сотен файлов это заметно; если так —
  считать только файлы, где строк добавлено больше, чем удалено (`git diff --numstat`).
- **Gate переходит на Node.** [ADR-0055](../../../docs/adr/0055-harness-scripts-in-node.md)
  («Решение», пункт 1) переводит Gate на Node, а открытый Ticket
  [worfy-windows/03](../../worfy-windows/issues/03-gate-на-node.md) заменяет `harness/hooks/gate.sh` на
  `gate.mjs`. Если worfy-windows/03 в main раньше этого Ticket-а, проверка пишется в Node-версию Gate
  (`gate.mjs`), а test — на её вызов. Если этот Ticket в main раньше, worfy-windows/03 переносит
  проверку в `gate.mjs` вместе с test-ом `gate-file-size.test.sh`.
- **Открытый вопрос:** нужно ли, чтобы предупреждение видел агент в hook-е `TaskCompleted`. Сейчас hook
  смотрит только код выхода. Решает исполнитель, итог — в «Итог».

## Итог

Сделано в ветке `worfy-review/03`. Проверка написана в `harness/hooks/gate.sh`: `gate.mjs` в main ещё
нет (worfy-windows/03 не влит), его перенос проверки вместе с test-ом — за worfy-windows/03.

- **Что печатает Gate.** После строки `[gate] scope (…)` и до проверки кэша — по одной строке на файл:
  `[gate] warning: file over 1000 lines: <path> (<строк на merge-base> → <строк сейчас>)`. Для `fast` и
  `full`, в stdout, как строка scope. Функция `size_warnings`, порог — `FILE_LINES_MAX=1000`.
- **Не блокирует.** Код выхода, строка вердикта, `verdict-<tag>.json`, маркеры и кэш — те же, что без
  предупреждения: test сравнивает вывод, код и файл вердикта двух прогонов (с длинным файлом и без)
  на зелёном и на красном Gate. В `gate.sh` правка только добавляет строки, ни одна прежняя не изменена.
- **Исключения** (`size_exempt`): `*.lock`, `*-lock.json`, `*-lock.yaml`, `npm-shrinkwrap.json`, `go.sum`;
  `*.min.js`, `*.map`, `*.snap`; папки `dist/`, `out/`, `build/` на любой глубине; двоичные файлы
  (`git diff --no-index --numstat` печатает `-`, учитывает и `.gitattributes`); удалённые файлы и
  symlink-и. Без merge-base проверка молчит.
- **Счёт строк** — `awk 'END { print NR }'` под `LC_ALL=C`: последняя строка без перевода строки
  считается, как у git; `wc -l` её терял бы. `git` зовётся только для файла, в котором сейчас больше
  1000 строк, — остальные отсекаются одним подсчётом.
- **Скорость** (риск из Ticket-а): на временном репозитории с 400 изменёнными файлами Gate fast стал
  дольше на ~1 с (0,3–0,5 с → 1,3–1,4 с), это ~2,5 мс на файл. Отбор по `git diff --numstat` не
  понадобился.
- **Строка написана через `printf` в одинарных кавычках — намеренно.** `test/unit/gate-state.test.ts:97`
  берёт из исходника `gate.sh` каждое `"[gate] <слово>` в двойных кавычках за слово вердикта и
  исключает по имени только `scope`. С двойными кавычками test краснеет: слово `warning` не вердикт.
  Сам разбор вывода в worfy (`src/main/gate/state.ts:157`, `GATE_LINE`) строку warning не берёт.
  Долг: в том test-е исключать и `warning` — файл вне следа этого Ticket-а.

Решено без владельца, подтверждено владельцем 2026-10-12:

- **Агент в hook-е `TaskCompleted` предупреждение не видит** (открытый вопрос из «Рисков»). Hook
  передаёт модели только stderr при коде 2, а предупреждение идёт в stdout и код не меняет. Агент видит
  его при ручном прогоне `gate.sh fast` (шаг 6 skill-а `ship-ticket`), Orchestrator — в gate full перед
  мержем. Доставка через hook — отдельный Ticket, если предупреждение окажется полезным.
- **Переименование.** Ticket считает файл, которого нет на merge-base, новым (0 строк). Длинный файл,
  который только переименовали, тогда давал бы ложное предупреждение `(0 → 1200)`. Gate ищет прежний
  путь (`git diff -M --name-status`) и берёт число строк оттуда. Не найдено (переименование без
  `git mv` и без коммита, или файл сильно переписан) — файл считается новым.
- **Новая папка без `git add`.** `git status` называет такую папку целиком, без файлов. Для проверки
  размера Gate раскрывает её (`git ls-files --others --exclude-standard`); список для плана проверок
  (`changed_paths`) не тронут.
- **Lock-файлы «и подобные»** — список из первого пункта «Исключения»; сгенерированное — ровно список
  Ticket-а.

Шаг владельца: правка начнёт действовать в живом Gate после `pnpm install:stable` — до него Gate
Stable copy предупреждений не печатает.

Ограничение: путь, который git берёт в кавычки (двойная кавычка, обратная косая черта, табуляция в
имени), предупреждения не получает. `changed_paths` снимает кавычки, но не раскрывает escape-ы, и файл
по такому имени не находится — так было и до этого Ticket-а, план проверок читает тот же список. Пути
с кириллицей, пробелом, `-`, `[`, `*` считаются (кириллица и пробел — в test-е, остальные — вручную).

Не проверено: gate full на Mac после rebase и gate full на Windows-ПК (платформенный PR, ADR-0056) —
перед мержем; test под bash 5 и GNU-утилитами идёт только в CI на Linux.
