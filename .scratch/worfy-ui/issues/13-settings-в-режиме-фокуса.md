# 13 — «Settings…» открывается и в режиме фокуса: окно поверх, режим фокуса под ним остаётся

Type: task
Status: claimed — 2026-10-15
Blocked by: 10
Source: решение владельца 2026-10-10 по пункту «Решено без владельца» Ticket-а [02](02-окно-settings.md) («В режиме фокуса „Settings…“ не открывается»): владелец хочет, чтобы «Settings…» (⌘, / Ctrl+,) открывалось и в режиме фокуса — окно поверх, режим фокуса под ним сохраняется.

## Что происходит

Режим фокуса — слой на весь экран с одной Session или Terminal-ом. Окно Settings — модальный
диалог приложения (Ticket 02).

- Сейчас в режиме фокуса «Settings…» не делает ничего — ни из меню, ни по ⌘, / Ctrl+,, ни из палитры:
  `openSettings()` выходит, если на экране есть слой `.w-focus`
  (`src/renderer/settings/settings-window.ts:27-29`, `:37`). Причина — порядок слоёв: слой режима
  фокуса лежит в корневом stacking context с `z-index: 1000` (`src/renderer/focus/focus.css:7`), окно
  Settings — с `z-index` 110 (`SETTINGS_LAYER`, `settings-window.ts:20`), и окно открылось бы
  невидимым под слоем.
- Ticket 02 записал это как решение без владельца «до Ticket-а 10». Владелец решение изменил.
- Ticket [10](10-режим-фокуса-с-боковой-панелью.md) переносит слой режима фокуса внутрь главной
  области (`.w-shell__main` со своим stacking context): после него окно Settings по порядку слоёв уже
  выше слоя, а Esc в окне Settings режим фокуса не закрывает («Что делаем» Ticket-а 10, пункты 1 и
  2). Но `settings-window.ts` и его test-ы в «Где в коде» Ticket-а 10 не входят: проверка в
  `openSettings()` после 10 остаётся и становится единственным, что мешает.
- Test-ы держат нынешнее поведение: unit `test/unit/settings-dialog.test.tsx:328` («does not open
  while focus mode is on screen»), e2e `test/e2e/settings.spec.ts:101` (конец test-а: в режиме
  фокуса окно не открывается).

## Что делаем

1. Убрать проверку режима фокуса из `openSettings()` и функцию `focusModeOnScreen`
   (`settings-window.ts`); поправить комментарии файла, которые её объясняют.
2. Окно Settings в режиме фокуса ведёт себя как вне его: модальное, перехват клавиш Ticket-а 02
   действует (⌘K, ⌘F, ⌘↩ под окном ничего не делают). Esc закрывает только окно; режим фокуса
   остаётся на экране с тем же содержимым, фокус клавиатуры возвращается туда, где был до открытия.
3. Test-ы: прежние ожидания «не открывается» заменить на «открывается поверх».

## Итог

Сделано, ветка `worfy-ui/13`. ADR не понадобился, номеров нет.

**Код.** Из `src/renderer/settings/settings-window.ts` убраны функция `focusModeOnScreen` и выход из
`openSettings()` при слое `.w-focus` на экране; комментарий у `SETTINGS_LAYER` теперь объясняет,
почему окно выше режима фокуса: после Ticket-а 10 слой режима фокуса нарисован внутри
`.w-shell__main`, у которой свой stacking context (`isolation: isolate`), а окно Settings — портал в
`body` с `z-index` 110. Перехват клавиш окна (Ticket 02) не менялся: он уже работает в режиме
фокуса — ⌘/Ctrl-сочетания внутри окна останавливаются в capture phase на `window` раньше слушателей
приложения, Esc внутри окна закрывает окно и до слушателя режима фокуса в bubble phase не доходит,
а слушатель режима фокуса в capture phase сам не считает Esc своим, пока фокус клавиатуры вне слоя.
После закрытия окно возвращает фокус туда, где он был, — в слой. Файлы Ticket-а 10 (порядок слоёв)
править не пришлось: e2e подтверждает, что окно сверху (`elementFromPoint` в середине окна и
настоящий клик по разделу).

**Test-ы.**
- unit `test/unit/settings-dialog.test.tsx`, блок «Settings window over focus mode» — настоящий
  `AppShell` и настоящий `FocusMode` (разделы окна заменены одним stub-разделом через `vi.mock`,
  настоящие читают настройки через preload): окно открывается вне слоя и не `inert`, фокус в нём;
  ⌘↩, Ctrl+↩ и ⌘K внутри окна не слышит ни один слушатель на `window`; Esc закрывает только окно —
  слой тот же элемент, плитки те же, фокус в слое, режим фокуса не закрывался; второй Esc закрывает
  режим фокуса; Esc при фокусе на странице под окном тоже закрывает только окно. Прежний случай
  «does not open while focus mode is on screen» удалён.
- e2e `test/e2e/settings.spec.ts`, третий test: вместо «в режиме фокуса окно не открывается» —
  открытие из меню поверх режима фокуса, проверка, что окно сверху, клик по разделу Machines,
  снимки, ⌘K / ⌘F / ⌘↩ под окном ничего не делают, Esc закрывает только окно (заметка в плитке та
  же, фокус в слое), второй Esc закрывает режим фокуса; затем открытие из палитры поверх режима
  фокуса и Close.
- Mutation testing: мутант, который возвращает в `openSettings()` выход при `.w-focus` на экране, —
  unit красный (3 из 3 новых случаев), e2e красный (`getByRole('dialog', { name: 'Settings' })` не
  найден после клика по меню); после восстановления из копии — зелёные.
