  props в DOM, поэтому `KEEP_OUT` (`ToastRegion.tsx`) держится в стороне от класса `.w-minimap`.
  Test — `test/unit/toasts-view.test.tsx`: при открытом Command palette стопка в нижней полосе
  обрезается над полем и над Minimap.
- **`loadEarlierUntil` после сбоя (#693).** Test на `after === before` при `!ok`
  (`test/unit/session-history-tail.test.tsx`): один запрос и один error toast; без проверки — 100.
- **Повторное открытие против `readOn` (#693).** «Load earlier», нашедший файл заменённым, очищает
  `cursor`, чтобы follow() открыл файл с конца. Шедшее в это время чтение вперёд (`readOn`) потом
  записывало свой `cursor` поверх, и файл читался дальше по старому месту. Теперь `readOn` после
  каждого ответа видит очищенный `cursor` и выходит, ничего не рисуя.
- **`readFromStart` (#693).** Между кусками держатся только новейшие `KEEP_EVENTS` событий и число
  отброшенных (`first` считается от начала файла, как раньше). Это делает функция `keepNewest`
  (`useClaudeHome.ts`); её test проверяет после каждого из 1000 кусков, что событий не больше
  `KEEP_EVENTS`. Отдельный test: такой файл читается за десятки мс; старый код копировал около 10^10
  элементов (18 с, test падает по timeout). Ответ `reset` посреди чтения начинает счёт заново: test
  проверяет `first` нового файла.
- **Якорь «Load earlier» (#693, `Transcript.tsx`, `useClaudeHome.ts`).** Якорь снимался при любой
  смене `firstIndex`. Если за время чтения пришли живые записи и cap отбросил старые, первая строка
  уезжала вперёд и якорь терялся; строки сверху потом сдвигали то, что читал человек. Теперь якорь
  снимается, только когда пришли строки сверху или чтение кончилось без них; при сдвиге первой
  строки вперёд он пересчитывается от неё (номер строки и высота log).
  Ревью PR #716, круг 1: в `ExternalSessionPanel` (Session, запущенная вне worfy) якорь всё равно терялся.
  Сдвиг начала заставлял `earlierOnce` ответить 'moved' и сбросить `loadingEarlier` до повторного
  запроса; Transcript видел кадр «чтение кончилось» и снимал якорь. Теперь `loadingEarlier` держится
  от первого запроса `earlier()` до последнего, со всеми повторами. Test идёт через настоящий store
  и `ExternalSessionPanel`, без `act()`, который склеивает кадры. Ещё test-ы: повторов не больше пяти,
  после них кнопка снова доступна; повтор без начала для чтения снимает `loadingEarlier`; первая
  строка после ответа всё ещё дальше прежней; строку якоря отбросил cap — scroll сдвигается на высоту
  пришедших сверху строк.
- **IME в карточке вопроса (#698).** `onKeyDown` пропускает клавиши во время composition
  (`isComposing`): Enter, который завершает ввод иероглифов в «Other», не отправляет ответ.
- **`question_resolved` и `"__proto__"` (#698).** `z.record` строит результат присваиванием в `{}` и
  теряет ключ `"__proto__"`; схема `answers` теперь `z.custom`, который проверяет объект строк и
  оставляет его как есть. Попутно, на той же строке карточки: ответ читается через `Object.hasOwn`.
  Раньше вопрос с текстом `"__proto__"` без своего ключа ронял карточку (React получал объект
  `Object.prototype`), а вопрос `"constructor"` показывал пустоту вместо «—».
