# 23 — факты Orchestrator-а читаются через `readLinesBefore`

Type: task
Status: claimed 2026-10-24T01:35Z
Branch: worfy-ui/23
Blocked by: 21
Source: review PR #693 (worfy-ui 21), раунд 1, замечание уровня low: в коде два чтения транскрипта
с конца, и одно из них не знает про строки, начатые в предыдущем окне так, как знает
`readLinesBefore`.

## Что происходит

- `readTranscriptFacts` (`src/main/agent/orchestrator-transcript.ts:61-95`) ищет модель и последний
  status block Orchestrator-а, читая файл с конца своими кусками: свой `carry` для строки, начатой в
  более раннем куске, свой разбор строк.
- Ticket 21 добавил `readLinesBefore` (`src/main/claude-home/tail.ts`): окно перед заданным байтом,
  только целые строки, смещение каждой строки, рост окна назад, когда строка длиннее окна. Тот же
  алгоритм теперь написан дважды.

## Что делаем

- Переписать цикл `readTranscriptFacts` на `readLinesBefore`: окно за окном назад (`before` = `start`
  предыдущего окна), строки окна — с последней к первой, пока не найдены обе части фактов.
- Поведение не меняется: тот же ответ на тех же файлах, тот же `chunkBytes` из `ReadFactsOptions`
  как размер окна.

- [ ] Новый test: строка длиннее окна на границе двух окон даёт тот же ответ, что и при чтении целиком.

## Итог

Ветка `worfy-ui/23`, база — main `a3f95bbf`.

`readTranscriptFacts` (`src/main/agent/orchestrator-transcript.ts`) читает окна `readLinesBefore`
размером `chunkBytes`: первое — в конце файла, каждое следующее — перед `start` предыдущего, строки
окна — с последней к первой, пока не найдены модель и status block. Свой `carry` и свой разбор строк
удалены. Два места, где `readLinesBefore` ведёт себя иначе, чем старый цикл, закрыты так, чтобы ответ
не менялся:
- `readLinesBefore` оставляет за курсором последнюю строку без перевода строки. Старый цикл её
  читал, поэтому байты после курсора первого окна читает `readTail` и разбирает их первыми.
- Для отсутствующего файла `readLinesBefore` отдаёт пустое окно, а старый код бросал `ENOENT`.
  `readTail` открывает файл через `open` и бросает так же.

Окно с `reset` (файл укоротили или заменили между окнами) останавливает чтение: ответ — то, что
найдено до него. Старый код держал один открытый файл и такого случая не видел.

Test-ы (`test/unit/orchestrator-transcript.test.ts`): прежние шесть — без правок. Новые: строка
длиннее окна на границе окон даёт ответ чтения целиком (окна 1, 7, 64, 200, 777, 1500 байт);
последняя целая строка без перевода строки; `ENOENT` для отсутствующего файла. Все три проходят и
на старой реализации. Mutation testing — четыре мутанта, все красные: первая строка окна
пропущена; `readTail` не вызывается; `readTail` глотает `ENOENT`; только одно окно.
