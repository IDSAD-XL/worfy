# 0053 — Несколько экранов на одном Project: общее состояние, своя камера и свой ⌘Z, Session на Machine Project-а
Дата: 2026-10-07. Статус: принят.

**Контекст.** ADR-0052 разрешает открыть Canvas Project-а с Linked machine. Тогда один Project
видят несколько экранов сразу. Экран здесь — окно worfy с Canvas Project-а: на Machine Project-а
или на Linked machine. Несколько окон на одной Machine worfy открывать уже умеет
(`createMainWindow()` из `second-instance` и `activate`, `src/main/index.ts:53`, `:62`), но два
окна одновременно никто не запускал. Всё ниже — чтение кода, без запуска.

Что есть сейчас:

- **Общее состояние уже живёт в main** и уходит всем окнам: Layout с ревизией по Project
  (`src/main/layout/store.ts:42`), список Project-ов, Autopilot, Card-ы, Session-ы Session Node-ов
  и Orchestrator. Рассылка перебирает `BrowserWindow.getAllWindows()` (`src/main/broadcast.ts:6-7`,
  `src/main/ipc/layout.ts:11`, `view.ts:17`, `cards.ts:10`, `projects.ts:29`, `:77`). Подписки
  hub-ов идут по `event.sender` окна (например, `src/main/ipc/workflow.ts:27`). Общего реестра
  клиентов нет. Окно отбрасывает состояние со старой ревизией
  (`src/renderer/canvas/useLayout.ts:22`).
- **Layout.** Main применяет операции в порядке прихода и поднимает ревизию без проверки базовой
  (`store.ts:195-200`): побеждает последняя. Node-ы не перекрываются (ADR-0038), поэтому Node
  может отпрыгнуть от места, где его только что видел другой экран.
- **Камера** (viewport — сдвиг и масштаб Canvas) — часть общего Layout
  (`src/shared/layout/types.ts:60`, `:73`). Renderer пишет её операцией `setViewport`
  (`src/renderer/canvas/Canvas.tsx:401`). Два экрана разного размера сбивали бы Canvas друг
  другу.
- **Своё у окна уже сейчас:** выделение, подсветка Edge-ей выбранного Node-а
  (`src/renderer/canvas/edge-focus.ts:25`), угол Minimap (`src/renderer/canvas/pinning.ts:39`),
  поиск, навигация по Session-ам.
- **Undo.** История живёт в renderer, по Project, 40 шагов (`src/renderer/canvas/history.ts:25`,
  ADR-0016). Обратная операция считается по копии Layout в окне (`history.ts:6-8`). Если другой
  экран тем временем изменил тот же Node, откат запишет устаревшее значение.
- **Session.** Session-ы Session Node-ов и Orchestrator принадлежат приложению и шлют события
  всем окнам (`src/main/agent/app-node-sessions.ts:4`, `src/main/agent/app-orchestrators.ts:8`).
  Канал `agent.start` привязывает Session к окну: события идут одному окну
  (`src/main/ipc/agent.ts:138`), и Session закрывается, когда окно уничтожено (`agent.ts:53-61`).
  Renderer этот канал сейчас не вызывает (grep). Сообщения в одну Session уходят по очереди
  (`agent.ts:127`, `:149-155`), поэтому два экрана не смешают текст.
- **Terminal.** Вывод идёт одному окну — тому, что открыло Terminal последним
  (`src/main/ipc/terminal.ts:45-56`, `:69`). Main хранит последние 256 КиБ вывода
  (`src/main/terminal/pty.ts:25`), и новый экран может войти посреди потока. Размер у pty
  (псевдотерминала, в котором идёт shell) один;
  `terminal.resize` шлёт только последний view Node-а
  (`src/renderer/canvas/nodes/TerminalNode.tsx:133`).
- **Системные диалоги и действия** выполняет main Machine Project-а: выбор папки
  (`src/main/ipc/projects.ts:45`), кнопка «+» у вложений (`agent.ts:105`, `:161`), подтверждение
  Card `card.ask` (`src/main/ipc/card-api.ts:59`), открыть ссылку (`src/main/ipc/shell.ts:67`) и
  файл (`shell.ts:61`). Вызов с Linked machine открыл бы диалог на экране, перед которым никого
  нет.
- **Уведомления** показывает main Machine Project-а (`new Notification`, `src/main/notify.ts:199`).
  Клик по уведомлению забирает одно окно по `event.sender.id` (`src/main/ipc/notify.ts:8`). Своего
  режима «не беспокоить» в worfy нет.
- **Сон.** Autopilot не даёт Machine уснуть через `powerSaveBlocker` на время прогона
  (`src/main/autopilot/power.ts:15`, ADR-0034). Больше никто не мешает Machine уснуть.
- **Autopilot.** Второй старт в том же Project main отклоняет (`alreadyRunning`,
  `src/main/autopilot/run.ts:148`, `:287`). Но тот же репозиторий на другой Machine — другой
  Project (ADR-0052), и эта проверка его не видит.

**Решение.**

1. **Общее состояние — вживую на всех экранах.** Всё, что main сейчас рассылает всем окнам,
   получают и экраны Linked machine-ов: Layout, Card-ы, Session-ы, Terminal, Autopilot, состояние
   workflow. Всё выполняется на Machine Project-а; экран показывает и шлёт команды. Правки Layout
   идут как сейчас: в порядке прихода, последняя побеждает. Блокировок Node-ов нет.
2. **Своё у каждого экрана:** камера Canvas, выделение, подсветка Edge-ей, угол Minimap, поиск,
   открытые панели. Камера уходит из общего Layout: у каждого экрана своя камера на каждый
   Project.
3. **⌘Z (Ctrl+Z на Windows) отменяет только свои правки.** Экран, как и сейчас, помнит только
   свои жесты (ADR-0016). Если тот же Node с тех пор изменил другой экран, шаг не применяется: он
   пропускается, и экран показывает подсказку.
4. **Session живёт на Machine Project-а и не зависит от окна.** Session, запущенная с любого
   экрана, принадлежит Machine Project-а — как сейчас Session-ы Session Node-ов и Orchestrator.
   Закрытие окна на Linked machine, обрыв связи и сон Linked machine её не закрывают. Писать в
   Session могут все экраны.
5. **Terminal** показывают и принимают ввод все экраны, где он открыт. Размер pty задаёт экран,
   где в Terminal последним печатали или кликали.
6. **Системные диалоги — в UI Machine, откуда их вызвали.**
   - Выбор папки на Machine Project-а — просмотр её файлов внутри worfy (ADR-0052).
   - Вложение кнопкой «+» берёт файл со своей Machine. Байты идут по сети тем же путём, что
     вставка и drag-drop (base64, до 20 МБ, `src/shared/agent/attachments.ts:29`), и ложатся в
     данные Project-а на его Machine.
   - Подтверждение Card (`card.ask`) показывает экран, где Card открыта.

   Действия, которым нужен рабочий стол Machine Project-а, с Linked machine недоступны.
7. **Уведомления** получают Machine Project-а и Linked machine-ы, подключённые к этому Project-у.
   «Не беспокоить» у каждой Machine своё.
8. **Machine Project-а не засыпает, пока к ней подключены.** Это выключается переключателем.
   Machine, которая всё же уснула, показывается в списке со статусом «спит». Будить её по сети
   (Wake-on-LAN) — позже.
9. **Один Autopilot на Epic на все Machine.** Autopilot не стартует, если на другой Machine уже
   идёт Autopilot над тем же Epic-ом того же репозитория — с тем же URL git remote `origin`.
   Кнопка называет причину и Machine («уже идёт на Mac»). Запустить второй можно только явным
   действием пользователя.

**Последствия.**

- Нужен реестр клиентов. Окно и сетевое соединение становятся одинаковыми подписчиками: `send`,
  `id`, событие «клиент ушёл». `toEveryWindow` и прямые `getAllWindows()` переходят на реестр.
  Hubs и Terminal отписывают клиента и по обрыву связи, а не только по `destroyed` окна. Как hubs
  отписывают клиента без `destroyed` сейчас — не проверено.
- Каналу `agent.start` нужен владелец-приложение вместо окна (`agent.ts:53-61`). Иначе Session,
  начатая с Linked machine, кончится вместе с её окном.
- Viewport уходит из `layout.json` (`types.ts:73`) в данные экрана. Что делать с viewport, уже
  записанным в `layout.json`, решает Ticket камеры. Закреплённые Node-ы хранят в Layout экранные
  координаты (ADR-0013). На экране меньшего размера они могут оказаться за краем; правило для них
  решает тот же Ticket.
- Для undo нужна пометка, кто и когда менял Node: в `layout.changed` её сейчас нет.
- Terminal шлёт вывод всем подписчикам вместо одного владельца (`terminal.ts:45-56`). Сейчас
  каждый кусок вывода pty — отдельное событие, без склейки (`pty.ts:239-242`); сколько это даёт
  по сети, не измеряли.
- Клик по уведомлению больше не забирает одно окно по `event.sender.id` (`notify.ts:8`).
  «Не беспокоить» на каждой Machine — режим Focus её ОС: он и так действует на каждой Machine
  отдельно, своего переключателя worfy не заводит (Ticket 13 Epic-а `worfy-link`). На Windows
  уведомления требуют `app.setAppUserModelId`, которого в `src/` нет (ADR-0054).
- Список действий «только на Machine Project-а» составляет Ticket нативных действий. Сейчас в нём
  открыть файл в редакторе (`shell.ts:61`): файл лежит на Machine Project-а. Куда идут открыть
  ссылку (`shell.ts:67`) и меню View ▸ Show Minimap (`src/main/menu.ts:11`), решает тот же Ticket
  по правилу пункта 6.
- Machine Project-а не спит, пока к ней подключены: это расход энергии. `powerSaveBlocker` есть и
  на Windows (`power.ts:15`). Держать ли при этом включённым экран, решает Ticket; Autopilot
  по-прежнему держит экран сам (ADR-0034). Как отличить «спит» от «недоступна», решает Ticket
  связи (ADR-0052).
- Проверка Autopilot видит только Machine в сети. Что делать, если Linked machine спит или
  недоступна, решает Ticket. Project без remote `origin` сравнить не с чем — его тоже решает
  Ticket. Два Stop от двух экранов уже упорядочены: второй ждёт первый (ADR-0050).

## Considered Options

- **Общее состояние, своя камера и свой ⌘Z у каждого экрана** (выбрано).
- **Один экран за раз: второй подключается, когда первый закрыт.** Отвергнуто: владелец работает
  на обеих Machine одновременно.
- **Общая камера (viewport в Layout, как сейчас).** Отвергнуто: экраны разного размера сдвигают
  Canvas друг другу при каждом движении.
- **⌘Z отменяет последнюю правку Project-а, чья бы она ни была.** Отвергнуто: откатывает работу
  человека за другим экраном без его ведома.
- **⌘Z как сейчас, без проверки.** Отвергнуто: откат по своей копии Layout пишет устаревшее
  значение поверх чужой правки.
- **Session принадлежит окну, как в `agent.start`.** Отвергнуто: закрытие окна на Windows
  убивало бы работу на Mac.
- **Размер Terminal по самому маленькому экрану или всегда по Machine Project-а.** Отвергнуто:
  тот, кто печатает, видит размер не своего экрана.
- **Системные диалоги на Machine Project-а, как сейчас.** Отвергнуто: диалог открылся бы перед
  пустым креслом, а вызов ждал бы ответа.
- **Уведомления только на Machine Project-а.** Отвергнуто: человек за Linked machine не узнает,
  что Session ждёт его.
- **Проверка Autopilot только внутри Project-а, как сейчас.** Отвергнуто: тот же Epic того же
  репозитория на второй Machine — другой Project, и два Autopilot-а брали бы одни и те же
  Ticket-ы.
- **Запрет второго Autopilot-а без обхода.** Отвергнуто: владелец оставил явный обход.
- **Wake-on-LAN сейчас.** Отложено: сначала связь и статус «спит».
