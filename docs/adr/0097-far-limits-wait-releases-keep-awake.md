# 0097 — Autopilot отпускает keep-awake на далёком ожидании Limits
Дата: 2026-11-06. Статус: принят.

**Контекст.** ADR-0034, пункт 2: blocker keep-awake типа `prevent-display-sleep` держится весь прогон Autopilot,
включая ожидание сброса Limits. До Epic-а `worfy-retry` это ожидание длилось не больше 24 ч: сброс дальше 24 ч от
первого отказа останавливал Run с `limits-timeout`.

На верхнем плане владельца окна `five_hour` нет, есть только недельное `seven_day`, и его сброс бывает через несколько
дней. Spec `worfy-retry`, вопрос Q8: с включённым Auto-continue Project-а Run ждёт и такой сброс. Держать экран
включённым днями ради ожидания владелец не хочет. Он выбрал вариант (в) 2026-11-04: ждать до сброса, keep-awake — только
когда до сброса ≤ 24 ч, раньше Mac может спать, продолжение уйдёт при первом пробуждении после сброса.

**Решение.** Поправка к пункту 2 ADR-0034 для одного случая: Run ждёт сброса Limits дальше 24 ч, и ждёт его только
потому, что Auto-continue Project-а включён (Ticket `worfy-retry` 05).

1. Пока до продолжения (сброс плюс 2 мин) больше 24 ч, не идёт ни один ход Session Orchestrator-а и не жив ни один
   background task, Run отпускает blocker keep-awake.
2. За 24 ч до продолжения Run берёт blocker снова. Берёт его и раньше, как только начинается ход (например, человека)
   или background task: правило ADR-0029 — Mac не засыпает, пока задачи живы — не меняется.
3. Продолжение уходит по часам стены: если Mac проспал сброс, оно уходит при первом пробуждении после него, и blocker
   берётся до отправки продолжения.
4. Во всех остальных случаях — Auto-continue выключен, сброс ближе 24 ч, нет времени сброса, ожидание повтора после
   ошибки API, задержка после Stop — пункт 2 ADR-0034 действует как написан.

Реализация: `src/main/autopilot/limits-wait.ts` (`keepAwake`, таймер «за 24 ч»), `src/main/autopilot/run.ts`
(`holdAwake`, `wake`).

**Последствия.**

- На далёком ожидании экран гаснет, и macOS может заблокировать его (настройка «Require password after screen saver
  begins or display is turned off»). После продолжения Wave агенты, которым нужно окно (e2e, `gate full`), ждут
  человека, пока экран не разблокируют: ровно та точка, ради которой написан ADR-0034. Это цена решения.
- Mac может уснуть совсем; продолжение тогда уходит при пробуждении, а не в момент сброса.
- Выключенный во время такого ожидания Auto-continue останавливает Run с `limits-timeout`; Stop во время него без
  идущего хода останавливает Run сразу с `user-stop`, а не держит Orchestrator unattended днями.

## Considered Options

- (а) Как раньше: предел 24 ч, потом `limits-timeout`. На верхнем плане недельное окно почти всегда дальше 24 ч, и
  Run почти никогда не дожидался бы сброса.
- (б) Ждать сколько угодно и держать keep-awake всё время. Экран горит днями.
- (в) Ждать, keep-awake — только за 24 ч до продолжения. Выбран владельцем.
