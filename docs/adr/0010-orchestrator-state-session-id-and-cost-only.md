# Состояние Оркестратора — в Раскладке только id Сессии и стоимость

Дата: 2026-10-05. Статус: принят.

Оркестратору Проекта нужно сохранять между запусками SDK session id (для `resume`) и показывать на
Узле состояние, модель, стоимость и последний блок состояния — сразу после запуска, до первого хода.

**Решение.** В `data` Узла вида `orchestrator` в `layout.json` main пишет только `sessionId` и
`costUsd`, через тот же Layout store, что и остальные изменения Раскладки (ADR-0003: main —
единственный писатель). Модель и последний блок состояния Claude Code уже пишет в транскрипт,
поэтому worfy их не копирует (ADR-0002, ADR-0005), а читает из транскрипта при открытии
Оркестратора и затем берёт из событий живой Сессии. Состояние Сессии живёт только в памяти.
Renderer получает всё это видом Оркестратора по `orchestrator.view` и `orchestrator.changed`.
Сохранённая Сессия без транскрипта не продолжается: Оркестратор начинает новую.

**Цена.** При каждом запуске main читает хвост транскрипта Оркестратора (с конца, до последнего
блока). Если транскрипт недоступен, до первого ответа Узел показывает «No status block yet» и
модель «—». Канал `orchestrator.*` — ещё одна подписка renderer с начальным снимком. Любой писатель
Раскладки с `patchData` (MCP-инструменты тикета 24) может перезаписать `sessionId` и `costUsd` —
защищать их придётся там.

Источник: тикет 08 (`.scratch/worfy-mvp/issues/08-узел-оркестратор.md`, раздел «Итог»), PR #12.

## Considered Options

- Все поля Узла (состояние, модель, стоимость, блок) в `data` Узла: один источник для renderer,
  блок виден сразу после запуска. Отвергнуто ревью: копирует факты транскрипта в состояние worfy
  вопреки ADR-0005, и после продолжения Сессии в терминале Узел показывает устаревший блок.
- Только события `agent.event` в renderer, без хранения: после перезапуска до первого хода Узел
  пуст, а `sessionId` для `resume` всё равно надо где-то хранить.
- В `data` только `sessionId` и `costUsd`, модель и блок — из транскрипта (выбрано).
