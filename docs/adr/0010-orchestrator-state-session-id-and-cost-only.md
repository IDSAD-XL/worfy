# Состояние Orchestrator-а — в Layout только id Session и стоимость

Дата: 2026-10-05. Статус: принят.

Orchestrator-у Project нужно сохранять между запусками SDK session id (для `resume`) и показывать на
Node состояние, модель, стоимость и последний блок состояния — сразу после запуска, до первого хода.

**Решение.** В `data` Node-а вида `orchestrator` в `layout.json` main пишет только `sessionId` и
`costUsd`, через тот же Layout store, что и остальные изменения Layout (ADR-0003: main —
единственный писатель). Модель и последний блок состояния Claude Code уже пишет в транскрипт,
поэтому worfy их не копирует (ADR-0002, ADR-0005), а читает из транскрипта при открытии
Orchestrator-а и затем берёт из событий живой Session. Состояние Session живёт только в памяти.
Renderer получает всё это видом Orchestrator-а по `orchestrator.view` и `orchestrator.changed`.
Сохранённая Session без транскрипта не продолжается: Orchestrator начинает новую.

**Цена.** При каждом запуске main читает хвост транскрипта Orchestrator-а (с конца, до последнего
блока). Если транскрипт недоступен, до первого ответа Node показывает «No status block yet» и
модель «—». Канал `orchestrator.*` — ещё одна подписка renderer с начальным снимком. Любой писатель
Layout с `patchData` (MCP-инструменты Ticket-а 24) может перезаписать `sessionId` и `costUsd` —
защищать их придётся там.

Источник: Ticket 08 (`.scratch/worfy-mvp/issues/08-узел-оркестратор.md`, раздел «Итог»), PR #12.

## Considered Options

- Все поля Node-а (состояние, модель, стоимость, блок) в `data` Node-а: один источник для renderer,
  блок виден сразу после запуска. Отвергнуто ревью: копирует факты транскрипта в состояние worfy
  вопреки ADR-0005, и после продолжения Session в терминале Node показывает устаревший блок.
- Только события `agent.event` в renderer, без хранения: после перезапуска до первого хода Node
  пуст, а `sessionId` для `resume` всё равно надо где-то хранить.
- В `data` только `sessionId` и `costUsd`, модель и блок — из транскрипта (выбрано).
