# 0036 — Test-ы обнаружения через glob работают на копии модуля вне `src/`
Дата: 2026-10-07. Статус: принят.

**Контекст.** Реестры расширений renderer-а находят свои файлы через `import.meta.glob`: типы
Node-ов (`src/renderer/canvas/nodes/index.ts`), разделы sidebar (`shell/Sidebar.tsx`), элементы
toolbar (`shell/Toolbar.tsx`) и блоки правой панели Session (`session/rail/index.ts`). Три
unit-test-а проверяли, что новый файл подхватывается сам: в `beforeAll` они писали временный файл
`ZzVitestProbe*` прямо в эти каталоги `src/` и удаляли его в `afterAll`. Из этого выходило
(HANDOFF worfy-mvp, «Риски и долги»; Ticket 19 worfy-daily):

- Vite раскрывает glob один раз, при первой трансформации модуля, и эта трансформация общая для
  всех файлов test-ов одного запуска. Если реестр Node-ов первым трансформировал другой файл,
  временный тип в реестр не попадал, и «draws a Node type added as one file» в
  `test/unit/canvas.test.tsx` краснел. Воспроизводилось командой
  `vitest run test/unit/focus-mode.test.tsx test/unit/canvas.test.tsx --no-file-parallelism
  --sequence.shuffle.files --sequence.seed=3` без `vi.mock` реестра в `focus-mode.test.tsx`.
  Этот `vi.mock` (Ticket 28 worfy-mvp) был обходом: любой новый test, который раньше импортирует
  реестр, снова ломал порядок.
- Пока файл существовал, он попадал в чужой вход: lint, typecheck и сборку, запущенные
  параллельно, и в другие файлы test-ов того же запуска. Пример — блок в `rail/`, если другой
  worker впервые трансформировал `rail/index.ts` через `main.tsx`. Убитый посреди test-а vitest
  оставлял `ZzVitestProbe*` в `src/` до следующего прогона.

**Решение.**

1. **Временные файлы в `src/` не пишутся.** Helper `test/unit/glob-probe.tsx` строит во временном
   каталоге системы (`os.tmpdir()`, `worfy-glob-probe-*`) зеркало репозитория. Каталоги на пути к
   каталогу glob-а там настоящие. Все остальные записи — symlink-и на настоящие. Проверяемый
   модуль скопирован байт в байт. Рядом с symlink-ами настоящих файлов лежит образец (probe).
   Test импортирует копию модуля.
2. **Glob остаётся настоящим.** Шаблон glob-а — тот, что в исходном файле, без правки. Раскрывает
   его тот же Vite. Результат содержит настоящие файлы каталога и образец. Остальные импорты копии
   ведут к тем же модулям, что и везде: относительные — через symlink-и, пакеты — через symlink
   `node_modules`. Опечатка в шаблоне или glob, заменённый списком, по-прежнему теряют образец, и
   test краснеет; это проверено мутантами всех четырёх шаблонов.
3. **Canvas рисует копию реестра.** В `test/unit/canvas.test.tsx` путь реестра Node-ов ведёт к копии
   через `vi.mock` с фабрикой, которая импортирует копию. Настоящий `Canvas.tsx` рисует Node
   образца его файлом, без правки `nodes/index.ts` и `Canvas.tsx`. Копия — отдельный модуль со
   своей трансформацией, поэтому порядок файлов test-ов роли не играет. `vi.mock` реестра в
   `test/unit/focus-mode.test.tsx` убран.
4. **Vite разрешено читать временный каталог** — `server.fs.allow` в `vitest.config.ts`: корень
   рабочего пространства и `os.tmpdir()`. Без этого Vite отказывает в загрузке файла вне корня
   («Cannot find module»).
5. **Защита на случай старых или оборванных прогонов.**
   - `vitest.config.ts` в начале каждого запуска удаляет `src/**/ZzVitestProbe*`, оставленные
     прежними версиями test-ов.
   - Он же удаляет каталоги `worfy-glob-probe-*` старше часа. Прогон длится минуты, так что такой
     каталог не принадлежит ни одному идущему прогону. Каталоги моложе часа остаются: они могут
     принадлежать прогону в соседнем checkout.
   - `ZzVitestProbe*` внесён в `.gitignore` и в ignore ESLint.
6. **CI.**
   - Test-ы идут в случайном порядке файлов: `pnpm test --sequence.shuffle.files`. Seed печатается
     в журнале («Running tests with seed …»), и тот же порядок воспроизводится локально через
     `--sequence.seed=<seed>`. Этот запуск заменяет обычный `pnpm test`: в Linux-джобе остаётся
     один прогон test-ов, CI не дорожает.
   - Шаг после test-ов требует пустого `git status --porcelain --untracked-files=all --ignored src`.
     `--ignored` нужен потому, что `ZzVitestProbe*` теперь в `.gitignore` и без него не виден.

**Последствия.** Test-ы обнаружения не зависят от порядка файлов и не меняют `src/`: lint,
typecheck и сборка рядом с ними видят только исходники. Проверка «файл добавлен — подхватился»
осталась для всех четырёх реестров. Непроверенным остаётся одно: что настоящий файл лежит в своём
каталоге, ведь копия лежит в каталоге с тем же путём, но в зеркале. Это и так видно: без своих
файлов приложение не рисует ни одного Node-а, и это ловят e2e-test-ы.

Цена:
- Helper на ~70 строк.
- Строка `server.fs.allow` в конфиге vitest.
- Копии живут во временном каталоге системы. Убитый прогон оставляет там несколько каталогов из
  symlink-ов; их удаляет следующий прогон, когда им исполнится час.
- Новый test, который проверяет glob, должен идти через `globProbe`. Если он снова напишет файл в
  `src/`, его поймает шаг CI.

## Considered Options

- **Копия модуля во временном зеркале репозитория (`globProbe`)** — выбрано. Glob настоящий,
  `src/` не меняется. Порядок файлов не важен, потому что копия — свой модуль.
- **Свежий импорт с query string (`?discovery=…`) и `vi.resetModules`.** Так уже делали
  `shell-discovery` и `session-rail-discovery`. Порядок это чинит только для модуля, который
  импортируется напрямую. `Canvas.tsx` импортирует реестр статически, и его трансформация
  остаётся общей. Временные файлы в `src/` при этом остаются.
- **Отдельный проект vitest с `isolate` для этих test-ов.** Изоляция в vitest — это свой реестр
  модулей у файла. Кеш трансформаций Vite остаётся общим на запуск, так что glob, раскрытый раньше
  другим файлом, не пересчитывается. Временные файлы в `src/` тоже остаются.
- **Отказаться от настоящего glob.** Например, проверять `collect*` на подставленном объекте модулей
  или читать шаблон регуляркой из исходника. Тогда опечатка в шаблоне или glob, заменённый
  списком, не ловятся. Ценность test-ов пропадает.
- **Временное зеркало внутри репозитория (например, `.vitest-glob-probe/`).** Не нужен
  `server.fs.allow`. Но каталог пришлось бы прятать от ESLint, tsc, vitest и git. Каталог внутри
  `node_modules` не подходит: vitest исполняет такие файлы как внешние, без трансформации `.tsx`.
