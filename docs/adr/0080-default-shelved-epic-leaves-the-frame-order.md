# 0080 — Epic, который ушёл на полку готовых сам, выпадает из сохранённого порядка рамок мимо ⌘Z; дополняет пункт 6 ADR-0075
Дата: 2026-10-20. Статус: принят.

**Контекст.** ADR-0075 раскладывает Epic frame-ы (рамки Epic-ов с Ticket-ами внутри) полосой из K колонок.
Порядок рамок и прошлый K хранятся в Layout одной записью — невидимым Node-ом `epic-arrangement` с
`data: { order, columns, at }` (пункт 6). Пункт 6 называет два случая, когда worfy пишет эту запись сам,
мимо истории ⌘Z (ADR-0016): смена K и первое открытие Project-а за день. Ещё одну запись делает команда
«Re-pack» — это жест пользователя и шаг ⌘Z.

Пункт 5 ADR-0075 убирает готовые Epic-и с полосы на полку «Done» (Done shelf): Epic, у которого все
Ticket-ы done и рамка свёрнута, становится chip-ом под полосой. Развёрнутая рамка «встаёт в полосу в конец
порядка». Готовый Epic свёрнут по умолчанию: флаг `collapsed` Node-а `epic:<epic>` не записан, и рамка
считается свёрнутой.

Ticket 02 Epic-а [worfy-canvas](../../.scratch/worfy-canvas/spec.md) (полка готовых, PR #554, влит
коммитом `50063ee7`) добавил третий случай автоматической записи. Hook `useArrangementUpkeep`
(`src/renderer/canvas/sources/epics.ts`) на каждом пересчёте рамок убирает из `order` Epic-и, которые
стоят на полке по умолчанию, — у них флаг `collapsed` не записан ни разу
(`src/renderer/canvas/sources/epics.ts:484-490`):

```ts
const shelved = new Set(state.defaultShelf)
const kept = state.record?.order.filter((epic) => !shelved.has(epic))
if (state.record !== null && kept !== undefined && kept.length < state.record.order.length) {
  ...
  void applyLayoutOp(projectId, { op: 'patchData', id: EPIC_ARRANGEMENT_ID, data: { order: kept } })
```

Запись идёт мимо ⌘Z. Read-only экран (ADR-0066) её не пишет.

Зачем она нужна. Запись `epic-arrangement`, сделанная до Ticket-а 02 (код Ticket-а 01), называет все
Epic-и, готовые тоже. Запись этого дня называет Epic, у которого последний Ticket стал done уже после
первого открытия. Если такой Epic остаётся в `order`, то при уходе с полки сам по себе — Ticket снова
открыт или добавлен новый — его рамка возвращается на старое место в порядке, а не в конец, как требует
пункт 5. Рамка номер `i` стоит в колонке `i mod K`, поэтому возврат на старое место переставляет по
колонкам все рамки после неё. Epic, которого нет в `order`, функция `orderFor`
(`src/renderer/canvas/epic-arrangement.ts:116`) ставит в конец, как новый. Ждать пересчёта при первом
открытии следующего дня нельзя: до него Epic, ушедший с полки, встанет не в конец.

Ревью PR #554 вынесло вопрос владельцу: пункт 6 ADR-0075 этого случая не называет.

**Решение** (владелец, 2026-10-20: «Согласен со всем»).

1. **Третий случай автоматической записи `epic-arrangement` принят.** Когда Epic стоит на полке готовых
   по умолчанию (все Ticket-ы done, флаг `collapsed` на его Node-е `epic:<epic>` не записан), экран с
   правом записи убирает этот Epic из `order` записи. Это одна операция `patchData` поля `order`, мимо
   ⌘Z, как смена K и первое открытие за день. Довод: Epic ушёл на полку без жеста пользователя, поэтому
   отменять через ⌘Z нечего.
2. **Epic, который свернул пользователь, эта запись не трогает.** Готовый Epic, свёрнутый кнопкой рамки,
   выходит из `order` в том же шаге ⌘Z, что и сворачивание (`toggleFrame`,
   `src/renderer/canvas/sources/epics.ts:310`). Отмена этого шага возвращает Epic в `order`, и запись мимо
   ⌘Z не должна убирать его снова: иначе ⌘Z не вернул бы порядок. Поэтому Epic с записанным флагом
   `collapsed` остаётся в `order`, даже когда стоит на полке. Пример — рамка, свёрнутая, пока у Epic-а был
   открытый Ticket; потом все его Ticket-ы стали done (test `test/unit/done-shelf.test.tsx:456`,
   «the upkeep leaves alone an Epic the user collapsed»).
3. **Остальное в пункте 6 ADR-0075 не меняется.** Read-only экран ничего не пишет; «Re-pack» — шаг ⌘Z;
   смена K и первое открытие за день — мимо ⌘Z.

**Последствия.**

- Запись `epic-arrangement` меняется сама в трёх случаях, а не в двух: смена K, первое открытие за день,
  Epic на полке по умолчанию. Последний случай пишет один раз на Epic: Epic, которого в `order` уже нет,
  повторной записи не вызывает.
- Epic, который уходит с полки сам (Ticket снова открыт или добавлен), встаёт в конец порядка, как
  требует пункт 5 ADR-0075, и рамки после его старого места не переставляются по колонкам.
- Epic, свёрнутый пользователем и оставшийся в `order`, при уходе с полки сам возвращается на прежнее
  место в порядке, а не в конец. Это цена пункта 2: ⌘Z кнопки сворачивания возвращает порядок целиком.
  Клик по chip-у ставит рамку в конец в любом случае (`expandFromShelf`,
  `src/renderer/canvas/sources/epics.ts:294`).
- Test-ы — `test/unit/done-shelf.test.tsx`: запись убирает Epic с полки из `order` мимо ⌘Z, и снова
  открытый Epic встаёт в конец; Epic, свёрнутый пользователем, остаётся в `order`.

## Considered Options

- **Убирать из `order` только Epic на полке по умолчанию, мимо ⌘Z** (выбрано).
- **Не писать запись; Epic на полке остаётся в `order` до первого открытия следующего дня.** Отвергнуто:
  до этого Epic, ушедший с полки сам, возвращается на старое место, а не в конец (пункт 5 ADR-0075), и
  переставляет по колонкам рамки после себя.
- **Убирать из `order` и Epic, свёрнутый пользователем.** Отвергнуто: запись мимо ⌘Z снова убирала бы
  Epic, которого ⌘Z кнопки сворачивания вернул в `order`, и отмена не возвращала бы порядок (ADR-0016).
- **Делать эту запись шагом ⌘Z.** Отвергнуто: шаг без жеста пользователя — ⌘Z отменял бы то, чего
  пользователь не делал (ADR-0016).
