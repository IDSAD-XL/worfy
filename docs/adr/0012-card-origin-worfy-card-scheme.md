# Адрес и изоляция Карточки — свой origin `worfy-card://<id>.<метка проекта>`

Дата: 2026-10-05. Статус: принят.

Карточка — исполняемый HTML/JS, написанный агентом.

**Решение.** worfy показывает Карточку в iframe на своей привилегированной схеме `worfy-card://`
(`standard`, `secure`). У каждой Карточки свой origin `worfy-card://<id Карточки>.<метка Проекта>`,
где метка — 8 hex-символов хеша пути Проекта из его id. iframe — `sandbox="allow-scripts
allow-same-origin"`: origin свой, поэтому доступа к окну worfy (file:// или dev-сервер) и к другим
Карточкам нет. Протокол отдаёт только файлы из папки Карточки с CSP (`connect-src https:`,
`frame-src 'none'`, без форм и плагинов), main не пускает фрейм на чужой origin, не открывает окна
и не даёт web-разрешений.

**Почему записано.** Решение трудно обратимо: origin — ключ хранилищ браузера Карточки
(localStorage, IndexedDB в userData worfy) и ожидаемый origin в мосте `postMessage` (тикет 26).
Смена схемы адреса теряет данные Карточек в этих хранилищах и меняет проверку отправителя.

Источник: тикет 25 (`.scratch/worfy-mvp/issues/25-рантайм-карточки.md`, раздел «Итог»), PR #15.

## Considered Options

- Весь ключ Проекта в хосте (`<id>.<ключ>`, как в тексте тикета 25) — отвергнуто: имя папки
  Проекта с пробелами, заглавными или не-ASCII буквами не проходит в хост без искажения.
- Ключ Проекта в hex/base32 в хосте — отвергнуто: длинные имена папок не помещаются в метку DNS
  (63 символа), а адрес становится нечитаемым.
- Один origin на все Карточки с путём `/<проект>/<id>/` — отвергнуто: Карточки видели бы
  хранилища и DOM друг друга.
- `srcdoc`/`data:` без своего протокола — отвергнуто: opaque origin без своих файлов и без
  контроля заголовков.
- Свой origin на Карточку с меткой Проекта из хеша (выбрано).
