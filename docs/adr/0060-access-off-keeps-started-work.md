# 0060 — Выключение доступа Linked machine-ам и отзыв Linked machine не останавливают то, что запущено раньше
Дата: 2026-10-13. Статус: принят.

**Контекст.** Пункт 6 ADR-0052 (Machine и Linked machine: два worfy связываются по локальной сети):

> **Доступ к своим Project-ам по умолчанию выключен.** Переключатель «Linked machines can work
> with my Projects» по умолчанию выключен. Пока он выключен, Linked machine не работает с
> Project-ами этой Machine: не открывает их Canvas и ничего в них не запускает. Без действия
> пользователя на этой машине worfy сеть не слушает. Когда переключатель включён, Linked machine может в Project-ах всё, кроме действий,
> которым нужен рабочий стол машины Project-а (ADR-0053).

О работе, запущенной с Linked machine при включённом переключателе, пункт молчит, а «ничего в них
не запускает» читается и как «после выключения в Project-ах не идёт ничего, начатого с неё». Пункт 9
того же ADR (отзыв Linked machine) о такой работе тоже не говорит.

Код делает иначе (Ticket `worfy-link/08` — доступ Linked machine к Project-ам). При выключении
`LinkPeer.setAccess(false)` в `src/main/link/ipc-adapter.ts` уничтожает клиента `project` каждого
соединения, и `LinkIpcAdapter.call` в том же файле отвечает на любой вызов, кроме каналов `link`,
отказом «Linked machines cannot work with the Projects of <Machine>: access is off». Session, прогон
Autopilot и очередь сообщений Session (`agent.send`) этот код не трогает: Session принадлежит
приложению на Machine Project-а, а не окну и не соединению (ADR-0053 — несколько экранов на одном
Project, пункт 4; Ticket `worfy-link/04`). С какой Machine они запущены, worfy не записывает.

Владелец решил 2026-10-12 оставить поведение кода («Итог» Ticket-а `worfy-link/08`), а 2026-10-13
подтвердил три уточнения: Terminal остаётся исключением, под переключателем нужна подсказка, на
отзыв Linked machine действует то же правило. Этот ADR уточняет ADR-0052, пункты 6 и 9: слова
«ничего в них не запускает» значат, что при выключенном переключателе Linked machine не начинает в
Project-ах ничего нового. ADR-0052 не правится, остальное в его пунктах остаётся в силе.

**Решение.**

1. **Выключение доступа закрывает вход, а не работу.** Клиент `project` соединения уничтожен: hub-ы
   (общие наблюдатели файлов), Terminal и Session больше не шлют ему событий. Каждый следующий
   вызов, кроме каналов `link`, получает «access is off»; вызов, который уже выполняется, доходит
   до конца. Соединение остаётся: Machine по-прежнему показана «в сети».
2. **Запущенное с Linked machine раньше продолжает работать.** Session-ы, Autopilot и очередь
   `agent.send` не останавливаются и не ставятся на паузу.
3. **Останавливает эту работу человек на самой Machine, обычными средствами:** Stop и Force stop у
   Autopilot (ADR-0051), Interrupt у Session — он же придерживает её очередь — и удаление сообщения
   из очереди. Отдельного действия «остановить всё, что запущено с Linked machine» нет.
4. **Terminal — исключение.** Shell закрывается, когда ушёл последний его подписчик (Ticket
   `worfy-link/05` — Terminal на нескольких экранах): Terminal, открытый только с Linked machine,
   при выключении доступа закрывается. Так код делает сейчас, и так остаётся: на этой Machine такой
   Terminal никто не видит.
5. **Отзыв Linked machine — то же правило.** Отозванная Machine теряет токен и запомненный
   сертификат, её соединения закрываются (`LinkService.revoke`, `src/main/link/service.ts`). Session-ы,
   Autopilot и очередь `agent.send`, запущенные ею раньше, продолжают работать; Terminal, открытый
   только с неё, закрывается по пункту 4. Кода, который в этом пути останавливал бы Session, прогон
   или очередь, нет (прочитано по коду).

**Последствия.**

- После выключения доступа или отзыва работа, начатая с Linked machine, может идти дальше и менять
  файлы Project-а: Session берёт следующее сообщение очереди, прогон Autopilot продолжается. Ни то,
  ни другое — не аварийная остановка.
- Видит эту работу только тот, кто сидит за этой Machine: Linked machine при выключенном доступе
  Project-ов этой Machine не видит, и уведомления о них ей не уходят (`src/main/link/notes.ts`).
- Под переключателем доступа в разделе Machines боковой панели
  (`src/renderer/shell/sidebar/MachinesSection.tsx`) появляется одна строка: «Work already started
  from a Linked machine keeps running». Делает её Ticket `worfy-link/19`.
- Блокировка сна «пока подключены Linked machine-ы» (Ticket `worfy-link/14`) отпускается в момент
  выключения (`src/main/link/keep-awake.ts`). Прогон Autopilot держит свою (ADR-0034), Session — нет.
- Код, кроме подсказки, не меняется; раздел «Доступ» в `spec.md` Epic-а `worfy-link` уже говорит то
  же. Раздел «switching access off» в `test/contract/link-access.test.ts` пункт 2 этого решения не
  проверяет; test на пункт 5 не искался.
- Право «только чтение» (Ticket `worfy-link/18`) наследует правило: понижение уровня не останавливает
  запущенное раньше — если владелец не решит иначе в том Ticket-е.

## Considered Options

- **Выключение и отзыв только закрывают вход: отписывают соединение и отказывают новым вызовам**
  (выбрано). Владелец: оставить запущенное работать. Session принадлежит приложению на Machine
  Project-а: её не закрывают ни закрытие окна, ни обрыв связи (ADR-0053, пункт 4) — и выключение
  доступа тоже.
- **При выключении — graceful Stop Autopilot-а, запущенного с Linked machine, и пауза его очереди
  `agent.send`; идущие Session-ы не трогать.** Рекомендовано владельцу и отклонено им 2026-10-12:
  «оставить запущенное работать». Сверх того, worfy не записывает, с какой Machine запущен прогон
  или поставлено сообщение: варианту понадобился бы новый учёт.
- **При выключении или отзыве останавливать всё, что запустила Linked machine.** Отвергнуто: работа
  обрывается на полушаге — как при Force stop, после которого шаг implementer-а (например, merge)
  может остаться недоделанным (ADR-0050). По той же причине ADR-0053 отверг Session, принадлежащую
  окну.
- **Оставлять работать и Terminal, открытый только с Linked machine.** Отвергнуто 2026-10-13
  (владелец согласился с рекомендацией): такой Terminal на этой Machine никто не видит, а правило
  «shell живёт, пока есть подписчик» (Ticket `worfy-link/05`) остаётся одним для всех экранов.
- **Исправить пункты 6 и 9 в самом ADR-0052.** Отвергнуто: принятые ADR правятся только в терминах
  (ADR-0017).
