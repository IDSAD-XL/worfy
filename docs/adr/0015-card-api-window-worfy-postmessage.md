# API Карточки — `window.worfy` поверх `postMessage`, workflow только для чтения

Дата: 2026-10-05. Статус: принят.

**Контекст.** Карточка — HTML и JS, которые написал агент (ADR-0003); она живёт в iframe на своём
origin `worfy-card://` (ADR-0012). Ей нужно хранить свои данные, задавать вопрос Сессии и видеть
workflow. Карточка — исполняемый код агента, поэтому доступа к файлам и процессам у неё быть не
должно, а всё, что уходит агенту от её имени, должен видеть пользователь.

**Решение.** Карточка общается с worfy только сообщениями `postMessage` в формате
`src/shared/cards/bridge.ts`. Рантайм `window.worfy` (`src/card-runtime/worfy-card.ts`) протокол
`worfy-card://` (`src/main/cards/protocol.ts`) вставляет inline-скриптом в каждую HTML-страницу
Карточки; файл на диске не меняется. Окно (`src/renderer/canvas/card-bridge.ts`) принимает
сообщение, только если `event.source` — `contentWindow` фрейма Карточки и `event.origin` — origin
именно этого фрейма. Сообщение разбирается zod-схемой, дальше идёт только разобранный запрос;
остальное молча отбрасывается. Набор операций закрыт:

- свои данные — JSON до 1 МБ в `<папка данных Проекта>/card-data/<id>.json` (ADR-0005);
- вопрос Сессии (`session.ask`) — только после подтверждения пользователя в системном диалоге,
  где виден получатель и ровно тот текст, что уйдёт. Получатель — живая в worfy Сессия, которая
  последней правила Карточку, иначе Оркестратор Проекта;
- снимок workflow и подписка на его изменения — только для чтения. Отвечает окно из своей копии
  модели workflow; операций записи workflow нет (ADR-0002).

В main уходят только три канала `cardApi.*`: `dataGet`, `dataSet`, `ask`.

**Следствие.** `window.worfy` и формат сообщений — контракт между приложением и Карточками, которые
агенты уже написали и которые лежат в данных пользователя. Смена API ломает их молча, поэтому
менять его можно только осознанно, вместе с инструкцией агенту (`src/main/mcp/agent-instructions.md`,
раздел про API). Новая операция Карточки — новая ветка схемы в `bridge.ts` и обработчик; запись в
workflow этим решением запрещена.

Источник: тикет 26 (`.scratch/worfy-mvp/issues/26-api-карточки.md`, раздел «Итог»), PR #27.

## Considered Options

- Node или IPC в Карточке (`nodeIntegration`, preload во фрейме) — отвергнуто: исполняемый код
  агента получил бы доступ к файлам и процессам.
- `MessageChannel`, переданный Карточке при загрузке, вместо проверки `source` и `origin` —
  отвергнуто на MVP: тот же контроль отправителя, но ещё одно рукопожатие, которое хуже переживает
  перезагрузку фрейма.
- Отправка вопроса Сессии без подтверждения — отвергнуто: Карточка — код агента, а текст уходит
  агенту от имени пользователя.
- `postMessage` с проверкой фрейма и origin, закрытый набор операций, рантайм, вставляемый
  протоколом (выбрано).
