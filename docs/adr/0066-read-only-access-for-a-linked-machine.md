# 0066 — Уровень доступа у каждой Linked machine и право «только чтение»
Дата: 2026-10-16. Статус: принят.

**Контекст.** Пункт 6 ADR-0052 (Machine и Linked machine: два worfy связываются по локальной сети):
переключатель «Linked machines can work with my Projects» один на Machine; пока он включён, Linked
machine может в Project-ах всё, кроме действий, которым нужен рабочий стол машины Project-а.
ADR-0060 уточнил тот же пункт: выключение закрывает вход, а не работу, начатую раньше.

Среди каналов `project` (пометка доступа Ticket-а `worfy-link/08`) есть те, что исполняют код на
машине Project-а: shell в Terminal, Session Claude Code в режиме `bypassPermissions`, ответ на
запрос разрешения, Autopilot, добавление любой папки Project-ом. Для своих машин владелец этот
доступ подтвердил. Для связи с чужой машиной он потребовал право «только чтение» (2026-10-12,
«Итог» Ticket-а 08) и 2026-10-13 ответил на пять вопросов Ticket-а `worfy-link/18`.

Этот ADR уточняет пункт 6 ADR-0052. ADR-0052 и ADR-0060 не правятся; остальное в них в силе.

**Решение.**

1. **Уровень у каждой Linked machine свой: Off, Read only, Full access.** Хранится в
   `link/settings.json` папки данных (`machines`: id → `read` или `all`; Machine без записи — Off).
   Новая связь — Off, в том числе повторное связывание той же Machine; отзыв стирает её уровень.
2. **Переключатель остаётся и выключает всех.** Пока «Linked machines can work with my Projects»
   выключен, уровень каждой Linked machine — Off, что бы ни было записано у неё; включён —
   действует её собственный уровень. Строки уровней в Settings → Machines в это время неактивны.
3. **Каждый канал `project` помечен `read` или `write`** (`src/shared/ipc/channels.ts`, `ChannelUse`).
   Пометка — обязательный аргумент объявления канала `project`: без неё `pnpm typecheck` падает;
   у каналов `link`, `desktop`, `local` её нет. Правило: `read` не меняет файлы и состояние
   Project-а и worfy, не запускает и не останавливает процессы и ничего не шлёт в Session или
   Terminal; подписка на события и отписка — чтение. Исключения по решению владельца:
   - транскрипты (`claudeHome.transcript`), события Session (`agent.event`) и уведомления — чтение;
   - `checks.get` и `checks.repos` — чтение, хотя запускают `git` и `gh`: они ничего не пишут;
   - вывод Terminal (`terminal.output`) — не чтение: событие помечено `write`.
   Поимённые списки — `test/unit/link-access.test.ts`.
4. **Отказ.** При Read only вызов канала `write` получает
   `{ok:false, error:"Linked machines can only view the Projects of <Machine>: access is read-only"}`
   в `LinkIpcAdapter.call` (`src/main/link/ipc-adapter.ts`) — после проверок «access is off» и
   «not open to Linked machines», до разбора входа и без запуска handler-а. В лог идут канал и
   Machine, вход вызова — нет. Клиент соединения с Read only не пересылает события `write`.
5. **Смена уровня заменяет клиента соединения.** Подписки старого клиента снимаются, Linked machine
   подписывается заново. Вызов, уже начатый, доходит; следующий проверяется по новому уровню.
   Понижение уровня не останавливает запущенное раньше — правило ADR-0060, с тем же исключением для
   Terminal, открытого только с Linked machine.
6. **Linked machine узнаёт свой уровень из сообщения `projects-access`**: в нём `level` и, для
   сборок до этого решения, `on`. Сборка, которая шлёт только `on`, читается как Full access или Off.
   Текст отказа уровень не задаёт.
7. **Read only — всё равно доверие.** Транскрипт Session, её события и уведомления могут показать
   секрет. Settings → Machines говорит это прямо под уровнем Read only.
8. **Старый файл.** `link/settings.json` версии 1 (один переключатель) читается так: включён —
   Full access у каждой Machine, связанной в этот момент; выключен — ни у кого. Файл сразу
   переписывается версией 2, чтобы Machine, связанная позже, не унаследовала старый переключатель.
   Нечитаемый файл — доступ выключен, как раньше.

**Последствия.**

- Запрет сна машины Project-а (`src/main/link/keep-awake.ts`) держится, пока подключена хотя бы одна
  Linked machine с уровнем Read only или Full access: читающей машине Project-ы тоже нужны.
- Уведомления (`src/main/link/notes.ts`) уходят Linked machine-ам с уровнем Read only и Full access.
- `link.setAccess` по-прежнему включает и выключает переключатель; уровень одной Machine задаёт новый
  канал `link.setMachineAccess` (`local`).
- Экран Linked machine-а с Read only действия записи пока показывает: они отвечают отказом. Скрыть
  их — Ticket `worfy-link/25`.
- Новый канал `project` требует решения «чтение или запись» в объявлении и в поимённом списке
  test-а; пока его нет, падает typecheck или test.

## Considered Options

- **Свой уровень у каждой Linked machine; переключатель — «выключить всем»** (выбрано; ответ
  владельца 1). Своей машине можно дать всё, чужой — только чтение.
- **Один уровень на Machine для всех Linked machine-ов.** Отвергнуто владельцем: с ним нельзя дать
  своей машине всё, а чужой — только чтение.
- **Убрать общий переключатель, оставить только уровни.** Отвергнуто: владелец оставил его как
  способ выключить доступ всем сразу.
- **Две пометки доступа вместо второго признака (`project-read`, `project-write`).** Отвергнуто:
  пришлось бы менять каждое место, где сравнивается пометка `project` (адаптер, вызовы на Linked
  machine, рассылка событий); второй признак меняет только объявления каналов `project`.
- **Скрывать или выключать действия записи на экране Linked machine-а в этом решении.** Отложено
  (ответ владельца 4): здесь — отказ с понятным текстом, скрытие — отдельный Ticket.
- **Узнавать уровень по тексту отказа.** Отвергнуто: текст — для человека; уровень приходит
  служебным сообщением.
