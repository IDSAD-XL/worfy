# 0020 — Profile из двух частей; аккаунт GitHub Project — через `GH_TOKEN`
Дата: 2026-10-06. Статус: принят.

**Контекст.** Сегодня Profile целиком лежит на машине владельца: `~/.claude/profiles/<имя>/`,
находится через реестр Gate. В нём смешаны факты о репозитории (команды проверки, где лежат
Ticket-ы, как называются ветки, линзы ревью) и факты о машине (абсолютные пути, папка worktree,
аккаунт GitHub). Второй человек или вторая машина пишут Profile заново. Аккаунт GitHub у Project-ов
разный: у владельца Atakama идёт через рабочий аккаунт, worfy и Auction — через личный. Глобальный
`gh` переключать нельзя: им одновременно пользуются другие Session-ы (`docs/lessons/ci-merge.md`).

**Решение.** Profile состоит из двух частей.

- Общая — в репозитории Project: команды проверки, где лежат Ticket-ы, ветки, линзы ревью,
  разрешённые MCP-серверы (ADR-0021). В репозиторий она попадает PR-ом агента, который люди
  ревьюят и мержат как любое изменение. worfy сам в репозиторий не пишет.
- Личная — на машине пользователя, вне репозитория: пути, папка worktree, аккаунт GitHub.

Подключение Project в worfy:

1. Пользователь выбирает папку (ADR-0018).
2. worfy проверяет, что Harness установлен (ADR-0019).
3. Агентская Session пишет черновик Profile: команды проверки, где лежат Ticket-ы (или заводит
   `.scratch/`), ветки, линзы, MCP-серверы.
4. Пользователь подтверждает черновик в форме.
5. Пользователь выбирает аккаунт GitHub из `gh auth status`; если подходящего нет, worfy предлагает
   `gh auth login`.
6. Общая часть уходит PR-ом, личная записывается на машине.
7. Project регистрируется в Gate.

Аккаунт GitHub — свойство Project. worfy и Harness во всём, что делают для Project (`gh`, `git` по
`origin`, Session-ы и их Subagent-ы), работают через `GH_TOKEN` выбранного аккаунта и глобальный
`gh` не переключают. Токен берётся у `gh` (`gh auth token -u <аккаунт>`), как уже требует урок
`docs/lessons/ci-merge.md`.

**Что меняется в прежних ADR.** ADR-0005: правило «worfy ничего не пишет в репозитории» остаётся —
общую часть Profile приносит PR агента, а не запись worfy. Но фраза «для остальных участников
репозитория worfy невидим» больше не точна: файл общей части Profile они видят. Это файл Harness,
а не состояние worfy. ADR-0007: к окружению Session добавляется `GH_TOKEN` аккаунта Project, и он
главнее такой же переменной из rc-файлов пользователя.

**Последствия.** Путь файла общей части в репозитории и место личной части на машине выбирает тема
обобщения Harness в Epic E3 («Harness как часть worfy»). Для Project над несколькими репозиториями
(ADR-0018) общей части нужен либо один из репозиториев, либо копия в каждом — это решает последняя
тема E3. До неё Profile остаётся в `~/.claude/profiles/`.

## Considered Options

- Весь Profile на машине, как сейчас. Отвергнуто: факты о репозитории живут вне него, и каждый
  участник и каждая машина пишут Profile заново и расходятся.
- Весь Profile в репозитории. Отвергнуто: в общий файл попадают абсолютные пути, папка worktree и
  аккаунт GitHub одного человека.
- worfy пишет общую часть в репозиторий сам, без PR. Отвергнуто: изменение мимо ревью и против
  ADR-0005.
- Переключать глобальный аккаунт (`gh auth switch`) на время работы с Project. Отвергнуто: ломает
  Session-ы и терминалы других Project-ов, которые идут параллельно.
- Общая часть PR-ом агента, личная на машине, `GH_TOKEN` на Project (выбрано).
