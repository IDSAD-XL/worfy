# 0059 — Зависимости plugin-а `worfy` ставит установщик worfy: с согласия, командами `claude plugin`, раньше самого plugin-а; установка не остаётся сделанной наполовину
Дата: 2026-10-10. Статус: принят.

**Контекст.** Plugin `worfy` объявляет зависимость `mattpocock-skills@claude-plugins-official`
(`harness/.claude-plugin/plugin.json`; [ADR-0047](0047-harness-lessons-by-pr-early-owner-switch.md),
пункт 5): её skills вызывают continuous-audit и tickets-to-tasks. Без неё Claude Code plugin не
грузит вовсе: в прогоне eval — `dependency-unsatisfied`, ни одного правила Harness в Session
(Ticket `worfy-harness/27`). Кто ставит объявленную зависимость, ADR-0047 не говорит. Установщик
(Ticket `worfy-harness/13`, [ADR-0040](0040-harness-delivery-local-marketplace.md)) решил это без
владельца: worfy зависимость не ставит, а называет в диалоге команду, которую пользователь
выполняет сам.

Приёмка E3 на пустом `~/.claude` (Ticket `worfy-harness/26`, пункт 1) на этом упала: зависимости
нет, поставить её некому, Retry только перечитывает состояние. В том же прогоне
`claude plugin install` ответил отказом, а plugin `worfy` остался записанным в
`installed_plugins.json` и включённым в `settings.json` — установка осталась сделанной наполовину.

Владелец решил 2026-10-10 (вариант «а»): зависимость ставит сам установщик, в том же диалоге
согласия, как qmd ставится с согласия ([ADR-0043](0043-qmd-is-part-of-harness.md), пункт 4).

**Решение.**

1. **Зависимости plugin-а `worfy` ставит установщик worfy.** Список — `dependencies` в
   `plugin.json` копии Harness этой сборки. Ставит он их командами Claude Code, встроенным бинарём
   SDK ([ADR-0048](0048-harness-plugin-spike-results.md)), и только после согласия пользователя:
   - `claude plugin marketplace add anthropics/claude-plugins-official` — если marketplace ещё не
     добавлен;
   - `claude plugin install <имя>@claude-plugins-official --scope user`.
   Сам worfy файлов зависимости не пишет и ничего не скачивает: скачивает и записывает Claude Code.
2. **worfy добавляет один marketplace — `claude-plugins-official`.** Его имя и репозиторий
   (`anthropics/claude-plugins-official`) — константа установщика. Зависимость из другого
   marketplace или без marketplace в имени worfy не ставит: установка останавливается до диалога
   с ошибкой, которая называет зависимость; ни одной команды записи не идёт. Так чужой
   marketplace не попадает в настройки пользователя потому, что его назвал `plugin.json`.
3. **Диалог согласия один.** До диалога установщик читает, что уже стоит (`claude plugin list
   --json`) и какие marketplace-ы известны (`claude plugin marketplace list --json`), — и при
   отсутствии папки plugin-а тоже. Диалог называет ровно те команды, что пойдут: сначала команды
   зависимости и то, что Claude Code скачает её из GitHub и запишет marketplace и plugin в свои
   настройки, потом копию Harness и команды `worfy`. Зависимость уже стоит — её команд в плане и
   в диалоге нет. Отказ — ни одной записи и ни одной команды, кроме двух чтений. Чтение состояния
   для toolbar и экрана первого запуска остаётся прежним: без папки plugin-а — ни одной команды.
4. **Сначала зависимость, потом `worfy`.** Команды зависимости идут до копии Harness. Упал шаг
   зависимости — копии нет, команды `worfy` не идут, в `plugin list` записи `worfy` нет; состояние
   — ошибка шага `dependency marketplace add` или `dependency install` с хвостом stderr.
5. **Установка кончается одним из двух состояний: стоит или не стоит.**
   - Первая установка `worfy` упала — установщик перечитывает `plugin list`; если запись `worfy`
     появилась, убирает её (`claude plugin uninstall worfy@worfy-harness --scope user`). Ошибка
     шага `install` говорит, что запись убрана; если упал и `uninstall` — ошибка шага `uninstall`
     с хвостами обеих команд.
   - Упавший `update` ничего не удаляет: прежняя версия остаётся.
   - `worfy` стоит, а зависимости в `plugin list` нет (состояние, которое оставил установщик
     Ticket-а 13; зависимость удалили позже) — это ошибка шага `dependency install` с именем
     зависимости, и у неё есть план: одни команды зависимости. Retry её ставит, руками ставить
     ничего не нужно.
6. **Статус зависимости виден.** Состояние Harness несёт список зависимостей: «стоит», «нет» или
   «не проверено» (пока нет папки plugin-а, список plugin-ов не читается). Он берётся из того же
   `plugin list`, отдельной команды нет. Экран первого запуска показывает его строкой «Plugin
   dependencies» в группе Harness.
7. **Запустить установку можно только с этой машины.** Каналы установки помечены `local`
   ([ADR-0052](0052-machines-and-linking.md), пункт 6): Linked machine установку зависимости в чужой
   `~/.claude` не запускает.
8. **Чего это решение не делает.** worfy не несёт копию `mattpocock-skills` внутри `.app`, не
   обновляет зависимость до новой версии и не удаляет её при удалении `worfy`.

**Что меняется в прежних ADR.**

- [ADR-0040](0040-harness-delivery-local-marketplace.md), пункт 7 (что установщик пишет в
  `~/.claude`) дополняется: через команды `claude plugin` в настройки Claude Code теперь попадают
  ещё запись официального marketplace и plugin зависимости. По-прежнему — только после
  подтверждения пользователя и только командами Claude Code; сам worfy пишет лишь в
  `~/.claude/worfy-harness/`.
- [ADR-0047](0047-harness-lessons-by-pr-early-owner-switch.md), пункт 5 (plugin объявляет
  зависимость `mattpocock-skills`) дополняется: объявленную зависимость ставит установщик worfy.
- Отменяется «решено без владельца» Ticket-а `worfy-harness/13`: «worfy сам зависимость не ставит,
  а только называет».
- [ADR-0043](0043-qmd-is-part-of-harness.md), пункт 4 (скачивание — с согласия) в силе и служит
  образцом: скачивание зависимости названо в диалоге до того, как что-либо запущено.

**Не проверено настоящим Claude Code.** Адрес официального marketplace взят из
`known_marketplaces.json` машины владельца; есть ли у встроенного Claude Code команда
`plugin marketplace list --json` и что она печатает — не проверялось: test-ы идут со stub-ом `claude`,
без сети. Поэтому установщик не полагается на неё: если команда отвечает ошибкой или не списком
записей с `name`, marketplace добавляется всегда, ответ «уже добавлен» не считается ошибкой, а
упавший `marketplace add` называет и причину, по которой список прочитать не удалось. Проверяет это
приёмочный прогон в песочнице (Ticket `worfy-harness/26`).

## Considered Options

- **Зависимость ставит установщик worfy, в том же диалоге согласия** (выбрано, вариант «а»
  владельца). Пользователь на пустой машине получает работающий Harness одним подтверждением.
- **worfy зависимость только называет, ставит пользователь** (как решил Ticket 13). Отвергнуто
  владельцем: на пустом `~/.claude` plugin `worfy` записан, но не грузится, а экран первого запуска
  не может довести машину до рабочего состояния.
- **Копия `mattpocock-skills` внутри `.app`, локальный marketplace, как у Harness.** Отвергнуто:
  чужой plugin пришлось бы обновлять вместе со сборкой worfy и ставить под чужим именем
  marketplace; сеть для него не запрет — qmd и его модели тоже скачиваются с согласия.
- **Убрать зависимость из `plugin.json`, а нужные skills перенести в Harness.** Отвергнуто:
  ADR-0047, пункт 5 оставляет `mattpocock-skills` зависимостью; это решение его не пересматривает.
- **Ставить `worfy` первым, зависимость после.** Отвергнуто: между двумя шагами plugin `worfy`
  записан и включён, но не грузится, — то самое состояние «наполовину», которое упавший второй шаг
  оставил бы навсегда.
- **После упавшей установки `worfy` убирать и копию Harness, и marketplace `worfy-harness`.**
  Отвергнуто: копия в `~/.claude/worfy-harness/plugin/` и запись marketplace сами plugin не
  включают; следующая попытка ставит поверх них без повторной копии.
