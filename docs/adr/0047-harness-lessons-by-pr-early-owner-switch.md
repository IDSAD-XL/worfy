# 0047 — Развитие Harness: урок — PR в `harness/`; `~/.claude` заморожен после импорта; машина владельца переходит на plugin рано; Stable copy не пересобирается во время Autopilot
Дата: 2026-10-07. Статус: принят.

**Контекст.** Сегодня Harness — файлы в `~/.claude` владельца, локальный git-репозиторий без
remote. Урок о работе агентов вписывают прямо в эти файлы, и он действует со следующей Session:
так 2026-10-06 в skill `epic-wave` попал узкий круг исправления (commit 1707b91). По ADR-0019
Harness становится plugin Claude Code из `harness/` репозитория worfy, с версией приложения, и
ставит его worfy. По ADR-0040 (доставка Harness) worfy при запуске копирует `harness/` своей версии
в `~/.claude/worfy-harness/plugin/` и ставит plugin `worfy` в область пользователя, а Session-ы самого
worfy получают plugin своей версии inline.

Autopilot над самим worfy идёт из Stable copy (`~/Applications/worfy-stable.app`); её ставит
`pnpm install:stable` (`scripts/install-stable.sh`) между прогонами. Wave-ы E3 сами переписывают
Harness. Нужно решить: куда идёт урок и когда начинает действовать, на каком Harness идут Wave-ы
E3 и когда машина владельца переходит со старых файлов на plugin. ADR-0019 отвечал на последнее:
«до конца E3 владелец работает со старыми файлами в `~/.claude`».

Факты spike Epic-а `worfy-harness` 2026-10-07 (SDK 0.3.289, встроенный Claude Code 2.1.289):

- SDK с `settingSources: user` грузит plugin-ы из области пользователя. После перехода plugin
  `worfy` видят Session-ы worfy, терминала и Claude desktop.
- `plugins: [{type: 'local', path}]` с тем же именем молча заменяет установленный plugin
  (`<name>@inline`). Session-ы Stable copy идут на её Harness, даже если в области пользователя уже
  стоит другая версия.
- `CLAUDE_CONFIG_DIR` изолирует settings, plugins и запись keychain: в песочнице нужен свой
  `/login`.
- Hooks plugin `SessionStart` и `SubagentStart` доходят до главной Session и до Subagent-а. До
  Subagent-ов Workflow-скриптов — не проверено; это проверяет Ticket 01 (spike Epic-а, итог —
  ADR-0048).

**Решение.** Решения владельца 2026-10-07 Session проектирования Epic-а `worfy-harness`: вопрос Q3
(как дорабатывать Harness), вопросы Q13 и Q33 (когда переходит машина владельца), вопрос Q14
(пересборка во время Autopilot), вопрос Q19 (что переносится).

1. **Урок, который меняет Harness, — PR в `harness/`.** Правило, skill, agent, скрипт или hook
   правится в `harness/` репозитория worfy обычным PR. После мержа PR, который трогает `harness/`,
   Orchestrator запускает `pnpm install:stable`. Новая Stable copy при запуске ставит Harness своей
   версии (ADR-0040), и урок действует со следующей Session. Где лежат уроки Project-а, по-прежнему
   задаёт его Profile (поле `lessons`; у worfy — `docs/lessons/`).
2. **История `~/.claude` переходит в `harness/`.** Ticket 02 импортирует в `harness/` файлы Harness
   из `~/.claude` вместе с их git-историей — только файлы из списка переноса (пункт 5). Уроки
   ссылаются на коммиты этой истории, и она остаётся рядом с Harness.
3. **После мержа Ticket-а 02 `~/.claude` заморожен.** Правки Harness идут только в `harness/`, в
   файлы `~/.claude` их больше не вносят. До перехода машины владельца (пункт 4) такие правки не
   действуют: Session-ы владельца идут на замороженных файлах.
4. **Машина владельца переходит на plugin рано.** Wave-ы до установщика (Ticket 13) и переноса
   (Ticket 14) ведёт Autopilot на старых файлах; установщик и перенос проверяются в песочнице. Затем
   Autopilot останавливается, и переход делает владелец — Ticket 16 (шаг владельца): кнопка в worfy
   и подтверждение списка «уберу / оставлю». После этого Orchestrator проверяет: в `~/.claude` только
   личное, Session видит plugin `worfy`, `epic-status` и Gate работают. Autopilot Ticket 16 не берёт.
   Все дальнейшие Wave-ы E3 идут на plugin. Откат — восстановление из резервной копии одной командой.
5. **Что переносится.**
   - В plugin: общие правила `CLAUDE.md`; agents implementer, reviewer, scout; семь skills
     (epic-wave, ship-ticket, retro, qmd, overnight-fix-loop, continuous-audit, tickets-to-tasks);
     `bin/`, кроме личных скриптов владельца (`telegram-mcp`, `auction-staging-db-mcp`,
     `agent-time-split`); `hooks/`.
   - Из конфигурации пользователя убираются записи hooks в `~/.claude/settings.json`, которые ведут
     в эти файлы, и запись qmd в `~/.claude.json`: MCP-сервер qmd теперь регистрирует plugin, и
     вторая запись запустила бы второй qmd (ADR-0043).
   - В `~/.claude/worfy-harness/` переезжают реестр Gate (`gate/config.json`), `gate/state`,
     Profile-ы (в schema 2, ADR-0042) и замки worktree.
   - Остаются: личные skills (cloudflare*, sandbox*, wrangler, sentry-cli, web-perf, turnstile-spin,
     agents-sdk, durable-objects и другие), `skills/synced`, личные MCP-серверы, настройки (`model`,
     `env`, `effortLevel`), память, транскрипты.
   - Мост Limits (`statusLine`, сейчас — `scripts/statusline-bridge.sh` в dev-checkout) переходит на
     скрипт из `.app`; запись `statusLine` меняется с согласия, в той же форме (Ticket 15).
   - Plugin `worfy` объявляет зависимость `mattpocock-skills`: её skills вызывают continuous-audit и
     tickets-to-tasks.
6. **Резервная копия и откат.** Перед удалением файлы копируются в
   `~/.claude/worfy-harness/backup-<дата>/`, а не в `~/.claude/backups/`: эту папку занимает Claude
   Code. Удаления из `~/.claude` — одним коммитом в его git. Откат — восстановление из копии и revert
   этого коммита. Как быть, если `~/.claude` не git-репозиторий, это решение не задаёт — решает
   Ticket 14.
7. **Без пересборки во время Autopilot.** Пока идёт прогон, Stable copy не пересобирается. Урок
   мержится, а прогон доходит до конца на старом Harness. В отчёте прогона и в worfy — пометка
   «Harness в main новее, чем в Stable copy» (Ticket 21). Пересборка — когда прогон не идёт: из CLI
   или `pnpm install:stable`. Пункт 1 действует только вне прогона.
8. **Перенос — исключение из ADR-0005.** Код worfy пишет в `~/.claude` (удаляет перенесённые файлы,
   правит записи `settings.json`, делает коммит в его git), в `~/.claude.json` (запись qmd) и в
   `~/.claude/worfy-harness/` (резервная копия, реестр Gate, `gate/state`, Profile-ы) — только после
   того, как пользователь подтвердил список «уберу / оставлю». Экран первого запуска предлагает
   перенос и делает его тоже только с подтверждения (Ticket 19). Установка plugin — отдельное
   исключение, ADR-0040. Перенос тестируется в песочнице — с отдельными `HOME` и `CLAUDE_CONFIG_DIR`
   во временной папке, — а не на настоящем `~/.claude`. Песочнице нужен свой `/login` (факт spike
   выше); его делает владелец, агенты в аккаунт не входят.

**Что меняется в прежних ADR.**

- ADR-0019 (Harness — plugin, его ставит worfy): фраза «до конца E3 владелец работает со старыми
  файлами в `~/.claude`» больше не верна — машина владельца переходит на plugin в Ticket-е 16,
  посреди E3. Резервная папка из ADR-0019 теперь названа: `~/.claude/worfy-harness/backup-<дата>/`.
  Правило ADR-0019 «ничего не удаляется» держится так: файлы не теряются — они в резервной копии, а
  удаление из `~/.claude` — один коммит, который откатывается.
- ADR-0005 (worfy ничего не пишет вне своей папки данных, кроме регистрации Project в Gate; ADR-0019
  добавил установку plugin и перенос в резервную папку): к записям вне папки данных добавляются
  правки `~/.claude/settings.json` и `~/.claude.json`, коммит в git `~/.claude` и папка
  `~/.claude/worfy-harness/`. Все они — только после подтверждения пользователя.

**Последствия.**

- Урок начинает действовать не сразу: нужны мерж PR и пересборка Stable copy, а во время прогона —
  ещё и конец прогона.
- Между мержем Ticket-а 02 и Ticket-ом 16 правки Harness не действуют нигде: в `~/.claude` их не
  вносят, а plugin ещё не стоит. Wave-ы этого отрезка идут на правилах дня импорта.
- После Ticket-а 16 Wave-ы E3 идут на Harness, который сами меняют; каждая следующая Wave — на
  Harness последней пересборки. Это пункт приёмки E3: на машине владельца в `~/.claude` только
  личное, и одна Wave Autopilot прошла на plugin без человека.
- Пометка «Harness в main новее» показывает, что прогон идёт не на последнем Harness. Пересобрать
  Stable copy — шаг того, кто запускает следующий прогон.
- Риск: если hooks plugin не доходят до Subagent-ов Workflow-скриптов, после переноса правила
  `CLAUDE.md` до них не дойдут. Ответ даст Ticket 01 (ADR-0048).

## Considered Options

- **Урок — PR в `harness/`, пересборка Stable copy вне прогона** (выбрано).
- **Plugin из основного checkout-а worfy**: локальный marketplace на `harness/` рабочей копии, урок
  действует сразу после мержа. Отвергнуто владельцем: Harness расходится с версией приложения —
  Stable copy, собранная раньше, шла бы на более новом Harness, а worfy читает вывод скриптов Harness
  и формат Ticket-ов (ADR-0019).
- **Личный слой в `~/.claude` с переносом в `harness/` раз в Epic.** Отвергнуто владельцем: правила
  жили бы в двух местах, и до переноса машина владельца шла бы не на том Harness, что лежит в
  репозитории.
- **Autopilot сам пересобирает Stable copy и перезапускается.** Отвергнуто владельцем: прогон
  заменял бы `.app`, из которого сам идёт, и перезапускал бы свои Session-ы посреди Epic-а.
- **Переход машины владельца в конце E3, как писал ADR-0019.** Не выбрано: Wave-ы E3 до конца шли бы
  на старых файлах, и plugin на настоящей машине впервые заработал бы только в приёмке. Ранний
  переход даёт оставшимся Wave-ам E3 идти на plugin.
- **Переход делает Autopilot.** Не выбрано: список «уберу / оставлю» подтверждает пользователь
  (ADR-0019), а Autopilot идёт без человека.
- **Проверять установщик и перенос на настоящем `~/.claude`.** Не выбрано: ошибка переноса сломала
  бы Harness, на котором идут Wave-ы. Песочница с отдельными `HOME` и `CLAUDE_CONFIG_DIR` даёт ту же
  проверку без этого риска, ценой одного `/login`.
