# 0081 — CI на Linux на каждый PR shard-ами и test-ы, которые задевает diff; полный набор — на `main` batch-ем; частично заменяет ADR-0068 и ADR-0065
Дата: 2026-10-20. Статус: принят 2026-10-20. Каждый пункт вступает в силу, когда вливается его Ticket
Epic-а `worfy-throughput`: пункт 1 — Ticket 12, пункты 2 и 4 — Ticket 11, пункт 3 — Ticket 13.

**Контекст.** Сейчас перед merge PR с кодом проходит `GATE_SCOPE=all` gate full на Mac: lint, typecheck,
весь `pnpm test`, весь `test:e2e` и `test:package` — на наборе готовых PR Wave (ADR-0065) или на каждом PR.
CI на PR нет (ADR-0068): GitHub CI идёт на `main` один раз на Wave, красный batch CI run — без revert.

Замер 2026-10-20 (Epic `worfy-throughput`, раздел «Решения владельца 2026-10-20» его spec-а):

- Test-файлов в `test/unit`, `test/contract`, `test/e2e` — 173 на 2026-10-07 и 435 сейчас (224 / 123 /
  88): около 20 в день, в 2,5 раза за 13 дней. Около 3260 unit, 2190 contract и 290 e2e test case-ов.
- gate (`harness/hooks/gate.mjs`) сужает набор только по пакету. worfy — один пакет, поэтому любая
  правка `.ts` запускает весь список скриптов. Выбора test-ов по diff и shard-ов нет.
- Playwright идёт в один поток (`workers: 1`, `fullyParallel: false`); 87 из 88 e2e-файлов запускают Electron
  (`launchApp` → `_electron.launch`, `test/e2e/helpers.ts:146`), кроме `linked-autopilot.spec.ts`.
- Job `check` в `ci.yml` на `main` — медиана 14,4 min, максимум 18,3 min по 37 зелёным CI run-ам; unit +
  contract — около 16 из 18 min на стандартном runner-е `ubuntu-latest` (для приватного репозитория —
  2 vCPU; по логу CI не подтверждено).
- Время gate fast и gate full на Mac неизвестно: gate не печатает длительность шагов.
- Под нагрузкой полного набора test-ов появляются flaky test-ы (`worfy-polish` 30, 32, 34).

Каждый PR платит за весь набор, а набор растёт. Время от зелёных проверок до merge растёт вместе с ним.

**Решение** (владелец, 2026-10-20, ответы на вопросы Q1–Q7: «Да на все семь, начинай с Q7»).

1. **CI на Linux на каждый PR.** unit и contract test-ы идут на каждый PR в 3–4 параллельных shard-ах на
   `ubuntu-latest`. Job-ов на macOS на PR нет. Это заменяет ADR-0068 в части «GitHub CI не gate перед
   merge PR» и «`ci.yml` запускается только вручную» (пункты 1 и 4) и прежнее правило владельца «без
   матриц в CI».
2. **PR вливается по test-ам, которые задевает его diff.** Перед merge — CI на Linux (пункт 1) и test-ы,
   которые задевает diff PR. gate full на каждый PR и на наборе Wave перед merge не нужен. Исключение —
   ADR-0065, пункт 5: платформенный PR и PR с меткой `needs-mac-gate` по-прежнему проходят свой gate
   full. Это заменяет ADR-0065, пункт 2 («один gate full на набор вместо rebase и gate full на каждый
   PR»), в части «gate full — условие merge».
3. **e2e и собранное приложение до merge — только по путям.** Весь `test:e2e` и `test:package` идут
   перед merge, только когда diff трогает renderer, main process, упаковку или watcher-ы. Список путей —
   поле Profile-а Project-а. Иначе — ночной run на `main`.
4. **Полный набор — на `main` batch-ем; красный `main` — bisect и revert.** Batch CI run на `main`
   (ADR-0068, пункт 2) остаётся и идёт на полном наборе. Красный полный набор — поиск виноватого
   commit-а делением пополам и revert его PR, автоматически. Это заменяет ADR-0068, пункт 3 («красный
   batch CI run — без revert, исправление вперёд»).
5. **Метрика и бюджет.** Метрика — время на часах от «проверки зелёные» до merge, по Ticket-у. Бюджет —
   15 min для Ticket-а без UI, 30 min для Ticket-а с UI. Превышение попадает в отчёт.
6. **Сначала замер.** Пункты 1–5 вводятся только после того, как gate печатает время шагов, а vitest и
   Playwright пишут время каждого test-файла (Ticket 10 Epic-а `worfy-throughput`).
7. **Аудит test-ов — после пунктов 1–4.** Дублирующий test убирается или сливается только с
   доказательством, что код остаётся покрыт (coverage или mutation testing). Новый test — в одном слое;
   второй слой требует причины в описании PR.

Что остаётся в силе: ADR-0065, пункты 4 и 5 (сверка дерева `main` на каждом merge; платформенные PR и
PR с меткой `needs-mac-gate` — по одному); ADR-0068, пункт 2 (batch CI run на `main` после Wave) и пункт
5 (режим включается полем Profile-а, другие Project-ы не меняются); ADR-0056 и ADR-0071 (вердикт Windows
для платформенных PR). ADR-0071, пункт 6, опирается на ADR-0068, пункт 3 (красный `main` — исправление
вперёд), который этот ADR заменяет; что делать с красным Windows run-ом на `main` — открытый вопрос,
записан в «Открытые вопросы» Ticket-а 11.

Как именно считать задетые test-ы, сколько shard-ов (3 или 4), чинить или убирать в карантин flaky test
на PR, кто запускает ночной e2e без job-а на macOS — не решено. Эти вопросы лежат в Ticket-ах 11–14 Epic-а
`worfy-throughput` и решаются по числам Ticket-а 10.

**Последствия.**

- PR получает ответ CI на Linux за время одного shard-а, а не всего набора; цель — уложиться в бюджет
  пункта 5.
- Сбой в test-е, который diff не задевает по графу, попадает в `main` и находится batch-ем. Цена — bisect
  и revert; `main` между batch-ами может быть красным.
- Граф import-ов не видит test-ы, которые запускают скрипты процессом (87 unit- и contract-файлов). Без
  таблицы таких связей выбор по diff пропускал бы именно их.
- Минут Actions больше: 3–4 shard-а на каждый push в PR против одного batch CI run-а на Wave. 2026-10-17
  бюджет Actions уже кончался (ADR-0068).
- UI-правка без e2e до merge невозможна, правка вне списка путей — возможна; e2e-сбой такой правки
  находится ночью.
- Переход нельзя растянуть: правка `ci.yml` действует на все PR в момент merge, поле Profile-а — после
  обновления Harness (тот же порядок, что у ADR-0068).

## Considered Options

- **Оставить как есть (ADR-0065 + ADR-0068).** Один gate full на Wave, CI только на `main`. Время до merge
  растёт с набором test-ов: около 20 файлов в день.
- **CI на PR одним job-ом, весь набор.** Около 16 min unit + contract на каждый PR: дольше бюджета 15 min
  для Ticket-а без UI ещё до gate на Mac.
- **CI на PR в shard-ах на Linux плюс задетые test-ы (выбрано).** Быстрый ответ на PR; полный набор — на
  `main`; цена — красный `main` между batch-ами и минуты Actions.
- **Job-ы на macOS на PR (e2e в CI).** Отвергнуто владельцем (Q4): минута macOS-runner-а в десять раз
  дороже Linux.
