# 0089 — Update Stable copy: worfy собирает `main` в своём clone на машине пользователя; GitHub Releases, подпись и нотаризация остаются в E4
Дата: 2026-10-31. Статус: принят. Действует для Stable copy на macOS и Windows. Epic — `worfy-update`
([spec](../../.scratch/worfy-update/spec.md)).

**Контекст.** Stable copy (`~/Applications/worfy-stable.app` на macOS, `%LOCALAPPDATA%\worfy-stable` на
Windows) сегодня обновляет только человек: `pnpm install:stable` в своём checkout-е
(`scripts/install-stable.mjs`). Скрипт собирает приложение (`pnpm package`), меняет копию и удаляет прежнюю
(`scripts/install-stable.mjs:804-811`), а пока копия запущена — отказывается (`:711-720`). Сам worfy о новой
версии не знает: build version `<semver>+<short SHA>` (`scripts/build-version.ts:14-19`) приложение
показывает в toolbar, но с `main` не сравнивает. Отставание Harness в `main` видно только Autopilot-у над
самим worfy (`src/main/autopilot/harness-drift.ts`, ADR-0047). Опубликованных сборок нет:
`electron-builder.yml:91` — `publish: null`. Подпись Developer ID, нотаризация Apple и подпись установщика
Windows по roadmap — в E4 («Для других людей») и только при первом внешнем пользователе (ADR-0019).
Репозиторий `IDSAD-XL/worfy` публичный, у каждого push в `main` есть check `ci-ok` (ADR-0083).

**Решение** (владелец, 2026-10-31).

1. **Источник — `main` через GitHub API без входа.** worfy читает SHA головы `main` при старте и раз в час.
   Нет сети или GitHub не ответил — проверка молча пропускается. Токен `gh` пользователя не используется
   никогда.
2. **Available update** — голова `main` новее запущенной Stable copy, её `ci-ok` от push — `success`, и
   между двумя commit-ами меняется приложение или Harness. Commit-ы, которые правят только документы и
   Ticket-ы, Update не предлагают.
3. **Сборка — в одном постоянном clone в папке данных worfy**: `~/Library/Application Support/worfy/update/`
   на macOS, `%APPDATA%\worfy\update\` на Windows. Clone переиспользуется между Update-ами (около 2–3 GB).
   Сборка — та же, что у `pnpm install:stable`. Checkout пользователя и папки его Project-ов worfy не
   трогает (ADR-0005). На машине нужны `node` и `pnpm`.
4. **Замена — после выхода worfy.** Отдельный процесс ждёт, пока worfy закроется, ставит новую копию на
   место Stable copy и запускает её. Прежняя копия остаётся рядом как `worfy-stable.previous`, одна. Откат
   из Settings возвращает её.
5. **Перезапуск — только кнопкой пользователя.** «Update automatically» (по умолчанию включено) собирает в
   фоне. Готовую сборку ставит «Restart now», а пока Session в ходе или идёт Autopilot — «Restart when
   idle». Нажатие — согласие и на Harness новой копии: он ставится после перезапуска без второго диалога и
   действует со следующей Session.
6. **Сбой сборки оставляет текущую Stable copy.** Повтор — на следующем новом commit-е или по «Check now».
7. **Dev-сборка Update не проверяет и не предлагает.** macOS и Windows — одинаково.
8. **GitHub Releases, `electron-updater`, подпись Developer ID и нотаризация в этот Epic не входят** — они
   остаются в E4.

**Последствия.**

- Главный компромисс: обновление работает без подписи, нотаризации и выпуска сборок, но только на машине,
  где есть `node`, `pnpm`, `git` и 2–3 GB места, и только из исходников `main`. Человеку без этих
  инструментов Update недоступен — Settings → Health называет, чего нет. Это совпадает с сегодняшним
  кругом пользователей worfy: его собирают из исходников (ADR-0019).
- Сборка на самой машине не проходит Gatekeeper как скачанное приложение: у файлов нет отметки quarantine,
  копия подписана ad-hoc, как после `pnpm install:stable`. Когда в E4 появятся подписанные сборки,
  источник Update сменится на них, а сигналы, Settings и откат этого Epic-а останутся.
- В папке данных worfy появляется папка `update/`: clone, журнал сборки, состояние. Это своё состояние
  worfy по ADR-0005; его не видят Linked machine-ы (каналы `local`).
- `scripts/install-stable.mjs` получает режим, который ждёт выхода запущенной копии, оставляет прежнюю как
  `worfy-stable.previous` и умеет откат. Ручной `pnpm install:stable` по-прежнему удаляет прежнюю копию.
- Сборка Update запускает `pnpm install` и скрипты пакетов `main` на машине пользователя. Код при этом тот
  же, что пользователь собрал бы руками, но собирается без его команды. Граница доверия — зелёный `ci-ok`
  на этом commit-е.
- Без входа GitHub даёт 60 запросов в час с одного адреса. Проверка тратит 1–4 запроса в час; превышение
  лимита — та же молчаливая пропущенная проверка, что без сети.

## Considered Options

- **Сборка в своём постоянном clone в папке данных worfy** — выбрано. Без подписи и выпуска сборок,
  повторная сборка тянет только изменения. Цена — инструменты сборки на машине и 2–3 GB.
- **GitHub Releases и `electron-updater`.** Отложено в E4: обновление приложения на macOS требует подписи
  Developer ID, а значит, и выпуска подписанных сборок на каждый commit `main`. Это и есть работа E4.
- **Скачивать сборку из artifacts CI.** Отвергнуто: GitHub отдаёт artifacts только с входом, даже у
  публичного репозитория, и хранит их ограниченное время. Сборка из artifact-а к тому же не подписана, и
  на скачанное приложение macOS ставит quarantine.
- **Собирать в checkout-е пользователя.** Отвергнуто: worfy не пишет в репозитории пользователя (ADR-0005),
  а в checkout-е бывают незакоммиченные правки и чужие ветки.
- **Новый временный clone на каждый Update.** Отвергнуто: каждый раз скачивается вся история и ставятся все
  зависимости, и на Windows временная папка чистится сама.
