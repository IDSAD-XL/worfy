# 0022 — Session без человека отклоняет смену режима разрешений
Дата: 2026-10-06. Статус: принят.

**Контекст.** Autopilot запускает Session-ы, рядом с которыми нет человека. Такая Session стартует
в `bypassPermissions` (Ticket 02 Epic worfy-daily). Пользователь может открыть её в worfy и сменить
режим посреди хода. В любом режиме, кроме `bypassPermissions`, Claude Code перед tool спрашивает
разрешение. Ответить на запрос некому, и прогон висит до утра.

**Решение.** Смена режима разрешений у Session без человека отклоняется: ответ IPC объясняет
причину, режим остаётся `bypassPermissions`. Изменение, в котором режима нет или режим —
`bypassPermissions`, проходит как обычно: модель и effort такой Session менять можно. Изменение,
в котором вместе с моделью или effort просит другой режим, отклоняется целиком. Признак «без
человека» живёт только в памяти main на время жизни Session и в `session-settings.json` не пишется.
У обычной Session смена режима работает как раньше.

**Последствия.** Чтобы работать с Session в другом режиме, пользователь останавливает Autopilot.
Ticket 04 Epic worfy-daily пишет любую попытку человека вмешаться в прогон в журнал как
`human-input`; отклонённая смена режима — тоже такая попытка.

## Considered Options

- Отклонять смену режима (выбрано). Прогон не зависает, причина видна сразу в ответе IPC.
- Поставить прогон на паузу и применить режим. Отвергнуто: человек явно у экрана, но Autopilot
  должен знать, когда он ушёл, чтобы продолжить. Сигнала «ушёл» нет: пауза превращается в
  остановку, о которой Autopilot не узнает.
- Применить режим молча. Отвергнуто: первый же запрос разрешения повесит прогон — тот самый
  дефект, который закрывает Ticket 02.
