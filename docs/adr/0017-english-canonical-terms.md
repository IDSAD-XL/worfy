# 0017 — Канонические термины английские; принятые ADR правятся только в терминах
Дата: 2026-10-06. Статус: принят.

**Контекст.** До 2026-10-06 словарь `CONTEXT.md` называл понятия по-русски: Проект, Холст, Узел,
Карточка, Раскладка, Сессия, Оркестратор, Эпик, Тикет. ADR-0010…0016 написаны в этих словах.
Интерфейс worfy при этом английский: `docs/design/BRIEF.md` требует в UI ровно слова Project,
Canvas, Node, Card и так далее. Одна вещь получала два имени — «Узел» в документах и Node на
экране, — и поиск по одному имени не находил текст, где стоит другое.

**Решение.** Канонические термины — английские, как в интерфейсе: Project, Canvas, Node, Card,
Layout, Limits, Terminal, Epic, Ticket, Wave, Autopilot, Gate, Harness, Profile, HANDOFF, Session,
Orchestrator, Subagent, Binding. Текст вокруг них остаётся русским. Термин пишется с заглавной
буквы, русское окончание — через дефис: Ticket-ы, Epic-и. Русские слова для этих понятий стоят в
`CONTEXT.md` в строках _Avoid_ и в новых текстах не используются.

ADR по-прежнему не переписывают, с одним исключением: в принятом ADR старое слово можно заменить
каноническим термином. Смысл решения, дата и статус при такой правке не меняются. Любое изменение
смысла — только новым ADR, который ссылается на старый.

**Последствия.** ADR-0001…0016 приводятся к новым терминам без новых ADR. Ревьюер такой правки
проверяет одно: в diff заменены только слова из словаря, ни одно утверждение не изменилось.

## Considered Options

- Русские канонические термины, как было. Отвергнуто: интерфейс английский, и у каждого понятия
  остаются два имени — в тексте и на экране.
- Английские термины только в новых документах, принятые ADR не трогать. Отвергнуто: поиск по
  термину (`qmd`, grep) не находит ранние ADR, а читатель видит два слова для одной вещи.
- Новый ADR на замену каждому старому ради терминов. Отвергнуто: шестнадцать ADR без нового
  решения, и ссылки «заменяет ADR-…» ничего не сообщают.
- Английские термины везде, принятые ADR правятся только в терминах (выбрано).
