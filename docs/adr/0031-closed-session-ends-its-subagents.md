# 0031 — Закрытая Session кончает своих Subagent-ов
Дата: 2026-10-06. Статус: принят.

**Контекст.** После ADR-0030 (task-notification из очереди) на Auction из 3179 Subagent-ов
`running` остался один. Уведомления о нём нет нигде: последняя запись его транскрипта — вызов
WebFetch (`stop_reason: tool_use`), а Session давно закрыта — записи в `~/.claude/sessions/` нет.
Без правила он показывается `running` навсегда, с растущим временем, и renderer опрашивает его
Session каждые 2 секунды.

Фоновый Subagent живёт в процессе Claude Code своей Session: процесс кончился — кончились и его
Subagent-ы (ADR-0029, контекст: закрытая Session Autopilot унесла четыре background task-а).

**Решение.**

1. **Закрытая Session кончает всех, кто не кончился.** main (`SubagentReader`) перед чтением
   файлов Session спрашивает `sessions/<pid>.json` той же домашней папки Claude, как реестр
   Session-ов (`src/main/claude-home/registry.ts`, Ticket 13 worfy-mvp). Session жива, если есть
   запись с её `sessionId` и процесс `pid` с этим `procStart` идёт. Если такой записи нет или её процесс `gone` (пункт 3) — к
   сигналам Session добавляется `session-closed`, и каждый её Subagent без конца получает статус
   `error`, как остановленный пользователем. Время его работы кончается его последней записью.
2. **Пока Session жива, Subagent без конца — `running`**, сколько бы его файл ни стоял. Ложный
   `done` или `error` у живого длинного Subagent-а хуже зависшего `running`.
3. **Не знаем — не закрываем.** `session-closed` не ставится, если транскрипт не под `projects/`,
   в домашней папке нет `sessions/`, запись реестра не читается (её могут переписывать в этот
   момент) или нельзя узнать, идёт ли процесс: `ps` не нашёлся, не уложился в 5 секунд, был убит
   или ничего не напечатал. Проверка процесса даёт три исхода — `alive`, `gone`, `unknown`
   (`processState()` в `registry.ts`). `gone` — процесса нет (`kill -0`), `ps -p` кончился кодом
   1 без вывода (процесс кончился между двумя проверками) или `procStart` другой (pid занят
   другим процессом). Сам реестр Session-ов по-прежнему считает `unknown` «не живой»
   (`processAlive()`).
4. **Порядок чтения.** Живость спрашивается до чтения файлов: если Session уже закрыта, в файлах
   уже лежит всё, что она написала, и Subagent, кончившийся перед самым выходом процесса, читается
   кончившимся, а не оборванным.
5. Тип `SubagentStatus` не меняется: `running | done | error`.

**Последствия.**

- На Auction после ADR-0030 и этого правила: `running` — 0 (живых Session-ов Auction в момент
  замера не было), `done` — 3127 (было 2834), `error` — 52 (было 34); по этому правилу `error`
  получил один Subagent.
- Subagent, оборванный закрытием Session, показывается `error` с последним текстом из его файла.
  Опрос его Session в renderer прекращается.
- main при каждом чтении Subagent-ов Session читает `sessions/*.json` и для записи этой Session
  проверяет процесс (`kill -0`, `ps -o lstart=`).
- Не проверено: Session, сменившая `sessionId` внутри одного процесса (например `/clear`), —
  запись реестра уже называет новый id, и Subagent-ы старого транскрипта, если они живут дальше,
  будут показаны `error`.

## Considered Options

- **Новый статус `stale` («не отвечает»).** Отвергнут: после ADR-0030 он нужен одному Subagent-у
  из 3179. Он меняет `SubagentStatus` и все его потребители — Node и строку rail-а (там
  исчерпывающие таблицы статусов), опрос, свёртку `done` на Canvas, — а по смыслу это тот же конец
  без результата, что и `stoppedByUser`, который уже `error`.
- **`running` → `done`, если файл не менялся N минут.** Отвергнут: живой Subagent часто молчит
  долго (`gh run watch` с timeout 600000, длинный test-раннер); правило дало бы ложный `done`.
- **`running` → `error` по тишине файла и закрытой Session вместе.** Отвергнут как лишний: закрытой
  Session достаточно — её Subagent-ы не могут работать, тишина ничего не добавляет.
- **Сбой `ps` считать «процесса нет», как `processAlive()`.** Отвергнут ревью PR #45: при
  недоступном `ps` работающий Subagent живой Session показывался `error`, и опрос его Session
  прекращался.
