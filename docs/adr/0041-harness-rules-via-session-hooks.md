# 0041 — Правила Harness доходят до Session и Subagent-а через hooks `SessionStart` и `SubagentStart`
Дата: 2026-10-07. Статус: принят.

**Контекст.** Общие правила Harness сегодня лежат в глобальном `~/.claude/CLAUDE.md` владельца:
262 строки, 13 489 байт, по-английски. Это правила Orchestrator-а (главной Session Project-а):
когда звать Subagent-ов и что требовать от них, Profile и коды выхода его скрипта, фазы работы,
Gate, блок статуса «— Этап / Сейчас / Дальше / Жду» в конце хода, простой язык. Рядом с общими
правилами в файле есть личные строки владельца. Claude Code грузит этот файл в каждую Session
пользователя.

Harness становится plugin-ом `worfy` (ADR-0019, ADR-0040), а plugin `CLAUDE.md` не несёт: файл в
корне plugin Claude Code не грузит, `claude plugin validate` о нём предупреждает. Документация
советует skill для инструкций и hook для правил, которые должны действовать всегда. Факты о hooks
из документации: hooks plugin и hooks из `settings.json` запускаются оба, параллельно;
`SessionStart` срабатывает на startup, resume, clear, compact и fork; `SubagentStart` тоже может
вернуть `additionalContext`; одна строка `additionalContext` ограничена 10 000 символами, а более
длинная уходит в файл, и в контекст попадает превью на 2 000 символов.

Spike 2026-10-07 (Agent SDK 0.3.289, встроенный Claude Code 2.1.289) проверил опытом: hooks
plugin `SessionStart` и `SubagentStart` с `additionalContext` доходят до главной Session и до
Subagent-а — да (контрольные строки из hook-ов дошли в обоих). До Subagent-ов, которых
запускает workflow-скрипт (ADR-0035), — не проверено; это проверяет Ticket 01
Epic-а E3 `worfy-harness` (spike; итог — ADR-0048).

Решение владельца 2026-10-07 по вопросу Q9 Session проектирования E3.

**Решение.**

1. **Правила Harness приходят из hooks plugin `worfy`.**
   - `SessionStart` отдаёт главной Session общие правила: Orchestrator, Subagent-ы, Gate, блок
     «— Этап / Сейчас / Дальше / Жду».
   - `SubagentStart` отдаёт Subagent-у только его часть: простой язык, «доказательство перед
     словом "зелено"» (без кода выхода и вердикта Gate проверку не называют пройденной), гигиена
     контекста.
2. **Каждая часть — не больше 10 000 символов**, чтобы она целиком попала в контекст, а не в
   превью. Не помещается — правила сжимаются или делятся на две части.
3. **Текст частей лежит в `harness/`** и выходит вместе с версией приложения (ADR-0040). Связка
   hooks — `harness/hooks/hooks.json`. Части пишутся по-английски (ADR-0044); пишет их Ticket 05.
4. **В `~/.claude/CLAUDE.md` пользователя остаётся только личное.** Общие правила уходят из него
   при переносе (форма «уберу / оставлю», ADR-0047, Ticket 14).

Правила Project-а (`rules.md` его Profile) тоже подмешивает только Harness, а не файл в
репозитории; это решает ADR-0042.

**Последствия.**

- Правила действуют в любой Session, где включён plugin `worfy`: в worfy и в терминале. Удаление
  plugin убирает их целиком; в файлах пользователя от Harness ничего не остаётся.
- `SessionStart` срабатывает и на compact: после сжатия контекста правила приходят заново.
- Нынешние 13 489 байт в одну часть не помещаются. Ticket 05 сжимает их или делит на части, и
  при сжатии правило может потеряться — это риск Ticket-а 05.
- Одинаково ли модель следует `additionalContext` и `CLAUDE.md`, заранее не известно. Итоговая
  проверка — первая Wave после перехода машины владельца на plugin (ADR-0047).
- Hooks из `settings.json` и hooks plugin работают параллельно. Пока в `settings.json` владельца
  остаются записи старых hooks Harness, они запускаются вместе с новыми; перенос их убирает
  (ADR-0047).
- Дойдут ли правила до Subagent-ов workflow-скриптов, покажет Ticket 01. Что делать, если не
  дойдут, решает ADR-0048.

## Considered Options

- **Hooks `SessionStart` и `SubagentStart` с `additionalContext`, части ≤ 10 000 символов**
  (выбрано). Работает везде, где включён plugin, и повторяется после compact; файлы пользователя
  не меняются.
- **Строка `@<путь к правилам>` в `~/.claude/CLAUDE.md` пользователя.** Отвергнуто: это правка
  файла пользователя, и строка остаётся там после удаления plugin.
- **`settings.agent` plugin** (главная Session идёт как агент plugin). Отвергнуто: подменяет
  системный prompt главной Session.
- **`CLAUDE.md` в корне plugin.** Отвергнуто: Claude Code его не грузит.
- **Правила только в skill.** Отвергнуто: skill грузится по вызову, и правило «всегда» перестаёт
  действовать всегда.
- **`systemPrompt.append` в Session-ах worfy.** Отвергнуто: работает только в worfy, а Harness
  должен действовать и в терминале (ADR-0019).
