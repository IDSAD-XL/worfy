# 0045 — Один Ticket — один репозиторий; Project над несколькими репозиториями — Silent mode; без прав на PR — локальный финиш
Дата: 2026-10-07. Статус: принят.

**Контекст.** По ADR-0018 Project — папка с workflow: сам git-репозиторий или папка над несколькими
репозиториями. Пример второго — Atakama: три репозитория (`Atakama-Browser-Extension`,
`Atakama-Browser-Server`, `Atakama-Browser-Shared`), их список уже есть в Profile Atakama
(`layout.repos`). ADR-0018 оставил на конец E3 главное: всё, что в worfy считает Project одним
репозиторием, должно работать по каждому репозиторию внутри — ветки и worktree Ticket-ов, PR и CI
(`src/main/github/prs.ts` вызывает `gh pr list` в корне Project), Gate, слежение за git.

Сегодня у Ticket-а одна ветка (`<epic>/<NN>`), одно worktree и не больше одного PR: `ticket done
<epic> <NN> [--pr N]` принимает один номер PR, а worfy находит PR и CI Ticket-а по его ветке. Чем
кончается Ticket, задаёт поле Profile `workflow.finish` (`~/.claude/profiles/README.md`):
`pr-green-ci` — PR с зелёным CI, мержит Orchestrator (так у worfy и Auction); `local-green` —
локально зелёные проверки, без PR и без мержа (так у Atakama).

Spike Epic-а `worfy-harness` 2026-10-07 показал: Atakama уже почти в Silent mode (режим, в котором
файлы workflow лежат вне git, ADR-0042). Её `.scratch/` и `HANDOFF.md` лежат в
`/Users/alexey/Work/Atakama` — папке над тремя репозиториями, вне git. У Auction, наоборот, 822
файла `.scratch/` под git.

С E3 Project подключают и другие люди (ADR-0019). У них может не быть прав открывать PR в
репозиторий, а у репозитория может не быть `origin`.

**Решение.** Решения владельца 2026-10-07: вопрос Q29 (Ticket и репозитории) и вопрос Q30 (финиш
без прав) Session проектирования Epic-а `worfy-harness`.

1. **Один Ticket — один репозиторий.** Функция, которая затрагивает три репозитория, — три Ticket-а
   со связями `Blocked by` между ними. У Ticket-а одна ветка, одно worktree и не больше одного PR —
   в своём репозитории.
2. **Node Ticket-а на Canvas показывает его репозиторий.** Gate, PR и CI Ticket-а берутся по его
   репозиторию, а не по корню Project. Как файл Ticket-а называет свой репозиторий, это решение не
   задаёт: это задача Ticket-а 22 (Silent mode в Harness) и Ticket-а 23 (worfy читает Project над
   несколькими репозиториями).
3. **Project над несколькими репозиториями — всегда Silent mode** (ADR-0042). Его Workflow folder
   (папка, где лежат файлы workflow Project-а) по умолчанию — папка над репозиториями, как у
   Atakama: её `.scratch/` и `HANDOFF.md` остаются на месте.
4. **Финиш зависит от прав.**
   - Есть права на PR в `origin` — финиш через PR (`workflow.finish: pr-green-ci`), как сейчас.
   - Нет прав или нет `origin` — локальный финиш: Ticket закрывается, когда локальный `gate full`
     зелёный и ветка влита локально. Сегодня `local-green` ветку не вливает; вливание — новое.
   - PR из форка — позже, не в E3.

   Значение пишется в Profile при подключении Project (Ticket 24 — подключение, Ticket 25 —
   аккаунт GitHub Project-а). Как именно проверяются права, это решение не задаёт.

**Что меняется в прежних ADR.** ADR-0018 оставлял открытым, как ветки, PR, CI и Gate работают в
папке над репозиториями. Ответ: по репозиторию Ticket-а, один репозиторий на Ticket. Остальное в
ADR-0018 в силе.

**Последствия.**

- Функция через несколько репозиториев становится цепочкой Ticket-ов. Wave вычисляется по
  `Blocked by`, как раньше: Ticket второго репозитория ждёт, пока закроется Ticket первого.
- worfy ищет PR и CI не в корне Project, а в репозитории каждого Ticket-а (Ticket 23). Для Project
  из одного репозитория ничего не меняется.
- Gate Project-а над репозиториями прогоняется в репозитории Ticket-а. Каждый репозиторий
  зарегистрирован в Gate своей записью, которая называет общий Profile, — так Atakama устроена уже
  сегодня (ADR-0018).
- В Silent mode ветка не несёт номера Ticket-а (ADR-0042). Связь Ticket-а с его веткой и PR нельзя
  взять из имени ветки, как сегодня; как её находить, решают Ticket-ы 22 и 23.
- При локальном финише нет PR и CI, которые видят другие люди: готовность доказывает только
  локальный `gate full`. Строка `Status: done` пишется без `--pr`. Описание `local-green` в контракте
  Profile и шаги финиша в skills `ship-ticket` и `epic-wave` меняются: они вливают ветку локально.

## Considered Options

- **Один Ticket — один репозиторий** (выбрано). Сохраняет то, на чём уже стоят скрипты Harness и
  worfy: на Ticket — одна ветка, одно worktree, один PR, один вердикт Gate.
- **Один Ticket — несколько PR**, по одному на репозиторий. Отвергнуто владельцем: на одну строку
  `Status:` приходилось бы несколько веток, вердиктов Gate и CI; `ticket done --pr N` принимает один
  PR, а Ticket закрывался бы только после мержей в разных репозиториях.
- **Full mode для Project над несколькими репозиториями: файлы workflow в одном из репозиториев или
  копия в каждом** (варианты подготовки к Session проектирования). Не выбрано: Ticket одного репозитория лежал бы в
  истории другого, а копии расходятся. У папки над репозиториями своего git нет, и Atakama уже
  держит файлы workflow в ней.
- **PR из форка, когда нет прав.** Отложено: в E3 этого нет; без прав Ticket кончается локальным
  финишем.
