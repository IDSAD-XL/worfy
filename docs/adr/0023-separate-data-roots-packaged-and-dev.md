# 0023 — Папки данных packaged-сборки и dev-запуска раздельны, один процесс на папку
Дата: 2026-10-06. Статус: принят.

**Контекст.** Autopilot над самим worfy идёт на стабильной копии `.app` (Ticket 03 Epic
worfy-daily). Пока он идёт, владелец запускает `pnpm dev`, а агенты пересобирают `dist/`. По
ADR-0005 все они брали одну папку `~/Library/Application Support/worfy` (`src/main/storage/paths.ts`,
`userData` туда же). Два процесса над одной папкой перезаписывают друг другу `limits.json` и
`bindings.json`. Ручная проверка 2026-10-06 показала и второй путь к тому же: щелчок по уведомлению
macOS запускал вторую копию worfy из другой сборки на диске, и она открывалась на той же папке.

**Решение.** Оба механизма сразу.

1. Dev-запуск (`app.isPackaged === false`: `pnpm dev`, `electron .`) берёт
   `~/Library/Application Support/worfy-dev`. Packaged-сборка берёт прежнюю `…/worfy`.
   `WORFY_DATA_DIR` по-прежнему перекрывает обе. Знает это только `paths.ts`; вид сборки ему
   сообщает `src/main/index.ts` до первого `dataRoot()`.
2. `app.requestSingleInstanceLock()` после `setPath('userData')`. Lock Electron держится на папке
   `userData`, поэтому это «один процесс на папку данных». Второй процесс над той же папкой
   выходит с кодом 0, а работающий выводит своё окно вперёд.

Копия и dev-запуск работают одновременно и не делят файлы. Копия и `dist/mac*/worfy.app` — обе
packaged и делят `…/worfy`: их развести нельзя, и lock не даёт им писать одновременно. Так же
разведены два `pnpm dev` из разных worktree.

**Что меняется по сравнению с ADR-0005.** ADR-0005 называет местом собственного состояния worfy
одну папку `~/Library/Application Support/worfy/`. Теперь это верно только для packaged-сборки:
состояние dev-запуска живёт в `~/Library/Application Support/worfy-dev/`. Над каждой из этих папок
работает не больше одного процесса worfy. Остальное в ADR-0005 в силе: worfy не пишет в
репозитории Project-ов, единственная запись вне `Application Support` — регистрация Project в
конфиге Gate.

**Последствия.** Мост status line (`scripts/statusline-bridge.sh`) без `WORFY_DATA_DIR` пишет
Limits в обе папки, какие из них есть: имена папок повторены в shell-скрипте, и contract test
сверяет их с `paths.ts`. У dev-запуска своя история: Project-ы, Binding-и, Layout, Limits из
`…/worfy` в него не переезжают. Данные, накопленные в `…/worfy` dev-запусками до этого решения,
достаются копии. Второй запуск `.app` при работающей копии ничего не открывает, только выводит окно
копии вперёд. e2e не затронуты: у каждого запуска свой временный `WORFY_DATA_DIR`, значит и свой
lock.

## Considered Options

- Раздельные папки и lock (выбрано).
- Только раздельные папки. Отвергнуто: `dist/`-сборка и копия обе packaged и делили бы одну папку
  без защиты.
- Только lock. Отвергнуто: dev-запуск не стартовал бы, пока работает копия, — а копия работает всё
  время, пока идёт Autopilot.
- Папка по пути к `.app` (например, хеш пути). Отвергнуто: копия при каждом обновлении теряла бы
  данные, если путь меняется, и папку нельзя назвать заранее в README.
