# 0070 — worfy-link вне локальной сети через overlay-сеть (Tailscale); заменяет пункт 7 ADR-0052
Дата: 2026-10-18. Статус: принят.

Этот ADR заменяет только пункт 7 («Только локальная сеть») [ADR-0052](0052-machines-and-linking.md)
(«Machine и Linked machine: два worfy связываются по коду в локальной сети»). Остальные пункты ADR-0052
действуют. ADR-0052 не правится.

**Контекст.** Machine — компьютер с worfy; Linked machine — другой компьютер с worfy, связанный с ним
по 6-значному коду (pairing). ADR-0052, пункт 7 разрешает связь только в локальной сети: ни проброса
порта, ни туннеля, ни relay-сервера. Spec Epic-а `worfy-link` повторяет это
(`.scratch/worfy-link/spec.md`, «Цель», «Решения владельца», «Не в этом Epic-е»).

Что есть в коде (прочитано, ничего не запускалось):

- Сервер связи сбрасывает соединение с адреса не из локальной сети ещё на TCP, до TLS handshake
  (`src/main/link/server.ts:118-125`), и второй раз — на upgrade до WebSocket (`server.ts:48`).
  Правило — `isLocalNetworkAddress` (`src/main/link/checks.ts:46-63`): IPv4 127/8, 10/8, 172.16/12,
  192.168/16, 169.254/16; IPv6 `::1`, `fc00::/7`, `fe80::/10`.
- Адрес Tailscale IPv4 лежит в 100.64.0.0/10 и сегодня отклоняется. Адрес Tailscale IPv6 лежит в
  `fd7a:115c:a1e0::/48`, внутри `fc00::/7`, и сегодня принимается как локальный.
- Machine-ы находят друг друга через Bonjour (`_worfy._tcp`, `src/main/link/discovery.ts`). Bonjour не
  проходит через overlay-сеть. Ввод адреса руками (`host:port`) уже есть (Ticket 02,
  `parseLinkAddress`, `src/shared/ipc/link.ts:38`). Окно «Link a machine» на Machine B показывает её
  адреса с портом (`service.addresses()`, `src/main/link/service.ts:250`).
- Заголовок `Host` сверяется со списком имён и адресов машины (`allowedHostNames`, `checks.ts`): адреса
  интерфейсов, `localhost`, имя в `.local`. Имени MagicDNS (DNS-имени машины внутри tailnet, например
  `pc` или `pc.<tailnet>.ts.net`) в списке нет.
- Pairing: код из 6 цифр, срок кода — 2 минуты, SPAKE2 (RFC 9382) поверх TLS с запомненным
  сертификатом. Окно «Link a machine» закрывается после 10 неудач подряд, но `open()` обнуляет счётчик
  (Ticket 22, `.scratch/worfy-link/issues/22-окно-связывания-занятый-слот-и-предел-попыток.md`). Ticket 22
  оставил предел между открытиями окна до выхода связи за локальную сеть.
- Находка Н3 ревью SPAKE2 (Ticket 17): Machine B отдавала id, имя, сборку и порт в `pake2`, до
  подтверждения ключа. Исправлено Ticket-ом 21 (PR #403, 2026-10-16): сведения о B идут в `pake4`, после
  проверки подтверждения A.

Решения владельца 2026-10-18 по вопросам Q15–Q24 этого дня (номера вопросов — этого раунда, не spec
`worfy-link`).

**Решение.**

1. **Связь можно пробовать вне локальной сети (Q15).** Отдельного ревью pairing перед этим не нужно.
   Условие «ревьюер-человек SPAKE2 до выхода за локальную сеть» (решение владельца 2026-10-16,
   Ticket 17) снято.
2. **Путь — overlay-сеть, которую ставит владелец (Q16).** Tailscale или WireGuard. Владелец ставит
   Tailscale на Mac и на ПК. worfy не ставит своего relay-сервера, не пробрасывает порт и не берёт
   библиотеку обхода NAT. TLS с запомненным сертификатом и SPAKE2 остаются поверх overlay-сети как есть.
3. **Отдельная настройка, по умолчанию выключена (Q24).** В Settings — переключатель «Связь через
   Tailscale» (название — владельца). Владелец включает его на каждой Machine. Пока он выключен, worfy
   принимает только соседей из локальной сети, как сегодня.
4. **Какие адреса принимаются (Q16, Q23).** При включённой настройке сервер связи дополнительно
   принимает адреса Tailscale: IPv4 100.64.0.0/10 и IPv6 `fd7a:115c:a1e0::/48`. Адрес из этих диапазонов
   принимается, только если соединение пришло на локальный адрес интерфейса Tailscale этой машины.
   Причина: тот же диапазон 100.64.0.0/10 провайдеры интернета используют для carrier-grade NAT, и сосед
   у того же провайдера иначе достучался бы до порта. То же правило — для `fd7a:115c:a1e0::/48`: этот
   диапазон больше не принимается как обычный локальный адрес `fc00::/7`.
5. **Как найти машину без Bonjour (Q22).** Сначала — ввод руками: имя MagicDNS (например `pc`) или
   IP-адрес. Порт берётся из окна «Link a machine» другой машины: оно его показывает. После pairing
   адрес запоминается, как сейчас. Позже, отдельным Ticket-ом, — список машин из Tailscale
   (`tailscale status --json`; нужен Tailscale CLI).
6. **Предел неудачных pairing между открытиями окна (Q17).** Не больше 10 неудачных попыток pairing за
   час на одну Machine, считая все открытия окна «Link a machine». Сверх предела — пауза и уведомление
   владельцу. Предел нужен при любом транспорте, и в локальной сети тоже.
7. **Код остаётся 6-значным (Q19).** С пределом пункта 6 и сроком кода 2 минуты этого хватает.
8. **Н3 (Q18).** Сведения о B уходят только после подтверждения ключа. Это уже сделано Ticket-ом 21;
   новой работы нет.
9. **Порядок (Q21).** Документы — сейчас. Код — после текущей очереди Epic-а `worfy-windows`.

Работа — Ticket-ы 27–31 Epic-а `worfy-link`: 27 — настройка и адреса Tailscale; 28 — предел неудачных
pairing; 29 — ввод имени MagicDNS или адреса руками; 30 — список машин из Tailscale; 31 — e2e и
приёмка с владельцем через Tailscale.

**Последствия.**

- Связь выходит за локальную сеть только там, где владелец сам поставил Tailscale и включил настройку
  на обеих Machine. Без этого поведение прежнее.
- Защита на соединении та же: TLS с запомненным сертификатом, токен, проверка `Host` и `Origin`
  (ADR-0052, пункты 5 и 8). Overlay-сеть — только транспорт; доверия к ней сверх этого нет.
- Соединение с адреса Tailscale при выключенной настройке сбрасывается на TCP, как любой не локальный
  адрес. Сосед у того же провайдера с адресом из 100.64.0.0/10 не проходит: соединение пришло не на
  интерфейс Tailscale.
- Адрес IPv6 Tailscale, который сегодня проходит как `fc00::/7`, без настройки больше не проходит. В
  локальной сети без Tailscale таких адресов нет.
- Проверка `Host` должна знать имена MagicDNS этой машины, иначе соединение по имени `pc` получит
  отказ до upgrade. Как их узнать без Tailscale CLI — решает Ticket 29.
- Предел пункта 6 меняет поведение и в локальной сети: после 10 неудач за час окно не открывается до
  конца паузы.
- Bonjour по-прежнему работает только в локальной сети; через Tailscale машину находят руками
  (Ticket 29), позже — из списка Tailscale (Ticket 30).

## Considered Options

- **Overlay-сеть владельца (Tailscale или WireGuard), отдельная настройка, адреса Tailscale только на
  интерфейсе Tailscale** (выбрано).
- **Только локальная сеть** (ADR-0052, пункт 7). Отвергнуто (Q15): владелец решил пробовать связь и через
  интернет.
- **Свой relay-сервер.** Отвергнуто (Q16): сервер надо держать и защищать, через него шёл бы весь
  трафик связи.
- **Проброс порта на роутере.** Отвергнуто (Q16): порт worfy открыт всему интернету.
- **Библиотека обхода NAT.** Отвергнуто (Q16): новая зависимость в main, а Tailscale уже решает эту
  задачу.
- **Принимать 100.64.0.0/10 с любого интерфейса.** Отвергнуто (Q23): тот же диапазон — carrier-grade NAT
  провайдера.
- **Адреса Tailscale без отдельной настройки.** Отвергнуто (Q24): владелец включает связь через
  Tailscale на каждой машине сам.
- **Ревьюер-человек SPAKE2 до выхода за локальную сеть** (решение 2026-10-16). Снято (Q15).
- **Код длиннее 6 цифр.** Отвергнуто (Q19): предела 10 неудач в час и срока 2 минуты хватает.
