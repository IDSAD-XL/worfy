# Окружение процесса Claude Code в worfy — интерактивный login shell пользователя из минимального окружения

Дата: 2026-10-05. Статус: принят.

Спецификация эпика `worfy-mvp` (риск 2) и тикет 07 (движок Сессий) брали окружение Claude Code из `$SHELL -lc env`. Spike тикета 06 (`scripts/spikes/path-probe/`; SDK 0.3.289, Claude Code 2.1.289, Electron 44.5.1, macOS arm64) показал, что для владельца этого мало.

**Решение.** Окружение процесса Claude Code — переменные интерактивного login shell пользователя. worfy один раз при старте, с таймаутом, запускает `$SHELL -ilc` с минимальным окружением: `HOME`, `USER`, `LOGNAME`, `SHELL`, `TMPDIR`, `LANG`, `SSH_AUTH_SOCK`, `__CF_USER_TEXT_ENCODING` из своего окружения и `PATH=/usr/bin:/bin:/usr/sbin:/sbin`. Shell печатает `env -0` между двумя строками-маркерами, тоже завершёнными NUL; worfy берёт записи между маркерами и делит их по NUL. Из результата убираются только `ANTHROPIC_API_KEY` и `ANTHROPIC_AUTH_TOKEN`, как требует спецификация (риск 3): с ними Claude Code входит по ключу, а не по подписке. Остальные переменные, в том числе `ANTHROPIC_*` и `CLAUDE_CODE_*`, которые пользователь сам задал в rc-файлах, доходят до Claude Code: Сессия worfy видит те же переменные из rc-файлов, что `claude` в терминале пользователя, и работает с его настройками (ADR-0002).

**Почему.** У приложения из Finder `PATH` равен `/usr/bin:/bin:/usr/sbin:/sbin`: нет `node`, `pnpm`, `gh`. `$SHELL -lc` добавляет Homebrew (`gh` находится), но не nvm: nvm подключается в `~/.zshrc`, который читает только интерактивный shell, поэтому `node` и `pnpm` не находятся. `$SHELL -ilc` находит все три (393 мс в первом прогоне, 324 мс в повторном с минимальным окружением). Минимальное окружение на входе shell нужно потому, что worfy бывает запущен не из Finder, а из терминала или окна Claude Code (`pnpm dev`, `open`). Тогда у него есть переменные родительской сессии — `ANTHROPIC_BASE_URL`, `CLAUDE_CODE_OAUTH_*`, `CLAUDE_CODE_SESSION_ID` и ещё 26 штук, — и через shell они перешли бы в дочерний Claude Code, который пошёл бы через чужой прокси и чужую сессию. Shell, запущенный из минимального окружения, их не видит: при запуске из окна Claude Code, где у вызывающего процесса было 29 таких переменных, окружение `-ilc` не содержало ни одной. Разбор по NUL нужен потому, что значение переменной может содержать перевод строки; построчный разбор вывода `env` резал бы такое значение и порождал ложные переменные.

**Цена.** Переменные, которые есть у процесса worfy, но не входят в список выше и не задаются rc-файлами, до Claude Code не доходят: например, заданные через `launchctl setenv`. Если такая понадобится, она добавляется в список явно.

Затронуты: тикет 07 (`src/main/agent/env.ts` и его test: маркеры, `env -0`, минимальное окружение на входе, удаление ровно двух переменных), спецификация эпика (риск 2 устарел: `-ilc` вместо `-lc`).

## Considered Options

- `$SHELL -lc env`, как в спецификации: не находит `node` и `pnpm`, установленные через nvm, — у владельца это так.
- `$SHELL -ilc` с полным окружением worfy на входе и удалением всех `ANTHROPIC_*`, `CLAUDE_CODE_*` и других переменных Claude Code из результата (первая редакция этого решения): убирает и переменные, которые пользователь сам экспортирует в rc-файлах (`ANTHROPIC_MODEL`, `CLAUDE_CODE_MAX_OUTPUT_TOKENS`), и Сессия worfy молча работала бы иначе, чем `claude` в терминале.
- `$SHELL -ilc` с полным окружением worfy на входе и удалением только двух ключей API: при запуске из окна Claude Code переменные родительской сессии доходят до дочернего Claude Code.
- Зашитый список каталогов (`/opt/homebrew/bin`, `~/.nvm/versions/node/*/bin`, `~/.local/bin`): ломается на другой машине и другом менеджере версий; так сейчас подстраховывается `~/.claude/hooks/stop.sh`, но команды модели в Bash этой подстраховки не имеют.
- Построчный разбор вывода `env`: ломается на значениях с переводом строки (например, экспортированные функции bash `BASH_FUNC_*%%`).
