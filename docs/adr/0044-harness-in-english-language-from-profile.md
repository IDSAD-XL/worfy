# 0044 — Harness на английском; язык общения и документов — из Profile; машинный контракт без языка
Дата: 2026-10-07. Статус: принят.

**Контекст.** Harness — правила, skills, agents, скрипты и hooks, по которым агенты ведут работу над
Project, — сегодня написан в основном по-русски. Spike Epic-а `worfy-harness` 2026-10-07 измерил:
skill `epic-wave` — 37 КБ, skill `ship-ticket` — 26 КБ, agent `implementer` — 17 КБ русского текста.
Только `~/.claude/CLAUDE.md` (13 489 байт) уже английский. По ADR-0019 (Harness — plugin Claude
Code, его ставит worfy) Harness становится частью приложения, которое в Epic-е E4 ставят другие
люди.

Язык Project задают два поля Profile (`~/.claude/profiles/README.md`). `language.reports` — язык
отчётов агентов и сообщений пользователю. `language.team` — язык того, что видит команда: коммиты,
PR, комментарии в коде и в ревью. Для документов Project (Ticket-ы, `spec.md`, ADR, HANDOFF)
отдельного поля нет: они пишутся на языке соседних файлов, а новый набор без соседей — на
`language.reports`.

Часть русского текста Harness — не проза, а строки, которые читают программы:

- вердикт Gate — строка `[gate] зелено | красно | ничего не прогналось | ПРОВЕРИТЬ НЕ УДАЛОСЬ`;
  worfy ищет её в транскриптах, когда в `gate/state` нет маркера (`src/main/gate/state.ts:8`);
- строка `Status:` в файле Ticket-а, которую пишет скрипт `ticket`;
- `echo "КОД=$?"` в skills `epic-wave` и `ship-ticket` — так агент видит код выхода скрипта;
- текст команды Autopilot: шаблон «Run wave» по умолчанию — `/epic-wave Ticket-ы {tickets} эпика
  {epic}` (`src/shared/projects/action-templates.ts:34`, ADR-0033).

Перевод прозы задел бы и эти строки, а с ними — чтение в worfy. Кроме того, spike показал, что skill
из plugin вызывается только с префиксом plugin (`/worfy:epic-wave`; голое `/epic-wave` не
работает). Значит, текст команды Autopilot в E3 меняется в любом случае (ADR-0040 — доставка
Harness и имя plugin `worfy`).

**Решение.** Решения владельца 2026-10-07: вопрос Q6 (язык Harness) и вопрос Q34 (проверка
перевода) Session проектирования Epic-а `worfy-harness`.

1. **Harness — на английском, перевод — в E3.** Переводят те же Ticket-ы, что переписывают файлы
   Harness под plugin: Ticket 05 (правила `CLAUDE.md` для hooks), Ticket 06 (skills `epic-wave` и
   `ship-ticket`), Ticket 07 (agents implementer, reviewer, scout), Ticket 08 (остальные пять skills,
   `bin/` и скрипты hooks). Каждый из них в своей группе файлов делает все правки сразу: перевод,
   пути через `${CLAUDE_PLUGIN_ROOT}`, префикс `worfy:`, машинные строки. Параллельные Ticket-ы не
   правят один файл.
2. **Язык общения и отчётов — `language.reports` Profile**, как сейчас. Английский текст Harness
   не меняет язык, на котором агент говорит с пользователем.
3. **Новое поле Profile `language.docs`** — язык документов Project: Ticket-ы, `spec.md` Epic-а, ADR,
   HANDOFF, уроки. Поле вносит Ticket 11 (Profile schema 2). `language.team` остаётся с прежним
   смыслом.
4. **Машинные строки не зависят от языка.** Вердикт Gate, строка `Status:`, `КОД=` и формат команды
   Autopilot становятся английскими константами или JSON. Точный новый текст задают Ticket-ы,
   которые эти строки меняют: Ticket 06 — формат команды Autopilot, Ticket 08 — скрипты, Ticket 09 —
   вердикт Gate. worfy и скрипты Harness читают и старые русские строки: они остаются в старых
   транскриптах и Ticket-ах.
5. **Машинный контракт Gate — JSON-файл.** Gate пишет вердикт JSON-файлом. worfy читает этот файл, а
   не слово «зелено» в транскрипте (Ticket 09, `src/main/gate/state.ts`). Строки `[gate] …` из
   транскриптов — запасной путь для старых транскриптов.
6. **Проверка перевода.** В каждом Ticket-е перевода ревьюер с линзой «смысл сохранён» сравнивает
   старый и новый текст. Итоговая проверка — первая Wave после перехода машины владельца на plugin
   (Ticket 16, ADR-0047). eval-кейсы (`claude plugin eval` — автоматические прогоны plugin на
   заданных примерах) — в E4.

**Что меняется в прежних ADR.**

- ADR-0033 (Autopilot называет Ticket-ы Wave): шаблон «Run wave» по умолчанию меняется на новый
  формат с префиксом `worfy:` (Ticket 06 — skill, Ticket 10 — worfy понимает префикс и новый
  формат). Старый текст по-прежнему понимается.
- ADR-0017 (канонические английские термины) не меняется: проза Harness переходит на английский,
  а термины `CONTEXT.md` и так английские.

**Последствия.**

- Человек, который не читает по-русски, может читать и править Harness. Владелец получает отчёты
  по-русски, как сейчас: `language.reports` у worfy, Auction и Atakama — `ru`.
- Агент выбирает язык по трём полям: сообщения пользователю — `language.reports`, то, что видит
  команда, — `language.team`, документы Project — `language.docs`.
- worfy перестаёт зависеть от языка вывода Gate. Чтение старых русских строк остаётся, пока есть
  старые транскрипты и Ticket-ы; когда его убрать, это решение не задаёт.
- Язык документов влияет на поиск: при `language.docs: ru` qmd берёт русскую модель (ADR-0043 —
  qmd как часть Harness).
- Правила `CLAUDE.md` для hooks должны уложиться в 10 000 символов на часть (ADR-0041 — правила
  через hooks `SessionStart` и `SubagentStart`). Перевод и сжатие делает один Ticket 05.
- Риск: перевод меняет смысл правила, а заметно это только в работе. Ревьюер «смысл сохранён» ловит
  расхождения в тексте, первая Wave на plugin — в поведении. Автоматических eval-кейсов до E4 нет.

## Considered Options

- **Перевод в E3, в тех же Ticket-ах** (выбрано). Эти файлы в E3 и так переписываются целиком:
  пути, префикс, машинные строки. Перевод в том же проходе не добавляет второго ревью тех же файлов.
- **Перевод в E4, до него проза по-русски** (предлагала подготовка к Session проектирования). Отвергнуто владельцем:
  файлы Harness переписывались бы дважды — в E3 под plugin, в E4 — переводом.
- **Машинные строки остаются словами в выводе, worfy ищет их в транскриптах** (русскими, как
  сейчас, или переведёнными). Не выбрано: worfy зависел бы от языка Harness, и перевод такой строки
  ломал бы чтение. Разбор транскриптов и сейчас требует отсеивать чужие строки — вывод других
  команд, текст пользователя и модели (`src/main/gate/state.ts:9-12`). JSON-файл не требует ни
  того, ни другого.
- **eval-кейсы `claude plugin eval` как проверка перевода в E3.** Перенесено в E4. В E3 перевод
  проверяют ревьюер с линзой «смысл сохранён» и первая Wave на plugin.
