# 0019 — Harness — plugin Claude Code из `harness/` репозитория worfy, его ставит worfy
Дата: 2026-10-06. Статус: принят.

**Контекст.** worfy становится самостоятельным сервисом: любой человек ставит его на свою машину
вместе со всем Harness. Подпись Developer ID и нотаризация — только в Epic E4 («Для других
людей») и только при первом внешнем пользователе; до тех пор worfy собирают из исходников.
Сегодня Harness — разрозненные файлы в `~/.claude` владельца: глобальный `CLAUDE.md`, `agents/`,
`skills/`, `hooks/`, скрипты в `bin/` (`ticket`, `epic-status`, `preflight`, `profile`), `gate/`,
`profiles/`. У них нет версии и установщика, а в общих файлах есть путь `/Users/alexey`, имена
Auction и Atakama и `~/.claude/atakama`. worfy читает вывод этих скриптов и формат Ticket-ов
(ADR-0002), поэтому приложение и Harness должны меняться согласованно.

**Решение.**

- Harness — plugin Claude Code. Исходник лежит в `harness/` репозитория worfy.
- Версия одна с приложением: worfy версии X ставит Harness версии X. Отдельных релизов Harness нет.
- worfy ставит и обновляет plugin в область пользователя (user scope) командой
  `claude plugin install`, а не раскладывает файлы сам. Так Harness действует в любой Session
  пользователя: в worfy, в терминале и в Claude desktop.
- Скрипты `ticket`, `epic-status`, `preflight`, `profile` и `gate` лежат внутри plugin и
  вызываются по пути plugin, а не из `~/.claude/bin` и `~/.claude/hooks`.
- Общие файлы обобщаются: из них уходят `/Users/alexey`, Auction, Atakama и `~/.claude/atakama`.
  Всё, что отличает один Project от другого, переезжает в Profile (ADR-0020).
- При установке worfy находит в `~/.claude` разрозненные файлы владельца, которые заменяет plugin,
  и показывает список «что уберу / что оставлю». После подтверждения файлы из первой части
  переносятся в резервную папку; ничего не удаляется. Личные skills, MCP-серверы и память
  пользователя в Harness не входят и не трогаются.

**Что меняется в прежних ADR.** Заменяет часть ADR-0005 о записи в `~/.claude`: там единственной
записью worfy вне своей папки данных была регистрация Project в Gate. Теперь к ней добавляются
установка и обновление plugin (пишет Claude Code по команде worfy) и перенос файлов в резервную
папку — только после подтверждения пользователя. В ADR-0002 «gate, hooks и скрипты из `~/.claude`»
теперь означает «из установленного plugin». Правило ADR-0002, что агенты в worfy работают с
конфигурацией пользователя (`settingSources: user + project + local`), остаётся: plugin в области
пользователя входит в эту конфигурацию.

**Последствия.** Темы Epic E3 («Harness как часть worfy») идут по порядку: plugin → обобщение →
установка, обновление и перенос → первый запуск (Claude Code и вход, git, gh, node) → подключение
Project (ADR-0020) → Project над несколькими репозиториями (ADR-0018). Правила из глобального
`CLAUDE.md` должны доходить до Session из plugin; как именно — решает первая тема. Harness нельзя
обновить отдельно от worfy. До конца E3 владелец работает со старыми файлами в `~/.claude`.

## Considered Options

- Оставить Harness файлами в `~/.claude` и раскладывать их скриптом установки. Отвергнуто: нет
  версии; установка перезаписывает правки пользователя в тех же файлах; при обновлении или
  удалении приходится угадывать, какие файлы принадлежат Harness.
- Отдельный репозиторий и своя версия Harness. Отвергнуто: появляется таблица совместимости версий
  worfy и Harness, хотя worfy читает вывод `epic-status` и `ticket` и формат Ticket-ов.
- Подключать plugin только к Session-ам, которые запускает worfy. Отвергнуто: в терминале и Claude
  desktop Harness пропал бы, а ADR-0002 требует, чтобы workflow работал и оттуда.
- Ставить plugin в область Project (project scope). Отвергнуто: это запись в `.claude/` каждого
  репозитория, а worfy в репозитории не пишет (ADR-0005); и Harness ставился бы заново в каждый
  Project.
- plugin в `harness/` репозитория worfy, версия вместе с приложением, область пользователя
  (выбрано).
