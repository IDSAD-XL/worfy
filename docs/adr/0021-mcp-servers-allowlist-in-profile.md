# 0021 — MCP-серверы агентов Project — по списку в Profile, по умолчанию только нужные workflow
Дата: 2026-10-06. Статус: принят.

**Контекст.** ADR-0002 решил, что агенты в worfy работают с конфигурацией пользователя, MCP-серверы
включены, — так же, как в терминале. Ticket 06 Epic worfy-mvp измерил цену: с MCP-серверами
владельца Session получает 634 tools, и на haiku второй ход падает с «Prompt is too long». Ticket 07
оставил серверы как есть и запускает Session на модели из настроек пользователя; сколько стоит ход
с 634 tools, не замерено. В Autopilot (Wave-ы идут без человека) эти tools оплачиваются в каждом
ходе Orchestrator и каждого Subagent. Самому workflow нужны два сервера: `qmd` (поиск по ADR, урокам
и Ticket-ам) и сервер Canvas worfy `worfy-canvas`.

**Решение.** В Profile (в общей части, ADR-0020) есть список MCP-серверов, разрешённых агентам
Project. По умолчанию в нём только серверы, нужные workflow: `qmd` и `worfy-canvas`. Session-ы,
которые запускает worfy (Orchestrator, новые Session-ы, Autopilot), получают только серверы из
списка. Их Subagent-ы, в том числе Subagent-ы workflow-скриптов, наследуют тот же набор.
Пользователь добавляет сервер в список, когда он нужен работе Project. Черновик списка пишет агент
при подключении Project (ADR-0020).

Рядом, отдельным Ticket-ом Epic E2 (worfy-daily, тема «устойчивость и цена»): haiku убран из выбора
модели, минимум — sonnet; Orchestrator по умолчанию идёт на модели пользователя из `settings.json`,
Subagent-ы наследуют её.

**Что меняется в прежних ADR.** Меняет ADR-0002 только в части MCP-серверов и только для Session-ов,
которые запускает worfy. `CLAUDE.md`, hooks, skills и Subagent-ы по-прежнему берутся из конфигурации
пользователя. Session, запущенная в терминале, получает серверы так, как настроил пользователь.

**Последствия.** Session в worfy и `claude` в терминале различаются набором MCP-серверов. Skill или
Ticket, которому нужен сервер вне списка, в worfy его не увидит. В Autopilot это дефект Profile: он
становится Ticket-ом, а не поводом вернуть все серверы. Пока Profile не разделён на две части
(ADR-0020), список лежит в нынешнем `~/.claude/profiles/<имя>/profile.json`.

## Considered Options

- Все серверы пользователя, как решили ADR-0002 и Ticket 07. Отвергнуто: 634 tools в каждом
  запросе, haiku не работает, а цена хода на основной модели неизвестна и умножается на число
  Subagent-ов.
- Только убрать haiku из выбора модели. Отвергнуто как единственная мера: падение уходит, размер
  запроса и цена остаются.
- Список запрещённых серверов вместо разрешённых. Отвергнуто: каждый новый сервер пользователя
  снова попадает к агентам, хотя никто этого не решал.
- Список в настройках worfy, а не в Profile. Отвергнуто: набор серверов — факт о работе Project,
  а не об одном приложении; Harness и другие Session-ы Project его бы не видели.
- Список разрешённых в Profile, по умолчанию `qmd` и `worfy-canvas` (выбрано).
