# 0018 — Project — папка с workflow: git-репозиторий или папка над несколькими репозиториями
Дата: 2026-10-06. Статус: принят.

**Контекст.** В worfy-mvp (Epic первой версии приложения) Project — ровно один git-репозиторий:
`src/main/projects/store.ts` отказывает в папке вне git, а worktree или подпапку заменяет корнем
основного репозитория. У владельца есть работа другого вида — Atakama: три репозитория
(`Atakama-Browser-Extension`, `Atakama-Browser-Server`, `Atakama-Browser-Shared`), а Epic-и,
Ticket-ы (`.scratch/`) и HANDOFF лежат в папке `Atakama` над ними и не коммитятся. Harness такую
работу уже ведёт: скрипт `profile`, который находит Profile по каталогу, для папки над
репозиториями берёт Profile, общий для всех репозиториев внутри неё. worfy её показать не может.

**Решение.** Project — папка, в которой живёт workflow одной работы пользователя: Epic-и, Ticket-ы,
HANDOFF, ADR. Это либо сам git-репозиторий (Auction, worfy), либо папка над несколькими
репозиториями (Atakama). У каждого Project один Canvas и один Profile.

- Git-репозиторий: правило worfy-mvp остаётся — worktree и подпапка приводятся к корню основного
  репозитория.
- Папка над репозиториями берётся как есть. Какие репозитории в неё входят, сегодня задают записи
  реестра Gate (`~/.claude/gate/config.json`), которые называют один Profile.
- Project без Ticket-ов — тоже Project: он подключается с пустым Canvas и предложением завести
  первый Epic.

Слово «репозиторий» не синоним Project (ADR-0017, `CONTEXT.md`).

**Последствия.** Всё, что в worfy-mvp считает Project одним репозиторием, для папки над
репозиториями должно работать по каждому репозиторию внутри: ветки и worktree Ticket-ов, PR и CI
(`src/main/github/prs.ts` вызывает `gh pr list` в корне Project), Gate (проверяет только
зарегистрированные репозитории), слежение за git (`src/main/workflow/watch.ts`). Это последняя
тема Epic E3 («Harness как часть worfy»). До неё worfy подключает только git-репозиторий, как
сейчас.

**Что меняется в прежних ADR.** ADR-0005: запрет «worfy ничего не пишет в репозитории Project-ов»
читается как запрет на всю папку Project. У Project над несколькими репозиториями это и сама
папка над ними, хотя она не git-репозиторий: её `.scratch/`, HANDOFF и ADR worfy только читает, как
и файлы внутри репозиториев. ADR-0002: источник правды о работе — файлы workflow в папке Project,
где бы она ни была; у Project над репозиториями они лежат вне git и не коммитятся.

## Considered Options

- Project — один git-репозиторий, как в worfy-mvp. Отвергнуто: Atakama стала бы тремя Project-ами
  с тремя Canvas, а её Epic-и и HANDOFF, которые лежат над репозиториями, не попали бы ни в один.
- Project — список репозиториев в настройках worfy, без общей папки. Отвергнуто: у Atakama общая
  папка уже есть, workflow лежит в ней, и Harness находит Profile по ней же; без папки `.scratch/`
  и HANDOFF негде держать.
- Project — папка с workflow: репозиторий или папка над репозиториями (выбрано).
