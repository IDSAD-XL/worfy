# 0071 — Полный `pnpm test` на Windows-runner-е GitHub считается вердиктом Windows для платформенных PR без Terminal, окон, e2e и упаковки; частично заменяет пункт 2 ADR-0056
Дата: 2026-10-19. Статус: принят.

**Контекст.** ADR-0056 (решение владельца Q23, 2026-10-07: «Windows-раннера на PR нет») держит вердикт
Windows на ПК владельца: перед мержем платформенного PR на Windows-ПК идёт gate full, его итог — строка
вердикта и код выхода. С ADR-0067 этот итог — отметка `check/windows` на SHA head-а, её ставит
Orchestrator на Mac по отчёту Session на ПК. С ADR-0069 PR Session Windows с общим кодом ещё и проходит
gate full на Mac (метка `needs-mac-gate`).

Цена цикла на двух машинах:

- **Два gate full на каждый head.** Платформенный PR проходит gate full на ПК и gate full на Mac.
- **Сдвиг head — оба заново.** Rebase на свежий main (ADR-0056, пункт 6) или правка круга ревью
  делает старую отметку `check/windows` чужой (ADR-0067: отметка привязана к SHA), и оба прогона идут
  снова.
- **Медленные сообщения между Session-ами.** Прямого канала нет (ADR-0056, пункт 4): запрос вердикта
  и отчёт идут через репозиторий и через владельца, и PR ждёт, пока ПК включён и его Session свободна.
- **e2e на каждой машине — по одному.** gate full и e2e идут под общим замком
  (`/tmp/worfy-e2e.lock` на Mac); пока один прогон держит замок, следующий PR ждёт.

При этом большая часть платформенных PR меняет код, который проверяют unit- и contract-test-ы: пути,
процессы, скрипты Harness, IPC. Workflow «Windows tests» (`.github/workflows/windows-tests.yml`, Ticket 25
Epic-а `worfy-windows`) уже гоняет на `windows-latest` до 12 таких файлов, а весь `pnpm test` на
runner-е был запрещён только потому, что на Windows он был красным (около 700 упавших test-ов на
2026-10-12). Часть unit/contract Ticket-а 14 и Ticket 65 делают main зелёным на Windows.

Минута Windows-runner-а — $0.010 (ADR-0056, «Факты»). Длину полного run-а замеряет Ticket 66; при
20 минутах run стоит $0.20 (оценка, не замер).

**Решение** (владелец, 2026-10-19).

1. **Когда main зелёный на Windows** — часть unit/contract Ticket-а 14 и Ticket 65 влиты, `pnpm test` на
   ПК — код 0, — `windows-tests.yml` получает второй режим: полный `pnpm test` (unit и contract) на
   `windows-latest`. Только `workflow_dispatch`, один job, предел времени — по замеру run-а. Режим
   списка до 12 файлов и его пределы остаются. Пределы обоих режимов закреплены в
   `test/contract/windows-tests-workflow.test.ts`.
2. **Orchestrator на Mac запускает полный run** на head каждого платформенного PR перед мержем и на
   `main` вместе с каждым batch CI dispatch (ADR-0068). Run засчитывается только для того SHA, на
   котором он шёл.
3. **Зелёный run — отметка `check/windows` `success`** для платформенного PR, который не трогает
   Terminal, код окон, меню и уведомлений, e2e и упаковку. Такому PR gate full на ПК не нужен.
4. **PR, который трогает хоть что-то из этого, ждёт вердикта ПК**, как по ADR-0056, пункт 2.
5. **Какой PR какой — решает скрипт, не суждение:** список путей в `scripts/windows-verdict-scope.mjs`
   (Ticket 66) сверяется с файлами diff-а PR. Совпал хоть один путь — вердикт ПК; ни одного — run.
6. Красный полный run на `main` — как красный batch CI run (ADR-0068, пункт 3): Autopilot run
   останавливается после Wave, сбой — Ticket или строка `blocked`, исправление вперёд.

Пункт 1 ADR-0056 (Windows-раннера на PR нет) не меняется: у run-а нет триггера `pull_request` и
`push`, его запускает только Orchestrator на Mac и владелец. Не меняются пункт 3 (ручной job «Windows»
в `ci.yml`), пункты 4–6, ADR-0067 (как ставится отметка) и ADR-0069 (`needs-mac-gate`).

**Последствия.**

- **Что по-прежнему проверяет ПК:** PR с Terminal (ConPTY, PowerShell, node-pty), с кодом окон, меню и
  уведомлений, с e2e и с упаковкой — gate full на ПК, как сейчас. Только ПК проверяет e2e
  (`test:e2e`) и собранное приложение (`test:package`) на Windows; приёмка Epic-а `worfy-windows` и
  ручные пункты на ПК остаются там же.
- **Цена:** один полный run на head платформенного PR из пункта 3 и один на `main` на Wave. Каждый
  сдвиг head такого PR — ещё один run. Цифру за run и предел времени записывает Ticket 66 в
  комментарий `windows-tests.yml`.
- **Цикл короче для PR из пункта 3:** вместо gate full на ПК и сообщения между Session-ами — dispatch и
  ожидание run-а на Mac. gate full на Mac перед мержем остаётся (ADR-0065, ADR-0069).
- **runner — не ПК:** чистый образ, права администратора, другой профиль пользователя. Сбой, который
  виден только на ПК владельца, такой PR не поймает; его увидит следующий gate full на ПК — так же,
  как ADR-0056 говорит о PR, которые не сочли платформенными.
- **Неполный список путей** пропускает PR мимо ПК. Поэтому список — в скрипте с test-ом, а ошибку в
  нём чинит PR, а не решение в момент мержа.
- **До мержа Ticket-а 66 ничего не меняется:** вердикт Windows для каждого платформенного PR — gate
  full на ПК (ADR-0056), режим «Windows tests» — только список до 12 файлов.

## Considered Options

- **Как сейчас: gate full на ПК для каждого платформенного PR (ADR-0056).** Отвергнуто для PR без
  Terminal, окон, e2e и упаковки: два gate full на head и сообщения между машинами стоят больше, чем
  дают для кода, который целиком проверяют unit- и contract-test-ы.
- **Полный run на `windows-latest` по триггеру `pull_request`.** Отвергнуто (Q23): run на каждый push
  в PR, а не один на head перед мержем, и платные минуты без решения Orchestrator-а.
- **Run считается вердиктом для всех платформенных PR.** Отвергнуто: e2e, Terminal и упаковка на
  runner-е не проверяются: полный режим гоняет только unit- и contract-test-ы.
- **Список «какой PR без ПК» — решение Orchestrator-а по diff-у.** Отвергнуто (владелец): правило
  должно проверяться скриптом, а не суждением.
- **Полный `pnpm test` на runner-е с e2e (`test:e2e`, `test:package`).** Отвергнуто: e2e Electron
  требуют рабочего стола и идут по одному; run стал бы дороже и медленнее, а замены ПК не дал бы.

## Amendments

- **2026-10-28, ADR-0083** (`worfy-throughput` 35). Вступает в силу по ADR-0083 — с первым зелёным `ci-ok`
  на `main`; до этого пункты 2, 3 и 6 действуют как написаны. Режим `full` идёт на каждый PR и push в `main`
  сам — job `windows / full-suite` в составе check `ci-ok`; Orchestrator его не запускает (пункт 2), run
  `windows-full` вместе с batch CI больше не нужен. Зелёный `ci-ok` — `check/windows` `success` для обычного
  PR и для платформенного со scope `runner` (пункт 3). Пункт 6 (красный run на `main` — только исправление
  вперёд, без revert) заменён пунктом 7 ADR-0083: revert виноватого PR или PR с исправлением. Пункты 1, 4 и 5
  (режим `full`, платформенный PR со scope `pc` ждёт ПК, решает скрипт) остаются.
- **2026-10-29, ADR-0086** (`worfy-throughput` 30). Пункт 4 в части «платформенный PR со scope `pc` ждёт ПК» заменён: такой PR вливается по `ci-ok`. ПК гоняет `GATE_SCOPE=all` gate full на `main` после merge такого PR: раз в Wave, а вне Wave — сразу после merge. Красный `main` на ПК — открытый issue с меткой `pc-main-red`: пока он открыт, PR со scope `pc` не вливаются, кроме PR, который его чинит.
