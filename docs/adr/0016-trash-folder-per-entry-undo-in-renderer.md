# Корзина Узлов — папка на запись в данных Проекта, история undo — в renderer

Дата: 2026-10-05. Статус: принят.

**Контекст.** Тикет 30 требует корзину удалённых Узлов и undo / redo Раскладки. Корзина — собственное
состояние worfy (ADR-0005), а Раскладку пишет только main (ADR-0003). Отмена должна откатывать
только жесты пользователя: Раскладку меняют ещё агент через MCP-tools и автоматические источники
Узлов (Сессии, Эпики, Subagent-ы).

**Решение.** Удалённый пользователем Узел уходит в `<папка данных Проекта>/trash/<мс>-<8 hex>/`:
`entry.json` (запись Узла Раскладки, время, какую Карточку он показывал), `card/` (папка Карточки,
перенесённая `rename`) и `card-data.json`. Путь строится только из папки данных Проекта, id
Карточки и метки записи, поэтому ни в репозиторий, ни в `~/.claude` попасть не может. Записи старше
3 дней удаляются при запуске. В корзину кладёт только пользователь (`trash.put`); `remove` из
MCP-tools и кнопок Узлов корзину не использует. Код — `src/main/layout/trash.ts` (`TrashStore`),
домен IPC `trash.*` — `src/shared/ipc/trash.ts` и `src/main/ipc/trash.ts`.

История undo живёт в памяти renderer (`src/renderer/canvas/history.ts`): по Проекту, 40 шагов, не
переживает перезапуск. Шаг — пара «отменить / повторить»: для операции Раскладки это обратная
операция и сама операция через тот же `layout.apply`, для удаления — `trash.restore` и повторный
`trash.put`. В историю пишут только операции, пришедшие через `LayoutOps` из `LayoutOpsContext`, то
есть жесты пользователя; всё автоматическое шлёт `applyLayoutOp` мимо истории. Один жест — один шаг.

**Следствие.** Формат записи корзины — данные на диске: его смена потребует читать старый формат ещё
3 дня. История теряется при перезапуске окна. Агент, удаливший Карточку через MCP, оставляет её
файлы на месте без Узла. Новый автоматический источник операций Раскладки обязан слать их мимо
`LayoutOps`, иначе ⌘Z начнёт отменять его правки вместо шагов пользователя.

Источник: тикет 30 (`.scratch/worfy-mvp/issues/30-корзина-и-undo-раскладки.md`, раздел «Итог»),
PR #31.

## Considered Options

- Корзина одним файлом-журналом на Проект — отвергнуто: сложнее переносить папку Карточки целиком.
- История в main — отвергнуто: main знал бы, кто прислал операцию, но пришлось бы различать окна и
  вводить источник операции в `layoutOpSchema` (`src/shared/layout/types.ts`).
- Корзина и для операций агентов — отвергнуто: агент не просил отмены, а записи засоряли бы popover.
- Корзина — папка на запись в данных Проекта, история — в памяти renderer, граница истории по
  каналу `LayoutOps` (выбрано).
