# Корзина Node-ов — папка на запись в данных Project, история undo — в renderer

Дата: 2026-10-05. Статус: принят.

**Контекст.** Ticket 30 требует корзину удалённых Node-ов и undo / redo Layout. Корзина — собственное
состояние worfy (ADR-0005), а Layout пишет только main (ADR-0003). Отмена должна откатывать
только жесты пользователя: Layout меняют ещё агент через MCP-tools и автоматические источники
Node-ов (Session-ы, Epic-и, Subagent-ы).

**Решение.** Удалённый пользователем Node уходит в `<папка данных Проекта>/trash/<мс>-<8 hex>/`:
`entry.json` (запись Node-а в Layout, время, какую Card он показывал), `card/` (папка Card,
перенесённая `rename`) и `card-data.json`. Путь строится только из папки данных Project, id
Card и метки записи, поэтому ни в репозиторий, ни в `~/.claude` попасть не может. Записи старше
3 дней удаляются при запуске. В корзину кладёт только пользователь (`trash.put`); `remove` из
MCP-tools и кнопок Node-ов корзину не использует. Код — `src/main/layout/trash.ts` (`TrashStore`),
домен IPC `trash.*` — `src/shared/ipc/trash.ts` и `src/main/ipc/trash.ts`.

История undo живёт в памяти renderer (`src/renderer/canvas/history.ts`): по Project, 40 шагов, не
переживает перезапуск. Шаг — пара «отменить / повторить»: для операции Layout это обратная
операция и сама операция через тот же `layout.apply`, для удаления — `trash.restore` и повторный
`trash.put`. В историю пишут только операции, пришедшие через `LayoutOps` из `LayoutOpsContext`, то
есть жесты пользователя; всё автоматическое шлёт `applyLayoutOp` мимо истории. Один жест — один шаг.

**Следствие.** Формат записи корзины — данные на диске: его смена потребует читать старый формат ещё
3 дня. История теряется при перезапуске окна. Агент, удаливший Card через MCP, оставляет её
файлы на месте без Node-а. Новый автоматический источник операций Layout обязан слать их мимо
`LayoutOps`, иначе ⌘Z начнёт отменять его правки вместо шагов пользователя.

Источник: Ticket 30 (`.scratch/worfy-mvp/issues/30-корзина-и-undo-раскладки.md`, раздел «Итог»),
PR #31.

## Considered Options

- Корзина одним файлом-журналом на Project — отвергнуто: сложнее переносить папку Card целиком.
- История в main — отвергнуто: main знал бы, кто прислал операцию, но пришлось бы различать окна и
  вводить источник операции в `layoutOpSchema` (`src/shared/layout/types.ts`).
- Корзина и для операций агентов — отвергнуто: агент не просил отмены, а записи засоряли бы popover.
- Корзина — папка на запись в данных Project, история — в памяти renderer, граница истории по
  каналу `LayoutOps` (выбрано).
