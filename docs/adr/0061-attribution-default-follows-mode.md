# 0061 — Умолчание поля Profile `attribution` зависит от режима: в Silent mode — `off`, в Full mode — `on`
Дата: 2026-10-13. Статус: принят.

**Контекст.** Пункт 6 ADR-0042 (Profile целиком на машине; Full mode и Silent mode):

> **Атрибуция** — поле Profile `attribution: on | off`: ставить ли в коммиты и PR строки
> атрибуции Claude. По умолчанию `on`; значение для каждого Project-а ставит владелец.

Строки атрибуции — это `Co-Authored-By: Claude …` в сообщении коммита и
`Generated with [Claude Code]` в описании PR. Silent mode — режим, в котором репозиторий Project-а
и GitHub не показывают следов workflow (ADR-0042, пункт 5). Умолчание `on` было одно для обоих
режимов, а проверка следов (`harness/bin/silent-check`) и guard (`harness/hooks/guard.mjs`)
запрещают строки атрибуции только при `off`.

Приёмка E3 на пустом репозитории (Ticket `worfy-harness/26`, пункт 2, запуск 2026-10-12) это
показала: Silent Project подключился через «Add project», и в его коммите стояло
`Co-authored-by: Claude Opus 5.5 <noreply@anthropic.com>`, а в PR — «Generated with Claude Code».
Причин было две. Умолчание в `harness/bin/profile` — `on`. И оно почти не срабатывало: черновик
подключения пишет поле явно, и в том запуске модель написала в нём `"attribution": "on"`; а
приёмочный test искал строки атрибуции только при `off` — то есть не искал.

Владелец решил 2026-10-13: «в silent mode по дефолту пусть атрибуция выключается». Этот ADR
уточняет ADR-0042, пункт 6: умолчание зависит от режима. ADR-0042 не правится; остальное в его
пункте 6 — поле, два значения, «значение для каждого Project-а ставит владелец» — остаётся в силе.
Правило умолчания решил владелец 2026-10-13; уточнения исполнителя (пункты 4–6 и поведение форм)
записаны в Ticket-е `worfy-harness/35` как «решено без владельца — подтвердить».

**Решение.**

1. **Умолчание по режиму.** У Profile-а без поля `attribution` значение берётся из режима:
   `silent` — `off`, `full` — `on`. Profile schema 1 режима не имеет и читается как Full, значит
   `on` — даже если в его файле написано `"mode": "silent"`. `"attribution": null` читается как
   «поля нет».
2. **Явное значение побеждает в обоих режимах.** `"attribution": "on"` в Silent Project-е оставляет
   строки атрибуции, `"attribution": "off"` в Full Project-е их убирает. Умолчание действует только
   там, где поля нет. Значение не из `on | off` (`""`, `"OFF"`, `0`, `false`) — сломанный Profile:
   `bin/profile` отвечает кодом 1 с причиной, как на недопустимый `mode`. Напечатанное как
   записано, оно читалось бы как «не `off`», и Silent Project нёс бы строки, которые запрещает его
   умолчание.
3. **Решённое значение читается из `harness/bin/profile`; правило «silent → `off`, full → `on`»
   записано в четырёх местах.** `profile --field attribution`, `profile --json` и сводка, которую
   читают агенты, печатают уже решённое значение. `bin/silent-check`, guard, hook `SessionStart`
   (`harness/hooks/session-start.sh`), skills и агенты читают его оттуда и своего умолчания не
   знают. Само правило закодировано в:
   - `harness/bin/profile` — для Profile-а без поля;
   - подмене в «Add project» (пункт 4) — `applyChoices` в `src/main/projects/connect.ts`;
   - предложении переноса (пункт 5) — `proposeAttribution` в
     `src/main/harness/migrate/profiles.ts`;
   - тексте skill-а `connect-project` (`harness/skills/connect-project/SKILL.md`).

   Два места в коде worfy зовут одну функцию — `defaultAttribution` в
   `src/main/harness/attribution.ts`. Вместе их держит contract test
   `test/contract/projects-connect.test.ts`: значение этой функции, предложение переноса и подмена
   в Silent-черновике равны тому, что `bin/profile --field attribution` печатает для Profile-а без
   поля, в обоих режимах. Фразу skill-а держит `harness/bin/tests/project-connect.test.sh`.
4. **В «Add project» значение для Silent mode ставит worfy, skill его только называет.** Когда
   черновик приходит от агента, worfy один раз, до показа формы, ставит в Silent-черновике
   `attribution: "off"` — что бы ни написала модель. Запуск 2026-10-12 упал именно на значении,
   которое написала модель, а решение владельца — про умолчание, оно не должно зависеть от того,
   послушает ли модель текст skill-а. Форма показывает значение в поле «Attribution»; то, что
   человек выбрал в этом поле, записывается как выбрано: проверка и запись берут черновик формы
   как есть, подмены на этом пути нет. В Full mode worfy значение не трогает — форма получает то,
   что предложил агент. Skill `connect-project` по-прежнему называет значение по режиму (`"off"`
   для Silent, `"on"` для Full) и говорит, что для Silent worfy ставит `"off"` сам. Схема
   черновика (`harness/profiles/draft.schema.json`) требует поле, так что Project, подключённый
   через worfy, всегда получает значение явно.
5. **Перенос Profile-ов schema 1** (`src/main/harness/migrate/profiles.ts`) предлагает значение
   так же: названное в старом Profile-е — как записано; иначе по предложенному режиму — `off` для
   Silent, `on` для Full. Форма переноса показывает поле рядом с режимом, владелец его подтверждает
   или меняет.
6. **Приёмка «silent» ищет строки атрибуции безусловно** (`test/acceptance/e3.spec.ts`): после
   подключения `profile --field attribution` печатает `off`, и строк атрибуции нет ни в сообщениях
   коммитов, ни в заголовках и текстах PR — что бы ни говорил Profile. Profile, вышедший с `on`,
   приёмку роняет, а не выключает этот поиск. Кроме выражений `silent-check`, приёмка ищет
   независимый признак: любую строку с адресом `noreply@anthropic.com`.

**Последствия.**

- **Уже подключённые Project-ы Harness не меняет.** Значение у них записано в `profile.json`
  явно — его писали и черновик подключения, и перенос. На машине владельца три Profile-а:
  `atakama` (Silent), `auction` (Full) и `worfy` (Full); у всех стояло явное `"on"`. 2026-10-13
  владелец сам переключил `atakama` на `"off"`; `auction` и `worfy` остаются с явным `"on"`.
  Harness чужой Profile не переписывает — это сделал владелец.
- **Новый Silent Project получает `off`** двумя путями сразу: значением, которое worfy ставит в
  черновик, и умолчанием в `bin/profile`, если поля в Profile-е нет (например, Profile написан
  руками).
- **При `off` guard отказывает** в `git commit` и `gh pr create|edit|comment|review|merge`, текст
  которых несёт строку атрибуции. Агент дописывает такие строки по своим общим инструкциям, а в
  Silent Profile-е слова `off` может и не быть, поэтому отказ с такой находкой кончается фразой,
  что делать: убрать строки, потому что `attribution` у Project-а `off` — либо так сказано в его
  Profile-е, либо Profile поля не задаёт, и `off` — умолчание Silent mode. Режима guard не знает,
  поэтому фраза одна и верна в обоих случаях. Hook `SessionStart` в начале каждой Session
  Project-а говорит только «Attribution is off for this project» и требование убрать строки; про
  умолчание Silent mode он не говорит.
- **Profile со значением `attribution` не из `on | off` перестаёт читаться** (код 1). Для
  `silent-check` это «Profile не прочитан» (код 2), а не «чисто». До этого решения такое значение
  печаталось как записано и совпадало по действию с умолчанием `on`.
- **В форме «Add project» режим под черновиком не меняется.** Режим выбирается до черновика, в
  форме он показан только для чтения, кнопки «назад» у формы нет. Вернуться к выбору режима можно
  только после неудавшегося или остановленного черновика, и тогда новый черновик целиком заменяет
  прежний. Значит, поле «Attribution» всегда несёт либо начальное значение для показанного режима
  (`off` для Silent, значение агента для Full), либо выбор человека.
- **В форме переноса смена режима поле `attribution` не трогает.** Там режим и атрибуция — два
  соседних поля, оба видны и оба попадают в показанный diff `profile.json`. Если владелец меняет
  предложенный Full на Silent, `attribution` остаётся прежним, пока он не поменяет и его.
  Владелец подтвердил это 2026-10-13.
- **Правка действует после установки Harness этой сборки** (`pnpm install:stable` — шаг
  владельца). Приёмка в песочнице ставит Harness своей сборки и от установленного не зависит.
- `harness/profiles/README.md` и `spec.md` Epic-а `worfy-harness` говорят новое правило.

## Considered Options

- **Умолчание по режиму в `bin/profile`; в «Add project» worfy сам ставит `off` в Silent-черновик;
  перенос предлагает значение по режиму; явное значение побеждает** (выбрано). Читатели значения
  не меняются; Harness подключённые Project-ы не трогает; копии правила держит вместе contract
  test.
- **Значение в черновике — только по тексту skill-а, worfy его не трогает.** Отвергнуто
  2026-10-13: запуск 2026-10-12 упал именно на значении `"on"`, которое модель написала в
  Silent-черновик. Решение владельца — про умолчание, и оно не может зависеть от того, послушает
  ли модель текст skill-а.
- **Ставить `off` при записи Profile-а, а не при получении черновика.** Отвергнуто: запись берёт
  черновик формы, и выбор человека `on` был бы затёрт.
- **Оставить умолчание `on`, а в Silent mode запрещать строки атрибуции всегда.** Отвергнуто:
  поле перестало бы что-либо значить в Silent mode, а пункт 6 ADR-0042 оставляет выбор за
  владельцем — он может хотеть строки атрибуции и в Silent Project-е.
- **Поменять только черновик подключения, умолчание в `bin/profile` оставить `on`.** Отвергнуто:
  Profile без поля (написанный руками или старой сборкой) в Silent mode снова дал бы следы, а
  `README` Profile-а и код говорили бы разное.
- **Поменять только умолчание в `bin/profile`.** Отвергнуто: черновик пишет поле явно, и новый
  Silent Project всё равно получил бы `"on"` — так и было в приёмке 2026-10-12.
- **Читать любое значение не из `on | off` как отсутствие поля.** Отвергнуто: опечатку вроде
  `"OFF"` в Full Project-е Harness молча прочитал бы как `on`. `bin/profile` на недопустимый
  `mode` уже отвечает кодом 1, и `attribution` идёт тем же путём; только `null` значит «поля нет».
- **Harness сам переписывает `attribution` у уже подключённых Silent Project-ов на `off`.**
  Отвергнуто как действие Harness: значение там записано явно, а явное значение ставит владелец
  (ADR-0042, пункт 6). Единственный такой Profile, `atakama`, владелец 2026-10-13 переключил сам.
- **В форме переноса менять `attribution` вслед за режимом, пока владелец поле не трогал.**
  Отвергнуто по решению владельца 2026-10-13: оба поля видны рядом и в diff, а форме пришлось бы
  помнить, какие поля трогал человек.
- **Исправить пункт 6 в самом ADR-0042.** Отвергнуто: принятые ADR правятся только в терминах
  (ADR-0017).
