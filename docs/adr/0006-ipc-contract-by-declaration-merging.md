# Каналы IPC дополняют общий контракт, обработчики подхватываются сами

Дата: 2026-10-05. Статус: принят.

Почти каждый тикет эпика `worfy-mvp` добавляет канал между renderer и main. Если каналы перечислены в одном файле, параллельные тикеты конфликтуют в нём всегда. Поэтому контракт IPC расширяется новыми файлами, а не правкой общих.

`src/shared/ipc/channels.ts` объявляет пустой интерфейс `IpcContract` и два вида каналов: запрос-ответ (`invokeChannel(name, input, output)`) и событие из main (`eventChannel(name, payload)`); вход, выход и событие описаны zod-схемами. Домен заводит файл `src/shared/ipc/<домен>.ts`: создаёт определения каналов и дополняет `IpcContract` через declaration merging (`declare module './channels'`), ключ равен имени канала. Обработчики домена — файл `src/main/ipc/<домен>.ts`, default export — список `defineHandler(канал, функция)`; `src/main/ipc/index.ts` находит такие файлы сам через `import.meta.glob` и регистрирует при запуске. Preload отдаёт в `window.worfy` три функции без списка каналов (`invoke`, `on`, `off`) и после тикета 02 не меняется. Renderer вызывает каналы через `src/renderer/ipc.ts`, где имя, вход и результат выводятся из `IpcContract`: канал вне контракта не компилируется.

Граница проверяется в main, а не доверяется типам: каждый обработчик обёрнут. Вызов принимается только от frame с URL приложения (собранный `out/renderer/index.html` или origin dev-сервера), вход разбирается схемой, исключение обработчика и выход вне схемы превращаются в `{ok:false, error}` — renderer не получает ничего, чего нет в контракте, а main не падает. События из main тоже разбираются схемой перед отправкой. Все каналы идут по Electron IPC под префиксом `worfy:`, чтобы мост не давал renderer-у доступ к чужим каналам.

Следствие: два домена с одинаковым именем канала или файл обработчиков неверной формы останавливают запуск приложения с ошибкой. Типы контракта собираются из всех файлов `src/shared/**`, поэтому файл домена должен лежать там, где его видит `tsc` (оба tsconfig включают `src/shared/**`).

## Considered Options

- Один файл со списком всех каналов (объект или union-тип). Отвергнуто: каждый тикет правит его, параллельные ветки конфликтуют в нём на каждом мерже.
- Список каналов в preload (по функции на канал в `window.worfy`). Отвергнуто: preload становится вторым центральным файлом, а меняется только вместе с main.
- Генерация контракта скриптом из файлов доменов. Отвергнуто: лишний шаг сборки и сгенерированный файл, который снова общий; declaration merging даёт то же средствами TypeScript.
- Доверять типам и не проверять данные в main. Отвергнуто: renderer показывает чужой контент (markdown, карточки), и граница процесса — место, где вход проверяется во время работы, а не только при компиляции.
- Регистрация обработчиков явным импортом в `src/main/ipc/index.ts`. Отвергнуто: та же проблема общего файла, что и у списка каналов.
