# Координаты закреплённого Node-а в Layout — экранные

Дата: 2026-10-05. Статус: принят.

**Решение.** Пока у Node-а `pinned: true`, его `x` и `y` в `layout.json` — экранные координаты
Canvas (пиксели от левого верхнего угла области Canvas), а не единицы Canvas; `w` и `h` — размер на
экране. Закрепление и открепление — одна операция `pin {id, pinned, x, y, w, h}`: флаг, положение и
размер меняются вместе, вызывающий пересчитывает их через текущий viewport
(`src/renderer/canvas/pinning.ts`). Правило держит main, единственный писатель Layout
(ADR-0003): `move` и `resize` закреплённого Node-а `src/main/layout/store.ts` отклоняет, кто бы их ни
прислал.

**Почему.** Node должен оставаться на своём месте экрана после перезапуска, а единицы Canvas этого
не дают без сохранения viewport момента закрепления.

**Следствие.** Всякий, кто читает Layout (MCP-tools Ticket-а 24, поиск Ticket-а 31), должен
учитывать `pinned`, прежде чем считать `x`/`y`/`w`/`h` прямоугольником Canvas. На дату решения
этого не делают `list_nodes` (не отдаёт `pinned`) и выбор места нового Node-а `place()` →
`placeNear` в `src/main/mcp/canvas-server.ts` (считает закреплённые Node-ы прямоугольниками Canvas);
определение «Layout» в `CONTEXT.md` об этом исключении не говорит.

Источник: Ticket 29 (`.scratch/worfy-mvp/issues/29-миникарта-закрепление-теги.md`, раздел «Итог»),
PR #14.

## Considered Options

- Экранные `x`/`y` при `pinned` (выбрано): одно поле, позиция переживает перезапуск, операция
  атомарна.
- Отдельные поля `screenX`/`screenY` рядом с канвасными: читатели Layout не путаются, но схема
  Node-а растёт, а канвасные `x`/`y` закреплённого Node-а теряют смысл и устаревают.
- Хранить канвасную позицию и viewport момента закрепления: восстановимо, но лишнее состояние на
  каждый Node и расчёт при каждом чтении.
