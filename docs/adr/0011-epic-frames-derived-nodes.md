# Рамки Epic-ов и Ticket-ы — производные Node-ы, Layout хранит только ручные изменения; MCP-tools их не показывают и не двигают

Дата: 2026-10-05. Статус: принят.

**Контекст.** Epic-и и Ticket-ы — состояние workflow (ADR-0002), Layout — собственное состояние
worfy (ADR-0005), пишет его только main (ADR-0003). Положение рамок и Ticket-ов считается из модели
workflow и меняется при каждой смене статуса или блокеров.

**Решение.** Рамки и Ticket-ы не хранятся в Layout. Renderer строит их из модели workflow чистой
функцией (`epic-layout.ts`) через точку расширения «источник Node-ов» (`canvas/sources/*.ts`).
Layout хранит на каждый Epic один Node `epic:<эпик>` вида `epic-frame` (`locked`, 1×1, не
рисуется), создаваемый при первом ручном изменении: `x`, `y` — смещение рамки от автоматического
места, `data.collapsed` — свёрнута ли рамка пользователем, `data["offset:<NN>"] = {dx, dy}` —
смещение Ticket-а от его автоматического места внутри рамки. Пересчёт автоматического размещения
сохраняет ручные смещения.

**Следствие для MCP-сервера Canvas (Ticket 24, инструменты агента для Layout).** Node в Layout
вида `epic-frame` — сохранённое состояние источника, а не Node на Canvas: `list_nodes` его не
отдаёт, `move_node`, `resize_node`, `hide_node`, `update_node` и `link_card` на него и на
`ticket:<эпик>/<NN>` отвечают ошибкой tool-а «рамки Epic-ов и Ticket-ы двигает только пользователь».
Виды и id — `src/shared/layout/derived.ts`, общий для renderer и main. Агент ссылается на Epic и
Ticket через `link_card` (`<эпик>`, `<эпик>/<NN>`), как в Ticket-е 24. Пункт Ticket-а 24 «Узлы с
`locked` (… Тикеты, рамки Эпиков) — только сдвигает» этим отменён.

**Цена.** Node-ы источников не видны тем, кто читает только `layout.json`, и значение полей Node-а
`epic-frame` задаёт renderer, а не main. Агент не раскладывает рамки и Ticket-ы.

Источник: Ticket 11 (`.scratch/worfy-mvp/issues/11-эпик-рамка-с-тикетами.md`, раздел «Итог»),
PR #18. Контракт с MCP-tools принят без решения владельца (он был недоступен) как обратимый.

## Considered Options

- Каждый Ticket и рамка — Node в Layout с абсолютными `x, y`: копирует производное состояние в
  `layout.json`; на крупном Project (Auction) — сотни операций IPC при открытии и при каждой смене
  статуса; два окна спорят за положения.
- Пакетная операция Layout: меняет схему Layout Ticket-а 05 и всё равно хранит производное.
- Производные Node-ы + смещения (выбрано): правка `Canvas.tsx` и `extensions.ts` один раз, дальше
  источники Node-ов добавляются файлом (пригодится Subagent-ам Ticket-а 15).
- Хранить в `x`, `y` Node-а `epic-frame` абсолютное положение рамки — отвергнуто. Так `move_node`
  работал бы без правок Ticket-а 24, но сдвинутая рамка перестала бы следовать за автоматическим
  местом: выросла рамка выше — и они наползают друг на друга; а размер в Layout всё равно
  отставал бы от настоящего.
- Если агенту понадобится двигать рамки: перенести `epic-layout.ts` в `src/shared` (функция
  чистая), и main, у которого уже есть модель workflow (Ticket 10), считает в `list_nodes`
  производные Node-ы с настоящими положением и размером, а `move_node` переводит в смещение от
  автоматического места. Не выбрано сейчас: модель workflow и расчёт размещения Epic-ов
  (`epic-layout.ts`) становятся зависимостью MCP-сервера, а Ticket 24 — зависимым от 11.
