# 0085 — Subagent прежнего процесса Session — статус `interrupted`; записи Subagent-ов можно скрыть
Дата: 2026-10-29. Статус: принят.

**Контекст.** В панели Subagent-ов у владельца висели записи «running 546h» и старые записи `error`.
Убить процессы и перезапустить worfy не помогало: убрать запись можно было, только отправив в архив её
Session. Причина «running 546h» — продолженная Session: Claude Code сохраняет `sessionId`, когда
Session продолжают в новом процессе (после выхода из worfy, падения, рестарта Session-а). Transcript
Orchestrator-а `f6ab7045` 2026-10-29 продолжился в том же файле через три перезапуска worfy. Процесс с
этим `sessionId` жив, поэтому по ADR-0031 Session не закрыта, и Subagent без записи о конце остаётся
`running` навсегда, хотя умер вместе с прежним процессом.

ADR-0031 отверг новый статус (раздел Considered Options, вариант `stale`): оборванный Subagent по
смыслу — `error`, а новый статус трогает все исчерпывающие таблицы статусов. Там же отвергнут переход
`running` → `done` по тишине файла: живой Subagent может молчать долго.

**Решение** (владелец, 2026-10-29).

1. **Новый статус `interrupted`.** `SubagentStatus` — `running | done | error | interrupted`.
   Subagent без записи о конце, у родительской Session которого текущий процесс запущен позже
   последней записи в transcript Subagent-а, — `interrupted`: он умер вместе с прежним процессом.
2. **Признак — смена процесса, не timeout.** Время запуска процесса — число `startedAt` (ms) записи
   `sessions/<pid>.json`, той, чей процесс жив по ADR-0031 (`pid` и `procStart`). `procStart` не
   разбирается и остаётся только проверкой «процесс жив». main (`SubagentReader.session`) кладёт
   `startedAt` сигналом `session-process` рядом с `session-closed`; учитывается только сигнал из
   потока самой Session. Последняя запись Subagent-а — время последней записи его transcript-а; у
   Subagent-а без файла — время его вызова, результата вызова или старта.
3. **Не знаем — `running`, как раньше.** Процесс не известен (`sessions/` нет, запись не читается,
   `ps` не ответил) или у записи нет числового `startedAt` — Subagent без конца остаётся `running`.
   Ложный конец живого Subagent-а хуже зависшего `running` (ADR-0031, пункт 2). Такую запись убирает
   кнопка «Hide» (пункт 6).
4. **Закрытая Session — `error`, как раньше** (ADR-0031): закрытая Session важнее нового признака.
5. **Прогон workflow-скрипта.** Агенты прогона идут через то же правило. Прогон без конца —
   `interrupted`, когда ни один его агент не `running` и хотя бы один `interrupted`; прогон без
   агентов — когда процесс запущен позже его вызова Workflow. Прогон без известного вызова
   (по папке) — так же по своим агентам.
6. **`interrupted` — законченный.** Опрос renderer-а его не держит, счётчик времени не тикает (время
   кончается последней записью), ребро рисуется как у законченного, на Canvas и в rail-е он
   сворачивается вместе с `done`. Цвет — нейтральный серый, как `done`, с меткой паузы и подписью
   «Interrupted»; не цвет `error` и не цвет `running`. Tooltip: процесс Session перезапустился после
   последней записи агента. В `CONTEXT.md` — термин «Interrupted».
7. **«Hide».** У каждой записи Subagent-а (Node на Canvas, строка rail-а) — кнопка «Hide», при любом
   статусе, `running` тоже. У свёртки законченных на Canvas и у группы «Done» в rail-е — кнопка
   «Hide» с tooltip-ом «Hide finished» (строки узкие): скрывает все законченные записи (`done`,
   `error`, `interrupted`) под этим родителем, в rail-е — всей Session; `running` не трогает. Запись, чей родитель скрыт, встаёт на место
   родителя. Скрытые записи (Session и id записи) хранит main в `hidden-subagents.json` папки данных
   Project-а (ADR 0005), не в `~/.claude`; они остаются скрытыми после перезапуска worfy. «Show
   hidden Subagents» в rail-е Session возвращает её скрытые записи. Каналы
   `claudeHome.hideSubagents` и `claudeHome.showSubagents` — `write`, на экране только для чтения
   (ADR-0066) кнопок нет; `claudeHome.hiddenSubagents` — `read`.

**Почему иначе, чем в ADR-0031.** Довод ADR-0031 «по смыслу это `error`» не держится: `interrupted`
отличается от `error` тем, что агент не упал — его процесс завершили снаружи. Пользователь может
продолжить работу или не обращать внимания; красить такой Subagent как сбой — ложная тревога. Довод
«новый статус трогает все таблицы статусов» верен, и цена принята: все таблицы (`CHIP` Node-а и
rail-а, подпись статуса, заголовок transcript-а Subagent-а, опрос, счётчик, ребро, свёртка) меняются
в том же PR. Довод против timeout по тишине файла остаётся в силе: признак здесь — новый процесс.

**Последствия.**

- Subagent продолженной Session, умерший с прежним процессом, показывается `interrupted`, а не
  `running` с растущим временем; опрос его Session прекращается.
- Не проверено: Subagent, который пережил смену процесса своей Session. Сегодня Subagent живёт в
  процессе Claude Code своей Session (ADR-0029, ADR-0031), так что такого не бывает; если Claude Code
  начнёт переносить Subagent-ов в новый процесс, правило даст ложный `interrupted` у того, кто не
  писал с момента нового запуска, и его надо будет пересмотреть.
- Не проверено: часы. `startedAt` и время записей transcript-а берутся с одной машины, но перевод
  часов назад между записью и новым запуском даст `running` вместо `interrupted` (как сегодня).
- Linked machine старой версии worfy не знает сигнала `session-process` и не примет ответ
  `claudeHome.subagents` от машины новой версии; обе машины обновляются вместе.
- Список скрытых растёт с каждым «Hide»; на Session хранится не больше 20 000 id, самые давно скрытые
  уходят первыми.

## Considered Options

- **Timeout по возрасту файла или тишине** (`running` → `done` или `error` через N часов).
  Отвергнут, как в ADR-0031: живой Subagent молчит долго, правило дало бы ложный конец.
- **Оборванный — `error`, как при закрытой Session.** Отвергнут владельцем: агент не упал; красный
  или янтарный цвет сбоя для него — ложная тревога.
- **Сравнивать `procStart` вместо `startedAt`.** Отвергнут: `procStart` — строка `ps` в формате
  системы (на Windows — своя), её разбор зависит от платформы и локали; `startedAt` — число ms,
  которое пишет сам Claude Code.
- **«Hide» только у законченных.** Отвергнут: при неизвестном процессе (пункт 3) запись `running`
  иначе не убрать.
- **Хранить скрытые записи в renderer-е (`localStorage`).** Отвергнут: worfy держит своё состояние
  в папке данных (ADR 0005), а скрытие должно пережить перезапуск и быть одним на все окна.
