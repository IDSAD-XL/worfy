# 0079 — worfy-link: Machine объявляет, какие сообщения связи принимает
Дата: 2026-10-20. Статус: принят.

**Контекст.** Ticket 10 Epic-а `worfy-pipeline` шлёт уведомление «ждёт тебя» о Ticket-е на Linked machines
новым сообщением связи. Сообщения связи (service messages) — точка расширения `worfy-link`: модуль
регистрирует сообщение по имени со схемой zod и шлёт его Machine по id (`src/main/link/messages.ts:4-9`).

Что есть сейчас:

- Версия протокола связи — одно число, `LINK_PROTOCOL_VERSION = 3` (`src/main/link/messages.ts:20`). Сервер
  отказывает в соединении, если число другое (`src/main/link/server.ts:52-54`). Поднять версию ради нового
  сообщения — значит разорвать связь со всеми сборками worfy старше.
- `hello` — первый кадр каждого соединения (`src/main/link/service.ts:607`): `id`, `name`, `protocol`,
  `build`, `port` (`src/main/link/messages.ts:58-68`). Списка сообщений, которые Machine понимает, в нём нет.
- Получатель бросает сообщение, имени которого не знает, и пишет предупреждение в лог
  (`src/main/link/messages.ts:103`). Сборка старше просто не покажет новое уведомление, но каждое такое
  сообщение — лишний кадр и строка лога у неё.

Решение владельца 2026-10-20 (grilling, Q12): новое сообщение уходит только тем Machine, которые объявили,
что его поддерживают, при установке связи; сборки старше эти уведомления не получают, и ничего не ломается.

**Решение.**

1. **`hello` получает необязательное поле `accepts`** — имена сообщений связи, которые эта Machine
   обрабатывает: те, что зарегистрированы на её link service (`LinkService.registerMessage`). Пределы —
   не больше 200 имён, каждое — как имя в кадре (`1–200` символов, `frameSchema`).
2. **Список живёт, пока живёт соединение.** Отправитель держит `accepts` каждой подключённой Machine в
   памяти; новое соединение и его `hello` заменяют список. В `link/settings.json` и в хранилище Machine он
   не пишется. `hello` из pairing (`src/main/link/pairing.ts:275-276`) список не задаёт: он приходит с
   `hello` соединения, которое идёт сразу после.
3. **Новое сообщение — только тем, кто его назвал.** Сообщение, которое появилось после этого ADR (первое —
   заметка Ticket-а `worfy-pipeline` 10), уходит Machine только если её `accepts` его называет. Machine без
   `accepts` (сборка старше) получает только сообщения, которые были до этого ADR.
4. **Версия протокола не меняется** (остаётся 3). `accepts` необязателен; сборка старше разбирает `hello`
   схемой `z.object`, а она в zod 4 отбрасывает незнакомые поля, так что `hello` новой сборки проходит
   у старой без ошибки. Версия поднимается, как и раньше, только когда меняется смысл уже существующего
   сообщения или кадра.

**Последствия.**

- Новое сообщение связи больше не требует поднимать версию протокола и обновлять обе Machine разом.
- Отправитель проверяет `accepts` перед каждой отправкой нового сообщения; это одна функция link service,
  её зовут модули, которые шлют сообщения.
- Machine, которая ещё не прислала `hello` по новому соединению, считается Machine без `accepts`: новое
  сообщение в это окно не уходит. Для уведомлений это та же потеря, что у Machine без соединения
  (`src/main/link/notes.ts`: «A Machine that is not connected misses the note»).
- Test: `hello` с `accepts` и без него проходит схему; сообщение не уходит Machine без `accepts` и уходит
  Machine, которая его назвала.

## Considered Options

- **Поле `accepts` в `hello` каждого соединения** (выбрано).
- **Поднять `LINK_PROTOCOL_VERSION` до 4.** Отвергнуто: сервер отказывает в соединении при любой другой
  версии (`server.ts:52-54`), и Mac и ПК со сборками разного возраста теряют связь целиком ради одного
  уведомления.
- **Слать всем; старая сборка бросит сообщение сама** (`messages.ts:103`). Отвергнуто владельцем (Q12):
  лишний кадр и предупреждение в логе сборки старше на каждое уведомление, и нет способа узнать, дойдёт ли
  сообщение.
- **Версия сборки в `hello` (`build`) как признак поддержки.** Отвергнуто: `build` — строка
  `<semver>+<SHA>`; сравнение по ней связывает каждое сообщение с номером версии, а dev-сборка с той же
  версией может не иметь нужного кода.
- **`accepts` в хранилище Machine (`store.touch`).** Отвергнуто: после обновления worfy на той Machine
  записанный список устаревает до следующего соединения; из `hello` соединения он всегда свежий.
