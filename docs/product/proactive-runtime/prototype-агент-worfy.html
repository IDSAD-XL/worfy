THROWAWAY PROTOTYPE — агент worfy, вопрос 10 карты proactive-runtime. Не код worfy и не spec. Нажмите, чтобы прочитать, что он проверяет и как им пользоваться.

Вопрос. Где и как владелец видит агента worfy? Три ответа:

  • A — раздел в sidebar рядом с Sessions и Pull requests;
  • B — отдельный экран Today по всем Project-ам и обеим машинам;
  • C — режим без экрана: агент виден только через уведомления и Command palette.

Решения владельца 2026-11-20, которые прототип соблюдает:

  • Права варианта C. Сам агент делает только действия из закрытого списка, и их текст задаёт main. Остальное он предлагает. Epic-и в очередь не ставит.
  • По агенту на каждую машину. Здесь агент на Mac; Project «demo» на PC он только читает.
  • Обязанности общие и не привязаны к устройству репозитория worfy:
    • Session молчит дольше N минут или ждёт ответа;
    • Run остановился;
    • CI ветки по умолчанию красный дольше N минут;
    • PR ждёт пользователя;
    • утренняя сводка.
    N и каждое правило — настройки. Правила одного Project-а показаны только как пример своих правил в настройках Project-а worfy: «land закончились, а Orchestrator спит» и «открыт issue с меткой pc-main-red».
  • У каждого источника своя проверка и свой интервал: Slack — около 10 минут, Jira — раз в час. Настраиваются work hours; вне их часть проверок спит. Выключается всё, включая самого агента.
  • Агент выключен по умолчанию, worfy предлагает его один раз, внешние источники включаются по одному. Это показывает кнопка «First run (new user)».
  • Действия закрытого списка main делает сам, без модели. Модель просыпается для срочного, пакетами в work hours, утром и когда ей пишут. Текст Slack и Jira сортирует Haiku 5.5. В настройках есть проверка Limits, дневной предел пробуждений и счётчики пробуждений и token-ов.
  • Знакомство. Первое сообщение агента говорит, кто он, что делает и чего не делает, и предлагает настроить сервисы. Изменения применяются по Apply. В чате к агенту всегда можно обратиться за донастройкой и за помощью по worfy.
  • У каждого сообщения агента есть 👍 и 👎. 👎 сразу становится правилом в памяти агента и скрывает такие пункты этой обязанности. 👎 на строке журнала переводит действие в режим «ask».
  • Шесть границ:
    • у агента только tools worfy-app: в чате он отказывается делать push, merge и отправку;
    • чужой текст помечен как данные, с источником и автором;
    • Prepare показывает точный текст Session до старта;
    • наружу агент ничего не отправляет;
    • Project-ы PC агент только читает;
    • всё попадает в журнал.
  • Рабочее допущение вопроса 07, вариант c: каждое пробуждение — новая Session приложения с файлом памяти. Владелец его словом не подтвердил.

Что проверяет каждый вариант:

  • A, раздел в sidebar: хватает ли узкой колонки рядом с Canvas, если агент всегда на виду. Настоящий sidebar — 264 px; здесь он 400 px, чтобы текст читался.
  • B, экран Today: нужен ли отдельный экран по всем Project-ам, который открывают утром. Риск: общие ленты находок у конкурентов закрыли — ChatGPT Pulse закрыт 2026-06-17 в пользу Scheduled tasks.
  • C, тихий режим: можно ли обойтись без экрана. Уведомлять только о том, что блокирует работу, остальное держать в ⌘K.

Как пользоваться:

  • Вариант переключают ← и →, полоса внизу или ?variant=A|B|C.
  • Кнопки строкой ниже двигают время, запускают пакетное пробуждение и проверку Slack, меняют Limits, закрывают день и начинают с нуля как новый пользователь.
  • «End of day» помечает нетронутые пункты как ignored. После трёх подряд обязанность встаёт на паузу.
  • Панель State справа показывает всё состояние после каждого действия.
  • Данные выдуманы.
