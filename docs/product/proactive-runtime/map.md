# Proactive worfy: агент worfy поверх всех Project-ов — карта

Тема Product Session `proactive-runtime`, начата 2026-11-20. Вход — бриф владельца из PR #2052 «docs(product): explore
Haiku-first Proactive Runtime for Worfy»: файл `brief.md` этой папки, ветка
`docs/proactive-haiku-first-discovery-2026-11-20`. На 2026-11-20 PR открыт, в main бриф ещё не влит.

## Destination

Владелец выбрал build: «сразу все делаем и на мне тестируем, если вдруг что - поправим» (2026-11-20). Цель карты:

- владелец принял черновик Epic-а [`worfy-assistant`](drafts/worfy-assistant.md) (первая строка под заголовком —
  `Advisor draft`). Термин «Assistant» и имя Epic-а предложил советник: слово «агент» в глоссарии worfy уже значит
  Claude Code или Codex, который ведёт любую Session. Владелец подтвердил («Да») и сказал: «Сохраняй если всё готово»
  (2026-11-20);
- перед приёмкой критик разобрал черновик.

Отдельного пилота с этапами и критериями опровержения нет: проверка идёт на владельце.

## Notes

- **Слова владельца, 2026-11-20:** «К конкретным техническим или структурным утверждениям серьезно не лишь наброски. И
  фича должна быть даже чуть больше чем просто реакцией на сигналы, возможно даже в виде какого-то агента поверх всех
  проектов, агент самого ворфи».
- **Что просит бриф:**
  - доказать нужность сверх PR Inbox, Notifications и Autopilot;
  - сверить каждую посылку с main и ADR;
  - задавать вопросы по одному;
  - разобрать вариант критиком;
  - предложить самый дешёвый эксперимент.

  Ни Ticket-ов, ни кода, ни Autopilot по одному этому брифу.
- **Skills темы:** `worfy:grilling` и `worfy:domain-modeling` для вопросов; `worfy:research` для фактов, заметки — в этой
  папке; `worfy:prototype` — один HTML-файл в этой папке; `worfy:to-spec` для черновика; `worfy:critic` перед приёмкой.
- **Решения владельца 2026-11-20, действуют для всей темы:**
  - Haiku 5.5 вместо закреплённой Haiku 4.5: «Переходим на 5.5, без проблем. Это по прежнему очень дешевая и очень
    быстрая модель»;
  - шум проактивных подсказок снимают like и dislike на сообщениях агента: по ним агент постепенно собирает, что
    владельцу нравится, а что нет;
  - правила Anthropic: «Отсутствие разрешения пропускаем, действуем в парадигме того что подобное разрешено»;
  - правило ADR-0058 (пункт 3), по которому Suggestion Terminal AI отменяется на thinking, меняется: «Тогда поменяй это
    правило, что бы оно не мешало». Изменение делает Orchestrator — Ticket worfy-polish 135
    ([описание](для-orchestrator-а-haiku-5-5.md));
  - регулярные проверки источников, у каждого типа свой интервал: Slack — около 10 минут, Jira — раз в час. Настраиваются
    work hours пользователя (ночью часть проверок спит) и каждый тип проверки;
  - по агенту на каждую машину, для её Project-ов: «верно»;
  - «всё должно быть опционально, в том числе и само наличие этого ассистента»;
  - дружелюбное знакомство: агент говорит, кто он и что умеет, и помогает настроить нужные сервисы. К нему всегда можно
    обратиться за донастройкой и за помощью разобраться в самом worfy ([вопрос 13](issues/13-знакомство-и-помощь.md)).
- **Ограничения:** репозиторий публичный — в файлах темы нет имён рабочих Project-ов, людей и адресов. Аналитики
  использования нет.
- **Предложение советника:** [предложение-агент-worfy.md](предложение-агент-worfy.md) — три слоя:
  - журнал внимания в main без модели;
  - агент worfy — Session приложения с MCP `worfy-app` и файлом памяти;
  - прежние исполнители.

  Обязанности для начала и цена тоже там.
- **Факты на 2026-11-20 (main `ad2169058`), сверены с кодом.** Модели и вход:
  - Haiku не выбирается моделью Session (`src/shared/agent/settings.ts:64-65`): с 634 MCP-tools владельца второй ход
    падал с «Prompt is too long» (ADR-0021).
  - Изолированный одноразовый вызов уже есть у narrator и Terminal AI: без настроек Project-а, MCP, tools и
    transcript-а, один ход (`src/main/vendors/claude/narrator.ts:53-62`). Модель — `claude-haiku-4-5`
    (`src/main/vendors/claude/terminal-ai.ts:70`): Haiku 5.5 нельзя без thinking (там же, `:64-69`).
  - worfy удаляет `ANTHROPIC_API_KEY` и `ANTHROPIC_AUTH_TOKEN` из окружения (`src/main/agent/env.ts:38`, `:77-80`), так
    что режима с API key нет. У Codex нет одноразового вызова (`src/main/vendors/codex/one-shot.ts:7`).
- **Сигналы:**
  - общей шины событий в main нет;
  - PR Inbox уведомляет только о «Review requested» и «New reply» (`src/main/notify.ts:618`), а какие события уже
    уведомлены, помнит в памяти (`:661-668`);
  - «Needs a fix» — группа PR и кнопка pr-fix (`src/main/actions/launch.ts:358-399`), без разбора комментария и без
    предложения;
  - по всем Project-ам есть только счётчики (`src/main/claude-home/pulse.ts:1-19`) и утренний digest PR без модели
    (`docs/features/notifications.md:80-100`).
- **Структура:**
  - все MCP-серверы worfy привязаны к одному Project-у через cwd (`src/main/mcp/canvas-server.ts:563-567`);
  - roadmap исключает советника по расписанию и Epic-и, которые worfy ставит в очередь сам (`docs/roadmap.md:438-439`);
  - `worfy-needs-you` и `worfy-triggers` отложены (`docs/research/2026-11-13-competitors/README.md:849-854`).
- **Потребность:** за 2026-08-21 — 2026-11-20 набралось 28 случаев, когда работа стояла
  ([research-история-простоев.md](research-история-простоев.md)). Там, где остановился агент или пришло событие PR либо
  CI, читаемый сигнал лежал от 4 часов до 14 дней. 2026-10-20 владелец поручил эту роль Orchestrator-у словами.

## Decisions so far

- [Что агент worfy делает сам, а что оставляет владельцу](issues/01-что-агент-делает-сам.md): вариант C. Агент сам
  делает только внутренние обратимые действия из закрытого списка, который утверждает владелец; всё остальное
  предлагает. Epic-и в очередь не ставит, вовне без щелчка не публикует.
- [Где живёт агент](issues/07-где-живёт-агент.md): вариант c.
  - Новая Session приложения на каждое пробуждение и файл памяти; cwd вне Project-ов.
  - Свои правила Harness (`WORFY_SESSION_KIND=agent`) и MCP `worfy-app`.
  - По агенту на каждую машину.
  - Будят его и регулярные проверки источников с work hours.
- [Для кого агент worfy в первой версии](issues/04-для-кого-агент.md):
  - у нового пользователя и после обновления агент выключен;
  - один раз worfy предлагает его включить;
  - после включения работают только внутренние обязанности, внешние источники включаются по одному;
  - у владельца агент включён — это пилот.
- [Пилот и что его опровергнет](issues/11-пилот-и-что-его-опровергнет.md): этапов и теневого режима нет. Всё сразу,
  проверка на владельце, исправления по ходу. Счётчики и like/dislike остаются.
- [Знакомство с агентом и помощь по worfy](issues/13-знакомство-и-помощь.md):
  - знакомство — при одноразовом предложении или когда пользователь впервые сам включает агента;
  - настройки меняет только щелчок Apply;
  - token-ы агент не видит;
  - отвечает о worfy по `docs/features`, которые кладутся в приложение, на языке Guide.
- [Как Assistant выглядит для владельца](issues/10-прототип-экрана-агента.md): вариант A прототипа — раздел в rail
  рядом с Canvas. У Assistant-а есть и свои уведомления: они отличаются от обычных уведомлений worfy и стоят в другом
  месте. Дизайн — в стиле worfy, красивее и интереснее; его делает первый Ticket Epic-а как прототип-Card, и владелец
  смотрит его до Ticket-ов UI.
- [Разбор критика](../critic/worfy-assistant-2026-11-20.md), вердикт Split. Владелец, «Все верно» на предложение
  советника: разделение на два Epic-а отклонено; пропущенные зависимости и причина простоя 2026-11-13 приняты. В
  черновике теперь 20 Ticket-ов в 9 Wave-ах.
- [Как worfy читает внешние источники](issues/12-как-читать-внешние-источники.md): вариант В — connectors claude.ai.
  Проверку делает одноразовый вызов Haiku 5.5 только с read tools одного connector-а. Пользователь видит, сколько
  token-ов и какую долю Limits потратил Assistant.
- [Что будит агента и как ограничить цену](issues/06-что-будит-агента-и-цена.md):
  - закрытый список действий main выполняет сам, без модели;
  - модель просыпается сразу при срочном, пачкой в work hours, утром и когда пишет пользователь;
  - Slack и Jira сортирует Haiku 5.5;
  - перед пробуждением — проверка Limits и дневной предел.

  Правила агента не привязаны к процессу репозитория worfy.
- [Замер: сколько событий в день дают источники](issues/05-замер-событий.md): после фильтра по полям — медиана 15
  пунктов в день, после склейки — 8,5. Для событий worfy и GitHub модель на каждое событие не нужна. Slack и Jira не
  измерялись.
- [Агент и прежние решения](issues/08-агент-и-прежние-решения.md):
  - из «Не в направлении» roadmap убран советник по расписанию; запрет на Epic-и, которые worfy ставит в очередь сам,
    остаётся;
  - ADR-0100 не меняется;
  - `worfy-needs-you` становится журналом внимания агента, `worfy-triggers` — его регулярными проверками.

  Правку roadmap делает Orchestrator ([описание](для-orchestrator-а-roadmap.md)), docs PR #2057.
- [Чего агент не сможет никогда, и где это закреплено](issues/09-чего-агент-не-сможет.md): шесть границ в коде:
  - только tools `worfy-app`;
  - чужой текст — данные;
  - сам агент делает только действия из закрытого списка с текстом от main; Session с текстом агента стартует только по
    щелчку владельца, и владелец видит этот текст;
  - наружу — только Send;
  - Project-ы второй машины — только чтение;
  - всё — в журнал.
- [Правила Anthropic для фонового агента на подписке](issues/02-правила-anthropic-для-фонового-агента.md):
  - прямого разрешения стороннему приложению будить Claude Code на подписке нет; Consumer Terms разрешают
    автоматический доступ только с API key или с явного согласия;
  - цена Haiku 5.5 в брифе верна, но thinking в Claude Code не выключить;
  - реакцию на review и CI Anthropic уже делает сама (Auto-fix в Desktop, Projects); взгляда по всем локальным
    Project-ам у неё нет.
- [Проактивные агенты у конкурентов](issues/03-проактивные-агенты-у-конкурентов.md):
  - общие ленты находок свернули: Pulse, Suggested Tasks у Jules, inbox решений Antigravity;
  - остались обязанности агента с областью, предложение по умолчанию и самостоятельность по классу действия;
  - главная измеренная проблема — шум; маленькие модели Linear убрал из triage.

## Not yet specified

- Агент для команды из нескольких людей.

## Out of scope

- Публикация вовне без щелчка владельца: ответ в PR, комментарий, письмо, сообщение. ADR-0105 в этой теме не
  пересматривается. Так просит бриф (раздел 6, пункт 5).
