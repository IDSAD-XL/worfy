# 05 — Замер: сколько событий в день дают источники у владельца

## Question

Сколько событий в день за 14 дней (2026-11-06 — 2026-11-20) дают источники Project-а worfy: PR и CI на GitHub, журналы
Autopilot-а, Session-ы, Ticket-ы, которые ждут владельца? Сколько из них остаётся после детерминированного фильтра:
комментарий не владельца, красный main, красный check без нового push дольше 30 минут, остановка Run-а, ошибка
Session, Ticket, заблокированный на владельце?

Ответ решает, нужен ли дешёвый разбор каждого события моделью или хватит нескольких пробуждений сильной модели в день.

## Answer

Заметка: [research-замер-событий.md](../research-замер-событий.md), период 2026-11-06 — 2026-11-20. Главное:

- **Сырой поток.** Медиана — около 930 событий в день без check run-ов (максимум 1 658) и 3 337 с ними. Догадка брифа
  «1 000 в день» верна только без check run-ов, а check run-ы — 71 % всего объёма.
- **После фильтра по полям** остаётся медиана 15 пунктов в день (максимум 26). Склейка по PR, Ticket-у и Session-у за
  день даёт медиану 8,5 (максимум 16). Фильтр работает без чтения текста.
- **Срочного мало.** main красный дольше 30 минут — 7 раз за 14 дней; остановок Autopilot-а — 5.
- **Вывод.** Для событий worfy и GitHub сортировать каждое событие моделью ради объёма не нужно: 3–4 пакетных
  пробуждения в день увидят по 2–5 пунктов, срочное будит сразу.
- **Чего замер не знает.**
  - Чужих комментариев в репозитории 0: всё пишет один аккаунт, поэтому правило «комментарий не владельца» не проверено.
  - Ожидание Session-а — оценка сверху.
  - Session-ы на PC и Codex не посчитаны.
  - Slack и Jira не измерялись.
