## Question

Что будит агента — события, расписание (утренняя сводка), слова владельца — и как ограничить цену?

Варианты разбора событий:

- детерминированные правила без модели;
- Haiku на каждое событие (бриф);
- пачка событий раз в N минут, на которую стартует одна новая Session сильной модели;
- локальная модель (исходная идея владельца).

Факты:

- Сколько подписки стоит один вызов, Anthropic не публикует. 34 запроса spike-а не сдвинули 5-часовое окно на 1 %
  (`docs/adr/0058-terminal-ai-assist-process.md:154-155`).
- Продолжение длинной Session после того, как cache остыл, заново отправляет весь контекст. Замер: 287 865 token-ов
  после паузы 44 часа, около $2,30 по цене API; на тёплом cache — около $0,06
  (`docs/product/code-stories/research-из-чего-строить-code-story.md:35-38`).
- Проверка бюджета перед вызовом есть только у Terminal AI: автоматические функции останавливаются, когда 5-часовое
  окно занято больше чем на 80 % (`src/main/terminal-ai/limits-gate.ts:20`). Вызовы narrator в учёт лимитов не попадают.

## Answer

Владелец, 2026-11-20: «Все остальное да», кроме правила «main красный дольше 30 минут»: «думаю это правило слишком
привязано конкретно к нашей специфике работы с этом репозитории».

1. **События worfy и GitHub разбирает фильтр по полям, без модели.** Замер — медиана 15 пунктов в день, после склейки
   8,5 ([вопрос 05](05-замер-событий.md)).
2. **Действия из закрытого списка main выполняет сразу и сам, без модели.** Каждое пишется в журнал агента.
3. **Модель просыпается:**
   - сразу, если дело срочное: работа стоит и закрытый список не помог; Run остановился;
   - пачкой в work hours и утром для сводки;
   - когда пишет пользователь.
4. **Slack и Jira проверяются по интервалам без модели.** Новый текст сортирует Haiku 5.5, сильного агента зовёт только
   сортировка. Как читать источники, решает [вопрос 12](12-как-читать-внешние-источники.md).
5. **Перед автоматическим пробуждением main проверяет Limits.** Есть дневной предел автоматических пробуждений; счётчики
   пробуждений и token-ов видны в настройках.

Принцип владельца для всех правил агента: не привязывать их к тому, как работают в репозитории worfy. Предложение
советника — подтвердить в черновике:

- встроенные правила опираются только на то, что есть у любого Project-а: Session молчит или ждёт ответа, Run
  остановился, CI основной ветки красный дольше N минут (N и само правило настраиваются), PR ждёт пользователя;
- процесс конкретного Project-а — land, `pc-main-red`, gate — задаётся правилами в настройках этого Project-а.
