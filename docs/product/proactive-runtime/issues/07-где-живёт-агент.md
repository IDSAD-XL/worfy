## Question

Где живёт агент worfy?

- Процесс: код в main worfy, отдельная Session Claude Code или то и другое.
- Папка: cwd вне всех Project-ов.
- MCP-сервер приложения (рабочее имя `worfy-app`): какие tools читают все Project-ы и какие создают предложения.
- Память между пробуждениями: файл состояния, обязательства, предпочтения владельца.
- Машина: Mac, PC или обе.
- Vendor: Claude Code, Codex или оба.

Факты:

- Все MCP-серверы worfy привязаны к одному Project-у через cwd Session. Session с cwd вне Project-а `worfy-canvas` не
  получает (`src/main/mcp/canvas-server.ts:565`).
- Session можно запустить из main без Node на Canvas (`src/main/agent/session/registry.ts:110`).
- Общей шины событий в main нет. Есть отдельные точки, на которые можно подписаться: `SessionRegistry.observe`,
  `PrInbox.onChange`, подписчик workflow hub, `healthReports().subscribe`.
- У Codex нет одноразового вызова (`src/main/vendors/codex/one-shot.ts:7`).

## Answer

Вариант c. Владелец, 2026-11-20: «2 вопрос тоже подверждаю, да». Детали с поправками владельца:

- **Где живёт.** Новая Session приложения на каждое пробуждение; память — файл состояния. cwd — папка данных worfy вне
  всех Project-ов.
- **Свои правила Harness.** Третий вид Session: `WORFY_SESSION_KIND=agent`.
- **MCP-сервер `worfy-app`**, привязанный к приложению. У агента только его tools — без Bash, записи файлов и сети
  ([вопрос 09](09-чего-агент-не-сможет.md)).
- **По агенту на каждую машину**, для её Project-ов; Project-ы второй машины — только чтение («верно»).
- **Будит агента не только граница работы.** Работают регулярные проверки источников, у каждого типа свой интервал,
  плюс work hours пользователя («Нет, будить нужно не только при работе…»). Как проверка доходит до модели, решает
  [вопрос 06](06-что-будит-агента-и-цена.md).
