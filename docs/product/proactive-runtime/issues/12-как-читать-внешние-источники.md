# 12 — Как worfy читает внешние источники: Slack, Jira, почта, календарь

Type: research
Status: done 2026-11-20
Blocked by: —
Source: [map.md](../map.md), Notes; решение владельца 2026-11-20 о регулярных проверках

## Question

Владелец решил: у каждого источника своя регулярная проверка со своим интервалом — Slack около 10 минут, Jira раз в
час. Work hours пользователя настраиваются, и ночью часть проверок спит. Каждый тип проверки настраивается.

Как приложение на машине пользователя может регулярно читать Slack, Jira, Gmail и Google Calendar?

- **Пути доступа.** Своё OAuth в main; MCP-серверы, которые пользователь уже подключил к Claude Code; connectors
  claude.ai в вызове модели.
- **Ограничения API.** Лимиты запросов при опросе раз в 10 минут или раз в час. Можно ли получать push без публичного
  адреса.
- **Раздача worfy другим.** Какие нужны scope и что нужно, чтобы раздавать worfy другим пользователям: проверка
  приложения Google для restricted scope, правила Slack для приложений вне Marketplace.
- **Что уже есть в worfy.** Может ли main вызвать tool MCP-сервера без модели; где хранить token-ы; что с проверками,
  пока Mac спит.

  `src/shared/autopilot/run-mode.ts:40`, `src/main/vendors/claude/mcp-inventory.ts:3-7` и `:19`,
  `src/main/link/secrets.ts:7-11` перечитаны вручную.
  - **MCP-клиента в main нет.** Список MCP-серверов worfy получает через query Claude Code без единого сообщения, то
    есть без вызова модели, за ~1,8 с, и видит только статус серверов (`src/main/vendors/claude/mcp-inventory.ts:3-7`).
    Вызвать tool чужого сервера main не может.
  - **Connectors claude.ai** в этом списке есть (`:19`), но вызвать их может только Session Claude Code. Значит,

    модели.
  - **Хранилище секретов одно:** файл с правами 0600 у Link (`src/main/link/secrets.ts:7-11`). Keychain (safeStorage)
    обходят намеренно: подпись worfy меняется с каждой сборкой, и Keychain спрашивал бы доступ после каждого обновления.
    Хранилище спрятано за интерфейсом `SecretStore`.
  - **Общего планировщика нет:** каждая периодическая работа в main заводит свой таймер — 22 вызова `setInterval` в

  - **Понятие времени суток есть одно** — окно старта Autopilot-а: по умолчанию 23:00–07:00, только часы, одно окно,
    без дней недели (`src/shared/autopilot/run-mode.ts:40`, `inWindow` там же). Для work hours его нужно обобщить.
  - **Сон машины.** Пока Mac спит, таймеры стоят; когда worfy закрыт, не работает ничего. Mac не засыпает только во
    время Run-а Autopilot-а и пока подключена Linked machine.
  - **Настройки машины** лежат в `app-settings.json`. Их каналы `local`: Linked machine их не видит.
  - **Интеграций кроме GitHub в коде нет.**
- 2026-11-20, что говорят документы vendors: [research-внешние-источники.md](../research-внешние-источники.md). Четыре
  факта, от которых зависит выбор, второй Subagent перечитал на официальных страницах 2026-11-20 и подтвердил дословными
  цитатами:
  - **Slack, правило 2025-05-29.** У app вне Marketplace, созданных после 2025-05-29, и у их новых установок
    `conversations.history` и `conversations.replies` дают «1 request per minute» и «a maximum of 15 objects per
    request». «Internal customer-built applications are not impacted by these changes» — у них по-прежнему 50+ запросов
    в минуту. `search.messages` эта запись не упоминает.
  - **Slack, `search.messages`.** Нужен user token со scope `search:read`, «Tier 2: 20+ per minute». Страница метода:
    «This is a legacy method»; вместо него Slack советует Real-time Search API, а он app вне Marketplace закрыт.
  - **Slack, PKCE с 2026-03-30.** Код обменивается «without a client secret». Redirect на `localhost` «cannot request
    bot scopes». «All refresh tokens issued to PKCE-enabled apps expire after 30 days».
  - **Jira.** «API token-based traffic is not affected by this change, and will continue to be governed by existing
    burst rate limits». Квота 65 000 points в час «across all tenants» — общая для каждого app (Forge, Connect, OAuth 2.0
    3LO), не только для 3LO.
  - **Gmail и Google Calendar.** Общий Google client worfy для Gmail требует проверки restricted scope, а если данные
    идут «from or through a third-party server», ещё и ежегодной оценки безопасности; цену Google не публикует. Обход —
    Personal mode: каждый пользователь создаёт свой client в Google Cloud. Calendar — sensitive scope: проверка без
    оценки безопасности. Эти факты не перепроверялись вторым Subagent-ом.
  - **Push без публичного адреса.** У Slack это Socket Mode, и только у app не из Marketplace. У Gmail — `watch` в
    Cloud Pub/Sub, который worfy всё равно опрашивал бы через pull-подписку. Jira и Calendar без своего HTTPS-сервера
    дают только опрос.

## Answer

Советник предложил четыре пути (вопрос 10 разговора, 2026-11-20):

- **А** — свой HTTP-клиент в main: API token Jira, internal app Slack и `search.messages`;
- **Б** — общее Slack app worfy со входом через PKCE;
- **В** — connectors claude.ai через вызов модели;
- **Г** — MCP-клиент в main.

Советник рекомендовал А. Владелец, 2026-11-20: «Вариант А - неудобен, нужно много действий руками, а internal app для
слака это дополнительные неудобства и вероятность того что админ не разрешит. Склоняюсь к варианту В. Так же добавить
нужно мониторинг сколько процентов лимита и токенов съел ассистент, что бы юзер мог это видеть».

Решение — **В**.

- **Пользователь подключает Slack и Jira в claude.ai.** Своих token-ов у worfy для этих источников нет. Какие
  connectors подключены, main узнаёт без вызова модели: из списка MCP-серверов, который уже собирает Claude Code
  (`src/main/vendors/claude/mcp-inventory.ts:15-22`).
- **Проверку источника делает отдельный одноразовый вызов Haiku 5.5.** В нём только read tools одного connector-а: нет
  ни tools Claude Code, ни `worfy-app`. Вызов возвращает структурированные пункты, main проверяет их форму. Session
  Assistant-а по-прежнему видит только tools `worfy-app` и получает пункты как данные, с источником и автором. Так
  границы 1 и 2 вопроса 09 держатся.
- **Что ещё не известно и проверяется первым шагом Ticket-а:**
  - можно ли оставить в вызове один connector и только его read tools;
  - сколько места в контексте займут tools connector-ов: с 634 tools у Haiku второй ход уже падал с «Prompt is too
    long» (ADR-0021).

  Если ограничить вызов нельзя, Ticket останавливается и возвращается к владельцу с вариантами.
- **Цена.** Каждая проверка — вызов модели: Slack раз в 10 минут за 10 рабочих часов даёт 60 вызовов в день, Jira раз в
  час — 10.
- **Мониторинг.** Пользователь видит, сколько token-ов и какую долю Limits потратил Assistant: всего, по источникам и
  по пробуждениям. Token-ы считаются по каждому вызову. Доли отдельного вызова в окне Limits worfy не знает: он видит
  только общий процент окна (`docs/features/transcripts-and-usage.md`). Поэтому процент — оценка, и на экране он
  помечен как оценка.
- **Admin.** Slack пишет, что admin workspace одобряет и ведёт все интеграции MCP-клиентов. Через что connector Claude
  ходит в Slack, не проверено. Одобрять в этом случае придётся известное приложение, а не своё internal app
  пользователя.
- **Gmail и Google Calendar.** С вариантом В это ещё два рецепта на том же механизме, без проверки Google для worfy.
  Советник предлагает не включать их в этот Epic; владелец об этом ещё не сказал.
