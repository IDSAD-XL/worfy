# 09 — Чего агент не сможет никогда, и где это закреплено

Type: grilling
Status: done 2026-11-20T03:20Z
Blocked by: 01
Source: [map.md](../map.md), Notes; бриф, раздел 8

## Question

Какие границы агент не переходит никогда, и как они закреплены в коде, а не только в тексте правил?

Факты:

- worfy публикует ответ на PR только через `prInbox.send` по щелчку Send (`src/shared/ipc/pr-inbox.ts:246-251`). Но
  Session в `bypassPermissions` может сама вызвать `gh api` и опубликовать текст. ADR-0105 называет эту силу агента
  «описана, а не закрыта» (`docs/adr/0105-pr-reply-only-on-the-users-click.md:55-58`).
- Новые Session-ы действий запускаются в `bypassPermissions` (`src/main/actions/launch.ts:9-11`).
- Текст review, письма или сообщения может содержать prompt injection. Владелец просил ставить вопросы безопасности
  только о настоящем внешнем атакующем (2026-11-07). Здесь он настоящий: репозиторий worfy публичный, и комментарий
  постороннего к PR попадёт в prompt агента, который запускает Session-ы.
- Linked machine читает, но не действует (ADR-0066).

## Answer

Владелец, 2026-11-20: «Принимаю все 6». Границы агента worfy, закреплённые в коде:

1. **Только tools `worfy-app`.** У агента нет Bash, записи файлов и сети. Образец — Session черновика профиля
   (`src/main/vendors/claude/options.ts:71-80`).
2. **Чужой текст — данные.** Текст других людей (комментарии PR, Slack, Jira, почта) приходит к агенту только через
   tools `worfy-app`, с источником и автором. Правила агента называют его данными, а не командами. Это мягкая граница,
   одна она не держит.
3. **Жёсткая граница.**
   - Сам агент делает только действия из закрытого списка, и их текст задаёт main, а не агент.
   - Session с текстом, который написал агент, стартует только по щелчку владельца. Владелец видит этот текст до
     старта — так же, как ответ в PR по ADR-0105.
4. **Наружу — только существующий щелчок Send.** Пути к `prInbox.send` у агента нет.
5. **Project-ы второй машины агент только читает** (ADR-0066).
6. **Журнал.** Каждое действие агента пишется в журнал вместе с пунктом, который его вызвал, и с like и dislike
   владельца.
