## Question

Как проактивных агентов делают продукты, которые уже вышли? Что их будит, что они делают сами и что предлагают, кто
одобряет действие, видят ли они много репозиториев сразу, помнят ли прошлые задачи? Что известно о доле принятых
проактивных предложений, о терпимости к ложным срабатываниям и об усталости от уведомлений?

## Answer

Заметка: [research-проактивные-агенты-у-конкурентов.md](../research-проактивные-агенты-у-конкурентов.md). Главное:

- Проактивность в продуктах 2025–2026 годов собрана из трёх частей:
  - trigger — расписание или событие;
  - ограниченный набор действий;
  - одобрение по классу действия.
- Ближе всех к агенту над всеми Project-ами подошли три продукта:
  - OpenAI dots (2026-09-29) — постоянный агент с целью. Сам он только исследует на чтение. Для каждого действия задан
    один из четырёх режимов: сделать без вопроса, сделать по заранее данному одобрению, спрашивать каждый раз, отдать
    человеку;
  - координатор Cursor;
  - Copilot Projects.

  Какую долю предложений принимают, не публикует ни один из них.
- Общие ленты находок свернули:
  - ChatGPT Pulse (2025-09 — 2026-06) заменили задачами по расписанию;
  - Suggested Tasks у Jules закрываются 2026-12-31;
  - Antigravity убрала inbox решений;
  - LangChain перевела Agent Inbox в архив.

  Остались конструкции «trigger, область, правила действия».
- Шум — главная измеренная проблема:
  - у готовых LLM 52–65 % предложений помощи приходятся на моменты, когда помощь не нужна;
  - комментарии AI-review меняют код в 0,9–19,2 % случаев, а комментарии людей — в 60 %;
  - вендоры выбирают молчание: Copilot ничего не пишет в 29 % review, Codex пишет только две высшие важности.
- Время подачи решает:
  - подсказку после commit берут в работу в 52 % случаев;
  - подсказку посреди задачи отклоняют в 62 % случаев;
  - trigger по бездействию пользователя не сработал.
- Двухступенчатую сортировку применяют Devin и Claude Code. Linear же убрал маленькие модели из triage: им не хватало
  контекста, данного заранее. Это предостережение для Haiku-first.
- Выводы для worfy (раздел «Что из этого следует для worfy»):
  - у агента — обязанности с явной областью, которые владелец видит и выключает по одной;
  - по умолчанию — предложение; самостоятельность включается по классу действия;
  - с первого дня считать «показано, принято, отклонено, проигнорировано»;
  - дешёвая модель — только первая ступень;
  - подавать на границе работы и пачкой;
  - «ничего не произошло» считает код worfy, без модели.
