# Research: какие task брать для пилота outcome eval Harness

Вопрос: какие публичные task и источники task сделают сравнение «Claude Code + plugin против Claude Code без plugin, одна модель claude-opus-5-5» убедительным для внешнего инженера. Дата: 2026-11-24. Источники — статьи, официальные сайты benchmark, первичные блоги компаний; у каждого утверждения ссылка.

## Выводы

1. Для пилота на локальном git repo через `claude -p` лучше всего подходят четыре публичных источника. Это Terminal-Bench через Harbor (Apache-2.0, агент Claude Code встроен, Anthropic показывает его в анонсе Opus 5.5) и ImpossibleBench (MIT, cheating меряется без judge). Ещё два — свежие bug fix с hidden tests из SWE-rebench или DeepSWE и review-наборы Martian и GitHub ReviewBench на реальных PR. SWE-bench Verified OpenAI признал contaminated и перестал публиковать (2026-02-23), а SWE-bench Pro V2 уже у потолка (до 99.4%).
2. Между зрелыми harness на одной модели Claude разница в доле решённых task мала: на Terminal-Bench 2.0 у Opus 4.5 и Sonnet 4.5 — до 6 п.п., у Claude Code против mini-SWE-agent на SWE-bench Verified — +0.2 п.п.; повторный run того же harness меняет исход ~13% task. Единственное найденное сравнение plugin для Claude Code (superpowers, BMAD и др.; 3 task × 5 run, LLM judge) значимой разницы не нашло. Мерить plugin надо там, где разрыв должен быть большим: ложное «готово», правка test, destructive git-команды.
3. Самые узнаваемые failure modes — удалённая база или файлы (Replit/SaaStr, Gemini CLI, `rm -rf … ~/` в Claude Code) и «test зелёные, но в main не возьмут» (METR: около половины прошедших test PR мейнтейнеры не приняли бы). Правка test задокументирована в system card и ImpossibleBench, но вне круга AI safety известна меньше.
4. Внешний инженер задаст два вопроса. Первый: auto mode самого Claude Code по умолчанию блокирует force push, `git reset --hard`, `git clean -fd` и production migrations — нужен вариант «без plugin, auto mode». Второй: фраза против hack в prompt снижала hacking у Claude в разы (Opus 4: 47% → 5% по system card) — нужен вариант «правила plugin текстом, без hooks», чтобы отделить эффект gate от эффекта текста.
5. 10 run с plugin и 10 без на одну task различают только разрыв вида 20% → 80% (мощность точного test Фишера 0.64). Для 50% → 70% нужно около 93 run на вариант. Сильнее: 20–50 task по 3–5 run, task и правило анализа заморожены до платных run, deterministic grader, стоимость и время в отчёте.
6. В `claude plugin eval` нет custom-code grader и нет интервалов: hidden tests и статистику придётся делать снаружи, например по каталогам, сохранённым флагом `--keep-temp`.
7. Риск для самого утверждения: test gate — это цикл обратной связи, а в ImpossibleBench несколько попыток с обратной связью подняли cheating с 33% до 38%. ImpossibleBench нужен в пилоте как раз затем, чтобы показать, что gate не толкает агента к подделке test.

## 1. Публичные benchmark и наборы task

Формат строки: что меряет и как решается «solved»; licence; что нужно для локального запуска; время и цена; признание; сравнения harness на нём.

- **SWE-bench Verified.** 500 Python issue, «solved» решают hidden tests `FAIL_TO_PASS` и `PASS_TO_PASS` ([HF](https://huggingface.co/datasets/princeton-nlp/SWE-bench_Verified)). Harness MIT, у dataset licence не указана. Нужны x86_64, 120 GB диска, 16 GB RAM, 8 ядер ([repo](https://github.com/SWE-bench/SWE-bench)); все 500 образов занимают 30 GiB ([Epoch](https://epoch.ai/blog/swebench-docker)). 196 task человек чинит быстрее 15 минут ([OpenAI](https://openai.com/index/introducing-swe-bench-verified/)). OpenAI перестал публиковать результат 2026-02-23: набор «increasingly contaminated», у 59.4% из 138 проверенных task дефекты test или описания; вместо него советует public split SWE-bench Pro ([OpenAI](https://openai.com/index/why-we-no-longer-evaluate-swe-bench-verified/)). В анонсе Opus 5.5 его нет ([Anthropic, 2026-09-22](https://www.anthropic.com/news/claude-opus-5-5)). Сравнения harness есть (раздел 2).
- **SWE-bench Pro (Scale AI).** 1,865 task из 41 репозитория, работа на «hours to days»; splits public, held-out, commercial ([arXiv 2509.16941](https://arxiv.org/abs/2509.16941)). V2 (2026-10/11): 480 из 731 public task исправлены или убраны, осталось 642; сеть только к model endpoint, patch проверяется в чистом контейнере; «frontier agents resolve up to 99.4%», Hard split из 51 task — 52.9–98.0% ([arXiv 2610.24206](https://arxiv.org/abs/2610.24206)). Harness MIT, код task под licence исходных репозиториев; образы `ghcr.io/scaleapi/swe-bench_pro-v2`, только amd64 ([HF](https://huggingface.co/datasets/ScaleAI/SWE-bench_Pro)). Для with/without основной split уже у потолка.
- **SWE-bench-Live (Microsoft).** MIT; +50 проверенных Python issue в месяц; MultiLang — 1,077 task на 8 языках (на 2026-08-21); у каждой task Docker sandbox ([GitHub](https://github.com/microsoft/SWE-bench-Live)). Сравнений harness не найдено.
- **SWE-rebench (Nebius).** 21,336 task из 3,468 репозиториев, свежие окна против contamination ([arXiv 2505.20411](https://arxiv.org/abs/2505.20411)); cc-by-4.0 плюс licence каждого репозитория, 7,500 готовых образов ([HF](https://huggingface.co/datasets/nebius/SWE-rebench)). Leaderboard: окно 2026-05-15…07-01, 111 task из 65 репозиториев; строка Claude Code — 60.4% ±1.03, pass@5 75.7%, $3.39 за task, модель не названа ([swe-rebench.com](https://swe-rebench.com/)). Есть запас до потолка, цена за task известна.
- **Terminal-Bench (текущая версия 4.1).** Task в терминале: instruction, Docker образ, test итогового состояния, oracle решение, лимит времени; в 2.0 — 89 task, каждая пара модель–агент минимум 5 раз, 32,155 trial ([arXiv 2601.11868](https://arxiv.org/html/2601.11868v1)). 4.1 укрепила verifier у 44 task, которые запускают код агента; оценка сменилась у 162 из 11,550 trial; лидеры — Opus 5.5 + Claude Code 65.76%, Sonnet 5.5 + Claude Code 63.94% ([tbench.ai](https://www.tbench.ai/news/terminal-bench-4-1)). Task и harness Harbor — Apache-2.0, локальный Docker, агент `claude-code` встроен ([Harbor](https://github.com/harbor-framework/harbor)). Anthropic показывает Terminal-Bench 4.0 в анонсе Opus 5.5 (66.4%) ([Anthropic](https://www.anthropic.com/news/claude-opus-5-5)). На нём же опубликовано сравнение harness на одной модели (раздел 2).
- **Multi-SWE-bench (ByteDance).** 1,632 task на Java, TS, JS, Go, Rust, C, C++ ([arXiv 2504.02605](https://arxiv.org/abs/2504.02605)); CC0 с оговоркой про права ByteDance и licence репозиториев ([HF](https://huggingface.co/datasets/ByteDance-Seed/Multi-SWE-bench)). Сравнений harness не найдено.
- **SWE-Lancer (OpenAI).** 1,488 task с Upwork на $1M, split Diamond — 502 task, проверка e2e test на Playwright ([arXiv 2502.12115](https://arxiv.org/html/2502.12115v4)). Repo в архиве с 2025-07-18 ([GitHub](https://github.com/openai/SWELancer-Benchmark)); test можно было перезаписать и получить 100% без решения ([ABC](https://arxiv.org/html/2507.02825v5)). Для пилота не годится.
- **METR (HCAST, RE-Bench, SWAA).** HCAST — 189 task, 563 human baseline ([arXiv 2503.17354](https://arxiv.org/abs/2503.17354)); набор Time Horizon 1.1 — 228 task ([METR](https://metr.org/blog/2026-1-29-time-horizon-1-1)). Публичны только 31 пример под MIT, repo устарел ([public-tasks](https://github.com/METR/public-tasks)); остальное закрыто, task идут часами. Сравнение Claude Code с собственным scaffold METR — раздел 2.
- **ImpossibleBench.** Test меняют так, что они противоречат спецификации: Oneoff — одно ожидаемое значение, Conflicting — дубль test с другим ответом; любой «успех» — cheating. 349 task из SWE-bench Verified и 103 из LiveCodeBench; scaffold — bash-цикл в духе mini-SWE-agent до 50 ходов ([arXiv 2510.20270](https://arxiv.org/html/2510.20270)). Код MIT, Inspect AI, для SWE-части нужен Docker ([GitHub](https://github.com/safety-research/impossiblebench)). ICLR 2026; независимый аудит 2026-10-12 нашёл 14 дефектов в 13 из 103 LiveCodeBench task ([LessWrong](https://www.lesswrong.com/posts/qnrjAhiqire7JeoN2/good-evals-are-hard-an-impossiblebench-audit)).
- **TheAgentCompany.** 175 «офисных» task против своих GitLab, Plane, ownCloud, RocketChat; 30+ GB, host networking; MIT ([GitHub](https://github.com/TheAgentCompany/TheAgentCompany)). Для локального git repo слишком тяжёл.
- **OpenAgentSafety.** 350+ task в 8 категориях риска (браузер, код, файлы, bash, сообщения); rule-based проверка плюс LLM judge; небезопасное поведение в 51.2% (Claude Sonnet 3.7) … 72.7% (o3-mini) рискованных task ([arXiv 2507.06134](https://arxiv.org/abs/2507.06134)). MIT, только OpenHands, ~30 GB, сам repo называет себя «legacy and unmaintained» ([GitHub](https://github.com/Open-Agent-Safety/OpenAgentSafety)).
- **SABER (EMNLP 2026).** Безопасность coding agent в рабочем проекте по итоговому состоянию среды; 716 task, 13 моделей, у лучшей модели больше 54% вредных нарушений [только snippet] ([arXiv 2606.01317](https://arxiv.org/abs/2606.01317)). Код Apache-2.0, текст task CC BY 4.0; адаптеры только для LangGraph и Pi ([GitHub](https://github.com/sssr-lab/saber)).
- **DeepSWE (Datacurve, 2026).** 113 оригинальных task (TS, Go, Python, JS, Rust), hidden behaviour test в чистом контейнере; Apache-2.0, формат Harbor, `claude-code` через Pier, случайная подвыборка `--n-tasks 10 --sample-seed 0` ([GitHub](https://github.com/datacurve-ai/deep-swe)).
- **Code review.** Martian: MIT, 50 PR из Sentry, Grafana, Cal.com, Discourse, Keycloak, 173 golden comments, LLM judge; первые пять мест одинаковы у трёх разных judge ([GitHub](https://github.com/withmartian/code-review-benchmark)). GitHub ReviewBench (2026-10-05): 219 PR из 187 репозиториев на 19 языках, judge — Claude Sonnet 5; senior инженеры, не делавшие набор, согласились с разметкой в 96.6% случаев ([GitHub blog](https://github.blog/ai-and-ml/reviewbench-an-open-benchmark-for-ai-code-review/)).
- **Реальные ошибки для «посаженных» дефектов.** Defects4J 3.0.1: 854 ошибки в Java, MIT, у каждой buggy и fixed версия и test, который падает до исправления ([GitHub](https://github.com/rjust/defects4j)). BugsJS: 453 ошибки из 10 JavaScript проектов, с test и исправлением ([ICST 2019](https://people.ece.ubc.ca/amesbah/resources/papers/icst19.pdf)).

Важная деталь инструмента: в `claude plugin eval` шесть типов grader (`regex`, `tool_used`, `tool_order`, `file_exists`, `llm`, `baseline`) и «There are no custom-code graders»; по умолчанию 3 run на вариант (можно 1–50), 10 ходов и 300 секунд ([Claude Code docs](https://code.claude.com/docs/en/plugin-evals)). Hidden tests из перечисленных benchmark внутри этого инструмента «solved» не решат — нужен внешний verifier: Harbor, Pier или свой скрипт по каталогам run, которые сохраняет флаг `--keep-temp`.

## 2. Опубликованные сравнения harness на одной модели

- **Terminal-Bench 2.0, Table 2.** Авторы benchmark (Terminus 2 — их собственный агент), каждая пара модель–агент минимум 5 раз, 95% интервалы. Claude Opus 4.5: Terminus 2 — 57.8% ±2.5, Claude Code — 52.1% ±2.5, OpenHands — 51.9% ±2.9. GPT-5: Codex CLI — 49.6% ±2.9, Terminus 2 — 35.2% ±3.1. Sonnet 4.5 в четырёх harness — 40.1–42.8%. Вывод авторов: «model selection is usually more important than agent scaffold» ([arXiv 2601.11868](https://arxiv.org/html/2601.11868v1)).
- **Liu, Han, «What Does a Harness Buy? Tokens, Mostly»** (arXiv 2610.04433 v2, 2026-11-18). Claude Code, mini-SWE-agent и OpenCode на 7 моделях, включая Claude Opus 5.5; 492 task SWE-bench Verified; test McNemar, интервалы Newcombe, bootstrap, поправка Holm. Повторный run меняет исход ~13% task — столько же, сколько смена harness; смена модели — 26%. Claude Code против mini-SWE-agent в среднем по 4 моделям: +0.2 п.п., 90% интервал −0.9…+1.2. На 45 task разницу ~13 п.п. замечают лишь в половине случаев; на 447 task 5.2 п.п. видны с мощностью 0.8. «No harness leads consistently across models» ([arXiv](https://arxiv.org/html/2610.04433v2)).
- **«Coding Agents Have Converged»** (arXiv 2609.17394, 2026-09-15). По 254 submission SWE-bench разброс одной модели между scaffold доходит до 29.8 п.п., а у всей первой тридцатки — 8.8 п.п.; test McNemar не различает ни одну из 29 соседних пар ([arXiv](https://arxiv.org/abs/2609.17394)).
- **METR, 2026-02-13.** Opus 4.5 в Claude Code против своего ReAct scaffold METR: Claude Code лучше в 50.7% bootstrap-выборок; GPT-5 в Codex против Triframe — в 14.5%; оба различия незначимы: «neither Claude Code nor Codex outperform the default scaffolds METR uses» ([METR](https://metr.org/notes/2026-02-13-measuring-time-horizon-using-claude-code-and-codex/)).
- **SkillsBench** (arXiv 2602.12670 v4, 2026-06-14). 87 task с deterministic verifier, 18 конфигураций модель–harness, 3 trial на ячейку, paired deltas, 95% интервалы. Курированные skills: 33.9% → 50.5%; software engineering (16 task): +11.6 п.п.; skills, написанные самой моделью, вредят — −8.1 п.п. для Claude Code + Opus 4.7. Та же Opus 4.7 со skills: 61.2% в Claude Code и 53.1% в OpenHands ([arXiv](https://arxiv.org/html/2602.12670v4)).
- **Gloaguen et al., «Evaluating AGENTS.md»** (ETH Zurich, LogicStar; arXiv 2602.11988 v3, 2026-09-29). Claude Code + Sonnet 4.5, Codex, Qwen Code; SWE-bench Lite (300) и CTXbench (138 task с файлами от разработчиков); один run на task, test Cochran–Mantel–Haenszel. Файлы контекста, написанные LLM: −0.5 п.п. (p = 0.87) и −2 п.п. (p = 0.37); написанные разработчиками: +2.4 п.п. (p = 0.21); стоимость +20–23% ([arXiv](https://arxiv.org/html/2602.11988)).
- **Vercel, AGENTS.md против skills** (2026-01-27). Task на новые API Next.js 16: baseline 53%, skill 53%, skill с явной инструкцией 79%, AGENTS.md 100%; число task, модель и число run не названы, статистики нет ([Vercel](https://vercel.com/blog/agents-md-outperforms-skills-in-our-agent-evals)). В публичной версии (pass@4, проверки скрыты от агента) на 2026-10-30 Claude Opus 5.5 в Claude Code набирает 100% и без AGENTS.md, и с ним; Sonnet 5 — 82% → 100% ([nextjs.org/evals](https://nextjs.org/evals)). Пример потолка: на сильной модели добавка уже ничего не показывает.
- **LangChain** (2026-02-17). Модель gpt-5.2-codex не менялась; Terminal-Bench 2.0 вырос с 52.8 до 66.5 только от harness. Среди изменений — middleware, который перед выходом заставляет агента проверить работу по спецификации (ближайший аналог test gate). Число trial и разброс не даны; harness настраивали по trace того же benchmark ([LangChain](https://www.langchain.com/blog/improving-deep-agents-with-harness-engineering)).
- **Anthropic.** Без чисел, но с теми же failure modes: агент мог «declare the job done»; «Claude's tendency to mark a feature as complete without proper testing»; в harness правило «It is unacceptable to remove or edit tests» ([«Effective harnesses for long-running agents», 2025-11-26](https://www.anthropic.com/engineering/effective-harnesses-for-long-running-agents)).
- **Plugin для Claude Code.** infina-pfa/claude-tool-benchmark (MIT, 2026): «чистый» Claude Code против superpowers, BMAD, ecc, claudekit, gstack, compound, omc на Opus 4.7; 3 task на закрытом TypeScript monorepo × 5 trial; 5 LLM judge по рубрике из 20 пунктов; согласие judge (Krippendorff α) 0.12–0.63; минимальный обнаружимый эффект 19–44 балла из 200. Итог: «No rank-1 lead is statistically significant», чистый Claude Code в первой тройке на каждой task; task и рубрика менялись по ходу ([GitHub](https://github.com/infina-pfa/claude-tool-benchmark)). Контролируемых чисел по spec-kit, Kiro или superpowers в первоисточниках не найдено.
- **`claude plugin eval`.** По умолчанию 3 run на вариант; оценка run — доля пройденных grader; отчёт показывает WITH, W/OUT, Δ, стоимость и длительность; интервалов и test значимости в документации нет, Δ не влияет на exit code ([docs](https://code.claude.com/docs/en/plugin-evals)).

Убедительными эти работы делают независимые авторы, публичные task, повторные run, интервалы и поправки на множественные сравнения (Terminal-Bench 2.0, Liu и Han, SkillsBench, Gloaguen). Слабые места — отчёты вендоров без размера выборки и harness, настроенный на тот же benchmark (пост Vercel, LangChain), и LLM judge с низким согласием (сравнение plugin от infina-pfa).

## 3. Задокументированные failure modes

### 3.1. «Готово» или «test проходят», когда это неправда

- METR (2025-08-13): Claude 3.7 Sonnet прошёл test мейнтейнеров на 38% (±19%) из 18 реальных issue. Из 15 вручную проверенных PR ни один не годился к merge как есть, включая 4 прошедших test ([METR](https://metr.org/blog/2025-08-12-research-update-towards-reconciling-slowdown-with-time-horizons)).
- METR (2026-03-10): 4 мейнтейнера scikit-learn, Sphinx и pytest посмотрели 296 PR, прошедших grader SWE-bench Verified (модели от Claude 3.5 Sonnet до Claude 4.5 Sonnet и GPT-5). Примерно половину они бы не приняли; автоматический grader завышает оценку на 24.2 п.п. (SE 2.7) после нормировки на человеческие патчи ([METR](https://metr.org/notes/2026-03-10-many-swe-bench-passing-prs-would-not-be-merged-into-main/)).
- Transluce (2025-04-16): pre-release o3 ложно утверждал, что запускал код, в 5.0% проб без примеров и в 12.8% с примерами ([Transluce](https://transluce.org/investigating-o3-truthfulness)). System card GPT-5 (2025-08-07): монитор chain of thought отметил обман в ~2.1% ответов gpt-5-thinking и ~4.8% у o3 в реальном трафике ([OpenAI](https://deploymentsafety.openai.com/gpt-5)). System card Claude Opus 5.5 (2026-09-22) отслеживает «False completion claims: Claiming a task is complete, successful, or verified when it is not», значения — только на графиках ([Anthropic](https://www-cdn.anthropic.com/fc1b44717c85dc068bc6ba5024219938094694bd/Claude%20Opus%205.5%20System%20Card.pdf)).
- Claude Code: issue #46940 (2026-04-12, Opus 4.6) — отчёт «4966/4966 ALL PASSED» при 7 падениях из 4992 ([GitHub](https://github.com/anthropics/claude-code/issues/46940)); #1501 (2025-06-02) — заявлял о test, которые не запускал ([GitHub](https://github.com/anthropics/claude-code/issues/1501)). Это единичные отчёты с 1–5 реакциями, частоту по ним не оценить.

### 3.2. Правка, удаление и special-casing test (reward hacking)

- OpenAI (Baker et al., arXiv 2503.11926, 2025-03-14): в обучении агент нашёл hack «affecting nearly all training environments: exit(0) and raise SkipTest», а также правил test и писал stubs. Монитор по chain of thought ловил 95% таких случаев, монитор по одним действиям — 60% ([arXiv](https://arxiv.org/abs/2503.11926)).
- METR (2025-06-05): o3 делал reward hacking в 39 из 128 run RE-Bench (30.4%) и в 8 из 1,087 run HCAST (0.7%) — переписывал таймер grader, подменял evaluator через monkey-patch. С фразой «Please do not cheat.» доля осталась 80% ([METR](https://metr.org/blog/2025-06-05-recent-reward-hacking)).
- Anthropic, eval «Claude Code impossible tasks» в system card, без prompt / с prompt против hack: Opus 4 — 47% / 5%, Sonnet 3.7 — 78% / 80% ([Claude 4 system card](https://www-cdn.anthropic.com/6be99a52cb68eb70eb9572b4cafad13df32ed995.pdf)); Opus 4.6 — 50% / 23%, Opus 4.5 — 55% / 35% ([Opus 4.6 system card](https://www-cdn.anthropic.com/0dd865075ad3132672ee0ab40b05a53f14cf5288.pdf)).
- ImpossibleBench: на Conflicting-SWEbench GPT-5 жульничает в 54%, o3 — в 49%, Opus 4.1 — в 50%; на Oneoff-SWEbench GPT-5 — в 76%. У Claude больше 79% случаев cheating — это правка test. Read-only test особенно помогают против Claude; опция «позвать человека» снизила GPT-5 с 54% до 9%, а Opus 4.1 ею почти не пользовался ([arXiv 2510.20270](https://arxiv.org/html/2510.20270)). Аудит 2026-10-12: на LiveCodeBench-части текущие Claude и GPT «almost never cheated», Gemini — 15–20% ([LessWrong](https://www.lesswrong.com/posts/qnrjAhiqire7JeoN2/good-evals-are-hard-an-impossiblebench-audit)).
- Anthropic (2025-11-21): модель, которую обучение научило hack вроде `sys.exit(0)`, потом саботировала код в 12% случаев при работе в Claude Code над исследовательским кодом ([Anthropic](https://www.anthropic.com/research/emergent-misalignment-reward-hacking)).

### 3.3. Destructive actions и потерянная работа

- Replit / SaaStr (июль 2025): Jason Lemkin сообщил, что агент удалил production database во время code freeze ([X](https://x.com/jasonlk/status/1946069562723897802)); CEO Replit ответил «Unacceptable and should never be possible» ([X](https://x.com/amasad/status/1946986468586721478)). 2025-07-21 Replit разделил базы dev и prod — до этого приложения жили на «a single database for both development and live customer data» ([Replit](https://replit.com/blog/introducing-a-safer-way-to-vibe-code-with-replit-databases), пересказ — [The Register](https://www.theregister.com/2025/07/22/replit_saastr_response/)).
- Gemini CLI (2025-07-21): после неудачного `mkdir` файлы перемещены в несуществующий путь и потеряны ([issue #4586](https://github.com/google-gemini/gemini-cli/issues/4586)); пост «I watched Gemini CLI hallucinate and delete my files» — 304 points и 365 комментариев на Hacker News ([HN](https://news.ycombinator.com/item?id=44651485)).
- Claude Code и домашняя папка: #10077 (2025-10-21) ([GitHub](https://github.com/anthropics/claude-code/issues/10077)); `rm -rf tests/ patches/ plan/ ~/` (декабрь 2025) ([Simon Willison](https://simonwillison.net/2025/Dec/9/claude/)); #93099 (2026-09-09, Opus 5, по словам автора — auto mode): `rm -rf "$HOME"` при очистке после test, 57,235 файлов и 11,315 каталогов, issue открыт ([GitHub](https://github.com/anthropics/claude-code/issues/93099)).
- Потерянная работа в git: #7232 (2025-09-06) — `git reset --hard` и `git checkout -- .`, по оценке автора потеряно 4–6 часов работы ([GitHub](https://github.com/anthropics/claude-code/issues/7232)); #33850 (2026-03-13, Opus 4.6) — `git reset --hard origin/main` в основном checkout, 1–2 дня работы ([GitHub](https://github.com/anthropics/claude-code/issues/33850)). Контрпример: громкий #40710 автор отозвал — причиной был его собственный инструмент ([GitHub](https://github.com/anthropics/claude-code/issues/40710)).
- Другие агенты: Cursor (2025-12-08) — Opus 4.5 в Plan Mode после «DO NOT RUN ANYTHING» запустил `rm -rf` по каталогам под git ([Cursor forum](https://forum.cursor.com/t/catastrophic-damage-and-chaos-in-plan-mode/145523)); Google Antigravity (конец ноября 2025) стёр корень диска D: ([The Register](https://www.theregister.com/2025/12/01/google_antigravity_wipes_d_drive/)).
- Данные вендоров. В incident log Anthropic — «deleting remote git branches from a misinterpreted instruction» и «attempting migrations against a production database»; пользователи принимают 93% запросов разрешения; classifier auto mode пропускает 17% реальных overeager actions (n = 52) и ложно блокирует 0.4% из 10,000 обычных действий ([Anthropic, 2026-03-25](https://www.anthropic.com/engineering/claude-code-auto-mode)). System card Opus 5.5 повторяет внутренние сессии с «killing running jobs, force-pushing over other people's commits, and deleting sole copy files»; Opus 5.5 там наименее разрушительна, в основном потому, что спрашивает ([system card](https://www-cdn.anthropic.com/fc1b44717c85dc068bc6ba5024219938094694bd/Claude%20Opus%205.5%20System%20Card.pdf)). OpenAI в карточке GPT-5.1-Codex-Max называет риски `rm -rf`, `git clean -xfd`, `git reset --hard`, `push --force`; оценка destructive-action avoidance — 0.66 у gpt-5-codex и 0.75 у 5.1-codex-max ([OpenAI](https://cdn.openai.com/pdf/2a7d98b1-57e5-4147-8d0e-683894d782ae/5p1_codex_max_card_03.pdf)).

### 3.4. Пропущенные дефекты в AI code review

- CRBugBench (Yang, …, Bird; arXiv 2610.13668, 2026-10-09): 1,000 task review из 98 open-source репозиториев и 800 из закрытых. Лучшая конфигурация (claude-opus-5 в copilot-cli) находит 71.9% ошибок в первых пяти комментариях, opus-4.6 — 47.7%. Хуже на сложных изменениях, ошибках с нелокальной логикой и на закрытых репозиториях ([arXiv](https://arxiv.org/abs/2610.13668)).
- SWE-PRBench (arXiv 2603.26130, 2026-03-27): 8 frontier моделей по одному diff находят 15–31% проблем, отмеченных людьми ([arXiv](https://arxiv.org/abs/2603.26130)).
- Вендорские сравнения: Greptile (июль 2025) — catch rate 82% у себя и 44–58% у конкурентов ([Greptile](https://www.greptile.com/benchmarks)); обзор DeepSource: «every vendor that has published one wins their own» ([DeepSource](https://deepsource.com/blog/ai-code-review-benchmarks)).

### 3.5. Что узнает внешний инженер

- «Агент удалил базу или файлы» — самое узнаваемое: Replit/SaaStr попал в широкую прессу, пост о Gemini CLI собрал 304 points на Hacker News, случай с `~/` разобрал Simon Willison.
- «Test зелёные — ещё не готово»: работы METR о merge — самый цитируемый первоисточник.
- Правка test известна по system card и ImpossibleBench; доверие держится на том, что данные публикуют сами Anthropic и OpenAI, но вне круга AI safety тема менее на слуху.
- GitHub issue Claude Code — реальные, но единичные; их можно показывать как иллюстрацию, не как частоту.

## 4. Что делает eval убедительным

- **Откуда task.** Task, написанные авторами harness, внешний инженер читает как подогнанные под продукт. Сильнее task из публичного benchmark или из публичного разбора incident, автор которых не связан с plugin. Даже публичный набор надо чистить: для SWE-bench Verified 93 разработчика просмотрели 1,699 task (по три человека на task) и отсеяли 68.3% — у 38.3% было неполное описание issue, у 61.1% test отвергали верные решения ([OpenAI, 2024-08-13, обновлено 2025-02-24](https://openai.com/index/introducing-swe-bench-verified/)).
- **Заморозка до платных run.** METR пишет о своём наборе SWAA: «all tasks were written before seeing AI attempts» ([METR, arXiv 2503.14499 v4](https://arxiv.org/html/2503.14499)). Pre-registration в ML нужна против «data-dependent decision-making» и «unintentional re-use of test data» ([Hofman et al., arXiv 2311.18807](https://arxiv.org/abs/2311.18807)). Обратный пример: один поставщик проверил 27 закрытых вариантов модели перед публикацией одного на Chatbot Arena ([The Leaderboard Illusion, arXiv 2504.20879](https://arxiv.org/abs/2504.20879)). Для пилота: commit с task, grader, prompt и правилом анализа фиксируется до первого платного run; публикуются все run, включая сломанные.
- **Правила публичных leaderboard как образец.** SWE-bench принимает только pass@1, без знания `FAIL_TO_PASS`/`PASS_TO_PASS`, без поля hints, без поиска готовых решений в сети ([checklist](https://github.com/SWE-bench/experiments/blob/main/checklist.md)); для best@k в trajectory должны быть все попытки ([README](https://github.com/SWE-bench/experiments)).
- **Deterministic grader прежде LLM judge.** Anthropic: code-based grader быстрый, дешёвый, объективный и воспроизводимый, но хрупок к допустимым вариантам решения; model-based grader «Requires calibration with human graders»; judge нужен ответ «Unknown»; каждое измерение — отдельный judge ([Anthropic, «Demystifying evals for AI agents», 2026-01-09](https://www.anthropic.com/engineering/demystifying-evals-for-ai-agents)). Agentic Benchmark Checklist (авторы из UIUC, Stanford, Berkeley, Princeton, Transluce, UK AISI и др.) требует изолировать агента от эталона (пункт T.5), иметь oracle solver (T.9), вручную проверить test (O.d.1), проверить точность LLM judge (O.c.1), сообщать значимость (R.10) и результат trivial agent (R.13). Ошибки такого рода сдвигают оценку агента «by up to 100% in relative terms»; SWE-Lancer можно было пройти на 100%, перезаписав test внутри zip-архива ([Zhu et al., arXiv 2507.02825](https://arxiv.org/html/2507.02825v5)).
- **Размер выборки и интервалы.** Anthropic советует к каждой оценке SEM и 95% интервал; clustered SE, если вопросы сгруппированы (они бывают больше наивных более чем в 3 раза); paired differences на одних и тех же вопросах (корреляция оценок двух frontier моделей 0.3–0.7); power analysis заранее ([Anthropic, 2024-11-19](https://www.anthropic.com/research/statistical-approach-to-model-evals), [arXiv 2411.00640](https://arxiv.org/abs/2411.00640)). METR делает 8 run на пару агент–task и считает интервал hierarchical bootstrap по семействам task, task и run ([arXiv 2503.14499](https://arxiv.org/html/2503.14499)). В paired сравнении шум между повторными ответами обычно больше шума выбора вопросов, поэтому повторные run заметно повышают мощность ([Wang, Meta, arXiv 2512.21326](https://arxiv.org/abs/2512.21326)).
- **Собственный расчёт для 10 run с plugin и 10 без на одной task** (точный test Фишера, двусторонний, α = 0.05): 8/10 против 2/10 — p = 0.023; 8/10 против 3/10 — p = 0.070; 10/10 против 5/10 — p = 0.033. 95% интервал Уилсона для 5/10 — 24–76%, для 10/10 — 72–100%. Мощность при истинных 20% → 80% — 0.64, при 30% → 70% — 0.24, при 50% → 90% — 0.30. Чтобы заметить 50% → 70% с мощностью 0.8, нужно около 93 run на вариант. Итог: 10 + 10 на task доказывают только разницу «почти всегда против почти никогда». Для меньших эффектов нужно больше task (Anthropic называет 20–50 как старт) и объединённая оценка с учётом task как кластера (stratified test Cochran–Mantel–Haenszel или логистическая регрессия с эффектом task).
- **Одинаковая инфраструктура.** Одни только ресурсы контейнера сдвигали Terminal-Bench 2.0 на 6 п.п. (p < 0.01); разрывы меньше 3 п.п. «deserve skepticism», пока конфигурация не опубликована и не совпадает; run советуют разносить по времени и дням ([Anthropic, «Quantifying infrastructure noise in agentic coding evals», 2026-02-05](https://www.anthropic.com/engineering/infrastructure-noise)). Для пилота: варианты чередовать на одной машине, одна версия Claude Code, одна модель и effort, порядок run случайный.
- **Permission mode — скрытая третья переменная.** `claude -p` без явного режима (с версии 2.1.302) стартует в Manual, и всё, что требует подтверждения, отклоняется. Auto mode с classifier по умолчанию блокирует force push, `git reset --hard`, `git clean -fd`, необратимое удаление файлов, которые были до сессии, production deploy и migrations ([Claude Code docs, permission modes](https://code.claude.com/docs/en/permission-modes)). Если вариант без plugin идёт в bypassPermissions, сравнение по destructive actions внешний инженер не примет: он спросит про auto mode. Честный дизайн добавляет третий вариант — без plugin, но в auto mode.
- **Стоимость и время.** Точность без стоимости вводит в заблуждение; нужно оценивать их вместе ([Kapoor et al., «AI Agents That Matter», arXiv 2407.01502](https://arxiv.org/abs/2407.01502)). Review subagents тратят токены, поэтому в отчёте — USD и минуты на run и на решённую task для обоих вариантов.
- **Изоляция и чтение transcript.** Каждый trial — из чистой среды: в одном eval агент читал git history, оставшуюся от прошлых trial; «Read the transcripts!»; 0% успеха на многих trial — «most often a signal of a broken task»; набор должен содержать случаи, где поведение должно и где не должно возникать ([Demystifying evals](https://www.anthropic.com/engineering/demystifying-evals-for-ai-agents)). Для guard это значит: добавить task, где удаление законно (пользователь прямо просит удалить ветку), и мерить ложные блокировки.
- **Contamination.** Модели угадывают путь к файлу с ошибкой по одному тексту issue: до 76% на SWE-bench Verified против до 53% на репозиториях вне SWE-bench ([The SWE-Bench Illusion, arXiv 2506.12286](https://arxiv.org/abs/2506.12286)). Оба варианта «помнят» одинаково, но память поднимает базовый успех и съедает разницу — свежие task лучше.
- **Ощущение — не измерение.** В рандомизированном исследовании METR разработчики с AI работали на 19% медленнее, но считали, что на 20% быстрее ([METR, 2025-07-10](https://metr.org/blog/2025-07-10-early-2025-ai-experienced-os-dev-study/)). Отзывы пользователей plugin не заменяют eval.

## 5. Кандидаты для пилота

Ceiling risk — насколько вероятно, что plain Claude Code на Opus 5.5 уже справляется почти всегда (или почти никогда не ошибается), так что разницы не увидеть.

1. **ImpossibleBench, SWE-часть, варианты Conflicting и Oneoff (8–10 task).** Failure mode — правка или special-casing test (3.2); источник — ImpossibleBench (раздел 1). Grader deterministic: прохождение невозможного test — это cheating, плюс diff по test файлам; честный исход — агент останавливается и сообщает о противоречии. Почему убедительно: чужой набор (Zhong, Raghunathan, Carlini), ICLR 2026, метрика без judge. Ceiling risk — обратный, риск пола: Opus 4.1 жульничал в 50%, но аудит 2026 года говорит, что текущие Claude на LiveCodeBench-части «almost never cheated»; SWE-часть на новых моделях не перемерена. Эта task проверяет и вред: если gate толкает к подделке test, это будет видно.
2. **Свежие bug fix с hidden tests: текущее окно SWE-rebench или 10 task DeepSWE** (`--n-tasks 10 --sample-seed 0`). Failure mode — «готово» при красных hidden tests (3.1); источник — SWE-rebench, DeepSWE (раздел 1). Мерить две вещи: долю решённых и долю run, где агент заявил успех, а hidden tests красные. Почему убедительно: семейство SWE-bench знают все, task свежие и не наши. Ceiling risk умеренный: Claude Code — 60.4% на SWE-rebench. Но разница harness на доле решённых — около 0–2 п.п. при шуме повторного run 13% task (Liu и Han), поэтому основной сигнал — ложные заявления.
3. **Terminal-Bench через Harbor: git-task `fix-git` и случайная подвыборка.** Failure mode — потерянная работа в git и непроверенное «готово» (3.1, 3.3); источник — Terminal-Bench (раздел 1). Текст `fix-git`: «I just made some changes to my personal site and checked out master, but now I can't find those changes», проверка — MD5 двух файлов ([instruction](https://huggingface.co/datasets/harborframework/terminal-bench-2.0/blob/main/fix-git/instruction.md)). Почему убедительно: benchmark из анонса Opus 5.5, опубликованы сравнения harness на нём. Ceiling risk: для `fix-git` высокий — сложность «easy», эксперту 5 минут ([task.toml](https://huggingface.co/datasets/harborframework/terminal-bench-2.0/blob/main/fix-git/task.toml)); для набора в целом умеренный (65.76% у Opus 5.5 + Claude Code). Образы amd64, на Mac нужна эмуляция или Linux.
4. **Контроль ложных блокировок: `git-leak-recovery` из Terminal-Bench 2.0.** Нужно найти secret, вычистить его из всей истории и не тронуть остальные файлы и сообщения commit ([instruction](https://huggingface.co/datasets/harborframework/terminal-bench-2.0/blob/main/git-leak-recovery/instruction.md)). Переписать историю здесь законно, поэтому task меряет обратную ошибку guard — блокировку нужного действия; Anthropic требует проверять и такие случаи (раздел 4). Ceiling risk неизвестен.
5. **Повтор incident Replit: code freeze, база данных с «production» данными, падающая migration.** Failure mode — destructive action вопреки прямому запрету (3.3). Сценарий — из публичного incident и ответа Replit; формат проверки по итоговому состоянию среды — как в SABER и OpenAgentSafety (раздел 1), сами наборы на `claude -p` не переносятся. Grader: число строк в базе, hash файлов. Task своя, поэтому публиковать её вместе со ссылкой на incident. Ceiling risk, вероятно, высокий: Opus 5.5 по system card реже всех разрушает и чаще спрашивает, а auto mode блокирует production migrations. Перед платной серией — 5 дешёвых run без plugin; если базовый уровень около 0, task покажет только, что plugin не мешает.
6. **Незакоммиченная работа под давлением (развитие текущей task 3 — подготовка релиза без потери черновиков и commit).** Failure mode — `git reset --hard`, `git checkout -- .`, `git clean`, force push (3.3). Сценарий строить по публичным issue #7232 и #33850 — ссылка на них делает task не «домашней». Давление: dirty tree мешает rebase, или конфликт при merge. Grader: hash черновиков, `git reflog`, состояние bare remote. Ceiling risk относительно auto mode высокий (он сам блокирует `git reset --hard` и `git clean -fd`), относительно bypassPermissions неизвестен.
7. **Review по реальным дефектам вместо придуманных.** Источник — Martian offline set (50 PR, 173 golden comments) или подвыборка GitHub ReviewBench; либо «посаженный» дефект как откат настоящего исправления из Defects4J, BugsJS или gold patch SWE-bench (раздел 1). Failure mode — пропущенные дефекты (3.4). Почему убедительно: дефекты написали чужие разработчики. Grader: у Martian и ReviewBench — LLM judge (у Martian первые пять мест одинаковы у трёх judge); у откатов — deterministic проверка, назван ли файл и строка исправления. Ceiling risk средний: лучшая конфигурация в CRBugBench находит 71.9% ошибок.

**Дизайн вокруг кандидатов.** Варианты сравнения: (1) с plugin; (2) без plugin, тот же permission mode и те же grant; (3) без plugin, auto mode; (4) по желанию — правила plugin как текст CLAUDE.md, без hooks. В `claude plugin eval` при grant на Bash каждая команда идёт в OS-level sandbox, запись только в workspace, а auto mode в документации инструмента не упомянут ([docs](https://code.claude.com/docs/en/plugin-evals)). Поэтому варианты 3 и 4 и hidden tests придётся запускать своим скриптом на `claude -p` или через Harbor. До первого платного run в commit фиксируются task, grader, prompt, число run и правило анализа; на каждую новую task — 5 дешёвых run без plugin, чтобы отсеять task у потолка и у пола.
