## Проблема

Человек работает в Claude Code: в терминале, в Claude Desktop или на Linux, где приложения worfy нет. Он хочет вести
работу так, как её ведёт worfy: Epic из Ticket-ов, Wave-ы в worktree-ах, gate до PR, review и merge. Без приложения
он этого сегодня не получит:

- plugin `worfy` ставит и обновляет только приложение; из публичного репозитория одной командой Claude Code его не
  поставить;
- qmd (локальный поиск по документам) и проверки первого запуска есть только в приложении;
- `/worfy:connect-project` в терминале просит человека самому запустить команду и вставить её вывод, а аккаунт
  GitHub не спрашивает;
- status line терминала указывает на скрипт внутри приложения и ломается, если приложение удалить.

Ядро при этом уже работает без приложения: hooks, gate, скрипты Harness и Profile к приложению не обращаются, Wave
доходит до merge.

Почему сейчас: параллельные Session-ы с worktree, PR и browser уже входят в подписки всех крупных вендоров; отличие
worfy — процесс, то есть Harness (заметка о рынке, раздел 5). На Linux приложения нет совсем.

## Решение

Harness ставится из публичного репозитория worfy одной командой Claude Code, так же обновляется и удаляется. Одна
проверка машины говорит, чего не хватает, и по согласию ставит qmd. В обычном Claude Code человек подключает Project,
пишет spec и Ticket-ы, запускает Wave `/worfy:epic-wave` и доходит до merge. Приложение и ручная установка знают друг
о друге и не мешают друг другу. CI job с первой Wave проверяет режим без приложения на Linux, macOS и Windows.
Autopilot, notifications, Mind map, Cards, Browser и Linked machines остаются только в приложении.

## Решения по реализации

- **Канал установки — публичный репозиторий worfy.** В корне репозитория появляется manifest marketplace, который
  указывает на папку Harness. Новый ADR снимает довод ADR-0040 против marketplace на GitHub («нужны сеть и доступ к
  private-репозиторию»): репозиторий публичный с 2026-10-28. Локальный marketplace приложения остаётся как есть.
- **Версии в источнике нет.** Plugin из Git-marketplace без поля `version` получает версией SHA коммита, и
  пользователи канала GitHub получают каждый коммит; закреплённая версия держала бы всех на одной копии
  (https://code.claude.com/docs/en/plugins/loading, «How Claude Code computes the version»). Правила версий
  приложения не меняются; случай «версия не из сборки приложения» закрывает Ticket 06.
- **Обновление руками.** Для marketplace не от Anthropic auto-update по умолчанию выключен (там же, «When auto-update
  runs»): инструкция даёт команду обновления и говорит, как включить auto-update.
- **Одно имя marketplace.** У пользователя может быть только один marketplace `worfy-harness`. Installer приложения,
  найдя его с другим источником (GitHub или клон), не перезаписывает молча: показывает строку с выбором и пишет её в
  log.
- **Проверка машины — скрипт Harness** с теми же строками, что First run приложения. Только читает, печатает действия
  и отвечает exit code-ом, всё ли готово.
- **qmd** ставится тем же скриптом или соседним, только после вопроса о скачивании моделей: закреплённая версия, файл
  согласия, collections. Без согласия Harness работает на grep.
- **`/worfy:connect-project` в терминале** сам запускает только читающий `project-connect --facts` и спрашивает
  аккаунт GitHub; `profile-set` учится писать `github.account`. Черновик и явное «да» перед записью остаются.
- **Status line без bundle.** Скрипт-мост status line лежит в Harness home, а не внутри приложения; когда приложения
  нет, он отдаёт строку предыдущей команды пользователя.
- **Конец Wave.** Отчёт `/worfy:epic-wave` печатает готовую команду следующей Wave.
- **Инструкция** пишется в описании Harness (en и ru). Строка в README, которая зовёт незнакомых людей ставить
  Harness, ждёт решения владельца по лицензии.
- Product Session, Mind map, Autopilot и notifications в терминал не переносятся.

## Решения по test-ам

- Хороший test проверяет поведение снаружи: команду, exit code, файлы в Harness home и настройках Claude Code, а не
  устройство скриптов.
- **Главный seam — CI job «Harness без приложения»** на Linux, macOS и Windows, с Wave 1: свежая временная папка
  Claude Code, установка plugin-а из папки репозитория, подключение учебного Project-а без вопросов, `gate fast`
  зелёный, `epic-status` видит учебный Epic. Первая версия работает на сегодняшнем Harness и собирается из готовых
  shell-тестов `project-connect`, `epic-status` и gate. Ticket-ы 01, 07 и 08 добавляют в него свои шаги: установку
  через manifest в корне, проверку машины, qmd.
- Скрипты проверки машины и qmd — contract test-ы, как у других скриптов Harness.
- Installer приложения: unit test-ы на чужой marketplace и на мост status line — рядом с test-ами installer-а.
- Приёмка владельца — руками, по чек-листу Ticket-а приёмки.

## Риски

- Claude Code может не поддержать manifest в корне, который указывает на подпапку. Ticket 01 начинает с проверки на
  чистой папке Claude Code; запасной путь — `extraKnownMarketplaces` с полем `path` или отдельный репозиторий.
- Имя `worfy-harness` занято у тех, кто ставит и приложение, и plugin руками. Если включены два plugin-а с одним именем
  из разных marketplace, hooks одного из них не работают (https://code.claude.com/docs/en/plugins/loading, «Hooks when
  two enabled plugins share a name») — поэтому Ticket 06.
- Установка из клона грузит Harness с текущей ветки клона: инструкция ведёт на канал GitHub, клон — для разработки.
- Windows без Git Bash: hooks идут в PowerShell, и gate может не стартовать — исследование это не проверяло; первая
  версия CI job на Windows ответит в Wave 1.
- CI: нужны ли команде `claude plugin` вход и сеть на runner-е — выясняет Ticket 02 в Wave 1; только бесплатные
  runner-ы.
- Публичный репозиторий: незнакомые люди могут найти канал до решения по лицензии.
