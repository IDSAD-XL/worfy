# Для Orchestrator-а: строка в spec `worfy-harness-guarantees` о памяти Claude

Решение владельца 2026-11-28, тема `claude-projects-parity`, вопрос Q14 (возражение 3 критика,
[разбор](../critic/worfy-memory-2026-11-28.md)): «принимаю».

Когда делать: вместе с переносом черновика [worfy-memory](drafts/worfy-memory.md) в Epic. Владелец принял черновик
2026-11-28 (Q15).

Что дописать в `.scratch/worfy-harness-guarantees/spec.md`, раздел «Риски», пункт «Память Claude Code открыта»
(сейчас строки 601-603 на `c66e7215a`), датированной строкой, по смыслу:

> 2026-11-28: исключение для памяти Claude Code действует только в Session с человеком. В Session без человека
> (Autopilot) запись в папку памяти закрывает Epic `worfy-memory`, Ticket 02 — guard в PreToolUse hook Session, который
> на каждом вызове проверяет, есть ли человек. Guard этого Ticket-а (06) исключение для памяти сохраняет.

Почему: Ticket 06 этого Epic-а строит guard защищённых папок и нарочно оставляет память открытой
(`.scratch/worfy-harness-guarantees/issues/06-guard-защищённые-области-в-любом-режиме.md`, строка 41: «Исключения:
память Claude Code»). Без этой строки после выхода обоих Epic-ов два spec-а и два ADR будут описывать одну папку
противоположными словами. Встраивать отказ в guard Ticket-а 06 владелец не стал: Ticket 06 стоит в Wave 4 чужого
Epic-а, а его отметка «без человека» задаётся при старте процесса и не видит, что остановленный Autopilot вернул Session
человеку.
