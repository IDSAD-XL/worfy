  строки 36–42). «P1 — Session convenience parity» (PR, строка 88).

  то, что уже работает), Epic (папка `.scratch/<epic>/` со spec и Ticket-ами) или код.

- **E2–E4** — этапы roadmap; E4 — выход к другим людям (`docs/roadmap.md:1`, `docs/roadmap.md:445-448`).

  чем-то пользуются.
- **Конкурент уже описан.** Досье от 2026-11-13 разбирает Claude Projects. Coordinator — один долгий разговор
  проекта: он сам отвечает, запускает thread или передаёт работу существующему. Overview группирует threads по
  состояниям. Library хранит файлы
  (`docs/research/2026-11-13-competitors/claude-code-cloud-sessions-and-projects.md:141-158`). Эта заметка
  конкурента не перепроверяет. Она сверяет PR с worfy.

### Выводы по A

- Маршрутизация уже есть, но по правилам, без модели. Адресат выводится из Binding-а. Адресат по умолчанию —
  Orchestrator. Куда ушёл текст, видно в toast-е и в строке transcript-а (`docs/features/projects.md:375-381`,
  `docs/features/pr-inbox.md:108-109`).
- По-настоящему нового четыре вещи:
  - разбор свободного текста по смыслу;
  - `@Session` в поле ввода;
  - разговор, который переживает смену Session-ов Orchestrator-а;
  - элемент работы для ad hoc задачи.
- Мелкая правка без Epic-а возможна уже сейчас: ручная Session, своя правка Orchestrator-а, PR без Ticket-а. Не
  хватает следа: до PR такой работы нет ни в Pipeline, ни в Changes.
- PR просит строить на Orchestrator-е (строка 32). Тогда сначала нужен ответ: что видит человек в разговоре, пока
  Run владеет Orchestrator-ом и меняет его Session на каждой Wave (`docs/features/sessions.md:349`).
- Прежние решения, которые придётся пересмотреть или обойти:
  - ADR-0100: Epic-и в очередь ставит только человек;
  - ADR-0002: своей базы работы у worfy нет;
  - глоссарий: conversation и «главный чат» — в списке Avoid;
  - граница Assistant-а: Session, текст которой человек не прочёл, не стартует.
- Роль «Assistant — только над Project-ами» не совпадает с кодом: Assistant уже будит Orchestrator и продолжает
  Session-ы Project-а. Делить полномочия удобнее вместе с приёмкой Epic-а `worfy-assistant` (Ticket 20).

### Выводы по B

- Canvas — домашний вид и цель почти всех переходов. Режим без Canvas — это не только скрыть кнопку. Нужны новые
  цели для Esc, Go to и клика по Ticket-у: сейчас все они ведут на Canvas.
- Обзор Project-а собран по частям: карточка Project-а в sidebar, секция и доска Pipeline, Acceptance, Waits и
  Summary Assistant-а. Одного экрана нет. Общий список «что ждёт человека» владелец уже отдал Assistant-у.
- Правило «не двигать то, что поставил пользователь» уже действует. Сами двигаются только производные Node-ы:
  рамки, Ticket-ы, Subagent-ы. Это решения владельца 2026-10-19 (Epic `worfy-canvas`, ADR-0075).
- Library — самая новая часть PR. Хранилищ много: папка данных, `.scratch/<epic>/evidence/`, `docs/product/`.
  Каталога, версий, комментариев к Card-ам и видимого происхождения нет. Версии и комментарии придётся хранить в
  папке данных одной Machine (ADR-0005).
- «Generative Workspace» по сути уже есть как Card. Нового два шага: агент вызывает функции Card-а; Card живёт
  вне Canvas. Card не меняет workflow — это решение ADR-0002.
- Наблюдения тестера из PR (строка 9) в репозитории нет. Все записи о тестерах — про ошибки и настройку. Откуда
  наблюдение — вопрос владельцу.
- Метрики PR (строка 42) некому считать: аналитики нет, и roadmap держит её «не в направлении».
