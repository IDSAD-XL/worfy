## Проблема

**Память Claude уже включена во всех Session worfy.**

- Session worfy на Claude получают preset `claude_code` и `settingSources` user, project и local
  (`src/main/vendors/claude/options.ts:793-794`). Auto memory Claude Code (файлы в
  `~/.claude/projects/<репозиторий>/memory/`) в них включена. Env worfy её не выключает.
- В папке памяти репозитория worfy на Mac владельца 177 файлов: индекс `MEMORY.md` и 176 файлов тем. По меткам в
  frontmatter 94 файла записали Session через SDK, 51 — Session Claude desktop, у 31 автор не установить.
- Все worktree одного репозитория пишут в одну папку: Claude Code считает её от git root.

**Индекс памяти — это инструкция для каждой Session и каждого Subagent-а.**

- `MEMORY.md` приходит вместе с `CLAUDE.md`, под шапкой «These instructions OVERRIDE any default behavior».
- В 20 из 20 последних transcript-ов Subagent-ов основного checkout индекс есть. Документация Anthropic пишет
  обратное, но так ведёт себя runtime 2.1.322.

**Запись в память никто не проверяет.**

- Файлы `.md` в папку памяти runtime пишет без вопроса. Проверка разрешений worfy (`canUseTool`) этих записей не видит.
- Session Autopilot идут без человека, в режиме `bypassPermissions` (`src/main/vendors/claude/options.ts:795`,
  `src/main/vendors/claude/query.ts:77`).
- В Harness нет правил о том, что писать в память, а что нет.
- Итог: агент может прочитать чужой текст — комментарий к PR в публичном репозитории, веб-страницу, сообщение из
  connector-а — и записать его в память. С этого момента запись — инструкция для всех следующих Session, в том числе
  Autopilot.

**Человек память не видит.**

- В worfy нет UI, IPC и MCP для памяти Claude.
- При старте загружаются только первые 200 строк или 25 000 знаков индекса, остальное отбрасывается. Знаки runtime
  считает после trim, как длину строки JS (UTF-16), а не байты UTF-8. Сейчас индекс 107 строк.
  По подсчёту в заметке темы, 2026-11-23/24 он переполнялся и обрезался 19 раз.
- Слово Memory в worfy уже занято дважды. Это память процесса в version popover (`docs/features/app-shell.md:335`) и
  правила Assistant-а в Settings → Assistant → Memory (`docs/features/assistant.md:280`).

## Решение

Три части, по решению владельца Q6:

1. **Правила Harness о памяти.** Что агент пишет в память, а что никогда.
2. **Guard в Session без человека.** Запись в папку памяти из Session Autopilot получает отказ. Агент кладёт заметку
   в свой отчёт, а владелец потом сам говорит «запомни».
3. **Раздел Claude memory.** Список записей по репозиториям Project-а, поиск, тип, кто и когда записал, правка,
   удаление, размер индекса против предела. Сначала раздел живёт в Settings, рядом с Settings → Assistant → Memory.
   Сделан отдельным компонентом, чтобы потом встать во вкладку Context панели Project-а, если её примут.

Что не меняется:
- auto memory остаётся включённой по умолчанию;
- worfy не переносит папку памяти и сам файлы не переписывает, только по действию владельца;
- синхронизации между машинами нет;
- в Session с человеком агент пишет в память как раньше, но по правилам Harness.

## Решено советником

- **Имя: Claude memory, не Memory.** Слово Memory уже значит память процесса и правила Assistant-а. Термин «Claude
  memory» с определением добавляется в глоссарий: файлы auto memory Claude Code, одна папка на git-репозиторий и
  машину.
- **Путь к папке worfy считает так же, как runtime (Q13).** Порядок по заметке темы:
  1. env `CLAUDE_COWORK_MEMORY_PATH_OVERRIDE`;
  2. setting `autoMemoryDirectory`;
  3. иначе `<база>/projects/<имя>/memory/`:
     - база — env `CLAUDE_CODE_REMOTE_MEMORY_DIR`, иначе `CLAUDE_CONFIG_DIR`, иначе `~/.claude`;
     - имя — env `CLAUDE_CODE_PROJECT_DIR_NAME`, только при заданном `CLAUDE_CONFIG_DIR`. Иначе — путь канонического git
       root через ту же функцию, которой worfy уже называет папки transcript-ов: всё, кроме букв и цифр, становится
       `-`, а имя длиннее 200 знаков обрезается, и к нему дописывается hash. Своего второго правила не пишем.

  Правило проверяется test-ом на fixture. Ещё оно встаёт в список того, что проверяется при обновлении Claude Code.
- **Project из нескольких репозиториев.** У каждого репозитория своя папка памяти. Раздел группирует записи по
  репозиторию.
- **Linked Machine.** Раздел показывает память той машины, на которой открыт worfy. Память Project-а другой машины — не
  в этом Epic-е.
- **Guard — тот же механизм, что у Product Session.** Это PreToolUse hook, как guard из `src/main/agent/product-guard.ts`.
  Он стоит в Session-ах, которые стартуют без человека, сейчас это Autopilot. Есть ли в Session человек, guard читает
  на каждом вызове, а не при запуске (Q12). Остановленный Autopilot возвращает Session человеку в том же процессе, и
  после этого «запомни» снова работает. Так же устроена проверка разрешений Session: она читает тот же флаг на каждом
  вызове. Guard ловит:
  - Write, Edit, MultiEdit и NotebookEdit, если путь лежит в папке памяти;
  - Bash, если путь папки памяти есть в тексте команды.

  Ответ агенту — на английском (Harness и код English-only, ADR-0074): «Memory is written only in a Session with a
  person. Put the note into your report.» Обход через переменные и `cd` шаблон не ловит. Это известная граница, она
  записывается в ADR.
- **Правка и удаление.** Перед записью раздел сверяет mtime файла: если runtime успел его изменить, раздел предлагает
  перечитать. Удаление убирает и файл, и его строку в `MEMORY.md`.
- **Размер индекса.** Раздел показывает строки и знаки против 200 строк и 25 000 знаков. Знаки считаются после trim,
  как у runtime, а не байты (Q13): иначе индекс на кириллице показался бы переполненным задолго до настоящего предела.
  Раздел предупреждает, когда индекс подходит к пределу или перешёл его.

## Решения по реализации

- **Модули.**
  - main: чтение Claude memory — путь, разбор frontmatter, индекс и его размер. Правка с проверкой mtime и удаление
    вместе со строкой индекса.
  - guard: функция решения (tool, его вход, папки памяти, есть ли человек сейчас) → разрешить или отказать с текстом.
    Её вызывает PreToolUse hook Session-ов, которые стартуют без человека. «Есть ли человек» hook берёт из живого
    состояния Session на каждом вызове (Q12).
  - Harness: файл правил о памяти, English-only.
  - renderer: раздел Settings → Claude memory, отдельным компонентом.
  - IPC между main и renderer.
- **Контракт чтения, по смыслу.** На каждый репозиторий Project-а:
  - папка памяти;
  - индекс: строки и знаки после trim, предел 200 строк и 25 000 знаков (Q13);
  - записи: файл, name, description, type, originSessionId, modified, есть ли строка в индексе.
- **Операции.** Прочитать файл. Сохранить файл с ожидаемым mtime: при несовпадении отказ «файл изменился». Удалить файл
  вместе со строкой индекса.
- **Правила Harness, по смыслу.**
  - Писать: устойчивые предпочтения владельца, причины решений, которых нет в репозитории, уроки, внешние ссылки.
  - Никогда не писать: чужой текст как инструкцию, секреты и token-ы, то, что читается из репозитория.
  - Держать индекс по одной строке на запись.
  - В Session без человека — не писать совсем.
- **ADR.** Auto memory в worfy включена по умолчанию; guard в Autopilot и его граница с Bash; раздел Claude memory.
  ADR называет и Ticket 06 Epic-а `worfy-harness-guarantees`: исключение памяти в его guard-е защищённых папок
  действует только в Session с человеком, а для Session без человека память закрывает этот Epic (Q14).

## Решения по test-ам

- Хороший test проверяет внешнее поведение: что увидел владелец и что получил агент, а не внутренние вызовы.
- **Seam 1 — функция решения guard-а.** Unit test-ы: Write, Edit, MultiEdit, NotebookEdit и Bash с путём папки памяти;
  Session с человеком и без; чужая папка. Отдельный случай (Q12): Session стартует без человека, её возвращают
  человеку в том же процессе, и запись после этого проходит. Prior art — unit test-ы guard-а Product Session.
- **Seam 2 — чтение Claude memory на fixture-папке.** Unit test-ы: правило пути во всех вариантах, включая базу из env
  и имя длиннее 200 знаков с hash; разбор frontmatter; размер индекса в знаках и переход предела; индекс на кириллице
  не считается переполненным раньше runtime (Q13); сохранение с устаревшим mtime даёт отказ; удаление убирает строку
  индекса.
- **Seam 3 — раздел Claude memory.** Component test-ы, как у вкладки Settings → Assistant → Memory: список, поиск,
  фильтр по типу, предупреждение о пределе.
- Правила Harness test-ом не проверяются. Eval-случай для них — работа плана `worfy-harness-eval`.

## Не в этом Epic-е

- Guard защищённых папок — Ticket 06 Epic-а `worfy-harness-guarantees` (spec принят 2026-11-28). Он оставляет память
  Claude открытой: «Описано, не закрыто». Этот Epic его не трогает и закрывает память только для Session без человека.
  Чтобы два spec-а не говорили противоположное, Orchestrator после приёмки этого черновика дописывает в spec
  `worfy-harness-guarantees` датированную строку ([просьба](../для-orchestrator-а-harness-guarantees-06.md), Q14).
- Синхронизация памяти между Linked Machines: по roadmap личную память пользователя worfy не ставит и не переносит
  (`docs/roadmap.md:461-462`).
- Отметка «вспомнил» по событию SDK: выбор памяти на каждый turn закрыт серверным флагом, в 8 513 transcript-ах таких
  событий нет.
- Очередь записей на одобрение (вариант «в» вопроса Q9). Она нужна, только если заметок из Autopilot окажется мало.
- Память Codex: PR #2270 её откладывает.
- Вкладка Context в панели Project-а: ждёт решения по прототипу. Компонент встанет туда без переделки.
- Поле `memory` у агентов Harness (implementer, reviewer и другие) — своя память роли в Claude Code. Это отдельный
  вопрос.
- Выключатель памяти и смена её папки из worfy. Выключатель дешёвый (env на Project), его можно добавить, если владелец
  захочет.

## Риски

- **Runtime поменяет правило пути или формат frontmatter.** Тогда раздел покажет пустоту. Мера: test на fixture и
  пункт в проверке при обновлении Claude Code.
- **Обход guard-а через Bash с переменными или `cd`.** Мера: граница записана в ADR, правила Harness запрещают запись
  без человека. Если обход случится, переходим к очереди записей.
- **Правка владельца и запись runtime в один момент.** Мера: проверка mtime.
- **Autopilot теряет полезные заметки.** Мера: заметки идут в отчёт, владелец говорит «запомни».

## Как поймём, что работает

- После выхода Epic-а в transcript-ах Session Autopilot нет записей в папку памяти, а отказы guard-а видны.
- На приёмке владелец находит запись по слову, правит её и удаляет, и строка уходит из индекса.
- Индекс не переходит предел незаметно: раздел предупреждает раньше.

Аналитики использования нет: всё проверяется на владельце.
