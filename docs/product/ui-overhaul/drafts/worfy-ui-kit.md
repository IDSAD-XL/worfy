## Проблема

Пользователь worfy открывает много окон и меню: Settings, окна Project-ов и Machine, Command palette, menu и popover
на Canvas. Ведут они себя по-разному:

- в 13 из 19 модальных окон Tab уводит фокус за пределы окна, на кнопки под ним;
- в 12 окнах после закрытия фокус не возвращается к кнопке, которая окно открыла;
- подсказок как компонента нет, вместо них около 335 атрибутов `title`. С клавиатуры их не видно. Подсказку «почему
  действие неактивно» на экране Linked machine (связанной машины только для чтения) видно только мышью;
- menu и popover у края окна уезжают за край. Переворачиваться вверх или вниз умеют только три места;
- Esc в каждом окне обрабатывается по-своему. Под focus mode это уже трижды давало баги;
- в segmented control, своих radio и tabs Flight recorder стрелки не работают.

Разработчик worfy, человек или агент, пишет каждый новый dialog и popover копией соседнего. В каждой копии заново
backdrop, Esc, нажатие снаружи, фокус и место на экране. Из 147 commit-ов в файлах этих компонентов 17 исправляли
именно поведение. Источник цифр — заметки темы `notes/inventory-overlays.md` и `notes/inventory-foundation.md`.

## Решение

У worfy появляется общий слой компонентов — kit — на Base UI (`@base-ui/react`, headless, MIT). Base UI отвечает за
поведение:

- focus trap и возврат фокуса;
- Esc и нажатие снаружи;
- место на экране с переворотом у края;
- стрелки и typeahead.

Вид строится на своём CSS и design tokens worfy. Менять его можно там, где это улучшает UX. На обёртки kit
переходят все модальные окна, popover-ы, menu,
context menu, важные подсказки и группы кнопок. Command palette и toast-ы сохраняют свою логику. Свои Button и Chip
получают варианты. Числа limits, context meter и стоимости меняются плавно через NumberFlow. Lint и проверка axe
следят, чтобы доступность не откатывалась.

Пользователь видит знакомые окна. Разница в том, что:

- Tab не уходит из окна;
- фокус возвращается на место;
- подсказки видны с клавиатуры;
- menu не уезжают за край;
- стрелки работают во всех группах.

## Решения владельца (тема ui-overhaul, 2026-11-11)

- Полного overhaul на shadcn/ui с Tailwind нет: «с остальным согласен». Остаётся довод цены: 35–45 Ticket-ов, весь
  CSS и сотни test-ов.
- Base UI — слой поведения под свой CSS. Первым идёт spike Base UI в Electron. Перед миграцией строится фундамент
  слоёв. Settings, Keyboard shortcuts и Guide переносятся одним шагом.
- Toast-ы остаются свои, Sonner не берём. У Command palette свой ranking, cmdk не берём. Vaul не берём.
- Коллекции эффектов (Magic UI, Aceternity UI, RareUI, 21st.dev) в UI не берём. Beautiful UI — образец для chat
  Session, но не в этом Epic-е.
- Свои Button и Chip с вариантами. `eslint-plugin-jsx-a11y` и axe в e2e.
- Выбор библиотеки и правила обёрток записываются в ADR.
- NumberFlow: «NumberFlow можно».
- Вид можно менять, если это улучшает UX: «насчет того что вид не поменяется это не так критично, изменения
  внешнего вида допустимы если они улучшают UX».
- Возражения критика 1–3 приняты: «ок», «ок», «да»
  ([рецензия](../../critic/worfy-ui-kit-2026-11-11.md)).
- Запрет копировать вид чужого продукта снят: «отменяем это решение, никаких запретов»
  ([#1802](https://github.com/IDSAD-XL/worfy/pull/1802)).

## Решения по реализации

- **Библиотека** — `@base-ui/react`: точная версия в `dependencies`, лицензия MIT. Запись идёт в ADR по образцу
  ADR-0037 (о раскладке рамки Epic-а через ELK, где пакет добавили с проверкой лицензии и без install scripts).
  Версия ставится не моложе суток: это правило pnpm. Обновления вручную, как у остальных зависимостей.
- **kit — обёртки в общем модуле `theme`**, рядом со своими `Select` и primitives. Обёртки: Dialog, Popover,
  PreviewCard (hover card), Menu, ContextMenu, Tooltip, ToggleGroup, RadioGroup, Tabs. AlertDialog в kit не входит:
  у него не осталось пользователей (возражение 3 критика). Каждая обёртка добавляет:
  - классы и tokens worfy;
  - слой из шкалы z-index;
  - закрытие по blur окна и при смене вида;
  - для popup-ов Canvas — пометку «внутри Node»: классы `nodrag`, `nopan`, `nowheel` и пропуск в обработчике
    Canvas, который снимает активность Node-а;
  - отметку keep-out для toast-ов.
- **Base UI импортирует только kit.** Для остального renderer-а действует правило lint `no-restricted-imports`.
- **Шкала слоёв** — именованные tokens z-index: overlay Canvas, панели, popover, dialog, menu поверх dialog,
  toast, самый верхний слой (menu version chip). Overlay-объявления из 79 своих переходят на шкалу.
- **Один helper «открытые слои»** заменяет шесть проверок по ролям. Он знает dialog, menu, listbox и popup, который
  ещё в DOM, но уже закрывается.
- **Esc: одно нажатие — одно действие.** Обёртки отмечают обработанный Esc через `preventDefault`. Как это сделать
  в Base UI, выясняет spike. Поле ввода чата перестаёт прерывать ход агента, если Esc уже обработан
  (`defaultPrevented`).
- **Settings, Keyboard shortcuts и Guide** переходят на Dialog kit одним Ticket-ом, их три guard-а на клавиатуру
  удаляются. Иначе два focus trap спорят за фокус. Правило ADR-0090 (окно worfy Guide) «открыт всегда только один
  из трёх диалогов» остаётся.
- **Остальные модальные окна** переходят пачками по областям приложения. Своих focus trap не остаётся.
- **Toast-ы.** Store и правила остаются свои: показ по Project, очередь сверх трёх, раскладка в обход открытых
  слоёв, `role="alert"` для ошибок. Dialog kit не считает клик по области toast-ов нажатием снаружи и не прячет её от
  screen reader-а.
- **Command palette** переходит в Dialog kit: focus trap, `aria-modal`, возврат фокуса. Свои остаются ranking,
  асинхронная группа «In transcripts», неактивные строки с причиной и клавиши. cmdk не берём.
- **Tooltip kit** сначала заменяет `title` там, где текст важен: подсказки «почему неактивно» на Linked machine и
  кнопки-иконки. Остальные `title` остаются, пока их место не трогают. Неактивная кнопка с подсказкой остаётся
  `aria-disabled`, как сейчас: у `disabled` подсказка не показывается.
- **Группы.**
  - ToggleGroup заменяет `SegmentedControl` и три его копии.
  - RadioGroup заменяет свои radio окна Start Autopilot и карточки вопроса.
  - Tabs заменяет tabs Flight recorder.
  - Tabs в Sidebar уже доступны с клавиатуры и остаются.
- **Остаются своими:** `Select` (уже доступен с клавиатуры и screen reader-а), Find bar, side panels, focus mode,
  selection toolbar и кнопка Focus. У последних своя раскладка внутри zoom Canvas.
- **`Select` внутри окна kit.** Список своего `Select` рисуется в `document.body` поверх всех окон. Модальный Dialog
  Base UI отключает клики снаружи окна и может спрятать список от screen reader-а. Решение выбирает spike из трёх
  вариантов, до переноса Settings:
  - `Select` рисует список внутри открытого окна;
  - kit считает список `Select` частью окна;
  - окна kit с `Select` открываются в режиме `modal: 'trap-focus'`: фокус остаётся в окне, клики снаружи работают.

  Возражение 1 критика, принято владельцем 2026-11-11.
- **Button и Chip** — свои компоненты с вариантами в `theme`, без библиотеки:
  - Button: primary, secondary, danger, link, icon, высоты по одной шкале из tokens;
  - Chip: варианты статуса, вместо примерно 15 своих.
- **NumberFlow** (`@number-flow/react`, MIT) показывает проценты limits, заполнение context meter и стоимость.
  - Анимация идёт только при смене значения, не при первом показе.
  - При Reduce motion цифры меняются сразу.
  - Обратный отсчёт Auto-continue не анимируется: он меняется каждую секунду и стоит в `role="status"`.
- **Доступность под присмотром.** `eslint-plugin-jsx-a11y` входит в `pnpm lint` с теми правилами, которые код
  проходит после Epic-а. Проверка axe добавляется в e2e главных экранов: Canvas, Session, Settings, Command palette,
  Guide.
- **Вид.** Обёртки берут существующие классы и tokens. Где DOM меняется, CSS переходит на data-атрибуты Base UI:
  `data-open`, `data-checked`, `data-side`. Вид можно менять, если это улучшает UX (решение владельца
  2026-11-11). PR называет такую правку отдельной строкой, чтобы её видели review и приёмка.
- Анимации открытия окон и menu сейчас нет. Этот Epic её не добавляет.

## Решения по test-ам

- Хороший test проверяет поведение снаружи: роль и имя, где фокус, какие клавиши работают, что закрылось. Как
  устроены обёртка и Base UI внутри, test не проверяет.
- **Seam 1 — unit test-ы kit** (vitest и testing-library). На каждую обёртку один файл:
  - роль и имя;
  - Tab не уходит из Dialog;
  - фокус возвращается;
  - Esc закрывает только верхний слой и отмечает нажатие как обработанное;
  - стрелки в группах;
  - клик по области toast-ов не закрывает окно;
  - закрытие по blur окна.

  Образцы — test-ы `select`, `settings-dialog`, `shortcuts-overlay`, `guide-window`, `modes-menu`, `canvas-menu`,
  `history-popover`.
- **Seam 2 — один e2e spec «слои»** в настоящем Electron:
  - popover и menu поверх Canvas;
  - в Node, который тащат;
  - рядом с Terminal и Browser;
  - под focus mode и поверх Settings;
  - клик по toast-у при открытом окне;
  - место у края окна.

  Образцы — `focus.spec.ts`, `browser-layer.spec.ts`, `select.spec.ts`, `toast-placement.spec.ts`.
- **Существующие test-ы остаются защитой.** Миграция сохраняет роли и `data-testid`. Значит, 2 617 вызовов
  `getByRole` и 5 145 вызовов `getByTestId` должны проходить без правок. Проверки классов (814 мест) и геометрии в e2e
  (389) правятся в том Ticket-е, который меняет их DOM.
- **Бюджет старта.** Существующий e2e test старта за 3 s должен остаться зелёным. Spike заранее меряет разницу.
- **axe** — новый шаг e2e на главных экранах, `eslint-plugin-jsx-a11y` — в `pnpm lint`.
- Файлы kit не подходят ни под одно правило таблицы e2e по путям. Поэтому PR с правкой kit гоняет все e2e spec-и.
  Так и оставить: kit трогает все окна.
- Приёмка владельца — руками, по чек-листу с клавиатуры на macOS. Windows проверяют e2e на CI runner-е.

## Не в этом Epic-е

- Редизайн всего приложения, shadcn/ui, Tailwind. Отдельные правки вида, которые улучшают UX, входят в Epic.
- 4 inline confirm внутри панелей (`role="alertdialog"`): «Resume the Session» в Session Node и в истории
  Session-ов, Confirm в Settings → Pipeline, удаление профиля Browser. Они остаются inline (возражение 3 критика).
  Известный изъян: фокус к вопросу не переходит и Esc его не закрывает. Это отдельная правка позже, без библиотеки.
- Перенос вида Beautiful UI в chat Session.
- Sonner, cmdk, Vaul. Magic UI, Aceternity UI, RareUI, 21st.dev.
- Свой `Select`, Find bar, side panels, focus mode, selection toolbar, кнопка Focus.
- Меню приложения, native-диалоги Electron, OS notification: web-библиотека их не заменит.
- Cards: у них нет шага сборки.
- Все 335 `title`: в Epic-е только важные, остальные — позже, когда трогают их место.
- Переключатель темы, i18n, анимация открытия окон.

## Риски

- **Spike ответит «нет».** Например, Base UI не уживётся с `<webview>`, xterm или перетаскиванием Node-а. Тогда Epic
  стоит после Wave 1, пока владелец не решит. Фундамент слоёв (02), Button, Chip и NumberFlow к этому времени уже
  готовы и нужны при любом пути. Запасные пути:
  - Radix с теми же обёртками. Но у него открыт
    [#4261](https://github.com/radix-ui/primitives/issues/4261): focus trap отбирает фокус у соседнего frame в
    Electron;
  - свои правки без библиотеки: focus trap в 13 окнах, стрелки, переворот у края. Это 4–6 Ticket-ов.
- **Клик внутри `<webview>` не доходит до document.** Popover из-за этого не закрывается
  ([Base UI #5410](https://github.com/mui/base-ui/issues/5410), там про iframe). Обёртка закрывает popup по blur
  окна. Работает ли это с `<webview>`, проверяет spike.
- **Menu открывается на нажатие кнопки мыши и мешает тащить**
  ([Base UI #6150](https://github.com/mui/base-ui/issues/6150)). Node-ы Canvas перетаскиваются. Проверяет spike.
- **Два focus trap на время миграции.** Окно kit поверх старого окна или наоборот будет перетягивать фокус.
  Поэтому три окна с guard-ами переходят одним шагом, а остальные — пачками по областям.
- **Размер.** Base UI целиком весит 166 KB min+gzip, один компонент — от 20 до 56 KB. Код грузится с диска.
  Охраняет e2e test бюджета старта 3 s.
- **Обновления.** Minor release Base UI выходит почти каждый месяц. Обновляем вручную, версия не моложе суток.
- **Правки test-ов.** Классы в test-ах упоминаются 814 раз, в e2e 389 проверок геометрии. Правятся там, где меняется
  DOM.
- **Windows.** Клавиши и Ctrl+K проверяют e2e на Windows runner-е в каждом PR.
