## Question

Как часто за последние 30 дней prompt-ы владельца в transcript-ах Claude Code содержат то, что ловят уже готовые
детекторы worfy: ключи и token-ы, email, IP, номера карт, длинные вставки, таблицы и дампы? Как часто в них
встречаются строки, похожие на секрет, но им не являющиеся (git SHA, UUID)? Отдельно worfy и другие проекты. Только
счётчики, без значений.

## Answer

Заметка: [research-секреты-в-prompt-ах-владельца.md](../research-секреты-в-prompt-ах-владельца.md). Только счётчики,
значения не выводились. Окно — 30 дней до 2026-11-28, transcript-ы Claude Code верхнего уровня; subagent-ы (5 888
файлов) и Codex не считались.

- Prompt-ы: 1 158. Настоящих секретов 0, дампов и таблиц 0, email — в 3. С августа (2 938 prompt-ов) `redactSecrets`
  сработал 4 раза, все — ссылки на переменные. Строк вида git SHA — в 60, UUID — в 30, домашнего пути — в 54.
- Вывод tool-ов, то есть то, что агент читает сам: 25 315 результатов, 20,7 MB текста — в сто с лишним раз больше,
  чем у prompt-ов (0,19 MB). `redactSecrets` сработал на 53 (0,21%), 47 из них — вывод Bash; строк вида token-а
  (GitHub, AWS, `sk-`, JWT, PEM) — 0. Email — в 135 результатах, 107 из них — ответы MCP-tool-ов в других проектах.
  SQL и таблицы — 8 результатов Bash, все в других проектах. UUID — в каждом четвёртом результате.
- Вывод: у владельца секретов по формату нет ни в одном канале, это подтверждает его слова. Текста, который агент
  читает сам, в сто раз больше, и данные людей (email) приходят туда прежде всего из MCP-tool-ов. Это довод в пользу
  второго Epic-а с proxy. Для MCP-tool-ов у Claude Code есть и более простой путь — замена вывода через hook, без
  оговорки о schema встроенных tool-ов.
