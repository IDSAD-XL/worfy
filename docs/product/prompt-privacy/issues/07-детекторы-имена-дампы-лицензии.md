## Question

Из чего строить распознавание, чтобы оно работало только на машине пользователя? Секреты: свои правила
(`redactSecrets`, `privacy.cjs`) или наборы правил gitleaks и secretlint, и какие у них лицензии. Имена: локальная
NER-модель (размер, поддержка русских имён), имена колонок дампа, свой список слов. Дампы и отчёты: CSV, SQL
`INSERT`, JSON, вывод psql — маскировать по колонке, сохраняя структуру. Какие false positive-ы типичны для текста
разработчика (git SHA, UUID, base64) и есть ли опубликованные цифры точности.

## Answer

Заметка: [research-как-скрывают-данные-до-модели.md](../research-как-скрывают-данные-до-модели.md), разделы 4 и 6.
Главное:

- Секреты: наборы правил gitleaks и secretlint — MIT, их можно встроить; trufflehog — AGPL-3.0, не годится для
  встраивания. Точность secret detector-ов скромная: precision 46–75% в сравнении 9 инструментов
  (https://arxiv.org/abs/2307.00714); false positive-ы дают общие regex и расчёт entropy. У gitleaks около 1 400
  stopwords только для правила `generic-api-key`.
- Движки для персональных данных Presidio и LLM Guard — MIT, но на Python. Из них стоит взять идеи: порог уверенности,
  `Vault` (одно значение — один placeholder), `Deanonymize` (возврат значений в ответ).
- Имена: локальная NER-модель в JS через transformers.js, например OpenAI Privacy Filter (Apache-2.0, ONNX около
  0,9 GB, в основном английский). На чужих данных готовые PII-системы ошибаются часто: в PIIBench span-level F1 ниже
  0,14 у всех восьми (https://arxiv.org/abs/2604.15776). Дешевле и предсказуемее — имена колонок дампа и свой список
  слов; NER-модель — отдельное решение после замера.
- Готовые образцы «уровня»: likelihood в Google Sensitive Data Protection (пять уровней, порог на каждый тип),
  `score_threshold` в Presidio; образец «по категориям» — `MASK` или `BLOCK` на каждый тип в LiteLLM и Bedrock
  Guardrails.
- Структурное маскирование дампов (по колонкам CSV, SQL, JSON, psql) готовым ни у кого из найденных не описано: это
  своя работа.
