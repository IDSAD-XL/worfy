## Проблема

Разработчик вставляет в prompt то, что ему нужно разобрать: лог с ключами и token-ами, отчёт с данными клиентов, дамп
таблицы из рабочей базы. Всё это уходит поставщику модели и хранится у него. У подписок Claude — 30 дней, до 5 лет,
если включено «Help improve our AI models». У API Anthropic — 30 дней. У личных аккаунтов ChatGPT, через которые
работает Codex, обучение на данных включено по умолчанию. Дальше агент разносит настоящие значения туда, где их видят
другие: в код, fixture-ы test-ов, commit-ы, тексты PR и Ticket-ы, в том числе публичного репозитория.

Сами агенты от этого не защищают. Ни Claude Code, ни Codex не дают hook-у переписать prompt: hook может только
заблокировать его, а заблокированный prompt всё равно остаётся в локальном transcript-е. Своего маскирования того, что
уходит модели, нет ни у одного из двух.

Владелец 2026-11-28: «я приучил себя не отправлять секреты в ллм, но знаю что многие так делают». Функция — для них.

## Решение

worfy сам отдаёт текст агенту, поэтому только он может заменить значения до модели. Это и есть Masking: найденное
значение заменяется placeholder-ом с типом и номером (`‹API_KEY_1›`, `‹EMAIL_2›`). Модель, transcript агента, PR и
Ticket-ы видят только placeholder-ы. Человек в чате worfy видит настоящие значения.

Как это выглядит для человека:

- Masking включён по умолчанию в каждом Project-е, на уровне «Secrets».
- Вставка в поле ввода сразу маскируется. Значок щита на кнопке Send показывает, сколько скрыто.
- Меню щита: ползунок уровня, категории по одной, режим «Detect only», предпросмотр того, что получит модель.
- Длинная вставка — дамп, отчёт — открывает лист проверки: слева оригинал с подсветкой, справа то, что получит модель.
- Клик по скрытому куску открывает его модели как есть, или скрывает такие всегда. Выделенный текст можно скрыть
  вручную.
- Одно и то же значение получает один и тот же placeholder во всей Session. Модель видит повторы и связи — например,
  что у клиента два заказа — но не сами значения.
- Дамп маскируется по колонкам: модель видит схему, типы, NULL и повторы.
- Настоящие значения не попадают в действия агента — файлы, команды, MCP. Ключ в `.env` кладёт человек.
- Интерфейс прямо говорит, чего Masking не закрывает: агент сам читает файл, базу или вывод команды; картинки не
  проверяются; Terminal view идёт мимо worfy.

## Решения советника без владельца

Их владелец принимает вместе с черновиком.

1. **Вложенный файл маскируется через копию.** Факт: worfy не вставляет текст вложенного файла в сообщение. Он пишет в
   сообщение путь, и агент читает файл сам (`src/shared/agent/attachments.ts`, `messageText`). Чтобы выполнить Q3 для
   текстовых вложений, worfy делает замаскированную копию файла в своей папке данных и даёт агенту путь копии. Так
   worfy уже поступает с перетащенными файлами вне Project-а. Если агент найдёт оригинал внутри Project-а сам, это канал
   «агент читает сам», вне первой версии.
2. **Таблица живёт столько же, сколько история Session.** Факт: удалить Session нельзя — законченная уходит в Archive,
   который «ничего не удаляет и срока не имеет» (`CONTEXT.md`, Archive; ADR-0076). Поэтому «удаляется вместе с Session»
   из Q5 значит: таблица удаляется, когда у Session не остаётся истории — когда Claude Code удалил её transcript по
   `cleanupPeriodDays`, а у Codex — rollout.
3. **Идентификаторы worfy не маскируются.** Сообщения Autopilot и Orchestrator worfy пишет сам: в них имена Epic-ов,
   Ticket-ов, веток и пути Project-а. Слово из своего списка внутри такого имени не заменяется, иначе агент не найдёт
   Epic. Агент всё равно увидит это имя в файлах, которые читает сам.
4. **Одна строка для модели о placeholder-ах.** В первом замаскированном сообщении Session worfy добавляет короткую
   строку: значения вида `‹…›` скрыты человеком, их нужно оставлять как есть. Иначе модель может «починить» placeholder
   или принять его за ошибку. Цена — одна строка на Session.
5. **Link показывает placeholder-ы.** Настоящие значения остаются на компьютере, где идёт Session. На телефоне чат
   показывает `‹EMAIL_2›`.
6. **Свой список слов хранится там же, где таблица**: в файле 0600, а не в общих настройках worfy. В открытом виде он
   виден только в настройках Project-а.
7. **Длинная вставка — от 300 символов.** Это порог листа проверки, взятый из прототипа. Медиана prompt-ов владельца —
   52 символа, 90-й перцентиль — около 300, поэтому обычный prompt лист не открывает.
8. **Файл через `@` получает подсказку.** Если prompt ссылается на файл через `@`, щит предупреждает, что содержимое
   агент прочтёт сам, без Masking.

## Решения по реализации

### Движок Masking

- Один модуль без DOM, общий для renderer и main: категории, уровни, детекторы, разбор дампов, placeholder-ы.
  Прототип показал, что такой движок проверяется в node без окна.
- Категории: Secrets, Finance, Contacts, Network, People, Identifiers, Own words. Уровни: Off, Secrets
  (Secrets + Finance + Own words), Secrets + contacts (+ Contacts + Network), All personal (+ People). Identifiers
  выключены во всех уровнях. Режимы: Mask и Detect only. Из прототипа, фрагмент:

  ```js
  var LEVELS = [
    { name: 'Выключено', cats: [] },
    { name: 'Секреты', cats: ['secrets', 'finance', 'words'] },
    { name: 'Секреты и контакты', cats: ['secrets', 'finance', 'words', 'contacts', 'network'] },
    { name: 'Всё личное', cats: ['secrets', 'finance', 'words', 'contacts', 'network', 'people'] }
  ];
  ```

- Детекторы Secrets берут семейства уже готового `redactSecrets` (контекст Terminal AI) и префиксы известных форматов
  из наборов правил gitleaks и secretlint (MIT, с указанием источника). trufflehog (AGPL-3.0) не берём. Без расчёта
  entropy: по исследованию, он главный источник false positive-ов.
- Finance: номера карт только с верной суммой Luhn, IBAN только с верной контрольной суммой.
- People: только колонки дампа (`name`, `full_name`, `fio`, `customer`, `client` и подобные), адреса, номера документов,
  даты рождения по ключевым словам. Имён в свободном тексте движок не ищет (Q6).
- Разбор дампа: CSV и TSV со строкой заголовка, таблицы psql и mysql, SQL `INSERT INTO … (cols) VALUES`, JSON-массив
  объектов. Категория колонки — по её имени. `id`, суммы, даты заказа и NULL не трогаются.
- Placeholder: `‹TYPE_N›`, тип по категории значения, номер растёт в пределах Session. Повторное значение получает
  прежний placeholder: так же делает `Vault` у LLM Guard. Значение уже в виде placeholder-а не маскируется второй раз.

### Где маскируется

- Поле ввода маскирует вставку сразу. Черновик хранит только placeholder-ы, таблица — в main.
- `Session.send` в main — единственная точка проверки для всего текста, который идёт агенту: поле ввода, Card,
  Autopilot, Orchestrator, Link, вложения. Уже замаскированный текст проходит её без изменений, новое найденное
  маскируется. Драйверы Claude Code (streaming input Agent SDK) и Codex (app-server, `turn/start` и `turn/steer`)
  получают только замаскированный текст.
- Все события Session (`prompt` и ответы агента) несут только замаскированный текст. Narrator Product Session,
  Flight Recorder и Code stories читают его же. Настоящие значения подставляет только вид чата в renderer: таблицу он
  читает через канал с меткой `local`, который Link не открывает. Ни события, ни каналы `project` настоящих значений не
  несут: Linked machine слышит и те, и другие.
- Вложенный текстовый файл — замаскированная копия в папке данных worfy, агенту — её путь (решение советника 1).
- Идентификаторы, которые worfy вставляет сам — имена Epic-ов, Ticket-ов, веток, пути Project-а, — не маскируются
  (решение советника 3).
- Первое замаскированное сообщение Session получает одну строку для модели о placeholder-ах (решение советника 4).

### Таблица и настройки

- Таблица «placeholder → значение» — на Session, в main. На диске — файл с доступом только для владельца (0600 в
  папке 0700) в папке данных worfy, за тем же интерфейсом хранилища секретов, что у Link. Не Electron `safeStorage`:
  с ad-hoc подписью worfy Keychain спрашивал бы доступ после каждого обновления Stable, а в CI его нет. Хранилище на
  Keychain заменит файл, когда подпись станет постоянной (ADR-0111). Таблица удаляется, когда у Session не остаётся
  истории (решение советника 2).
- Настройки Masking — на Project, в личных настройках worfy рядом с остальными настройками Project-а, не в
  репозитории: уровень, включённые категории, режим. Свой список слов — в том же файле, что таблица (решение советника
  6). Пока Epic не закончен, Masking выключен по умолчанию; последний Ticket включает «Secrets» у всех Project-ов, и
  новых, и уже подключённых.
- Журналы worfy пишут только замаскированный текст.

### Интерфейс

- Щит на кнопке Send: счётчик скрытого; меню щита — ползунок уровня, категории со счётчиками, «Detect only»,
  «Preview for the model». Отдельного переключателя рядом с Send нет: полоса под полем ввода и так тесная.
- Лист проверки для вставки от 300 символов: оригинал с подсветкой, текст для модели, категории со счётчиками, «Insert
  masked» и «Insert as is».
- Клик по скрытому куску в поле ввода: «Send as is», «Always mask», категория. Выделение: «Mask».
- Чат: настоящие значения с пунктирным подчёркиванием, по наведению — placeholder; переключатель «As the model saw it».
  Link показывает placeholder-ы (решение советника 5): канал `local` ему закрыт.
- Подсказки о границах: в меню щита — «Masking does not cover what the agent reads itself»; при картинке — «Images are
  not checked»; при `@`-файле — предупреждение (решение советника 8).
- Тексты интерфейса — на английском, как весь worfy. Документ функции — `docs/features/` на английском и в `ru/`, по
  правилу документов worfy.
- Глоссарий `CONTEXT.md`: Masking — замена конфиденциальных значений в тексте, который worfy отдаёт агенту,
  placeholder-ами с типом и номером; настоящие значения остаются на этом компьютере. Masked value — значение, скрытое
  от модели.

## Решения по test-ам

- Хороший test проверяет внешнее поведение: какой текст дошёл до драйвера агента, что показал чат, что записано на
  диск, — а не внутренние структуры движка.
- Seam 1 — движок. Contract test на наборе выдуманных текстов разработчика: лог с ключами, дамп psql, CSV-отчёт, письмо
  клиента, код, diff, лог с git SHA, UUID и путями. Планка Q4: на уровне «Secrets» скрыты 100% ключей известных
  форматов; в коде, diff и логе с SHA, UUID и путями ничего не скрыто. Повторы получают один placeholder. Набор растёт с
  каждым найденным пропуском.
- Seam 2 — `Session.send` → драйвер. Contract test с fake-драйверами Claude Code и Codex. Prompt с ключом из каждого
  входа — поле ввода, Card, Autopilot, вложение — доходит до драйвера только placeholder-ами. Все события Session несут
  только placeholder-ы; вид чата получает настоящие значения через канал `local`. После перезапуска таблица читается из
  файла снова — в CI тоже, потому что это файл, а не Keychain.
- Seam 2, Link: contract test проверяет, что ни одно настоящее значение не доходит до Linked machine — ни в событиях,
  ни в ответах каналов `project`.
- Seam 3 — поле ввода, e2e test: вставка лога, счётчик на щите, предпросмотр, отправка; длинная вставка открывает лист
  проверки; «Send as is» открывает один кусок.
- Ключи в fixture-ах собираются из кусков при запуске test-а. Причина: guard `scripts/check-personal.mjs` ловит
  token-ы и email во всех tracked-файлах, а GitHub push protection — правдоподобные token-ы. Прототип уже сделан так.
- Хранилище на Windows проверяет Windows verdict: Ticket хранилища — платформенный.
- Prior art: test-ы `redactSecrets` для Terminal AI и `harness/bin/tests/evidence-check.test.sh` для правил
  `privacy.cjs`.

## Риски

- **False positive-ы, и Masking выключают.** На prompt-ах владельца строк вида git SHA, UUID и пути в десятки раз
  больше, чем секретов. Против — уровень по умолчанию только с точными форматами, идентификаторы выключены, планка Q4.
- **Пропуск даёт ложное чувство защиты.** Precision готовых secret detector-ов — от 46% до 75%, лучший recall — 88%
  ([заметка](../research-как-скрывают-данные-до-модели.md), раздел 6.4). Против — честная
  подсказка «Masking can miss things», предпросмотр, «Always mask», набор fixture-ов растёт с каждым пропуском.
- **Модель путается в placeholder-ах.** Агенту иногда нужно настоящее значение. Против — «Send as is» для одного куска
  и строка для модели о placeholder-ах.
- **Слово из своего списка внутри имени Epic-а ломает команду Autopilot.** Против — идентификаторы worfy не
  маскируются.
- **Таблица хранит секреты на диске.** Открытым текстом, в файле 0600 — так же, как ssh хранит ключи, а worfy —
  секреты Link. Локальные файлы — не цель (Q2); Keychain — когда подпись worfy станет постоянной.
- **Настоящие значения уходят на Linked machine.** Link слышит те же каналы `project` и события, что окна. Против —
  события только с placeholder-ами, таблица через канал `local` и contract test Link.
- **Prompt cache.** Masking детерминирован в пределах Session — одно значение, один placeholder, — поэтому повторный
  текст побайтно тот же и cache не ломается.

## Как поймём, что работает

Аналитики нет, поэтому — проверки, а не метрики:

- Планка Q4 зелёная в CI.
- Ручная проверка владельца на Mac для Claude Code и для Codex. Вставить лог с ключом, дамп и письмо. Отправить.
  Убедиться: в transcript-е агента нет ни одного настоящего значения (поиск по файлу); чат показывает настоящие
  значения; после перезапуска worfy — тоже.
- Windows verdict для Ticket-а хранилища.
