# Скрытие конфиденциальных данных в prompt-е — карта

Тема Product Session `prompt-privacy`, начата 2026-11-28. Идея владельца 2026-11-28: чтобы «без страха вставлять
конфиденциальную информацию прямо в промпт», «с настройкой уровня блюра либо отдельно включаемыми категориями, типа апи
ключи, имена, или данные клиентов если вставляешь какой-то отчет или дамп с реальной БД», «именно как для
разработчика». Образец — Moon Blur от Realmoon: [заметка](research-moon-blur.md).

## Destination

Владелец принял черновик Epic-а `worfy-prompt-privacy` (`drafts/worfy-prompt-privacy.md`, первая строка под
заголовком — `Advisor draft`). До приёмки владелец попробовал прототип вставки с маскированием (один HTML-файл в этой
папке), а критик разобрал черновик. Подтверждено владельцем 2026-11-28: «1-5 да».

Достигнут 2026-11-28: владелец принял черновик («да»); критик — Reorder, возражения 1–3 приняты («все да»).

## Notes

- Skills темы: `worfy:grilling` и `worfy:domain-modeling` для вопросов, `worfy:research` для фактов (заметки — в этой
  папке), `worfy:prototype` для прототипа, `worfy:to-spec` для черновика, `worfy:critic` перед приёмкой.
- Репозиторий публичный. В файлы этой папки не попадают ни значения из prompt-ов и transcript-ов, ни имена людей,
  компаний и других проектов: только счётчики и категории.
- Moon Blur (подробно — в [заметке](research-moon-blur.md)):
  - маскирует текст до модели: модель получает placeholder вида `[MB_IBAN_1]`, человек видит в ответе настоящие
    значения;
  - в web-чате всегда включён, уровней нет, есть один переключатель «Stricter protection of people» и свой список слов;
  - уровни есть у их агента для кода Moon CLI: `off`, `secrets` (по умолчанию), `redact`, `strict`, `detect`, на
    папку, в личных настройках, не в репозитории;
  - Moon CLI маскирует и файлы, и вывод команд, потому что агент свой; в файлы, которые агент правит, и в MCP-серверы
    подставляет настоящие значения;
  - сами признают, что имена клиентов, компаний и проектов не ловятся, а код в backtick-ах web-чат не проверяет.
- Факты о worfy на 2026-11-28 (main `c66e7215a`):
  - весь текст для Session идёт через одно место: `Session.send` (`src/main/agent/session.ts:461`) → `deliver`
    (`:952`) → `run.handle.send` (`:958`). Claude Code получает его через streaming input Agent SDK
    (`src/main/vendors/claude/session.ts:435`), Codex — через app-server, `turn/start` или `turn/steer`
    (`src/main/vendors/codex/session.ts:591`). Через то же место идут Autopilot (`src/main/autopilot/run.ts:2833`),
    Card (`src/main/ipc/card-api.ts:74`), Orchestrator и Link;
  - мимо него идёт только Terminal view: ввод пишется прямо в PTY (`src/main/terminal/pty.ts:842`);
  - строка пользователя в чате — это тот же текст, что ушёл агенту; после перезапуска worfy чат читается из
    transcript-а агента (`src/shared/transcript/parse.ts`);
  - вставка в поле ввода (`src/renderer/session/MessageInput.tsx:371`) кладёт текст как есть; картинки становятся
    вложениями;
  - черновик prompt-а хранится открытым текстом в localStorage до отправки (`src/renderer/session/drafts.ts:28`);
  - готовые детекторы есть, но не для prompt-а: `redactSecrets` (`src/shared/terminal-ai/redact.ts:99`) для контекста
    Terminal AI заменяет ключи, token-ы, пароли и `*_KEY=` на `[redacted]`; `harness/lib/privacy.cjs` ловит домашний
    путь, имя хоста, адрес Tailscale, UUID, email, token-ы и слова личного списка, маска необратима. Обратной
    подстановки настоящих значений нет нигде;
  - false positive-ы уже встречались: комментарий `harness/lib/privacy.cjs:101` («not a branch like sk-learn-upgrade»);
    false positive-ы имени хоста, решение владельца 2026-11-11;
  - narrator Product Session отправляет Haiku дайджест хода вместе с сообщением пользователя
    (`src/main/agent/narrator.ts:18`) — это второй вызов модели с тем же текстом.
- Аналитики нет. Замер prompt-ов владельца (Ticket 05): за 30 дней настоящих секретов 0, дампов 0, email — в 3 из
  1 158. Владелец 2026-11-28: «я приучил себя не отправлять секреты в ллм, но знаю что многие так делают». Функция —
  для других разработчиков; как часто они вставляют секреты, неизвестно.

## Decisions so far

- [Что Claude Code и Codex дают скрыть: prompt, вывод tool-ов, файлы](issues/01-что-claude-code-и-codex-дают-скрыть.md):
  prompt hook-ом не переписать, только заблокировать — маскирует сам worfy; вывод tool-ов Claude Code подменяется
  через `PostToolUse.updatedToolOutput`, с дырами; Codex умеет только блокировать; всё, что уходит модели Claude Code,
  видит лишь proxy через `ANTHROPIC_BASE_URL`, в том числе при входе по подписке.
- [Детекторы: секреты, имена, дампы, лицензии](issues/07-детекторы-имена-дампы-лицензии.md): правила gitleaks и
  secretlint (MIT) можно встроить, trufflehog (AGPL) — нет; precision secret detector-ов 46–75%; NER-модель для имён
  около 0,9 GB и на чужих данных ошибается часто; маскирование дампа по колонкам готовым не найдено.
- [Как часто в prompt-ах владельца есть секреты и личные данные](issues/05-секреты-в-prompt-ах-владельца.md): за 30
  дней секретов по формату нет ни в prompt-ах, ни в выводе tool-ов; текста, который агент читает сам, в сто раз
  больше, и email туда приходят прежде всего из MCP-tool-ов.
- [Что и от кого защищаем](issues/02-что-и-от-кого-защищаем.md): значения не уходят поставщику модели, и агент не
  разносит их в код, commit-ы, PR и Ticket-ы; локальные файлы и экран — не цель; функция — для других разработчиков.
- [Какие входы маскируются в первой версии](issues/03-какие-входы-маскируются.md): весь текст, который worfy отдаёт
  агенту, для Claude Code и Codex; маскирование уже при вставке.
- [Уровни и категории](issues/04-уровни-и-категории.md): категории — основа, уровень — готовый набор; «Секреты» по
  умолчанию у всех Project-ов, идентификаторы выключены; настройка на Project, вне репозитория; модели распознавания
  имён нет.
- [Чем заменять и где показывать настоящие значения](issues/06-чем-заменять-и-где-настоящие-значения.md):
  placeholder с типом и номером, один на значение в Session; настоящие значения — только в чате worfy, не в действиях
  агента; таблица — в файле 0600, как секреты Link (было «Keychain»; пересмотрено по возражению критика 2026-11-28),
  события Session несут только placeholder-ы.
- [Прототип: вставка с маскированием](issues/08-прототип-вставки.md): основа — щит на кнопке Send с уровнем и
  категориями (вариант C); лист проверки только для длинной вставки (B); клик по скрытому куску (A).
- [Как назвать функцию в интерфейсе и в глоссарии](issues/09-как-назвать-функцию.md): «Masking»; для человека —
  «masked value».
- [Как проверить качество распознавания до выпуска](issues/10-как-проверить-качество.md): набор выдуманных текстов в
  fixture-ах; 100% ключей известных форматов скрыты, код, diff и лог с SHA, UUID и путями не тронуты.

## Out of scope

  proxy через `ANTHROPIC_BASE_URL` ([Какие входы маскируются](issues/03-какие-входы-маскируются.md)).
- Модель распознавания имён: владелец 2026-11-28 — «не делаем такое»
  ([Уровни и категории](issues/04-уровни-и-категории.md)).
- Запрет отправки секрета, как `strict` у Moon CLI: не в первой версии
  ([Уровни и категории](issues/04-уровни-и-категории.md)).
- Текст на картинках и скриншотах — интерфейс говорит, что картинки не проверяются; Terminal view — ввод идёт прямо в
  CLI. Владелец 2026-11-28: «все да».
