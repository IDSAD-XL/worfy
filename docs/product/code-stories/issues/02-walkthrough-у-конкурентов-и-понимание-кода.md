## Question

Как устроены обзоры изменений у конкурентов: Walkthrough у Factory, `pr-walkthrough.html` у HumanLayer, changeset
walkthrough у Traycer, Artifacts у Google Antigravity, Spotify Xirp, стили ответа Explanatory и Learning у Claude Code?
Что из этого годится для того, кто отвечает за код, а не для reviewer-а? Что известно из исследований о том, как человек
понимает код, написанный агентом, и помогают ли объяснения и вопросы на проверку?

## Answer

Заметка: [research-walkthrough-и-понимание-кода.md](../research-walkthrough-и-понимание-кода.md). Главное:

- Code story целиком не делает никто. Ближе всего по форме CodeRabbit Change Stack (preview): пронумерованные шаги в
  порядке, в котором изменение объяснил бы человек, объяснения у диапазонов строк, chat из выделенного диапазона. Это
  инструмент reviewer-а: chat опирается на репозиторий и web, а не на ход работы автора; проверки понимания нет.
- Адресат как у Code stories — у Google Antigravity (walkthrough для того, кто не следил за агентом), но сам walkthrough —
  краткий пересказ без требований и рисков.
- Проверку понимания делают только небольшие open-source инструменты.
- Когда код пишет AI, человек понимает его хуже: у Anthropic (52 разработчика, рандомизированный эксперимент) 50% против
  67% в quiz без AI.
- За проверку: ответ на вопрос держит знание дольше перечитывания (через неделю 56% против 42%; в метаанализе g=0.50, с
  обратной связью 0.73); около трети студентов с кодом, прошедшим test-ы, ошиблись в вопросах о нём.
- Против обязательной проверки: перенос на новые задачи слабый; в эксперименте с вопросами к коду от AI прирост
  незначим, а время выросло в 1.8–2.7 раза; GPT-4 отвечает на 88% таких вопросов. Данные почти только о студентах.
- Объяснение без способа проверки повышает согласие с AI, даже когда тот неправ; излишнее доверие снижает объяснение,
  которое делает проверку дешевле.
- Досье и README исследования конкурентов ошибались о Factory, HumanLayer, Antigravity и Xirp (раздел «Где досье и
  README ошибались» заметки).
