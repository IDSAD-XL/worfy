## Question

Для каких PR пишется Code story: PR Ticket-а, PR обычной Session без Ticket-а, PR коллег, которые ждут review владельца в
виде Pull requests? Кто её пишет и когда — агент, который писал код, пока его рассуждения ещё в контексте, или другой
агент позже, по кнопке? Сколько в ней шагов и где лежит story PR, у которого нет Ticket-а?

## Answer

Владелец 2026-11-15, раунд 2: «6-8 согласен».

- Q6, какие PR: любые. У PR Ticket-а story появляется сама. У PR обычной Session и у PR коллег, которые ждут review
  владельца в виде Pull requests, — по кнопке «Code story». У PR коллег рассуждений агента нет: story собирается из
  diff-а, описания PR и кода.
- Q7, кто пишет story PR Ticket-а: сам implementer, последним шагом перед PR, пока его рассуждения в контексте. В ней —
  что сделано, почему так, какие варианты отброшены, в чём он не уверен, чего не проверяют test-ы. worfy не присылает о
  ней уведомления: story ждёт на карточке Ticket-а и в PR. Story Epic-а собирается из story его PR. Это поправка к
  [Ticket 03](03-единица-code-story.md), Q2: story PR Ticket-а появляется сама, а не по кнопке; story Epic-а worfy
  по-прежнему предлагает, когда влит последний PR Epic-а.
- Q8, размер: в story маленького PR 1–3 шага, большого — до 10; в story Epic-а 5–10 главных шагов из story его PR.
- Q9, где лежит story PR (владелец, раунд 3: «9-10 да»). Story PR Ticket-а — файл `stories/NN-<slug>.md` в папке
  Epic-а рядом с `issues/`; implementer коммитит его в тот же PR. Reviewer-ы читают story вместе с кодом, правки по
  review обновляют её в той же ветке, privacy check Epic-а `worfy-evidence` уже смотрит всё, что ветка добавляет в
  tickets root (`docs/features/evidence.md`, первый абзац). В режиме Silent файл ложится в папку Workflow. Story по
  кнопке — PR обычной Session и PR коллег — лежит в данных worfy на этой машине и в репозиторий не попадает.

Отклонённые альтернативы: story PR Ticket-а по кнопке, которую потом собирает другой агент (рассуждений автора к тому
времени нет); story только у PR Ticket-ов; 5–10 шагов на любой PR.

Риск, оставленный на следующий раунд: автор описывает свой код слишком гладко. Как story проверяется и как обновляется
после правок по review — после исследования (Ticket 01).

## Comments

- 2026-11-15, владелец, Q12: «Пять правил (рекомендую)». Story остаётся правдивой так:
  1. инструкция implementer-у просит решения и доказательства, а не запись хода рассуждений — на такую запись API
     отвечает отказом `reasoning_extraction`;
  2. script сверяет каждый фрагмент story с кодом PR;
  3. verifier проверяет утверждения story как часть обычного review: неверное утверждение — такая же находка, как
     ошибка в коде;
  4. последний шаг story PR — «Что нашёл review и что осталось», из вердикта;
  5. если по review правят код, story правят в той же ветке.
- 2026-11-15, владелец, Q14: «Включена, с выключателем (рекомендую)». Story PR включена по умолчанию; настройка
  Project-а её выключает. Цена по оценке — несколько процентов от Ticket-а; точное число дадут первые Ticket-ы.
