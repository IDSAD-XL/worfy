- Идея владельца, 2026-11-14. За код отвечает человек, а не модель: «он за него несет ответственность, а не ллмка».
  Своего редактора кода worfy не строит. Вместо него контекст идёт обратно, от агента к человеку. Три части:
  - story из 5–10 частей: ключевой фрагмент diff, объяснение простыми словами, ссылка на требование Ticket-а или spec,
    риски и то, чего test-ы не покрывают;
  - вопрос к любой строке; ответ цитирует код и опирается на ход работы агента;
  - проверка понимания по желанию: 2–3 вопроса в конце story.

## Decisions so far

- [Из чего строить Code story: что остаётся от работы агента](issues/01-из-чего-строить-code-story.md): больше всего
  «почему» — текст PR на GitHub; рассуждения агента зашифрованы и доступны только модели при resume, пока жив
  transcript; отброшенные варианты записаны редко; resume на остывшем cache — $1,20–2,65 за первый вызов.
- [Walkthrough-и у конкурентов и что известно о понимании кода агента](issues/02-walkthrough-у-конкурентов-и-понимание-кода.md):
  ближе всего по форме CodeRabbit Change Stack — для reviewer-а, без хода работы автора и проверки понимания; проверка
  понимания помогает запоминанию, но как обязательная мало что доказывает.
- [Кто отвечает на вопрос к строке](issues/07-кто-отвечает-на-вопрос-к-строке.md): новая Session со story, diff-ом,
  Ticket-ом, текстом PR и вердиктами; ответ цитирует строки и источник. «Спросить автора» — только после замера.
- [Как сохранить «почему», пока агент работает](issues/06-как-сохранить-почему.md): это story PR, которую пишет
  implementer (Ticket 11); инструкция просит решения и доказательства, а не запись хода рассуждений.

- [Единица Code story, когда она появляется и как называется](issues/03-единица-code-story.md): story Epic-а worfy
  предлагает сама, когда влит последний PR Epic-а. Термин — «Code story», её части — «шаги». «По кнопке» для PR
  Ticket-а заменено решением Ticket 11. Шаги — в порядке объяснения, а не по файлам; первый — что было не так, последние
  — что не меняли, как проверено, что нашёл review.
- [Где живёт Code story](issues/04-где-живёт-code-story.md): файл в папке Epic-а в tickets root — в git в режиме Full,
  в папке Workflow в режиме Silent. Язык — `language.reports` из profile.
- [Code stories и черновики worfy-changes-view и worfy-acceptance](issues/05-code-stories-и-черновики-changes-view-и-acceptance.md):
  отдельный Epic без зависимости от них; полный diff — ссылкой на PR.
- [Code story на PR: какие PR, кто её пишет и какого она размера](issues/11-code-story-на-pr.md): story у любого PR.
  Story PR Ticket-а пишет сам implementer последним шагом перед PR и коммитит её в тот же PR
  (`stories/NN-<slug>.md`); уведомления о ней нет. Story PR Session и PR коллег — по кнопке, в данных worfy. Story
  Epic-а собирается из story его PR. Размер: 1–10 шагов по размеру PR, у Epic-а 5–10. Правдивость — пять правил (Q12):
  решения и доказательства вместо хода рассуждений, script сверяет фрагменты, verifier проверяет утверждения, шаг «Что
  нашёл review», правки в той же ветке. Story PR включена по умолчанию, настройка Project-а выключает (Q14).
  Окончательную story Epic-а собирает Orchestrator; story можно получить и раньше, по открытому PR; сборка невидима, с
  одним progress bar (Q13, Ticket 03).

- [Проверка понимания](issues/10-проверка-понимания.md): необязательная кнопка «Проверить себя» в конце story, 2–3
  вопроса с правильным ответом и ссылками на строки; ничего от неё не зависит; шаги получают отметку «прочитано».

- [Прототип Code story на настоящем изменении worfy](issues/08-прототип-code-story.md): на `worfy-mcp-live`. Владелец:
  содержание понравилось, UI нужно сделать интереснее — Ticket 12. Прототип показал, что «почему» часто не записано, что
  чтение Ticket-ов вместе находит разрывы, и что story после merge стоит около 100 тыс. token-ов на PR.
- [Где владелец читает Code story и задаёт вопрос](issues/09-где-читают-code-story.md): свой вид на всю основную
  область, как Run history; входы с рамки Epic-а, карточки Ticket-а, из Pull requests и из toast; сборка и ответы
  невидимы, только progress bar.
- [Как выглядит вид Story](issues/12-как-выглядит-вид-story.md): подача «Stories» — шаг на экран, полоска сегментов
  сверху, клик по половинам, главы-PR в story Epic-а. От карты изменения — только маленькая схема в шаге «Стыки между
  Ticket-ами», брошенная передача — красная пунктирная стрелка.

  [.scratch/worfy-code-stories/spec.md](../../../.scratch/worfy-code-stories/spec.md), 17 Ticket-ов в 7 Wave-ах. Черновик
