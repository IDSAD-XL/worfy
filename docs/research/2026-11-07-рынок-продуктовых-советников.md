# Рынок продуктовых советников: кто уже спорит с владельцем продукта

- **Дата:** 2026-11-07
- **Карта:** [`.scratch/worfy-product/`](../../.scratch/worfy-product/map.md). Исходные решения карты:
  Product Session — вид Session-советника для Product owner-а в одиночку, который не меняет код
  ([04](../../.scratch/worfy-product/issues/04-граница-product-session-и-разработки.md)); Mind map — живая схема из
  узлов Идея, Вопрос, Решение, Возражение ([05](../../.scratch/worfy-product/issues/05-экран-product-session-и-mind-map.md));
  критик перед приёмкой spec с вердиктом Keep, Reorder, Split или Defer и 3–5 идей по просьбе, из них хотя бы одна
  против roadmap ([08](../../.scratch/worfy-product/issues/08-поведение-советника.md)).
- **Статус:** исследование, не решение. Ticket-ов не заводит. Обзор рынка с поиском в сети внутри самого worfy —
  второй Epic ([03](../../.scratch/worfy-product/issues/03-работы-и-форма-продуктового-режима.md)); этот документ —
  разовый обзор для первого.
- **Вопрос.** Кто уже даёт AI-советника по продукту, критика продуктовой стратегии или генератор идей для тех, кто
  строит продукт, и кто держит живую карту идей рядом с AI-чатом?
- **Ответ коротко.**
  - **По умолчанию не спорит никто.** Возражать пользователю обещают только отдельные роли и шаги, которые человек
    зовёт сам: Product Leader Sidekick в Miro, ProdPad CoPilot, «Analyze Requirements» в Kiro, «Idea assessment» в
    GitHub Spec Kit. Постоянной точки, где критик приходит без просьбы, нет ни у кого из просмотренных.
  - **Живой Mind map рядом с чатом нет.** Whimsical (приложение для ChatGPT, connector для Claude, MCP-сервер) и Mapify
    меняют карту из чата, но только по просьбе. Ни один не говорит, что карта сама растёт вместе с разговором.
  - **Код читают немногие.** Из PM-инструментов код читают только Productboard Spark и Linear. Остальные питаются
    отзывами клиентов: звонки, тикеты поддержки, CRM.
  - **Coding tools планируют, но не судят цель.** У Cursor, Claude Code, Devin, Factory, Kiro, GitHub Copilot и Codex
    есть режим плана: вопросы, Markdown-план, одобрение. Новых идей продукта они не предлагают — только планируют
    данную задачу.
  - **Против лести говорят модели, а не продукты.** OpenAI и Anthropic пишут об этом в Model Spec и Constitution.
    В продуктах это не отдельный режим: ни в ChatGPT, ни в Claude режима критика нет.
- **Как проверено.** Страницы вендоров (документация, help center, changelog, цены) прочитаны 2026-11-07 тремя
  research-агентами; ключевые цитаты о критике (Miro, ProdPad, Kiro, Spec Kit, Whimsical, Claude Code) и страница цен
  Cursor перечитаны отдельно. Чего не удалось открыть — раздел 8. Цены — на дату чтения, в USD.

## 1. Общие AI-помощники: ChatGPT Projects и Claude Projects

Владельцы продуктов часто ведут продуктовую работу в «проекте» общего чат-помощника. Это ближайшая замена Product
Session, поэтому они первые.

- **ChatGPT Projects.** Проект держит чаты, файлы и инструкции. Файлов на проект: Free 5, Go/Plus 25,
  Pro/Business/Enterprise/Edu 40. Есть «project-only memory» — память, которая не видит чатов вне проекта. Проектом
  можно поделиться в workspace. Источник: <https://help.openai.com/en/articles/10169521-projects-in-chatgpt>.
  - **Цена:** Plus $20 в месяц; Business $25 за место помесячно или $20 при оплате за год
    (<https://help.openai.com/en/articles/6950777-what-is-chatgpt-plus>,
    <https://openai.com/business/chatgpt-pricing/>). Страницы OpenAI отдали 403; факты взяты из текста результатов
    поиска по этим страницам — **не перечитаны напрямую**.
- **Claude Projects.** Проект держит базу знаний (документы, код, файлы), инструкции и историю чатов. На платных
  планах большие файлы ищутся через RAG (в проект грузятся только нужные куски), ёмкость «up to 10x». Team и
  Enterprise делятся проектами. Источник: <https://support.claude.com/en/articles/9517075-what-are-projects>.
  - **Цена:** Pro $20 в месяц ($17 при оплате за год), Max $100, Ultra $200, Team Standard $25/$20 за место
    (<https://claude.com/pricing>).
- **Спорит ли.** Режима критика нет ни у того, ни у другого. Человек просит критику словами или пишет её в
  инструкции проекта. Поведение против лести задаёт модель — раздел 5.
- **Код и трекер.** В проект можно положить код файлами. Связи с трекером задач проект сам не даёт.
- **Mind map.** Нет.

## 3. Mind map рядом с AI-чатом

- **Whimsical.** Приложение для ChatGPT «will generate a new board or edit an existing board based on your request»;
  пример запроса — «Add a mind map to summarize the key stages of bug reporting». Работает на всех планах ChatGPT,
  включая Free. Есть connector для Claude и MCP-сервер. Карта меняется только по запросу. Источник:
  <https://whimsical.com/learn/integrations/chatgpt>.
- **Mapify** (команда Xmind, раньше Chatmind). Строит Mind map из PDF, видео и текста; «Mapify Chat… helps you edit,
  expand, translate, and reorganize maps with simple prompts». Это самое близкое к карте, которую ведёт чат, но тоже
  по запросу. Источник: <https://mapify.so/chatmind>. Цены (Basic $5.99 за год / $9.99 помесячно, Pro $11.99/$19.99)
  взяты из текста результатов поиска — **не перечитаны**.
- **Miro.** «Generate mind map» из корневого узла или Create with AI → Mind Map, есть на Free. Карта лежит на доске;
  чата, который держит её в согласии с разговором, не найдено. Источники — раздел 2.
- **Taskade.** Вид Mind Map у проекта плюс AI-агенты; спора с пользователем не найдено. Цены (Pro $10 в месяц при
  оплате за год, Business $25) — из блога самого Taskade, это вторичный источник:
  <https://www.taskade.com/blog/best-mind-mapping-apps>.

Итог раздела: карта, которую агент сам меняет по ходу разговора, где узел — это Идея, Вопрос, Решение или
Возражение, а у принятого или отклонённого совета есть причина, — у просмотренных продуктов не найдена. Найдены
карты-сводки, которые чат строит или правит по команде.

## 5. Против лести: что пишут сами поставщики моделей

Sycophancy — когда помощник соглашается и хвалит вместо того, чтобы сказать, как есть.

- **OpenAI.** Обновление GPT-4o от 2025-04-25 откатили с 2025-04-28 как «overly flattering or agreeable»
  (<https://openai.com/index/sycophancy-in-gpt-4o/>, <https://openai.com/index/expanding-on-sycophancy/>; обе
  страницы отдали 403, факты из текста результатов поиска). Model Spec от 2026-10-29, раздел «Don't be sycophantic»
  (<https://model-spec.openai.com/2026-10-29.html>): модель «should not change its stance solely to agree with the
  user» и ведёт себя «more like a firm sounding board… rather than a sponge that doles out praise». Личности ChatGPT
  (например, «Cynical») меняют тон, но не дают режима критика:
  <https://help.openai.com/en/articles/11899719-customizing-your-chatgpt-personality>.
- **Anthropic.** Constitution (<https://www.anthropic.com/constitution>): «Claude should be diplomatically honest
  rather than dishonestly diplomatic», «engage critically with speculative ideas rather than giving empty validation»,
  «Claude can comply with a request while honestly expressing disagreement or concerns about it». Пост от 2025-12-18
  (<https://www.anthropic.com/news/protecting-well-being-of-users>): модели 4.5 на 70–85% меньше склонны к sycophancy,
  чем Opus 4.1; упомянут открытый инструмент аудита Petri. Anthropic сообщает о sycophancy 18%, когда пользователь
  возражает, против 9% без возражения: <https://www.anthropic.com/research/claude-personal-guidance>.
- **Вывод раздела.** Против лести работают на уровне модели: модель меньше поддакивает. Процедуры, которая
  заставляет найти возражения к плану, у самих чат-продуктов нет. Её строят сверху: роль (Miro), шаг (Kiro, Spec Kit)
  или отдельный агент — как решил Ticket 03 карты для worfy. Цифры 18% и 9% говорят, что давление пользователя
  удваивает поддакивание; это довод держать критика отдельным агентом, который не видит спора владельца с советником
  (**предположение**: опыт на Product Session не проверен).

## 7. Выводы для Product Session

1. **Постоянная точка критика — то, чего нет на рынке.** Все найденные критики приходят по запросу. Решение Ticket 08
   (критик перед каждой приёмкой spec нового Epic-а, без просьбы) — отличие worfy. **Взять:** список того, что Kiro
   ищет в требованиях (противоречия, неоднозначности, конфликтующие ограничения, пробелы) — как checklist брифа
   критика. **Взять:** у Spec Kit — вердикт с исходом «нужно уточнить»: у Keep, Reorder, Split, Defer такого исхода
   нет.
2. **Не притворяться, что знаешь пользователей.** Рынок строит советника на голосе клиента: звонки, тикеты поддержки,
   отзывы. У соло Product owner-а этих данных нет. Product Session должна опираться на то, что у неё действительно
   есть: код, Ticket-ы, ADR, research, слова владельца, — и прямо говорить, когда для суждения нужны данные о
   пользователях. Это совпадает с Ticket 02 карты.
3. **Живая Mind map — второе отличие, и его легко потерять.** Whimsical и Mapify показывают обратный пример: карта
   строится по команде и тут же устаревает. **Избегать:** карты-сводки в конце разговора. **Взять:** форму MCP-tool,
   как у Whimsical, — она уже выбрана (`mind_map_*` по образцу `worfy-canvas`, Ticket 07).
4. **План — файл в репозитории.** Cursor («Save to workspace»), Factory (`.factory/docs/`), Kiro (папка spec-а) и
   Spec Kit кладут план в репозиторий. Решение хранить работу Product Session в `docs/product/<тема>/` (Ticket 05)
   идёт с рынком; так spec, разбор критика и Mind map видны в git и в review.
5. **Мерка пользы — доля принятых советов.** Ни у одного просмотренного продукта такой публичной мерки не найдено.
   Отсутствие проверено только по страницам выше, не по всему рынку; это **предположение**. Если оно верно, это третье
   отличие worfy и его стоит показывать.
6. **Код и трекер в одном месте — редкость.** Из PM-инструментов только Productboard Spark и Linear читают код; coding
   tools читают код, но не судят о продукте. worfy держит код, Ticket-ы и Session в одном приложении, поэтому
   возражение критика может ссылаться на `file:line` и на Ticket, а не только на отзыв.

## 9. Открытые вопросы владельцу

1. **Исход «нужно уточнить».** Добавить к вердикту критика Keep, Reorder, Split, Defer пятый исход — «не хватает
   данных, вот вопрос» (по образцу needs-clarification в Spec Kit)? Или это всегда Defer с вопросом?

   ограничения, пробелы) как обязательный проход по spec до возражений о цели?
3. **Голос пользователей.** Если у Project-а есть GitHub issues или отзывы, должна ли Product Session читать их в
   первом Epic-е, или это часть второго Epic-а (обзор рынка с поиском в сети)?
4. **Выгрузка Mind map.** Нужен ли экспорт Mind map в Miro или Whimsical через их MCP, или карта живёт только в
   worfy и в `docs/product/`?
5. **Доля принятых советов наружу.** Показывать ли долю принятых советов в README и guide как довод «советник,
   который отчитывается о своей пользе», или держать её только внутри Project-а?
