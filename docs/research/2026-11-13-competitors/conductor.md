## Модель работы

- **Тип — hybrid.** Основа — локальное приложение для macOS. Рядом — Conductor Cloud (Linux sandbox в облаке),
  iOS-приложение, публичный HTTP API и hosted MCP server [1][96][97][131].
- **Локальное приложение:**
  - Распространяется как DMG [106]. Работает только на macOS. Для Windows и Linux «пока нет», есть лист
    ожидания [51].
  - Есть отдельные сборки для Intel и Apple Silicon [29]. На запуске была только сборка для Apple Silicon. Сборка
    для Intel вышла через пять дней [168].
  - Приложение предупреждает на macOS старше Tahoe (26) [30]. При этом исправления для macOS до 14.4 ещё
    выходят [26]. Минимальная версия macOS не подтверждена.
  - Стек: Tauri. Это приложение на системном движке Safari (WebKit). Backend формально на Rust, но почти весь код
    на TypeScript. Так говорит CEO в видео YC; текст прочитан через сторонний transcript [124]. На HN основатель
    тоже ответил, что приложение сделано на Tauri 2.0 [175].
  - Косвенно это подтверждают исправление для старых версий WebKit [47: 0.87.0] и отдельная alpha-сборка на
    Chromium [47: 0.62.0, 0.65.0]. В OpenAPI перечислены каналы сборок: prod, alpha, alpha-chromium, beta, patch, dev
    и funhouse [98].
  - Исследование функций оставило UI framework неподтверждённым. Два других направления нашли Tauri в интервью и на
    HN [124][175].
  - Web-приложение (сайт и кабинет) написано на Elixir и Phoenix, по словам CEO [124].
- **Conductor Cloud** (с версии 0.78.0 от 2026-07-30) [28]:
  - Каждый облачный workspace — отдельный Vercel Sandbox в регионе us-east-1 [104].
  - Документация называет его изолированной microVM [103]. Анимация на главной показывает загрузку Firecracker
    microVM [1].
  - Здесь заметки расходятся. Исследование устройства не нашло слова microVM в Cloud FAQ и в истории Vercel и
    оставило вопрос открытым [104][133]. Страница документации о Cloud Computer это слово содержит [103].
  - Ресурсы: Amazon Linux 2023, 8 vCPU, 16 GB RAM [103][104].
  - Диск: документация пишет о 32 GB временного NVMe [103][104]. Changelog 0.82 пишет, что диск удвоили до
    64 GB [27]. Источники расходятся.
  - Vercel выбрали за быстрый запуск и поддержку snapshots — так пишет сам Vercel в истории клиента (партнёрский
    источник) [133].
  - Облако работает только с репозиториями GitHub [104].
  - Self-hosted облака «пока нет». Его строили для Enterprise [104].
  - Бета облака прошла 2026-05-18…20 [25].
- **iOS-приложение:** только iPhone, нужна iOS 26 или новее, бесплатное, версия 1.1.3 [131]. Вышло вместе с версией
  0.90 (2026-10-02) [26][25].
- **Web:** app.conductor.build — аккаунт, оплата, API keys, настройки организации [96][26]. Полный web-клиент не
  подтверждён.
- **Агенты.** Conductor называет агента «harness». Это runtime, который пишет код. Сам Conductor — слой workspaces
  вокруг него [59].
  - Claude Code — встроен; можно взять версию, установленную в системе [59].
  - Codex — встроен; можно взять версию из системы [59].
  - OpenCode — встроен; можно указать свой исполняемый файл [59].
  - Cursor Agent — работает через Cursor API с `CURSOR_API_KEY`. Локального исполняемого файла нет [59]. Встроенный
    Cursor Agent SDK версионируется в changelog [47: 0.84.0, 0.85.0].
  - Встроенные исполняемые файлы лежат в `~/Library/Application Support/com.conductor.app/bin`. Их версии закреплены,
    и документация просит их не обновлять и не менять [66].
  - Claude Code работает через Claude Agent SDK [23]. С версии 0.48 Conductor запускает исполняемый файл Claude Code
    через Bun и больше не зависит от Node. Приложение стало меньше на 150 MB [31][47: 0.48.0].
  - Другие CLI-агенты работают только как preset-ы в Big Terminal Mode (терминал на всю главную панель): Claude,
    Codex, OpenCode, Amp, Pi, Copilot и Gemini [85]. В исправлении 0.86 упомянуты «Pi chats» [27], но harness-ом
    Pi не описан.
  - В OpenAPI список агентов содержит ещё недокументированное значение `acp` [98]. Что за ним стоит, не
    подтверждено.
  - Каждая вкладка чата — один harness и одна модель. Несколько вкладок в одном workspace работают на одной
    ветке [59].
- **Модели, которые сейчас принимает API** [98]:
  - Claude: Fable 5.2, 5.1 и 5; Opus 5.5 1M, 5 1M, 4.8, 4.7 и 4.6 1M; Sonnet 5.5 1M, 5 1M и 4.6; Haiku 5.5 и 4.5.
  - OpenAI: GPT-6.1 Sol и Terra; GPT-6 Astra, Sol и Luna; GPT-5.6 Sol, Terra и Luna; GPT-5.5 и 5.4; 5.3-Codex и его
    вариант Spark; 5.2-Codex; preview «Daybreak Blue».
  - Cursor: Composer 2.5, Auto, Grok 4.5, 4.6 и 4.7.
  - Уровни effort: none, low, medium, high, xhigh, max, ultra, ultracode.
  - Через OpenCode доступна модель любого провайдера: OpenRouter, Baseten, Cerebras, Vercel AI Gateway, OpenCode
    Zen/Go, ChatGPT, Copilot или локальные модели [59][61].
- **Вход и оплата моделей:**
  - Conductor берёт токены, уже сохранённые на машине (вход в Claude Pro или Max, `codex login`), или работает с
    API key [66][62].
  - «Sign in with ChatGPT» (с 2026-09-29) подключает план ChatGPT к Codex. Это сделано в партнёрстве с
    OpenAI [24].
  - Claude Code можно направить в Bedrock, Vertex, Foundry, OpenRouter, Vercel AI Gateway или GLM через переменные
    окружения [62][30].
  - Документация предупреждает: случайно оставленный в окружении `ANTHROPIC_API_KEY` переводит Claude на оплату по
    API [60].
  - Anthropic собиралась ограничить использование планов Claude через Agent SDK в сторонних инструментах.
    2026-06-15 ограничения отложили на неопределённый срок. Пользователи Conductor продолжают работать на своём
    плане Claude [23].

- **Как пользуются (по рассказам пользователей):**
  - Обычно — два-три активных workspace, по одному на баг или функцию. Один пользователь перестал заводить мелкие
    задачи в Linear и просто открывает workspace [222][223].
  - Интенсивно — 10–20 агентов одновременно. Каждый сообщает, когда готов к review. Автор говорит, что так можно
    работать только при глубоком знании кодовой базы [178]. Другой пишет, что Conductor занял больше 95% его
    работы [172].
  - Одна команда отменила все места в Cursor: в Conductor ей работалось намного продуктивнее [185].
  - Инженер, который переносил Postgres на Rust, вёл в Conductor несколько sessions Codex и переключал аккаунты
    Codex при rate limit [198]. Позже он перешёл на параллельные функции самого Claude Code и центрального агента,
    который запускает subagents [199].
  - Без присмотра: ночные pipelines из последовательных merge PR и deploy в одном workspace (issue #21) [105 #21].
    Набор gstack (настройка Garry Tan) работал внутри Conductor и автономно строил несколько вариантов
    продукта [183].

## Функции

Список собран по документации, changelog и OpenAPI. Номер в скобках после функции — версия, в которой она
появилась. Пометку «experimental» ставит сам вендор.

### Проекты и workspaces

- **Модель данных** [54][57]:
  - Project — один репозиторий.
  - В репозитории много workspaces.
  - Workspace — одна ветка и один git worktree. Путь по умолчанию — `~/conductor/workspaces/<repo>/<city>` [57].
    С версии 0.31.0 место можно менять [47: 0.31.0].
- **Изоляция workspace — для разработки, а не для безопасности.** Агенты работают с правами пользователя, без
  sandbox [54][66].
- **Добавить репозиторий.** Можно открыть локальную папку, открыть проект GitHub или создать новый репозиторий кнопкой
  «Quick start» с push в GitHub. Quick start умеет сразу подключить gstack — набор настроек агента от Garry
  Tan [52][32][39].
  - Если у проекта нет git remote, Conductor предлагает его создать (0.50) [31].
  - GitHub CLI встроен в приложение (0.25.12) [38].
- **Создать workspace:**
  - Окно создания по ⌘N называется «Dispatcher». Переключатель «create more» оставляет окно открытым, чтобы
    создать несколько workspaces подряд (0.63) [30].
  - Источник нового workspace — ветка, pull request, GitHub issue, Linear issue или просто prompt. Выбор — через
    «Create from» (⌘I) (0.66) [30].
  - Новая ветка отходит от свежего `origin/<base>` [54]. Перед этим Conductor делает `fetch origin` [54].
  - ⌥Enter создаёт workspace с подставленным, но не отправленным prompt. Так работает «добавить в backlog». Есть
    отдельная страница Backlog [29][83].
  - В окне создания работают slash commands и @-упоминания файлов [27][30].
  - Deep link `conductor://prompt=…&path=…&branch=…` открывает окно создания с заполненными полями [84].
  - В записи 0.10.0 упомянут более ранний экран «Dispatcher». Что это было, не подтверждено [47: 0.10.0].
- **Имена:**
  - Каждый workspace получает имя города. Городов больше 295, у некоторых есть уровень «legendary». Собранные
    города копятся в «Passport» — коллекции пользователя [87][37].
  - Ветка автоматически переименовывается по первому сообщению. Это можно выключить [26][54]. Агенту в первом
    чате прямо поручают переименовать сгенерированную ветку [54].
  - Облачные workspaces нумеруются: W-123 [26].
  - Workspace можно переименовать [31].
- **Жизненный цикл:**
  - Pin — закрепить вверху списка [39].
  - Fork — новый workspace с текущими изменениями и summary чата (0.25.6) [38].
  - «Continue on new branch» — продолжить работу на новой ветке после merge [35].
  - Сменить целевую ветку PR [36].
  - Archive срабатывает мгновенно. Незакоммиченные изменения сохраняются коммитом [31][32]. Есть необязательный
    archive script, удаление ветки при архивировании и автоматический archive после merge [68][71].
  - Восстановить из панели History [53]. Archive и restore сохраняют историю чата [53].
  - Принудительно архивировать workspace, где ещё работает чат [30].
- **Monorepo.** Можно выбрать видимые «working directories». Остальные папки скрываются через git sparse
  checkout [90].
- **Несколько репозиториев.** Команда `/add-dir` подключает к агенту другие workspaces или любую папку (0.25.6,
  0.44) [38][32][91].
- **Gitignored-файлы.** «Files to copy» и файл `.worktreeinclude` копируют в новый локальный workspace файлы, которые
  git игнорирует, например `.env*` [73]. Если есть `.worktreeinclude`, он важнее настроек [57][74].
- **Папка `.context`.** Своя в каждом workspace, в git не попадает. Хранит вложения, планы и заметки, общие для
  агентов этого workspace [37][54].

### Как сделать workspace запускаемым

- **Scripts:** setup script, archive script и «actions» — именованные команды запуска. Раньше actions назывались
  run scripts [68].
  - У actions есть иконки, значения по умолчанию, доступность локально или в облаке и скрытие для отдельного
    пользователя [68].
  - Режимы запуска: `concurrent` и `nonconcurrent`. Во втором режиме запуск action сначала останавливает другие
    actions [68].
  - Action можно запускать автоматически после setup [30].
  - Setup можно перезапустить из панели [35]. Если setup упал, кнопка «Ask AI to fix» поручает исправление
    агенту [32].
  - Scripts получают переменные `CONDUCTOR_WORKSPACE_PATH`, `CONDUCTOR_ROOT_PATH`, `CONDUCTOR_WORKSPACE_NAME` и
    `CONDUCTOR_PORT` [68]. Полный список переменных — на отдельной странице документации [75].
- **Порты.** Каждый локальный workspace получает 10 портов: от `CONDUCTOR_PORT` до `CONDUCTOR_PORT+9` [68].
  - Именованные Preview URLs наполняют кнопку «Open» [71].
  - Адреса localhost в выводе распознаются автоматически [44].
- **Spotlight testing.** Переносит отслеживаемые git изменения одного workspace в корневой checkout репозитория.
  Так один тяжёлый стек (фиксированный порт, Docker, одна база данных) перезагружается с этими изменениями, и не
  нужно поднимать стек в каждом workspace. Работает для одного workspace за раз и только в одну сторону [69].
- **Shell.** Conductor считывает окружение login shell с timeout 5 секунд. Поддерживает direnv, mise, asdf и
  rbenv. Команды выполняет в zsh, запасной вариант — fish [76][32][33][31].

### Chat и управление агентом

- **Вкладки.** Несколько вкладок чата в одном workspace (0.17). Experimental режим «Tab Freak Mode» разрешает до
  10 вкладок [41][30][47: 0.57.0].
  - Чат можно сделать fork в новую вкладку или в новый workspace, даже посреди хода агента [30][28].
  - Вкладки переименовываются. Закрытую вкладку можно открыть снова [34][83].
- **Composer (поле ввода):**
  - @-упоминания файлов, папок и комментариев; `#` — PR; `@todos`; `@terminal`; `@add directory` [31][52][81].
  - Вложения, вставка файлов, голосовая диктовка (experimental), snippets [46][26][83].
- **Сообщения во время работы агента: steer или queue.**
  - «Steering» (0.50) вставляет новое сообщение в текущий ход агента. ⌘⏎ переключает между очередью и
    steering [31].
  - Очередь можно переставлять и править с клавиатуры [30][31].
  - Версия 0.86 убрала очередь сообщений: всё, что отправлено во время работы агента, теперь его
    направляет [27][47: 0.86.0]. Более поздние записи changelog всё ещё упоминают сообщения в очереди [26], а API
    по-прежнему описывает отправку «или постановку в очередь» [96]. Источники расходятся.
- **Режимы и effort:**
  - Plan Mode: агент сначала строит план, задаёт вопросы по ходу, пользователь одобряет план с замечаниями или
    передаёт его в другой чат [58][37][38][36].
  - Fast Mode [58].
  - Уровни effort вплоть до «Ultracode». Ultracode — это x-high effort плюс динамическая orchestration workflow
    Claude Code (0.61) [30][47: 0.61.0].
  - «Loadouts» — до 5 любимых моделей с переключением по ⌃⌘1–5. Набором можно поделиться (0.85, 0.86) [27].
  - Поиск по моделям [26].
- **Что умеет каждый harness** [58]:

  | Возможность | Claude Code | Codex | Cursor | OpenCode |
  |---|---|---|---|---|
  | Plan Mode | да | да | нет | нет |
  | Fast Mode | да | да | нет | нет |
  | Thinking / reasoning level | зависит от модели | зависит от модели | нет | нет |
  | Personalities | нет | да | нет | нет |
  | Goals | нет | только локальные workspaces | нет | нет |
  | Checkpoints | да | да | нет | нет |
  | Skills | да | да | нет | да |

- **Только для Codex:**
  - Personalities [32].
  - Goals — постоянная цель на много ходов с бюджетом токенов. Задаётся командой `/goal`, работает только локально.
    Цель можно поставить на паузу и продолжить [58][47: 0.65.0].
  - Статус goals противоречив. Версия 0.86 пишет, что goals убрали [27]. Документация их ещё описывает [58]. Версия
    0.90 записывает события паузы и продолжения goal [47: 0.90.0]. Текущий статус не подтверждён.
- **Checkpoints.** Откат кода и чата к любому ходу для Claude и Codex [80]. «Reset chat» с флажком «Also reset
  files» [27]. Как это устроено — в разделе об устройстве.
- **Управление контекстом:**
  - Мгновенные summaries чата.
  - Summary прежних чатов можно приложить к новому чату.
  - Смена агента посреди чата открывает новую вкладку с summary.
  - Родная команда `/compact`. Порог автоматического compact настраивается (0.1.0, 0.2.0). Кнопка «Compact and
    Retry», когда контекст кончился (0.9.1) [47: 0.1.0, 0.2.0, 0.9.1].
  - Оглавление и outline чата.
  - Поиск по чату.
  - Источники: [33][40][36][31][35][26].
- **Отображение ответов:**
  - Вызовы инструментов сворачиваются по алгоритму «важности». Режим «Garry mode» (⌃O) раскрывает их все [29].
  - Subagents и фоновые задачи показаны с таймерами [28].
  - Агенты вставляют screenshots прямо в ответы [27].
  - У bash-фрагментов в ответах есть кнопка Run [26].
  - Поддерживаются диаграммы Mermaid, формулы LaTeX и видеоплеер [34][37][38][27].
  - Prompts subagents и вызовы инструментов видны в transcript [47: 0.23.0]. Вызовы MCP сгруппированы, ошибка
    видна прямо в строке [47: 0.85.0].
  - Сообщения между агентами Claude Code agent teams помечены как «Send message» [47: 0.93.0].
- **Файлы инструкций.** Агенты используют `AGENTS.md` и `CLAUDE.md`, slash commands из `.claude/commands`, skills,
  plugins Claude Code, hooks и memory [63][82][39][44].
- **Встроенные system prompts.** Conductor добавляет агенту свои system prompts: что он работает внутри Conductor,
  что такое workspace и тому подобное. Есть и prompts для отдельных действий — например, при создании workspace или
  «Create PR». Пользователь может их менять [66].
- **Встроенные skills.** Skill «Conductor» (0.56) учит агента настраивать сам Conductor. Skill `/prototype` (0.78)
  тоже встроен [30][28][95]. Официальный skill `conductor` опубликован в индексе `/.well-known/skills/index.json`, и
  стартовый репозиторий команды его включает [108].
- **Sync Agent Configs** (0.57) копирует skills, slash commands и MCP servers между Claude Code и Codex [30]. С этой
  версии агенты «знают» о Conductor [47: 0.57.0].
- **MCP.** Conductor берёт конфигурацию MCP каждого harness. Показывает popover и окно со статусом MCP servers и
  повторной авторизацией. Есть список рекомендуемых servers: Composio, Cloudflare, Linear и другие [88][89][27].
- **Собственные инструменты агента.** Это MCP servers внутри процесса, сделанные через `createSdkMcpServer` из
  Agent SDK [18][19]:
  - вопрос пользователю с вариантами ответа [18];
  - чтение diff workspace и комментарии к строкам diff [19];
  - `GetTerminalOutput` — чтение терминала (0.30.0) [47: 0.30.0];
  - `RunLocalCommand` — облачный агент выполняет команду на Mac пользователя (0.83.0) [47: 0.83.0].
  - Как эти инструменты попадают в Codex, Cursor и OpenCode, не подтверждено.
- **Claude Code agent teams** (experimental) включаются переменной `CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1` [66].
- **Manual Mode™** (2026-03-03) — простой редактор файлов, в котором пользователь правит код сам [25]. С
  2026-09-02 файлы по умолчанию правятся прямо в diff [25].

### Разрешения и approvals

- По умолчанию агенты работают с полными правами пользователя [66]. Approvals инструментов включаются отдельно:
  - сначала — как настройка Enterprise (0.41) [32][47: 0.41.0];
  - потом — как переключатель пользователя в Settings → Account, с возможностью обязать всю организацию
    (0.45) [32][47: 0.45.0];
  - настройка пользователя `tool_approvals_enabled` [71].
- Для MCP-инструментов, web search и web fetch: approve, deny или «permanently allow» (0.44) [32].
- Уведомление macOS, когда агент просит разрешение [32].
- **Автоматические approvals:**
  - для Codex — `tool_approval_policy = always_approve` [71][27];
  - experimental «Auto permission mode» сам одобряет безопасные действия и спрашивает человека только о рискованных
    (0.70) [29][47: 0.70.0].
- Облачные агенты могут выполнять команды на Mac пользователя («RunLocalCommand»), если он это разрешил [64][27][26].
- Big Terminal Mode при выключенных approvals запускает агентов в режимах без проверок: `claude
  --dangerously-skip-permissions`, `codex … --ask-for-approval never --sandbox danger-full-access`, `copilot
  --allow-all`, `gemini -y` [85].

### Review, Git, PR и CI

- **Diff Viewer (⌘⇧D)** [79]:
  - Движок отображения diff под названием Pierre. Режимы split и unified, фильтр по коммитам, diff каждого хода
    агента, пометка «просмотрено», скрытие пробелов, группировка по папкам.
  - Правка файлов прямо в diff (0.84).
  - Inline и многострочные комментарии уходят агенту как вложения [53]. Комментарии review из GitHub подтягиваются в
    diff, их можно закрыть отсюда.
  - Источники: [79][34][40][36][31][27][33][32].
- **AI review.** Действие «Review» отправляет агенту prompt из настройки «Code review preferences». Модель review и
  уровень thinking выбираются. Prompt review задаётся для каждого репозитория. Правым кликом можно сменить
  агента-reviewer или добавить указания [63][40][33][47: 0.22.0, 0.22.6].
  - Родная команда Codex `/review` [28].
  - Claude оставляет комментарии к diff через свой инструмент (0.29) [36][19].
  - С 0.2.0 можно завести свои subagents Claude Code для code review и тестов [47: 0.2.0].
- **Checks tab** — вкладка проверок [78][36]:
  - Показывает git status, данные PR, CI checks (logs, re-run, «fix»), deployments (Vercel и GitHub), комментарии и
    todos.
  - Упавшие checks можно отправить агенту (0.12) [43]. Вкладка построена на `gh` CLI. Одно из действий —
    отправить агенту logs упавшего CI [20].
  - Упавшие GitHub Actions можно перезапустить [47: 0.34.2].
- **Todos** блокируют merge, пока их не отметят [81]. Todos добавляют и пользователь, и агент [81]. Todos
  пользователя синхронизируются в локальный файл, который агенты читают [20].
- **Страница PR (0.73):**
  - Правка заголовка и описания, approve в один клик, merge.
  - Automerge после зелёного CI (0.55). Настройка «Treat optional checks as blocking» — считать необязательные
    checks обязательными (0.90). Статус merge queue. Для stacked PR automerge скрыт
    (0.82) [47: 0.55.0, 0.90.0, 0.82.0].
  - Merge сливает только тот код, который есть в workspace.
  - Источники: [29][26][27][31].
- **Stacks.** GitHub stacks (0.80) и Graphite [28][35].
- **Кнопка следующего шага.** Предлагает следующее действие: создать PR, исправить ошибки, разрешить конфликты,
  сделать commit и push, подтянуть свежие изменения [45][83].
- **Комментарии review-ботов** Greptile и Cursor Bugbot показываются на странице PR [26][29].
- Отдельные страницы документации описывают review и merge [77] и путь от issue до PR [92].

### Файлы, редактор, previews, терминал, браузер

- **Файлы.** Дерево файлов, быстрое открытие по ⌘P, поиск по файлам ⌘⇧F (0.87), редактор CodeMirror [40][27][33].
- **Previews.** Markdown (с frontmatter), HTML, PDF, CSV в виде таблицы, JSON и JSONL, изображения с масштабом,
  видеоплеер с покадровым шагом [29][31][27][26].
- **Терминал:**
  - Терминал переписан; sessions восстанавливаются [32][31].
  - ⌘L отправляет выделенный текст терминала в чат [45]. Claude умеет читать терминал [36].
  - Big Terminal Mode выводит терминал на всю главную панель [85]. Его sessions восстанавливаются после
    перезапуска [85].
- **Браузер:**
  - Experimental встроенный браузер для preview. Функция «Agentation» позволяет кликнуть по элементу страницы и
    оставить заметку; заметка прикрепляется к чату (0.62) [30].
  - Claude Code умеет пользоваться Chrome (0.30) [36].
- **Open In.** Открыть workspace в Cursor, VS Code, Zed, IDE JetBrains, Xcode, Sublime, Warp, Alacritty и
  других [93][42][38].
- **Вкладка Artifacts.** Анонсирована в X 2026-10-05 [117]. Changelog описывает её как вкладку в панели Git с
  плитками previews (logs, Markdown); её можно скрыть в Settings → General; одно исправление убрало из неё файлы
  сборки Xcode [26]. Точный состав вкладки в документации не описан (не подтверждено) [26]. Под постом о ней
  основатель утверждал, что агенты уже достаточно хороши, чтобы человек смотрел панель с итогом, а не diff.
  Пользователи возражали [117].
- **Dashboard.** Кнопка в sidebar открывает dashboard (с первых версий) [46]. Он есть и в облачных
  организациях [26]. Что на нём показано, не подтверждено [46][26].

### Автоматизация: API, Routines, MCP server, CLI, deep links

- **HTTP API (beta)** по адресу `api.conductor.build/v0` [96][98]:
  - Projects, workspaces и sessions: создать, отправить сообщение, узнать статус, отменить.
  - Вложения до 100 MB, не больше 10 на сообщение. Вложения из API попадают в `.context/attachments/` [96].
  - SQL только на чтение по представлению `session_transcripts_view`. Ответ — не больше 500 строк, timeout
    5 секунд [98].
  - Sections, общий доступ к preview, любимые модели.
  - Готовые prompts в документации превращают любого агента в «менеджера Conductor». Такой агент планирует, создаёт
    workspaces, отправляет задания, опрашивает статус, корректирует и раскладывает задачу на несколько параллельных
    PR [96].
  - Workspaces, созданные через API, делают коммиты от имени вызывающего [96].
- **Routines** — сохранённый prompt, который запускается в новом облачном workspace [27][96]:
  - Расписание: каждый час, каждый день, по будням или раз в неделю.
  - События GitHub с фильтром по label, автору или базовой ветке.
  - Webhooks.
  - У запусков routines есть панель Runs [26].
  - Команда Conductor использует routines для внутренних отчётов, ежедневного stand-up и исправления мелких проблем в
    своих system prompts [25].
- **Hosted MCP server** по адресу `api.conductor.build/mcp`. Вход через OAuth или API key, 20 инструментов [97].
  Через него агенты создают workspaces и управляют ими (2026-08-20) [25].
- **CLI `conductor`:** routines, сообщения, модели [96][28]. Команду `conductor sql` убрали в 0.92
  (2026-10-23) [25]. С 2026-10-02 локальные агенты больше не пытаются создавать workspaces и управлять ими через
  CLI [25].
- **Deep links `conductor://`**, в том числе для Linear issues и «async plans» — планов, закодированных в
  base64 [84].
- **Slack** подключается через MCP Slack в облачных workspaces [11].

## Принципы и подходы

### Философия основателей

- **Доклад «Orchestras, Not Factories»** на конференции AI Engineer. Видео опубликовано 2026-09-27 [128]. Другой
  transcript датирует доклад на World's Fair 2026-06-30 [126]. Точное место и дата не подтверждены.
  - Holtz прямо говорит, что не любит выражение «software factory» — «фабрика софта» [128].
  - Его позиция: человек остаётся в центре. Он руководит командами из людей и агентов, а не запускает конвейер.
    Его сравнение: дирижёр управляет всем оркестром и при необходимости занимается одной группой
    инструментов [128][124].
- **Пять других принципов из того же доклада** [128]:
  - Держаться у переднего края. Кто ждёт, пока практики станут общими, отстаёт на три–шесть месяцев.
  - Не пытаться обыграть рынок. Если workflow подходит всем, крупные лаборатории встроят его в свой harness по
    умолчанию. Свои доработки имеют смысл только там, где у команды есть особое знание о своих пользователях или
    кодовой базе. Holtz называет такое знание «real alpha».
  - «Slop-free zones» — зоны без небрежного AI-кода. Migrations, документацию и skill-файлы всегда внимательно
    проверяет человек. CI самого Conductor требует review человека при каждом изменении файла migrations.
  - «Feed the beast» — снабжать агентов данными. Внутренний агент команды, «CIA», складывает сообщения Slack,
    отчёты об ошибках из Discord и записи встреч в базу Postgres. Агенты обращаются к ней через SQL-инструмент.
  - «Free-range agents» — агенты без привязки к ноутбуку. Они работают в облачных sandbox, продолжают работу после
    закрытия ноутбука и сами запускают других агентов.
- **«Code is sawdust».** В подкасте Mastra (2026-09-08) Holtz сравнил код с опилками, которые остаются от разговора
  с агентом. Смысл: долговечная ценность — prompts и дизайн, а код можно сгенерировать заново, когда модели станут
  лучше. Conductor постепенно уменьшал роль чтения кода [127].
- **Видео YC (2026-06-04).** Главы видео: код становится побочным продуктом; не делать AI архитектором; зоны без
  небрежного кода; закрепление workflow и выработка уверенности; почему терминала мало [124]. По стороннему
  transcript, Holtz говорит [124]:
  - Основные абстракции должен проектировать человек. Пример — сам workspace, абстракция вокруг worktree.
  - GUI лучше CLI, потому что люди воспринимают мир зрительно и пространственно.
  - Решения он принимает по ощущению, а не по аналитике.
- **Миссия:**
  - Пост о найме (2025-10-08): люди перейдут от написания кода к руководству командами AI, и для этого нужны
    совсем новые интерфейсы. Встроенный текст поста обрезан; полную версию дал сниппет поиска [114].
  - Профиль Jackson de Campos в YC: команда строит интерфейс человека к организациям из AI [130].
  - Пост о Series A: большую часть софта скоро будут писать команды AI, и для управления ими нужны новые
    интерфейсы. Conductor должен стать платформой для управления огромными организациями из AI — от телефона до
    VPC клиента [21].

### Модель работы в документации

- **Главный тезис.** Документация пишет: «The workspace is the unit of delegation.» Ветка и pull request —
  единица интеграции. Workspace лучше всего работает, когда в нём идёт один поток работы [53].
- **Иерархия** [54]:
  - Project хранит один репозиторий.
  - В репозитории много workspaces.
  - Workspace соответствует одной ветке.
  - У ветки один рабочий каталог, созданный через `git worktree`.
  - В workspace может работать много процессов — его «running environment».
- **Изоляция и безопасность:**
  - Изоляция workspace — это изоляция для разработки, а не граница безопасности [54][57].
  - Агенты работают с правами пользователя и без sandbox [66].
  - Совет FAQ для осторожных — запускать Conductor на отдельной машине или в VM [66].
- **Как делить работу** [55]:
  - Независимая работа — в разных workspaces.
  - Работа на общей ветке — несколько агентов в одном workspace. Примеры: один пишет код, другой делает review;
    починка тестов; сравнение подходов.
  - Документация признаёт, что агенты в одном workspace могут править одни и те же файлы [55]. Есть таблица для
    выбора между отдельными workspaces и общим [55].
  - Совет из документации: заводить workspace на каждую единицу работы, которую можно выпустить отдельно [53].
- **Постоянные и временные указания.** Режимы агента — временная настройка. Постоянные указания живут в настройках
  репозитория или в файлах инструкций в git: `AGENTS.md`, `CLAUDE.md`, skills [58].
- **Conductor формирует поведение агентов** [66][95]:
  - Добавляет свои system prompts. Их можно менять для каждого репозитория [66].
  - Встраивает закреплённые версии Claude Code и Codex [66].
  - Поставляет встроенный skill Conductor, чтобы агенты могли настраивать сам Conductor [95].

### Как работает сама команда Conductor

- Conductor вырос из внутреннего инструмента. Команда делала чат-приложение Chorus, клонировала репозиторий пять
  раз, а потом открыла для себя git worktrees [128].
- Предыдущие продукты: Melty — open-source редактор, где каждое сообщение чата становится коммитом git; Chorus —
  open-source AI-чат для Mac [107].
- «Prompt Requests» (февраль 2026): пользователи присылают prompt вместо кода. Если prompt понравится, команда
  запустит его и сольёт результат [25].
- CEO рассказывает, что всегда запускает Claude с автоматическим согласием на все разрешения [124].
- Команда обычно координирует несколько агентов на одной задаче через subagents [16].
- Routines команда использует для внутренних отчётов, ежедневного stand-up и исправления мелких проблем в своих
  system prompts [25].
- По словам CEO, все агенты команды имеют доступ к Conductor API и могут сами запускать новых агентов через
  API [127][126].
- Checkpoints команда сделала так: написала спецификацию, и GPT-5 почти целиком реализовал её с первой
  попытки [16].
- Сторонний transcript видео YC приписывает Holtz расход токенов около $22 000 в месяц (не подтверждено) [124].

### Ключевые понятия

- **Workspace** — единица работы: ветка, git worktree, процессы, чаты, diff и PR [54].
- **Project** — один репозиторий со всеми его workspaces [54].
- **Harness** — runtime агента, который пишет код: Claude Code, Codex, Cursor или OpenCode [58][59].
- **Dispatcher** — окно создания workspace по ⌘N [30].
- **Города и Passport** — каждый workspace назван по городу; собранные города копятся в «Passport», у некоторых
  есть уровень «legendary» [25][87].
- **`.context`** — папка в каждом workspace, которую git игнорирует. Хранит вложения, планы и заметки [57][25].
- **Files to copy** — шаблоны gitignored-файлов, которые копируются в новый worktree, в стиле
  `.worktreeinclude` [57].
- **Setup script и actions** — подготовка workspace и именованные команды запуска. Actions до октября 2026 года
  назывались run scripts. `$CONDUCTOR_PORT` даёт каждому workspace свой порт [56][25].
- **`.conductor/settings.toml`** — файл настроек репозитория. Заменил `conductor.json` [95].
- **Spotlight testing** — перенос изменений workspace в корень репозитория, чтобы один server обслуживал все
  workspaces [56].
- **Режимы агента и редактора:** Big Terminal Mode, Manual Mode™ (редактор файлов; вендор шутливо называет его
  работой «по-пещерному»), Checkpoints, Plan Mode, Fast Mode, effort Ultracode, Codex Goals, Steering [25][58].
- **Организация работы:** Dispatcher, Loadouts (наборы любимых моделей), Sections (разделы sidebar), Routines
  (запуски по расписанию и событиям) [25].
- **Облако и команда:** Home (общий экран организации), Follow, «Reassign to», Organization, Cloud Computer
  (общая облачная машина организации), Multiplayer [99][102].
- **Агенты как пользователи:** Conductor API, MCP server и CLI [96][25].
- **Прочее:** Remote control [86], «Prompt Requests» [25], Wrapped [25].
- **Roundhouse** — внутреннее имя публичного API в OpenAPI спецификации [98].

### Чем подход отличается

- **Workspace в центре, а планирование — у человека.** Встроенного планировщика и графа задач нет. Разбивает
  работу человек или Plan Mode [53][58].
- **Свой цикл агента не нужен.** Conductor оборачивает родных агентов вендоров и не перепродаёт модели. Пользователь
  приходит со своими подписками [59][1][66].
- **GUI вместо терминала.** Чат и боковая панель, организованная вокруг PR и worktree, а не вокруг чатов [186][124].
- **Ставка на облако для работы без человека** — «free-range agents» [128].
- **Агенты — тоже пользователи.** API, MCP server и CLI позволяют агентам создавать workspaces и решать, когда
  работа готова [25][127].
- **Безопасность — забота пользователя.** По умолчанию полные права и нет sandbox. Approvals — по желанию [54][66].
- **Общий контекст — в простых файлах.** Для `.context` команда сознательно выбрала файлы, а не базу данных и не
  специальные инструменты [17].

### Разбиение задач и планирование

- **Встроенного планировщика и графа задач нет.** Делить работу — практика человека: workspace — единица
  делегирования, ветка и PR — единица интеграции [53]. Документация советует заводить workspace на каждую единицу,
  которую можно выпустить отдельно [53]. Есть таблица выбора между отдельными workspaces и общим [55].
- **Планирование на уровне агента:**
  - Plan Mode: агент сначала строит план; пользователь одобряет его или даёт замечания [58]. Одобрение с
    замечаниями — с 0.25.5 [47: 0.25.5].
  - План можно отправить в новый чат или передать другому [47: 0.22.7, 0.30.0].
  - Планы Claude Code сами сохраняются в `.context`, и другой harness может их реализовать [17].
  - Ранний «Auto mode», где Opus планирует, а Sonnet пишет код, был в 0.8.0 [47: 0.8.0].
- **Todos.** Их добавляют и пользователь, и агенты. Workspace заблокирован, пока todos не отмечены [81]. Todos
  пользователя синхронизируются в локальный файл, который читают агенты [20].
- **LLM в роли orchestrator — через API.** Документация даёт два готовых prompt [96]:
  - **Планировщик и reviewer.** Пишет самодостаточное задание (brief), создаёт workspace, опрашивает статус session
    примерно каждые 15 секунд, читает новые сообщения transcript через параметр `after=`, корректирует агента, затем
    проверяет результат по заданию.
  - **Fan-out.** Задачу, слишком большую для одного PR (иногда на несколько репозиториев), делит на части, создаёт
    workspace на каждую часть, запускает все части до начала ожидания, следит за ними и возвращает таблицу PR.
  - Облачные workspaces получают `CONDUCTOR_API_URL` и `CONDUCTOR_API_TOKEN` с правами на этот workspace. Значит,
    агент может сам делать эти вызовы [96].
  - CEO говорит, что команда даёт агентам API для запуска новых агентов и что у всех их агентов есть доступ к
    Conductor API [126][127].
- **Routines (только облако).** Запуск по расписанию (каждый час, каждый день, раз в неделю, по будням) или по
  событиям GitHub с фильтром по label, автору или базовой ветке [47: 0.85.0, 0.87.0]. Ещё — по webhook через
  API [96].

### Параллельность и координация

- **Два уровня** [55]:
  - Отдельные workspaces для независимой работы. У каждого своя ветка, worktree, процессы и PR.
  - Несколько чатов в одном workspace, когда нужна одна ветка. Документация признаёт, что такие агенты могут править
    одни и те же файлы.
- **Координация между workspaces.** Блокировок, merge queue и поиска конфликтов между workspaces в документации нет.
  Что их действительно нет, не подтверждено. Конфликты решаются при PR действием с prompt «Resolve
  conflicts» [63][53]. Команда обычно координирует агентов одной задачи через subagents [16].
- **Общие ресурсы:**
  - Каждый workspace получает 10 портов, от `CONDUCTOR_PORT` до `CONDUCTOR_PORT+9` [68].
  - `run_mode = "nonconcurrent"` останавливает другие actions перед запуском этой [68].
  - Spotlight подменяет корневой checkout изменениями одного workspace [69].
- **Другие механизмы:**
  - Работа с несколькими репозиториями: `/add-dir` открывает агенту другие workspaces [91][47: 0.25.6].
  - Fork: новый workspace получает изменения и summary чата [47: 0.25.6].
  - Multiplayer в облаке: workspaces, чаты и присутствие общие для организации; люди могут писать в чат коллеги;
    работу передают через «Reassign to» [99].
- **Что ограничивает параллельность:** аккаунт провайдера модели, ресурсы машины и approvals [94].

### Изоляция

- **Локальные workspaces:**
  - Один git worktree на workspace, обычно `~/conductor/workspaces/<repo>/<workspace>` [57]. Место настраивается с
    0.31.0 [47: 0.31.0].
  - Новая ветка отходит от настроенной базовой ветки после `fetch origin` [54].
  - Workspaces названы по городам [66].
  - Это не sandbox. Изоляция workspace — для разработки, а не граница безопасности [57]. Агенты работают прямо в
    системе без sandbox [66].
- **Подготовка workspace:**
  - «Files to copy» и `.worktreeinclude` копируют только gitignored-файлы. `.worktreeinclude` важнее
    настроек [57][74].
  - Setup script запускается после checkout. Archive script — перед архивированием [68].
  - Scripts получают `CONDUCTOR_WORKSPACE_PATH`, `CONDUCTOR_ROOT_PATH`, `CONDUCTOR_WORKSPACE_NAME` и
    `CONDUCTOR_PORT` [68].
- **Остановка процессов.** Stop отправляет SIGTERM группе процессов action, через фиксированные 5 секунд — SIGKILL.
  Дерево процессов не обходится, поэтому потомки в других группах процессов могут выжить [68].
- **Monorepo.** Невыбранные папки скрываются через git sparse checkout [90].
- **Spotlight testing.** Следит за workspace, делает checkpoint-коммит и делает его checkout в корне репозитория.
  Синхронизирует только отслеживаемые файлы и только в одну сторону. При выключении корень восстанавливается [69].
- **Облачные workspaces:**
  - Workspace — Vercel Sandbox, созданный из активной сборки «Cloud Computer» организации. Сборка содержит
    репозитории, переменные окружения, secrets и установленные программы [99][103].
  - Уже созданные workspaces остаются на своей сборке [99].
  - Шаги жизненного цикла: `building_snapshot`, `preparing`, `setting_up` [98].
  - Sandbox засыпает после 20 минут без активности и жёстко останавливается через 23 ч 50 мин, даже если активен.
    Процессы не переживают ни то ни другое [101].
  - Доступ: односторонняя синхронизация из облака на Mac, SSH, проброс портов. `CONDUCTOR_PORT` в облаке нет [101].
  - С 0.87.0 setup scripts из общих облачных workspaces не запускаются сами на Mac коллег [47: 0.87.0].

### Состояние, checkpoints и память

- **Состояние workspace:**
  - Workspace — единица состояния: чаты, diff, состояние PR и архивные действия привязаны к нему [57].
  - Archive и restore включают историю чатов [53].
  - Sessions терминала Big Terminal Mode восстанавливаются после перезапуска [85].
  - Входы и выходы облачных sessions хранятся на серверах Conductor в зашифрованном виде [65][104].
  - Путь выхода из облака на случай закрытия — «Transfer to local» и «Export data» [47: 0.93.0].
- **Checkpoints — поведение:**
  - Появились в 0.19.0 (2025-11-05) [47: 0.19.0]. Для Codex — в 0.44.0 [47: 0.44.0].
  - Перед каждым ответом поддерживаемого агента состояние рабочей ветки сохраняется в отдельной git ref, вне
    истории ветки [80].
  - Откат навсегда удаляет более поздние сообщения и возвращает код. После этого агент ничего не знает об удалённой
    части [80].
- **Checkpoints — механизм** [16][109]:
  - Hooks срабатывают в начале и в конце каждого хода.
  - Сохраняются три состояния:
    - HEAD;
    - index — через `git write-tree`;
    - весь рабочий каталог вместе с неотслеживаемыми файлами — через временный `GIT_INDEX_FILE`, `git add -A` и
      `write-tree`.
  - `git commit-tree` пишет коммит, метаданные — в сообщении коммита.
  - `git update-ref refs/conductor-checkpoints/<id>` направляет ref на этот коммит.
  - Восстановление по шагам:
    1. `git reset --hard <head>`;
    2. `git read-tree --reset -u <worktree-tree>`;
    3. `git clean -fd` — ignored-файлы остаются;
    4. `git read-tree --reset <index-tree>`.
  - Есть команда `diff <id1> <id2|current>`.
- **Checkpoints — отвергнутые варианты** [16]:
  - Снимки файлов перед каждой правкой пропускают изменения от linters, менеджеров пакетов и генераторов кода.
  - `git stash` не видит неотслеживаемые файлы.
  - `git stash -u` с последующим apply трогает файлы на диске на каждом ходе.
  - Хранение в своей базе SQLite потребовало бы заново написать `git diff`.
- **Checkpoints — ограничения и история:**
  - Когда в одном workspace работают несколько чатов, checkpoints смешиваются [80][16].
  - Ранняя схема, вероятно, делала настоящие коммиты. В PR одного репозитория команды от 2025-10-21 есть коммиты
    «conductor-checkpoint-start» и «Changes auto-committed by Conductor» [106]. Это вывод.
- **Идемпотентность API** [98]:
  - Создание workspace не идемпотентно.
  - Повторная отправка сообщения с тем же `messageId` отбрасывается как дубликат.
  - Отмена идемпотентна и асинхронна: нужно опрашивать статус, пока session не станет idle.
- **Памяти уровня Conductor нет.** Постоянные указания живут в `AGENTS.md`, `CLAUDE.md`, `.claude/commands`, skills
  и настройках репозитория [58][63]. Sync Agent Configs копирует skills, slash commands и MCP servers между Claude
  Code и Codex [47: 0.57.0]. Официальный skill `conductor` опубликован в `/.well-known/skills/index.json`, его
  включает стартовый репозиторий команды [108].
- **Папка `.context/`** (своя в каждом workspace, в git не попадает):
  - Хранит вложения (изображения, документы, Linear issues, summaries чатов), планы Claude Code и заметки [17].
  - Команда рассматривала базу данных, вставку в prompt и специальные инструменты контекста, но выбрала простые
    файлы [17].
  - Вложения из API попадают в `.context/attachments/` [96].
  - Папки `.context` облачных workspaces синхронизируются на Mac [47: 0.85.0].
- **Compact:** команда `/compact` и настраиваемый порог автоматического compact [47: 0.1.0, 0.2.0]; «Compact and
  Retry», когда контекст кончился [47: 0.9.1]; compact идёт через родные API Anthropic [47: 0.17.2].
- **Summaries переносят контекст между чатами:** summary прежних чатов можно приложить к новой вкладке
  [47: 0.22.6]; смена harness посреди чата открывает новую вкладку с summary [47: 0.28.7]; fork несёт
  summary [47: 0.25.6].

### Проверка качества

- **Встроенного test gate нет.** Тесты — это actions с кнопкой Run в workspace или Spotlight из корня [56].
  Автоматическое тестирование покрывает «по одному сервису за раз» [56].
- **Review агентом.** Кнопка «Review» [47: 0.22.0] отправляет prompt из «Code review preferences» [63]. Модель
  review и уровень thinking выбираются [47: 0.22.6]. Свои subagents Claude Code для code review и тестов можно
  завести с 0.2.0 [47: 0.2.0]. Это один reviewer. Набора review lenses (разных углов проверки) в документации нет.
- **Review человеком.** Комментарии в Diff Viewer становятся вложениями для агента [53]. Агенты сами оставляют
  комментарии к строкам diff [19].
- **Checks tab.** Git status, данные PR, CI и status checks, deployments, комментарии GitHub и todos [78].
  Построена на `gh` CLI, умеет отправить агенту logs упавшего CI [20]. Упавшие GitHub Actions можно
  перезапустить [47: 0.34.2].
- **Ограничение merge:**
  - Conductor «может заблокировать или отговорить» от merge, пока открыты todos или упали checks [78].
  - Automerge после зелёного CI [47: 0.55.0].
  - Настройка «Treat optional checks as blocking» [47: 0.90.0].
  - Для stacked PR automerge скрыт [47: 0.82.0].
- **Практика команды:** зоны, где каждое изменение строго проверяет человек, и migrations, которые требуют review
  человека в CI [126].

### Права и безопасность

- **Доверие по умолчанию.** У агентов те же права, что у пользователя, sandbox нет [66]. CEO говорит, что команда
  всегда запускает Claude с автоматическим согласием на все разрешения [124].
- **Approvals инструментов:** сначала настройка Enterprise [47: 0.41.0], потом переключатель пользователя с
  необязательным принуждением на уровне организации [47: 0.45.0]. Experimental «Auto permission mode» сам одобряет
  безопасные действия и спрашивает только о рискованных [47: 0.70.0]. Уведомление macOS, когда агент просит
  разрешение [47: 0.45.0].
- **Ошибки в approvals:**
  - Approvals можно было пропустить [47: 0.54.0].
  - MCP servers с именем, начинающимся на «conductor», обходили approvals [47: 0.82.0].
  - Subagents зависали в ожидании при managed approvals [47: 0.46.0].
- **Слои настроек** (сверху вниз по приоритету) [70]:
  1. Managed (организация).
  2. Переопределения проекта в `.conductor/settings.local.toml`.
  3. Настройки репозитория в `.conductor/settings.toml`.
  4. Настройки пользователя в `~/.conductor/settings.toml`.
  5. Встроенные значения по умолчанию.
  - Managed-значения выключают соответствующий элемент UI и применяются при запуске агента. Документация называет
    их предварительными («provisional») [72].
- **Другие меры:**
  - Enterprise data privacy — локальный переключатель. Выключает функции, которым нужен внешний AI (например,
    AI-заголовки чатов), и свои MCP servers [65].
  - Secrets облака хранятся в Cloud Computer и скрыты после сохранения. Инструменты admin-агента их не читают [103].
  - Облачным агентам можно разрешить действовать на локальном Mac [64].
  - Remote control: iPhone управляет Mac через relay с end-to-end шифрованием [86]. Коды связывания одноразовые и
    истекают через 10 минут [86].
  - Исправлены уязвимости: внедрение shell-команд через специально составленные имена веток, адреса клонирования и
    имена файлов [47: 0.87.0].
  - Workspaces, созданные через API, делают коммиты от имени вызывающего [96].
  - Архивная страница цен заявляет SOC 2 Type II [7].

## Что говорят пользователи

Основа — Hacker News, ответы под постами основателя в X, 39 issues репозитория релизов, блоги пользователей,
Product Hunt и YouTube [105][149][150][151][119]. Reddit и Discord недоступны, их мнения не подтверждены. Страницы
сравнения от конкурентов помечены как вендорские.

### Кто и как пользуется

- Для категории параллельных агентов Conductor — точка отсчёта. Конкуренты делают импорт из Conductor и руководства
  по переезду [148][147]. Пользователи другого инструмента, Orca, показывают его разработчикам чат Conductor как
  образец [112]. Один комментатор назвал новый инструмент «ещё одним клоном Conductor» [208].
- Типичные сценарии и масштабы — в разделе «Модель работы»: от двух-трёх workspaces до 10–20 агентов
  сразу [222][223][178][172].

### Что хвалят

1. **Worktrees без лишних усилий.** Это самая частая похвала.
   - Один пользователь пишет, что Conductor убрал почти все неудобства работы с worktrees [222].
   - Аккуратный способ работать — одна ветка и один PR на каждое изменение — стал таким же быстрым, как небрежный [223].
   - До Conductor некоторым worktrees казались слишком хлопотными [173].
   - Пользователь, ушедший на T3 Code, скучает по простой уборке worktrees после archive [251].
   - Когда Cursor 3 вышел без автоматических worktrees для каждого агента, один пользователь назвал их главной
     функцией Conductor [184].
2. **Статус всех агентов на одном экране.**
   - Видно, что делает каждый параллельный агент. Вкладки терминала этого не давали [171].
   - Пока агент работает, пользователи заняты другими задачами [162].
   - Уведомление приходит, когда агент закончил или ждёт ответа [144].
3. **Дизайн и сосредоточенность.**
   - Хвалят чистый UI. Некоторые после него перестали искать другие инструменты [221].
   - Давний пользователь ценит, что Conductor не пытается делать всё сразу [250]. Simon Willison назвал его
     аккуратным приложением для macOS [170].
   - Пользователи терминальных конкурентов просят чат, как в Conductor [112]. Сооснователь конкурента Superset
     признал, что чат у Conductor отполирован лучше [202].
4. **Много моделей и свои подписки.**
   - Легко пробовать разные модели, даже внутри одного workspace [206].
   - Работает на имеющихся планах Claude или ChatGPT или на API keys [104][140].
   - Пользователи отмечают, что компания брала деньги за облачные машины, а не за inference [225].
5. **Цикл PR и CI.**
   - Упавшие checks CI и конфликты merge исправляются в один клик [141].
   - Sidebar построен вокруг PR и worktrees, а не вокруг чатов [186].
   - Пользователи радовались merge свайпом в мобильном приложении [116]. Им нравятся также импорт задач из GitHub и
     Linear и review diff прямо в приложении [144].
6. **Scripts подготовки и уборки workspace.** Они копируют gitignored-файлы, раздают каждому workspace свои порты и
   тестовые базы данных.
   - Когда scripts написаны, подготовка сводится к одному шагу, а UI показывает, что запущено в каждом
     workspace [191].
   - Разработчик на Rails описал полную настройку и пишет, что Conductor заменил ему редактор [142].
7. **Отзывчивость команды.**
   - Команда лично отвечала на отзывы из приложения и быстро выпускала просьбы [231].
   - Один пользователь назвал скорость выпуска лучшей из всех, что видел [232]. Другой отмечает почти ежедневные
     обновления [140].
8. **Облако для опытных пользователей.**
   - Webhooks, API sessions и отдельная VM на каждый workspace дали одному пользователю большой выигрыш [233].
   - Другой вёл сотни workspaces через CLI и назвал Cloud и мобильное приложение переломом в работе [118].

### Что ругают

1. **Только Mac.**
   - На запуске была сборка только для Apple Silicon. Сборка для Intel вышла через пять дней [168].
   - Просьбы о Linux, Windows и WSL2 повторяются весь 2026 год [164][181][116].
   - Как минимум одно конкурирующее приложение сделали специально для пользователей Windows и Linux, которые упёрлись
     в это ограничение [182].
2. **Закрытый код, обязательный аккаунт, привязка к вендору.**
   - В неделю запуска пользователи возражали: нет privacy policy, а по закрытому коду трудно проверить, что
     происходит с данными [159].
   - Первая версия просила полный доступ ко всем репозиториям и организации GitHub [157]. Через два дня перешли на
     точечный доступ или локальный вход `gh` [158].
   - Весь 2026 год часть пользователей отказывалась зависеть от закрытого кода [179]. Авторы конкурентов называют
     закрытый код и принудительный вход причиной делать свои инструменты [195].
   - Privacy notice подтверждает ограниченную аналитику приложения — crash logs и использование функций [12].
     Обзор отметил аналитику PostHog и широкий доступ к GitHub как риск для закрытого кода компании [143].
   - Облако хранит сообщения чатов на серверах Conductor. Локальные sessions — нет [104].
3. **Всё завязано на GitHub.**
   - Ранние сборки клонировали репозиторий из GitHub, поэтому каждый workspace требовал полной установки
     зависимостей. Пользователи хотели работать с уже существующим checkout [155][167]. Поддержка локального git
     появилась примерно через десять дней после запуска, но вход в GitHub всё равно требовался [169].
   - Для одного пользователя обязательный workflow через PR на GitHub оказался неприемлемым [189].
   - Просят поддержку GitLab (issue #7) [105 #7]. Облако работает только с GitHub [104].
   - Просят несколько аккаунтов GitHub (issue #33). У одного пользователя смена аккаунта GitHub сделала приложение
     непригодным (issue #15) [105 #33][105 #15].
4. **«Это просто обёртка».**
   - Одному пользователю не хватало ощущения и горячих клавиш терминального интерфейса Claude Code [160]. Другие
     называют Conductor графической оболочкой над Claude Code [176].
   - CTO объяснил: продукт построен на Agent SDK Anthropic, который открывает большую часть, но не все возможности
     Claude Code [177].
   - Конкретные пробелы:
     - Slash commands молча игнорируются в первом сообщении session, потому что Conductor кладёт в это сообщение
       свои указания (issue #25) [105 #25].
     - Status line Claude Code пользователя не показывается, поэтому лимиты использования не видны (issue
       #36) [105 #36].
     - Skills не загружаются, пока не переключить провайдера туда и обратно [110].
     - Conductor встраивает свои закреплённые версии Claude Code и Codex вместо установленных в системе [152][26].
   - Ушедшие на Superset называют причиной родные CLI без лишнего груза [200] и отображение текста [201].
   - Conductor добавил experimental Big Terminal Mode для любого CLI-агента [192]. Один пользователь спросил, не
     становится ли Conductor тогда просто менеджером worktrees [203].
5. **Зависимость от политики Anthropic.**
   - В апреле 2026 года Anthropic запретила использовать подписку в сторонних harness. В мае объявила изменения
     подписок для Agent SDK. Пользователи боялись конца Conductor или объявляли его, некоторые собирались перейти на
     Codex [190][196][197].
   - 2026-06-15 изменение отложили на неопределённый срок [23].
   - В октябре пользователь заметил, что исчезла связанная страница помощи Anthropic, и счёл это плохим знаком для
     Conductor [211].
   - Один пользователь счёл продажу компании разумной: вендоры моделей могут отрезать доступ по подписке [224].
6. **Навигация по коду.** Нет перехода к определению и поиска использований. Пользователи держат рядом Zed или
   IDE [187][188][251]. Issue #30 просит эту функцию [105 #30].
7. **Реальность worktrees.**
   - Неотслеживаемые `.env`, установка зависимостей, конфликты портов с Docker, общие тестовые базы и git submodules —
     всё это нужно решать [156][193][166][142].
   - Scripts это решают, но требуют заметных усилий [142][143].
8. **Производительность и стабильность.**
   - Машина тормозила на MacBook M3 с 36 GB памяти [154].
   - Утечка файловых дескрипторов заставляла одного пользователя перезагружаться дважды в день. Позже переустановка
     застряла в цикле [194].
   - Версия 0.52.1 зависала при запуске, нагружая CPU почти на 100% (issue #16). Версия 0.83.0 показывала чёрное окно
     8–13 секунд при каждой активации (issue #29) [105 #16][105 #29].
   - Один комментатор решил, что это Electron, и назвал приложение медленным. Основатель ответил, что оно на
     Tauri 2.0 [174][175].
9. **Работа с несколькими репозиториями.**
   - Её просили ещё на запуске [165].
   - В ноябре 2026 года одному пользователю всё ещё приходилось держать по session на репозиторий и пересылать
     сообщения между ними. Это подтолкнуло его к альтернативам [239].
   - Поддержка частичная. Пользователь Codex привёл модель дополнительных папок Conductor как удачное решение [111].
10. **UI делит людей.** Активный пользователь назвал UI очень плохим [117]. Другие считают UI лучшей частью
    продукта [221][202].
11. **Дрейф продукта.**
    - Часть давних пользователей ещё до продажи считала, что продукт застоялся, подорожал и ушёл в сторону
      enterprise [229][230]. Один писал, что Conductor отстаёт от конкурентов [249].
    - Пользователи говорят, что он почти не отличается от Claude Code Desktop [235][236]. Другие вернулись к
      официальным CLI и desktop-приложениям [237][238].

### Истории сбоев

- **Ночной pipeline стоял около 7 часов.** Перезапуск session убил идущую задачу deploy и заодно cron-наблюдателя,
  которого агент поставил сам. Уведомления не было, ничего не возобновилось (issue #21) [105 #21].
- **Вопрос без ответа.** Очистка простаивающих sessions через 30 минут убила агента, пока он ждал ответа
  пользователя. Через 4 с лишним часа UI всё ещё показывал, что агент ждёт (issue #27) [105 #27].
- **Чужой текст PR.** Действие Create PR подставило заголовок и описание старого, не связанного PR и велело агенту
  использовать их без изменений (issue #23) [105 #23].
- **Ошибки помельче:**
  - После squash merge слитые workspaces возвращаются в статус In Progress (issue #34) [105 #34].
  - Вход в Codex через ChatGPT увеличивает стартовый контекст примерно в 7 раз (issue #37) [105 #37].
  - Истёкший встроенный лицензионный ключ показывает баннер в окне чата (issue #39) [105 #39].
- **Неделя запуска:** клонирование из GitHub заставляло ставить зависимости в каждом workspace заново [155].
- **Ирония, замеченная на HN.** Самая популярная публичная просьба — свои звуки завершения (issue #12,
  15 реакций) [105 #12] — вышла в том же выпуске, который объявил о закрытии. Комментаторы HN над этим
  посмеялись [219][26].

### Почему приходят и почему уходят

- **Приходят ради:** автоматизации worktrees [222][173]; обзора многих агентов [171]; многих моделей в одном
  приложении [206]; доводки интерфейса [221]; бесплатного локального плана [140].
- **Уходили до сделки с Meta, потому что нужны были:**
  - работа на нескольких машинах и удалённое управление [226][228];
  - доступ с телефона к локальным sessions, а также CLI и MCP server [227];
  - родные CLI [200];
  - open source, self-hosting и мобильный доступ [204][207][230];
  - возврат в терминал или к официальным приложениям [209][237][238].
- **Уходили после 2026-11-04** вынужденно, из-за объявленного закрытия. Многие переехали за несколько дней, и
  разворот через неделю застал часть из них врасплох [220][119].

### Сравнение с альтернативами

- **Conductor считают лучше в:** доводке и чате [202]; жизненном цикле workspace и scripts подготовки [191][251];
  простоте по сравнению с терминальными мультиплексорами [205].
- **Conductor считают хуже в:**
  - открытости и платформах [179][181];
  - удалённой работе и работе на нескольких машинах [226];
  - доступе с телефона к локальным sessions — до 2026-10-23 он был только для облака [116][26];
  - верности родным CLI [200];
  - навигации по коду [187].
- **Категория стала товаром.** В треде о Meta десятки основателей предлагали замену. Пользователи решили, что у
  категории нет защиты от копирования [243][244].

### Скепсис ко всей категории, адресованный Conductor

- Узкое место — review человеком. Worktrees добавляют ещё один слой, но это не решают [161][163][143].
- Внимания хватает примерно на три sessions [213]. Параллельные агенты тратят токены, заново собирая один и тот же
  контекст [214].
- Один пользователь пишет с Conductor намного больше кода, но пока не выпускает пропорционально больше [180].
- Основатель утверждал, что агенты уже достаточно хороши: человек может смотреть панель с итогом, а не diff.
  Пользователи возражали: что делать, если итог говорит «готово», а diff показывает другое [117].

### Чего просят пользователи в темах, близких к worfy

- **Работа без присмотра.** Два самых подробных отчёта об ошибках описывают долгие запуски, которые молча умирают и
  не возобновляются (issues #21, #27) [105 #21][105 #27].
- **Видимость лимитов.** Просят постоянно видимую полосу с расходом за 5 часов и за неделю (issue #36) [105 #36].
  Просят вход в несколько аккаунтов и вид subagents [119]. При rate limit переключают аккаунты [198].
- **Родной CLI против SDK.** Пользователи замечают пробелы из-за слоя SDK: slash commands, status line, skills,
  закреплённые версии [105][110][152]. Некоторые уходят к инструментам, которые запускают родные CLI [200].
- **Подготовка worktree.** Основные усилия уходят на порты, базы данных и env-файлы для каждого
  workspace [142][191][193].
- **Сессии на несколько репозиториев** [239][165][111].
- **Удалённая работа, несколько машин, присмотр с телефона** [226][228][227][116]. Просят и удалённую разработку по
  SSH (issue #14) [105 #14].
- **Review.** Пользователи колеблются между чтением diff и доверием к итогу [117]. Review остаётся узким
  местом [161][143].
- **Платформы.** Требуют Windows, Linux и WSL2 [181][116][164].
- **Доверие.** В разговорах о переходе на другой инструмент главное — закрытый код, принудительный вход, где лежат
  данные и риск покупки компании [179][195][245][246].
- **Навигация по коду** — пробел, который замечают в приложениях, построенных вокруг агентов [187][105 #30].

## Слабые места и чего нет

- **Будущее неясно.** 2026-11-04 вендор объявил переход в Meta, закрытие облака и закат локального приложения в
  начале 2027 года [3]. 2026-11-12 решили продолжить разработку [119][2]. Явной отмены дат Cloud не найдено,
  страница цен исчезла, открыта ли регистрация — неясно [2][146][1]. Часть пользователей больше не доверяет
  продукту [249][253][254].
- **Только macOS.** Для Windows и Linux есть только лист ожидания [51]. Просьбы о Windows, Linux и WSL2 повторяются
  весь 2026 год [164][181][116].
- **Закрытый код и привязка к GitHub.** Исходников нет [106]. Облако работает только с GitHub [104]. Нет GitLab и
  Bitbucket, нет нескольких аккаунтов GitHub [105 #7][105 #33].
- **Нет слоя планирования.** Нет Epics, графа задач и зависимостей. Встроенного orchestrator нет. Orchestration — это
  prompt для внешнего LLM, который опрашивает REST или MCP примерно каждые 15 секунд [53][96].
- **Слабая работа без присмотра на Mac.**
  - Автоматический повтор после rate limit есть только у Codex [47: 0.84.0, 0.91.0].
  - Для Claude приложение только показывает время сброса лимита. Ожидания сброса и продолжения не
    найдено [47: 0.9.2].
  - Routines работают только в облаке [27].
  - Долгие запуски умирали молча и не возобновлялись (issues #21, #27) [105 #21][105 #27].
- **Нет локальной проверки качества.** Тесты — это actions и Spotlight. Автоматическое тестирование — по одному
  сервису за раз [56]. Reviewer один, review lenses нет [63].
- **Безопасность по умолчанию слабая.**
  - Полные права пользователя, нет sandbox [66][54].
  - Approvals включаются отдельно. «Auto permission mode» — experimental [32][29].
  - Были ошибки, при которых approvals можно было обойти [47: 0.54.0, 0.82.0].
  - Preset-ы Big Terminal Mode при выключенных approvals запускают агентов без всех проверок [85].
- **Пробелы из-за слоя Agent SDK:** slash commands в первом сообщении, скрытая status line, загрузка skills,
  закреплённые версии CLI [105 #25][105 #36][110][152]. Зависимость от политики Anthropic по подпискам [23].
- **Координация параллельных агентов.** Блокировок, merge queue и поиска конфликтов между workspaces в документации
  нет [63][53]. Агенты в одном workspace могут править одни и те же файлы [55]. Checkpoints смешиваются, когда в
  workspace несколько чатов [80].
- **Остановка процессов неполная.** Потомки в других группах процессов переживают Stop [68].
- **Ограничения облака.** Sandbox засыпает через 20 минут простоя и жёстко останавливается через 23 ч 50 мин;
  процессы при этом умирают [101]. Один регион — us-east-1 [104].
- **Нет записи запуска.** Временной шкалы отдельного запуска сверх transcripts и checkpoint refs не найдено [98][16].
- **Нет планирования под лимиты.** Показ стоимости для Claude Code убран как неточный [47: 0.39.0].
- **Стабильность и скорость:** тормоза, утечка файловых дескрипторов, зависание при запуске, чёрное окно на
  8–13 секунд [154][194][105 #16][105 #29].
- **Нет навигации по коду** — перехода к определению и поиска использований [187][105 #30].
- **Работа с несколькими репозиториями частичная** [239][91].
- **Документация расходится с changelog:** goals и очередь сообщений [27][58]; размер диска облака [103][27]; ответ
  FAQ о деньгах [66][9].
- **Приватность.** Аналитика в PostHog включает сообщения об ошибках провайдера и stack traces [65]. Облачные чаты
  хранятся на серверах вендора [65].
- **Чего нет по сравнению с продуктами вроде worfy:** бесконечного полотна, Epics, входящих PR, связи двух
  компьютеров напрямую, удаления личных данных со screenshots, режима экономии, планирования запусков под лимиты.
  Подробно — в следующем разделе.

## Пересечение с worfy

Термины worfy в этом разделе:

- Canvas — бесконечное полотно, на котором worfy показывает работу агентов.
- Epic — группа связанных Ticket-ов. Ticket — одна задача.
- Orchestrator — session, которая планирует работу и раздаёт Ticket-ы.
- Wave — набор Ticket-ов, которые запускаются вместе. Autopilot — запуск Wave-ов без человека: он ждёт сброса лимитов
  подписки, повторяет запросы после ошибок API и одобряет запросы разрешений по заданной policy.
- Gate — локальный запуск проверок для Ticket.
- Harness worfy — plugin, который приносит в Claude Code rules, skills, subagents и hooks. У Conductor слово
  «harness» значит другое — сам агент (Claude Code, Codex, Cursor, OpenCode) [59].
- Flight Recorder — временная шкала запуска без присмотра. Work track — вся работа проекта за день или неделю.
- Cards — карточки, которые агенты строят на Canvas через MCP server.
- Product Session — советник по продукту с живым Mind map и критиком спецификаций.
- PR inbox — список входящих PR. Linked machines — компьютеры, связанные по локальной сети.
- Evidence — screenshots-доказательства с удалением личных данных. Eco mode — режим экономии лимитов.

### Где пересекаются

- **Desktop-приложение для параллельных coding-агентов.** Оба запускают sessions Claude Code и Codex. Conductor —
  ещё Cursor и OpenCode [59].
- **Worktree на задачу.** В Conductor workspace — это git worktree и ветка [57]. В worfy у каждого Ticket свой git
  worktree.
- **PR и статус CI.** У Conductor — Checks tab, страница PR, automerge после зелёного CI [78][29]. У worfy — PR со
  значками CI.
- **Review агентами.** У Conductor — одно действие Review, комментарии Claude к diff и `/review` Codex [63][36][28].
  У worfy — subagents-reviewers с review lenses.
- **Формирование поведения агента.** Conductor добавляет свои system prompts, prompts на действие для репозитория,
  встроенный skill и Sync Agent Configs [66][71][30][108]. У worfy эту роль играет Harness-plugin.
- **Автоматические approvals.** У Conductor — experimental «Auto permission mode» и `always_approve` для
  Codex [29][71]. У worfy — одобрение по policy в Autopilot.
- **Повтор после ошибок.** Conductor сам повторяет запросы Codex после rate limit [27]. worfy повторяет запросы после
  ошибок API.
- **Счётчики лимитов и уведомления.** У обоих есть счётчики расхода и уведомления [27][28][32][26].
- **Терминал рядом с агентом.** У Conductor — `@terminal`, Claude читает терминал, Big Terminal Mode [31][36][85].
  У worfy — Terminal с AI-помощником.
- **Встроенный браузер.** У Conductor — experimental preview с заметками Agentation [30]. У worfy — Browser с
  профилями.
- **Screenshots в ответах агентов.** У Conductor агенты вставляют screenshots в ответы [27]. У worfy — Evidence.
- **Сводка работы.** У Conductor — SQL-рецепт «Daily Report» в документации API, тепловая карта токенов и
  Wrapped [96][26][39]. У worfy — Work track.
- **Статусы задач.** Доска backlog / in progress / in review / done у Conductor [34] — ближайшее к статусам
  Ticket-ов worfy.
- **Один пользователь на Mac.** Бесплатный Conductor — локальное приложение для одного человека [9]. worfy —
  приложение для одного пользователя на macOS.

### Где расходятся

- **Интерфейс.** У Conductor — sidebar, вкладки и боковые панели; основатель держится принципа «GUI вместо CLI»;
  бесконечного полотна нет [124]. У worfy — Canvas.
- **Слой планирования.** У Conductor его нет: работу делит человек или Plan Mode; есть доска статусов, todos и
  issues как источники workspaces [53][34][81][30]. У worfy — Epics, Tickets и Orchestrator.
- **Работа без присмотра.** Conductor ставит на облачные sandbox («free-range agents») [128]. Локально у него только
  Caffeinate, Codex goals и повтор Codex после rate limit; routines — только в облаке [31][58][27]. Ожидания сброса
  лимита Claude и продолжения нет [47: 0.9.2]. У worfy — локальный Autopilot с Wave-ами, ожиданием сброса лимитов,
  повторами и одобрением по policy.
- **Проверка.** У Conductor нет локального Gate: есть actions, Spotlight и checks CI [56][78]. У worfy — Gate на
  каждый Ticket.
- **Review.** У Conductor один reviewer без lenses [63]. У worfy — несколько subagents-reviewers с lenses.
- **Наблюдаемость.** У Conductor нет записи запуска, только transcripts, checkpoint refs и SQL по
  transcripts [98][16]. У worfy — Flight Recorder.
- **Команда или один человек.** У Conductor есть организации, общие чаты, Follow, «Reassign to», SSO и
  SCIM [102][28]. worfy — для одного пользователя.
- **Облако.** У Conductor есть Conductor Cloud [99]. worfy работает локально и связывает машины по локальной сети.
- **Телефон и удалённый доступ.** У Conductor — iOS-приложение и Remote Control Mac с iPhone через relay [131][86].
  Облачные агенты могут выполнять команды на Mac [64]. Связи двух компьютеров между собой не найдено. У worfy —
  Linked machines по LAN.
- **Агенты для агентов.** У Conductor — публичный HTTP API, hosted MCP server и CLI, чтобы внешние агенты создавали
  workspaces и управляли ими [96][97]. У worfy MCP server служит для Cards на Canvas.
- **Подключение агентов.** Conductor запускает Claude Code через Claude Agent SDK и встраивает закреплённые версии
  CLI [23][66]. worfy запускает sessions Claude Code и Codex CLI.
- **Число агентов.** У Conductor четыре harness и preset-ы любых CLI в Big Terminal Mode [59][85]. У worfy — Claude
  Code и Codex.
- **Платформы.** Conductor — macOS и iOS [51][131]. worfy — macOS, порт на Windows в работе.
- **Есть у Conductor, нет в описании worfy:** Spotlight testing [69], 10 портов на workspace [68], checkpoint на
  каждый ход [80], steering [31], routines [27], deep links [84], интеграция с Linear [30], Diff Viewer с
  комментариями агенту [79], имена workspaces по городам [87].
- **Есть в worfy, не найдено у Conductor:** Cards на полотне (ближайшее — вкладка Artifacts и previews HTML и
  Markdown) [26][31]; Product Session с Mind map и критиком; PR inbox; Linked machines между компьютерами; удаление
  личных данных со screenshots; Eco mode; планирование запусков под лимиты подписки.

## Механизмы, которые стоит изучить

1. **Checkpoint на каждый ход агента в отдельных git refs.**
   - Что это: откат кода и чата к любому ходу для Claude Code и Codex [80].
   - Как работает: hooks в начале и конце хода сохраняют HEAD, index (`git write-tree`) и весь рабочий каталог с
     неотслеживаемыми файлами (временный `GIT_INDEX_FILE`, `git add -A`, `write-tree`). `git commit-tree` пишет
     коммит с метаданными в сообщении, `git update-ref refs/conductor-checkpoints/<id>` хранит его вне истории ветки.
     Восстановление — `reset --hard`, `read-tree --reset -u`, `clean -fd`, `read-tree --reset`. Есть команда `diff`
     между двумя checkpoints [16][109].
   - Чем интересно: история ветки чистая, неотслеживаемые файлы и правки от linters и генераторов не теряются.
     Команда описала, почему отвергла снимки файлов, `git stash` и хранение в SQLite. Ограничение — checkpoints
     смешиваются, если в workspace несколько чатов [16][80].
   - Источник: [16][109][80].
2. **Spotlight testing.**
   - Что это: проверка изменений одного workspace на общем тяжёлом стеке в корне репозитория [69].
   - Как работает: Conductor следит за workspace, делает checkpoint-коммит и делает его checkout в корневом checkout.
     Синхронизация — только отслеживаемых файлов и только в одну сторону. При выключении корень
     восстанавливается [69].
   - Чем интересно: не нужно поднимать Docker, базу данных и фиксированный порт в каждом worktree.
   - Источник: [69][56].
3. **Подготовка worktree к запуску.**
   - Что это: набор правил, после которых новый worktree сразу запускается [68][73].
   - Как работает: «Files to copy» и `.worktreeinclude` копируют только gitignored-файлы, например `.env*`. Setup
     script запускается после checkout, archive script — перед архивированием. Scripts получают
     `CONDUCTOR_WORKSPACE_PATH`, `CONDUCTOR_ROOT_PATH`, `CONDUCTOR_WORKSPACE_NAME` и `CONDUCTOR_PORT`. Каждый workspace
     получает 10 портов подряд. Режим `nonconcurrent` останавливает другие actions. Stop шлёт SIGTERM группе
     процессов и через 5 секунд SIGKILL [57][74][68].
   - Чем интересно: пользователи называют подготовку worktree главным местом, куда уходят усилия [142][191][193].
   - Источник: [68][73][74].
4. **Папка `.context` и передача плана между harness.**
   - Что это: папка в каждом workspace, которую git игнорирует. В ней вложения, summaries чатов, Linear issues, планы
     Claude Code и заметки [17].
   - Как работает: планы Claude Code сами сохраняются в `.context`, и другой harness может их реализовать. Вложения
     из API попадают в `.context/attachments/`. Облачные `.context` синхронизируются на Mac. Команда рассматривала
     базу данных, вставку в prompt и специальные инструменты, но выбрала простые файлы [17][96][47: 0.85.0].
   - Чем интересно: общий контекст для агентов разных вендоров без своего формата памяти.
   - Источник: [17][37].
5. **Steering вместо очереди.**
   - Что это: сообщение, отправленное во время работы агента, попадает в текущий ход [31].
   - Как работает: с 0.50 ⌘⏎ переключал режим между очередью и steering. С 0.86 очередь убрана, и любое сообщение
     направляет агента. API всё ещё описывает очередь и удаляет её при отмене [31][47: 0.86.0][96].
   - Чем интересно: человек корректирует агента, не останавливая ход.
   - Источник: [31][27][47: 0.86.0].
6. **Слои настроек в TOML с managed-слоем.**
   - Что это: пять уровней настроек — managed, локальное переопределение проекта, общие настройки репозитория в git,
     пользователь, значения по умолчанию [70].
   - Как работает: managed-файл `~/.conductor/settings.managed.toml` блокирует соответствующие элементы UI и
     применяется при запуске агента. Общие настройки репозитория лежат в `.conductor/settings.toml` и действуют у
     всех [72][70].
   - Чем интересно: одна схема покрывает личные настройки, настройки проекта в git и правила организации.
   - Источник: [70][71][72].
7. **API и MCP для агента-менеджера.**
   - Что это: публичный HTTP API (`api.conductor.build/v0`) и hosted MCP server с 20 инструментами [96][97].
   - Как работает: готовый prompt «планировщик и reviewer» пишет самодостаточное задание, создаёт workspace, опрашивает
     статус примерно каждые 15 секунд, читает новые сообщения через `after=` и проверяет результат по заданию.
     Prompt «fan-out» делит задачу на несколько PR. Облачный workspace получает токен с правами только на себя.
     Повтор сообщения с тем же `messageId` отбрасывается. Ошибки несут флаг `retryable` и источник (ui, sidecar,
     git, agent, network, db). SQL по transcripts ограничен 500 строками и 5 секундами [96][98].
   - Чем интересно: orchestration собрана из простых вызовов, которые повторяются без вреда.
   - Источник: [96][97][98].
8. **Routines с триггерами GitHub.**
   - Что это: сохранённый prompt, который запускается в новом облачном workspace [27].
   - Как работает: расписание (каждый час, каждый день, по будням, раз в неделю), события GitHub с фильтром по label,
     автору или базовой ветке, webhook через API. У запусков есть панель Runs [27][26][47: 0.85.0, 0.87.0][96].
   - Чем интересно: команда сама использует их для отчётов, stand-up и исправления своих system prompts [25].
   - Источник: [27][96][25].
9. **Remote Control через relay.**
   - Что это: управление локальными workspaces Mac с iPhone [86].
   - Как работает: трафик идёт через relay вендора с end-to-end шифрованием. Связывание — одноразовым QR-кодом, код
     истекает через 10 минут. Пока телефон подключён и Mac на зарядке, Mac не засыпает. Функция выключена в режиме
     Enterprise data privacy [86].
   - Чем интересно: доступ к локальным агентам с телефона без облачного исполнения.
   - Источник: [86].
10. **Маршрутизация внимания.**
    - Что это: способы показать, какой из многих агентов ждёт человека [33][27].
    - Как работает: переход к следующему чату, который ждёт человека (⌘⌥L); пометки «needs input» и непрочитанного;
      experimental таблица статусов (запуски routines, ошибки, идущие checks, слитые PR); уведомления о завершении,
      вопросах, плане и разрешениях с именем ветки; обновление приложения ждёт, пока агенты не остановятся;
      Caffeinate не даёт Mac уснуть [33][83][67][38][27][32][47: 0.24.0, 0.39.0][31].
    - Чем интересно: пользователи называют обзор многих агентов главной причиной прийти [171].
    - Источник: [33][27][32][31].
11. **Ограничение merge.**
    - Что это: правила, которые не дают слить незаконченную работу [81][78].
    - Как работает: открытые todos блокируют merge. Настройка «Treat optional checks as blocking» делает
      необязательные checks обязательными. Automerge срабатывает после зелёного CI и скрыт для stacked PR. Checks tab
      отправляет агенту logs упавшего CI. Кнопка следующего шага предлагает создать PR, исправить ошибки, разрешить
      конфликты, сделать commit и push или подтянуть изменения [81][47: 0.90.0, 0.55.0, 0.82.0][20][45].
    - Чем интересно: проверка готовности встроена в путь к merge, а не вынесена в отдельный шаг.
    - Источник: [81][78][20].
12. **Формирование поведения агентов разных вендоров.**
    - Что это: способы задать агентам одинаковые правила, не меняя сами CLI [66][71].
    - Как работает: Conductor добавляет свои system prompts. Для каждого репозитория есть слоты prompts на действия:
      General, Code review, Create PR, Fix errors, Resolve conflicts, Branch rename. Skill `conductor` опубликован в
      `/.well-known/skills/index.json`. Sync Agent Configs копирует skills, slash commands и MCP servers между Claude
      Code и Codex [66][71][63][108][30].
    - Чем интересно: одна точка настройки для нескольких harness. Минус — пользователи замечают побочные эффекты:
      slash commands не работают в первом сообщении, потому что туда попадают указания Conductor [105 #25].
    - Источник: [66][71][63][108][30].
