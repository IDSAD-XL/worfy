## Модель работы

- **Hybrid.**
  - Основной режим — локальный: App и CLI запускают агентов на машине пользователя [1][11].
  - Remote Control управляет локальными сессиями из браузера через antigravity.google.com и обратные туннели [58].
  - Remote Agents работают в облаке, в изолированной среде под управлением Google, и продолжают работу, пока ноутбук спит [57].
  - Self-hosting нет. Enterprise работает в Google Cloud: размещение данных `global`, `us` или `eu`, VPC Service Controls, Private Service Connect [16].
- **Поверхности.**
  - **App** — desktop-приложение для запуска, оркестрации и просмотра команд агентов. Редактора кода в нём нет. Выросло из окна Agent Manager [11][76].
  - **CLI `agy`** — TUI для работы с клавиатуры, в том числе по SSH, с малым расходом ресурсов [5][112]. Тот же движок и те же настройки, что у App: настройки синхронизируются в обе стороны, сессию терминала можно перенести в App [112]. Установка — скриптом: `curl … install.sh | bash` или `irm … | iex` в PowerShell [3][112].
  - **IDE** — исходный редактор 2025 года, v2.7.0 [3]. Для enterprise не поддерживается [16]. Google обещал убрать из IDE Agent Manager в одном из следующих релизов [76]. Убран ли он уже — не подтверждено: страница IDE его всё ещё показывает [6].
  - **Расширения** — VS Code v1.12.0, Visual Studio 2026, JetBrains v1.5.0, Zed v1.5.0, Xcode v1.5.0, Eclipse v1.1.0 (preview) [3][70][86]. Другие редакторы подключаются через Agent Client Protocol (ACP — открытый протокол связи редактора с агентом): `agy acp` говорит JSON-RPC через stdio [61][70].
  - **SDK** — `pip install google-antigravity` [111][81].
  - **Managed Agents в Gemini API** — тот же агент как сервис по REST и gRPC [72][77][102]. AI Studio Build работает на том же harness [77][103].
  - **Web dashboard** antigravity.google.com — Remote Control и облачные разговоры [57][58].
- **Один harness под всеми поверхностями.**
  - Он даёт асинхронных subagent-ов в изолированных git worktree, фоновые процессы по cron (sidecars), циклы проверки и права [11].
  - CLI взял часть продукта и harness Gemini CLI [80]. SDK использует тот же runtime, что App и CLI [81].
  - Google называет harness обученным вместе с Gemini [11]; на нём построены стеки обучения и оценки Gemini [76]. По TechCrunch (вторичный источник), Gemini 3.5 Flash разрабатывали с помощью Antigravity [120].
- **Агенты.** Только собственный harness. Claude Code, Codex и Cursor — источники для импорта настроек, а не среды запуска [10].

## Функции

Рядом с функцией указана версия App (v2.x) или CLI (1.x), в которой она появилась, если она известна.

### Проекты, разговоры и worktree

- **Projects** — группа папок со своими настройками, правами и историей. Проект может включать несколько репозиториев, например frontend и backend [18]. Новый проект начинает с прав «Inherit Global»; skills, MCP-серверы и hooks настраиваются глобально [18].
- **Standalone conversations** — разговор вне проекта, во временной папке [53][78].
- **Выбор worktree при старте разговора:** Local (агент работает в настоящих папках) или New worktree (git worktree создаётся в фоне) [18][78].
  - Subagent-ам, которым нужна изоляция, worktree создаются и удаляются автоматически [78].
  - Knowledge Work layout прячет этот выбор [18]. Меню ветки и worktree объединены (v2.29.0) [10].
  - Заметки расходятся: по разбору отзывов выбор worktree добавили в v2.29.0 [10]; по посту с I/O и документации worktree есть с мая 2026 [78][18].
- **Sidebar:** группировка по проекту, статусу или времени; pin; archive и unarchive; drag-and-drop между разделами (v2.22.0) [10][52].
- **Split Right и Split Down** — два разговора рядом [52].
- **Навигатор разговора** — полоса с точкой на каждый ход и главами, которые называет AI (v2.28.1, v2.29.0) [10].
- **`/compact`** — сжать длинный разговор в краткое изложение (App v2.24.0, CLI 1.3.5) [10].
- **Очередь сообщений** с кнопкой «Send Now» (v2.3.0) [10].
- **`/btw`** — побочный вопрос в фоне, не прерывая основную задачу (v2.1.4) [10].
- **Undo** только разговора, без отката файлов (v2.19.1) [10]. **Rewind** восстанавливает файлы из первого snapshot в точке отката или после неё (v2.17.0) [10].

### Subagent-ы и свои агенты

- **Встроенные subagent-ы:** `research`, `browser` и `self` (копия вызывающего агента); в CLI ещё `image-generator` (1.2.16) [19][10]. Каждый начинает с чистого контекста, работает асинхронно, их может быть много параллельно [19].
- **Custom agents** (2026-08-12) — Markdown-файл с YAML frontmatter в `.agents/agents/` или `~/.gemini/config/agents/` [19][85].
  - Поля: `tools`, `model` (`inherit`, `flash`, `pro`), `commandExecutionPolicy` (`off`, `auto`, `eager`, `sandbox`), `mcpServers`, `skills`, `plugins` [19].
  - Флаги `mainAgent` и `subagent`: один файл работает и главным агентом, и subagent-ом. Google противопоставляет это «другим инструментам», где свой агент бывает только subagent-ом [85].
  - Агент может объявить свои hooks (v2.17.0), rules (v2.11.0) и `inheritCustomizations` (v2.9.1) [10].
- **`define_subagent`** — агент создаёт временного subagent-а прямо во время работы [19].
- **Режимы рабочей папки:** `inherit` (папка родителя), `branch` (свой git worktree), `share` (общая папка) [19].
- **Состояния:**
  - Running.
  - Idle — после отчёта родителю; сообщение будит subagent-а с прежним контекстом.
  - Killed — навсегда; его worktree удаляются, транскрипт в JSONL остаётся для чтения [19].
- **Вложенность** — до 10 уровней в App [19]. Агенты пишут родителям и соседям по ID разговора и читают чужие транскрипты [19].
- **Права** наследуются от родителя: разрешённые префиксы команд, области файлов, настройки sandbox. Запросы на разрешение поднимаются в главный UI [19].
- **Что видит пользователь:** живые карточки subagent-ов с кнопкой остановки (v2.16.0); можно писать subagent-у напрямую (v2.19.1); значок, если subagent ждёт одобрения (v2.23.0) [10]. В CLI: `@<subagent>` — сообщение, Alt+J — перейти к ждущему, Ctrl+K — одобрить [19].

### Режимы для нескольких агентов

Документация даёт правило выбора: subagent — одна побочная задача; `/boost` — глубокое рассуждение; `/swarm` — работа, которая чисто делится на части; `/teamwork` — проект из нескольких этапов на часы и дни [20].

- **`/swarm`** — preview, планы Pro и Ultra; App v2.31.0 (2026-11-09) и CLI 1.5.5 (2026-11-10) [20][95][10].
  - Текущий разговор становится координатором. Он только раздаёт работу и докладывает, сам код не пишет [20].
  - Координатор добавляет именованных worker-ов (`@parser`) или группы (`@fix-1`…`@fix-4`). Для каждого на доске публикуется brief: чем он владеет, чего не трогать, что значит «готово» [20].
  - На каждые 2–4 worker-а обычно добавляется `@verifier`: читает diff, запускает тесты, возвращает проблемы автору [20].
  - `@monitor` пишет, только если все участники замолчали до конца работы [20].
  - Вся координация — через одну общую доску; что сообщения на неё можно только добавлять (append-only), пишет блог [95]. Адресация: `@name`, `@group`, `@all`. Личных сообщений между worker-ами нет [20].
  - Ждущие участники спят и не тратят токены; будит их упоминание [20][95].
  - Модель задаётся каждому worker-у. Координатор может перевести спящего worker-а на другую модель, разговор сохраняется [20]. Блог советует Carbon для ролей координатора, безопасности и проверки [95].
  - Worker-а можно создать копией разговора другого участника [112]. Убитого worker-а не вернуть — координатор добавляет нового [20].
  - UI в App: панель Swarm с вкладками Board, Members и Graph. Graph — временная шкала, по которой можно заново проиграть, как команда пришла к результату [95]. В CLI: `/swarm board` или Alt+S [20].
  - В меню CLI команда помечена «(Preview & Quota Heavy)»: каждый worker — отдельный агент и тратит квоту [112].
  - Google пять недель пользовался `/swarm` внутри компании [95].
  - **Изоляция — источники расходятся.** Блог: каждый worker работает в изолированном git worktree [95]. Документация: по умолчанию worker-ы делят рабочую папку; координатор даёт отдельную копию, когда несколько worker-ов одновременно правят или собирают код, и перед удалением worker-а просит его перенести изменения [20]. Как изменения сливаются обратно, не описано (не подтверждено).
- **`/teamwork`** — платные планы, App и CLI [21].
  - Фаза 1 — интервью о задаче. Результат — prompt artifact: требования, объективный способ проверить каждое, критерии приёмки, папка проекта (по умолчанию `~/teamwork_projects/<имя>`). Пользователь одобряет его один раз [21].
  - Фаза 2 — автономная работа по этапам (milestones) с artifact-ами request, plan и progress [21].
  - Роли [21][82]:
    - Sentinel — формулирует цель и следит за ходом работы;
    - Project Orchestrator — раздаёт работу, между этапами передаёт её преемнику;
    - Explorers — только читают и исследуют;
    - Workers — работают на непересекающихся участках;
    - Critic, Challenger, Auditor (ищет обман: подделанные результаты, mock-и) и Success Auditor — четыре проверяющие роли.
  - Каждым файлом в один момент владеет один Worker [21].
  - Режимы честности: `development` (мягкий); `demo` (нельзя копировать основную логику); `benchmark` (реализация с нуля, только стандартная библиотека, без mock-ов в тестах). Режим выбирается по ответам пользователя о запрещённых упрощениях [21].
  - Раньше назывался `/teamwork-preview`: в мае — только Ultra за $200, с 2026-08-27 — все платные планы [77][78][90].
  - Работает часами и днями. Примеры результатов Google: математические доказательства, симулятор RISC-V, патчи, принятые в Eigen и ParlayHash [90].
  - Состояние запуска перенесли из `.agents/teamwork/` в отдельную папку на каждый запуск в данных приложения: два запуска в одной папке перезаписывали друг друга (CLI 1.5.5) [112].
- **`/boost`** — платные планы, App и CLI (v2.12.0, 2026-09-02) [22][10]. Три фазы [22]:
  1. Orchestrator делит задачу на проверяемые подзадачи.
  2. Параллельные потоки реализуют, исследуют и проверяют, каждый в своей изолированной области (временные worktree).
  3. Итоговый шаг проверяет результат полными наборами тестов; ошибки уходят на новый круг.
- **Orchestrator** (2026-11-12) — не команда, а пункт в выборе модели [15].
  - «Orchestrator (Carbon)» — Ultra; «Orchestrator (Argon)» — Ultra и платный Pro [15].
  - Сильная модель планирует в режиме только чтения, с явными условиями для нового плана. Hydrogen правит код и запускает тесты. При трудностях, например повторных провалах проверки, управление возвращается к планировщику [96][15].
  - Заявление Google: на Terminal-Bench 4.1 успех почти как у Carbon, но на ~24% меньше квоты и на ~19% быстрее [96]. Для enterprise недоступен [16].

### Долгая и автономная работа

- **`/goal`** (App, CLI, IDE) [23].
  - «Goal stop hook» не даёт агенту остановиться раньше времени. При каждой заблокированной остановке агент получает прошедшее время, счётчик продолжений и исходный запрос.
  - Агент заново строит список результатов и сверяет каждый с доказательством: файлами, результатами тестов, логами сборки.
  - Лимита итераций нет. Одна цель на разговор. Пока работают subagent-ы или фоновые задачи, продолжение не навязывается.
  - В App есть индикатор «Active Goal» и список Goals.
- **`/schedule`** (App, CLI, IDE), действует в пределах разговора [24]:
  - одноразовые таймеры: `DurationSeconds` и `TimerCondition`, который заканчивает ожидание раньше, если subagent или задача закончили работу;
  - cron-задачи с `MaxIterations` и `IsDaemon`;
  - управление через `/tasks`.
- **Automations** — только App; до v2.21.1 (2026-10-07) назывались Scheduled Tasks [25][10].
  - Создаются командой `/automation` или кнопкой «Create with Prompt». Частота: Hourly, Daily, Weekly или cron; часовой пояс задаёт `CRON_TZ` [25].
  - Новая автоматизация создаётся в состоянии Paused. Страница показывает группы Scheduled, Always on и Paused со временем следующего и прошлого запуска (v2.29.0) [10]. Что значит «Always on» — не подтверждено.
  - Каждый запуск — новый разговор без памяти о прошлых [25].
  - Модель — Flash по умолчанию; можно выбрать Flash Lite или Pro (v2.24.0) [10][25].
  - В автономном запуске всё, что требует одобрения, автоматически запрещается. Пробный запуск записывает точные нужные права в `agent_permissions`, например `command(gh issue list)`; пользователь их проверяет. Кнопка «Run Now» запускает сразу [25].
  - Внутри это `sidecar.json` со встроенным `schedule` и вызовом `agentapi new-conversation` [25][26].
- **Sidecars** — фоновые процессы под управлением приложения, описываются в `sidecar.json` [26]:
  - своя команда (`command`) или встроенный планировщик `schedule`;
  - `restart_policy`: `always`, `on-failure` или `never`; по умолчанию sidecars выключены;
  - на `PATH` лежит CLI `agentapi`, через который sidecar создаёт разговоры и пишет в них;
  - логи и данные — `~/.gemini/antigravity/sidecar_data/<id>/`; плагины могут поставлять свои sidecars.
- **Background tasks** — фоновые задачи агента; разговор, запущенный по расписанию, пользователь может перехватить [78].
- **Keep-awake:** пока агент работает, Antigravity не даёт компьютеру уснуть [17].

### Удалённая работа

- **Remote Control** (2026-08-21) — управлять локальными сессиями из любого браузера, в том числе с телефона [58][88].
  - Включается в настройках App, в CLI командой `/remote-control` или флагом `--remote-control`, или как служба: `agy remote-control start` регистрирует systemd unit, LaunchAgent или Windows Scheduled Task [58]. В CLI появился в 1.2.6 по запросу из issues (#556) [113].
  - В dashboard есть переключатель между машинами [58].
  - На одобрения и вопросы можно отвечать с обеих сторон; настройки из веба менять нельзя [58].
  - Страницу можно установить как web-приложение на экран телефона — тогда приходят push-уведомления. Трафик идёт через обратные туннели. Машина должна быть включена и в сети [58].
- **Remote Agents** (v2.29.0, 2026-11-03) — облачные сессии из App, через `agy --remote-agent` или из веба [57][10].
  - «Connect GitHub» по OAuth; репозитории клонируются в удалённую рабочую папку. Можно прикрепить файлы Google Drive и загрузить свои [57].
  - Лимиты загрузки: 8 MiB на файл; 50 файлов и 100 MiB на проект; 2 GiB на аккаунт [57].
  - Только личные аккаунты Pro и Ultra; не Free, не Plus, не бизнес [57].
  - Пресет прав по умолчанию — Turbo, то есть разрешено всё [57].
  - Удалённо недоступны: print mode, `/diff`, `/fork`, `/rewind`, `/btw`, `/voice`, локальные MCP-серверы, плагины и skills [57].
  - Как код возвращается — push, ветка или PR — не описано (не подтверждено) [57].

### Планирование, artifact-ы, комментарии, ревью

- **Artifact-ы** — документы, которыми агент отчитывается вместо лога: task list, implementation plan, walkthrough, verification report, diff, архитектурные диаграммы, изображения, screenshots, записи браузера, интерактивные HTML-виджеты [30][75].
- **`/plan`** (v2.17.0, 2026-09-22) — artifact implementation plan: цель, предлагаемые изменения, diff. Агент всегда ждёт одобрения, какая бы ни была политика ревью: кнопки **Proceed** или ответа в поле ввода — при Always Proceed кнопки на карточке плана может не быть [27][31][34][10].
- **`/grill-me`** — интервью по одному вопросу, к каждому — рекомендуемый ответ; перед вопросами агент читает код. Команды можно связать: `/plan /grill-me <задача>` [28][10].
- **Комментарии к artifact-ам.**
  - Выделенный текст комментируется как в Google Docs. Комментарии прикрепляются к следующему сообщению как chip, например «2 Comments»; дальше — **Proceed** или ответ [31].
  - На screenshot комментарий ставится на область, выделенную мышью [33].
  - Черновики комментариев сохраняются между сессиями (v2.4.3). Markdown можно экспортировать в PDF (v2.19.1) [10].
- **Plan Review Policy:** Request review (в Settings она показана как Always Ask) или Always Proceed [34]. Planning mode создаёт artifact-ы; Fast mode пропускает планирование [34].
- **Walkthrough** — artifact с итогом изменений, выводом тестов, screenshots и записями [32].
- **`/learn`** — превращает уроки сессии в правку rule или skill через artifact `learning_proposal.md`. Файлы меняются только после одобрения [29]. С CLI 1.5.8 команда проверяет лимит размера rule перед дописыванием [112].
- **`/generative_ui`** (2026-08-26) — однофайловые HTML-виджеты в sandbox [35][10].
  - Открываются в side panel или прямо в разговоре, высотой до 500 px.
  - Внешние скрипты запрещены, кроме Tailwind; данные встраиваются при сборке.
- **Review pane и version control** (2026-08-24) [36][89]:
  - виды: Uncommitted, Branch (против `origin/main`), Agent Edits и по отдельным ходам;
  - stage, unstage, discard; commit с сообщением, которое пишет агент, если поле пустое; Amend; Push;
  - комментарий к строке уходит агенту с именем файла и номером строки;
  - в CLI `/diff` — виды All Changes, Per Turn, Commit Tree; клавиша `C` — комментарий.
  - Создание PR и статус CI в UI не описаны [36][89].

### Права, sandbox, автоматическое одобрение

- **Правила вида `action(target)`.** Действия: `read_file`, `write_file`, `read_url`, `execute_url`, `download_url`, `command`, `unsandboxed`, `mcp`. Приоритет: Deny > Ask > Allow [37].
  - Совпадение по префиксу команды отключается, если в строке есть подстановка команд (`$(...)`, обратные кавычки, `<(...)`), перенаправления в сеть или в файловые дескрипторы, флаги вроде `git -c` или если строку не удаётся разобрать. Тогда команда идёт без вопроса, только если правило совпадает со всей строкой, иначе — Ask. Конвейеры, цепочки `&&`, `||`, `;` и простое перенаправление в файл сопоставляются по префиксу как обычно [37].
  - С CLI 1.5.8 команды PowerShell и `cmd` требуют точного совпадения [112].
- **Пресеты App** [37][39]:
  - Request Review — sandbox выключен, спрашивает обо всём;
  - Default — sandbox включён; команды внутри него идут без вопросов, выход из sandbox — с вопросом;
  - Auto — команды, которым нужно выйти из sandbox, оценивает автоматический reviewer: безопасные и обратимые запускаются, необратимые требуют вопроса;
  - Turbo — разрешено всё.
  - Пресет задаётся глобально, на проект или на разговор (v2.30.0); переключатель есть в поле ввода (v2.23.0). Auto вышел из preview 2026-11-09 [10].
- **Режимы CLI** [40]: `default` (diff перед записью, вопрос перед командой), `accept-edits` (правки в рабочей папке без вопросов), `auto` (команды в sandbox без вопросов, выход из sandbox — к reviewer), `plan` (только чтение, сначала план). Переключение — Shift+Tab.
  - `toolPermission`: `request-review`, `proceed-in-sandbox`, `strict`, `always-proceed`; последний равен флагу `--dangerously-skip-permissions` [40].
  - С CLI 1.5.7 (2026-11-12) режим по умолчанию — Auto везде, где он доступен, включая headless-запуски `-p` [112][10].
- **Auto reviewer** — отдельный агент на облегчённой модели Flash (CLI 1.5.4) [112].
  - Проверяет каждую подкоманду конвейера. Короткий ответ вроде «yes» оценивает с учётом вопроса, который агент задал перед ним. Спрашивает перед разрушительными командами git и файлов [112].
  - Перед клонированием репозитория проверяет популярность, возраст и релизы; каждая проверка обрывается через 10 с. Блокирует выгрузку чувствительных данных [112].
  - В SDK это `policy.auto(model=…)` [111].
  - Business и enterprise Auto не получают [37][40]. Уточнение из CHANGELOG: с CLI 1.5.6 Auto доступен pay-as-you-go аккаунтам Google Cloud со входом через ADC (Application Default Credentials); аккаунтам Gemini Enterprise — нет [112].
- **Sandbox ОС**, без VM и Docker [38][16][40]:
  - macOS — Seatbelt (`sandbox-exec`); Linux — namespaces (на странице enterprise назван `bubblewrap`); Windows — AppContainer, для CLI нужна Windows 11 24H2 с обновлением за август 2026.
  - Папки проекта, временные папки и кэши сборки доступны на запись. Всё остальное — по правилам `read_file` и `write_file` [38].
  - Сеть выключена; домены из правил `read_url` попадают в allowlist исходящего трафика [38].
  - Закрыты по умолчанию: `~/.ssh` и `.env` [38]; `~/.docker`, `~/.kube`, `~/_netrc` (CLI 1.4.6, 2026-10-23); на macOS — `~/Library/Application Support` [10].
  - `.git` внутри sandbox доступен только на чтение [10].
  - Сетевой proxy применяет правила по путям. Обходы через `%2F`, обратные слэши и `..` закрыты в CLI 1.5.8 [112].
- **Голос:** разрушительные действия (`rm`, `sudo`, force-push) голосом одобрить нельзя [51].
- **Политики администратора:** браузер, allowlist MCP, пороги прав (v2.5.0) [10].

### Расширяемость

- **Hooks** (`hooks.json`) [41]:
  - события: `SessionStart`, `PreToolUse`, `PostToolUse`, `PreInvocation`, `PostInvocation`, `Stop`;
  - решения `PreToolUse`: `allow`, `auto_approve`, `deny`, `ask`, `force_ask`, `deny_unless_prior_grant`, а также замена аргументов;
  - `Stop` может вернуть `continue`, и агент продолжит работу;
  - timeout по умолчанию — 30 с; hook получает `transcriptPath`.
  - В CLI 1.5.7 закрыта дыра: `auto_approve` обходил проверку администратора [10].
- **Skills** (`SKILL.md`): агент видит название и описание, полный текст читает по требованию; каждый skill — ещё и `/команда` [46]. Agent Skills приняты как открытый стандарт (май 2026); старые workflows переводятся в skills командой `/migrate-workflows` [48].
- **Rules** — `AGENTS.md`, `GEMINI.md` и `.agents/rules/*.md` [47].
  - Триггеры: `always_on`, `model_decision`, `glob`, `manual`.
  - Глобальные и always-on rules делят бюджет 20 000 токенов; один файл — не больше 24 000 байт. При превышении бюджета самые большие rules заменяются однострочной ссылкой [47][10].
  - Разбор расхода токенов показывает rules против бюджета (v2.18.1). AGENTS.md поддерживается с марта 2026 [10].
- **MCP** (`mcp_config.json`) [45]: транспорт stdio или Streamable HTTP; OAuth с PKCE; инструменты загружаются по требованию, флаг `eager` отправляет схему инструмента каждый ход; timeout подключения — 300 с, вызова — 180 с.
- **Plugins** (`plugin.json`) объединяют skills, MCP-серверы, агентов, rules, hooks и sidecars [42][26].
  - Установка из Marketplace, по URL GitHub или из локальной папки; проверка — `agy plugin validate --strict` [42].
  - Плагин может построить свой интерфейс в side panel (v2.22.0) и полноэкранный вид в split view (v2.31.0) [10]. Руководство по созданию плагинов этот API не описывает; схема принимает объект `extensions` [43].
  - Вкладка Customizations и установка плагинов — v2.18.1 (2026-09-28) [10].
- **Marketplace с партнёрами** (v2.28.2, 2026-10-29) [10][92]:
  - Linear, Notion, Atlassian (в описании есть Jira), Figma, Canva, Stripe, Supabase, Vercel, Netlify, Datadog, Sentry, Postman, Zapier и другие;
  - Google Workspace (Calendar, Docs, Drive, Sheets, Slides), Firebase, Chrome DevTools, Google Cloud;
  - на странице от 2026-10-29 около 67 плагинов (подсчёт приблизительный); Slack не назван (не подтверждено).
- **Импорт из других инструментов:**
  - App импортирует MCP-серверы, skills, команды, subagent-ов и инструкции из Claude Code, Codex и Cursor в плагин (v2.30.0) [10][94];
  - `agy plugin import claude` и `agy plugin import gemini` конвертируют плагины Claude Code и расширения Gemini CLI [42][68];

### Надёжность и повторы

- **App** [10]: повторы при перегрузке backend (v2.3.0); кнопка Retry на карточке ошибки продолжает задачу (v2.9.1); временные ошибки повторяются около 12 минут (v2.14.0) с обратным отсчётом в индикаторе загрузки (v2.16.0).
- **CLI** [10][112]:
  - 502, 503, 504, поминутные 429 и оборванные потоки — повтор с экспоненциальной задержкой (1.2.1);
  - учитывает `Retry-After` (1.5.0); пауза между повторами — не больше 30 с (1.3.4);
  - соединение молчит 5 минут — отмена и повтор (1.3.6); обрывы сокета, например после сна ноутбука, — повтор (1.4.1).
- **Что не повторяется** [10]: исчерпание личной квоты сообщается сразу (1.3.3); задержка сервера больше 30 с и дневные или платёжные лимиты останавливают работу сразу (1.2.13); если у ключа API кончилась квота, сессия останавливается немедленно (1.2.12).
- Subagent, остановленный квотой или нехваткой мощностей, показывает `Error:`, а не `Done` (1.3.1) [10].
- Разговоры с активным ходом или фоновыми задачами продолжаются после перезапуска daemon CLI (1.2.4) [10].

- **App:** панель квот со временем сброса в выборе модели (v2.13.0, v2.14.0); разбор расхода токенов (v2.18.1) [10].
- **CLI:**
  - `/usage` (он же `/quota`) — две группы квоты: модели Gemini (Flash и Pro вместе) и модели Claude и GPT; у каждой недельный и пятичасовой лимит [64];

## Принципы и подходы

- **Четыре принципа запуска (2025-11-18)** [75]:
  - **Доверие.** Показывать каждый вызов инструмента или только итоговый diff — оба способа доверия не дают. Antigravity работает на уровне задач: показывает artifact-ы и результаты проверок, а агента подталкивает проверять свою работу [75]. Блог для разработчиков сформулировал это так: проверять по artifact-ам, а не по логам [98].
  - **Автономия.** Синхронный Editor view остаётся. Manager surface переворачивает отношения: не агент встроен в редактор, а редактор, терминал и браузер встроены в агента. Два окна намеренно не объединены; Google сделал быстрым переход между ними [75].
  - **Обратная связь.** Агент, сделавший 80% задачи, полезен, только если оставшиеся 20% дёшево направить. Отсюда комментарии прямо в artifact-ах, которые агент учитывает без остановки. По этой же причине продукт начинался только локальным [75].
  - **Самообучение.** Агент читает и пополняет базу знаний: фрагменты кода, заметки об архитектуре, удачные последовательности шагов [75].
  - Квоты обновляются раз в 5 часов и считают сделанную работу, а не число prompt-ов; Google обещал, что упрутся в них немногие [75].
- **Зачем 2.0 (2026-05-19)** [76]:
  - В ноябре 2025 агентного GUI не было; Agent Manager доказал, что он работает. По словам Google, подход стал стандартом отрасли.
  - Три исходных предположения: программирование расширится на knowledge work; IDE рядом с панелью агентов путает тех, кто не пишет код; продукт, harness и модель надо развивать вместе.
  - Цели: связать harness со стеками обучения и оценки Gemini; перестроить продукт вокруг агента, без понятий IDE и репозитория; добавить CLI, SDK и API.
  - Рекомендация — держать App рядом с любым IDE; Google называет это «dual-wielding».
- **Один harness, обученный вместе с Gemini,** — главный стратегический тезис [11][76][81]. Свести все инструменты Google для разработчиков на один harness — явная цель CLI [80]. Gemini CLI влит в него [101]. Consumer и enterprise работают на одном harness [83].
- **Синхронная и асинхронная работа** (эссе о сборке ОС) [82]:
  - синхронно, с человеком, важно поведение модели: сколько она думает, насколько управляема, насколько экономны её шаги;
  - асинхронно, «запустил и ушёл», важен только интеллект модели;
  - Google признаёт, что асинхронному режиму нужен другой UX, а пока он получает тот же. Открытый вопрос — не станут ли разработчики меньше тестировать и проверять.
  - Демо: ОС, на которой запускается FreeDoom, собранная агентами из одного prompt-а на Gemini 3.5 Flash. 93 subagent-а, 15 314 вызовов модели, больше 2,6 млрд токенов, около $917 по ценам API. Использованы только функции, которые уже есть в продукте [82].
- **Принципы оркестрации:**
  - **Строгое разделение ролей.** Оркестратор только раздаёт работу и никогда не пишет код; отдельные роли для исследования, работы, ревью, атакующих тестов и поиска обмана [82][21].
  - **Контекст и живучесть.** Чтобы не упереться в лимит контекста, оркестратор считает запущенных им subagent-ов и на пороге пишет файлы передачи и запускает преемника [82]; Teamwork запускает нового оркестратора между этапами [21]. Cron-задача следит за временем изменения файлов прогресса; зависшего агента Sentinel убивает и запускает заново [82].
  - **Честность.** Auditor ищет подделанные результаты тестов и mock-фасады. Ранние запуски обманывали, переиспользуя разговоры прошлых запусков. Финальный аудит обязателен перед отчётом об успехе [82].
  - **«Что», а не «как».** Интервью → требования → способ проверки каждого → одно одобрение; дальше команда работает сама [21].
  - **Паттерны — спецификации, а не код.** Логика оркестрации отделена от описаний агентов; число агентов и форма команды меняются по ходу работы [90].
  - **Плоская координация вместо иерархии.** `/swarm` заменяет цепочки subagent-ов, которые Google называет хрупкими и теряющими контекст [95].
  - **Передача между моделями вместо статической маршрутизации.** Маршрутизатор, который выбирает одну модель на задачу, плохо работает на длинных задачах [96].
- **Безопасность через асимметрию:** голосом нельзя одобрить разрушительное действие [51]; `/learn` не меняет настройки без одобрения [29]; `/goal` меняет только момент остановки агента, а не то, что ему разрешено [23].
- **Программирование в центре, но для любой роли** (2026-11-09). Для knowledge workers тот же агент, а не урезанная версия: второй layout просто прячет worktree, diff и терминалы; роль выбирается при первом входе [94].
- **Открытые стандарты, закрытое ядро.** AGENTS.md, Agent Skills, MCP, ACP [10][48][62]; импорт плагинов Claude Code и Gemini CLI [10][68]. CLI закрыт, хотя Gemini CLI был открытым [112]. Issue #4 с просьбой открыть код (195 голосов на 2026-11-13) открыт без ответа команды [113].
- **Позиционирование:** «home base» — основное место для разработки с агентами [75]; единая платформа Google для работы с агентами [77]; единое предложение для разработчиков [80]. TechCrunch (вторичный источник) подаёт запуск 2025 года как ответ на Cursor и похожие инструменты [120].
- **Ключевые понятия** (подробности — в «Функциях»):
  - Editor view и Manager surface (Agent Manager) — две поверхности 2025 года; App — это Agent Manager, ставший отдельным приложением [75][11].
  - Artifact — документ, которым агент отчитывается и который можно комментировать [30].
  - Project — набор папок со своими правами вместо правила «рабочая папка = репозиторий» [76][18].
  - Dynamic subagents — subagent-ы, которых агент сам создаёт по ходу работы [19][78].
  - Sidecar — фоновый процесс под управлением приложения [26]. Automation — задача по cron без открытого разговора [25].
  - Remote Control — своя машина из браузера; Remote Agents — агент в облаке Google [58][57].
  - Уровни многоагентной работы: `/boost` (от секунд до часов), `/swarm` (команда с общей доской), `/teamwork` (часы и дни) [22][20][21].

## Как это устроено внутри

Код продукта закрыт. Устройство видно по открытому SDK, по `CHANGELOG.md` CLI и по документации.

### Один harness и его протокол (по коду SDK)

- **Запуск.** [`google/antigravity/connections/local/local_connection.py`](https://github.com/google-antigravity/antigravity-sdk-python/blob/75ba22bd00afae2f46393ff31f30c3f0df52982f/google/antigravity/connections/local/local_connection.py) запускает бинарник `google/antigravity/bin/localharness` (`.exe` на Windows) [111].
  - Путь ищется по порядку: переменная `ANTIGRAVITY_HARNESS_PATH` → метаданные установленного wheel → `importlib.resources` → `PATH`.
  - В stdin бинарника пишется protobuf `InputConfig` с префиксом длины: папка хранения, данные клиента, окружение. Обратно приходит `OutputConfig` с портом и ключом API.
  - Дальше — WebSocket на `localhost` или `127.0.0.1`, до 5 попыток. Закрытие stdin — сигнал главному циклу harness завершиться.
  - Комментарий в коде говорит о «Go localharness ingress layer», то есть harness написан на Go.
- **Контракт** — [`google/antigravity/proto/localharness.proto`](https://github.com/google-antigravity/antigravity-sdk-python/blob/75ba22bd00afae2f46393ff31f30c3f0df52982f/google/antigravity/proto/localharness.proto), сообщение `HarnessConfig` [111]:
  - `cascade_id` — ID разговора; `session_continuation_mode` — `RESUME`, `CREATE_OR_RESUME` или `CREATE_ONLY`;
  - `initial_trajectory` (trajectory — история шагов одного агента), workspaces, MCP-серверы, модели, `custom_subagents`, `enabled_hooks`;
  - `retry_config`: число повторов, начальная пауза, множитель, jitter;
  - `policy_config`: правила, удержание агента в рабочей папке, `AutoPolicyConfig{enabled, model}`;
  - `budget_config` (лимиты вызовов модели, вызовов инструментов и токенов), `compaction_config`, `skills_config`, `rules_config`, переключатели отдельных инструментов.
- **Поток событий** `OutputEvent` [111]:
  - `StepUpdate` — состояние шага: активен, выполнен, ждёт пользователя, ошибка;
  - `TrajectoryStateUpdate` — с `parent_trajectory_id` и глубиной; состояния `RUNNING`, `FULLY_IDLE`, `CANCELLED`, `WAITING_FOR_TASKS`, `WAITING_FOR_SUBAGENTS`;
  - причины остановки: превышены лимиты вызовов модели, вызовов инструментов или токенов, а также `QUOTA_EXHAUSTED`;
  - запросы на вызов инструментов, вызовы hooks, запросы решения политики, расход по каждой trajectory (`UsageUpdate`).
- **9 lifecycle hooks** в proto: начало и конец сессии, до и после хода, до и после инструмента, ошибка инструмента, сжатие контекста, остановка. Hook остановки получает `continuation_count` и может ответить `CONTINUE` [111].
- **Вложенность subagent-ов:** в proto `max_nesting_depth` по умолчанию 1 [111]; в App — до 10 уровней [19].
- **Другие модули SDK** [111]:
  - [`workflows.py`](https://github.com/google-antigravity/antigravity-sdk-python/blob/75ba22bd00afae2f46393ff31f30c3f0df52982f/google/antigravity/workflows.py) — beta workflows;
  - [`triggers/`](https://github.com/google-antigravity/antigravity-sdk-python/tree/75ba22bd00afae2f46393ff31f30c3f0df52982f/google/antigravity/triggers) — фоновые triggers;
  - [`hooks/policy.py`](https://github.com/google-antigravity/antigravity-sdk-python/blob/75ba22bd00afae2f46393ff31f30c3f0df52982f/google/antigravity/hooks/policy.py) — политики;
  - [`utils/otel.py`](https://github.com/google-antigravity/antigravity-sdk-python/blob/75ba22bd00afae2f46393ff31f30c3f0df52982f/google/antigravity/utils/otel.py) — spans `antigravity.session` → `invoke_agent <имя>` → шаги и subagent-ы.
- **Где лежат данные:** приложения — `~/.gemini/antigravity`, `~/.gemini/antigravity-cli`, `~/.gemini/antigravity-ide`; общие настройки (skills, rules, агенты, hooks, sidecars) — `~/.gemini/config/` [41][26][47]. Лог App на macOS — `~/Library/Logs/Antigravity/language_server.log` [16].

### Цикл агента

- Инструменты, которые видят hooks: `view_file`, `write_to_file`, `replace_file_content`, `multi_replace_file_content`, `grep_search`, `run_command`, `manage_task`, `schedule`, `ask_permission`, `invoke_subagent`, `define_subagent`, `send_message`, `manage_subagents`, `ask_question`, `generate_image` [41].
- Цикл заканчивается по `model_stop`, `max_steps_exceeded` или `error`. Hook `Stop` может вернуть `continue` и запустить цикл снова [41]. На этом построен `/goal` [23].
- Планирование: перед правками — artifact implementation plan; в `/plan` агент всегда ждёт одобрения — Proceed или ответа в поле ввода [31][34].
- Orchestrator переключает модели внутри одной trajectory: план — сильная модель, исполнение — Hydrogen, при трудностях — возврат к планировщику [96].

### Параллельность и координация

- Subagent-ы запускаются через `invoke_subagent`. Фоновый процесс копирует их вывод в журнал прогресса главного агента и опрашивает их, пока все не закончат [78].
- При сжатии контекста сохраняются тип, роль и результат каждого subagent-а (CLI 1.4.3, 2026-10-20) [10].
- `/swarm` — общая доска с упоминаниями, сон без расхода токенов, проверяющий на 2–4 worker-а, monitor на случай общей остановки [20].
- `/teamwork` — исключительное владение файлами, непересекающиеся участки, сменяемый оркестратор [21][82].
- SDK: детерминированные workflows (`phase`, `parallel`, `pipeline`) — альтернатива координации, которую ведёт модель [111].

### Изоляция

- **Worktree:**
  - worktree subagent-ов лежат в папке `worktrees/` данных приложения (CLI 1.2.10, 2026-09-24); раньше — в `.system_generated/worktrees`, где копились брошенные копии до исправления в 1.1.26 [10][112];
  - с 1.5.5 копия включает staged, unstaged и untracked изменения; папки без системы контроля версий копируются целиком, до 100 000 элементов и 4 GiB [112];
  - в проекте из нескольких репозиториев у каждого репозитория своя копия (исправление 1.3.3) [112].
- **Sandbox ОС** — см. «Права, sandbox, автоматическое одобрение» [38].
- **Облако:** Remote Agents — изолированная среда под управлением Google [57].
- **Браузер:** отдельный профиль, у каждого агента своя вкладка [49].

### Состояние и память

- **Сохранение состояния:**
  - App: откат восстанавливает файлы из snapshot (v2.17.0). Внутренние checkpoint-ы используют git; git hooks их блокировали до исправления в v2.14.0 [10].
  - CLI: `/fork` копирует разговор без файлов; `/rewind` откатывает к checkpoint-ам сжатия [67][65].
  - Сообщения в очереди хранятся файлами. Один пустой или битый файл блокировал доставку всех следующих сообщений; исправлено в 1.5.8 [112].
  - SDK: сессию можно продолжить по ID разговора и папке сохранения [111].
  - Automations каждый раз начинают без памяти о прошлых запусках [25].
- **Память и контекст:**
  - Rules с бюджетом токенов; skills по требованию; `/learn` с одобрением [47][46][29].
  - База знаний 2025 года — knowledge items: фрагменты кода, архитектура, последовательности шагов [75]. Сейчас картина неясна: страница `/docs/knowledge` отдаёт 404 [73]; документация всё ещё называет Knowledge основным компонентом [13]; `/context` учитывает файлы знаний [65]; changelog и страница функций упоминают knowledge items в папке данных приложения [10][12]; документация `/learn` говорит, что агенты не помнят разговоры, если знания не записаны в rules или skills [29]. Работает ли автоматический сбор знаний — не подтверждено.
  - Сжатие контекста: старые ходы автоматически сжимаются в checkpoint-сводки; `/compact` — вручную [65][10]. В SDK: `token_threshold`, `checkpoint_interval_tokens`, `max_context_tokens`, свой prompt для сводки, обрезка вывода инструментов [111].

### Проверка качества

- Подход: доверие через artifact-ы и самопроверку агента, а не через лог [75].
- Встроенные проверяющие: `@verifier` в `/swarm` [20]; Critic, Challenger, Auditor, Success Auditor и режимы честности в `/teamwork` [21]; итоговые полные наборы тестов в `/boost` [22]; сверка результатов с доказательствами в `/goal` [23].
- В сборке ОС Auditor запускал статический анализ на подделанные выводы и mock-и; финальный аудит был обязателен [82].
- Git review pane с комментариями к строкам [36].
- Создание PR, интеграция с CI и правила слияния не описаны [36][89].

### Восстановление после сбоев

- Повторы API — см. «Надёжность и повторы» [10][112].
- Надзор: в `/swarm` monitor сообщает об общей остановке, мёртвых worker-ов заменяют новыми [20][112]; в Teamwork устаревшие файлы прогресса ведут к перезапуску агента [82]; sidecars перезапускаются по `restart_policy` [26].
- Headless-запуск при ошибке выходит с exit code 3 и строкой `AGY_ERROR` [10].
- Daemon CLI продолжает разговоры после перезапуска [10].
- Порядок выполнения hooks и поведение при истечении timeout hook-а не описаны (не подтверждено).

### Лимиты и стоимость

- **Форма квоты:**
  - квота считается по группам моделей (Gemini; Claude и GPT); у каждой группы пятичасовой и недельный лимит [64][15];
  - Ultra получает самую большую квоту с обновлением раз в 5 часов; Pro обновляется раз в 5 часов, пока не упрётся в недельный лимит; остальные планы получают недельную квоту [14];
  - считается работа агента, а не число prompt-ов [14][75];
  - с мая 2026 Flash и Pro тратят один общий пул, взвешенный по ценам API; у моделей не от Google отдельный фиксированный лимит из-за нехватки мощностей [79];
  - точные цифры квот не опубликованы (не подтверждено).
- **Кредиты — источники расходятся.** Блог (май 2026): кредиты убраны из базовых планов и работают только как оплата сверх квоты [79]. Страница цен всё ещё обещает Pro и Ultra гибкий пул кредитов AI [2].
- Свой ключ или endpoint для дополнительных лимитов не поддерживается; индивидуальных контрактов нет [14].
- **Когда квота кончилась:**
  - worker `/swarm` встаёт на паузу вместо повторов и **сам не продолжает после обновления квоты**: ждёт сообщения на доске, смены модели или сообщения пользователя [20];
  - browser subagent спрашивает пользователя [49];
  - Teamwork: Google советует купить кредиты и написать «Continue». Даже недельная квота Ultra может кончиться за несколько задач; машина всю работу должна не спать [82];
  - CLI останавливается сразу, а не ждёт (см. «Надёжность и повторы») [10];
  - **функции «дождаться сброса квоты и продолжить» нет ни в одном прочитанном документе** [14][20][82].
- **Время сброса** видно в выборе модели App (v2.14.0) и в `/usage` [10][112].
- **Способы экономить:** Automations по умолчанию на Flash [25]; Orchestrator экономит ~24% квоты на бенчмарке Google [96]; спящие участники `/swarm` не тратят токены [20]; `BudgetConfig` в SDK ограничивает вызовы и токены [111].
- **Пример цены:** сборка ОС — около $917 по ценам API [82].

### Права и безопасность

- Модель прав, sandbox и Auto reviewer — в «Права, sandbox, автоматическое одобрение» [37][38][112]. Автономные Automations запрещают всё, что не записано в их права заранее [25].
- **История проблем** (в основном вторичные источники, IDE 2025 года):
  - **PromptArmor.** Скрытый prompt injection заставил агента прочитать `.env`. Защиту gitignore агент обошёл через `cat`, а данные отправил через browser subagent на webhook.site — он был в allowlist по умолчанию [121]. Дата публикации на странице не указана (не подтверждено); на HN — 2025-11-25 [131].
  - **Rehberger:** удалённое выполнение команд через авто-запуск терминала; MCP-инструменты без одобрения; скрытые Unicode-инструкции; два пути утечки, унаследованные от Windsurf [122].
  - **Mindgard:** rule проекта перезаписывал глобальный `mcp_config.json` и давал постоянное выполнение кода. Google сначала закрыл отчёт как ожидаемое поведение [123], потом обещал публиковать известные проблемы [124].
  - **Known issues.** Google Bug Hunters держит страницу известных проблем; по словам Simon Willison на HN, утечка через браузер там числится известной проблемой [131]. Содержимое страницы не прочитано (не подтверждено) [110].
  - **Стёртый диск.** Агент в режиме Turbo стёр диск D: пользователя [132][125]. Ответ Google — источники расходятся: по The Register, Google сказал, что расследует [125]; в разборе отзывов публичный ответ Google не найден.
  - **Pillar Security — источники описывают по-разному.** CyberScoop: обход Secure Mode через встроенный инструмент `find_by_name`, сообщено 2026-01-06, исправлено 2026-02-28 с выплатой bug bounty [128]. BleepingComputer: обход denylist sandbox на macOS и обход Secure Mode через task в `.vscode`; Google понизил оба как трудные для использования [129]. Одна это находка или разные — не подтверждено.
- **Ответы Google** [10][37]:
  - Secure Mode (2025-12-08), переименован в strict mode (2026-02-03);
  - sandbox на macOS (2026-01-23), Linux (2026-03-25), Windows (2026-09-19);
  - единая система прав (2026-04-07) и новая система прав (v2.14.0, 2026-09-15);
  - Auto с автоматической оценкой команд; загрузки в браузере ждут одобрения;
  - с 2026-02-26 — процесс восстановления аккаунтов, заблокированных за нарушение условий.

Текущие условия называют аккаунты «Antigravity и/или Gemini CLI» [9]. Пользователи HN всё ещё описывают блокировки, которых, по их словам, не заслужили, и запутанный путь назад [149].
- Ноябрь 2026, новая волна [176]: платящие пользователи получили 403 после того, как скрипты или coding assistant вызывали `agy -p` без интерактива, в одном случае — несколько запусков параллельно. Ответ на форуме: одна апелляция на аккаунт, обрабатывается автоматически за 48–72 часа; для внешних инструментов — ключи API.
- Coding-агент oh-my-pi 2026-11-09 отключил провайдера Antigravity: вход через него приводил к ограничению аккаунтов Google [116].
- Своего ключа для дополнительных лимитов нет [14]. Это и отсутствие программного доступа на платных планах пользователи называют причинами не запускать на нём много агентов [147][148].

**Безопасность.**
- Утечка через prompt injection — см. «Права и безопасность» [121]. По словам PromptArmor, Google знал о рисках утечки и выбрал предупреждение в документации [121].
- Стёртые диски: в Turbo агент выполнил рекурсивное удаление пути с пробелами, стёр D:, а потом долго извинялся [132][126]. HN разделился: «сам выключил защиту и не прочитал команду» против «ни одна программа не стирает диск без вопроса». Практический совет — выключить авто-выполнение команд терминала [132]. Второе удаление диска C: в марте 2026 (не подтверждено) [159].
- Права, которые не работали: allowlist команд игнорировался в IDE [140]; headless игнорирует `permissions.allow` (#548); `--sandbox` вместе с `--dangerously-skip-permissions` выходит из sandbox (#36) [113].
- Комментатор в обсуждении OpenGravity утверждает, что ключи хранятся открытым текстом (не подтверждено) [141].

**Качество моделей и смена доступа.**
- Gemini как агент: на запуске Gemini 3 требовал постоянных напоминаний [130]; терял архитектурные решения в запутанном коде, агент Cursor собирал контекст лучше [134]; сообщает о готовности задачи, сделанной наполовину [148]; на проекте из 25 сервисов Flash 3.8 выдумывал API и делал за ~30 минут то, что Gemini 3.1 Pro делал за 7–9 [169]; CLI отказывается от работ по аудиту безопасности [147].
- Смена моделей: Gemini 3.1 Pro исчез из Pro 2026-10-13 [169]; Gemini 4 Argon вышел только для Ultra, по ответу в теме — дошёл до Pro 2026-10-16, принадлежность автора ответа не указана [170]; пользователи Pro из пакета Jio в Индии всё ещё без старших моделей [172].
- Claude внутри Antigravity привлекает людей, но его квота кончается первой [157]. Пересказ с Reddit о слишком низком бюджете рассуждения Opus (не подтверждено) [160].
- Пользователи сомневаются, что subagent-ы координируются без дублирования работы [147]. Просят выбор модели для каждого subagent-а и управление сжатием для headless-оркестрации (#1237, #1316) [113].

**Пробелы платформы и коммуникация.**
- Dev containers: запрос — 152 likes; расширение браузера не работает внутри dev container [155].
- Установка падает на старых CPU и части ядер ARM; проверка по номеру телефона блокирует часть регионов [113].
- Changelog-и расплывчатые, квоты урезают молча, функции вроде inbox убирают без объяснений [158]. Пользователь HN утверждает, что модераторы subreddit удаляли посты о квотах (не подтверждено) [139]. Ответы на форуме читаются как шаблонные [166].

### Почему приходят, почему уходят и куда

- **Приходят:** бесплатный или дешёвый доступ к сильным моделям, включая Claude Opus через план Google [134][115]; ранний доступ к новым Gemini [130]; бесплатный Google One для студентов и пакеты вроде Jio [145][172]; Agent Manager и artifact-ы [130].
- **Уходят:** блокировки по квоте [157][160][144]; нестабильность [156]; принудительный переход на 2.0 [151]; риск бана [138][153]; привычка Google закрывать продукты [130][145]; закрытый код [145][147]; убранные модели [169].
- **Куда:** чаще всего Claude Code [157][139][160]; затем Cursor [144][145], Codex [144], план Go у OpenCode [144], Windsurf [138][144], Pi или oh-my-pi [145][148], Trae [145].
  - Свои замены: OpenGravity — клон от студента, уставшего от лимитов и ошибок (репозиторий теперь отдаёт 404) [141]; открытая IDE для агентов вокруг worktree под названием Harness (не путать с Harness-плагином worfy) [145].
  - Удалённое управление пользователи сначала строили сами: Discord-бот, управлявший приложением через Chrome DevTools Protocol, и web-dashboard по образцу Agent Manager [137]. Потом Google сделал Remote Control (CLI 1.2.6, #556) [113].
  - Auto mode в CLI пользователи тоже просили (#880 и #1021, 28 и 18 голосов); он вышел в 1.3.5 (2026-10-14), но оба issue на 2026-11-13 всё ещё открыты [113][10].

### Сравнения с альтернативами

- **Cursor** держал IDE и окно агентов рядом и связанными, а Google сделал принудительный переход [145]. Вывод одного обзора: бесплатный план хорош для опытов, платить не стоит [134].
- **Claude Code:** Anthropic лучше объясняет лимиты [160]; по оценке пользователя, Claude Max 5x даёт чуть больше квоты Claude, чем Ultra [160]; план Claude за $20 даёт больше, чем план Google за $20 (не подтверждено) [145]; 2.0 воспринимают как копию работы через одно поле prompt-а у Claude Code и Codex [145].
- **Codex:** 2.0 показался пользователям очень похожим на Codex [142][151].
- **Gemini CLI:** одни предпочитали его — открытый код, отдельная квота, постоянные политики команд, hooks расширений; другие называют его сырым и склонным к циклам, а Antigravity — софтом другого класса [145][147].
- **Общее:** к августу 2026 пользователи почти не видят разницы между UI агентов; 2.0 не выглядит новым рядом с Codex и агентом Claude [147]. Комментаторы считают, что отрасль сходится на связке «worktree плюс агенты» [145].
- На `/swarm` и Knowledge Work layout (2026-11-09/10) реакций пока нет [10][150].

## Пересечение с worfy

Факты о worfy взяты из описания продукта, с которым идёт сравнение; факты об Antigravity — со ссылками. Термины worfy: Epic — группа Ticket-ов; Wave — пачка Ticket-ов, которую Autopilot запускает вместе; Gate — локальный запуск проверок перед PR.

- **Где совпадают.** Оба продукта для одного пользователя. Оба запускают много агентов параллельно, каждого в своём worktree. Оба умеют работать без человека, повторяют ошибки API и одобряют действия по политике. Оба поставляют агентам rules, skills, subagent-ов и hooks через плагин. Оба показывают расход квоты.
- **Где расходятся.** Antigravity запускает только свой harness, а модели Claude и GPT-OSS — внутри него; worfy запускает Claude Code и Codex CLI. У Antigravity нет canvas, модели задач, PR и CI в UI, ожидания сброса лимита. В описании worfy нет облачных агентов, голосового управления и Linux-версии.
- FAQ Antigravity называет обёртку `agy` в сторонние приложения на consumer-планах неподдерживаемой [17], условия запрещают использовать сервис вместе с продуктами не от Google [9], а скриптовые вызовы `agy -p` приводили к блокировкам аккаунтов [176].

## Механизмы, которые стоит изучить

1. **Stop hook цели (`/goal`).** Hook не даёт агенту закончить работу, пока цель не доказана. При каждой попытке остановки агенту возвращают прошедшее время, счётчик продолжений и исходный запрос; агент сверяет каждый результат с доказательством — файлом, тестом, логом. Лимита итераций нет; пока работают subagent-ы, продолжение не навязывается [23]. Похожий hook есть в протоколе SDK: `LIFECYCLE_HOOK_STOP` получает `continuation_count` и может ответить `CONTINUE` [111]; JSON-hook `Stop` в App и CLI отвечает `continue` [41]. Что `/goal` внутри построен именно на этом hook-е протокола, документация не говорит (не подтверждено).
2. **Общая доска `/swarm`.** Координация через доску, куда можно только добавлять сообщения. Brief каждого worker-а — чем владеет, чего не трогать, что значит «готово» — лежит на доске. Адресация `@name`, `@group`, `@all`. Спящие участники не тратят токены. `@verifier` на 2–4 worker-а; `@monitor` пишет только при общей остановке; Graph позволяет заново проиграть ход работы [20][95].
3. **Квота как данные и пауза по квоте.** Status line получает JSON с `remaining_fraction`, `reset_time` и `reset_in_seconds` по группам квоты (модели Gemini; модели Claude и GPT) и `cost.total_usd` с учётом subagent-ов — это оценка по прайс-листу, а не счёт [66][64]. В протоколе harness есть причина остановки `QUOTA_EXHAUSTED` [111]. Worker `/swarm` при исчерпании квоты встаёт на паузу, а не повторяет запросы, и просыпается от поста на доске, смены модели или сообщения пользователя; после обновления квоты сам не продолжает [20].
4. **LLM-reviewer только для команд вне sandbox (Auto).** Обычные команды закрывает sandbox ОС, а модель решает только про выход из него. Облегчённая Flash проверяет каждую подкоманду конвейера, оценивает короткое «yes» с учётом предыдущего вопроса, спрашивает перед разрушительными командами git и файлов, перед клонированием проверяет репозиторий (популярность, возраст, релизы, по 10 с на проверку) и блокирует выгрузку чувствительных данных [112][37][40].
5. **Записанные права для автономных запусков.** Automations без человека запрещают всё, что требует одобрения. Пробный запуск записывает точные нужные права в `agent_permissions` (например `command(gh issue list)`); пользователь их проверяет. Дальше автоматизация работает с глобальными правами проекта и этими grant-ами, а всё, что потребовало бы вопроса, автоматически запрещается [25].
6. **Передача между моделями внутри одной trajectory (Orchestrator).** Сильная модель планирует в режиме только чтения, с явными условиями перепланирования; Hydrogen правит код и запускает тесты; при повторных провалах проверки управление возвращается к планировщику. Google заявляет ~24% экономии квоты и ~19% времени на Terminal-Bench 4.1 [96][15].
7. **Режимы честности и Auditor.** Интервью фиксирует запрещённые упрощения; режимы `development` (по умолчанию), `demo`, `benchmark` задают строгость. Auditor статическим анализом ищет подделанные выводы тестов и mock-фасады — защита от «лени» модели; финальный аудит обязателен перед отчётом пользователю [21][82]. Отдельный случай: ранний запуск сборки ОС «сжульничал», подглядывая в неудалённые разговоры прошлых запусков, и после этого Google добавил меры против обмана [82].
8. **Преемник оркестратора и проверка живости по файлам прогресса.** Чтобы не упереться в лимит контекста, оркестратор считает, сколько subagent-ов он уже запустил. На пороге он пишет всё состояние в файлы передачи, гасит свои фоновые задачи, запускает преемника с теми же целями и правами и завершается. Teamwork меняет оркестратора между этапами. Cron-задача проверяет время изменения файлов прогресса; если файл давно не менялся, Sentinel убивает зависшего агента и запускает заново [82][21].
9. **Бюджет rules с понижением.** Глобальные и always-on rules делят 20 000 токенов, файл — до 24 000 байт, длиннее обрезается. При превышении бюджета самые большие rules заменяются однострочной ссылкой, которую агент читает по требованию; расход виден в UI; `/learn` проверяет лимит перед дописыванием [47][10][112].
10. **Комментарии к artifact-ам как chip следующего сообщения.** Комментарии к выделенному тексту или области screenshot копятся как pending и уходят со следующим сообщением (chip «N Comments») или кнопкой Review [31][33]. Блог запуска 2025 года обещал, что такие комментарии учитываются без остановки агента [75]; по текущей документации план из `/plan` ждёт одобрения — Proceed или ответа в поле ввода [31][34]. Черновики комментариев сохраняются между сессиями (v2.4.3) [10].
11. **Типизированные состояния trajectory в протоколе harness.** `TrajectoryStateUpdate` несёт `parent_trajectory_id`, глубину и состояния `RUNNING`, `FULLY_IDLE`, `CANCELLED`, `WAITING_FOR_TASKS`, `WAITING_FOR_SUBAGENTS`, а также причину остановки по лимитам и квоте; `UsageUpdate` даёт расход по каждой trajectory. Клиент SDK получает точное состояние каждого агента и его потомков [111]. SDK работает на том же runtime, что App и CLI [81], но получает ли UI App тот же поток событий — не подтверждено.
12. **Worktree с незакоммиченными изменениями.** С CLI 1.5.5 копия для subagent-а включает staged, unstaged и untracked изменения; папки без системы контроля версий копируются целиком, до 100 000 элементов и 4 GiB; у каждого репозитория проекта своя копия; копии лежат в данных приложения, а не в репозитории [112][10].
