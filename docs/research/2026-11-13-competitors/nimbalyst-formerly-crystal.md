## Модель работы

### Где работает

- **Гибрид, в основном локально.** Приложение local-first: файлы, sessions и база данных лежат на машине пользователя [76]. Промпты уходят только выбранному провайдеру моделей [15][52].
- **Облачные части:**
  - сервер синхронизации и совместной работы `wss://sync.nimbalyst.com` на Cloudflare Workers [76][90][77];
  - web console console.nimbalyst.com для Teams [11][49][50];
  - необязательное удалённое выполнение: headless runner `nimbalyst-node` (запуск агентов без окна приложения) и sandbox Cloudflare в собственном аккаунте пользователя [115][116][117].
- **Шифрование.** Личная синхронизация между desktop и телефоном — zero-knowledge: сервер не видит содержимого. Используются AES-256-GCM и ключи из PBKDF2 со 100 000 итераций [80][51]. Данные команд шифруются ключами, которыми управляет Nimbalyst. Inventory (перечень функций в репозитории) прямо пишет, что это не zero-knowledge [80].
- **Self-host.** Enterprise Beta ставит сервер совместной работы в аккаунт Cloudflare клиента или даёт его как управляемый сервис. Исходники сервера предлагаются только для внутреннего использования компании-клиента [28]. Inventory советует клиентам, которым нужны zero-knowledge данные команды, запускать ПО на своей инфраструктуре [80]. Публичной инструкции по self-host не нашли (не подтверждено).

### Агенты и модели

- **Своего цикла агента нет.** Nimbalyst запускает чужих агентов и показывает их работу [82].
- **12 встроенных lanes.** Lane — способ запуска одного агента или одной модели. Ключи берутся из настроек или из уже выполненного входа в CLI. Из переменных окружения ничего не читается [80][39].
  - **Claude Agent** — по умолчанию. Построен на Claude Agent SDK: MCP, plan mode, sub-agents [82].
  - **Claude Code CLI** — выключен по умолчанию. Запускает настоящий интерактивный `claude` в терминале на подписке Pro или Max, без оплаты по API. Добавлен в 0.65.0 (2026-06-09) [80][74].
  - **OpenAI Codex** — через Codex app-server. Включён по умолчанию на новых установках. Вход через Codex login, API key необязателен [82][39].
  - **Codex через ACP** (Agent Client Protocol — открытый протокол связи редактора с агентом) — экспериментальный [82].
  - **Alpha-lanes:** OpenCode, GitHub Copilot CLI, Grok Build, Cursor Agent и Gemini через Google Antigravity [40][82].
  - **Только чат**, без цикла инструментов агента: Claude API, OpenAI API и LM Studio для локальных моделей [80][82].
  - Расширения могут регистрировать своих провайдеров агентов [1][80].
- **Источники расходятся в том, как подключён Codex.** Changelog в феврале 2026 называет провайдер на Codex SDK [74]. Inventory и страница о подписках говорят «SDK или ACP» [80][14]. Документ о типах провайдеров описывает app-server по JSON-RPC [82].
- **Модели в последних релизах** (названия вендора): Claude Fable 5.2 (0.83.0); Opus, Sonnet и Haiku 5.5; GPT-6.1 Terra и GPT-6.1 Sol для Codex [75][19].
- **Провайдер закреплён за session.** Сменить его посреди session нельзя [82]. Проект может переопределить провайдера; каждая lane сообщает, насколько надёжно она отдаёт список изменённых файлов [80].
- **Детали Claude.**
  - Свои модели берутся из настройки Claude `modelPicker`, для маршрутизации через gateway. Приложение следует только loopback-адресу в `ANTHROPIC_BASE_URL` [80][82].
  - Поддержаны Claude Enterprise SSO и свой путь к исполняемому файлу Claude для корпоративных обёрток SSO [74][39].
  - Есть страница документации про Claude на Vertex и Bedrock [27]. Codex работает на Amazon Bedrock с 0.82.4 [74].
  - Релиз 0.59.1 ставит `CLAUDE_CODE_ENTRYPOINT='cli'`, чтобы трафик подписки по OAuth не получал низкий приоритет как сторонний [74].
  - Переключатель экспериментальной функции Claude «Agent Teams» вынесен в интерфейс. У каждого участника команды агентов свой индикатор прогресса [34].

### Один пользователь или команда

- **Individual** — один человек, аккаунт не нужен [2].
- **Teams** — команда: общие документы и trackers, сообщения, администрирование [2][80]. Проект в Teams — один git-репозиторий. Его узнают по remote `origin` [80][49].
- **Видение компании** — маленькие команды людей, где каждый ведёт своих агентов [3][61].

### Платформы

- **Desktop:** macOS 12+ (Apple Silicon и Intel), Windows 10+ x64 (`.exe`), Linux (`.deb` и AppImage). `.deb` нужен, потому что AppArmor блокирует AppImage на Ubuntu 24.04+ [76][80][21].
- **WSL.** Под WSL приложение работает как Linux-приложение. Вставку и обработку ссылок чинили в 0.82.1–0.82.3 [74]. Нативное выполнение в WSL из Windows-приложения — открытый запрос #26 с 9 голосами [130].
- **iOS и iPadOS.** Компаньон в App Store: продавец Nimbalyst Inc., бесплатно, v1.3.0, iOS 18+ [180].
- **Android.** Нативное приложение есть в репозитории [118]. Changelog в июне 2026 упоминает Android-вариант [74]. Документация вендора пишет, что поддержка Android только планируется [51][23]. Страницы в Play Store не нашли. Публичная доступность не подтверждена.
- **Командная строка:** `nim` (пакет npm `@nimbalyst/cli`) и необязательная команда оболочки `nimbalyst` на macOS [80].
- **Каналы релизов.** README называет stable (по умолчанию) и alpha [76]. Inventory называет stable, beta и alpha [80]. Alpha-функции включают по одной, независимо от канала [40][91].
- **Язык.** Интерфейс только на английском [52]. Запрос на перевод — открытый issue #597 [130].

## Функции

Полный список по зонам продукта. Одна важная поправка к описанию «холст с агентами»: Project Canvas и Mind Map — это редакторы файлов, а не виды sessions агентов. Sessions видны в списке, на Kanban-доске, в строке меню macOS и на телефоне [29][42].

### Режимы рабочего места

- **Четыре режима.** Files — визуальное редактирование файлов. Agent — управление sessions и review. Task — trackers (списки задач). Wiki — страницы [27][4].
- **Multi-project rail** — полоса для переключения между несколькими проектами; добавлена 2026-05-11 [74].

### Окно агента

- **Раскладка.** Слева список sessions с поиском по названию и по содержимому (Search contents). В центре transcript — лента сообщений и вызовов инструментов. Правая панель переключается между Edited Files (изменённые файлы), Review и Chat with Session [29].
- **Новая session** — Cmd/Ctrl+N. Меню кнопки добавляет New Worktree, New Blitz, New Terminal, New Super Loop и New Meta Agent. Набор пунктов зависит от Developer Mode, наличия git и alpha-переключателей [29].
- **Фоновый запуск** — Cmd/Ctrl+Shift+N. В окне запуска выбирают агента, модель и effort, добавляют Actions, slash-команды, упоминания файлов и элементов tracker, картинки. Пользователь остаётся в текущем виде [29].
- **Масштаб.** Вендор пишет, что можно вести «более 10» sessions одновременно [24]. Пользователи сообщают о падениях при 6–10 sessions [142].

### Composer (поле ввода промпта)

- `@`-упоминания файлов, подсказки slash-команд и skills [80].
- Сохранённые наборы промптов «Actions» в файле `nimbalyst-local/ai-actions.md` [80].
- Вложения-картинки и «чипы» выделенного фрагмента из редакторов [80].
- **Очередь сообщений.** Сообщения, отправленные пока агент работает, ставятся в очередь. С 0.83.0 они доставляются вместе, одним ходом, и у каждого подписан автор: человек или другая session [75][74]. До 20 сообщений из очереди склеиваются в один промпт [108].
- Подсказка следующего промпта, которую подставляет Tab [80].

### Модели, effort и plan mode

- Выбор модели для каждой session — Cmd/Ctrl+Shift+M [80][29].
- Уровни effort, в том числе «Ultra» для Codex. Включение и выключение extended thinking. Plan mode по Shift+Tab [80][29].

### Запросы к человеку

- **Пять видов интерактивных запросов** [80][84][74]:
  - AskUserQuestion — вопрос агента с вариантами ответа;
  - PromptForUserInput — структурированная форма ввода (с 2026-05-09);
  - ExitPlanMode — одобрение плана;
  - GitCommitProposal — предложение коммита;
  - ToolPermission — разрешение на вызов инструмента.
- **Они переживают перезапуск приложения.** Запрос хранится в базе данных, а не только в памяти процесса [80][84].
- На эти запросы можно ответить с телефона [80][51].

### Review правок

- **Diff по вызовам инструментов.** Каждый вызов, который меняет файл, показан как красно-зелёный diff. Есть баннер «ожидает review» и кнопки approve all и reject all [80].
- **Review в отрисованном документе.** В визуальных редакторах правки принимают или отклоняют по блокам прямо в документе, а не в текстовом diff [76][62].
- **Diff-режим редакторов.** Можно принять или отклонить правки по каждому файлу. Для CSV правки видны по ячейкам, для mockup есть ползунок «до/после» [80].
- **Правка попадает на диск до review.** Документ о слежении за файлами описывает правки как ожидающие review [86]. Issue #1335 и страница документации о red/green diff показывают, что файл к этому моменту уже изменён на диске [148][45].

### Операции с session

- Переименование и автоматическое имя, pin, теги, фаза, ветвление (fork), архив, удаление, экспорт в HTML [80].
- Ссылки для просмотра session с end-to-end шифрованием, сроком жизни 1, 7 или 30 дней [80].
- Сохранённые черновики и состояние «прочитано/не прочитано» [80].

### Внешние sessions CLI

- **Импорт.** Ручной импорт sessions Claude Code CLI; нужен Claude Code 2.1.x+. Повторный импорт безопасен: session с новыми сообщениями помечается «Has Updates» [33].
- **Живое слежение** за внешними sessions Claude Code и Codex CLI — по желанию, выключено по умолчанию [80].

### Kanban sessions

- **Доска** — Cmd/Ctrl+Shift+K. Колонки: Backlog, Planning, Implementing, Validating, Complete [29].
- При наведении на карточку виден живой предпросмотр session [29].
- Агенты сами ставят session имя, теги и фазу через внутренний MCP tool [80].
- Только человек переводит session в Complete [81][80].
- Команда `/session-cleanup` предлагает исправить фазы и архивировать устаревшие sessions [80].
- Своих названий колонок нет. Это открытый запрос #82 [130].
- Пользователь сообщает, что карточки на доске расходятся с настоящим состоянием sessions (issue #1849) [150].

### Workstreams и деревья sessions

- **Workstream** — группа связанных sessions. Они показаны вкладками с общим видом изменённых файлов. Команда `/launch-new-session` запускает соседнюю session [30].
- Sessions вкладываются в деревья, активность детей суммируется у родителя. Именованный контейнер-папка «workstream» пока только в разделе Unreleased ветки main [80][74].
- **Правила дерева** [74][85]:
  - глубина до 256 уровней;
  - session, которая запустила другую, — её «manager» и получает её отчёты о завершении;
  - режим отчёта: нет отчёта, только финальный ответ или сообщения по ходу работы.
- **Отчёта по умолчанию нет.** Заметки по функциям относят это изменение к версии 0.82.1, заметки по развитию — к изменениям от 2026-10-23 [74][85].
- Смысл слова workstream менялся несколько раз: сначала worktree (май 2026), потом вложенное дерево (октябрь), теперь контейнер для равноправных sessions (unreleased) [74][80].

### Наблюдение и уведомления

- **Значок внимания** группирует sessions: Awaiting input (ждут ответа), Running, Unread. Кнопка «Mark all read» ничего не одобряет [29].
- **Уведомления на desktop.** Уведомления ОС, по умолчанию — о завершении [39]. Агент может сам запросить уведомление, с ограничением частоты, через `notify_user` [80][93]. Звуки завершения: chime, bell, pop или свой аудиофайл [39].
- **Строка меню macOS.** Полоса «fleet» называет sessions, когда они стартуют, заканчивают, блокируются или падают, и отмечает те, что перестали отвечать. Её панель умеет отметить всё прочитанным [74][29].
- **Badge** на Dock в macOS; иконка в tray на Windows и Linux [80][74].
- **«Не отвечает».** Признак ставится, если ход агента молчит 15 минут [108].
- **Телефон.** Push-уведомления о завершённых, упавших и ждущих sessions. Пока пользователь активен на Mac, push не приходят [51][23]. iPhone Live Activity и Dynamic Island ранжируют sessions по тому, как долго они ждут человека [80].

### Счётчики лимитов и расхода

- **Popover расхода Claude.** Полосы для session (5-часовое окно) и для недели. С 0.78.0 — недельные лимиты по отдельным моделям и время сброса. Кольцо расхода в левой колонке окна [74].
- **Другие провайдеры.** Счётчик Codex с окнами 5 часов и 7 дней, который подстраивается под переменную длину окна. Чип расхода Gemini [74].
- **Недельная история** (0.82.6, 2026-11-03). График расхода против линии равномерного темпа и итоговый процент каждой прошлой недели. История пишется локально и только пока приложение запущено [80][74].
- **Счётчики контекста.** Заполнение context window с отслеживанием темпа и необязательная полоса контекста под каждой строкой списка sessions [80]. При этом THE_HARNESS.md, внутренний документ команды о «harness», называет монитор context window отсутствующим [81].
- **AI Usage Report** (меню Window). Итоги по токенам, тепловая карта активности, карточки по проектам. Вкладка Tools показывает число вызовов инструментов и кнопку backfill — дозаполнение истории. Стоимости и лимитов в отчёте нет; он отсылает к панелям провайдеров [32]. Совпадает ли описание страницы с кодом — не подтверждено [32][114].
- **Карточки лимита** в transcript: жёлтая «rate limit warning» и красная «blocked» [80].

### Уровни автономии (разрешения агента)

- **Четыре уровня** в диалоге доверия при первом открытии проекта: Agent-verified, Allow everything, Allow edits only, Ask every time. Agent-verified стоит по умолчанию с 0.70.2 (2026-07-21) [83][74][38].
- **Agent-verified** пропускает рутинную работу без вопросов. Рискованные действия он передаёт встроенному автоматическому проверяющему самого провайдера. У Claude это классификатор auto-mode из SDK (`permissionMode: 'auto'`). У Codex — `approvals_reviewer = "auto_review"` с режимом `workspace-write` и одобрением по запросу. То, что проверяющий не пропустил, приходит человеку [38][83][103][104].
- **Allow everything** — без вопросов и без проверки. **Allow edits only** — разрешены правки файлов; для Codex это режим `workspace-write` [83][104].
- **Ask every time.** Инструменты только для чтения одобряются сами. На остальное есть выбор: Deny, Allow Once, Session, Always. «Always» сохраняет правило в `.claude/settings.local.json` [38][83].
- **Область доступа.** Файлы по умолчанию доступны только внутри рабочей папки. Дополнительные папки и шаблоны URL — явные разрешения. Одобрения с телефона работают через опрос сохранённых строк запросов и ответов [83].
- **Жёсткие правила поверх уровней** [38][83]:
  - `~/.ssh` и `~/.aws` закрыты всегда;
  - веб-доступ идёт через allowlist адресов;
  - составные shell-команды одобряются только разово;
  - в недоверенном проекте все действия агента запрещены.
- **0.82.0 (2026-10-23).** При «Allow everything» с проверками Agent-verified hook, который просит одобрения, теперь ждёт человека [74].

### Meta Agent (alpha, выключен по умолчанию)

- **Что это.** Тип session-оркестратора; появился в 0.57.7 (2026-04-02). Встроенная инструкция: агент сам не трогает код, а планирует, раздаёт работу, следит и координирует [74][92][91].
- **Как выглядит.** Пункт New Meta Agent в меню новой session, если включён alpha-переключатель [29][91]. Meta Agent sessions можно создавать и с iOS и Android [80].
- **Инструменты** на MCP-сервере приложения [93]:
  - `list_worktrees`, `create_session`, `spawn_session`;
  - `get_session_status` и `get_session_result`; полный ответ ребёнка обрезается до 50 000 символов;
  - `consume_session_inbox`, `list_queued_prompts`;
  - `send_prompt` — может прервать текущий ход ребёнка;
  - `notify_user` — при срочности «critical» отправляет push на телефон;
  - `respond_to_prompt` — отвечает на запрос ребёнка: разрешение, вопрос или выход из plan mode;
  - `list_spawned_sessions`.
- **Сам отвечает на запросы детей.** Инструкция велит всегда одобрять разрешения детей на уровне session, одобрять планы, совпадающие с задачей, и отвечать на вопросы детей или передавать их человеку [92].
- **Правила поведения из инструкции** [92]:
  - запускать как можно меньше детей;
  - считать доказательством список изменённых файлов и область инструментов ребёнка, а не его текстовый отчёт;
  - после полезных находок писать ответ, а не запускать новых детей.
- **Пресеты процесса** [92]:
  - `default`;
  - `implement-review-test` — для каждого куска работы по очереди идут session реализации, session review и session тестов; пресет работает сам и не задаёт человеку вопросов;
  - `research`.

  Пресет ставит сам агент через tool метаданных session. Переключателя в интерфейсе не нашли (не подтверждено).
- **Лимиты.** Не больше 4 детей в работе одновременно и не больше 50 за жизнь родителя (`MAX_IN_FLIGHT = 4`, `LIFETIME_BACKSTOP = 50`). Запросы детей, которые ждут ответа или выполняются, тоже считаются в эти четыре. Глубина дерева — до 256 [94][85].
- **Сам Meta Agent не может править файлы.** Его sessions идут со списком разрешённых инструментов. Встроенные Read, Write, Edit и Bash у Claude и Codex запрещены. `spawn_session` в этот список не входит [102].
- **Дети наследуют провайдера и модель родителя** [74].
- **Worktree детей — источники расходятся.**
  - Заметки по функциям: worktree для ребёнка необязателен и задаётся параметром [92][93][94][85].
  - Заметки по устройству, по чтению кода: `create_session` игнорирует аргументы worktree. Такие дети всегда работают в общей папке, чтобы родитель видел их файлы. `spawn_session` работает в папке вызывающего и делает worktree только по запросу (`useWorktree=true`) [93].

### Super Loops (alpha)

- **Что это.** Автономный цикл по одной задаче в своём worktree. Появился в 0.52.69 (2026-02-14). Changelog пишет, что идея взята у «Ralph loops» — приёма, когда агента много раз подряд запускают с той же задачей и чистым контекстом, а прогресс хранят в файлах [74][34][96][80].
- **Как работает.** Каждая итерация начинается с чистым контекстом и читает свои файлы прогресса. Задача лежит в `.superloop/task.md`, рядом `IMPLEMENTATION_PLAN.md` и `.superloop/progress.json`. Фазы: planning, затем building [34][96].
- **Настройки.** Модель и предел итераций, по умолчанию 20 [80][96].
- **Как выглядит.** Панель прогресса показывает фазу, номер итерации, выученное (learnings) и блокеры. Кнопки: pause, resume, stop, force-resume. Заблокированный цикл показывает виджет обратной связи и продолжает работу после ответа человека [80][96].
- **Защита** [96]:
  - один активный цикл на worktree;
  - после 3 неудачных итераций подряд цикл останавливается; паузы между попытками — 5, 10 и 20 секунд;
  - при перезапуске приложения идущие циклы ставятся на паузу, а брошенные итерации помечаются неудачными;
  - таймаута на одну итерацию нет.

### Blitz (alpha)

- **Что это.** Один и тот же промпт запускается в нескольких изолированных worktree, до 10 (`MAX_BLITZ_WORKTREES = 10`). Появился в 0.52.68 (2026-02-13) [74][97][80].
- **Сравнение.** Когда все попытки закончились, автоматически стартует session-анализ. Она сравнивает результаты через `get_session_summary` и `get_workstream_edited_files` и рекомендует победителя [97][80].
- **Model blitz** — Blitz, где попытки идут на разных моделях. Такие Blitz называются по именам моделей [80][40].

### Agent Teams (экспериментальный переключатель)

- **Что это.** Переключатель экспериментальной функции Claude «Agent Teams»: один агент раздаёт работу помощникам (teammates). Поддержка появилась 2026-02-06 [74][34].
- **Как работает.** Nimbalyst перехватывает инструменты команды Claude. Hook PreToolUse ловит вызовы `Task` с `team_name` и вызовы `SendMessage` и отклоняет их. Вместо этого каждый помощник запускается внутри процесса через `query()`. Состояния помощника: running, idle, completed. Сообщения идут через `streamInput()`, запасной путь — inbox в файле [88][34].
- **Как выглядит.** У каждого помощника свой индикатор прогресса [34].

### Crew (alpha, с 0.79.0)

- **Что это.** Постоянные «персоны» агентов, описанные в папке `nimbalyst-local/crew/`. У каждой есть роль, заметки, журнал, расписание смен (по неделям или с интервалом), уровень уведомлений (note, flag, page), тихие часы и бюджет токенов с учётом токенов cache [80][98].
- **Как работает.** Смена — обычная session. Команда `/crew:hire` проектирует нового участника по описанию должности [80][98].
- **Бюджеты по умолчанию.** 60M токенов в неделю и 6 смен в день на участника; 600M токенов в неделю на всю команду. Участник начинает новую «главу» (chapter), когда контекст заполнен на 70% или прошло 7 дней [98].
- **Ограничения.** Только desktop. Работает, только пока проект открыт. Пропущенный запуск срабатывает один раз при повторном открытии [80][98][74].

### Automations

- **Что это.** Markdown-файлы в `nimbalyst-local/automations/`. Во frontmatter — расписание: ежедневно, еженедельно или каждые N минут. Результат: новый файл, дописать в файл или заменить файл. Провайдер и модель — необязательные поля [31][99].
- **Как выглядит.** Команда `/automation` создаёт автоматизацию; новые создаются выключенными. «Run Now» запускает сразу. У каждой есть `history.json` со ссылками на session, которая её выполнила [31].
- **Ограничения.** Работают, только пока приложение открыто. Пропущенные запуски не догоняются. Папка сканируется каждые 30 секунд [31][99].

### Wakeups, auto-resume и перезапуск

- **Wakeup** — отложенное «разбудить session». Агент сам планирует его через `schedule_wakeup` на срок от 60 секунд до 7 дней (с 0.58.5, 2026-04-28) [80][29][74].
  - Wakeup переживает перезапуск. Он показывает баннер с кнопками Fire now и Cancel и срабатывает, только пока приложение запущено [80][29][109].
  - Wakeups, просроченные к запуску приложения, показываются человеку, а не срабатывают сами [109].
- **Auto-resume после сброса лимита Claude.** Включается по желанию, есть с 0.81.1 [80][74].
  - По коду: wakeup ставится через минуту после сброса, sessions разносятся на 30 секунд друг от друга, сброс дальше 7 дней пропускается. Session получает «Continue.» и системную пометку о причине остановки. Любой новый ход отменяет auto-resume [106].
  - Код покрывает только lane Claude Agent [106]. По release notes нельзя подтвердить, касается ли функция lane Claude Code CLI и Codex [71].
- **Перезапуск приложения.**
  - Inventory и changelog пишут, что sessions продолжают работу сами. Приложение откладывает свой перезапуск, пока sessions активны. Сообщения из очереди, в том числе отправленные с телефона, выполняются сами [80][74].
  - Для lane Claude Code CLI с 0.65.0 после перезапуска возобновляется только session в фокусе. Так одновременный перезапуск всех sessions не упирается в rate limit подписки [74].
- **Не найдено** в inventory и changelog (отсутствие не подтверждено) [80]:
  - автоматический повтор ошибок API;
  - планирование запусков под окна подписки;
  - экономный режим расхода токенов.

  Ближайшее — панель Tools & Token Cost: для каждой группы инструментов выбирается загрузка сразу или по требованию [80].

### Worktrees

- **Нужен Developer Mode** — переключатель, который открывает функции для разработчиков: worktree, terminal, review PR [80][35].
- **Создание.** Cmd/Ctrl+Alt+W, из элемента tracker или из PR. Несколько sessions могут делить один worktree [80][35].
- **Где лежат.** Через simple-git в `../<project>_worktrees/<name>`, на ветке `worktree/<name>` [111].
- **Операции** [80][35][111]:
  - merge в базовую ветку: нужно чистое дерево, берётся lock;
  - rebase с автоматическим stash;
  - диалог squash;
  - проверка конфликтов перед merge и кнопка «Resolve with Agent» — конфликт разрешает агент;
  - архив с фоновой очисткой, которая повторяется при старте приложения;
  - pin и переименование.
- **У каждого worktree свой терминал** [80][35].
- Документ `docs/WORKTREES.md` последний раз менялся 2026-01-12 и отстаёт от кода [89].

### Git panel

- **Список изменений.** Коммит вручную или «Commit with AI», с выбором отдельных hunk [80].
- **Auto-commit** — переключатель, который пропускает одобрение предложенного коммита [80][110].
- **Коммит в другой worktree** агент может только предложить. Такое предложение всегда требует одобрения на desktop, даже при включённом auto-commit (с 2026-10-23) [80][110][74].
- **История коммитов** со счётчиками ahead/behind и ссылками на sessions, которые сделали каждый коммит. Связь git log с sessions — с 0.73.0 (2026-08-11) [80][74].
- **Связь с tracker.** Сообщение коммита вида «Fixes NIM-123» автоматически закрывает связанный элемент tracker [110].
- **Несколько репозиториев в проекте** поддержаны [80].
- **Очередь git-операций.** Деструктивные git-операции в одном репозитории идут по одной через `GitOperationLock` с таймаутом 30 секунд [111].

### Режим review PR

- **Когда появился.** 0.64.5 (2026-06-06) [74][36].
- **Как открыть.** Cmd/Ctrl+U. Нужны Developer Mode и GitHub или GitHub Enterprise через `gh`. Токены не хранятся [36].
- **Фильтры:** Open/Closed, Awaiting my review, Created by me, With conflicts, Draft, Review Status [36].
- **Вкладки:** Conversation, Files Changed, Commits, Checks. Checks опрашиваются, а не приходят в реальном времени: раз в 60 секунд, пока окно активно, и раз в 5 минут в фоне. Check runs CI берутся через `gh` [36][112].
- **«Review with AI»** открывает одну session агента с промптом только на чтение [113]:
  - прочитать PR через `gh pr view` и `gh pr diff`;
  - искать ошибки корректности, регрессии, недостающие тесты и нарушения соглашений;
  - ответить строкой рекомендации, затем списком находок с файлом и строкой.
- **Другие действия.** «Open in Worktree», связь с элементами tracker, approve и merge (squash, merge или rebase, всегда с подтверждением). Merge может продвинуть связанные элементы tracker [80][36].
- **Ограничения** [36][130]:
  - нельзя писать inline-комментарии и запрашивать изменения (request changes);
  - только GitHub; запрос на GitLab открыт (#1488);
  - экрана создания PR не нашли (не подтверждено).

## Принципы и подходы

### Миссия и «почему»

- **Миссия** — помочь людям хорошо работать с агентами и друг с другом. **Видение** — маленькие подвижные команды людей, которые плотно работают друг с другом и со своими агентами [3].
- **Страница About построена на пяти противопоставлениях** [3]:
  - цель — не оркестровка агентов ради неё самой, а люди и агенты, работающие вместе;
  - вместо терминала — визуальный интерфейс;
  - вместо агентов, прикрученных к старым инструментам, — одно рабочее место;
  - вместо работы в одиночку с агентами — команды с агентами;
  - вместо lock-in — open source и локальные файлы.

### Шесть убеждений

Они повторяются на главной, на странице About и в посте об открытии кода [1][3][62]:

1. Визуальный интерфейс передаёт человеку больше всего информации.
2. Каждый становится менеджером агентов.
3. Общий контекст должен жить в одном графе.
4. Открытые форматы, open source, локальные файлы.
5. Работа прямо в документе: review, комментарии и правки AI живут внутри него.
6. Шестое убеждение менялось. В апреле 2026 это было «расширяй и меняй своё рабочее место» через платформу расширений [62][3]. На нынешней главной — «владей своим harness и вкладывайся в него» [1].

### Откуда это пришло

- **Январь 2025.** stravu.com — лист ожидания продукта для командной стратегии и принятия решений с AI [191].
- **Июнь–октябрь 2025.** Stravu — облачный командный «AI notebook» на AWS [191]:
  - текст, таблицы, диаграммы, графики 2x2 и формулы;

- **The $0 office suite** (2026-02-16). Бесплатная локальная замена документам, таблицам, диаграммам и trackers с AI внутри. Деньги планируются от командных функций [58].
- **6 Agents, 1 Manager, 0 Chaos** (2026-02-27). Панель sessions, worktree и review до push. Управлять агентами — новый навык, для него нужны свои инструменты [59].
- **Context is the new code** (2026-03-01). Качество результата зависит больше от контекста (specs, wireframes, модели данных, тесты), чем от промпта. Review контекста становится новым code review [60].
- **The future is small teams** (2026-03-07). Победят команды из 3–7 человек, где каждый ведёт агентов. Стоимость координации растёт как n(n−1)/2, и агенты делают эту проблему хуже [61].
- **Интеграция** (2026-05-12 и 2026-05-19). Сделать в одном месте ту часть каждого SaaS-инструмента, которая важна: trackers, документы, диаграммы, mockup, код, sessions; позже ветки сообщений. Связать всё связями с типом [63][64].
- **The agent harness** (2026-05-20, обновлено 2026-07-15) [65][5][6][7]:
  - harness — долговечный слой, которым команда владеет поверх harness вендоров (Claude Code, Codex);
  - восемь опор: context, provenance, capability, workflow, restraint, verification, visual interface, coordination;
  - Blueprint — шаблон, который можно скопировать; Benchmark Protocol оценивает прогон из 100 баллов: correctness 40, verification 20, policy adherence 15, context efficiency 10, recovery 10, provenance 5; результатов не опубликовано;
  - страница ссылается на неназванные исследования Stanford и Tsinghua о шестикратной разнице в качестве только из-за harness.
- **Claude Code Desktop vs Nimbalyst** (2026-06-01). Это разные слои. Официальное приложение получает функции первым и лучше для глубокой работы в одной ветке разговора. Nimbalyst управляет всем набором sessions [66].
- **MCP is not a workspace** (2026-07-29). MCP даёт агентам доступ к другим инструментам, но не хранит связи между элементами. По замеру компании ответ на один вопрос через Slack, GitHub и Linear стоит примерно в 12 раз больше токенов, чем одно чтение из общего workspace. С Google Docs — примерно в 30 раз, с Figma — примерно в 40 раз [67].
- **Приоритеты** (2026-08-18). С агентами объём реализации больше не главное ограничение. Каждой области функций дают стратегию: Differentiate, Do, Unsure или Not Do. Каждой функции — оценку риска. Функция низкого риска в области Do не требует участия продакт-менеджера [68].
- **Agentic development environment** (2026-08-19). Узкое место — review. Планы, которые агенты не могут прочитать, устаревают. Orca и Emdash названы соседями по категории [69].
- **Wiki** (2026-10-02). Агенты сжимают свою работу в короткую wiki для человека. Агент пишет, человек читает и правит. Агент никогда не выдумывает решения и цитаты [70].

### Чем подход отличается

Пункты собраны из заявлений вендора; формулировки — наши.

1. **Review правок AI в отрисованном документе, по блокам.** Это наследие Stravu [62][76][191].
2. **Не-кодовые артефакты — полноценные файлы, которые агенты читают и пишут:** mockup, модели данных Prisma, Excalidraw, Mermaid, таблицы, листы расчётов, доски [76][80].
3. **Provenance** — запись того, откуда взялся результат. Правки файлов, sessions и элементы tracker связаны в обе стороны. С 0.73.0 git log показывает, какая session AI сделала коммит. Заголовок редактора показывает последнюю session, которая трогала открытый файл [81][74].
4. **Обычные файлы и открытые форматы.** Определения trackers — YAML, документы — обычные файлы. Граф можно смотреть без приложения [8][76].
5. **Независимость от вендора агента.** 12 lanes, пользователь приносит свой доступ. Компания пишет, что не перепродаёт токены и не обходит лимиты [80][14].
6. **Одобряют люди, по правилу.** Агенты не закрывают session. В review lane одобряет только человек. Коммит в другой worktree всегда требует одобрения на desktop, даже с auto-commit [81][80].
7. **Multiplayer и мобильность — центральные ставки.** Общие документы и trackers с присутствием, сообщения и inbox организации, iOS и Android, Live Activities, список sessions в строке меню macOS [10][80].

### Отношение к автономии

- **Автономные функции есть, но все — по желанию или alpha.** Super Loops, Blitz и Meta Agent закрыты alpha-флагами и выключены по умолчанию [91]. Crew — alpha, работает только на desktop и только пока проект открыт [80][98]. Agent Teams — экспериментальный переключатель, выключен по умолчанию [34].
- **Своей политики разрешений нет.** Уровень по умолчанию Agent-verified отдаёт рискованные действия встроенному проверяющему вендора [83].
- **Собственный процесс команды автоматизирован сильнее, чем продукт** [79]:
  - команда `/orchestrate` в репозитории запускает соседние sessions с явным выбором модели;
  - у каждого куска работы своё, непересекающееся владение файлами;
  - reviewers независимые и работают на другой модели;
  - ведётся журнал прогона;
  - session-оркестратор раз на пачку запускает gate: `pnpm typecheck` и тесты перед push;
  - git hooks держат жёсткие правила.
- **Чего не хватает, по их же документу THE_HARNESS.md** [81]:
  - автоматического reviewer перед коммитом;
  - обязательного шага «сначала падающий тест»;
  - обнаружения конфликтов между параллельными sessions;
  - повтора (replay) упавших sessions.
- **Самоулучшение.** Команда разбирает прошлые sessions командой `/analyze-sessions`, чтобы улучшать свой harness [81].

### Цикл агента

- **Своего цикла агента для главных провайдеров нет.** Nimbalyst запускает агента вендора и переводит его события в один формат transcript [82]:
  - `claude-code` (Claude Agent) — `@anthropic-ai/claude-agent-sdk` внутри процесса приложения;
  - `openai-codex` — Codex app-server, JSON-RPC по stdio; вариант через ACP закрыт экспериментальным переключателем;
  - `opencode` — локальный сервер OpenCode по HTTP/SSE (alpha);
  - `copilot-cli` и `grok-build` — ACP по stdio; `cursor-agent` — один headless-процесс NDJSON на ход; все три alpha;
  - чат-провайдеры `claude`, `openai`, `lmstudio` — без цикла работы с файлами.
- **Общий базовый класс** для alpha-агентов держит предусловия, проверку разрешений на каждый ход, сохранение сырых событий и прерывание [101].
- **Gemini** работает через language server Antigravity. Этот транспорт не хранит состояние и не умеет function calling. Поэтому Nimbalyst даёт свой цикл инструментов и каждый ход заново собирает весь разговор в один промпт [101].
- **Провайдер фиксируется**, как только в session появились сообщения [82].
- **Как запускается SDK — источники расходятся.** Документ о провайдерах пишет, что SDK работает внутри процесса [82]. Сооснователь в issue #1177 говорит, что каждый ход — отдельный процесс CLI, запущенный с `--resume` [133].
- **Lane Claude Code CLI** (0.65.0) [100][74]:
  - запускает интерактивный бинарник `claude` в PTY (терминал ghostty-web), никогда в режиме печати `-p`;
  - `--session-id` равен собственному id session в Nimbalyst; при перезапуске используется `--resume`; `--mcp-config` несёт loopback-адреса, в которых закодирована session;
  - разрешения: `--settings` вставляет hook PreToolUse для `Bash|Edit|Write|MultiEdit|NotebookEdit|WebFetch` с таймаутом 600 секунд; hook вызывает loopback endpoint `/permission`; в режимах «разрешить всё» вместо этого ставится `--dangerously-skip-permissions`; комментарий в коде говорит, что интерактивный CLI молча игнорирует `--permission-prompt-tool`;
  - `--disallowedTools AskUserQuestion` направляет вопросы в собственный MCP tool Nimbalyst; ещё ставятся `--append-system-prompt` и `ENABLE_TOOL_SEARCH=true`; из окружения убираются `ANTHROPIC_API_KEY` и `CLAUDECODE`;
  - transcript: `ANTHROPIC_BASE_URL` указывает на loopback proxy; proxy передаёт трафик в Anthropic и копирует поток SSE байт в байт; заголовок OAuth проходит, не читаясь; proxy сообщает об ответах 429 и 529;
  - ошибки делятся на классы context_limit, rate_limit, overloaded, auth, api_error и generic.
- **Чем оплачивается путь SDK — не подтверждено.** Источники расходятся:
  - документ о провайдерах: вход через Claude CLI или аккаунт, сохранённый ключ необязателен [82];
  - комментарий в заголовке CLI-провайдера: путь SDK оплачивается по API key пользователя [100];
  - CEO в обсуждении #417 (2026-06-10): два варианта — SDK с API key или CLI с подпиской [138];
  - справка Anthropic: при входе по подписке SDK расходует лимиты плана; июньские изменения приостановлены [181].
- **Tools.** Собственные MCP-серверы Nimbalyst работают по HTTP/SSE на 127.0.0.1 [81][103]:
  - ядро `nimbalyst` грузится сразу: AskUserQuestion, PromptForUserInput, display_to_user, update_session_meta;
  - остальные грузятся по требованию через ToolSearch Claude: `nimbalyst-host`, `nimbalyst-trackers`, `nimbalyst-situational` и по одному серверу на расширение.
- **Защита loopback.** Каждый запуск приложения генерирует случайный 32-байтный bearer token, который живёт только в памяти. Он не даёт веб-страницам вызывать локальные серверы [105].
- **Plan mode.** Планирование идёт через plan mode провайдера. Файлы планов пишутся в `nimbalyst-local/plans`. ExitPlanMode — durable prompt, на который отвечает человек [103][84].

### Декомпозиция задач

- **Kanban.** Sessions идут по фазам; в complete переводит только человек [81]. Смены фаз пишутся в историю [110].
- **Trackers.** Планы, bugs и features — элементы с типом. Коммит с сообщением вида «Fixes NIM-123» закрывает связанный элемент [110].
- **Meta Agent — явный механизм декомпозиции.** Он планирует, раздаёт и контролирует работу, но сам код не правит. Пресет `implement-review-test` раскладывает каждый кусок на реализацию, review и тест [92].
- **Super Loops** делят работу на planning и building и держат на диске `IMPLEMENTATION_PLAN.md`, `task.md` и `.superloop/progress.json` [96].
- **Порядок по зависимостям.** В коде агентов не нашли ничего похожего на эпики, тикеты и волны с зависимостями. Порядок оставлен Meta Agent или человеку. Это прочтение кода автором заметок; документ этого не утверждает. При этом у trackers есть вид Ready, и элементы записывают, чего ждут [80].

### Параллельность и координация

Шесть механизмов, от самого ручного к самому автономному.

1. **Ручные параллельные sessions.** Человек — менеджер: смотрит Kanban, проверяет diff, делает коммиты [59].
2. **Meta Agent** (alpha, с 0.57.7) [91][74].
   - Tools на MCP-сервере приложения [93].
   - Лимиты: 4 ребёнка в работе и 50 за жизнь родителя. Durable prompts, которые ждут ответа или выполняются, считаются в эти четыре [94]. Глубина дерева — до 256 [85].
   - Сам Meta Agent файлы не правит: встроенные Read, Write, Edit и Bash ему запрещены [102].
   - Дети, созданные через `create_session`, работают в общей папке. Изоляции между ними нет [93].
   - Модель дерева: `parent_session_id` задаёт место session в дереве, `created_by_session_id` — её менеджера. Перенос session в дереве никого не делает её менеджером [85].
3. **Blitz** — до 10 новых worktree с одним промптом и session-анализ в конце [97][74].
4. **Agent Teams** — помощники Claude, запущенные внутри процесса через `query()` вместо собственных инструментов команды Claude [88][34].
5. **Crew** — персоны со сменами, бюджетами и журналом [98][74].
6. **Automations** — файлы с расписанием; папка сканируется каждые 30 секунд [99].

**Координация параллельных писателей:**

- `GitOperationLock` на репозиторий пускает деструктивные git-операции по одной, таймаут по умолчанию — 30 секунд [111].
- Merge и rebase сначала проверяют конфликты [111][80].
- **Перекрытие одних и тех же файлов живыми sessions не решено.**
  - Блог вендора пишет, что sessions, трогающие одни и те же файлы, помечаются [59].
  - THE_HARNESS.md пишет, что автоматическое обнаружение конфликтов между параллельными sessions не построено, и команда полагается на то, что пользователь заметит их по `git status`. Документ предлагает ручную проверку через `get_workstream_edited_files` и список sessions по файлу [81].
  - Автоматическое предупреждение — не подтверждено.

### Изоляция

- **Worktree.** Создаётся через simple-git в `../<project>_worktrees/<name>`, на ветке `worktree/<name>` [111]. Несколько sessions могут делить один worktree [80].
- **Super Loops** допускают один активный цикл на worktree [96].
- **Локальных контейнеров и VM нет.** Агенты работают от имени пользователя на его машине, внутри sandbox самого провайдера:
  - Codex: «Ask» — режим read-only с одобрением по запросу; «Allow edits» — `workspace-write`; «Allow everything» — `danger-full-access` [104];
  - Claude: доступ к файлам по умолчанию только внутри workspace, чувствительные пути закрыты [83].
- **Meta Agent.** Дети, созданные через `create_session`, не изолированы друг от друга: папка общая [93].
- **Удалённый вариант** (0.78.0). Cloudflare sandbox разворачивается как приватный Worker в аккаунте пользователя [116][74]:
  - один экземпляр `standard-3`; засыпает после 5 минут простоя; диск временный;
  - `enableInternet=false` и исходящий allowlist: github.com, api.anthropic.com, platform.claude.com, console.anthropic.com, sync.nimbalyst.com;
  - одновременно отслеживаются не больше 4 удалённых transcript;
  - OAuth-ключ подписки Claude копируется в sandbox.

  Sandbox запускает headless runner, который подключается к личной синхронизации как устройство «headless» [115].

### Состояние

- **База данных — источники расходятся.** CLAUDE.md репозитория описывает два живых backend за одним координатором записи: PGLite (Postgres, собранный в WASM) и better-sqlite3 [79]. В issue #365 сказано, что в 0.63 PGLite заменили на better-sqlite3 [143].
- **Transcript.** Таблица `ai_agent_messages` только дописывается и служит единственным сохраняемым источником правды [79]. Канонические события собираются в памяти; cache держит 16 последних sessions. Урезание хранимых кусков сократило объём примерно на 60% [87].
- **Что ещё сохраняется в базе:**
  - интерактивные запросы (durable prompts) [84];
  - сообщения в очереди, с арендой владения (lease) [108];
  - wakeups в таблице `ai_session_wakeups` [109];
  - строки дерева sessions [85];
  - снимки файла до и после каждой правки AI, сжатые gzip и с хэшем SHA-256, и таблица `session_files` [86].
- **Синхронизация.** Личная и мобильная — end-to-end, zero-knowledge. Командная — серверная, на Cloudflare Workers, Durable Objects и D1, вход через Stytch B2B [90][77]. Endpoint — `wss://sync.nimbalyst.com` [76].
- **Резервные копии.** Пользователь назвал свои sessions самым ценным на ноутбуке и спросил, как их сохранить. CEO указал на резервные копии базы на диске (август 2026) [162].

### Память и контекст

- **Монитор context window — источники расходятся.** THE_HARNESS.md называет его отсутствующим [81]. Inventory перечисляет счётчики контекста с отслеживанием темпа [80]. Классификатор ошибок CLI распознаёт отказ `context_limit` [100].
- **Контекст держат малым** [96][98][81][103]:
  - Super Loops начинают чистую session на каждой итерации и переносят выученное в `progress.json`;
  - участник Crew начинает новую главу при 70% контекста;
  - редкие tools грузятся по требованию через ToolSearch.
- **Prompt cache — главный рычаг стоимости.**
  - 0.70.2 (2026-07-21) прекратил сброс cache посреди session. Его вызывали обновления тегов, автоназвание session и поздно подключившиеся серверы расширений. В том же релизе поменяли загрузку редких встроенных tools [74].
  - 0.72.8 (2026-08-07) перестал перезаписывать cache на большинстве ходов [74].
  - Причина, по разбору сооснователя в issue #1177. Каждый ход пользователя идёт отдельным процессом Claude Code CLI. Процесс живёт около 30 секунд после результата, а следующий промпт запускает новый процесс с `--resume`. CLI заново строит снимок git status в каждом процессе. Если рабочее дерево изменилось, cached префикс промпта не совпадает. По данным команды, 62,8% первых ходов после `--resume` переписывали весь префикс, против 0,4% последующих ходов внутри того же процесса [133].
  - Исправление — считать git status один раз на session [133][74]. Держать один процесс живым между ходами — отдельная задача, по словам сооснователя [133].
  - Версия исправления — источники расходятся. Maintainer в #889 называет 0.70.5 [132]. Changelog называет 0.70.2 и 0.72.8 [74].
- **Память проекта** — `CLAUDE.md` и два расширения:
  - Nimbalyst Memory (выключено по умолчанию): индекс SQLite, ранжирование BM25, смешивание с embeddings, tool `recall` [123];
  - Wiki (включено по умолчанию): учит агентов писать страницы решений со связями по типам [124].
- **Самоулучшение.** Команда разбирает прошлые sessions командой `/analyze-sessions`, чтобы улучшать свой harness [81].

### Проверки качества

- **Встроенного test gate и автоматического reviewer нет.** THE_HARNESS.md перечисляет reviewer-subagent перед предложением коммита как не построенный [81].
- **Review каждой правки.** Счётчик очков сопоставляет изменение файла с вызовом инструмента, который его сделал: +100, +40 или +30 очков, порог 30, окно 10 секунд. Правки ждут review за полосой одобрения. Коммит git сам одобряет ожидающие diff, которые в него вошли. Одна session может изменить не больше 500 файлов [86].
- **Правки к этому моменту уже на диске.** В issue #1335 пользователь показал: документация обещала, что ничего не пишется до одобрения, а на деле правки агента сразу попадают на диск. Revert агенту не сообщается, и агент считает свою правку на месте. CEO согласился и поправил документацию (2026-08-22) [148]. Теперь документация называет diff местом review для уже применённых правок, а не очередью удержания, и советует самому сказать агенту об откате [45].
- **Предложения коммита.** Агент предлагает коммит, человек одобряет. Настройка `autoCommitEnabled` пропускает одобрение. Коммит в другой worktree всегда требует одобрения [110].
- **Пресет `implement-review-test`** запускает sessions review и тестов, но ничто не делает их обязательным шагом [92].
- **Blitz.** Session-анализ выбирает лучшую из N попыток [97].
- **Playwright** (alpha-расширение): `list_tests`, `run_test`, `get_failures`, `get_flaky_tests`, `get_history` [126].
- **PR.** Опрос каждые 60 секунд при активном окне и каждые 5 минут в фоне; check runs CI берутся через `gh` [112]. «Review with AI» — одна session с промптом только на чтение [113].
- **Tracker.** Агент не может одобрить работу в review lane [80].
- **Процесс самой команды строже продукта.** Gate (`pnpm typecheck` и тесты перед push) запускает session-оркестратор раз на пачку; git hooks держат правила [79].

### Восстановление после сбоев

- **Ошибки хода.** Повторяются только транспортные ошибки «Stream closed», не больше двух раз (`MAX_STREAM_CLOSED_RETRIES = 2`). Ошибки сервера API не повторяются; пользователь получает подсказку проверить status.anthropic.com [107].
- **Лимиты.** Событие SDK `rate_limit_event` несёт статус, время сброса, тип окна (например, `five_hour`) и долю использования. Nimbalyst превращает его в отметку в transcript и прикрепляет время сброса к ошибке [107]. Виджеты лимита в transcript есть с 0.55.2 (2026-03-01) [74].
- **Auto-resume** (0.81.1). Wakeup через минуту после сброса, sessions разнесены на 30 секунд, сброс дальше 7 дней пропускается, session получает «Continue.» с системной пометкой, любой новый ход отменяет resume. Работает только для Claude Agent [106][74].
- **Wakeups.** Их ведёт один таймер, строки лежат в базе. Пока приложение закрыто, ничего не срабатывает. Wakeups ждут, пока закрыто окно их workspace. Просроченные к запуску показываются человеку, а не срабатывают [109].
- **Зависшие ходы.** Для каждого идущего хода раз в минуту бьётся пульс по часам. По нему строка меню, панель island и Live Activity на iOS помечают молчащую session «не отвечает» через 15 минут. Через 4 часа пульс перестаёт считать ход живым [108].
- **Другие модули восстановления** [108]:
  - очистка «зомби»-состояния running;
  - повторная отправка ожидающих сообщений из очереди при старте;
  - склейка до 20 сообщений из очереди в одно.
- **Перезапуск — источники расходятся.** Inventory пишет, что sessions продолжают работу сами [80]. Changelog для lane CLI (0.65.0) пишет, что после перезапуска возобновляется только session в фокусе, чтобы не упереться в rate limit подписки [74].
- **Durable prompts** переживают перезапуск [84]. Архив worktree с фоновой очисткой повторяется при старте [111].
- **Super Loops** [96]:
  - после 3 неудачных итераций подряд — остановка, паузы 5, 10 и 20 секунд;
  - предел — 20 итераций по умолчанию;
  - при перезапуске идущие циклы ставятся на паузу, брошенные итерации помечаются неудачными;
  - заблокированный цикл продолжает работу после обратной связи;
  - таймаута на итерацию нет.

### Лимиты и стоимость

- **Счётчики.** Приложение читает OAuth-токен Claude из Keychain macOS или из `.credentials.json`. Оно опрашивает `https://api.anthropic.com/api/oauth/usage` каждые 30 минут и делает паузу после 60 минут простоя. Показывает окна 5 часов, 7 дней и недельные окна по моделям, хранит недельную историю. У Codex и Gemini свои сервисы расхода [114]. Публичная страница AI Usage Report описывает счётчики токенов и tools и за лимитами отсылает к панели провайдера [32]. Актуальна ли эта страница — не подтверждено.
- **Бюджеты** [98][94][97][96]:
  - Crew — токены на участника и на всю команду;
  - Meta Agent — лимиты запуска детей;
  - Blitz — до 10 worktree;
  - Super Loops — 20 итераций по умолчанию.
- **Планирования прогона под оставшийся лимит не нашли** [80].
- **Модель оплаты.** Пользователь приносит свой доступ. Nimbalyst не перепродаёт и не считает токены [2][14].
- **Реальная стоимость по отчётам пользователей.** В #889 два Meta Agent за час израсходовали 75% 5-часового лимита Max 20x [132]. В #1177 Nimbalyst делал в 3,49 раза больше записей в cache за ход, и ход стоил примерно в 1,8 раза дороже [133].
- **Ответ команды.** Панель Tools & Token Cost (2026-07-08), исправления cache (0.70.2 и 0.72.8) и разделение внутренних MCP-серверов на ядро и серверы по требованию [74][81].

### Разрешения и безопасность

- **Уровни автономии.** Четыре уровня; по умолчанию Agent-verified, который передаёт рискованные действия классификатору вендора [83][74][38].
- **Ask every time.** Инструменты только для чтения одобряются сами. Одобрение действует на один вызов, на session или всегда в проекте; «всегда» сохраняется в `.claude/settings.local.json` [83].
- **Область.** По умолчанию — только workspace. Дополнительные папки и шаблоны URL — явные разрешения. Одобрения с телефона идут через опрос строк в базе [83].
- **0.82.0.** При «Allow everything» с проверками Agent-verified hook, который просит одобрения, теперь ждёт человека [74].
- **Секреты.** API keys провайдеров берутся только из настроек Nimbalyst, никогда из `process.env` [79]. Путь CLI убирает из окружения `ANTHROPIC_API_KEY` [100]. Loopback MCP-серверы требуют bearer token текущего запуска [105].
- **Место, за которым стоит следить.** Выводы — только по чтению кода, без запуска:
  - инструкция Meta Agent велит всегда одобрять запросы детей решением allow на уровне session [92];
  - `respond_to_prompt` входит в список tools, который строит host MCP endpoint [105][93];
  - `MetaAgentService.respondToPrompt` проверяет только, что вызывающий находится в том же workspace. Проверки, что вызывающий — менеджер целевой session, не нашли [95];
  - alpha-флаг прячет роль Meta Agent в интерфейсе, но host tools этим флагом не закрыты [91][105];
  - может ли session, которая не управляет другой, ответить на её запросы разрешений, — не подтверждено.
- **Sandbox Cloudflare.** OAuth-ключ подписки Claude копируется в sandbox [116].
- **Шифрование.** Личная синхронизация — zero-knowledge, командная — нет [80].
- **Телеметрия.** Анонимная аналитика PostHog [76].

### Эпоха Crystal (июнь 2025 – февраль 2026)

- **Хвалили.** Пользователи называли приложение отличным; один написал, что оно сделало ровно то, что он хотел, и лучше, чем он представлял (июль 2025). Crystal был в списке Awesome Claude Code [167]. Главный довод автора — запускать Codex и Claude Code рядом и выбирать лучший результат [174].
- **Ломалось** [167][166]:
  - macOS 0.3.0+ открывался без окна; больше 10 сообщений «у меня тоже» до декабря 2025; не исправлено к моменту deprecation;
  - свежая установка 0.3.1 падала из-за отсутствующей таблицы базы; исправлено в 0.3.2;
  - сборка из исходников падала, на Linux и WSL был чёрный экран, свой путь к Claude игнорировался;
  - зависал main thread; пользователь написал, что Conductor на той же машине работал плавно; это исправили, и v0.3.1 заявляет снижение нагрузки на CPU больше чем на 40%.
- **Доверие.** Пользователь назвал нераскрытый сетевой трафик разрушающим доверие; трафик оказался от самого Claude Code. Другой пожаловался, что приложение добавило себя в автозагрузку [167]. Nimbalyst теперь документирует анонимную аналитику PostHog, которую можно отключить [76]. Заголовков issues про телеметрию у Nimbalyst не нашли [131].
- **Так и не сделали в Crystal:** auto-resume после лимитов (#18, июнь 2025), удалённый или серверный режим, более заметную работу без skip-permissions [167].
- **Прочее.**
  - Пользователь выбрал Conductor вместо Crystal только из-за визуального списка дел (2025-08-01) [167].
  - Комментаторы HN путали имя с языком программирования Crystal и советовали сменить название (сентябрь 2025) [174]. Повлияло ли это на новый бренд — не подтверждено.
  - Автор писал, что его параллельная работа стоила бы $24 тыс. в месяц по ценам API (2025-07-03) [174]. Большой расход токенов заложен в саму идею продукта.

### Сравнения с альтернативами

- **Claude Code CLI и расширение VS Code:** у Nimbalyst больше токенов на единицу работы [132][133]; до октября 2026 не было auto-resume [153].
- **Codex CLI:** Nimbalyst медленнее [147].
- **vibe-kanban:** автор #889 пишет, что vibe-kanban так не расходовал токены [132].
- **Orca:** пользователи Orca перешли бы ради общей доски по проектам или headless-режима [158][163].
- **Conductor:** в эпоху Crystal он работал плавнее и имел визуальный список дел [167]. Пользователи HN отмечают, что Conductor есть только для Mac [172].
- **tmux и herdr:** пользователи держат терминальный мультиплексор рядом с Nimbalyst, потому что агенты не читают вкладки его терминала [164].
- **Cursor:** для одного пользователя единственное препятствие — нет Vim-режима [164]. Блогер считает их почти равными [184].
- **Claude Code Desktop:** CEO в своём посте признаёт, что официальное приложение получает функции первым, и пишет, что держит установленными оба [66].
- **Тесное поле.** Пользователь HN перечислил около 10 похожих инструментов: Paseo, Orca, Kepler, Emdash, Superset, Conductor, Parallel Code, JetBrains Air [173].
- **Вторичные обзоры.**
  - Augment относит Nimbalyst к инструментам с человеком в цикле и отмечает меньше поддерживаемых агентов [186].
  - Гид amux написан конкурентом. Он отмечает, что агенты останавливаются, когда компьютер спит, но всё же называет Nimbalyst лучшим визуальным рабочим местом [187].
  - ReviewNexa приводит результаты тестов с цифрами без источника и называет приложение MIT в период, когда код был закрыт. Достоверность низкая [190].
  - Отзывы на главной, «тысячи разработчиков» и список компаний — от самого вендора и не проверены [1].

### Что убрали или переосмыслили

1. **Закрытый код стал open source** (декабрь 2025 – апрель 2026) [176][62].
2. **Облачный notebook стал local-first desktop** [191][1].
3. **Шифрование команд.** Клиентское end-to-end шифрование (февраль 2026) заменили серверными ключами, обёрнутыми KMS. Это явно не zero-knowledge; так сделали ради доступа из web, CLI и облачных агентов. Личная синхронизация осталась zero-knowledge [74][80].
4. **Подключение Claude.** Сначала был только Agent SDK. 2026-05-24 CEO написал, что OpenAI явно поддерживает такие продукты, а сигналы Anthropic путаные. 2026-06-10 он объявил два варианта: SDK с API key или CLI с подпиской [138]. Lane CLI до сих пор выключен по умолчанию [80]. Справка Anthropic теперь пишет, что использование при входе по подписке расходует лимиты плана, а июньские изменения приостановлены [181].
5. **Граф знаний заменили wiki-страницами.** Прежние claims, qualifiers и knowledge packs убрали (сентябрь–октябрь 2026) [74][80].
6. **Частые переименования.** Shared Docs стали Pages, затем Wiki, за несколько дней [74].
7. **Правки коллег в общих trackers** больше не идут через accept/reject. Правки AI по-прежнему идут (август 2026) [74].
8. **Иерархию sessions переопределяли четыре раза** [74][80]:
   - worktree как workstream (май);
   - вложенные деревья (октябрь);
   - дети по умолчанию не отчитываются родителю (2026-10-23);
   - контейнеры равноправных sessions (unreleased).
9. **Alpha-функции** включаются не каналом релиза, а флагами по каждой функции [91].
10. **Словарь harness плывёт.** На главной «семь частей», на странице harness — восемь. THE_HARNESS.md пишет «семь слоёв», но в таблице перечисляет восемь [1][5][81].
11. **Лицензия сервера синхронизации.** При подготовке к открытию кода (04-28) он лежал в репозитории под AGPL-3.0. Теперь это отдельный проект, лицензия не указана [74][77][9].

### Планы и дорожная карта

- **Публичная доска roadmap** (github.com/orgs/Nimbalyst/projects/4) требует входа в GitHub с правом `read:project`. Её содержимое не читали (не подтверждено) [195].
- **Unreleased в changelog:** контейнеры workstream и `nim wiki publish` с ролью Commenter [74].
- **Android:** документация пишет, что поддержка планируется [51][23].
- **Teams станет платным** после запуска [49].
- **Один процесс CLI на всю session** вместо нового процесса на каждый ход — отдельная задача, по словам сооснователя [133].
- **Пробелы, которые команда называет сама:** reviewer перед коммитом, обязательный падающий тест, обнаружение конфликтов между sessions, replay упавших sessions [81].
- **Запросы, ждущие решения maintainer:** дизайн headless-режима от участника [158]; исправление потери работы фоновых sub-agents (#1269) [151]. Remote SSH (#49) и другие популярные запросы открыты [130].
- **Горизонт по эссе основателя:** визуальный слой над агентами станет нормой примерно через два года, считая от февраля 2026 [56].

## Слабые места и чего нет

- **Нет встроенного quality gate.** Нет ни автоматических тестов, ни автоматического reviewer перед коммитом. Нет обнаружения конфликтов между параллельными sessions и replay упавших sessions. Так пишет собственный документ команды [81].
- **Ошибки сервера API (5xx) не повторяются.** Повторяется только «Stream closed», до двух раз [107].
- **Auto-resume после лимита узкий:** по желанию, только для Claude Agent, только пока приложение открыто [106][80]. Пользователи долго его просили [153].
- **Без открытого приложения ничего не работает.** Automations, wakeups и Crew ждут запущенного приложения. Пропущенные запуски Automations не догоняются. Закрытая крышка ноутбука останавливает агентов [80][31][157][154].
- **Вся автономия — alpha или эксперимент:** Meta Agent, Blitz, Super Loops, Crew, Agent Teams [91][80][34].
- **Meta Agent.** Лимит — 4 ребёнка одновременно. Дети через `create_session` работают в общей папке без изоляции. Meta Agent сам одобряет разрешения детей. Пользователи сообщают о лишних запусках, зависаниях и потере работы [94][93][92][95][152][151].
- **Нет упорядочивания работы по зависимостям** вроде эпиков, тикетов и волн. Это вывод по чтению кода; у trackers есть только вид Ready [80].
- **Расход токенов выше, чем у обычного CLI,** по замерам пользователей. Есть отказы от продукта из-за этого [133][132].
- **Нет Eco-режима и планирования прогонов под лимиты** [80].
- **Стабильность.** Падения на Windows и при 6–10 sessions, перегрузка базы, высокий CPU после запуска [139][140][141][142][143][144]. Вендор при этом пишет про «более 10» sessions [24].
- **Review правок идёт после записи на диск,** а откат не сообщается агенту [148][45][149].
- **Kanban расходится с реальностью:** фазы зависят от учёта самого агента [150].
- **PR:** нет inline-комментариев и request changes, только GitHub, Checks опрашиваются по таймеру [36][130][112].
- **Монитор context window** — источники расходятся: THE_HARNESS.md называет его отсутствующим, inventory перечисляет счётчики контекста [81][80].
- **Canvas — только файлы.** Нет карточек sessions и MCP tool для досок [42][121].
- **Terminal и Browser.** У терминала нет AI-помощника [37]. Менеджер профилей браузера не найден (не подтверждено) [44]. Агенты не читают вкладки терминала, и пользователи держат tmux рядом [164].
- **Удалённая работа** [157][130][159][80][115][116]:
  - нет Remote SSH;
  - нет синхронизации sessions между двумя desktop;
  - удалённо нельзя ответить на вопросы и запросы разрешений;
  - на удалённой стороне нет worktree;
  - OAuth-ключ подписки копируется в sandbox.
- **Данные команд не zero-knowledge** [80].
- **Android.** Публичная доступность не подтверждена, функций меньше, чем у iOS [118][159].
- **Интерфейс только на английском** [52].
- **Нет SLA поддержки. SOC 2 заявлен без аудитора и даты** [183][15].
- **Нагрузка на maintainers.** Один ведущий maintainer, место второго открыто. 463 issues ждут triage. Вклады участников ждут решения [77][131][151][158].
- **Частая смена понятий:** workstream, Pages и Wiki, harness из семи или восьми частей [74][80][1][5][81].
- **Документация отстаёт от кода:** WORKTREES.md, страница web console, прежнее обещание, что правка не пишется до одобрения [89][50][28][148].
- **Нет скриншотов-доказательств с privacy scrub** (удалением личных данных). Анонимизация есть только в отчёте об ошибке [80].
