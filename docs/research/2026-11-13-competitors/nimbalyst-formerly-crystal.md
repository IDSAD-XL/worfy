## Модель работы

### Где работает: local, cloud или hybrid

- **Гибрид с упором на локальную работу.** Основа — локальное desktop-приложение на Electron. Внутри — редакторы
  Lexical (форматированный текст) и Monaco (код), React и Excalidraw [73].
- **Агенты работают на компьютере пользователя, от его имени.** Локальных контейнеров и виртуальных машин нет. Каждый
  агент работает внутри sandbox своего провайдера [104][80].
- **Prompts уходят только к выбранному провайдеру.** API keys хранятся на устройстве в зашифрованном виде [15][49].
- **Облачные части:**
  - сервер синхронизации и совместной работы на Cloudflare, адрес `wss://sync.nimbalyst.com` [73];
  - синхронизация команд работает на Cloudflare Workers, Durable Objects и D1 (сервисы вычислений и хранения
    Cloudflare); вход — через Stytch B2B (сервис входа для компаний) [83];
  - web console для Teams — console.nimbalyst.com [11][48];
  - необязательное удалённое выполнение в **собственном** аккаунте Cloudflare пользователя через headless runner —
    программу, которая запускает sessions без интерфейса [115][114].
- **Телефон и desktop** синхронизируются через облако с end-to-end шифрованием [76][26].
- **Self-host:**
  - Enterprise Beta ставит сервер совместной работы в аккаунт Cloudflare клиента или даёт его как управляемый
    сервис [29];
  - inventory функций пишет: клиенты, которым нужны данные команды без доступа вендора (zero-knowledge), запускают
    программу на своей инфраструктуре [76];
  - публичной инструкции по self-host не нашли (не подтверждено).
- **Каналы релизов.** README называет stable (по умолчанию) и alpha. Inventory называет stable, beta и alpha [73][76].
  Alpha-функции включаются по одной, отдельными переключателями, независимо от канала [38][82].
- **Телеметрия** — анонимная аналитика PostHog, её можно выключить [73].

### Агенты и модели

- **Двенадцать встроенных lanes.** Lane — встроенный способ подключить агента или модель. Каждая работает на ключах,
  введённых в настройках, или на CLI, в который пользователь уже вошёл. Из переменных окружения ничего не
  читается [76][37][84].
- **Coding-агенты:**
  - **Claude Agent** — по умолчанию. Работает на Claude Agent SDK (`@anthropic-ai/claude-agent-sdk`) прямо в процессе
    приложения. Есть MCP, plan mode и sub-agents [81].
  - **Claude Code CLI** — выключена по умолчанию. Запускает настоящий CLI `claude` в терминале. Вендор обещает работу на
    подписке Claude Pro/Max без оплаты API по токенам. Появилась в 0.65.0 (2026-06-09) [76][74]. В июне 2026 года CEO
    называл её alpha с множеством ошибок [133][134].
  - **OpenAI Codex** — через Codex app-server, протокол JSON-RPC поверх stdio. Включена по умолчанию в новых установках.
    Использует вход в Codex, API key — по желанию [37][81].
  - **Codex через ACP** (Agent Client Protocol — открытый протокол связи редактора с агентом) — экспериментальная [81].
  - **Alpha-lanes:** OpenCode (локальный сервер OpenCode по HTTP/SSE), GitHub Copilot CLI и Grok Build (ACP поверх
    stdio), Cursor Agent (отдельный headless-процесс на каждый ход с выводом NDJSON), Gemini через Google
    Antigravity [38][81].
- **Chat-lanes без цикла инструментов агента:** Claude API, OpenAI API и LM Studio для локальных моделей [76][81].
- **Расширения могут добавлять своих провайдеров агентов** [1][76].
- **Источники расходятся в том, как подключён Codex.** Changelog в феврале 2026 года называет провайдер на Codex
  SDK [74]. Inventory и страница о подписках пишут «SDK или ACP» [76][14]. Документ о типах провайдеров описывает
  app-server по JSON-RPC [81].
- **Детали Claude:**
  - Свои модели берутся из настроек `modelPicker` самого Claude — для маршрутизации через gateway. Приложение следует
    только за `ANTHROPIC_BASE_URL`, который указывает на loopback-адрес (127.0.0.1) [76][81].
  - Поддерживается Claude Enterprise SSO. Свой путь к исполняемому файлу Claude нужен для корпоративных обёрток
    SSO [74][37].
  - Есть страница документации про Claude на Vertex и Bedrock [28]. Codex тоже работает на Amazon Bedrock
    (0.82.4) [74].
  - Релиз 0.59.1 ставит `CLAUDE_CODE_ENTRYPOINT='cli'`, чтобы трафик подписки по OAuth не получал пониженный
    приоритет как сторонний [74]. Перед этим был issue #174 (2026-05-06, исправлен): подписчиков ограничивали, когда
    параллельно работал официальный CLI, потому что встроенный SDK помечал свой трафик как `sdk-ts`, а не `cli` [132].
- **Чем оплачивается путь Claude Agent — не подтверждено.** Источники расходятся:
  - документ о типах провайдеров: вход через Claude CLI или аккаунт, сохранённый ключ — по желанию [81];
  - комментарий в заголовке файла CLI-провайдера: путь через SDK оплачивается API key пользователя [92];
  - CEO в июне 2026 года объявил два варианта: SDK с API key или CLI с подпиской [134];
  - справка Anthropic: запланированное изменение оплаты Agent SDK приостановлено 2026-06-15, а использование Agent SDK
    и сторонних приложений по-прежнему расходует лимиты подписки [187];
  - пользователи путают два пути [133][134].
- **Модели, названные в последних релизах** (как их пишет вендор): Claude Fable 5.2 (0.83.0); Opus, Sonnet и Haiku
  5.5; GPT-6.1 Terra и GPT-6.1 Sol для Codex [75][18].
- **Каждая lane сообщает, насколько надёжно она отдаёт список изменённых файлов:** structured (структурированно),
  tool-args (по аргументам инструментов) или none (никак) [76][100]. Провайдера можно переопределить на уровне
  проекта [76].
- **Провайдер session фиксируется**, как только в ней появились сообщения [81].
- **Agent Teams.** В интерфейсе есть переключатель «Agent Teams (Experimental)» самого Claude. У участников команды
  агентов — отдельные индикаторы прогресса [32].

### Один пользователь или команда

- **Individual** — один человек, без аккаунта, всё хранится локально [2].
- **Teams** — команда: общие документы и trackers в реальном времени, inbox организации, комнаты и личные сообщения,
  роли Owner, Admin и Member [76][11][47].
- **Проект в Teams — это один git-репозиторий.** Его опознают по remote `origin` [76][11][47].
- **Целевой размер команды** в эссе основателя — 3–7 человек, каждый ведёт своих агентов [60].
- **Аудитория:** разработчики и продакт-менеджеры; отдельные страницы решений для маркетинга, исследований, quant,
  customer engineering и консалтинга [1].

- **CLI:** `nim` (пакет npm `@nimbalyst/cli`) и необязательная shell-команда `nimbalyst` на macOS [76].
- **Язык интерфейса** — только английский [49]. Перевод интерфейса — открытый запрос (#597) [72].

## Функции

Ниже — все функции, которые нашли в документации, inventory функций (`docs/FEATURE_INVENTORY.md`), changelog и коде.
«Alpha» значит: функция выключена по умолчанию и включается отдельным переключателем в настройках [38][82]. «Developer
Mode» — режим настроек, который открывает функции для разработчиков: worktrees, терминал, review PR [30][33][34][42].

### Режимы рабочего места

- **Четыре режима:** Files — визуальное редактирование файлов; Agent — управление sessions с review; Task — trackers
  задач; Wiki — страницы знаний [28][4].
- **Панель нескольких проектов** (multi-project rail) — с 2026-05-11 [74].

### Окно агента

- **Раскладка.** Слева — список sessions с поиском по названию и кнопкой «Search contents» (поиск по содержимому). В
  середине — transcript. Правая панель переключается между Edited Files (изменённые файлы), Review и Chat with
  Session [30].
- **Новая session** — Cmd/Ctrl+N. В меню есть ещё New Worktree, New Blitz, New Terminal, New Super Loop и New Meta
  Agent. Какие пункты видны, зависит от Developer Mode, наличия git и alpha-переключателей [30].
- **Запуск в фоне** — Cmd/Ctrl+Shift+N. Можно выбрать агента, модель и effort, добавить Actions (сохранённые prompts),
  slash-команды, упоминания файлов и элементов tracker, картинки. Пользователь остаётся в текущем экране [30].
- **Масштаб.** Вендор пишет, что можно держать больше 10 sessions одновременно [21].

### Composer — поле ввода prompt

- Упоминания файлов через `@`, подсказки slash-команд при наборе, skills [76].
- Сохранённые наборы prompts — «Actions» в файле `nimbalyst-local/ai-actions.md` [76]. С 2026-05-21 actions можно
  программировать так, чтобы они запускали соседние sessions [74].
- Вложения-картинки и chips с выделенным фрагментом из редакторов [76].
- Сообщения, которые пришли, пока агент работает, ставятся в очередь. С 0.83.0 они доставляются агенту вместе, одним
  ходом, и у каждого подписан автор — человек или другая session [75][74].
- Подсказка следующего prompt: Tab вставляет её в поле [76].
- Черновики сохраняются [76].

### Модели, effort и plan mode

- Выбор модели для каждой session — Cmd/Ctrl+Shift+M [76][30].
- Уровни effort, включая «Ultra» для Codex. Extended thinking можно включить или выключить [76][30].
- Plan mode — Shift+Tab [76][30]. Файлы планов сохраняются в `nimbalyst-local/plans` [94].
- Режим session «Auto» — с 2026-06-06 [74].

### Запросы к человеку

- **Пять видов интерактивных запросов:** AskUserQuestion (вопрос агента), PromptForUserInput (структурированная форма
  ввода, с 2026-05-09), ExitPlanMode (одобрение плана), GitCommitProposal (предложение коммита) и ToolPermission
  (разрешение на инструмент) [76][85][74].
- **Запросы переживают перезапуск приложения:** они хранятся в базе данных [76][85].
- У AskUserQuestion нет таймаута. Hook разрешений в пути SDK ждёт ответа до 24 часов [94].

### Review правок

- Красно-зелёный diff на каждый вызов инструмента, баннер «ждёт review», кнопки approve all и reject all [76].
- В редакторах — режим diff с одобрением и отклонением по файлу, diff по ячейкам CSV и слайдер «до и после» для
  mockups [76].
- Коммит в git автоматически одобряет ожидающие diffs, которые в него вошли. Одна session может изменить не больше
  500 файлов [100].
- **Правки пишутся на диск сразу.** Diff — это экран review уже применённых правок, а не очередь, которая держит
  правку до одобрения [51][144]:
  - раньше документация обещала обратное. Пользователь заметил расхождение в issue #1335, CEO согласился и исправил
    документацию 2026-08-22 [144];
  - откат (Revert) агенту не сообщается. Документация советует самому написать агенту об откате [51][144].

### Операции с session

- Переименование, автоматическое название, закрепление (pin), теги, фаза, ответвление (branch/fork), архив, удаление,
  экспорт в HTML [76].
- Ссылки для просмотра session с end-to-end шифрованием и сроком жизни 1, 7 или 30 дней [76].
- Отметки «прочитано» и «не прочитано» [76].

- Ручной импорт sessions Claude Code CLI. Нужен Claude Code 2.1.x или новее. Повторный импорт безопасен, у обновлённых
  sessions появляется метка «Has Updates» [50].
- Живое слежение за внешними sessions Claude Code и Codex CLI — по желанию, выключено по умолчанию [76]. Слежение за
  внешними sessions Claude появилось в 0.78.1 (2026-09-17) [74].

### Kanban sessions

- **Session Kanban** — Cmd/Ctrl+Shift+K. Колонки: Backlog, Planning, Implementing, Validating, Complete [30].
- При наведении на карточку видно живое превью session [30].
- Агенты сами ставят себе название, теги и фазу через внутренний MCP-инструмент `update_session_meta` [76][146].
- В Complete session переводит только человек [79]. Смены фаз записываются в историю [101].
- Команда `/session-cleanup` предлагает исправить фазы и называет кандидатов в архив [76].
- Свои названия колонок — открытый запрос (#82) [72].

### Workstreams и деревья sessions

- **Workstream** — группа связанных sessions. Они показаны вкладками и имеют общий список изменённых файлов. Команда
  `/launch-new-session` запускает соседнюю session [31].
- Sessions вкладываются друг в друга деревом, со сводкой активности по дереву. Именованный контейнер-папка «workstream»
  пока лежит в разделе Unreleased — ещё не выпущен [76][74].
- **Правила дерева** [74][86]:
  - глубина — не больше 256 уровней;
  - session, которая создала другую, — её «manager» и получает отчёты о завершении;
  - отчёт может быть: никакой, только финальный ответ или сообщения по ходу работы;
  - по умолчанию отчёта нет — с 0.82.1; changelog датирует это изменение 2026-10-23 [74][86].
- Понятие workstream переопределяли несколько раз: сначала worktree считался workstream (май), потом появились
  вложенные деревья (октябрь), теперь — контейнеры-«соседи» (ещё не выпущены) [74][76].

### Наблюдение и уведомления

- **Значок внимания** делит sessions на три группы: Awaiting input (ждут человека), Running (работают), Unread (не
  прочитаны). «Mark all read» ничего не одобряет, только снимает отметки [30].
- **Уведомления ОС** о завершении — включены по умолчанию [37].
- Агент может сам попросить внимания через `notify_user`. Число таких уведомлений ограничено. Срочность «critical»
  отправляет push на телефон [76][88].
- Звук завершения: chime, bell, pop или свой аудиофайл [37].
- **Полоса в menu bar macOS** («fleet»). Называет sessions, когда они стартуют, завершаются, блокируются или падают, и
  помечает те, что перестали отвечать. Её панель может отметить всё прочитанным [74][30]. Появилась 2026-08-31 [74].
- Значок на Dock в macOS, иконка в tray на Windows и Linux [76][74].
- **Телефон:** push о завершённых, упавших и ждущих sessions. Пока пользователь активен на Mac, push не приходят [26].
- **iPhone Live Activity и Dynamic Island** — живой виджет на экране блокировки и в верхней части экрана iPhone.
  Sessions ранжируются по тому, как долго они ждут человека [76].
- **Radar** — сводка того, что сделали коллеги, пока вас не было. Доступна и агентам как инструмент. Появилась
  2026-09-03 [76][74].

### Счётчики лимитов и расхода

- **Окно расхода Claude:** полосы для 5-часового окна session и недельного окна. С 0.78.0 — недельные лимиты по
  моделям и время сброса. Кольцо-индикатор в левом поле [74].
- **Codex:** счётчик с окнами 5 часов и 7 дней, подстраивается под переменные окна. Для Gemini — chip с расходом [74].
- **Недельная история** (0.82.6, 2026-11-03): график расхода против линии равномерного темпа и итоговый процент каждой
  прошлой недели. Пишется локально и только пока приложение открыто [76][74].
- **Счётчики контекста:** заполнение окна контекста с отслеживанием темпа. По желанию — полоска контекста под каждой
  строкой списка sessions [76].
- **AI Usage Report** (меню Window): итоги по токенам, тепловая карта активности, карточки по проектам. Вкладка Tools —
  число вызовов и кнопка дозагрузки истории (backfill). Данных о стоимости и лимитах нет — отчёт отсылает к панелям
  провайдеров [35]. Совпадает ли эта страница документации с кодом — не подтверждено [111][35].
- **Карточки лимита в transcript:** жёлтая «rate limit warning» и красная «blocked» [76]. Виджеты rate limit в
  transcript появились в 0.55.2 (2026-03-01) [74].
- **Панель Tools & Token Cost** (2026-07-08): для каждой группы инструментов задаёт загрузку сразу или по
  требованию [76][74].

### Уровни автономии — разрешения агента

- **Четыре уровня** в диалоге доверия, который появляется при первом открытии проекта [80][36]:
  - **Agent-verified** — рекомендуемый, по умолчанию с 0.70.2 (2026-07-21) [74]. Обычная работа идёт без запросов.
    Рискованные действия проверяет встроенный автоматический reviewer провайдера [36][80].
  - **Allow everything** — без запросов и без проверки.
  - **Allow edits only** — без запросов разрешены только правки.
  - **Ask every time** — спрашивать каждый раз. Инструменты только для чтения одобряются сами [80].
- **Кто проверяет в Agent-verified** [36][80][94][104]:
  - у Claude — классификатор auto-mode из SDK (`permissionMode: 'auto'`);
  - у Codex — `workspace-write` с `approvals_reviewer = "auto_review"` и одобрением по запросу;
  - то, что reviewer провайдера не одобрил сам, приходит человеку.
- **Области одобрения в режиме Ask:** Deny, Allow Once, Session, Always. «Always» записывает правило в
  `.claude/settings.local.json` [36][80].
- **Жёсткие правила** [36][80]:
  - `~/.ssh` и `~/.aws` закрыты всегда;
  - доступ в сеть — через allowlist адресов;
  - составные shell-команды получают только разовое одобрение;
  - в недоверенном проекте все действия агента запрещены.
- Доступ к файлам по умолчанию ограничен workspace. Дополнительные папки и шаблоны адресов разрешаются явно [80].
- Одобрения с телефона работают через опрос сохранённых в базе строк запроса и ответа [80].
- **Соответствие для Codex** [104]: «ask» — read-only и одобрение по запросу; «Allow edits» — `workspace-write`; «Allow
  everything» — `danger-full-access`.
- **0.82.0 (2026-10-23):** в режиме «Allow everything» с проверками Agent-verified hook, который просит одобрения,
  теперь ждёт человека [74].

### Meta Agent (alpha)

- **Что это.** Тип session-оркестратора. Появился в 0.57.7 (2026-04-02) [74][87]. По встроенным инструкциям он никогда
  не трогает код сам — только планирует, делегирует, следит и координирует [87].
- **Инструменты** MCP-сервера хоста [88]:
  - `list_worktrees`, `create_session`, `spawn_session`;
  - `get_session_status` и `get_session_result` — полный ответ режется на 50 000 символов;
  - `consume_session_inbox`, `list_queued_prompts`;
  - `send_prompt` — может прервать идущий ход;
  - `notify_user` — срочность «critical» шлёт push на телефон;
  - `respond_to_prompt` — отвечает на запрос разрешения, вопрос или выход из плана дочерней session;
  - `list_spawned_sessions`.
- **Worktree у дочерних sessions — источники расходятся.** По описанию функций `create_session` и `spawn_session`
  принимают необязательный worktree, область инструментов read, write или full и режим отчёта [86][87][88][89]. По
  чтению кода `create_session` игнорирует аргументы worktree: дочерние sessions всегда работают в общем каталоге, чтобы
  родитель мог читать их файлы. `spawn_session` создаёт worktree только по запросу (`useWorktree=true`) [88].
- **Сам отвечает на запросы детей.** Инструкции велят всегда одобрять запросы разрешений детей на уровне session,
  одобрять планы, которые совпадают с задачей, и отвечать на вопросы детей или передавать их человеку [87].
- **Правила поведения** [87]:
  - создавать как можно меньше дочерних sessions;
  - доказательством считать список изменённых файлов ребёнка и его область инструментов, а не текст его отчёта;
  - получив полезные данные, писать ответ, а не создавать новых детей.
- **Пресеты процесса** [87]:
  - `default`;
  - `implement-review-test` — сам проходит цикл «реализация → review → тест» для каждой части работы, в одном worktree,
    и не задаёт человеку вопросов;
  - `research`;
  - пресет агент ставит себе сам через инструмент метаданных session. Переключатель в интерфейсе не нашли (не
    подтверждено).
- **Лимиты:** не больше 4 детей одновременно и 50 за всю жизнь родителя (`MAX_IN_FLIGHT = 4`,
  `LIFETIME_BACKSTOP = 50`). Ожидающие и выполняемые сохранённые запросы тоже считаются в эти четыре [89].
- **Meta Agent не может править файлы.** Его sessions работают с allowlist инструментов. Для Claude и Codex встроенные
  инструменты вне списка запрещены, включая Read, Write, Edit и Bash. В allowlist нет и `spawn_session` [91].
- Дети наследуют провайдера и модель родителя [74]. Sessions Meta Agent можно создавать с iOS и Android, если
  alpha-переключатель включён [76].

### Super Loops (alpha)

- **Что это.** Автономный цикл над одной задачей в своём worktree. Появился в 0.52.69 (2026-02-14). Changelog пишет, что
  идея взята из «Ralph loops» — приёма, где агента перезапускают в цикле со свежим контекстом, а прогресс хранят в
  файлах [76][74][32].
- В одном worktree — не больше одного активного цикла [106].
- Каждая итерация начинается со свежего контекста и читает свои файлы прогресса: задача — в `.superloop/task.md`,
  план — в `IMPLEMENTATION_PLAN.md`, прогресс — в `.superloop/progress.json` [106].
- Пользователь выбирает модель и максимум итераций — по умолчанию 20 [106].
- Две фазы: планирование, потом построение [106].
- Панель прогресса показывает фазу, итерацию, выводы (learnings) и блокеры. Кнопки: pause, resume, stop, force-resume.
  Заблокированный цикл показывает виджет обратной связи [76][32].

### Blitz (alpha)

- Один prompt запускается в нескольких изолированных worktrees — до 10 (`MAX_BLITZ_WORKTREES = 10`). Появился в 0.52.68

- «Model blitz» — вариант, где worktrees подписаны именами моделей [76].
- Когда все дети закончили, сама стартует session анализа. Она сравнивает результаты через `get_session_summary` и
  `get_workstream_edited_files` и рекомендует победителя [107].

### Crew (alpha, с 0.79.0 от 2026-09-29)

- **Что это.** Постоянные персоны-агенты, описанные в `nimbalyst-local/crew/` [76][108].
- У каждой — имя, роль, характер, заметки, журнал, расписание смен (раз в неделю или через интервал), уровень
  уведомлений (note, flag, page), тихие часы, недельный бюджет токенов и число смен в день. Cache tokens тоже
  считаются в бюджет [76][108].
- **Значения по умолчанию:** 60 млн токенов в неделю и 6 смен в день на участника; 600 млн токенов в неделю на всю
  Crew. Участник начинает новую «главу» (chapter), когда контекст заполнен на 70% или прошло 7 дней. Так контекст
  остаётся небольшим [108].
- Смены идут как обычные sessions. Команда `/crew:hire` проектирует нового участника по описанию должности [76][108].
- Только desktop. Работает, только пока проект открыт. Пропущенный запуск выполняется один раз при открытии
  проекта [76][108].

### Automations

- Файлы Markdown в `nimbalyst-local/automations/` [22].
- Расписание: каждый день, каждую неделю или каждые N минут. Результат: новый файл, дописать в файл или заменить файл.
  Провайдер и модель — необязательные поля [22].
- Команда `/automation` создаёт новую. Новые automations стартуют выключенными. «Run Now» запускает сразу [22].
- У каждой — `history.json` со ссылками на session, которая её выполнила [22].
- Папка сканируется каждые 30 секунд [109].
- **Работают только при открытом приложении. Пропущенные запуски не выполняются** [22].

### Wakeups, auto-resume и перезапуск

- **Wakeup** — отложенный запуск session. Агент может сам назначить его через `schedule_wakeup` на срок от 60 секунд
  до 7 дней. Инструмент появился в 0.58.5 (2026-04-28) [76][30][74].
- Wakeup переживает перезапуск. Над session висит баннер с кнопками Fire now и Cancel. Срабатывает только при
  запущенном приложении [76][30].
- Wakeups ждут, пока закрыто окно их workspace. Просроченные к запуску wakeups показываются человеку, а не
  срабатывают [98].
- **Auto-resume после сброса лимита Claude.** По желанию, только для lane Claude Agent. Появился в 0.81.1: в changelog —
  2026-10-12, релиз на GitHub — 2026-10-13 [76][74][70]. Как он устроен — в разделе «Как это устроено внутри» [96].
- **Перезапуск приложения** [76][74]:
  - sessions продолжают работу сами после перезапуска;
  - приложение откладывает перезапуск, пока sessions активны;
  - prompts из очереди, включая отправленные с телефона, выполняются сами.
- **Не нашли** ни в inventory, ни в changelog (отсутствие не подтверждено) [76]:
  - автоматический повтор после ошибок API;
  - планирование запусков под окна подписки;
  - режим экономии (eco) или режим малого расхода токенов;
  - ближе всего — панель Tools & Token Cost.

    Ключи Cloudflare приложение не хранит;
  - один sandbox на установку, экземпляр `standard-3`. Засыпает после 5 минут простоя. Файлы в нём не сохраняются;
  - `enableInternet=false` и allowlist исходящих адресов: github.com, api.anthropic.com, platform.claude.com,
    console.anthropic.com, sync.nimbalyst.com;
  - OAuth-ключ подписки Claude копируется в sandbox.
- **Ограничения удалённой работы** [76][115][114]:
  - на вопросы и запросы разрешений удалённо ответить нельзя;
  - worktree на удалённой стороне не создаётся;
  - одновременно открыто не больше 4 удалённых transcripts, до 8 MiB на просмотр;
  - состояние выполнения теряется при перезапуске хоста.
- **Выбор машины.** В desktop есть селектор «Execution machine» для удалённых хостов [115]. Sessions, запущенные с
  телефона, работают на одном выбранном desktop [74][177].
- **Синхронизации sessions между двумя desktop нет** — открытый issue #1628 [72].

### Worktrees

- Нужен Developer Mode [76][33].
- Создаются по Cmd/Ctrl+Alt+W, из элемента tracker или из PR. Несколько sessions могут делить один worktree [76][33].
- Путь — `../<project>_worktrees/<name>`, ветка — `worktree/<name>`. Создаются через библиотеку simple-git [102].
- **Операции** [76][102]:
  - merge в базовую ветку — нужен чистый рабочий каталог, операция берёт блокировку;
  - rebase от базовой ветки с автоматическим stash;
  - диалог squash;
  - проверка конфликтов перед merge и кнопка «Resolve with Agent» — решить конфликт агентом;
  - архивирование с фоновой очисткой, которая повторяется при старте приложения;
  - pin и переименование.
- У каждого worktree свой терминал [76].
- Sessions в worktrees появились в v0.51.x (2026-01-13) [74].

### Git panel

- Список изменений. Коммит вручную или «Commit with AI», с выбором отдельных кусков изменений (hunks) [76].
- Переключатель автокоммита. Настройка `autoCommitEnabled` убирает шаг одобрения коммита [76][101].
- Предложения коммитов: агент предлагает, человек одобряет. Предложение коммита в другой worktree (с 2026-10-23) всегда
  требует одобрения, даже при автокоммите [76][101][74].
- Сообщение коммита вида «Fixes NIM-123» закрывает связанный элемент tracker [101].
- История коммитов со счётчиками ahead/behind и ссылками на sessions, которые сделали каждый коммит (с 0.73.0,
  2026-08-11). Заголовок редактора показывает последнюю session, которая трогала открытый файл [76][74].
- Поддерживаются проекты из нескольких репозиториев [76].

### Review PR

- Режим review PR — с 0.64.5 (2026-06-06). Открывается по Cmd/Ctrl+U. Нужны Developer Mode и GitHub или GitHub
  Enterprise через `gh`. Токены приложение не хранит [74][34].
- Фильтры: Open/Closed, Awaiting my review, Created by me, With conflicts, Draft, Review Status [34].
- Вкладки: Conversation, Files Changed, Commits, Checks [34].
- **Checks не обновляются вживую, их опрашивают:** раз в 60 секунд, пока приложение на переднем плане, и раз в 5 минут
  в фоне. Данные CI берутся через `gh` [34][112].
- **«Review with AI»** открывает одну session агента с prompt только для чтения [113]:
  - прочитать PR через `gh pr view` и `gh pr diff`;
  - искать ошибки корректности, регрессии, недостающие тесты и нарушения соглашений проекта;
  - ответить рекомендацией в одну строку, затем находками с файлом и строкой.
- Другие действия: «Open in Worktree», связь с элементами tracker, approve и merge (squash, merge или rebase, всегда с
  подтверждением). Merge может продвинуть связанные элементы tracker [76][34].
- **Ограничения** [34][72]:
  - нельзя писать inline-комментарии и запрашивать изменения (request changes);
  - только GitHub; запрос на GitLab открыт (#1488);
  - экрана создания PR не нашли (не подтверждено).

### Trackers

- **Режим Tracker** — Cmd+T. Виды: список, таблица, сетка, Kanban, доска по тегам, timeline, inbox [76].

- **Вид «Ready»** (2026-08-23) — элементы упорядочены по тому, сколько другой работы каждый разблокирует. Элементы
  записывают, чего они ждут [76][74]. Связи между элементами tracker — с 2026-06-22 [74].

- **Коллекции milestone и release** со сводками. `nim release finalize` заполняет элементы релиза при сборке [76].
- **Полоса review:** агент может перевести работу в review, но одобрить её не может [76].
- Элемент — полноценный совместный документ с комментариями и чатом с AI. Ещё: живые chips ссылок через `#`,
  сохранённые и общие виды, точки «не прочитано», личные и командные trackers [76].
- **Агенты и trackers** [76][45]:
  - агенты создают, обновляют и ищут элементы;
  - переключатель «AI Agent Access» на проект убирает у агентов инструменты tracker;
  - связь session с элементом создаётся только явно — документация называет это намеренным решением;
  - у элемента есть кнопка «Launch Session», а его контекстное меню может запустить worktree.
- Правки коллег в общих trackers больше не проходят accept/reject. Правки AI по-прежнему проверяются (август

### Шифрование

- Данные команд шифруются ключами на команду, которыми управляет Nimbalyst. Inventory прямо пишет: это не
  zero-knowledge [76].
- Так было не всегда. В феврале 2026 года шифрование команд было end-to-end с ключами у клиента. 2026-07-15 его
  сделали серверным, с ключами под KMS (облачной службой ключей). 2026-07-28 убрали организации с ключами у клиента.
  Причина — доступ из web, CLI и облачных агентов [74][76].
- Личная синхронизация desktop и телефона остаётся zero-knowledge: AES-256-GCM, ключи из PBKDF2 со 100 000
  итераций [76][26].

## Принципы и подходы

### Миссия и «почему»

- **Миссия:** помочь людям хорошо работать с агентами и друг с другом. **Видение:** маленькие подвижные команды людей,
  которые плотно работают друг с другом и со своими агентами [3].
- **«Почему» на странице About — пять противопоставлений** [3]:
  - цель — не оркестровка агентов. Компания пишет, что всё вокруг строилось вокруг оркестровки, а она строит продукт
    для совместной работы людей и агентов;
  - вместо терминала — интерфейс, где главное визуальное;
  - вместо агентов, прикрученных к старым инструментам, — одно рабочее место;
  - вместо работы одного человека с агентами — команды с агентами;
  - вместо привязки к вендору (lock-in) — open source и локальные файлы.

### Шесть убеждений

Они повторяются на главной, на странице About и в посте об открытии кода [1][3][53]:

1. Визуальный интерфейс передаёт человеку больше всего информации.
2. Каждый становится менеджером агентов.
3. Связанный контекст должен жить в одном общем графе.
4. Открытые форматы, open source, локальные файлы.
5. Работа на месте: review, комментарии и правки AI живут внутри документа.
6. Шестое убеждение поменялось. В апреле 2026 года это было «расширяй и меняй своё рабочее место» через платформу
   расширений [53][3]. Сейчас на главной — «владей своим harness и вкладывайся в него» [1].

### Откуда это пришло

- **Январь 2025.** stravu.com — страница листа ожидания для командной стратегии и принятия решений с помощью AI [188].
- **Июнь–октябрь 2025.** Stravu — облачный командный «AI-блокнот» на AWS [188]:
  - текст, таблицы, диаграммы, матрицы 2x2 и формулы;
  - добавления AI показаны зелёным, удаления — красным, человек их одобряет;
  - оценка уверенности и ссылки на источники;
  - чат с AI на нескольких людей.
- **Главная идея — одобрять правки AI красно-зелёным diff прямо в отрисованном документе — пришла отсюда** [188].
  Основатели пишут, что именно эта функция превратила markdown-редактор в рабочее место для агентов [168].
- Как Crystal и markdown-редактор сошлись в Nimbalyst — в разделе «Направление развития».

### Эссе основателя

Все эссе написал Karl Wirth.

- **«Turn This Rock into a Statue»** (2026-01-14) — как вести агентов: сформулировать ясное видение, вместе с агентом
  довести подробный документ плана, потом проверять работу итерациями [54].
- **«DOS to Windows for Agents»** (2026-02-02) [55]:
  - сегодняшние терминальные агенты похожи на DOS;
  - визуальный слой поверх CLI, а не вместо него, даст обзор, управление многими агентами, прямую работу с объектами
    мышью и доступность;
  - он предсказывает, что визуальный слой станет нормой примерно через два года.
- **«IDE for Words, Diagrams, and Mockups»** (2026-02-10) — спецификации, mockups и диаграммы становятся исходником
  для кода. Целевые читатели — продакт-менеджеры и tech leads [56].
- **«The $0 Office Suite»** (2026-02-16) — бесплатная локальная AI-замена документам, таблицам, диаграммам и
  trackers. Деньги планируют брать за командные функции [57].
- **«6 Agents, 1 Manager, 0 Chaos»** (2026-02-27) — панель управления, worktrees и review перед push. Управлять
  агентами — новый навык, которому нужны специальные инструменты [58].
- **«Context Is the New Code»** (2026-03-01) — качество результата больше зависит от контекста (спецификации,
  wireframes, модели данных, тесты), чем от prompt. Review контекста становится новым code review [59].
- **«The Future Is Small Teams»** (2026-03-07) [60]:
  - выиграют команды из 3–7 человек, где каждый ведёт агентов;
  - стоимость координации растёт как n(n−1)/2;
  - агенты делают задачу координации тяжелее.
- **«Why we put Obsidian, Linear, Terminal, Codex app, and Conductor in one workspace»** (2026-05-12) и **«Integrate
  80% of everything»** (2026-05-19) [61][62]:
  - сделать ту часть каждого SaaS-инструмента, которая важна: trackers, документы, диаграммы, mockups, код, sessions;
    в планах — ветки сообщений;
  - связать всё типизированными связями.
- **«What Is an Agent Harness? Eight Pillars»** (2026-05-20, обновлено 2026-07-15) [63][5][6][7]:
  - harness — постоянный слой, которым владеет команда, поверх harness вендоров (Claude Code, Codex);
  - восемь опор: контекст, provenance, возможности (capability), процесс (workflow), ограничения (restraint),
    проверка, визуальный интерфейс, координация;
  - к нему есть Harness Blueprint и Benchmark Protocol на 100 баллов; результатов нет;
  - страница harness ссылается на безымянные исследования Stanford и Tsinghua: будто бы один только harness даёт
    шестикратную разницу в качестве [5].
- **«Claude Code Desktop vs Nimbalyst»** (2026-06-01) [64]:
  - это разные слои;
  - официальное приложение получает функции первым и лучше для глубокой работы в одном потоке;
  - Nimbalyst управляет всем набором sessions.
- **«MCP Is Not a Workspace»** (2026-07-29) [65]:
  - MCP даёт агентам доступ к другим инструментам, но не хранит связи между элементами;
  - по замеру компании, ответ на один вопрос через несколько инструментов (Slack, GitHub, Linear) стоит примерно в
    12 раз больше токенов, чем одно чтение из связанного рабочего места. С Google Docs — около 30 раз, с Figma — около
    40 раз.
- **«How Claude Code Changed How We Prioritize Features»** (2026-08-18) [66]:
  - с агентами трудоёмкость реализации больше не главное ограничение;
  - каждой области функций дают стратегию: Differentiate, Do, Unsure или Not Do;
  - каждой функции — оценку риска;
  - функция с низким риском в области Do не требует участия продакт-менеджера.
- **«What Is an Agentic Development Environment»** (2026-08-19) [67]:
  - узкое место — review;
  - планы, которые агенты не могут прочитать, устаревают;
  - Orca и Emdash названы соседями по категории.
- **«Overwhelmed Working with Coding Agents?»** (2026-10-02) — про wiki: агенты сжимают свою работу в короткую wiki для
  человека. Агент пишет, человек читает и правит, агент не должен выдумывать решения и цитаты [68].

### Чем подход отличается

То, что вендор называет своим отличием:

1. **Review правок AI в отрисованном документе, по блокам.** Это наследие Stravu [53][73][188].
2. **Не-кодовые артефакты — полноправные файлы, которые агенты читают и пишут:** mockups, модели данных (Prisma),
   Excalidraw, Mermaid, таблицы, листы расчётов, доски [73][76].
3. **Provenance — откуда взялось изменение.** Правки файлов, sessions и элементы tracker связаны в обе стороны [79][74]:
   - с 0.73.0 (2026-08-11) git log показывает, какая AI-session сделала каждый коммит;
   - заголовок редактора показывает последнюю session, которая трогала файл.
4. **Простые файлы и открытые форматы.** Определения trackers — YAML, документы — обычные файлы. Граф можно изучить без
   приложения [8][73].
5. **Независимость от вендора агента.** Двенадцать встроенных lanes. Пользователь приносит свой доступ. Nimbalyst не
   перепродаёт токены и не обходит лимиты [76][14].
6. **Одобряет человек — по правилу** [79][76]:
   - агенты никогда не отмечают session завершённой;
   - в полосе review tracker одобряет только человек;
   - коммит в другой worktree всегда требует одобрения на desktop, даже с автокоммитом.
7. **Ставка на совместную работу и мобильность** [10][76]:
   - общие документы и trackers с присутствием коллег;
   - сообщения и inbox организации;
   - приложения для iOS и Android, Live Activities на iPhone, список sessions в menu bar macOS.

Итог: центр продукта — review под управлением человека, совместная работа и широкий набор артефактов. Автономия — по
желанию и в alpha [3][82].

### Отношение к автономии

- **Все функции автономии — по желанию или alpha** [82][76][108][32]:
  - Super Loops, Blitz и Meta Agent — alpha-переключатели, выключены по умолчанию;
  - Crew — alpha, выключен по умолчанию, только на desktop, работает только при открытом проекте;
  - Agent Teams — экспериментальный переключатель, выключен по умолчанию.
- **Уровень по умолчанию Agent-verified не применяет своей policy Nimbalyst.** Он передаёт рискованные действия
  встроенному reviewer вендора: классификатору auto-mode из Claude SDK или `auto_review` в Codex [80].
- **Лимиты подписки:** auto-resume после сброса лимита Claude — по желанию, только lane Claude Agent, через
  wakeup [74][76]. Показ недельных лимитов по моделям [74]. Недельная история против линии равномерного темпа [76].
  Планирования запусков под лимиты не нашли (не подтверждено).
- **Собственный процесс разработки команды автоматизирован сильнее продукта** [84]:
  - команда `/orchestrate` в репозитории запускает соседние sessions с явным выбором модели, раздельным владением
    файлами для каждой части работы, независимыми reviewers на другой модели и журналом запуска (run ledger);
  - session-оркестратор запускает gate (`pnpm typecheck` и тесты перед push) один раз на пачку;
  - жёсткие правила обеспечивают git hooks.
- **Чего нет, по их собственной документации.** THE_HARNESS.md перечисляет как не сделанное [79]:
  - автоматический reviewer перед коммитом;
  - обязательный gate «сначала падающий тест»;
  - обнаружение конфликтов между параллельными sessions;
  - повтор (replay) упавших sessions;
  - монитор окна контекста.
- **В посте «6 Agents, 1 Manager, 0 Chaos» менеджер — человек:** он смотрит на Kanban, проверяет diffs и делает
  коммиты [58].

### Бизнес-модель и позиционирование

- **Open core.** Desktop- и iOS-приложения — MIT. Страница про open source не покрывает сервер синхронизации, web
  console и hosted wiki [9][77].
- **Деньги — с командных функций** (эссе про офисный пакет за $0) [57]. Teams станет платным после запуска [11][47].
- **Главная** называет продукт визуальным рабочим местом для Codex и Claude Code и заявляет, что это первое визуальное
  рабочее место для agentic development [1].
- **Работает рядом** с IDE и Claude Code Desktop, а не вместо них [64][4].
- **Своё эссе про ADE** (agentic development environment — среда разработки с агентами) ставит Nimbalyst в одну
  категорию с Orca и Emdash [67].
- **Объём маркетинга:** 40 страниц сравнения и 149 постов в блоге с июня 2025 года, большинство — сравнения и списки
  «лучших» [17][19].
- **Аудитория расширяется:** разработчики и продакт-менеджеры; страницы решений для маркетинга, исследований, quant,
  customer engineering и консалтинга; второй бренд NimWiki продаёт wiki о компаниях, рынках и стратегии с матрицами
  2x2. Это возвращает к исходной идее Stravu — помогать принимать решения [1][27][188].
- **Social proof:** полоса логотипов (Automattic, Amazon, Redfin, Vanta, Gainsight, Zillow, UKG, Twilio, Yahoo,
  Amperity) и заявление о «тысячах» пользователей. Ни кейсов, ни чисел нет; это заявления вендора [1][10].

### Цикл агента

- **Своего цикла агента для главных провайдеров нет.** Nimbalyst запускает агента каждого вендора и переводит его
  события в один формат transcript [81]:
  - `claude-code` («Claude Agent») — `@anthropic-ai/claude-agent-sdk` прямо в процессе приложения [81];
  - `openai-codex` — Codex app-server, JSON-RPC поверх stdio. Вариант через ACP — за экспериментальным
    переключателем [81];
  - `opencode` — локальный сервер OpenCode по HTTP/SSE (alpha) [81];
  - `copilot-cli` и `grok-build` — ACP поверх stdio; `cursor-agent` — новый headless-процесс с выводом NDJSON на каждый
    ход. Все три — alpha [81]. У них общий базовый класс: проверка предусловий, разрешения на каждый ход, сохранение
    сырых событий и обработка прерывания [93];
  - Gemini работает через language server Antigravity. Этот транспорт не хранит состояния и не умеет вызывать функции.
    Поэтому Nimbalyst сам ведёт цикл инструментов и каждый ход заново собирает всю беседу в один prompt [93];
  - chat-провайдеры (`claude`, `openai`, `lmstudio`) не имеют цикла работы с файлами [81].
- **Провайдер session фиксируется**, как только в ней есть сообщения [81].
- **Lane `claude-code-cli`** (с 0.65.0, 2026-06-09). Changelog подаёт её как работу на подписке Pro/Max без оплаты API
  по токенам [74]. Как она устроена [92]:
  - запускает интерактивный `claude` в PTY (псевдотерминале) на ghostty-web, никогда не в режиме `-p` (print);
  - `--session-id` — собственный id session Nimbalyst; `--resume` — при перезапуске; `--mcp-config` — loopback-адреса,
    в которых закодирована session;
  - разрешения: `--settings` добавляет PreToolUse hook для `Bash|Edit|Write|MultiEdit|NotebookEdit|WebFetch` с
    таймаутом 600 секунд. Hook вызывает loopback endpoint `/permission`. Режимы «разрешить всё» вместо этого используют
    `--dangerously-skip-permissions`. Комментарий в коде объясняет: интерактивный CLI молча игнорирует
    `--permission-prompt-tool`;
  - `--disallowedTools AskUserQuestion` отправляет вопросы агента в собственный MCP-инструмент Nimbalyst. Ещё флаги:
    `--append-system-prompt` и `ENABLE_TOOL_SEARCH=true`. Из окружения удаляются `ANTHROPIC_API_KEY` и `CLAUDECODE`;
  - transcript: `ANTHROPIC_BASE_URL` указывает на loopback-proxy. Proxy пересылает трафик в Anthropic и побайтно
    копирует поток SSE (server-sent events — потоковый ответ API). Заголовок OAuth проходит насквозь непрочитанным.
    Proxy сообщает об ответах 429 и 529. Сбои делятся на классы: context_limit, rate_limit, overloaded, auth, api_error
    и generic.
- **Процесс на каждый ход.** По объяснению сооснователя в issue #1177, каждый ход пользователя идёт отдельным
  процессом Claude Code CLI. Процесс живёт около 30 секунд после ответа, а следующий prompt запускает новый процесс с
  `--resume` [129]. Как это бьёт по prompt cache — в разделе «Что говорят пользователи».
- **Инструменты.** Собственные MCP-серверы Nimbalyst работают по HTTP/SSE на 127.0.0.1 [79][94]:
  - сервер ядра `nimbalyst` загружается сразу: AskUserQuestion, PromptForUserInput, display_to_user,
    update_session_meta;
  - остальные загружаются по требованию через ToolSearch Claude (поиск инструментов по запросу): `nimbalyst-host`,
    `nimbalyst-trackers`, `nimbalyst-situational` и по одному серверу на расширение.
- **Защита loopback.** При каждом запуске приложение создаёт случайный bearer token длиной 32 байта и держит его только
  в памяти. Это не даёт веб-страницам вызывать loopback-серверы [95].
- **Transcript.** Таблица `ai_agent_messages` только дописывается (append-only) и служит единственным сохранённым
  источником правды. Канонические события восстанавливаются в памяти, с cache последних 16 sessions. Ужатие
  сохранённых кусков сократило объём примерно на 60% [84][110].

### Декомпозиция задач

- **Kanban фаз:** backlog, planning, implementing, validating, complete. В complete переводит только человек [79]. Смены
  фаз пишутся в историю [101].
- **Планы** — через plan mode самого провайдера. Файлы планов — в `nimbalyst-local/plans` [94]. ExitPlanMode —
  сохраняемый запрос, на который отвечает человек [85].
- **Trackers** — типизированные элементы: планы, ошибки, функции. Коммит с текстом «Fixes NIM-123» сам закрывает
  связанный элемент [101]. Вид Ready упорядочивает элементы по тому, сколько работы каждый разблокирует, а элементы
  записывают, чего ждут [76].
- **Meta Agent — явный механизм декомпозиции** [87]: планирует, делегирует, следит; сам код не правит; создаёт как можно
  меньше детей; доказательством считает изменённые файлы ребёнка и его область инструментов, а не текст отчёта;
  получив полезное, пишет ответ.
- **Пресеты:** `default`, `implement-review-test`, `research`. `implement-review-test` для каждой части работы запускает
  session реализации, потом session review, потом session тестов. Работает сам и не задаёт человеку вопросов [87].
- **Super Loops** делят работу на фазы планирования и построения. На диске хранят `IMPLEMENTATION_PLAN.md`, `task.md` и
  `.superloop/progress.json` [106].
- **Структуры с зависимостями — вроде эпиков, задач и волн с порядком запуска — в коде не нашли.** Порядок оставлен
  Meta Agent или человеку. Это вывод исследователя из чтения кода; документа, который это говорит, нет.

### Параллельность и координация

Шесть механизмов — от самого ручного к самому автономному.

1. **Ручные параллельные sessions.** В посте «6 Agents, 1 Manager, 0 Chaos» менеджер — человек: он смотрит на Kanban,
   проверяет diffs и делает коммиты [58].
2. **Meta Agent** — за alpha-флагом, выключен по умолчанию. Флаг появился в 0.57.7 (2026-04-02) [82][74]:
   - инструменты сервера хоста перечислены в разделе «Функции» [88];
   - лимиты: не больше 4 детей в работе и 50 за жизнь (`MAX_IN_FLIGHT = 4`, `LIFETIME_BACKSTOP = 50`). Ожидающие и
     выполняемые сохранённые prompts считаются в четыре. Глубина дерева — до 256 [89][86];
   - сам Meta Agent не может править файлы: allowlist инструментов запрещает встроенные Read, Write, Edit и Bash, и в
     нём нет `spawn_session` [91];
   - **дети делят один каталог.** `create_session` игнорирует аргументы worktree. По описанию инструмента дети всегда
     работают в общем workspace, чтобы родитель читал их файлы. Значит, в запуске Meta Agent дети не изолированы друг от
     друга [88];
   - `spawn_session` вызывает и обычная session через `/launch-new-session`. Он работает в каталоге вызывающей session
     и создаёт worktree только по запросу (`useWorktree=true`). Отчёт: none, final или messages [88];
   - **модель дерева:** `parent_session_id` задаёт место в дереве, `created_by_session_id` называет manager. Перенос
     session в дереве никого не делает её manager [86].
3. **Blitz (alpha).** Один prompt — максимум на 10 новых worktrees. Когда все дети закончили, сама стартует session
   анализа и рекомендует победителя [107]. Выпущен в 0.52.68 (2026-02-13) [74].
4. **Agent Teams (экспериментальный).** `TeammateManager` перехватывает командные инструменты Claude. PreToolUse hook
   ловит вызовы `Task` с `team_name` и вызовы `SendMessage` и запрещает их. Вместо этого каждый участник запускается
   внутри процесса через `query()`. Состояния: running, idle, completed. Сообщения идут через `streamInput()`,
   запасной путь — inbox в файле [105][32].
5. **Crew (alpha с 0.79.0, 2026-09-29).** Долгоживущие персоны: у каждой работа, расписание и журнал. Они работают
   сменами в своих sessions [108][74]. По умолчанию — 60 млн токенов в неделю и 6 смен в день на участника, 600 млн в
   неделю на всю Crew. Новая «глава» — при 70% контекста или через 7 дней [108].
6. **Automations.** Файлы Markdown, где во frontmatter (блоке настроек в начале файла) задано расписание: интервал,
   ежедневно или еженедельно. Папка сканируется каждые 30 секунд [109].

**Координация между параллельными sessions, которые пишут в один репозиторий:**

- Блокировка `GitOperationLock` на репозиторий выполняет разрушающие git-операции по одной. Таймаут по умолчанию —
  30 секунд [102].
- Merge и rebase сначала проверяют конфликты [102][76].
- **Пересечение правок одного файла в живых sessions не решено:**
  - блог пишет, что sessions, которые трогают одни и те же файлы, помечаются [58];
  - документ harness перечисляет автоматическое обнаружение конфликтов между параллельными sessions как несделанное и
    пишет, что команда полагается на то, что человек заметит это через `git status` [79];
  - документ harness предлагает ручную проверку через `get_workstream_edited_files` и список sessions по каждому
    файлу [79];
  - **есть ли автоматическое предупреждение — не подтверждено.**

### Изоляция

- **Worktrees** создаются через simple-git в `../<project>_worktrees/<name>`, на ветке `worktree/<name>` [102]. Документ
  `docs/WORKTREES.md` последний раз менялся 2026-01-12 и старше кода [103]. Несколько sessions могут делить один
  worktree [76].
- **Операции с worktree** [102]: создать; merge в базовую ветку (нужен чистый каталог, берётся блокировка); rebase от
  базовой ветки с автоматическим stash; squash; статус; архив с фоновой очисткой, которая повторяется при старте.
- **Super Loops:** один активный цикл на worktree [106].
- **Локальных контейнеров и VM нет.** Агенты работают от имени пользователя на его компьютере, внутри sandbox своего
  провайдера:
  - Codex: «ask» — read-only и одобрение по запросу; «Allow edits» — `workspace-write`; «Allow everything» —
    `danger-full-access` [104];
  - Claude: доступ к файлам по умолчанию внутри workspace, чувствительные пути закрыты [80].
- **Удалённый вариант** (0.78.0, 2026-09-14) [74]. Пользователь разворачивает sandbox Cloudflare как приватный Worker в
  своём аккаунте Cloudflare [114]:
  - один экземпляр `standard-3`, засыпает после 5 минут простоя, диск не сохраняется;
  - `enableInternet=false` и allowlist исходящих адресов: github.com, api.anthropic.com, platform.claude.com,
    console.anthropic.com, sync.nimbalyst.com;
  - одновременно наблюдаются не больше 4 удалённых transcripts;
  - OAuth-ключ подписки копируется в sandbox;
  - в sandbox работает headless runner, который подключается к личной синхронизации как устройство «headless» [115].

### Память и контекст

- **Счётчик контекста и монитор контекста — источники расходятся.** Inventory описывает счётчик заполнения окна
  контекста с отслеживанием темпа [76]. THE_HARNESS.md называет монитор окна контекста несделанным [79]. Возможно, речь
  о разном: показ в интерфейсе против автоматической реакции (не подтверждено). Классификатор ошибок CLI распознаёт
  сбой `context_limit` [92].
- **Контекст держат малым за счёт устройства:**
  - Super Loops начинают свежую session на каждой итерации и переносят выводы в `progress.json` [106];
  - «главы» Crew сменяются при 70% контекста [108];
  - редкие инструменты загружаются лениво через ToolSearch [79][94].
- **Главный рычаг стоимости — исправления prompt cache** [74]:
  - 0.70.2 (2026-07-21) убрал сброс cache посреди session. Его вызывали обновления тегов, автоматическое название
    session и поздно подключившиеся серверы расширений. В том же релизе поменяли загрузку редких встроенных
    инструментов;
  - 0.72.8 (2026-08-07) перестал переписывать cache на большинстве ходов;
  - maintainer в issue #889 2026-07-23 написал, что сброс cache посреди session исправлен в 0.70.5. Changelog относит
    исправления к 0.70.2 и 0.72.8. Источники расходятся [128][74].
- **Память проекта** — `CLAUDE.md` и два расширения:
  - **«Nimbalyst Memory»** (v0.1.2, выключено по умолчанию). Индексирует markdown проекта в одноразовый индекс SQLite
    кусками по 200–500 токенов. Ранжирует локально по BM25 (классический алгоритм поиска по словам). Может смешивать
    результаты с плотными embeddings через Reciprocal Rank Fusion (слияние рейтингов двух поисков). Отдаёт факты и
    инструмент `recall` по MCP [121];
  - **«Wiki»** (knowledge, включено по умолчанию). Учит агентов писать страницы решений с типизированными
    связями [122].
- **Граф знаний заменили на wiki.** Прежние claims, qualifiers и knowledge packs убрали в пользу страниц wiki
  (сентябрь–октябрь 2026) [74][76].
- **Самоулучшение.** Команда запускает у себя цикл `/analyze-sessions`: он ищет в прошлых sessions, что улучшить в
  harness [79].

### Проверка качества

- **Встроенного gate на тесты и автоматического reviewer нет.** Документ harness перечисляет reviewer-subagent перед
  предложением коммита как несделанный [79].
- **Что есть:**
  - **review каждой правки.** Счётчик очков связывает каждое изменение файла с вызовом инструмента, который его сделал:
    +100, +40 или +30 очков, порог — 30, окно — 10 секунд. Правки ждут review за панелью одобрения. Коммит в git
    одобряет ожидающие diffs, которые в него вошли. Одна session может изменить не больше 500 файлов [100];
  - **предложения коммитов.** Агент предлагает, человек одобряет. Настройка `autoCommitEnabled` пропускает одобрение.
    Коммит в другой worktree всегда требует одобрения [101];
  - **пресет `implement-review-test`** запускает sessions review и тестов. Ничто не заставляет их работать как
    обязательный gate [87];
  - **session анализа Blitz** сравнивает N попыток [107];
  - **расширение Playwright** (alpha): `list_tests`, `run_test`, `get_failures`, `get_flaky_tests`, `get_history` [124];
  - **PR** опрашиваются каждые 60 секунд на переднем плане и каждые 5 минут в фоне. Проверки CI берутся через
    `gh` [112];
  - **полоса review в trackers:** одобряет только человек [76].
- **Свой процесс команды строже продукта:** `/orchestrate` с независимыми reviewers на другой модели и gate на пачку —
  это в репозитории, а не в продукте [84].

### Восстановление после сбоев

- **Ошибки хода.** Повторяются только транспортные ошибки «Stream closed», не больше двух раз
  (`MAX_STREAM_CLOSED_RETRIES = 2`). Ошибки сервера API не повторяются: человек получает подсказку проверить
  status.anthropic.com [97].
- **Лимиты.** Событие SDK `rate_limit_event` несёт статус, время сброса, тип (например, `five_hour`) и долю
  использования. Nimbalyst превращает его в метку в transcript и время сброса, привязанное к ошибке [97].
- **Auto-resume** (по желанию, с 0.81.1) [96][74]:
  - назначает wakeup через минуту после сброса лимита;
  - разносит sessions по 30 секунд друг от друга, чтобы они не стартовали разом;
  - пропускает сброс, до которого больше 7 дней;
  - отправляет «Continue.» с системной пометкой, почему работа остановилась;
  - любой новый ход отменяет его;
  - работает только для провайдера Claude Agent.
- **Wakeups.** Их ведёт один таймер, строки сохраняются в базе. Пока приложение закрыто, ничего не срабатывает. Wakeups
  ждут, пока закрыто окно их workspace. Просроченные на момент запуска показываются человеку, а не срабатывают [98].
  Агент сам назначает wakeup через `schedule_wakeup` (0.58.5, 2026-04-28) [74].
- **Зависшие ходы.** Для каждого идущего хода раз в минуту срабатывает heartbeat — отметка «ход жив» по часам, а не по
  токенам. По нему полоса в menu bar, панель island и Live Activity на iOS помечают молчащую session «not responding»
  через 15 минут. После 4 часов heartbeat перестаёт утверждать, что ход жив [99].
- **Другие модули восстановления** [99]:
  - снимают «зомби»-состояние running у sessions, которые на самом деле не работают;
  - при запуске заново отправляют ожидающие prompts из очереди;
  - сливают до 20 prompts из очереди в один.
- **Перезапуск.** Возобновляется только CLI session в фокусе. Так перезапуск всех sessions разом не упирается в rate
  limit подписки (0.65.0) [74][99].
- **Super Loops** [106]:
  - останавливаются после 3 неудачных итераций подряд, с паузами 5, 10 и 20 секунд;
  - по умолчанию не больше 20 итераций;
  - при перезапуске идущие циклы становятся paused, а осиротевшие итерации — failed;
  - заблокированный цикл продолжает работу, когда человек дал обратную связь;
  - таймаута на итерацию нет.

### Лимиты и стоимость

- **Счётчики.** Приложение читает OAuth-токен Claude из Keychain macOS или из `.credentials.json`. Раз в 30 минут
  опрашивает `https://api.anthropic.com/api/oauth/usage`; после 60 минут простоя пользователя опрос останавливается.
  Показывает окна 5 часов, 7 дней и недельные окна по моделям, хранит недельную историю. Для Codex и Gemini — свои
  службы расхода [111]. Публичная страница AI Usage Report описывает только счётчики токенов и инструментов и отсылает
  к панели провайдера за лимитами [35]. Совпадает ли она с кодом — не подтверждено.
- **Бюджеты и потолки:**
  - бюджеты токенов Crew на участника и на всю Crew [108];
  - потолки Meta Agent на число детей [89];
  - Blitz — не больше 10 worktrees [107];
  - Super Loops — 20 итераций по умолчанию [106].
- **Планирования запуска под оставшийся лимит не нашли** (не подтверждено) [76].
- **Реальная стоимость** — главная жалоба пользователей. Замеры и объяснение причины — в разделе «Что говорят
  пользователи» [128][129].

### Права и безопасность

- **Четыре уровня автономии** выбираются в диалоге доверия при первом открытии проекта; подробно — в разделе
  «Функции» [80].
- **Секреты.** API keys провайдеров берутся только из настроек Nimbalyst, никогда из `process.env` [84]. Путь CLI
  удаляет `ANTHROPIC_API_KEY` из окружения [92]. Loopback MCP-серверы требуют bearer token текущего запуска [95].
- **Место, за которым стоит следить** (по чтению кода, без проверки запуском):
  - инструкции Meta Agent велят всегда одобрять запросы детей на уровне session [87];
  - `respond_to_prompt` входит в список инструментов, который строит MCP endpoint хоста [95][88];
  - `MetaAgentService.respondToPrompt` проверяет только, что вызывающий находится в том же workspace [90]. Проверки, что
    вызывающий управляет целевой session, исследователь не нашёл;
  - alpha-флаг прячет роль Meta Agent в интерфейсе, но инструменты хоста за этим флагом не стоят [82][95];
  - может ли session, которая не управляет другой, ответить на её запросы разрешений, — не подтверждено.
- **Sandbox Cloudflare получает копию OAuth-ключа подписки** [114].
- **Данные команд — не zero-knowledge** [76].
- **Телеметрия** — анонимная PostHog [73].
- **Где решает человек** [80][85][94][100][79][26][88][98][106][87]:
  - диалог доверия и запросы разрешений с выбором области;
  - сохраняемые запросы, которые переживают перезапуск: вопросы, ввод, выход из плана, предложения коммитов,
    разрешения. У AskUserQuestion нет таймаута, hook разрешений SDK ждёт до 24 часов;
  - одобрение каждой правки; только человек отмечает session завершённой;
  - телефон: одобрения в iOS-приложении, push при срочности «critical»;
  - просроченные wakeups ждут клика; заблокированный Super Loop ждёт обратной связи;
  - на другом краю — пресет `implement-review-test`, который не спрашивает человека ни о чём.

### Наблюдаемость

- Живые transcripts строятся из событий SDK, из JSON-RPC app-server или из копии SSE [92][110]. Приложение может следить
  и за внешними sessions Claude, которые запустило не оно (0.78.1, 2026-09-17) [74].
- Каждое изменение файла привязано к session. Точность зависит от провайдера: structured, tool-args или none [100].
  Виды workstream показывают изменённые файлы [79].
- Виджеты rate limit в transcript (0.55.2, 2026-03-01) и счётчики расхода с историей [74][111].
- Поверхности статуса, которые видны всегда: полоса в menu bar, панель island и Live Activity на iOS [99].
- Project Graph (alpha, выключен): один граф стратегии, планов, модулей, trackers, sessions, коммитов и файлов с
  сохранёнными видами [123].
- Скриншотов-доказательств с удалением личных данных не нашли. Есть расширение браузера для превью HTML-файлов и живых
  адресов [120].

  - другой заметил, что приложение само добавило себя в автозапуск (login items);

- **Так и не сделали в Crystal** [164]: auto-resume после лимитов (#18, июнь 2025), удалённый или серверный режим,
  понятную работу без пропуска проверок разрешений (skip-permissions).
- **Ещё:**
  - один пользователь выбрал Conductor вместо Crystal только из-за наглядного списка задач (2025-08-01) [164];
  - на HN название путали с языком программирования Crystal и рано советовали его сменить (2025-09) [171]. Повлияло ли
    это на бренд Nimbalyst — не подтверждено;
  - автор говорил, что его собственная параллельная работа стоила бы $24 тыс. в месяц по ценам API (2025-07-03) [171].
    Большой расход токенов заложен в саму идею продукта.

### С чем сравнивают

- **Claude Code CLI и расширение для VS Code:** больше токенов на ту же работу [128][129]. До октября 2026 года не было
  auto-resume [149].
- **Codex CLI:** медленнее [143].
- **vibe-kanban:** автор #889 пишет, что vibe-kanban так не расходовал токены [128].
- **Orca:** пользователи Orca перешли бы ради общей доски по всем проектам или headless-режима [154][159].
- **Conductor:** во времена Crystal работал плавнее и имел наглядный список задач [164]. Пользователи HN замечают, что
  Conductor работает только на Mac [169].
- **tmux и herdr:** рядом с Nimbalyst держат терминальный мультиплексор, потому что агенты не читают вкладки терминала
  Nimbalyst [160].
- **Cursor:** нет режима Vim — единственное, что мешает одному пользователю перейти [160]. Блогер считает их почти
  равными [181].
- **Claude Code Desktop:** пост самого CEO признаёт, что официальное приложение получает функции первым. Сам он держит
  установленными оба [64].
- **Соседей много.** Пользователь HN назвал около десятка похожих инструментов: Paseo, Orca, Kepler, Emdash, Superset,
  Conductor, Parallel Code, JetBrains Air [170].
- **Вторичные обзоры:**
  - Augment относит Nimbalyst к инструментам, где человек сам раздаёт работу агентам и следит за ней, и отмечает, что
    поддерживаемых агентов меньше [183];
  - гид amux написан конкурентом. Он отмечает, что агенты останавливаются, когда компьютер спит, но всё же называет
    Nimbalyst лучшим визуальным рабочим местом [184];
  - ReviewNexa приводит результаты тестов с числами без источников и пишет, что приложение было под MIT в то время, когда
    код ещё был закрыт. Доверие к этому обзору низкое [186];
  - отзывы на главной, заявление о «тысячах» пользователей и список компаний — слова самого вендора, они не

### Что убрали или переосмыслили

1. **Закрытый код стал открытым.** С декабря 2025 по апрель 2026 года [173][53].
2. **Облачный блокнот стал локальным desktop-приложением** [188][1].
3. **Шифрование команд.** В феврале 2026 года — end-to-end с ключами у клиента. Потом — серверное, с ключами под KMS.
   Inventory прямо пишет, что это не zero-knowledge. Причина — доступ из web, CLI и облачных агентов. Личная
   синхронизация осталась zero-knowledge [74][76].
4. **Как подключён Claude.** Сначала — только Agent SDK. 2026-05-24 CEO написал, что OpenAI явно поддерживает такие
   продукты, а сообщения Anthropic путаные. 2026-06-10 он объявил два варианта: SDK с API key или CLI с подпиской [134].
   Lane CLI до сих пор выключена по умолчанию [76]. Справка Anthropic теперь пишет: при входе через подписку расход
   идёт из лимитов плана, а изменения, запланированные на июнь, приостановлены [187].
5. **Граф знаний заменили страницами wiki.** Прежние claims, qualifiers и knowledge packs убрали (сентябрь–октябрь
   2026) [74][76].
6. **Частые переименования.** Shared Docs стали Pages, потом Wiki — за несколько дней [74].
7. **Правки коллег в общих trackers больше не проходят accept/reject.** Правки AI по-прежнему проверяются (август
   2026) [74].
8. **Иерархию sessions переопределяли четыре раза** [74][76]:
   - worktree считается workstream (май);
   - вложенные деревья (октябрь);
   - дочерние sessions по умолчанию не отчитываются родителю (2026-10-23);
   - контейнеры-«соседи» (ещё не выпущены).
9. **Alpha-функции раньше зависели от канала релизов, теперь включаются отдельными переключателями** [82].
10. **Слова про harness расходятся.** На главной — «семь частей», на странице harness — восемь опор. THE_HARNESS.md
    пишет «seven layers», но его таблица перечисляет восемь [1][5][79].
11. **Лицензия сервера синхронизации.** При подготовке к открытию кода (2026-04-28) он лежал в репозитории под
    AGPL-3.0. 2026-05-19 его убрали. Теперь это отдельный проект, лицензия не указана [78][74][77][9].

## Слабые места и чего нет

### Стоимость и лимиты

- **Расход квоты — главная жалоба пользователей.** Замер в issue #1177: запись в cache на ход в 3,49 раза больше, чем в
  CLI, стоимость хода — примерно в 1,8 раза выше [129]. Issue #889 открыт с июля [128]. Похожие отчёты — #823 и
  #662 [130][131].
- **Причина — в устройстве процесса.** Каждый ход — отдельный процесс CLI с `--resume` [129]. Исправления cache вышли в
  0.70.2 и 0.72.8, но теста, который сравнил бы одинаковую работу, нет [74][128].
- **Auto-resume узкий:** включается по желанию, работает только для провайдера Claude Agent и пропускает сброс, до
  которого больше 7 дней [96][97].
- **Ошибки сервера API не повторяются.** Повторяются только обрывы потока «Stream closed», не больше двух раз [97].
- **Планирования запусков под лимиты и режима экономии (eco) не нашли** (не подтверждено) [76].

### Работа без присмотра

- **Всё работает, только пока открыто приложение.** Automations пропущенные запуски не выполняют [22]. Wakeups при
  закрытом приложении не срабатывают, а просроченные ждут клика человека [98]. Crew работает только при открытом проекте и
  выполняет пропущенную смену один раз при открытии [76][108].
- **Ноутбук не годится как хост:** агенты останавливаются, когда закрыта крышка [153]. Гид конкурента отмечает то
  же [184].
- **Вся автономия — alpha или по желанию:** Meta Agent, Super Loops, Blitz, Crew, Agent Teams [82].
- **Meta Agent:**
  - дочерние sessions из `create_session` работают в одном общем каталоге и не изолированы друг от друга [88];
  - не больше 4 детей одновременно и 50 за жизнь [89];
  - инструкции велят всегда одобрять запросы разрешений детей на уровне session [87];
  - `respond_to_prompt` проверяет только, что вызывающий в том же workspace [90];
  - открытые ошибки: лишние дети, зависшие статусы, остановка оркестратора [148];
  - сообщение во время работы фоновых sub-agents уничтожает их работу без записи о потере [147].
- **Фоновые sub-agents получают отказ** даже на вызовы из allowlist (#1364, открыт) [151].
- **Сбои Automations:** зависания, пропуски, выключенная automation продолжала запускаться, на Windows планировщик не
  срабатывал [150].

### Проверка качества и координация

- **Нет встроенного gate.** THE_HARNESS.md перечисляет как несделанное: автоматический reviewer перед коммитом,
  обязательный gate «сначала падающий тест», повтор (replay) упавших sessions [79].
- **Нет автоматического обнаружения правок одного файла в нескольких sessions.** Блог пишет, что такие sessions
  помечаются, а документ harness — что это не сделано. Источники расходятся [58][79].
- **Kanban точен, только если агенты сами обновляют фазу.** У одного пользователя 184 sessions без фазы [146].
- **Review правок — после записи на диск.** Revert агенту не сообщается [144][51].
- **Review PR ограничен** [34][112][72]:
  - нельзя писать inline-комментарии и запрашивать изменения;
  - только GitHub, запрос на GitLab открыт;
  - checks не обновляются вживую — их опрашивают раз в 60 секунд или 5 минут;
  - экрана создания PR не нашли (не подтверждено).

### Поверхности рядом с агентом

- **Project Canvas — только для файлов.** Карточки для session агента нет, MCP-инструмента для досок нет: агенты пишут
  JSON доски напрямую [39][119].
- **В терминале нет AI-помощника** [42]. Агенты не читают вкладки терминала, поэтому пользователи держат рядом tmux [160].
- **Менеджера профилей браузера не нашли** (не подтверждено) [41].
- **Скриншотов-доказательств с удалением личных данных нет.** Удаление личных данных есть только в процессе отчёта об
  ошибке [76].

### Удалённая работа и платформы

- **Remote SSH нет** — это самый популярный открытый запрос [153][72].
- **Удалённый sandbox Cloudflare** [76][115][114]:
  - получает копию OAuth-ключа подписки;
  - удалённо нельзя ответить на вопросы и запросы разрешений;
  - на удалённой стороне не создаётся worktree;
  - одновременно — не больше 4 удалённых transcripts;
  - состояние выполнения теряется при перезапуске хоста.
- **Синхронизации sessions между двумя desktop нет** (#1628) [72].
- **Windows:** тихие выходы, нехватка памяти в renderer, задержки 15–20 секунд при переключении sessions [135][136][137].
- **Нагрузка:** падения при 6–10 sessions, перегрузка встроенной базы, 100% CPU после запуска [138][139][140].
- **Обновления:** версии ломали отправку сообщений и правку markdown [141][142]. Режима обновления только вручную
  просят [161].
- **Путь Codex медленнее самого Codex** [143].
- **Android** — alpha, отстаёт от iOS, публичная доступность не подтверждена [116][155][26].
- **Интерфейс только на английском** [49].
- **Electron:** вторичный обзор и пользователь пишут, что он тратит больше ресурсов, чем нативное приложение [180][157].

### Команда, доверие и документация

- **Данные команд — не zero-knowledge:** ключами команд управляет Nimbalyst [76].
- **SLA не опубликован** [180]. SOC 2 Type II заявлен без аудитора и даты [15].
- **Нагрузка на maintainers.** Руководитель проекта один [77]. 463 открытых issues не разобраны [72]. Участники
  проекта ждут решений maintainer по готовым исправлениям, а автор дизайна headless-режима ушёл к другому
  проекту [147][154].
- **Термины часто меняются:** workstream переопределяли четыре раза, Pages за три дня стали Wiki, harness — то семь
  частей, то восемь [74][76][1][5][79].
- **Документация отстаёт от кода:** `docs/WORKTREES.md` последний раз менялся в январе 2026 года [103]; страница web
  console, вероятно, устарела [48]; документация review правок обещала обратное тому, что делал код [144].

## Пересечение с worfy

Термины worfy в этом разделе:

- Canvas — бесконечное полотно, на котором worfy показывает работу агентов. Cards — карточки, которые агенты строят на
  Canvas через MCP. У Nimbalyst есть свой Project Canvas, но на нём лежат файлы, а не sessions [39].
- Epic — группа связанных Ticket-ов. Ticket — одна задача.
- Orchestrator — session, которая планирует работу и раздаёт Ticket-ы.
- Wave — набор Ticket-ов, которые запускаются вместе. Autopilot — запуск Wave-ов без человека: он ждёт сброса лимитов
  подписки, повторяет запросы после ошибок API и одобряет запросы разрешений по заданной policy.
- Gate — локальный запуск проверок для Ticket.
- Harness worfy — plugin, который приносит в Claude Code rules, skills, subagents и hooks. У Nimbalyst слово «harness»
  шире: постоянный слой проекта вокруг модели, которым владеет команда, с восемью опорами — от контекста до
  координации [5][63].
- Flight Recorder — временная шкала запуска без присмотра. Work track — вся работа проекта за день или неделю.
- Product Session — советник по продукту с живым Mind map и критиком спецификаций.
- PR inbox — список входящих PR. Linked machines — компьютеры, связанные по локальной сети.
- Evidence — screenshots-доказательства с удалением личных данных. У Nimbalyst «Evidence Trails» — это вид Project
  Graph, а не screenshots [44]. Eco mode — режим экономии лимитов.

## Механизмы, которые стоит изучить

### 1. Настоящий `claude` CLI в PTY с hook разрешений и копирующим proxy

- **Что это.** Lane, которая запускает интерактивный `claude` в псевдотерминале, а не через SDK [92][74].
- **Как работает** [92]:
  - `--session-id` и `--resume` держат одну session;
  - `--settings` добавляет PreToolUse hook на `Bash|Edit|Write|MultiEdit|NotebookEdit|WebFetch` с таймаутом
    600 секунд. Hook спрашивает loopback endpoint `/permission`;
  - `ANTHROPIC_BASE_URL` указывает на loopback-proxy. Proxy побайтно копирует поток SSE для transcript, заголовок OAuth
    не читает, сообщает об ответах 429 и 529;
  - сбои делятся на классы: context_limit, rate_limit, overloaded, auth, api_error, generic.
- **Чем интересно.** Приложение получает структурированный transcript и свои одобрения, а трафик остаётся трафиком
  обычного CLI на подписке.
- **Источник:** [92][74].

### 2. Сохраняемые интерактивные запросы

- **Что это.** Вопросы, ввод, выход из плана, предложения коммитов и запросы разрешений хранятся в базе и переживают
  перезапуск [85].
- **Как работает.** Запрос и ответ — строки в базе. Телефон опрашивает их [80]. У AskUserQuestion нет таймаута, hook
  разрешений SDK ждёт до 24 часов [85][94]. Meta Agent отвечает детям через `respond_to_prompt`, а ожидающие запросы
  считаются в лимит из четырёх детей [89].
- **Чем интересно.** Ответить можно с другого устройства, позже или из другой session.
- **Источник:** [85][80][94][89].

### 3. Привязка каждой правки к вызову инструмента

- **Что это.** Счётчик очков решает, какой вызов инструмента сделал изменение файла [100].
- **Как работает.** +100, +40 или +30 очков, порог — 30, окно — 10 секунд. Снимки файла до и после правки сжаты gzip и
  подписаны хешем SHA-256, связи хранятся в таблице `session_files`. Одна session меняет не больше 500 файлов. Каждый
  провайдер сообщает точность: structured, tool-args или none [100][76].
- **Чем интересно.** Meta Agent считает доказательством изменённые файлы ребёнка, а не текст его отчёта [87].
- **Источник:** [100][76][87].

### 4. Auto-resume через wakeups с разнесением запусков

- **Что это.** Возобновление sessions после сброса лимита подписки [96].
- **Как работает:**
  - событие `rate_limit_event` даёт время сброса [97];
  - wakeup ставится через минуту после сброса, плюс 30 секунд на каждую session, которая уже ждёт. Сброс дальше 7 дней
    пропускается. Session получает «Continue.» с системной пометкой, почему работа остановилась. Любой новый ход
    отменяет wakeup [96];
  - wakeups хранятся в базе. Просроченные к запуску приложения показываются человеку, а не срабатывают [98];
  - после перезапуска приложения сама продолжает работу только CLI session в фокусе [74][99].
- **Чем интересно.** Sessions не стартуют разом и не упираются в rate limit сразу после сброса.
- **Источник:** [96][97][98][99][74].

### 5. Heartbeat живого хода

- **Что это.** Отметка «ход жив», которая не зависит от токенов [99].
- **Как работает.** Раз в минуту для каждого идущего хода. Через 15 минут тишины menu bar, панель island и Live Activity
  помечают session «not responding». После 4 часов heartbeat перестаёт утверждать, что ход жив. Отдельные модули
  снимают ложный статус running и заново отправляют prompts из очереди при запуске [99].
- **Чем интересно.** Долгий ход отличается от зависшего, даже когда модель долго молчит.
- **Источник:** [99].

### 6. Цена процесса на ход и порядок в prompt cache

- **Что это.** Публичный замер и объяснение, сколько стоит новый процесс CLI на каждый ход [129][128].
- **Как работает.** Каждый ход — новый процесс с `--resume`. Снимок `git status` собирался заново и ломал совпадение
  prefix: 62,8% первых ходов переписывали весь prefix против 0,4% внутри одного процесса. Исправление — `git status`
  один раз на session [129][74]. Ещё cache сбрасывали обновления тегов, автоматическое название session и поздно
  подключившиеся серверы расширений (0.70.2) [74]. Редкие инструменты загружаются лениво через ToolSearch [79][94].
- **Чем интересно.** Видно, какие изменения контекста посреди session стоят денег.
- **Источник:** [129][128][74][79][94].

### 7. Потолки Meta Agent, правило доказательств и allowlist

- **Что это.** Ограничения, которые держат оркестратор в роли оркестратора [87][88].
- **Как работает:**
  - не больше 4 детей одновременно и 50 за жизнь; ожидающие prompts тоже считаются [89];
  - allowlist запрещает Read, Write, Edit и Bash, в нём нет и `spawn_session` [91];
  - полный ответ ребёнка режется на 50 000 символов [88];
  - дерево глубиной до 256. Manager — тот, кто создал session. Отчёт: никакой, финальный или по ходу работы; по
    умолчанию никакой [86][74].
- **Чем интересно.** Оркестратор технически не может сам править код и не может запустить больше детей, чем
  разрешено.
- **Источник:** [87][88][89][91][86][74].

### 8. Blitz с автоматическим сравнением

- **Что это.** Один prompt в нескольких изолированных worktrees [107][76].
- **Как работает.** До 10 worktrees. В варианте «model blitz» worktrees подписаны именами моделей. Когда все дети
  закончили, сама стартует session анализа: она сравнивает результаты через `get_session_summary` и
  `get_workstream_edited_files` и рекомендует победителя [107][76].
- **Чем интересно.** Выбор лучшего из нескольких вариантов делает агент, а не человек.
- **Источник:** [107][76].

### 9. Super Loops

- **Что это.** Автономный цикл над одной задачей в своём worktree [106][74].
- **Как работает.** Каждая итерация — свежий контекст и файлы `.superloop/task.md`, `IMPLEMENTATION_PLAN.md`,
  `.superloop/progress.json`. Сначала планирование, потом построение. По умолчанию 20 итераций. После 3 неудачных
  итераций подряд цикл останавливается, паузы между попытками — 5, 10 и 20 секунд. При перезапуске идущие циклы
  становятся paused. Один цикл на worktree. Таймаута на итерацию нет [106].
- **Чем интересно.** Контекст не копится: прогресс живёт в файлах.
- **Источник:** [106][74].

### 10. Бюджеты и «главы» Crew

- **Что это.** Постоянные персоны-агенты, которые работают сменами [108][76].
- **Как работает.** По умолчанию — 60 млн токенов в неделю и 6 смен в день на участника, 600 млн в неделю на всю
  Crew. Cache tokens тоже считаются. Новая «глава» — при 70% контекста или через 7 дней. Уровни уведомлений note, flag
  и page, тихие часы. Пропущенная смена выполняется один раз при открытии проекта [108][76].
- **Чем интересно.** Бюджет задан на персону и на неделю, а не на запуск.
- **Источник:** [108][76].

### 11. Очередь prompts: аренда, восстановление и слияние

- **Что это.** Prompts, которые пришли, пока агент работает [99][75].
- **Как работает.** Prompts в очереди хранятся в базе с арендой владения (lease). При запуске ожидающие отправляются
  заново. До 20 prompts сливаются в один ход [99]. С 0.83.0 сообщения от человека и от других sessions доставляются
  вместе одним ходом, у каждого — пометка автора. Slash-команды идут отдельным ходом [75][76].
- **Чем интересно.** Session получает всё накопившееся за один ход и знает, кто что написал.
- **Источник:** [99][75][76].

### 12. Agent-verified: решение о риске принимает классификатор вендора

- **Что это.** Уровень автономии по умолчанию [80][36].
- **Как работает.** У Claude — классификатор auto-mode из SDK (`permissionMode: 'auto'`). У Codex — `workspace-write` с
  `approvals_reviewer = "auto_review"` [80][104]. Что reviewer вендора не одобрил, приходит человеку. Поверх —
  жёсткие правила: `~/.ssh` и `~/.aws` закрыты, сеть — через allowlist, составные shell-команды одобряются только
  разово, в недоверенном проекте всё запрещено [36][80]. С 0.82.0 в режиме «Allow everything» с проверками hook,
  который просит одобрения, ждёт человека [74].
- **Чем интересно.** Своей policy не нужно, но решение о риске остаётся у вендора.
- **Источник:** [80][36][104][74].
