## Модель работы

**Где работает: hybrid, с упором на облако.**
- Devin Cloud — исходный продукт. Каждая сессия идёт на отдельной VM в облаке Cognition [84][189].
  - Внутри — shell, IDE и браузер [84][1].
  - Позже добавлен полный рабочий стол с управлением мышью и клавиатурой (computer use) [94][38].
- Devin Desktop (бывший Windsurf) и Devin CLI работают на машине пользователя. Оба используют один локальный агент — Devin Local [137][146]. Devin Cloud для Desktop не обязателен: Desktop работает и с одними локальными агентами [132].
- Связь локальной и облачной работы:
  - `/handoff` переносит локальную работу в облачную сессию и обратно [152];
  - Local Hands даёт облачной сессии инструменты на машине пользователя [110];
  - Outposts — именованные очереди облачных сессий, которые обслуживают машины клиента [164];
  - Desktop показывает локальных и облачных агентов в одном окне [133][134].
- Облачная часть делится на две половины [189]:
  - Brain — сервис планирования без собственного состояния (stateless). Всегда работает в облаке Cognition.
  - Devbox — VM, где исполняется код. Только Devbox может переехать в сеть клиента.
- В мае 2026 года Cognition сообщила: впервые сессий, запущенных событиями, automations, расписаниями и другими Devin, стало больше, чем запущенных человеком [38].

**Размещение для компаний.**
- Enterprise Cloud — общий (multi-tenant) сервис. У каждой сессии своя изолированная машина [189].
- Customer Dedicated Deployment — Devbox в выделенной (single-tenant) VPC клиента. VPC — частная облачная сеть. Связь через AWS PrivateLink или туннель IPSec. Машины создаются на каждую сессию [189].
- Devin Connect — шлюз внутри сети клиента [190]:
  - HTTP CONNECT proxy с allowlist, где по умолчанию всё запрещено;
  - доступ через исходящий reverse tunnel или через PrivateLink;
  - конфигурация проверяется по принципу fail-closed: ошибка в конфигурации закрывает доступ;
  - конфигурация перечитывается каждые 5 секунд.
- Outposts — машины клиента обслуживают облачные сессии из очереди [164].
- Федеральный сектор США:
  - работает в AWS GovCloud [193];
  - Desktop и CLI имеют FedRAMP High, IL4 и ITAR — американские государственные допуски по безопасности; облако ещё в процессе получения [194][50];
  - Desktop и CLI без доступа к интернету (air-gapped) — в бета. Модели размещает заказчик, лицензия — подписанный файл, audit log — локальный [195].
- Где физически работает облако — источники расходятся (не подтверждено): подпись к схеме на странице размещения называет Azure [189], страница безопасности говорит об AWS-окружении Cognition [184].

**Агенты и модели.**
- Основной агент — собственный агент Devin. Для каждой сессии выбирается режим: Lite, Normal, Ultra, Fusion, SWE-2 или Free. Подробности — в разделе «Функции» [85].
- В планы входят модели Anthropic, OpenAI, Google и Cognition, а также DeepSeek, Kimi и GLM [161]. Страница цен называет ещё модели SpaceXAI [81]. В посте о запуске CLI названы Opus 4.7, GPT-5.5 и SWE-1.6 [34].
- Собственные модели Cognition:
  - семейство SWE: SWE-1.5, SWE-1.6, SWE-1.7, SWE-2, SWE-2 Flash [16][27][47][59][74];
  - SWE-grep — поиск контекста в коде [15];
  - SWE-check — поиск ошибок в diff [28];
  - модель для Tab-дополнения в редакторе [143].
- В Devin Desktop можно запускать сторонних агентов через ACP (Agent Client Protocol — открытый протокол подключения агентов к редакторам): Codex CLI, Claude Agent, OpenCode, Junie, Gemini CLI или свой агент [136]. Это именно сторонние агенты, а не только сторонние модели [136].
- Свои API-ключи сторонних LLM Devin не принимает [189]. Единственное найденное исключение — оплата через подписку ChatGPT [181].

**Один пользователь или команда.**
- Один пользователь: Free, Pro и Max дают все поверхности — облако, CLI и Desktop [179].
- Команда: Teams — до 100 участников, общие кредиты, SSO, общие skills и правила, сессии с несколькими участниками [81][179][76].
- Enterprise: несколько организаций, дерево бюджетов, свои роли, правила и skills от администратора, выделенное размещение [191][183][192][189].
- Продукт позиционируется как участник команды: Devin работает в Slack, Teams, Linear, Jira, GitHub и через API [84][23].

**Платформы.**
- Desktop: macOS, Windows 10 и новее, Linux (tar, deb, rpm; glibc 2.28 и новее). Страница установки до сих пор называет минимальной версией macOS OS X Yosemite — это похоже на устаревшую запись [144].
- Сборки air-gapped: macOS (Apple silicon и Intel), Linux x86_64 и aarch64, Windows x64 и arm64 [195].
- CLI: macOS, Linux, WSL (Windows Subsystem for Linux) и Windows [146].
- Облачные машины:
  - Linux — по умолчанию;
  - VM с macOS: Xcode, iOS Simulator, загрузка в TestFlight [126];
  - VM с Windows, shell по умолчанию — Git Bash [127]. Источники описывают доступ по-разному: «ограниченная доступность» [127] и «бета только для Enterprise» в посте от 2026-05-21 [36];
  - Android-эмулятор [128].
- Web: веб-приложение устанавливается как PWA (веб-приложение, которое ставится как обычная программа) на компьютер и телефон [91]. Нативного мобильного приложения не найдено (не подтверждено).

## Функции

### Облачная сессия: запуск и режимы

- **Ask и Agent.** Ask — для вопросов и планирования, код не меняет. Разговор в Ask можно превратить в prompt, передать агентской сессии и смотреть её статус [85][96]. Раньше Ask Devin назывался Ada; переименован в 2025-11 [90].
- **Выбор режима агента** для каждой сессии. Администратор решает, какие режимы доступны [85]:
  - Lite — самый дешёвый;
  - Normal — по умолчанию;
  - Ultra — для самых сложных задач, заметно дороже;
  - Fusion — сильная основная модель (lead) плюс дешёвая модель-помощник (sidekick);
  - SWE-2 — research preview собственной модели Cognition, три уровня effort;
  - Free — только в Teams, работает на SWE-2, две сессии одновременно.
- **Fast mode** — примерно в 2 раза быстрее, расход в 4 раза больше ACU [91].
- **Запуск в фоне** — с 2026-06-24 [91].
- **Идемпотентное создание через API** (2026-09-11): повтор запроса с тем же ключом возвращает уже созданную сессию [91].
- **Планирование.** С 2024-11-05 Devin сам замечает сложные задачи и сначала предлагает план [89]. С Devin 2.0 (2025-04-03) есть interactive planning: за секунды он показывает нужные файлы, находки и черновик плана, который пользователь правит [6].
- **Confidence ratings** (2025). Devin оценивает свою уверенность цветом — зелёный, жёлтый или красный — в нескольких точках сессии [8]:
  - ниже зелёного он задаёт уточняющие вопросы и ждёт одобрения плана;
  - зелёные сессии примерно вдвое чаще заканчивались принятым PR, чем красные;
  - issues из Linear и Jira можно оценить пачкой, не запуская сессий.

### Облачная сессия: что видит пользователь

- **Вкладки сессии** [92][91]:
  - Activity (с 2026-10-26) — один поток всего, что сделал Devin, с поиском и фильтрами; заменил вкладки Progress и Shell [91];
  - Progress (с 2026-10-28) — живой список задач, работает как фильтр над Activity [91];
  - Terminal (с 2026-10-05), Files, Context, IDE и Browser [92][91];
  - пост о плане Teams от 2026-11-12 показывает ещё вкладки Computer, Changes и Side chat [76].
  - Описания расходятся: страница инструментов сессии называет Progress единым логом команд shell, правок файлов и действий в браузере [92]; release notes описывают Progress как список задач поверх Activity [91].
- **История shell** прокручивается по времени. Команды, которые Devin выполнил позже выбранного момента, показаны серым. Терминал можно сделать доступным для записи [92].
- **IDE.** Пользователь может поставить Devin на паузу и сам работать в IDE на базе VS Code [92].
- **Side chats (`/btw`).** Вопросы только на чтение, привязанные к моменту сессии [92][91]:
  - можно открыть несколько сразу;
  - каждый либо ждёт в очереди за агентом, либо прерывает его;
  - основную работу они не меняют.
- **Браузер** [92][94]:
  - CAPTCHA, MFA и OAuth проходит сам пользователь;
  - cookies сохраняются в пределах сессии;
  - сохранение профиля браузера упаковывает профиль Chrome в zip и предлагает обновить окружение — следующие сессии стартуют уже с входом на нужные сайты;
  - Playwright подключается через CDP (Chrome DevTools Protocol) на порту 29229.
- **Computer Use** — управление всем рабочим столом: Linux, Windows, macOS с iOS Simulator и Outposts с дисплеем [94]. С Devin 2.2 (2026-02-24) так тестируются desktop-приложения [21].
- **Android-эмулятор:** Devin собирает PR, делает smoke test и присылает видео [128].
- **Доказательства тестирования (test mode)** [93][91]:
  - после PR кнопка «Test the app» запускает настройку;
  - Devin пишет test plan для одного, самого важного e2e-сценария;
  - когда CI зелёный, записывает выполнение на видео;
  - на видео есть пометки; возле них воспроизведение замедляется;
  - просмотрщик показывает pass или fail.
  - Пока test mode тарифицируется по одной пятой обычной цены; Cognition называет это поддержкой экспериментов, то есть это временная цена [38]. Как он устроен — в разделе «Как это устроено внутри → Проверка качества».
- **Design Mode** (2026-11-11): выбрать элемент в preview, поменять его свойства, нарисовать пометки и отправить размеченную картинку Devin [91].
- **Reminders** (2026-11-11): Devin ставит себе напоминание и просыпается позже, в том числе в сессиях из automations [91]. С 2026-11-12 в ленте сессии видна строка «Reminder set» [91].
- **Voice mode:** удерживать пробел и говорить [100]. Live Voice Mode — с 2026-09 [91].
- **Шаблоны prompt организации** вызываются как slash-команды [101]. Свои slash-команды — с 2025-12 [90].
- **Несколько участников в одной сессии** (Teams), с именами участников [76].

  - в стеке от 2 до 100 PR; они вливаются снизу вверх;
  - Devin остаётся привязан к каждому слою, сам разрешает конфликты и следит за CI всего стека.

- **PR от имени пользователя** — с 2025-06-11 [90]. При связке аккаунтов GitHub PR выглядят как написанные пользователем [168].

### Жизненный цикл и надёжность сессии

- Сессия засыпает после 5 минут простоя. Windows- и GPU-машины — после 30 минут. В Enterprise время настраивается от 5 до 120 минут [182].
- Спящая сессия ничего не стоит. Ожидание пользователя, ожидание тестов и клонирование почти не тарифицируются [182].
- Сессию можно возобновить в течение 14 дней. До 2026-10-09 было 30 дней [182][91].
- Сбой машины (2026-09-09): карточка предлагает «Try restart» или «Continue in a new session» и предупреждает, что файлы машины и запущенные процессы не переносятся [91].
- Перезагрузка VM — с 2026-09-16 [91].
- Сообщения не теряются при обрыве связи (2026-09-30) [91]. Сообщения в очереди переживают сон и возобновление (2026-09-09) [91].
- Статус Waiting показывает, что Devin спит намеренно (2026-08-26) [91].

### Работа со многими сессиями

- Закрепление, папки, дерево дочерних сессий, подписчики [91].
- Группы статусов в боковой панели (2026-09-25): Working, Ready, Blocked, Inactive. PR, которые ждут ревью, показаны отдельно от сессий, которым нужен ответ пользователя [91].
- Значок вкладки браузера: зелёная точка — Devin работает, оранжевая — ждёт пользователя [91].
- Оранжевая отметка в боковой панели у сессий, остановленных из-за квоты (2026-06-03) [91].
- Inbox уведомлений (2026-10-07). Для каждого события можно выбрать, отправлять ли push на телефон [91].
- Session Insights: автоматическая классификация каждой сессии и полный разбор больших [113]. Подробнее — в разделе «Как это устроено внутри → Наблюдаемость».

### Оркестрация: managed Devins (бывший MultiDevin)

- **MultiDevin (2024-09).** Функция только для Enterprise. Один Devin-менеджер запускал до 10 Devin-исполнителей, затем сливал изменения успешных исполнителей в одну ветку или PR [3][89]. Сейчас слово MultiDevin в документации есть только в release notes 2024 года [83][89].
- **Managed Devins (2026-03-19, для всех пользователей)** [25][91]:
  - сессия-координатор делит работу и запускает дочерние сессии; у каждой своя VM и своя ссылка [103][25];
  - координатор задаёт каждой дочерней сессии prompt, skills, теги и лимит ACU и может писать ей позже [103];
  - координатор сам просыпается, даже из сна, когда дочерняя сессия закончила или ей нужен ответ [103];
  - он следит за расходом ACU, может усыпить или остановить дочернюю сессию и запланировать сообщение самому себе [103];
  - дочерние сессии возвращают структурированный результат по схеме [91];
  - с 2026-08-21 боковая панель показывает дочерние сессии вложенным деревом; это изменение вида, а не новая возможность запуска; с 2026-09-25 дочерняя сессия получает короткое резюме родителя [91];
  - по умолчанию дочерние сессии запускаются без подтверждения; это меняет переключатель «Auto-approve child sessions» в Preferences [103];
  - координатор читает транскрипты дочерних сессий, чтобы в следующий раз лучше делить работу [25];
  - всё это доступно и через Devin MCP server; один вызов ждёт, пока завершатся все параллельные сессии [103][105].
- Как managed Devins объединяют работу дочерних сессий: по документации и посту о запуске координатор «разрешает конфликты и собирает результаты»; в примерах — отдельный PR на каждую дочернюю сессию или общий отчёт [103][25]. Точный механизм слияния не описан (не подтверждено). MultiDevin сливал всё в одну ветку [89].
- **Смежные возможности координатора.** Каждая привязана к своему праву роли: Use Devin Sessions, Manage Playbooks, Manage Knowledge, Manage Schedules. Все эти права по умолчанию входят в роли `org_member` и `org_admin`; ограничить их можно своей ролью [103]:
  - разбор прошлых сессий; пример из документации — почему потрачено 42 ACU вместо ожидаемых 12;
  - создание и улучшение skills по итогам сессии;
  - управление knowledge и расписаниями.
- **Урок Cognition:** схемы с несколькими агентами работают, когда запись в код остаётся однопоточной [32].

### Оркестрация: Dynamic Workflows

- Devin пишет и запускает детерминированный Python-скрипт, который управляет агентами [104].
- Функции скрипта [104]:
  - `register_workflow(meta)`;
  - `agent(prompt, phase=, schema=)` — запускает агента и возвращает dict;
  - `pipeline(items, stage1, stage2…)` — этапы без барьера: элемент переходит на следующий этап, не дожидаясь остальных;
  - `parallel([...])` — только там, где этапу нужны все предыдущие результаты;
  - `log()`.
- Каждый агент по умолчанию — отдельная сессия на своей VM. Агенты передают работу через git-ветки [104].
- Есть вариант общей VM в рабочем дереве координатора. Тогда одновременных агентов меньше, а агенты, которые пишут параллельно, должны получать непересекающиеся файлы [104].
- Агента можно привязать к режиму, например Lite [104].
- Возобновление [104]:
  - run записывается под run ID и возобновляется;
  - ключ каждого вызова агента — хеш prompt, схемы и настроек; завершённые агенты воспроизводят записанный результат, а не запускаются снова;
  - для этого скрипт не должен зависеть от времени, случайности и окружения.
- Ограничения и управление [104]:
  - до 7 дней на один run;
  - по умолчанию запуск одобряется автоматически;
  - панель показывает этапы, агентов и живой статус;
  - остановка скрипта усыпляет его дочерние сессии;
  - в Enterprise функцию нужно включить;
  - рабочий workflow можно сохранить как skill.
- Рекомендация документации: использовать для пяти и более независимых частей или для поэтапных pipeline. Расход ACU может быть намного больше, поэтому сначала пробовать на части работы [104].
- Дата запуска не подтверждена (не подтверждено).

### Оркестрация: Agentic MapReduce и Security Swarm

- **Agentic MapReduce** (2026-07-01) — пять шагов [45]:
  1. Plan — агент пишет селекторы: запросы Tree-sitter или обход графа вызовов.
  2. Shard — код делится на детерминированные пачки.
  3. Map — одна дочерняя сессия на пачку.
  4. Reduce — находки дедуплицируются, ранжируются и связываются между пачками.
  5. Verify — отдельная sandbox-сессия подтверждает каждую серьёзную находку.
- Каждый файл покрыт по построению. Повторный запуск смотрит только изменённые файлы [45].
- На этом работает security scanning Devin [45]. С 2026-11-02 скан может охватывать до 1000 репозиториев [91].
- **Security Swarm** (2026-07-01) [46]:
  - параллельные агенты сканируют части кодовой базы;
  - находки собираются в пути атаки (attack paths) и воспроизводятся в изолированных окружениях;
  - повторные сканы смотрят только изменённый код.
- **Devin Security** (2026-10-26): по словам Cognition, тысячи параллельных VM-сессий; каждая воспроизводит уязвимость, чинит её, тестирует и открывает PR [69].

### Automations, расписания, oncall

- **Automations** [116]:
  - триггеры:
    - Slack — сообщение, упоминание группы пользователей или реакция;
    - Teams, GitHub, GitLab, Linear, Jira, Pylon и PagerDuty;
    - расписание — правила повторения iCalendar, разовые запуски, свой часовой пояс у каждого расписания;
    - webhook — секрет передаётся в заголовке, тело больше 200 KB обрезается;
    - несколько триггеров объединяются через OR;
  - preflight check — фильтр до начала платной работы: LLM-фильтр или скрипт на Python, Node или Bash, который хранит состояние между запусками; по умолчанию 10 элементов за запуск, максимум 50; автоматического повтора нет;
  - действия: начать сессию, написать в существующую сессию, triage (постоянная сессия-наблюдатель «Triage Devin»), отправить email;
  - лимиты: потолок ACU на сессию; 50 запусков в час по умолчанию (150 для Slack triage); лимит одновременных запусков и очередь; запуски сверх очереди отбрасываются.
- Персональные automations — с 2026-06-03. Automations API и Terraform — с 2026-08-07 [91].
- **Scheduled sessions** [117][26]:
  - задаются обычным текстом;
  - переносят состояние между запусками в собственных заметках Devin;
  - сочетаются с managed Devins;
  - новые расписания теперь создаются как automations с триггером-расписанием [117][83].
  - Даты расходятся: release notes дают 2026-02-03 [91], пост в блоге — 2026-03-20 [26].
- **Devin Oncall** (GA 2026-10-19) [118][91]:
  - разовая настройка: Devin изучает системы клиента и пишет для них skills; обновляет их еженедельно или ежемесячно [118];
  - Responders берут до 10 триггеров каждый и объединяют повторяющиеся события в одну issue;
  - во время инцидента Devin заходит в канал и ведёт отчёт, который обновляется сам;
  - регулярные отчёты содержат action items, из которых запускаются сессии.
- **Auto-triage** [119][35]:
  - постоянная родительская сессия следит за каналом Slack и запускает дочерние;
  - хранит общий scratchpad — заметки о том, что уже разобрано;
  - документация советует network policy, потому что ввод из Slack недоверенный.

### Devin Review и качество кода

- **Запуск:** пост в блоге — 2026-01-21 [19], release notes — 2026-01-22 [91].
- **Что делает** [106][19]:
  - группирует связанные изменения и объясняет их рядом с diff [106];
  - выстраивает файлы в порядке чтения и распознаёт перемещённый код [19];
  - открывается со страницы ревью или комментарием `/devin review` в PR [106].
- **Хосты:** GitHub, GitLab, Azure DevOps, Bitbucket Cloud и Data Center [106].
- **Правила авто-ревью** [106]:
  - старт при создании PR или при переводе в ready;
  - один раз или на каждый push;
  - фильтр по репозиторию и автору;
  - пропуск, пока у PR есть merge-конфликты;
  - commit status check с именем «Devin Review». Условие прохождения настраивается: ревью завершено (по умолчанию), все треды закрыты или находок нет.
- **Находки** [106]: Bugs (severe или non-severe), Flags (investigate или note), Security (с классом CWE и severity).
- **Повторное ревью** новых push переносит прошлые находки и проверяет, исправлены ли они. В стеке каждый PR сравнивается со слоем ниже [106].
- **Стоимость в интерфейсе** [106]:
  - бейдж размера (от XS до XL) показывает ожидаемую цену ревью;
  - у каждого PR свой лимит расходов на автоматические ревью;
  - это мягкая блокировка: авто-ревью останавливается, ручные ревью работают, повторное включение даёт новый лимит.
- **Effort:** Normal или Ultra [106].
- **Merge прямо со страницы ревью.** У стеков PR своя панель [106].
- **Custom reviewers** (beta): именованные ревьюеры со своими инструкциями — простым текстом или из skill репозитория, организации или enterprise. У каждого свои правила запуска, лимит расходов и история последних 20 версий инструкций. Находки идут в общий check `Devin Review` или, по выбору, в отдельный CI check ревьюера. Ревьюер из skill может синхронизироваться с ним [106].
- **Autoapprover** (beta): одобряет PR по правилам из `APPROVAL_POLICY.md` и читает этот файл из целевой ветки, поэтому PR не может переписать собственные правила [106]. Устройство — в разделе «Как это устроено внутри → Проверка качества». Дата запуска не подтверждена (не подтверждено).
- **Файлы инструкций, которые читает Review:** REVIEW.md, AGENTS.md, CLAUDE.md, CONTRIBUTING.md, правила Cursor и Windsurf [106].
- **Auto-Fix** [106][91][20]:
  - сессия, которая открыла PR, сортирует каждую находку: исправить, проверить или передать человеку [106];
  - Devin исправляет комментарии и Devin Review, и любых ботов — линтеров, CI, сканеров [20][106];
  - Devin публикует одно ревью-резюме «Fixed by Devin»; находки, которые он счёл неверными, не публикуются [106];
  - на своих PR Devin исправляет находки ещё до их публикации (2026-09-30) [91];
  - merge-конфликты исправляются автоматически в течение 12 часов активности сессии или 36 часов, если PR одобрен (2026-09-21) [91].
- **Стоимость по данным Cognition** [75][179]:
  - с августа стоимость ревью упала на 82% [75];
  - типичное ревью стоит $0.25–0.75; около 80% PR обходятся меньше чем в $1 [75];
  - около $2.25 на одну исправленную ошибку [75];
  - новые push получают инкрементальное ревью [75];
  - ревью публичных PR бесплатно, через devinreview.com [179][75].
- **Review API** — с 2026-05-08. Обновлённая страница ревью и права MCP по каждому инструменту — 2026-11 [91]. CLI `npx devin-review` убран 2026-09-21 [91].
- **Code scans (`/scan`)** [107]: производительность, запросы к базе данных, покрытие тестами, мёртвый код, качество кода, чистка, телеметрия, доступность (accessibility) и compliance. Есть вкладка находок и инкрементальный скан новых коммитов.
- **Страница Security** — находки по всей организации [108].
- **Экспорт SARIF** (стандартный формат результатов статического анализа) — с 2026-10-14 [91].
- **Подключения:** SonarQube, Linear и Vanta — с 2026-10-30; Veracode и Black Duck — закрытая бета (2026-11-12) [91].

### Devin Desktop (бывший Windsurf)

- **Название и настройка** [132][39]:
  - переименован 2026-06-02 обновлением по воздуху (over-the-air);
  - команда `devin-desktop` заменила `surf`;
  - папки `.devin/` важнее папок `.windsurf/`;

- **Позиционирование:** «Agent Development Environment» для локальных и облачных агентов [133]; место, где разработчик проводит больше 90% рабочего дня [132]. FAQ говорит, что будущее профессии — управление командами агентов, локальных и облачных [132].
- **Agent Command Center** — одно окно для локальных и облачных агентов [133][134]:
  - Kanban-доска по статусам — с Windsurf 2.0 (2026-04-15) [141][30];

  - в канале next можно перетащить сессии на карточку Kanban и так создать Space [142].
- **Agent window** (v3.11.212, 2026-10-23) [141]:
  - тот же UI, что в веб-приложении;
  - до 8 сессий рядом;
  - группировка по workspace и дочерние сессии;
  - вкладка Changes с видом «что изменилось с последнего просмотра»;
  - вкладка Preview с выбором элемента на странице;
  - Enter направляет работающего агента; Cmd/Ctrl+Enter ставит сообщение в очередь;
  - дистрибутивы WSL могут удалённо принимать агентов.
- **Поведение сессии** [134]:
  - пока агент работает, сессия только для чтения;
  - сессию можно дублировать, чтобы попробовать другой вариант разговора;
  - сообщения в очереди можно править;
  - одно системное уведомление на сессию, когда она закончила или ждёт ответа; по умолчанию выключено; работает одинаково, где бы ни работал агент.
- **Три вида агентов:**
  - **Devin Local** [137];
  - **облачный Devin** [135]: входит во все self-serve планы; одним кликом получает локальный план; очередь отправки хранится на сервере и переживает перезагрузку страницы;
  - **сторонние агенты через ACP** [136][39]:
    - Codex CLI, Claude Agent, OpenCode, Junie, Gemini CLI или свой агент;
    - доступны на Free, Pro, Max и Teams; в Enterprise выключены по умолчанию;
    - оплата и условия — у стороннего поставщика;
    - Desktop сам не скачивает их бинарники;
    - администратор может раздать командный реестр агентов;
    - у них те же Kanban, Spaces и общий контекст.
- **Devin Local** [137]:
  - общий harness с CLI;
  - prompt caching;
  - subagents (preview), включая свои в `agents/<name>.md`;
  - OS sandbox: изоляция файловой системы, списки allow и deny для сети;
  - встроенный subagent Quick Review;
  - `/share` загружает транскрипт со скрытыми секретами.
  - Devin Local заменяет memories и workflows из Windsurf на rules и skills [132].
- **Режимы прав** [138]:

| Режим | Поведение |
|---|---|
| Code | Автоматически одобряет правки внутри workspace |
| Smart | Быстрая модель сама одобряет действия, которые считает явно безопасными. Установка пакетов, git-команды, меняющие состояние, `rm`, `sudo`, разрушительные вызовы облачных CLI и чувствительные файлы всегда требуют вопроса. Режим пока доступен не всем |
| Ask | Только чтение |
| Plan | Исследование только на чтение; пишет Markdown-план с кнопкой «Implement» |
| Bypass | Правила deny и ask от администратора всё равно действуют |
| Autonomous | Используется в sandbox |

### Devin CLI

- **Установка** [146]: curl-скрипт (macOS, Linux, WSL), Homebrew cask, установщик Windows или PowerShell.
- **Статус:** запуск 2026-04-27 [34]; stable v3000.12.57 — 2026-11-12 [155]. Пока не поддерживает Knowledge, Playbooks и Secrets [146].
- **Подкоманды:** cloud, connect, acp, sandbox, ssh, forward, worker, plugins, migrate [148].
- **Режимы:** normal, accept-edits, smart, plan, bypass (`/yolo`) и autonomous в sandbox [147].
- **Правила прав** [149]:
  - allow, ask или deny;
  - на одном уровне побеждает deny;
  - настройки организации важнее всего;
  - команду можно отредактировать перед одобрением.
- **Subagents** [151]:
  - работают в foreground или background;
  - background subagents сами отклоняют инструменты, которые ещё не одобрены;
  - встроенные профили: explorer только на чтение и general worker;
  - свой профиль может закрепить модель.
- **Облако из терминала** [153][152][62]:
  - `devin --cloud`, `-p` и `--resume`;
  - `/handoff` переносит репозиторий, ветку, разговор и незакоммиченные изменения в облачную сессию;
  - обратный handoff забирает ветку PR из облачной сессии на локальную машину;
  - `devin ssh` открывает shell на облачной VM;
  - закрытие терминала не останавливает облачную сессию.
- **Handoff из других агентов** [152][109][174]:
  - open source плагин Devin Handoff для Claude Code, Codex, Cursor или обычного shell;
  - рецепт через API;
  - документация предупреждает: payload с `git diff` может содержать секреты.
  - Репозиторий `club-cog/devin-handoff`, на который ссылается документация, открыть не удалось (не подтверждено).
- **ACP-режим:** Devin работает внутри JetBrains AI Chat, Zed и Xcode 26.6; флаг `--sandbox` добавляет изоляцию на уровне ОС [154][150].
- **`/goal`** (2026-10-14): агент продолжает работу через ходы и сам продолжает в конце каждого хода, пока цель не достигнута или не заблокирована. После 50 ходов он ставит себя на паузу [155].
- **`/usage`** (2026-08-21): дневная и недельная полосы расхода и время сброса [155].
- **Статус для терминала** через escape-последовательность OSC 7501: idle, working, blocked, done или failed (2026-10-14) [155].
- **Compaction** (сжатие истории разговора) [155]:
  - порог настраивается;
  - есть hooks `PreCompact` и `PostCompact`;
  - skills, выпавшие при сжатии, перечисляются снова (2026-10-14).

### Local Hands и Outposts

- **Local Hands** — облачная сессия получает второй набор инструментов на машине пользователя [110]:
  - разрешено: shell, чтение, поиск и правка файлов, копирование файлов между машинами; управления экраном нет;
  - каждый вызов спрашивает: разрешить один раз, на эту сессию или отклонить;
  - всегда спрашивают, даже в bypass: файлы учётных данных и приватные ключи, повышение привилегий, разрушительные команды, интерпретаторы shell, хранилища секретов, запись в профили shell и в git config;
  - код подключения одноразовый, приходит только владельцу сессии и истекает через 10 минут; доступ можно отозвать;
  - подключение машины делает сессию приватной;
  - недоступно в сессиях по расписанию, из automations и у service users;
  - включено по умолчанию вне enterprise.
  - Дата запуска не подтверждена (не подтверждено).
- **Outposts** [164][53][169]:
  - именованные очереди сессий, которые обслуживают машины пользователя: `devin worker start --outpost=<name>` [164];
  - воркерам нужен только исходящий HTTPS; N воркеров обслуживают N сессий [164];
  - задания забираются атомарно [164];
  - партнёрские sandbox: Namespace (macOS), Modal, Daytona, E2B, Cloudflare и другие; есть reference-реализация для Kubernetes [164][53];
  - доступно в Pro, Max и Teams [164];
  - в Slack команда `!outpost <name>` отправляет сессию на нужный outpost [169].
  - Протокол очереди — в разделе «Как это устроено внутри → Outposts».

### Память, skills, плагины, совместимость с Claude Code

- **Memory** (2026-10-09) [120][91]:
  - git-репозиторий Markdown-заметок; MEMORY.md загружается всегда, остальные заметки читаются по необходимости;
  - каждая запись — одна строка с пометкой сессии-источника и даты;
  - каждое сохранение — коммит, который сливается с изменениями других сессий; устаревшая запись отклоняется и повторяется;
  - хранит предпочтения, исправления, решения и типичные ошибки; не хранит состояние задач, резюме, секреты и то, что дёшево найти заново;
  - память личная в пределах организации; сессии из automations её не читают и не пишут;
  - Dreaming — фоновая сессия примерно раз в день объединяет, чистит и перестраивает заметки;
  - формат следует открытой спецификации Agent Memory Repo [120][198].
  - С 2026-11-06 память можно выключить для сессии и её дочерних сессий (`memory_enabled: false`) [91].
- **Skills** [121][91]:
  - файлы SKILL.md в формате agentskills.io в папке `.agents/skills/`, или skill пишется на странице Customize — личный, организации или enterprise;
  - встроенные skills: implement, plan, triage, review;
  - skills запускаются автоматически или вызовом `@skills:name`;
  - frontmatter может ограничить инструменты и права skill;
  - Devin сам предлагает новые skills с кнопкой «Create PR» [121];
  - Playbooks и Knowledge переходят в skills; новые аккаунты с 2026-10-24 работают только со skills [121][122][130][91].
- **Plugins** [123]:
  - пакет из skills, rules, hooks, MCP servers и subagents;
  - работает в облаке, CLI и Desktop как команды `/<plugin>:<skill>`;
  - есть marketplace и управление для администраторов.
- **Совместимость с Claude Code — явная:**
  - манифест плагина: Devin читает `.devin-plugin/plugin.json`, затем `.claude-plugin/plugin.json`; плагины Claude загружаются со своим `.mcp.json` и переменной `${CLAUDE_PLUGIN_ROOT}` [156];
  - hooks Claude Code по умолчанию читаются из `.claude/settings*.json` и `~/.claude/settings.json` [157];
  - правила и skills: CLAUDE.md, `~/.claude/CLAUDE.md`, `.claude/skills/**/SKILL.md` и `.mcp.json`; правила Cursor, Copilot, Codex, Kiro, OpenCode и Zed тоже импортируются [159][160];
  - миграция одним prompt переводит настройки другого агента в AGENTS.md и `.agents/skills/`; оригиналы не удаляются, секреты не копируются, hooks и MCP servers не включаются [131].
- **MCP:**
  - marketplace с транспортами stdio, SSE и HTTP [111]; появился 2025-07-28 [90];
  - среди серверов — Sentry, Datadog, Postgres и Notion [167];
  - личные MCP servers — с 2026-04-10 [91].

### Devin как участник команды

- Devin работает в инструментах команды: Slack, Teams, Linear, Jira, GitHub и API [84][23]. По документации, он полезнее всего как часть команды и её процессов [84].
- На Devin действуют те же branch protections и правила SDLC (процесса разработки), что и на людей. Его PR проверяют люди [88].
- Самооценка 2025 года: Devin на уровне senior в понимании кодовой базы, но на уровне junior в исполнении; при этом его ёмкость не ограничена [18].
- Слабые места по той же самооценке: неясные требования, требования, которые меняются по ходу задачи, результаты, которые нельзя проверить, и soft skills [18].
- В посте о покупке The Interaction Company: работа с Devin должна быть проактивной, он должен знать пользователя, с ним должно быть приятно общаться [55].

### Архитектура агентов: позиция и её пересмотр

**2025, «Don't Build Multi-Agents» (Walden Yan) [9].**
- Принцип 1: делиться полным trace агента, а не отдельными сообщениями.
- Принцип 2: каждое действие несёт неявные решения. Параллельные агенты принимают противоречащие решения.
- Рекомендация: один линейный агент плюс модель сжатия контекста. Для сжатия Cognition дообучила меньшую модель.
- В обсуждении на HN большинство согласилось: один агент с хорошо управляемым контекстом надёжнее [227].

**2026, «Multi-Agents: What's Actually Working» [32].**
- Работают схемы, где несколько агентов добавляют «интеллект» — ревью, советы, — а запись в код остаётся однопоточной.
- Generator–verifier (генератор и проверяющий):
  - Devin Review находит в среднем 2 ошибки на PR, около 58% из них серьёзные;
  - ревьюер работает лучше с чистым контекстом;
  - отдельный шаг фильтрации решает, на какие находки реагирует кодер.
- «Smart Friend»: маленькая основная модель вызывает большую. Рекомендованная передача — fork полного контекста; Cognition считает это разумным компромиссом.
- «Map-reduce-and-manage»: менеджер делит работу, дочерние агенты исполняют.
- Read-only subagents для поиска — нормально.
- Неструктурированные swarms в основном отвлекают.
- Открытые проблемы — в обмене информацией:
  - менеджеры по умолчанию слишком детально предписывают;
  - дочерние агенты сами не сообщают о находках;
  - агенты считают, что делят состояние с дочерними, хотя это не так.
- Почему позиция поменялась: модели стали лучше работать как агенты, а использование выросло примерно в 8 раз за полгода.

**Локальный harness.** Документация CLI теперь говорит, что subagents и улучшают качество, и снижают стоимость [151]. Subagents работают в foreground или background; свои профили — Markdown-файлы в `agents/` [137][151].

### Проверка: «вернись с доказательством»

- **Повод.** Впервые больше сессий запускается асинхронно — событиями, automations, расписаниями и другими Devin. Без проверки такие изменения быстро становятся неуправляемыми [38].
- **Правила тестирования (Ido Pesok)** [38]:
  - test plan строится по исходному коду, а не по догадкам;
  - ожидаемое поведение записывается до каждого действия;
  - ненадёжные шаги вроде login переносятся в детерминированные скрипты и сохраняются как skills;
  - UI-тестирование отдаётся моделям, которые хорошо читают скриншоты;
  - результат — видео с главами и отчёт, где каждое утверждение помечено passed, failed или untested.
- **Ревью — самый медленный шаг.** Cognition считает, что теперь работу ограничивает code review, а не генерация кода. Она называет проблему «Lazy LGTM»: большие diff одобряют, не разобравшись в них [19].
- **Codemaps.** Инструменты должны заставлять разработчика думать, а не отключать его внимание. Ответственность за код остаётся главной ролью инженера [17].
- **Замкнутый цикл.** Если ревьюер — человек или бот — оставил комментарий, Devin его обрабатывает. Cognition считает, что ценность даёт связанная система, а не отдельный инструмент [20].

### Модели, стоимость и измерения

- **«Agent lab».** Цель — не обучить модель саму по себе, а построить готового агента [16].
  - Модели оцениваются по 100+ категориям задач разработки [37].
  - Cognition называет себя независимой agent lab [56] и нейтральной стороной среди поставщиков моделей («Switzerland of AI») [51].
  - Она ведёт публичный leaderboard моделей — Arena Mode [51].
- **Скорость.** Цель — ответ агента за 5 секунд. Cognition называет это «flow window»: время, за которое разработчик не теряет концентрацию [15]. Разработчик не должен выбирать между быстрым и умным AI [16].
- **Цена за задачу, а не за токен** [60]:
  - в связке lead и sidekick (Fusion) lead-модель вдвое дороже за токен оказалась дешевле в итоге [49];
  - в 81% запусков Fable в роли lead сам не правил код [49];
  - вывод Cognition: Opus ведёт себя как менеджер, который всё переделывает за стажёра, а Fable — как менеджер, который доверяет толковому инженеру [49];
  - если заставлять модель делегировать больше, результат хуже [49];
  - делегирование не работает на коротких задачах и при последовательной отладке [49];
  - модели переключаются в момент compaction, поэтому переключение почти не добавляет стоимости кэша [44].
- **Измерять результат, а не активность.** Дашборды «потраченных токенов и строк кода» Cognition отвергает [41]. Вместо этого агент-оценщик оценивает, сколько часов понадобилось бы человеку на каждую полезную сессию [42]:
  - он откалиброван занижать;
  - корреляция с оценками людей в логарифмической шкале — 0.74;
  - около половины оценок в пределах 2x от человеческой;
  - считается только работа, которую пользователь не расписал сам.
- **Гарантия.** Если Devin дал меньше инженерной ценности, чем заплатил клиент, Cognition оплачивает использование, до $10M, пока ценность не сравняется [41].
- **Отношение к бенчмаркам.** Корректность — уже минимум; вопрос в том, принял бы maintainer этот PR [43].
  - Задачи FrontierCode пишут maintainers 36 репозиториев, больше 40 часов на задачу; задачи закрыты [43].
  - На FrontierCode 2.0 лучшая модель на момент запуска, Opus 5.5, набрала около 47% [70].

### Правила для людей, которые ставят задачи

- Если задачу можно сделать за 3 часа, Devin, скорее всего, справится [84][86].
- Держать сессии размеров XS, S или M. Сессии L и XL помечаются как нездоровые [86][113].
- 2025: держать сессии до 10 ACU, потому что в длинных сессиях качество падает [90].
- Успех растёт с конкретностью. Когда инструкции начинают повторяться, нужен playbook — это как свой system prompt для повторяющейся задачи [23].
- Быть категоричным и самому принимать решения по дизайну: эстетику Devin сам не придумает [87].
- Coding Agents 101 [11]:
  - говорить, как именно делать;
  - писать prompt с защитой от ошибок (defensive prompting);
  - дать доступ к CI, тестам, типам и линтерам;
  - ставить checkpoints;
  - раньше прекращать неудачные попытки;
  - начинать заново, если нет прогресса;
  - заводить отдельные аккаунты для агента, staging-окружения и ключи только на чтение.
- Безопасность: данные из событий нельзя считать доверенными инструкциями [35].

### Инфраструктура как принцип продукта

- Отдельная microVM со своим ядром на каждую сессию: контейнеры делят ядро [33].
- Снимок всей машины на уровне hypervisor: сессия засыпает, пока ждёт CI или ревьюера [33].
- Свой hypervisor otterlink и открытый формат blockdiff, который хранит только изменённые блоки диска [10].
- Оркестрация управляет тысячами одновременных VM [33].
- Ожидание пользователя или тестов не тарифицируется. Сессия засыпает после 5 минут простоя [182].
- Ноябрьский гайд по безопасности советует переносить разработку в облачных агентов и удалённые окружения и не держать её на ноутбуке [73].

### Ключевые понятия продукта

- **Session (сессия)** — один запуск агента. У сессии есть машина (blueprint и snapshot); простаивая, она засыпает; бывает приватной или общей [182][110].
- **ACU (Agent Compute Unit)** — единица учёта в Enterprise. Self-serve планы теперь считают квоту и доллары [182][29].
- **Режимы агента** — Normal, Fast, Lite, Ultra, Fusion и Free (на SWE-2) [181][179]. Fast — примерно в 2 раза быстрее за 4x ACU [91]. Adaptive — роутер, который выбирает модель под задачу [83][162].
- **Knowledge, Playbooks, Skills.** Knowledge и Playbooks переходят в Skills. Skills следуют открытому стандарту Agent Skills; файлы лежат в `.agents/skills/<name>/SKILL.md` [121].
- **Memory и Dreaming** — личный git-репозиторий заметок и ежедневная фоновая сессия, которая их чистит [120].
- **Managed Devins** — координатор и дочерние сессии, каждая на своей VM; координатор просыпается по событиям дочерних сессий [103][25].
- **Dynamic Workflows** — Python-скрипт, который управляет многими агентами и умеет возобновляться [104].
- **Automations** — цепочка «триггер, условия, preflight check (LLM-фильтр или скрипт), действие» [116]. Сессии по расписанию ведут свои заметки, и каждый запуск продолжает предыдущий [26].
- **Oncall** — три части: Responders, Incidents и Reports [118].
- **Session Insights** — разбор сессии после завершения: класс размера, цветная временная шкала проблем, улучшенный вариант prompt, список knowledge-записей, которые помогли или сбили с толку [113].
- **Devin Coach** — проверка prompt до отправки. Предлагает сначала план, более лёгкий режим, новую сессию или деление на дочерние сессии. Для администратора есть вид «Blockers» — сгруппированные проблемы, на которые агенты наткнулись во время работы [185].
- **Confidence ratings** (2025) — оценка уверенности цветом [8].
- **Local Hands** — инструменты облачной сессии на машине пользователя, с одобрением каждого вызова [110].
- **Outposts** — именованная очередь сессий, которую обслуживают воркеры клиента; воркерам нужны только исходящие соединения [164].
- **Handoff** — `/handoff` упаковывает разговор и текущую git-ветку в облачную сессию [109].
- **Agent Command Center, Spaces, ACP** — одно окно для всех агентов, группы с общим контекстом и протокол подключения сторонних агентов [134][40][136].
- **Stacked PRs** — намеренные упорядоченные серии PR, которые вливаются снизу вверх [102].
- **Autoapprover и custom reviewers** (оба beta) — автоматическое одобрение PR по политике и именованные ревьюеры с инструкциями из текста или из skill [106].
- **Security Profiles** — allowlists для сети, MCP servers и доступа к git [115]. **Secure mode** убирает возможность публиковать в интернет [91].
- **Blueprint** — декларативное описание окружения; из него собирается snapshot [125].
- **Brain и Devbox** — облачный сервис планирования без состояния и VM для исполнения кода [189].

### Чем подход отличается

- Облако по умолчанию: своя VM на сессию, бесплатный сон, пробуждение по событиям — CI, комментарии, дочерние сессии [33][182][103].
- Работа приходит из событий и интеграций, а не только из чата [38][116].
- Вертикальная интеграция: свой hypervisor, свои модели, своя IDE, свой ревьюер [10][59][132][106].
- Проверка — часть продукта: тест-видео, Devin Review, Autoapprover [38][106].
- Открытые форматы настройки: Agent Skills, AGENTS.md, Agent Memory Repo, ACP, MCP. Devin читает конфигурацию Claude Code [121][129][198][136][156][157].

## Как это устроено внутри

Devin — закрытый продукт. Внутренний цикл агента — его prompts, схемы инструментов и модель на каждом шаге — не опубликован (не подтверждено). Ниже — то, что Cognition описала сама, и три открытых репозитория [196][197][198].

### Общая архитектура

- **Brain и Devbox** [189]: Brain — сервис без состояния в облаке Cognition; Devbox — VM, где исполняется код. При разных вариантах размещения место меняет только Devbox.
- **Подключение.** При старте Devin открывает защищённый WebSocket к изолированному контейнеру в tenant Cognition [189]. Где работает этот tenant — источники расходятся (не подтверждено): подпись к схеме называет Azure [189], страница безопасности — AWS-окружение Cognition [184].
- **Составная система.** Devin делает много вызовов моделей: чтобы планировать, действовать, оценивать и пользоваться инструментами [4].
  - В работе — модели, дообученные на закрытых данных.
  - Упрощённый «Devin-Base» нужен, чтобы измерять эффект от смены базовой модели [4].
- **Инструменты:** shell, редактор и браузер [1]; позже — полное управление компьютером: скриншоты, мышь, клавиатура [38].
- **Собственные модели внутри цикла:**
  - SWE-grep — subagent поиска контекста: до 8 параллельных tool calls за ход, не больше 4 ходов, только ограниченные инструменты grep, read и glob [15];
  - SWE-check — детектор ошибок в diff, обученный через RL, примерно в 10 раз быстрее frontier-моделей [28];
  - дообученная меньшая модель, которая сжимает длинную историю действий [9].
- **В основном асинхронно.** Сессий, запущенных событиями, automations, расписаниями и другими Devin, теперь больше, чем запущенных людьми [38].
- **Почему VM, а не контейнеры** [33]:
  - контейнеры делят ядро, поэтому взломанная сессия может добраться до других;
  - контейнер не умеет сохранить всё своё состояние. Агент, который ждёт CI или ревью, либо тратит вычисления, либо теряется при переносе на другой узел;
  - Devin сохраняет память, дерево процессов и файловую систему на уровне hypervisor. Пока сессия простаивает, вычисления выключены. Сессия продолжает работу, когда приходит результат CI или комментарий ревью;
  - оркестрация предсказывает спрос и держит наготове пулы запущенных VM;
  - каждая сессия получает права инженера, который её запустил, и оставляет audit trail, который нельзя незаметно изменить.

### Слой VM: otterlink и blockdiff

- **otterlink** — собственный hypervisor Cognition. По сравнению с EC2 он запускает VM примерно в 10 раз быстрее, а снимок диска делает за пару секунд вместо 30+ минут, то есть примерно в 200 раз быстрее [10]. Это две разные метрики одного поста: 10× — запуск VM, 200× — снимок диска.
- **Диски** [10]:
  - диски VM — файлы на файловой системе хоста XFS с reflink. Reflink — copy-on-write копия: она ссылается на те же блоки, пока их не изменят;
  - каждый диск VM — copy-on-write копия базового образа; внутри гостевой системы — ext4;
  - от OverlayFS отказались: в нём нет нормальных инкрементальных снимков, а Docker внутри переходил на медленный драйвер vfs;
  - от ранней схемы с откатом через ZFS внутри гостя тоже отказались: она покрывала только домашнюю папку.
- **Что дают снимки** [10]:
  - во сне хранится около 50 MB состояния сессии вместо окружения на несколько GB, поэтому пробуждение быстрое;
  - откат диска собирается из инкрементальных снимков;
  - fork и приостановка сессии используют тот же механизм.
- **Код blockdiff** [197] — https://github.com/CognitionAI/blockdiff, commit 8d10a60b (2025-01-03):
  - `src/main.rs` — один файл на Rust, 678 строк; сигнатура формата — `BDIFFv1\0` (строка 54);
  - `create_diff` (строка 350) сохраняет только блоки, которые различаются между двумя файлами;
  - `apply_diff` (строка 434) создаёт целевой файл как reflink-копию базового и записывает изменённые блоки;
  - сравнивать содержимое было бы слишком медленно — 30–60 секунд на образ 128 GB, — поэтому формат опирается на учёт copy-on-write в ядре [10].
  - Число строк и номера строк проверены по локальной копии репозитория.

### Окружение: blueprint, сборка, snapshot

- **Blueprint — это YAML** с разделами [125]:
  - `initialize` — инструменты и runtime;
  - `maintenance` — зависимости. Выполняется при сборке и показывается агенту в начале сессии, но сам в сессии не запускается;
  - `knowledge` — никогда не выполняется. По соглашению содержит команды `lint`, `test` и `build`, которыми Devin проверяет свою работу;
  - `runs-on` (необязательный) — один snapshot на платформу;
  - `shell`;
  - `post-build` — только на уровне организации и enterprise. Ненулевой exit code проваливает сборку, и snapshot не создаётся;
  - `clone`.
- **Три уровня, которые складываются:** enterprise, затем организация, затем репозиторий. Нижний уровень не может переопределить верхний [125].
- **Сборки** [125]:
  - запускаются при сохранении и примерно каждые 24 часа (для macOS — раз в неделю);
  - одновременно идёт только одна сборка; новый запуск отменяет сборку в очереди;
  - состояния: Queued, Building, Success, Partial, Failed, Cancelled. Из Partial тоже получается рабочий snapshot;
  - обычная сборка занимает 5–15 минут; любая команда прерывается через 3 часа;
  - дифференциальные сборки пропускают `initialize` для унаследованных workspaces.
- **Pinning** закрепляет сессии за сборкой Success или Partial не старше 7 дней и пропускает периодические обновления [125].
- **Секреты** удаляются перед сохранением snapshot. Но значение, которое записали в файл на шаге `initialize`, остаётся в snapshot [125].

### Сессия: состояния и жизненный цикл

- **Состояния в API** [176]: `new`, `claimed`, `running`, `exit`, `error`, `suspended`, `resuming`.
- **`status_detail` при `running`:** `working`, `waiting_for_user`, `waiting_for_approval` (safe mode), `finished` [176].
- **`status_detail` при `suspended`** [176]:
  - `inactivity` и `user_request`;
  - лимиты и оплата: `usage_limit_exceeded`, `out_of_credits`, `out_of_quota`, `no_quota_allocation`, `payment_declined`, `org_usage_limit_exceeded`, `user_usage_limit_exceeded`, `total_session_limit_exceeded`, `contract_expired`;
  - `error`.
  - Лимиты — это причины приостановки со своими именами, а не ошибки.
- **Сон** [182]: по умолчанию после 5 минут простоя, для части Windows- и GPU-сессий — после 30; в Enterprise — от 5 до 120 минут. Сон бесплатный. Также не тарифицируются ожидание пользователя, ожидание тестов и клонирование.
- **Что будит спящую сессию:**
  - комментарии в PR или ошибки линтера — с 2024-11-22 [89];
  - повторный запуск по комментарию в PR (2026-05-29) [91];
  - трафик на preview URL или по SSH (2026-09-25) [91];
  - открытие вкладок Files или Terminal (2026-10-05) [91];
  - дочерняя сессия закончила или ей нужен ответ — тогда просыпается координатор [103];
  - напоминание, которое Devin поставил себе сам (2026-11-11) [91].
- **Контракт создания сессии** [175]:
  - `resumable` (по умолчанию true) сохраняет состояние VM после остановки;
  - `max_acu_limit`;
  - `structured_output_schema`: JSON Schema Draft 7, не больше 64 KB, без внешних ссылок. С `structured_output_required` агент обязан вызвать `provide_structured_output` с `is_final=true`, прежде чем закончить ход;
  - `security_profile`, `session_secrets`, `memory_enabled`.
- **Идемпотентность:** `idempotency_key` при повторе возвращает исходную сессию, а пока создание ещё идёт — ответ 409 (2026-09-11) [91].

### Планирование и цикл агента

- Внутренний цикл не публичный: prompts, схемы инструментов и выбор модели на каждом шаге не известны (не подтверждено).
- **Как росло планирование:**
  - Planning mode замечает сложные задачи и сначала предлагает план (2024-11-05) [89];
  - Interactive Planning (Devin 2.0) за секунды возвращает нужные файлы, находки и черновик плана, который можно править [6];
  - Confidence ratings (Devin 2.1): зелёный, жёлтый или красный в нескольких точках сессии. Всё, что ниже зелёного, вызывает уточняющие вопросы и ожидание одобрения. Зелёные сессии дают принятые PR вдвое чаще красных. Issues Linear и Jira можно оценивать пачкой без запуска сессий [8].
- **Legacy Cascade (Desktop):** фоновый агент планирования уточнял долгий план, пока выбранная модель действовала. Были список задач, очередь сообщений и именованные checkpoints с откатом [140].
- **CLI `/goal`:** работа продолжается через ходы и автоматически возобновляется в конце каждого хода, пока цель не достигнута или не заблокирована. После 50 ходов — пауза (2026-10-14) [155].
- **Слабые места, которые признаёт Cognition:** неясные требования и смена объёма работы посреди задачи [18].
- **SWE-bench 2024:** на задачу давали не больше 45 минут [2]; результат — 13.86% решённых задач [199].

### Параллельность и координация

- **MultiDevin (2024-09-03):** 1 менеджер и до 10 исполнителей. Менеджер сливает изменения успешных исполнителей в одну ветку или PR [89].
- **Managed Devins** [25][103]. Координатор:
  - определяет объём работы;
  - запускает дочерние сессии на своих VM, каждой даёт prompt, skills, теги и лимит ACU;
  - отправляет им сообщения;
  - просыпается, когда дочерняя сессия закончила или ей нужен ответ, — поэтому ему не нужно опрашивать;
  - следит за расходом ACU каждой дочерней сессии;
  - усыпляет или останавливает зависшие дочерние сессии;
  - планирует сообщения самому себе.
  - Пачки дочерних сессий стартуют без вопроса, если не выключен «Auto-approve child sessions» [103].
- **Управление идёт через MCP server:**
  - встроенный Devin MCP создаёт дочерние сессии, пишет им и правит knowledge и расписания [115];
  - публичный Devin MCP даёт инструменты `devin_session_create`, `devin_session_search`, `devin_session_interact` (status, message, sleep, terminate, archive) и `devin_session_events` [105];
  - инструмент `devin_session_gather` ждёт, пока несколько сессий придут в устойчивое состояние, вместо опроса [105];
  - один это сервер или два разных — не подтверждено (не подтверждено).
- **Опубликованные уроки:**
  - запись в код однопоточная; дополнительные агенты дают «интеллект» (ревью, советы), а не действия [32];
  - менеджеры, обученные на мелких поручениях, слишком детально предписывают [32];
  - агенты считают, что дочерние делят их состояние, — это неверно [32];
  - дочерние агенты не сообщают находки соседям, если их этому не обучить [32];
  - работающая схема — map-reduce-and-manage; неструктурированные swarms в основном отвлекают [32];
  - более ранний принцип: делиться полными trace, потому что каждое действие несёт неявные решения [9].
- **Dynamic Workflows** [104]:
  - API: `register_workflow(meta)`; `agent(prompt, phase=, schema=)` возвращает dict; `pipeline(items, stage1, stage2…)` без барьера между этапами; `parallel([...])` — только где этапу нужны все предыдущие результаты; `log()`;
  - возобновление: скрипт запускается заново с начала. Ключ каждого вызова `agent()` — хеш prompt, схемы и настроек исполнения. Завершённые вызовы воспроизводят записанный результат. Правка prompt перезапускает этого агента и всё, что от него зависит дальше по цепочке;
  - правило детерминизма: скрипт не зависит от времени, случайности, сгенерированных ID, переменных окружения, файлов и сети;
  - бюджет: по умолчанию и максимум — 7 дней на run;
  - политика ошибок пишется в коде: пропустить, подставить значение по умолчанию, повторить или остановиться. При возобновлении упавшие агенты повторяются в новых сессиях;
  - размещение: отдельная VM на агента (по умолчанию) или общая VM с меньшим лимитом одновременности, где параллельные агенты, которые пишут, получают непересекающиеся файлы;
  - рабочий скрипт можно закоммитить как skill: `workflow.py` рядом с `SKILL.md`.
- **Security Swarm** использует тот же map-reduce [46]: параллельные агенты сканируют части кодовой базы; находки собираются в пути атаки и воспроизводятся в изолированных окружениях; повторные сканы — только по изменённому коду. Devin Security заявляет тысячи параллельных VM-сессий; каждая воспроизводит уязвимость, исправляет, тестирует и открывает PR [69].
- **CLI subagents** [151][155]:
  - у каждого своя цепочка разговора; историю родителя он не видит [151];
  - foreground: tool calls одобряет пользователь; background: неодобренные инструменты отклоняются, родитель получает уведомление по завершении [151];
  - родитель подводит итог результатов; у каждого профиля своя модель; для более глубокой вложенности нужен `max-nesting` в своём профиле [151];
  - прерывание ставит работающие subagents на паузу с сохранённым состоянием до следующего сообщения (2026-07-29) [155].
- **Fusion — несколько агентов на уровне моделей** [44][49][60]:
  - сильная lead-модель и дешёвая sidekick работают как два агента. У каждого свой постоянный контекст и инструменты. Они обмениваются только поручениями (briefs), результатами и обратной связью [44];
  - lead отвечает за план, снимает неясности, проверяет и коммитит [44];
  - модели переключаются на compaction, где кэш всё равно теряется. Лёгкие классификаторы подают сигнал о переключении посреди сессии. Большая часть закэшированных входов истекает через 5 минут, и дизайн это учитывает [44];
  - до 60% дешевле на собственном бенчмарке Cognition [44].
- **Исследование стоимости Fusion** (3000 eval-сессий) [49]:
  - Fable 5 в роли lead делал 11.5 ходов, Opus 4.8 — 26.5;
  - Fable-lead не правил код в 81% запусков, Opus-lead — в 24%;
  - оба передавали работу около 3 раз за запуск. Fable делегировал рано, с поручениями уровня design doc (ограничения, граничные случаи, критерий готовности), и проверял один итоговый diff. Opus 20–45 ходов исследовал сам и забирал файлы sidekick обратно в свой контекст;
  - Fable с sidekick стоил $1.86 против $2.04 у Opus с sidekick, при более высоком результате;
  - короткие задачи и последовательная отладка на части не делятся.
- **Настройка Fusion под пару моделей** [60]: насколько подробны поручения, может ли sidekick возражать, какое исследование делегировать. Исследование, которое определяет план, остаётся у lead.
- **«Smart friend»** (маленькая основная модель вызывает большую) не сработал с SWE-1.5 в роли основной и сработал между двумя frontier-моделями [32].
- **Локальная сторона:**
  - Agent Command Center показывает локальных и облачных агентов в одном окне [134];
  - worktrees Devin Local лежат в `~/.windsurf/worktrees/<repo>`, возвращаются кнопкой Merge и никогда не удаляются автоматически, даже при удалении сессии [139];
  - CLI `/handoff` отправляет контекст разговора, репозиторий, ветку и незакоммиченный diff в свежую облачную VM. Обратный handoff забирает ветку PR облачной сессии [152].

### Outposts: очередь и протокол захвата

- **Разделение:** цикл агента остаётся в облаке Cognition. Бинарник `devin-remote` на машине клиента исполняет tool calls через шлюз `wss://` [165].
- **Очередь** [165]:
  - ресурсы описаны в форме Kubernetes: metadata, spec, status;
  - клиент сначала получает список, затем слушает поток server-sent events (`MODIFIED`, `DELETED`) с доставкой «хотя бы один раз»;
  - клиент обновляет записи по `session_id` (upsert).
- **Захват (claim)** [165][166]:
  - захват — атомарная операция compare-and-swap; проигравший получает 409;
  - успешный захват возвращает connect token, URL шлюза и `claim_deadline`. Если срок прошёл, сессия возвращается в очередь;
  - отдельный вызов release освобождает сессию, если машину не удалось подготовить;
  - каждый outpost сообщает `queue_depth` и `active_claims`;
  - оператор может показать баннер в работающей сессии.
- **Центрального планировщика нет** [166]:
  - у каждого воркера стабильный `acceptor_id`. К нему привязаны захваты, продления и восстановление после перезапуска;
  - захват умершего воркера просто истекает;
  - если нужно больше примерно 16 координаторов, Cognition просит связаться с ней.
- **Контракт запуска** [165]:
  - переменные окружения: `DEVIN_OUTPOST_GATEWAY_URL`, `DEVIN_OUTPOST_CONNECT_TOKEN`, `DEVIN_OUTPOST_SESSION_ID`, `DEVIN_REMOTE_STATE_DIR` и несколько базовых системных (PATH, HOME и подобные);
  - `devin-remote` завершается с exit code 0, когда сессия засыпает или заканчивается;
  - бинарники закреплены по SHA коммита, рядом лежат файлы с SHA-256 в `static.devin.ai/devin-rs/remote/`. Что бинарник написан на Rust, выведено только из этого пути (не подтверждено).
- **Обнаружение потерянного состояния** [166]: при старте Devin пишет stamp-файлы `.devin-outpost-stamps/<session_id>` и `outpost_stamp`. Если при возобновлении stamp-файла нет, значит, папка не сохранилась, и Devin пишет предупреждение.
- **Reference Kubernetes operator** [196] — https://github.com/CognitionAI/devin-outpost-k8s, commit 9ea7f418 (2026-11-06), лицензия MIT:
  - `src/controller/mod.rs`: controller следит за ресурсами `OutpostPool` и их Pod-воркерами. Наблюдатель очереди (`src/controller/queue_watch.rs`) только запускает reconcile. Сам reconcile заново получает полный список и приводит систему к нужному состоянию. По комментарию в коде, сбои watch увеличивают задержку, но не ломают корректность;
  - `src/controller/plan.rs`: чистая функция-планировщик превращает наблюдаемое состояние в действия. Исполнители действуют по принципу best effort; следующий проход доводит систему до нужного состояния;
  - захваты продлевает центральный процесс, срок жизни захвата — около 5 минут. Pod-воркеры не держат токен пула. Реплики с выбором лидера (leader election) переключаются в пределах этого срока;
  - сессия завершена: освободить захват, удалить Pod, его Secret и артефакты snapshot;
  - сессия приостановлена: сделать snapshot по `ResumePolicy` (`StartFresh` по умолчанию, `GkeSnapshot` или `FilesystemSnapshot`; описание — в `src/crd/outpost_pool.rs`), затем удалить Pod и освободить захват;
  - воркер завершился с ненулевым exit code: перезапуск на месте до `worker_restart_limit` (по умолчанию 5, `src/config.rs`), затем освободить захват;
  - Pod не стартовал за `worker_startup_timeout` (по умолчанию 10 минут, `src/config.rs`): сообщить в очередь операцию `startup-failure`. Она навсегда снимает эту попытку и объясняет пользователю причину;
  - отдельного custom resource на сессию намеренно нет; всё состояние восстанавливается из list-запросов;
  - `src/network_policy/mod.rs`: allowlists по именам хостов через network policies Cilium или GKE, в режимах Auto, Through или Off.
  - Пути файлов, значения по умолчанию и лицензия проверены по локальной копии репозитория.

### Контекст и память

- **Сжатие.** Длинная история проходит через модель сжатия, а не делится между агентами [9].
- **«Context anxiety» у Sonnet 4.5** [14]:
  - модель делала работу небрежнее, когда считала, что приближается к пределу контекста;
  - помогло включить окно 1M токенов и при этом ограничить фактическое использование 200k;
  - собственные заметки модели (CHANGELOG.md, SUMMARY.md) оказались недостаточно полными, чтобы заменить систему памяти Devin.
- **Compaction в CLI** [155]: порог настраивается; есть hooks `PreCompact` и `PostCompact`; skills, выпавшие при сжатии, перечисляются снова (2026-10-14).
- **Memory drive** (2026-10-09) [120][91]:
  - память личная в пределах организации и не делится; это git-репозиторий Markdown-заметок;
  - у каждой сессии свой checkout. `MEMORY.md` добавляется в контекст, остальные заметки читаются по требованию;
  - записи — однострочные пункты с пометкой `[source: <session id>; added: <date>]`;
  - сохранение — коммит, который сливается с изменениями других сессий. Устаревшая запись отклоняется и повторяется. Конфликтующие правки разрешаются, а не перезаписываются;
  - память можно выключить для сессии и её дочерних сессий (`memory_enabled: false`, 2026-11-06) [91].
- **Dreaming** [120] — фоновая сессия примерно раз в день:
  - объединяет пересекающиеся заметки;
  - удаляет временные заметки и заметки, которыми не пользовалась ни одна сессия;
  - добавляет пропущенные уроки;
  - перестраивает структуру;
  - сохраняет ссылки на источники и явные предпочтения пользователя.
- **Открытая спецификация Agent Memory Repo** [198] — https://github.com/AgentMemoryRepo/agentmemoryrepo, commit 8798cb26 (2026-10-06), лицензия MIT; файлы `SPEC.md` и `README.md`:
  - `MEMORY.md` — точка входа; метаданные в виде `[key: value]`, ссылки — `[[path]]`;
  - агенты клонируют репозиторий, ищут в нём grep, обновляют и делают push после каждой правки;
  - соглашение для swarms: файлы `findings.md` и `questions.md`. Отказ git push упорядочивает двух агентов, которые правят одну строку.
- **Знания команды:**
  - Skills следуют стандарту Agent Skills. Рекомендуемый путь — `.agents/skills/<name>/SKILL.md`; пути `.devin/` и `.claude/` тоже читаются [121];
  - Knowledge устарел и автоматически переносится в skills-плагин `knowledge` (2026-09-18) [130][91];
  - Playbooks становятся Skills; новые аккаунты стартуют без Playbooks с 2026-10-24 [122];
  - в контекст попадают только первые 16 KiB файла `AGENTS.md`. Дальше агент получает уведомление об обрезке и читает остальное по требованию [129].
- **Состояние между запусками повторяющейся работы:**
  - Devin по расписанию ведёт заметки между запусками [26];
  - preflight-скрипты automations получают `STATE_FILE` (JSON-курсор до 64 KiB) и `LAST_RUN_FILE` (результаты последних 200 элементов) [116];
  - работа дедуплицируется по `id` плюс `version` элемента. По умолчанию за запуск отправляется не больше 10 новых элементов, максимум 50 [116].

### Проверка качества

- **Test mode** [38]:
  - Devin сначала пишет test plan по исходному коду. Планы без опоры на код придумывали несуществующие пути через приложение;
  - он размечает временную шкалу: заметки о настройке, названия тестов, утверждения с отметкой passed, failed или untested. Cognition выяснила, что запись ожидаемого поведения заранее снижает число ложных заявлений об успехе;
  - повторяющиеся шаги вроде login становятся skill;
  - пробуют отдавать фазу тестирования другой модели;
  - результат: отчёт со скриншотами с подписями и видео с главами, где простои вырезаны;
  - известные сбои: скриншот сделан не вовремя (например, пропущено всплывающее уведомление); «обман» — нужное состояние UI вызывается через JavaScript, а не через интерфейс;
  - test mode пока тарифицируется по одной пятой обычной цены — временно, «для экспериментов».
- **Devin Review** [106][19]:
  - Bug Catcher сообщает Bugs (severe или non-severe), Flags (investigate или note) и находки Security с классом CWE и severity [106];
  - публикует commit status `Devin Review`. Условие прохождения настраивается: ревью завершено (по умолчанию), треды закрыты или находок нет [106];
  - повторные ревью новых push переносят прошлые находки и проверяют, исправлены ли они [106];
  - каждый PR в стеке сравнивается со слоем ниже [106];
  - лимит расходов на авто-ревью для PR — мягкая блокировка: авто-ревью для этого PR останавливается, ручные работают, повторное включение даёт новый лимит [106];
  - custom reviewers хранят последние 20 версий своих инструкций [106].
- **Autoapprover** [106]:
  - оценивает соответствие намерению, качество кода и риск инцидента;
  - читает `APPROVAL_POLICY.md` из корня репозитория, из изменённых папок и их родителей — всегда из целевой ветки. Поэтому PR не может написать собственные правила одобрения. PR, который меняет такой файл, всегда требует человека;
  - заново оценивает каждый push, может отозвать своё одобрение и никогда сам не делает merge;
  - упавшая или пропущенная оценка Autoapprover не означает, что прежнее одобрение отозвано: одобрение может остаться на PR, и его нужно проверить у Git-провайдера.
- **Замкнутый цикл** [20][106]: Devin исправляет комментарии Devin Review и любого бота — линтеров, CI, сканеров. Auto-Fix сортирует каждую находку: исправить, проверить или передать человеку.
- **Ревью с чистым контекстом** [32]:
  - на PR самого Devin ревьюер всё равно находит около 2 ошибок на PR, около 58% — серьёзные;
  - лучше всего работает, когда у кодера и ревьюера нет общего контекста;
  - затем кодер отфильтровывает находки, опираясь на то, что знает о намерении пользователя.
- **Оценка качества у Cognition** [4]:
  - cognition-golden — внутренний бенчмарк с реальными окружениями;
  - агенты-оценщики проверяют результат, в том числе в браузере, по критериям. Оценка от 0 до 1, усреднённая по нескольким запускам Devin и оценщика;
  - на вопросы Devin отвечают симулированные пользователи.
- **Заявленные результаты (данные вендора):** 67% PR принято против 34% годом раньше [18]; 659 PR от Devin принято в собственный код Cognition за одну неделю [23].

### Лимиты, стоимость и остановка

- **Учёт** [182]: Enterprise платит в ACU. Self-serve сначала тратит квоту плана, потом предоплаченные кредиты. Расход складывается из действий и времени VM. Windows примерно на 9% дороже.
- **Планы** [179]: у мест Pro и Teams есть дневная и недельная квота, дневная больше седьмой части недельной. У Max — только недельная. Без кредитов automations останавливаются, а Review становится простым просмотрщиком diff.
- **Дерево бюджетов** [183]: когда кончился любой бюджет на пути, новые сессии не стартуют, работающие засыпают. Запросы CLI и Desktop блокируются с объяснением, новые ревью тоже. Окно бюджета — месяц от дня начала биллинга.
- **Режим подписки ChatGPT** [181]:
  - на лимите ChatGPT облачная сессия встаёт на паузу с явным сообщением и сама на квоту Devin не переходит;
  - пользователь возобновляет её после сброса лимита или выключает опцию;
  - Desktop и CLI вместо этого повторяют запрос на квоте Devin, затем на кредитах, и показывают уведомление;
  - облачным сессиям всё равно нужна квота Devin для старта.
  - Пост о запуске описывает поведение иначе — см. «Функции → Цены, квоты, контроль расходов» [65].
- **Ограничители расходов:**
  - `max_acu_limit` на сессию [175];
  - лимит ACU на каждую дочернюю сессию в managed Devins [103];
  - на каждую automation: лимит ACU, лимит частоты (по умолчанию 50 в час, 150 для Slack triage), число одновременных запусков, глубина очереди, после которой события отбрасываются [116];
  - лимит расходов на ревью PR [106].
- **Лимиты видны пользователю:**
  - причины лимита — это состояния сессии [176];
  - оранжевая отметка в боковой панели у сессий, остановленных из-за квоты (2026-06-03) [91];
  - CLI `/usage` с дневной и недельной полосой и временем сброса (2026-08-21) [155];
  - серверные rate limits больше не подписываются ошибочно как «Quota exhausted» (2026-09-10) [155].
- **Способы снизить стоимость:**
  - Fusion и роутер Adaptive [44][181][162];
  - скидка на test mode [38];
  - subagents добавляют свой расход к расходу родителя — это надо учитывать [151];
  - Devin Coach до отправки отмечает расточительные prompts — например, предлагает сначала план [185];
  - Session Insights делит сессии на классы XS–XL по расходу и помечает L и XL как нездоровые [113].
- **Риск доступности моделей (заявление вендора):** Cognition пишет, что доступ к Fable 5 приостановлен 2026-06-12 по директиве правительства США [44].

### Восстановление после сбоев

- **Workflows:** при возобновлении завершённые вызовы агентов воспроизводятся, упавшие повторяются в новых сессиях [104].
- **Outposts:** истёкшие захваты возвращаются в очередь; воркеры перезапускаются на месте до лимита; запуск, который так и не удался, заканчивается состоянием `startup-failure` с причиной [166][196].
- **Сбой машины:** блокирующая карточка предлагает «Try restart» или «Continue in a new session» и предупреждает, что файлы машины и запущенные процессы не переносятся (2026-09-09) [91]. Упавшую сессию можно повторить ответом в треде Microsoft Teams (2026-10-19) [91].
- **CLI** [155]:
  - если связь оборвалась посреди ответа, уже полученный текст сохраняется, а запрос повторяется. Повторяющиеся сбои показываются одним уведомлением (2026-10-22);
  - ACP при закрытии канала возвращает структурированную ошибку с признаком «можно повторить». Клиент переподключается, а не отправляет prompt заново (2026-09-21);
  - если модель отказывается отвечать, ход повторяется на других моделях из заданного списка (2026-09-10).
- **Постоянные и временные сбои различаются:** неверный webhook Jira сразу показывает причину для переподключения, а временные сбои Jira повторяются (2026-10-02) [91]. Письма о сбоях запусков по расписанию ограничены по частоте (2026-04-10) [91].
- **Прочее:**
  - сессии Ultra сообщают, когда lead-модель работает хуже обычного и когда восстановилась (2026-08-19) [91];
  - сообщения в очереди переживают простой и возобновление (2026-09-09) [91];
  - hooks работают по принципу best effort: упавший hook не останавливает сессию [158];
  - упавшая или пропущенная оценка Autoapprover не означает, что прежнее одобрение отозвано; одобрение может остаться на PR [106].
- Повторы и backoff при ошибках API моделей в облаке не описаны (не подтверждено).

### Права и безопасность

- **Security profiles** [115] задают:
  - allowlist сети для всего трафика;
  - allowlist MCP;
  - доступ только на чтение к собственному MCP Devin;
  - уровень доступа к git: только чтение или полный;
  - удаление токена `gh`. Токен можно оставить только при полном доступе к git и доступном `api.github.com`.
  - Профили привязываются к enterprise, организации, automation или сессии.
  - **Обязательный** профиль — нижняя граница. Отказ от него игнорируется, а более мягкие выборы пересекаются с ним: allowlists сужаются до общего, доступ к git берётся минимальный.
  - Доступ, выданный посреди сессии, тоже ограничивается обязательным профилем.
  - Дочерние сессии подчиняются цепочке родителя, поэтому делегирование не обходит ограничения.
  - Профиль вычисляется при загрузке и заново при каждом пробуждении или перезагрузке.
- **Secrets** [114][91]:
  - секрет передаётся конкретной команде как переменная окружения и только там, где он нужен. Во все shell секреты не экспортируются [114];
  - секреты репозитория никогда не пишутся в blueprints и snapshots [114];
  - секреты, запрошенные посреди сессии, живут только в этой сессии [114];
  - строки приватных ключей скрываются агрессивнее с 2026-10-07 [91];
  - клонирование идёт через git proxy Devin [91].
- **AI Guardrails** [186]: проверяют сообщения пользователя, включая комментарии в PR, на prompt injection и утечку данных. Действия: `log_only`, `warn_user` или `block_message`. События пишутся в audit logs.
- **GitHub** [168]:
  - связка аккаунтов делает PR авторства пользователя;
  - рекомендуются branch protections;
  - «Require session access for PR comments» пропускает комментарий в PR, только если у его автора есть доступ к сессии.
- **Режимы прав CLI** [149]:
  - Normal;
  - Accept Edits — правки в workspace одобряются автоматически;
  - Smart — быстрая модель сама выполняет только явно безопасные вызовы. Никогда не одобряются автоматически: установка пакетов, git-команды, меняющие состояние, `rm` и `sudo`, `kubectl delete` и разрушительные облачные CLI, всё, что касается dotenv-файлов, ключей, git config или конфигурации самого агента;
  - Bypass;
  - Autonomous — только с `--sandbox`.
  - Правила deny и ask организации сильнее любого режима.
- **Sandbox CLI** [150]:
  - запись разрешена только в workspace и в выданные области;
  - если sandbox не удалось поднять, CLI не стартует;
  - на Linux нужны bubblewrap и socat; Windows не поддерживается;
  - фильтрация сети помечена как нестабильная.
- **Local Hands** [110]: облачная сессия получает второй набор инструментов на машине пользователя. Одноразовый код связи получает только владелец сессии, срок — 10 минут. Каждый вызов требует одобрения; есть варианты «на эту сессию» и bypass. Вызовы с учётными данными, повышением привилегий и разрушительные команды спрашивают всегда.
- **Hooks** [158]:
  - события: `PreToolUse`, `PostToolUse`, `PermissionRequest`, `UserPromptSubmit`, `Stop`, `PostCompaction`, `SessionStart` и `SessionEnd` (в облаке не срабатывает);
  - блокирующий hook `Stop` может зациклить агента;
  - в облаке каждое пробуждение считается возобновлением, поэтому hook «один раз за сессию» должен проверять поле `source`.

### Где Devin спрашивает человека

- Одобрение плана, если уверенность ниже зелёной [8].
- `waiting_for_approval` в safe mode [176].
- Одобрение пачки дочерних сессий, если авто-одобрение выключено [103].
- Новые адреса в сети [115].
- Вызовы Local Hands [110].
- Секреты, запрошенные посреди сессии [114].
- PR, которые Autoapprover оставил человеку, и находки, которые Auto-Fix передал человеку [106].
- Пользователь может поставить Devin на паузу и взять IDE на себя [92].
- Side chats (`/btw`) только на чтение и не прерывают основную работу [92].
- Очередь отправки на сервере переживает перезагрузку страницы [135]. Сообщения в очереди можно править, пока Devin простаивает (2026-10-16) [91].

### Наблюдаемость

- **Progress** — единый лог команд shell, правок файлов и действий в браузере. По истории команд можно посмотреть состояние сессии на любой момент [92]. О расхождении с release notes — в разделе «Функции → Облачная сессия: что видит пользователь».
- **Живые виды:** панель workflow показывает каждую фазу и живой статус агентов [104]; у тест-видео есть главы [38]; строка «Reminder set» появляется, когда Devin ставит себе напоминание (2026-11-12) [91].
- **Session Insights** [113]: лёгкая классификация после каждой сессии. Сессии L и XL при завершении автоматически получают полный разбор: временную шкалу проблем и улучшенный prompt.
- **Разбор по запросу:** Devin может разобрать прошлую сессию, например почему ушло 42 ACU вместо ожидаемых 12 [103]. `devin_session_events` выдаёт и ищет события сессии [105].
- **Парк сессий:**
  - enterprise queue API считает сессии в состояниях `new`, `resuming` или `claimed`, созданные за последние 30 дней: до 10 — норма, 11–50 — повышенная нагрузка, больше 50 — высокая [177];
  - hypervisor API сообщает heartbeat и загрузку для VPC-tenants, которыми управляет клиент [177];
  - audit logs записывают события guardrails [186].
- **Локально:**
  - CLI передаёт терминалу состояния idle, working, blocked, done или failed через escape-последовательность OSC 7501 (2026-10-14) [155];
  - Desktop может показывать системное уведомление, когда агент закончил или ждёт ответа [134].

  - при отладке SSH Devin держался одной неверной гипотезы;
  - переусложнённый, запутанный код;
  - ложные срабатывания при проверке безопасности;
  - игнорирование соглашений проекта (nbdev, Quarto) и лишние зависимости;
  - коллега потратил часы на одну фичу с Devin, а потом написал её сам примерно за 90 минут.
- Главный вывод Answer.AI: они не нашли закономерности, по которой можно предсказать, какие задачи получатся [213]. Читатели HN согласились: инструмент, поведение которого нельзя изучить, — плохой инструмент [214].
- Комментатора удивило, что у Devin нет мягкого способа попросить помощи. Он предложил оркестратор, который примерно каждые 10 минут проверяет, не нужна ли исполнителю остановка или помощь [215].
- Другие жаловались на лишние изменения, которые Devin не смог откатить по просьбе. Один обозреватель советовал отменить подписку: времени не экономит и дорого [216].
- Годовой отчёт вендора 2025 года признаёт те же слабости [18]:
  - Devin плохо справляется с неясными требованиями и сменой объёма посреди задачи;
  - в отличие от junior-инженера, он не учится от подсказок по ходу задачи.
- Пост о GA советует: давать задачи, которые можно сделать самому; держать сессии короче ~3 часов; ждать проблем с merge-конфликтами [5].
- Zhu Liang видел, как сессии теряют качество после ~2.5 часа или 10 ACU [219].

**Скорость.** В 2024 году давний тестировщик назвал стандартный Devin слишком медленным. Сооснователь ответил, что он уже в 3–4 раза быстрее, чем в апреле [212]. Zhu Liang видел долгие простои [219].

**Цены и квоты непрозрачны и часто меняются.**
- В январе 2026 года потенциальный покупатель не понял ACU: около $2.50 за штуку, неясная плата за поддержание VM и нет ориентира, на сколько хватит начального плана [230].
- На текущей странице цен квоты обновляются ежедневно и еженедельно, но размеры не указаны. Сверх квоты — по ценам API [81].
- Пользователи сообщают [234]:
  - на плане за $20 лимит кончается быстрее, чем у Claude Code или Codex;
  - быстрый вариант модели на Cerebras съел 14% дневной квоты за один prompt;
  - нет опубликованного списка моделей и квот по моделям.
- Бывшие клиенты Windsurf:
  - после покупки поддержка пропала, цены поднимали дважды, бренд закрыли — они ушли [234];
  - старый дешёвый план стал хуже [234];
  - один продолжает платить только потому, что ему сохранили старую цену [236].
- Trustpilot для windsurf.com: 1.4 из 5 по 58 отзывам. Жалобы: квоты урезали за ночь, смена планов, списания после отмены, поддержка не отвечает. Профиль не подтверждён компанией, выборка самоотобранная (вторичный источник) [243].
- У платящего клиента заморозили аккаунт: все его карты отклонялись, и это остановило production-работу [238, issue #2]. На Trustpilot для devin.ai — похожий сбой продления и отзыв о сломанном коде после 3 часов работы (вторичный источник) [242].

**Разрозненный продукт и ошибки harness.**
- Пользователь из enterprise пишет, что веб-клиент и desktop — два разных harness с очень разным качеством. Claude и Codex он считает намного лучше [236].
- Другой называет разрыв между облачным Devin и Devin Desktop стыдным, а Desktop — Windsurf с новым оформлением [236].
- Devin CLI называют худшим в своём классе и полным ошибок. Пример — он терял ответы на вопросы агента [236].
- Пользователи эпохи Windsurf строили обходные пути, потому что команды в терминале зависали [236]. Соответствующая issue объясняет это игнорированием ошибок записи в pipe терминала; обход — выключить shell integration [239, issue #245].
- Трекер Devin CLI [238]:
  - память долгих локальных сессий на Windows растёт без предела; в одном отчёте — 65.7 GB в дочернем процессе ACP. Причина — цикл, который снова и снова находит skills. Исправлено в конце октября 2026 [#25, #31];
  - падения renderer на Linux [#54];
  - сторонние ACP-сессии падают с «invalid params» или висят на «Setting up…» [#36, #37]; сообщения дублируются с Google Antigravity [#58];
  - на некоторых аккаунтах локальный агент не запускается с «Permission denied … error number 12», а облачные сессии работают [#28];
  - сессии, созданные через API, не видны в списке веб-интерфейса [#45];
  - контекст растёт, потому что compaction сохраняет резюме в боковую ветку истории [#56].

**Пробелы в работе без человека — самое важное для оркестрации.**
- Команда запускает Devin CLI без присмотра, каждый воркер в своём git worktree. Правки файлов всё равно требовали одобрения, несмотря на правила allow, и воркеры останавливались. Обход: выключить инструменты edit и write и делать все изменения через shell-команды в sandbox [238, issue #24].
- Отклонённый вызов инструмента MCP завершает неинтерактивный запуск с exit code 0 и без ответа [238, issue #15].
- Запросы одобрения от background subagents прятались в свёрнутых карточках. Это блокировало работу нескольких агентов до исправления в октябре 2026 [238, issue #32]. Документация CLI при этом говорит, что background subagents сами отклоняют неодобренные инструменты [151]. Причина расхождения не выяснена.
- Фоновые shell-задачи не сообщают агенту о завершении [238, issue #57].
- В трекере Windsurf: панель агента (Cascade) хранила только последние 20 разговоров, позже 50, и молча удаляла старые. Экспорта и поиска не было [239, issues #136, #127].
- Переименование Windsurf в Devin Desktop на месяцы сломало вход в расширении VS Code [239, issue #336].

**Привязка к вендору.** Пользователи недовольны, что модели SWE доступны только внутри Devin — без API и без OpenRouter. Чтобы просто попробовать модель, они не хотят ставить отдельный набор инструментов [236][234].

**Безопасность.** Johann Rehberger (блог Embrace The Red) заплатил $500 за месяц доступа [224][225][226]:

- он нашёл четыре способа утечки секретов: команды shell, переход в браузере, картинки в Markdown и ссылки в Slack [225];
- инструмент Devin, который открывает локальный порт в интернет, запускался внедрённым текстом с веб-страницы без одобрения [226];
- сообщение вендору отправлено 2025-04-06. Вендор подтвердил получение, но больше 120 дней не отвечал на повторные письма. Исследователь советует одобрение вне чата и запрет исходящего трафика по умолчанию [224][226].

- Zhu Liang: больше 10 задач. Четыре задачи потратили около 46 ACU — примерно $92, то есть около $23 на задачу. Итог: приемлемо, лично для него стоит $500 [219].

### С чем сравнивают

- **Cursor.**
  - 2025: пошаговое управление в Cursor работало лучше. Cursor сделал рабочую интеграцию там, где Devin не справился [213].
  - 2026: Cursor даёт больше за деньги подписки [234] и выпускает функции быстрее, чем Windsurf и Devin Desktop [236].
  - Но один тестировщик предпочёл облачных агентов Devin облачным агентам Cursor [236].
  - Builder.io описывает разницу так: в Cursor разработчик продумывает код сам вместе с агентом, в Devin — отдаёт работу целиком. Это вторичный источник без практической проверки, и Builder.io продаёт конкурирующий продукт [244].
- **Claude Code и Codex.**
  - Их видят инструментами отдельного разработчика, а Devin — участником команды [236].
  - Их часто оценивают выше по качеству [236] и по соотношению цены и результата [234].
  - Некоторые команды строят свой аналог на managed agents от Anthropic [235].
- **Copilot.** Devin считают лучше [236]. Комментарии ревью Copilot считают шумными [230].
- **Узкие агенты.** Основатели конкурирующих продуктов утверждают, что агенты с узкой задачей успешнее, а enterprise просит более простой подход [218].
- **Автор OpenHands:** код агентов нужно ревьюить, как код выпускника буткемпа. Около 20% коммитов в OpenHands написаны самим OpenHands [217].

### Почему выбирают и почему уходят

- **Выбирают:** миграции, исправления безопасности и backlog в масштабе многих сессий; поручения из Slack или через API; облачные sandbox, общие для команды; дешёвые собственные модели; смешивание агентов через ACP [210][221][236][234].
- **Уходят:** приходится разбирать непредсказуемый результат; непрозрачные и меняющиеся квоты и цены; сбои оплаты и поддержки; ошибки harness; недоверие с 2024 года; привязка к вендору; Claude Code, Codex или Cursor выгоднее [213][216][234][236][238][243].

**Две оговорки о доказательствах.**
- В 2025 году Cognition выступала против архитектур с несколькими агентами, и читатели HN в основном согласились, что один агент с хорошо управляемым контекстом надёжнее [227]. В 2026 году Cognition выпустила managed Devins с координатором и дочерними сессиями [25].
- Весомые положительные отзывы приходят от платящих команд. Заметная часть похвалы в сети — от сотрудников, которые раскрыли место работы [230][236][228][233].

### Общие темы изменений (синтез исследователя)

## Слабые места и чего нет

**Качество и предсказуемость.**
- Результат трудно предсказать: Answer.AI не нашли закономерности, какие задачи получатся, 3 успеха из 20 [213][214].
- Вендор сам признаёт слабости: неясные требования, смена объёма посреди задачи, результаты, которые нельзя проверить [18].
- Длинные сессии теряют качество — примерно после 2.5 часа или 10 ACU [219]. Cognition сама советовала держать сессии до 10 ACU (2025) [90] и помечает сессии L и XL как нездоровые [113].
- Рабочий размер задачи — около 3 часов работы человека [84][86].
- Test mode: скриншот может быть сделан не вовремя; агент может вызвать нужное состояние UI через JavaScript, минуя действия пользователя, и тест покажет успех [38].
- DeepWiki содержит фактические ошибки [229][240].
- В 2025 году у Devin не было мягкого способа попросить помощи [215].

**Работа без человека.**
- Правки файлов требовали одобрения, несмотря на правила allow [238, issue #24].
- Отклонённый вызов MCP завершает неинтерактивный запуск с exit code 0 и без ответа [238, issue #15].
- Запросы одобрения от background subagents прятались и блокировали работу; исправлено в октябре 2026 [238, issue #32].
- Фоновые shell-задачи не сообщают о завершении [238, issue #57].
- Automations: у preflight нет автоматического повтора; запуски сверх очереди отбрасываются; тело webhook больше 200 KB обрезается [116].
- Local Hands недоступен в automations, расписаниях и у service users [110].
- Блокирующий hook `Stop` может зациклить агента; `SessionEnd` в облаке не срабатывает [158].
- `/goal` в CLI сам останавливается после 50 ходов [155].

**Лимиты и деньги.**
- Квоты и цены непрозрачны и часто меняются; размеры квот и список моделей по квотам не опубликованы [230][234][81][243].
- Pro и Max ограничены 10 одновременными облачными сессиями; у Free в строке одновременных сессий стоит значок «нет» [81].
- На лимите подписки ChatGPT облачная сессия ждёт ручного возобновления [181]. Автоматического продолжения после сброса квоты не найдено (не подтверждено).
- Облачной сессии нужна квота Devin даже при оплате через ChatGPT [181].
- Свои API-ключи LLM не принимаются [189].
- Dynamic Workflows могут тратить гораздо больше ACU [104]; subagents добавляют свой расход к расходу родителя [151].
- Повторы при ошибках API моделей в облаке не описаны (не подтверждено).
- Доступность моделей зависит от внешних решений: по словам Cognition, доступ к Fable 5 приостановлен 2026-06-12 по директиве правительства США [44].

**Разрозненность и ошибки.**
- Веб-клиент и Desktop — два разных harness с разным качеством [236].
- Ошибки CLI и Desktop: рост памяти на Windows до 65.7 GB, ошибки ACP, падения на Linux, сессии из API не видны в веб-интерфейсе [238].
- Вход в расширении VS Code был сломан месяцами после переименования; Cascade молча удалял старые разговоры [239].
- Sandbox CLI не поддерживает Windows; фильтрация сети нестабильна [150].
- CLI пока без Knowledge, Playbooks и Secrets [146].
- Worktrees в Desktop не удаляются автоматически, даже при удалении сессии [139].
- Устаревшие данные в документации: OS X Yosemite как минимальная macOS [144].
- Документация и посты противоречат друг другу: вкладка Progress [92][91], поведение на лимите ChatGPT [181][65], срок бесплатного SWE-2 [143][76], дневные лимиты [51][179].

**Безопасность и доверие.**
- В 2025 году исследователь показал prompt injection с запуском вредоносной программы, утечки секретов и открытие портов наружу; вендор больше 120 дней не отвечал [224][225][226].
- Документация сама предупреждает: ввод из Slack недоверенный [119]; payload handoff с `git diff` может содержать секреты [152][109].
- Значение, записанное в файл на шаге `initialize`, остаётся в snapshot [125].
- Часть пользователей не доверяет бренду из-за демо 2024 года и бенчмарков, которые Cognition строит сама [234][236][233][230].
- Цифры результатов — заявления вендора без аудита. По Gumroad видна разница: 252 PR от бота против заявленных 1500+ принятых [241][82].

**Привязка к вендору.**
- Модели SWE доступны только внутри Devin, без API [236][234].
- Связь с машинами клиента (Local Hands, Outposts) идёт через облако Cognition [110][165].

**Чего нет или не найдено.**
- Автоматического продолжения после сброса квоты (не подтверждено).
- Автоматических повторов при ошибках API моделей в облаке (не подтверждено).
- Скрытия личных данных на скриншотах и записях (не подтверждено). Найдено только скрытие секретов в транскриптах `/share` [137] и строк приватных ключей [91].
- Критики спецификаций (не подтверждено).
- Нативного мобильного приложения (не подтверждено); есть только PWA и мобильный веб [91].
- Свободного canvas: есть Kanban, список и до 8 сессий рядом [141][30].
- Слоя эпиков и тикетов, которые человек утверждает заранее. Работу делит модель координатора; из backlog есть только предварительная оценка уверенности по issues Linear и Jira [103][8].
- Отдельного локального Gate с вердиктом. Проверка — это команды из blueprint, check Devin Review в PR и видео теста [125][106][93].
- Публичного roadmap.
- Независимых бенчмарков; все цифры — от вендора [18][43].
- Открытого кода основного продукта [197][196].

**Где подходы расходятся в целом.**
- **Где идёт работа.** worfy — локальное приложение. Devin по умолчанию работает в облаке, на своей VM для каждой сессии [189][33].
- **Кто платит за модели.** worfy работает в пределах подписок пользователя. Devin продаёт свою квоту и ACU; чужие API-ключи не принимает, исключение — подписка ChatGPT [189][181].
- **Для кого.** worfy — для одного человека. Devin продаётся командам и enterprise: SSO, роли, бюджеты, несколько организаций [179][191][183].
- **Чей агент.** worfy показывает и запускает агентов Claude Code и Codex. У Devin свой агент и свои модели, сторонние агенты подключаются через ACP [136][59].
- **Как делится работа.** В worfy — Epics и Tickets, которые раздаёт Orchestrator. В Devin — модель-координатор или скрипт workflow [103][104].
- **Где проверка.** В worfy — локальные тесты, Gate и reviewer subagents. В Devin — check Devin Review в PR, видео теста и Autoapprover [106][38].
- **Как видна работа.** В worfy — бесконечный Canvas. В Devin — Kanban, список и окна рядом [141][134].

## Механизмы, которые стоит изучить

1. **Повтор завершённой работы по хешу вызова (Dynamic Workflows).**
   - Что это: возобновление многоагентного run без повторного запуска и оплаты завершённых шагов.
   - Как работает:
     - скрипт оркестрации запускается заново с начала;
     - ключ каждого вызова `agent()` — хеш prompt, схемы результата и настроек;
     - завершённые вызовы сразу возвращают записанный результат;
     - правка prompt перезапускает только этот вызов и всё, что от него зависит;
     - скрипт не читает время, случайные значения, ID, окружение, файлы и сеть, иначе хеши не совпадут;
     - политика ошибок пишется в коде: пропустить, значение по умолчанию, повторить, остановиться; упавшие агенты при возобновлении идут в новые сессии;
     - лимит run — 7 дней.
   - Источник: [104].
2. **Типизированный результат дочерней сессии.**
   - Что это: дочерняя сессия возвращает данные по схеме, а не свободный текст.
   - Как работает: при создании сессии передаётся `structured_output_schema` (JSON Schema Draft 7, до 64 KB). С `structured_output_required` агент обязан вызвать `provide_structured_output` с `is_final=true` до конца хода. В workflows `agent()` возвращает dict по схеме; в managed Devins дочерние сессии отдают результат по схеме.
   - Источник: [175][104][91].
3. **Пробуждение по событиям и ожидание группы сессий.**
   - Что это: координатор не опрашивает дочерние сессии, а спит, пока не произойдёт событие.
   - Как работает: координатор просыпается, когда дочерняя сессия закончила или ей нужен ответ. Инструмент `devin_session_gather` ждёт, пока несколько сессий придут в устойчивое состояние. Спящую сессию также будят комментарии в PR, ошибки линтера, трафик на preview и напоминание, которое агент поставил себе сам.
   - Источник: [103][105][89][91].
4. **Причины остановки как состояния сессии.**
   - Что это: у каждой остановленной сессии есть машинно-читаемая причина.
   - Как работает: состояние `suspended` с `status_detail` — `inactivity`, `user_request`, `out_of_quota`, `usage_limit_exceeded`, `org_usage_limit_exceeded`, `payment_declined` и другие. Отдельный статус Waiting показывает намеренный сон. В боковой панели — оранжевая отметка у сессий, остановленных квотой. Серверные rate limits не подписываются как «Quota exhausted».
   - Источник: [176][91][155].
5. **Политика одобрения из целевой ветки (Autoapprover).**
   - Что это: автоматическое одобрение PR, правила которого PR не может изменить сам.
   - Как работает: `APPROVAL_POLICY.md` читается из корня, из изменённых папок и их родителей — всегда из целевой ветки. PR, который меняет такой файл, всегда требует человека. Оценка повторяется на каждый push; одобрение можно отозвать; сам merge Autoapprover не делает; упавшая или пропущенная оценка не означает, что прежнее одобрение отозвано — его надо проверить у Git-провайдера. Функция в beta, доступна не всем аккаунтам.
   - Источник: [106].
6. **Цикл ревью: перенос находок, сортировка исправлений, мягкий лимит расходов.**
   - Что это: ревью, которое помнит прошлые находки и само доводит исправления.
   - Как работает:
     - повторное ревью переносит прошлые находки и проверяет, исправлены ли они;
     - Auto-Fix сортирует находки: исправить, проверить или передать человеку; неверные находки не публикуются; итог — одно резюме «Fixed by Devin»;
     - лимит расходов на авто-ревью PR останавливает только автоматические ревью;
     - custom reviewers — именованные ревьюеры с инструкциями из текста или из skill, со своими правилами, лимитом расходов, историей из 20 версий и отдельным CI check по выбору;
     - ревьюер работает с чистым контекстом, а кодер потом фильтрует находки по намерению пользователя.
   - Источник: [106][20][32][75].
7. **Режим Smart с неснимаемым списком «всегда спрашивать» и обязательные профили.**
   - Что это: автоматическое одобрение рутинных действий с жёсткой нижней границей безопасности.
   - Как работает:
     - быстрая модель одобряет только явно безопасные вызовы;
     - установка пакетов, git-команды, меняющие состояние, `rm` и `sudo`, разрушительные облачные CLI, dotenv-файлы, ключи, git config и конфигурация агента — всегда вопрос человеку;
     - правила организации сильнее любого режима;
     - обязательный security profile — нижняя граница: выборы пересекаются с ним, дочерние сессии наследуют ограничения родителя, профиль вычисляется заново при каждом пробуждении;
     - в Local Hands — одобрение «один раз», «на сессию» или отказ и одноразовый код связи на 10 минут.
   - Источник: [149][138][115][110].
8. **Память с происхождением записей и ежедневной чисткой.**
   - Что это: личная память пользователя, которую видят все его сессии; с командой и организацией она не делится. У каждого факта есть источник и дата.
   - Как работает: git-репозиторий Markdown-заметок; `MEMORY.md` всегда в контексте; записи — однострочные, с `[source: <session id>; added: <date>]`; сохранение — коммит, при конфликте — отказ и повтор; фоновая сессия Dreaming примерно раз в день (если пользователь работал с Devin) объединяет заметки, удаляет неиспользуемые, добавляет пропущенные уроки и сохраняет источники; список того, что не хранится, задан явно; формат — открытая спецификация.
   - Источник: [120][198][91].
9. **Захват работы из очереди с арендой и сверкой состояния (Outposts).**
   - Что это: машины клиента сами забирают сессии из очереди, без центрального планировщика.
   - Как работает:
     - захват — compare-and-swap, проигравший получает 409;
     - у захвата есть `claim_deadline`, продление и release;
     - у воркера стабильный `acceptor_id`; захват умершего воркера истекает, и сессия возвращается в очередь;
     - в Kubernetes operator watch только запускает reconcile, а reconcile перечитывает всё и приводит систему к нужному состоянию; действия вычисляет чистая функция в `src/controller/plan.rs`;
     - лимит перезапусков воркера (`WORKER_RESTART_LIMIT`, по умолчанию 5) и состояние `startup-failure` с причиной;
     - stamp-файлы показывают, что рабочая папка не сохранилась.
   - Источник: [165][166][196].
10. **Test mode с утверждениями и видео.**
    - Что это: доказательство того, что изменение работает, в виде видео и отчёта.
    - Как работает: test plan строится по исходному коду; ожидаемое поведение записывается до действия; утверждения помечаются passed, failed или untested; login выносится в skill; видео с главами без простоев и скриншоты с подписями; проверка запускается после зелёного CI. Известные сбои — скриншот не вовремя и обход UI через JavaScript. Пока цена — одна пятая обычной; Cognition подаёт это как временную меру «для экспериментов».
    - Источник: [38][93].
11. **Разбор сессий и проверка prompt до отправки (Session Insights и Devin Coach).**
    - Что это: анализ того, куда ушёл расход и почему сессия пошла плохо, плюс подсказки до запуска.
    - Как работает: каждая сессия получает класс размера XS–XL по расходу; сессии L и XL автоматически получают полный разбор — временную шкалу проблем, улучшенный prompt и список knowledge, которые помогли или сбили. Разбор можно запросить вручную (пример: 42 ACU вместо 12). Coach до отправки предлагает сначала план, лёгкий режим, новую сессию или деление на дочерние сессии; вид Blockers группирует проблемы агентов.
    - Источник: [113][185][103].
12. **Lead и sidekick с переключением на compaction (Fusion).**
    - Что это: связка дорогой и дешёвой модели, где дорогая планирует и проверяет, а дешёвая исполняет.
    - Как работает: lead отвечает за план, снимает неясности, проверяет и коммитит; sidekick исполняет; модели обмениваются только поручениями, результатами и обратной связью; модель переключается на compaction, где кэш всё равно теряется; поручения уровня design doc. Принуждение к делегированию ухудшает результат; короткие задачи не делятся. Данные Cognition: Fable-lead — 11.5 ходов против 26.5 у Opus, $1.86 против $2.04.
    - Источник: [44][49][60][163].
