## Модель работы

- **Hybrid.** Каждая сессия выбирает одно environment — место, где работает агент [1]:
  - Local — компьютер пользователя.
  - Cloud — VM Anthropic или self-hosted. Работает и после закрытия приложения. Расходует лимиты плана без отдельной платы за compute [1][19].
  - SSH — Desktop сам ставит Claude Code на удалённую машину [1].
  - WSL 2 на Windows 10 и 11 [1][38].
- **Агенты.** Только Claude. Во всех пяти способах параллельной работы (subagents, agent view, agent teams, dynamic workflows, Projects) исполнители — сессии Claude. Другие инструменты подключаются только как MCP-серверы — внешние инструменты по протоколу Model Context Protocol [16]. Поддержки Codex или агентов других вендоров не найдено (не подтверждено).
- **Модели.** Opus 5.5 — с 2026-09-21, Sonnet 5.5 — с 2026-09-27 [3]. В строке ввода выбираются модель и effort — сколько модель думает [1]. Уровень Ultracode на шкале effort — с 2026-06-05 [3]: он повышает effort, и Claude сам решает, когда запускать workflow [11][57]. Сторонние провайдеры моделей — только через отдельную сборку «Claude Desktop on 3P» (Bedrock, Google Cloud Agent Platform, Microsoft Foundry) или через gateway [1][6][39].
- **Движок.** Встроенная копия Claude Code: Node.js и CLI ставить не нужно [2]. Движок тот же, что у CLI, но только интерактивный: без `--print` и `--output-format` [1].
- **Пользователи.** Сессии и Projects принадлежат одному человеку. Projects нельзя расшарить; cloud-сессии и Artifacts — можно [12][19][34]. Для Team и Enterprise есть админ-консоль, managed settings и SSO; для Enterprise — SCIM [1][6].
- **Платформы.** macOS (universal), Windows x64 и ARM64 (MSIX), Linux beta (.deb и apt для Ubuntu 22.04+ и Debian 12+, x86_64 и arm64) [1][37]. Рядом работают веб-страница claude.ai/code и мобильное приложение Claude. Через них идут cloud-сессии, Remote Control (управление локальной сессией с веба или телефона) и Dispatch (разговор Cowork на телефоне, который ставит задачи компьютеру) [1][19][21].
- **Переходы между поверхностями.**
  - CLI → Desktop: `/desktop` или `claude --desktop [--continue|--resume <id>]` (v2.1.285+, macOS и Windows x64, только подписка) [1].
  - `/resume` в Desktop показывает сессии CLI; импорт сессий CLI — с 2026-07-09 [1][3]. Источники расходятся: по сбору отзывов, те же docs говорят, что Desktop не видит сессии CLI, VS Code и облака, а запрос на общую историю CLI и Desktop открыт (157 👍) [1][70].
  - Desktop → облако: Open in > Cloud переносит сводку разговора. Из SSH и WSL недоступно [1].

## Функции

### Окно и сессии

- **Вкладка Code.** Рядом вкладки Chat и Cowork. Cowork — агент для работы, не связанной с кодом [1][47][138].
- **Sidebar сессий.** Фильтры по статусу, проекту и environment [54]. Вкладка All sessions с фильтром Environment заменила вкладку Projects 2026-06-16 [3]. Группы по environment и свои секции — с 2026-10-15 [1][3]. Есть вид Archived [1]. Command palette ⌘K архивирует и удаляет сессии (2026-07-07) [3].
- **Строка ввода.** Environment, папка (в облаке — репозитории), режим прав, модель и effort, usage ring — кольцо расхода плана [1]. Меню «+» добавляет вложения, skills, connectors и plugins [1]. Файлы упоминаются через @; изображения и PDF прикрепляются или перетаскиваются [1]. Карточки вопросов с вариантами ответа — 2026-06-23; пометки на скриншотах прямо в поле ввода — 2026-07-21 [3].
- **Сообщения во время работы.** Новое сообщение встаёт в очередь или корректирует текущий turn (один ответ агента) [1]. Очередь можно переставлять, дополнять изображениями (2026-07-02) и менять через действия (2026-07-16) [3].
- **Подсказки prompt.** Серые подсказки принимаются клавишей Tab. Каждая стоит фонового запроса за счёт usage; их можно выключить [1].
- **Panes** (области окна). Chat, diff, browser, terminal, file, plan, tasks, subagent, iOS Simulator [1]. Их перетаскивают, меняют размер, закрывают `Cmd+\` и выносят в отдельное окно [1]. Сворачивание — с 2026-11-05 [3].
- **Split view и окна.** Несколько сессий рядом (Option-click или Open in > Split view) или в новых окнах [1]. Восстановление окон — с 2026-08-06 [3].
- **Session rail** (панель деталей сессии). Сборы расходятся в составе карточек. Один называет четыре: Environment с переключателем Remote Control, Changes, Running tasks и Context с долей занятого context window [1][3]. Два других по changelog перечисляют ещё Connectors, Outputs, Servers и Background tasks (2026-10-15) [3].
- **Plan box.** В конце turn — краткий итог и кнопки следующего шага (2026-10-15) [3].
- **Transcript.** Виды Normal, Thinking и Verbose (Ctrl+O). Вид Summary убран в v1.46388.1 [1]. Вид по умолчанию настраивается с 2026-09-10 [3]. Длинный разговор сжимается сам или по `/compact` [1].
- **Terminal.** Встроенный, открывается ``Ctrl+` ``, с вкладками, стартует в папке сессии. Работает локально и по SSH [1][3].
- **Files pane.** Правка локальных файлов с Auto save. Если файл изменился на диске — выбор Override или Discard [1]. В cloud, SSH и WSL — только просмотр; `.mcp.json` и `.claude/settings.json` здесь не правятся [1]. Комментарии к строкам — с 2026-10-01 [3]. Правый клик по пути: приложить к контексту, открыть в VS Code, Cursor или Zed, показать в Finder или Explorer, скопировать путь [1].
- **Side chat.** Cmd+; или `/btw`. Побочный разговор: читает контекст сессии, ничего не пишет обратно и не сохраняется на диск [1].
- **Background tasks.** Pane с subagents, фоновыми shell-командами и workflows [1]; с 2026-06-16 — и с dev-серверами [3].
- **Жизненный цикл сессии.** Переименование и архив; авто-архив после merge или закрытия PR [1]. Worktree сессии удаляется примерно через 30 дней после архива или последнего открытия. Кнопка Archive anyway выбрасывает незакоммиченную работу [1]. Настройки хранения и `/storage` — 2026-10-20; rewind в cloud-сессиях — 2026-08-13 [3].
- **Уведомления.** Уведомление ОС, если сессия закончила, пока её не видно [1]. Push на телефон — через Remote Control или Dispatch [1][21].
- **Прочее.** Output styles — с 2026-09-02; чтение AGENTS.md — с 2026-09-21 [3].
- **Чего нет в Desktop.** Inline-автодополнения кода, agent teams и диалоговых команд CLI вроде `/permissions` [1].

### Environments

- **Saved environments.** Кнопка Save as environment — с 2026-10-15 [3]. Desktop сам создаёт до восьми сохранённых environments из папок, использованных за последний месяц [1].
- **Cloud-сессии.** Изолированная VM на сессию; трафик GitHub идёт через proxy [19]. Одна сессия может охватывать несколько репозиториев [1]. Смотреть их можно на claude.ai/code и в мобильном приложении [1]. Запуск — из веба, с телефона, из Desktop или командой `claude --cloud` [19]. Сессией можно поделиться с командой или публично [19].
- **SSH-сессии.** Удалённая машина: x86_64 или arm64, glibc 2.17+ или musl, SFTP, около 1 GB диска [1]. Поддержаны проверка host key, jump hosts и контейнеры через ProxyCommand [1]. С v2.31226.0 задача продолжает работать, пока Desktop отключён [1].
- **WSL 2.** Параллельные сессии, side chats, diff, статус PR, worktrees. Plugins нет, files pane — только просмотр; terminal и connectors ещё раскатываются [38].
- **Linux beta.** Без computer use, диктовки и пакетов для Fedora и RHEL [37]. Пакет .deb — с 2026-06-30, автообновление через apt — с 2026-07-07 [3].

### Права и одобрения

- **Пять режимов** [1]: Manual; Accept edits; Plan; Auto — каждый запрос решает классификатор-модель; Bypass permissions — то же, что флаг `--dangerously-skip-permissions`.
- **Режим по умолчанию — источники расходятся.** Docs Desktop называют Manual [1]. Блог Anthropic пишет, что Auto стал режимом по умолчанию для новых сессий Pro, Max и Team с 2026-08-14. Обновление от 2026-10-22 объявило, что со следующей недели Auto станет режимом по умолчанию и в большинстве приложений Claude на этих планах [59].
- Bypass сначала нужно разрешить: в настройках на Pro, Max и Ultra или политикой организации на Team и Enterprise [1]. В cloud-сессиях есть только Accept edits, Plan и Auto [1].
- Режим запоминается по папке. Админ может запретить Auto и Bypass [1]. Auto требует Opus 4.6+, Sonnet 4.6+, Haiku 5.5 или Fable [1]; Fable страница цен называет лучшей моделью Anthropic [42].
- Запросы прав показываются прямо в разговоре [3]. Инструменты connectors с пометкой Needs approval спрашивают в любом режиме (2026-11-12) [3].
- У каждой scheduled task — свой режим прав и свой список Always allowed [13].

### Worktree, diff и review

- **Worktree.** Переключатель Worktree на каждую сессию, по умолчанию выключен [1]. Настраиваются место (по умолчанию `<project-root>/.claude/worktrees/`) и branch prefix. Файл `.worktreeinclude` копирует в worktree нужные gitignored-файлы [1]. По changelog: прогресс создания с кнопкой Stop (2026-06-30), понятные имена веток (2026-07-07), worktree живёт до архива сессии (2026-09-29) [3]. Источники расходятся: docs на 2026-11-13 называют переключатель выключенным по умолчанию [1], а в середине октября пользователь не мог выключить автосоздание worktree [80].
- **Diff с комментариями.** Клик по числу изменений в карточке Changes открывает diff [1]. Наведение на строку даёт комментарий; Cmd/Ctrl+Enter отправляет все комментарии сразу, и Claude правит код [1].
- **`/code-review`** (любой план). Работает фоновым subagent [1][24]. Карточка Code review группирует находки по файлам. Кнопки: Walk through in diff, Fix this one, Dismiss, Apply fixes. Работает в local, SSH и WSL [1][24]. Флаги: `--fix`, `--comment` (inline-комментарии на GitHub или через glab на GitLab), `--max-findings`, уровни effort [24].
- **Ultrareview** (`/code-review ultra`). Набор облачных reviewer-агентов; каждую находку отдельно воспроизводят и проверяют [25]. Review идёт 5–15 минут; по умолчанию до 500 файлов и 8 000 изменённых строк в ветке [25]. С v2.1.227 может опубликовать находки одним обычным комментарием в PR от аккаунта пользователя [25]. Команда `claude ultrareview` работает из CI и скриптов, exit codes 0, 1 и 130 [25]. Три запуска бесплатно, дальше около $5–25 за review из usage credits — оплачиваемого расхода сверх лимита плана [25].
- **Managed Code Review** (Team и Enterprise; GitHub, включая GitHub Enterprise Server) [26]:
  - работает через Claude GitHub App на инфраструктуре Anthropic;
  - несколько агентов параллельно, затем проверка находок, удаление дублей и ранжирование по важности;
  - выдаёт inline-комментарии, сводку и check run «Claude Code Review», который никогда не падает; PR не одобряет и не блокирует;
  - запускается при открытии PR, после каждого push или по `@claude review`; читает `REVIEW.md` из базовой ветки; уровни Quick, Standard, Deep;
  - доступ к репозиторию — только на чтение; код не собирает и не запускает;
  - недоступен с Zero Data Retention, конфигурацией HIPAA и ключами шифрования клиента.
  - Цена — по токенам, в среднем $15–25 за review [50].

### PR, CI и merge

- **PR в карточке Changes** со статусами CI [1]. Управление PR переехало туда 2026-10-15 [3]. Нужен установленный и залогиненный `gh` CLI [1].
- **Auto-fix.** Claude чинит упавший CI [1]. В локальных сессиях он ещё отвечает на новые review-комментарии владельца репозитория, членов организации, collaborators и GitHub Apps [1].
- **Merge when ready.** Включает auto-merge GitHub. Делает squash, если в репозитории нет merge queue. Auto-merge должен быть разрешён в репозитории. В SSH и WSL недоступно [1].
- **Авто-архив** сессии после merge или закрытия PR [1].
- **Cloud Auto-fix** (нужен Claude GitHub App). Чинит CI и отвечает на review-комментарии; при неясном комментарии спрашивает [19]. Отвечает на GitHub от аккаунта пользователя с пометкой Claude Code [19]. На merge-конфликты не реагирует: GitHub не присылает для них webhook [19].
- **Кнопки на карточках threads в Projects:** Resolve conflicts, Fix CI, Address comments, Merge it, Review PR, Create PR [12].
- **Хостинги кода.** Функции PR — только для GitHub; GitHub Enterprise Server — на Team и Enterprise [19]. Репозитории GitLab и Bitbucket можно взять в cloud-сессию, но push обратно нельзя [19].

### Лимиты и работа без присмотра

- **Auto-continue после 5-часового лимита.** На карточке лимита сессии есть флажок «Auto-continue when limits reset». С ним Desktop после сброса повторяет прерванный turn и показывает время повтора на карточке [7]. Флажок включён по умолчанию с v1.32352.0 (2026-08-17) [3].
  - Когда флажок появился — не подтверждено. По одному сбору заметок он старше 2026-06-05, когда начинается changelog [3]. Пользователи заметили опцию в macOS-приложении 2026-08-15 [75].
  - На карточке недельного лимита такого флажка нет [7].
  - Сообщения, набранные на лимите, встают в очередь (2026-09-04) и уходят сами при сбросе (2026-09-08) [3]. С 2026-10-13 после сброса продолжают и сессии с фоновыми агентами [3].
  - В CLI своя настройка [7]: не больше трёх автопродолжений подряд, и сбросы дальше 24 часов он не ждёт [8].
- **Workflows ждут сброса** с ограничениями: приложение открыто, сессия локальная во вкладке Code, сброс ближе 24 часов, run ждал меньше двух раз [11].
- **Projects** ждут и 5-часовой, и недельный лимит и по умолчанию продолжают сами [12].
- **Ultra** — без 5-часового лимита для подтверждённых аккаунтов [42].
- **Компьютер не засыпает.** Настройки keep-awake — пока Claude работает, от батареи, для отдельной сессии — с 2026-09-04 [3]. Продолжение после сна — с 2026-08-04 [3].
- **Показ расхода.** Usage ring открывает расход плана, общий для всех поверхностей Claude Code [1]. Карточка Context показывает заполненность context window [1]. Есть команды `/usage` и `/usage-credits` [7]. Отдельные сообщения для лимитов сессии (5 часов), недели, только Opus и только Sonnet — каждое со временем сброса. Предупреждение — на 85% лимита сессии [7].
- **Повторы ошибок.** До 10 автоматических повторов с exponential backoff, до 15 через `CLAUDE_CODE_MAX_RETRIES` [7]. Для работы без присмотра есть `CLAUDE_CODE_RETRY_WATCHDOG=1` (v2.1.186+): бесконечные повторы HTTP 429 и 529; с v2.1.199 он ещё поднимает предел повторов прочих временных ошибок до 300 [7][10]. При перегрузке API (HTTP 529) Desktop предлагает перейти с Opus на Sonnet [7].
- **`/goal`.** Условие завершения до 4 000 символов; после каждого turn его проверяет маленькая модель [15]. На лимите `/goal` ставит работу на паузу и продолжает через auto-continue. Временные ошибки повторяет 3 раза; в простое проверяет состояние каждые 30 минут с backoff [15].
- **Cowork** (не вкладка Code): scheduled tasks повторяются через 5, 15 и 30 минут, если модель недоступна (2026-09-04) [3].
- **Планирование под лимиты.** Ближе всего — подсказка о размере workflow: предупреждение Large workflow выше 25 агентов или 1,5 млн токенов [11].

### Автоматизация и несколько агентов

- **Desktop scheduled tasks** (локальные; Desktop 1.1.5368+) [13]:
  - срабатывают, только пока приложение открыто и компьютер не спит; срок проверяется раз в минуту с фиксированной задержкой на задачу;
  - расписание: Hourly, Daily, Weekdays, Weekly, Manual или cron; в форме минимум час, а сам Claude может поставить запуск раз в минуту или разовый;
  - по желанию — свой worktree на каждый запуск;
  - пропуски: один догоняющий запуск за последний пропуск в пределах 7 дней и уведомление;
  - опции Keep computer awake, режим прав и список Always allowed; история с причинами пропуска; Run now; Active/Paused;
  - prompt лежит в `~/.claude/scheduled-tasks/<task-name>/SKILL.md`.
  - Статусы запуска с 2026-11-10: Last run failed, Needs input, Didn't run, Waiting for its previous run to finish [3].
- **Cloud scheduled tasks** (бывшие Routines; research preview) [14]:
  - триггеры — расписание, вызов API (`/fire`) и события GitHub (PR, release, issue) с фильтрами PR;
  - по умолчанию режим Auto;
  - лимиты: 100 плановых запусков в час на аккаунт, 30 в час на задачу для Run now и API, интервал не меньше часа.
- **Dynamic workflows.** Скрипты на JavaScript с `agent()`, `pipeline()`, `parallel()` и `phase()` запускают subagents [11]. Desktop спрашивает одобрение — Once, Always или Deny — и показывает прогресс в Background tasks [11]. По умолчанию 16 агентов одновременно (настраивается от 1 до 256), до 1 000 агентов на run [11]. Зависший агент перезапускается до 5 раз; run можно возобновить [11]. В комплекте — `/deep-research` [11].
- **`/batch`.** Запускает 5–30 subagents, у каждого свой worktree [16].
- **Projects** (public beta; Pro, Max, Ultra; веб, desktop и телефон) [12]:
  - coordinator — координирующий разговор — запускает threads: рабочие cloud-сессии или сессии на компьютере пользователя через Remote Control «Work locally» (v2.1.280+, worktree по желанию);
  - pane Overview группирует threads: Ready for review, Waiting on you, Working, Landing, Idle, Resolved; thread без активности неделю закрывается сам;
  - threads работают в режиме Auto и следят за своими PR с включённым Auto-fix;
  - у проекта есть файл памяти MEMORY.md, инструкции до 16 000 символов, Library файлов и scheduled tasks;
  - модель и effort задаются отдельно для coordinator и для threads; кнопки Pause, Restart, Archive, Delete;
  - лимиты: 500 новых threads в день; загрузки — 1 000 файлов и 2 GB, 480 MB на файл, 10 папок;
  - только GitHub; проект принадлежит одному пользователю, поделиться им нельзя.
  - Пост о запуске (2026-09-17) обещал локальные threads очень скоро, а Team и Enterprise — позже [60].
- **Suggested tasks.** Claude предлагает побочные задачи карточками с кнопками Start, Do it here, Options, Start all [1]. В облаке такие предложения — с 2026-08-27 [3].
- **Nested sessions** (2026-10-15). Дочерняя сессия видна под родительской и отчитывается ей. Настройка решает, что делать с просьбой, не связанной с текущей задачей [3]. С 2026-11-12 в режиме Auto сессия, которую запустил Claude, сама запускает новые без одобрения: до 10 на одно сообщение пользователя и до 5 одновременно [3].
- **Сообщения между сессиями.** Claude перечисляет, читает, пишет, переименовывает и архивирует другие сессии Desktop: local, SSH, WSL; cloud и CLI — нет [1]. По умолчанию видит 20 последних; сообщения приходят карточками [1]. Архив чужой сессии требует одобрения, кроме режимов Auto и Bypass [1]. Реализация — инструменты ListAgents и SendMessage: локальный сокет, а между машинами — через Remote Control (v2.1.224+) [22]. Отправитель может попросить уведомить его, когда получатель освободится, — на срок до 12 часов. Входящие сообщения принимаются, откладываются или отклоняются по политике [22].
- **Agent teams** (команды агентов) — только в CLI [1]. **Agent view** (`claude agents`) — вид агентов в CLI, research preview [17].

## Принципы и подходы

### Философия

- **Модель — это продукт, harness тонкий.** Harness — обвязка вокруг модели: инструменты и управление контекстом [31].
  - Boris Cherny в 2025 году сравнил Claude Code с Unix-утилитой и назвал его самой тонкой обёрткой над моделью. Принцип команды — сначала делать простое; память сделали markdown-файлом, который читается в контекст [144].
  - В марте 2026 он сказал: модель — это продукт, продукт — это модель [141].
  - Команда удаляет код при каждом новом релизе модели и выбирает самый простой вариант. Около 90% кода Claude Code написано самим Claude Code (вторичный источник) [146].
  - В октябре 2026 системный prompt для сильных моделей сократили больше чем на 80%: skills и инструменты грузятся только по необходимости [61].
  - Страница доклада AI Engineer 2025 описывает продукт как намеренно маленький и без навязанных мнений. Это формулировки страницы, а не проверенные цитаты [145]. Выпуску YC Light Cone приписывают мысль, что команда строит продукт под модель, которая выйдет через полгода (не подтверждено) [139].
- **Один движок — много поверхностей.** Цикл агента одинаков в терминале, desktop, IDE, вебе, Remote Control, Slack и CI; меняется только интерфейс [31]. Desktop и CLI делят CLAUDE.md, MCP-серверы, hooks, skills и настройки [1]. Desktop — для параллельных сессий, раскладки panes и визуального review; CLI — для скриптов и автоматизации [1].
- **Человек задаёт направление и проверяет.** Страница продукта: пользователь задаёт направление как архитектор и оркестратор, а работу делает Claude [41]. Redesign 2026-04-14: в работе много задач, пользователь их координирует [54]. Projects: поручать работу Claude, как руководителю аппарата (chief of staff) [60]. Cat Wu: проектируют под экспоненциальный рост моделей; следующий большой шаг — проактивность, когда Claude сам настраивает автоматизации; о конкурентах, по её словам, не думают (вторичный источник) [142]. Конференция Code w/ Claude 2026 шла под темой «Building on the AI exponential» [56].
- **Агент сам проверяет свою работу.**
  - Auto-verify включён по умолчанию: скриншоты и проверка ошибок до конца ответа [1]. Review — второй взгляд до того, как код уйдёт с машины [49].
  - Совет Anthropic для долгих агентов: initializer-сессия, файл прогресса, защищённый список функций, одна функция на сессию, описательные коммиты, тестирование так, как это делал бы человек; каждая сессия заканчивается в состоянии, готовом к merge [45].
  - Dynamic workflows отвечают на три сбоя одного длинного контекста: agentic laziness (агент бросает работу раньше времени), self-preferential bias (предпочитает собственные решения) и goal drift (уход от цели). Ответ — отдельные subagents, adversarial verification, турниры, изоляция агентов, которые читают недоверенный ввод, и отдельный проход-скептик. Сравнительная оценка надёжнее абсолютной; параллельность должна окупать затраты на координацию [58].
- **Автономия через классификатор, а не одобрения человека.** Auto mode (2026-03-24) снижает риск по сравнению с `--dangerously-skip-permissions`, но не убирает его [52]. Данные Anthropic (2026-08-07) [59]:
  - пользователи одобряют 97% запросов прав; отклоняют 39% планов и только 3% отдельных запросов;
  - 25% интерактивных сессий стартуют в Bypass;
  - на 1 053 тестировщиках человек поймал 13,6% опасных команд, Auto mode — 89%;
  - нежелательные действия — в 6,3% сессий с ручным одобрением против 2,4% с Auto;
  - команды Team и Enterprise с Auto делают примерно на 25% больше PR.
  - Обязательные правила Anthropic советует держать в hooks, deny rules и managed settings, а не в CLAUDE.md [32].
- **Быстрые релизы и работа на себе.** В 2025 году — 60–100 внутренних релизов в день и 20 прототипов списка задач примерно за два дня (вторичный источник) [146]. Cherny сказал, что с ноября не написал сам ни строчки кода, и предсказал, что к концу 2026 разработка ПО будет в основном автоматизирована [141]. Код на инженера Anthropic вырос на 200% за год (март 2026) [50]. Computer use выпустили рано, чтобы узнать, где он работает [51]. Desktop выпустил 81 релиз за пять месяцев [3].

### Ключевые понятия

- **Session** — разговор со своей историей и папкой проекта [1].
- **Environment** — где работает сессия: Local, Cloud, SSH или WSL. Saved environment хранит папки и настройки worktree и ветки [1][3].
- **Worktree** — git-изоляция сессии в `.claude/worktrees/` [1].
- **Permission modes** — Manual, Accept edits, Plan, Auto, Bypass [1].
- **Session rail, panes, side chat, Changes card, Code review card** — элементы окна сессии [1][3].
- **Suggested tasks и nested sessions** — побочные задачи, которые Claude предлагает и запускает как дочерние сессии [1][3].
- **Remote Control, Dispatch, cloud session** — работа с телефона и в облаке [1][21][51].
- **Scheduled tasks** — локальные (пока приложение открыто) и облачные (бывшие Routines) [13][14].
- **Projects** — coordinator, threads, pane Overview и общая память [12][60].
- **Dynamic workflows и Ultracode** — скрипты, которые запускают много subagents, и режим, где Claude сам решает, когда писать такой скрипт [11][57][58].
- **Auto-continue и Keep awake** — продолжение после сброса лимита и запрет сна компьютера [3][8].

### Чем подход отличается (синтез по источникам)

- **Один вендор владеет моделью, harness, облаком и подпиской.** Отсюда ожидание сброса лимита плана [8], облако без платы за compute [1] и бесплатные для пользователя токены классификатора Auto на потребительских планах [59].
- **Координацию берёт на себя сам Claude:** Projects [60], nested sessions [3], workflows, которые Claude пишет сам [58], самозапуск сессий в Auto с 2026-11-12 [3]. Во всех способах параллельной работы исполнители — сессии Claude [16].
- **Долгая работа — сначала в облаке.** Threads Projects идут в облаке; локальные — через Remote Control и только пока компьютер не спит [12][60].
- **Агент управляет самим приложением:** сессиями, PR, sidebar, окнами [1][O].
- **Уклон в enterprise и удалённую разработку.** В changelog с июня по ноябрь 2026 больше всего записей у раздела 3P — 560, из них 184 «Added»; у раздела Code — 349, из них 54 «Added»; 87 записей Code упоминают SSH [3]. 3P — сборка Claude Desktop через Bedrock, Google Cloud Agent Platform, Microsoft Foundry или gateway для регулируемых клиентов и требований к месту хранения данных [39].
- **Работу без присмотра ограничивают намеренно:** 3 автопродолжения подряд [8], 2 ожидания на workflow run [11], 10 и 5 сессий при самозапуске [3], запрет dev-серверов для безнадзорных запусков [3].

## Как это устроено внутри

### Архитектура

- Electron-приложение. С v1.49585.0 (2026-09-08) — Electron 44 и Chromium 152 [3]. По словам Felix Rieseberg, внутри есть также Rust, Swift и Go [103].
- Вкладка Code держит свою копию движка Claude Code. Desktop её скачивает и обновляет; версия может отличаться от `claude` в терминале [1]. v5.11492.2 несёт 2.1.321 [3].
- MCP-серверы Desktop грузит из `claude_desktop_config.json`; connectors claude.ai передаёт в Claude Code напрямую [1].
- Свои инструменты Desktop — in-process MCP-серверы. OpenTelemetry помечает их `tool_source=sdk_host_builtin_mcp`; `service.name` — `claude-code-desktop`; cloud-сессии, запущенные из Desktop, — `remote_desktop` [33]. Построен ли Desktop на публичном Agent SDK — не подтверждено.
- Встроенные серверы в сессии: `ccd_session`, `ccd_turn`, `ccd_session_mgmt`, `ccd_pr`, `ccd_host`, `ccd_sidebar`, `ccd_view`, `ccd_window`, `ccd_directory`, `ccd_connectors`, `ccd_settings`, а также `Claude_Browser`, `Claude_Code_iOS_Simulator`, `computer-use`, `terminal`, `scheduled-tasks`, `ReportFindings`, `Artifact` [O]. Полные определения прочитаны только для `ccd_turn` и части `ccd_session`; что делают остальные сверх названия — не подтверждено [O].
- Redesign 2026-04-14 перестроил приложение ради скорости и потоковых ответов, добавил preview HTML и PDF [54].

### Цикл агента и планирование

- Цикл: собрать контекст, сделать действие, проверить — и снова. Harness даёт инструменты и ведёт контекст [31].
- Stop прерывает работу сразу. Сообщение, набранное во время работы, читается после текущего действия [1]. Очередь сообщений переживает сбой и выход из приложения (v3.1623.0 от 2026-10-20, v4.29.0 от 2026-10-27) [3].
- **План turn.** `update_plan` держит список задач под последним сообщением. Запрос помечается как первая задача, продолжение или новая задача. Новая задача начинается с предложения отдельной сессии [O].
- **Закрытие turn.** `wrap_up` рисует блок: итог, не больше одного вопроса и не больше двух кнопок; кнопки бывают действиями приложения [O]. Блок вышел в v2.42304.0 (2026-10-15) [3]. Пользовательский отчёт подтверждает, что его рисует `wrap_up` [97].
- **Деление на сессии.** `start_session` помечает предложение как собственную инициативу Claude или как offer [O][98]. `dismiss_task` отзывает устаревшее предложение [O]. `hand_off_to_session` делает fork разговора вместе с оставшимся планом в новую сессию. В worktree новая сессия получает свежий worktree от вершины ветки; незакоммиченные правки остаются в старой [O].
- **Другие способы планирования.** Plan mode с inline-комментариями к плану [1][27]. `/goal` — модель-оценщик после каждого turn [15]. С Ultracode Claude сам решает, нужен ли workflow. Один запрос может стать несколькими workflows (понять, изменить, проверить), и это расходует больше токенов [11]. В Projects coordinator делит цель на threads [12].

### Параллельность и координация

- **Сессии** работают рядом в split view или в отдельных окнах [1]. Nested sessions отчитываются родителю; самозапуск в Auto — до 10 на сообщение пользователя и 5 одновременно [3]. Пользовательский отчёт: конец turn дочерней сессии будит родителя, а каждая nested session поднимает свой набор MCP-серверов [98].
- **Слой сообщений** (ListAgents, SendMessage) [22]:
  - на одной машине — сокет на сессию (macOS, Linux) или named pipe (Windows), без серверов Anthropic;
  - на другую машину пользователя — через серверы Anthropic по её Remote Control; в cloud-сессии — тоже через серверы Anthropic;
  - получатель выбирает accept, hold или refuse (`crossSessionInbound`);
  - лимиты: до 100 отложенных сообщений (старые выбрасываются), до 50 принятых в очереди, лимит частоты на отправителя, одинаковые повторы выбрасываются, около 1 млн символов на сообщение внутри одной машины; подписка «сообщи, когда освободится» живёт 12 часов;
  - `isolatePeerMachines` требует одобрения пользователя, прежде чем сообщение уйдёт с машины.
  - Источники расходятся: docs Desktop пишут, что Claude не достаёт до cloud-сессий и сессий CLI [1]; docs по сообщениям описывают доставку в cloud-сессии [22].
  - Сообщение занятой сессии доставляется после её текущей работы [1].
  - Сессия вкладки Code ставит SendMessage на паузу после серии отправок без сообщения пользователя и ждёт, пока тот напишет. Предел был 10: так пишут пользовательский отчёт [99] и CHANGELOG CLI. Claude Code 2.1.321 поднял его до 20 (в Desktop — с v4.23118.1 от 2026-11-09), а 2.1.323 от 2026-11-12 — до 100 000. В Desktop версия 2.1.323 на 2026-11-13 ещё не вошла [4][3].
- **Workflows** [11]. У скрипта нет файловой системы, shell и `import()`. По умолчанию 16 агентов одновременно (1–256), 4 096 элементов на вызов, 1 000 агентов на run. Агенты с общим началом prompt стартуют с задержкой до 5 секунд после первого, чтобы переиспользовать его prompt cache. Карточка одобрения показывает имя workflow, его фазы и предупреждение о токенах. Prompts, вычисленные скриптом, помечены, чтобы классификатор Auto не принял их за просьбы пользователя.
- **Subagents** — до 20 одновременно по умолчанию [18].
- **Projects** [12]. Thread стартует с инструкциями проекта (до 16 000 символов), индексом памяти проекта, CLAUDE.md каждого репозитория и connectors проекта. Лимиты, о которых пользователь просит Claude, — только пожелания. Принудительный лимит один — 500 новых threads в день. Pause Project (v1.24012.0, 2026-07-21) останавливает coordinator и запуск новых сессий [3].

### Изоляция

- **Worktree** [23]:
  - четыре проверки, пока сессия изолирована в worktree (они действуют и на её subagents): правки main checkout запрещены; команды нельзя запускать изнутри main checkout; git-перенаправления в него заблокированы; блокируются команды, чьё использование git нельзя проверить по их тексту. Про последнюю docs прямо пишут, что её нельзя выключить; способа выключить остальные docs не описывают;
  - `cp` и shell-перенаправление в main checkout эти проверки не ловят;
  - конфигурацию проекта (settings, hooks, skills, agents, `.mcp.json`) сессия читает из main checkout, а CLAUDE.md и rules — из worktree; так стало в v2.16120.0 (2026-09-29) [3];
  - одобрения прав сохраняются в `settings.local.json` main checkout;
  - пока агент работает, держится `git worktree lock`.
  - Источники расходятся: docs описывают worktree на каждую сессию [1]. Пользователи сообщают о пуле worktrees: новая сессия попадает в каталог старой, а каталог сессии на паузе тихо переключается на чужую ветку (20 👍, открыт) [79].
- **Cloud** [19][20]. Одна изолированная VM на сессию. Сеть — None, Limited или Full; GitHub — через отдельный proxy. Git credentials, ключи подписи и секреты остаются вне sandbox; их подставляет proxy. Около 4 vCPU, 16 GB RAM и 30 GB диска. Простаивающая VM ставится на паузу и может быть освобождена: разговор восстанавливается, а фоновая работа — нет.
- **SSH** [1]:
  - helper и Claude Code ставятся в `~/.claude/remote/`; helper не слушает сетевой порт;
  - при отключённом Desktop задача идёт, вывод копится в буфере 16 MiB; на хостах Linux и macOS helper останавливается, если Desktop не подключался 30 дней;
  - правки в worktree ждут около 30 секунд и падают — кроме хостов Linux и macOS, где проверка правок работает без Desktop; вызовы connectors падают через ~30 секунд; новый workflow ждёт проверки Desktop до 10 минут; одобрения и вопросы ждут без срока;
  - вход продлевается только при подключённом Desktop, поэтому ночная задача может остановиться;
  - перезапуск для обновления ждёт SSH-задачу; через 72 часа может пройти, если Desktop сумеет снова подключиться к задаче;
  - если процесс задачи пропал, Desktop запускает новый из сохранённой истории;
  - Merge when ready и auto-verify в SSH недоступны.
  - Источники расходятся: пользовательский issue (открыт с апреля) — SSH-сессии умирали при отключении клиента [90]; docs — задачи переживают сон и отключение в описанных пределах [1].
- **Local.** Bash sandbox — Seatbelt на macOS, bubblewrap и socat на Linux и WSL2 [29]. Браузер — чистый профиль; классификаторы проверяют действия записи на внешних сайтах в любом режиме; локальные dev-серверы одобрения не требуют [1]. Безнадзорные запуски не могут стартовать dev-серверы в Browser (v1.28929.0, 2026-08-11) [3]. iOS Simulator — только в local-сессиях [36].

### Состояние, память, контекст

- Transcripts — файлы JSONL в `~/.claude/projects`. Перед каждой правкой делается checkpoint файла. Сессию можно продолжить или сделать fork [31].
- Transcripts Desktop хранятся бессрочно, если не задан `desktopSessionCleanupPeriodDays` [30][9]. Удаление сессии удаляет и transcript (v2.9939.2, 2026-09-24) [3].
- Scheduled tasks лежат в `~/.claude/scheduled-tasks/<name>/SKILL.md` [13]. Локальные переменные окружения хранятся зашифрованными [1]. Режим прав запоминается по папке отдельно для компьютера, SSH-хоста и дистрибутива WSL (v3.6556.1, 2026-10-22) [3].
- Память: CLAUDE.md, CLAUDE.local.md, а AGENTS.md — запасной вариант [3][31]. Auto memory грузит первые 200 строк или 25 KB файла `MEMORY.md` [31].
- Контекст сжимается сам при заполнении или по `/compact`; расход виден на карточке Context и в `/context` [1]. Idle compaction — после примерно часа простоя, от 200k токенов, при 1-часовом времени жизни кэша [9]. Threads Projects сжимаются сами; coordinator работает по последним сообщениям, последним threads и памяти проекта [12].

### Проверка качества

- **Auto-verify** включён по умолчанию. Claude стартует dev-сервер, делает скриншоты, смотрит структуру страницы, кликает и заполняет формы. Настройка — в `.claude/launch.json`; `"autoVerify": false` выключает проверку [1].
- **`/code-review`** — фоновый fork-subagent. Находки идут в карточку через инструмент `ReportFindings`, по умолчанию до 32. После правок каждая находка получает статус fixed, skipped или no change needed [24][1][O].
- **Ultrareview** — облачные reviewers воспроизводят каждую находку независимо [25].
- **`/goal`** — маленькая быстрая модель после каждого turn решает: выполнено, ещё нет или невозможно. Цикл останавливается после нескольких turns без вызова инструментов [15].
- **PR.** Карточка Changes показывает CI [1]. Как локальный мониторинг PR узнаёт об изменениях — не подтверждено. Cloud Auto-fix работает по webhooks Claude GitHub App: понятные правки делает сам, о неясных комментариях спрашивает [19].
- **Hooks и gate.** События `Stop`, `SubagentStop` и `PermissionRequest` есть [28]. Детерминированного вердикта проверки на уровне проекта в docs Desktop не найдено [1][28].

### Восстановление после сбоев

- **Движок** [7][10]. До 10 повторов с backoff. Повторяются: 5xx и 529 до начала стрима, оборванные соединения, один зависший стрим, 429 (кроме лимита трат), переполнение контекста (с меньшим `max_tokens`), испорченные вызовы инструментов. Сбой посреди ответа после завершённого блока сохраняет частичный ответ и продолжает работу [7]. Упавший subagent возвращает ошибку раннего завершения или частичный результат [7][18].
- **Workflow replay** [11]. `Date.now()` и `Math.random()` в скрипте бросают исключение, поэтому перезапуск повторяет те же вызовы. Завершённые агенты возвращают сохранённый результат; заново идут первый изменённый или упавший агент и все после него. Зависший агент — до 5 перезапусков; вывод, не прошедший проверку схемы, — 5 повторов. Агентов, упавших на лимите, перезапускают повторным запуском workflow (v2.1.318+).
- **Desktop** [3]:
  - продолжение после сна с баннером и вариантом продолжить в облаке (v1.25927.0);
  - карточки Try again переживают перезапуск (v1.26832.0);
  - remote MCP-серверы переподключаются (v1.37937.1);
  - сессия, застрявшая на старой версии CLI, продолжает на текущей (v2.16120.0);
  - пропавшую папку возвращают через fork сессии (v1.18286.0);
  - установка SSH повторяется, если сервер загрузки Anthropic занят (v4.4212.0, 2026-10-29).
- **Projects.** Если облачный sandbox на паузе не возобновляется, thread продолжает со свежего clone, и незакоммиченная работа может пропасть [12].

**Ожидание сброса в одной сессии** — правила движка, v2.1.234+ [8]:

- При сбросе движок просит Claude продолжить с места остановки. Последнее сообщение пользователя заново не отправляется.
- Если машина спала дольше ~30 минут и сброс пришёлся на сон, нужен Enter от человека.
- После 3 автопродолжений подряд движок останавливается и ждёт решения пользователя. Счётчик обнуляет prompt человека. Тот же предел — у `/goal` и у scheduled tasks внутри сессии.
- Сам не стартует, если сброс дальше 24 часов (так у большинства недельных лимитов), в сессиях Remote Control, у teammates в agent teams и при лимите семейства Opus или Sonnet, когда выбрана модель другого семейства.
- Не предлагается вовсе в фоновых сессиях, в `-p`, при оплате по API-ключу или через облачного провайдера, при usage-based billing и за gateway без сохранённого входа claude.ai.
- Ожидание отменяется при выходе, смене аккаунта, clear, rewind, `/resume`, `/restart`, переносе в Desktop, в фон или в облако, при выключении настройки и если hook `UserPromptSubmit` блокирует prompt продолжения.
- Запросы прав в продолженном turn остаются, поэтому задача без присмотра может на них встать.
- CLI показывает обратный отсчёт, Esc его отменяет. Выключается в `/config` или через `autoContinueAtUsageLimit=false`. Пользователи API-ключей не ждут [8].
- Настройка `autoContinueAtUsageLimit` по умолчанию `true` [7][9]. Читается только из user settings, `--settings` и managed settings. Если её задаёт только файл настроек проекта, она выключается [9]. Флажок Desktop отделён от этой настройки [7].
- v1.32885.1 (2026-08-18) ждёт время сброса, которое сообщает сервер, и шлёт понятное сообщение о продолжении [3].

**Ожидание в workflows** [11]. На лимите run ставится на паузу: агенты на лимите ждут, новые не стартуют, после сброса run продолжает. Условия:

- подписка claude.ai без usage-based billing;
- интерактивный терминал или локальная сессия Code — не SSH, WSL, Dispatch, scheduled task, не запуск из Remote Control или корпоративного launcher и не при выключенном необязательном трафике;
- включены и настройка, и флажок Desktop;
- сброс в пределах 24 часов;
- run ещё не ждал дважды; третье попадание на лимит роняет агента.
- Во вкладке Code run обещает продолжить, только если приложение открыто.
- Версии — источники расходятся: docs workflows называют v2.1.271 в терминале и v2.1.319 во вкладке Code [11]; CHANGELOG CLI относит паузу workflows во вкладке Code к 2.1.323 от 2026-11-12 [4][5]; Desktop от 2026-11-13 несёт 2.1.321 [3].

**Projects** [12]. Продолжение по умолчанию; переключатель — в Project settings > General. Выйти за лимит плана можно только с включёнными usage credits; thread сам включить их не может. Threads по умолчанию — Opus с высоким effort, coordinator — с низким. Простаивающие threads, которые следят за PR, просыпаются на падение CI или review-комментарий и тратят лимит.

**Retry watchdog** [10][7]. `CLAUDE_CODE_RETRY_WATCHDOG=1` повторяет 429 и 529 без предела. Backoff — до 5 минут или до времени сброса из ответа, так что сессия на лимите дожидается окна. На 429 о лимите трат или исчерпанных usage credits watchdog сразу сдаётся. Прочие временные ошибки — до 300 повторов, около 3 часов. `CLAUDE_CODE_RETRY_WATCHDOG_MAX_USAGE_LIMIT_WAIT_MS` (v2.1.301+) ограничивает ожидание лимита; `…_USAGE_LIMIT_RECHECK_MS` (v2.1.305+) задаёт, как часто проверять, снят ли лимит. Работает ли watchdog в локальных сессиях Desktop — не подтверждено: Desktop сам задаёт часть переменных (например, `API_TIMEOUT_MS`), а watchdog в этом списке нет [1].

**Scheduled.** Локальные tasks идут, только пока приложение открыто и компьютер не спит [13]. Cloud tasks расходуют обычные лимиты плана (v1.14271.0, 2026-06-18) [3]. На лимите их запуски отклоняются, если usage credits выключены; у каждого типа триггера — часовой предел [14].

**Контроль трат.** Модель, effort и fast mode на сессию [1][O]. Предупреждение Large workflow выше 25 агентов или 1,5 млн токенов и шкала размера small, medium, large [11]. Usage ring (v2.42304.0) [3] и предупреждение на 85% [7]. Планировщика работ под окно лимита не найдено [11][7].

### Права и безопасность

- Режим `dontAsk` есть только в CLI; в облаке нет Bypass [1].
- **Auto mode** [27][53]:
  - порядок решения: сначала безопасные инструменты из allowlist и правила пользователя, затем правки внутри проекта, затем классификатор;
  - широкие allow rules вроде `Bash(*)` и правила для интерпретаторов при включении Auto отбрасываются;
  - классификатор работает в две стадии: быстрый фильтр, а рассуждение chain-of-thought — только если фильтр что-то отметил;
  - он не видит сообщений самого Claude и вывода инструментов; отдельная серверная проверка ищет prompt injection в результатах инструментов;
  - модель классификатора по умолчанию — Sonnet 5; серверная проверка в Desktop требует Claude Code v2.1.281+ [27];
  - после 3 блоков подряд или 20 всего Claude Code возвращается к вопросам человеку [27];
  - замеры ошибок: 0,4% ложных срабатываний на 10 000 реальных вызовов; 17% пропусков на 52 реальных чрезмерно рьяных действиях; 5,7% пропусков на синтетической утечке данных [53].
- **Desktop** [1][3]: вопросы не истекают по времени; запросы прав — в разговоре (v2.42304.0); connectors с Needs approval спрашивают в любом режиме (v5.11492.0); API-ключи и токены маскируются в transcripts (v1.17377.1).
- **Remote Control** [21]: только исходящий HTTPS через polling; transcript хранится на серверах Anthropic, пока сессия подключена; Trusted Devices требуют вход не старше 18 часов и биометрию.
- **Админ** [1]: managed settings, профили MDM, реестр Windows, файл политики Linux.
- **Уязвимость preview pane.** Noma Labs нашла цепочку утечки файлов с оценкой CVSS 8.7. HTML-файл больше 256 KB в склонированном репозитории рендерился, когда пользователь просил Claude его проверить, без дополнительного запроса. Сообщено 2026-07-04. По хронологии Noma, исправление вышло 2026-08-17 в Desktop 1.30096.1 и новее; в changelog Desktop версия 1.30096.1 датирована 2026-08-13 [137][3]. На HN тема набрала 16 points [115].

### Что хвалят

- **GUI вместо вкладок терминала, когда сессий много.** Одно приложение вместо окна VS Code на каждый репозиторий; сворачиваемый вывод инструментов; изображения и браузер в сессии; перетаскивание PDF и картинок; fork разговора с любого места; scheduled tasks [123]. Работают копирование, undo и многострочный ввод [107]. Бывшие противники вкладки Code теперь предпочитают её CLI [121]. Часть пользователей вообще не открывает IDE: запускает Claude и Codex из нативных приложений, а diff смотрит на GitHub [121][119]. Много сессий вместе с Remote Control проще, чем окна терминала [108].
- **Удалённые машины.** SSH-машины добавляются легко и без задержки ввода; одна история сессий на ноутбуке, в облаке и на SSH-хостах; подключение с телефона [123]. Работа продолжается после закрытия ноутбука. Минус — на сервере нужен свой сервис для каждого проекта и один сервер на каталог [117]. Пользователь плана $20 собирает Android-приложения с телефона на VM [121].
- **Темп функций догнал сторонние оркестраторы.** После новости, что Conductor (Mac-приложение для параллельных агентов) переходит в Meta (2026-11-04, 222 points), комментатор написал: Conductor теперь почти не отличается от Claude Code Desktop, кроме поддержки нескольких harness и моделей [122]. Мультипровайдерные инструменты отстают; темп держит только T3 Code [122]. Бывшие пользователи Conductor и T3 Code вернулись к официальным приложениям [122][121].
- **Обзоры (вторичные).**
  - Very Good Ventures: статус сессий в sidebar, живой мониторинг параллельных reviewer subagents, разбор расхода контекста (виден лишний расход от MCP-серверов), терминал, side chat, PR. Итог — удобство, а не новые возможности по сравнению с CLI [130].
  - VentureBeat: sidebar, side chat, preview, редактор, быстрый diff. Прогноз: GUI станет стандартным местом для управления и review работы агентов, а CLI останется для исполнения [126].
  - Product Hunt: управление параллельными сессиями — функция, о которой пользователи не знали, что она им нужна. Открытый вопрос — как отследить, какая сессия что правила [129].
- **Работа сквозь лимиты.** Переписывание игры шло всю ночь через сбросы лимитов, затем — Project с coordinator; около 200 млн токенов Opus 5.5 за две недели, поверхность не названа [120]. Планы, которые раньше вставали ночью, теперь идут через dynamic workflows [108].

### Что ругают

- **Скорость, память, стабильность.**
  - Ранние отзывы: разговор грузится около секунды, новые задачи зависают на секунды, возврат в терминал через 10 минут (февраль) [104]; медленно и с ошибками (май) [106]; desktop-приложения Claude и Codex медленные, непредсказуемые, расходуют много памяти и меняются быстрее, чем стоит (июнь) [110].
  - Windows-приложение поднимало VM Hyper-V на 1,8 GB при каждом запуске, даже для одного чата: 434 points и 304 комментария на HN [109]. Issues про эту VM, про bundle Cowork на 10 GB (239 👍) и про фоновую службу Cowork открыты [87]. Кто-то из-за VM не стал ставить приложение [111].
  - Позже мнения смягчились: в сентябре современную версию назвали быстрой [113]. Boris Cherny сказал, что полгода назад приложение было медленным и ненадёжным, а теперь гораздо лучше. John Gruber возразил: у него 30 секунд до готовности, потом ошибка [135].
  - Закрытые баги: 36 GB RAM и падения после обновления; падение на огромном `.jsonl` сессии; kernel panic от нехватки памяти; macOS остановила приложение после 8,5 GB записи на диск за 11 минут [88].
  - Windows: окно всегда поверх остальных (291 👍) и отказ перезапуска из-за осиротевшего lock (208 комментариев) — закрыты 2026-10-23; ошибка запуска после падений и тормоза после обновления — открыты [86]. Падение GPU-процесса из-за вкладки браузера — 113 комментариев [85].
  - Выход из аккаунта примерно раз в неделю и потеря всех открытых окон — а это единственный способ следить за текущей работой [114].
- **Изменения UI без предупреждения.**
  - v2.37337.1 (2026-10-13/14) ввела environments и убрала группировку sidebar по папке — без анонса и без возможности отказаться [71]. Сессии десятков репозиториев смешались; около двух часов ручной перерегистрации 19 папок; команда на Team (16 мест, растёт до ~50) не могла работать; кому-то отказали в возврате денег. Обходы — просить Claude перестроить sidebar его же инструментами или писать plugins. Сотрудник команды desktop извинился 2026-10-16, вернул группировку по папке и закрыл issue 2026-10-19 [71]. По changelog environments появились 2026-10-15 [3] — источники расходятся в дате.
  - Блок следующего шага в конце turn (58 👍, 24 комментария, открыт) [72]: сжимает выбор до двух вариантов и прячет текст, который отправит кнопка; заменяет письменный отчёт в конце turn; убирает подсказки prompt; отвечает по-английски пользователю, который пишет по-японски; конфликтует с настройками accessibility. Единственный обход — правило в CLAUDE.md не использовать блок.
  - Убрана панель расхода с экрана новой сессии (97 👍, ещё два дубля) [73]. Заполненность контекста пропала из usage ring [91]. Кнопка по умолчанию стала Always allow вместо Allow once [74]. Убрана нижняя строка с номерами PR и текущим worktree [80]. На Windows развернули сортировку sidebar и сняли предел на группу без записи в release notes (вторичный источник) [133]. Тихое автообновление перезапускает приложение, пока пользователя нет, и рвёт все сессии Remote Control (17 👍) [90].
  - Пост «Goodbye Claude, hello Pi» (821 points на HN): автор ушёл к harness Pi из-за быстрых релизов без заботы о качестве и частой смены system prompt [136][123].
- **Worktrees и git.** Стало труднее выбирать ветку для worktree — автор ушёл в JetBrains ThinkRail [121]. Пул worktrees путает каталоги и ветки (20 👍, открыт); просят один worktree на сессию с удалением при архиве [79]. Просят показывать имя worktree (21 👍) и уважать свой branch prefix [80]. Просили diff против других веток, кроме main (143 👍, закрыт); фоновый `git fetch` нельзя выключить [81]. В diff не отображаются изображения; нет кнопок stage hunk, amend, rebase [130]. У Theo изменения не отрисовывались в diff [128].
- **PR, CI, Auto-fix.**
  - Хвалят ответы на review и проверку CI без захода на GitHub [130].
  - Надёжность [82]: общий переключатель Auto-fix не действовал на PR, созданные через `gh` (открыт с июня); чекбокс на Windows ничего не делал; следили только за первым PR сессии; на новых PR Auto-fix не включался. Просят сделать подпись «Addressed by Claude Code» необязательной и будить сессию, когда checks прошли [82].
  - Мониторинг PR расходовал личную квоту GitHub GraphQL — около 2 000 points на старт turn (исправлено 2026-08-24). Новая ошибка — около 5 000 запросов в час, исчерпывает оба лимита GitHub API (открыта) [83].
  - Только GitHub: на self-managed GitLab проверки CI падают; для Azure DevOps за сборками никто не следит, но правило, которое запрещает Claude самому опрашивать CI, действует [84]. Встроенную кнопку Create PR нельзя скрыть или заменить своим skill [130].
- **Browser pane.** Хвалят живой preview без отдельных окон браузера [126]. Жалобы [85]: запросы на действия повторяются после Always allow; `.local` и внутренние имена хостов нельзя сделать доверенными (39 👍); Allow all websites игнорировалось (34 👍, закрыт); не работают passkeys; pane уничтожается после 30 минут в скрытом виде; на Mac с 8 GB памяти её не хватало (закрыт); просили не открывать preview на каждую правку (22 👍, закрыт). Theo: preview тормозит [128].
- **Права и автономия.** Bypass не запоминается, приложение спрашивает снова [128]. На macOS Bypass не включается (65 комментариев, открыт); новая сессия спрашивает одобрение даже в Bypass; серверная проверка Auto иногда не даёт вердикта и блокирует Bash и плановые пробуждения (39 👍) [89]. На Windows Claude Code работает без sandbox — советуют VM [109]. Спрашивают, как вообще изолировать desktop-приложение; ответ — в облачных контейнерах это проще [123].
- **Сессии, окна, аккаунты, история.**
  - Несколько аккаунтов — самый популярный desktop-issue: 1 047 👍 и 244 комментария на 2026-11-13, открыт с января. Переключение — это выход и потеря контекста [68].
  - Списки сессий привязаны к аккаунту. Сообщество пишет утилиты, чтобы сливать и переносить их, в том числе чтобы чередовать аккаунты, когда один упёрся в недельный лимит [100][101].
  - Несколько окон — 274 👍, открыт; обход — второй экземпляр приложения и двойной расход памяти [69]. Нет вкладок — для части power users это причина не пользоваться [123].
  - История CLI и Desktop раздельная (157 👍) [70]. @-поиск файлов сломан [112].
  - Конкурент Nimbalyst (заинтересованная сторона): нет поиска по сессиям и долговечных метаданных, доски по репозиториям и веткам, многошаговых процессов, места для spec и заметок [134]. Mods сообщества добавляют закреплённые проекты с живыми статусами сессий [102].
  - В Projects просят локальные сессии как полноценные threads и полные вызовы инструментов и diff в виде thread [92].
- **Привязка к вендору и автоматизация.** Только модели Anthropic — неудобно тем, кто переключает модели, чтобы обойти rate limit [126]. TUI можно скриптовать, GUI — трудно [123]. Интеграция с GitHub по-разному работает в чате, во вкладке Code и в CLI [116]. Theo в апреле ругал отсутствие AGENTS.md и необходимость править `.gitignore` и конфиги Claude [128]; AGENTS.md поддерживается с 2026-09-21 [3].
- **Расход лимитов.** На запуске redesign: лимит заканчивался за ~30 минут, работа вставала посреди задачи; Codex доделывает работу на лимите и щедрее; на Max проблем нет [125]. Opus 4.7 на плане $20 — около двух сообщений [105]. Вторичный обзор пересказывает посты X о трате 5-часовой квоты за 4–8 минут (не подтверждено) [127]. Просят постоянно видимый расход (31 👍), вернуть индикатор контекста (33 👍) и панель расхода (97 👍) [91][73]. Индикатор контекста виден только при наведении [126]; ни Codex, ни Claude Code не показывают токены удобно [131]. Один пользователь хвалит показ расхода внизу окна [121].
- **Auto-continue.** Запрос «продолжать при лимите сессии»: 212 👍, 82 комментария, закрыт 2026-10-22 [75]; связанный запрос — 103 👍 [76]. До этого пользователи обходились сами: «continue» через tmux, скрипты восстановления, очереди на ночь, задача планировщика Windows с `claude --resume … -p` и пропуском проверок прав. Ещё один приём — крошечный запрос рано утром, чтобы 5-часовое окно сбрасывалось к началу рабочего дня [75][76]. Пробелы:
  - из ~11 параллельных сессий auto-continue предложила только первая; остальным нужен ручной Try again; сессия на паузе выглядит как завершённая (открыт, помечен stale) [77];
  - лимит остановил workflow из 4 агентов посреди работы, работа пропала; модель не видит остаток бюджета [78]. Позже workflows перестали перезапускать готовых агентов (2026-11-03) и стали ждать сброса во вкладке Code (2026-11-12) [4];
  - auto-continue не включается при подключённом Remote Control [94]; docs как раз исключают такие сессии из автоматического ожидания [8];
  - лишнее продолжение после уже возобновлённой сессии [95];
  - аккаунт заморожен после ночного безнадзорного запуска с `/goal`, workflows и auto-continue; причина не подтверждена [96];
  - nested sessions израсходовали недельный лимит примерно за день [98].

### С чем сравнивают

- **Codex app** — чаще всего. Приложения взаимозаменяемы, Codex чуть лучше создаёт проекты и сессии [121]. Catalin Pit выбирает Codex: просторнее, проще sidebar, plugins в 2 клика вместо 5 [131]. ## Слабые места и чего нет

- **Только Claude.** Модели и агенты одного вендора; Codex и другие агенты не поддерживаются; сторонние модели — только через сборку 3P или gateway [16][1][126].
- **Пробелы auto-continue:**
  - недельный лимит не покрыт: у его карточки нет флажка, а сбросы дальше 24 часов движок не ждёт [7][8];
  - не больше 3 продолжений подряд без человека [8];
  - приложение должно быть открыто [11]; после сна дольше ~30 минут нужен Enter [8];
  - workflows ждут максимум дважды и не ждут в SSH, WSL и scheduled tasks [11];
  - запросы прав в продолженном turn останавливают задачу [8]; SSH-задача встаёт, когда истекает вход [1];
  - по отчёту пользователя продолжает только одна сессия из многих [77].
- **Нет планирования под лимиты и аналога Eco mode.** Есть только выбор модели, effort, fast mode и предупреждение Large workflow [1][11].
- **Нет детерминированного gate проекта.** Проверки модельные (auto-verify, `/goal`, review) или собираются вручную через hooks [1][15][28].
- **Нет записи хода безнадзорной работы и сводки работы проекта по дням.** Есть transcripts, Background tasks, история scheduled tasks, Overview в Projects и OpenTelemetry [1][13][12][33].
- **Нет canvas.** Раскладка — sidebar, split view, panes и отдельные окна [1][54].
- **Нет работы над продуктом** — советника, Mind map, критика spec (не найдено; не подтверждено).
- **Браузер с одним чистым профилем;** несколько профилей не найдено [1].
- **Очистка скриншотов от личных данных не найдена** (не подтверждено). Маскируются только ключи и токены в transcripts [3].
- **PR-функции только для GitHub** и требуют `gh`; GitLab и Bitbucket — без push; мониторинг PR расходует квоту GitHub API [1][19][83][84].
- **Worktree выключен по умолчанию;** по отчётам пул worktrees путает каталоги и ветки [1][79].
- **Projects** — beta, сначала облако, только GitHub, без совместного доступа; Team и Enterprise — позже [12][60][92].
- **Почти нет командной работы:** сессии и проекты принадлежат одному человеку [12][19][34].
- **Нет нескольких аккаунтов, нескольких окон в одном экземпляре и вкладок** [68][69][123].
- **Стабильность и регрессии:** изменения UI без анонса и отката [71][72][73][133]; память и падения [88][86]; VM Hyper-V на Windows при каждом запуске [109][87]; тихие автообновления рвут Remote Control [90].
- **В Desktop нет agent teams и `-p`;** GUI трудно скриптовать [1][123].
- **Платформы:** Linux beta без computer use; в WSL нет plugins; на Windows нет sandbox (по пользователю) [37][38][109].
- **Безопасность preview:** уязвимость с утечкой файлов через рендер недоверенного HTML (CVSS 8.7, исправлена) [137].
- **Безнадзорная работа ограничена намеренно:** 10 и 5 сессий при самозапуске, пауза SendMessage после серии отправок без человека (10 по отчёту пользователя, 20 с Claude Code 2.1.321; 2.1.323 поднимает предел до 100 000), запрет dev-серверов для безнадзорных запусков [3][4][99].

## Механизмы, которые стоит изучить

1. **Auto-continue с жёсткими пределами.** Продолжение работы после сброса 5-часового лимита. Движок шлёт Claude служебную просьбу продолжить и не повторяет сообщение пользователя. Не больше 3 раз подряд, счётчик обнуляет prompt человека; сбросы дальше 24 часов не ждёт; после сна дольше ~30 минут ждёт Enter. Desktop добавляет флажок на карточке лимита, время повтора и очередь сообщений, которые уходят при сбросе. Источники: [8][7][3][9].
2. **Пауза workflow на лимите и детерминированный replay.** Run из многих агентов переживает лимит и перезапуск. На лимите агенты ждут, новые не стартуют; run ждёт не больше двух раз. `Date.now()` и `Math.random()` в скрипте запрещены, поэтому повтор даёт те же вызовы: готовые агенты отдают сохранённый результат, заново идёт первый изменённый или упавший агент и всё после него. Агенты с общим началом prompt стартуют с задержкой до 5 секунд ради общего prompt cache. Источник: [11].
3. **Retry watchdog.** Режим повторов для работы без присмотра. `CLAUDE_CODE_RETRY_WATCHDOG=1` (v2.1.186+) бесконечно повторяет 429 и 529 с backoff до 5 минут или до времени сброса из ответа сервера. На лимите трат сразу сдаётся; прочие временные ошибки — до 300 повторов (с v2.1.199). Потолок ожидания лимита и интервал перепроверки задаются отдельно. Источники: [10][7].
4. **Классификатор Auto mode.** Модель одобряет запросы прав вместо человека. Порядок: allowlist и правила пользователя, правки внутри проекта, затем классификатор; широкие allow rules отбрасываются. Две стадии: быстрый фильтр, а рассуждение — только по отмеченному. Классификатор не видит сообщений Claude и вывода инструментов. После 3 блоков подряд или 20 всего решения снова переходят к человеку. Доля ошибок опубликована. Источники: [27][53][59].
5. **Обязательные проверки worktree.** Агент в worktree не может править main checkout, запускать в нём команды, перенаправлять в него git и выполнять git-команды, которые нельзя проверить по тексту. Про последнюю проверку docs прямо пишут, что её нельзя выключить; способа выключить остальные docs не описывают. На время работы держится `git worktree lock`. В сессиях Desktop конфигурация берётся из main checkout, CLAUDE.md — из worktree. Известный пробел — `cp` и shell-перенаправление. Источники: [23][1].
6. **Слой сообщений между сессиями.** ListAgents и SendMessage; на одной машине — сокет или named pipe без серверов. Получатель выбирает accept, hold или refuse. Есть лимиты очередей и частоты, выброс одинаковых повторов и подписка «сообщи, когда освободится» на 12 часов. `isolatePeerMachines` требует одобрения перед отправкой за пределы машины. Источник: [22].
7. **Предохранители самозапуска.** В Auto сессия, запущенная Claude, запускает новые без одобрения, но не больше 10 на одно сообщение человека и 5 одновременно (v5.11492.0, 2026-11-12). SendMessage из сессии вкладки Code встаёт после серии отправок без человека: 10 по отчёту пользователя и CHANGELOG CLI, 20 с Claude Code 2.1.321; 2.1.323 от 2026-11-12 поднимает предел до 100 000, то есть почти снимает его. Безнадзорные запуски не стартуют dev-серверы (v1.28929.0, 2026-08-11). Источники: [3][4][99].
8. **Закрытие turn: список задач и блок следующего шага.** `update_plan` держит список задач и помечает запрос как первую задачу, продолжение или новую. `wrap_up` рисует итог, один вопрос и до двух кнопок с действиями приложения: commit, create PR, merge, fix CI и другие. Пользователи жалуются, что две кнопки сжимают выбор и прячут отправляемый текст. Источники: [O][3][97][72].
9. **Находки review как типизированный вызов инструмента.** `ReportFindings` передаёт до 32 находок в карточку с действиями; после правок каждая получает статус fixed, skipped или no change needed. Ultrareview воспроизводит каждую находку отдельно. Managed review проверяет находки, удаляет дубли, ранжирует их и ставит check run, который не падает. Источники: [24][1][O][25][26].
10. **Overview в Projects и пробуждение по PR.** Threads сгруппированы по статусам Ready for review, Waiting on you, Working, Landing, Idle, Resolved. Thread без активности неделю закрывается сам; простаивающий просыпается на падение CI или review-комментарий. Принудительный предел — 500 threads в день; пределы из просьб пользователя — только пожелания. Источник: [12].
11. **Догоняющий запуск и статусы scheduled tasks.** Срок проверяется раз в минуту. За пропуски — один догоняющий запуск за последний пропуск в пределах 7 дней и уведомление. Статусы: Last run failed, Needs input, Didn't run, Waiting for its previous run to finish; история хранит причины пропуска. Источники: [13][3].
12. **SSH helper, который переживает отключение.** Helper без сетевого порта ведёт задачу без Desktop, копит вывод в буфере 16 MiB, держит одобрения без срока, а при пропаже процесса Desktop запускает новый из сохранённой истории. Слабое место — вход продлевается только при подключённом Desktop. Источник: [1].
