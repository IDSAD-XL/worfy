## Модель работы

- **Развёртывание — local.** Всё работает на одной машине пользователя [7][29]:
  - CLI `gt` и CLI трекера задач `bd` (Beads);
  - tmux — в нём работает сессия каждого агента;
  - демон на Go, без LLM;
  - локальный SQL-сервер Dolt. Dolt — SQL-база с историей версий как в git. В ней хранятся задачи и состояние системы.
- Есть Docker Compose [42]. Официальной hosted-версии нет [7][42].
- **Hosted-версия Kilo.**
  - Kilo Code писал о beta 2026-03-04: оплата за compute, токены без наценки («zero markup»), 500+ моделей [159].
  - GA — 2026-05-19, со встроенным Wasteland — общей доской задач для многих установок Gas Town [160].
  - На HN запуск виден 2026-03-18 [162]. Дата расходится с блогом Kilo (03-04).
  - Сейчас https://kilo.ai/gastown отвечает HTTP 308 на /cloud, а там Gas Town не упомянут [161]. Предлагается ли версия сейчас — (не подтверждено).
  - Посты Kilo — вторичный источник для Gas Town.
- **Размер.** Town — так Gas Town называет корневую папку со всеми проектами и агентами. Один town рассчитан на одну машину. Масштаб, по замыслу, — через много town-ов, как git масштабируется через много репозиториев [135]. README обещает 20–30 агентов [7].
- **Агенты.** Своего агента в Gas Town нет. Он запускает готовые CLI агентов в tmux и не импортирует их библиотеки: интеграция — это конфигурация, а не компиляция [40].
  - Встроенные presets: claude (по умолчанию), gemini, codex, kiro, cursor, auggie, amp, opencode, copilot, pi, omp. В коде есть ещё vibe (Mistral) и groq-compound [7][85].
  - Hooks (вызовы на событиях жизненного цикла агента) есть у Claude, Gemini, Cursor и OpenCode. Resume есть у всех, кроме OpenCode. Fork сессии — только у Claude [40].
  - У Codex по умолчанию нет hooks. Gas Town при старте сам вводит `gt prime` и посылает nudge — короткое сообщение в живую сессию. Пользователя просят выставить `project_doc_fallback_filenames=["CLAUDE.md"]` [7]. Opt-in hooks у Codex — experimental [40].
  - Copilot: hooks лежат в `.github/hooks/gastown.json`; нужен seat и политика CLI на уровне организации [7].
- **Модели** зависят от CLI агента. Пример настроек отправляет OpenCode на Kimi K2.5 или на Sonnet через OpenRouter [46]. Cost tiers раскладывают роли по Opus, Sonnet и Haiku [49][87].
- **Один пользователь.** Gas Town рассчитан на одного человека и много агентов. Человека система называет Overseer; у него есть identity и inbox [27][134].
  - Учётных записей, ролей пользователей, входа и общего web-доступа нет. Dashboard по умолчанию слушает только localhost [27][49][62].
  - Командные элементы: федерация Wasteland, общий удалённый Dolt-сервер, атрибуция агентов в git, «CV» агентов для сравнения моделей [44][29][11][12].
  - Маршрутизация по возможностям агента помечена «Planned», федерация между town-ами — «partially implemented» [12].
- **Платформы** [7][43][182]:
  - macOS (Homebrew);
  - Linux (`go install`);
  - Windows: нативно — только CLI без tmux; для работы с tmux — WSL;
  - Docker, Nix flake;
  - npm-бинарники для macOS, Linux x64/ARM64 и Windows x64.
- **Интерфейсы:** сессии tmux, TUI-лента `gt feed`, локальный web dashboard `gt dashboard` [7]. Minimal mode обходится без tmux: человек сам запускает `claude --resume` или `codex`, а Gas Town только ведёт состояние [7].
- **Каналы установки отстают от релизов:**
  - Homebrew Core stable — 1.1.0. PR в Homebrew Core для 1.2.0 не прошёл formula test: Gas Town 1.2.0 принимал Beads не новее 1.0.4, а Homebrew ставил 1.0.5. PR для 1.2.1 тоже закрыт без слияния. Issue #4179 открыт [183][113][187].
  - Официальный tap gastownhall/homebrew-gastown уже отдаёт 1.2.1 [184].
  - npm-пакет @gastown/gt остался на 0.12.0 от 2026-03-12 [182].
  - Release notes v1.0.0 называют неверное имя npm-пакета — `@anthropic/gastown` [3].

## Функции

### Основной сценарий

1. **Установка и старт.** `gt install ~/gt --shell --git` создаёт town. `gt up` запускает Dolt, демон, Deacon, Mayor и по одному Witness и Refinery на проект (роли описаны ниже). `gt doctor --fix` проверяет и чинит установку [7][49].
2. **Проект.** `gt rig add <name> <git-url>` подключает rig — один git-репозиторий под управлением Gas Town. `--prefix` задаёт префикс ID задач. `--adopt` и `gt rig quick-add` подключают уже существующую папку [7][8][49].
3. **Разговор с координатором.** `gt mayor attach` открывает Mayor — сессию Claude Code, с которой человек обсуждает работу [7].
   - Шаблон Mayor задаёт правило «File it, sling it»: завести задачу (`bd create`), затем раздать её (`gt sling`). Сам Mayor чинит только мелочи [90].
   - DoltHub описывает Mayor как интерфейс, похожий на Claude Code [163].
4. **Раздача.** `gt sling <bead> <rig>` (bead — запись о задаче в трекере Beads) запускает polecat — worker-агента в его собственном git worktree. Заодно создаётся convoy — группа отслеживаемых задач, чтобы работа была видна на dashboard [49][19].
5. **Сдача.** Polecat вызывает `gt done`: ветка уходит push-ем, создаётся bead-заявка на слияние (merge request) [7][49].
6. **Слияние.** Refinery — агент очереди слияния проекта — собирает merge requests, запускает проверки и сливает. По README polecat-ы никогда не пушат в main [7].
7. **Итог.** Когда все задачи convoy закрыты, convoy считается «landed»: подписчики получают сводку с длительностью [19].

### Рабочее пространство и проекты

- **Раскладка папок.** Корень town — `~/gt`. В нём папки Mayor и Deacon и beads уровня town (их ID начинаются с `hq-`). На каждый rig — bare-репозиторий, основная база beads и папки witness, refinery, crew и polecats [11][14].
- **Команды `gt rig`** [49]:
  - add, list, remove, status, start/stop/restart, boot/reboot;
  - park/unpark — демон не перезапускает rig сам;
  - dock/undock — выключение надолго;
  - settings, config, reset;
  - `menu` — popup-меню в tmux.
- Имя rig — только буквы, цифры и подчёркивания [7].
- **Crew** — `gt crew add/at/list/start/stop/restart/refresh/pristine/rename/remove/next/prev` [49]. Crew member — постоянный clone для человека или долгоживущего агента. Он пушит в main напрямую, и Witness за ним не следит [11].
- `gt worktree <rig>` — поработать в другом rig, не теряя своей identity [11].
- **Слои настроек:** wisp (временная запись) → identity bead rig-а → умолчания town → встроенные умолчания [14].
- Репозиторий может нести `.gastown/settings.json` со своими test gates и стратегией слияния [8].
- **Shell integration** — `gt shell install`. С 1.2.1 он предлагает добавить репозиторий в town, только если задано `GASTOWN_OFFER_ADD=1` [8].
- **Служебные команды:** `gt enable/disable/uninstall` для всей системы, `gt upgrade`, `gt stale`, `gt info` («что нового»), completions для bash, zsh и fish [7][49].

### Учёт работы: beads, convoys, waves

- **Beads** (`bd`) — трекер задач Yegge; данные лежат в Dolt [7][13]. Bead — одна запись. Это может быть issue, epic, task, merge request, письмо агенту или escalation [13][27].
  - ID — префикс плюс 5 символов, например `gt-abc12` [7][13].
  - Зависимости задаёт `bd dep add`. `bd ready` показывает работу без блокеров [14].
  - ID по префиксу направляются в нужную базу через `routes.jsonl` [14].
- **Convoy** (ID вида `hq-cv-*`) — группа задач из разных rig-ов [49][19].
  - Команды: create, add, list, status, close, check, stranded, land, watch, unwatch.
  - Задача, добавленная в закрытый convoy, открывает его снова [19].
  - `--from-epic` обходит детей epic в ширину и берёт только листовые задачи [19].
- **Waves.** `gt convoy stage <epic|tasks|convoy>` проверяет граф зависимостей и делит задачи на waves — группы задач, которые можно запускать одновременно [24].
  - Wave 1 — задачи без незакрытых блокеров. Wave N+1 — задачи, все блокеры которых лежат в более ранних waves.
  - Команда сначала показывает дерево, потом таблицу waves. Она предупреждает о задачах-сиротах и оценивает, сколько polecat-ов нужно на каждую wave.
  - `gt convoy launch` раздаёт wave 1. Дальше демон подаёт задачи сам, по мере закрытия блокеров: по событиям примерно раз в 5 с плюс проверка застрявших convoy раз в 30 с [24][49][77].
- **Mountain** — режим для длинного epic: `gt mountain <epic>`, появился в 0.12.1 [49][8].
  - Команда делает stage, ставит метку `mountain` и делает launch.
  - Метка включает поиск зависаний, пропуск задачи после N неудач и проверки прогресса силами Deacon и его помощников [23].
  - Подкоманды: status (с progress bars), pause, resume, cancel [49].
  - Design doc задаёт N=3 и обещает, что можно уйти на обед и вернуться к готовой работе. Сам doc помечен «Status: Design» [23].
  - В части пропуска код следует design: Witness после 3 неудач по задаче ставит метку `mountain:skipped` (константа `MountainMaxFailures = 3`, перепроверено 2026-11-13). Остальные обещания design в коде не сверялись [59].
- **Integration branches** — `gt mq integration create|status|land <epic>` [22][14].
  - Polecat-ы ответвляются от integration-ветки epic, Refinery сливает в неё.
  - Весь epic приходит в main одним merge commit. Auto-landing по умолчанию выключен.
- **История работы** [49]:
  - `gt changelog` — закрытая работа по всем rig-ам; флаги `--today`, `--week`, `--since`;
  - `gt trail` (alias `recap`) — последние коммиты, beads и hooks;
  - `gt audit --actor` — одна лента по git, beads и событиям;
  - `gt log -f` — события жизненного цикла агентов;
  - `gt ready` — незаблокированная работа по всему town.

### Раздача работы

- **`gt sling`** — единственная команда раздачи [49][50].
  - Кому: себе, crew, в rig (сам создаёт polecat), конкретному polecat, Mayor или Dogs (агентам-помощникам).
  - Флаги: `--args` (инструкции обычными словами), `--stdin`, `--account`, `--agent`, `--merge=direct|mr|local`, `--no-merge`, `--review-only`, `--base-branch`, `--branch` или `--pr N` (продолжить работу в существующем PR), `--formula`, `--max-concurrent`.
  - `--ralph` даёт каждому шагу свежий контекст.
  - Пакетная форма: `gt sling a b c rig`.
- `gt assign` — создать bead и отдать его crew member одной командой [49].
- **Scheduler** [26]:
  - `scheduler.max_polecats` по умолчанию равен -1: работа раздаётся сразу.
  - При N>0 демон раздаёт работу на каждом heartbeat раз в 3 минуты, не больше лимита.
  - Circuit breaker останавливает раздачу после повторных неудач.
  - Команды: status, list, run, pause, resume, clear.
- **Formulas** — TOML-шаблоны workflow. Запущенная formula становится molecule — отслеживаемым многошаговым запуском [7][14].
  - Типы: workflow; convoy (параллельные «legs» и шаг синтеза); expansion; aspect [14][97].
  - Встроенные примеры [98]:
    - shiny: design → review → test;
    - rule-of-five: 4–5 проходов доработки;
    - tdd-cycle и security-audit;
    - design, mol-plan-review и mol-prd-review: группы параллельных аналитиков;
    - mol-idea-to-plan: от смутной идеи к готовому плану;
    - mol-polecat-work и его варианты для monorepo;
    - демо Towers of Hanoi: показывают, что запуск из 1000 шагов переживает сбои.
  - `gt mol dag` показывает граф зависимостей шагов, `gt mol progress` — прогресс по шагам [49].

### Роли и жизнь сессий

- **Роли** [7][11][13]:
  - Mayor — один на town; координирует работу.
  - Deacon — один на town; ведёт patrol — повторяющийся цикл проверок по чек-листу — и следит за здоровьем системы.
  - Witness — один на rig; следит за polecat-ами.
  - Refinery — один на rig; ведёт очередь слияния.
  - Polecats — worker-ы.
  - Crew — постоянные рабочие места.
  - Dogs — агенты-помощники для инфраструктурных задач.
  - Boot — dog, который раз в 5 минут проверяет Deacon.
- **Polecat** [18][49][8]:
  - у него постоянная identity, история работ («CV») и agent bead, но короткие сессии;
  - состояния: Working, Idle, Done, Stalled, Zombie;
  - имена берутся из тематических пулов (mad-max, minerals, wasteland) и не повторяются между rig-ами;
  - имя ветки строится по шаблону, например `{user}/{year}/{month}/{description}` [14].
- **Контекст роли.** `gt prime` через SessionStart hook добавляет в сессию 300–500 строк контекста роли [14].
  - На диске лежит только `~/gt/CLAUDE.md`.
  - Настройки роли передаются флагом `--settings`. Поэтому `.claude/` и `CLAUDE.md` в репозитории клиента не меняются.
- **Handoff** — `gt handoff` перезапускает сессию со свежим контекстом. Работа продолжается с hook — слота, где лежит назначенная агенту работа [49].
  - `--collect` упаковывает текущее состояние в handoff-письмо.
  - `--cycle` вызывается из PreCompact hook.
  - Есть slash-команды `/handoff` и `/done` [49][8].
- **Seance** — `gt seance --talk <id> [-p "вопрос"]`. Команда запускает `claude --fork-session --resume`, чтобы спросить о чём-то прошлую сессию и не изменить её [49].
- **Typed memories** — `gt remember --type feedback|project|user|reference`, `gt memories`, `gt forget`. Память хранится как beads и добавляется в контекст при prime [49].
- **Итог работы.** `gt done` завершает работу со статусом COMPLETED, ESCALATED или DEFERRED [49].
- Сессии помечены `[GAS TOWN]`, поэтому их легко найти в списке `/resume` у Claude [14].

### Очередь слияния, проверка, review (Refinery)

- **Batch-then-bisect.** По README Refinery тестирует merge requests пачкой поверх текущей ветки. Если пачка падает, он делит её пополам, находит плохой MR и сливает хорошие [7][8].
  - **В коде не подключено.** Код пачек есть, но вне tests его никто не вызывает, а formula Refinery о пачках не пишет (перепроверено 2026-11-13). Architecture doc помечает фазу 2 «Blocked by Phase 1» [84][6][15][100].
- **Gates** [14][46][8]:
  - команды: setup, typecheck, lint, test, build;
  - именованные gates с timeout;
  - фаза `post-squash` проверяет ещё раз после squash и перед push;
  - test и lint идут параллельно;
  - flaky test по умолчанию повторяется один раз;
  - при конфликте (`on_conflict`) — `assign_back` (вернуть worker-у) или `auto_rebase`;
  - ещё: timeout для брошенных claim-ов, удаление слитых веток, `auto_push`.
- **Стратегия слияния** по умолчанию — `direct` [86][8].
  - `pr` сливает через API хостинга: GitHub по умолчанию, Bitbucket Cloud как вариант. Так работают branch protection и merge queue GitHub.
  - `require_review` не даёт слить, пока PR не одобрен.
  - Тело PR — описание bead и статистика diff [8].
  - Просьбу о режиме PR с branch protection и ожиданием CI (#2630) Yegge закрыл 2026-03-29 со ссылкой на переход к Gas City. 2026-05-19 её открыли снова; на 2026-11-13 она открыта. Стратегия `pr` при этом есть с 1.0.0 — в коде, changelog и formula Refinery [120][86][8][100].
- **Review** [98][14]:
  - formula `code-review` (тип convoy) запускает 10 параллельных review legs, по одной на lens: correctness, performance, security, elegance, resilience, style, smells, wiring, commit discipline, test quality;
  - шаг синтеза сводит результаты;
  - presets в таблице formula: gate, full, security-focused, refactor. Текст описания formula называет gate, full и custom; custom — это выбор legs флагом `--legs` [103];
  - запуск: `gt formula run code-review --pr=123`.
- Slash-команда `/review` ставит diff оценку от A до F. Diff — uncommitted, staged, вся ветка или PR [90][8].
- Plugin `quality-review` ведёт качество слияний по каждому worker-у [107].
- Formula patrol для PR-feedback и plugin `github-sheriff` превращают упавший CI в открытых PR в beads [98][107].

### Работа без присмотра, зависшие агенты, лимиты

- **Цепочка watchdog** [7]: демон на Go раз в 3 минуты делает heartbeat → Boot (агент) разбирает ситуацию → Deacon делает patrol → Witness-ы и Refinery.
- **Правило GUPP** (Gas Town Universal Propulsion Principle): если на hook агента есть работа, он обязан её выполнить [13].
- **Поиск зависших** в `gt feed --problems` [7][49]:
  - категории: GUPP violation (работа на hook, но 30 минут нет прогресса), Stalled, Zombie (сессия tmux мертва), Working, Idle;
  - одна клавиша — nudge, другая — handoff, Enter — подключиться к сессии.
- **Перезапуск.** Witness перезапускает зависшие сессии (30+ минут без вывода), а не удаляет их [98].
  - Паузы между перезапусками растут экспоненциально (backoff): от 30 с до 10 минут. 5 перезапусков за 15 минут — crash loop. `gt daemon clear-backoff` сбрасывает backoff [76][8].
  - Расхождения нет. В 0.11.0 убрали поиск зависших сессий в демоне: он убивал здоровых Witness и Refinery, и проверку перенесли в plugin stuck-agent-dog [8]. Перезапуск зависших polecat-ов силами Witness — другой механизм, и в коде он есть [101][81].
- **Usage limit** (с 1.2.0). Прежде чем убить зависшую сессию Deacon, демон читает её pane в tmux и ищет сообщения Claude о лимите. При совпадении он не убивает сессию, а ставит фиксированную паузу 60 с; сменить аккаунт должен quota_dog. Эта пауза не считается в бюджет crash loop [8][75][76]. В коде проверка вызывается только для Deacon (`restartStuckDeacon` в daemon.go), хотя changelog пишет об «agent's tmux pane» [71][8].
- **Ротация аккаунтов** [49][68][69][75]:
  - `gt account add/list/default/switch/status`; каждый аккаунт — своя папка `~/.claude-accounts/<handle>`;
  - `gt quota scan|status|rotate|watch|clear` ищет текст лимита в каждом pane: жёсткий лимит («You've hit your … limit», «resets 7pm») и почти лимит («80% of your daily usage», «10 messages remaining»);
  - ротация берёт свободный аккаунт, которым дольше всего не пользовались, и меняет token входа в macOS Keychain; папка конфигурации сессии остаётся прежней. Затем pane перезапускается командой агента с `--continue`. Help-текст `gt quota rotate` пишет «Sends /resume», но код делает именно `--continue` [68];
  - нужно минимум 2 аккаунта [68];
  - `--from <acct> --idle` переключает заранее;
  - `quota watch` и quota patrol демона (quota_dog) работают раз в 5 минут; quota_dog по умолчанию выключен [75][73];
  - аккаунт снова считается свободным, когда проходит распознанное время сброса;
  - только macOS; на других платформах — stub.
- **Plugin rate-limit watchdog** (был в v1.0.0) [107][3]:
  - раз в 3 минуты шлёт к Haiku запрос на 1 token с `ANTHROPIC_API_KEY`;
  - на HTTP 429 вызывает `gt estop`, после восстановления API — `gt thaw`;
  - стоит около $0,05 в день;
  - его убрали из main 2026-04-12 (PR #3550), в релизах начиная с v1.0.1 его нет. Причина: probe требует `ANTHROPIC_API_KEY`, а у town-ов на подписке Claude Max ключа нет, и каждый запуск plugin падал [185][186].
- **Emergency stop** — `gt estop [--rig] [-r reason]` [49][67]:
  - замораживает сессии агентов сигналом SIGTSTP; контекст сохраняется;
  - Mayor и человека не трогает;
  - `gt thaw` возобновляет работу.
- **Нагрузка:**
  - opt-in проверки CPU, памяти и числа сессий перед запуском worker-ов [8][74];
  - `--max-concurrent` задаёт темп запуска [49];
  - patrol без работы идут с пониженным reasoning effort и паузами до 15 минут; по changelog это экономит около 66% на простаивающих rig-ах [8].
- **Восстановление** [8]:
  - `gt up` снова подключает работу, чья сессия упала;
  - checkpoint dog сам коммитит незавершённую работу в worktree;
  - работа погибших polecat-ов раздаётся заново, и новый worker получает контекст неудачной попытки.
- **Запросы разрешений:**
  - presets запускают агентов со всеми подтверждениями выключенными: `claude --dangerously-skip-permissions`, `codex --dangerously-bypass-approvals-and-sandbox`, `gemini --approval-mode yolo`, `copilot --yolo`, `amp --dangerously-allow-all`, `cursor-agent -f`, `kiro --trust-all-tools` [85];
  - если старт завис на 90 с, Witness нажимает клавиши, не проверяя экран, чтобы закрыть диалоги «workspace trust» и «bypass permissions» [81];
  - pre-tool guards блокируют немногое: `sudo` и установку системных пакетов, интерактивные `cp/mv/rm -i`, нарушения PR workflow [8][39];
  - политики подтверждения по отдельным инструментам нет [85][81].

### Связь между агентами, уведомления, escalation

- **Mail** — почта между агентами: inbox, read, send, reply, thread, search, archive, drain, mark-read, очереди и claims, channels, groups [49]. Интерактивные роли получают почту на каждом prompt, автономные — при старте сессии [14].
- **Nudge** — короткое сообщение живой сессии. Три режима [49]:
  - `wait-idle` (по умолчанию) — дождаться prompt и доставить;
  - `queue` — доставить на границе следующего хода агента;
  - `immediate` — сразу, нажатиями клавиш в tmux.
  - Ещё: адресат-channel, `gt broadcast`, `gt notify verbose|normal|muted`, `gt dnd` (режим «не беспокоить»).
- **Escalation** — `gt escalate -s CRITICAL|HIGH|MEDIUM` [27]:
  - каждая escalation — bead; маршрут: Deacon → Mayor → Overseer (человек);
  - каналы: mail, email (SMTP), SMS webhook, Slack webhook, log file;
  - неподтверждённая escalation через 4 часа считается устаревшей и поднимается на уровень выше, не больше двух раз;
  - подкоманды `ack`, `close`, `list`, `stale`.
- **Уведомления о convoy.** Завершение convoy и снятие зависимости между rig-ами шлют уведомления. `--notify --human` подписывает человека [8][19].
- **Desktop-уведомлений ОС** в коде не найдено. Демон может вызвать необязательный скрипт пользователя `~/gt/bin/gt-notify` — например, для сообщений в Slack о сбоях Deacon [71][6].

## Принципы и подходы

### Откуда взялся

- Это четвёртый оркестратор Yegge за 2025 год [134][135]:
  - `vibecoder` — TypeScript на Temporal, август 2025. Оказался громоздким: работу LLM приходилось резать на мелкие workflow.
  - `vc` — Go. Слишком монолитный: пытался сделать агентов лучше, а не многочисленнее.
  - Gas Town на Python — с 2025-11-23.
  - Переписан на Go в конце декабря 2025.
- **Beads появился первым** — в октябре 2025, репозиторий создан 2025-10-12 [134][5]. Yegge подаёт Gas Town как продолжение Beads. Другого хранилища нет: Beads хранит и данные, и управляющее состояние [134].
- **Mail взята из MCP Agent Mail** Jeffrey Emanuel. Он заметил, что почта и трекер задач вместе заставляют агентов самоорганизоваться. Gas Town хотел превратить такую самоорганизацию в координированную работу [135].
- **Сроки:** репозиторий — 2025-12-16 [5]; molecules придуманы 2025-12-17, wisps — 2025-12-21; первый полностью автономный запуск — вечер 2025-12-29; launch post — 2026-01-01 [134]; v0.1.0 — 2026-01-02 [8].
- **Предсказание.** В эссе марта 2025 Yegge предсказал, что кто-то свяжет вместе много копий Claude Code. Весь год он предлагал компаниям «Kubernetes for agents»: многоуровневый надзор, merge queue, workflows, plugins, quality gates. Никто этого не сделал, и он сделал сам [134].

### Принципы

1. **GUPP — propulsion.** Агент, у которого на hook есть работа, начинает её сразу, без подтверждения [13][16].
   - Правило против такого сбоя: перезапущенный агент представляется и ждёт, а его супервизор считает, что работа идёт. В итоге всё стоит [16].
   - На практике Claude Code всё равно часто ждёт ввода. Обходной путь — nudge через tmux через 30–60 с после старта [134].
2. **MEOW — Molecular Expression of Work.** Цели раскладываются на мелкие отслеживаемые шаги: beads, epics, formulas, molecules [13][134]. Yegge считает, что сам Gas Town может не прожить и года, а этот слой проживёт годы [134].
   - **Расхождение у самого вендора:** README расшифровывает MEOW как «Mayor-Enhanced Orchestration Workflow», а glossary и launch post — как «Molecular Expression of Work» [7][13][134].
3. **NDI — Nondeterministic Idempotence.** Агент, его hook и его molecule — постоянные записи в git. Поэтому workflow в итоге завершится, даже если сессии падают и ошибаются, — пока на него запускают новых агентов [13][134]. По эффекту это похоже на durable replay в Temporal, но механизм другой. Yegge прямо пишет, что это не замена Temporal [134].
4. **ZFC — Zero Framework Cognition.** Код на Go — только транспорт, решения принимают агенты [10].
   - В Go не должно быть жёстко заданных порогов и эвристик поведения. Вместо новых subcommands предпочитают formulas.
   - Вопрос к каждому изменению: это транспорт или «мышление»?
   - По этому правилу убрали «decision engine» у Boot — он тратил токены без предела [8].
   - Правило не абсолютное: в 0.9.0 пороги перенесли в `operational.json`, а не убрали [8]. В коде много порогов времени в виде настраиваемых умолчаний [88].
5. **Bitter Lesson.** Расчёт на рост моделей и на чистые данные наблюдения, а не на ручные эвристики, которые устаревают [10]. Chris Sells (теперь CEO) говорит то же об оркестрации: больше compute и больше reviewer-ов — лучше результат [152].
6. **Discover, don't track.** Состояние выводится из реальности — из tmux и журнала. Отдельной копии состояния не держат [40][33][23].
7. **No agent holds the thread.** Любой агент-координатор теряет контекст при compact. Поэтому состояние — это сам epic, а каждая проверка идёт со свежим контекстом [23].
8. **Float over integer.** Одна застрявшая задача не должна останавливать epic: работа идёт в обход неё [23].
9. **Graceful degradation.** У каждой возможности есть запасной путь [40][33][7][134]:
   - нет hooks — стартовые команды вводятся через tmux;
   - нет resume — новая сессия плюс handoff-письмо;
   - есть minimal mode без tmux.
10. **Атрибуция и история как основа доверия** [11][12]. Пункты философии:
    - атрибуция обязательна;
    - работа — это данные;
    - история важна: доверие определяет track record;
    - масштаб заложен по умолчанию;
    - проверка вместо доверия.
    - У агентов есть CV, модели можно сравнивать A/B [12][11][18].
11. **Desire paths** — удобство для агентов: смотреть, какие команды агенты пытаются вызвать, и делать такие команды, пока каждая догадка агента не станет верной [135][139].
    - 100+ subcommands Beads сделаны для агентов, а не для людей [139].
    - Шаблоны ролей велят агенту завести bead `desire-path`, если разумная догадка не сработала [92].
    - Теория за этим — «Survival Ratio». Инструмент выживает, если сэкономленные им токены больше, чем стоит агентам знать о нём и пользоваться им. Из этого выведены шесть способов повлиять на это отношение [139].
12. **Борьба с heresies.** Heresy — правдоподобное, но неверное убеждение об архитектуре, которое агенты копируют в код. Средство — именованные аксиомы в контексте агентов, на которые может сослаться reviewer [136].
    - Аксиомы: ZFC, GUPP, MEOW, Discovery over Tracking, Beads as the Universal Data Plane [136].
    - Примеры в шаблонах: «Idle Polecat Heresy» (закончивший worker обязан вызвать `gt done`, без шага одобрения) и «Scotty Test» у Refinery (не проходить мимо сбоя, даже если сбой был до тебя) [92].
13. **Пропускная способность важнее экономии.** Часть исправлений делается 2–3 раза, часть работы теряется. Это принимают ради скорости [134].
    - Человек — product manager. Он даёт системе спецификации, а система превращает их в код («idea compiler») [134].
    - Смотреть, как агенты работают, не нужно; нужно читать результаты [136].
    - Самая трудная задача — давать системе достаточно спецификаций [134].
14. **Надёжность — это настройка** (эпоха Gas City). Больше reviewer-ов, судей и guardrails — больше надёжности. Процесс без присмотра никогда не отдают одному агенту — минимум 2–3 [144].

### Чем подход отличается (по словам авторов)

- **Примитив — работа, а не оркестрация.** Yegge противопоставляет это Loom, Claude Flow и другим, где ядро — оркестрация. У Gas Town слой оркестрации тонкий: он лежит поверх описания работы и проверяемого журнала [138].
- **Сессии одноразовые, identity постоянные.** Агент — запись в git, сессии взаимозаменяемы [134].
- **Цель — завершение, а не uptime.** Kubernetes держит процессы живыми. Gas Town доводит работу до конца и отпускает worker-а [134].
- **Тяжёлый и opinionated: многое решено за пользователя.** По словам Yegge, это смесь Kubernetes и Temporal. Каждый компонент понадобился, чтобы система держалась сама [134].
- **Размер — одна машина**, рост — через много town-ов [135].
- **Для опытных.** Целевой пользователь — на «Stage 7+» из 8 стадий Yegge: 10+ агентов, которыми человек управляет вручную [134].
  - К марту планку снизили: тот, кто уже пользовался coding-агентом, готов [141].
  - Gas City позже добавила стадии 9–11, до «factory builder» [144].
- **Против формы Claude Code.** Yegge называет другие CLI агентов клонами формы Claude Code 2025 года [134]. Он ждёт, что агенты будут соревноваться в том, насколько они хорошие «factory workers» с настоящим API для оркестратора [135]. В марте он писал, что Claude Code рискует стать продуктом, а не платформой, и что агент-worker такого рода будет создан [141].

## Как это устроено внутри

Основа раздела — чтение кода на коммите 94cc822 (2026-11-12); ничего не запускалось. В клоне 663 Go-файла без тестов, около 249 тысяч строк [6].

### Что где работает

- **Один бинарник `gt` на Go и `bd` (Beads).** Они управляют CLI агентов в tmux и не импортируют библиотек агентов [40].
- **Демон — обычный Go без LLM.** Код описывает его как «dumb scheduler»: он только планирует, а работу делают существующие команды `gt` [75].
  - Раз в 3 минуты демон делает heartbeat — проход восстановления с пронумерованными шагами [71][88]:
    - перезапустить упавшие Dolt, Deacon, Witness-ы, Refinery или Mayor;
    - обработать запросы жизненного цикла;
    - отметить worker-ов, у которых есть работа, но нет прогресса;
    - найти брошенную работу и проверить здоровье сессий worker-ов;
    - закрыть простаивающие сессии worker-ов и осиротевшие процессы subagent-ов Claude;
    - удалить лишние ветки;
    - раздать работу из очереди (шаг 14).
  - Отдельные таймеры: проверка здоровья Dolt, backups, экспорт JSONL, удаление и compaction данных, checkpoint незавершённой работы, test run на main, ротация аккаунтов [71].
- **Роли с LLM — сессии Claude Code (или другого CLI) в tmux.** У каждой — prompt роли и чек-лист patrol [11][15].
  - Boot — новый короткоживущий агент. Он решает, разбудить, подтолкнуть nudge-ем или перезапустить Deacon [82].
  - Crew — долгоживущие полные clones под управлением человека; они пушат в main [11].
- **Хранилище в два уровня** [15]:
  - beads уровня town (`hq-*`): почта, convoys, identity агентов;
  - у каждого проекта своя база beads с префиксом ID: issues и merge requests;
  - worktree-ы находят общую базу через файл `.beads/redirect`.

### Единицы работы и состояние

- **Bead** — единица работы: issue, task, epic, merge request, письмо, запись агента [13].
- **Hook** — закреплённый за агентом bead с его текущим заданием [13].
- **GUPP**: нашёл работу на hook — выполняй, без лишнего подтверждения [16].
- **Formula** — TOML-шаблон workflow. Четыре типа [97]:
  - `workflow` — последовательные шаги;
  - `convoy` — параллельные legs и шаг синтеза;
  - `expansion` — шаблонные шаги, например rule-of-five;
  - `aspect` — параллельный анализ.
- **Molecule** — экземпляр formula [17]:
  - по умолчанию хранится только один «root wisp» (одноразовый bead), а шаги агент видит прямо в выводе `gt prime`;
  - с `pour = true` шаги становятся вложенными beads с восстановлением по checkpoint; это для дорогих и редких процессов;
  - режим «только root» сократил записи wisp примерно с 6 000 до 400 в день.
- **Convoy** — bead уровня town, который следит за пачкой задач в разных проектах. Он считается landed, когда все задачи закрыты, и уведомляет подписчиков [19]. Каждый `gt sling` сам создаёт convoy, если не передан `--no-convoy` [25].
- **Хранение:**
  - один SQL-сервер Dolt на town, порт 3307, пользователь `root`, по умолчанию без пароля; пароль можно задать через `GT_DOLT_PASSWORD` [29][189];
  - каждый агент пишет прямо в `main` внутри транзакции BEGIN / DOLT_COMMIT / COMMIT [15];
  - раз в 15 минут очищенный снимок JSONL уходит в git-репозиторий на случай аварии [29][73];
  - жизненный цикл данных из шести стадий: create → live → close → decay → compact → flatten. Dogs удаляют wisps старше 7 дней и сжимают историю коммитов [15][73].
- **Слабое место.** Открытый issue #764 (2026-01-18): состояние выполнения лежит в записях задач, которые можно удалить. Например, закрытие `hq-mayor-role` ломает Mayor [110].

### Цикл агента: polecat от раздачи до выхода

1. **`gt sling <bead> [rig]`** [52][50]:
   - проверяет здоровье Dolt и запас соединений (admission control);
   - отказывает проектам в состоянии park или dock;
   - держит лимит повторных запусков на bead — по умолчанию 3, сброс через `gt sling respawn-reset`;
   - берёт простаивающий polecat или выделяет имя из пула — по умолчанию 50 имён [88];
   - создаёт git worktree на новой ветке, запускает агента в tmux и вешает bead на его hook;
   - флаги: `--agent`, `--account`, `--merge direct|mr|local`, `--base-branch`, `--pr` (продолжить ветку существующего PR), `--review-only`, `--ralph` (свежий контекст на каждый шаг) [50].
2. **Первое сообщение** — «beacon»: `[GAS TOWN] <recipient> <- <sender> • <time> • <topic>`, затем просьба выполнить `gt prime --hook` и начать работу. Эта метка делает сессию находимой в `/resume` [93].
3. **`gt prime --hook`** запускается из SessionStart hook. Он определяет роль по рабочей папке и по порядку добавляет: шаблон роли, directives оператора, файлы контекста, handoff-письмо, bead с hook, чек-лист formula [54][15].
4. **Чек-лист `mol-polecat-work` (v11)** [99]:
   - load-context → branch-setup → implement. Правила шага implement:
     - объём задачи — договор: прежде чем расширить его, надо написать Mayor;
     - никогда не вызывать `sudo` и не ставить системные пакеты;
     - записывать находки в bead (`bd update --notes`), потому что сессия может умереть в любой момент;
     - побочные баги заводить новыми beads, а не чинить;
     - если застрял на 15 минут — написать Witness.
   - commit-changes → self-review (`/review --branch`, оценка A–F; исправить CRITICAL и MAJOR) → build-check (build и typecheck; tests — по желанию);
   - pre-verify: rebase на target и полный набор gates;
   - submit-and-exit: `gt done --pre-verified`.
5. **`gt done`** [53]:
   - статусы выхода: COMPLETED, ESCALATED, DEFERRED;
   - отклоняет ветку без коммитов;
   - если ветка слишком отстала от target, отказывает или делает auto-rebase («contamination check»);
   - делает push, создаёт bead merge request, сообщает Witness (`POLECAT_DONE`) и закрывает свою сессию;
   - возобновляемый: пройденные стадии записаны как checkpoints в bead агента.
6. **Репозиторий сам себе противоречит о повторном использовании polecat:**
   - код запуска сначала пробует взять sandbox простаивающего polecat [52];
   - концептуальный doc пишет, что законченные сессии выводятся из работы и не используются повторно, пока остаётся состояние слияния или очистки [18];
   - formula работы говорит агенту, что `gt done` уничтожает его sandbox («nukes») [99].
   - По changelog жизненный цикл менялся трижды: переиспользование сразу после задачи (0.2.0), постоянные polecat-ы с пулом простаивающих (0.9.0), «retired completion» с июля 2026 — законченная сессия не возвращается в пул [8][18][5].

### Планирование и разбиение

- **Mayor: «File it, sling it».** Изменение кода — это `bd create` и `gt sling`. Сам Mayor чинит только тривиальное. Шаблон предупреждает о «Solo Artist trap» — о трате контекста координатора на код [90].
- **`mol-idea-to-plan`** [105]:
  - intake → черновик PRD;
  - параллельный review PRD в 6 legs: requirements, gaps, ambiguity, feasibility, scope, stakeholders;
  - **одна точка решения человека** — уточняющие вопросы;
  - design в 6 legs: API, data, UX, scale, security, integration;
  - 3 раунда сверки с PRD и 3 раунда self-review плана;
  - создание beads с зависимостями;
  - 3 прохода проверки beads против плана.
- **`gt convoy stage <epic|tasks|convoy>`** [24][58]:
  - строит DAG из связей `blocks` и `waits-for`;
  - отказывает при циклах и при beads, которым некуда уйти;
  - считает waves алгоритмом Kahn — топологической сортировкой по уровням [23];
  - создаёт convoy в состоянии staged — его ещё ничто не раздаёт;
  - для epic добавляет в последнюю wave задачу «capstone validation» (`mol-validate-prd`) [58]. Такой formula среди встроенных в клоне нет [58][6];
  - `gt convoy launch` раздаёт только wave 1 [24].
- **Дальше подача идёт по событиям, без барьера между waves.** ConvoyManager демона раз в 5 с опрашивает события beads. Когда задача закрылась, он раздаёт следующую готовую. Проверка застрявших convoy раз в 30 с ловит пропуски [25][77].
- **Mountain** (`gt mountain <epic>`) делает stage, ставит метку и запускает epic [59]:
  - Witness считает неудачи по задаче и после 3 пропускает её (`mountain:skipped`); работа идёт в обход [59][23];
  - состояние — сам epic и его beads; зависания проверяют новые Dog-агенты со свежим контекстом [23].
- **Integration branches:** дети epic сливаются в `integration/<epic>`, новые worker-ы ответвляются от неё. Вся ветка приходит в main одним merge commit, по желанию — автоматически [22].

### Параллельность и координация

- **По умолчанию раздача без предела.** Пакетный sling запускает по worker-у на bead с паузой 2 с. `--max-concurrent` только задаёт темп запуска, общий предел он не ставит [25].
- **Ограничитель ёмкости — opt-in.** Он включается при `scheduler.max_polecats > 0` [26]:
  - `gt sling` тогда создаёт временный bead «sling context», а bead работы не трогает;
  - шаг 14 демона раздаёт `min(capacity, batch_size, ready)` под file lock;
  - context закрывается как «circuit-broken» после 3 неудач раздачи;
  - команды: `gt scheduler pause / resume / clear`;
  - worker-ов считают, перебирая сессии tmux.
- **Ограничение по нагрузке машины** — тоже выключено по умолчанию [74]. Оно смотрит нагрузку CPU на ядро, свободную память и предел числа сессий. Ограничивает только worker-ов, Refinery и Dogs; супервизоров — никогда.
- **Два канала сообщений** [28]:
  - **Mail** создаёт beads, то есть коммиты Dolt. Только для сообщений, которые обязаны пережить смерть сессии получателя. У каждой роли — бюджет писем.
  - **Nudge** не сохраняется. Три режима [66]:
    - `wait-idle` (по умолчанию): дождаться prompt и доставить;
    - `queue`: JSON-файл, который UserPromptSubmit hook разбирает на границе следующего хода; срок жизни — 30 минут для обычных и 2 часа для срочных; в очереди не больше 50;
    - `immediate`: tmux `send-keys` — прерывает агента посреди работы.
- **Протокольные сообщения** [28]: `POLECAT_DONE`, `MERGE_READY`, `MERGED`, `MERGE_FAILED`, `REWORK_REQUEST`, `RECOVERY_NEEDED`, `HELP`, `HANDOFF`. С 0.9.0 они идут через nudge, а не mail; это сократило коммиты Dolt примерно на 80% [8].
- **Циклы patrol** [101]: супервизоры ждут через `gt mol step await-signal`.
  - Он просыпается от любой активности beads или по timeout с backoff от 30 с до 5 минут.
  - После циклов без работы он выводит `EFFORT: reduced`, и агент делает сокращённый patrol — цель около 10% токенов полного.

### Изоляция

- **Только на уровне git.** Worker получает git worktree от `mayor/rig`; у Refinery свой worktree; crew — полные clones [15].
- **Sandbox по умолчанию нет.** SECURITY.md: worker-ы делят доступ к файловой системе и выполняют shell-команды от имени пользователя, который их запустил [9].
- **Sandbox — в основном в проектах:**
  - план exitbox (локально) и Daytona (облачный контейнер) — предложение от 2026-03-02 [37];
  - в конфигурации есть префикс `exec_wrapper` [86];
  - есть `gt-proxy-server` и `gt-proxy-client`: mTLS (TLS 1.3), identity берётся из CN клиентского сертификата, allowlist команд и подкоманд, rate limit на identity, git через bare-репозиторий [41];
  - Docker Compose снимает все Linux capabilities, кроме шести [42][188];
  - spike с macOS `sandbox-exec` (2026-03-08) показал, что он работает, но в продукт не вошёл [38].

### Состояние и память

- **Контекст восстанавливают вставкой, а не памятью.** PreCompact hook снова вызывает `gt prime --hook` [89].
- **`gt handoff`** переводит работу в новую сессию [55][101]:
  - `--collect` собирает задание с hook, inbox и готовые beads в handoff-письмо;
  - `--cycle` — полный перезапуск;
  - между двумя handoff — пауза 2 минуты.
- **`gt seance --talk <id>`** запускает `claude --fork-session --resume <id>`. Агент спрашивает предшественника и не меняет его сессию [56].
- **`gt remember --type feedback|user|project|reference`** кладёт память в key-value хранилище beads. При prime память добавляется в контекст, feedback — первой [57].
- **Переопределения оператора** [15]:
  - directives (Markdown на роль, на town или проект) идут после шаблона роли;
  - formula overlays заменяют, дополняют или пропускают шаги;
  - `gt doctor` находит overlays, которые ссылаются на исчезнувшие шаги.
- **Desire paths.** Если команда не сработала, а догадка была разумной, агент заводит bead `desire-path`. Так собирается обратная связь об удобстве инструментов для агентов [91].

### Проверка качества и слияние

- **Со стороны worker-а** — self-review, build-check и pre-verify (цикл агента выше) [99]. `gt done --pre-verified` записывает SHA target-ветки. Пока HEAD target не сдвинулся, Refinery может не запускать gates повторно; авторы называют это слиянием примерно за 5 секунд [99][83].
- **Refinery — агент LLM на formula `mol-refinery-patrol`** [100]:
  - merge rehearsal: на ветке `temp` влить target в ветку worker-а и запустить gates;
  - разбор падения: если виновата ветка — письмо `FIX_NEEDED` worker-у, ветка остаётся. Если ошибка уже была в main — убрать дубликаты, завести bug и всё равно слить;
  - писать код ему запрещено («FORBIDDEN»);
  - стратегия direct: `merge --no-ff`, push, затем сверка SHA локальной и удалённой веток;
  - стратегия pr: `gh pr create`, `gh pr checks --watch --fail-fast`, слияние только при явном решении review `APPROVED`, затем `gt mq post-merge`.
- **Настройки очереди на стороне Go** [83]:
  - именованные gates идут параллельно; у каждого — timeout и фаза: `pre-merge` или `post-squash` (при падении на этой фазе слияние откатывается);
  - один повтор для flaky tests;
  - lock «merge slot» пропускает push-и в main по одному;
  - предупреждение о брошенном claim — через 2 часа, критично — через 6 часов;
  - конфликты возвращаются worker-у; после 5 попыток — escalation к Mayor.
- **quality-review только измеряет.** Он ставит каждому слиянию оценку от 0 до 1 и записывает её, но не блокирует. Оценка ниже 0,45 называется «breach» [100].
- **Batch-then-bisect в коде не подключён:**
  - README и architecture doc описывают очередь в стиле Bors с пачками и делением пополам [7][15];
  - код есть: `AssembleBatch`, `ProcessBatch`, `bisectBatch`; умолчания — пачка из 5, ожидание 30 с, один повтор пачки при flaky-падении [84];
  - вызова вне tests на коммите 94cc822 нет: `AssembleBatch` и `ProcessBatch` вызываются только из tests, а formula Refinery о пачках не пишет (перепроверено 2026-11-13) [6][100]; architecture doc помечает фазу 2 «Blocked by Phase 1» [15];
  - changelog 0.9.0 записывает очередь batch-then-bisect как добавленную [8].
- **Другие проверки:**
  - test run на main раз в 30 минут: gates на main, падения уходят в escalation [80];
  - formula `code-review`: 10 параллельных reviewer-ов, каждый — отдельный worker, который пишет в файл; затем синтез. Семь смотрят код (correctness, performance, security, elegance, resilience, style, smells), три — реализацию: wiring (зависимость установлена, но не подключена), commit discipline, test quality. Presets в таблице formula: gate, full, security-focused, refactor; описание formula ещё называет custom — выбор legs флагом `--legs` [103];
  - `rule-of-five`: черновик и 4 прохода доработки — correctness, clarity, edge cases, excellence [104];
  - `mol-pr-feedback-patrol`: раздаёт worker-ов на PR с `CHANGES_REQUESTED`, падающими checks или нерешёнными тредами; убирает дубликаты; останавливается на 20 открытых beads [106].
- **Guard PR workflow** запрещает агентам `gh pr create`, `git checkout -b` и `git switch -c`. Объяснение в коде: worker-ы Gas Town пушат прямо в main [63]. README при этом пишет, что polecat-ы в main не пушат, а сливает Refinery [7].

### Восстановление после сбоев

- **Цепочка надзора:** демон → Boot → Deacon → Witness. Witness-ы ещё проверяют метку heartbeat у Deacon — авторы называют это «кто следит за следящими» [20][71][82].
- **Три хранилища heartbeat** [20]:
  - файл heartbeat у Deacon;
  - состояние, которое сессия сообщает сама: `gt heartbeat --state=working|idle|exiting|stuck`. Witness читает его, а не гадает по таймерам;
  - метка на bead агента.
- Скрипт не должен объявлять агента застрявшим по одному хранилищу. Сначала нужна сверка с активностью в tmux [20].
- **Классы zombie, которые находит Witness** [81]:
  - stuck-in-done (дольше 60 с);
  - agent-dead-in-session;
  - bead-closed-still-running;
  - done-intent-dead;
  - idle-dirty-sandbox;
  - session-dead-active;
  - agent-self-reported-stuck;
  - never-heartbeated (например, ошибка авторизации 401 на старте);
  - submitted-still-running.
- **Сначала перезапуск.** Мёртвые, зависшие (30+ минут без вывода) и застрявшие в done сессии перезапускаются в том же worktree. Удалить worker-а («nuke») можно только вручную [101][81]. (В 0.11.0 убрали другой механизм — поиск зависших сессий в демоне, который убивал здоровых Witness и Refinery [8].)
- **Демон отмечает застой** [72][71]:
  - работа на hook без обновлений 30 минут → письмо Witness;
  - брошенная работа;
  - «mass death»: 3 сессии умерли за 30 с → одно событие.
- **Backoff при crash loop** [76]: 30 с, затем удвоение до 10 минут; 5 перезапусков за 15 минут — crash loop; 30 минут стабильной работы сбрасывают счёт.
- **Уроки инцидентов:**
  - после инцидента «serial killer» появилось правило: демон никогда не убивает worker-ов. Решает plugin `stuck-agent-dog`, и он не трогает crew, Mayor и Witness-ов [108]. По changelog Deacon лишился права убивать worker-ов в 0.2.3, после того как убивал целые crews посреди задачи [8][136];
  - plugin `session-hygiene` убрали, после того как он раз за разом убивал сессии crew [8].
- **Защита незавершённой работы:**
  - checkpoint dog (включён по умолчанию, раз в 10 минут) коммитит грязные живые worktree как `WIP: checkpoint (auto)` [78][73];
  - Stop hook `polecat-stop-check` вызывает `gt done`, если сессия закончилась с несданными коммитами или грязной работой [65];
  - `.polecat-checkpoint.json` хранит molecule, шаг, файлы, ветку и bead с hook [79].
- **Повтор с контекстом.** При повторной раздаче передаются ветка и причина закрытия прошлой попытки: `prior_branch`, `prior_failure` [51].
- **Emergency stop** [67][71]: `gt estop [--rig]` замораживает сессии сигналом SIGTSTP, контекст сохраняется. Демон перестаёт перезапускать агентов. Mayor не замораживается. `gt thaw` продолжает работу.
- **Escalation** [27]: уровни MEDIUM, HIGH, CRITICAL; маршруты — bead, mail, email, SMS, Slack; неподтверждённая escalation поднимается снова через 4 часа, не больше двух раз.

### Лимиты и стоимость

- **Распознавание лимита — чтение экрана.** Regex по нижним 20 строкам каждого pane tmux [69][70]:
  - жёсткий лимит: «You've hit your … limit», «API Error: Rate limit reached», «OAuth token revoked»;
  - почти лимит: «80% of your daily usage», «N messages remaining»;
  - время сброса разбирается из текста вида «resets 7pm (America/Los_Angeles)».
- **Ротация аккаунтов** (`gt quota scan / rotate / watch`). Нужно минимум 2 аккаунта [68]:
  - выбирается свободный аккаунт, которым дольше всего не пользовались;
  - `gt quota rotate` (его же вызывает quota_dog) меняет token в macOS Keychain для `CLAUDE_CONFIG_DIR` сессии; сама папка остаётся прежней;
  - pane перезапускается командой агента с `--continue`. В `internal/quota/executor.go` есть второй путь: новая папка конфигурации, ссылка на файл сессии и `--resume <id>` [68].
- **`quota_dog`** запускает ротацию раз в 5 минут. Но он opt-in и в patrols по умолчанию не входит [75][73].
- **Пауза по usage limit — не сбой:** фиксированный backoff 60 с [76][75][8]. Ставит её только проверка зависшего Deacon в демоне. Для worker-ов такой паузы в коде нет: их лимиты видит только сканер `gt quota` для ротации [71][69].
- **Один аккаунт после сброса лимита сам не продолжает.** Так нашла заметка о внутреннем устройстве. Issue #1066 «Handle rate limit resets» (2026-01-29; метки status/accepted и priority/p2) открыт. Кода, который ждёт времени сброса и продолжает сессию, не нашлось [112]. Распознанное время сброса используется только чтобы снова считать аккаунт свободным для ротации [49][75].
- **Контроль затрат:**
  - cost tiers раскладывают роли по моделям (подробности и расхождение — в «Функциях») [87];
  - набор promptfoo из 94 случаев проверяет, принимают ли дешёвые модели те же решения супервизора, что и Opus [48];
  - простаивающие сессии worker-ов закрываются через 15 минут, чтобы не занимать слоты API [71][88].
- **Учёт затрат слабый:**
  - `gt costs record` (Stop hook) суммирует токены из transcript-ов Claude по таблице цен, прописанной в коде с пометкой «as of Jan 2025»; для неизвестных моделей берутся цены Sonnet [60];
  - шаг ежедневной сводки затрат у Deacon помечен «[DISABLED]» [102].

### Права и безопасность

- **Все presets обходят разрешения** [85][89]:
  - Claude: флаг `--dangerously-skip-permissions`, а в настройках `defaultMode: bypassPermissions` и `skipDangerousModePermissionPrompt`;
  - Codex: `--dangerously-bypass-approvals-and-sandbox`;
  - Gemini: `--approval-mode yolo`;
  - диалоги доверия и bypass при старте принимаются нажатиями клавиш через tmux [95].
- **Guardrails — PreToolUse hooks, которые выходят с exit code 2:**
  - `tap guard dangerous-command` блокирует `sudo`, установку пакетов, `rm -rf /`, `git push --force`, `reset --hard`, `clean -f`, `DROP TABLE` [64]. В шаблоне Claude как matchers подключены только `sudo` и команды установки [89];
  - `tap guard pr-workflow` блокирует для агентов `gh pr create`, `git checkout -b` и `git switch -c` [63].
- **Настройки hooks лежат в папках Gas Town.** Они передаются через `--settings` из общих родительских папок, поэтому репозиторий клиента остаётся чистым. Порядок слияния: base → роль → проект и роль [39].
- С 1.0.0 Mayor одобряет расширение объёма работы worker-а, и есть PreToolUse guard против `sudo` [8].
- Dolt слушает порт 3307, вход — `root`, по умолчанию без пароля; `GT_DOLT_PASSWORD` задаёт пароль [29][189].
- Dashboard: по умолчанию только localhost, CSRF token для POST, allowlist команд с подтверждением изменяющих [62].
- OpenTelemetry с 0.8.0 может писать содержимое инструментов и prompts пользователя [8]. `GT_LOG_AGENT_OUTPUT` передаёт ходы разговора [45].
- **Инцидент #3649** [109]: по сообщениям пользователей, release formulas из поставки заставляли их установки открывать PR в upstream-репозиторий — на кредиты пользователей и от их аккаунтов GitHub. Комментатор считал, что это release flow maintainer-а, запущенный случайно. Issue закрыт по политике maintenance mode.
- Refinery одного пользователя сам слил чужие PR через залогиненный `gh` [121].

### Наблюдаемость

- **`.events.jsonl`** — события sling, hook, handoff, done, spawn, kill, nudge, session_death, mass_death, merge, scheduler [94].
- **`gt feed`** — TUI с деревом агентов, панелью convoys и потоком событий. Problems view подсвечивает застрявших (работа на hook, 30 минут без прогресса): attach, nudge и handoff — одной клавишей [61].
- **`gt dashboard`** — локальная страница, по умолчанию 127.0.0.1:8080. Обновляется через server-sent events; опрос htmx раз в 30 с — запасной путь [61][62][190].
- **OpenTelemetry** включается переменными окружения. `GT_LOG_AGENT_OUTPUT` передаёт ходы разговора [45].
- **Атрибуция:** `GIT_AUTHOR_NAME` — identity агента в виде пути, email — владельца. Каждый bead хранит `created_by`, поэтому у каждого агента копится track record для сравнения моделей [21][11].

### Связь с CLI агентов

- **Уровни интеграции** [40]:
  - Tier 0 — любой терминальный CLI через tmux `send-keys` и `capture-pane`;
  - Tier 1 — JSON preset: флаг resume, имена процессов, prompt готовности;
  - Tier 2 — hooks жизненного цикла;
  - Tier 3 — headless-режим или fork.
- **Codex:** hooks по умолчанию нет (запасной путь — nudge при старте), есть subcommand `resume` и `exec` для headless. Opt-in hooks Codex — experimental [40].
- **Собственная критика — design «Factory Worker API»** [30]. Он насчитал 28+ мест, завязанных на Claude Code, tmux, macOS Keychain или раскладку файлов. Среди них:
  - `send-keys` кусками по 512 байт и последовательность «ESC+600ms» для readline;
  - распознавание простоя regex-ом по prompt `❯`;
  - чтение transcript-ов и цены, прописанные в коде;
  - ротация token-ов только на macOS;
  - 10 разных флагов `--dangerously-*`.
- **Что тот же design предлагает:** агенты сами сообщают своё состояние (`started`, `ready`, `busy`, `idle`, `stopping`, `stopped`) через API вместо чтения терминала; структурированные события вместо поиска строк; интерфейсы, не зависящие от агента; один `run_id` на запуск; при неизвестном состоянии — fail-closed [30].
- **ZFC на практике:** правило — Go только транспорт, порогов в Go нет [10]. В коде при этом много порогов времени в виде настраиваемых умолчаний [88].

### Как менялось мнение

1. **Январь, запуск.** Тема на HN — в основном насмешки и сомнения: не сатира ли это; шутки про наркотики; сравнения с крипто; многие возражали, что автор не читал код. Меньшинство ранних пользователей писали отчёты о реальной работе [171]. Главный комментарий на Lobsters назвал проект performance art [180].
2. **Конец января.** Эссе Maggie Appleton определило, как о проекте писали дальше: как инструмент сделан плохо, но полезен как спекулятивный design fiction [164][172].
   - В те же недели meme coin $GAS на крипто-платформе BAGS платил Yegge комиссии с торгов. Appleton со ссылкой на его пост называет около $75 000 [164]. Собственные посты Yegge называют около $300 000 к 2026-01-19 [137][138]. Цифры расходятся.
   - Yegge раскрыл, что монету создал не он, он ею не управляет, и это не доля в компании [137].
   - HN называл это pump-and-dump; обвинение всплывает и в поздних темах [172][173][175][176].
3. **Февраль–март.**
   - Активные пользователи столкнулись с большими расходами и искали обходные пути — например, переводили patrol-роли на дешёвые модели [126].
   - Claude Code выпустил задачи с зависимостями в 2.1.16 (2026-01-22) и research preview agent teams в 2.1.32 (2026-02-05) [170]. Пользователи HN увидели в этом, что платформа забирает идеи Gas Town [172:46734791][177:48021329].
   - Запуск Wasteland на HN в основном высмеяли: называли его growth hack для Dolt и писали, что участие требует нескольких подписок Claude Max [174].
4. **Апрель.**
   - Вышел 1.0. Yegge писал, что он просто работает, стабилен неделями и на нём строят реальные вещи [143].
   - Тема HN спрашивала, что же он реально сделал [175].
   - На следующий день issue #3649 попал на главную HN [176].
5. **Конец апреля — май.** Gas City дошла до 1.0, и Yegge предложил переходить [144]. Issues Gas Town начали закрывать со ссылкой на Gas City [109][114][121]. Заметка об отзывах относит выход Gas City 1.0 к маю, но релиз v1.0.0 датирован 2026-04-21, пост Yegge — 2026-04-24, тема HN — 2026-05-04 [150][144][177].
6. **Июль–ноябрь.**
   - Оставшиеся пользователи пишут, что он так и не начал работать без присмотра [128], что их Mayor всё время пытается чинить сам Gas Town [129], что пакет Homebrew сломан [113].
   - В августе Yegge опубликовал разбор итогов [145][169]:
     - Gas Town перестал нормально работать с приходом Claude Opus 4.7. Модель всё хотела добавить ещё одну вещь и доработать Gas Town и не бралась за реальную работу;
     - добиться, чтобы worker-ы работали всю ночь без постоянного присмотра, так и не удалось;
     - он перестал строить переиспользуемые фреймворки оркестрации;
     - о Gas Town он написал: «I only ever wound up using it to build itself» [145].

### Что хвалят

- **Эксперимент и удовольствие.** Защитники видят в нём игровой эксперимент или design fiction, а не продукт [172:46735034][164]. Некоторым нравятся названия [171:46509159].
- **Mayor экономит чтение.** По словам Yegge, пользователям, особенно нетехническим, нравится говорить с одним агентом, который сам читает вывод worker-ов, — в отличие от длинной ленты текста Claude Code [143]. Он же пишет, что Mayor лучше его worker-ов разбирает входящие PR [142].
- **Память между сессиями.** Один пользователь HN назвал Beads таким же важным изменением, как появление Claude Code. Его привычка — спросить агента, что дальше, и дать ему самому выбрать bead [172:46735601][172:46738868].
- **Устойчивость.** Активный пользователь пишет, что агенты так встроены в систему, что она продолжает работу почти после любой ошибки [176:47788455].
- **Идеи — даже у критиков:**
  - деревья супервизоров и почтовые ящики в стиле Erlang [166][173:46713870];
  - специализированные роли под супервизорами; постоянные identity агентов при одноразовых сессиях; агент очереди слияния [164];
  - комментатор Lobsters увидел в проекте реализацию Viable System Model Стаффорда Бира — кибернетической модели того, как организация сама себя регулирует [181].
- **Скорость, когда работа хорошо делится.** Пользователь сообщает о большом ускорении, если параллельные части потом стыкуются [127].
- **Экосистема сообщества** [122][131][117][142]:
  - web UI и Kubernetes/OpenShift operator;
  - dashboard на 17 страниц с графиками затрат и действиями: nudge агента, перезапуск зависших сессий;
  - cron-скрипты, которые подталкивают застрявшую работу;
  - общий набор workflow — gt-toolkit Dane Poyzer.

### Что ругают

#### Стоимость и потраченные впустую токены

- Launch post предупреждал: Gas Town очень дорогой, Yegge понадобился второй аккаунт Claude [164][171:46508024]. Пост самого Yegge говорит о втором, затем третьем аккаунте [134]. paddo.dev пересказывает пост Yegge в X: он был на третьем плане Claude за $200 в месяц [165].
- Официальных цифр затрат нет; на HN их просили [175:47771856]:
  - один пользователь оценивает работу многих агентов сразу в десятки–сотни долларов в день [115];
  - Appleton оценивает траты Yegge в $2 000–5 000 в месяц [164];
  - DoltHub потратил около $100 примерно за 60 минут — примерно в 10 раз больше обычного Claude Code. Gas Town при этом сам слил PR с падающими тестами [163];
  - **расхождение:** часто повторяемую цифру «$100 в час» один пользователь HN проследил до ответа AI-поиска со слабыми источниками [175:47771274].
- **Потери, заложенные в устройство:**
  - patrol-агенты (Deacon, Witness, Dogs) тратили тот же бюджет Opus, что и worker-ы. У одного пользователя квота на все модели была на 100%, а квота Sonnet — на 2% [126];
  - пользователи винят переписку агентов друг с другом и повторное чтение одного и того же кода [175:47773404][175:47775470];
  - Yegge признаёт, что синхронизация и починка Beads незаметно тратят токены [145].
- **Траты без остановки.** Неудачная установка оставила фоновый процесс в цикле на всю ночь, и он израсходовал лимит Claude пользователя. Исправление убрало один цикл решений AI и ограничило число активных worker-ов 25 на всю установку [119].
- **Цена входа:**
  - Yegge упоминает компании с тремя и более аккаунтами Claude для Gas Town и пользователя с 22 аккаунтами за $4 400 в месяц [140];
  - друга Yegge с 22 планами Max автоматически заблокировал fraud detection Anthropic [138];
  - HN считал, что участие в Wasteland требует нескольких подписок Max [174:47253416].
- **Поздние траты Yegge больше, но это уже не Gas Town: это разработка его игры Wyvern через его новый закрытый orchestrator Wheelhouse** [145][146]:
  - около $87 000 в месяц в пересчёте на цены API (69 млрд токенов в июле);
  - фактически он платит около $2 800 в месяц за 13 аккаунтов Claude Max;
  - когда они исчерпаны, работу берёт резервная группа worker-ов Codex.
- Пользователи Gas City просят watchdog против трат в простое [151].

#### Запустить вообще

- **Mayor работает сам вместо раздачи.** В январе Mayor пользователя делал всю работу сам и вёл себя как обычный `claude` [171:46506903]. В апреле — то же, после поиска совместимой пары версий Dolt и Beads [175:47789079].
- **Worker-ы сразу сдаются.** На v0.11.0 polecat-ы закрывали задачи примерно за 30 с, не написав кода, — каждый раз. Сошлись несколько ошибок, среди них пустой поиск задачи и выход «нечего делать» в prompt worker-а. Починка заняла несколько PR [116].
- **Работа встаёт без присмотра.** Refinery показан как работающий, а 15–20 merge requests часами не тронуты. Вопрос Mayor о ходе работы снова запускал поток. Пользователь писал cron-скрипты с nudge, пока фоновая проверка здоровья раз в несколько минут не сделала их ненужными [117].
- **Трудно остановить.** Сессии оживали после `gt shutdown --nuclear` [118].
- **Регрессии в 1.0.0** и Mayor, который сам заводит issues в upstream [109].
- **Пользователи уходят (июль 2026).** Давний сторонник вернулся к простым агентам. Другой не смог передать worker-у ни одной задачи. Третий назвал систему полной ошибок с самой инициализации: за каждым worker-ом надо следить [128][113].
- **Трудная установка:**
  - `go install` собирает бинарник, который отказывается работать, если собран не через Makefile [114];
  - несовпадение версий gt и bd ломало установки и релизы [113][124].
- **Копится состояние на длинных запусках.** Открытый баг: команда compaction ничего не делает, а десятки тысяч временных записей всё ещё считаются активными [123].
- **Отчёты DoltHub:** Mayor неверно докладывал статус, работа оставалась без push [163].
- **Трудный вход:** новичку надо разобраться во всём сразу, а понятия пересекаются [164].

#### Beads и Dolt как источник проблем

- **Хрупкое управляющее состояние.** Beads хранит роли агентов, workflows и convoys. Если запись роли закрыта или потеряна, агент теряет identity. Convoys зависят от того, что Deacon их опрашивает [110].
- **Отзывы на HN** [173:46714631][173:46715234][175:47770794][175:47772212][175:47773376][171:46510810]:
  - Beads ломается с каждым релизом; у одного пользователя развалился через пару недель;
  - вернуться к Markdown-файлам было легко;
  - много работы с git; смена ветки портит состояние;
  - `doctor` всегда находит проблемы, которые не может исправить;
  - размер Beads — около 225k строк Go для трекера задач — стал постоянной шуткой.
- **Фоновая нагрузка.** Dolt в простое пишет и читает диск со скоростью 3–30 кБ/с. Один пользователь сообщил, что ноутбук сильно греется, и завёл issue в Dolt [175:47772311][175:47773009].
- **Трудно удалить:** агенты снова ставят Beads в проекты [175:47782102].
- **Позиция Yegge.** Он признаёт, что Beads 0.x имел проблемы синхронизации, merge conflicts и поведение «last write wins»; в 1.0 их заменил Dolt [143]. В августе он всё ещё называл Beads немного сырым [145].
- **В Gas City то же** [151]:
  - простаивающая установка запускает 7+ подпроцессов bd в секунду (11 👍);
  - другая — 50–70 процессов в секунду;
  - Dolt разряжает батарею M5 MacBook меньше чем за час.

#### Агенты работают над Gas Town, а не над проектом пользователя

- **Issue #3649** [109]. 72 реакции, из них 40 👍 (2026-11-13). Две цифры из заметок — разные счётчики, а не расхождение [109].
  - Пользователь нашёл, что worker-ы чинят issues самого Gas Town и открывают PR в upstream — от его аккаунта GitHub и на его лимит Claude. Он привёл четыре таких PR.
  - Причина по его разбору — release formulas с жёстко прописанным upstream-репозиторием и инструкции в prompt Mayor. Он просил сделать это opt-in.
  - Другие считали, что это release formula maintainer-а, запущенная случайно.
  - Issue закрыт со ссылкой на Gas City.
- **На HN** мнения разделились: баг или аналог скрытого майнера биткоинов. Многие просили раскрытия и лимитов трат [176].

### С чем сравнивают

- **Свой harness.** Общее мнение: кто успешно работает со многими агентами, тот сделал свой инструмент [175:47773062][175:47773227]. Варианты:
  - главный агент раздаёт работу subagent-ам через маленький CLI [175:47772062];
  - многошаговые workflows с плотными инструкциями [175:47773404];
  - циклы «предлагает — проверяет», где один агент предлагает, а другой проверяет [172:46742140][176:47786938].
- **Встроенное в Claude Code:** задачи с зависимостями и agent teams [170][177:48021329].
- **Простые трекеры:** Linear через MCP, задачи в Markdown-файлах, GitHub issues и PR с CI [175:47771840][172:46739306][179][173:46715234].
- **Названные инструменты:**
  - OpenClaw — по словам пользователя, похож на Gas Town, но навязывает меньше своих решений [176:47787002][174:47250609];
  - Ralph loops — приём, когда агента запускают по кругу на одной задаче, пока она не будет сделана [172];
  - gstack [175:47786720];
  - Overstory [114] и OpenRig [129];
  - Docket — собственный инструмент Klabnik [166];
  - Gas City [144];
  - hosted-версия Kilo: на HN запуск 2026-03-18; сейчас kilo.ai/gastown показывает Kilo Cloud Agents без упоминания Gas Town; закрыта ли она — (не подтверждено) [162][161];

### Gas City — что развивается сейчас

- **v1.0.0 вышел 2026-04-21.** Написали Julian Knutsen и Chris Sells; Yegge говорит, что писал не он [144][150].
- **Устройство.** Gas City — платформа, в которую вынесли механику Gas Town [149]. Она делит Gas Town на декларативные «packs» — наборы агентов, formulas и запусков по расписанию. Pack, повторяющий Gas Town, идёт по умолчанию, поэтому Gas City сначала работает как прямая замена [144][149].
- **Позиционирование:** SDK для компаний, в отличие от Gas Town — эксперимента «Wild West» [144].
- **Релизы** [150]:
  - v1.0 — supervisor API на OpenAPI; MCP-проекция для Claude, Codex и Gemini;
  - v1.3 — Packs v2, включая packs с методологиями работы;
  - v1.4 — dashboard вокруг запусков: живая скорость расхода токенов и оценка темпа трат; runtimes tmux, subprocess, ACP и Kubernetes;
  - v1.5 — процессом Dolt управляет Beads;
  - v1.5.1 — 2026-10-24.
- **Roadmap 1.6** (2026-10-05) [150]:
  - надёжность reconciler сессий;
  - производительность: служебный учёт уходит в локальный SQLite, а версионируемые beads работы остаются в Dolt — частичный отказ от принципа «только Dolt»;
  - вход для новых contributor-ов — людей и агентов.
- **Активность:** 498, 540, 1 081 и 335 коммитов в августе–ноябре [5].
- Жалобы на Gas City — в разделе «Что говорят пользователи» [151].

## Механизмы, которые стоит изучить

1. **План waves до запуска (`gt convoy stage`).**
   - Что: проверка графа зависимостей epic и расчёт waves до того, как что-то раздано.
   - Как работает: строит DAG из связей `blocks` и `waits-for`; отказывает при циклах и задачах без маршрута; считает waves алгоритмом Kahn; показывает дерево, таблицу waves, задачи-сироты и оценку числа worker-ов на wave. Создаёт convoy в состоянии staged, который ещё ничего не раздаёт. Для epic добавляет финальную задачу проверки (`mol-validate-prd`; самой formula в репозитории нет). `gt convoy launch` раздаёт только wave 1.
   - Источник: [24][58][23].
2. **Подача задач по событиям вместо барьера между waves.**
   - Что: следующая задача уходит в работу, как только закрылся её блокер, не дожидаясь конца всей wave.
   - Как работает: ConvoyManager демона раз в 5 с опрашивает события beads и раздаёт готовую задачу. Проверка застрявших convoy раз в 30 с ловит пропуски.
   - Источник: [25][77].
3. **Дисциплина повторов.**
   - Что: предел повторов на задачу, пропуск безнадёжной задачи и передача опыта прошлой попытки.
   - Как работает: лимит повторных запусков на bead — 3, сброс явной командой `gt sling respawn-reset`. В режиме mountain Witness после 3 неудач ставит `mountain:skipped`, и остальная работа epic продолжается. Зависания проверяют новые Dog-агенты со свежим контекстом, потому что состояние — сам epic. При повторной раздаче новый worker получает `prior_branch` и `prior_failure` — ветку и причину закрытия прошлой попытки.
   - Источник: [52][50][59][23][51].
4. **Классы «почему встал» и самоотчёт агента.**
   - Что: типизированная причина остановки сессии вместо общего «завис».
   - Как работает: Witness различает 9 классов zombie — от stuck-in-done до never-heartbeated (например, ошибка 401 на старте). Сессия сама сообщает состояние командой `gt heartbeat --state=working|idle|exiting|stuck`. Правило: не объявлять агента застрявшим по одному сигналу, сначала сверить с активностью tmux. Демон отличает одиночную смерть сессии от «mass death» — 3 смерти за 30 с дают одно событие. В `gt feed --problems` застрявшие видны с порогом 30 минут; nudge, handoff и attach — одной клавишей. Design Factory Worker API предлагает следующий шаг: агенты сами сообщают события жизненного цикла, у каждого запуска свой `run_id`, при неизвестном состоянии — fail-closed.
   - Источник: [81][20][72][71][49][30].
5. **Сохранение незавершённой работы.**
   - Что: работа ticket-а не теряется, если сессия умерла.
   - Как работает: checkpoint dog раз в 10 минут коммитит грязные живые worktree как `WIP: checkpoint (auto)`; позже такие коммиты сжимаются squash-ем. Stop hook `polecat-stop-check` вызывает `gt done`, если сессия закончилась с несданной работой. `.polecat-checkpoint.json` хранит molecule, шаг, файлы, ветку и bead. `gt done` возобновляемый: пройденные стадии записаны как checkpoints; он отклоняет ветку без коммитов и слишком отставшую от target.
   - Источник: [78][73][65][79][53].
6. **Распознавание usage limit и отдельный учёт пауз.**
   - Что: лимит подписки отличается от сбоя и не тратит бюджет перезапусков.
   - Как работает: regex по нижним 20 строкам pane ищет жёсткий лимит и «почти лимит» (например, 80% дневной квоты) и разбирает время сброса с часовым поясом. Пауза по лимиту — фиксированные 60 с, вне бюджета crash loop; в коде её ставит только проверка зависшего Deacon. Сам crash loop: backoff 30 с → 10 минут, 5 перезапусков за 15 минут, сброс после 30 минут стабильной работы. Ротация аккаунтов (минимум 2 аккаунта, только macOS) меняет token в macOS Keychain и перезапускает pane с `--continue`; quota_dog делает это раз в 5 минут, но по умолчанию выключен. На одном аккаунте после сброса лимита работа сама не продолжается — это открытый #1066.
   - Источник: [69][70][76][75][68][71][112].
7. **Заморозка вместо остановки (`gt estop` / `gt thaw`).**
   - Что: остановить всех агентов, не теряя их контекста.
   - Как работает: сигнал SIGTSTP замораживает процессы сессий; можно заморозить один rig; Mayor не замораживается; демон на это время перестаёт перезапускать агентов; `gt thaw` продолжает. В v1.0.0 plugin rate-limit watchdog делал это сам: раз в 3 минуты запрос на 1 token к Haiku, на HTTP 429 — estop, после восстановления — thaw. Его убрали 2026-04-12: probe требовал `ANTHROPIC_API_KEY` и не работал на подписке Claude Max.
   - Источник: [67][49][71][107][3][185].
8. **Быстрое слияние по SHA уже проверенного target.**
   - Что: не запускать gates повторно, если main не менялся с момента проверки worker-ом.
   - Как работает: `gt done --pre-verified` записывает SHA target-ветки. Пока HEAD target тот же, Refinery сливает без повторных gates — по словам авторов, примерно за 5 секунд. Рядом: фаза `post-squash`, которая проверяет ещё раз после squash; lock «merge slot», который пропускает push-и в main по одному; сверка SHA локальной и удалённой веток после push; test run на main раз в 30 минут.
   - Источник: [99][83][100][80].
9. **Lenses review как параллельные worker-ы и режим «только измерять».**
   - Что: review разбит на 10 независимых взглядов, а новый критерий качества сначала только измеряется.
   - Как работает: formula `code-review` запускает 10 reviewer-ов отдельными worker-ами. Каждый пишет в свой файл, затем шаг синтеза сводит результаты. Кроме обычных lenses есть wiring (зависимость установлена, но не подключена), commit discipline и test quality. quality-review ставит каждому слиянию оценку 0–1 и записывает её, но не блокирует; ниже 0,45 — «breach».
   - Источник: [103][100][98].
10. **Разная доставка сообщений агентам.**
    - Что: явный выбор, прерывать ли агента и должно ли сообщение пережить его сессию.
    - Как работает: nudge в режиме `wait-idle` ждёт prompt; в режиме `queue` пишет в JSON-файл, который UserPromptSubmit hook разбирает на границе следующего хода (срок жизни 30 минут или 2 часа для срочных, не больше 50 в очереди); в режиме `immediate` вводит текст через `send-keys` и прерывает агента. Mail создаёт bead и нужна только для того, что обязано пережить смерть сессии получателя; у каждой роли бюджет писем.
    - Источник: [66][28][49].
11. **Дешёвое наблюдение в простое.**
    - Что: агенты-наблюдатели тратят мало токенов, когда работы нет.
    - Как работает: `gt mol step await-signal` ждёт активности beads с backoff от 30 с до 5 минут. После циклов без работы patrol идёт в сокращённом режиме (`EFFORT: reduced`, цель — около 10% токенов полного). Cost tiers отправляют patrol-роли на Sonnet или Haiku. Набор promptfoo из 94 случаев проверяет, принимают ли дешёвые модели те же решения, что Opus. По changelog простаивающие rig-и стали дешевле примерно на 66%.
    - Источник: [101][87][48][8].
12. **Контекст между сессиями: handoff, seance, typed memories.**
    - Что: способы перенести знание из одной сессии агента в другую.
    - Как работает: `gt handoff --collect` собирает задание, inbox и готовые задачи в письмо и перезапускает сессию со свежим контекстом (не чаще раза в 2 минуты); PreCompact hook снова вставляет контекст роли. `gt seance --talk <id>` делает fork прошлой сессии через `claude --fork-session --resume` и задаёт ей вопрос, не меняя оригинал. `gt remember --type feedback|user|project|reference` хранит память в beads и вставляет её при старте сессии, feedback — первой.
    - Источник: [55][89][56][57].
