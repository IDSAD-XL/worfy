## Модель работы

**Local / cloud / hybrid: hybrid.**

- Облако HumanLayer — слой управления [22][34][35]:
  - API — `riptide-api.humanlayer.com`;
  - потоки sessions — `sync.humanlayer.com`. Там работает ElectricSQL — движок, который синхронизирует строки
    Postgres в клиентов;
  - веб-приложение — `app.humanlayer.com`;
  - консоль администратора — `cloud.humanlayer.com`;
  - вход — через WorkOS, сервис аутентификации.
- Агенты всегда работают на host — машине, которой владеет пользователь или команда. Desktop app запускает локальный
  daemon. Remote daemon ставится через CLI на любую машину [22].
- Вызовы моделей HumanLayer не проксирует. Агент на host обращается к провайдеру напрямую [29].
- Своих машин для запуска агентов HumanLayer не даёт:
  - cloud daemons на сайте — это daemons на собственных VM или sandbox клиента [1];
  - skill `/hl:teleport` перечисляет Freestyle, Daytona, E2B, Modal, EC2/GCP и любую машину, доступную по SSH или
    Tailscale [74];
  - managed compute — машины, которыми управляет сам вендор, — в источниках не найден (не подтверждено).
- Prompts, сообщения, задачи и approvals хранятся в облаке HumanLayer [181]. Режима без облака нет. On-prem и
  air-gapped (без связи с интернетом) — только на Enterprise [181][1].
- Окружения [34]:
  - production — `*.humanlayer.com`, beta — `*.codelayer.cloud`;
  - у них разные базы и аккаунты. Integrations подключаются в каждом окружении заново;
  - beta app ставится рядом с основным как `HumanLayer-Beta.app`.
- Self-hosting:
  - по посту об открытии кода, файл Docker Compose, скорее всего, уже работает [2];
  - инструкции для своего запуска ещё пишутся [35];
  - нужны ключи сторонних сервисов: WorkOS, Slack, Linear и других [2].
- Enterprise: on-prem или частный VPC [1].
- Телеметрия — заметки расходятся:
  - по заметкам о функциях, сборка из исходников ничего не отправляет вендору [35], а daemon из npm не шлёт
    телеметрию ошибок [22];
  - по заметкам о коде, daemon отправляет ошибки в Sentry и пишет структурированные logs с traces в
    `~/.humanlayer/riptide/logs` [36][50].

**Агенты и модели.**

- Daemon запускает три агента [57][56]:
  - `claude` — Claude Code через Claude Agent SDK, библиотеку Anthropic для запуска Claude Code из кода [62];
  - `codelayer` — собственный harness HumanLayer для моделей OpenAI Codex [17];
  - `fold` — экспериментальный harness [60].
- Ещё четыре значения — только mirror: `pi`, `opencode`, `codex`, `claude-code`. Такие sessions человек запускает сам
  в своём терминале. Приложение их показывает и позволяет ими управлять, но не запускает [57][56][70].
- **Claude Code:**
  - с 0.144.0 — единственный harness для моделей Anthropic [11];
  - использует установленный `claude` и его вход, то есть подписку пользователя. Путь к бинарю меняет
    `HUMANLAYER_CLAUDE_PATH` [11];
  - работает и через AWS Bedrock [28], и через LLM gateway [29];
  - окна подписки (5 часов, 7 дней, недельные окна по моделям) учитываются по каждому host [66][65].
- **Codex:**
  - документация пишет, что Codex sessions идут через CodeLayer [17];
  - вход — `humanlayer agents auth codex login`, через браузер или device code [27];
  - можно задать свой endpoint Responses API переменными `CODELAYER_CODEX_*`: Bedrock, Azure AI Foundry или OpenAI
    API [27];
  - разговоры Codex хранит HumanLayer, локальные файлы для них не нужны [22];
  - по коду, daemon запускает собственные пакеты агента HumanLayer, которые обращаются к Codex/Responses API, а
    вход через device code ChatGPT выполняет сам daemon. Бинарь Codex CLI не запускается [67][68]. В заметках о
    функциях это записано как вывод из документации [17][22][27]; заметки о коде подтверждают его по исходникам.
- **Fold** (эксперимент Use Fold Coding Agent):
  - новые Codex sessions идут на Fold вместо CodeLayer [60];
  - провайдеры — `codex` и `xai`, модели Grok 4.5 и 4.6 [58][11];
  - Fold ведёт durable event log — журнал событий, который переживает перезапуск. Каждый prompt берёт эксклюзивный
    claim (право на обработку) на session [69];
  - отдельный репозиторий `humanlayer/fold` описывает Fold как ядро агента на TypeScript-библиотеке Effect, не
    привязанное к провайдеру; у репозитория 182 звезды [115][112].
- **Провайдеры в схеме** — `anthropic`, `copilot`, `codex`, `firepass` (router Fireworks, например для Kimi) и `xai`
  [58]:
  - интерфейс для работы не на Claude показывает только Codex, а с включённым Fold — ещё xAI [58];
  - Copilot и Firepass после 0.144.0 (2026-07-23) только отображаются как legacy: этот релиз убрал альтернативных
    провайдеров CodeLayer [58][11];
  - CLI `automation run` их ещё принимает [59];
  - сайт всё ещё пишет, что Copilot и Fireworks поддерживаются [1].
- **Модели в выборе:**
  - Claude — алиасы OPUS, SONNET, HAIKU, FABLE и версии: Opus 4.5–5.5, Sonnet 4.6–5.5, Haiku 4.5, Fable 5 и 5.1 [58];
  - Codex — от GPT-5.4 до GPT-6.1 Sol. GPT-6.1 Sol стоит по умолчанию с 0.180.0 [58][11].
- **Effort** — сколько модель рассуждает: low, medium, high, xhigh, max. У Codex есть Fast Mode [59][27][11]. По
  умолчанию для Claude — high [62].
- **Режимы разрешений:** `default`, `accept_edits`, `auto` (auto mode самого Claude Code), `bypass` (без запросов)
  [73][57][56]. Выбор Opus 4.8 переключал session в auto mode Claude Code (0.131.3) [11]. Automation-запуски идут без
  запросов разрешений [26].
- **Запасная модель:** если модель отказывает и есть запасная (например, Fable 5 → Opus 4.8), session продолжает на
  запасной (0.128.0) [11].
- **Передача между вендорами:** session можно перевести с Claude Code на Codex и обратно. Новая session продолжает ту
  же задачу в том же worktree с полным transcript (0.179.0) [11].
- Чего нет:
  - локальные модели вендор отклонил в ноябре 2025 как недостаточно хорошие для реальной работы с кодом [208];
  - Cursor — в roadmap без даты [187]. Agent Client Protocol (ACP — общий протокол подключения агентов к редакторам)
    вендор отверг как слишком узкий для hooks HumanLayer [187];
  - OpenCode как backend выбрать нельзя, есть только mirror [170][71].

**Один пользователь или команда.**

- Продукт сделан для команд: организации, общий доступ к задачам, комментарии, multiplayer prompting, метрики, Slack,

## Функции

### Основные объекты

Продукт работает с пятью объектами: Task, Session, Workspace, Project и Host [13][73].

**Task** — одна единица работы. Это группа sessions, общие файлы задачи, комментарии и review, история, которая
продолжается через агентов и машины [13].

- Файлы задачи лежат в `.humanlayer/tasks/<slug>/` (slug — короткое имя задачи для путей и веток). Это symlink на
  `~/.humanlayer/riptide/artifacts/<task id>/`. Daemon добавляет папку в `.gitignore` [13][22][70].
- Эти файлы продукт называет artifacts. Что синхронизируется в облако [13]:
  - Markdown (`.md`, `.mdx`), plain text и JSON/JSONL — как текстовые artifacts, до 10 MB каждый;
  - изображения, PDF и HTML — через object storage;
  - только файлы, которых агент коснулся своими файловыми инструментами: Read, Write, Edit, MultiEdit, apply_patch.
    Это не backup репозитория.
- Системный prompt запрещает агенту править artifacts через Bash, Python или sed. Так интерфейс видит каждое
  изменение [18].
- Доступ задаётся на задачу. С правом edit можно добавлять sessions и менять файлы задачи [13].

**Session** — один разговор: свой агент и модель, рабочий каталог, сообщения и состояние запуска [13].

- Статусов 13: `draft`, `ready_for_launch`, `launching`, `running`, `ready_for_input`, `needs_approval`,
  `waiting_for_usage_limit`, `interrupt_requested`, `interrupted`, `resuming`, `failed`, `waiting_for_workspace`,
  `lost` [46][55][57][73].
- Session, брошенная из-за обрыва daemon, получает статус `lost`. Её можно продолжить (0.160.0) [11].

**Workspace** — один или несколько git worktrees задачи.

- Время создания worktree выбирается на задаче: Now, Later или Never [16].
- Конфиг — `.humanlayer/workspace.json` (общий для команды) и `workspace.local.json` (для одной машины) [21]. Поля:
  - `disabled` и `setupBlocksFirstSession` (первая session ждёт окончания setup);
  - `pathTemplate`, по умолчанию `~/.humanlayer/workspaces/{{TASKSLUG}}/{{REPOBASENAME}}`;
  - `branchTemplate`, по умолчанию — slug задачи;
  - `sourceRef` — от какой ссылки git создавать ветку;
  - `setupCommand` — выполняется через `sh -c` после копирования файлов;
  - `copyGlobs` — какие файлы скопировать в worktree. Список только дополняется. По умолчанию в нём варианты `.env`
    и `.claude/settings.local.json`;
  - `repos` — записи с `localPath` и флагом `primary`.
- Multi-repo [20][18]:
  - по worktree на каждый репозиторий, все в одном каталоге задачи;
  - session стартует в основном (primary) репозитории;
  - skills и файлы CLAUDE.md/AGENTS.md грузятся из всех репозиториев;
  - настройки Claude и конфиг MCP берутся только из каталога запуска.
- `/rpi:configure-workspace` готовит конфиг, показывает предлагаемый JSON и спрашивает перед записью [16][19].
- Workspace фиксирует commit своего первого успешного setup (0.161.0). Новые конфиги стартуют с `origin/main`
  (0.160.0) [11].
- С 0.201.0 минималистичный интерфейс по умолчанию даёт задачам из каталога свой worktree. Вариант In this directory
  правит файлы на месте. Выбор запоминается для каждого каталога [11].

**Project** (Projects V2) — сохранённый список репозиториев [73].

- В каждой записи: удалённый адрес репозитория (remote identity), ветка по умолчанию, `autoPushBranch`, copy globs и
  setup command [73].
- У каждого пользователя и host есть repository sources — откуда брать репозиторий: существующий checkout
  (`filesystem`) или `managed_clone` (клон, которым управляет HumanLayer) [73].
- Host может сам клонировать репозиторий, создать ветку и выполнить setup. Session можно перенести на другой host с
  запушенной ветки. Незапушенные изменения остаются на первом host [73].
- Переключатель эксперимента предупреждает: выключить Projects V2 в организации потом нельзя [60].

**Host** — любая машина, где работает daemon. Раздел Settings → Hosts (до 0.183.0 назывался Daemons) показывает
статус Online, Stale или Offline [11][25].

### Workflows и skills (семейство RPI)

**Workflows** [16]:

- RPI: вопросы → research → design discussion (обсуждение решений) → structure outline (план по фазам) →
  implementation → PR.
- PRD-Oriented: то же, но вместо design discussion идут PRD (product requirements document, документ требований
  продукта) и TDD (technical design document, документ технического дизайна).
- Oneshot: implementation → PR.
- Freeform: без фиксированных фаз.
- RPI стоит по умолчанию с 0.101.7 [11].
- Сайт показывает ещё RPI Outline и продаёт шесть фаз под именем QRSPI: Questions, Research, Design, Structure, Plan,
  Implement [1]. В документации у RPI по умолчанию отдельного детального шага Plan нет. Сайт и документация здесь
  расходятся [1][16].

**Skills** [16]:

- 22 skills, вызов — `/rpi:<имя>`.
- Пары create и iterate (создать и доработать): research questions, research, design discussion, PRD, TDD, outline,
  plan. Путь через plan — legacy.
- Одиночные skills: `configure-workspace`, `create-worktree`, `implement-plan`, `implement-outline`,
  `iterate-implementation`, `describe-pr`, `ci-commit`, `review-artifact-comments`.
- Artifacts нумеруются `NN-…`. Если они расходятся, побеждает более поздний: plan > outline > TDD > PRD > design
  discussion > research > ticket [16]. Skill реализации по outline задаёт короткую цепочку: outline > design >
  research > ticket [78].

**Где агент обязан ждать человека** [16][15]:

- Решения в design discussion остаются открытыми, пока пользователь не ответит ясно.
- PRD задаёт один вопрос за сообщение и может рисовать HTML-макеты.
- TDD задаёт один вопрос за сообщение и требует двух отдельных одобрений: System Design и Program Design. Может
  рисовать HTML-диаграммы.
- Отзыв на outline никогда не запускает реализацию.
- Реализация останавливается для ручной проверки после каждой фазы и коммитит каждую фазу.

**Auto-advance** — автоматический переход к следующей фазе [16][73]:

- Флаги на задаче покрывают пять переходов:
  - вопросы → research;
  - research → design discussion или PRD;
  - plan → worktree или implementation;
  - setup worktree → implementation;
  - implementation → PR.
- Четыре перехода никогда не идут сами: design → outline, PRD → TDD, TDD → outline и outline → implementation.
- Каждый переход срабатывает один раз.
- Skill orchestrate предлагает значения флагов по умолчанию для каждого workflow [73].
- Если подключён Linear, старт фазы переводит issue в состояние этой фазы [31].

**`/rpi:describe-pr`:**

- находит или создаёт PR. Коммитит и пушит, если ясно, кому принадлежит ветка [16];
- пишет `pr-description.md` [16];
- добавляет `pr-walkthrough.html` — HTML-обзор изменений, если PR трогает не меньше 300 строк в не меньше 5 файлах
  [16];
- с 0.182.0 следит за CI checks, чинит падения, которые вызвал PR, и спрашивает одобрения перед разрешением merge
  conflicts [11].

**Служебные команды:**

- `/rpi:show-me` — компактные диаграммы, деревья и наброски (0.154.0) [11][5];
- `/bro` — пересказывает последнее сообщение агента простыми словами (0.147.0) [11].

**Subagents** [17][80]:

| Subagent | Модель |
| --- | --- |
| codebase-analyzer, codebase-locator, codebase-pattern-finder | Sonnet; Haiku, если включён Faster Research Subagents |
| web-search-researcher | Sonnet |
| implementer-agent | Sonnet |
| implementation-reviewer | Sonnet |
| outline-implementer-agent | модель родителя |

- `implementation-reviewer` сравнивает сделанное с планом, чтобы написать описание PR. Качество кода он не проверяет
  [80].
- У Codex все дочерние агенты берут GPT-модель родителя с effort low. Исключение — outline implementer: он сохраняет
  effort родителя [17].
- Ещё о subagents [11]:
  - вложенность в CodeLayer — не глубже 3 уровней (0.161.0);
  - subagent можно продолжить после завершения или сбоя (0.155.0);
  - subagents Codex наследуют контекст вызывающего агента (fork), а не стартуют с нуля (0.155.0).

**Добавки в системный prompt** [18]:

- mermaid-диаграммы рисуются в интерфейсе;
- Claude Code не должен запускать subagents в фоне;
- каталог artifacts задачи и его правила;
- описание multi-repo workspace;
- статус setup workspace.

**Свои skills пользователя:**

- FAQ сайта говорит, что HumanLayer работает над тем, чтобы пользователи приносили свои skills и workflows [1].
- Фактически daemon sessions уже грузят то, что есть в репозитории и у пользователя:
  - skills репозитория сразу появляются в slash-меню (0.181.0) [11];
  - daemon sessions грузят установленные пользователем plugins Claude Code [70];
  - CodeLayer читает skills из `.codex/skills`, `.agents/skills` и `.claude/skills` и предпочитает AGENTS.md файлу
    CLAUDE.md (0.149.0) [11].
- Публичный набор `humanlayer/skills` (`npx skills add humanlayer/skills --skill rpi|show-me|visual-pr|improve-claude-md…`)
  работает в любом агенте [113]. Его skill `/rpi` v1.1.0 (2026-11-01) теперь называется Research, Design, and
  Implement. Каждая фаза идёт в свежей session. Добавлен проход, который делает каждый документ короче и нагляднее
  [113].

### Review diff

- Diff задачи — рабочее дерево против базы. Он пересобирается после каждой записи, правки или shell-команды агента и
  стримится в облако [70][11].
- Совместный просмотр diff стоит по умолчанию с 0.162.0. Нужен worktree со временем создания Now [11][60]. Что есть
  [11]:
  - ветки комментариев на строках с ответом и resolve. Отзыв уходит агенту;
  - клавиши `j`/`k`, `n`/`p`, `h`/`l`;
  - отметка файлов как просмотренных пачкой, фильтр «только непросмотренные»;
  - при повторном открытии файла видно только то, что изменилось с прошлого review;
  - просмотр целого файла и дерево папок со счётчиками комментариев и отметками о просмотре;
  - сортировка файлов по последнему изменению агента;
  - копируемые ссылки на заголовок файла или на комментарий;
  - полноэкранный review с панелью комментариев и diff в стиле GitHub.

### Команда и совместная работа

- **Видимость:**
  - с 0.162.0 задачи по умолчанию видны всей организации [11]. Issue #1117 жалуется на эту принудительную видимость
    [171];
  - доступ задаётся на задачу. С правом edit можно добавлять sessions и править файлы задачи [13].
- **Multiplayer prompting** — несколько людей ведут одну session:
  - запущенной session можно поделиться на заданное время. Коллеги пишут prompts, прерывают ход и решают approvals.
    У каждого сообщения виден отправитель. Включает администратор (0.160.0) [11];
  - общий черновик prompt показывает курсоры с именами и присутствие коллег (0.175.0) [11][61].
- **Владение и доски:**
  - владение задачей можно передать (0.160.0) [11]. Workspace задачи на машину нового владельца не переносится
    (#1154) [162];
  - доска Mine/Everyone и общие projects (0.182.0) [11].
- **Администрирование:**
  - участники, приглашения, запросы на доступ, отключение и возврат участников (0.138.0) [11][105][61];
  - администраторы могут переименовать или архивировать чужие задачи (0.137.0) [11].
- **Метрики:**
  - командные: weekly active users, метрики совместной работы, выгрузка CSV, детализация по пользователю (0.105.0)
    [11][105];
  - Advanced Metrics на Pro и Enterprise (0.169–0.175) [11][105]:
    - задачи по расходу токенов или по стоимости;
    - каждый столбец делится по агенту, модели, фазе, человеку или режиму;
    - тренды по дням;
    - доступ можно открыть всем участникам;
  - стоимость записывается на того, кто запустил session (0.179.0) [11].
- **Context Shards** — на Pro продаются как Compounding Engineering, то есть знания, которые копятся в организации.
  Ранний доступ с 0.164.0 [11][92][1]:
  - shard — короткая инструкция с объяснением и до 5 цитат из прошлых сообщений как доказательство;
  - администратор проверяет shards и выпускает их в организацию. Пользователь включает или отклоняет каждый;
  - shards вставляются в системный prompt только при свежем запуске session. По заметкам о направлении, daemon
    вставляет до 100 shards за запуск [92][63][11];
  - где код генерации — заметки расходятся. Заметки о функциях читали таблицу shards и код daemon и пишут, что кода,
    который создаёт shards, в открытом репозитории нет (не подтверждено) [92]. Заметки о коде называют третий файл
    того же источника, `packages/ai/src/agents/context-shards/generate-context-shard-candidates.ts`: там LLM отбирает
    правила из прошлых разговоров [92].
- **HumanLayer Library Researcher** (эксперимент): поиск по зависимостям и библиотекам, который бережёт контекст.
  Работа уходит в облачный agentic workflow HumanLayer [60][17].

### Hosts, удалённая работа и автоматизация

- **Remote daemon** [23][24]:
  - установка: `npm i -g @humanlayer/cli`;
  - затем `humanlayer login` (device flow) или `daemon launch --launch-token` с токеном из Settings;
  - daemon сам не перезапускается после падения. Документация даёт рецепт user service для systemd.
- **Сеть:** только исходящий HTTPS — к API, sync, WorkOS, GitHub, npm registry и endpoints моделей [22].
- **Хранение и сбои** [22]:
  - в контейнере вход сохраняется, если сохранить `HUMANLAYER_RIPTIDE_HOME` и файл `host_id`;
  - Claude Code для продолжения разговора нужен каталог `~/.claude`;
  - host можно усыпить, пока его sessions ждут ввода;
  - если daemon молчит около 2 минут во время работы или approval, session помечается `failed`.
- **Обновления:**
  - приложение само обновляет daemons, поставленные через npm. На Windows daemon обновляют вручную [23];
  - флаг `--no-self-update` держит версию CLI, закреплённую в образе sandbox [23][11].
- **Управление hosts:**
  - эксперимент Host load: CPU, память, нагрузка, диск и самые тяжёлые процессы на каждом host [60][11];
  - локальный daemon можно выключить (0.183.0) [25];
  - удалённые hosts в sidebar помечены значком облака (0.160.0) [11].
- **`/hl:teleport`** переносит задачу на другой host за один проход [74][11]:
  - задаёт все вопросы в начале;
  - коммитит и пушит незакоммиченную работу;
  - копирует выбранные пользователем файлы с секретами. Называет ключи, значения не печатает;
  - ставит агентов на новом host и входит в них;
  - пишет `handoff.md` и запускает там новую session.
- **`/hl:orchestrate`** — skill, который через CLI `humanlayer api …` смотрит projects, создаёт задачи в своих
  worktrees, ставит auto-advance, запускает sessions, проверяет статусы и PR, переносит artifacts [73][11]. Правило
  skill: у каждой задачи свой worktree, две задачи в одном checkout не запускать [73].
- **`humanlayer automation run`** [26]:
  - входит по PAT и на время задания поднимает свой daemon;
  - при первом запуске с `--ensure-task` создаёт задачу, при следующих использует её снова;
  - `--shutdown-on inactivity` (по умолчанию после 2 минут простоя, чтобы follow-up из веба ещё работали) или `stop`;
  - exit code отражает результат session;
  - запуски идут в режиме `bypass`, без запросов разрешений;
  - в документации есть пример для GitHub Actions и шаблоны повторяющихся агентов: расписание cron; guard, который
    пропускает запуск, пока открыт PR агента; concurrency group; файл памяти агента; цикл `/iterate` по комментариям к
    PR.

### Лимиты подписки и стоимость

- **Счётчики:** окна Claude на каждом host — 5 часов, 7 дней, 7 дней для Opus и Sonnet, по моделям. Это полосы,
  которые становятся янтарными после 80% [66][65][61]. Предупреждения начинаются с 80% (0.182.0) [11].
- **Парковка на лимите:** когда Claude Code ставит ход на паузу из-за отказа по лимиту, session получает статус
  `waiting_for_usage_limit`. Она возвращается в `running`, когда ход продолжается после сброса (0.179.0)
  [66][65][11].
- **Но** пользователь в #1164 (2026-11-12) пишет, что после исчерпания лимита продолжает session вручную [160]. Как
  работает парковка и почему она срабатывает не всегда — в разделе об устройстве.
- Лимиты Codex не отслеживаются: схема лимитов — только для Claude [66].
- Не найдено: планирования запусков под лимиты подписки и политики автоматических повторов при ошибках API.
- Счетов за токены нет: своя подписка или свои ключи [1].

## Принципы и подходы

HumanLayer описывает себя как multiplayer control plane для команды: «The multiplayer control plane for your software
factory» — так написано на сайте [1]. Это multiplayer IDE для coding-агентов плюс облако. Sessions агентов, документы
плана и diff кода собраны в одно общее рабочее место команды [1][126]. Продукт продаётся частями: можно принести свои
машины, своё окружение разработки и свой harness агента или взять весь стек HumanLayer [1][126].

### Канон: заявленная философия по порядку

**12-Factor Agents (апрель 2025)** [116][140]:

- Хорошие production-агенты — это в основном детерминированный код, где шаги LLM стоят в выбранных местах. Это не
  просто цикл над набором инструментов.
- Среди factors (принципов):
  - свои prompts;
  - свой context window;
  - обращение к людям через tool calls;
  - маленькие узкие агенты;
  - запуск, пауза и продолжение через простые API;
  - агент как stateless reducer — функция без своего состояния, которая из истории событий получает следующий шаг.
- Factor 3 говорит: всё — это context engineering.
- У репозитория около 27,2 тыс. звёзд [112][116].

**Advanced context engineering и RPI (август 2025; доклад в YC 2025-08-20)** [117][139][7]:

- Frequent intentional compaction — частое осознанное сжатие контекста. Весь workflow строится вокруг управления
  контекстом. Заполнение держат около 40–60%. Прогресс сжимают в Markdown-файлы, с которых стартует свежая session.
- Workflow: research → plan → implement. Git worktree нужен только шагу implement.
- Human leverage — где человек влияет сильнее всего. Одна плохая строка research даёт тысячи плохих строк кода, одна
  плохая строка плана — сотни. Поэтому review человека идёт на research и планы.
- Mental alignment: главная задача code review — держать команду в курсе того, как меняется код. У HumanLayer эту
  роль теперь несут spec, планы и research.
- Заявления того времени:
  - команда перестала читать каждую строку PR, spec — источник истины;
  - команда из трёх человек тратила около $12 тыс. в месяц на Opus;
  - coding-агенты станут commodity, а трудная часть — изменить то, как работают команды.

**No Vibes Allowed (AI Engineer Code Summit, ноябрь 2025)** [132][131]:

- Dumb zone — зона, где результаты хуже, потому что контекст заполнен.
- Около 40% заполнения — мягкий ориентир, а не жёсткий порог.
- Subagents — изолированные контексты для исследования, которые возвращают короткие выводы. Это не ролевые
  персонажи.
- Инструкции репозитория раскладывают по уровням. Агент грузит только то, что относится к текущей области
  (progressive disclosure).
- Агенты усиливают суждение человека, но не заменяют его. В главах доклада есть раздел о том, чтобы не отдавать
  агенту думание.
- Около 689 тыс. просмотров [132].

**Everything We Got Wrong About RPI (Coding Agents Conference, 2026-03-03)** [134][142]:

- По аннотации организаторов, RPI давал обратный эффект, когда команды отдавали агентам думание.
- Исправление — QRSPI: меньше «магических» prompts, больше структуры, больше владения решениями у человека.
- Фазы QRSPI: Questions, Research, Design, Structure, Plan, Implement [1].
- Обзор Riptide за февраль 2026 уже показывает этот поток [141]:
  - сначала пишутся вопросы, и research идёт в свежем контексте, не видя ticket;
  - design discussion — самый важный документ;
  - structure outline состоит из вертикальных срезов;
  - потом построчный план, worktree, реализация и PR.
- Дата доклада в заметках расходится. По заметкам о направлении — 2026-03-03, выложен 2026-03-24 [134]. По заметкам о
  коде страница ресурсов HumanLayer датирует его 2026-04-20 [4]. 2026-04-20 — это дата keynote на AIE Miami, на
  который ведёт ссылка QRSPI с сайта [142].

**Why Software Factories Fail: harness engineering is not enough (эссе 2026-07-22; keynote на AI Engineer World's
Fair)** [118][133]:

- Тезис: lights-off software factory — фабрика софта, где код никто не читает, — не работает.
- HumanLayer сам работал так с июля 2025. Во время сбоев команде пришлось разбираться в коде, который она перестала
  читать.
- Почему не работает: coding-модели обучают на наградах вида «tests прошли, ничего не сломалось». Плохой дизайн, цена
  которого видна через месяцы, в такой награде не штрафуется. Больше review-ботов поднимают нижнюю планку качества, но
  не верхнюю.
- Решение — вернуть людей и планировать до кода, в четыре шага:
  1. product review: проблема, мера успеха, HTML-макеты;
  2. system architecture: контракты, схемы, sequence diagrams;
  3. program design: типы, сигнатуры, деревья вызовов, diff дерева файлов;
  4. vertical slices — срезы, которые человек может запустить или проверить через `curl` на каждом шаге, вместо
     планов по слоям.
- Грубое деление: около 40% задач делаются за один раз (one-shot). Средним задачам хватает одного документа плана.
  Большим нужны все шаги.
- Review по выбору автора: пройти spec с тем, кто будет смотреть PR.
- Цель — в 2–3 раза быстрее при том же качестве, а не в 10–100 раз.
- Совет в конце: знать пределы моделей, оптимизировать внутри них, искать leverage, читать код.
- Названное направление продукта: building blocks (готовые части) для software factory и лучшие verifiers
  поддерживаемости кода, возможно — лучшие модели.
- Сопутствующее эссе: написание кода и до AI занимало 25–50% времени работы над фичей. Выигрыш — в ускорении
  планирования и согласования [119].

**Измерения (июль–октябрь 2026)** [120]:

- Dex публикует результаты повторных запусков SlopCodeBench. Этот benchmark добавляет требования по этапам и
  проверяет, что старое поведение продолжает работать.
- Результаты октября 2026: frontier-модели проходят все tests на checkpoint (strict pass rate) только в 12–16%
  случаев.
- Средний effort иногда обыгрывал extra-high при цене в 2–4 раза ниже.
- Вывод Dex: модели становятся лучше в поддержке кода со временем, но медленно.

**Принципы, записанные в самом продукте:**

- Сайт [1]:
  - не отдавать агенту думание;
  - каждая фаза — место, где можно возразить;
  - ловить ошибки до того, как они станут 2000 строк кода;
  - design doc — интерфейс к коду, а не отдельный документ;
  - продукт opinionated (с жёсткими мнениями о том, как работать): запуск за 10 минут, prompts терпят разный ввод,
    сам HumanLayer строится в HumanLayer.
- Страница установки [106]: «путь HumanLayer» — двигаться быстро, искать leverage, владеть кодом. Она просит вложить
  время в новый способ работы и делиться design docs с будущим reviewer PR.
- Документация [15][16][14]:
  - агенты пишут код быстрее, чем люди успевают его смотреть, поэтому решения переносятся раньше;
  - брать самый короткий workflow, который контролирует главный риск;
  - checkpoints оставляют решения о продукте и дизайне за пользователем;
  - поздние artifacts важнее ранних, а живой код важнее любого документа.
- Процесс contributions следует тому же правилу [44]. Внешний автор сначала делает design discussion через RPI, где
  решены все вопросы, и открывает proposal. Только после этого maintainer за него ручается через инструмент Vouch
  (автор — Mitchell Hashimoto), и PR этого автора остаются открытыми.
- Backpressure — контроль объёма вывода [8][93][9]:
  - checks печатают одну строку при успехе и полный вывод при сбое;
  - в их репозитории запрещено передавать вывод tests в `head` или `grep`;
  - Stop hook их репозитория запускает quality checks и typecheck и при сбое выходит с кодом 2, чтобы агент чинил.
- Fork session — это снять ходы с конца контекста. Середину контекста не правят никогда [6].

**Как менялась позиция меньше чем за год:**

- август 2025: можно не читать каждую строку, spec — источник истины [117];
- март 2026: RPI позволил командам отдать думание агенту [134];
- июль 2026: читать код; добавить program design и vertical slices [118].

### Ключевые понятия

- **Метод:**
  - context engineering, frequent intentional compaction, dumb zone [116][117][132];
  - RPI и QRSPI, research questions, design discussion, structure outline, program design, vertical slices;
    workflows Oneshot, RPI, PRD-Oriented, Freeform [1][16][118];
  - lights-off factory [118].
- **Объекты продукта:**
  - Task — группа sessions плюс файлы задачи, комментарии, история и владелец [13];
  - Session — один разговор агента [13];
  - Artifact — пронумерованный файл в `.humanlayer/tasks/<slug>/`. Синхронизируется, когда агент трогает его
    файловыми инструментами [16][13];
  - Workspace — один или несколько git worktrees задачи, конфиг в `workspace.json` и локальный файл поверх него
    [11][16];
  - Host и daemon — локальный, удалённый или временный daemon для CI; launch tokens для запуска [22][26].
- **Управление потоком:**
  - skills `create-*` и `iterate-*` [16];
  - auto-advance, который никогда не проходит design → outline → implementation без человека [16][15];
  - цепочка приоритета artifacts: plan > outline > TDD > PRD > design discussion > research > ticket [16];
  - время worktree: Now, Later, Never [16].
- **Совместная работа:** review через комментарии к artifacts и diff; multiplayer prompting (общий живой черновик
  prompt); публичные ссылки на review; передача владения задачей [1][11].
- **Знания:** Context Shards — сгенерированные заметки организации со ссылками на прошлые sessions; на Pro продаются
  как Compounding Engineering [11][92][1].
- **Skills HumanLayer:** `/hl:orchestrate` (разбить работу, запустить задачи в своих worktrees, следить за PR),
  `/hl:teleport` (перенести задачу на другой host), `/rpi:show-me` (наглядные объяснения), `/rpi:describe-pr` [11].

### Чем подход отличается

1. **Checkpoints человека до кода, а не автономия.** Самая резкая публичная позиция HumanLayer — против lights-off
   фабрик [1][118]. Auto-advance нарочно останавливается на design и outline [16].
2. **Документы как общий интерфейс.** Команда вместе работает над планами, spec и макетами, а они прямо уходят агенту.
   В отличие от Notion или Google Docs, документ связан с работой [1][13].
3. **Нейтральность к harness при своём harness.** BYOK; Claude Code для моделей Anthropic; свой harness для Codex
   [11][57]. Mirror чужих sessions [70][71][72]. Fold — ядро агента, не привязанное к провайдеру [115]. Заметки о
   направлении отмечают (это их анализ): это расходится с тезисом самого Dex, что команда без весов модели всегда в
   худшем положении [118].
4. **Multiplayer по умолчанию.** Задачи видны всей организации [11]. Issue #1117 называет такую видимость
   раздражающей [171].
5. **Доверие через обучение.** Доклады, эссе и еженедельный подкаст с BoundaryML (AI That Works) работают как воронка
   продаж [1][106][122].
6. **Бизнес.** Подписка за место (per-seat SaaS), модели по BYOK, варианты для предприятий [1]. Вендор выступает
   против маркетинга «тратьте больше токенов» и обещает ускорение в 2–3 раза при сохранении качества [118]. Раньше
   предлагалась и помощь forward-deployed инженеров [41][117].

### Топология: облачный control plane и daemon на каждом host

- Postgres — единственный источник истины. Строка session служит шиной команд [45].
- API пишет в Postgres через Drizzle (ORM для TypeScript) [45].
- Electric стримит изменения строк через logical replication Postgres. Клиенты получают их как shape streams — живые
  отфильтрованные потоки строк таблиц. Строки лежат у клиента в локальных коллекциях TanStack DB [45].
- UI и daemon — симметричные клиенты. Оба читают через Electric и пишут только через API [45].
- API возвращает id транзакции Postgres. Клиент может дождаться, пока его собственная запись вернётся через
  синхронизацию [45].
- Proxy добавляет условия WHERE по организации и пользователю. Для daemon он ещё фильтрует sessions и approvals по
  `host_id`, так что каждый daemon видит только строки своего host [45][47].
- Аутентификация: UI — JWT от WorkOS; daemon — токен RS256, который выпускает API, с userId, orgId и hostId [45].
- Сеть: на host нет входящих портов. Daemon нужен только исходящий HTTPS к `riptide-api.humanlayer.com` и
  `sync.humanlayer.com` [22].
- Daemon работает в одном event loop. Синхронные вызовы файловой системы и процессов запрещены: они уже вызывали
  зависания [48].

### Цикл агента

**Dispatch через строки базы, а не через RPC.**

- Статусы session [46][55]: `draft → ready_for_launch → launching → running → ready_for_input | needs_approval |
  waiting_for_usage_limit | interrupt_requested → interrupted`, плюс `resuming`, `failed`, `waiting_for_workspace` и
  `lost`.
- Кто двигает переходы [46]:
  - API — действия пользователя: create, launch, continue, interrupt;
  - daemon — исполнение. `launching → running` происходит, когда Claude прислал id своей session. Завершение работы
    агента, ожидание approval и сбои — тоже переходы daemon.
- Как daemon получает работу [50]:
  - он читает три потока: изменения sessions, задач и строк setup workspace. Ограничения параллельности нет;
  - supervisor перезапускает упавший consumer с backoff: от 1 секунды, с удвоением, до 30 секунд;
  - обработка одного изменения дольше 5 секунд записывается как head-of-line blocking — одно медленное событие
    задерживает всю очередь.
- Launch срабатывает на статусах `ready_for_launch` или `waiting_for_workspace` [51]. Continue — на команде continue,
  это статус `resuming` [52].
- Registry внутри daemon гарантирует не больше одного run на session, какой бы путь его ни заметил первым [53].
- Центрального scheduler нет. `host_id` — обязательное поле (NOT NULL), его выбирают при создании session [56].
  Session для выключенного host просто ждёт в `ready_for_launch` [73].
- Обёртка run [54]:
  - регистрирует run, чтобы корректно его остановить при выключении;
  - при исключении ставит session `failed` с текстом ошибки, если пользователь не прерывал её сам;
  - в фоне записывает, с каким репозиторием и веткой работала session, чтобы потом связать с ней PR.
- Executor выбирается полным перебором значения `coding_agent`: `claude`, `codelayer` или `fold` [51][57].

**Claude Code через Claude Agent SDK.**

- Daemon вызывает `query()` из `@anthropic-ai/claude-agent-sdk` версии 0.3.280 [49][62]. Ключевые опции [62]:
  - preset системного prompt `claude_code` с добавленным текстом HumanLayer;
  - `settingSources: user, project, local` — свои CLAUDE.md, настройки и plugins пользователя работают;
  - два локальных plugin: `rpi` (skills workflow) и `hl` (встроенные skills HumanLayer);
  - встроенные subagents;
  - фиксированный список инструментов: Agent, SendMessage, Monitor, Workflow, Bash, Edit, Read, Write, Glob, Grep,
    TodoWrite, ToolSearch, WebSearch, WebFetch, Skill;
  - заранее разрешены только Grep, Glob и Skill;
  - `allowDangerouslySkipPermissions: true`, а настоящий режим берётся из строки session;
  - thinking: бюджет 31 999 токенов или adaptive thinking для Opus 5.5 и Sonnet 5.5;
  - effort по умолчанию — `high`;
  - переменные окружения выключают в Claude Code cron, фоновые задачи и auto-memory.
- Добавки в системный prompt [63]:
  - никогда не запускать subagents в фоне, не использовать `resume`, не выбирать модель без просьбы;
  - правила для mermaid и markdown;
  - блок `<humanlayer_session>` со сведениями о session;
  - правила каталога artifacts;
  - по условию: контракт multiplayer, context shards, сведения о multi-repo workspace, прогресс setup workspace.
- Hooks — все PostToolUse [63]:
  - снимок diff задачи после Write, Edit, MultiEdit и Bash;
  - синхронизация artifacts после Write, Edit, MultiEdit, Read и Bash;
  - на инструменте Skill — hook, который добавляет URL задачи, и hook маршрутизации workflow.
  - Approvals идут через `canUseTool` (подробно — в разделе о правах).
- Тёплые процессы:
  - после хода процесс Claude не завершается. Follow-up сообщения пишутся в его живой поток ввода;
  - простой — до 10 минут по умолчанию (`RIPTIDE_CLAUDE_SESSION_IDLE_TTL`) [64];
  - если процесса уже нет, daemon продолжает session по `coding_agent_session_id`. Это требует локального transcript
    Claude [52].
- Fork: `resume` + `forkSession` + `resumeSessionAt` на id события [62][51]. В блоге команды fork объяснён так: снять
  ходы с конца контекста, середину не править [6].
- Прочее [65]:
  - отказ модели с запасной моделью переписывает модель session;
  - границы compaction хранятся вместе с их summary.

**Codex через CodeLayer, собственный harness HumanLayer, а не Codex CLI.**

- Документация пишет, что Codex sessions идут через CodeLayer [17].
- Daemon запускает собственные пакеты агента HumanLayer, которые обращаются к Codex/Responses API [67].
- Вход — через device code ChatGPT, его выполняет daemon [67][68].
- Endpoints Bedrock, Azure и OpenAI задаются переменными `CODELAYER_CODEX_*` [27].
- Состояние агента хранится в Postgres (snapshots и сообщения), поэтому resume не нужны локальные файлы [67][22].
- Дочерние агенты берут GPT-модель родителя, в основном с effort low [17].
- Провайдеры в схеме: `anthropic`, `copilot`, `codex`, `firepass` (Fireworks) и `xai` [58].

**Fold (экспериментальный).**

- Третий harness HumanLayer, по умолчанию выключен, для Codex и xAI [57][58].
- Ведёт durable event log.
- Каждый prompt берёт эксклюзивный claim на session. Новый prompt может забрать claim у потерянного [69].

**Mirror sessions.**

- Sessions `opencode`, `pi`, `codex` и `claude-code` daemon не запускает. Их зеркалируют из терминала пользователя
  [57].
- Plugin Claude Code состоит из двух половин [70]:
  - mod — модуль hooks, ему нужен Claude Code 2.1.287;
  - MCP server, который не даёт модели ни одного инструмента.
- Что делает plugin [70]:
  - читает файлы transcript с сохранённых смещений в байтах и переводит записи в события HumanLayer;
  - шлёт heartbeat как host, который только зеркалирует;
  - вставляет ответы из веба как prompts;
  - зеркалит approvals в обе стороны;
  - синхронизирует папку и diff задачи;
  - убирает `HUMANLAYER_PAT` из окружения, которое получают команды Bash.

### Планирование и разбиение работы

- Workflows, которые показывает `/hl:orchestrate` [73]:
  - RPI: Questions → Research → Design → Outline → Implement → PR;
  - PRD: Questions → Research → PRD → TDD → Outline → Implement → PR;
  - Oneshot: Implement → PR;
  - Freeform: группа sessions без фаз.
- Доклад команды называет явную версию QRSPI [4].
- Artifacts фаз — пронумерованные Markdown-файлы в `.humanlayer/tasks/<slug>/`. Папка — symlink в
  `~/.humanlayer/riptide/artifacts/`. В облако файлы уходят, только когда их тронул файловый инструмент агента
  [63][13].
- Research [75]:
  - запускает 2–6 параллельных subagents в фиксированных ролях: locator, analyzer, pattern-finder, web researcher;
  - ticket не читает, чтобы оставаться объективным к текущему коду;
  - разрешён один дополнительный проход по открытым вопросам.
- Structure outline: фазы — тонкие вертикальные срезы, каждый проверяется отдельно [76][15].
- Реализация [77][78][81]:
  - skill-оркестратор запускает по implementer subagent на фазу;
  - потом сам заново запускает builds, tests и lint;
  - ждёт ручной проверки человека и коммитит фазу;
  - прогресс записан в artifact: чекбоксы `- [x]` и заголовки `✅ Phase N`. Продолженный run начинает с первого
    неотмеченного пункта;
  - при расхождении документов: outline > design > research > ticket [78].
- Модели subagents [17][80]:
  - research-агенты — Sonnet, или Haiku с переключателем Faster Research Subagents;
  - implementer и implementation reviewer — Sonnet;
  - outline implementer берёт модель родителя.
- Фоновая философия [7]: frequent intentional compaction, заполнение контекста 40–60%; review человека — на research
  и планы, потому что плохая строка плана превращается в сотни плохих строк кода.

### Работа без присмотра: auto-advance

- **Маршрутизация фаз внутри session** [82]: PostToolUse hook на Skill вставляет в контекст правильную следующую
  команду. Решение зависит от типа workflow и времени worktree (`now`, `later`, `never`).
- **На сервере, когда session пришла в `ready_for_input`** [83][84]:
  1. Haiku читает последнее сообщение ассистента и извлекает next step: skill, prompt и, по желанию, каталог.
  2. `checkAutoAdvance` проходит таблицу из пяти переходов [85]:

| Завершённая фаза | Следующая фаза |
| --- | --- |
| Research questions | Research |
| Research | Design discussion, или PRD для `prd_tdd` |
| Plan | Setup worktree, или реализация при времени `now` или `never` |
| Setup worktree | Реализация |
| Реализация | Describe PR |

- **Когда переход срабатывает** — должно выполниться всё сразу [85]:
  - флаг включён. Для владельца решает флаг задачи, для соавтора — его собственная настройка;
  - на session стоит метка фазы;
  - фаза завершена. Для вопросов и research это artifact с подходящим `type` во frontmatter. Для поздних фаз —
    `next_step_found`;
  - нет более новой неархивной соседней session, у которой уже есть метка следующей фазы.
- **Что делает срабатывание** [85]:
  - в транзакции создаёт новую строку session с тем же host, агентом, моделью, effort и режимом разрешений;
  - затем выключает флаг. Каждый переход срабатывает один раз;
  - prompt реализации велит выполнить все фазы подряд без пауз и коммитить после каждой. Prompt worktree велит
    действовать, не спрашивая пользователя.
- **Покрытие и значения по умолчанию:**
  - design → outline, PRD → TDD, TDD → outline и outline → implementation не переходят сами никогда [16];
  - шаги plan и worktree по умолчанию выключены, потому что пропускают review плана человеком [73];
  - первые sessions auto-advance и Oneshot запускаются в режиме `bypass` [86].
- **Известный сбой** [166]: извлечение однажды вернуло рассуждения модели в поле `suggestedDirectory`. Daemon взял этот
  текст как рабочий каталог. Claude не запустился, и session нельзя было продолжить.
- **Работа между задачами** — тоже skill агента. `/hl:orchestrate` через CLI `humanlayer api` создаёт задачи,
  запускает sessions и опрашивает статусы и PR. Его правило: у каждой задачи свой worktree, две задачи в одном checkout
  не запускать [73].
- Графа зависимостей, scheduler волн и merge queue в коде API и daemon нет [85][73].

### Параллельность и координация

- **Параллельная работа:**
  - каждая session — свой процесс Claude;
  - ограничения числа sessions на host в daemon не найдено (не подтверждено за пределами прочитанного кода). Один
    пользователь сообщил о 31 session на одном host [166];
  - subagents внутри session работают только на переднем плане [63].
- **Несколько людей в одной session** [87]:
  - общий composer построен на Yjs (библиотека совместного редактирования) поверх durable streams;
  - ходы оборачиваются в `<message from="Name">`. Если инструкции двух людей противоречат друг другу, побеждает
    более поздняя.
- **Очередь сообщений** [84][87]:
  - сообщения, отправленные во время хода, идут в `queued_messages`;
  - сервер доставляет их, когда ход закончился, по умолчанию пачкой;
  - сообщения с interrupt and send доставляются при прерывании.
  - Interrupt заставляет сервер отклонить все ждущие approvals [84].
- **Задачи на разных hosts:**
  - sessions одной задачи могут идти на разных hosts [13];
  - project с `autoPushBranch` пересобирает worktree из запушенной ветки на новом host. Незапушенная работа остаётся
    на старом [73];
  - `/hl:teleport` передаёт работу на другой host через `handoff.md` и запушенную ветку. Файлы с секретами
    перечисляются по имени ключа, не по значению [74].

### Изоляция

- **Git worktrees** [21][20][73]:
  - путь по умолчанию — `~/.humanlayer/workspaces/<slug>/<repo>`;
  - ветка `<slug>`, от `origin/main`, если не настроено иначе;
  - поддерживаются multi-repo workspaces;
  - после создания выполняется `setupCommand`, `copyGlobs` копирует файлы вроде `.env`;
  - по желанию `setupBlocksFirstSession`.
- **Как создаётся worktree** [88]:
  - сначала `fetch --prune`;
  - проверка, что существующая удалённая ветка задачи содержит исходный commit;
  - если worktree уже есть, он принимается в работу;
  - git работает неинтерактивно, timeout — 5 минут на команду.
- **Ожидание и время создания:**
  - session ждёт в `waiting_for_workspace`, пока у каждого репозитория не появится worktree [73];
  - если репозиторий упал раньше, чем создан worktree, session ждёт вечно [73];
  - время `later` добавляет отдельную фазу setup worktree. Oneshot считает `later` за `never` [16];
  - с 0.201.0 задачи из каталога по умолчанию получают worktree [11].
- **Sandbox ОС или контейнера в daemon нет.** Агент получает доступ к файлам и сети того пользователя, от которого
  запущен daemon [22]. Сильнее изолировать можно, только поставив remote daemon в sandbox или VM. Teleport
  перечисляет Freestyle, Daytona, E2B и Modal [74].
- **Diff задачи без касания index пользователя** [89][11]:
  - daemon держит отдельный («теневой») git-каталог на каждую задачу и репозиторий в `.shadow/`;
  - он читает объекты настоящего репозитория через git alternates (механизм, который позволяет одному репозиторию
    брать объекты из другого) и стартует из настоящего index;
  - исключает `.humanlayer/`, `.shadow/` и `.env*`;
  - публикуется через durable streams.

### Состояние и память

- **Строка session** [56]:
  - id session Claude;
  - стоимость (`total_cost_usd`) и расход токенов по моделям с idempotent ключами отчётов (повторный отчёт не
    считается дважды);
  - токены контекста и предел контекста (по умолчанию 168 000);
  - `is_compacting`, `error_reason` и `permissions_mode`;
  - данные fork и метки;
  - next steps, извлечённые LLM, и структурированное summary.
- **Другие таблицы** [90]: задачи, approvals, события разговора, artifacts с версиями и комментариями, комментарии к
  diff, PR, коммиты, hosts в сети, состояние CodeLayer и Fold, context shards.
- **Стриминг текста** [91][65]: дельты токенов идут через durable streams. Готовые сообщения пишутся через API как
  события разговора.
- **Локальные файлы** [22]:
  - `~/.humanlayer/riptide/` — учётные данные, `host_id` и artifacts;
  - для resume Claude должен сохраниться `~/.claude/`.
- **Память — три слоя:**
  1. Artifacts задачи. Они идут за задачей через sessions, агентов и машины [13].
  2. Context Shards: LLM вынимает из прошлых разговоров короткие правила, каждое — с цитатами (до 5). Администратор
     выпускает или отклоняет каждое правило. Включённые правила вставляются только при свежем запуске, никогда при
     resume или fork [92][63].
  3. CLAUDE.md пользователя через `settingSources` [62]. Auto-memory Claude выключена [62].
- **Как держат контекст маленьким** [8][93][36]: backpressure — checks печатают одну строку при успехе и полный вывод
  при сбое; в их репозитории запрещено передавать вывод tests в `head` или `grep`.

### Проверка качества

Продуктового локального gate нет. Проверку ведут инструкции skills и команды самого репозитория.

- **Во время реализации** [77][81]:
  - implementer запускает критерии успеха фазы. Оркестратор заново запускает builds, tests и lint;
  - после каждой фазы — ручная проверка человеком, если session не была запущена через auto-advance.
- **`/rpi:describe-pr`** [79][11]:
  1. Создаёт или обновляет описание PR.
  2. Ждёт 5 минут и проверяет, можно ли сделать merge.
  3. Запускает `gh pr checks --watch --fail-fast`.
  4. При сбое читает logs упавших checks. Чинит падения, которые вызвал PR. Flaky или не связанный с PR сбой
     перезапускает один раз.
  5. После 3 попыток починить один и тот же check останавливается.
  6. Merge conflicts не разрешает без плана, который одобрил пользователь.
- **Review:**
  - единственный встроенный review subagent — `implementation-reviewer` (Sonnet). Он сравнивает план с
    `git diff main...HEAD` и сообщает, что сделано по плану, что отклонилось, что добавлено и что пропущено. Это идёт
    в текст PR [80];
  - HTML walkthrough добавляется для PR от 300 строк в 5 и больше файлах [16];
  - агентов review с разными углами проверки (lenses) нет.
- **CI и атрибуция:**
  - статус CI checks приходит через webhooks GitHub App `check_run` и `status` и хранится как поток статусов PR [94];
  - коммиты агента несут trailer `HumanLayer-Session`. Его добавляют git hooks, которые лежат вне репозитория.
    Наблюдатель за HEAD приписывает коммиты по trailer, а без trailer — по совпадению содержимого [95].
- **Собственная настройка команды:** Stop hook их репозитория запускает quality checks и typecheck и при сбое
  выходит с кодом 2, чтобы агент чинил [93][9].

### Восстановление после сбоев

- **Heartbeat и замолчавшие hosts:**
  - daemon шлёт heartbeat каждые 15 секунд [97];
  - Lambda-sweeper помечает host stale после 120 секунд тишины. Он роняет running sessions этого host и отклоняет его
    ждущие approvals [98][22];
  - как часто запускается sweeper (не подтверждено): инфраструктурного кода нет в репозитории.
- **Потерянные sessions** [98]:
  - статус `lost` ставится, если нет событий: `running` — 10 минут, `launching` — 2 минуты, `resuming` — 1 минуту,
    `interrupt_requested` — 30 секунд;
  - исключения: ещё открытый вызов Bash в пределах своего timeout и вызов MCP моложе 20 минут;
  - сообщение пользователя переводит `lost` в `resuming`. Это lost-resume: провайдер может заменить устаревшую
    локальную работу [54][52].
- **Повторы:**
  - повторы запросов к API модели оставлены самому Claude Code (его события `api_retry`). Неуспешный результат ставит
    session в `failed`; пользователь продолжает, отправив сообщение [65][46];
  - запросы daemon к API HumanLayer повторяются при сетевых ошибках, 408, 425, 429 и 5xx [99].
- **Гигиена процессов** [100]:
  - каждые 5 секунд daemon проверяет, жив ли его родительский процесс;
  - обработчика `uncaughtException` нет намеренно. Комментарии в коде описывают прошлый цикл, когда logging в закрытый
    вывод раздул logs до 8 GB.
- **Открытые дефекты:**
  - процесс Claude переживает закрытие простаивающей session через 10 минут. Пик памяти — 39 GB за 3 дня [168];
  - 35 потерянных процессов `claude` и около 19 GB у UI с daemon за 2 дня [164];
  - промахи prompt cache Codex после resume, потому что JSONB в Postgres переупорядочивает ключи [165].

### Лимиты подписки и стоимость

- **Окна** [66][65]:
  - события `rate_limit_event` от Claude обновляют одну запись окон на host: пять часов, семь дней, Opus, Sonnet,
    OAuth apps, окна по моделям;
  - полный снимок `/usage` тоже читается через SDK.
- **Парковка на лимите** [65][66]:
  - отказ по лимиту без overage переводит session в `waiting_for_usage_limit`;
  - daemon ставит освобождение на время сброса плюс 60 секунд, или через 5 часов, если событие не принесло время
    сброса;
  - новая активность SDK отменяет освобождение. События `api_retry` его не снимают.
- **Когда ход заканчивается.** Если Claude Code сам завершает ход, а не ждёт окна, событие result переводит session в
  `ready_for_input` или `failed`. Ничто не продолжает её автоматически [65]. Issue #1164 (2026-11-12) просит
  auto-resume [160].
- **Заметки расходятся в оценке.** По release notes 0.179.0 и заметкам о направлении, sessions продолжаются сами после
  сброса [11]. По коду — только когда Claude Code сам ждёт окна [65]. Пользователь в #1164 продолжает вручную [160].
  Баг это, случай Codex или непонятный интерфейс — (не подтверждено).
- **Предупреждения:** лимиты отправляются в heartbeat примерно через 1 секунду после изменения. Предупреждения — с 80%
  [97][66][11].
- **Стоимость** [1][56]:
  - свои ключи или подписки;
  - стоимость считается на session;
  - потолка бюджета, лимита ходов или планирования запусков под лимиты в коде нет.

### Права и безопасность

- **Режимы:** `default`, `accept_edits`, `auto` (auto mode самого Claude Code) и `bypass`. Они отображаются в режимы
  SDK. Режим и модель меняются на ходу через controls SDK [103].
- **Порядок решения об approval** (`canUseTool`) [101][102]:
  1. Встроенный allow list: Skill, Bash, который начинается с `rpi`, Read/Write/Edit внутри каталогов artifacts,
     инструменты комментариев HumanLayer.
  2. Правила always allow, одобренные раньше в этой session. Для Bash работает `*`.
  3. Иначе — строка approval и ожидание её изменения через Electric или отмены.
  4. Ответ: allow (временно или навсегда) или deny с комментарием проверяющего.
- Interrupt заставляет сервер отклонить все ждущие approvals [84].
- **Без присмотра — режим `bypass`.** Это automation в CI и первые sessions Oneshot и auto-advance [26][86]. Политики
  auto-approval, кроме auto mode самого Claude Code, нет.
- **Граница доверия** [22]:
  - daemon имеет все права своего пользователя;
  - сохранённые sessions и launch tokens — это учётные данные;
  - launch token даёт учётные данные одному процессу.
- Plugin Claude Code убирает `HUMANLAYER_PAT` из окружения Bash [70].
- SOC 2 Type II — заявление вендора на сайте; независимо не проверено (не подтверждено) [1].

### Где участвует человек и наблюдаемость

- **Где решает человек** [16][15]:
  - решения design discussion остаются открытыми, пока пользователь их не закрыл;
  - одобрение PRD;
  - два одобрения TDD: system design и program design;
  - отзыв на outline меняет outline и никогда не запускает код;
  - ручная проверка после каждой фазы реализации.
- **Обратная связь:** комментарии к artifacts и diff попадают к агенту через инструменты `mcp__humanlayer__*` (get,
  reply, update) [70][102]. Колокольчик и Slack сообщают людям [11].
- **Наблюдаемость:**
  - запись работы — это transcript session;
  - CPU, память и лимиты host лежат в `online_hosts` [104];
  - daemon отправляет ошибки в Sentry и пишет структурированные logs с traces в `~/.humanlayer/riptide/logs` [36][50];
  - ленты событий автономного запуска нет.
- **Automation в CI** (`humanlayer automation run`) [26]:
  - поднимает временный daemon, вход по PAT;
  - запускает одну session в режиме `bypass`;
  - выходит с exit code по результату;
  - по умолчанию живёт до 2 минут простоя, чтобы follow-up из веба ещё работали;
  - шаблоны: guard на один открытый PR агента, файл памяти в репозитории, цикл `/iterate` по комментариям.

    говорит о выигрыше около 50% в продуктивности и в токенах [40].
  - Основатель Casco также заводил bug reports, то есть продуктом действительно пользовались [209].
- **Независимая поддержка.** Под демо платформы автор YouTube, который учит команды в корпорациях, пишет, что пришёл к
  очень похожему workflow за два года. Его довод: агентам нельзя доверить работу в одиночку [135].

### Что ругают

**Отход от сценария стоит дорого.**

- Главная жалоба — #1108, сентябрь 2026 [175]:
  - план на 11 фаз; в фазе 6 найден мелкий баг;
  - просьба к HumanLayer починить его запустила subagent примерно на 20 минут и съела кредиты пользователя;
  - пользователь ушёл в обычный Claude CLI, там исследовал и починил баг, а потом вернулся в HumanLayer к фазе 7;
  - он просит цикл research/plan/implement для багов внутри той же задачи и предупреждает: если отправлять людей
    обратно в CLI, продукт их потеряет.
- Второй пользователь соглашается [175]:
  - трудно выйти из workflow ради незапланированной добавки и вернуться;
  - непонятно, какой skill запускает агента для design;
  - интерфейс грубоват для первого раза.
- Агенты в итерации пытаются закончить слишком рано; hook срабатывал слишком охотно [176].
- Skill PRD переписывает весь документ после каждого сообщения. На Codex это бывает чаще [193].

**Workflows жёсткие.**

- У команды уже есть своя последовательность skills и циклы AI code review после открытия PR. Они хотят встроить их
  [196]:
  - непонятно, что именно сейчас в работе, когда проходишь по шагам каждой задачи;
  - даже со всеми включёнными флагами auto-advance запуск не запушил описание PR;
  - ответ вендора (август 2026): свои workflows скоро будут.
- Slash-меню показывало только RPI skills HumanLayer. Свои skills Claude Code, Codex или OpenCode не находились, хотя
  срабатывали, если набрать их вручную (#1057, июль 2026) [184]. В 0.181.0 skills репозитория появились в slash-меню
  [11].
- В CodeLayer maintainers отключили инструмент вопросов Claude Code (AskUserQuestion) и часть встроенных команд,
  например `/mcp` и `/clear` [204]:
  - самый популярный по реакциям issue репозитория — о том, что вопросы AskUserQuestion показывались сырым JSON;
  - его закрыли как не планируемый для CodeLayer.
- Ограничить агента подпапкой monorepo не планируется [206].

**Надёжность цепочки daemon плюс облако.**

- **Сбой облака** [174]:
  - 2026-09-09 API для daemons отвечал HTTP 500. Каждая новая session в приложении показывалась как не запустившаяся;
  - на самом деле Claude Code локально отработал до конца, но приложение не получило результат;
  - сбой подтвердили несколько пользователей, в том числе на Codex.
- **Поломки после обновлений.** С 6 июня по 2 ноября вышло 59 релизов [11]. Два инцидента пришли с обновлениями:
  - после одного обновления каждая session падала с internal server error. Причина — обработка отказов новой модели.
    Пользователь просил откатить версию [192];
  - обновление приложения посреди запуска осиротило daemon, который ещё работал [183]. Предупреждение об этом
    добавили в 0.152.0 (4 августа), безопасность обновлений усилили в 0.181.0 и 0.183.0 [11].
- **Утечки памяти на долгих запусках** (обе открыты на 13 ноября):
  - daemon не останавливает процессы Claude, когда закрывает простаивающие sessions. Один пользователь намерил пик
    памяти 39 GB за 3,4 дня [168];
  - у другого приложение с daemon заняли около 19 GB примерно за 2 дня на Mac с 18 GB памяти. Было 35 потерянных
    процессов `claude`, интерфейс завис [164].
- **Зависания без уведомления:**
  - агент простоял час на правиле «прочитай перед записью» и не сказал об этом пользователю [189];
  - в CodeLayer session застряла в ожидании approval, а потом застряла и на прерывании [203];
  - продолжение прерванной session падало с непонятными ошибками, входить приходилось через CLI [209].
- **Установка в эпоху CodeLayer:**
  - daemon падал в цикле на segmentation fault Bun. Claude, поставленный через nvm, не находился, если приложение
    открыто не из shell. В issue 13 комментариев, исправление заняло около 3 недель [207];
  - DMG не был подписан, и Gatekeeper macOS предупреждал при установке. Ответа не было [201];
  - HumanLayer требовал более новый Claude Code, чем стабильный канал, который закрепляют в управляемых окружениях
    [195].

  и так использовал окно токенов Claude [202]. Это прямая просьба о планировании автономной работы под лимиты.

**Приватность и облачная синхронизация.**

- Переписанный продукт запускает агентов локально, но хранит prompts, сообщения, задачи и approvals в облаке
  HumanLayer [181].
- Пользователь назвал это препятствием для чувствительной к приватности, регулируемой или изолированной от сети работы
  и попросил режим только локально [181].
- Ответ: on-prem и air-gapped установки — только на тарифе для предприятий [181].
- Открытый код делает self-hosting возможным в принципе, но ключи сторонних API (например, WorkOS, Slack, Linear) всё
  равно нужны [2].
- Ещё в CodeLayer активный пользователь отправлял logs лично, потому что в них было содержимое репозитория [209].

**Командные функции.**

- Каждая задача по умолчанию видна всей организации. Пользователь пишет, что в больших командах это шум и может
  ощущаться как слежка [171]. Ответа на 13 ноября нет.
- После того как задачей поделились, владелец не мог писать в session коллеги. Так задумано ради безопасности: только
  чтение. Команда перешла на комментарии [194].
- Переданную задачу нельзя было запустить на машине нового владельца: workspace был только на host коллеги. Его
  пересоздали вручную [162]. Skill для переноса задачи на другую машину вышел за месяц до этого [11]. Что пользователь
  о нём не знал — вывод заметок об отзывах.

**Полировка интерфейса.**

- Верхняя навигация путает. Пользователь хочет интерфейс чище, как у Superset (что это за продукт — не подтверждено)
  или Linear, и короткое демо [197].
- Прыжки прокрутки и мерцание мешают смотреть за работающим агентом [210].
- В мобильном вебе: поля ввода увеличивают страницу на iPhone, изображения не грузятся, кнопки мелкие [172]. Это при
  том, что исправление zoom на iOS значится в 0.151.0 [11].

**Охват агентов и моделей.**

- **OpenCode:** просят с 2025 года, в ответах обещали. Два PR сообщества умерли, не попав в код. Запрос всё ещё открыт
  [170][208]. Сейчас есть plugin, который показывает sessions OpenCode в HumanLayer, но выбрать OpenCode как backend в
  интерфейсе нельзя [71][35].
- **Cursor:** просят, есть несколько +1. В roadmap, без даты. Agent Client Protocol отвергнут как слишком узкий для
  hooks HumanLayer [187].
- **Локальные модели:** отклонены в ноябре 2025 как недостаточно хорошие для реальной работы с кодом [208].
- **Путаница с BYOK:**
  - команда оплатила Pro ради BYOK и не нашла поля для API-ключа. В HumanLayer BYOK значит использовать свой
    существующий вход в Claude или Codex [199];
  - существующие подписки работают [200].

### Скепсис к вендору и методу

- **Это реклама:**
  - несколько комментаторов Hacker News сочли эссе 2025 года рекламой, которая подводит к продукту. Другие сочли набор
    prompts и агентов избыточным для большинства [147];
  - в 2026 году эссе о фабриках назвали длинной рекламой IDE [149].
- **Слабые доказательства:**
  - критики заметили, что кейс 2025 года держится на одном исправлении бага и двух больших PR, один из которых ещё
    draft [147];
  - заявление о 7 часах не сходится с 40 коммитами за 7 дней [147];
  - PR на 20 тыс. строк провоцирует review «для галочки» [147].
- **Стоимость:**
  - эссе называет около $12 тыс. в месяц на Opus для команды из трёх человек [147];
  - Dex сказал, что два PR стоили около $650 в токенах API, прежде чем команда перешла на план Max [148];
  - некоторые читатели ответили, что поэтому продолжают писать код руками [147].
- **Метод всё время меняется.** Это самая громкая тема на YouTube:
  - под докладом о том, что пошло не так с RPI, верхние комментарии смеются над переходом от «не читать код» к «читать
    код» (190 и 115 лайков). Ещё один называет докладчика продавцом низкокачественного кода от AI [134];
  - под интервью у Ondrej верхние комментарии шутят, что понятия в AI живут около трёх недель (302 лайка). Ещё один
    высмеивает совет, который на одной неделе хвалит циклы агентов, а на следующей объявляет их мёртвыми [137];
  - один комментатор Hacker News защитил Dex за то, что тот открыто признаёт ошибки [149];
  - сам Dex сказал, что репозиторий HumanLayer заполнился низкокачественным кодом от AI, и его пересобрали руками с
    нуля [150].
- **Качество текста:** отчёт о benchmark за октябрь 2026 критиковали за то, что он читается как написанный Claude
  [155].
- **Сомнения в самом продукте.** Комментатор под демо платформы спросил, зачем целая IDE ради лучших планов, и
  предложил сделать это plugin для Claude Code или расширением VS Code [135]. Другие назвали продукт ещё одним
  инструментом оркестрации, написанным «на вайбе», повтором Traycer или сатирой [135][136].
- **Недоверие к AI-reviewer-ам разделяют и пользователи, и основатель:**
  - комментатор YouTube (81 лайк) видел, как циклы review агентами выдумывают проблемы и добавляют баги [133];
  - Dex писал, что не доверяет review-агентам решить проблему объёма [144].
- **Фабрики без присмотра делят аудиторию:**
  - тезис HumanLayer опирается на собственный неудачный опыт полностью автономной работы в июле 2025 [133];
  - в треде Hacker News одни ответили, что модели с тех пор стали лучше [149];
  - один рассказал, как ночной запуск без присмотра устроил беспорядок [149];
  - другой 8 месяцев держит систему, которая в основном выпускает код сама [149].
- **API 2024 года вызывал другие сомнения:** легко сделать у себя; цена за сообщение выглядела дорогой рядом с Zapier
  или IFTTT; люди, которые одобряют действия, устанут и начнут одобрять не глядя [153].

### Почему приходят и почему уходят

**Почему приходят:**

- уже доверяют методу по докладам или prompts и хотят тот же поток с командным интерфейсом [132][135];
- общие artifacts с комментариями [175][193];
- видно работу subagents [154];
- работает с существующими подписками Claude и Codex [200][154];
- можно продолжить работу с телефона [172];
- multi-repo worktrees и задачи из tickets Linear или Jira [135][1].

**Почему уходят или застревают** (со слов пользователей или как разумный вывод из их слов):

- доработки отправляют обратно в CLI [175];
- свои pipelines skills и review не встраиваются [196];
- Windows экспериментален (пользователи уходят на WSL), на Linux есть только веб [190][186];
- sessions хранятся в облаке [181];
- сбои и утечки памяти [174][168][164];
- представление о цене: один комментатор решил, что нужна оплата API, а не подписка [135][1];
- теперь — переход в Factory с предупреждением минимум за 30 дней [3].

### Темп

### Что добавили за последние полгода (2026)

- **Июнь:** RPI по умолчанию; бесплатный план для команд до 3 человек; сайт документации; уведомления в Slack;
  multi-repo workspaces [11].

  задачи другому владельцу; вкладки; Context Shards (ранний доступ); предварительная версия Fold; sessions в GitHub
  Actions (эксперимент); subagents, которые можно продолжить и fork-нуть; вложенность subagents не глубже 3 уровней

## Слабые места и чего нет

### Слабые места по источникам

- **Будущее продукта.** HumanLayer уходит в Factory. Hosted-платформа живёт переходный период не меньше 30 дней по
  посту HumanLayer [3]; Factory срока окончания не называет [125]. Инструкций для self-hosting ещё нет, и нужны ключи
  сторонних сервисов [35][2]. Последний релиз — 2026-11-02, после него только два исправления запуска CLI [109][35].
- **Сайт устарел.** FAQ пишет, что open source пока нет; Copilot и Fireworks указаны как поддерживаемые; продаются
  шесть фаз QRSPI с Plan, которого нет в RPI по умолчанию [1][11][58][16].
- **Зависимость от облака.**
  - Сбой 2026-09-09: sessions отработали локально, но приложение их потеряло [174].
  - Prompts, сообщения и approvals хранятся в облаке. Без облака — только on-prem на Enterprise [181][1].
  - Если daemon молчит около 2 минут во время работы или approval, session считается упавшей [22].
  - Production и beta — разные аккаунты и базы, integrations подключаются заново [34].
- **Платформы.**
  - Desktop — только macOS на Apple silicon [12][109]. Linux desktop app (не подтверждено) [108][11][163].
  - Windows экспериментален: artifacts не записывались, hosts падали на ошибке кредитов, daemon обновляют вручную
    [190][178][23].
  - В вебе нет терминала, управления workspaces и автодополнения каталогов [22]. Мобильный веб с ошибками [172].
- **Долгие запуски.** Утечки процессов и памяти — до 39 GB [168][164]. Зависания без уведомления [189]. Обновление
  посреди запуска осиротило daemon [183]. Обновление сломало все sessions [192].
- **Лимиты.**
  - Автоматическое продолжение работает, только если Claude Code сам ждёт окна [65]. Пользователь продолжает вручную
    [160].
  - Лимиты Codex не учитываются [66]. Передача в Codex после лимита зависла на ошибке 401 [167].
  - Планирования запусков под лимиты нет [66][56].
  - Повторы ошибок API — только встроенные в Claude Code [65].

- **Без присмотра — только `bypass`.** Политики auto-approval нет [101][26][86]. Sandbox ОС нет [22].
- **Проверка качества.** Локального gate нет [77][79]. Один reviewer, и тот сверяет план с diff, а не качество кода

- **Жёсткий workflow.** Отход от сценария дорогой [175]. Свои pipelines не встроить [196]. Skill PRD переписывает весь

- **Команда.** Видимость задач на всю организацию принудительна [171]. Session коллеги для владельца задачи — только

## Пересечение с worfy

Термины worfy в этом разделе:

- Canvas — бесконечное полотно, на котором worfy показывает работу агентов.
- Epic — группа связанных Ticket-ов. Ticket — одна задача.
- Orchestrator — session, которая планирует и раздаёт Ticket-ы.
- Wave — набор Ticket-ов, которые запускаются вместе. Autopilot — запуск Wave-ов без человека.
- Gate — локальный запуск проверок перед PR.
- Harness — plugin worfy, который приносит в Claude Code rules, skills, subagents и hooks.
- Flight Recorder — лента событий автономного запуска. Work track — вся работа проекта по дням и неделям.
- Cards — карточки, которые агенты строят на Canvas через MCP server.
- Product Session — продуктовый советник с живым Mind map и критиком spec.
- Linked machines — связанные машины в локальной сети.
- Evidence screenshots — скриншоты-доказательства с privacy scrub (удалением личных данных).
- Eco mode — режим, который бережёт лимиты подписки.

### Где пересекаются

- **Агенты Claude Code и Codex.** HumanLayer запускает Claude Code через Claude Agent SDK, а модели Codex — через свой
  harness CodeLayer [62][67][17]. worfy запускает sessions Claude Code и Codex CLI.
- **Worktree на единицу работы.** HumanLayer: worktree на задачу, multi-repo, `setupCommand`, `copyGlobs`, ветка из
  slug задачи [21][20][88]. worfy: свой git worktree на каждый Ticket.

- **Работа без человека.** HumanLayer: auto-advance между фазами внутри задачи [85][16]; `automation run` в CI [26];

- **Лимиты подписки.** HumanLayer: полосы окон Claude по каждому host, предупреждение с 80%, статус

## Механизмы, которые стоит изучить

1. **Парковка session на лимите и освобождение по времени сброса.**
   - Что это: отдельный статус `waiting_for_usage_limit` и таймер освобождения в daemon [65][66].
   - Как работает:
     - события `rate_limit_event` от Claude обновляют одну запись окон на host: 5 часов, 7 дней, Opus, Sonnet, OAuth
       apps, окна по моделям. Полный снимок `/usage` берётся через SDK [66][65];
     - отказ по лимиту без overage переводит session в `waiting_for_usage_limit` [65];
     - daemon ставит освобождение на время сброса плюс 60 секунд, или через 5 часов, если время сброса не пришло [65];
     - новая активность SDK отменяет таймер. События `api_retry` его не снимают [65];
     - снимок лимитов уходит в heartbeat примерно через 1 секунду после изменения; предупреждения — с 80% [97][66][11].
   - Ограничение: если Claude Code сам закончил ход, а не ждал окна, session уходит в `ready_for_input` или `failed`,
     и её никто не продолжает [65]. Пользователь в #1164 продолжает вручную [160].
   - Источник: [65][66][97][11][160].
2. **Liveness: heartbeat, замолчавший host и пороги `lost` по статусу.**
   - Как работает:
     - daemon шлёт heartbeat каждые 15 секунд [97];
     - Lambda-sweeper помечает host stale после 120 секунд тишины, роняет его running sessions и отклоняет его ждущие
       approvals [98][22];
     - session получает `lost`, если нет событий: `running` — 10 минут, `launching` — 2 минуты, `resuming` — 1 минуту,
       `interrupt_requested` — 30 секунд [98];
     - исключения: открытый вызов Bash в пределах своего timeout и вызов MCP моложе 20 минут [98];
     - сообщение пользователя переводит `lost` в `resuming` [54][52];
     - supervisor перезапускает consumer потоков с backoff от 1 до 30 секунд. Обработка события дольше 5 секунд
       записывается как блокировка очереди [50];
     - registry гарантирует не больше одного run на session [53]. Daemon каждые 5 секунд проверяет, жив ли
       родительский процесс [100].
   - Чем интересно: пороги зависят от статуса, а долгие законные операции (длинный Bash, долгий вызов MCP) не
     считаются зависанием.
   - Источник: [97][98][50][53][100].
3. **Auto-advance с извлечением следующего шага через LLM.**
   - Как работает:
     - внутри session PostToolUse hook на Skill вставляет в контекст следующую команду по типу workflow и времени
       worktree [82];
     - когда session пришла в `ready_for_input`, Haiku читает последнее сообщение ассистента и извлекает next step:
       skill, prompt и, по желанию, каталог [83][84];
     - `checkAutoAdvance` идёт по таблице из пяти переходов [85];
     - переход срабатывает, только если флаг включён, на session есть метка фазы, фаза завершена (artifact с нужным
       `type` во frontmatter или `next_step_found`) и нет более новой соседней session с меткой следующей фазы [85];
     - в одной транзакции создаётся новая строка session с тем же host, агентом, моделью, effort и режимом
       разрешений. Затем флаг выключается [85];
     - четыре перехода — к outline, к TDD и к коду — никогда не идут сами [16].
   - Известный сбой: модель вернула свои рассуждения в поле `suggestedDirectory`. Daemon взял это как рабочий каталог,
     session не запустилась и не продолжилась (#1129) [166].
   - Источник: [82][83][84][85][16][166].
4. **Строка Postgres как шина команд между облаком, интерфейсом и daemons.**
   - Как работает:
     - API пишет в Postgres. Electric стримит изменения строк через logical replication. Клиенты держат строки в
       локальных коллекциях TanStack DB [45];
     - UI и daemon — симметричные клиенты: читают через Electric, пишут только через API [45];
     - API возвращает id транзакции, и клиент ждёт, пока его запись вернётся через синхронизацию [45];
     - proxy фильтрует строки по организации, пользователю и `host_id` [45][47];
     - `host_id` в строке session обязателен. Session для выключенного host просто ждёт в `ready_for_launch` [56][73];
     - daemon не открывает входящих портов, ему нужен только исходящий HTTPS [22].
   - Чем интересно: команды доходят до машин без RPC и без входящих соединений. Состояние переживает перезапуск
     любого клиента.
   - Источник: [45][47][56][73][22].
5. **Цепочка решения об approval через `canUseTool`.**
   - Как работает:
     1. встроенный allow list: Skill, Bash, который начинается с `rpi`, Read/Write/Edit внутри каталогов artifacts,
        инструменты комментариев HumanLayer [102];
     2. правила always allow, одобренные раньше в этой session, с `*` для Bash. Панель показывает правило, которое
        предлагает Claude Code, например `Bash(bun test:*)` [101][61];
     3. иначе — строка approval и ожидание её изменения через Electric или отмены [101];
     4. ответ — allow временно или навсегда, или deny с комментарием проверяющего [101];
     - interrupt заставляет сервер отклонить все ждущие approvals [84]. Режим разрешений и модель меняются на ходу
       через controls SDK [103].
   - Чем интересно: решение по каждому вызову инструмента принимается по строке в базе, поэтому ответить можно с
     любого устройства, а ответ сохраняется.
   - Источник: [101][102][103][84][61].
6. **Diff задачи через отдельный git-каталог с alternates.**
   - Как работает: daemon держит отдельный git-каталог на задачу и репозиторий в `.shadow/`. Он читает объекты
     настоящего репозитория через git alternates и стартует из настоящего index. Исключает `.humanlayer/`, `.shadow/` и
     `.env*`. Diff пересобирается после каждой записи, правки или shell-команды агента и публикуется через durable
     streams [89][11][70].
   - Чем интересно: diff виден в реальном времени, а index и история пользователя не меняются.
   - Источник: [89][11][70].
7. **Синхронизация документов через hooks на инструментах агента.**
   - Как работает:
     - папка задачи — symlink в `~/.humanlayer/riptide/artifacts/`, добавлена в `.gitignore` [13][22];
     - PostToolUse hooks на Write, Edit, MultiEdit, Read и Bash отправляют затронутые файлы [63];
     - системный prompt запрещает менять artifacts через Bash, Python или sed, чтобы каждое изменение шло через
       файловые инструменты [18];
     - текст до 10 MB хранится как текст; изображения, HTML и PDF — в object storage [13];
     - artifacts нумеруются `NN-…`. Если они расходятся, побеждает более поздний [16].
   - Источник: [13][22][63][18][16].
8. **Прогресс реализации записан в самом плане.**
   - Как работает: skill-оркестратор запускает по implementer subagent на фазу. Потом сам заново запускает builds,
     tests и lint и коммитит фазу. Прогресс отмечается чекбоксами `- [x]` и заголовками `✅ Phase N` в artifact.
     Продолженный run начинает с первого неотмеченного пункта [77][78][81].
   - Чем интересно: продолжить работу после сбоя или в новой session можно без отдельного хранилища состояния.
   - Источник: [77][78][81].
9. **Атрибуция коммитов агента через trailer и очистка чужих коммитов.**
   - Как работает: git hooks вне репозитория, которые включаются переменной окружения, добавляют в коммиты агента
     trailer `HumanLayer-Session`. Наблюдатель за HEAD приписывает коммиты по trailer, а без него — по совпадению
     содержимого. Коммиты людей, которых не приписал ни один способ, перед загрузкой лишаются сообщения, автора и путей
     файлов [95][96][11].
   - Чем интересно: связь между PR и session строится без файлов в репозитории и без отправки чужих коммитов в облако.
   - Источник: [95][96][11].
10. **Mirror sessions, запущенных в своём терминале.**
    - Как работает: plugin Claude Code состоит из модуля hooks и MCP server без инструментов. Он читает файлы
      transcript с сохранённых смещений в байтах и переводит записи в события HumanLayer. Шлёт heartbeat каждые 15
      секунд как host, который только зеркалирует. Вставляет ответы из веба как prompts, зеркалит approvals в обе
      стороны, убирает `HUMANLAYER_PAT` из окружения Bash [70]. Такие же plugins есть для OpenCode и pi [71][72].
    - Источник: [70][71][72].
11. **Context Shards — правила организации, извлечённые из прошлых sessions.**
    - Как работает: LLM отбирает из прошлых разговоров короткие правила, у каждого — объяснение и до 5 цитат.
      Администратор выпускает или отклоняет каждое правило. Пользователь включает или нет. Включённые правила
      вставляются в системный prompt только при свежем запуске, не при resume и fork; до 100 за запуск [92][63][11].
    - Источник: [92][63][11].
12. **Цикл CI в `describe-pr` с лимитом попыток.**
    - Как работает: skill создаёт или обновляет описание PR. Ждёт 5 минут и проверяет, можно ли сделать merge.
      Запускает `gh pr checks --watch --fail-fast`. При сбое читает logs. Чинит падения, которые вызвал PR, а flaky или
      не связанный сбой перезапускает один раз. После 3 попыток на один check останавливается. Merge conflicts без
      одобренного плана не разрешает [79][11].
    - Источник: [79][11].
