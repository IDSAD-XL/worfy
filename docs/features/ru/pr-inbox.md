# Pull requests

> Перевод [английской версии](../pr-inbox.md), commit `same-pr`.

**PR inbox** Project-а: открытые pull request-ы (PR) пользователя и запросы ревью у него в репозиториях Project-а,
сгруппированные по тому, чей ход, с нитями ревью и их последними комментариями. В UI — **Pull requests**. Вид только
читает GitHub: ничего в нём не публикует, не закрывает нити и ничего не помечает там
([ADR-0105](../../adr/0105-pr-reply-only-on-the-users-click.md)). Термины — в [Concepts](concepts.md); badge-и PR и CI
у Ticket-а — на странице [Gate и GitHub](gate-and-github.md).

## Вид Pull requests

### Поведение

**Где открывается.**

- **Pull requests** в View switch toolbar-а — пятая вкладка после Canvas, Session, Pipeline и Runs. Без Project-а
  вкладка неактивна, tooltip говорит открыть Project.
- Строка **Pull requests** в Command palette, группа View, при открытом Project-е.
- Группа в разделе **Pull requests** sidebar-а: вид Project-а этой строки, прокрученный к этой группе, её заголовок
  выделен, её первый PR выбран (увиденным не помечается). Строка другого Project-а сначала выбирает этот Project.

Вид принадлежит активному Project-у. У другого Project-а — свой inbox и свой выбор.

**Две панели.** Слева — компактный список PR по группам, справа — выбранный PR целиком. В окне, где под вид остаётся
уже примерно 720 px, список стоит над PR, и каждая часть прокручивается сама.

**Группы.** Пять, всегда в этом порядке, у заголовка каждой — счётчик. Список показывает только группы, где есть PR.

| Группа | Что в ней |
|---|---|
| Needs my review | Ревью просят у пользователя — лично или через команду — или просят снова после его ревью |
| Needs my answer | Нерешённая нить, последний комментарий которой не пользователя, — на его PR или в нити, где он писал; упоминание пользователя новее его последнего комментария там |
| Needs a fix | PR пользователя с красным CI, запрошенными правками или конфликтом merge |
| Ready | PR пользователя одобрен, зелёный, без конфликта. Вливают люди: группа — напоминание тому, кто вливает |
| Waiting on others | PR пользователя, хода пользователя нет |

Группу и порядок внутри неё решает main: Needs my review — сначала старые PR, остальные — сначала старая активность.
PR без Ticket-а — такая же строка, как остальные.

**Строка списка.** Аватар автора (две буквы login-а на своём цвете; у самого пользователя — с кольцом), заголовок, под
ним имя репозитория и номер (`web#41`; весь `owner/repo#N` — tooltip), chip Ticket-а (`<epic> <NN>`), если PR — Ticket-а,
и точка CI — с текстом рядом, когда CI не зелёный. Справа: возраст, число открытых нитей со значком реплики (оранжевое на
PR самого пользователя, где ждут его; tooltip — «2 open threads») и синяя точка, когда есть новые комментарии (tooltip —
«N new since you looked»).

- **Заголовок**: обрезается многоточием, когда не помещается; весь заголовок — его tooltip.
- **Точка CI**: зелёная — проходит, оранжевая — упал, пустое синее кольцо — идёт, пустое серое кольцо — CI нет. Её текст —
  tooltip.
- **Возраст**: у Needs my review — возраст PR; в остальных — его последнего комментария или ревью. В tooltip — время.
  Цвет говорит, сколько PR ждёт: серый — меньше 12 часов, светлее — меньше 3 дней, оранжевый — меньше 14 дней, красный —
  дольше.
- **Chip Ticket-а**: Ticket, чья строка `PR:` называет этот PR, иначе Ticket, чья ветка — ветка PR (его строка `Branch:`
  или `<epic>/<NN>`). Номер считается только в своём репозитории: `PR: lib#41` называет #41 репозитория с именем `lib`
  (или `owner/lib`), а голый `PR: #41` — #41 репозиториев из строк `Repo:` Ticket-а; любого репозитория — только когда
  строки `Repo:` у Ticket-а нет.
- **N new since you looked**: комментарии других новее последнего взгляда пользователя на PR.

**Выбор.** Щелчок по строке выбирает её PR; **↑** и **↓** двигают выбор по списку — откуда угодно в показанном виде,
кроме текстового поля, меню и диалога, — и останавливаются на его концах. Пока пользователь не выбрал, вид сам выбирает
первый PR, который ждёт ответа пользователя, иначе первый в списке; PR, ушедший из inbox, уступает этому выбору. Если PR
один, выбран он.

**Выбранный PR.** Правая панель показывает:

- заголовок, `owner/repo#N`, chip Ticket-а, `Draft` у черновика PR, «via team», если ревью просят только у команды
  пользователя, автора, ветку и «N new since you looked»;
- **что делать дальше** — одна плашка в цвете группы PR, по группе, CI, ревью и черновикам: «Your review is asked» с
  **Start review** (вкладка Files на GitHub); «Answer N open threads» — сколько черновиков ответов готово ниже, или что их
  напишет Draft replies; «CI failing», «Changes requested» или «Merge conflict» с **Open checks**, когда CI упал; «Ready to
  merge» с **Open to merge**; «Waiting for reviewers» или «Draft PR: no review asked yet»;
- четыре ячейки: **CI**; **Review** (Approved, Changes requested, Review required или None yet); **Merge** (Mergeable,
  Behind the base, Blocked, Checks failing, Conflicts, Draft или Unknown — по состоянию merge на GitHub); **Size** —
  добавленные и удалённые строки (`+184 −22`) с полосой их долей, или `—`, если GitHub их не дал;
- **Open on GitHub**, **Draft replies** и **Mark seen** — активна, пока у PR есть новые комментарии;
- «Threads N open · M resolved», затем нити ревью — сначала открытые, потом решённые, приглушённые. У каждой — файл и строка, ссылка на комментарий на GitHub
  (там видна эта строка кода), `Outdated`, если код ушёл вперёд, и её последние три комментария с автором и возрастом.
  Удалённый аккаунт — `ghost`, как на GitHub;
- **Conversation**: последние комментарии вкладки разговора PR, если они есть.

Выбор PR — щелчок, **↑** или **↓**, вход, который называет PR, — и **Mark seen** записывают, что пользователь посмотрел:
«N new since you looked» гаснет. PR, который вид выбрал сам, и первый PR группы, о которой попросила строка sidebar-а, не
записывают ничего. Черновики ответов читаются только у выбранного PR. Ссылки открываются в браузере системы, никогда не в окне.

**Строка состояния** под заголовком:

- «Next search in 4 min» или «Next search now», когда время пришло; в tooltip — время;
- «The last read failed: <причина>», если последнее чтение GitHub упало или читатель ждёт rate limit;
- notice читателя, если он есть, например «GitHub notifications unavailable for this token — checking every 5 minutes»;
- «Mark seen failed: <причина>», если main не смог записать взгляд.

До первого ответа вид пишет «Reading pull requests…». Project, который не читает pull request-ы — переключатель выключен
в Project settings или ни один его репозиторий не на GitHub, — показывает об этом одну строку и ни одной панели. Чтение
без единого PR показывает вместо панелей спокойную заметку «No open pull requests and no review requests.»

**Открытие на одном PR.** Вход может попросить один PR Project-а: открывается вид этого Project-а, PR выбран, его строка
прокручена в поле зрения, PR помечен увиденным. Если в inbox такого PR нет, вид открывается и пишет «This pull request is
not in the inbox: owner/repo#N».

**Раздел sidebar.** **Pull requests**, под Pipeline. Для каждого Project-а Machine окна, у которого есть PR: его имя,
потом строка на каждую непустую группу со счётчиком. Project, который не читает pull request-ы или не имеет их, не
показывает ничего. Если нигде ничего нет, раздел пишет «No pull requests». Project, чей inbox не читается, пишет почему.

**Переключатель.** В Project settings — **Read pull requests from GitHub**, по умолчанию включён. Выключенный, worfy не
запускает gh для PR inbox этого Project-а, вид сразу говорит об этом, а sidebar его не показывает. Включённый снова,
Project читается сразу, не дожидаясь следующего поиска. Переключатель применяется по Save, как остальные поля окна.

#### На Linked machine

Окно на Linked machine показывает inbox Project-а той Machine, как та его прочитала; само оно GitHub не спрашивает. С
доступом Read only PR можно выбирать, но ничего не помечается увиденным, **Mark seen** неактивна с подсказкой read-only,
переключатель Project settings неактивен. Ссылки открываются на той Machine, где по ним щёлкнули.

### Как работает

- GitHub читает main — по Project-у, с GitHub-аккаунтом Project-а, только репозитории Project-а: поиск раз в 5 минут,
  потом детали сдвинувшихся PR, среди них размер (`additions`, `deletions`). Main считает группы и счётчики и шлёт виду снимок
  ([ADR-0105](../../adr/0105-pr-reply-only-on-the-users-click.md), пункт 1). Вид его только рисует.
- Слова коллег остаются в памяти main. Что пользователь видел, идёт в папку данных Project-а — id, commit и время, без
  текстов ([ADR-0005](../../adr/0005-worfy-own-state-inventory.md) с поправкой ADR-0105).
- Renderer держит одну копию inbox каждого Project-а для вида и раздела. Он спрашивает main снова, когда main сообщает
  об изменении inbox и когда меняются настройки Project-а, — так переключатель виден сразу.
- Main читает Project-ы по одному: чтения по таймеру и чтение по запросу (Project показан впервые или включён снова) ждут
  друг друга в одной очереди.
- Все входы, открывающие вид, идут через одну функцию. С PR она оставляет просьбу; вид берёт её, когда снимок пришёл, и
  стирает, поэтому возврат к виду не выбирает этот PR снова.
- Правая панель привязана к PR (React `key`): другой PR начинает со своих черновиков, набранных текстов и прокрутки.
  Shell держит все виды смонтированными и прячет лишние, поэтому **↑** и **↓** работают, только пока этот вид показан.
