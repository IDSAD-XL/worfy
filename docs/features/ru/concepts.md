## Canvas

**Project** — папка одной работы пользователя: git-репозиторий или папка над несколькими репозиториями. У Project ровно
один **Canvas** — бесконечная плоскость, на которой лежат **Node**-ы. Node — любой объект на Canvas: Ticket, Session, Card,
Terminal и так далее. Положение и размер Node-ов — это **Layout**, собственное состояние worfy, а не часть workflow.

**Derived Node** — Node, место которого считает worfy из workflow: рамка Epic-а, Ticket, дерево Subagent-ов. Ticket и дерево
Subagent-ов руками не двигаются, рамка Epic-а двигается только целиком. **Edge** — линия между Node-ами одного из трёх видов:
Blocked by (Ticket → Ticket), Binding (Session или Subagent → Ticket или Epic) и Subagent (Session → Subagent). **Family** —
Node и всё, что связано с ним Binding-ами и деревом Subagent-ов. Family подсвечивается при наведении и выделении, Node-ы при
этом не двигаются.

**Card** — небольшое HTML-приложение, которое собрал агент. Card принадлежит Project, а не Session, поэтому менять её может
любая Session этого Project. **Terminal** — Node с интерактивной shell-сессией пользователя; агенты им не пользуются.
**Browser** — Node со встроенным браузером Chromium: сайт или веб-приложение, открытое под одним **Browser profile**. Browser
бывает **Live** — страница работает — или **Asleep** — на его месте последний снимок страницы, а сама страница закрыта до
пробуждения. Browser profile — сохранённый вход под одной ролью, куки и данные сайтов. Входит в аккаунт пользователь;
Session-ы приходят уже со входом и паролей не видят. Browser profile принадлежит Project и лежит на Machine.

**Done shelf** — ряд chip-ов под видимыми рамками Epic-ов: Epic, у которого все Ticket-ы done и рамка свёрнута, стоит там
chip-ом с именем и счётом. **Archive** хранит законченные Session-ы, которые worfy убрал с Canvas сам: в истории их Ticket-а
или Epic-а, а без Binding-а — в popover «Archive». Он ничего не удаляет, срока не имеет и корзиной не является. **Limits** —
доля использованных окон подписки Claude (5 часов и 7 дней) и время их сброса.

## Workflow

**Epic** — набор Ticket-ов под одну цель, лежит в папке `.scratch/<epic>/`. **Ticket** — одна единица работы внутри Epic-а
(`issues/NN-slug.md`) со статусом `open`, `claimed`, `blocked` или `done` и списком Ticket-ов, которые его блокируют.
**Wave** — Ticket-ы Epic-а, которые можно брать в работу параллельно прямо сейчас: открыты, все блокеры закрыты, общих файлов
нет. Wave вычисляется и нигде не хранится; нумерованные Wave-ы в `spec.md` Epic-а — это прогноз, а Wave, которую берут в
работу, вычисляется заново при запуске.

**Feature** — возможность продукта, которой пользуется разработчик. Он живёт дольше любого Epic-а, и его меняют несколько
Epic-ов. **Feature page** описывает один Feature или несколько близких в их текущем состоянии.

**Pipeline** — упорядоченный список **Stage**, через которые проходит каждый Ticket одного Project-а; у каждого Project-а он
свой. Без настройки это Queued, Implementing, CI, Agent review, Gate & merge, Closing, Done. Stage вычисляется из статуса
Ticket-а, его ветки, PR и отметок проверок и нигде не хранится. Статус — не Stage: один `claimed` идёт на нескольких Stage
подряд, а `blocked` — пометка на любом Stage.

Файлы workflow (Epic-и с Ticket-ами, HANDOFF, ADR, lessons) лежат в **Workflow folder** Project-а. Project работает в одном из
двух режимов. В **Full mode** Workflow folder — это корень репозитория, и файлы видны всем, кто с ним работает. В **Silent
mode** это папка вне репозитория, которую пользователь выбирает при подключении Project-а. Тогда в репозитории от workflow не
остаётся следа: ни в файлах, ни в ветках, commit-ах и PR. Project над несколькими репозиториями всегда в Silent mode.
**HANDOFF** — файл в Workflow folder со снимком текущего состояния работы: что в работе, что дальше и что ждёт владельца.

**Autopilot** — режим, в котором Wave-ы Epic-а идут без человека. worfy не даёт Machine уснуть, ждёт сброса Limits и
продолжает с того же места; любая точка, где понадобился человек, считается дефектом. **Stable copy** — собранная копия worfy
вне репозитория, из которой Autopilot ведёт Wave-ы самого worfy: на macOS `~/Applications/worfy-stable.app`, на Windows папка
`%LOCALAPPDATA%\worfy-stable`. Она обновляется между запусками. Во время запуска агенты Wave собирают и проверяют dev-сборку в
своих worktree.

**Gate** — проверка готовности изменений (`gate.mjs`) с исходом «зелено», «красно» или «не удалось проверить». Это не CI на
GitHub. **Gate full** — полный Gate на одной Machine: lint, typecheck, все test-ы, e2e и проверка собранного приложения. Gate
fast — то же без e2e и сборки. С [ADR-0083](../../adr/0083-ci-ok-on-every-pr-is-the-merge-condition.md) PR вливается, когда на его head-коммите
есть три вещи: зелёный check `ci-ok` CI на GitHub, commit status `review` со значением `success` (ревью агентов пройдено) и
отметка `check/windows` со значением `success` (Windows verdict, см. ниже). PR только с документами не требует `check/windows` и ревью агентов, кроме страницы `docs/features/`: её проверяет один агент. Gate full — инструмент implementer-а и разбора сбоя. **Windows verdict** отвечает на вопрос,
работает ли изменение PR на Windows. Для каждого PR это job `windows` в составе `ci-ok`. Для платформенного PR, который трогает
то, чего GitHub runner не проверяет (Terminal, окна, меню, уведомления, e2e, упаковка), это Gate full на Windows-ПК владельца.
Какой из двух нужен, решает скрипт scope, а этот Gate full идёт на `main` после merge
([ADR-0086](../../adr/0086-pc-gate-full-once-per-wave.md)).

## Agents

**Session** — один разговор с Claude Code: один транскрипт, который можно продолжить. На Canvas одна Session — один Node, где
бы она ни была запущена (worfy, терминал, Claude desktop). **Orchestrator** — главная Session Project-а, из которой расходится
работа; у каждого Project-а она ровно одна и закреплена на Canvas. **Subagent** — агент, которого Session запустила для части
работы, например scout, implementer или reviewer. У него свой транскрипт и итог, он принадлежит запустившей его Session и может
запускать своих Subagent-ов.

**Interrupted** — Subagent, процесс Session которого кончился раньше, чем он закончил; это не сбой. **Background task** — работа,
которую Session запустила и не ждёт в своём ходе: Subagent, команда Bash с `run_in_background` или workflow-скрипт. Она живёт,
пока жив процесс Claude Code её Session, а о конце сообщает task-notification, которая начинает новый ход Session. Background
task — не Ticket.

**Binding** связывает Session или Subagent с Ticket-ом либо Epic-ом, над которым он работает. Binding определяется по сигналам
из работы агента или задаётся пользователем вручную. У Session или Subagent-а не более одного Binding-а, а у Ticket-а их может
быть несколько (реализация, ревью, доработка).

**Harness** — набор правил, skills, агентов, скриптов и hooks, по которому агенты Claude ведут работу над Project: Epic-и,
Ticket-ы, Wave-ы, Gate и ревью. В него входит qmd — поиск по документам и Ticket-ам Project-а. worfy его ставит и обновляет.
Остальные личные skills, MCP-серверы и память пользователя в него не входят. Harness один на Machine и ведёт каждый Project по
его **Profile**: как проверять изменения, где лежат Ticket-ы, как называются ветки и worktree, линзы ревью, MCP-серверы для
агентов, аккаунт GitHub и режим. Profile целиком лежит на Machine пользователя, в репозитории его нет. **User personalization** —
собственные настройки пользователя для Harness, вне plugin и вне Profile, одни для всех его Project-ов: язык отчётов и личные
правила.

## App и Machines

**Settings** — настройки самого worfy на этой Machine и окно, где они меняются. Это собственное состояние worfy, они действуют во
всех Project-ах этой Machine и не попадают ни в репозиторий Project-а, ни в Profile. **Getting started** — список из шести шагов
для нового пользователя: от проверок First run до Ticket-а Demo project, доведённого через ревью и доработку до merge. Шаги
отмечаются сами, когда сделаны; список можно пропустить, и он ничего не блокирует. **Demo project** — Project, который worfy
создаёт сам для Getting started: маленький локальный git-репозиторий без GitHub, в Full mode, с одним Epic-ом и одним Ticket-ом.
Агенты работают в нём по-настоящему, а удаляется он одной командой вместе со своим Profile.

**Machine** — компьютер пользователя, на котором стоит worfy. Точнее, Machine привязана к папке данных worfy, поэтому две
установки с разными папками данных на одном компьютере, например dev-сборка и Stable copy, — это две Machine. Project живёт ровно
на одной Machine: там лежит его папка и работают его Session-ы, worktree и Gate. Один репозиторий, подключённый на двух Machine, —
это два Project-а, у каждого свой Canvas.

**Linked machine** — Machine, связанная с этой по коду из 6 цифр. Связь двусторонняя, удаляется (Remove) с любой стороны. Если
здесь включён доступ «Linked machines can work with my Projects» (по умолчанию выключен), Linked machine видит Project-ы этой
Machine и работает с ними: открывает Canvas, пишет в Session, печатает в Terminal и запускает Autopilot. Всё это выполняется на
Machine Project-а.

## Terminal AI

**Terminal AI** — помощь модели Claude в Terminal-е и раздел Settings, где она включается и выключается. Это не Session и не
агент: у него нет транскрипта, Node-а и Binding-а, он ничего не запускает и только предлагает текст для строки ввода. Команду
запускает пользователь. Его запросы расходуют Limits.

**Suggestion** — серый текст в строке ввода, продолжение того, что пользователь набирает, из истории его команд или от модели.
Пользователь принимает его целиком или по словам либо скрывает; пока он не принят, он не часть строки. **Next command** — Suggestion
на пустой строке после законченной команды. **Command request** — просьба словами, что нужно сделать в Terminal-е; в ответ в строку
ввода встаёт команда, которая не запускается. **Fix** — действие после команды, которая кончилась ошибкой: Terminal AI ставит в
строку ввода исправленную команду и не запускает её.
