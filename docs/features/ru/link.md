# Link

> Перевод [английской версии](../link.md), commit `c1ea91d9`.

Две Feature. **Machine** — это данный worfy так, как его знает link: id, имя, ключ и сертификат, привязанные к одной
папке данных. **Linked machine** — другая Machine, соединённая с этой по шестизначному коду. Её Project-ы можно открыть
отсюда, если она это разрешает. Термины объяснены в [Concepts](concepts.md).

## Machine

### Behaviour

Machine — это одна папка данных worfy, а не один компьютер. У dev-сборки и у копии Stable на одном Mac разные папки,
поэтому это две Machine, и их можно соединить друг с другом.

**Identity.** Первый запуск над папкой данных создаёт Machine: id, имя, закрытый ключ и сертификат. Папка их хранит.
Имя — это имя компьютера без домена, например `Alexeys-MacBook-Pro`. Распакованная сборка добавляет ` (dev)`, иначе две
Machine на одном Mac показывали бы одно имя. Узкая строка обрезает само имя и оставляет `(dev)` видимым. В интерфейсе
нет действия, которое переименует Machine, и последующее переименование компьютера сохранённое имя не меняет.

**Project-ы.** Project живёт ровно на одной Machine: там его папка, Session-ы, worktree и Gate. Одна папка, подключённая
на двух Machine, — это два Project-а, у каждого свой Canvas и свой Layout. Перемещение Node в одном не двигает Node в
другом.

**Прослушивание.** У Machine без Linked machine открытого порта нет. Сервер link слушает, только пока на это есть
причина:

| Причина | Как долго |
|---|---|
| Есть хотя бы одна Linked machine | Пока не удалена последняя |
| «Link a machine» открыт в окне этой Machine | Пока его не закроет последнее такое окно или пока не наберётся слишком много неудачных попыток |
| Эта Machine сама соединяется с другой | На время этой попытки, чтобы другая сторона узнала порт, который отвечает |

**Порт.** При первом прослушивании порт выбирает операционная система. worfy запоминает его и просит тот же при следующем
запуске, поэтому Linked machine находит эту Machine там же, где и раньше. Если порт занят, система выбирает новый, и
дальше хранится он. Сервер слушает на всех интерфейсах. Порт, который не удалось занять, или ключ, который не удалось
прочитать, никогда не останавливают worfy. Остальные части приложения работают, а «Link a machine» показывает причину.

**Раздел Machines.** «Machines» в sidebar стоит между Projects и Epics и свёрнут, пока пользователь его не развернёт.
В нём список Linked machine, а под списком «Link a machine…». Переключатели link находятся в Settings → Machines. И то, и
другое описано в разделе [Linked machine](#linked-machine).

### How it works

- **Machine принадлежит папке данных.** Первая проверка link должна была работать с dev-сборкой и копией Stable на одном
  Mac, поэтому Machine нельзя узнавать по имени компьютера, а два worfy не могут делить один порт
  ([ADR-0052](../../adr/0052-machines-and-linking.md), [ADR-0023](../../adr/0023-separate-data-roots-packaged-and-dev.md)).
  Роли host и client относятся к одному соединению. Любая Machine играет обе.
- **Самоподписанный сертификат, без центра сертификации.** Сертификат — ECDSA P-256, действует 20 лет и начинается на день
  раньше текущего времени. Доверие держится на fingerprint, запомненном при соединении, поэтому корневой сертификат нигде
  не устанавливается.
- **Потерянный ключ даёт новый сертификат с тем же id.** Ключ, которого нет или который не подходит к сертификату,
  заменяется при запуске, с предупреждением в log. Linked machine тогда видят «Certificate changed» и должны соединиться
  заново.
- **Секреты лежат в обычном файле.** Закрытый ключ и token-ы, которые эта Machine предъявляет другим, нужны как есть, так
  что хешами они быть не могут. `link/secrets.json` в папке данных пишется с правами 0600 в папке с правами 0700, как ssh
  хранит свои ключи. safeStorage из Electron не используется: на macOS он держит свой ключ в Keychain под подписью кода
  приложения, а ad-hoc подпись worfy меняется с каждой сборкой. Windows использует тот же файл, не DPAPI.

### Implementation

| Что | Где |
|---|---|
| Id, имя, сертификат; `link/machine.json` | `src/main/link/identity.ts` |
| Хранилище секретов; `link/secrets.json` | `src/main/link/secrets.ts` |
| Сервис: причины слушать, порт, link приложения и его остановка при выходе | `src/main/link/service.ts` |
| Запуск и выход в приложении | `src/main/index.ts` |
| Папка данных | `src/main/storage/paths.ts` |

Файлы Machine лежат в `<data folder>/link`: `machine.json`, `secrets.json`, `linked.json`, `settings.json` и journal
`link.log`. `src/main/link/service.ts` также читает три переменные окружения для test-ов: `WORFY_LINK_HOST` (единственный
адрес для прослушивания), `WORFY_LINK_BONJOUR=0` (Bonjour выключен) и `WORFY_LINK_INTERFACES` (интерфейсы машины, только
в распакованной сборке).

Test-ы: `test/contract/link-server.test.ts` (когда сервер слушает, сертификат на настоящем TLS),
`test/unit/link-secrets-write.test.ts`. `test/contract/link-bench.ts` запускает несколько сервисов над временными папками
данных в одном процессе.

## Linked machine

### Behaviour

#### Связывание

1. Откройте «Link a machine…» на обоих worfy. Каждый показывает свой шестизначный код и свои адреса.
2. На любом из них выберите другой worfy в списке или введите его адрес как `host:port` и нажмите Next.
3. Введите код, который показывает другой worfy, затем Link.

После этого оба окна говорят `Linked with <name>`, и каждая Machine показывает другую в Machines. Link работает в обе
стороны, поэтому вторая сторона заново не соединяется. Machine, которая уже соединена, окно показывает как «Already
linked», без возможности соединиться, и говорит, какой переключатель включить на той стороне. Новый link начинается с
доступа Off на обеих сторонах.

**Список.** Пока окно открыто, Bonjour ищет и показывает worfy, найденные в локальной сети, кроме этой Machine; у уже
связанных Machine свои строки «Already linked». Хранится не больше 64 объявлений. Объявление — это заявление, а не
доказательство. «Two addresses» отмечает два объявления с одним id Machine на разных адресах, одно из которых — не та
Machine. «Other version» отмечает worfy с другим протоколом link: связывание с ним будет отклонено, пока оба не запустят
одну версию.

**Код.**

| Правило | Значение |
|---|---|
| Длина | 6 цифр |
| Срок жизни кода | 2 минуты, затем сам появляется новый |
| Код сгорает | От первого сообщения обмена любой попытки, в том числе неудачной; затем появляется новый код |
| Попыток одновременно | Одна; вторая получает «another Machine is linking right now; try again in a moment» |
| Ожидание каждого шага обмена | 15 секунд |

Неверный код даёт «the code did not match, or the connection to the other Machine was intercepted; nothing was linked».

**Слишком много неудач.** Каждая попытка — это одна догадка об одном коде, и попытка, закончившаяся до первого сообщения,
тоже считается. 10 неудач подряд закрывают связывание на это открытие. 10 неудач за скользящий час, считая все открытия и
все адреса, закрывают связывание и ставят его на паузу, пока самой старой из десяти не исполнится час. Во время паузы:

- Окно говорит `Linking is paused until <time> after repeated failed attempts. Restart worfy to link sooner.`
- Machine показывает одно уведомление с числом попыток и адресами, с которых они пришли.
- worfy, который пытается связаться во время паузы, узнаёт, что связывание на паузе, но не узнаёт, до какого времени, если эта
  Machine ещё слушает: так бывает, пока у неё есть Linked machine или пока она сама связывается с другой. Иначе порт закрыт,
  и он получает «could not reach».
- Когда пауза заканчивается, открытое окно само снова открывает связывание.

Счётчик живёт в памяти, поэтому перезапуск снимает паузу. На уже соединённые Machine это не влияет.

**Другие отказы.** Они тоже ничего не сохраняют: адрес самой этой Machine; id Machine, уже соединённой здесь с другим
сертификатом, с текстом, который просит сначала удалить её; worfy с другим протоколом link, с текстом, который называет обе
версии.

**Закрытие окна.** Окно закрывают Close, Esc или клик вне окна. Связывание остаётся открытым, пока оно открыто в любом окне
этой Machine. Когда закрывается последнее, идущая попытка обрывается и ничего не сохраняет.

#### Состояния Linked machine

| Состояние в разделе Machines | Значение |
|---|---|
| Online | Соединение открыто, неважно какой стороной |
| Sleeping | Она сказала, что засыпает, не сказала, что проснулась, и с тех пор не открылось ни одного соединения. Это состояние важнее соединения, которое ещё не оборвалось |
| Offline | Соединения нет, такого сообщения не было. worfy продолжает пытаться |
| Certificate changed | Последний dial встретил сертификат, отличный от запомненного. Tooltip просит удалить её и соединиться заново |

Точка рядом с заголовком «Machines» видна и при свёрнутом разделе. Она янтарная, когда хотя бы у одной Machine «Certificate
changed». Иначе она зелёная и пульсирует, когда хотя бы одна online, а их число — в её tooltip. Если online нет никого,
точки нет.

Под каждой строкой — строки доступа. «Can work with your Projects» или «Can't see your Projects» описывают это
направление. «Shares its Projects with you» или «Doesn't share its Projects» описывают другое направление и появляются,
только пока Machine подключена и сообщила об этом.

#### Reconnect, Change address, Remove

У строки без соединения есть кнопки Reconnect, Change address… и Remove. В контекстном меню любой строки те же действия,
без Reconnect для Machine в online. В Command palette есть «Reconnect machine…» для каждой Machine без соединения и «Remove
machine…» для каждой.

**Переподключение автоматическое.** Пауза между dial удваивается от 1 секунды до 30 секунд, а открытое соединение её
сбрасывает. worfy делает dial сразу, без паузы, в трёх случаях: при пробуждении, при смене адресов этой машины и при
Reconnect. Адреса читаются каждые 5 секунд. В счёт идут только адреса IPv4, по которым может идти link: локальной сети
и Tailscale, не 169.254/16 и не IPv6. Новый набор засчитывается, когда его видят два чтения подряд, поэтому на смену
worfy реагирует через 5–10 секунд после неё, а строка journal называет пришедшие и ушедшие адреса. Пока идёт dial, Reconnect показывает «Connecting…» и неактивен.

Один dial пробует по порядку, с лимитом 10 секунд на шаг: запомненный адрес; имя Machine в `.local`, если известно; её имя
MagicDNS, если известно и пока включён «Link through Tailscale»; адрес, где её сейчас видит Bonjour, если он другой.
Machine, которая отвечает «not linked», сразу заканчивает dial. Другой протокол на запомненном адресе отменяет попытки по
именам, но адрес, где её видит Bonjour, всё равно пробуется.

Bonjour ищет, пока Linked machine недоступна, и её объявление сразу получает там один dial. Любой адрес, кроме запомненного,
засчитывается, только когда там отвечает запомненный сертификат. Тогда новый адрес сохраняется.

Соединение проверяется ping-ом каждые 15 секунд, и соединение без pong к следующему ping обрывается. При пробуждении или
смене сети каждое открытое соединение проверяется сразу и обрывается, если pong не пришёл за 3 секунды.

**Change address…** принимает адрес или имя с портом. worfy сохраняет его, только если там отвечает сертификат, с которым
Machine соединялась, и этот dial становится соединением: все остальные соединения между двумя Machine, какая бы сторона ни
сделала dial, закрываются, и у пары остаётся только новое. Machine всё это время остаётся на связи, без «disconnected», а
journal на каждой стороне записывает, какое соединение каким заменено. Другой сертификат или отсутствие ответа окно
показывает как отказ, а адрес и открытые соединения остаются прежними.

**Remove** всегда сначала спрашивает, и фокус начинается на Cancel. Он сразу забывает Machine здесь, включая её уровень
доступа и token-ы. Другая сторона теряет link сразу, если подключена, иначе при следующем соединении: она получает отказ и
тоже забывает эту Machine. Удаление последней Linked machine останавливает сервер, поэтому другая сторона показывает этот
компьютер как Offline, пока тоже не удалит его или пока здесь не откроют «Link a machine». Новое соединение требует нового
кода.

«Certificate changed» снимается, когда запомненный сертификат отвечает снова, например если адрес занимал другой worfy.
Machine, у которой действительно новый сертификат, нужно удалить на той стороне, которая помнит старый, и соединиться заново.

#### Доступ к Project-ам этой Machine

Для доступа в Settings → Machines есть один переключатель и уровень для каждой Linked machine.

«Linked machines can work with my Projects» по умолчанию выключен. Выключен — значит Off для всех, какой бы уровень ни был
задан: строки уровней неактивны и показывают Off, а сохранённые уровни показываются снова, когда переключатель включён.

| Уровень | Что получает Linked machine |
|---|---|
| Off | Не может видеть и менять Project-ы. Любой вызов, кроме собственного ping самого link, получает отказ «access is off». |
| Read only | Видит Project-ы, Session-ы и уведомления. Вывод Terminal не покидает эту Machine, а любое изменение получает отказ. В transcript Session может оказаться секрет, так что и это требует доверия. |
| Full access | Работает с Project-ами так же, как пользователь здесь: Session-ы, Terminal, Autopilot. |

Изменение действует сразу, и соединение остаётся. Подписки Linked machine заканчиваются, а вызов, который уже идёт,
завершается. Между Read only и Full access её окна на этой Machine загружаются заново. При Off они оставляют свой Canvas под
строкой, описанной ниже.

**Off закрывает вход, а не работу.** Session-ы и run-ы Autopilot, запущенные с Linked machine, продолжают идти, в том числе
после Remove. Человек за этой Machine останавливает их обычными действиями. Исключение — Terminal: shell заканчивается, когда
уходит его последний экран, поэтому shell, открытый только с этой Linked machine, заканчивается вместе с её доступом.

**Что не открывает ни один уровень:**

- Ничего за пределами Project-ов этой Machine. Путь оценивается по его настоящему пути, поэтому `..`, символическая ссылка из
  Project-а наружу или другое написание папки не проходят.
- Действия, которым нужен этот рабочий стол: системный диалог или shell ОС.
- Состояние этого экрана: активный Project, меню, Limits, настройки link и код связывания.
- Project, локальный для этой Machine (Demo project). Linked machine его не видит, а вызов с его именем получает отказ.

#### Keep awake

«Keep this computer awake while linked machines are connected» по умолчанию включён. Система не засыпает, а дисплей может
погаснуть, пока выполняется всё сразу: переключатель включён, доступ включён и хотя бы одна подключённая Linked machine имеет
Read only или Full access. Блокировка снимается, как только что-то из этого перестаёт выполняться, и при выходе. При
выключенном доступе переключатель неактивен и показывает выключенное состояние, а сохранённое значение показывается снова,
когда доступ включён.

#### Link through Tailscale

По умолчанию сервер принимает только соседей из локальной сети и loopback: 127/8, 10/8, 172.16/12, 192.168/16 и 169.254/16, а
в IPv6 ::1, fc00::/7 и fe80::/10. Проброса портов, туннеля и relay нет. «Link through Tailscale» добавляет tailnet
пользователя по таким правилам:

- По умолчанию выключено и от доступа не зависит. Настройка решает, кто вообще может достучаться до сервера, в том числе для
  связывания.
- Должно быть включено на обоих компьютерах. Dial на адрес Tailscale с выключенной настройкой получает отказ с текстом, где
  её включить.
- Сосед из диапазона Tailscale (100.64.0.0/10, fd7a:115c:a1e0::/48) проходит, только когда соединение пришло на адрес
  Tailscale этой машины. 100.64.0.0/10 — это ещё и carrier-grade NAT, поэтому сосед у того же провайдера приходит на домашний
  адрес и получает отказ.
- Выключение закрывает соединения и попытки соединиться через Tailscale, в обе стороны.

Пока настройка включена, «Link a machine» показывает адреса Tailscale этой Machine первыми, с отметкой «Tailscale», а поле
адреса принимает и имя MagicDNS с портом, например `pc:52000`.

**Список tailnet.** Пока настройка включена, «In your tailnet» берётся из `tailscale status --json`: сначала машины online,
без этой Machine и без Linked machine, известных по адресу Tailscale или имени MagicDNS. Выбор машины online подставляет её
адрес в поле, а порт всё равно вводится вручную: он указан под кодом на другом worfy. Машина offline серая, и выбрать её
нельзя. Нет CLI — нет списка. CLI, который падает или не отвечает за 3 секунды, тоже не даёт списка: одно предупреждение в
log и никакой ошибки в окне.

**Имя MagicDNS этой машины.** Пока настройка включена, сервер принимает имена `Host` под `ts.net`, только если это
собственное имя MagicDNS этой машины. worfy читает это имя, `Self.DNSName`, из `tailscale status --json` при первом запросе
на соединение после смены сети и хранит его до следующей смены. Запрос ждёт CLI не больше 3 секунд. Полное имя и его первая
часть проходят; любое другое имя под `ts.net` получает отказ. Если CLI нет или он падает, worfy угадывает имя по имени
компьютера: его первая часть, в любом tailnet. Тогда машина, переименованная в консоли администратора Tailscale, получает
отказ по новому имени. С CLI переименование становится видно после следующей смены сети или перезапуска worfy. Адрес
Tailscale работает в обоих случаях.

#### On a Linked machine

Это то, что окно на этой Machine делает с Project-ом другой.

**Открытие.** Если есть хотя бы одна Linked machine, раздел Projects группирует Project-ы по Machine: сначала эта, затем
остальные по имени. У каждой Linked machine есть состояние: Online или Unavailable, и «Read only» рядом с Online, когда она
делится так. Machine с выключенным доступом показывает строку `<name> doesn't share its Projects`. Клик по Project-у другой
Machine заново загружает окно на той Machine. Окно показывает Project-ы одной Machine, и toolbar называет её.

**Всё идёт на Machine этого Project-а.** Session-ы, Terminal-ы, Autopilot, Gate и Browser-ы работают там. Экран их показывает
и отправляет команды. Открытие Project-а там держит открытыми его Orchestrator и документы, как для её собственного активного
Project-а, и её активный Project не меняется.

- **Общее для всех экранов:** Layout, Card-ы, Session-ы, состояние Terminal и Autopilot. Изменения Layout применяются в порядке
  прихода, и побеждает последнее.
- **Своё у каждого экрана:** selection, подсветка Edge, Find и открытые панели. ⌘Z (Ctrl+Z на Windows) отменяет
  только изменения этого экрана. Живая камера принадлежит окну, а одна сохранённая камера на Project хранится на Machine этого
  экрана.

**Когда до Project-ов не достучаться.** Окно оставляет свой Canvas под одной строкой и само загружается заново, когда это снова
возможно: `<name> is unreachable` (соединения нет), `<name> stopped sharing its Projects` (там выключили доступ) или `<name> is
no longer linked to this Machine` (link удалён).

**Add project.** При наличии Linked machine «Add project» сначала спрашивает Machine. На этой Machine он открывает системный
выбор папки. На Linked machine папки просматриваются внутри worfy, до 2000 в папке, и Project добавляется там, не меняя её
активный Project. Machine, которую нельзя выбрать, говорит почему: её сертификат изменился, она спит, она не online, она не даёт
Linked machine работать со своими Project-ами или даёт доступ только на чтение.

**Действия, которые принадлежат рабочему столу.**

- «+» на Session открывает файловый диалог Machine экрана, а копию хранит Machine этого Project-а.
- Ссылка открывается на той Machine, где по ней кликнули.
- «Open in editor» показывает toast `File is on <name>`, потому что редактор открылся бы на экране, которого здесь никто не
  видит.

**Уведомления.** Machine этого Project-а решает, о чём уведомлять, и отправляет сообщение Session каждой подключённой Linked
machine с Read only или Full access. Каждая Machine показывает сообщение по своим правилам: фокус своего окна, свой лимит — одно
на Session за 10 секунд — и своя ОС. Machine, которая не подключена, сообщение пропускает, и на потом ничего не хранится. Клик
открывает Session.

**Autopilot.** Правило «один run на Epic и origin» действует на всех соединённых Machine. Перед стартом Autopilot спрашивает
каждую Linked machine о её run-ах, независимо от того, включён ли доступ. Machine, которая не подключена или не ответила за
3 секунды, старт не блокирует, и старт её называет.

**Экран только для чтения.** Canvas можно смотреть, двигать и масштабировать. Notice сверху говорит `<name> gives this Machine
read-only access`. Действия записи остаются на экране, неактивные, с этим tooltip, и main всё равно отклоняет такой вызов. Node
не двигаются и не меняют размер. Node с Terminal показывает замену, его shell не запускается, а его вывод не отправляется.

#### Windows

Строка Machine без соединения получает подсказку, пока Bonjour ищет и Machine не отвечала на поиск последние 30 секунд.
Подсказка говорит, что Machine может быть выключена, спать или быть в другой сети, а если она включена и рядом — проверить, что
Windows firewall разрешает этой программе принимать соединения: UDP 5353 для поиска машин и TCP-порт link. Программа названа по
её пути, а в dev-сборке это `electron.exe`.

Tailscale CLI ищется в Path, затем в папке Tailscale внутри Program Files.

### How it works

- **Тот же контракт, но по сети.** Вызов с Linked machine выполняет те же обработчики IPC, что и вызов из окна, только
  зарегистрированные на адаптере, а не на `ipcMain` из Electron, и входы и ответы проходят те же схемы
  ([ADR-0052](../../adr/0052-machines-and-linking.md)). Renderer никогда не говорит с другой Machine. Он вызывает свой main, а
  main передаёт вызов дальше. Вернувшееся разбирается схемой этого канала на этой стороне, так что Linked machine не может
  передать окну ничего другого.
- **У каждого канала есть отметка доступа.** Одна и та же отметка решает, что может вызывать Linked machine и куда окно
  отправляет вызов:

  | Отметка | Значение | В окне на Linked machine |
  |---|---|---|
  | `link` | Служебный канал (`link.ping`); открыт всегда | Остаётся на этой Machine |
  | `project` | Работа с Project-ами, ещё и с отметкой `read` или `write` | Уходит на ту Machine |
  | `desktop` | Нужен рабочий стол; для Linked machine закрыт всегда | Уходит на ту Machine, которая отказывает |
  | `local` | Собственное состояние экрана; для Linked machine закрыт всегда | Остаётся на этой Machine |

  Имя, которого адаптер не знает, закрыто. Доступ только на чтение — это уровень той же проверки
  ([ADR-0066](../../adr/0066-read-only-access-for-a-linked-machine.md)). `terminal.output` — событие `write`, поэтому вывод
  Terminal в этот уровень не входит.
- **Канал.** HTTPS с TLS 1.3 и WebSocket поверх него. Каждая сторона предъявляет свой сертификат, и fingerprint сравнивается с
  запомненным при соединении. Client проверяет fingerprint сервера до того, как запрос записан, поэтому token никогда не
  доходит до сервера с другим сертификатом. Сервер отказывает в таком порядке, до рукопожатия WebSocket: сосед вне разрешённых
  сетей (сброс на уровне TCP, до TLS), любой заголовок `Origin`, `Host`, который не называет эту машину и порт (против DNS
  rebinding), другая версия протокола, неизвестный путь, затем собственная проверка endpoint. Каждый отказ до проверки
  endpoint пишет в log `[link] refused a connection from <peer>: <reason> (Host <host>)`, без query string пути.
- **Pairing доказывает два сертификата, а не только код.** Обмен — SPAKE2 (RFC 9382, P-256), код в нём — пароль. Идентичности
  в transcript — это fingerprint двух сертификатов, которые видела каждая сторона, поэтому машина посередине делает transcript
  разными, и подтверждение ключа не проходит на обеих сторонах. Перехваченный обмен нельзя проверить на других кодах offline.
  Каждая сторона представляется, только когда подтверждение другой сошлось. Сторона, показывающая код, сохраняет link, когда
  вводящая сторона его приняла, а вводящая сохраняет после этого, поэтому она никогда не делает dial с token, которого не знает
  другая.
- **Token-ы.** Каждая сторона выдаёт другой 32 случайных байта. Она хранит только хеш SHA-256 выданного token, а token, который
  предъявляет, идёт в файл секретов. Для входа нужны и token, и сертификат одной Linked machine. Ответ 401 от Machine, чей
  сертификат прошёл проверку, значит, что она забыла эту Machine, поэтому эта сторона тоже её забывает.
- **Адрес — только подсказка.** Объявление Bonjour или адрес, введённый вручную, ничего не доказывают, пока там не ответит
  запомненный сертификат. Входящее соединение, прошедшее проверки, тоже обновляет запомненный адрес. Имя `.local` узнаётся только
  из объявления на адресе открытого соединения.
- **Вызовы идут по одному соединению на Machine.** Dial делают обе стороны, так что могут быть открыты два соединения, и Machine
  online, пока открыто хотя бы одно; Change address… закрывает все, кроме своего. Вызовы идут по одному, и передаются только его события. Когда управление забирает другое
  соединение, или доступ снова открывается, или уровень меняется между Read only и Full access, меняется счётчик под названием
  epoch: всё, на что подписалось старое соединение, пропало, и окно на той Machine загружается заново.
- **Служебные сообщения — это не каналы IPC.** `hello`, `revoked`, `sleeping`, `awake`, `projects-access`, `note`, `ticket-note`,
  `autopilot-runs-ask` и `autopilot-runs` принадлежат самому link, и каждое разбирается схемой при получении. Каждый `hello`
  перечисляет, что принимает эта сборка, а сообщение, добавленное позже, например `ticket-note`, идёт только той Machine, которая
  его назвала, поэтому более старая сборка продолжает работать
  ([ADR-0079](../../adr/0079-link-machines-announce-accepted-messages.md)).
- **Почему Tailscale и нет другого выхода за пределы локальной сети:**
  [ADR-0070](../../adr/0070-worfy-link-outside-the-lan-through-an-overlay-network.md). Там же и пауза после неудачных попыток, с её
  известным пределом: любой в сети может держать связывание на паузе, угадывая неверно.
- **Почему несколько экранов работают так:** [ADR-0053](../../adr/0053-several-screens-on-one-project.md). Почему выключенный
  доступ не останавливает работу: [ADR-0060](../../adr/0060-access-off-keeps-started-work.md).

**Лимиты на соединении.** Протокол link версии 3. Одно сообщение в установленном соединении — не больше 16 MiB, а вызов или ответ
сверх этого получает собственную ошибку и оставляет соединение открытым. Сообщение pairing — не больше 64 KiB. Вызов ждёт ответа
30 секунд. Файл Card или сохранённое изображение идёт частями не больше 4 MB. Выход ждёт goodbye от Bonjour не больше 1,5 секунды,
что позволяет другим worfy сразу убрать эту Machine из своего списка.

**Log-и.** Ни код связывания, ни token не попадают в консоль или текст ошибки, а код идёт только в окна этой Machine. Каждая строка
`[link]` также идёт в `link/link.log`, который ротируется на 1 MiB и хранит 3 старых файла, всего 4 MiB. Перед записью он заменяет
всё, что похоже на секрет. Неудачный dial записывается один раз на причину, а не один раз на повтор.

**Поток данных вызова.** Окно на Linked machine M вызывает канал. `src/renderer/ipc.ts` читает его отметку и отправляет канал
`project` или `desktop` как `linked.invoke` в main этой Machine. `src/main/link/remote-calls.ts` отправляет его по текущему
соединению M. На M `src/main/link/service.ts` передаёт frame в `src/main/link/ipc-adapter.ts`, который проверяет отметку и
уровень и выполняет тот же обработчик, что и для окна, с отправителем, чей id — строка. Так `src/main/link/caller.ts` отличает
удалённый вызов от окна. Ответ возвращается, разбирается схемой этой стороны и доходит до окна. Broadcast-ы M доходят до её client
`project` как frame-ы событий и приходят как `linked.event`. Окна, подписанные на один root на M, считаются в
`src/main/ipc/linked.ts`, потому что M видит одного client на всех: закрытие идёт на M, только когда отпускает последнее окно.
