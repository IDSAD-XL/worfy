# Browser

> Перевод [английской версии](../browser.md), commit `same-pr`.

Два Feature. **Browser** — Node со страницей Chromium, в которой работают и пользователь, и Session-ы. **Browser profile** —
сохранённый вход под одной ролью, под которым открывается Browser. Термины объяснены в [Concepts](concepts.md).

## Browser

### Behaviour

Browser — это Node на Canvas со страницей сайта или веб-приложения, открытой под одним Browser profile. Пользователь ходит
в нём руками. Session ведёт его инструментами: по просьбе в чате или чтобы проверить Ticket глазами нужной роли.

**Создание.** "New browser" в контекстном меню Canvas или в Command palette создаёт Node размером 640 на 440 пикселей.
`browser_open` Session создаёт такой же рядом с Node этой Session, не поверх другого Node. Какой profile получает новый
Browser — в разделе [Browser profile](#browser-profile). В заголовке — имя profile, Back, Forward, Reload, адресная
строка, кнопка sidebar-а Browser settings и метки, о которых ниже. Выделенную рамку можно менять за её handles, вплоть до
360 на 200.

**Адресная строка.** Enter отправляет страницу по набранному адресу. Адрес без `://` получает `https://`. Адрес с другой
`схемой://`, кроме `http` и `https`, текст с пробелами или адрес, из которого всё равно не получается верный URL,
отклоняются, и строка помечается как неверная. Esc оставляет строку как была и больше ничего не делает.
У нового Browser адреса нет, он показывает пустую страницу. Адрес, до которого дошла страница, по ссылке или через строку,
хранится в Node, поэтому строка его показывает, а после перезапуска он открывается снова. Это не шаг ⌘Z. Back и Forward
неактивны на концах истории страницы. Все три кнопки неактивны, пока у этого окна нет готовой страницы Browser; сюда входит
и рамка, показывающая кадры из другого окна.

**Страница на Canvas.** Страница двигается и масштабируется вместе с рамкой и обрезается по её краю. Другой Node или меню
над рамкой перекрывают страницу. Колесо над страницей прокручивает страницу, а Canvas остаётся на месте. Пока основная
кнопка мыши, нажатая на Canvas, удерживается, страница мышь не получает. Страница продолжает работать, когда рамка уходит
с экрана, пока её не усыпят правила ниже. В Focus mode страница лежит поверх тела рамки в её плитке и принимает там ввод.
Выход из Focus mode возвращает её на рамку: та же страница, с её историей, прокруткой и набранным текстом.

**Viewport страницы.** Sidebar задаёт размер, в котором раскладывается страница: "Fit to card", значение по умолчанию,
делает её размером с тело рамки; готовые размеры — 1440 × 900, 1280 × 800, 768 × 1024 и 390 × 844; "Custom" принимает
целые числа от 200 до 3840. С viewport-ом страница вписывается в тело целиком, от левого верхнего угла. Меняются только
ширина и высота, устройство не эмулируется, поэтому готовые размеры названы своим размером. Выбор хранится в Node и
переживает перезапуск. Ни один инструмент Session его не задаёт. Esc закрывает sidebar.

**Ссылки, которые просят окно.** Страница никогда не открывает окно. Для ссылки `target="_blank"` или `window.open`:

- Если просит frame с origin самой страницы, по адресу уходит сама страница. Форма, отправляющая POST таким способом,
  открывает свой адрес обычным GET.
- Если просит frame другого origin или запрос без referrer, страница остаётся. Рамка предлагает адрес в Open bar, "The page
  wants to open", с Open и кнопкой закрытия. Новый запрос заменяет адрес, а навигация страницы убирает bar.
- Адрес не http и не https не открывается и не предлагается.

Open bar всегда показывает схему и host целиком и не показывает имя пользователя. Сокращается только остальная часть адреса,
последние 24 символа которой сохраняются. Полный адрес — в tooltip. Страница не получает веб-разрешений: любой запрос камеры,
микрофона, уведомлений, геолокации или буфера обмена отклоняется, а любая проверка разрешения отвечает «нет».

#### Что показывает рамка

| Рамка показывает | Значение |
|---|---|
| Страницу | Live, и её рисует это окно |
| Кадры страницы | Live, и её рисует другое окно или другая Machine |
| Приглушённую картинку под "Asleep · Click to wake" | Asleep. Картинка — страница в момент, когда она уснула |
| Только "Asleep · Click to wake" | Asleep без картинки: worfy перезапускался, или снимать было нечего |
| "Choose a profile" | Страницы нет: см. [Browser profile](#browser-profile) |
| "Unsaved changes" в заголовке | У страницы есть обработчик `beforeunload`, поэтому она не засыпает |
| "Over the Live limit" в заголовке | Live сверх предела: пользователь открыл его, когда все остальные Live Browser-ы были заняты, или предел снизили |
| "Claude is driving" и цветная рамка | Его ведёт Session |
| "Return control to Claude" в заголовке | Пользователь перехватил его у Session |

#### Live и Asleep

У Live Browser работает страница, и каждая такая страница — отдельный процесс. У Asleep Browser страницы нет: его куки
остаются на диске, а main хранит картинку и положение прокрутки. Main проверяет правила раз в секунду, сразу для всех окон.

| Settings → Browser | По умолчанию | Предлагается | Принимается в файле |
|---|---|---|---|
| Live browsers at once | 3 | 1, 2, 3, 4, 5, 6, 8, 10 | 1–10 |
| Sleep when off screen after | 30 с | 10 с, 30 с, 1, 2, 5, 10 мин | 1–3600 с |
| Sleep when unused after | 5 мин | 1, 2, 5, 10, 15, 30 мин, 1 ч | 1–240 мин |
| Readable from zoom | 40 % | 25, 30, 40, 50, 60, 75 % | 10–100 % |

Live Browser засыпает в двух случаях, оба — только пока у его страницы нет фокуса клавиатуры:

- Ни один экран не показывает его с читаемым zoom дольше порога вне экрана. Рамка в окне на Canvas, у которого zoom ниже
  читаемого, считается вне экрана. Чтобы удержать Browser, хватает одного экрана, где он читаем. Скрытое окно, например
  свёрнутое, не показывает ни одного Browser. Browser в плитке Focus mode считается показанным и читаемым. Пока плитка
  Focus mode показывает Browser, читаемым считается всё окно, поэтому Browser-ы внутри окна, даже на Canvas с zoom ниже
  читаемого, засыпают позже.
- Им никто не пользовался дольше порога неиспользования. Использование — это нажатие, клавиша, касание или прокрутка на
  странице, ввод в его кадрах, вызов Session или пробуждение.

Он не засыпает в таких случаях:

- Его сейчас ведёт Session: вызов идёт, или последний вызов закончился меньше порога неиспользования назад. Browser,
  который перехватил пользователь, ведомым не считается.
- У страницы есть обработчик `beforeunload`. Main спрашивает прямо перед сном, а страницу с обработчиком — снова каждые 5
  секунд.
- Страница не ответила за 3 секунды, например при открытых DevTools. Browser остаётся Live без метки.

**Предел** считает все Browser-ы Machine, во всех Project-ах. Открытие или пробуждение сверх предела усыпляет Live Browser,
которым дольше всех не пользовались и которому можно уснуть. Если таких нет, Browser пользователя открывается сверх предела
с меткой, а вызов Session отклоняется с "All Live Browsers are busy" и ничего не меняет. Метка уходит, когда Live Browser-ы
снова укладываются в предел. Предел, сниженный в Settings, действует со следующей проверки: те, что сверх него и могут
уснуть, засыпают, остальные получают метку.

**Пробуждение.** Browser будит клик по рамке или вызов Session. Страница снова загружает адрес из Node, и main прокручивает
её обратно. Пробуждение — это перезагрузка, поэтому форма без обработчика `beforeunload` теряет набранное. Asleep Browser с
картинкой остаётся Asleep, когда экран снова его показывает.

**После перезапуска.** Картинки хранятся только в памяти. После перезапуска, или когда ни одно окно не показывает Project и
все его Browser-ы спят, main о них забывает. Следующий первый экран Project-а будит его Browser-ы до предела, сначала
показанные, остальные становятся Asleep без картинки. Такой Browser просыпается сам, когда экран показывает его с читаемым
zoom и есть свободное место.

Вызову Session нужно окно этой Machine, показывающее Project: только такое окно может нарисовать страницу. Без него вызов на
Browser без страницы отклоняется и просит открыть Project.

#### Кто ведёт

Session ведёт Browser с первого вызова на нём, и рамка об этом говорит. "Claude is driving" остаётся между вызовами. Browser
ведёт только одна Session за раз, вызов другой Session отклоняется. Session может вести Browser-ы, которые открыла она, и
те, что открыл пользователь, но не тот, что открыла другая Session. Вызов, который взял Browser и не смог подключиться к
странице или застал её вне origin-ов, отдаёт его обратно. Вызов, который не удался позже, на отклонённом адресе или
элементе, которого нет на странице, продолжает его вести.

**Перехват.** Нажатие, клавиша или касание пользователя на странице или рамке перехватывают Browser. Движение мыши и
прокрутка — нет, как и собственные события Session. С этого момента пользователь ходит куда угодно, а любой вызов Session
отвечает "The user took over this Browser". Идущий клик или набор больше ничего не отправляет странице. "Return control to
Claude" возвращает Browser той Session, что его вела. У Browser, которого никто не ведёт, перехватывать нечего. Пока Session
кликает или печатает, фокус клавиатуры окна остаётся там, где его держит пользователь.

#### Что может Session

Инструменты дают MCP server `worfy-browser`, по одному server-у на Session. Session получает его, когда запускается в
Project-е с подключённым canvas и когда список MCP server-ов Profile, если он есть, называет `worfy-browser` или
`worfy-canvas`.

| Инструмент | Что делает |
|---|---|
| `browser_list` | Browser profile-ы Project-а с их origin-ами; его Browser-ы с profile, адресом, тем, кто открыл, Ticket-ом, состоянием Live и тем, кто ведёт |
| `browser_open` | Новый Browser под существующим profile, по желанию сразу по URL и для Ticket-а |
| `browser_navigate` | Отправляет страницу по URL и ждёт загрузки |
| `browser_click` | Прокручивает элемент в видимую область и кликает в его середину; элемент, который не показан, отклоняется |
| `browser_type` | До 10 000 символов в поле, после того, что в нём есть; `submit` нажимает после них Enter |
| `browser_screenshot` | PNG страницы как она есть сейчас |
| `browser_read` | Дерево accessibility текстом, с `[ref=…]` у каждого элемента, обрезанное на 60 000 символов |
| `browser_console` | Последние 200 сообщений консоли и неперехваченных ошибок, старые первыми |
| `browser_network` | Последние 200 запросов, старые первыми: метод, URL, тип, статус; без тел |

Элемент — это CSS-селектор или ref из `browser_read`, ровно что-то одно. Ref старой страницы отклоняется. Log-и начинаются
с первого вызова Session на странице, а разбуженная или переехавшая страница начинает их заново. Вызов ждёт, пока окно
нарисует страницу, не больше 15 секунд. Клик или набор ждёт 300 мс навигацию, которую мог запустить. Загрузку ждут не
больше 20 секунд, и одной команде странице даётся 20 секунд.

**Origin-ы.** Session остаётся на origin-ах Browser profile этого Browser, сравниваются они целиком: другой порт localhost —
другой сайт.

- Адрес `browser_open` и `browser_navigate` проверяется до того, как страница сдвинется. Всё, кроме http и https, отклоняется,
  а profile без origin-ов не даёт Session открыть ни одной страницы.
- Любая другая навигация всей страницы в main frame за пределы списка отменяется, пока Session ведёт Browser: нажатая
  ссылка, redirect, скрипт, форма. Страница остаётся где была, а вызов отвечает отказом с названием origin и списка.
- Frame-ы внутри страницы и запросы её ресурсов не проверяются.
- Страница вне origin-ов, куда пользователь ушёл руками перед возвратом Browser, не принадлежит Session: читать и
  использовать её нельзя. Уйти с неё можно только через `browser_navigate`. Пустая страница не принадлежит ни одному сайту, её
  использовать можно.
- После первого вызова Session загрузки страницы идут мимо её service worker, пока страница не закроется, так что service
  worker не может ответить на навигацию раньше, чем её увидит проверка.

Собственные переходы пользователя origin-ами не ограничены.

**Пароли.** `browser_type` отказывается печатать в поле пароля. Он идёт за фокусом от элемента через открытые shadow root и
frame-ы и отказывает, если на этом пути есть поле пароля. Отказывает он и для frame-а другого сайта, поля с закрытым shadow
root и страницы, которая уводит фокус, потому что всё это нельзя проверить. Текст принимают input текстового вида, text area
и редактируемый элемент. Session никогда не входит в аккаунт сама; см. [Browser profile](#browser-profile).

#### Когда Session уходит с Canvas

Операция, которая убирает с Canvas последний Node Session, в той же операции убирает Browser-ы, открытые этой Session: Hide,
Remove, Delete в Trash или архив. Session, которую архив не трогает (pinned, Keep), сохраняет их от архива, но не от Hide и
не от Remove. Остаются три вида Browser:

- Открытый пользователем. Того, кто его открыл, у него нет, а управление Session заканчивается.
- Заблокированный пользователем.
- Перехваченный пользователем и не возвращённый, или такой, у страницы которого есть обработчик `beforeunload` или которая
  не отвечает 3 секунды. Main спрашивает страницы прямо перед операцией. Такой Browser остаётся как Browser пользователя: он
  больше не считается открытым этой Session, выходит из Family, и вести его может любая Session.

Повторный показ Session и Restore не возвращают Browser-ы. ⌘Z от Hide, Remove, Delete или "Archive finished sessions now"
пользователя возвращает: Session приходит со своими Browser-ами на прежние места, оставшиеся снова считаются открытыми ею, а
перехваченному возвращается и перехват. ⇧⌘Z повторяет шаг и оставляет пользователю те же Browser-ы. Собственный таймер
архива шага ⌘Z не создаёт.

Пока все её Node-ы вне Canvas, Session не открывает и не ведёт Browser. Session без единого Node, агент, которого Canvas не
показывает, вне Canvas не считается. Клик или набор, идущий в момент ухода Session, останавливается перед следующим
событием с "This Session left the Canvas", а страницы, к которым ведёт вызов, проверяются, пока он не закончится или
пользователь не воспользуется страницей. Снова показанная Session сразу снова ведёт Browser.

**Family.** Browser, открытый Session, входит в её Family и в Family Ticket-а, для которого открыт, вместе с Epic frame
этого Ticket-а. У Browser, открытого пользователем, Family нет.

#### Несколько окон

У Browser одна страница. Из окон этой Machine, показывающих Project, одно её рисует, остальные показывают её кадры. Рисует
первое окно, показавшее Project. Каждое другое окно смотрит кадры, пока показана его рамка, и отправляет странице свои клик,
перетаскивание, прокрутку, клавиши и адрес как ввод пользователя. Нажатие, клавиша или адрес перехватывают Browser у Session,
прокрутка — нет. Back, Forward и Reload там неактивны, Open bar нет.

Когда ввод пользователя в другом окне затих на 1,5 секунды, страница переезжает туда: main запоминает прокрутку, старое окно
закрывает страницу, а новое снова открывает адрес из Node. Значит, переезд — это перезагрузка. Страница не переезжает, пока у
неё есть обработчик `beforeunload` или она не отвечает, пока её ведёт Session или на ней идёт вызов. Окно тогда остаётся
с кадрами, и следующий ввод пробует снова. Когда рисующее окно закрывается или перезагружается, страница уходит окну, где
работали последним, а иначе тому, что дольше всех показывает Project.

Кадры — JPEG качества 60, не больше 1280 × 1280 и не чаще одного на 100 мс, отправляются, только пока экран их смотрит.

На macOS ⌘A, ⌘C, ⌘V, ⌘X, ⌘Z и ⌘⇧Z из кадров идут со своей командой редактирования: Chromium выполняет их из меню
приложения, и одной клавиши недостаточно. Копирование и вставка используют буфер обмена Machine этого Project-а.

#### On a Linked machine

Browser работает на Machine своего Project-а. Linked machine никогда не рисует страницу и не держит её куки.

**С полным доступом** рамка работает как в другом окне этой Machine, с теми же кадрами и той же частотой. Проверки пароля во
вводе нет, поэтому пользователь может войти в аккаунт через кадры. Экран сообщает Machine, что показывает, каждые 20 секунд,
и сообщение действует 60 секунд, поэтому Browser, видимый там, не засыпает из-за ухода с экрана. Это верно, только пока окно
Machine показывает Project. Без такого окна страницу нарисовать нельзя, и пробуждение с Linked machine отклоняется.

**С доступом read-only** в рамке только имя profile: нет адресной строки, кнопок, кадров, меток и картинки. Цветная рамка
ведомого Browser всё равно видна. Layout, который она получает, не содержит адресов Browser. Перехватить Browser она не
может.

#### Windows

Единственное отличие в коде Browser — команды редактирования для ⌘-сочетаний: Windows Machine их не добавляет, и клавиша с её
модификаторами идёт странице как есть.

### How it works

- **`<webview>` в собственном слое.** `<webview>` — элемент страницы, поэтому zoom Canvas его масштабирует, а Node-ы и меню
  перекрывают ([ADR-0078](../../adr/0078-browser-node.md)). Canvas рисует только Node-ы на экране, что уничтожило бы страницу
  внутри Node. Поэтому слой внутри viewport-а React Flow, под всеми Node-ами, рисует каждую страницу на месте тела её рамки.
  Тело прозрачное и пропускает мышь.
- **main решает, окна сообщают.** Каждое окно говорит main, какие рамки показывает и с каким zoom. Main держит состояние
  каждого Browser и говорит каждому окну, какие страницы ему рисовать. Сообщение Linked machine истекает, потому что её экраны
  могут исчезнуть без предупреждения.
- **Управление идёт через CDP.** Main использует `webContents.debugger` Electron у страницы, на Machine Project-а. Он
  подключается при первой необходимости: вызов Session, вопрос перед сном, screencast. Он остаётся подключённым. Когда
  страницу забирает DevTools, следующий вызов подключается снова и проверка origin снова работает, а log-и остаются.
- **Проверка origin — в домене Fetch.** После первого вызова Session на странице каждый запрос документа приостанавливается.
  Для main frame, пока ведёт Session, он проверяется, а запрос не из списка завершается как `Aborted`, что Chromium считает
  отменённой навигацией. Guard, который не может прочитать origin-ы, отказывает.
- **Набор идёт внутри страницы.** Текст вставляется собственной командой редактирования страницы, а Enter — событиями
  страницы с implicit submission из HTML. Клавиша через ввод Chromium увела бы фокус окна worfy. Клик — настоящий, trusted, от
  Chromium, и окно возвращает фокус после отпускания.
- **У страницы нет возможностей приложения.** `<webview>` подключается без preload и без Node integration, с context isolation
  и sandbox, с включённой web security и только на partition-е Browser profile одного из Project-ов этой Machine. Main
  проверяет каждое подключение и отклоняет любое другое.
- **Viewport — это CSS.** `<webview>` получает размер viewport-а и CSS-масштаб, а main его не читает
  ([ADR-0087](../../adr/0087-browser-page-viewport.md)). Кадр и картинка вписываются так же, а ввод пересчитывается тем же
  масштабом.

## Browser profile

### Behaviour

Browser profile — сохранённый вход под одной ролью, например admin, moderator или user: его куки, логины и данные сайтов.
Пользователь входит в аккаунт руками в Browser. Session-ы приходят уже со входом и паролей не видят. Profile может быть
открыт в нескольких Browser-ах, у которых куки общие; Browser другого profile их не видит. Profile принадлежит Project-у и
лежит на Machine, в репозитории следов нет. Вход переживает перезапуск.

**Окно "Browser profiles…"** открывается по имени profile в заголовке рамки и из меню "Choose a profile". Оно показывает
profile-ы Project-а с числом Browser-ов на Canvas, использующих каждый, и создаёт новый по имени. Создаёт, меняет и удаляет
profile-ы только пользователь, инструмента Session для этого нет.

| Поле | Правила |
|---|---|
| Name | Обязательно, до 60 символов, уникально в Project-е без учёта регистра. Переименование сохраняет вход |
| Origins | По одному в строке, до 50. Ровно `scheme://host:port`, http или https: без пути, query, пользователя и `*`. Хранятся так, как пишет браузер. Пустой список допустим |
| Sign-in page | Необязательно. Один адрес http или https до 2000 символов, на одном из origin-ов profile, без имени пользователя и пароля |
| Available to Autopilot | Выключено, пока пользователь не включит |

Окно показывает ошибку во время набора, а main проверяет ещё раз перед записью. Изменение origin-ов, после которого sign-in
page оказывается вне их, отклоняется.

**Default.** У Project-а без файла profile-ов есть один profile, Default, без origin-ов и недоступный Autopilot. Session не
может открыть под ним ни одной страницы, пока пользователь не добавит origin-ы. Default можно переименовать и удалить, как
любой другой. Список, который пользователь опустошил, остаётся пустым.

**Какой profile использует Browser.**

| Node | Project | Browser |
|---|---|---|
| Хранит существующий profile | любой | Использует его |
| Хранит удалённый profile | любой | Спрашивает: "The Browser profile of this Browser was deleted." |
| Новый | Ровно один profile | Берёт его и дальше хранит |
| Новый | Несколько | Спрашивает: "This Browser has no Browser profile yet." |
| Новый | Ни одного | Спрашивает: "This Project has no Browser profile yet." |
| Сохранён до появления profile-ов, с адресом | Есть Default | Использует Default и дальше хранит его |
| Сохранён до появления profile-ов, с адресом | Нет Default | Спрашивает, как при удалённом profile |

Browser, сохранённый до появления profile-ов без адреса, считается новым. У Browser, который спрашивает, нет страницы, а его
адресная строка говорит "Choose a profile first". Его меню показывает profile-ы и "Browser profiles…". Другого способа
сменить уже выбранный profile рамка не предлагает.

**Удаление.** "Delete…" спрашивает ещё раз и называет, сколько Browser-ов на этом Canvas используют profile. Его куки, логины,
кэши и данные сайтов стираются, а эти Browser-ы просят другой profile. Открытые на нём страницы сначала закрываются, и
хранилище стирается после их ухода или в любом случае через 2 секунды. Если стереть не удалось, окно об этом говорит, а
profile к этому моменту уже удалён. Новый profile никогда не получает id существующего или `default`.

**Истёкший вход.** Страница считается вышедшей из аккаунта в двух случаях, и её текст при этом не читается:

- Это sign-in page этого profile: те же origin и путь, query не важен. Profile без неё опирается на 401.
- Её главный документ ответил 401. 401 от frame-а внутри страницы или от скрипта не считается.

Вне Autopilot ответ на `browser_open`, `browser_navigate`, `browser_click` или `browser_type` тогда несёт заметку, что вход
истёк, и просит Session обратиться к пользователю. Заметка называет sign-in page только по origin и пути.

**Autopilot.** Session в Autopilot знает только profile-ы с отметкой "Available to Autopilot":

- `browser_list` не показывает других profile-ов и Browser-ов под ними. Вызов с таким profile отклоняется до того, как что-либо
  создано, разбужено или взято, с ответом сообщить `sign-in needed as <name>`.
- `browser_open` требует `ticket`, `<epic>/<NN>` из Epic-а, над которым работает запуск. Вне Autopilot он необязателен, и
  принимается любой Ticket Project-а.
- Истёкший вход отклоняет вызов с `Sign-in expired in Browser profile "<name>"`. Пока страница там, разрешён только уход через
  `browser_navigate`, потому что клик мог бы нажать кнопку single sign-on. Session сообщает
  `sign-in expired in Browser profile <name>` и продолжает без этой проверки.

#### On a Linked machine

Profile один на все экраны, потому что Browser работает на Machine Project-а и куки остаются там. С полным доступом окно
работает как на Machine, а его изменения выполняются там. Linked machine с read-only читает список: имена, origin-ы и sign-in
page. Её создание, изменение и удаление отклоняются ещё до handler-а, а окно показывает поля только для чтения и заметку.

### How it works

- **Один постоянный partition на profile.** У каждого profile есть partition `persist:worfy-browser-<hash>-<id>`, где `<hash>` —
  окончание id Project-а ([ADR-0078](../../adr/0078-browser-node.md)). Electron держит его в папке данных worfy. Он назван по id
  profile, а не по имени, поэтому переименование сохраняет вход.
- **Id не может забрать старый вход.** Это slug имени, до 24 символов, и шесть случайных hex-цифр. Поэтому новый profile с
  именем удалённого получает свой partition.
- **Список partition-ов читается при каждом подключении.** Partition удалённого profile отклоняется сразу.
- **Чтение ничего не пишет.** Список — read-канал, который может вызвать Linked machine с read-only, поэтому файл появляется при
  первом изменении ([ADR-0005](../../adr/0005-worfy-own-state-inventory.md)).
- **Испорченный файл не стоит profile-ов.** Нечитаемый файл откладывается в сторону, и Project возвращается к Default. Sign-in
  page с пользователем или паролем, записанная в файл руками, читается как отсутствующая, а profile остаётся.
