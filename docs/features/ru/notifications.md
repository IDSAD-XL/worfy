# Notifications

> Перевод [английской версии](../notifications.md), commit `same-pr`.

worfy сообщает пользователю двумя способами. **Системное уведомление** — баннер операционной системы на случай, когда worfy не на
переднем плане. **Toast** — короткое сообщение внутри окна. Этот Feature входит в [App shell](app-shell.md), а своя страница у него из-за
объёма. Термины объяснены в [Concepts](concepts.md).

## Behaviour

### Системные уведомления

| Событие | Заголовок | Текст | Что открывает клик |
|---|---|---|---|
| Session, которую запускает worfy, закончила ход | Имя её папки | То, что она сказала, иначе «Finished its turn» | Session |
| Она ждёт ответа на запрос разрешения | Имя её папки | «Needs permission: `<tool>` `<input>`» | Session |
| Она задаёт вопрос | Имя её папки | «Asks: `<first question>`» | Session |
| Session из терминала или Claude Desktop перешла из busy в idle | Её имя, иначе имя её папки | «Finished its turn» | Session |
| Ticket стал ждать владельца или эту Machine | `<epic> NN` is waiting for you | Его Blocked reason, иначе `<epic> NN — <title>` | Pipeline board его Project-а |
| PR с меткой cross-machine gate ждёт дольше часа | Имя Project-а | PR и что делать дальше | Ничего: поднимает окно |
| Слишком много неудачных попыток pairing за час | Link a machine is paused | Сколько, с каких адресов, до какого времени | Ничего: поднимает окно |

Ход, прерванный пользователем, уведомления не даёт. Текст уведомления Session обрезается до 160 символов. Для Bash запрос — это команда,
для другого инструмента — его input в JSON. Session, чья папка ещё неизвестна, получает заголовок «Session».

Правила:

- **Ничего не показывается, пока окно worfy в фокусе.** Исключение — пауза pairing: это предупреждение о сети, и оно показывается при любом
  фокусе.
- **Одна Session показывает не больше одного уведомления за 10 секунд.** Уведомление, задержанное фокусом, не считается. Уведомление Ticket-а
  считается так же, по Project-у и Ticket-у.
- **Ожидание Ticket-а уведомляет один раз**, и только если worfy видел, как оно началось: то, что уже ждало при первом чтении Project-а, ничего
  не даёт. Ожидания `team` и `agent` ничего не дают. Новое ожидание того же Ticket-а уведомляет снова.
- **PR из gate queue уведомляет один раз на последний commit.** Новый commit, отчёт или merge заканчивают это ожидание. На чтение очереди
  смотрят каждую минуту, а пока окно в фокусе, PR ждёт следующего чтения.
- **Session из терминала или Claude Desktop** видна через registry watcher-ы, которые работают, пока Project открыт в окне или на подключённой
  Linked machine. Первое появление Session изменением не считается.
- Переключателя для уведомлений в worfy нет. Focus mode системы действует на них, как на любое приложение.

Клик поднимает окно и восстанавливает его, если оно свёрнуто. На macOS worfy живёт и без окон, тогда клик открывает новое. Уведомление ждёт
страницу своего окна до 30 секунд, а потом перезагрузка уже ничего не открывает.

### Toast-ы

Toast-ы стоят у правого края окна, поверх всего в нём, включая окно Settings. У каждого есть кнопка Dismiss.

| Вид | Сколько стоит | Кнопки |
|---|---|---|
| `info`, `success` | 4 секунды | нет |
| `error` | пока не закроют | нет |
| `action` | пока не закроют | от 1 до 3; нажатие запускает действие и закрывает toast |

- На экране не больше 3 toast-ов. Новый вытесняет самый старый из тех, что скрываются сами. Когда все на экране стоят до закрытия, новый ждёт в
  очереди, и его время начинается, когда он выходит.
- Toast с ключом заменяет toast с тем же ключом на месте, и его время начинается заново.
- Toast Project-а показывается, только пока этот Project активен. Пример — «Archived N finished sessions» с Undo.
- Указатель или фокус клавиатуры на toast останавливают его время. Когда оба ушли, время начинается заново целиком.
- Toast никогда не забирает фокус. Tab доходит до его кнопок, а Esc на toast в фокусе закрывает его и возвращает фокус.
- Стопка уходит с дороги. Она становится в первую свободную полосу сверху в своей колонке, в стороне от toolbar, заголовка вида, minimap,
  открытого диалога или меню, с отступом 12 пикселей. Пока toast показан, место измеряется заново каждые 200 мс. Когда ни одна полоса не вмещает
  стопку целиком, она обрезается до самой высокой полосы не меньше 40 пикселей и прокручивается. Когда такой полосы нет, она остаётся под toolbar и
  закрывает всплывающий элемент, чтобы ошибка всё равно была видна.
- Область — это landmark «Notifications». Toast-ы `error` объявляются как alert, остальные вежливо.

### Windows

- «В фокусе» проверяется по системе. Electron может считать окно в фокусе, хотя Windows не пустила его на передний план, поэтому когда Electron
  говорит да, worfy спрашивает Windows, какому процессу принадлежит окно переднего плана. Проверка — один вызов Windows PowerShell, и она идёт,
  только когда решается судьба уведомления. Когда она падает или занимает больше 2 секунд, действует ответ Electron, а первый такой сбой идёт в log.
- Собранное приложение показывает уведомления под AppUserModelId `dev.worfy.app`, заданным до первого окна. Dev-запуск берёт как id путь своего
  `electron.exe`.

### On a Linked machine

Machine Project-а решает, о чём уведомлять, и передаёт каждое уведомление в два места: на свой экран и на Linked machine
([ADR-0053](../../adr/0053-several-screens-on-one-project.md)). Её собственный фокус не задерживает уведомление для них.

- Уведомление идёт на Linked machine, которая сейчас подключена и имеет доступ: «Linked machines can work with my Projects» включено, а её уровень
  `read` или `all`. Доступ только для чтения уведомления получает. Machine, которая не подключена, уведомление пропускает, и для неё ничего не хранится.
- Каждая Machine показывает уведомление по своим правилам: фокус своего окна, свои 10 секунд, Focus mode своей системы.
- Клик действует на той Machine, где сделан: её окно поднимается и открывает Session среди Project-ов другой Machine.
- Ticket, ждущий `owner`, доходит до этой Machine и до каждой Linked machine, у которой есть доступ и которая принимает это сообщение. Ожидание с
  именем Machine доходит только до неё, по имени целиком, как его показывает Settings → Machines. Решает Machine Project-а.
- Linked machine отбрасывает уведомление Ticket-а, когда в её списке есть Project того же репозитория, потому что она сама о нём уведомила. Остальные она
  показывает с именем отправителя в заголовке, а клик открывает Pipeline board этого Project-а на той Machine, только для чтения.
- Пауза pairing и уведомления gate queue остаются на своей Machine.
- Toast-ы принадлежат своему окну и никуда не передаются.

## How it works

- **Правила живут отдельно от Electron.** `Notifier` и `NoteDisplay` получают части Electron как зависимости, поэтому test-ы передают свои. macOS берёт
  имя и иконку уведомления из bundle процесса, поэтому своей иконки уведомление не задаёт.
- **Ожидания читаются из файлов Ticket-ов.** Уведомления Ticket-ов следуют за моделью workflow, которую workflow hub поддерживает слежением за файлами, а
  не за Stage hub, который каждую минуту запускает `bin/profile`, git и gh. У одного ожидания один ключ: его время Status, когда в нём есть время суток,
  иначе слово Status и Blocked reason.
- **Клик не зависит от готовности страницы.** Уведомление всегда ждёт в main, а `notify.open` только просит смонтированный overlay забрать его сейчас.
  Overlay, смонтированный позже, заберёт его тогда.
- **Ticket-ы идут отдельным сообщением**, которое получает только Machine, назвавшая его в `accepts`
  ([ADR-0079](../../adr/0079-link-machines-announce-accepted-messages.md)). Оно называет Project по id, имени и match key и никогда по локальному пути, а
  ожидание идёт как hash. Machine читает match key Project-а через git не чаще раза в минуту и помнит последние 10 000 полученных ожиданий, чтобы показать
  каждое один раз. Лучше показать уведомление дважды, чем потерять: Project, чей ключ не прочитался, ни с чем не совпадает.
- **Уведомления gate queue** следуют ролям из [ADR-0069](../../adr/0069-cross-machine-gate-label-and-roles.md): текст говорит «Run Process gate queue» на
  обслуживающей Machine и «No machine has taken it yet» на запрашивающей.
- **Run-ы e2e не показывают баннеров.** Quiet windows никогда не в фокусе, поэтому каждый законченный ход test-а показал бы баннер. Решение об уведомлении
  всё равно принимается, и оно всё равно идёт на Linked machine.
- **Toast-ы — одно хранилище на renderer.** Любой код renderer-а вызывает `showToast`, а рисует их один компонент.
