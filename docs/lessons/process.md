# Процесс: ревью, круги доработки, Wave-ы

## Второй круг ревью проверяет доработку, а не ищет всё заново

Повторное ревью после круга доработки блокирует Ticket только в трёх случаях: (а) находка первого
круга не исправлена и не опровергнута; (б) дефект внесён правками доработки; (в) новый дефект
уровня high. Остальное новое — `[low]` с префиксом `debt:`, оно уходит в долги `HANDOFF.md`.
Свежий ревьюер без этого правила всегда находит что-то новое, и Ticket на критическом пути встаёт:
в Wave 2 так были заблокированы 02, 03 и 32, а за ними 27 зависимых Ticket-ов. В бриф второго круга
давать список находок первого круга и дифф только круга доработки.
Источник: worfy-mvp, Wave 2 (02, 03, 32); worfy-mvp/21.

## Ревьюер знает правила владельца о непроверенном

Ручную проверку, которую нельзя автоматизировать (уведомление macOS, системный диалог, живой
терминал), можно оставить `[ ]` со строкой «не проверено: …» в «Итог» Ticket-а — это не находка.
Обратное правило: приложенное «доказательство», которое не показывает заявленного (снимок не того
окна, вывод не той команды), — находка уровня high. В Ticket-е 21 ревьюеры, не знавшие первого
правила, считали честно помеченные ручные пункты находками.
Источник: worfy-mvp/21.

## Узкий круг исправления для Ticket-а на критическом пути

Правило «один круг доработки» стоит Ticket-у на критическом пути (у него ≥3 транзитивно зависимых
Ticket-а) всей цепочки зависимых. Если подтверждённые находки второго круга не уровня high, Ticket
получает ещё один круг ровно по этим находкам, затем проверку только этого круга. Листовым
Ticket-ам — по решению владельца. Находки второго круга перед этим подтверждают агенты-скептики:
каждый пытается опровергнуть одну находку, в круг идут только устоявшие.
Источник: worfy-mvp/21, решение владельца 2026-10-06.

## Зависимые считать от реально заблокированных Ticket-ов

Сколько Ticket-ов встанет за заблокированным, считать по `Blocked by` только от Ticket-ов в состоянии
`blocked`. Ticket, пропущенный в Wave как уже влитый, ничего не блокирует; если считать и от него,
критический путь раздувается, и решение о круге исправления принимается по ложной цифре.
Источник: ночной прогон worfy-mvp 2026-10-05/06.

## Wave можно вести по зависимостям, а не по таблице

С разрешения владельца Ticket стартует, как только все его блокеры влиты и у его следа по файлам нет
общих файлов с Ticket-ами, которые идут сейчас. Таблица Wave-ов в `spec.md` — план, а не барьер: ждать
конца всей Wave ради одного медленного Ticket-а незачем.
Источник: ночной прогон worfy-mvp 2026-10-05/06.
