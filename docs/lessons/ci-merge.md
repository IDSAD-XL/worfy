# CI и мерж в `main`

## CI ждать одной долгой командой, а не частым опросом

У агента ограничено число ходов. Частый опрос CI дважды исчерпал их посреди CI run, и мерж
оборвался. Ждать так: `gh run watch <id> --exit-status` с timeout Bash 600000 мс; не дождался —
повторить ту же команду.
Проверка: harness/bin/tests/epic-wave-ship-ticket.test.sh:93 — блок `gh run watch` в шаге 8 skill-а
ship-ticket; timeout 600000 и повтор той же команды test не сверяет.
Источник: ночной прогон worfy-mvp 2026-10-05/06.

## CI не стартует на PR в состоянии DIRTY

GitHub не создаёт run `pull_request`, пока у PR `mergeStateStatus: DIRTY`: чеки не краснеют, а
отсутствуют. Документный коммит Wave меняет файлы Ticket-ов, и открытые PR Wave становятся DIRTY.
Перед ожиданием CI, кругом доработки и мержем — rebase на `main`.
Проверка: проверки нет: правило «rebase перед ожиданием CI» — текст агентов и skill-ов, test его не сверяет.
Источник: ночной прогон worfy-mvp 2026-10-05/06.

## Мержи и документные коммиты в `main` — по одному, под замком

Когда параллельно идут несколько Wave-ов или workflow, мерж PR и документный коммит в `main` берут
замок: `mkdir <scratchpad>/main.lock` (успех — замок взят), снять `rmdir` при выходе, в том числе
при ошибке. Замок старше 90 минут считать зависшим и снимать. Без замка два коммита в `main` из
параллельных Wave-ов гонятся: push второго отклоняется, а открытые PR становятся DIRTY.
Проверка: проверки нет: `wave-gate merge` берёт замок `main`, но test сверяет только путь замка в файле
состояния, а не то, что мерж его ждёт.
Источник: ночной прогон worfy-mvp 2026-10-05/06.

## Чужой глобальный аккаунт `gh` — токен аккаунта Project-а, глобальный аккаунт не переключать

Если глобальный `gh` переключён на другой аккаунт, команды `gh` и `git` по `origin` должны идти от
аккаунта Project-а (поле `github.account` Profile-а). С plugin `worfy` `GH_TOKEN` этого аккаунта
ставит hook `SessionStart` (`harness/hooks/gh-token-env.sh`, `worfy-harness` 18); ручной префикс
`GH_TOKEN=$(gh auth token -u <аккаунт>)` нужен только в Session без plugin-а. Ответ «Could not resolve
to a Repository» или `Repository not found` при `git push` — сверить `gh auth status` с
`github.account`. Глобальный аккаунт без разрешения владельца не переключать: им пользуются другие
Session-ы.
Проверка: harness/hooks/tests/gh-token-env.test.sh:92 — hook ставит `GH_TOKEN` аккаунта Project-а; что он
не зовёт `gh auth switch` и `gh auth login`, проверяет тот же файл.
Источник: ночной прогон worfy-mvp 2026-10-05/06; `worfy-harness` 18 (2026-10-08).

## «(кэш)» в строке `[gate]` — test-ы не перезапускались; перед мержем это годится, только если rebase ничего не сдвинул

`gate.sh` кэширует зелёный результат по отпечатку: HEAD плюс незакоммиченные изменения. Строка
`[gate] зелено (…): … (кэш)` значит, что e2e в этот раз не шли — зачтён прошлый зелёный прогон того
же дерева. Rebase, который сдвинул ветку на новый `main`, меняет HEAD, и кэш не сработает. Поэтому
кэш перед мержем допустим, только когда ветка уже стояла на текущем `main`. В отчёте писать «из
кэша», а не «прогнан». Красное не кэшируется: упавший прогон всегда идёт заново.
Проверка: harness/hooks/tests/gate-verdict.test.sh:24 — второй зелёный прогон идёт «(кэш)»; что правка
файла кэш сбрасывает, а красное не кэшируется, проверяет тот же файл.
Источник: worfy-daily/28, PR #66.

## CI на GitHub — только Linux; e2e и собранный `.app` проверяет локальный `gate full` перед мержем

2026-10-06 владелец посчитал цену: macOS-раннер — около $75 в месяц, а e2e и упаковка занимали 6,5
из 8,7 минуты прогона. С PR #42 CI — job на `ubuntu-latest` (lint, typecheck, unit и contract
test-ы), PR только с документами CI не запускает, e2e и `.app` проверяет только `gate full` перед
мержем. Следствия: test, завязанный на macOS, помечать `it.skipIf(process.platform !== 'darwin')`,
иначе на Linux он красный; e2e разных агентов — по одному под замком `/tmp/worfy-e2e.lock` (урок о
`firstWindow` в `agents.md`). Правила — `~/.claude/profiles/worfy/rules.md`.
Код: `.github/workflows/ci.yml`.
Проверка: проверки нет: `runs-on: ubuntu-latest` в `.github/workflows/ci.yml` test не сверяет; test без
`skipIf` для macOS краснеет только в самом CI на Linux.
Источник: PR #42; коммиты `~/.claude` f5f0cbb, 8d2fbea.
